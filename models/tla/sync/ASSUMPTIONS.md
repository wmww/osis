# Sync convergence model: assumptions
> Summary: What SyncConvergence.tla abstracts away from spec/sync.md §5–§7 and spec/commits.md §5, and why.

- **One label, one blind server.** Everything written is in the label's closure and entitled to it; "outside the required set", retagging, projections across labels and certificate copies are not modeled. Multi-label behaviour is per label, so one label carries the convergence question.
- **Blobs are records** `[c, ds, v]`: commit, delta set, encryption index. A fresh encryption (new salt) is a new `v`, and `v` also stands for the blob ID order (duplicate and carrier tiebreaks); `Vs = {0,1}` bounds re-encryptions. Prefix, wrap, stamp, padding and token cryptography are not modeled: every writer holds every delete token (all retention is `writer`), stamps are always valid, so authorization never fails for honest nodes.
- **One retention class per commit**, so each commit has one body (one projection). Retention, expiry and keep bounds are per commit constants (`Exp`, `LeastAbs/Rel`, `MostAbs/Rel`; 99 = absent). A snapshot's constants are the schema defaults (none in every scenario). A commit carrying a purge request has the extra keep-at-least `created + PurgeKeep` (MEMBERSHIP_KEEP), which also lifts its keep-at-most to at least that.
- **CRDT is abstract.** Each scenario fixes which deltas a commit kills (`Kills`, at the killer's creation time) and which deltas a snapshot covers (`Covers`): a body is covered iff its delta set is a subset (an empty one always). Coverage does not depend on the viewer, except that the viewer must have applied and hold the snapshot. Joins always succeed (no parked bodies, no unfetched pages: "establishes nothing" never arises). `state[n]` is the set of deltas n has joined (from its writes, received bodies, and the deltas a received snapshot covers); nothing removes from it.
- **Commits are written by a fixed author in a fixed causal order** (`Deps`). Content writes are weakly fair. A snapshot commit (one per scenario, fixed author) is written unfairly (optional compaction) except when due: its author must delete a body with live writes and sees no carrier, must drop past keep-at-most a held body with live writes and holds no covering snapshot, must send a timed delete for a body that still has live writes and sees no covering snapshot under the label, or applied a purge and holds no covering snapshot under the label; then the write is weakly fair. One snapshot commit per scenario, so covered-equal snapshots (sync §7) never arise.
- **Sync is per entry.** `Recv` delivers any server entry the node has not seen since it was last added (cursor semantics: a re-added ID is a new log event), in any order (a reordering server). Nodes read the server's entry set directly when deciding to upload ("the label lacks"); carriers (snapshot, strict superset, identical body with a lower blob ID) count only once received. A deletion removes the entry from every node's view at once, so the stale-view race of S12 is not exercised; the tiebreak that closes it is modeled.
- **Global discrete clock**, `0..MaxT`, no skew. Keep bounds and expiry compare against it. Tombstone lifetime is a fair `TombGC` step at any time after deletion. Purge scenarios use `MaxT < PurgeKeep`: every node is back within MEMBERSHIP_KEEP.
- **Classification** follows sync §6 literally per node (applied commits, held blobs, held snapshots); must-not-hold wins every overlap.
- **Local drop** of every must-not-hold body is weakly fair. A node that drops a body for a purge keeps a rewrite without the purged deltas (`v = 0`). A writer drops a body with live writes past keep-at-most only while it holds a covering snapshot (commits §5; the other drop reasons need none, S16). **Timed delete** (`SendTimed`, fair): the replacing writer (author of a held commit that killed one of the body's writes) sends one per entry, timed at first death plus D, once a covering snapshot is under the label if the body still has live writes.
- **Adversary**: unfair, bounded steps: `AdvDrop` (server loses an entry, no tombstone), `AdvReplay` (stale stamped entry re-added when no tombstone blocks it), `GoOff` (node offline; it comes back by a fair `GoOn`).
- **Liveness under weak fairness** of every honest step kind per node and commit (per-commit so one blob's churn cannot starve another's). Compaction is optional (unfair).
