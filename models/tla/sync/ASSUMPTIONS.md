# Sync convergence model: assumptions
> Summary: What SyncConvergence.tla abstracts away from spec/sync.md §5–§7 and spec/commits.md §5, and why.

- **One label, one blind server.** Everything written is in the label's closure and entitled to it; "outside the required set", retagging, projections across labels and certificate copies are not modeled. Multi-label behaviour is per label, so one label carries the convergence question.
- **Blobs are records** `[c, ds, v]`: commit, delta set, encryption index. A fresh encryption (new salt) is a new `v`; `Vs = {0,1}` bounds re-encryptions. Prefix, wrap, stamp, padding and token cryptography are not modeled: every writer holds every delete token (all retention is `writer`), stamps are always valid, so authorization never fails for honest nodes.
- **One retention class per commit**, so each commit has one body (one projection). Retention, expiry and keep bounds are per commit constants (`Exp`, `LeastAbs/Rel`, `MostAbs/Rel`; 99 = absent).
- **CRDT is abstract.** Each scenario fixes which deltas a commit kills (`Kills`, at the killer's creation time) and which deltas a snapshot covers (`Covers`): a body is covered iff its delta set is a subset. Coverage does not depend on the viewer, except that the viewer must have applied and hold the snapshot. Joins always succeed (no parked bodies, no unfetched pages: "establishes nothing" never arises).
- **Commits are written by a fixed author in a fixed causal order** (`Deps`); writes, including the re-snapshot after a purge and the snapshot before deleting a live body, are weakly fair. So the model assumes someone eventually compacts; the spec never says who must (AMBIGUITIES.md).
- **Sync is per entry.** `Recv` delivers any server entry the node has not seen since it was last added (cursor semantics: a re-added ID is a new log event), in any order (a reordering server). Nodes read the server's entry set directly when deciding to upload ("the label lacks") or that a covering snapshot is under the label (only snapshots they have received count). Messages, paging, range reconciliation and handshakes are abstracted to these steps.
- **Global discrete clock**, `0..MaxT`, no skew. Keep bounds and expiry compare against it. Tombstone lifetime is a fair `TombGC` step at any time after deletion.
- **Classification** follows sync §6 literally per node (applied commits, held blobs, held snapshots), with must-not-hold taking priority over must-hold (AMBIGUITIES.md).
- **Local drop** of every must-not-hold body is weakly fair. A writer that drops a body for a purge keeps a rewrite without the purged deltas (`v = 0`).
- **Adversary**: unfair, bounded steps: `AdvDrop` (server loses an entry, no tombstone), `AdvReplay` (stale stamped entry re-added when no tombstone blocks it), `GoOff` (node offline; it comes back by a fair `GoOn`).
- **Liveness under weak fairness** of every honest step kind per node and commit (per-commit so one blob's churn cannot starve another's). Compaction is optional (unfair).
