# Sync convergence model: assumptions
> Summary: What SyncConvergence.tla abstracts away from spec/sync.md §5–§7 and spec/commits.md §5, and why.

- **One label, one host.** Everything written is in the label's closure and entitled to it; "outside the required set", retagging, projections across labels and certificate copies are not modeled. Multi-label behaviour is per label, so one label carries the convergence question.
- **Blobs are records** `[c, ds, v]`: commit, delta set, encryption index. A fresh encryption (new salt) is a new `v`, and `v` also stands for the blob ID order (duplicate and carrier tiebreaks); `Vs = {0,1}` bounds re-encryptions. Prefix, wrap, stamp, padding and token cryptography are not modeled: every writer holds every delete token (all retention is `writer`), stamps are always valid, so authorization never fails for honest nodes.
- **One retention class per commit**, so each commit has one body (one projection). Expiry and history are per commit constants (`Exp`, 99 = absent; `KeepUntil[c]` the keep-at-least T and `KeepAfter[c]` the D after replaced, 0 none; `NoneC` the `none` commits, a snapshot carrying a `none` write live among them). The relative bound is judged by the compactor from the kill times of the commits it applied (the global clock stands for signed `ts`), so compactors holding different kills may differ; readers never compact. A commit carrying a purge request is kept at least until `created + PurgeKeep` (ROLE_KEEP).
- **CRDT is abstract.** Each scenario fixes which deltas a commit kills (`Kills`, at the killer's creation time; a body with a killed delta is replaced) and which deltas a snapshot covers (`Covers`): a body is covered iff its delta set is a subset (an empty one always). Coverage does not depend on the viewer, except that the viewer must have applied and hold the snapshot. commits §5 frontiers: a snapshot is written only by a node that applied every commit whose deltas it covers (`Write` guard; the scenarios' `Deps` already ensure it), so its frontier reaches what it covers; with one snapshot per scenario a snapshot never covers another. Joins always succeed (no parked bodies, no unfetched pages: "establishes nothing" never arises). `state[n]` is the set of deltas n has joined (from its writes, received bodies, and the deltas a received snapshot covers); nothing removes from it.
- **Commits are written by a fixed author in a fixed causal order** (`Deps`). Content writes are weakly fair. A snapshot commit (fixed author) is written unfairly (optional compaction) except when due: its author must delete a body with live writes and sees no carrier, holds a replaced `none` body with no covering snapshot (`OwesCover`), or applied a purge and holds no covering snapshot under the label; then the write is weakly fair. The `none` scenarios give each writer its own cover; covered-equal snapshots (sync §7) are not exercised (the covers never cover each other).
- **Sync is per entry.** `Recv` delivers any host entry the node has not seen since it was last added (cursor semantics: a re-added ID is a new log event), in any order (a reordering host). Nodes read the host's entry set directly when deciding to upload; "the label lacks" a body unless a blob of its commit there holds every delta of it that no snapshot under the label covers (sync §6; snapshots as the node has received them, `LHolds`; `Converge` uses the global view, `GHolds`). Carriers (snapshot, strict superset, identical body with a lower blob ID) count only once received. A deletion removes the entry from every node's view at once, so the stale-view race of S12 is not exercised; the tiebreak that closes it is modeled.
- **Global discrete clock**, `0..MaxT`, no skew, so clock-offset sampling (sync §6, RTT-bounded samples) is not modeled; neither are connections (request timeouts and redials, sync §6) nor signals (sync §9, including the `MAX_DRIFT` replay window). Keep bounds and expiry compare against it. Tombstone lifetime is a fair `TombGC` step at any time after deletion. Purge scenarios use `MaxT < PurgeKeep`: every node is back within ROLE_KEEP.
- **Classification** follows sync §6 literally per node (applied commits, held blobs, held snapshots); must-not-hold wins every overlap.
- **Local drop** of every must-not-hold body (purged, expired, a covered `none` body past its keep-until, a strict subset) is weakly fair. A node that drops a body for a purge keeps a rewrite without the purged deltas (`v = 0`). Nothing else drops: a covered body past its keep-until goes only by compaction (unfair).
- **Adversary**: unfair, bounded steps: `AdvDrop` (host loses an entry, no tombstone), `AdvReplay` (stale stamped entry re-added when no tombstone blocks it), `GoOff` (node offline; it comes back by a fair `GoOn`).
- **Liveness under weak fairness** of every honest step kind per node and commit (per-commit so one blob's churn cannot starve another's). Compaction is optional (unfair).
