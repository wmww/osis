# Roles model: ambiguities and findings
> Summary: Places where spec/permissions.md §1–§2, §5.1 and §5.2 left a choice or failed a checked property. M1 (a removed admin's backdated write on its remover's edge survived as a chain write) is fixed; M2 (sticky drops) is known and kept as an expected failure; readings M3–M6 are settled by spec edits matching the model and osis-perm.

## Findings (expected failures in run.sh)
- **M1. Chain-write exemption lets a removed admin forge (`MC_forge.cfg`, LateEdge). Fixed** by option (a): spec/permissions.md §5.1 now counts writes on A's chain only as its frontier lists them (the commit IDs of its chain certificates at R's point); the model's exemption is gone, honest frontiers always hold the author's chain certificates (`Certs`), and `MC_forge` passes. Original finding: §5.1 Frontier: "a frontier MUST NOT cover what A had not received as of T. A's own chain writes and R itself always count." Read as the writes that set the admin edges on A's admin paths (as osis-perm does), this counts writes A never received. Trace: n1 is A's first admin; n2, n3 admins; n2 removes n3 at ts 8 (frontier empty); afterwards n3 writes n2's edge as admin `until` 9, stamped ts 6. At n2's removal that write set n2's own admin edge, so it counts as n2's chain write and is never dropped: n2's admin expires at 9 while n3 stays removed. Any lowering of the remover's chain edge works the same way (an `until` after the removal, a lower invite); a lowering that takes effect before T instead voids the removal, which is the accepted backdating race (the earliest stamp wins until disputes are settled per node, notes/disputes-plan.md step 3). osis-perm reproduced it (the forgery applied, the remover ended with no role).
  Options: (a) drop the exemption: A's frontier lists its chain writes (it holds them as certificates, so they are always received); a forged one is then dropped and A's edge reverts. Residue: a chain write A never received that its authority at T happens to rest on falls, and R with it (rare: A's own view had another path). (b) Exempt only chain writes that do not lower the edge they set (forged raises only help A). (c) Exempt only chain writes ordered before the newest write A had received on that edge. **Recommendation: (a)**, one rule ("nothing but the frontier decides"), at the cost of a few frontier entries; (b) if the residue of (a) matters.
- **M2. Drop order matters (`MC_sticky.cfg`, DropOrderFree).** §5.1 steps 4–5 restart at the first write that adds to D, and D only grows within an evaluation. Trace (with honest frontiers): n2 removes n3 at ts 8 (frontier empty); n3 then grants n2 admin on B stamped ts 6, which n2 never held, so the removal drops it; n1 removes n2 at ts 10 (frontier empty), dropping n2's removal. Walk order keeps the grant dropped although what dropped it is invalid; finding n1's demotion first keeps the grant. Known (notes/permissions.md, sticky drops; re-grant repairs). Determinism holds only because the order is fixed: an implementation that discovers drops in another order (by thing, by component, in parallel) diverges. The text is precise enough ("restarts"); worth a sentence that the first adding write in walk order wins.

## Readings
- **M3. Several-edge removal: one point or in sequence.** commits §2 allows one commit removing several holders' edges; §5.1 "each edge write of a commit is judged on its own". Model: every edge write of a commit is judged against the state before the commit, then applied in holder order (osis-perm likewise). In sequence, removing B (through which the author is admin) first would make the author's second removal unauthorized. Resolved: §5.1 now says "judged on its own, against the state before the commit".
- **M4. Self-removal through an actor that holds admin on the target.** §2: a write lowering X's edge is a self-removal when admin on X is the author's only authority for it. If X itself is admin on the target, the author's edge-admin authority may come through X. Resolved: §2 says authority through X does not count (the author's class on the target is taken with X's edge there disregarded), as osis-perm and the model (`Judge`, `clsWithout`). An explicit write demoting its own author (§5.1 kept standing) then needs authority of the author's own beside X; `MC_group` gives n2 a direct admin edge on A ending at 9.
- **M5. Re-grant "valid again" (§5.2).** "A re-grant makes every write of the re-granted actor valid again, including those in the gap": literally every write, including forgeries backdated before the actor's first grant. Model: writes from the first point the author held the required role (as osis-perm); earlier ones stay invalid. Also "re-granted" is judged at the end of time (every `until` passed), so validity does not depend on the clock. Resolved: §5.2 now says an actor holding the role in the final state (every edge with an `until` counted as removed) is re-granted and its writes from the first point it held the role are valid again.
- **M6. Who "reaches the holder".** §5.1 step 4: X reaches M (or is M) through alive edges at R's point, before R. Model: before R. Resolved: §5.1 now says "is or reaches the holder (by edges alive just before R)" (osis-perm likewise).

## Not modeled
Invites and invite grants (so whether an invite grant is an explicit write that resets the restore window is open), links and single-use redemptions, mutual role beyond B on A, more than two things, frontiers per counter range (a frontier is a set of commit IDs), pending commits and certificates.
