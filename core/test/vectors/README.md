# osis conformance vectors

Language-neutral test vectors for the osis wire formats (spec/wire.md and the sections it cites). Another implementation passes a file by reproducing every live case.

## Files
`<subject>/<name>.vec`, UTF-8 text. Records are runs of `key: value` lines separated by blank lines; lines starting with `#` are comments. The first record is the header: `subject`, `spec` (the governing section), `source` (`hand-written` or the generator command). Every later record is a case with at least:
- `case`: a name unique in the file;
- `spec`: the spec section it checks;
- `pending: <reason>` (optional): the case is listed but not yet checked; frozen files have none.

Byte strings are lowercase hex. Inputs too large to inline are written as `xof("<ascii>", <n>)` (the first n bytes of the unkeyed BLAKE3 XOF of the ASCII string) or `zeros(<n>)`. Lists of integers are comma-separated without spaces.

## Subjects
- `cbor/` (spec/data-model.md §5): `hex`, then `diag` (the bytes decode, re-encode to themselves, and print as `diag` in RFC 8949 §8 notation: floats in shortest round-trip form with `.0` when integral, `NaN`, `Infinity`; tags as `n(content)`) or `reject: <rule>`. Rules: `truncated`, `too-large`, `too-deep`, `trailing`, `non-shortest`, `indefinite`, `reserved-info`, `int-range`, `utf8`, `map-order` (unsorted or duplicate keys), `set-order`, `equal-links` (two set elements or map keys that are links of one content hash), `simple` (null, undefined, other simple values, half or single floats), `nan` (NaN other than `7ff8000000000000`), `tag-content` (a profile tag around content of the wrong shape).
- `tid/` (spec/wire.md §3): `record` (canonical bytes of the creation record), `tid`, `text`, `uri` (a copy also `creator`); or `record` with `reject: creation-fields` (both or neither of fields 0 and 1, or field 3 without 0).
- `chunker/` (spec/wire.md §6): `table-blake3`, `g0`, `g255` (little-endian bytes of the gear table and entries); `input` with `lengths` (chunk lengths in order).
- `chunker/tree.vec` (spec/wire.md §6): chunk tree of `input` with the format chunker: `dedup` (dedup secret), `chunks` (leaf count), `level-<k>` (link counts of the level-k nodes in order), `root-hash` (root content hash). No encryption: the shape and hashes depend on the bytes and the dedup secret only.
- `chunker/pages.vec` (spec/crdt.md §8, spec/wire.md §6): an element array (`input`) paged at the format's parameters: `pages` (element counts of the pages in order), `link-pages` (link counts of the link pages in order, when the page links exceed `PAGE_TARGET`), `top` (content hashes of the array's links as written, keyed by `dedup`).
- `padme/` (spec/wire.md §5, hand-written): `l` and `padme` (= padme(l)); `p` and `padded` (= pad(p)); or `padded` with `reject: padding`.
- `tid/key-actor.vec`: as `tid/`, plus `seed` and `signing-key` (from the seed as in `keys/`) and the `nonce` used (random for a node, `kdf("creation nonce", seed, "")` for a link key).
- `kdf/` (spec/crypto.md §1): `purpose`, `secret`, `input`, `out` (the XOF form when longer than 32 bytes); `derive-key-context`, `material`, `out` for a direct BLAKE3 derive_key.
- `keys/` (spec/crypto.md §3, §6, spec/sync.md §2, §10): inputs (seeds, secrets, tid, label ID, step key, index, unix ms) then the derived keys, secrets and hashes, named by what they are. Ed25519 keys are RFC 8032 keys from a 32-byte seed; `-value` fields are canonical bytes of the agility enum value.
- `box/` (spec/crypto.md §1, §4, spec/wire.md §7, §9): an `epoch nonce` case (`actor`, `role`, `n`, `secret`, `nonce`: the nonce rule); the recipient by `recipient-kem-seed`; slot fields (`actor`, `member`, `role`, `n`, `nonce`, or `label-id`, `step-key`, `group` (whose epoch the entry box names), or `recipient`, `prefix`), form fields (`keyset-n`/`keyset-nonce` or `keyset: none`, `suite`; `s-epoch-n`/`s-epoch-nonce`), the `ad`, randomness in draw order (`ephemeral`, the X25519 private key, then `mlkem-m`), `payload` (canonical bytes), then `sealed`, `wrap`, `box` or `blob`. Rejections: `reject: decrypt`; `reject: malformed` (a box whose item does not name its key's epoch).
- `wrap/` (spec/crypto.md §5): `read-secret`, `blob-id`, `blob-key`, `wrap`; a blob over an opaque `prefix` with its `plaintext`, `padded`, `blob-key` (the randomness drawn), `blob`, `blob-id`. Rejections: `reject: decrypt`.
- `delete/` (spec/crypto.md §7): `secret`, `seed` (`kdf("delete key", secret)`), `key` (its Ed25519 public key), `level`, `salt` (prefix salt; two per level), `header-blind`, `commitment` (level || blinded key), `label-id`, `blob-id`, `at`, `digest` (the Delete digest, spec/wire.md §11.2), `signature` (the blinded signature; deterministic nonce prefix `kdf("delete nonce", seed, salt || header-blind)`). A key-actor case: `key-actor-seed`, `signing-seed` (`kdf("sign", seed)`), whose key is the delete key. `reject: signature` for a plain signature by the unblinded key under the commitment.
- `sign/` (spec/crypto.md §2, spec/wire.md §11.2): `domain` (or the open inputs and their `digest`), `seed`, `public`, `digest`, `signature`.
- `schema/` (spec/data-model.md §9, §10): case `core schema` with `id`, `revision`, `value` (canonical bytes of the core schema as a `schema` value: every field written, `none` spelled out, docs included) and `hash` (unkeyed BLAKE3 of `value`); then per core aspect `ak` and `value` (canonical bytes of a typed write through the core schema type: every declared field present).
- `commit/` (spec/wire.md §4, spec/commits.md): inputs `signing-seed`, `dedup` (dedup secret of every touched thing), `delete-secrets` (`level:secret` for the admin, author-chain write and thing write secrets; the header lists their delete keys), `blind` (the header blind drawn), `delta-<ai>-<di>` (canonical delta or snapshot bytes); outputs `header` (canonical bytes), `commit-id`, `signature` (raw Ed25519 under `"osis v1 commit"`), `blob` (commit blob plaintext, unpadded). A header-only purge rewrite gives `blob` and `commit-id`. The linked-list case lists all drawn `randomness` (the header blind, then each list blob's prefix salt), `aspect-list-blake3`, and `list-blob-<i>` = `blob-id prefix-salt commitments plaintext` in write order (`commitments` the prefix's 33-byte commitments concatenated: the level-2 key's only) (blob IDs are opaque test IDs; content hashes are keyed by `dedup`). Rejections: `header` with `reject: <rule>`: `parked-version` (format version above ours: park, spec/versioning.md §2), `aspect-class`, `membership-expires`, `expires-ts`, `purge-expires`, `purge-membership`, `origins`, `import-things` (an import with deltas on more than one thing), `frontier`, `counter-range`, `order`, `chunk-keys`, `fixed-retention`, `fixed-expires`, `unused-key`, `delete-levels`, `delete-key` (not a valid Ed25519 point), `ephemeral` (an ephemeral marker on anything but a commit-form content snapshot without chunks, purge, undo or linked lists, an unknown marker, or a relay-only or presence commit with `expires`). The `ephemeral commit`, `relay-only commit` and `presence commit` cases carry their writes under a session source of their author, with that session's frontier (spec/crdt.md §2.1, §8).
- `blob/prefix.vec` (spec/wire.md §5): `salt`, `expiry` (wall ms or `none`), `class` (0 durable, 1 ephemeral, 2 relay-only, 3 presence), `commitments` (comma-separated 33-byte hex, levels ascending), optional `keys` (`level:delete-key` pairs the commitments blind under the salt and `header-blind`) → `prefix`. Rejections `reject: <rule>` on `prefix`: `prefix-order` (levels unsorted or repeated), `prefix-level` (level outside 1..3), `prefix-count` (more than 3), `prefix-short`, `prefix-class` (a class byte above 3); `parked: framing` for an unknown framing version (stored as a blob with no expiry and no commitments).
- `blob/blobs.vec` (spec/wire.md §5, §6): `prefix`, `plaintext`, `padded`, `blob-key` (the randomness drawn), `blob`, `blob-id`, `link-hash` (content hash under `dedup`); the chunk case adds `delete-secret`, `delete-level`, `delete-key`, `header-blind` (its prefix commits to the key blinded by its salt and the header blind). `reject: padding` for a blob whose AEAD opens but whose plaintext breaks the Padmé rule.
- `step/steps.vec` (spec/wire.md §8, spec/sync.md §2): group secrets, `index`, `group`, read epoch, reader seeds (key actors: claim by the X25519 half of the KEM key; the static reader by its signing key, entry box sealed to its KEM key), randomness in draw order (`step-secret`, `ephemeral`, `mlkem-m`, 32 bytes per `padding` key, 8 bytes per `shuffle` swap: Fisher-Yates from the end, `le64 mod (i + 1)`), then the step's keys, `claims` (in written order), `claim-set`, `claims-hash`, `signed-digest`, `step`, `step-id`, `label-id`, the readers' `claim-key-<i>`, `static-entry` and `entry-box` (canonical `box` value). The order of claims is the registrar's choice: a reader checks membership, not positions. Rejections: `step-signature` (child under its `parent`), `label-id` (genesis delete key not hashing to the label ID), `claim-count` (not a power of two).
- `inbox/` (spec/wire.md §9): `recipient`, `recipient-kem-seed`, `now`, randomness (`salt`, `ephemeral`, `mlkem-m`) → `prefix`, `payload` (canonical `InboxPayload`; the commit is a stand-in value until commit vectors land), `blob`, `blob-id`; `reject: decrypt` for another recipient.
- `lan/announce.vec` (spec/sync.md §10, provisional like the datagram): `dialable-seed`, `dialable`, `lan-secret`, `unix-ms`, `window`, transport `key`, `port` → `tag`, `digest` (BLAKE3 of tag || key || be16 port, the signed digest), `signature` (Ed25519 under `"osis v1 lan announce"`), `keystream` (`kdf_xof("lan sig", lan secret, le64(window) || digest)`, 64 bytes), `sealed` (their XOR), `datagram` (the 124 bytes).
- `link/` (spec/wire.md §10): `bytes` (canonical link or card) and `text`. Rejections on `bytes`: `link-cap` (more than 8 addresses, 4 peers, 4 relays, or a URL over 256 bytes); `parked: format` for a format other than 1.
- `bundle/` (spec/wire.md §12): `bundle` (the file bytes) and `records` (record kinds in order); an importer reads every record, verifies paths and stamps, and accepts it. `reject: stamp` for an entry whose stamp does not verify under its label's head write key.
- `proto/messages.vec` (spec/wire.md §11): `frame` (a body and its frame); `hello`; `fixture` (the label the messages use: its ID, steps and claim set, and the challenge and static key opens are signed for); then one message per case: `kind`, `hex` (the body, which decodes and re-encodes to itself). Rejections: `hex`, or a body too long to inline as `head`, `item`, `count`, `tail` (the body is `head || item` repeated `count` times `|| tail`), or a `frame`; then `reject` (`cap`, `count`, `id`, `head`, `shape` (an item of the wrong length), `cbor`, `size`, `step`, `ranges`, `unknown-kind`, `frame-length`) and `answer`, the Error code sent back.
- `proto/reconcile.vec` (spec/wire.md §11.3): `ids` and their `fingerprint`.
- Further subjects are documented here as they land; MANIFEST lists them.

## Manifest and freezing
`MANIFEST` lists every file: `provisional` (checked; may change with the implementation), `pending` (named, not yet producible), or `frozen <blake3> <FC-n>`. Nothing is frozen before the first stable release: every file is provisional and changes with the implementation. At a release, files are frozen (`gen-vectors freeze <path> FC-<n>`), and from then on a frozen file's bytes must hash to the listed BLAKE3; changing one is a format change logged as a `## FC-<n>: <title>` entry in `FORMAT_CHANGES.md` naming the file and the reason. The runner fails on an unlisted file, a missing listed file, a changed frozen file, or an entry that does not name the file.

## Running (osis)
- `cargo test -p osis-vectors`: one test per file, plus the manifest policy.
- `cargo run -p osis-vectors --bin gen-vectors`: rewrites every provisional generated file from the implementation (frozen and pending files are never touched). `gen-vectors list` shows status and case counts.
- Generated files must equal a fresh generation; hand-written files (`cbor/`, `padme/`) are checked case by case.
