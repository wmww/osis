# Sync: what a node holds
> Summary: Area 1: the node thing and the node root, the dial list, sync units (what a sync ID carries), own things and first entry, the node closure, the holders held for keys and the sync set they give, release, who is to be waited for, redeeming, and reading and writing through another node.

**Principle:** a node holds exactly its node closure: what its node root reaches by strongs, walked sync unit by sync unit, entering an independent thing that the sync unit's keys cannot open only by keys of it its roles give, and, for keys alone, the holders on its paths to what it enters. Roles never decide what syncs: strongs do; a role decides only what the node may do with what it syncs and which holders' key parts it fetches. It syncs the sync ID of each independent thing it holds, and a sync ID carries exactly its thing's sync unit. Nothing else decides (no list of peers or of sync IDs to keep), and nothing waits for a peer that is not connected.

## 1. Node thing and node root
- **Node thing** N: each node has one, minted with the node's key (spec/permissions.md §3) at its first start: an ordinary independent thing with a sync ID, the thing the node signs as. It holds the node's roles (on its accounts, spec/permissions.md §8). Its sync unit is N alone: no strong of N reaches the node root.
- **Node root**: each node has one, minted with admin N at its first start; local: it has no sync ID, its commits go under none, and nothing references it.
  - Its `holds.0` (spec/data-model.md §8) holds the node's strongs, a strong to N among them, written at its first start; its `clients^.0` names whom the node acts for (spec/data-model.md §9), and its `settings^.0` the thing holding the node's settings.
- **Settings**: a node's settings (`caps^.0`, spec/data-model.md §9) are N's entries, keyed by N, on the thing its node root's `settings^.0` names while N holds write or admin on it (its account, spec/permissions.md §8), written by that thing's admins; absent (no such thing, or no entry): the defaults. Signing as N stays N's key's alone.
- **Dial list** `dial.0` on any thing (spec/data-model.md §9): each node's entry, keyed by its node thing: its dialable key and its URLs (spec/sync-transport.md §3), each node keeping its own (a new key replaces it), and keeping it on each thing it names as soon as it may write there; its readers dial them (spec/sync-opens.md §1), for dialing only. A node of an account keeps its entry on the account and on the account's profile (spec/permissions.md §8).
- No core data tells a node what another node holds.

## 2. Sync units and the sync set
- A thing **counts as independent** at a node when it has role secrets of its own (spec/crypto.md §3), by that count from the role commits the node holds, or, holding no keyset part of it, when the node holds a secret of it that a valid box of its `secrets.0` gave and a step its `sync.0` places (spec/crypto.md §7 Checked keys) bears the sync key of a sync secret of it so given (spec/sync-ids.md §4 Owner: a box is any writer's word, a step an admin's; the epoch need not be established, spec/crypto.md §4; a node keeping a thing unread reads none of its role commits). Otherwise a thing whose keyset commit the node does not hold counts as dependent until one arrives. Any other thing counts as **dependent**: its read secrets derive along its record chain (spec/crypto.md §3).
- **T's keys open** a thing X when X's secrets derive from T's, or T holds read or above on X's independent (spec/sync-judgement.md §1 Entitlement), or the public does (spec/permissions.md §1) by its grant on X's independent itself, as the public pieces T's sync ID carries show it (below). Read access counts through chains of role grants with key access held by no destroyed thing (a keyless grant, closing a cycle, and a destroyed thing read nothing through them: spec/crypto.md §4 Key access, Destroyed): the lowest role along a chain, the best chain counting (T's effective role, spec/permissions.md §1).
- **Sync unit** of an independent thing T: T, and each thing reached from T by strongs (spec/data-model.md §8 What counts) through things T's keys open only, that T's keys open, dependent or independent. A strong to a thing T's keys do not open adds nothing to the sync unit (it may bring in a stub, below), and the walk does not go on from it. A cycle adds a thing, never a loop.
  - **Stub**: T's sync unit carries the stub of each independent thing X a strong of it reaches where T's keys do not open X and T holds sync or above on X (T's effective role): the edge pieces on X of the holders T holds its role on X through (T itself, or a holder T holds sync or above on with key access), each as sync copies (spec/wire.md §4: T's keys do not open X, so T holds sync alone there): no header, evidence or record, and none of its content. X is no thing of the sync unit.
  - **Public pieces**: T's sync unit carries, for each thing a strong of it reaches, the public's edge piece on that thing's independent X (spec/permissions.md §4 Key part: the role commits writing the public's grant on X, a removal among them, and each role commit on X boxing it once its grant is set, with X's boxes to it; with their evidence) as certificate copies, from what the logging node holds. They tell T's readers whether the public reads X with nothing of X carried for it, so what the public reads is entered founded (First entry).
  - Every reader of T reads every thing the walk reads, so readers holding the same data compute the same sync unit.
- **What a sync ID carries**: T's sync ID (spec/sync-ids.md §2) carries exactly T's sync unit, its stubs as certificate copies (spec/sync-judgement.md §1). A thing may be carried under several sync IDs; an independent thing is carried under its own sync ID too. A dependent thing is carried under T's sync ID only while T's sync unit holds it: none is carried for having been minted with some admin. **Carriers**: a thing is under T's sync ID only as a node holding it logs it there (spec/sync-judgement.md §1 Retag, §3 Own store): an independent thing of the unit is carried under its own sync ID too, which T's readers sync; a dependent one only by a node reading T that holds it otherwise (it made it, or a unit it syncs carries it: a **bridge**). Nothing fetches a thing of T's unit from elsewhere: a node reading T holds such a dependent only once a bridge logged it under T, as logged there, and later writes on it reach T's readers through a bridge alone; a strong to a dependent of another thing that no node reading T holds brings in nothing under T (Dependent entry reads it under its independent's sync ID where that unit holds it), and the walk goes on only from what is held. A stub is carried alike: X's stub is under T's sync ID only as a node reading T logs it from an edge piece on X of a holder T holds its role through that it holds otherwise: T's own (in T's key part), or another holder's from that holder's key part it holds or from X it reads. A stub no node reading T so holds brings in nothing, whatever role T holds on X.
- **Own things** of a node: the things its keys hold grants on (spec/permissions.md §1): its node thing and any other (a link key it redeems by). The node's **role** on a thing is its own things' effective role on it (spec/permissions.md §1) by the thing's grants, and those of the holders on the way, as the node holds them: a grant is its target's own data and syncs with it (spec/permissions.md §2), so a node syncing a thing judges its role there by what it syncs. A thing's grants count where the node syncs the thing (an own thing, a thing the node closure holds, read or kept unread, or a held strong reaches where First entry carries it, a holder held for keys, a link it redeems; a dependent thing with the thing its secrets derive from) or holds an offer of it (spec/sync-inbox.md §5), and where the thing is a holder with a role now, with key access, on a thing whose grants count. On any other thing the node's role is none, whatever grants of it the node holds as another thing's certificates, but for the public's (spec/permissions.md §1), which counts wherever the node holds its grant: it is every party's role. Nothing else gives a role. The role is judged on the least state (First entry): an entry a piece keeps only while a loss is carried out gives no role, nor does anything held through it.
- **First entry**: a node enters a thing only by a unit it syncs carrying it (whole, its stub, a dependent of it at Dependent entry, or its edge piece in the key part of an own thing or a thing the node reads, spec/permissions.md §4 Key part) or by an offer of it the node holds (spec/sync-inbox.md §5). An edge piece carries its target while its edge is current, or while the node still holds a read secret of the target (a loss not carried out yet, spec/permissions.md §3 Lost access): a removal's piece tells of the removal and carries nothing once the loss is carried out. A strong to a thing neither brings in holds nothing, whatever role the node's own things have on it through holders. Entry is founded: what a node holds is the least state these rules give (keys found from a synced thing up), recomputed from what it holds at every change, so a thing's own unit and a key part held only through it carry nothing toward entering it, and no entry is kept for supporting itself.
- **Node closure**: the node root's **local part** (the node root and the dependent things the node opens, holding a read secret or the keys of the thing their secrets derive from, that it reaches by strongs through such things only), and the sync units the walk enters, walked sync unit by sync unit. Within a sync unit the walk follows its strongs; at a strong to an independent thing T that the sync unit's keys do not open (or one reached from the local part) it enters T's sync unit by the node's role on T:
  - **read**, at read or above, once the node holds a read secret of T it gives (a box to an own thing or to a holder it opens). T's sync unit is in the node closure.
  - **kept unread**, at sync, once the node holds a sync secret of T so. The node stores T's sync unit unread, and the walk stops at T: it reads none of T's strongs, so it enters nothing from T, and an independent thing in T's sync unit is entered (read or kept unread) only where the walk reaches it otherwise.
  - else not entered: the walk stops at T, T is not in the node closure, a read of it fails, and nothing else is affected. The lost-access trigger judges by the same role (spec/permissions.md §3 Lost access).
  - **Dependent entry**: at a strong in T's read sync unit to a dependent thing D of another independent thing X that T's keys open (through X's grants: T's role on X, or the public's), the walk also enters X's sync unit, read, once the node holds a read secret of X given it by a box. X's sync ID carries D where X's unit holds it, so D's later writes, X's rotations and its removals reach the node whoever else reads T (Carriers).
  - A strong in a sync unit to a dependent thing the sync unit's keys do not open is not followed, nor one in the local part to a dependent thing the node does not open; a strong to a thing whose record the node does not hold makes nothing held. A thing of the local part that no entered sync unit holds is local, under no sync ID.
  - The walk follows every change of the strongs it reads, of the secrets the node holds, of its role, and of the role commits and records that decide which things are independent and what keys open.
- **Held for keys**: keys are found from a synced thing up. For each independent thing C the node syncs (read, or kept unread: of its grants the node holds then only the edge pieces its holders' key parts give it), the node holds **for keys** every holder C's grants name (a thing: never the public, whose boxes anyone opens) with a role on C, and every holder the grants of a holder so held name in turn at read or above, each by a grant with key access (spec/crypto.md §4 Key access), other than an own thing or a thing the node closure reads, that the node opens (it holds a read secret of it: a box to an own thing, or to a holder it opens, gave it): it holds that holder's key part (spec/permissions.md §4), pulled from the holder's sync ID by role entries alone (spec/sync-ids.md §6 Role entries), and nothing of its content. The walk up ends at the node's own things: a holder the node opens nothing of is on no path of its own, and nothing of it is fetched.
  - Its key parts are the node's own role entries: it holds them, judges by them and serves them as any; it is no source of the holder's content, and its complete pass of the holder's sync ID is one of role entries.
- A strong to a thing the node never got holds nothing: if its last holder released it first (§3), it is gone, and the strong reads as not held. A read of a thing the node does not hold reads absent, whether the thing was destroyed, released or never held; no node keeps a marker telling these apart.
- **Not carried** (`NotCarried`, a diagnostic): the node names each strong in the node closure whose target is neither in the sync unit (or the local part) the strong is in nor held otherwise. A write adding such a strong is not refused: it reports it at once, as a warning.
- **Sync set**: for each independent thing T in the node closure, read: T's sync ID; kept unread: the sync IDs it keeps for T (spec/sync.md §3). For each holder held for keys, its sync ID, for role entries alone. And a link's sync ID, read, while the node redeems the link (§5).
- **Writing**: a node writes only what it holds; it fires at what it does not. The commits a node makes in one storage transaction must leave every thing they write that was outside its node closure as they were written in it at the transaction's end, or the node refuses them all before anything applies (`Invalid`); a role commit a node writes on a thing it holds for keys alone (its role entries: a rotation, a re-seal, an edge write) is no write outside it. A sealed fire (spec/sync-inbox.md §2) is built and never applied by its sender, so it is no write here; a node fires as a write only at what it holds (spec/sync-inbox.md §2). An addendum a node owes (spec/permissions.md §5.2) on a thing outside its node closure waits until it holds it.
- **Making a thing** is Writing a thing outside the node closure: every thing the commits of one storage transaction make (an app's write, or a node's first start: N and the node root with its strong to N, §1) is in the node closure at the transaction's end, or the node refuses them all: a thing is held only where a strong reaches it. A thing they write only role entries on (its minting with its secrets, keys and sync ID) may instead hold a role then on a thing in the node closure: it is held as any holder of what the node syncs, its record and public key record under that thing's sync ID (spec/sync-inbox.md §1), as a link key is (spec/permissions.md §7).
- **Cost**: a change that adds to the node closure costs work in proportion to what it adds; removing a strong costs at most work in proportion to the part of the node closure it held, never to its target's other referrers. A record held or forgotten, or a thing becoming independent, costs work in proportion to the sync units it changes. Holding for keys fetches key parts only for holders the grants of a read thing name, each found from the thing below it.

## 3. Release
- **A thing goes when its last reference goes**: every node holding it releases it, waiting for no absent peer; once no node holds it, a strong to it reads as not held.
- A thing R **leaves** the node closure when the walk (§2) no longer reaches it: a strong removed, a thing on its path leaving, or the node no longer holding a secret its role gives.
- **Release**: the node drops R once, for each sync ID it syncs that carried R when R left, the pass in flight with its connected sources has ended: every source of it but those full or refusing caught up (spec/sync-status.md §1) by streams read to their end from Pulls sent after R left, and R is still outside the node closure then. With no such source, at once. It never waits for a peer that is not connected. R back in the node closure before then is kept as it was.
- **Nothing of R stays** but what stays of any thing outside the node closure (spec/commits.md §5 What a held thing needs: its evidence and key parts, while a held thing needs them, under the sync IDs still synced, spec/sync-judgement.md §2); the rest of it, and the node's own writes on it not yet held elsewhere, go in the transaction that drops it (spec/commits.md §5 Forgetting, A released thing). R is not destroyed (spec/commits.md §5 Destruction): it may be fetched again where something references it, and what of it arrives again counts as never received; content of it arriving while it is outside the node closure waits until it is back (spec/commits.md §4 Outside the node closure).
- A **retained copy** (spec/permissions.md §3 Retain) is excepted: it is kept, read only, though no secret enters it. An own self-removal from R still to be sealed keeps R's record and role-class state until it is (spec/commits.md §5 What a held thing needs).
- **Stopping**: when a sync ID leaves the sync set, the node stops syncing it by the same timing; on stopping S, it closes S on every connection, drops S from every record in that step (spec/sync-opens.md §3), and shreds S's entries in its store (keys and wraps erased).
- **A thing leaving a sync unit**: when T's sync unit no longer holds thing X, X's parts leave the bodies under T's sync ID; each holder drops its copies there by its own view, and holders of the delete keys (spec/crypto.md §7) delete there the entries that leaves without a body (spec/sync-judgement.md §1 Retag, §2), each once its own view agrees. A node whose view still holds X there logs it again (spec/sync-judgement.md §3 Own store). X stays under every sync ID whose sync unit holds it.
- Lowering from read to sync is no release: S becomes kept unread with its store (spec/sync.md §3).
- **To be waited for** on S, by node N: a peer with S open (a source, spec/sync-status.md §1), or whose record N keeps holds S as a member (spec/sync-opens.md §3), or that may hold S by the rosters N holds (a thing it proved, other than N's own things, with a proven role on S's thing, spec/sync-opens.md §2; S kept unread: any peer) while no record N keeps naming the things it proved has acknowledged S's current credentials (`acked_pos` below `changed_at(S)`, spec/sync-opens.md §5 Testing). A peer told them that does not share S, one never met (no record), and one whose records went (`RECORD_BUDGET`) are not; nor is one whose proven things, by the rosters N holds now, have no proven role on S's thing (a node removed from an account, spec/sync-opens.md §3: who a peer may be).
- **Held for keys no more**: a holder the grants of no thing the node closure reads name, directly or through holders held for keys (the last strong below it dropped, a grant on the way removed), is held for keys no more: its sync ID leaves the sync set by the timing of release, its key part goes as any thing's outside the node closure, and its secrets go by the lost-access rule (spec/permissions.md §3 Lost access).

## 4. Redeeming
- A node writing a link's join (spec/permissions.md §7 Redeem) writes, in the join's transaction, strongs to K and to the link's target in the joiner's `holds.0`, each unless the node closure holds it already. Redeeming a public link (spec/wire.md §10) follows the sync ID of the target's independent (the target, or the independent the link names) and writes a strong to its target in the joiner's `holds.0` unless the node closure holds it, and nothing else, once the public's grant on the target's independent is held (its sync ID's role commits, read by the public entry): the joiner's sync unit then carries the target (§2 T's keys open; a dependent one by Dependent entry); importing a contact card is such a redeem.
- Nothing else makes a node hold a thing it is granted a role on: syncing it is the holder's own choice, a strong.

## 5. Source
- A link's sync ID is in the redeemer's sync set, read, while it redeems the link (from the link text until a held `sync.0` records it, spec/sync-inbox.md §6), whatever it holds of K; a public link's (its target's) likewise, until its strong is written.
- A node MAY read and write an independent thing, with its sync unit, through another node it is a client of (its source, spec/sync-transport.md §6).
- A thing of a sync unit sourced at another node is read and written there, whatever else holds it; the copy this node holds never answers.
- **The node thing is never sourced away**: it is never cut from the sync set.
- **Sourced away**: the sync set's walk takes no path through a thing sourced at another node, so the thing and what the walk reaches only through it leave the sync set, each sync ID by the timing of release (§3). They stay in the node closure: nothing of them is released, and the node holds the copy it had. Cost: the move costs work in proportion to what is below the thing; while it is away, a change costs as §2 says, never a walk of what is below it.
- **Moving back**: the thing syncs here again and stays read at its source until history is complete here (spec/sync-status.md §3) for it and each thing the sync set holds through it: each read sync ID of the sync set carrying one of them has had a complete pass (with none, at once). Then it is read here.
- A write on a sourced thing is refused while a sync unit holding it (spec/sync-judgement.md §1) syncs here or is sourced at a second other node (one other than the source the write goes to).
