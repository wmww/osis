# Reference graph tests
> Summary: The test plan for issues/reference-graph.md (Execution step 6): 38 properties in what users observe, the cheapest test of each with its crate and lane, which are written (Written: parts 1 and 2, repros of findings, not written), and the sync differential and sims against held-model `closure`.

## Layers
Each rule is tested at the lowest layer that shows it: engine facade or plain-value first, a sync world only where crossing nodes is the point (per test: engine `it` facade about 0.1 CPU-s, osis `it` 0.3-1, a sync world test 1-7, a differential seed about 9, a sim seed about 6). The debug index check (notes/test-harnesses.md, Debug checks) is the incremental-against-from-scratch oracle of the closure structure: `Core::same_index` compares the node closure's spanning edges and the reference index, so every test checks P5 of notes/closure-model.md and no separate P5 property is written.

## Properties
Lane: (a) refs, tickets as values, schema, API, index; (b) node root, walk, sync units, release; (c) `@` signals, inbox, tickets in sync, notices. Crate: `engine` = core/engine/tests/it, `osis` = core/osis/tests/it, `sync` = core/sync/tests/it (world tests on copied fixtures), `base`, `schema`, `vectors`.

## Differential and sim set
osis-sync `differential::histories_hold_their_closure`, `sims::`, harness `history.rs` (`Model`, `excused`, `check`). held-model `spec_closure`'s 24 tests are the oracle's self-checks.
- **World**: `history::world_of(seed, accounts, nodes)`: one node per account, every account every other's contact by card redeem (`introduce`), then a node paired to each account in turn.
- **Steps**: `New` (under the account root) and `NewIn` (under a thing, its first admin), `Write`, `Give` (sync/read/write to an account or a thing: chains), `Lower`, `Revoke`, `Rotate` (a writer), `Strong`/`Unstrong` (from the account root, an accept, or from a thing, to any history thing), `Pair` (from any node of an account), and the faults (power, partitions, loss, disk faults, skew). Declining is drawing no accept. `Grant` (give, then accept) and `Remove` stay as rule tests' shorthands.
- **Model, from the history and the reference alone**: things 0..A accounts, A..2A their roots, then the history's; kinds keyed once a grant or rotation applied (a plain thing derives from its nearest keyed first admin); grants from the reference's rosters plus each thing's first admin as admin and each account admin of its root; strongs from the reference's `holds.0`. Per account a `NodeView`: its root, open by keys; a ticket per thing given the account directly, at the lower of the best role given and the account's role at the end by chains starting at a thing the node closure reaches by strongs (`hc::World::roles_from_reached`: a grant naming the account is taken only at a strong to its thing, spec/sync-inbox.md §5 Nothing before the strong), so open, sync-only or none; the least fixpoint over what the closure reaches. Tickets are where the grant's fire puts them (the inbox, always held) and D's copies: no generated step writes a ticket elsewhere.
- **Gone things** (`Made::gone`, `history::note_gone`): at each run with every node on, no partition, loss or liar, a history thing no account's model closure holds is held by no node, so gone for good (spec/sync-set.md §3): the model drops strongs into it from then on. Judged on an incremental reference fed what was handed (`Quiet`), from the history alone.
- **Compared at quiet** (every node on, healed, run): per node and history thing, a value read exactly when the model reads it (a keyed thing in `read`; a plain thing held and opened by the node's keys or a read unit's), then value and roster as the reference; per keyed thing the sync set's holding (read, unread, none) as the model's, but a node keeping a thing unread may still list it after its removal (it cannot read the removal: it stops, entries dropped, path kept, spec/sync-judgement.md §6); no store entry under a keyed thing's sync ID the model has neither read nor stored; some node holds a body of each still-held thing's value; no kept entry of a body judged invalid; quiet within `STORM_CAP`; every fourth seed plays twice with identical traces.
- **Excuse** (spec/permissions.md §3 Left out): from `Made::know`, the events each node surely received (its own, unioned across nodes sharing a run on a clean network); permitted only when the account's last grant and a change of read keys are concurrent by it and no boxed account holds write or above at the end. The thing's maker's account is always boxed and admin, so it never fires in these histories: a left-out holder is always re-sealed.
- **Size** (`history::size`): small 3 nodes, 2 accounts, 30 steps, 6 seeds, odd seeds faulted; `OSIS_FULL=1` 4, 3, 60, 100. `OSIS_SYNC_SEED`/`OSIS_SYNC_SEEDS` pick seeds; `OSIS_SYNC_SHRINK=1` shrinks.
- **Sims** (a seed per variant drawn by seed at small size, at least 2: `a_peer_refusing_role_entries` 4, `store_failures` 3; 40 large; three accounts, thing 0 written by 0 and 1, kept unread by 2; the oracle plus the outcome): `a_reader_through_a_node_keeping_it_unread`, `crashes_and_restarts_in_place` (with a grant across crashes), `lost_and_repeated_messages` (a peer holding requests open on odd seeds), `a_peer_refusing_role_entries` (refusing roles, full, forgetting or withholding by seed), `store_failures` (skewed clocks by seed).
