# osis-perm: implementation
> Summary: The shape, invariants and reasons of osis-perm (the role timeline): its boundary, evaluation by components, the incremental paths (extend, append, shadow placement, new leaves) and what each rests on, point queries, saved walks, walk cost, self-removal attribution, the readings of spec/permissions.md §5.1 the code fixes (demotion scope, which writes carry a frontier), layer 2, sticky residue, trust sets, differentials. Where things live, per-step mechanics and test names are in the code (`walk.rs`, `cache.rs`, `cert.rs`, `content.rs`, `scope.rs`, `trust.rs`, each with a module comment).

Principle: **every fast path equals the from-scratch walk**: each incremental path declines back to it when exactness is in doubt, and debug builds compare them.

## Boundary and evaluation
- **Boundary**: perm parses no bytes, holds no state and depends on osis-base only. The node implements `HeldSet` (things, applied role commits with an edge write per thing, `created.0`) and adapts headers into `types` records; a `created.0` that does not hash to its tid is ignored. Value conversions of `edge` and `frontier` belong to osis-schema `core_types`. Every walk up creation records outside perm is `osis_base::record_chain`, capped at `MAX_CHAIN_DEPTH` (the engine judges writes on a too-deep thing invalid); perm follows record edges one at a time with no cap, since spec §1 defines effective role by paths.
- **Evaluation**: `Timeline::evaluate` is the from-scratch walk; queries take `At` (state before a point; `At::END` is the end of time, where re-grant is judged). `Timelines` splits the held set into components (things joined by edges, authors and records), each cached by its exact inputs; `changed()` lists the things whose component the last update evaluated, and the node re-judges only deltas on those whose inputs moved (`Changed::commits`, from `history_diff`; a debug assertion checks the rest is unchanged).

## Incremental paths
Debug builds compare every one with a from-scratch walk on inputs up to 400 commits (`Walked::check_scratch`), driven by one generator test (`incremental_equals_from_scratch`). Figures: issues/perm-eval-cost.md.
- *Extend* (a component that only gained role commits): the final walk rolls back to the earliest new commit p and goes on. D is kept in the order the final walks found it: drops found before the first one found by a write at or after p stay (every walk up to them saw only items before p); the rest are forgotten and the walk rolls back to the first write they dropped too.
- *Append* (every touched thing in a component, `created.0` unchanged, new commits whose author, holders and targets are in it or are new nodes): the component is neither re-partitioned nor gathered again. A new node can join because nothing it reaches is held yet, so no earlier audit met it. Each new commit is placed without walking where that is exact, else the walk resumes from it. Declined: a drop of D at or after it, a later item writing an edge it sets, two ops on one edge, its own audit dropping something new.
- *Which later items may read a placed write* is a static over-approximation: with (M, T) its edges, roles change only for what reaches some M on what some T reaches, and only up to the widest role among the edge's values before and after; so classes change only through an admin value or an invite, demotion thresholds only through write or more. With no such item the write's changes, undo entries and mark are spliced in directly.
- *Shadow placement*: a shadow pass walks the placed write, then each item that may read it; where every effect equals what the walk recorded, the write's own effects are spliced in; the first item that does otherwise makes the walk exact up to it. A re-judged item costs about 0.5 ms at 10^4, so past an eighth of a long rest (`SHADOW_SHARE`, 512 items or more) the write re-walks instead.
- *New leaves* (things only their `created.0` names, above a root whose component gained no commits) skip the re-partition and re-gather. A leaf's record edge is its only edge, so every node's role on it is its role on its first admin at every point: the leaf takes the first admin's demotion vectors (`alias_leaves`, top-down). Without aliasing, validity was order-dependent (a holder offline through a revoke took the item as a leaf after the demotion and kept no demotion on it), and a re-walk cost 0.4-1.9 s per new thing under a much-demoted team against about 40 ms. A late `created.0`, things below it and a new node join the same way. Declined: a record gone, a node gone that has no record, a new node first admin of a thing walked before, a record changed under its ID.
- *What an append changed* is read from what it did (`Timeline::appended`): the changes it placed, and when the walk went on, the history it rolled back over against the history now; no copy of the walk before. Placements splice in at the mark, so a write at the end of a long history moves flat work (`scale::role_history_arrival_moves_flat`).
- A record can grow under its commit ID (edge writes arriving late), so held records are compared with walked ones by content (frontiers by size), not by ID. Trusted components take none of these paths.

## Queries, saving and cost
- **Point queries** read an edge state kept every 32 history changes through an overlay of the changes since (`Edges` shares per-thing maps between clones until written: +60 MB peak on 12.9 GB at 10^4, against +1 GB with full copies). `first_held` (re-grant's start) replays the node's roles over the history, searching again only where a narrowed edge may have carried a role or an expiry; debug builds compare each answer with a full search (`Memo::first_held_checked`). Rejected: a static filter over edges on some path of the union of all edge states (in the org bench every holder reaches nearly everything through teams).
- **Saved walks** (`node/walks`, notes/engine-store.md Open): a component's whole walk is saved under its root with its inputs; a component with no timeline in memory is restored from a walk saved under any of its things whose inputs are a subset of its own and continued by one extend. Unit = BLAKE3 tag ‖ body; the tag covers a format string, the node's rules tag, the walk's whole input re-gathered from the held set and the body, so other rules, inputs or damaged bytes mean a from-scratch evaluation, never an error. Frontiers are tagged by size only (`HeldSet` documents that a record's frontier is fixed by its commit ID): hashing contents cost O(frontier) per save (48M IDs: 0.9 s). Saved when a component has at least `min` commits and grew by a quarter since its last save: amortized O(1) per commit (saving at every commit about tripled a commit's cost at 10^4).
- **Walk cost**: every state change logs its inverse with a mark per item, so a walk that grows D resumes at the first write D now skips. Per-node `roles_from` is cached across writes. `audit_fall` reads every candidate X's roles from one backward search per thing, or for at most `FORWARD_MAX` candidates from cached forward roles. Counted (perm `scale::`, an org of 311 nodes, 221 things): evaluate walks each commit once; a write after the history is placed walking nothing; a restored walk walks nothing, a continued one only what was added; a record chain walks each commit once at any depth; evaluating with drops restarts per drop (issues/perm-eval-cost.md).
- **Self-removal attribution** (`Attr::SelfRemoval(class, on)`): listed under (author, `on`), the holder for one through a holder, so a fall on that holder audits it; its frontier coverage reads the write's own target. A commit whose self-removal goes through a holder is not placed incrementally (rare).

## Readings of §5.1 the code fixes
The models follow them.
- "As if the holder still held the role" restores the edge to the join of its values since the last explicit write on it (plus, for a node that lowered it by its own write, that node's values before; a value already expired when written restores nothing), so a gap left by `until` or self-removal is finalized only by the next explicit write on that edge, not by any write concerning X (a per-node "held class" cross-wired things in the joint model).
- A's chain writes: the writer adds the commit IDs of `Timeline::certificates(A, target, R's point)` to the frontier (notes/certificates.md), and a frontier's commit IDs cover session-form writes too (`Frontier::covers`). The walk exempts nothing but R itself.
- **What R puts in question** (`Timeline::demotion_scope`) is read from the walk with R appended: R's audit can drop a write that held up another standing, so a scope from the walk without R loses honest writes. The writer (`Engine::demotion_frontier`) starts as if every held write were received (`Timeline::all_held`, no re-walk) and asks again until the answer is inside the frontier (usually two probes). An `until` expiring between the probe's `ts` and the commit's can widen R's fall past the scope: needless drops of received writes, convergent, not fixed.
- **Every explicit write that audits carries a frontier**, whatever call writes it (spec/permissions.md §5.1 step 4; `Engine::needs_frontier`, `Timeline::audits`): a write that takes something away is judged by what its author had received, and only explicit writes take; a grant is a put like a demotion to a lower role, so exempting grants from audits is no option. An `until` alive at R takes nothing, so it does not audit (else every timed grant would carry a frontier for nothing). The writer rule refusing an auditing write without one also catches an `until` passing between probe and commit: the write fails rather than drop every write of the holder's.
- A write whose holder is its target is no write; a record edge is written like any edge.
- Self-removal: lowers the grant, author admin of the holder, and either the holder is the author or the author has no edge-admin authority on the target (decided at review: removing one's holder actor from a doc one is also admin of by its record edge is an explicit demotion that audits that actor's admins); a redemption's is attributed `Invite(level)`.
- Frontier coverage of snapshots (spec/commits.md §5): a session range is covered when its last counter is (`>= hi - 1`), or when the snapshot lists no entry for the session.

## Layer 2, residue, trust
- **Layer 2** (`content.rs`): re-grant (role at `At::END`) validates writes from where the author first held the required role on the thing; else held at the commit's point and no later explicit demotion below the required role; else the frontier of any later such demotion decides; then the addenda (notes/addenda.md). Deliberate (decided at review): a write after `until` or a self-removal is invalid until the next explicit demotion, whose frontier then decides it. Role commits are commit form; the node voids overlapping session-form ranges on other aspects (engine `apply/atomic.rs`).
- **Sticky residue** (`common::residue`, used where a projection or another drop order may differ): a drop whose cause R is not, in the settled walk, an applied class fall of the dropped write's author X on its target N through the write's class. `Walked::falls` records a class fall only where X has an earlier held write on N: a function of the held set, never on a leaf, so not aliased by extend. Why residue exists: notes/role-timeline.md, Sticky drops leave residue.
- **Trust sets and disputes** (`trust.rs`; the rule, seeds, detection and costs: notes/disputes.md): an edge's "preceding value" is the last held op on it in point order, else its record value; `Timelines::set_trust` drops the components the old or new set names and evaluates them anew; such components take no incremental path, save or restore, and `demotion_scope` on one re-walks from scratch. Only osis-perm, the API layer and the store may name these (tools/policy.py).
- Differentials: joint and edges models agree exactly on 100k histories each; `trust_model_agrees` compares the walk under trust sets with the model's `trust::side` and a `Timelines` switched T, T', T with a fresh evaluation under T. Open: the model's library exposes walks and generators but no named scenario list; counterexample shrinking and quiescence checks are unbuilt.
