# whole-2b complaints
> Summary: Workflow notes from building one blob per commit (sections, prefix groups).

- A background `cargo build ... > $D/x.log` whose dir did not exist yet failed at once and reported exit 0 (the notes/build.md footgun, met again): make the dir in an earlier call.
- The design text (issue 2b bullets) said "one section per reader actor under the actor's read secret"; the first green run of the lower crates hid two bootstrap holes that only the node `it` tests showed (a plain group given secrets of its own, a key actor's card sealed by its person's device). Cost about an hour of debugging with an env-gated eprintln in `open_commit`; a per-crate test run of osis-node `sync_more:: deletion:: labeling::` (5 s) was the right loop, tier 1 (minutes) was not.
- `cargo test --workspace` on this box with the osis `it` binary failing 214 tests took 95 s before reaching osis-node: stop it and run the narrow filter when a systemic failure shows.
- Three more bootstrap holes surfaced one at a time, each by a different node test (a plain group given secrets of its own; an ephemeral owner chain whose records ride inside the section; a thing placed into a reading group from another actor's tree). Each needed a rule, not a fix: a worker cannot tell from the issue text which of these the design intended to cover. A short "who holds which secret when" table in the design note would have saved most of a day.
- The remaining red tests are all key-actor flows (links, recovery restore after pairing) exercised only by the osis and chat `it` suites, where a failure is "future did not resolve in N steps" with no diagnostics: a node-level repro had to be written by hand each time. A harness hook that prints the stuck node's pending commits and unopened entries on timeout would cut this.
- Takeover (second worker): the handover's red list was incomplete: `required::broken_delta_falls_alone` and `timed_dead::pending_commit_holds_back_no_own_upload` were red at the 2b commit already (checked with `tools/bin-at`), and the osis/chat red tests were green after the rebase onto main. Run tier 1 with `--no-fail-fast` before writing a handover's red list.
- The wip carried an env-toggled rule (`OSIS_NO_CREATION_COPY`) and env-gated eprintlns in nine files; an `OSIS_*` variable set by hand also trips `testenv`'s unknown-variable panic in the node harness tests, so toggling by env var "proved" 20 node tests depend on the rule. Toggle by editing the source, never by an `OSIS_*` env var.
- Five toggle experiments (node, osis and chat `it` each) took 25 min under load 25: a script running them in sequence in the background while reading code was the right shape.
- Review: `net.item(n, g, owner, ..)` with a key actor as owner makes a thing g's readers cannot read (its reader actor is the key actor); a test meant to read it at a group reader silently reads None. Use `g` as owner unless the edge is set.
- whole-2b fix: a hostile-host variant meant to fail without the fix passed twice for test-setup reasons (a live part on another thing still triggered the re-upload; keep-at-most 0 on `t:gone.0` stripped the blob to one group before the Replace). Check a new test against the disabled fix before trusting it.
- rv2: `negative::deletion_across_local_dating_no_churn` looked like the probe for "two holders whose must-hold differs", but once synced both date X's death alike; the skew at a keep-at-most bound was the real case (issues/kept-at-most-skew-churn.md).
