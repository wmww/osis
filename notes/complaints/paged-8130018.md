# paged-8130018
- A running `cargo test` (the 200-seed paged run, ~30 min) holds the build lock: tier 1 in the same worktree blocks until it ends. Run long seed ranges with the test binary itself (the path in cargo's `Running` line) to keep cargo free.
- The differential compared cached states only: the store had lost a creation in both worlds and the cache of the whole world hid it; the diff only showed up once streaming evicted pages. A reload of every state per step costs about 3x the tier-1 run, so tier 1 reloads after the last step only.
- My `timeout 60 cargo test --no-run` (to probe the lock) killed a build midway: later links failed with undefined `.llvm.*` symbols in osis-engine, then osis-node, then osis. Fixed by deleting `target/debug/incremental/{osis_engine,osis_node,osis,osis_sim,osis_cli,it,...}-*` and touching each crate's root file (deleting incremental alone does not rebuild). Never kill cargo mid-build.
- Review: re-taking the path from `f` assumed a page of the set was loaded; a touch with no dots (an add-and-remove commit: `W` only) loads none, so the fix wiped the creation. Any "take X from the joined state" needs the state to hold X's stored copy first.
