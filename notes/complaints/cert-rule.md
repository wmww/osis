# cert-rule complaints
- The sync world test of "two readers' stores converge" could not hold: a reader whose certificate wrap is blocked never logs nor pulls the copy (fixed on sync-rebuild by cert-bodies while this branch ran). Found only after adding store-equality to the test; read's acts are deduplicated per verdict, so a `log_own` that makes nothing is silent. A trace line for "log made nothing" would have saved several probe rebuilds.
- `Timelines::certificates`' `keys` holds only things with a record link, so accounts (key actors) never brought their `keys.0` or signing chain through `cert_parts`: the name ("actors whose current keys.0 goes along") reads broader than it is.
- The base moved twice under the branch (cert-bodies merged mid-task): two findings (an unlogged must-hold copy, histories_converge seed 16 failing when no node placed its own account's chain) were artefacts of the old base and went with a rebase; about an hour of probing. Rebase onto the integration branch before chasing a sync-world failure.
- (review) Finding why a memo key re-derives takes probing: `count_causes` names only the table type (`JSetMap<(Tid, Ak), ..>`), never the key read. A cause label carrying the key's Debug (when `costs::on()`) would have shown `current_keys(account)` in one run instead of four rebuilds.
