# net-3i2
> Summary: test net's `drop_link` drops the node's actions (a lost redial leaves a dial that never comes up); hint labels at peers that cannot read had no test before Open went; link redemption leaned on Open's speed.

- Test net `drop_link` (and so `set_online(false)`, `cut`-style helpers) handles the node's `Down` but throws its actions away: a redial it made is lost and the node keeps a connection that never comes up, so a node brought back online never dials that host again. Cost about an hour on `unread::a_peer_on_an_older_head_is_moved_by_any_reader_spec_sync_5` (tracing it with `OSIS_SYNC_TRACE`). Running the actions broke `leaving::` tests, so the harness is unchanged and the test avoids dropped links (`blocked` from the start).
- osis link redemption passed only because Open by static entry ran right after Hello, before the sharer's next step (which no longer lists the link key) reached the host; the filter path takes several round trips and loses that race.
- A label known by a hint (an inbox grant) at a peer that cannot read it was opened by Open in every test; nothing exercised the filter path for it, so its failure (the hint key not the head's epoch, the open ending on a head move) showed only as six unrelated-looking `inbox_life` failures.
- The serving session's flow-control tests used Path pages as their big reply; with Path gone only Pings and Status are left, so `pipelined_replies_bounded` needs about 3 M Pings (fast, but the bound it checks is now hard to reach by any honest request).
- The handoff's diagnosis of the link failures (a step right after the link was made not listing the link key) was wrong: every failing assertion was a used or revoked link expecting a clear refusal, and live link keys are listed at every step. Printing `readers` and the box holders at each `issue_step` found it in minutes; check the failing line before trusting a cause in a bullet.
- `sim-sweep` single seeds (`--seeds 1 --from N --setup 0 --only X --jobs 1`) with a targeted `eprintln!` were the fastest way into `member_churn`: the failures were two different causes (a forked `label.0` tree, a claim-opened head moving twice) behind one diagnostic.
- `git checkout <file>` to drop a debug edit also dropped uncommitted real edits in the same file (cost a confusing build error and a rerun). Commit a wip before adding throwaway prints, and remove prints by pattern, not by checkout.
- member_churn's failures moved with every fix (a third patch in the same state machine): the open-at-a-peer-that-cannot-read state needs a class study; a 60-seed sweep against main's 60 seeds is what showed it, 15 seeds alone looked green.
- `hub_loop::clients_end_to_end` failed once under load: the hub session learnt a Hit's open (`Down::Open`) after the Shared answer went, so the tester's Delete could arrive first. Fixed by telling the hub before the answer; not reproducible by rerunning, so watch it in the gate.
- The label-state redesign's regression test took about ten probe rounds: in the test net a granted node also reads L through co-reader peers (needs `blocked_peers`), gets a rotation's new sync secret by an inbox resend (so it opens by sync key, not claim), and catches up on `label.0` as soon as its stream flows (needs `held_to` then `hide_blobs`); each masked the stuck state. `inbox_life::open_at` and `moved_unheard` now do the stepping and the unheard move.
- A/B against the pre-change code without a second worktree: `git checkout <old> -- core/node/src`, apply a scripted debug patch, run the one test, `git checkout HEAD -- core/node/src` (tests and the wip commit untouched). Cheap, about 45 s a build.
- Two admins' concurrent child steps (one refused 9 after its open ended) could not be made deterministic in the test net: only the sim reaches it (`member_churn` setup 0 seed 51).
- (review) The Open walk's notes survived in notes/label-access.md (In node sync), notes/sync-protocol.md (Path pages, `StopPath`), notes/testing.md and doc comments; the remnant grep in the bullet covered names, not prose like "an Open" or "Path page". Grep prose too.
- (review) `hub_loop::clients_end_to_end` failed again in a loaded run after that fix: the node Pulls L from each client right after the Hit's answer; read in the same batch, the test's `peer` loop dropped it, read apart it landed among the Delete's events and broke `[DeleteStatus]`. The Delete was taken; the assertion now ignores node-kind messages. Printing the events after the awaited answer found it at once.
