# one-peer-3h1
> Summary: Footguns met building 3h1's first pieces.

- Three test harnesses (osis-node `Net`, sim `World`, sim `NetSim`) each build hosts their own way; making hosts nodes meant three separate plumbings of node sync above a hub. One shared helper for "a node's hub with node sync above it" would have made it one change.
- `hub_store_on` admits nothing by default, `HostStore::open` admits everything: a test host built on the former silently refused every label (all deletion tests failed with no diagnostic pointing at admission).
- Piping `cargo test` through `grep | head` in a background task cut the output mid-list and reported exit 0; write to a log file and grep it after.
- Review: a test playing a listener by hand against a node's dial needs a fresh address key: `follow` to a host the node is already connected to reuses the connection and dials nothing.
- Debugging the shared set across three node roles in an osis `World` test meant ad-hoc `eprintln!` behind an env var; no per-connection trace of Offers and their answers exists.
- Every node in an osis/sim test prints into one stderr: debug lines need the `SyncEngine` pointer to tell nodes apart, and ConnIds repeat across nodes (conn 1 at every node), which misled a first read.
- Comparing pass counts with main meant checking main out in the worktree and rebuilding osis-node twice (about 3 min each); a per-pass "why dirty" counter in `PassStats` would make such diffs a test print.
- The sim sweep was never run on the wip branch before the hand-off: 38 failures at 15 seeds surfaced only at the end.
- A sim failure's "one more round changes" list printed every host change since the quiet began (heads of a label at two values), which reads as churn; the stuck node was only visible in the `busy` part.
- Attributing passes needed ad-hoc instrumentation (a thread-local "last event" printed at each pass); a `PassStats` cause per pass would make the scale test's per-pass reasons a print.
- The coordinator's guess for member_churn 4 (a superseded step's kept claim opening) was wrong: a peer answers Opened only at its head; tracing Open answers per try found two Opens in flight.
- By-hand networking: `sources::thin_client_over_quic` fails on main every run (issues/thin-client-quic-rotation.md); `sources::disconnecting_ends_a_wait_on_the_node` timed out once under load in the crate run, passes alone.
- Review rebase: main moved (a terminology commit) while the rebase ran; resolving the issue file by `checkout --ours` per commit also drops non-conflicting hunks from other commits, so the 3h1 status was rewritten by hand onto main's text.
- purge_falls_churn 670132555640: the reviewer's guess (`accept_head` keeping an old step's `open_key`) was wrong; the sim trace cuts every line at about 200 chars, so the Opened head and the Path answer needed `eprintln!` in `opened` and the host's filter generation to see. A per-connection log of what each Hit tested (key, in filter or not) would have shown it at once.
- Reproducing the race in osis-node needed a host tamper turning the Path's 8 into an empty PathReply: the harness can hold host-to-node bytes but cannot reorder a node's queued requests against another node's Register.
- Review: the issue called the paired-serving runtime test "flaky under load, passes alone every time"; a 50-run loop alone showed it stalls about 1 in 30 on the branch and never on main. Loop a real-time test alone against `tools/bin-at main` before calling it load flake.
- Runtime stall: two of the four node roles in the osis test share one account, so `engine.me()` tags in debug lines mixed Alice and her paired node; `engine.tid()` (the node) tells them apart. A loop with the probes on raised the stall rate from about 1 in 30 to about 1 in 7, which made it fast to catch.
- The storm of self-dials (a node dialing its own key about every 5 ms for a second, then stopping) cost no test failure, only slow passing runs; nothing counts dials per peer, so it showed only in a probe of Dial actions.
- The own-node redeem refusal's sim repro did not reproduce on this branch: the redeemer's two own nodes never connected in the sim World without a shared group; the node-level test reproduces it instead.
- Review: a regex rename of "box" (node sense) in comments hit every crypto-box comment too ("boxes the holder", "entry box"); the node sense needs hand edits, line by line.
- Review: a seed that hits the 200000-message cap takes 4-5 min alone in debug, so each bisect step costs a build plus that; the harness prints no count of what looped. A per-kind message count on the quiescence panic would point at the storm at once.
- Storm chase: each replay ran 4-6 min to the 200000-message cap (main's eph-churn-loop `SETTLE_ROUNDS` makes the same seed fail in 7 s; cherry-picked it to iterate). Tracing needed hand-made statics: `OSIS_*` variables not in testenv-known.txt panic the test, and `unsafe` (to set one) is forbidden, so a probe flag had to be a pub static in osis-node.
- Backtraces in the test profile name few frames (inlined), and file paths did not show either, so "who cleared this presence" needed reasoning from the call sites instead.
- The renamed-to-host identifiers from the last review: "host" is deprecated too; a reviewer renaming node words should check issues/deprecated-terms.md first.
- Fourth review: rebasing 34 branch commits over 38 of main's conflicted at the second commit; squashed to the reviewed tip and rebased once. Main's eph-invalid-parts rule lived in `memory_want`, which the branch deletes: the rebase merged cleanly and only `reader_flood_takes_no_cap` caught the lost rule.
- Fourth review: main moved 14 commits during the first gate (eph-churn-loop, eph-reverts-seed), so a second conflicted rebase and a second gate. Main's memory-lane fixes keep landing in functions this branch deletes (`memory_want`, `memory_reconcile_thing`, `sync_label`): each rebase has to port the rule by hand onto the stream.
