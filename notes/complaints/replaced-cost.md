# replaced-cost
- The paged harness's seed runner has a 600 CPU-s hang limit: timing seed 16 before a fix needs `OSIS_SEED_TIMEOUT_SECS` raised, else it is reported hung at 600 s with no total.
- No perf or gdb on the box: to see where a 20-minute run spends its CPU, `tools/cpuprof` must run it again from the start (samples are written only at exit), so start the profile alongside the timing run, not after it.
- The issue's profile blamed `first_deaths`' walk of later bodies; replacing it alone left seed 16 at the same 1550 CPU-s. Most of the cost was `deaths` dating every dead write eagerly through `date`, which streams the held snapshots once per dead write whose superseder's delta is invalid. A filtered `cpuprof --report` (FILTER: a function name) shows which caller holds the samples; inlined callers vanish from it, so filter on the callee and read its callers.
