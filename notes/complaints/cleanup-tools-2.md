# cleanup-tools-2
- tools/policy.py took 8.9 CPU-s per run (every commit and gate): per-line regex scans over 17 MB of sources, the same files read by several checks. Python's `re` scans fast only for a pattern that starts with a literal; a leading `\b` (or an alternation of `\b...` branches) makes it try every position, 10-50x slower. Write `X(?<!\wX)` or prefilter with the pattern minus its `\b`s (`has` in tools/rustsrc.py).
- policy.py, dead_pub.py and doc_refs.py have no tests of their own; checking a rewrite meant a throwaway repo copy with planted violations, old vs new output compared.
- Review: policy_test.py, as the first plant of the env check, failed itself: env_vars scans tools/*.py, so a test naming a planted `OSIS_*` variable is counted. It splits the names (`"OSIS" + "_"`, `OSIS[_]`).
- policy_test.py adds 3 s to the instant checks (9 CPU-s / 11 s wall in the review gate, already past gate.checks' 3 u wall share before it); every gate wall share is spoken for (129 of 130 u, 1 u kept for the steps between), so the hit stays until issues/gate-five-minutes.md rebalances the shares.
