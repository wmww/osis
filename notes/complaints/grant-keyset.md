# grant-keyset
- `gen-vectors -- corpus` rewrote 14 unrelated fuzz seeds (box, proto_frame, step: random bytes per run) besides the schema_dsl ones the change needed; had to restore them by hand. The corpus generator is not deterministic for those targets.
- `timeout 600 core/test/tla/run.sh small | tail` lost the whole output when the timeout hit at load 40 (run.sh small took 12 min, not "about a minute"); write it to a log instead.
- The judgment vectors change for any schema change (bundle bytes and `read=` hashes), not only for judgment changes: checking "did judgments change" needs a hash-normalized diff of the verdict lines.
- Gate took 1074 s at load 50+ (mostly the post-rebase rebuild and tier 1).
- (review) The perm tier-2 command at load 30-50 took 470 s wall (221 s in the one test binary that runs anything; the rest is building/launching 15 binaries that filter everything out).
- (fable round) `send_skipping(from, to, {})` re-sends every package of `from`, so a test that keeps one part withheld must pass the skip set on every later delivery too; one new test first passed for the wrong reason (the grant arrived whole). Worth a helper that remembers a peer's withheld set.
- (fable round) After a rebase that conflicted on the judgment vectors (taken from main, meaning to regenerate), `gen-vectors` left them stale: the judgment vectors are written by `cargo test -p osis-node --test it -- --ignored judgment_vectors_write`, not by gen-vectors; one gate run (15 min at load 30) lost to that. notes/build.md could say so next to the gen-vectors line.
- (fable round) A branch's rotation `_large` run (`rotation::tests:: -- --ignored`) also runs the ignored repros, which fail by design; use `--skip repro_`.
- (review 2) A crafted commit by a peer that holds nothing of the target thing fails `commit` with "own commit not applicable" (parked: no creation record); give the attacker peer the thing's state first (`send_skipping` from a peer whose view you want it to share).
- (review 2) `git rebase main` conflicted on the generated `core/schema/tests/gen/core.rs` and `core/test/vectors/schema/core.vec`; resolution is take either side and regenerate (`OSIS_REGEN_VECTORS=1 cargo test -p osis-schema --test it codegen`, `gen-vectors`), which notes/build.md says only under Scripted renames.
- (rebase onto main, 81 commits) Every intermediate commit's generated files were taken from main and regenerated once in the regen commit; `gen-vectors -- corpus` again rewrote unrelated box/commit_header/inbox/proto_frame/step seeds (restored). Two new main tests built `ct::Edge` literals and needed `keyset: None`.
