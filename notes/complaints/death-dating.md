# death-dating
- An engine-only rebuild (`cargo build -p osis-engine`) took 4 min at load 40; the node test binary another 4-5 min per iteration. Instrumenting (an env-gated `eprintln!`) cost two such rounds; the first round printed nothing because the path I suspected (the replay) never ran: the dates came from the incremental path. Print at both before suspecting one.
- The order harnesses refuse unknown `OSIS_*` variables (core/base/testenv-known.txt): an ad-hoc `OSIS_DEBUG_*` probe variable fails the run before any test; name probes without the prefix.
- A test that passes on both binaries proves nothing: my first frontier-credit pin passed on main because the snapshot carried no kept write and so kept no deaths; a second because the overwrite created a fresh record. Check the fix-disabled run before trusting the shape (`tools/bin-at --patch` builds main with the new test in a few minutes).
- Review: an `eprintln!` probe inside a `run_seeds` harness prints nothing without `--nocapture` (libtest captures passing tests), so a "0 hits" probe looked like an unreachable check until rerun.
