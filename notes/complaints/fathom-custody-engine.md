# fathom-custody-engine
- `Engine::run` rolled back (an ingest trial) restores the store but not every in-memory map (`Core::accounts` kept a seed taken in the trial): custody keys off the store record to stay right. A trap for anything caching secrets in `Core`.
- Pairing becoming a rotation shifted every account test's base epoch (FIRST_EPOCH assumptions in tests_signing, tests_forks, flows): a `setup_head` helper and a seed hand-over test helper (`keep_seeds`) absorb it.
- osis-sync sibling tests depend on joiner-target (plain rotations revoking at outsiders); couldn't land green alone.
- Rebasing the 4 branch commits onto joiner-target conflicted per commit; squashing them on their old base first (`merge --squash`) made it one conflict pass.
- osis-sync failures after a design change are slow to diagnose: no per-node "why did it dial / refuse / re-seal" log; I added throwaway eprintlns each time (dial `Why`, store refusal reason, reseal candidates). A traced reason per act in `OSIS_SYNC_TRACE` would save hours.
- Phase 1 finish: osis-sync failures took most of the time again: four were unrelated to the re-seal (a rebase onto a moved main, a derived-epoch restart, `core.me()` vs `core.member()`); diagnosing each needed throwaway eprintlns in engine and sync (no per-node "why re-seal / why refuse / why not dial" trace).
- `Mutation::set` of an unchanged value writes nothing (`commit_tx` returns `None`): a re-put meant as a carrier silently makes no commit.
- `LocalPeer` packages hand parts over in the clear, so an engine test of "can it open" must check held secrets, not reads.
- Phase 2 outgrew a session: D's roster as edges on D is read across engine, sync and osis (role_now/roster/key_holders of nodes on D, own_node, card ends, pairing checks, ~60 engine tests built on separate removal commits). A grep list of every D-role read before starting would have sized it.
- `wt claim` of an existing branch landed on a stale local copy (pre-rebase history, 62 commits behind its pushed tip): a branch pushed under another ID needs `git reset --hard origin/<branch>` after the claim; nothing warns.
- Phase 3: `refresh_epochs` building the account view to derive merge seeds at its top broke the "an open builds no chain" invariant in ~800 tests at once; anything done per account belongs inside its per-account loop.
- Phase 4: an engine panic inside a sampled `check_index` (a rebuild mismatch) carries no context of the run that led there; the differential's `CUSTODY_TRACE` / `CUSTODY_PROBE` hooks (print every act and item, check the index after every delivery) found the late-named box in minutes. A debug `want`/`got` legend in the mismatch message (which is live, which rebuilt) would have saved an hour.
- Phase 4: heavy-lock waits of several minutes for a single 64-seed run when another branch's gate held it.
