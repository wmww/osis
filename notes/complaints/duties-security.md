# duties-security
- A test of an account fork through sync ran into a separate bug first (a sibling's concurrent rotation never opens: issues/sync-sibling-rotation-unopened.md); an hour of tracing before the duty itself could be tested. `OSIS_SYNC_TRACE` shows `+entry` without `+commit` for an entry that stays NotOpen, but nothing says why; a trace line for NotOpen would have saved most of it.
- `passes_wanted` counts a pass begun at the same engine ms as a role commit's arrival as after it (`began >= since`): in a World, where the clock stands between steps, a commit arriving in the ms a pass was noted wants no pass at all. Tests need `w.advance(1)`; in the product a Pull sent before the commit in the same ms ends a pass that counts (spec/permissions.md §3: it must not). Not fixed here.
- A drop that reloads the engine mid-settle (lost access, `removal_done`, `forget_local`) leaves the rest of that settle on stale memo feeds; restarting modules on every reload broke unsyncing (its forget reloads too), so only the lost-access step restarts them.
