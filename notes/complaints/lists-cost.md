# lists-cost
- The brief said every commit at a sync ID re-ran the lists check; measured (cert-blob settles over the outsider fixture), a plain write settled nothing. What did cost was each role change: ~30 settles of the whole per-S effect (closure walk, every rotation's wrap check, every own cert blob's store row) per node removal. Measure before trusting a review's cost claim.
- The sync harness's `Rotate` step rotates a thing, which writes no thing lists; an account rotation needs a node removal, so counting list work at n rotations is only cheap inside the engine (`rotate_in` with `also`).
- `costs::take` counts nothing unless the probe test calls it before the measured step on the same thread; a first probe that printed `[]` looked like "no work" until checked against a step known to do some.
- (review) An equality test against a whole derivation that shares the incremental code's derivation function (`carried_lists`) catches only placement bugs, never derivation bugs: mutating the function changes both sides. The random histories also held no thing lists at all until an account-rotation step was added; check a mutation fails a test before trusting the test.
- (review) The cost was never the read-things fold: it was a second `Effects` key over the sync set, whose `due()` scans the read log of everything the sync set read at every follow. A memo shared between the two keys left the cost as it was (each key still records the memo's whole dependency set); taking the read things from certified's set by its feed did it. A `follow_certificates` called twice per `Engine::follow` also costs: `due()` is not free when nothing moved.
