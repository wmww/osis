# eph-lane
> Summary: worktree wiped mid-task; the ephemeral suite's no-quiescence tests take minutes to fail.

- My worktree `.worktrees/wt4` (and the tmpfs scratchpad) was deleted from under me while step C was uncommitted: every `.worktrees/wt*` but a fresh one was gone, `git worktree list` showed them prunable. Lost about two hours of edits; replayed them from the transcript into a fresh `wt claim`. Commit a wip early and often in long tasks; whoever cleans worktrees should check `git worktree list` for claimed ones first.
- A sync bug that loops (a fetch/push echo, an immediate resend) fails the `Net` oracle only after 200 000 messages: several minutes per test, and the whole ephemeral suite runs for 10 minutes before reporting. A lower default (20 000) would have saved an hour; the message-kind histogram (`OSIS_SYNC_TRACE` plus `awk`) was the fastest way to see what looped.
- `OSIS_TRACE_UPLOADS` shows uploads only; there is no trace for fetches, deletes or ingest outcomes. I added and removed `eprintln!`s three times.
- A pass storm (a label re-dirtied by what its own pass wrote, here a snapshot forgotten at once) shows as one slow seed, no failure, and no diagnostic; the ephemeral suite ran 8 minutes before I noticed. Finding it took a backtrace print in `Core::mark_changed` filtered to `/core/` source lines (frame names were useless: everything inlines into `with_work`), and `--nocapture`, without which a passing test's `eprintln!`s never appear (I lost one run to that).
- The sim's `labels` check failed on "lacks body ... its entries []" for memory bodies; the entries were there. `SyncEngine::entries` had grown a `!e.memory` filter (mine, to keep a count test quiet), and the sim learns which blob holds which commit from that very call (`observe_node`), so no memory blob was ever "known" and the message hid the entries too. A test accessor that lies about what the node holds costs more than the test it quiets.
