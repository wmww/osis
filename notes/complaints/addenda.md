# addenda
- The brief named sections "Validation results", "Decided for the model" and "Decided after the model" of the issue; the first lived only on the unmerged `addenda-model` branch (as "Model results"), found by merging it first.
- Content parts are streamed, not decoded whole (`apply::Parts`): an index that reads a content delta's entries (addenda) must put its aspect in `whole_part`, which no note says; found by probing why a local addendum was judged invalid (its part list was empty).
- Inside the transaction that applies a removal the demoted thing's new delete keys are not usable yet (`framing_for` refuses a write with `Permission`) though they are after it commits; an addendum written in the epilogue has to wait for the next role or key change (`Core::addenda_wait`). No note says what becomes usable when.
- `cargo test --workspace` after the API change took three rounds to compile because of test-only `.await`s and `w.until(..)` wrappers spread over eight files; a grep for the removed calls before the first build would have saved two builds.
- Order oracles and hand-built removals (`common::set_edge` with a frontier) silently changed meaning once every writer answers removals: a node under test writing its own addenda is order-dependent by design. The knob `Engine::write_addenda(false)` is set by `order::play`/`fresh`, `common::net_off` and `set_edge` with a hand-built frontier; a test that wants witnesses leaves it on.
- Review: the branch's wip commits included drop-at-once and its revert, so `git rebase main` conflicted in code that no longer exists; squashing first (`git reset --soft $(git merge-base HEAD main)`) left only three notes conflicts.
- Review: tier-2 `scale::addenda_rejudge_cost_*` at N=10^5 in release spends most of its time filling 10^5 commits one `LocalPeer` commit at a time.
