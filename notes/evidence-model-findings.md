# Evidence model findings
> Summary: What held-model `evidence` says about evidence per sync ID (notes/write-path-design.md §2): lazy delivery, a lowering's list whole in every copy, readers judged against a reference holding every removal some honest node syncing their sync ID holds, the gap (a removed key's writes showing where no such node holds the removal) counted; the model's closure variants (`Variant`: (iv) holds everything), delivery stages compared by their gap, record edges in keys-open travel, J2 joins, entry creations, drops at once, verdicts final after a complete pass; the findings registry (numbers stable, cited from code), cost shape, generators, what the design takes from the model.

Model: core/test/held-model/src/evidence.rs, tests tests/it/spec_evidence.rs, README (held-model, Evidence). Judging is roles-model `paths` with `Rules::fixed` (the rule A1 builds).

## The rule as modelled (`Rule::fixed`, `Stage::A2`)
- **Required set of sync ID S over a held set H**: the evidence closure (`paths::evidence`) of these seeds: the bodies (H's commits on things of S's unit) and the grants naming S's thing as holder (with `keys_open`, Role changes travel's keys-open half: also those naming a thing S's keys open). The closure adds every held edge write on a seed's key hop and on an edge of its path (E1), and closes over what it adds. What lies on a thing outside the unit is a copy (per (commit, thing)), the rest bodies. A removal is in it only as evidence of a body (notes/write-path-design.md §2, D1) or by Role changes travel (D3): lazy delivery, nothing logged for its own sake.
- **A function of current holdings**: every honest node logs under each sync ID it syncs what its own view requires there now; what no syncing node's view requires leaves (a delete-key holder deletes it, a holder still requiring it logs it again). Nothing is kept for having once been required: a removal's copy leaves with the last body it judges.
- **Delivery**: a node syncs a sync ID and the sync ID of every thing in that unit; it holds what those carry and what it wrote; a writer syncs the thing it writes and its path's things. A granter logs a grant under its holder's sync ID. The thief logs its own bodies and the grants they rest on, read as if the lowerings it withholds were never written (finding 39).
- **Readers**: a reader holding one sync ID holds its entries; a lowering's list is in the lowering, so whoever holds it reads all of it (E4; `Lists::Unit`, a reader seeing its unit's entries only, is the control: finding 4).
- **The reference and the gap** (finding 38): a reader of S is judged against a node holding everything written but the lowerings taking something away that S lacks and no honest node syncing S holds (`World::reference`); where that node and the node holding everything differ is the gap (`World::gap`), counted.
- **Pending**: a commit pends while a hop it rests on (`paths::World::rests`: its key hop, then its path's edges; no record hop) has no held edge write ordered before it, or the latest such pends. Pending, joined and chained all read roles-model's `rests` and `paths::chained`: held-model keeps no copy of what a commit rests on.
- **Promoting** (`promotions`, `PromoteWhen`): a reader promotes (or a cover drops what it covers) on a valid body; `AfterPass` on S's whole entries, the control `WhenNothingPends` on any arrival where the body does not pend. A body judged invalid is dropped at once (spec/commits.md §5 Invalid), waiting for nothing.

**Delivery stages** (`Stage`, `Rule::keys_open`): Role changes travel's keys-open half (an edge write naming holder h a seed under each sync ID whose thing holds read or above on h through grants and record edges, any time: `ROLE_KEEP` read as for good) on or off; `Rule::records` (record edges in keys-open travel: on; off is the control, finding 21); the actor seed alone. Each over (iv)'s closure and judge, so the stages differ in delivery only, compared by their gap.

**The closure variants** (`Closure`, `Variant`, `Pend`; the engine's derivation takes E1, every edge write: notes/a2-spec/README.md Open 2): which edge-class commits the closure takes (`Takes`: all, chained, applied by the logging node's walk), whether a member brings its stated path's edges only where the path is **joined** (each non-record edge holds a chained grant ordered before it), and when a commit pends (`Pend::Any`: no held edge write ordered before on an edge; `Pend::Granted`: no held chained grant giving what the part needs on the hop (`Join::Needed`, finding 23), or the latest chained write pends). **Chained** (`World::chained`, roles-model `paths::chained`): self-removals and finalizes included (a superset of what any walk applies: P0). Every logging path takes the same closure: a node's view, a granter's delivery under the holder, the thief's own logs. **Entry creations** (`World::creations`, `CommitEdges`): an edge-class part pends while a part of its commit on its thing leaving its holder no grant resets an entry whose creation (the first grant on that edge before it chained over what was written before its commit: its writer names it, and knows no later write) is not held (finding 25); the closure brings every edge write's creation.

Choices where the design was open, each the smallest reading: "the closure over the paths" is `paths::evidence` (hop edges' writes of any validity, the named remaining admin edge, closed); records are static (record blobs not modelled; a record edge is changed by edge writes like any edge); a lowering the reference may excuse takes something away (`takes_away`: below admin at its `ts`, on a record edge or after a write on its edge giving more); which grants count where is not modelled (every grant counts); dependent things have no sync ID; unit membership is an input in time (the closure model checks the walk); role commits write one thing.

## Properties and results
Each a named check over every step of a world (`World::p1`..`p5_order`), the arrival-order check at the end, each against S's reference (finding 38):
- **P8** (`p8_promotions`) every promotion a reader takes agrees with its reference at that step.
- **P1** a one-sync-ID reader's verdict (pending, valid, invalid) on every body it should carry equals its reference (a body owed by an honest writer and absent fails too). **P2** a body under several sync IDs is judged alike under each whose references agree (else the gap at one); P1 at each implies it, so it has no check of its own. **P4** every honest entry S holds is in its reader's required set; forgetting each content body moves no other verdict and leaves no copy only it needed. **P5** retags and a holder raised later are moves of the worlds, checked by P1 at every step; arrival order: the reader missing any part of a body's evidence judges it as its reference without that part (locality).
- **P9** (`p9_leak`) no roster leak: every copy an honest node logs under S is on a thing whose roster gives a role on a thing of S's unit (`roster_reach`: joined to it by record edges and chained grants, at any time), or in the closure of the grants naming S's thing (Role changes travel: S's own roles). **P10** (`p10_junk`) junk costs nothing: no honest node logs under S an edge-class commit on a thing outside S's unit that is unchained over everything written. **P0** (`p0_applied_chained`) the model's own: every write the node holding everything applies is chained.
- **Worlds**: the family (`family`, 30,720 worlds: route [A] or [A, O], five unit timelines with D or O joining or leaving R's unit, listed or not, a thief, a re-grant, an addendum, a raise after the removal, K's grant to Z left unlisted, who syncs what, O apart from D's admin, record edges on the route: `Shape::mint`); random worlds of 14 moves (`random`); hand worlds per finding and risk.
- **The closure variants** (`spec_variants`, `spec_story`; P0 to P10): over a family slice and 100 random worlds (moves added: a member's edge write on A or O to any holder, junk where it holds no admin; content along [A, R] with A writing R half the time, R holding nothing on D, or [O, A]; X removing or re-granting two members in one commit) and 40 story seeds under the six unit crossings: (iv) holds everything; the draft fails P9 and P10 only; (ii) and (iii) fail P1, P2, P5, P8 (finding 13), (v) P9, (vi) P1 (finding 14). Property `evidence_along_joined_chained_paths_plain` (about 50 CPU-s) and `_large`.
- **Record edges** (`spec_reach` `records_*`): record edges in keys-open travel carry finding 19's removal to R; read through grants only (`OSIS_REACH_CONTROL=grants`), every stage has the gap there.
- **Lazy delivery** (`spec_reach`, `spec_gaps`; finding 38): every stage holds every property against its reference; the gap is where they differ. The design has it in findings 17's, 18's and 20's (raised) worlds; the actor seed alone adds finding 19's.
- **`Rule::fixed` and `Stage::A2` hold every property against the reference**: the default slice (every 291st family world), `_plain` (every 17th, 40 random: 1,848 worlds, 105 with the gap; `wide`: 12 worlds, none; story `_plain`: none failing) and `_large` (every 5th, 400 random: 6,544 worlds, 360 with the gap; `wide`: 240 worlds, 5 with the gap). Gate cost: the three `_plain` evidence properties about 48 CPU-s together.

Numbers are stable (code and notes cite them); a missing number is not reused.
1. **No honest node between the removal and the write is the gap** (`reach_with_no_honest_node_between_the_removal_is_the_gap_at_d`). World: X removes K from A; K writes D through [A, O]; O's admin W syncs O alone, D's admin Y syncs D and R, nobody honest syncs A with O or D. D's reader holds K's write and the grants it rests on but not the removal, and shows K's write valid where the node holding everything judges it invalid: the gap (38) at D under every stage.
2. **Copies are a function of current holdings, never placed once.** Placed when the commit needing them is logged and left alone (`Placement::AtLog`, the literal "logged with the commit that needs it"): (a) O on K's path is in R's unit when K's write is logged (A's grant on O a body, no copy) and leaves; the grant leaves R with O and R's reader pends on K's write for good; (b) a removal is no body of an enclosing unit, so placed with nothing it never reaches R: R's reader judges K's write valid; (c) copies outlive what needed them (P4). 6,272 family worlds fail. Fix (`Placement::Function`, the design's own words "a function of the commits U holds"): every honest holder logs what its view requires now.
3. **A raise after the removal is judged by current holdings** (the family's `raised` shapes). A reads D only when K is removed, so no unit lets K write; Y raises A to write later and the stolen K writes D. An honest node syncing A and D requires the removal under D once the raise and K's write are held; with none, D is in the gap.
4. **A copy carries its lowering's list whole** (`f4_a_reader_needs_the_leaf_of_each_evidence_copy`). K grants Z on A, Z writes D, X's removal of K lists the grant. A reader reading only the entries for its unit's things (`Lists::Unit`) reads the grant unlisted, drops it and judges Z's write invalid (roles-model finding 5, here through units); `Lists::Whole` holds (300 random worlds: 10 P1 failures under `Unit`).
5. **A verdict on partial evidence is provisional until a complete pass.** A reader holding K's write and K's grant but not a removal ordered before the write finds a setter on every edge, so nothing pends, and judges the write valid until the removal arrives. No rule over the held set alone tells this apart from complete evidence (1,334 such provisional verdicts over 300 random worlds); a missing edge write with no other setter pends. Judgement is local (the reader missing a part judges as the node holding everything but that part does: P5 holds), so the rule is: verdicts are final for a sync ID only after a complete pass of it (spec/sync-status.md §1), as must-not-hold already is; promotion of a deposit and anything shown as settled wait for it.
6. **A lowering is evidence of every commit its verdict reads, not only those it lists.** K writes c0 and c1 on D along [A]; X, having received c0 alone, removes K listing c0. Kept only with the commits it names, the removal leaves when c0 is covered and forgotten; c1, unnamed and invalid, then pends for good at D's reader, where the node holding everything judges it invalid (P4-forget). Kept while any commit resting on the lowered edge is held, in any order (a list is read for a commit stamped after its lowering too, roles-model `paths` `content`), it leaves with the last.
7. **Acting before a complete pass is reversed by what was lacking; after one, by a later write or by an earlier one whose delivery lagged (finding 33)** (`p8_*`). On finding 5's world a reader acting where nothing pends promotes the thief's write that the node holding everything judges invalid (`PromoteWhen::WhenNothingPends` fails); acting on S's whole entries never disagrees at any step of the family slice or the searches. A promotion after a complete pass is still reversed by a write made later (a removal written after it cuts the promoted write): every act is either undone by the rules or waits for a complete pass (spec/commits.md §4 Provisional), but the drop of a body judged invalid, which is at once (finding 12).
8. **The split form adds no evidence requirement across things** (`split_a_part_on_another_thing_adds_no_evidence_requirement`): K writes T1 along [A] and T2 along [B] in one commit, Y removes K from B: T1's sync ID requires nothing of B's edges and judges T1's part valid, T2's reader the other invalid, each as the node holding everything. A sync ID's evidence is computed from its bodies' parts on its own unit's things, whose path entries exactly its readers open (notes/path-form.md).
9. **A commit's edge writes on one thing apply together, so their evidence goes together** (`f9_a_removal_of_two_holders_waits_for_each_creation`, `World::creations`). X removes h1 and h2 from A in one commit C (several holders, one frontier, spec/commits.md §2); h1 writes D through [A] after C. D's evidence held (h1, A)'s writes, so C, but not h2's grant G2 on A, whose entry C resets; spec/permissions.md §2 has C apply none of its edge writes until that creation is held ("one whose creation the reader never gets never applies there"; engine `add_role_commit`), so D's reader never applies C and shows h1's write, which the node holding everything judges invalid, for good. Fix: an edge write in the set brings the creation of each entry its commit's parts on that thing reset (`CommitEdges::Creations`), or, as the draft words it, every edge write on each other edge its commit writes there (`AllWrites`, more copies); both hold, `Off` fails P1 (reader pending, the node holding everything invalid).
11. **The closure trusts stated paths and writes that never apply** (`f11_a_non_admin_of_a_path_thing_grows_the_evidence_with_writes_that_never_apply`: 3 and 30 junk grants, 27 more copies under D). Every edge write on a path edge is evidence whatever its validity, and its own stated path is closed over. (a) Cost: a writer of A without admin signs any number of edge writes on any edge (h, A) (none applies; role commits are kept whatever their validity, spec/permissions.md §6); every honest node holding them and the bodies of a thing written through (h, A) logs them there: the dependents' storage grows with what a non-admin of A writes, unbounded, and none of their writers or admins can stop it. (b) Confidentiality: a writer of D stating a path [M1, M2, A] through things an honest node U holds, where M2 holds no role on A, makes U copy the writes on (M1, M2) under D: a roster that gives no role on D, to D's readers. The README's induction ("each edge's holder holds a role on T") holds only where the stated path is joined. Modelled (`spec_variants`): the draft fails P10 (`variants_junk_*`: 27 more copies for 27 more junk grants, none under any chained closure) and P9 (`f11_a_stated_path_no_grant_joins_leaks_a_roster_unless_paths_must_be_joined`, and the random worlds' [A, R] path), each over the random and story worlds too. Fixed by (iv), with findings 13 to 15; the engine accepts both under E1 (notes/a2-spec/README.md Open 2).
12. **Dropping on a provisional invalid verdict can lose a valid write** (argued). X removes K (5) and grants it again (6); K writes c (7). A reader holding the removal but not the re-grant judges c invalid (a held edge write before c sets the edge, so nothing pends). Dropped at once, c leaves its own store; if every reader of D drops it on the same view and K's node is gone, c is gone where the node holding everything shows it, and "fetched where shown" has no source. Accepted (Tess, notes/write-path-design.md Decided): a drop is at once, as built (spec/commits.md §5 Invalid), nothing kept aside; a wait would only narrow the loss (finding 33).
13. **A chained closure needs pending on chained grants** (`f13_a_path_set_only_by_junk_waits_at_the_reader_where_the_draft_refuses`). Q writes D through [A] where (Q, A) holds only K's junk grant. The node holding everything holds an edge write on (Q, A) before the write, so under the draft's pending rule (any write) it judges the write invalid; a reader whose closure takes chained writes holds none there and pends: P1, and with it P2, P5, P8 (ii, iii: 8 and 9 of 111 worlds). The pending rule read a write no walk applies. Fix: a part pends while an edge of its path holds no held chained grant ordered before it, or the latest held chained edge write so ordered pends (`Pend::Granted`; A1's own "a removal leads nowhere"). Then the node holding everything pends too: a write no chained grant reaches waits wherever it is, as a write through a path nobody ever wrote on already does under the draft. Refused or waiting, nobody shows it.
14. **The closure cannot take applied writes only** (`f14_a_dropped_grant_is_read_by_the_regrant_so_applied_only_strands_a_write`; (vi), 7 to 9 family worlds of 111). The re-grant rule reads each edge's first chained grant, dropped or not (spec/permissions.md §5.2), so a write the walk does not apply is read by a verdict. Q (admin by X) grants K (g1); K writes D; X removes Q, dropping g1; X grants K again: the node holding everything counts K's path from g1 and shows the write, a closure without g1 pends it. Applied-ness is also non-monotone (a write applying over a set may not over a larger one, and the reverse), so a fixpoint "take a write iff it applies over the closure so far" has no stable meaning; chained-ness only grows with arrivals and is exactly what the walk reads of writes it does not apply. So chained is the least closure the walk admits.
15. **What a non-admin can still force under (iv)** (`f15_a_writers_finalizes_and_a_may_grant_holders_grants_are_chained_and_copied`). Chained writes include a writer's finalizes (chained by write on the target, spec/permissions.md §4) and a may-grant holder's grants (chained by its may-grant), and a holder thing's admins' self-removals: each is copied under every dependent whose bodies' paths use the edge, whether or not it ends or grants anything (27 more copies for 27 more). So the bound is: copies under S are the chained writes on edges S's bodies use; a party forces as many as it makes such writes: an admin any, a may-grant holder its grants, a writer finalizes, a holder's admin self-removals; a writer with neither admin nor a may-grant nothing else. Options: accept (a writer of t already grows t's own storage without bound; this extends it to dependents' copies on used edges), or a finalize chained by admin only (who may finalize: a spec change), or a finalize or a may-grant holder's grant evidence only where it can take effect (needs a rule over the edge's walk: not monotone, not modelled).
17. **Lazy delivery reaches no further than an honest node holding the removal** (`reach_with_no_honest_node_between_the_removal_is_the_gap_at_d`). A removal is logged under S only where an honest node holding it syncs S and its view requires it there: finding 1's world is the gap at D under every stage, and so is every world of this class (family, random, story and `wide` alike).
18. **A removed writer's other route is the gap** (`reach_a_removed_writers_other_route_is_the_gap_at_r`). Y grants K write on D directly and A write on D and R; K writes D directly (stated path [], no hop through A); X removes K from A; the stolen K writes R through [A]. X syncs A and D, Y syncs D and R, nobody honest syncs A and R. By stated paths D's evidence holds nothing of (K, A), so no node holding the removal holds R: the gap at R under every stage. The sampled worlds never reach it (a second route plus a bridge through the thing it reaches): the hand world is the evidence.
19. **Role changes travel's keys-open half carries removals to the things reading through the removed-from thing** (`reach_keys_open_travel_carries_a_removal_to_the_things_reading_through_it`). K writes R through [A, O, D]; Y removes O from D; the stolen K writes R again. Y syncs D and A, N syncs A and R, R's admin V syncs R alone. A reads through O, so the removal goes under A (Role changes travel) and N carries it to R. The actor seed alone fails P1 at R; keys-open travel holds. So keys-open travel is a seed of the required set (notes/a2-spec/README.md, Role changes travel).
20. **A removal through a read hop is the gap once it decides** (`gaps_a_removal_on_a_path_through_a_read_hop_is_the_gap_once_it_decides`; `wide` seed 14204407699, split and late). K writes O through [A], A holding only read on O, after X removed K from A; nobody honest syncs A and O. The write is invalid everywhere (no write reaches O through A), removal or not. Once a write grant joins A to O (at any time, backdated included) the removal decides K's write and no node holding it holds O: finding 17's class.
21. **Keys open through record edges** (`records_*`). A mint admin's keys open the thing it minted (spec/sync-set.md §2: effective role climbs record edges; a dependent's secrets derive from its mint admin's). Read through grants only, the model under-reads: finding 19's world with O minted by A fails P1 at R under every stage. Fix (`Rule::records`): a record edge is an admin edge from the mint admin to the thing, standing since the thing's creation and ordered before every write, in the read graph and the write graph, read at any time as grants are (a record edge lowered or removed later still counts, as a grant removed later does). Then every stage holds the world but the actor seed alone.
23. **A hop joins a part only by a grant giving what the part needs** (`Join`; `gaps_a_write_through_a_read_hop_pends_at_a_reader_lacking_the_read_grant`, `gaps_wide_worlds_reach_the_read_hop`; osis-engine `evidence::hand::f23_*`). World: the stolen K writes R through [A, O], A holding only read on O, O write on R; X, W and Y each sync their own thing alone and the thief withholds every grant giving below write. The node holding everything judges the write invalid (a hop holding a grant that gives too little: the walk, osis-perm `paths` `place`, walks the part and refuses it); R's reader, holding no grant on (A, O), pends (a hop holding no grant: the walk leaves the part inert). Three rules, each a switch read by joined paths and pending alike under (iv) (`World::join`, by hand `OSIS_EV_JOIN`):
    - **J1**, a hop joined by any held chained grant ordered before the part (the draft's (iv)): P1 fails at every stage, and P4-held (X's grant to K, which the thief logs under R, joins no path R's reader holds); `wide`'s read-hop move reaches it in about one world in eight. No closure rule closes it: the read grant is evidence wherever held, but only W and A's syncers hold it and none syncs R.
    - **J2**, a hop joined, and a part pending, only by a held chained grant giving what the part needs on that hop (`World::need`: write for content, admin for an edge write, write for a finalize, a may-grant grant's role on its path's hops before the last and as may-grant on the last; `until` disregarded; `Join::Needed`): the node holding everything waits too. Every property holds over the family, random, story and `wide` worlds (read-hop move included) against the reference. Cost: a write needing more than every grant on some hop of its path gives (a reader's content, a writer's edge write) waits at every node for good where it was refused, as one through a hop nobody granted already does under (iv) (finding 13); neither is shown. Finding 20's read-hop removal leaves the closure.
    - **J3**, joined as J1, a hop no held chained grant joins judged (invalid), never pending (`Join::Refused`): P1 holds in this world, P4-held fails there, and P1 fails in other `wide` worlds (a reader without a grant still on its way judges invalid what the node holding everything judges valid; one such is finding 26's world). Pending on a missing grant is what keeps a reader from judging on evidence it lacks.
    - **J4**, joined as J1 (the closure takes a path any grant joins), pending as J2 (`Join::PendNeeded`): P1 holds in this world, P4-held fails. Probed on the hand worlds only.
   The engine takes none of these: its derivation is E1 (every edge write on a stated path's edges), and a part pends on any held edge write (notes/a2-spec/README.md Open 2).
24. **A list entry names its commit's parts on its leaf's thing alone** (`gaps_a_list_entry_names_its_part_on_its_leafs_thing_alone`; `wide` seed 14204407701, split, late and mint). Z writes one commit in the split form, a part on D through [A, O] and a part on A directly; X removes Z from A listing the commit in D's leaf only (nothing checks what a list holds). roles-model `paths` reads an entry as naming every part of its commit, whatever leaf holds it (`World::in_leaves`: commit-wide, A1's single list), so the node holding everything, seeing D's leaf, keeps Z's part on A; A's reader holds no leaf of D (its leaf key is D's readers' alone) and drops it: P1 fails under the actor seed (keys-open travel puts a write on D under A by chance in the other stage). Only a per-thing reading is implementable by a reader holding one sync ID: a part on t is named only by t's leaf. Read so, every stage holds. The judge (roles-model `World::in_leaves`) and the walk (osis-perm `paths::List`, one leaf per thing) read lists so, held-model through the judge; the remover lists a commit in the leaf of each thing it has a part on resting on the lowered edge (the leaf form is not built: a removal's list is one set of commit IDs, each naming its commit's parts on every thing, spec/permissions.md §5.1 Frontier).
25. **Only a removal waits for the creation of the entry it resets** (`World::ends_grant`). The model's pending rule held every edge-class part back while a part of its commit on its thing reset an entry whose creation was not held, grants included; spec/permissions.md §2 waits only for a removal's (a write leaving its holder no grant: none, or `until` 0; a reset beside a put of a live grant is not waited for). `wide` (read-hop move, J2): W grants A read on O, later admin; the thief writes D through [A, O] and logs W's admin grant, withholding the read grant that created the entry the admin grant resets; D's reader pended on the admin grant where the node holding everything showed the write valid. With the spec's rule it holds; the closure still brings every edge write's creation (OPEN 13 (a)).
26. **A cut's list keeps a commit whatever its path's other edges gave** (found by J3 in `wide`, not fixed here). Q writes H through [A] after W removed A from H (listing nothing: the write came later); X then removes Q from A listing Q's write. roles-model `paths` (content: `cuts.iter().any(listed)`), osis-perm `paths` (`content.rs` `listed`) and spec/permissions.md §5.2 Content ("Otherwise it is valid iff the frontier of a cut of P below r lists its commit") make it valid: X's list revives a write W's earlier cut of another edge had already refused, so any later remover of a writer of A revives what A wrote through a thing it had lost. A list should keep a commit only from its own cut: valid where P gave r just before its key with that cut's edge read as before the cut, and no other cut ordered after it unlisted. Under J1 and J2 the world pends where no grant joins the cut hop, which hides it there; with a grant giving write before W's cut it was shown valid at every node. Settled in A1 (notes/path-model-findings.md 44): a cut's list answers that cut alone (roles-model `Answers::PerCut` in `fixed`, the walk's `stands`), so the write is invalid at every node.
31. **Role changes travel's keys-open half is still read** (notes/a3-spec/README.md Open 11). Read access through a holder thing reads it: a node reading X through T1 → H → X without syncing H learns of grants on (H, X) and their removals only from the copies under T1's sync ID (spec/sync-set.md §2 T's keys open; osis-sync `holding::a_removal_reaches_a_reader_opening_the_holder_through_a_second_thing_spec_permissions_4`). Fix: the half stays whole, for good (notes/a2-spec/README.md OPEN 15).
33. **A drop after a complete pass is wrong while an earlier-ordered removal lags** (argued). Q, made admin of A by X, removes K at 6 listing nothing; K's write c on D (2) is cut by it; K's node is gone. Q's pass logs the removal under D; a complete pass of D judges c invalid. X then removes Q at 5 (before Q's removal by key, so it is void): the node holding everything shows c valid; until X's removal reaches D, D's reader holds the void removal alone and drops c after a complete pass, and nobody else holds c. So finding 7's "after a complete pass, reversed only by a later write" is false wherever a removal's delivery lags (by a key rotation or a bridge, possibly never): a complete pass gives agreement with what S's sources held, not with every input written. Promotion stays undone by the rules (a promoted body judged invalid leaves the store); a drop of a body judged invalid and a delete at a store resting on a verdict (a cover whose writer an undelivered removal removed) are not: waiting for a pass narrows a delete's loss to "an earlier-ordered removal had not reached S's sources" (a drop is at once: finding 12). Stated: notes/a3-spec/README.md Open 12.
38. **Lazy delivery leaves the gap, counted against a reference** (`World::reference`, `World::gap`; issues/removed-key-writes-show-far.md; `spec_evidence::gap_*`). Under lazy delivery a removal reaches S only where a node holding it holds S (D1, D3). Each reader is judged against a node holding everything but the lowerings S lacks that no honest node syncing S holds; every property holds against it, and where it differs from the node holding everything is the gap: a removed key's writes shown valid where nothing holding the removal syncs. Controls (`_plain`): judged against the node holding everything, P1 fails in exactly the 105 gap worlds; honest nodes logging no removal copy (D1 off for copies) fail P1 in 1,286 of 1,848 worlds; the same with a reference excusing every lowering S lacks (held by a source or not) shows no P1 failure at all, so the source clause is what holds delivery to D1. A copy dropped under one sync ID only (the largest), or by one node only, fails P1, P5 or P8 with the gap unchanged: the first hop of a removal always has a source holding it as a body there. The slice's gap is a baseline (`p1_to_p8_hold_on_a_slice_of_the_family`): it may only shrink. The reference follows the rule's own delivery: a rule bringing less (keys-open travel off) shows as more gap, not as a failure, so delivery rules are compared by their gap. Counts: 105 of 1,848 `_plain` worlds, 360 of 6,544 `_large`, `wide` 0 of 12 and 5 of 240.
39. **The thief withholding a removal logs nothing only that removal brings** (found by `evidence_reach_and_generator_gaps_large`: `wide` seed 11, mint). X removes K and Q from A in one commit; the stolen K writes H through [A]. The thief's closure over its holdings brought the removal, and with it the creation of Q's entry it resets (finding 9); it logged that grant under H but not the removal, so H held an honest grant its reader requires for nothing (P4-held). The thief now reads its closure as if the lowerings it withholds were never written. A model fix (the honest rule is unchanged). A real thief may log that grant: junk a delete-key holder deletes, no verdict moved (every reference holds every grant); P4-held counts honest-written entries, not honestly logged ones.
40. **Keysets carry whole demotions; in the model they close no gap** (`World::rotate`, `Rule::keysets`, `p11_keysets`; notes/a3-spec/README.md Open 8; `spec_evidence::keysets_a_rotation_carries_the_demotions_its_writer_holds`). A rotation's keyset is a body on its thing carrying the demotions its writer holds applied, each whole; they are in the required set of every sync ID holding the keyset, and a keyset pends where one is missing (spec/crypto.md §4, Held keyset). P11 holds: every carried demotion the closure takes is in each such sync ID's entries and its reader's required set; a removal arrives with the keyset before any body needs it. Control (seed off): P1 (the keyset pending where the reference holds it valid), P11 and P5 fail in 4 of the 1,848 `_plain` worlds and 5 story-property worlds (10 carrying keysets among them). The gap is the same with and without keysets (105 `_plain` worlds): a writer rotating a thing syncs it, so one holding the demotion is already a source there (D1 brings it once a body needs it). Rotation reaches further only through nodes holding keys without syncing, which the model does not have: a member of the removed-from thing re-sealing a thing it writes at that thing's new keyset (spec/crypto.md §4 Carried).
41. **D4, the reader's deposit on sight, is simple; a third of what it closes rests on deposits nobody promotes** (`Rule::deposit`, `Node::stamps`; `spec_evidence::d4_a_reader_holding_the_removal_deposits_it_and_a_writer_promotes_it`, `d4_explore` by hand). A node logs under a sync ID only where it can stamp it (the family's nodes stamp their own things and what they write: Y syncing A and Q syncing R only read there); with D4 a node syncing S that cannot stamp it deposits the removal copies S's required set takes over its holdings, recomputed each round, so a copy leaves with the bodies it judges and nothing beyond E1 is kept. Stamping alone moves the gap from 48 to 105 `_plain` worlds (172 to 360 `_large`). Over the whole family and 400 random worlds: the gap in 1,716 worlds under D1 to D3, 840 with D4, no failure with D4. Of the 876 worlds D4 takes out of the gap, 624 have every deposit promoted (a node that can stamp S syncs it, holds the deposit and logs it: D1 by another node), 252 rest on a deposit no stamping node ever logs (5,456 worlds hold one somewhere): there the reader must judge by an unpromoted deposit and the depositor deposit again for as long as it syncs S, the two troubles write-path D4 names. So D4 needs a mechanism of its own exactly where a unit has no writer syncing it; its promoted form (a reader deposits, a writer syncing the unit promotes, readers judge only promoted entries) needs none and closes the 624.
42. **A write's key hop brings the edge writes on it** (E1; `spec_variants::e1_the_edge_writes_on_a_writes_key_hop_are_evidence_in_every_variant`). A commit signed by a key as a thing rests on its key hop (Keys K3), so the closure takes the edge writes on that hop with those on its path's edges. Bringing the path's edges alone leaves a reader holding a key's grant on a path thing without the list write that lists the key: it refuses the grant and the writes along it (P1), or, where a removal of the list write's writer drops it once held, judges valid, before that removal arrives, what its reference without the removal judges invalid (P5 order in story worlds: the stolen admin X adds a made-up key, the key removes H, H's later grant to N5 carries N5's addendum on T1; H's removal of X arriving last).
43. **A key hop no held write puts pends, never judges invalid** (notes/write-path-design.md §2 Pending, Hops; spec/commits.md §4 Unjudgeable; `spec_variants::a_key_hop_no_write_puts_pends_until_one_is_held`). A key signing as a thing whose record holds no key rests on a hop only a held edge write puts: without one the commit, and every write resting on it, pend; the grant is neither chained nor joined until the key's grant is held. A pending rule reading path edges alone (the control) judges them invalid on missing evidence. Reached only in story worlds (a minted thing's key signing): 576 of 1.9M verdicts in `evidence_along_joined_chained_paths_large` move from invalid to pending; every property holds both ways (reader and reference move together); the random families sign only by record keys.

Not found: re-grants reach every reader without travelling as removals do (`Scope::Edge` adds nothing in the family or the random worlds): the party they restore logs them (a re-granted writer's node holds the re-grant as evidence of its own writes). A world with the restored party gone and no honest node syncing both would need it; the design's "only removals travel at once" stands until such a world matters.

## Cost (P6)
- Under (iv) (`cost_copies_follow_path_edges_and_churn_never_writes`, `cost_with`): copies under D are the chained writes on the outside edges its bodies' paths use, flat in writes (path of k = 1 to 4 holder things, m outside: m copies at 3 and 30 writes), one more per re-grant on a used outside edge (churn inside the unit is bodies), and repeated under each sync ID whose unit carries D (D in c units, a path of 3 with 1 outside D's own unit: 1 + 3(c - 1)). The worst a non-admin forces: nothing but its finalizes and may-grant grants on used edges (finding 15); an admin: its own writes on used edges (`variants_an_admins_writes_on_a_used_edge_are_copies_in_every_variant`); the draft: anything any writer of a path thing signs on a used edge (finding 11).
- Copies under a sync ID are the edge writes on outside things of the paths its writes state, shared by every write: n writes along a path of k holder things, m outside the unit, hold m copies at n = 3 and at n = 30 (`p6_*`, `cost`); bodies grow by one per write. Copies grow with role churn on the used outside edges (every held edge write on such an edge is in the closure), never with writes.
- Against issues/many-sync-ids-cost.md ("about half a sync ID's entries are certificate copies": a root's rotation, the grant, two account chains, logged per member's sync ID): along stated paths a unit written by one signer through [A] holds one copy (the signer's grant on A) plus the changes to that edge, and nothing for rotations or chains. Against issues/zero-growth.md: copies are a function of commits held (P4), so releasing the commits releases the copies; repeated role changes on a used edge grow the copies, the accepted "growth with role changes".

## What the design takes from the model
- The required set as above, computed from the node's own holdings at every change (not at logging time), retag included: a thing leaving a unit turns the evidence still needed into copies, logged by any holder whose view requires them.
- A lowering's copy carries its list whole (E4).
- Verdicts final only after a complete pass of the sync ID; promotion and deletes at peers resting on a verdict wait for it (7).
- Evidence holds a commit's other edge writes on the same thing (9); every edge write goes, chained or not (11, E1); drops are at once (12).

## Generators
- **Minted things** (finding 21): the family's `Shape::mint` (0 grants only; 1 the hop after A a record edge: A mints O, or D with K writing through [A]; 2 a mint chain two deep: A mints O, O mints D, K's path climbing records past A; with `raised` the last record edge lowered to read and raised again by X, D's admin by descent), 30,720 shapes (default slices every 291st); `random` (a third of the worlds A mints O, half of those O mints D, the starting grants on record edges left out and the edge moves made by the thing's admin by descent); `wide` with `Wide::mint` (each of O, H, D, R minted by an earlier thing one time in three, mint chains up to four deep, routes along record edges, churn changing them).
- **Story worlds** (`story_world`, `spec_story`): roles-model `paths`' stolen-node story (`Sim`, its random worlds and family), its commits written in the order made by their signers' nodes (X's device, whose key the thief holds, dishonest), nodes syncing what the story's do, readers trusting the honest removals, under six unit crossings (`STORY_UNITS`: each alone; ORG, on T2's paths, in T2's unit; T1 and its dependent D1 in A's unit; ORG joining T2's unit after the removal; ORG leaving it; T1 leaving A2's unit), checked at the end of each tick. It brings: role commits along non-record paths (H's grants on D1 through [A, T1], B's removals through [A], X's through [A2]), the remaining admin edge and the last-admin rule (M's leave relying on B; X's self-removals and timed self-sets relying on H), may-grant grants (G through A2, RD2 by D1's flag) with finalizes and `until` (moves 40 to 42, 49 to 51, a timed admin), covers (K's, an unaware one, a backdated one by the thief) and purge requests by author, commits of several edge writes (move 43) and of several things (X's role write on T1 and T2), addenda on T1, T2 and D1 by the state-based rule, a dependent written by descent, two-hop paths. Over 40 seeds by six crossings: (iv) holds everything; the draft fails P10 only (the thief's junk copied by honest nodes). Under (ii) P1, P2, P5, P8 fail (finding 13): the worlds have teeth for the closure.
- **`wide`** (`Wide`, spec_gaps.rs): five things A, O, H, D, R each holding a random role on each later one, members granted directly on another thing (second routes), content mostly along written edges with paths of up to five things (four holder things), K removed and re-granted on any thing it has a route on, an admin's churn on every edge with random frontiers, junk edge writes on any thing, addenda, retags among the five, A granted read on a thing no honest node syncs together with the thing the thief then writes through it (finding 23's read hop: about one world in eight); options: split commits (parts on two things, each its own path) and late path entries (`World::opens`: a part's path unknown until its opener, a key commit on its thing, is held: it brings nothing and pends, everywhere alike; some never open). Sparse bridges (each node syncs another thing one chance in five), so delivery decides. With per-reader trust (`p1_trusting`, two random trust sets per world: P1 for a reader and a node holding everything trusting alike). Results over 240 worlds and the family slice, every stage: the only failures against the node holding everything are finding 17's class (P1, P3, P5, P8 together; P1 under each trust set exactly where P1 fails); no new class. So evidence carries no trust, a split part brings its own thing's evidence only, and a path entry opening late brings its evidence then (`gaps_*` hand worlds).
- **What is still not produced**, each with why:
  - Finding 18's shape (a removed writer's second route plus a bridge through the thing it reaches): `wide` has both parts but never together in the sampled worlds; the hand world stands for it.
  - Records that change: none in the built system (a thing's record and mint chain are fixed at its creation; destruction is a separate rule, spec/commits.md §5), so none modelled; record edges changed by edge writes are (the family's minted `raised` shapes, `wide`'s churn).
  - Finding 18's second-route shape and finding 19's keys-open shape with a record edge on the way: no sampled world reaches either for any stage; the `records_*` hand worlds stand for them.
  - Deletes at stores.
- Delivery rests on: every sync ID has an honest syncing node, a writer syncs what it writes and its path's things, a granter delivers under the holder's sync ID. A unit whose only writers are the thief is out of scope.
