# Decode bounds
> Summary: The one rule for memory on decode and read (what a node holds of an input is bounded by the bytes its author delivered for it, or by the reader's own bound, never by what the input names), the mechanism per input (`Limits::max_alloc`, the state read charge, a state's pieces read one at a time, groups of a body's pages for `covered`, header list keys and frontier IDs, coded peer filters, counted tree reach), and what is left.

**Rule.** What a node holds of an input is a decoder-set multiple of the bytes the input's author delivered for it (sent, or made the node store), or at most the reader's own bound for what it asked to read; never what the input names, claims or shares with other inputs. The decoder enforces it where it allocates; callers pick no numbers of their own. spec/wire.md §12 Memory states it.

## By input
| input | supplied by | decoded at | bound |
|---|---|---|---|
| a paged delta's link tree | writer | `codec::walk_tree` (both decoders) | one link list per level on the way down; each page fetched once (a blob linked twice is bad input), so depth and work are pages delivered |
| a value inside a blob or message | writer, peer | `osis_base::decode` and readers by shape | its bytes (`Limits::max_bytes`; at most about 56 B per byte; messages also 2^20 items) |
| a large value read whole | writer | `osis_blob::read_value` (engine `read_large_max`, osis `read_link`) | the reader's bound: canonical bytes, and as much again decoded (`Limits::max_alloc`) |
| an aspect's state, read whole or at a path | writers (as stored) | `Tx::load_lazy`, `pages::join_row` under `Tx::reading` | the reader's bound: each piece charged its bytes or decode, whichever is more (`pages::charge`) |
| an aspect's state, read for itself (presence for `aspects.0` and content, tree roots) | writers (as stored) | `Tx::each_piece`, `pages::each_piece` | a piece at a time: the skeleton, then a page with its keys' records; presence under the reader's bound |
| a body judged covered | writer | `retention::snapshot::covered_body` | a group of its pages about the two parts' root bytes, with its skeleton, and per write a dot |
| a commit's linked header lists | author | `Header::resolve` | the bytes of its own lists: a list's tree is keyed to its header (list key) |
| a demotion's frontier | signer | `osis_commit::frontier_ids` | its bytes: 32 B an ID held against 34 sent, one copy |
| the trees a thing's sources link | writers | `tree_refs::Reach` | what opens each counted link and its counts, about 350 B a link |
| a peer's filter | stranger | `Opens::beacons`, records load | its coding (`osis_proto::filter::Beacons`) |

- **`Limits::max_alloc`** (osis-base `cbor.rs`): the decoder charges each slot (`Value` per promised item), box (enum payload, link, ticket, unknown tag) and string before allocating it, and fails `TooLarge` past the bound; `check` charges alike, so it refuses exactly where `decode` does. Charges are never returned (an unknown tag's content, decoded and dropped, stays charged), so the charge bounds the peak. `decode_charged` returns the charge. Default unbounded: `max_bytes` bounds it. Test: `decode_allocates_within_its_bound_spec_wire_12` (the charge covers what the value holds, every hostile shape).
- **Link trees.** A paged position's link pages nest as deep as the array needs (spec/wire.md §6), with no depth constant: `walk_tree` keeps one link list per level reached (a page each), fetches each blob once and refuses leaves at two depths, so a chain of single-link pages costs a fetch and a page per level its author delivered, and a diamond or cycle stops at the second link to a blob. Test: `tests_review::hostile_link_trees_are_bounded_by_their_pages_spec_8` (a 10,000-deep chain fetches 10,001 pages, then the re-encode refuses it). The encoder holds a target's links or one open group per level (`codec::tests_levels`).
- **Whole reads.** `read_value` decodes with `max_alloc` = its byte bound, and a decode past it is `TooLarge` (local), not bad input. The osis read budget charges each link the greater of its canonical bytes and its decode, so one `read_limit` bounds a read over many links. One-byte unknown tags decode to about 36 B per byte: `a_value_read_whole_holds_at_most_its_bound_spec_wire_12` (osis-blob).
- **State reads.** A read through `Engine::get_within`/`get_at_within` (osis: the read limit) charges each piece of the state it loads, the unit, a body or a page, the greater of its stored bytes and its decode (`Fragment::approx_bytes`), refused before decoding a piece whose bytes exceed what is left, so it holds at most the bound plus one piece; past it `TooLarge` (local). The read leaves the cache about as it found it (`Tx::reading`). Ratio: a map of small entries holds about 100 times its value's bytes decoded (640 B by `approx_bytes`, about 1.9 KB allocated, per int entry), so the limit refuses its whole read near 1% of the limit in value bytes; a streamed read (value built page by page, never the state) would cost about the value, but needs every key's records across pages joined (the key index) and placements for sequences. Test: `api::a_whole_read_loads_at_most_its_bound_spec_wire_12` (osis: pages loaded before the refusal flat in the state's size).
- **State pieces.** A read of a state for itself, not for its value, walks it a piece at a time (`Tx::each_piece`, `pages::each_piece`), never joining a page into the cache: the skeleton, then each page below the skeleton's spine on its path (`Fragment::spine`: what pruning and an enum's case there depend on). Presence (`Tx::present_within`: `aspects.0`, `has_content`) stops at the first present piece: a state is present iff a write in it survives, and each piece holds what prunes its writes. Tree roots (`tree_refs::roots_of`) read each piece as the whole reads there: a page of a map or set also takes the records of its keys or values lying on other pages (`Fragment::key_records`, through the key index: a key reads as its records' join, a value's records hide each other). A collection paged inside another's elements reads whole for roots (a key's records then reach into pages below; rare). Each page and what it pulls is charged against what the read's bound leaves and dropped (peak: the skeleton, a page and its keys' records). This crate's tests compare every state's roots with the whole read's. Test: `tests_paged::internal_reads_hold_a_piece_at_a_time_spec_wire_12` (osis-engine), the listing in `api::a_whole_read_loads_at_most_its_bound_spec_wire_12`.
- **Covered.** `covered_body` streams the body once for its writes by dot (`CopyIndex`), value-less dots and stamps, then judges it against the snapshot's part at its positions in groups: its skeleton plus pages up to the two parts' root bytes (decoded), each group's check alone (positions join independently; the skeleton in every group holds where pages meet). A body fitting one group is read once. A body paged below a map entry is one group: `Fragment::positions_at` takes the snapshot's whole record there, so a group would meet every other group's writes. This crate's tests compare every snapshot cover with the whole-body oracle. Test: `internal_reads_hold_a_piece_at_a_time_spec_wire_12`.
- **Depth.** A value nests at most `MAX_VALUE_DEPTH` as read: a link counts as the value it reads as (`Value::deeper_than`: a leaf), the writer checks before chunking (`osis_crdt::out_of_profile`), and a read gives a link only the levels left at its position (`read_value`'s `room`; deeper: unreadable). Tests: `api::depth_counts_a_large_value_as_read_spec_data_model_5`, `a_large_value_reads_within_its_room_spec_data_model_5` (osis-blob).
- **Header lists.** Keyed by `kdf("header list", actor dedup, skeleton)`, the skeleton being the header's bytes with its linked positions `[]` (`Header::list_secret`; the writer computes it before linking, the reader from the decoded header). Two commits differing outside their lists key them apart, so no small commit can name another's 64 MiB list. A resolved list stays in `Meta` at about 5 B per byte (as inline lists do: the engine's commit indexes are in memory by design). Test: `a_linked_list_serves_its_own_commit_only_spec_wire_4` (osis-commit).
- **Frontiers.** Inline or linked, a frontier is exactly `{0: set<32-byte ID>}`, read straight into a sorted `Arc<[CommitId]>` (`frontier_ids`) that the header and the judging `osis_perm::Frontier` share: a 64 MiB frontier peaks at its bytes plus about as much again. The meta row keeps it encoded alike. Test: `flows::linked_frontier_spec_perm_5_1` (one copy).
- **Tree reach.** A counted link keeps no `Link`: its key is what opens it (blob, hash, key), a read node keeps what opens its links. About 350 B per counted link (both reaches, a 4-8 MiB value: 84 KB chunks; 800 B with a `Link` in each), within the rule's ratio; it grows with what is held, as the store does, until the thing goes or the node restarts. Test: `a_counted_reach_holds_little_per_chunk_spec_sync_7` (freed.rs).
- **Filters.** A peer's filter is held as Golomb-Rice runs, as on the wire, with an index point every `STRIDE` (64) entries; a run at least as long as the one before merges into it (at most log2 n + 1 runs, each entry recoded at most log2 n times). An arriving generation builds its run page by page, and its row is the run's bytes. About 1.3 B an entry against 8; per connection at most `MAX_FILTER_ENTRIES` whole plus as many added. Test: `opens::a_peers_filter_is_held_as_sent_spec_wire_11_2` (osis-sync).

## Rejected
- A format item cap on linked values (`MAX_PAGE_ITEMS`): an item count is not memory (a link holds five times an int), and the reader's own bound already caps it.
- Holding linked lists as bytes: saves about 5x and leaves the count of commits sharing one list unbounded.
