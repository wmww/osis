# Engine and node crates
> Summary: How osis-engine (`core/engine`) and osis-node (`core/node`) divide the node: the layering and the one engine-to-sync hook, transactions and rollback, the module map of both crates, and the engine's public surface by area. Index of the engine-* notes, which hold the rules of each area. Not here: node-sync's design (notes/sync.md), the API over it (notes/api.md, notes/api-implementation.md), ephemeral data (notes/ephemeral.md).

## Layering
- osis-engine (layer 7) is the node's local state: identity, clock, writing and reads, receiving and applying commits, validity, retention, undo, events, labeling, role flows and rotation. osis-node (layer 8) is `sync/`, the sans-I/O sync engine and its tokio driver, over the engine. osis-node re-exports the engine's modules and root items at the same paths (`osis_node::engine`, `osis_node::flows`, ...), so dependents name only `osis_node`; only osis-node depends on osis-engine (notes/architecture.md).
- The engine knows nothing of sync except one hook, `engine::SyncRecords`, which node-sync implements (`sync::state::Records`) and installs in `SyncEngine::new` (`Engine::set_sync_records`; kept across a reload). Its methods write or drop sync records inside engine transactions, so a crash between the engine's change and node-sync's never loses one: `note_unsent` (the inbox delivery a flow's commit owes, in that commit's transaction), `owe` (a flow's placement or direct send, recorded while owed), `forget` (the `y/` records of what `retention::forget` drops; returns the blobs no kept record names). An engine never wrapped writes and drops no sync records.
- The other direction: node-sync learns what to judge again from `Engine::take_changed` (`Core::changed`, kept only while a `SyncEngine` wraps the engine; notes/sync.md Work sets). It also reaches into `Engine::core` (`Core` is `#[doc(hidden)] pub`) and `Engine::run`; narrowing that to accessors is open.
- The persisted index's rules tag (`core/engine/build.rs`) hashes the sources of the engine and of every osis crate it depends on, not node-sync's: a sync change re-judges nothing at open (notes/engine-store.md).

## Transactions and rollback
- Synchronous, no I/O of its own, time from a `Clock`, randomness injected. Every mutating call runs in one store transaction (`Engine::run(|tx: &mut Tx| ..)`, `Tx { txn, core, rng }`); events go out after it is durable, outside locks.
- Every in-memory index is journaled (`engine::journal`: `JMap`, `JSet`, `JSetMap`, `JNested`; `Indexes`, whose commit and rollback the `indexes!` macro derives from its field list; `Groups` and the held set journal themselves). A failed transaction undoes its own changes newest first and evicts the states it wrote: O(changes), not a copy of every index. Perm's timelines follow the restored held set (`update_touched` around what the undo touched). A failed transaction that changed nothing keeps every derived cache (`Core::rollback` returns early; a debug assertion in `Engine::run` checks that no index changed without `touch`).
- `Core` (in memory, rebuilt by `apply::load` at open and after forgetting): the states cache with page indexes, `Core::ix` (the journaled indexes: each field documented in `engine/mod.rs`), perm's held set (`engine::held::Held`) and `Timelines`, pending reasons and kept waits, secrets, groups, caches for node-sync (`bodies`, `labels`, `live_trees`, ...). Invariant on the commit indexes (`by_aspect`, `by_thing`): they find commits, never decide anything alone, since any signer's header can list any aspect; what a thing has reads the state, and what a commit counts for reads its parts valid here (`Meta::valid_at`).

## Public surface (engine)
A map by area, not a full list (rustdoc has that).
- Lifecycle: `Engine::create(backend, root, Config, clock, rng)` (fresh identity; the node thing's `created.0` with `node.0`, then `keys.0`), `Engine::open(..)` (load, re-examine pending), `reload`, `tid`, `identity`, `now` (corrected clock), `set_clock_offset`, `subscribe`/`subscribe_durable() -> Receiver<Event>`, `register_schema`, `app_record`/`set_app_record` (the `u/` records the `osis` crate keeps), `report(diagnostic)` (deduped like the engine's own).
- Writing: `Mutation` (`create`, `persist`, `free`, `set`/`replace`/`remove_aspect`/`op` through any `RawKey`, `retention`, `expires`/`expires_all`, `purge`, `undo(target)`, `frontier`, `act_as`, `confine`, `sign_as`, `commit_form`, `require_synced`); `Engine::new_thing(&mut m, admin)`, `Engine::commit(m) -> Option<CommitId>` (notes/engine-apply.md, Writer side).
- Receiving: `ingest(bytes, blobs)` / `ingest_from(.., peer)` / `ingest_memory` -> `Ingested::{Applied, Duplicate, Pending(reason), Parked}`; `reexamine`, `set_syncing(tid, on)`, `tick` (expiry, keep-at-most, drift), `pending()`.
- Relaying: `commit_ids`, `header`, `commit_bytes`, `blob`, `package`.
- Reads: `get`, `get_at` (a paged state loads the pages on the path only), `get_range`, `get_full`, `read_large`, `read_large_max` (`TooLarge` past a bound), `next_chunk` (one chunk of a large value per call: the API's `stream`), `get_typed`, `part_value`, `aspects`, `groups_of`, `roster`, `role_on`, `state`, `has_content`, `all_aspects`, `first_admin`, `history`/`history_entry`/`watch_history`.
- Retention (node-sync judges deletions and re-snapshots from the commit index; no queue): `snapshot(tid, ak)`, `compaction_snapshot`, `covered(snapshot, body, tid, ak)`, `drop_body`, `body_keep`, `body_live`, `deaths`, `body_not_dropped` (true for a missing part too), `due_live_drops`, `defer_deaths`/`settle_deaths`, `suspects`, `state_digest`.
- Undo: `revert(id)` (an undo commit, spec/commits.md §7), `revert_batch`, `revert_as`; `held_commits(scope)` (held commits with header and per-aspect body-held, for the `osis` commit query; stacks, scopes and redo live there).
- Role inputs: `receipt(tid, ak)`, `frontier(scope, as_of)`, `epochs(actor)`.
- Labeling (notes/sync.md, Implementation (node sync)): `group_actor`, `may_read`, `closure`, `labeled_groups`, `group_labels`, `labels_of`, `label_bodies` (`label_bodies_meta` without plaintexts, cached per commit in `Core::bodies`; `body_plaintext`), `commit_bodies_under`, `latest_by` (newest valid applied write on an aspect, optionally by an author), `part_body`, `linked_blobs`, `wrap_secret`, `stranded_secret`, `deposit_seed`, `head_keys`, `certificates`, `revoke_certificates`, `aspect_commit`, `tree_missing`, `live_trees`, `body_links`, `relink`.
- Flows (each returns `Done { commits, deliveries }`; node-sync carries out the `Delivery` values: `Inbox` blob for an actor's inbox label (with the `Resend` that seals it again), `Direct` commits to a node, `First` placements before any other upload of the sync, `Certificate` copies under a home label, `Deposit` under a label the author does not write): `create_person(hosts)`, `pair(person, node)`, `paired`, `recover(card, lost, presync)`; `grant`/`grant_as`, `demote`/`demote_as(signer, target, Demotion)`, `presync_scope`, `PreSync`; `accept_inbox(blob)`; `create_link`, `redeem`, `bear`, `finalize_link`, `revoke_joiner`; `create_label`, `replace_label`, `issue_step`, `label_of`, `refresh_deposit_seed`; `create_with_admin`; tied grants (`placement`, `untie`); `hold_key_actor(seed)`, `drop_key_actor`; acting (`actor_role`, `mint_actor`, `grants_of`).
- Rotation and lost access (notes/engine-roles.md, notes/engine-lost-access.md): `ensure_rotated(actor) -> (Done, roles still blocked)`, `rotate_eagerly`, `departures`, `give_own_secrets`, `own_secrets_due`, `reseal_due(actor, &dyn SyncState)`, `reshare(actor, holder)`; `drop_lost_secrets`, `lost_due`, `next_lost_due`, `drop_lost_due`, `forget_lost(LostScope)`, `lost_leaving`, `would_forget`, `keep_bearer`, `kept_copies`.
- Events (`events/`): `Applied` (with its changed `(tid, ak)` set), `Joined`, `Changed { cause }`, `Roster`, `Ephemeral` (local and remote ephemeral changes and fired signals), `History`, `SyncStatus`, `Diagnostic` (`DiagnosticKind`: one enum for the engine's kinds and those node-sync and the API report through `Engine::report`, e.g. `Callback`, `NotSynced`, `Stranded`, `Mismatch`).
