# Engine and node crates
> Summary: How osis-engine (`core/engine`) and osis-node (`core/node`) divide the node: the layering and the one engine-to-sync hook, transactions and rollback, the module map of both crates, and the engine's public surface by area. Index of the engine-* notes, which hold the rules of each area. Not here: node-sync's design (notes/sync.md), the API over it (notes/api.md, notes/api-implementation.md), ephemeral data (notes/ephemeral.md).

## Layering
- osis-engine (layer 7) is the node's local state: identity, clock, writing and reads, receiving and applying commits, validity, retention, undo, events, labeling, role flows and rotation. osis-node (layer 8) is `sync/`, the sans-I/O sync engine and its tokio driver, over the engine. osis-node re-exports the engine's modules and root items at the same paths (`osis_node::engine`, `osis_node::flows`, ...), so dependents name only `osis_node`; only osis-node depends on osis-engine (notes/architecture.md).
- The engine knows nothing of sync except one hook, `engine::SyncRecords`, which node-sync implements (`sync::state::Records`) and installs in `SyncEngine::new` (`Engine::set_sync_records`; kept across a reload). Its methods write or drop sync records inside engine transactions, so a crash between the engine's change and node-sync's never loses one: `note_unsent` (the inbox delivery a flow's commit owes, in that commit's transaction), `owe` (a flow's placement or direct send, recorded while owed), `forget` (the `y/` records of what `retention::forget` drops; returns the blobs no kept record names). An engine never wrapped writes and drops no sync records.
- The other direction: node-sync learns what to judge again from `Engine::take_changed` (`Core::changed`, kept only while a `SyncEngine` wraps the engine; notes/sync.md Work sets). It also reaches into `Engine::core` (`Core` is `#[doc(hidden)] pub`) and `Engine::run`; narrowing that to accessors is open.
- The persisted index's rules tag (`core/engine/build.rs`) hashes the sources of the engine and of every osis crate it depends on, not node-sync's: a sync change re-judges nothing at open (notes/engine-store.md).

## Transactions and rollback
- Synchronous, no I/O of its own, time from a `Clock`, randomness injected. Every mutating call runs in one store transaction (`Engine::run(|tx: &mut Tx| ..)`, `Tx { txn, core, rng }`); events go out after it is durable, outside locks.
- Every in-memory index is journaled (`engine::journal`: `JMap`, `JSet`, `JSetMap`, `JNested`; `Indexes`, whose commit, mark and rollback the `indexes!` macro derives from its field list; `Groups`, the held set and `Sides` journal themselves). A failed transaction undoes its own changes newest first and evicts the states it wrote: O(changes), not a copy of every index. Perm's timelines follow the restored held set (`update_touched` around what the undo touched). A failed transaction that changed nothing keeps every derived cache (`Core::rollback_to` drops them only after a `touch` or a state write).
- **Atomic steps.** Rule: a local step (one pending commit's apply in `reexamine`, one part's judging in `examine`, one answer in `answer_removals` or `answer_rotations`, one cover in `settle_none`) is applied fully or not at all; a caller that catches its error goes on from exactly the state before it. `Tx::step` is the one mechanism, and a whole failed transaction is the same rollback from the transaction's start mark: a store savepoint (`Transaction::savepoint`: an undo log of the dirty units and blobs, the memory overlay's journal; nothing spills while one is open, so a rollback is memory only) plus `Core::mark`/`rollback_to`. What a mark covers, by class (`Core::rollback_classes` lists every `Core` field and fails to compile on an unlisted one): restored are the journals (by log length; `JMap` journals a key again after a mark; `ix`, `sides`, `schemas`; the timelines follow `ix.held`), the queued events, `commits_named`, `listed_before`, `to_date`, `written`, `MemorySync::dropped`/`reasons`, the stale sets, `batched`, `memory_tx`, `dirty`; every cache goes when anything changed since the mark (`dirty`, `written`, or any index journal), `generation` stepping; work lists and hints whose consumer re-checks each entry keep a failed step's entries, costing a look (`drop_due`, `none_due`, `valueless_dirty`, `changed`, `redeliver`, `missed`, the held set's `moved`/`records`, `timer_floor`, the HLC, a fresh session: a session costs only through its writes); the rest is set outside steps. A cache filled from restored state belongs in the dropped class. A mark is taken with every held change given to the timelines (each held-set change runs `update_timelines` before returning; debug-asserted): the rollback re-evaluates the timelines around what it restores and would otherwise absorb an earlier change without marking what it moved. A write this node makes on its own at a transaction's end is a step that never fails the transaction: an answer (`answer_removals`, `answer_rotations`) that fails is reported (`OwnWriteFailed`, any error class) and stays due, a purge-on-replace cover is reported and left; each first asks `write::may_write` (the write's own checks), and one that may write only later (minting or delete keys not here) waits. Tests: `apply::tests_steps` (a step failing after it ran equals one failing before it ran: indexes, perm view, decrypted store).
- `Core` (in memory, rebuilt by `apply::load` at open and after forgetting): the states cache with page indexes, `Core::ix` (the journaled indexes: each field documented in `engine/mod.rs`), perm's held set (`engine::held::Held`) and `Timelines`, pending reasons and kept waits, secrets, groups, stored commit records and parts decoded once per record write (`engine/decoded.rs`), caches for node-sync (`bodies`, `labels`, `tree_refs`, ...). Invariant on the commit indexes (`by_aspect`, `by_thing`): they find commits, never decide anything alone, since any signer's header can list any aspect; what a thing has reads the state, and what a commit counts for reads its parts valid here (`Meta::valid_at`).

## Derived values
Rule: a value derived from mutable facts depends on exactly what it read (`engine/memo.rs`; the plan and what still sits behind hand-keyed caches: issues/derived-state-recomputed.md).
- **Stamps.** Every container of mutable facts stamps its changes and its reads (`memo::Stamps`): the journaled collections (`get`/`contains` read one key, `Deref` the whole collection; an undo is a change), the held set (`created` per thing, the rest as one), `held::Timelines` (per thing; an update stamps every thing of the components it evaluated or continued), `memo::Stamped` maps (`Core::key_actors`, `Core::accounts`), `memo::Tracked` values (`Core::account`), the time (`Core::time`, a `memo::Clock`: `get` reads it whole, `until(t)` only up to `t`, so an answer that holds until the next `until` or role commit in a component (`Core::horizon`) moves when the clock reaches it, and every answer when the clock goes back; set at each transaction and by node-sync before it asks), the states by aspect (`Core::states_read`: `Tx::load_lazy` reads, `Core::wrote` and `state_changed` change) and the stored commit records by ID (`Core::records_read`: `Tx::get_commit`, `put_commit`, `remove_commit`, a commit's leftovers (`leftover::get`, `has`, `put`, `remove`) and a cached copy index (`copies::copy_index`); a rollback moves the states it wrote, and every record when it changed anything, a record or leftover written alone included). A key absent costs nothing: all absent keys of a collection share one stamp, moved by any removal there. Keys are stamped by hash, so two colliding keys share a stamp (a spurious rerun, never a stale answer). A container dropped (a `Core` rebuilt) holds nothing that read it.
- **`Memo<K, V>`.** `get(k, f)` runs `f` recording the stamps it read (a thread-local frame; a memo read inside passes its reads on) and keeps the answer while each stamp is the one seen. `Memo::get_in(ctx, ..)` is the same for a function that needs the engine whole and may fail (it runs a transaction); a failure is not kept. `get_checked_in` takes the debug comparison's function apart, for an `f` with effects (`SyncEngine::rotations`: `ensure_rotated` rotates when something is due and fails so; the comparison runs `Engine::rotated_already`, whose transaction always rolls back). What `Engine::run` does around its function (settling, the end-of-transaction follow-ups, persisting, debug checks) is read unrecorded (`memo::Unrecorded`, which opens no frame when no memo computes on the thread): a memo depends on what its function read, not on the transaction's own upkeep. `get_amended_in` brings a kept answer that no longer holds up to date from itself: its `amend` runs recorded, and its answer is kept only if every read of the kept answer that moved is accounted (each read of that stamp, by the function or an earlier amend, was inside `memo::accounted`: an input the amend compares by value with what the kept answer saw) and was read so again by this amend; any other move, or an amend giving `None`, runs the function anew. The rule is exact, not by hash: a dep is accounted only while every read landing on its stamp was, so two keys sharing a hash (and so a stamp) make it unaccounted unless both reads were accounted ones (`an_amend_is_kept_only_over_what_it_accounts_for`). An amend counts for the debug comparison as a hit after a change. No key to pick beyond the argument, no invalidation call, nothing to do on rollback. An answer no longer asked for is dropped when the memo has doubled since it last checked every entry (`SWEEP`). A hit costs a lock per container the answer read, not a lookup per key: an entry keeps its reads grouped by container with the container's change count at which they last all held, and looks keys up only in a container that changed since (an answer over an aspect's n held bodies is otherwise O(n) per hit, O(n²) per pass that asks each body).
- Node-sync uses the same types (`engine::memo` is public): its own state a memo reads is stamped (`StampedSet`: the retired labels and handed-off groups), and the time is `Core::time`, read only where the answer depends on it, so an answer that judged no role does not move with the clock (`SyncEngine::labels`; `SyncEngine::rotations` up to the actor's horizon, read before the run it covers: a horizon read after it misses an `until` the wall clock passed during the run).
- **What can be missed.** A function reading a mutable `Core` field outside these containers, or the store. Debug builds compare a hit with a fresh run (`memo::Checks`) on two schedules: the 1st, 4th, 16th, ... hit of an entry at which a container it read has changed since its last such hit (an amend is one), which finds a missed read whose container, or another the function reads, changes with it; and the entry's hits 16, 256, 4096, ... whatever changed, which finds a missed read that changes alone (the rotations memo's clock read removed: the comparison fails 3 tests, 5 fail in all) once the answer is asked that often. Gating the second on any change in the engine would not do: a missed read may be of a field no stamp counts. A hit inside a comparison (`memo::comparing`) counts for nothing, and no cache rechecks there (`Core::recheck_at`): a memo is compared on its own hits outside comparisons. A new memo's inputs get a stamped container first. A debug check that reads beside a cache hit runs under `memo::unrecorded`: its reads would otherwise cover the read the hit missed (a `copy_index` hit's stamp goes unnoticed that way). Counted: `retention::tests::memos_follow_leftovers_through_writes_and_undo` (each stamp removed fails it).
- On memos: `Core::epochs`, `Core::account_view` (the signing chain; `refresh_epochs` re-judges this node's account by `Core::epochs_judged_from`, compared by value and read without building the chain, so an open decodes no header), `Core::account_epochs`. `Engine::head_keys`, `holders_named`, `inbox_actors`, `labels_of`, `held_links`, `Core::acting`, `rotation::members::key_access`. `Engine::published_under`. `retention::bounds::held_writes` per aspect (amended: while the aspect holds no invalid part, each body's writes are its own, so when its held commits only grew, `amend_held_writes` notes the new bodies' writes; its accounted reads are the aspect's commits and invalid parts, so a drop, a late part, a validity flip or a rollback of records reads it anew; a join decodes its own body, `retention::tests::a_join_decodes_its_own_body_not_the_aspects`), `Core::replaced_dates` per part and `part_bounds` per commit (`Engine::part_keeps`: the bounds but for the clock, applied after; `replaced_at`, `date_due`). `rotation::departures` and `reseal_candidates` per actor (the latter reads the time up to the actor's horizon). `flows::secrets_in` (`secrets.0` decoded) is kept by a memo and patched by each join: the writer takes the kept answer before its write (`Memo::held`) and keeps the patched one at the stamps after it (`Memo::amend`), so a write costs its delta, not the roster. The patch reads the written keys back from the state, so the join first loads every page holding an entry of one (`apply::keys::secrets_paths`): a key's other live entries, concurrent puts, sit on pages the join's own dots do not touch (sim `member_churn` seed 517046069431 fails the memo's comparison without it).
- Counted: rotation `tests::epochs_are_derived_once_per_change_of_what_they_read`, `tests_account::account_view_is_built_once_per_rotation`, `memo::tests`.

## Public surface (engine)
A map by area, not a full list (rustdoc has that).
- Lifecycle: `Engine::create(backend, root, Config, clock, rng)` (fresh identity; the node thing's `created.0` with `node.0`, then `keys.0`), `Engine::open(..)` (load, re-examine pending), `reload`, `tid`, `identity`, `now` (the wall clock), `subscribe`/`subscribe_durable() -> Receiver<Event>`, `register_schema`, `app_record`/`set_app_record` (the `u/` records the `osis` crate keeps), `report(diagnostic)` (deduped like the engine's own).
- Writing: `Mutation` (`create`, `deleting`, `set`/`replace`/`remove_aspect`/`op` through any `RawKey`, `retention`, `expires`/`expires_all`, `purge`, `undo(target)`, `frontier`, `act_as`, `confine`, `sign_as`, `commit_form`, `require_synced`); `Engine::new_thing(&mut m, admin)`, `Engine::commit(m) -> Option<CommitId>` (notes/engine-apply.md, Writer side).
- Receiving: `ingest(bytes, blobs)` / `ingest_from(.., peer)` / `ingest_memory` -> `Ingested::{Applied, Duplicate, Pending(reason), Parked}`; `reexamine`, `set_syncing(tid, on)`, `tick` (expiry, purge floors, drift), `pending()`.
- Relaying: `commit_ids`, `header`, `commit_bytes`, `blob`, `package`.
- Reads: `references_to`/`references_from` (the reference index's rows), `get`, `get_at` (a paged state loads the pages on the path only), `get_range`, `get_full`, `read_large`, `read_large_max` (`TooLarge` past a bound), `next_chunk` (one chunk of a large value per call: the API's `stream`), `get_typed`, `part_valueless`, `aspects`, `groups_of`, `roster`, `role_on`, `state`, `has_content`, `all_aspects`, `first_admin`, `places`/`listed_at`/`commit_row`/`reverters`/`watch_commits` (commit listings, `engine::listing`), `held_parts`/`held_part` (what is held of each part, listed or not).
- Retention (node-sync judges deletions and re-snapshots from the commit index; no queue): `snapshot(tid, ak)`, `covered(snapshot, body, tid, ak)`, `drop_body`, `part_keeps` (per commit, by aspect index: one judgment per part), `delta_live`, `replaced_at`, `drop_from`, `body_not_dropped` (true for a missing part too), `suspects`, `state_digest`.
- Undo: `revert(id)` (an undo commit, spec/commits.md §7), `revert_commit`, `revert_as`, `check_revertible(_as)` (what `undo_target` fails with); `held_commits(scope)` (held commits with header and per-aspect body-held, for `osis` undo and redo; stacks, scopes and redo live there).
- Schemas: known schemas, one per app AK, never from the wire (`Engine::register_schema` replaces one of a lower or equal version, a local typed write only a lower one; `d/` + AK, read at open), serve undo's typed views and large write-back after a restart. `osis::Osis::aspect_key` types only by this session's registrations, so the CLI's `schema rm` untypes.
- Role inputs: `frontier(scope, as_of)`, `epochs(actor)`.
- Labeling (notes/sync.md): `group_actor`, `may_read`, `closure`, `labeled_groups`, `group_labels`, `labels_of`, `label_bodies` (`label_bodies_meta` without plaintexts, cached per commit in `Core::bodies`; `body_plaintext`), `commit_bodies_under`, `latest_by` (newest valid applied write on an aspect, optionally by an author), `part_body`, `linked_blobs`, `wrap_secret`, `deposit_seed`, `head_keys`, `certificates`, `revoke_certificates`, `aspect_commit`, `tree_missing`, `live_trees`, `tree_refs`, `body_links`, `relink`.
- Flows (each returns `Done { commits, deliveries }`; node-sync carries out the `Delivery` values: `Inbox` blob for an actor's inbox label (with the `Resend` that seals it again), `Direct` commits to a node, `First` placements before any other upload of the sync, `Certificate` copies under a home label, `Deposit` under a label the author does not write): `create_account(hosts)`, `pair(node)`, `paired`; `grant` (`grant_as` in unit tests), `demote(target, Demotion)`, `removal_scope`; addenda (`flows/addenda.rs`, run by `Engine::run` at every durable transaction's end); `accept_inbox(blob)`; `create_link`, `redeem`, `bear`, `finalize_link`, `revoke_joiner`; `issue_step`, `label_of`, `refresh_deposit_seed`; `create_with_admin`; tied grants (`placement`, `untie`); `hold_key_actor(seed)`, `drop_key_actor`; acting (`actor_role`, `mint_actor`, `grants_of`).
- Rotation and lost access (notes/engine-roles.md, notes/engine-lost-access.md): `ensure_rotated(actor) -> (Done, roles still blocked)`, `departures`, `give_own_secrets`, `own_secrets_candidates`, `give_own_secrets_again`, `reseal_due(actor, &dyn SyncState)`, `reshare(actor, holder)`; `drop_lost_secrets`, `lost_due`, `next_lost_due`, `drop_lost_due`, `forget_lost(LostScope)`, `lost_leaving`, `would_forget`, `keep_bearer`, `kept_copies`.
- Events (`events/`): `Applied` (with its changed `(tid, ak)` set), `Joined`, `Changed { cause }`, `Roster`, `Ephemeral` (local and remote ephemeral changes), `History` (entries that read otherwise, and fired ephemeral signals' entries as fired), `SyncStatus`, `Diagnostic` (`DiagnosticKind`: one enum for the engine's kinds and those node-sync and the API report through `Engine::report`, e.g. `Callback`, `NotSynced`, `Stranded`, `Mismatch`).
