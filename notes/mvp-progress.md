## Deviations
Each is a requirement of spec/requirements.md not fully met, with the issue (or accepted limit) behind it.
- **Large values**: an edit uploads the changed chunks plus the root node (met since; notes/testing.md, Scale checks), but range reads fetch every chunk before the offset: issues/large-value-seek.md; residues issues/large-value-residues.md.
- **Some operations are O(state) or O(history)** (Scale): the perm walk from scratch (10^4 edge writes about 0.5 s, at open and on early late arrivals): issues/perm-eval-cost.md; a text or list loads whole in a session, set ops by value load every page: issues/node-sequences-not-paged.md; sequence reads and ops place every element: issues/crdt-seq-linearization-cost.md; a change perm evaluates anew re-judges its whole component, open reads every commit header: issues/node-core-gaps.md; sync passes judge every present entry: issues/node-sync-gaps.md.
- **Peer input bounds** (Scale: "never causes unbounded allocation"): a tiny sequence snapshot run expands to 2^16 records: issues/crdt-run-amplification.md.
- **Determinism** (Decentralization: "never of arrival order"): an invite grant's `secrets.0` resets of entries the node has not seen pass, so validity depends on arrival order: issues/invite-grant-secrets.md.
- **Chat costs** (Cost goal): measured (`costs_join_message_removal`, tier 2, passes) join 41 KB, message 2.5 KB, removal 26 KB at 4 holders (37 KB at 8) with others sending only heartbeats; the waste after flows round 2 was certificate re-copies (fixed: certificates per label). Left: the wire-format knobs (header once per commit, one KEM key per keyset, one sealed box per holder) in issues/chat-costs.md.
- **LAN** (Offline and network: "works over LAN"): built. The driver's LAN loop (feature `lan`) announces a fresh key per network with a sealed signature under the dialable key (spec/sync.md §10, datagram provisional); one driver (`Multi`) carries hosts and peers; tier-2 tests over iroh on localhost and through a self-hosted relay. IPv4 and IPv6, network changes from iroh's netwatch; a LAN route replaces a relay connection; `reach.0` rotation; first contact by a direct link.
- **Accepted for post-MVP** (Tess): issues/reseal-triggers.md (a holder whose deposits are refused can wait for a manual re-share; within the Permissions limit "re-sealing is triggered, never guaranteed").
- **Accepted re-seal residue** (residue 2): TLA+ `rotation/MC_drop_refresh` fails `CurrentOpens` as expected (a refused stranded heartbeat); same item as reseal-triggers. Also accepted: re-seal after `secrets.0` compaction (notes/sync.md, Limits).
- **Forward-secure deletion** (Deletion): the root key lives in an overwritten file (`RootTier::FileOverwrite`); the hardware keystore tiers the requirement now assumes are not built: issues/root-key-erasure-tier.md.
- **Not checked**: "Runs in browsers" (no wasm build; the lower crates are sans-I/O and take rng and clock as parameters); "pushed, not polled" holds for connected nodes, push wake-ups for sleeping devices are a proposal (notes/networking.md).
- **API conveniences not built** (no wire impact): queries and backlinks, `undelete` and text cut/paste, `sync_policy`, bearer `open_link`, streaming writes, `pending_uploads`: issues/api-deferred.md.

## Method used by the run (from the deleted plans/mvp_meta.md)
Kept for the next agent-driven run. Roles: a toplevel plans waves, spawns opus sub-agents in worktrees per plan, reviews every branch with a fresh agent before merging, escalates design problems to a fable agent, keeps this note. Ground rules given to every sub-agent:
- **Spec authority**: spec/ at the time of implementation trumps notes/ and plans/. A TBD is filled by plans/protocol-spec.md; filling it is not a spec change. A spec sentence that is wrong or unimplementable: minor clarification → edit it, record it under "Spec edits" in notes/mvp-progress.md, continue; significant or breaking (changes bytes already frozen in vectors, removes a property, changes an accepted limit in spec/requirements.md) → do not edit; write an issue tagged `tess-call` with the options and the recommended one, implement the most conservative reading that keeps the requirement, and continue elsewhere.
- **Requirements**: never weaken a spec/requirements.md item to fit code. If one cannot be met in a minor way after a real attempt, file an issue (`escalate`), note the gap, continue.
- **Complexity budget**: prefer removing a client-side convenience over adding a mechanism; no new wire fields or message kinds outside the spec; no new dependency without its line in notes/architecture.md; no new crate without a line in the crate map; abstractions in notes/architecture.md §2 are fixed unless an issue reopens them.
- **Code**: simple safe Rust; `#![forbid(unsafe_code)]`; no panics on data; error classes per notes/architecture.md §3; every test cites its spec section; seeded randomness only; no formatting tools; compact prose, comments, commit messages.
- **Tests, targeted**: `cargo test --workspace`, or `cargo test -p <crate>`, narrowed with `--test it <module>::` while iterating (notes/build.md). Tier-2 tests are `#[ignore]`. Never add a test that sleeps or touches the network in tier 1.
- **Bookkeeping**: tick the plan's Steps as they land and append one line to its Progress per session; update the notes the plan names; create issues (with Summary and Tags) for nontrivial problems found; delete an issue only when its fix is merged; never record dates or estimates.
- **Git**: commit to the worktree branch with clear messages (ending with the attribution line the session gives); commit at least at every step boundary and before returning; never push, pull, rebase or rewrite history; never use bare `git stash`.
- **Return**: end with a report: what landed (commits), what is open, any escalation, any interface change other crates must know.

Mechanics:
- **Integration branch**: the branch this plan runs on. Sub-agents work in worktrees (`Agent` with `isolation: "worktree"`) on their own branch; they never touch the integration branch.
- **Spawn prompt** (per plan): "Read notes/architecture.md, plans/<plan>.md and the spec sections it names; spec trumps the plan. Execute the plan's Steps in order, committing per step. Ground rules: <§3 verbatim>. When done or blocked, update Progress and return the report." Add the wave's known interface facts (what merged since the plan was written). Spawn independent plans of a wave in one message so they run concurrently.
- **Merge**: when an agent returns, an opus **integrator** agent (or the toplevel for trivial cases) merges the branch into the integration branch (`git merge --no-ff`), resolves conflicts (regenerating `Cargo.lock` by `git checkout --theirs Cargo.lock && cargo update -w --offline` or a fresh build; workspace `Cargo.toml` members are pre-registered so they rarely conflict), runs `cargo clippy --workspace -- -D warnings` and `cargo test --workspace`, fixes breakage caused by the merge (not the plan's own open steps), commits. A failing integration is never left on the branch: fix or revert the merge and re-spawn the plan agent with the failure.
- **Review before merge**: every plan branch gets a fresh opus reviewer (`/code-review`-style, medium) given the plan and spec sections: correctness against the spec, panics on data, missing tests, unjustified deps. Findings go back to the plan agent (SendMessage to continue it with context) or to the integrator if small. Branches touching the permanent wire surface (protocol-spec, osis-base CBOR and tid, commit header, blob prefix, label steps, vectors freeze) are additionally reviewed by the toplevel before merge.
- **Interface changes**: a plan that must change another crate's public API makes the smallest change, notes it in its report, and the integrator updates dependents; a disputed change becomes an issue and a fable or toplevel decision.
- **Progress file**: notes/mvp-progress.md, kept by the toplevel: one line per plan (not started / running (agent, branch) / review / merged at <sha> / blocked (issue)), the current wave, open escalations, spec edits made, tess-calls pending. This is the resumption point after any context loss. The toplevel re-reads it and `git log` before acting.
- **Resuming a plan**: when an agent stops with steps unticked (context exhausted, blocked then unblocked), spawn a fresh opus agent on the same plan; its Progress lines and the branch's commits are the hand-off. Merge partial branches when they are green and useful; do not keep long-lived branches.
- **Parallel load**: run every independent plan of a wave at once, but keep the integration branch moving: merge as soon as a branch is green rather than waiting for the wave. Downstream plans start when their gate is merged, not when the wave ends.
- **Communication between agents**: through merged code and notes only. An agent needing a fact from another plan reads the integration branch (ask the toplevel to merge first) rather than guessing.

Escalation ladder:
Ladder, applied by the toplevel to every blocker a report raises:
1. The plan agent tries alternatives inside the spec and its budget first, and says what it tried.
2. Re-spawn or continue the opus agent with a concrete hint, or spawn a second opus agent on the narrow problem (a failing differential case, a merge conflict, a flaky invariant) while the first continues.
3. A fable agent for a design-level problem: given the spec sections, the notes' rationale and the concrete failure; it returns a decision and, if needed, a minor spec or notes edit. Record it in notes/mvp-progress.md.
4. The toplevel spins up additional agents beyond this plan where the problem warrants (a missing model, a spike comparing two approaches, a review of an affected area). This plan is not a cage.
5. Tess-call issue when the fix would be a significant spec change, a requirement compromise beyond "minor", or a restructure of a fixed abstraction; implement the conservative reading meanwhile and keep every other plan moving.
Stop the run (report to Tess) only when no solution stays within the complexity budget, avoids a major restructure of the design, and keeps the requirements. Minor unmet requirements after a real attempt: issue + continue.
Watch for and act on: two agents reinventing the same helper (merge into the lower crate); test suites getting slow (move to tier 2, cut proptest cases); a crate pulling heavy deps (feature-gate); divergence between notes and code (fix notes in the same merge).


Lessons: never share a CARGO_TARGET_DIR between worktrees (cargo keys path crates by workspace-relative path and silently reuses another worktree's artifacts); per-agent target dirs with CARGO_INCREMENTAL=0 are ~2–4 GB; at most three building agents on 4 cores; never chain `git commit -a` after a `git merge` in one command (a conflicted merge gets committed with markers).
