# Security tests
> Summary: The forensic attack that defines "forensically clean" (what evidence it uses, how it finds keys, what it misses, the leaks it is checked against), metadata and negative tests, and what past security reviews checked and found sound so a new review does not redo it.

## Forensic attack (`osis_store::attack`, `Engine::forensic`)
The definition of "forensically clean" (spec/requirements.md, Deletion). Evidence: the keys the current store tree yields, the read secrets of every thing the node's code holds now (`Engine::forensic` adds them), and every row and blob the backend was ever given (`MemoryBackend::record_history`; `copy` copies a recording device). To a fixpoint it reads every row and blob raw, opens rows with store keys (tree nodes yield more), takes every random-looking 32 bytes (at least 16 distinct byte values) of anything recovered as a candidate key on every blob, and for entries keyed by a blob ID (store wraps, the ciphertext store's entry rows; table pages decoded by the store's own `forensic_leaf`) tries the value's leading wrap under every candidate as a read secret. Each find says where (`Source`).
- **Exact, not sampled**: the recovered set is the brute-force one (`shred::sealed_keys_change_no_recovery` checks it against trying every key). Shortcuts: a row is tried with the one key that sealed it (`Evidence::sealed`, recorded by its AEAD tag through `Backend::note_sealed` in debug builds; a note is checked, never trusted) and with every key when unrecorded or wrong; each candidate is prepared once (`osis_crypto::Trial`); a blob or section is ruled out by one keystream byte, every wrap at once by one byte under the wrap nonce; failed tries are not repeated on a thread (`forensic::Failed`). Section wraps have no known plaintext byte, so candidates × unopened sections are most of an attack's cost. Per attack well under a second; crash loops fork one set-up device per crash point; `shred` tests attack once per state.
- **Seen to bite**: a shredded drop not rotating its parent node's key fails the store `shred` tests; the synced cases (a dropped blob keeping its wraps or its key row, under one sync ID or several) await sync tests (below).
- Markers find content; a dropped map key's keyed index hash is an extra needle where it matters (`expired_entry_paged_*`).
- **Not covered**: keys inside a blob stored in clear (raw blobs and rows are not harvested: ciphertext would flood the candidates; clear rows are); a wrap not at the start of a blob-keyed entry's value; secrets only derivable from dropped ones (no KDF chains over old secrets); memory, swap, the root store's past records; non-memory backends (redb: `file_backend_holds_no_plaintext` greps the file). "Random-looking" misses a real key with probability about 2^-55.
- **Not levers**: attacking only rows written after the subject arrived (an older row can hold a key that opens a later one), or the union of several crash points' evidence (the forks draw the same keys from one seed: a false find).
- Row lengths: `shredded_small_drop_keeps_unit_lengths_within_a_class_step`.
- Tests: store `tests/it/shred.rs`; engine `tests/it/shred.rs`, `flows.rs` (removal erasure); osis-sync `shred.rs` (a synced node's purge, online and away; by hand: about 250-700 G instructions in debug, the attack on a three-account world's devices). Not covered: a crash at every write of sync's forget. On the sync harness the attack needs a recording world (`World::record` before nodes are added; `World::forensic`, `World::recorded`).

## Metadata and negative tests
- **Metadata** (core/sync/tests/it/metadata.rs, a recording three-account world, node 1 keeping S unread): its store device holds no value, map key, content AK, core AK, role secret of the thing, or the writers' node tids and signing keys in clear, live or overwritten; every blob it keeps has a Padmé length. By hand: everything an attack on its whole device decrypts holds none of them but the core AKs (its own things carry those; about 350 G instructions in debug). Claim sets padded to a power of two: osis-label `step::claim_set_hides_count`. Not covered: few size classes over value lengths, no blob ID, salt or wrap shared across sync IDs.
- **Negative tests**: store refusals in core/sync/tests/it/store.rs, hostile peers in core/sync/tests/it (scripted peers and `harness/lies.rs`), decoder limits in osis-proto tests/it/limits.rs; perm refusals in osis-perm tests/it/scenarios.rs; node ones in osis-engine tests/it/flows.rs; QUIC mutual auth and no 0-RTT in osis-transport `quic::tests` (by hand).

## Security reviews
What reviews checked and found sound; each fix landed with a test citing its spec sentence.
- **crypto, keys, perm, flows**. Tested invariants: secrets from unchecked (pending) boxes are reading-only until an applied valid box carries them (`osis-keys/tests/it/boxes.rs` `unchecked_boxes_are_reading_only`, `reading_only_through_history`; `lying_box_ignored_in_either_order_spec_crypto_4`); a grant raced by a rotation of another role keeps its box at the current epoch, which then does not cover its holder's departure (`covers.rs` `grant_raced_by_rotation`); an invite grant's `secrets.0` exemption covers only its grantees' boxes, as puts only (`invite_grant_resets_unmerged_any_order_spec_perm_2`); `keys.0` admin keyset, key, inbox and deposit seed need admin, and an actor's key field is never sealed to (`apply::validity::keys_tests`); a register write at the root of `keys.0` or `secrets.0` is refused (`writer_cannot_replace_keys_or_secrets_spec_perm_3`, `invite_grant_cannot_replace_secrets_spec_perm_2`); record chains capped at `MAX_CHAIN_DEPTH`; store file modes (`existing_store_files_become_owner_only_spec_requirements_deletion`). Checked sound: signature domains (fixed-length digest after distinct domain strings, strict verification, keys validated at parse); sealed boxes (fresh ephemeral, combiner over both secrets, both ciphertexts and the key, non-contributory X25519 refused); symmetric boxes (nonce from a unique AD); history boxes (random secret per epoch, re-written by copying ciphertext); wraps and blob keys; redacted Debug and wiped payloads; explicit demotions rotate every role left; rotations replace a key actor's removed box with its lower roles; re-seals only at chain-established epochs; invite grants cannot lower or change grants or exceed the invite; self-removal needs a lowering in every component; perm overlap voiding; every encrypting getter (`secret`, `held`, `newest_held`, `newest_secret`, `held_established`) skips reading-only secrets, readers use `reading_secret`/`held_newest_first`; file modes on every secret-bearing file. Not done: forged-commit end-to-end tests for the pending-box path (tested at the epoch record); frontier contents are trusted from the demoter (hostile admins are out of scope).
- **sync**: the rebuilt osis-sync has had no security review yet. Its hostile-peer rules (spec/sync-hostile.md) are tested per module in core/sync/tests/it; the transport's checks (TLS 1.3 only, ALPN, 0-RTT off, RFC 7250 Ed25519 SPKI exact, client auth mandatory, key pinned) are osis-transport's.
- Fix-reverted runs (fix stubbed, test must fail) confirmed `unchecked_boxes_are_reading_only` and `unshredded_large_overwrite_is_unrecoverable_after_a_later_shred`.
