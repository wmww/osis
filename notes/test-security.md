# Security tests
> Summary: The forensic attack that defines "forensically clean" (what evidence it uses, how it finds keys, what it misses, the leaks it is checked against), metadata and negative tests, and what past security reviews checked and found sound so a new review does not redo it.

## Forensic attack (`osis_store::attack`, `Engine::forensic`)
The definition of "forensically clean" (spec/requirements.md, Deletion). Evidence: the keys the current store tree yields, the label read secrets the node's code computes now (`Engine::forensic` adds them), and every row and blob the backend was ever given (`MemoryBackend::record_history`; `copy` copies a recording device). To a fixpoint it reads every row and blob raw, opens rows with store keys (tree nodes yield more), takes every random-looking 32 bytes (at least 16 distinct byte values) of anything recovered as a candidate key on every blob, and for entries keyed by a blob ID (store wraps, node-sync `y/e`; table pages decoded by the store's own `forensic_leaf`) tries the value's leading wrap under every candidate as a read secret. Each find says where (`Source`).
- **Exact, not sampled**: the recovered set is the brute-force one (`shred::sealed_keys_change_no_recovery` checks it against trying every key). Shortcuts: a row is tried with the one key that sealed it (`Evidence::sealed`, recorded by its AEAD tag through `Backend::note_sealed` in debug builds; a note is checked, never trusted) and with every key when unrecorded or wrong; each candidate is prepared once (`osis_crypto::Trial`); a blob or section is ruled out by one keystream byte, every wrap at once by one byte under the wrap nonce; failed tries are not repeated on a thread (`forensic::Failed`). Section wraps have no known plaintext byte, so candidates × unopened sections are most of an attack's cost. Per attack well under a second; crash loops fork one set-up device per crash point; `shred` tests attack once per state.
- **Seen to bite**: a dropped blob keeping its wraps or its key row fails the `shred_sync` tests with and without the shortcuts, as does keeping the wraps only of a blob under one label or one under several; a shredded drop not rotating its parent node's key fails 25 node `shred` tests and 8 store ones.
- Markers find content; a dropped map key's keyed index hash is an extra needle where it matters (`expired_entry_paged_*`).
- **Not covered**: keys inside a blob stored in clear (raw blobs and rows are not harvested: ciphertext would flood the candidates; clear rows are); a wrap not at the start of a blob-keyed entry's value; secrets only derivable from dropped ones (no KDF chains over old secrets); memory, swap, the root store's past records; non-memory backends (redb: `file_backend_holds_no_plaintext` greps the file). "Random-looking" misses a real key with probability about 2^-55.
- **Not levers**: attacking only rows written after the subject arrived (an older row can hold a key that opens a later one), or the union of several crash points' evidence (the forks draw the same keys from one seed: a false find).
- Row lengths: `shredded_small_drop_keeps_unit_lengths_within_a_class_step`.
- Tests: store `tests/it/shred.rs`; node `shred.rs` (purge, expiry, purge on replace, paged, chunked), `shred_sync.rs` (a synced node's purge, online and offline, and a crash at every write of the purge and of node-sync's forget), `flows.rs` (removal erasure); host `hygiene.rs`, `metadata.rs`; osis `hosting.rs`.

## Metadata and negative tests
- **Metadata** (core/node/tests/it/metadata.rs, real engines over an osis-host hub): stored bytes hold no value, map key, tid, AK, node tid, signing key or role secret (a label-ID control proves the search works); every stored blob's padded length is a Padmé length and 48 value lengths fall in at most 5 size classes; two labels share no blob ID, salt or wrap; claim sets of 3 and 4 readers are both 4, of 5 readers 8, shuffled.
- **Negative tests**: host refusals in osis-host tests/it/limits.rs and hub.rs and osis-proto tests/it/loopback.rs; perm refusals in osis-perm tests/it/scenarios.rs; node ones in osis-node tests/it/flows.rs, peers_review.rs, negative.rs; QUIC mutual auth and no 0-RTT in osis-transport `quic::tests` (by hand).

## Security reviews
What reviews checked and found sound; each fix landed with a test citing its spec sentence.
- **crypto, keys, perm, flows**. Tested invariants: secrets from unchecked (pending) boxes are reading-only until an applied valid box carries them (`osis-keys/tests/it/boxes.rs` `unchecked_boxes_are_reading_only`, `reading_only_through_history`; `lying_box_ignored_in_either_order_spec_crypto_4`); a grant raced by a rotation of another role keeps its box at the current epoch, which then does not cover its holder's departure (`covers.rs` `grant_raced_by_rotation`); an invite grant's `secrets.0` exemption covers only its grantees' boxes, as puts only (`invite_grant_resets_unmerged_any_order_spec_perm_2`); `keys.0` admin keyset, key, inbox and deposit seed need admin, and an actor's key field is never sealed to (`apply::validity::keys_tests`); a register write at the root of `keys.0` or `secrets.0` is refused (`writer_cannot_replace_keys_or_secrets_spec_perm_3`, `invite_grant_cannot_replace_secrets_spec_perm_2`); record chains capped at `MAX_CHAIN_DEPTH`; a purged chunk reused concurrently is re-encrypted (`purged_chunk_reused_concurrently_is_reencrypted_spec_sync_1`); store file modes (`existing_store_files_become_owner_only_spec_requirements_deletion`). Checked sound: signature domains (fixed-length digest after distinct domain strings, strict verification, keys validated at parse); sealed boxes (fresh ephemeral, combiner over both secrets, both ciphertexts and the key, non-contributory X25519 refused); symmetric boxes (nonce from a unique AD); history boxes (random secret per epoch, re-written by copying ciphertext); wraps and blob keys; redacted Debug and wiped payloads; explicit demotions rotate every role left; rotations replace a key actor's removed box with its lower roles; re-seals only at chain-established epochs; invite grants cannot lower or change grants or exceed the invite; self-removal needs a lowering in every component; perm overlap voiding; every encrypting getter (`secret`, `held`, `newest_held`, `newest_secret`, `held_established`) skips reading-only secrets, readers use `reading_secret`/`held_newest_first`; file modes on every secret-bearing file. Not done: forged-commit end-to-end tests for the pending-box path (tested at the epoch record); frontier contents are trusted from the demoter (hostile admins are out of scope).
- **label, host, node-sync**: tests in osis-node `tests/it/hostile_host.rs` (raw frames: `Net::conn_to`), osis-proto `tests/it/hostile_peer.rs`, osis-host `tests/it/bounds.rs` `partial_frames_bounded`, `frame::tests::capped_first_frame`. Tested invariants: stream events of a peer that cannot read L for a sync ID not in the stream store nothing (`unsolicited_push_stores_nothing_spec_wire_11_2`); a Behind answer's steps verify as a chain from the asked step; captured signals past `MAX_DRIFT` are dropped; junk under an opened label is kept nowhere; a substituted entry box teaches nothing; wrap swaps ignored (`wrap_not_opening_to_known_key_ignored_spec_sync_5`); relayed stamps checked against the head; the unvouched-entries cap is per host (`unvouched_cap_per_host_spec_sync_3`, `old_step_stamp_vouches_nothing_spec_sync_5`); outside deletes wait for a settled view. Checked sound: open proofs bind label, challenge and the opened side's static key; Behind items answer only a credential of the named step; register accepts only a genesis hashing to the label or a child of the head; stamps, deposits and keyed deletes check the head's key; token deletes need a prefix commitment plus the key its level names; stamped entries refuse expired, tombstoned, oversized, bad-stamp blobs; Delete needs node sync's open on the connection; relays verified against the head's write or deposit key, rate-limited, never stored; deposit budget, caps and rate limits; an identical entry taken again logs nothing; client side: relayed stamps verified, steps from Behind answers verified under the parent, a wrap replacing a known blob key must open to it, Deleted events never drop a held commit body; transport: TLS 1.3 only, ALPN enforced, 0-RTT off, RFC 7250 Ed25519 SPKI exact, CertificateVerify verified, client auth mandatory, host key pinned, handshake 5 s, idle 60 s, 16 bidi streams; nodes dial hosts and a link's sharer with an ephemeral key and co-readers with their dialable key, separate from the signing key; LAN datagrams exactly 60 bytes with magic; host metadata: deposit keys per label ID, label keys per group, claim keys per step, certificate blobs fresh per label.
- Fix-reverted runs (fix stubbed, test must fail) confirmed `unchecked_boxes_are_reading_only`, `unshredded_large_overwrite_is_unrecoverable_after_a_later_shred`, `junk_under_opened_label_kept_nowhere`, `replayed_ephemeral_signal_dropped`, `substituted_entry_box_teaches_nothing`; `forged_entry_box_teaches_nothing` passes with the derive check removed (it stops at path verification).
