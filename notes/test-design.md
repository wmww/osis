# Test design (plan)
> Summary: Decided (Tess): one property test per stated property per component, examples and minimal reproducers beside it, sizes as a knob, selection derived from what a branch touched. Ordered steps, each one worker plus one reviewer, with what each deletes, adds and how we know it is done. The one place test-system work is tracked.

notes/testing.md and notes/build.md describe what runs today; this note is what it becomes and the order of work. The gate lock is done (tools/gate.sh takes tools/heavy's lock for tier 1 and the sim sweep only: two overlapping all-core runs each took about twice as long, so locking them costs nothing; docs-only gates take no lock).

## Principle
Each component's note states its few properties at the top (crdt: the join equals the model's lawful join; engine: what a node reads is a function of the commits it holds; perm: the incremental walk equals the walk from scratch and the walk equals roles-model; rotation: no departed holder reads later content, every holder ends reading everything; sync: everything settles and must-hold bodies reach the host). Each property has exactly one randomized test with an oracle (a model or the from-scratch path) that compares what users observe. A rule that needs a picture gets a small hand-written example. A test that names no property or rule goes.

| kind | what | size | runs |
|---|---|---|---|
| example | one spec rule or one minimal reproducer; steps in the body, no generator seed | under 1 s | every gate |
| property | one generator, one oracle, one function with a size knob | `quick` in the gate, `plain` for reviewers, `full` before a release | gate; reviewer for touched crates; release |
| model | crdt-model, roles-model, held-model, TLA, with their own self-checks | small | when the model or its spec sections change |
| system | the sim: what no single engine can show (sync liveness, host contents, state bound) | every scenario x 5 seeds in the gate; breadth before a release | gate; release |
| timing, fuzz | release timing, libFuzzer | by hand | by hand |

Rules for every step:
- Sizes are one function with a knob (`quick`/`plain`/`full`), never `_small`/`_large` twins; only `plain`/`full` read `OSIS_*` ranges, and an override prints its range.
- Oracles compare observables: reads, rosters, promised history (`history()` within kept history), errors. Best-effort APIs (undo availability, `commits()`, `changed()`, `Change.origin`) are never compared across nodes. An excuse comes from the generated history, never from the node under test; exchanges between nodes run through real sync.
- A generator does not steer around a known difference (`purge_author_history`'s comment is a carve-out); a failure is a design question.
- Before deleting a harness, every open issue whose replay uses it gets a minimal example (`#[ignore] repro_*` naming the issue) or a replay that survives the step. Open now: churn-cursor-rebuild-differs, eph-churn-delete-upload-loop, eph-reverts-restarts-differ (ephemeral harnesses).
- Each step ends with notes/testing.md updated for what it removed or added, the tier-1 CPU-s of the touched binaries before and after (`/usr/bin/time`, judged as CPU-s), and the per-branch list in testing.md still naming a test for every area until step 12.

## Measured (main 8f3cd8d0, osis-node `it` tier 1, each test alone, load about 85)
- 1147 tests, 1404 CPU-s; the 252 at 1 CPU-s or more cost 81%. `order::` 92 tests, 604 CPU-s (43%); `arrival_order_found_histories` alone 160. Alike/any-order/every-order tests across modules: 114, 461 CPU-s, all checking G1's property.
- Seed-named tests: 30 node `order::` (osis-sim has none), plus 37 `check(<seed>, ..)` pinned histories and the `found()` lists.
- Last periodic run (e3cdd005f): tier-2 set 54,474 CPU-s; order alike + exhaustive 19,650; sweep 35,350; TLC 8,800 (Depth0 79%: fairness re-evaluates its recursive operators on every transition; `D0_nc` 23 CPU-s safety-only against 203 with liveness).
- Running test binaries in parallel is not worth building: tier 1 is CPU-bound and every-binary-at-once was measured not to help. Only less work shortens it.

## Steps
**1. TLA trim.** Done: `core/test/tla/run.sh <module>`, each module's safety on every listed instance, liveness on one (sync and sides keep theirs), one negative control or open finding that must fail; at one worker on a quiet box depth0 55 s, sync 37 s, cover 19 s, rotation 18 s, sides 15 s, lockout 10 s, finalize 3 s (about twice that at load 10). Larger instances by hand, by name (notes/testing.md Models).

**2. Sim duplicates.** Done. osis-sim tests hold only what the gate's sweep cannot show (a scenario's faults happening, replay exactness, the work-sets comparison, scale counts, examples); no seed-named test (testing.md Simulator). The promotion gate's example is osis-node `sync_more::promotion_waits_for_the_chain_at_the_host_spec_sync_5` (fails with the chain check in `promote` off). The gate only acts when the promoter cannot complete the chain: its own certificate copies count as placed with the promotion (spec/sync.md §5), so a lost copy upload never reaches it; the example's promoter holds the chain commit as its header only (`Net::lose_deposits` loses the author's deposit of it).

**3. Pinned seeds in osis-node and osis-engine.** Done. Tier 1 replays no pinned seed: a hand-written history is checked in named orders (explicit ones, or order.rs `NAMED`: as made, reversed, as fetched); an open issue's replay is a `repro_*`. Order harness runs are sized `quick(seeds, len)` (tier 1, no environment) or `tier2(seeds, len)` (the `OSIS_ORDER_*` overrides); thread-count variables are still read everywhere. Left for step 9: the pinned seed lists inside tier-1 property runs of ephemeral (`random_window_*`, `ephemeral_reverts_*`).

**4. G1 oracle in today's order harness.** Done. Each node is judged against the keep-everything node holding the same commits (`order::node_checks`), from the API only: reads (errors included) and rosters, now and with every bound and expiry past, after the node's own sync exchange (`fetch_missing`: what it counts missing comes again from the history's packs, as node-sync refetches); the one excuse is `waited_at_expiry`, from the history. P1 before the exchange does not hold and is not checked, except in `settled` histories: Deterministic's limits (a fallen cover or purge, an edit dropped while it did not count, addenda included) leave a node apart until a copy arrives. P3 `value_past_end` before and after the exchange, the permission index against its walk from scratch, held-model (applied, validity, edge writes, reads, forbidden values, covered purge-on-replace bodies gone, kept-until-T presence), P4 reopen and rebuild. Internal checks kept because they are the point: P3 (purged or expired values gone from held bodies), the index reopened against a rebuild (until step 6), `perm_digest` incremental against scratch. Held bodies, states, pending sets, timelines and death dates are compared nowhere; keep for D's dating is `held::keep_for_d`, used by two scripted examples only. The seven AMBIGUITIES.md engine rules have examples in retention.rs. Measured at load 15-45: osis-node `it` tier 1 1011 -> 888 CPU-s (`order::` 228 -> 142); the order tier-2 set at plain 3979 -> 2585 CPU-s.

**5. G1 property: one test, `held_set_decides`.** Done (notes/testing.md Held-set property). One generator (seven feature groups, each on its own rng stream; the seed picks one of eight emphases, each with a start that reaches its outcome), orders from one config (`ORDERS`), sizes `quick` (tier 1), `plain` and `exhaustive` (every order of every held set of histories of at most 6 commits, tier 1 at 4), judged by `node_checks` against the keep-everything node and held-model, plus a reopen after every ingest (`reopens_alike`) and a delivery without what snapshots cover (`covered_away`). Deleted: the 23 `order::arrival_order_*` configs and their generators, `carrierless_part_alike_*`, `new_node_alike_*`, `reopen_after_each_commit_*`, `parts::parts_differential`, `part_away_differential`, `rosters_alike_across_sync_sets`, `parts::split_delivery_any_order_reads_alike` (a sweep of the same property), `retention::purge_rights_any_arrival_order`, `waits::gap_snapshots_converge`, `sessions::gap_cover`, engine `validity_alike_*_random`, the held-model survey. Kept: `keep::any_order_*` (kept copies at the removed holder's own node; `held_set_decides` judges non-holder nodes only), and every other scripted `*_alike*` test: each is a minimal reproducer or a rule example naming what it pins, or reaches what the generator does not (relay junk, parked parts, lasting headers, forensic recovery, listings, `group.0` sync sets). The two open issues the deleted harnesses replayed are `repro_*` with the history as made (`repro_settled_purges_3751`, `repro_purge_author_order_452234901986`). Gap, the step's own weakness: a role commit carrying anything but `roles.0`/`keys.0` (every flow grant, removal, record-only creation) takes every aspect out of held-model's comparison, a carve-out (issues/held-model-role-commit-scope.md). Sabotage at `quick`: by-author purges reaching nothing (held-model: forbidden value held), covered purge-on-replace bodies never dropped (held-model), a body dropped while invalid never made missing when valid again (keep-everything node, after the exchange), each fails. A sequence flag join letting a held delete beat a later undelete passes `quick`; plain-full fails it on texts only (index rebuild, held-model), never on a list or through the keep-everything node. Full plain size is not green yet: issues/held-set-decides-full-size.md. A keep-at-least bound on durable covered drops is unreachable: those drops are node-sync's (`sync/local.rs`), never an engine-only harness's. Measured back to back at load 21-44: osis-node `it` tier 1 1020-1040 -> 896-918 CPU-s (about -12%, not the planned 40%: `order::` was 163 CPU-s of it, now 92); osis-engine lib unchanged (about 238). Found: the settled check compared aspects the settling tail never compacts (`required^.0`); it now compares only what a writer compacted last (`settled_last`).


**5b. held-model values from crdt-model.** Done. held-model's values are crdt-model fragments: one model of values, every encoding. crdt-model gained, from the spec: `death` (write identity `key`, `winning`, `supersedes` as "dead in the join with it", `holds` by dot, `covers` by canonical bytes, §4.7 `valueless`), `origins` (dot to commit by the headers' forms and ranges) and un-merge by origin dot keeping the records the valid snapshots hold (§4.6); held-model's `crdt.rs`, `Op`/`Write`/`Read`/`AspectKind` and its write-by-write undo went (undo is crdt-model's structural diff to the state without the undone commit), and its generator writes registers, maps, texts, sets, counters, lists and a struct holding a map through crdt-model's ops. The adapter decodes bodies from the engine's wire bytes and compares every content aspect; `Fragment::flat` went. Coverage at plain-full (80 seeds from 132230, green): compared aspects holding register 280k, struct 151k, map 63k, text 50k, list 17k, set 7.8k, counter 3.6k. Sabotage at `quick`: list reads reversed fails through held-model alone (`t:listtext.0`); a held text delete beating a later undelete (`join_flag`), a set element's content kept under its own reset and a list element shown above its reset pass quick (quick draws no list delete, no effective set removal: a reach gap of the generator, not of the oracle; a hand history fails the set one through held-model at once). Found on the way: a key-erased removal was taken as a value-less write (bodies counted never received), and held-model's `settle` never fetched back a body dropped as invalid that turned valid again.

**6. G2 incremental equals from scratch.** Done. Engine: `Engine::check_index` (notes/testing.md Index check) runs after sampled durable transactions in debug builds (per open, when the count of transactions that changed a state or a part, or of those that changed more than valid joins, reaches a power of four): an open from the persisted index and a rebuild from the commit records each give the running node's index and timelines, so every test is an open-equals-rebuild test; a sabotaged reopen path (an overreach flag or the epoch intros not loaded) fails about 500 node tier-1 tests. Deleted: `walks::` (its damage, crash and restore rules kept as `caches::`; `uncovered_part_judged_anew` moved to retention.rs, calling `check_index`), the order harness's reopen-against-rebuild index compares, `flows::persisted_index_equals_rebuild` (its damage half is `caches::damaged_caches_are_rebuilt`), `sessions::pruned_sessions_converge*`, `retention::register_rebuild_*` (the early stop's cost is `validity.rs`'s flat-in-n check). Found: equivocating commits of one counter range kept one `ranges` entry by arrival order (fixed: keyed by commit too), a node's own rotation not reading the history its new secrets open (fixed: `rotation::record` observes `secrets.0` again). Measured back to back at load 12-33: osis-node `it` tier 1 about 970 -> 1060 CPU-s against main 816058ea6 (the check about 12% of its CPU by cpuprof). Paged property (`paged_apply_matches_whole`, one `differential` with a size knob): it judges `replaced_at` on the final held sets only. Seed 16 takes 90-110 CPU-s (judging about 4% of it; ingest with its purge-on-replace snapshots, `settle_none`, about 30%; the stored-state reloads after every step about 20%), and seeds at random offsets 130-200 CPU-s each (not profiled), so "slowest full seed under a minute" is not met yet. Perm: one `incremental::incremental_equals_from_scratch` taking the eight shapes in turn, a quarter of samples checking `Changed`; tier 1 16 samples, `_large` 8000 (full about 2470 CPU-s, passed at a random `OSIS_PERM_SEED`).

**7. G3 crdt equals the model.** Done. One differential, osis-crdt `tests_model::crdt_equals_model` (notes/crdt.md Tests): five modes by seed index (kitchen sink; encodings at one position; maps of texts and lists; twin writers forging copies; hostile text and list writes), lockstep joins in random orders with duplicates, the wire both ways, strip, un-merge, a coverage tally of modes and encodings at every size; `Quick` 100 seeds, tier 2 `Plain` 1000 / `Full` 10,000, sizes differing only in count. Deleted: the per-type lockstep and wire tests (`tests_join` `*_match*_model*`, `tests_seq` text, list, kitchen-sink, map-of-text, slots and `seq_wire_*`, `tests_wire` `wire_*` byte identity), the three `hostile_*_match*_model*`, `seq_differential_large_spec_5_7`, `model_order_independent*`, and `tests_laws`' honest laws (their `contains`, `part_at` and honest-copies checks run per join in the differential). Kept: the forged-copy laws (`tests_laws::forged_copies_*`, no model compare), crdt-model's own laws, the decoder, diff and op differentials (other properties). Each of eight join sabotages (register keeps its first write, bag ignores meta, set drops element resets, struct skips the replace prune, enum keeps its first case, map drops creations, sequence keeps the two least position writes, slots ignore other slots' resets) fails `Quick` in 13-61 of 100 seeds. osis-crdt tier 1 binary about a quarter less, back to back at load 10-26 (98-120 -> 76-89 CPU-s; the differential at `Quick` about 8 CPU-s). Found: a map dot's records pushing a text creation out of `pos` in the record holding it left the two decoders disagreeing on its snapshot (the model also dropped the creation in its dot prune); fixed by spec §3.3 rule 5 (a creation and its position write are one write; a reader holds the pruned form), `implied_creation_pos_decodes_back_spec_3_3`. Hostile snapshots must decode and read as the state.

**8. G5 rotation.** Done: osis-engine `rotation::tests_property` (notes/testing.md, Rotation property), one generator mixing forks, departures, forgeries, holder-actor cycles, a withheld admin and rotators left out of a role, both properties checked on every seed, replacing the seven `_large` harnesses and their tier-1 pinned seeds. The withheld oracle's excuses went: a departed peer's knowledge is what it held or made plus the final boxes, and an epoch is judged only where its rotator saw the peer depart. Four sabotages fail it (testing.md); it passes every seed unsabotaged. Measured at load 15-25: osis-engine lib tier 1 244 -> 230 CPU-s (the deleted tier-1 seed tests 28, the new one 14); the rotation tier-2 set at plain 77 -> 177 CPU-s (100 seeds; the seven harnesses ran 10-20 cheaper seeds each).

**9. G6 ephemeral**, inside the ephemeral redesign (issues/eph-unify.md), not before. One node-level property (holders sharing non-lossy hosts read alike, caps respected); the sim scenarios for liveness only. Delete `random_window_{converges,inflight,one_capped_host}`, `random_churn_converges`, `ephemeral_reverts_{within_rights,with_restarts}`, `memory_random_*` x3, `many_authors_under_host_rates` (12 min in dev; rates become a counted-work check, step 10).

**10. Scale counts work.** Done. Every scale check is a tier-1 debug test counting work at n and 10n (cost spans by count, engine and perm counters, `PassStats`, `MemoryBackend::io` bytes written, byte sizes) against `flat` (2x + 2) or `linear` (15x + 15); notes/testing.md Scale checks lists them. Byte budgets stay; RSS checks are by hand (node `memory::`, label `multi_gb_value_streams`); `cargo bench` stays the by-hand timing kind. The paged text check is tier 2 (a 700k-char text takes 11 s to write in debug). The three broken checks were test bugs: the set and text ones reopened the engine with one fixed rng seed, so every session drew the same nonce and its commit failed `Permission` (`LocalPeer::restart` mixes the open count in); the roster one wrote an ill-typed `secrets.0` history key. Violations found are `repro_*` naming their issues: text-move-loads-placement, kill-judges-label-entries, purge-flip-rebuilds-per-request, invalid-arrival-replays-aspect, role-history-join-cost, perm-eval-cost; covered-cost-whole-snapshot has no counter that sees its walk yet.

**11. Tier-1 slow tail.** After steps 2-8, measure each binary's tests alone (`RUSTC_BOOTSTRAP=1 <binary> -Z unstable-options --report-time`, CPU-s by `/usr/bin/time`) and shrink, merge, move or delete every test over about 1 s. Known: osis `port_clients::client_session_differential_against_grants`, node `shred_sync::purged_synced_body_crash_safe` (forensic attack per crash point), `wrap_poison::useless_*`, proto `slow_link::bulk_over_slow_link`, chat `flows::new_node_of_a_participant_sees_history`, `encodings::big_list_insert_fits_blobs` (8 MiB), host `ephemeral_churn_keeps_durable_cursors`, base `decode_peak_within_the_bound`, `write_ops::commit_equals_single_op_commits`, `tied::*`, `inbox_life::{pending,burst}_grants_*`. Levers that worked: fewer, larger elements where a size threshold is the point; a config knob for a batch size; one clock jump past a lifetime; cpuprof before guessing. Easy wins: shared starting network cloned per test; rules tested at the engine or perm layer, a full `Net` only where sync is the point; the debug re-decode on every `secrets_in` cache hit (22% of osis `it`) moved into `Engine::recheck`. Done: no tier-1 test over about 1 s alone on a quiet box.

**12. Derived selection.** A tool computes a branch's reviewer set: every property test (at `plain`) of the crates its paths touch and their dependents in the Cargo graph, plus the sim scenarios of those crates. Three of the last periodic run's six bugs were tests no per-branch list named; derived selection removes that class. Deletes the per-branch list in notes/testing.md Tiers. Done: `tools/gate.sh --plan` (or a sibling) prints the set; testing.md and coordination.md rewritten to this organization (below).

Any time, small: a deterministic test of `close` on `Runtime::Tokio` (notes/api.md Handle and sync: after `close` returns no driver poll touches a timer of a shut-down runtime). The one race test catches a removed `net::wait_ended` about a third of runs and a removed `quiet` gating in `run_host` never; `num_alive_tasks() == 0` after `close` is wrong (the task is released after the guard drops). Needs a seam: a hook holding the driver inside an engine call while `close` runs, released after shutdown began. Also judgment vectors still missing: linked header lists (an aspect list past `CHUNK_THRESHOLD`, about 300 KB of hex) and the secrets-side rotation scenarios (core/test/vectors/README.md).

Follow-up, the `waited_at_expiry` excuse: it spares any read on an aspect a part may have waited at its expiry on. Tighter would accept only the oracle's read or the read without the waited parts, but it is not simple: the set is "may have waited" (the ready rule is conservative), so a node may hold any subset of those parts applied, and a keep-everything node given the packs without them counts them missing and refetches them, where a part gone at T is never received. Needs an oracle that drops a part at T as the node does, and per-part readiness from the history. Until then the drop rule is checked by `held_set_decides`'s `reopens_alike` (no excuse) and `waits::part_waiting_at_expiry_goes_whatever_the_ticks_spec_commits_5`.

## What notes say after the steps
- **testing.md**: Tiers becomes the kinds table above (tier 1 = examples + properties at `quick`; tier 2 = properties at `plain`/`full` + real-socket tests; tier 3 = models, system breadth, timing, fuzz). The per-branch list goes (step 12); Seed runners loses the `_large` twin rule and table for the size knob; Arrival-order differential shrinks to `held_set_decides` and its oracle; TLC is `run.sh <module>` by the branch that edits a module.
- **coordination.md Test budget**: reviewers run the derived set at `plain`; no `OSIS_FULL` runs per branch except once for a new or rewritten property; "add up the oracle set's CPU-s" goes.
- **coordination.md Periodic checks**: before a release only, properties and the sim at `full`; the command list becomes one tool call per component; after a design step, that component's properties at `full`.
