# Engine: receiving and writing commits
> Summary: How the engine examines, pends, applies and re-examines commits (`apply/mod.rs`, `apply/waits.rs`, `apply/carriers.rs`, `apply/atomic.rs`) and what its writer refuses: sessions and counters, the HLC and clock, how a part waits alone, missing evidence and chain depth, junk and bad parts, faults setting their unit aside, late parts, carriers and the one parking place, the writer-side rules, and apply costs. The rules themselves are spec/commits.md §2-§4; this note says how the code keeps them. Not here: validity and re-judging (notes/engine-validity.md), retention on apply (notes/engine-retention.md), role commits (notes/engine-roles.md), streamed joins (notes/engine-paged.md).

## Principle
What applies is a function of the parts held and everything else held, never of arrival order or which parts came together. A header or signature fault refuses the commit; each part is judged alone from the signed header, its bytes and held data; a wait ends as the held set grows, and a validity falling (a step's `sync.0` write, an edge write a path rests on) can start one again: an applied commit whose every held part turns unjudgeable pends again, so what applies is one result for every order (osis-engine `order::held_set_decides`). What cannot be judged yet waits in one place.

## Sessions, counters and the HLC
- **Counters** (spec/crdt.md §2.1): every content commit writes under this open's session (`Core::session`, a random nonce per `Engine::create`/`open`); expiring memory commits under a second one (`Core::expiring`), so an expired commit forgotten with its counters leaves no gap in `session`'s ranges that a snapshot frontier could not pass. Counters per (aspect, session) are memory overlay rows (`Transaction::counter`/`reserve_counters`, never on disk, rolled back with an aborted transaction), reserved in the transaction that applies the signed commit.
- A restored or cloned store is a new session, so nothing it writes overlaps what the lost or sibling copy wrote: no restore gate, no counter adoption, no `OverlappingCounters` on honest nodes. Two live copies still answer for one dialable key (its `dial.0` entries) and LAN tag: a connectivity flap (LAN receivers keep the first source address they verified), not a correctness problem. Rejected: counters per (aspect, node) with a restore gate (one frontier entry per node that ever wrote an aspect in every later snapshot, two live copies void each other, and a lying frontier can push a restored copy to commit form for good).
- When an own write of the current sessions turns invalid, later writes go under fresh sessions past the hole (`Core::fresh_session`: same random first 8 bytes, next count), with an `OwnWriteInvalid` diagnostic.
- Role commits and snapshots are commit form (`write::commit_in`, `retention::write_snapshot`); `Mutation::commit_form` asks for it on a content commit.
- **HLC** (`engine/clock.rs`): a writer exhausting `logical` within one ms moves to the next ms instead of waiting. Own dots are written under a zero commit ID placeholder from the start (`write.rs` `own_source`), so the writer's own source sorts above foreign dots (spec/crdt.md §3.3 rule 2).
- **Clock**: every node runs on its own wall clock; nothing a peer sends moves it, so a wrong clock harms only its holder (spec/requirements.md): fast, its writes park elsewhere until real time catches up; slow, it parks others' writes and its own sort early. A node's own commits (`Origin::Local`, signed as any own thing) are never refused for drift: its HLC may run ahead of a clock set back. A peer's clock offset feeds only the `ClockSkew` diagnostic. Rejected: correcting the clock from peers' offsets (a median, a cap, a quorum, own nodes first): any correction lets other nodes move this one, and each bound needs picked numbers and special cases.

## Examining a commit (`apply::examine`)
- A commit pends whole only for drift, its author's epoch or an unresolved header list (the held author's signature is checked first, so a false one costs no list), never for its parts' waits. Its author's or actor's record unknown, or every held part unjudgeable: it pends whole (`Exam::Awaits`).
- **A part waits alone** (`Aside`, `Waiting`) for its pages (`WaitBlobs`), parked, or unjudgeable (`thing_wait`: record, chain, author's reach), in the applied commit's pending copy (`pend_aside`), parked under every record its parts await (`note_awaited`, `Waits::records_of`, read by `waits::wakes_of` whatever the first reason). The other parts apply (as the header alone if need be), so a commit can be applied and listed by `pending()` at once, and whether it applies does not hang on which copy came first (a header-only copy, or a destruction that drops its waiting part and then falls). Only parts the blob holds can wait: a part not held (another's private thing in a mixed commit) makes nothing wait and joins late if it comes. Nothing in apply reads what the node syncs. Accepted cost (notes/whole-commits.md): a node syncing two sync IDs fresh may show one thing's part before the other thing's record arrives.
- **Evidence missing** (`MissingChain`): the author's or a record chain's `created.0` is missing, or an edge of the path the commit states for the part's thing has not arrived (`validity::unreached`: the hops of that one path as the walk reads them, `osis_perm::paths::hops`, each a record edge or set by a held edge write, grant or removal, of any validity, ordered before the part (content at the start of its `ts`, an edge write at its key and place in its commit, `validity::Place`) and not itself unjudgeable). `Held::writes_on` keeps each edge's writes by point; a held write's own wait is judged the same way, recursively (`Reach`): each edge's writes are judged in order up to the first judgeable one, each once per part (`first`), and a judgment reads only strictly earlier writes, so it ends and a part's wait is linear in the writes it reaches (`scale::the_path_wait_reads_each_write_once_spec_commits_4`; rescanning an edge per write reading it was quadratic in forged held writes). A held write can be unjudgeable itself: a `roles.0` part applies when any of its writes is judgeable (a self-removal beside a forged grant). A grant ordered after a part is no evidence its writer relied on: counting it would judge an honest part invalid before its own earlier grant came, and drop its body. No other path is read (spec/permissions.md §1 Path): a signer on the thing's record chain, or reaching it by other grants, waits all the same where the path it states has an edge nobody set. Revoked authors keep their grants' writes, so their commits apply, judged invalid; a re-grant re-merges. A `roles.0` part is read per edge write it makes: it waits while every one is unjudgeable at its own place, a self-removal's path ending at its holder (`validity::writes_unreached`, once the part is decoded, `apply::edge_unreached`; before, `thing_wait` reads it as a self-removal after every write of its commit; a commit with a reset whose creation is not held makes no write yet and is read along the whole path). A thing too deep is not waited for (its deltas are invalid by the records alone). A node's own commit goes through the same wait: an honest writer's path is granted by what it holds, and one stating an edge nobody granted it is refused as `Error::Permission` (`apply_local`); only a hostile test writer (`skip_writer_rules`) applies its own such commit, to send it. A thing whose every held part waits keeps its entry's path key with the waiting copy alone (`Waiting::keys`): the applied record's paths are decided by what joined, whichever copy came first. Waiting commits and parts wake on `Wake::Moved`, which every edge write brings.
- **Chain depth** (spec/permissions.md §1): `validity::too_deep` makes every delta but `created.0` invalid on a thing whose chain is not known to end at a thing minted with a key within `MAX_CHAIN_DEPTH` links (deeper, or a record on it not held: forgetting a record never makes a deep delta valid); per delta, from creation records alone, so nodes holding different parts agree. `thing_wait` stops waiting for the chain there (`ChainStep::TooDeep`). A deep thing's `roles.0` writes never reach perm (`validity::add_role_commit` skips them); the writer refuses such a commit.
- **Junk and bad parts**: a part not hashing to its header entry, or on an aspect of the wrong storage class, is dropped alone (diagnostic) and the commit applies without it; a blob holding only such parts is refused. Hashes are checked before a pending copy is stored where they can be; a commit whose header lists are unresolved, or whose thing's record is away, keeps the first copy of each slot unchecked (a later copy proving itself against its header entry replaces it: `proves`, by the thing's record held or carried by the part itself, so junk sent first never holds a pending commit back). When one proves junk the commit is named (`Core::redeliver`), its name and opened blobs kept even when the junk was all its stored copy held (`retry_pending`), and sync opens every entry naming a blob of it again (`store::follow`), then calls `Engine::redelivered`. A part that hashes but is bad by itself (`judge_part`: the author signed garbage) is dropped alone, unmarked: only those bytes can ever hash there. A node that could open only a bad section holds nothing of that commit; a node opening none applies its header.
  - A slot counting as never received (body dropped, part past its expiry) is not brought back by a held copy: only a new copy does that, or a restart would change what a node reads. A copy with a junk part or signature is no source even for its true parts: a sender holding the true part could withhold it anyway. A true copy deleted everywhere while junk holds the slot waits for a holder's new copy (keeping such copies while the commit pends would let one sender grow one commit's copies by flood-and-delete).
- **Prefix vs header** (spec/commits.md §4 last rule) is checked where a blob is opened (`Engine::open_commit`), its commitment groups only once linked header lists resolve (issues/sync-unbuilt.md); `ingest` takes plaintext.
- **`created.0` minting** (spec/commits.md §2): `carried_records` refuses a durable commit whose `created.0` part is not exactly one minting (`write::is_minting`: one source, one stamp, equal to `mint_created` under the `creation` view); several commits' mintings join. Header validation and `Engine::snapshot` refuse `created.0` in a durable snapshot, so no junk enters a state kept forever. The codec already keeps slots and foreign stamps out of a writer delta; the minting rule adds refusing resets and untyped structure.
- **Role-class content rules** are writer-side only (Writer side): a received commit breaking them is applied, and perm judges each edge write at its point.
- **A fault sets its unit aside** (spec/commits.md §4 No local error from peer bytes): a fault (`Error::is_fault`: local, not a store failure) is a broken invariant of this build, so the work it arose in is left undone until the next open (an upgrade may do it) and told (`DiagnosticKind::Fault`), and the node goes on with everything else. The unit is a piece of work a transaction can do alone (`Engine::take_units`): a commit taken (an arrival with its blobs, pages and carried records; a commit a round wakes, its blob walk included), a tick's due timer or leaving aspect (`retention::TickUnit`), a loose record learned. A transaction takes its units together; one failing with a fault takes each again in a transaction of its own, and a unit whose own transaction faults (its work, or the end work it makes due) is set aside; a fault no unit brings alone is still told.
  - Set aside: a commit pends as `Reason::Fault` (`apply::set_aside`: its stored copy kept, or the bytes it came as, with its blobs and pages), woken only by `Wake::Open`; a timer or leaving aspect waits in `Core::ticks_aside` (memory: an open starts it empty), skipped by the tick and by `next_timer`; a record stays unlearned; a fallen memory aspect's snapshot (`resnapshot_fallen`) waits until it falls again.
  - A unit taken alone does only its own work (`Core::alone`): the commits a thing entering the node closure wakes (`wake_entered`, otherwise examined in the same transaction) go to the next round, each its own unit, so a fault in a commit an arrival brings in never sets the arrival aside. An arrival is one unit: its transaction failing with a fault is tried again alone, and then followed by one that only sets it aside (`Engine::set_aside_arrival`, whose units are the commit and each record it carries). Within a transaction a woken commit's examination is a step (`retry_pending`), so its own fault sets it aside in place, with no split.
  - A store failure still fails the transaction (retried; one acting on work taken out of memory owes a reload). A setting aside that faults itself does nothing but record the unit's own state, so the fault is in the node's held state and fails every transaction alike: the error is returned.
  - One mechanism: a set-aside commit is a pending commit, so nothing held, written or claimed reads it, sync keeps its entry as carrier (`Opening::Pends`) and no peer is blamed. Rejected: a step around every arrival: no store spill while a savepoint is open, so a large streamed apply would grow in memory (`tests_paged::failed_streamed_apply_leaves_nothing_spec_commits_4`). Test hooks: `Core::apply_fault` (in the commit's own step; osis-sync's tests use it too), `Core::end_fault` (at the end of the transaction doing a unit's work); tests `apply::tests_faults`.
- **Which local errors peer bytes can reach** (audited): none known. `retention/bounds.rs` (`Killed::note` at every join, `dated_replaced_at`: a dead write with no superseder held) and the reference counts going below zero (`engine/refs.rs`, `refs/kept.rs`, `tree_refs.rs`) were reachable by forged copies; closed by a write's identity never being its payload (spec/crdt.md §4.8), hiding read from the copies as joined (`osis_crdt::Held`), a set's reach taking the references its records name (`Set::at`), and no wire form for a position or flag write at an element's or embedding's stamp (osis-crdt `tests_model::reach_holds_the_change`, osis-engine `retention::tests_forged`). The checked delta's decode-only reread gives the same pieces (osis-crdt `tests_stream`). A snapshot that cannot be encoded leaves its aspect uncompacted (notes/engine-retention-trigger.md). The other local errors read the node's own store back: store damage only.

## Late parts (`apply::late_parts`, `atomic::join_late`)
A part of an applied commit arriving later: one that waits is kept pending under the commit's ID and joined once it can be; an invalid one joins and un-merges as on apply. Late `created.0` records and `roles.0` parts reach perm as on apply (the commit's edge writes re-added from every held part: a certificate copy may bring `roles.0` after `created.0`), then held deltas are re-judged. Late `secrets.0` parts: notes/engine-roles.md (`secrets.0`, `keys.0` and established epochs). A snapshot part that comes back judged invalid gives nothing: the parts dropped under its cover alone go missing again (`retention::uncover`), as when a held snapshot turns invalid.

## Unjudgeable commits and parts (`apply/waits.rs`, `apply/carriers.rs`; notes/expiry-creation-design.md §3)
- **One parking place** (notes/sync.md Arriving early): what cannot be judged yet, a whole commit or a part of an applied one, is kept in the commit's pending copy while a carrier holds it (spec/commits.md §4 Pending storage) and examined again when what it awaits arrives. A waiting part is never thrown out to be fetched again: sync keeps an entry whose commit `pends` as its carrier (`Opening::Pends`), so an applied commit's part arriving before its record is never lost to an entry already taken.
- **Pending again** (`atomic::pend_again`, after each re-judge, over the commits it judged): an applied commit, not this node's own (spec/commits.md §4: its own counts as an own invalid part, kept; `order::an_own_commit_turning_unjudgeable_stays_at_its_node_spec_commits_4`), holding no valid part and whose every held part (bodies and parts waiting alone) is unjudgeable (`apply::unjudgeable`) is forgotten as never received (`unindex_unreceived`, its pending copy with it) and named for redelivery: sync opens its entries again, so it pends with them as carriers, as a commit arriving then would; with none left it stays never received (Pending storage). Its carriers are learned only so: an applied commit keeps none. Its parts' flags read false already, so no state moves; a role commit's edge writes leave the timelines, and what rested on them is judged again in the same loop. Who triggers it: whoever can make a held write fall (a backdated removal of a step's recorder); each fall re-keys O(commits under the thing) already (`Core::steps_recorded`), and each costs one redelivery per commit so forgotten.
- **Carriers** (`apply/carriers.rs`, rows `pc/`; its module doc has who supplies each and what bounds it): an entry in the sync store (let go by `Engine::release_entry` once no entry in sync's store names a blob of the commit: notes/sync-store.md), a fire held here that carries the commit, or the newest stranded report on a sync ID whose holder keys carry it. At the end of every durable transaction a commit pends only while it has a carrier (`carriers::settle`): the transaction where the last goes forgets its pending copy, and its parts count as never received.
- A commit that cannot be judged (`Reason::MissingChain`, `UnknownCreated`: its author's or actor's record, or every held part's) pends like any other (`Ingested::Pending`): its stored copy keeps every part, its unjudgeable ones included (`note_unjudged` notes their records), with its signature's verdict (notes/engine.md, Signature verdicts).
- `reexamine` examines what is left pending at every call, but skips a commit whose awaited record is still unknown (unless its boxes are due a re-read), so a first sync examines each once more only when its record comes.
- Reading-only secrets a commit's boxes gave are sourced from it (`Waits::reading`, rebuilt at load) and go at its last part's apply (`forget_unchecked`), when it is judged bad, or when its last carrier leaves. A commit with unchecked boxes keeps them until its last part applies. A refused box is read again when the budget frees (`Wakes::reread`).
- Tests with no sync layer keep carriers and fetch through `local_peer::Peer::receive` (a carrier delivered again when `take_redeliver` names its commit; every copy taken kept as sync's store keeps entries, `Peer::entries`, and opened again when it names one neither held nor pending; a copy of a missing part when `Wakes` names it); `Peer::tick` and `Peer::reexamine` run them too. Test peers run what is due through those, never `<peer>.engine.tick()`/`reexamine()` (`tools/policy.py`); a test ingesting straight into `engine` (no fetch stand-in) may reexamine through an `&mut Engine` it holds. Tested straight through `Engine::ingest`, each commit given once: waits.rs `every_part_given_once_joins_in_any_order_plain_spec_commits_4` (a property).

## Writer side
- **Writer-side role rules**: at most one `roles.0` grant per role commit (except a redemption's grant plus self-removal, and an explicit removal of several others' grants on one target with a frontier, `revoke_joiner`); a frontier only on a commit that lowers a grant, a removal of an absent or expired grant included; a removal or demotion of another holder on a thing with a `keys.0` keyset carries its `secrets.0` and `keys.0` deltas (its rotation), a self-removal none (`validity::self_removal`: the author's own grant, or admin on the holder with no admin on the target without the holder's grant). A remove + put of one grant counts as its new grant, so a raise carries no rotation. A local commit breaking them, or with any delta invalid here, fails before it leaves.
- **Commit form encoding**: own writes of a commit-form delta are re-sourced to a commit placeholder before encoding (`build_and_apply`), so entries order as a reader decoding with the real commit source orders them (own commit first, spec/crdt.md §3.2); under the signer's own session, foreign dots sharing a map (a link redemption re-writing history boxes) would break canonical bytes.
- `Mutation::dead_resets`: map tombstones for entry dots whatever their liveness (`osis_crdt::reset_entries`: a removal of an absent grant).

## Costs
- **A commit's parts are read once** (`apply::PartsRead`): each `keys.0` part's keysets (`keys::KeysBody`: typed `KeysWrite`, each keyset with its keys parsed, `KeysetRec`) and perm's reading of its `roles.0` parts (`PermParts`) are read on first ask and shared by everything an apply, a late join (`with_held`: late and other held parts, read once for judging and joining) or a rebuild notes from them: required roles and proofs (`note_required`, may-grant grants from `PermParts`), keyset parts, keysets and rotations (`before_join`), perm's edges and the `node/perm` row.
- Counted (osis-engine `scale::`, notes/test-scale.md Scale checks): a grant does the same work with n and 10n content commits held (`grant_is_flat_in_content_commits`); an open from the persisted index rebuilds nothing (notes/engine-store.md). A first sync's ingests grow linearly, each pending commit examined again a fixed number of times (without the wait cache every pending commit would be examined again after each applied one, quadratic): `scale::a_first_sync_is_linear_spec_commits_4`.
