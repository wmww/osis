# Properties and models
> Summary: The big randomized properties (the held-set property `held_set_decides` with its held-model comparison, the rotation property), the independent models (crdt-model, roles-model, held-model, TLA+ and how to run and extend them), conformance vectors and fuzzing. Running and replaying seeds: notes/test-harnesses.md; the simulator: notes/test-sim.md.

## Held-set property (osis-engine `tests/it/order.rs`, `held_set_decides`)
What a node shows is a function of the commits it holds (spec/requirements.md Deterministic). One test, one generator, sizes as a knob; each node is judged against the node holding the same commits and keeping every body, and against held-model, so orders agree because each node equals them.
- **Generator** (`generate`): random histories on three `LocalPeer`s (0 is G's first admin, 1 writes, 2 admin). Seven feature groups (general `random_step`, purges, keeps, history settings, record-only things, sequences, parts), each on its own rng stream so a change to one leaves the others' steps as they were. Steps are `Step::Aim`ed at an author and thing that can write them (an undo at a commit a revert writes, `Engine::check_revertible`). After every step each writer re-snapshots for the purges it applied, as sync does (`Engine::purge_resnapshots`): a part missing when purged (dropped while invalid and valid again in the walk that made the purge stand) counts as never received and is not fetched, so only that snapshot makes the node read as its holders (`purge_of_a_part_dropped_while_invalid_reads_alike_by_the_resnapshot_spec_commits_5`). The seed picks an emphasis (`Emphasis`, seed % 8: purges, keeps, settings, record-only, lists, parts away, settled, addenda) that weights its group fivefold and starts with a setup reaching its outcome, then `HeldHere`: what was made so far is a held set of its own, so that outcome is judged whatever later steps do to it (a later removal can invalidate a start's purges or revive its fallen setting); parts away (`Cfg::away`), settled (`settled`: every writer compacts every aspect last, delivered as made) and addenda (`play_with`) shape the whole history. Every history ends in `Removals` (deletes, writes into a deleted element, undeletes).
- **Orders** (`ORDERS`): held sets are the whole set, a first sync part way, and partial sets. Each goes to fresh nodes as made, reversed, as fetched (`fill_order`), every order when small, shuffles; with late parts (`deliver_split`: only for a held set with a multi-aspect commit); in part at an earlier clock (`clock_of`, so drift parks). Every judged node runs sync's covered drops after each ingest and tick (`drop_covered`), and in clocked orders held-model judges each drop (`held::Drops`). The whole set's first two orders are also delivered reopening after every ingest (`reopens_alike`).
- **Sizes** (`Size`): `quick` (default tests: seeds 0..8 of 32 steps, and 100..108 capped to 3 commits in every order; no environment), `plain` (80 seeds of 60 steps at `OSIS_FULL=1`, a tenth by default), `exhaustive` (80 seeds capped at 6 commits, every order of every held set, the named three orders and a quarter of the rest (`TWIN_SHARE`, drawn from the seed and held set) again with late parts, 24 clocked). The default test keeps every order's twin: its seeds are fixed, so a share would leave the same orders untried for good. Seeds and each seed's orders run on every core (`testenv::pooled_map`). Env vars: notes/test-harnesses.md.
- **Oracle** (`node_checks`, from the API only): every aspect's read and every thing's roster, now and two hours later, after the node's sync exchange (`fetch_missing`: every commit the node itself counts a part of missing comes again, as sync's refetch). The one excuse, from the history: an aspect a commit expired by `played.now` lists (`expired_by_now`, spec/requirements.md Decentralization (the arrival-order limit)); about 1% of compared reads. Rejected: a precise excuse accepting only the keep-everything read or a reference given each commit at its stamp; a node in another order can read a third value (a part valid at its arrival applied and expired value-less where every reference dropped it waiting), so no fixed set of references gives the outcome. Before the exchange only settled histories are compared (`Played::settled_last`). Every node takes the walk's side in each dispute it detected (`deliver_with`). Also per node: P3 `value_past_end`, the permission index against its walk from scratch (`perm_digest`), held-model, and every plain order judged anew alike after a reopen (`misjudged`). Held bodies, states, pending sets and death dates are compared nowhere: **a seed where bodies or states differ but what nodes show agrees is not an issue.**
- **Coverage tally** (`Seen::floors`, derived from the run's size): every run judged nodes against both references and tried late parts on every held set with a multi-part commit; each emphasis reached its outcome; a run with every emphasis reached every step kind, an invalid part, a waiting commit, a judged signal, a clock move, purged or expired deltas judged, a reopen, a sync exchange bringing content back, and (`held::REMOVALS`) a list element reset, a write above its reset, a winning text undelete and a removed set value.
- **Cost** (each alone under the lock): the default test about 280 G instructions; plain (8 seeds) about 600 G, 300 CPU-s; exhaustive (8 seeds) about 1250 G. Seeds differ fourfold. Late parts dominate exhaustive (each wakes and judges again what waited on it). Orders as made start from a copy of the setup's node (`Played::setups`); copying for late-parts orders too saved nothing and held six times the memory.
- **Scripted examples** beside it are minimal reproducers in named orders (`NAMED`: as made, reversed, as fetched; or explicit ones), each naming the rule it pins; open issues' replays are `repro_*`. A failure prints the `check(seed, &h, cfg)` it failed under; an issue pastes it whole. A shrunk history can pass under `NAMED` alone: a held-model difference needs `model: true` (`Cfg { model: true, ..NAMED }`), and one seen only in clocked or parts-away orders needs `clock`/`away` too; the reproducer keeps what it needs and is checked to fail with its fix undone.

## held-model comparison (`tests/it/held.rs`, `Cfg::model`)
Every node `held_set_decides` judges is converted into held-model's input and compared on what a user observes: applied commits (role commits too), validity, which edge writes apply, every known thing's roster, reads, no forbidden value held, no purge-on-replace body held that a right holder's held snapshot covers, and promised history: a node never drops a body the settings it holds keep in history, nor a live one before its aspect's live bound (spec/commits.md §5 Kept while live). Keep for D's dating rule is checked by the scripted `held::keep_for_d`. Every difference is tallied by kind (`Coverage::differs`); the first fails the test.
- **Input**: every held commit and known creation record, undo, acting, invites, `until`, self-removals, finalizes and addenda as the node's role input holds them (`ix.held`); bodies as crdt-model fragments decoded from the engine's wire bytes; history is the thing's `retention^.0` settings (`Delta::Retention`); a body dropped for its bounds is fed as missing, one dropped as covered as `Body::Dropped(cover)`. Byte-functions are cached per history (`held::History`).
- **Scope**: every content aspect of every encoding. Left out, counted by reason: paged, ephemeral, waiting for blobs or parked, the node's own writes from outside the history, and every aspect when the role input is outside the model (a role-class snapshot, a role frontier not inline, a role commit carrying parts outside the model: notes/test-design.md, Small items). Not compared as reads: `keys.0`, `secrets.0`, `label.0`, `created.0`, `retention^.0`, `addenda.0` (issues/held-model-setting-reads.md).
- **Seen to bite** at `quick`: reversed list reads; a held text delete beating a later undelete; a list element shown above its reset; a set element's content kept under its own reset; a roster showing write as read.

## Rotation property (osis-engine `rotation::tests_property`)
No departed holder reads later content; every holder ends reading everything (spec/crypto.md §4, spec/permissions.md §2-§3). `rotation_holds_spec_crypto_4` (default, seeds 8..16) and `rotation_holds_large_spec_crypto_4` (100 seeds, `OSIS_FULL=1` 1000, `OSIS_ROTATION_START`/`_SEEDS`; about 1.5 CPU-s a seed). `OSIS_ROTATION_DUMP=1` on a leak prints a peer and actor legend, how the epoch was made, and the way the peer opens it (each box with its keyset, the step its state was first met, stale or within the limit), settled and over every state met.
- **Generator**: five peers, actor G with every other peer at a random role; with holder actors (seed mod 4 = 3, else one seed in six) more actors granted roles on each other around a cycle. Rounds of random removals, demotions, self-removals (a forging writer, hostile after), `secrets.0` compactions, grants, `until`s, re-grants, rotations leaving members out or boxing nobody (a vandal, hostile after); partial or full syncs between rounds, so rotations fork and unaware demoted rotators make invalid rotations. Then an admin re-seals and rotates every actor; an honest admin removes every hostile peer (the Lockouts recovery, notes/crypto.md); everything syncs, every node takes the walk's side in each dispute, and every node re-seals and rotates until nothing is written (16 rounds bound). The seed's emphasis (forks, departures, forgeries, holder actors) weights the draw; `tally` asserts every shape is reached in any run of 8 seeds or more.
- **Oracle**, per actor at its first admin: nothing blocked, every holder with key access boxed; every holder counts and has established the current epochs the first admin does, and holds the secrets its role's holders hold. Leaks: a peer without access to role r at the end opens, from every secret it ever held and the final boxes, neither the epoch a remaining writer encrypts under (unless blocked there) nor any epoch whose rotator held its departure and saw it below r (a peer reading a holder actor the epoch boxes or proves at r is not below it; where the rotator held no secret of a boxed actor, the stated limit for an epoch whose secret the sealer lacks applies). No other excuses. A failure prints the history and when the peer first held the secret.
- **Seen to bite** (each sabotage alone, 200 seeds): the re-seal trigger looking only at the newest fork; history adds off; establishment without names met; an invalid rotation's epochs kept established. Not caught: coverage by any author's entry (`publishes` also asks that the author hold the role), the blocked walk ignoring stale and keyless holder-actor boxes (the `tests_members` examples catch it), entries covering without a keyset publishing them.

## Models (core/test/)
Independent oracles: written from spec/ (never from code), never depended on by the implementation, never patched to match it.
- **crdt-model**: the reference CRDT (notes/crdt.md, Reference model). Differentials: osis-crdt `tests_model` (join, wire, strip and un-merge; the one crdt property, notes/crdt.md Tests) and `tests_decoder.rs`.
- **roles-model** (src/lib.rs): per model `walk(h)` (pure), `random_hist`, `quiescent(h)` and a `Display` trace; `shrink::shrink` reduces a failing history to a 1-minimal one. The searches print counterexamples shrunk. Run by hand through `tools/heavy`: `cargo run --bin roles-model -- 2000000 joint|edges|disputes`, `-- 1000000 addenda` (4 min on 16 threads), `-- 0 addenda-exh` (11 min), `-- 800000 epochs`, `-- 0 epochs-exh`, `-- 0 epochs-exh-c` (each within one `heavy` hold); sizes and results in core/test/roles-model/README.md. `-- N digest` hashes every verdict of N random histories per model (stable within one toolchain); a refactor keeps it: at 1,000,000 joint e29ad7c11da132ca, edges d51880160a427893, edges-prov 609e565eb98bc3c8. Differentials: osis-perm `tests/it/differential.rs` (the walk, trust sets against `roles_model::trust::side`, addenda against `roles_model::addenda`, the account epoch rule against `roles_model::epochs`).
- **held-model**: what a node holding a body set reads, written from spec/ alone (purge, expiry, validity, apply) and, for history, from notes/engine-retention-history.md; its values are crdt-model fragments. The reference of `held_set_decides` (held-model comparison above). Every drop is a cover, purge, expiry or invalidity; it judges only what users observe. Its AMBIGUITIES.md is the rule backlog.
- **TLA+** (core/test/tla/): `sync` (one label at one host: upload, download, deposits, deletes, expiry, compaction, purges, snapshots, tombstones, offline nodes, a misbehaving host), `rotation` (read-role rotation of one actor; the directory also holds Depth0, Finalize, Cover, Lockout, Merge and other read-role models), `net` (the networking rework: node-wide log, shared sets, a peer that cannot read, opens, hold/log/delete per sync ID, destruction and emptying, a node keeping S unread; written before the build), and `sides` (a design exploration of an admin dispute, not from spec/ alone; `matrix.sh` runs every scenario under every mode). Each README gives instances, results, state counts and times; each AMBIGUITIES.md the findings.
  - Run by hand when TLA or its spec sections change, never as part of a bigger thing (models read no code: rerunning an unchanged model finds nothing): `core/test/tla/run.sh <module>` (modules in run.sh's header; each under 3 min at one worker except `depth0`, 15-23 min (`D0_nc3`, `D0_gone_live` 400-510 s each); a module name maps to one .tla, so a new .tla takes a module name of its own; `TLC_WORKERS` sets workers, more than one through `tools/heavy`; a hand `-metadir` on disk, never under tmpfs /tmp). It downloads the jar to `~/.cache/tla`. Each module checks safety on every listed instance and liveness on one, and keeps a negative control (or open finding) that must fail; the script exits non-zero on any other result. Larger instances by name: `run.sh <module> <cfg>...`. Size a new or grown by-hand instance first by a one-worker run of a minute, unlocked (its state count and queue growth say the size); then one instance per `tools/heavy` call, each under the `heavy` hold limit (`tools/limits.py table`: about 440 s wall on fastbox-0) with a third to spare, never several instances in one call: gates queue behind a hold, and one hour-long TLC hold kept four agents waiting about an hour each.
  - Not covered by the TLA+ models: record edges removed by their own admins, several labels or hosts, sections and certificate copies, retagging, parked bodies and unfetched pages, clock skew, delete levels, purge classes, nodes offline past `ROLE_KEEP`, connections and timeouts, signals; write and admin rotation, keysets and departures inside a holder, demotion and `until` in rotation, steps without rotation, entry boxes and key actors, `label.0`/`secrets.0` compaction, the stale-view carrier race.
  - **A new TLA+ target**: a fresh agent given spec/ and the target's sections only (never notes/ or code) writes the model under `core/test/tla/<target>/` with a README (instances, results, times), an assumptions list and an ambiguity list; crypto as access (secrets as set membership, boxes as edges); 2-3 nodes, 1-2 hosts, tiny bounds, symmetry sets; safety as invariants, liveness under weak fairness of honest steps; each property cites its spec sentence. Findings go to spec first, then the model follows the fixed text and reruns. TLA+ when notation independence matters and the state is small; stateright when an actor-shaped model would also serve the simulator.

## Conformance vectors (core/test/vectors/, osis-vectors)
- Format, subjects and rule IDs: core/test/vectors/README.md. `.vec` text records of `key: value` lines; every case has `case` and `spec`; `pending: <reason>` marks a case not yet checked.
- Only `cbor/values.vec` and `padme/padme.vec` are files, hand-written, each with a checker. Every other subject is a generator (`core/test/vectors/src/subjects/`, fixed inputs: seeds are 32 repeated bytes) run in memory by its test, so its asserts check the implementation. No generated output is tracked (Tess): before the wire format is stable a committed vector only compares the implementation with its own earlier output; the generators stay so a stable release can write files out. Waiting on Tess: `blob/blobs` (the pending commit blob case), `inbox`.
- **Adding one**, in the change that lands an encoding: a generator `fn() -> VecFile` in `subjects/<subject>.rs` asserting what it computes, added to `subjects::GENERATED` and `generated!` in core/test/vectors/tests/vectors.rs, the crate as an osis-vectors dependency. Rejections use the README's rule IDs.
- **Judgment vectors** (`judgment/`): a bundle of labels' bodies, blobs, read secrets, clock and arrival order in; per body validity, held/dropped/missing, covers, rosters, state and read digests out. Generated in osis-engine `tests/it/judgment.rs` (histories by `order::play`); `judgment_vectors_spec_permissions_5_2` checks each file's shape and replays it through a fresh engine; `judgment_vectors_can_fail` (by hand) checks a changed verdict fails.

## Fuzzing (core/test/fuzz/, outside the workspace)
core/test/fuzz/README.md: running, the target table, adding a target, crash handling. `cargo +nightly fuzz run --fuzz-dir . <target> -- -max_total_time=300` per target; crash inputs land in `artifacts/`. `seq_ops` (`arbitrary` op scripts replayed by osis-crdt's `fuzz_seq::replay`, built with `--cfg fuzzing`, which also turns on the crate's test-only checks) needs no seeds; others are seeded by `cargo run -p osis-vectors --bin fuzz-seeds` (the untracked `corpus/`). A target per parser of peer or disk bytes; a crash becomes a regression test in the crate the code lives in, citing its spec section and `fuzz: <target>`.
- Panics: the workspace denies `unwrap_used`, `expect_used`, `panic` and `indexing_slicing` in every library crate (allowed in tests, the cli binary, and two commented one-line exceptions). Casts on peer numbers are checked by hand; fuzzing runs with overflow checks on.
