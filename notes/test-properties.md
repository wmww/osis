# Properties and models
> Summary: The big randomized properties (the held-set property `held_set_decides` with its held-model comparison, the rotation property), the independent models (crdt-model, roles-model, held-model, TLA+ and how to run and extend them), conformance vectors and fuzzing. Running and replaying seeds: notes/test-harnesses.md; the simulator: notes/test-sim.md.

## Held-set property (osis-engine `tests/it/order.rs`, `held_set_decides`)
What a node shows is a function of the commits it holds (spec/requirements.md Deterministic). One test, one generator, sizes as a knob; each node is judged against the node holding the same commits and keeping every body, and against held-model, so orders agree because each node equals them.
- **Generator** (`generate`): random histories on three `LocalPeer`s (0 is G's mint admin, 1 writes, 2 admin). Seven feature groups (general `random_step`, purges, keeps, history settings, record-only things, sequences, parts), each on its own rng stream so a change to one leaves the others' steps as they were. Steps are `Step::Aim`ed at an author and thing that can write them (an undo at a commit a revert writes, `Engine::check_revertible`). After every step each writer re-snapshots for the purges it applied, as sync does (`Engine::purge_resnapshots`): a part missing when purged (dropped while invalid and valid again in the walk that made the purge stand) counts as never received and is not fetched, so only that snapshot makes the node read as its holders (`purge_of_a_part_dropped_while_invalid_reads_alike_by_the_resnapshot_spec_commits_5`). The seed picks an emphasis (`Emphasis`, seed % 8: purges, keeps, settings, record-only, lists, parts away, settled, addenda) that weights its group fivefold and starts with a setup reaching its outcome, then `HeldHere`: what was made so far is a held set of its own, so that outcome is judged whatever later steps do to it (a later removal can invalidate a start's purges or revive its fallen setting); parts away (`Cfg::away`), settled (`settled`: every writer compacts every aspect last, delivered as made) and addenda (`play_with`) shape the whole history. Every history ends in `Removals` (deletes, writes into a deleted element, undeletes) on a thing of its own, held also as a set of its own with the setup (`Played::own_sets`): held-model judges it even where a waiting role commit (a part held away for good) takes every other held set out of its scope, so the per-emphasis removal floors hold by construction.
- **Orders** (`ORDERS`): held sets are the whole set and partial sets (a first sync part way, then without one writer or a random third: `held_sets`), then the history's own. Each goes to fresh nodes as made, reversed, as fetched (`fill_order`), every order when small, shuffles; with late parts (`ingests` with a split: only for a held set with a multi-aspect commit); in part at an earlier clock (`clock_of`, so drift parks). Every judged node runs sync's covered drops after each ingest and tick (`settle`), and in clocked orders held-model judges each drop (`held::Drops`). At each delivery's end the wakes have missed nothing a full scan of the pending commits applies (`finish`, `Engine::lost_wakes`; a scan after every ingest cost a quarter of plain, and planted wake losses that no scan caught at either place are caught by waits.rs and the scripted examples). The whole set's first orders are also delivered reopening after every ingest (`reopens_alike`).
- **Delivery tree** (`Tree`, `walk`): a seed's deliveries without a clock (each order as it is and with late parts, the rests, the reference) are one tree of moves; a shared prefix is ingested once, by one node copied (`Peer::copy`, exact) where deliveries part, and the tasks run on every core, newest first (`pool`). A late-parts pick is drawn from the moves before it, so a twin shares its order's prefix up to its first split commit. `tree_ends_are_fresh_deliveries` holds every end byte for byte to a fresh replay (stores, indexes, reads, pending and thrown-out commits); a failure on the way to a branch is the result of the first end below it (`Tree::first`). The walk is over nodes up to equality (`node_key`: the store's rows, indexes, reads, pending and thrown-out commits, clock; every move and check is a function of the node): an end is judged once per class (an order's checks with its reopen, or `node_checks`, and its oracle) and node, a branch walked once per shape (`Tree::shape`) and node; the rest count as `alike`. Orders converge: at the exhaustive size about 9 in 10 ends are alike (two fifths of its cost saved), at plain almost none (a key costs about 2%). Clocked and reopening deliveries run alone: each moves its own clock.
- **Sizes** (`Size`): `quick` (default tests, a covering set, each emphasis once: seeds 0..4 of 16 steps (the emphasis start sets most of a history), one order of each kind and three partial held sets; and 100..104 (the other four emphases) capped to 3 commits in every order of every held set; no environment), `plain` (80 seeds of 60 steps at `OSIS_FULL=1`, a tenth by default), `exhaustive` (80 seeds capped at 6 commits, every order of every held set, the named three orders and a quarter of the rest (`TWIN_SHARE`, drawn from the seed and held set) again with late parts, 24 clocked). The default test keeps every order's twin: its seeds are fixed, so a share would leave the same orders untried for good. Seeds and each seed's deliveries run on every core (`testenv` permits). Env vars: notes/test-harnesses.md.
- **Oracle** (`node_checks`, from the API only): every aspect's read and every thing's roster, now and two hours later, after the node's sync exchange (`fetch_missing`: every commit the node itself counts a part of missing comes again, as sync's refetch). Every pass end (a delivery's, the exchange's, the oracle's: `pass_end`) releases what left the node closure, as sync does with no source in flight (spec/sync-set.md §3), then settles needs: without it a thing a strong held for a while stays and one never held goes. The one excuse, from the history: an aspect a commit expired by `played.now` lists (`expired_by_now`, spec/requirements.md Decentralization, Deterministic); about 1% of compared reads. Rejected: a precise excuse accepting only the keep-everything read or a reference given each commit at its stamp; a node in another order can read a third value (a part valid at its arrival applied and expired value-less where every reference dropped it waiting), so no fixed set of references gives the outcome. Before the exchange only settled histories are compared (`Played::settled_last`). Every node takes the walk's side in each dispute it detected (`deliver_with`). Also per node: P3 `value_past_end`, the permission index against its walk from scratch (`perm_digest`), held-model, and every plain order judged anew alike after a reopen (`misjudged`). Held bodies, states, pending sets and death dates are compared nowhere: **a seed where bodies or states differ but what nodes show agrees is not an issue.**
- **Coverage tally** (`Seen::floors`, derived from the run's size): every run judged nodes against both references and tried late parts on every held set with a multi-part commit and in every emphasis's seeds; each emphasis reached its outcome; a run with every emphasis reached every step kind, an invalid part, a waiting commit, a judged signal, a clock move, purged or expired deltas judged, a reopen, a sync exchange bringing content back, and (`held::REMOVALS`) a list element reset, a write above its reset, a winning text undelete and a removed set value.
- **Cost** (instructions, each alone under the lock at `OSIS_ORDER_START=0`; each size prints its ingests, copies and alike ends): the default test about 255 G (9,200 ingests); plain (8 seeds) about 1,360 G (65,400 ingests); exhaustive (8 seeds) about 1,520 G (59,000 ingests, 2,960 copies, 5,336 of 6,035 tree ends alike). Seeds differ fourfold; the settled seed bounds the default's wall. Ingest (the engine's apply) is most of a delivery. Then, in exhaustive, every tree node's drop check (`Engine::check_index`: a quarter, on alike ends as on judged ones) and `node_key` (a twentieth); in plain, clocked orders (a quarter, three fifths of it held-model after every ingest) and the ends' checks (a third, of it the drop check a third). `node_key` leaves the indexes out: each node's drop checks them against its store.
- **Scripted examples** beside it are minimal reproducers in named orders (`NAMED`: as made, reversed, as fetched, never reopening after every ingest, which is the generator's check; or explicit ones), each naming the rule it pins; open issues' replays are `repro_*`. A failure prints the `check(seed, &h, cfg)` it failed under; an issue pastes it whole. A shrunk history can pass under `NAMED` alone: a held-model difference needs `model: true` (`Cfg { model: true, ..NAMED }`), and one seen only in clocked or parts-away orders needs `clock`/`away` too; the shrunk history is a debugging aid: the reproducer is written by hand with only what the bug needs, and is checked to fail with its fix undone.

## held-model comparison (`tests/it/held.rs`, `Cfg::model`)
Every node `held_set_decides` judges is converted into held-model's input and compared on what a user observes: applied commits (role commits too), validity, which edge writes apply, every known thing's roster, reads, no forbidden value held, no purge-on-replace body held that a right holder's held snapshot covers, and promised history: a node never drops a body the settings it holds keep in history, nor a live one before its aspect's live bound (spec/commits.md §5 Kept while live). A drop is judged by the body as last seen held; one last seen on an out-of-scope aspect (fed to the model empty) by its body read then (`held::unread_body`), so its drop is judged once the aspect is in scope. Keep for D's dating rule is checked by the scripted `held::keep_for_d`. Every difference is tallied by kind (`Coverage::differs`); the first fails the test.
- **Input**: every held commit and known creation record, undo, acting, invites, `until`, self-removals, finalizes and addenda as the node's role input holds them (`ix.held`); bodies as crdt-model fragments decoded from the engine's wire bytes; history is the thing's `retention^.0` settings (`Delta::Retention`); a body dropped for its bounds is fed as missing, one dropped as covered as `Body::Dropped(cover)`. Byte-functions are cached per history (`held::History`).
- **External fires**: the adapter passes `ExternalFires::Enabled` (a fire by a party holding no write is valid only while the current setting enables its signal), as the engine judges.
- **Scope**: every content aspect of every encoding. Left out, counted by reason: paged, ephemeral, waiting for blobs or parked, the node's own writes from outside the history, and every aspect when the role input is outside the model (a role-class snapshot, a role commit carrying parts outside the model: notes/test-design.md, Small items). Not compared as reads: `keys.0`, `secrets.0`, `sync.0`, `created.0`, `retention^.0`, `addenda.0` (issues/held-model-setting-reads.md).
- **Seen to bite** at `quick`: reversed list reads; a held text delete beating a later undelete; a list element shown above its reset; a set element's content kept under its own reset; a roster showing write as read.

## Custody differential (osis-engine `rotation::tests_custody`)
The engine's account nodes and readers against roles-model `custody` (spec/permissions.md §5.4-§5.5, spec/crypto.md §9): real `LocalPeer` engines as the model's parties (A, B, C, X, T of account P; R1 a writer of P's thing t, so t keeps epochs of its own; R2 a reader whose user switches; Z a bare peer X seals as) play the model's random worlds (random and lockstep schedules, B offline and unaware, C apart removing T, X with every header and boxed key: forks, revokes, adds Z or itself, takes, withholds, answers, certifies merges, re-seals, writes; the settle with P's users switching back; where C removed T, A re-adding T in the settle through the real pairing, `Engine::pair` then `paired` at T, as the model's `readd`: where the model waits for A's line to carry the removal and would merge, the pairing merges first and pairs on the merge; where it cannot merge, the pairing is refused making nothing). Every engine commit the model knows is mirrored into a `custody::World` (plain rotations, certificates read from their tips, seed boxes including those a box carries besides its first, t's rotations and writes) with the engines' receipts and commit-ID ties. After each tick, per observer: rotations held with chain, merges held, counting epochs, heads, preferred head, warning; at P's nodes the revocations taken (only grow but at a switch), D's roster, the seeds held and what they derive (custody, only growing); t's own epoch secrets only grow; a write the model counts counts; a switch takes. Before each honest act, `custody::act` on a copy: the plain rotation (signed at, removes, takes, answers as epochs, boxed) and certificate (joined line, boxed) must be the engine's, each model re-seal the engine makes, t re-keyed where the model re-keys it, writes at the model's head. Settled: bounded rotations (a re-add an event), one epoch per tip set, secrecy (X holds no seed of an epoch an honest node made where X's removal is taken), warned, one head on the honest side whose seed X lacks, every honest write counts (on t too), no X write after its removal counts but one an honest node of P held before the removal (spec/permissions.md §5.5), none rotating in the last round, a re-added T on A's roster and its own. `engine_agrees_with_custody_model_spec_permissions_5_4` (default, seeds 0..4, about 10 CPU-s) and `engine_agrees_with_custody_model_large_spec_permissions_5_4` (200 seeds, about 2,100 G instructions, the costliest engine property: 60% delivery, of it the engine's apply, re-judging validity and dating replaced parts, 23% the engines' acts; `OSIS_FULL=1` 2000, `OSIS_CUSTODY_START`/`_SEEDS`; trace with `CUSTODY_TRACE=1`, index checks per delivery with `CUSTODY_PROBE=1`, both with `--nocapture`). Controls by hand (`control_*`, each a planted engine fault the differential fails on): `custody_judged`, `roster_bare`, `merge_random` (`merge-carries` has no engine counterpart: such a certificate is bad input; `stale_shut` shuts only boxes arriving after their epoch went stale, which these worlds seldom deliver: `a_box_at_a_revoked_account_epoch_is_read_*` checks it).
- **Seen to bite**: a write at a merge epoch pending for good (the merge's ID is no commit's); a certificate's maker unread where only a joined epoch's seed is held; a node made to leave by a rotation boxing it nothing; a certificate standing with nothing blocking the merge; a switched node not answering the line it rotated on; newcomer boxes carrying seeds of lines beside; a box sealed at an epoch named late (its answered fork arriving) never opened; removed or seed-less nodes signing; a rotation re-taking what its line carries; a re-added node not holding the seeds its held boxes carried before it left (`a_re_added_node_holds_the_seeds_its_held_boxes_carry_spec_crypto_9`); and model gaps (the epoch rule's unrevoked clause, the rejection rule's rotations signed at the rejector's epoch, merges answered, t re-keyed wherever a taken revocation is not carried).

## Rotation property (osis-engine `rotation::tests_property`)
No departed holder reads later content; every holder ends reading everything (spec/crypto.md §4, spec/permissions.md §2-§3). `rotation_holds_spec_crypto_4` (default, seeds 8..16) and `rotation_holds_large_spec_crypto_4` (100 seeds, `OSIS_FULL=1` 1000, `OSIS_ROTATION_START`/`_SEEDS`; about 1.5 CPU-s a seed). `OSIS_ROTATION_DUMP=1` on a leak prints a peer and thing legend, how the epoch was made, and the way the peer opens it (each box with its keyset, the step its state was first met, stale or within the limit), settled and over every state met.
- **Generator**: five peers, thing G with every other peer at a random role; with holder actors (seed mod 4 = 3, else one seed in six) more things granted roles on each other around a cycle. Rounds of random removals, demotions, self-removals (a forging writer, hostile after), `secrets.0` compactions, grants, `until`s, re-grants, rotations leaving members out or boxing nobody (a vandal, hostile after); partial or full syncs between rounds, so rotations fork and unaware demoted rotators make invalid rotations. Then an admin re-seals and rotates every thing; an honest admin removes every hostile peer (the Lockouts recovery, notes/keys.md); everything syncs, every node takes the walk's side in each dispute, and every node re-seals and rotates until nothing is written (16 rounds bound). The seed's emphasis (forks, departures, forgeries, holder actors) weights the draw; `tally` asserts every shape is reached in any run of 8 seeds or more.
- **Oracle**, per thing at its mint admin: nothing blocked, every holder with key access boxed; every holder counts and has established the current epochs the mint admin does, and holds the secrets its role's holders hold. Leaks: a peer without access to role r at the end opens, from every secret it ever held and the final boxes, neither the epoch a remaining writer encrypts under (unless blocked there) nor any epoch whose rotator held its departure and saw it below r (a peer reading a holder actor the epoch boxes or proves at r is not below it; where the rotator held no secret of a boxed holder, the weaker property stated for an epoch whose secret the sealer lacks applies). A secret first handed by a grant that applies nothing and does not count, its author still holding that role, nobody departing the role after the grant (the author's departure counted even once it reads again) and no later epoch of it made, is not counted as the peer's for the first: spec/crypto.md §4 Boxes leaves the grantee reading until the role's next rotation (an admin demoted to reader while granting X read; `left_reading`, from the grant's commits, the role timelines and the epochs made). No other excuses. A failure prints the history and when the peer first held the secret.
- **Seen to bite** (each sabotage alone, 200 seeds): the re-seal trigger looking only at the newest fork; history adds off; establishment without names met; an invalid rotation's epochs kept established. Not caught: coverage by any author's entry (`publishes` also asks that the author hold the role), the blocked walk ignoring stale and keyless holder-actor boxes (the `tests_members` examples catch it), entries covering without a keyset publishing them.

## Deep departure property (osis-engine `rotation::tests_deep`)
A writer above a departure from a holder actor, holding every keyset and box record of the chain, writes under no epoch the removed party opens; once every peer settles, nothing stays blocked and every holder is boxed (spec/crypto.md §4, Encrypting under, Holder actors: Stale; model Depth0 `NoLeakDeep`). `deep_departure_holds_spec_crypto_4` (default, seeds 0..4) and `deep_departure_holds_large_spec_crypto_4` (100 seeds, `OSIS_FULL=1` 1000, `OSIS_DEEP_START`/`_SEEDS`; about 2 CPU-s a seed).
- **Generator**: six peers; G above a chain of two or three holder actors, each with a random admin and readers, the holder actors' edges before or after the members (box records by grant or rotation); V reads X1 or X2 only and its admin removes it; then random pairwise syncs, rotations due and re-seals.
- **Oracle**: a writer of G pulls every commit the others hold and rotates what is due; unless G's read epoch is blocked there, V does not open it from what it kept and every box any peer holds. After settling: G unblocked at its admin, every thing's holders boxed, V opens no writer's G epoch.
- **Seen to bite** (100 seeds): stale boxes judged only for sealing (11 leak).

## Cut and addenda differentials (osis-engine)
Randomized differentials with a covering default seed set and a `_large` twin: `rotation::tests_cut::nothing_before_a_cut_reaches_its_holder` and (`OSIS_CUT_START`/`_SEEDS`, 20 seeds, `OSIS_FULL=1` 200), `apply::tests_addenda::a_removed_writers_writes_read_alike_in_any_arrival_order_and_tie` (`OSIS_ADDENDA_START`/`_SEEDS`, 40, `OSIS_FULL=1` 400). Each default set was chosen by planted faults over 40-48 seeds and checked against plants not used to choose it (the counts at each seed constant); the addenda set also asserts every tie case and both re-grant cases ran. Faults no seed caught: in the addenda test, a commit judged at its own point rather than its `ts`'s start, and a demotion at the commit's `ts` not counted as later (the scripted tie tests beside it catch the first). The newcomer test also asserts N unwraps no sync ID entry from before its cut: content wrapped (not sealed) under the roles secret hands N only headers, which no engine read shows. Its expiring values (written before the cut, read before and after they end) are in the planted faults that choose its set: no expiring snapshots at a cut, no stripping at an expiring snapshot's expiry.

## Reference-graph differential and sims (osis-sync `differential::`, `sims::`)
`differential::histories_hold_their_closure`, harness `history.rs` (`Model`, `excused`, `check`); held-model `spec_closure`'s tests are the oracle's self-checks. Open full-size classes: issues/differential-full-size-classes.md.
- **World**: `history::world_of(seed, accounts, nodes)`: one node per account, every account every other's contact by card redeem (`introduce`), then a node paired to each account in turn.
- **Steps**: `New` (minted with the account root as admin) and `NewIn` (minted with a thing as admin), `Write`, `Give` (sync/read/write to an account or a thing: chains), `Lower`, `Revoke`, `Rotate` (a writer), `Strong`/`Unstrong` (from the account root, an accept, or from a thing, to any history thing), `Pair`, and the faults (power, partitions, loss, disk faults, skew). Declining is drawing no accept.
- **Model, from the history and the reference alone**: things independent once a grant or rotation applied (a dependent thing derives from its independent); grants from the reference's rosters plus each mint admin; strongs from the reference's `holds.0`. Per account a `NodeView`: its root, open by keys; a ticket per thing given the account directly, at the lower of the best role given and the account's role at the end by chains starting at a thing the node closure reaches by strongs (`hc::World::roles_from_reached`: spec/sync-inbox.md §5 Nothing before the strong); the least fixpoint over what the closure reaches. A thing kept unread holds its root alone. Tickets are where the grant's fire puts them and D's copies.
- **Gone things** (`Made::gone`): at each run with every node on and a clean network, a history thing no account's model closure holds is held by no node, so gone for good (spec/sync-set.md §3); the model drops strongs into it from then on.
- **Compared at quiet**: per node and history thing, a value read exactly when the model reads it, then value and roster as the reference; per independent thing the sync set's holding (read, unread, none) as the model's (a node keeping a thing unread may still list it after its removal, spec/sync-judgement.md §6); no store entry under an independent thing's sync ID the model neither reads nor stores; some node holds a body of each held value; no kept entry of a body judged invalid; quiet within `STORM_CAP`; every fourth seed plays twice with identical traces. A value write a release lost (spec/sync-set.md §3 Nothing of R stays) is not handed to the reference (`lost_writes`).
- **Excuse** (spec/permissions.md §3 Left out, from `Made::know`): only when the account's last grant and a change of read keys are concurrent and no boxed account holds write or above at the end; the maker is always boxed and admin, so it never fires in these histories.
- **Size**: default 6 seeds of 3 nodes, 2 accounts, 30 steps (odd seeds faulted); the 5 sims at a seed per variant (2 to 4), about 16 G a seed (`tools/pertest.py`). `OSIS_FULL=1` (100 seeds of 4 nodes, 3 accounts, 60 steps; sims 40 seeds) is a release-size run under `tools/heavy`. `OSIS_SYNC_SEED`/`OSIS_SYNC_SEEDS` pick seeds; `OSIS_SYNC_SHRINK=1` shrinks. Mutations it fails on: no ticket's secret taken at a strong, no NotCarried; the small size passes with kept-unread entry removed (the sims catch it). A no-op release storms past the seed timeout (`OSIS_SEED_TIMEOUT_SECS`).
- **Sims** (three accounts, thing 0 written by 0 and 1, kept unread by 2; the oracle plus the outcome): `a_reader_through_a_node_keeping_it_unread`, `crashes_and_restarts_in_place`, `lost_and_repeated_messages`, `a_peer_refusing_role_entries`, `store_failures`.
- Every test checks the closure structure incrementally against a from-scratch walk (the debug index check, notes/test-harnesses.md: `check_closure`), so notes/closure-model.md P5 needs no property of its own.

## Models (core/test/)
Independent oracles: written from spec/ (never from code), never depended on by the implementation, never patched to match it.
- **crdt-model**: the reference CRDT (notes/crdt.md, Reference model). Differentials: osis-crdt `tests_model` (join, wire, strip and un-merge; the one crdt property, notes/crdt.md Tests) and `tests_decoder.rs`.
- **roles-model** (src/lib.rs): per model `walk(h)` (pure), `random_hist`, `quiescent(h)` and a `Display` trace; `shrink::shrink` reduces a failing history to a 1-minimal one. The searches print counterexamples shrunk. Run by hand through `tools/heavy`: `cargo run --bin roles-model -- 2000000 joint|edges|disputes`, `-- 1000000 addenda` (4 min on 16 threads), `-- 0 addenda-exh` (11 min), `-- 2000 epochs`, `-- 0 custody-exh` (about 2,700 CPU-s; when `custody.rs` changes) (each within one `heavy` hold); sizes and results in core/test/roles-model/README.md. `-- N digest` hashes every verdict of N random histories per model (stable within one toolchain); a refactor keeps it: at 1,000,000 joint e29ad7c11da132ca, edges d51880160a427893; at 200,000 joint 6b08a391fe7071c2, edges 0d28d693df4bcfcf. Differentials: osis-perm `tests/it/differential.rs` (the walk, trust sets against `roles_model::trust::side`, addenda against `roles_model::addenda`, and in `tests/it/epochs.rs` the account chain and epoch rule against `roles_model::epochs`, layer 2 over `custody`'s chain, at every observer and receipt prefix).
- **held-model**: what a node holding a body set reads, written from spec/ alone (purge, expiry, validity, apply) and, for history, from notes/engine-retention-history.md; its values are crdt-model fragments. The reference of `held_set_decides` (held-model comparison above). Every drop is a cover, purge, expiry or invalidity; it judges only what users observe. Its AMBIGUITIES.md is the rule backlog.
- **TLA+** (core/test/tla/): `sync` (one sync ID at one node keeping it unread, the model's "label" at a "host": logging, pulling, deposits, deletes, expiry, compaction, purges, snapshots, tombstones, offline nodes, a misbehaving holder), `rotation` (read-role rotation of one thing; the directory also holds Depth0, Finalize, Cover, Lockout, Merge and other read-role models), `net` (the networking rework: node-wide log, shared sets, a peer that cannot read, opens, hold/log/delete per sync ID, a node keeping S unread; written before the build), and `sides` (a design exploration of an admin dispute, not from spec/ alone; `matrix.sh` runs every scenario under every mode). Each README gives instances, results, state counts and times; each AMBIGUITIES.md the findings.
  - Run by hand when TLA or its spec sections change, never as part of a bigger thing (models read no code: rerunning an unchanged model finds nothing): `core/test/tla/run.sh <module>` (modules in run.sh's header; each under 3 min at one worker except `depth0`, 15-23 min (`D0_nc3`, `D0_gone_live` 400-510 s each); a module name maps to one .tla, so a new .tla takes a module name of its own; `TLC_WORKERS` sets workers, more than one through `tools/heavy`; a hand `-metadir` on disk, never under tmpfs /tmp). It downloads the jar to `~/.cache/tla`. Each module checks safety on every listed instance and liveness on one, and keeps a negative control (or open finding) that must fail; the script exits non-zero on any other result. Larger instances by name: `run.sh <module> <cfg>...`. Size a new or grown by-hand instance first by a one-worker run of a minute, unlocked (its state count and queue growth say the size); then one instance per `tools/heavy` call, each under the `heavy` hold limit (`tools/limits.py table`: about 440 s wall on fastbox-0) with a third to spare, never several instances in one call: gates queue behind a hold, and one hour-long TLC hold kept four agents waiting about an hour each.
  - Not covered by the TLA+ models: record edges removed by their own admins, several sync IDs or unread holders, sections and certificate copies, retagging, parked bodies and unfetched pages, clock skew, delete levels, purge classes, nodes offline past `ROLE_KEEP`, connections and timeouts, signals; write and admin rotation, keysets and departures inside a holder, demotion and `until` in rotation, steps without rotation, entry boxes and key actors, `sync.0`/`secrets.0` compaction, the stale-view carrier race.
  - **A new TLA+ target**: a fresh agent given spec/ and the target's sections only (never notes/ or code) writes the model under `core/test/tla/<target>/` with a README (instances, results, times), an assumptions list and an ambiguity list; crypto as access (secrets as set membership, boxes as edges); 2-3 nodes, 1-2 of them keeping S unread, tiny bounds, symmetry sets; safety as invariants, liveness under weak fairness of honest steps; each property cites its spec sentence. Findings go to spec first, then the model follows the fixed text and reruns. TLA+ when notation independence matters and the state is small; stateright when an actor-shaped model would also serve the simulator.

## Conformance vectors (core/test/vectors/, osis-vectors)
- Format, subjects and rule IDs: core/test/vectors/README.md. `.vec` text records of `key: value` lines; every case has `case` and `spec`; `pending: <reason>` marks a case not yet checked.
- Only `cbor/values.vec` and `padme/padme.vec` are files, hand-written, each with a checker. Every other subject is a generator (`core/test/vectors/src/subjects/`, fixed inputs: seeds are 32 repeated bytes) run in memory by its test, so its asserts check the implementation. No generated output is tracked (Tess): before the wire format is stable a committed vector only compares the implementation with its own earlier output; the generators stay so a stable release can write files out. Waiting on Tess: `blob/blobs` (the pending commit blob case), `inbox`.
- **Adding one**, in the change that lands an encoding: a generator `fn -> VecFile` in `subjects/<subject>.rs` asserting what it computes, added to `subjects::GENERATED` and `generated!` in core/test/vectors/tests/vectors.rs, the crate as an osis-vectors dependency. Rejections use the README's rule IDs.
- **Judgment vectors** (`judgment/`): sync IDs' bodies and blobs as wrapped entries, read secrets, clock and arrival order in; per body validity, held/dropped/missing, covers, rosters, state and read digests out. Generated in osis-engine `tests/it/judgment.rs` (histories by `order::play`); `judgment_vectors_spec_permissions_5_2` checks each file's shape and replays it through a fresh engine; `judgment_vectors_can_fail` (by hand) checks a changed verdict fails.

## Fuzzing (core/test/fuzz/, outside the workspace)
core/test/fuzz/README.md: running, the target table, adding a target, crash handling. `cargo +nightly fuzz run --fuzz-dir . <target> -- -max_total_time=300` per target; crash inputs land in `artifacts/`. `seq_ops` (`arbitrary` op scripts replayed by osis-crdt's `fuzz_seq::replay`, built with `--cfg fuzzing`, which also turns on the crate's test-only checks) needs no seeds; others are seeded by `cargo run -p osis-vectors --bin fuzz-seeds` (the untracked `corpus/`). A target per parser of peer or disk bytes; a crash becomes a regression test in the crate the code lives in, citing its spec section and `fuzz: <target>`.
- Panics: the workspace denies `unwrap_used`, `expect_used`, `panic` and `indexing_slicing` in every library crate (allowed in tests, the cli binary, and two commented one-line exceptions). Casts on peer numbers are checked by hand; fuzzing runs with overflow checks on.
