# Properties and models
> Summary: The big randomized properties (engine: held-set with its held-model comparison, forged copies, rotation, deep departure, cut, addenda; osis-sync: the reference-graph differential and sims), the independent models (crdt-model, roles-model, held-model, TLA+: running and extending them), conformance vectors and fuzzing. Running and replaying seeds: notes/test-harnesses.md; the simulator: notes/test-sim.md.

## Held-set property (osis-engine `tests/it/order.rs`, `held_set_decides`)
What a node shows is a function of the commits it holds (spec/requirements.md Deterministic). One test, one generator, sizes as a knob; each node is judged against the node holding the same commits and keeping every body, and against held-model, so orders agree because each node equals them.
- **Generator** (`generate`): random histories on three `LocalPeer`s (0 is G's mint admin, 1 writes, 2 admin). Seven feature groups (general `random_step`, purges, keeps, history settings, record-only things, sequences, parts), each on its own rng stream so a change to one leaves the others' steps as they were. Steps are `Step::Aim`ed at an author and thing that can write them (an undo at a commit a revert writes, `Engine::check_revertible`). After every step each writer re-snapshots for the purges it applied, as sync does (`Engine::purge_resnapshots`): a part missing when purged (dropped while invalid and valid again in the walk that made the purge stand) counts as never received and is not fetched, so only that snapshot makes the node read as its holders (`purge_of_a_part_dropped_while_invalid_reads_alike_spec_commits_5`). The seed picks an emphasis (`Emphasis`, seed % 8: purges, keeps, settings, record-only, lists, parts away, settled, addenda) that weights its group fivefold and starts with a setup reaching its outcome, then `HeldHere`: what was made so far is a held set of its own, so that outcome is judged whatever later steps do to it (a later removal can invalidate a start's purges or revive its fallen setting); parts away (`Cfg::away`), settled (`settled`: every writer compacts every aspect last, delivered as made; `holds.0` before content, since a thing whose strong a node dropped while invalid is in no node closure there and its own compactions count for nothing until the strong comes back) and addenda (`play_with`) shape the whole history. Every history ends in `Removals` (deletes, writes into a deleted element, undeletes) on a thing of its own, held also as a set of its own with the setup (`Played::own_sets`): held-model judges it even where a waiting role commit (a part held away for good) takes every other held set out of its scope, so the per-emphasis removal floors hold by construction.
- **Orders** (`ORDERS`): held sets are the whole set and partial sets (a first sync part way, then without one writer or a random third: `held_sets`), then the history's own. Each goes to fresh nodes as made, reversed, as fetched (`fill_order`), every order when small, shuffles; with late parts (`ingests` with a split: only for a held set with a multi-aspect commit); in part at an earlier clock (`clock_of`, so drift parks). Every judged node runs sync's covered drops after each ingest and tick (`settle`), and in clocked orders held-model judges each drop (`held::Drops`). At each delivery's end the wakes have missed nothing a full scan of the pending commits applies (`finish`, `Engine::lost_wakes`; not after every ingest: that cost a quarter of plain, and the planted wake losses neither scan caught are caught by waits.rs and the scripted examples). The whole set's first orders are also delivered reopening after every ingest (`reopens_alike`).
- **Delivery tree** (`Tree`, `walk`): a seed's deliveries without a clock (each order as it is and with late parts, the rests, the reference) are one tree of moves; a shared prefix is ingested once, by one node copied (`Peer::copy`, exact) where deliveries part, and the tasks run on every core, newest first (`pool`). A late-parts pick is drawn from the moves before it, so a twin shares its order's prefix up to its first split commit. `tree_ends_are_fresh_deliveries_plain` (parts-away seeds) holds every end byte for byte to a fresh replay (stores, indexes, reads, pending and thrown-out commits); a failure on the way to a branch is the result of the first end below it (`Tree::first`). The walk is over nodes up to equality (`node_key`: the store's rows, indexes, reads, pending and thrown-out commits, clock; every move and check is a function of the node): an end is judged once per class (an order's checks with its reopen, or `node_checks`, and its oracle) and node, a branch walked once per shape (`Tree::shape`) and node; the rest count as `alike`. Orders converge: at the exhaustive size about 9 in 10 ends are alike (two fifths of its cost saved), at plain almost none (a key costs about 2%). Clocked and reopening deliveries run alone: each moves its own clock.
- **Sizes** (`Size`), both properties (no default test): `held_set_decides_plain` (80 seeds of 60 steps at `OSIS_FULL=1`, a tenth at the gate), `held_set_decides_exhaustive` (80 seeds of 40 steps capped at 6 commits after the setup: every order of every held set, the named three orders and a quarter of the rest (`TWIN_SHARE`, drawn from the seed and held set) again with late parts, 24 clocked). Seeds and each seed's deliveries run on every core (`testenv` permits). Env vars: notes/test-harnesses.md, Env vars and seeds.
- **Oracle** (`node_checks`, from the API only): every aspect's read and every thing's roster, now and two hours later, after the node's sync exchange (`fetch_missing`: every commit the node itself counts a part of missing comes again, as sync's refetch). Every pass end (a delivery's, the exchange's, the oracle's: `pass_end`) first drops what a judged loss of read access no longer covers (`Engine::role_duties`: the pass is the complete one spec/permissions.md §3 When it learns it waits for), then releases what left the node closure, as sync does with no source in flight (spec/sync-set.md §3), then settles needs: without the drop a node given a grant and then its removal keeps the grant's secrets and reads the thing, where one applying both in one transaction never took them (`secrets_of_a_removed_grant_drop_at_the_pass_end_spec_permissions_3`); without the release a thing a strong held for a while stays and one never held goes. No excuse: a gone write reads as never held at every node (spec/crdt.md §4.7). Rejected: a precise excuse accepting only the keep-everything read or a reference given each commit at its stamp; a node in another order can read a third value (a part valid at its arrival applied and expired where every reference dropped it waiting), so no fixed set of references gives the outcome. Before the exchange only settled histories are compared (`Played::settled_last`). Every node takes the walk's side in each dispute it detected (`deliver_with`). Also per node: P3 `value_past_end`, the permission index against its walk from scratch (`perm_digest`), held-model, and every plain order judged anew alike after a reopen (`misjudged`). Held bodies, states, pending sets and death dates are compared nowhere: **a seed where bodies or states differ but what nodes show agrees is not an issue.**
- **Coverage tally** (`Seen::floors`, derived from the run's size; not checked when one seed ran, a replay): every run judged nodes against both references and tried late parts on every held set with a multi-part commit and in every emphasis's seeds; each emphasis reached its outcome; a run with every emphasis reached every step kind, an invalid part, a waiting commit, a judged signal, a clock move, purged or expired deltas judged, a reopen, a sync exchange bringing content back, and (`held::REMOVALS`) a list element reset, a write above its reset, a winning text undelete and a removed set value.
- **Cost** (instructions, each alone under the lock at `OSIS_ORDER_START=0`; each size prints its ingests, copies and alike ends): plain (8 seeds) about 1,360 G (65,400 ingests); exhaustive (8 seeds) about 1,520 G (59,000 ingests, 2,960 copies, 5,336 of 6,035 tree ends alike). Seeds differ fourfold. Ingest (the engine's apply) is most of a delivery. Then, in exhaustive, every tree node's drop check (`Engine::check_index`: a quarter, on alike ends as on judged ones) and `node_key` (a twentieth); in plain, clocked orders (a quarter, three fifths of it held-model after every ingest) and the ends' checks (a third, of it the drop check a third). `node_key` leaves the indexes out: each node's drop checks them against its store.
- **Scripted examples** beside it are minimal reproducers in named orders (`NAMED`: as made, reversed, as fetched, never reopening after every ingest, which is the generator's check; or explicit ones), each naming the rule it pins; open issues' replays are `repro_*`. A failure prints the `check(seed, &h, cfg)` it failed under; an issue pastes it whole. A shrunk history can pass under `NAMED` alone: a held-model difference needs `model: true` (`Cfg { model: true, ..NAMED }`), and one seen only in clocked or parts-away orders needs `clock`/`away` too. A shrunk history is a debugging aid, never the reproducer (notes/principles.md, Never pin a seed).

## held-model comparison (`tests/it/held.rs`, `Cfg::model`)
Every node `held_set_decides` judges is converted into held-model's input and compared on what a user observes: applied commits (role commits too), validity, which edge writes apply, every known thing's roster, reads, no forbidden value held, no purge-on-replace body held that a right holder's held snapshot covers, and promised history: a node never drops a body the settings it holds keep in history, nor a live one before its aspect's live bound (spec/commits.md §5 Kept while live). A drop is judged by the body as last seen held; one last seen on an out-of-scope aspect (fed to the model empty) by its body read then (`held::unread_body`), so its drop is judged once the aspect is in scope. Keep for D's dating rule is checked by the scripted `held::keep_for_d`. Every difference is tallied by kind (`Coverage::differs`); the first fails the test.
- **Input**: every held commit and known creation record, undo, acting, may-grant grants, `until`, self-removals, finalizes and addenda as the node's role input holds them (`ix.held`); bodies as crdt-model fragments decoded from the engine's wire bytes; history is the thing's `retention^.0` settings (`Delta::Retention`); a body dropped for its bounds is fed as missing, one dropped as covered as `Body::Dropped(cover)`. Byte-functions are cached per history (`held::History`).
- **External fires**: the adapter passes `ExternalFires::Enabled` (a fire by a party holding no write is valid only while the current setting enables its signal), as the engine judges; no generated history holds an external fire yet (issues/held-set-external-fires.md), so the comparison does not reach the rule.
- **Scope**: every content aspect of every encoding. Left out, counted by reason: paged, ephemeral, waiting for blobs or parked, the node's own writes from outside the history, and every aspect when the role input is outside the model (a role-class snapshot, a role commit carrying parts outside the model: notes/test-design.md, Small items). Not compared as reads: `keys.0`, `secrets.0`, `sync.0`, `created.0`, `retention^.0`, `addenda.0` (issues/held-model-setting-reads.md).
- **Seen to bite**: reversed list reads; a held text delete beating a later undelete; a list element shown above its reset; a set element's content kept under its own reset; a roster showing write as read.

## Forged-copies property (osis-engine `retention::tests_forged`)
Hostile input never produces a local error (spec/commits.md §4): writer 1 signs, as snapshots, the deltas of crdt-model's twin histories (two writers sharing a source and clock: copies of one stamp with other payloads, one dot under two stamps) and hostile sequence writes (`crdt_model::gen`), each as the snapshot wire carries it; the forger applies each, peer 0 receives them as made, peer 2 reversed; every peer ticks a day on (dating the bodies under a kept history) and restarts. No step returns a local-class error (a forger's own build failing otherwise is skipped), and all read alike. `forged_copies_fail_no_node_plain` (one seed per kind) and `forged_copies_fail_no_node_large` (300 seeds at `OSIS_FULL=1`, a tenth by default; `OSIS_FORGED_START`/`_SEEDS`). The random samples reach the identity rules seldom; the hand cases give it teeth, one per identity rule, each failing with it undone: a reference copy of an int set element's write (`a_forged_copy_of_a_set_element_*`), copies of a value removal naming other references (`forged_copies_of_a_value_removal_*`), a text reset copy of a register write (`a_forged_reset_copy_of_a_register_write_*`), a delete copy of an undelete (`a_forged_delete_copy_of_an_undelete_*`), a register write re-encoding a text holding its embedding, the read unchanged (`a_register_write_joining_a_text_holding_its_embedding_is_stored_*`: a join's `Changes` misses it, the state never stored); paged: `apply::tests_paged::forged_copies_in_a_paged_nested_set_apply_as_whole_*`. osis-crdt's own hand cases (`tests_winners`) catch each rule undone too, and its `testutil::joined` checks every test join into a state reports any change it makes; its reach law over 1000 model seeds does not catch the reset copy, the flag tie or hiding read per body undone (the twin generator seldom makes those shapes).

## Rotation property (osis-engine `rotation::tests_property`)
No departed holder reads later content; every holder ends reading everything (spec/crypto.md §4, spec/permissions.md §2-§3). `rotation_holds_plain_spec_crypto_4` (seeds 0..8) and `rotation_holds_large_spec_crypto_4` (100 seeds, `OSIS_FULL=1` 1000, `OSIS_ROTATION_START`/`_SEEDS`; about 1.5 CPU-s a seed). `OSIS_ROTATION_DUMP=1` on a leak prints a peer and thing legend, how the epoch was made, and the way the peer opens it (each box with its keyset, the step its state was first met, stale or within the limit), settled and over every state met. No shrink: a history is drawn as it plays from one generator, with no step list to drop from; a failure prints the history's log, an engine's drop check failing included, and the addenda check (`flows::addenda::missed`) runs after every durable transaction in debug builds, so a missed wake or unstamped read fails at the transaction that made it.
- **Generator**: five peers, thing G with every other peer at a random role; with holder actors (seed mod 4 = 3, else one seed in six) more things granted roles on each other around a cycle. Rounds of random removals, demotions, self-removals (a forging writer, hostile after), `secrets.0` compactions, grants, `until`s, re-grants, rotations leaving members out or boxing nobody (a vandal, hostile after); partial or full syncs between rounds, so rotations fork and unaware demoted rotators make invalid rotations. Then an admin re-seals and rotates every thing; an honest admin removes every hostile peer (the Lockouts recovery, notes/keys.md); everything syncs, every node takes the walk's side in each dispute, and every node re-seals and rotates until nothing is written (16 rounds bound). The seed's emphasis (forks, departures, forgeries, holder actors) weights the draw; `tally` asserts every shape is reached in any run of 8 seeds or more.
- **Oracle**, per thing at its mint admin: nothing blocked, every holder with key access boxed; every holder counts and has established the current epochs the mint admin does, and holds the secrets its role's holders hold. Leaks: a peer without access to role r at the end opens, from every secret it ever held and the final boxes, neither the epoch a remaining writer encrypts under (unless blocked there) nor any epoch whose rotator held its departure and saw it below r (a peer reading a holder actor the epoch boxes or proves at r is not below it; where the rotator held no secret of a boxed holder, the weaker property stated for an epoch whose secret the sealer lacks applies). A secret first handed by a grant that applies nothing and does not count, its author still holding that role, nobody departing the role after the grant (the author's departure counted even once it reads again) and no later epoch of it made, is not counted as the peer's for the first: spec/crypto.md §4 Boxes leaves the grantee reading until the role's next rotation (an admin demoted to reader while granting X read; `left_reading`, from the grant's commits, the role timelines and the epochs made). No other excuses. A failure prints the history and when the peer first held the secret.
- **Seen to bite** (each sabotage alone, 200 seeds): the re-seal trigger looking only at the newest fork; history adds off; establishment without names met; an invalid rotation's epochs kept established. Not caught: coverage by any author's entry (`publishes` also asks that the author hold the role), the blocked walk ignoring stale and keyless holder-actor boxes (the `tests_members` examples catch it), entries covering without a keyset publishing them.

## Deep departure property (osis-engine `rotation::tests_deep`)
A writer above a departure from a holder actor, holding every keyset and box record of the chain, writes under no epoch the removed party opens; once every peer settles, nothing stays blocked and every holder is boxed (spec/crypto.md §4, Encrypting under, Holder actors: Stale; model Depth0 `NoLeakDeep`). `deep_departure_holds_plain_spec_crypto_4` (seeds 0..4) and `deep_departure_holds_large_spec_crypto_4` (100 seeds, `OSIS_FULL=1` 1000, `OSIS_DEEP_START`/`_SEEDS`; about 2 CPU-s a seed).
- **Generator**: six peers; G above a chain of two or three holder actors, each with a random admin and readers, the holder actors' edges before or after the members (box records by grant or rotation); V reads X1 or X2 only and its admin removes it; then random pairwise syncs, rotations due and re-seals.
- **Oracle**: a writer of G pulls every commit the others hold and rotates what is due; unless G's read epoch is blocked there, V does not open it from what it kept and every box any peer holds. After settling: G unblocked at its admin, every thing's holders boxed, V opens no writer's G epoch.
- **Seen to bite** (100 seeds): stale boxes judged only for sealing (11 leak).

## Cut and addenda differentials (osis-engine)
Randomized differentials with a covering seed set in a `_plain` property and a `_large` twin: `rotation::tests_cut::nothing_before_a_cut_reaches_its_holder_plain` (`OSIS_CUT_START`/`_SEEDS`, 20 seeds, `OSIS_FULL=1` 200), `apply::tests_addenda::a_removed_writers_writes_read_alike_plain` (`OSIS_ADDENDA_START`/`_SEEDS`, 40, `OSIS_FULL=1` 400). Each covering set was chosen by planted faults over 40-48 seeds and checked against plants not used to choose it (the counts at each seed constant); the addenda set also asserts every tie case and both re-grant cases ran. Faults no seed caught: in the addenda test, a commit judged at its own point rather than its `ts`'s start, and a demotion at the commit's `ts` not counted as later (the scripted tie tests beside it catch the first). The newcomer test also asserts N unwraps no sync ID entry from before its cut: content wrapped (not sealed) under the roles secret hands N only headers, which no engine read shows. Its expiring values (written before the cut, read before and after they end) are in the planted faults that choose its set: no expiring snapshots at a cut, no stripping at an expiring snapshot's expiry.

## Reference-graph differential and sims (osis-sync `differential::`, `sims::`)
`differential::histories_hold_their_closure_plain` and the five `sims::*_plain` (properties: seed runners, run at the gate when osis-sync or a crate below it changes, never in the default tests), harness `history.rs` (`Model`, `excused`, `check`); held-model `spec_closure`'s tests are the oracle's self-checks. Open full-size classes: issues/differential-full-size-classes.md.
- **World**: `history::world_of(seed, accounts, nodes)`: one node per account, every account every other's contact by card redeem (`introduce`), then a node paired to each account in turn.
- **Steps**: `New` (minted with the account root as admin) and `NewIn` (minted with a thing as admin), `Write`, `Give` (sync/read/write to an account or a thing: chains), `Lower`, `Revoke`, `Rotate` (a writer), `Strong`/`Unstrong` (from the account root of an account given a role, or from a thing, to any history thing), `Pair`, and the faults (power, partitions, loss, disk faults, skew).
- **Model, from the history and the reference alone**: things independent once a grant or rotation applied (a dependent thing derives from its independent); grants from the reference's rosters plus each mint admin; strongs from the reference's `holds.0`. Per account a `NodeView`: its root, and the account as its own actor; the walk enters a thing by the account's role over those grants (`hc::closure`); an edge between things that no writer of the holder wrote counts only once the node reads its target another way (`Made::unoffered`: no history thing takes `grant@~0`). A thing kept unread holds its root alone.
- **Gone things** (`Made::gone`): at each run with every node on and a clean network, a history thing no account's model closure holds is held by no node, so gone for good (spec/sync-set.md §3); the model drops strongs into it from then on.
- **Compared at quiet**: per node and history thing, a value read only where the model reads the thing, there value and roster as the reference; per independent thing the sync set's holding (read, for keys, unread, none) as the model's (a node keeping a thing unread may still list it after its removal, spec/sync-judgement.md §6); no store entry under an independent thing's sync ID the model neither reads nor stores; some node holds a body of each held value; no kept entry of a body judged invalid; quiet within `STORM_CAP`; every fourth seed plays twice with identical traces. A value write a release lost (spec/sync-set.md §3 Nothing of R stays) is not handed to the reference (`lost_writes`); a thing's making lost so is handed whole (its record is in it) and its value reads as none.
- **Excuse** (spec/permissions.md §3 Left out, from `Made::know`): only when the account's last grant and a change of read keys are concurrent and no boxed account holds write or above at the end; the maker is always boxed and admin, so it never fires in these histories.
- **Size**: small (the gate's) 6 seeds of 3 nodes, 2 accounts, 30 steps (odd seeds faulted); the 5 sims at a seed per variant (2 to 4), about 16 G a seed (`tools/pertest.py`). `OSIS_FULL=1` (100 seeds of 4 nodes, 3 accounts, 60 steps; sims 40 seeds) is a release-size run under `tools/heavy`. `OSIS_SYNC_START`/`OSIS_SYNC_SEEDS` pick seeds; `OSIS_SYNC_SHRINK=1` shrinks. Mutations it fails on: no NotCarried; the small size passes with kept-unread entry removed (the sims catch it). A no-op release storms past the seed timeout (`OSIS_SEED_TIMEOUT_SECS`).
- **Sims** (three accounts, thing 0 written by 0 and 1, kept unread by 2; the oracle plus the outcome): `a_reader_through_a_node_keeping_it_unread_plain`, `crashes_and_restarts_in_place_plain`, `lost_and_repeated_messages_plain`, `a_peer_refusing_role_entries_plain`, `store_failures_plain`.
- **Caught up** (`streams::caught_up_matches_what_each_side_holds_plain_spec_sync_status_1`, `OSIS_CAUGHT_START`/`_SEEDS`: 100 seeds small, 1000 `OSIS_FULL=1`): two `streams` sides over two sync IDs, random logs, frame orders and full pipes; a side saying its source caught up holds what the source holds and the reverse (NetStream.tla `CaughtUpHolds`).
- Every test checks the closure structure incrementally against a from-scratch walk (the debug index check, notes/test-harnesses.md: `check_closure`), so notes/closure-model.md P5 needs no property of its own.

## Models (core/test/)
Independent oracles: written from spec/ (never from code), never depended on by the implementation, never patched to match it.
- **crdt-model**: the reference CRDT (notes/crdt.md, Reference model). Differentials: osis-crdt `tests_model` (join, wire, strip and un-merge; the one crdt property, notes/crdt.md Tests) and `tests_decoder.rs`.
- **roles-model** (core/test/roles-model/README.md): `paths` (the role rules along stated paths: the oracle of osis-perm's `paths::` differentials, in `core/perm/tests/it/paths/`, and held-model's judge). Hand worlds are default tests, the sampled searches `_plain` and `_large` properties; by hand through `tools/heavy`: the `paths*` modes (sizes and results in the README).
- **held-model**: what a node holding a body set reads, written from spec/ alone (purge, expiry, validity, apply) and, for history, from notes/engine-retention-history.md; its values are crdt-model fragments. The reference of `held_set_decides` (held-model comparison above). Every drop is a cover, purge, expiry or invalidity; it judges only what users observe. Its AMBIGUITIES.md is the rule backlog. Also a test bed for rules not built: `overlap` (S3's overlap among otherwise valid commits, which fails: issues/overlap-among-valid-commits.md).
- **TLA+** (core/test/tla/): `sync` (one sync ID at one node keeping it unread, the store: logging, pulling, deposits, deletes, expiry, compaction, purges, snapshots, tombstones, offline nodes, a misbehaving holder), `rotation` (read-role rotation of one thing; the directory also holds Depth0, Reseal, Joint, JointRule, Lockout, Cut, Finalize, Cover, Tail, Account, Withdrawn and Planted), `net` (the networking rework: node-wide log, shared sets, opens, hold/log/delete per sync ID, a node keeping S unread; written before the build), and `sides` (a design exploration of an admin dispute, not from spec/ alone; `matrix.sh` runs every scenario under every mode). Each README gives instances, results, state counts and times; each AMBIGUITIES.md the findings.
  - Run by hand when a model or its spec sections change, never as part of a bigger run (models read no code: rerunning an unchanged model finds nothing): `core/test/tla/run.sh <module>` (modules, defaults and times in run.sh's header: each module under 3 min at one worker but `depth0`, 10-20 min, past the `heavy` hold limit below); larger instances by name: `run.sh <module> <cfg>...`. A module name maps to one .tla, so a new .tla takes a module name of its own. `TLC_WORKERS` sets workers, more than one through `tools/heavy`; a hand `-metadir` goes on disk, never under tmpfs /tmp. Each module checks safety on every listed instance and liveness on one, and keeps a negative control (or open finding) that must fail, on the property it names where listed `fail:<Name>` (a cfg checking more than one property names it); the script exits non-zero on any other result.
  - Sizing a new or grown instance: first a one-worker run of a minute, unlocked (its state count and queue growth say the size); then one instance per `tools/heavy` call, each under the hold limit (`tools/limits.py table`: about 440 s wall on fastbox-0) with a third to spare. Never several instances in one call: gates queue behind a hold (one hour-long TLC hold kept four agents waiting about an hour each).
  - Not covered by the TLA+ models: record edges removed by their own admins, several sync IDs or unread holders, sections and certificate copies, retagging, parked bodies and unfetched pages, clock skew, delete levels, purge classes, nodes offline past `ROLE_KEEP`, connections and timeouts, signals; write and admin rotation, keysets and departures inside a holder, demotion and `until` in rotation, steps without rotation, entry boxes and key actors, `sync.0`/`secrets.0` compaction, the stale-view carrier race.
  - **A new TLA+ target**: a fresh agent given spec/ and the target's sections only (never notes/ or code) writes the model under `core/test/tla/<target>/` with a README (instances, results, times), an assumptions list and an ambiguity list; crypto as access (secrets as set membership, boxes as edges); 2-3 nodes, 1-2 of them keeping S unread, tiny bounds, symmetry sets; safety as invariants, liveness under weak fairness of honest steps; each property cites its spec sentence. Findings go to spec first, then the model follows the fixed text and reruns. TLA+ when notation independence matters and the state is small; stateright when an actor-shaped model would also serve the simulator.

## Conformance vectors (core/test/vectors/, osis-vectors)
- Format, subjects and rule IDs: core/test/vectors/README.md. `.vec` text records of `key: value` lines; every case has `case` and `spec`; `pending: <reason>` marks a case not yet checked.
- Only `cbor/values.vec` and `padme/padme.vec` are files, hand-written, each with a checker. Every other subject is a generator (`core/test/vectors/src/subjects/`, fixed inputs: seeds are 32 repeated bytes) run in memory by its test, so its asserts check the implementation. No generated output is tracked (Tess): before the wire format is stable a committed vector only compares the implementation with its own earlier output; the generators stay so a stable release can write files out. Waiting on Tess: `blob/blobs` (the pending commit blob case), `inbox`.
- **Adding one**, in the change that lands an encoding: a generator `fn -> VecFile` in `subjects/<subject>.rs` asserting what it computes, added to `subjects::GENERATED` and `generated!` in core/test/vectors/tests/vectors.rs, the crate as an osis-vectors dependency. Rejections use the README's rule IDs.
- **Judgment vectors** (`judgment/`): sync IDs' bodies and blobs as wrapped entries, read secrets, clock and arrival order in; per body validity, held/dropped/missing, covers, rosters, state and read digests out. Generated in osis-engine `tests/it/judgment.rs` (histories by `order::play`, their setup's probe kept per process: `order::after_setup`); `judgment_vectors_<file>_*` (one test per file: models, rules, edges, bounds, sync IDs, blobs) check each file's shape and replays each case on a fresh engine, an order starting with the file's setup on a copy of one that received it (as fresh: every replay's output alike either way); `judgment_vectors_can_fail` (by hand) checks a changed verdict fails.

## Fuzzing (core/test/fuzz/, outside the workspace)
core/test/fuzz/README.md: running, the target table, adding a target, crash handling. `cargo +nightly fuzz run --fuzz-dir . <target> -- -max_total_time=300` per target; crash inputs land in `artifacts/`. `seq_ops` (`arbitrary` op scripts replayed by osis-crdt's `fuzz_seq::replay`, built with `--cfg fuzzing`, which also turns on the crate's test-only checks) needs no seeds; others are seeded by `cargo run -p osis-vectors --bin fuzz-seeds` (the untracked `corpus/`). A target per parser of peer or disk bytes; a crash becomes a regression test in the crate the code lives in, citing its spec section and `fuzz: <target>`.
- Panics: the workspace denies `unwrap_used`, `expect_used`, `panic` and `indexing_slicing` in every library crate (allowed in tests, the cli binary, and two commented one-line exceptions). Casts on peer numbers are checked by hand; fuzzing runs with overflow checks on.
