# CRDTs and commits: rationale
> Summary: Why spec/crdt.md and spec/commits.md look the way they do: Tess's decisions, design choices with reasons, known anomalies, rejected alternatives, how osis-crdt and osis-commit are built, the reference model `core/test/crdt-model/` and its tests, text size measurements, worked examples (cited by tests), research pointers.

Property (notes/test-design.md): what osis-crdt computes (join, read, wire, strip, un-merge) equals the reference model's, whose join is lawful; `tests_model::crdt_equals_model` checks it.

## Tess's decisions
- One conflict rule everywhere: every state element carries a timestamp and an author dot, later wins, removal is a reset. No causal contexts, no multi-value register.
- Collection elements are identified by creation dot; a removal resets the observed dots, so an add the remover never saw survives. Tombstones carry no content (no fingerprint): a map removal names its key only in role-class aspects, whose keys are public ids.
- **Removal is final** ("if something is deleted it stays deleted, no recreation as a side-effect of editing"): a nested write newer than an entry's or list element's removal stays in the state hidden until a reset sweeps it (spec/crdt.md §1, §5.6 Live, §5.7 Live).
- **Expiry takes only a commit's own values** (notes/expiry-creation-design.md): an element shows while it is not removed and holds a live value, its creation's or anyone's inside it, so a reaction outlives a disappearing message and a removal alone does not keep it. A map write carries its record's key as its own value; a list creation and `W` are value-carrying; an undelete's char is its writer's. Accepted: an offline edit inside an entry someone else deleted is dropped without notice, as is a `put` on an existing key (it writes into the entry); a writer on a stale view reads its own write until the removal arrives. Undo of a removal re-adds with a fresh dot. A delta's fragment alone shows nothing of a write into another's entry, so the engine finds links by `Fragment::values` (`Engine::relink_field`, `linked_blobs`) and history rows by `Fragment::read_written`.
- A plain `set` diffs structurally; an explicit replace resets.
- Every composite merges recursively down to leaf registers; enum cases never merge with each other.
- The movable text/list CRDT ships in the MVP, as good as fuzzing and testing make it.
- Apps see plain values and listeners, no CRDT details. A lost concurrent write looks like any LWW loss.
- Authenticated malicious writers are out of scope (gaming the HLC to win LWW is not a concern).
- No tombstone compaction: worse merging after long separation is acceptable, discarding edits is not.
- Retention per delta (who may purge, keep bounds; spec/commits.md §5), purge per commit without batching, expiry (§6).
- Undo is per actor by default, plus an API listing every change in scope from which an admin may undo others'.
- Accepted: a node receiving a multi-aspect commit after one delta was purged applies the rest, so it may briefly see an aspect combination no author produced.
- The commit floor (Implementation (`osis-commit`)) is fine for editing workloads; revisit only if huge commit volumes appear.

## Design choices and why
- **Second session** (spec/crdt.md §2.1): an expired ephemeral commit is forgotten with its counters; under a session of its own it leaves no gap a snapshot frontier could not pass.
- **Every state element carries its dot**, so un-merge and revoke frontiers are uniform. **No commit DAG**: causality is intra-aspect only, tids may dangle.
- **Stamps.** The HLC tiebreak lives in the dot's source, which works for commit-form dots too (the commit ID is unknown before signing). Commit-level writes share one delta stamp: 3-6 bytes saved per write and most intra-commit ordering questions gone; a delta still consumes at least one counter so frontiers cover every commit. `>=` survival lets a replace and the embeddings put content at the reset's own stamp.
- **Second dot form** (commit ID, index): unlinkable, and collision-free when several nodes sign with one key (per-node counters under a shared key would let any holder reuse another's dot and knock out its edit). Its cost falls only on such commits: runs do not continue across commits, one 32-byte `Sources` entry per foreign commit, revoke frontiers list commits.
- **`Sources` and encoding IDs live in the delta**, not the header: a delta is self-contained (projection, purge rewrite and hashing need no header) and its order rule is defined per delta; "first appearance across the commit" would be circular over several deltas. Cost: a source repeated per delta of a multi-aspect commit.
- **Why join is a lattice**: the union of write sets with per-register maximum is a join-semilattice, and prune is a closure operator commuting with it (a write a reset drops would be dropped by that reset after any later join). **Encoding slots**: keeping the register as its own slot makes a position's state a product of lattices, so the laws hold across encodings; cost, in a `string` → `text` upgrade the last register write is stored twice until a reset.
- **Presence stamp**: an explicitly empty collection exists, one emptied by removals stays present, `remove_aspect` makes it absent. Only `W` is stored and the rest computed, so expiry can lower presence. `W` is always encoded; omitting it under a greater inner stamp would break un-merge.
- **Derived sources** give the register → text embedding one identity per character without a third dot form. A `Derived` record goes with its write, matching a node that saw only the value-less register. Kept although the string → text upgrade is rare: with reset-only embedding an old app's string save concurrent with a newer text edit would read as the edit alone; with embedded characters it reads as the string plus the edit, placed.
- **Bag contributions are set elements**, so undo of an increment is an idempotent element reset. No bag GC: dropping non-extreme max/min elements or folding contributions changes the read under a later reset landing between the folded stamps, and under expiry of the extreme. Bag reads are order-independent (exact int sums clamped, float sums in dot order, IEEE totalOrder).
- **Enum payloads filed per case**: a writer editing case A's payload while another switched to B must not flip the value back to A with a half-written payload; the newer payload write stays hidden until a reset (spec/requirements.md, Data model).
- **Expiry and purge are value erasure, not a floor.** They change no stamp or order, only whether a value is known, so they commute with join and arrival order; a late older write still loses to the expired one. Dropping the commit's resets instead would let content they pruned survive on a node that received it after T; a floor at T diverges if applied only where the expired write wins, and expires others' newer writes if applied to every register the commit wrote. A purged write is held value-less from the purge on; a snapshot that carried its value is held stripped (its leftover). Expiry is per commit (the header's `expires`, carried in the blob prefix).
- **Death of a write** (spec/crdt.md §4.8) is per write, not per delta: one surviving character must not keep a paragraph's deleted text alive under "no history", and a long-lived text must stay compactable under "30 days after replaced". Dropping a body is always possible locally (snapshot the aspect, drop), so purge on replace never needs another node.
- **Un-merge is defined by the held set**: a node that merged a later-revoked author's writes and one that never applied them hold the same bodies and must read the same, so the result is the join of retained bodies less the author's writes (§4.6), never an edit of the joined state: every flip, drop, strip and re-arrival is `apply::rebuild`.
- **Diff takes the writer's view**: without it an old writer's save of a `set<struct>` removes every element a newer writer extended and adds a stripped copy. The diff algorithm is not normative, only "kept elements keep their dot".
- **`put_new` (`Op::Put`)**: at a map key a new entry whatever is live (invite grants' `secrets.0` puts); at a register position a register write even when equal (chunk repair); refused elsewhere, since a composite would merge with what is there. A repair is a plain write with a fresh stamp: it overrides a concurrent unseen edit and can bring back a map entry whose removal it has not seen, so it is limited to positions whose chunks are gone and rate-limited (notes/engine-paged.md, Dropped chunks). Two puts of one key in one commit share a stamp; no writer does that. A repair via listeners must be a deterministic function of state, else two nodes ping-pong.
- **A removal covers the adds the remover saw** (spec/crdt.md §5.5; a commit header counts as seen): `remove v` resets each live element of `v` it holds and, for a tid, writes one value removal on a fresh dot naming the tid and the counter ranges of the aspect's parts held as headers only (`groups::header_only_parts`: valid, body missing, not below a held root reset). It hides the tid's elements in those ranges stamped below it; an add the remover never heard of, or a later one, shows. Why: `delete` and an undone creation must unlist the thing alike whoever deletes, also where a group's add is held as a header only (`Engine::listing_groups`; `groups::seeing` gives each writer its ranges). Tids only: a header-only part cannot be named by dot (the counter is in the body), so the record names the value, and only a public id may sit in a tombstone; an app value's add held as a header only survives its removal, within the requirement. Hidden, not pruned (`winners` leaves the element out; each removal wins at its own position, `Place::Gone`, and dates the death of what it hides), so join never prunes by value and stays lawful under forged copies (a removal's copies join by `(stamp, v, parts)`), strip and un-merge. Reads, liveness, `values`/`each_value` and set ops skip hidden elements (`fragment::live_elems`, `hidden`); paging loads a tid's records through the value index when a delta names it (`PagedTouch::tids`). Undo re-adds the tid with a fresh dot where an element it hid was live. Cost (`approx_bytes`, 1000 add/remove cycles of one tid): 219 KB without header-only parts, 477 KB with one per removal (the hidden element keeps its register until the set is reset). Rejected: a value-free range removal (hides the part's other members too); removal by value of every older add (drops unseen adds, spec/requirements.md Data model); prune by value in the join (joins stop commuting under copies of one dot under two values, or a removal pruned before the element arrives); refusing a delete while a `group.0` part is missing (a delete completes offline, notes/api-design.md).
- **A map entry record is identified by (dot, key)** (spec/crdt.md §5.6): every record carries its key, each write in it as its own value. Removals are keyed only in role-class aspects, so a `secrets.0` removal's target (and role) is read from the delta alone and snapshot tombstones keep the key there; elsewhere a removal is the dot's key-erased record, whose reset reaches every record of the dot, since an app map key is user content and must not outlive the entry (spec/requirements.md Deletion; receivers refuse a keyed reset there, `osis_commit::check_entry_keys`). Writers pick the form by `Writer::keyed_removals`; the differential harnesses mix both (odd writers keyed). Not dot-only identity: a node that dropped the creation would not know what a removal removed, so a `secrets.0` removal's validity would depend on the bodies held, and an equivocated creation key would give different roles at different nodes. Copies under forged or equivocated keys join part by part (§4.1): every write of the dot sits under the greatest key among its copies. The key never decides another part, since expiry erases it: else expiring before and after a join would differ (`tests_life::copies_under_two_keys_expire_alike_spec_4_7`).
  - **The records of a dot are one entry** (§5.6, `state::prune_dot`): every reset of the dot reaches each record (a keyed reset reaching only its own was order-dependent across a forged second key), and each write sits in one record, the greatest-keyed holding a copy (`Fragment::without` on the lesser; `Fragment::restrict` gives each record its writes as the dot's join holds them). Not by `winners`: it leaves out a `prev` position and a text creation under a delete, which a record must keep, and "wins here" changes as writes arrive. `filter_by` matches a map's records by dot, a nested entry being its dot whatever its key (else an inner write under the lesser outer key read as nothing). A slot's embedding is the register's writes (§7): `filter_by` filters a `Slots` position's register and slots and embeds again, and `state::fit_embedding` makes a slot's copy of a register write the embedding of its winning copy. Copies are told by stamp, not dot: a forged write of `s.dot` under a later stamp is its own (`slot_copies_of_the_register_write_are_told_by_stamp_spec_7`). The by-dot splits (un-merge, `erase_keys`) need nothing: embedded parts carry the register write's dot. crdt-model states the rule independently (`writes::writes` splits records into single writes, `death::key` names them key-erased). A copy counts only as the join holds it, so stripping a state equals joining the stripped delta with the rest (X creates `k` with `a = 1`, Y later sets `a = 2`: X's value-less copy loses in either order). `tests_laws::entry_copies` checks laws in every order, model, expiry and un-merge on random forged copies of one entry, flat and nested (`slot_embedding_sits_with_its_register_write_spec_7`, `slot_copy_of_the_register_write_is_its_embedding_spec_7` the smallest).
  - Expiry moves each expired write, value-less, from its keyed record to the dot's key-erased record (`Map::erase_keys`); others' writes stay under their own copy of the key. The key-erased record's fragment joins into each live record's read, so a snapshot carrying an expiring entry (value-less, keyless) plus the expiring delta reads as the delta's holders do.
  - Cost: a dot with two records with content clones and joins them at each `prune_dot`, O(entry) per join touching it: rare (expired co-writers, snapshot copies before T).
- **Writes into a key follow what they touch** (spec/crdt.md §5.6 Ops; `ops::key_writes` here and in the model). Concurrent puts leave a key with several live records, read as their join. A write to the key is computed against that join; a write into or onto an element (the outermost below the key) goes into every record holding a write of that element, or into all when none does (a creation); any other write (value, case, reset, `W`) into all. So removing one record (by a node that saw only it) takes exactly what that remover saw plus edits into it: another record's deleted element stays deleted, an overwritten value stays overwritten, an insert made after the conflict survives in the other records; and the sweep may judge record by record. Undo joins a commit's records of one key and undoes them once, routed the same way (else a re-created element would come back twice).
  - A creation copied into several records keeps one dot (one write at several positions, §4.8), so a delta repeats a counter there. Readers never check counters for distinctness (§2.3): a repeated counter is a forged copy, which joins handle (`forged_copies_*`).
  - Cost: on a key with n live records (n concurrent creations, kept until the key is removed or its map replaced; no cap), writes to the whole key, new elements and later edits into them are written n times; edits into an element one record created go there only.
  - Paging: an op into a key never runs on a sequence held in part: `pages::walk` reaches one position per record, `pages::ensure_path` loads everything paged below each, `attach_ops` attaches only an op reaching one position (else the state loads whole); `Seq::holds` notes a stray miss.
  - Rejected: writing into the lowest live record (removing that record brought back an element deleted there); a creation into one chosen record (an insert's survival of a partial removal would depend on dot order); folding a conflicted key into one fresh entry (fresh dots lose concurrent edits and typing).
- **Map tombstones live until the map is reset**, because an older nested write may still arrive and must lose (and a newer one stay hidden). Same-key entries are not merged: the dots are different authors' identities, and joining at read time gives the same value with no rewrite.
- **Removal keeps entry creations whose own dot stays** (`remove_writes`): an entry left with only its `created` stays, and a `Slots` position is edited in place (re-joining would prune them), so a later join gives the stamp to the entry where another body holds content; dropping it made `created` depend on arrival order. A record holding only its creation stays through prunes and on the wire (`[Dot, Ci, R, key, []]`), so content rejoining later finds the entry live. A keyed record's creation counts toward `written` (§4.3): a map of such shells is present and reads empty.
- **No set/bag tombstone GC** (uniform with maps). Received-range GC would be sound but needs a `W` fold for presence and a "dot in received ranges with no record is tombstoned" join rule in every node, and makes snapshots differ between nodes; it cannot be opt-in "only when big" (shared semantics), and `replace` is no compaction tool (fresh dots lose concurrent removes). Cost: about 10 bytes per removal forever (spec/requirements.md, Scale); the diff emits no resets, so most sets never see one. If a workload needs it: run-compressed tombstone records (contiguous dots, one reset stamp), a divergence-free wire change.
- **Text deletes by flag, lists by element reset.** Text content is immutable, so a flag plus undelete-with-char restores it exactly; the char rides the undelete's flag write, one register over creation and flags by stamp (a flag below its creation is forged and pruned). A read shows the undelete's own char, so whether a node still holds a deleted creation's char (snapshots and paged states drop it, §5.7) never changes a read; an undelete whose char expired or was purged hides the element. A list element's content is a mergeable fragment: a flag would leave a newer nested write in local state but off the wire (deleted elements carry no content), so nodes bootstrapped from a snapshot would read an undelete differently. As a reset, the write survives hidden (live only while `created` is not below `R_elem`; `created` is not pruned under it, keeping the anchor placed), snapshots carry it, and undo re-inserts with a fresh dot. Delete is never a move to a trash position, which would drag concurrent inserts along.
- **A list creation is value-carrying** (spec/crdt.md §4.7, §5.7 Live): held value-less it keeps its anchor, and the element shows while its content holds a live value (else a durable element emptied by nested removals would vanish). Value-less is a bit on the creation (`SeqElem::valueless`), joined valued-wins and carried as a `Creation` marked `false`, so un-merge and resets cannot lose it. `W` likewise (`Meta::w_valueless`, `[Stamp, false]`): an expiring `{}` goes at T. One `strip` serves expiry, purge and snapshots: nothing ends at T, so a snapshot written before T reads as one after.
- **Hidden writes go by a sweep, not in the lattice** (spec/sync.md §7, Sweep). Swept: a non-live map entry or list element (text: an undelete's char) whose creation is dead, as removal is final: the record has its own reset, or no creation of it is held though its delta is reflected (`apply::copies::reflected`: applied valid, or under a held valid snapshot's frontier or Absorbed). A live record is judged as it reads, with its key-erased record (`Map::record_frag`); a key with several records record by record (writes into a key follow what they touch). `Engine::snapshot` first commits the resets (`Fragment::sweep`), `MAX_DELTA_BARE` content-less elements per commit, until none is left (a commit taking nothing is an error, never a loop), so value and repeated key leave state and snapshots by the ordinary path and a purge-on-replace body holding one is covered. Undo writes back reads with fresh dots, so never shows a hidden write. Not swept, as something can still show them: a record lacking its creation whose delta is not reflected (a re-grant brings an invalid one back, revokes.rs `others_writes_in_an_invalid_record_*`); a creation not live for want of a value (a valued write may arrive); a non-current enum case's payload (a case write stamped between reset and payload write shows it; it dies at the next case write); role-class aspects; memory commits. Writer-side only, so no model twin; `sweep_laws` checks a stale view's sweep changes no read at a node holding everything, also one element at a time. Rejected: in the lattice (a record's reset is pruned by a parent reset, so order-dependent); a snapshot omitting a non-live entry's content (not dead, not covered, bytes still held); creation stamps from headers (a node may never hold the header). Cost: a lookup per record lacking its creation in the snapshot's walk (osis-node `waits::sweep_counts_hidden_records_spec_sync_7`); past the cap one walk per `MAX_DELTA_BARE` (`sweep_is_bounded_and_finishes_spec_sync_7`, `waits::sweep_past_the_bare_cap_spec_sync_7`); a removal repeated by a sweep stays when the first remover turns out invalid; a stale sweep's reset is a write, so a collection reset meanwhile reads empty, not absent (§4.3).
- **Records with no write go**, in every collection (spec/crdt.md §4.2): a sequence record whose writes a reset pruned is placed exactly like a virtual anchor (on END by its dot, its children below it, §6.1), so dropping it changes no read or placement (`pruned_commit_leaves_nothing_spec_4_2`, `reset_drops_old_records_spec_4_2`). So a replace keeps only the new value's records (`replaces_keep_state_flat_spec_4_2`), no keyed map record holds a removed entry's sequence records, a rebuild settled above a body's `ts` reads no older body (`settled_above`), and a text slot left with only the register's embedding goes (§7). Rejected: keeping write-less records as bare anchors (a virtual anchor places a later insert the same; the records grew without bound under replaces).
- **A sequence's order comes from valid writes only** (Tess): un-merge and stripping a snapshot's copies (`remove_writes`) take an element's creation (anchor and char) with the writes; others' writes on it stay, and a record left with no write goes. An anchor naming a dot with no record is a virtual anchor on END (§6.1), whatever the reason. So every read is a function of the valid writes held, and dropping an invalid body equals never having received it (`tests_seq::valid_order`). Accepted: a valid element anchored at an invalid one lands at the end. Rejected: keeping an invalid creation as a hidden anchor (an ex-writer kept steering the order); hiding an element whose anchor is unknown (a node that dropped a record would read differently from one that never had it).
- **Moves and cycles.** A move writes `pos` only for range roots (rewriting interior elements changes their sibling keys and reorders concurrent neighbours); the range spans deleted elements inside the selection; outside subtrees re-anchor in reverse visual order. The creation write is kept apart from the top-2 positions (runs need it, and it gives text content a stamp). Cycle breaking demotes the oldest move in the cycle, the one the other movers did not know about, keeping the newest intention; falling back twice needs three or more concurrent moves over the same elements, and END keeps content visible instead of hiding it.
- **Sibling keys** (Tess: exact undo): an undo's restoring position write carries the restored write's sibling key, so the element sorts among its old anchor's children where it was (`eab`, move `a`, undo gives `eab`, not `aeb`), and a concurrent insert there newer than the old write stays before it, as if the move never happened. The key is immutable payload of one write: join stays top-2 by stamp, the order a function of state; cycle breaking uses write stamps. Key `ts` strictly below the write's. Cost: a writer's delta may carry a commit-table entry per commit its keys name (the only foreign stamps a writer's delta holds, rule 7). Rejected: anchoring the restore at the end of the preceding sibling's subtree (no wire change, but the state is not restored).

## Known anomalies
All convergent.
- A move displaces a concurrent insert made right after the moved range's predecessor (Worked examples).
- An enum payload edit concurrent with a case change stays hidden.
- A field write concurrent with a reset of its struct or the aspect (`replace`, `remove_aspect`) shows that field alone: positions have no creation, so the later write wins. Inside a map entry or list element the removal wins instead (removal is final).
- While a text aspect is in transition, every save by an old LWW app wipes concurrent older text edits.
- A changed list entry the diff does not pair becomes delete and insert, losing concurrent edits to it; apps editing list entries concurrently use path ops.
- Un-merge restores what the invalid author's writes superseded only from retained bodies; a node that dropped them under a cover that fell reads them absent until a peer re-supplies the body.
- Undo of a reset re-adds content with fresh dots, so a later undo of an original element no longer cancels its restored copy (only out-of-order selective undo sees this). Bag undo re-adds contributions without a reset, so concurrent newer contributions survive; other encodings' reset undo is a `replace` and wipes concurrent newer writes inside the value.
- Undo chains on one position: a register or position undo writes back the value before the undone commit while the position reads what the undone write wrote, whoever wrote it now. So undo steps back through repeated edits and redo forward, with no judgment of which commits are in effect; a later edit to an equal value by anyone is overwritten. Enum case writes are undone as resets.
- Differing copies of one write (forged; snapshots vouch, spec/permissions.md §5.2) join by the copy order of spec/crdt.md §4.1: the attacker picks the outcome and every holder agrees, which is all a writer gets by writing a new value anyway; the original's body stays held (no snapshot holding another copy of a live write covers it, spec/commits.md §5), so removing the forger gives it back.

## Rejected
- A wall-clock staleness horizon for tombstones: nodes separated longer diverge or lose edits; any independent reset-style compaction has the same problem.
- LWW-element sets and maps: the tombstone names a value hash or key and cannot be dropped without stability information.
- OR-set/OR-map with causal contexts: dot addressing's add-wins semantics, plus a version vector in every state and delta.
- Stability-based GC of tombstones or per-commit stamps: needs every writer's frontier and stalls on offline nodes ("whether others are alive is never a protocol condition").
- A terminal reset or retire marker in the encoding lattice: representation changes are transitions to new IDs (notes/versioning.md).
- Destructive join of unrelated encodings (later encoding wins, the loser a reset): not associative with eager embedding (`(register ⊔ counter) ⊔ text` ends a counter, `register ⊔ (counter ⊔ text)` a text).
- Attributing state elements through commit headers instead of dots (zero bytes in state, history lookup at revocation): not uniform.
- Columnar or bit-packed encodings (20-30% gain, not worth leaving CBOR); dropping stamps from deletions (changes undo; deletions are not the dominant cost).

## Implementation (`osis-crdt`)
- **Structures**: `Fragment` enum, one struct per encoding (`fragment.rs`), crate-private fields; set and bag elements `BTreeMap<Dot, _>`, map records `BTreeMap<Eid, _>`, struct fields and enum payloads `BTreeMap<u64, _>`. Sequences: `seq.rs` (element state, join, prune, presence, read, strip, un-merge, text embedding), `seq_span.rs` (range records), `seq_wire.rs` (runs), `seq_ops.rs` (ops, net effect, undo), `seq_diff.rs` (diff, `edit`), `linearize.rs`, `seq_lin.rs` (placement cache), `seq_place.rs` (placement held in part); the generic code calls only the hooks re-exported from `seq.rs` and owns a sequence's reset and `W`. A text keeps deleted elements' chars locally (undo and paste read them); snapshots do not carry them, so a bootstrapped node's state differs only there.
- **Live** (`Map::is_live`, `seq::is_visible`; spec/crdt.md §5.6, §5.7 Live): everything that shows, places by index or diffs goes through these two.
- **Range records** (`seq_span.rs`; a snapshot run `[Dot, 2^12, [], [], [], []]` is 8 bytes, spec/requirements.md Scale): a `SeqElem` with `span > 1` stands for consecutive uniform elements of one source (no content, no position write but the creation, one deleted write or reset, no creation or a creation chain of one `ts`). Decode makes one per uniform stretch of a run, so records are O(input). Join cuts an incoming record at the state's record starts after splitting state ranges at its bounds, and splits a chain a reset falls inside (`chain_cut`); nothing coalesces except on a sequence's own reset, so `Seq` equality is per element (`elems_eq`). Invariant: no record key inside another's span (a `Derived(S, c)` key splits an `S` range at `c + 1`), so `find` is the record at or before a dot. Deltas from ops and undo are expanded per element where convenient (`expand`); a received state never is. Tests coalesce every model state into ranges (`testutil::frag`).
- **Slots**: every prune of a `Slots` re-embeds the register slot into each other slot, so a received `Slots` lacking the embedding converges with one built by join. A join leaving the register and effective reset `E` as they are (`kept_reset`: the common case, sequence writes) joins only the delta's slots under `E` (`join_slots_kept`), so untouched slots and the text slot's placement cache stay; anything else re-embeds and prunes the whole position. A lone non-register slot is chosen without scanning (it holds the embedding, so beats the register): the register is chosen only when alone. `Batch` layers a sequence op over the `Slots` slot of its encoding when that slot carries the position's reset (`seq_slot`). Both decoders judge rule 7's "pruning would change it" with deleted chars dropped (the embedding restores a deleted embedded char the wire never carries, rule 5) and return the pruned position, so a bootstrapped node holds such a char again (returning the unpruned form would let one writer make peers' states unencodable).
- **Deaths are computed, not reported** (`winners.rs`): the writes that win in a fragment (§4.8 Which write) are the one definition of supersession; a write of `a` is dead in `a ⊔ b` iff it wins in `a` and not in `a ⊔ b`. Three dead writes stay in the fragment, left out by `winners`: a position write beaten as `cur` (kept as `prev`), a text creation under a delete (judged by the element's winning flag, so an undelete revives it: a body holding it is kept longer than §4.8 says, never shorter; embedded chars die with their register write), and a write beaten in another record of its map dot. Entry and element content sits below its record's writes (`Place::In`), so an entry reset prunes it but a value written there supersedes none of the record's writes. `tests_winners` checks against a pairwise from-scratch definition. `Changes` says only whether the read may have changed. `Fragment::carried` (the same walk, counting) counts every write copy, those three included, once per record of a map dot.
- **Interning**: `Source` is an `Arc<SourceKind>`; a stamp is `ts` + pointer + counter. Equality and order never depend on sharing; `Interner` dedupes per decode (a node may keep one per aspect). Dot and source comparisons borrow: decoded deltas never share the state's source `Arc`s.
- **Join** (`state.rs`) is delta-driven: `join_into(other, e_parent, changes)` walks only what `other` carries; existing children are pruned only when an own reset rises. Equals union-then-prune (`tests_model`). An empty state takes the other side pruned.
- **Wire** (`wire.rs`, `codec.rs`, `stream.rs`): bytes are read and written in place, no `osis_base::Value` tree: `Enc` writes straight into the output (`cbor::put_*`); a decode checks each blob once against the CBOR profile (`cbor::check`, nothing built; `CanonicalBytes` for pages) and walks `cbor::Item` views; only register values and map keys become `Value`s. Encoding runs the fragment encoder twice (a collecting pass for `Sources`/`Commits`). Every element array and field map goes through `codec::Pager`, holding written bytes while they fit the page target, then cutting as elements come: about one page per open position plus links (a 10^5-key map's delta: 13 MB above the delta, against 129 MB for a whole encoder).
  - Reading in place keeps the tree decoder's verdicts: `cbor::check` gives `cbor::decode`'s result and error (a value with a map or set keyed by links is decoded once whole for `EqualLinks`; osis-base tests/cbor.rs asserts it at every decode); a blob is checked whole before any grammar rule or page fetch, so a profile violation is `Cbor` bad input first. `cbor::List` steps over checked items by heads in one flat pass (`checked_len`): the recursive `Reader::item` walks each byte once per enclosing level.
  - Decoding (`stream`) checks grammar, ranges and rule 7, then re-encodes and requires the input bytes: every canonical rule, paging included, is that one comparison (the `Pager` replays the input's pages, so a page cut differently is missing). It streams: the root decodes into a skeleton with every paged collection (reached through `Step`s) left empty and re-encodes against the root with the input's own tables (`Enc` check mode, `Dec::checker`); each collection then decodes a leaf page at a time and re-encodes element by element (`Out`: seams ascend, one open run carried across pages); at the end the tables must be what a collecting pass builds. Paged positions inside a page, a `Slots` slot or a sequence's content decode whole. `stream_delta`/`stream_snapshot` hand over the skeleton, then a `Piece::Page` per leaf page; `decode_delta` reassembles and prunes (§3.3 rule 5).
  - Checked once: bytes that passed the check on this node are read again decode-only (`Checked`, made only by `Checked::verified`, in product code only by the engine's `apply::checked`, enforced by tools/policy.py; `stream_checked`, `decode_checked`): no re-encode, prune or table checks, positions in the root decode's order (`Deferred::order`), the re-encode's for canonical bytes (`tests_stream` requires equal pieces in equal order for every accepted input and mutant).
  - Oracles: the whole encoder (every element held, cut at the end) is `codec::oracle::encode_*`; in this crate's tests every `encode_delta`/`encode_snapshot` also runs it into content-addressed sinks and requires the same root and pages (`oracle::twin`). The whole-delta decoder is `codec::oracle`; `tests_stream` mutates roots and pages and requires the same decisions.
  - Rule 1 quirk (list runs counted as if not closed by content size): the collecting pass cannot cut at `CHUNK_MAX`, since a run's content bytes depend on `Ci` indices from the `Commits` table it is building; so `Runs` defers the sources of a run's position and flag writes to the end of the uncut run in every mode (`Enc::defer`).
  - Sequences: runs per §3.3 rule 3 over `Enc::sorted`, built incrementally (`Runs`: one open run, so a streamed sequence re-encodes across pages); a list run with content is cut where its fragments reach `CHUNK_MAX`; a segment's `Ci` is the creation stamp's commit index (`Enc::commit_of`); closed runs flush after each record, so pages are put in nested-page order. Decode rejects: n = 0 or > `MAX_RUN`, bad indices, list undeletes, content length mismatches, segments of another source, `Derived` creation runs in a writer's delta, empty list element fragments, runs carrying no write, more than `MAX_DELTA_BARE` content-less elements in a writer delta (counted across pages before allocating), writer `FlagW` stamps off the delta stamp, overlapping flag writes; the re-encode covers maximality and order. It cuts runs where segments, position or flag writes change and loops per element only over a writer's own counters (bounded by rule 7).
- **Paging**: `PageParams` (format: 64 KiB target, 16/256 KiB cuts, 512 fanout) come from the `PageSink`/`PageSource`; tests shrink them. `osis_base::PageCutter` cuts; link pages use the tree-node rule; a third level is refused. `page_array` is the public split of one element array (vectors); struct and enum field maps page alike, so no delta outgrows a blob (spec/commits.md §1; `CommitBuilder::max_blob` shrinks it for tests) and a commit is limited only by its header lists (`MAX_LIST_BYTES`): a bulk `replace` of a huge map is one commit, streamed by pages. Decode records each position's pages after its items (`Dec::done`), the put order, so equal page plaintexts replay to their own links. Each put is its own blob (a decode refuses a blob linked twice; the node's `LocalPages` derives a distinct ID per put).
- **Page items** (`MAX_PAGE_ITEMS` 2^21, spec/crdt.md §8; `codec::check_items`/`check_root`): counted from heads before the blob is checked, one per CBOR item plus text bytes, so at most the blob's bytes: blobs up to 2 MiB skip the walk. Ephemeral deltas alike; relay-only deltas never page (`PageParams::UNPAGED`). Why 2^21: an honest page is under `CHUNK_MAX` bytes plus its last element, and the largest elements are a map entry (key up to 128 KiB plus a `Slots` fragment: a 128 KiB register plus up to 9 slots each at most `PAGE_TARGET` inline, about 720 KiB), a list run (`Content` under `CHUNK_MAX`, one such fragment, about 33 items per element of position, flag and segment writes) and a text run (up to about 36 items per element; measured 16 for a text moved twice and half deleted). At `MAX_RUN` 2^16 one run would pass 2^21, hence `MAX_RUN` 2^12: the worst page is then about 256 K + 983 K + 135 K = 1.4 x 2^20 items. 2^20 would fail only the many-slot `Slots` corner (about 1.38 M). The root's tables are not counted (bounded by `MAX_BLOB`).
- **Ops** (`ops.rs`, `batch.rs`): `diff`/`create`/`replace` match the model write for write under a `View`. A set element is one register holding the whole value (`set_elem`; both decoders reject another fragment there); a link fits only a register position. `Batch` makes a commit's net effect: ops resolve against state ⊔ batch-so-far, borrowing the state where the batch has no writes and copying the position where it has (`current`; a map key joins only its entries, `key_lookup`). A whole map's or set's `diff` finds stored keys and live elements by lookup: O(n log n) (`tests_ops::whole_collection_diff_is_linear_spec_9`, `ops::visited_probe`).
  - At a sequence position the batch already wrote, an op resolves against the state's sequence layered under the batch's records (`seq::Layered`: the batch's new records and the state records its writes meet, copied and split where they land, the state's placement followed through them; read through `SeqRead`, cache plan/follow through `Recs`); under a batch reset or where the cache cannot follow, it copies. The view is kept (`Seen`, by path) for the next op there, joined with each op's delta while `prune(acc) ⊔ d` equals the overlay at the op's elements (`seq::Foot`, O(op · log n)), so N ops on one text cost O(N · (√n + log n)); any other op drops it. A debug check compares the kept view with what `current` would copy.
  - Ops see state joined with the batch slot by slot (`slot`): a batch writing a register at P and then a field of P resolves the field against the state's struct, and the overlay of differing encodings keeps only the later write. `overlay` lets a later op override, drops a reset's earlier content, omits created-and-removed elements, then sets `W` if the collection would be left with no write (one-by-one ops would have left it present).
- **Seq ops**: `Op::Insert/Delete/Move` by visible index (`Move.to` indexes the sequence without the range, like the model). `Op::Paste { dots, at }`: cut/paste is client behaviour, no protocol concept; `cut_dots` gives the visible dots a cut removes, and paste moves the placement slice they span and undeletes it, failing (the caller then inserts) if a dot or its char is gone, the dots no longer lie in clipboard order (`paste_out_of_clipboard_order_fails_spec_5_7`), or visible text lies inside the range. `Op::InsertAfter { anchor, items }` and `Op::DeleteDots { dots }` serve a caller keeping the placement apart (not the node): write for write the index ops', new elements right after the anchor when the writer's `ts` is above every stamp of the sequence, as §2.2/§8 make a node's commits.
  - `Op::Edit { base, new }` (what `diff_values` emits for sequences): `seq_diff::edit` aligns `base` to the current read at base's own indices when the read has base's length and equals it over the changed middle widened by `CTX` = 32 elements a side, a stretch unique in base (else in periodic text a concurrent shift lands the edit a period off); otherwise by exact LCS over the whole read. A list element changed on both sides is edited in place (`diff_values` through a nested `Batch`) only when it is the one unmatched element of its gap on each side. `window`/`edit_window` give a sequence held in part that stretch; a whole pass is told apart from a miss (`PlaceMisses::whole`).
  - Delete flags the whole range, hidden elements included (over `MAX_DELTA_BARE` refused: split across commits); its undo undeletes only what showed before. Move reads only the range's rows plus the `outside` rows hanging from it, each skipped with its subtree (`Placement::hanging`), and `to` skips by rank: O(range + √n). Each flag-only element of a range record becomes its own chained root, counted against `MAX_DELTA_BARE`, so move/insert equal the model's write for write whatever the record split. A record with no position write is left out of the range like a virtual anchor (moving it would make the undo inexact: `move_leaves_unplaced_record_on_end_spec_5_7`).
- **Seq net effect** (`seq_ops::overlay`): later writes override; a list element reset in the commit drops the commit's earlier content of it; a deleted char is not carried; a text element the commit made carries no flag (it would lie below the creation at the delta stamp and lose): removed, it is its creation without its char; a created-and-removed element is omitted only when nothing else in the commit anchors at it (§4.5).
- **Seq undo**: insert → flag/element reset; text delete → undelete with the pre-commit char where that state showed it; list delete → re-insert after the old element with a fresh dot; undelete → delete where it was deleted before; position writes → old anchors and sibling keys with fresh counters in the old stamps' order, only while `cur` has the undone write's anchor and key; nested list content through `undo.rs`.
- **Diff** (`seq_diff.rs`): Myers after trimming the common prefix and suffix, giving up past 512 edits (the middle is then replaced: any script is valid, §9); inserts anchor after the preceding matched or paired element; opaque list elements are left out of the alignment.
- **Linearization** (`linearize.rs`): whole state per call, by index into the dot-ordered records. A range record is one node, split after each element something anchors at and where a virtual `Derived` anchor falls inside it, so node order matches per-element order; a dot an anchor names without a record is a virtual node on END. `Placement` is per node; anchors are found by binary search after trying the node just before in dot order (where typing anchors). Cycles: rounds of walks (from every node, then from the victims), each node once per round, nodes reaching HEAD or END marked; a walk demotes the cycle it closes. Linear on adversarial graphs.
- **Placement cache** (`seq_lin::Lin`, behind a `OnceLock<Arc<_>>`, not part of `Eq`), per `Seq` of `LIN_MIN` = 64 records or more (1 under `cfg(test)`, so the model differential checks it):
  - Rows (node, last element, parent, chosen edge stamp, depth, shown, a visible text char) in `Arc` blocks of about √n (4 to 256 when built, split above twice that; `take` merges one below half with a neighbour), each with its visible count and least depth, plus a depth shift per block outside the `Arc`. A subtree is the rows up to the next one no deeper (all-deeper blocks skipped). A row-dot → block map in sorted `Arc` chunks of about √n (at least 64). A copy clones only what it writes; lookups and a splice cost O(√n).
  - Every join follows it: `elems` is private, `elems_mut` drops the cache, `join_elems` plans each record before it joins and `Lin::follow` splices new runs where they place (after the anchor and past its children with greater edge stamps; at HEAD before the END rows). The newest of a delta's runs and moves, above `Lin::newest`, goes right after its anchor without reading the children, unless it moves onto an element new in the delta. Moved elements are re-placed in write-stamp order so a mover's outside re-anchors come first; one landing where it was only shifts depths. Flag and content writes carry their visibility from the plan walk, per block (`flip`; `plan_pieces` for a decoded record over several state records). A record whose join changed nothing is not followed.
  - Rebuilds: a delta with more than max(√n, 64) runs, moves and row cuts, or whose placements look at more than max(n, 1024) rows and blocks (a skipped sibling counts 8; cuts charged with their walk), so hostile deltas cost about a whole pass (`hostile_moves_join_bounded_spec_6`, `hostile_cuts_join_bounded_spec_6`); a move closing a cycle, touching an element on a broken cycle (`Lin::cyc`; else old demotions stay forced, §6.2), naming an unknown anchor or dropping one inside a range record; resets and new `Derived` records.
  - A write over part of a range record or a new anchor inside one cuts the row where a whole pass cuts the node (`cut_row`, `Plan::Cut`: the second piece becomes the first's only child, its subtree one deeper by `reshift`; creation-less pieces sit side by side on END). A row the delta moves sits by its old chosen write's sibling key until re-placed (`sits`): the join may have replaced that write by a copy (§4.1), so reading the record (`Sibs::key`) would misplace a sibling.
  - Held `Derived` elements and anchors at them are followed like any other, at a `Slots` position too. Text `read` and `diff`/`edit` take chars from the rows; a list `read` steps through records in dot order alongside the visible rows (no per-row value cache: a list element's read can be any size). `testutil::check_lin` compares the cache with a whole pass after every join, and the dot map, counts and `present()` against `written()`.
- **Held in part** (`seq_place.rs`, `SeqPlace`): the node stores a paged sequence's placement in this form (top, block rows by arena id, dot-map chunks by first dot; notes/engine-paged.md, Paged state) and loads it in part (`from_top`: blocks and chunks as stubs with counts, least depth, first dot). Attached to a sequence held in part (`set_seq_place`, `cover` = the loaded pages' dot ranges), joins follow it and index ops resolve through it; reading a stub or a record outside the cover notes a miss (`seq_lin::Partial`, shared by copies; `Covered` wraps record lookups, also under `Layered`) and fails (the follow returns `false`, the op's result is void), so a read returns whole once its misses load, never short. Presence needs a visible placed node, `is_empty` any placed node, `inner_max`/`written` every record (`all`). Stored rows keep no char (`fill_chars` only on a whole load; `Vis::chars` takes it from the record). `dry_follow` follows a copy over copies of the touched records (`Over`) so the node loads misses before the join; `diff` lists changes against the stored placement (blocks by `Arc` identity, chunks by first dot). `Set` loads a sequence whole. `Fragment::visible_range` and `read_elems` read by index from the cache or stored dots. What remains: issues/crdt-seq-linearization-cost.md.
- **Undo** (`undo.rs`): §4.6 states only constraints (rights, no revived value-less content, copy expiry, SHOULD restore the prior read); receivers never re-derive an undo, so this is one writer's choice. Cancel per dot over the original delta, walked in step with the current state and the pre-commit state (`before`). A position absent before the commit, under one present before, is reset (`remove_aspect`'s delta) when it reads now what the undone delta joined into `before` reads; else the per-write rules run. That reset also drops later concurrent writes into it, as the register rule overwrites a later equal edit; the engine runs it on the whole state when it reaches a paged collection held in part (`undo_in`: others' entries sit on untouched pages). A register absent before inside a present struct stays (no nested register reset). A key removed with several entries returns as one entry of their joined value (separate re-adds would tie on the undo stamp). A nested edit under a map key is undone against the join of the key's live entries before (`entry_frag`). A pre-commit value not fitting the view (two schemas on one AK) fails (`Mismatch`).
- **Undo positions** (`touch.rs`): `touches(f)` lists where a fragment writes, as paths through struct fields and enum cases to an element's dot, a map record's dot (keyed: `[Key(k), Dot(d)]`), or a composite, register or `Slots` position; `present_at` reads presence along one (`None` past another encoding). Undo reads the state before only there and the presence above, so the engine joins only the parts writing there (notes/engine-retention-history.md Undo). **Restores** (`undo::restores`): whether undoing a delta writes back replaced content, by its writes' kinds alone (§4.6); the property tests check an undo restoring nothing copies nothing back (`Writer::copied` empty).
- **Un-merge** (`lifecycle.rs`, §4.6): the node joins its held bodies with `remove_writes(pred)` applied (an author's dots or one delta's), never on the joined state. It removes exactly the matching writes, record creations included; others' writes nested in such a record stay, the record reading as if its creation was never held (one rule for every collection). `holds_dots` says whether there is anything to remove. The same function strips a snapshot's copies.
- **Access** (`access.rs`): `Map::entries()` and `Map::live(k)` (the node adapts `roles.0` entries into perm edge writes, reads `secrets.0` keys); `Fragment::at(path)` reads one position (a key with one live entry in place, O(log n); several joined). `Batch` resolves through such a key in place too (`key_lookup`), so a nested write into a large inner map copies nothing. `present()` stops at the first presence-counting write (= `written().is_some()`).
- **Paging hooks** (`paging.rs`, for the node's paged states): `elem_count` (records), `elem_dots`, `elem_range` (the collection restricted to root records in a dot range), `touched_elems`, `Step` / `Paths` (positions below struct fields, enum payloads and map entries), `step`, `at_steps`, `wrap` (a fragment holding one piece at a path, entry keys and creations carried), `reduced` (paged collections cut to their reset and `W`), `collections`, `touched_paths` (what joining a delta can change per paged collection, and whether the rest; `None` for a reset at or above one).
- **Walk** (`walk.rs`): `Fragment::writes` lists every write's origin dot with its `ts` for judging a snapshot's writes and ranking them. One read-only walk (`walk::walk`, a `Visit` over stamps and records, never expanding range records) drives `writes`, `live_writes`, `holds_owned`, `holds_owned_write` and lifecycle's `holds_dots`, `holds_stamp`, `holds_write`, `origin_dots`, `keyed_resets` and keyed-record writes.
- **Entry creation** (`Entry::created`, spec §3.2, §5.6): `(ts, entry dot)`, set by ops for fresh entries, implied when decoding a writer's own creations, carried as `Ci` by snapshots, pruned like any write, dropped with the content, kept through paging. **Authors** (`Snapshot::authors`, §8): per `Commit` source the node and `ts` its writes are judged as; omitted when empty. `has_reset`, `is_plain_struct`, `is_put_only_map` (`shape.rs`).
- **Key index**: `Map.keys` (key -> keyed records `Eid` carrying it, a superset; lookups check liveness, `Map::live_ids`; not part of `Eq`), kept by `join_entries`, `Map::new`, batch `overlay`. Records are `entries: BTreeMap<Eid, Entry>` (`Eid { dot, key }`, `Key` ordered by canonical bytes); a dot's records are contiguous, the key-erased one first (`Map::of_dot`), pruned together (`state::prune_dot`). Index paths and `Remove` of a map key still scan or clone.
- **Left near-parallel on purpose** (merging came out line-neutral): set element vs map entry join and overlay (state.rs `join_elems`/`join_entries`, batch.rs `overlay_elems`/map arm; the entry's creation prune sits between content prune and join); the mutating walks `strip_values`, `remove_writes`.
- **Costs counted**: a received insert, delete or move into a text of 30 and 300 runs follows the cached placement, no whole pass (`small_joins_follow_cached_placement_spec_6`, `seq_lin::probe`); its placement work grows about with the square root of the runs. A small change inside a huge value is O(change) at the node (osis-node `scale::`, notes/test-scale.md Scale checks).
- **Tests**: the property `tests_model::crdt_equals_model` (a seed's mode by index: the kitchen sink; writers of different encodings at one position; maps of texts and lists, lists of structs; twin writers sharing source and clock, so same-stamp copies with differing payloads and one dot under two stamps; hostile single-record text and list writes). Each history is joined twice in random order with duplicates, state and read equal to the model's after every join and the cached placement a whole pass's; piece laws without a model counterpart (`part_at`, `contains`, honest copies; hostile: `part_judges_as_whole`, a placement held in part); each writer's delta and a snapshot after each delta byte-identical with the model's, decoded alike by both decoders and back to the state (twins excepted: a forged dot under two stamps has no encoding); strip and un-merge equal to the model's and commuting with join; a coverage tally at every size. `Quick` (100 seeds, about 8 CPU-s) in the default tests; `crdt_equals_model_large` runs `Small` (1000) or `Large` (10,000, `OSIS_FULL=1`); `OSIS_CRDT_START`/`OSIS_CRDT_SEEDS` replay one seed at any size. Beside it: every rule 7 run rejection, the worked examples as `*_spec_example` tests, random undelete, ops against a plain-string model, batch = one by one, replica convergence, undo, diff, `edit` rebase, cut/paste identity, list delete vs newer nested write, Derived anchors after expiry; the placement cache against a whole pass after every join (typing, siblings, wire deltas, moves with cycles: `cached_placement_follows_moves_spec_6_2`, about 80% of move joins followed; hostile deltas bounded by `seq_lin::probe`, a per-thread work counter, as default tests never time wall clock; `tests_seq::snapshot_then_edit`); held in part: `snapshot_edits_follow_cache_spec_6`, `index_ops_on_partial_placement_match_whole_spec_5_7`, `set_on_partial_text_matches_whole_spec_5_7`, `set_after_op_on_partial_matches_whole_spec_5_7`. Fuzz: `seq_follow`, `seq_ops` (`fuzz_seq.rs`). By hand: osis-bench `budget_text_snapshot_ratio` (synthetic typist or the automerge-paper trace via `OSIS_TEXT_TRACE`: 2.9x at 100 edits per commit, 6.7x at 10).

## Implementation (`osis-commit`)
- **Commit floor**: a minimal content commit (header plus one register delta) is about 300 bytes once nonce, framing, tag and padding count, plus a 57-byte wrap per label and a prefix of about 35 bytes.
- **Header** (`header.rs`): `Header` with every spec/wire.md §4 position; a list that goes by link keeps its root in `links` and is empty until `resolve(src, actor dedup)` reads the chunk tree. Encoded and read in place (`Header::encode_into`, `Header::read` over a `cbor::Item`); `decode` checks structure and canonical bytes (re-encode equals input, no tree either way), `decode_stored` reads a header this node verified without the re-encode and delete-key point checks; `validate` checks every rule a header shows (sort orders, indices, ranges, kind vs aspect class, one delta per aspect, fixed retention, delete levels exactly the retention's, expiry, purge, frontier only on kind 1) and needs resolved lists. A higher format version is `UnknownVersion` (Parked) before the arity check.
- **Header lists are read by shape** (`header.rs` `read_*` over `osis_base::Reader`, inline and linked; `tree::parse_node` too; `frontier_value` for a linked header or frontier): worst honest shape about 5 B of memory per list byte (purge at 21 B per item), where a whole-value `decode` costs up to about 56 B per byte. Items in strictly ascending bytes, checked in `Header::decode`, so a repeated chunk link is refused at its first repeat. `validate` still states each list's own order.
- **Header lists** (`lists.rs`): crate-root `write_list(bytes, dedup, sink, prefix)`/`read_list(root, dedup, src, max)` adapt `BlobSink`/`BlobSource` (prefix inputs in, plaintext out; own traits: crdt's `PageSink` computes the link hash from plaintext, which a tree node's hash is not, and takes no prefix) to the tree module with `ChunkParams::FORMAT`; `MAX_LIST_BYTES` = 64 MiB (format constant, spec/wire.md §2: a resolved header is in memory); `Header::resolve` (past it, bad input); `MemoryBlobs` (tests).
- **Commit blob** (`blob.rs`): `CommitBlob { header, sigs, parts }` (the stored form, parts sorted by `ai`: `part(ai)` is a search), encoded by concatenation (header and delta bytes are already canonical items); decode reads it in place, keeps each part's delta bytes, then re-encodes and compares; `decode_stored` skips the re-encode for bytes this node wrote. `missing()` = header deltas the blob lacks. `Envelope` is the wire form: one `Section` per reader actor (`seal_commit`, `Envelope::open`).
- **Retention** (`retention.rs`): fixed tables, `write_retention`/`write_expires` (fixed > override > schema default > untyped `admin`), `snapshot_retention` (fixed-retention aspects keep the fixed one, others `writer`), `role_kept`, `purge_keep_until` (the purge floor `ts + ROLE_KEEP`), `delete_levels`; what a history keeps is the engine's door (notes/engine-retention-history.md).
- **Delete keys** (`keys.rs`): the `Secrets` trait (dedup, and the public delete keys: admin, author-chain write, thing write); `delete_keys` lists every level the retention calls for (a missing key is `Build`); `DeleteKey { level, key }` in the header (validated as a point when decoded); `Prefix { salt, thing, expiry, keys }` is a linked blob's prefix input. osis-label computes the commitments (`Prefix::for_delete_keys`, one per level: each key blinded by the blob's salt and its `blind`, a commit blob's the header's, a linked blob's the thing blind of its link blind and `thing`, spec/crypto.md §7) and lays them out.
- **Builder** (`builder.rs`): `CommitBuilder` takes resolved per-aspect `AspectWrite`s (delta bytes encoded by the caller against `writer_ctx`, retention, expiry, schema); sorts, hashes, builds the delete-key table, validates (caller mistakes surface as `Build`), links lists above `CHUNK_THRESHOLD`, signs, checks the whole commit fits one blob (`blob_bound`). Header-list blobs: prefix expiry = the commit's `expires`; the commit's level-2 commitment only.
- **Chunk trees** (`tree.rs`, `pub mod tree`): the only implementation, re-exported by osis-label under the same names: streaming `TreeWriter`/`TreeReader` over `TreeSink`/`LinkSource` (errors are commit's `Error`: `Corrupt` for a content hash or level, `TooLarge` beyond the caller's bound, `Missing` retry-safe), `write_tree`/`read_tree`, `HashSink`, `node_plaintext`/`parse_node`. The reader takes an output bound and follows spec/wire.md §6 tree reader bounds (a non-final chunk below `CHUNK_MIN` is bad input; at most `max / CHUNK_MIN + 1` chunks visited). The visit cap is what bounds work: repeated links are legal (identical chunks share a blob), so a tree of empty or repeated chunks would otherwise cost hundreds of thousands of fetches for no output. osis-label's `Error` is this same type (`UnknownFraming`, `Verify` are label's cases).
- **Verify** (`verify.rs`): `verify_part`/`stream_part` (delta hash under the thing's dedup secret, then osis-crdt decode against `delta_ctx`: own source = author node or `Commit(id)`, header range, kind) and `verify_blob` (signature, `validate`, every part); `read_part`/`read_part_whole` decode a part this node checked in full, without the checks.
- **Prefix inputs and rewrites** (`groups.rs`): `prefix_groups` (one commitment group per distinct delete-key set among a blob's aspects, spec/wire.md §5) and `prefix_expiry` are what any blob of the commit must carry (label's prefix-vs-header check, rewrites); `rewrite` (a purge's) keeps header and signature; `blob_bound` the whole-commit size check.
- **Structure** (`validate.rs`): a resolved header's structural rules. **Thing lists** (`thing_list.rs`) and **record blobs** (`record_blob.rs`): the rotation's list blobs and raw creation records (spec/wire.md §3, §4).

## Reference model (`core/test/crdt-model/`)
A small, slow, obviously-correct implementation of spec/crdt.md: `State` (fully resolved stamps), join, prune, read, the ops, un-merge (exactly the writes of the origin dots named, §4.6), the wire encoder/decoder (own canonical CBOR subset), embeddings, diff; `death.rs` (a write's identity, winning writes, supersedes as "dead in the join with it", holds by dot, covers by canonical bytes, §4.7 value-less writes) and `origins.rs` (dot to commit by the headers' forms and ranges), stated over `writes::writes` and join. osis-crdt is tested against it; held-model takes its values from it. Property tests (`tests/props.rs`):
- convergence under random delivery orders, duplication and omitted prefixes: equal reads and equal encoded states;
- join laws on random states, within and across encodings (every association and order of three states);
- single writer vs a sequential model after every op;
- wire round trip and byte-identical re-encode; the decoder never panics on random or mutated input;
- embeddings commute with join; a register delta joined into a text equals its embedding joined;
- forged copies (osis-crdt `tests_laws.rs` `forged_copies_*`: two writers share one source and clock, so their writes are same-stamp copies with differing payloads): join laws with `contains` and `part_at`, a cached placement followed against a fresh one (against the model: `tests_model`'s twins);
- diff (`read(join(S, diff(S, v))) == v`);
- death and covering: a state holds and covers each of its writes; a write another supersedes alone is dead in any join holding both; with nothing expired a state holds no value-less write;
- expiry: random expiring commits stripped at random points, equal to join-then-strip; strip commutes with join and is idempotent; value-less registers embed like stripped valued ones;
- snapshots: round trip with frontiers, frontiers equal last counters, bootstrapping from a snapshot reads the same;
- the worked examples below;
- decoder strictness (`decoder_rejects_writer_rule_violations`, `decoder_rejects_rule_7_strict`): own-counter ranges (§2.3, every dot of a run), foreign stamps in a writer's delta, nested register resets, maximal runs (re-derived from the decoded elements), a creation written as a `PosW`, more than the top-two position writes, overlapping or unmerged `FlagW` ranges, an empty text `Content` string, own (`Ci` 0) stamps in a snapshot, runs carrying no write, empty list element fragments (§4.2 Emptiness, at any depth), a `Slots` that pruning would change (slots empty, below the register's embedding, or not holding it; §7).

Decoder differential (osis-crdt `tests_decoder.rs`): random histories' writer deltas and snapshots, mutated at the byte level (byte nudged, overwritten by a small CBOR item, inserted, removed, tail cut) and structurally (decoded to a value tree, an int nudged or set to a boundary, an array element dropped, duplicated or swapped, a map entry dropped, re-encoded canonically, so mutants reach the semantic checks), decode alike (accept/reject, and equal fragments) in the model and the implementation. Value tags beyond set, tid and enum are not modeled (the implementation keeps unknown tags, spec/data-model.md §5): where the model rejects for a tag, the implementation must reject too or have decoded an unknown tag or a link. 48 cases per default-test run; a 2000-case release run is green.

Not modeled: the schema projection of the diff (the model's diff is untyped); links (copy and key order by bytes: osis-crdt `links_compare_by_bytes_spec_3_3`). The model's decoder checks the canonical-form rules its own way: prune stability by comparing the stamps `walk` yields before and after a prune, read depth by a walk (`Frag::read_depth`), commit-level stamps by `levels_at`.

## Structural diff: the reference script
The spec fixes only the identity rule and `read(join(S, diff)) == v`; osis-crdt's script (`ops.rs`, `seq_diff.rs`; the model's `diff.rs`) is, per encoding, recursive:
- register: write iff `read(S) != v` (bit-exact for floats) or S absent.
- bag: counter: `inc(v - read(S))` if different; max/min: reset + contribution if `v != read(S)` (a max cannot go down otherwise).
- struct: per field of `v`, recurse into `S.fields[id]`. Fields in S but not in `v` are left alone (open structs: the writer knows only its fields; a typed `v` has all of them). A field absent in S whose value in `v` equals its declared default produces no write (defaults are never materialized).
- enum: same case → recurse into the payload; different case → `set_case`.
- set: adds for values in `v` whose `view` matches no live element; removes for live, non-opaque elements whose `view` is not in `v` (one reset stamp). Large values compare by keyed content hash.
- map: keys (under `view`) only in `v` → put; non-opaque keys only in S → remove; both → recurse with the key's read (the join of its live entries) as S, the writes going into the key's live records by `key_writes` (§5.6 Ops).
- list: opaque elements are set aside and keep their place; LCS (Myers) over the rest with equality = `view(read(elem)) == item` (deep); unmatched old elements and new items are **paired in order** while both remain and recursed into (a changed entry is an edit, not delete+insert); leftover old → delete (element reset), leftover new → insert after the preceding matched/paired element.
- text: Myers diff over chars → deletes and inserts (no move detection). Equal strings → no writes.
- absent S: everything is a creation; composites with no content get an explicit `W`.

## Canonical form decisions
One rule throughout: what the decoder accepts re-encodes and re-prunes to itself, so a delta has one byte form and carries nothing its own join would drop.
- **Prune-stable deltas** (§3.3 rules 5, 7): a carried write its own resets prune is bad input, not "accepted, dropped at join": a dropped write is still a write for un-merge and frontiers (a snapshot carrying it under another author's reset would revive it when that author is revoked), so one delta would have two meanings. Checked by pruning a copy and requiring every carried write copy to stay (`codec::prune_stable`, `Fragment::carried`; not `winners`, which leaves out carried `prev` writes and deleted text creations; not fragment equality: what prune drops that is no write has its own rule 7 line, `record_without_write_rejected_spec_3_3`; a write in several records of one map dot is rejected, `write_copied_across_records_rejected_spec_3_3`). A streamed page is checked an element at a time (a map dot's records together; whole pages would raise `stream_memory_big_map`'s peak from 45 to 83 MB) under its path's effective reset (`stream::reset_at`), the last map dot carried into the next page (`prune_page`, `map_dot_prunes_across_pages_spec_3_3`). A creation implies its position write; where the top-2 leave it out, pruning drops only that implied copy (`implied_creation_pos_decodes_back_spec_3_3`). Decoders return the pruned form.
- **Read depth, not a fragment nesting cap** (§3.3 rule 7): a fragment that would read deeper than 64 with every write live is rejected; the count follows `Value::depth` (struct, map, list +1; enum, set +2; map keys one below the map). A plain nesting cap lets a state read as a value no osis decoder accepts. Writers check the same count before resolving an op (`batch::out_of_profile`: a case step counts 2, set elements and list items one below the position). The count bounds the decoder's recursion across pages (every page level adds one); inside one blob the CBOR depth does.
- **Set/bag element value of the dot's source** (rule 7): only the element's creation writes the value register, so its stamp has the dot's source (a writer's delta stamp, or the embedded write itself, §7). Not the dot's own counter: a writer's element `k` holds a value at the delta stamp `lo`.
- **Commit-level writes at the delta stamp** (§2.3, rule 7): every reset, `W`, register value, case write, element reset and flag of a writer's delta, not only `FlagW`; the other counters of `[lo, hi)` belong to creations and position writes.
- **Links compare by bytes** in copy order and map key order (rule 2): `Value`'s order compares links by content hash, so `opt_value_cmp` compares encodings whenever either side holds a link.
- **Enum case ids at most 2^63 - 1** (spec/data-model.md §5): every other integer is i64 and `Value::uint` saturates, so a larger case would be written as `i64::MAX`.

## Text size
Benchmark `core/test/crdt-model/src/bin/text_bench.rs`: Kleppmann's automerge-paper trace (259,778 single-character edits, final text 104,852 bytes, 182k elements of which 77k deleted), one writer, net effect per commit, encoded as a foreign node's snapshot. Target 1.5-3x the plain text. The table does not apply the §4.5 rule "omit a created-and-removed element only once nothing anchors at it" (which `text_bench` follows); the trace is not in the repo. The synthetic typist of osis-bench gives 2.89x and 6.73x under the rule.

| edits per commit | commits | commit table | runs | flag writes | snapshot | ratio |
|---|---|---|---|---|---|---|
| 1 | 259,778 | 2.47 MB | 6,288 | 77,463 | 4.64 MB | 44x |
| 10 | 25,931 | 243 KB | 6,062 | 12,721 | 687 KB | 6.6x |
| 100 | 2,598 | 24 KB | 6,000 | 5,431 | 331 KB | 3.2x |

Content is 105 KB and run records about 150 KB (6,000 runs at 25 bytes, the floor for this trace). The rest scales with commits (about 9 bytes of commit table plus 4 of run segment each) and deleting commits (about 8 bytes). Per-write timestamps are the design, so the client rule is one commit per editing pause, never per keystroke: at a 2 s cadence (about 10 edits) about 7x, at 20 s about 3x. In a foreign snapshot: a run about 20 bytes plus content, a segment about 4, a deleted range about 7, a commit table entry about 9; a deleted element in a run-compressed snapshot 3-4 bytes; a state grows with the edit runs made since the last reset.

What buys the size: deleted elements carry no content on the wire (182k → 6k runs), the per-delta commit table with bare indices (1-3 bytes per foreign stamp instead of 10), delta-coded table entries, runs spanning commits via segments, the shared delta stamp. Accepted (spec/requirements.md, Scale): about 13 bytes per commit forever, so clients commit per editing pause.

## Worked examples
Dots `a1`, `b3` (source letter, counter); stamps `(t, dot)`. Tests in `core/test/crdt-model/tests/props.rs` cite these.
- **Typing**: a at t=1 types `FOOBAR`: run `[1, 6, [0, [[0, 6]]], "FOOBAR", [], []]`. F=a1→HEAD, O₁=a2→a1, O₂=a3→a2, B=a4→a3, A=a5→a4, R=a6→a5.
- **Concurrent inserts at one anchor**: b at t=2 inserts `x` after O₂ (`[1, 1, [[1,3], [[0, 1]]], "x", [], []]`, sources `[a]`); c at t=3 inserts `y` after O₂. Children of O₂: y, x, B → FOOyxBAR.
- **Move with a concurrent insert**: from FOOBAR, b at t=2 inserts x after O₂ (x=b1→a3); a at t=3 moves FOO to the end: roots [F], pred HEAD, outside [B]. Writes B→HEAD (3,a7), F→R (3,a8). Read: BARFOOx.
- **Range with several roots**: abc built by inserting c, b, a at HEAD (t=1..3). Move `ab` after c (t=4): a→c, b→a. Read: cab.
- **Concurrent moves of one element**: from `abc`, a→c at t=5 and a→b at t=4. Read: bca; nothing duplicated.
- **Cycle**: from `acb` (a=a1→HEAD, c=a2→a1, b=a3→a2), B at t=5 moves a after b: c→HEAD (5,b1), a→b (5,b2); C at t=4 moves b after a: b→a (4,c1). Cycle a→b→a: b's edge (4) is oldest, b falls to prev (→c). Read: cba. Adjacent swaps do not cycle, since the mover re-anchors the outside successor to pred.
- **Reset against a newer insert**: from `abc` (t=1), A replaces with `xyz` at t=5 while B inserts `q` after b at t=6. a, b, c lose every write and go; q sits at b's virtual anchor on END. Read: `xyzq` in either order. An insert at t=3 is dropped. `remove_aspect` at t=5 instead: absent until q arrives, then `q`.
- **Move displaces a concurrent insert** (a known anomaly): from `abcd`, B at t=5 moves b to the end: c→a (5,b1), b→d (5,b2); C at t=4 inserts x after a. Children of a: c (5) before x (4). Read: `acdbx`; C intended `axcdb`. A move by position register cannot avoid rewriting the successor's anchor.
- **Delete vs move**: b deleted at t=4, moved after c at t=5. Read: ac; a later insert anchored at b appears after c.
- **Unknown anchor**: x (t=2) after O₂ arrives before FOOBAR: reads `x`, at O₂'s virtual place on END, until O₂ arrives. A reset of FOOBAR at t=5 prunes x; y (t=6) after O₂ survives it: `Zy`.
