# CRDTs and commits: rationale
> Summary: Why spec/crdt.md and spec/commits.md look the way they do: owner decisions, design choices with reasons, known anomalies, rejected alternatives, implementation hints, the reference model `core/test/crdt-model/` and its tests, text size measurements, worked examples (cited by tests), research pointers.

## Owner decisions
- One conflict rule everywhere: every state element carries a timestamp and an author dot, later wins, removal is a reset. No causal contexts; no multi-value register.
- Collection elements are identified by creation dot; a removal resets the observed dots, so an add the remover never saw survives. Tombstones carry no content (no fingerprint).
- `set_aspect` diffs structurally by default; an explicit replace resets.
- Every composite merges recursively down to leaf registers; enum cases never merge with each other.
- Movable text/list CRDT ships in the MVP, as good as we can make it, with whatever fuzzing and testing that takes.
- Apps see plain values and listeners; no CRDT details reach the API. A lost concurrent write looks like any LWW loss.
- Authenticated malicious writers are out of scope (gaming the HLC to win LWW is not a concern).
- No tombstone compaction: worse merging after long separation is acceptable, discarding edits is not.
- Retention per delta (who may purge, keep bounds; spec/commits.md §5), purge per commit without batching, expiry (§6).
- Undo is per actor by default, plus an API listing every change in scope from which an admin may undo others' changes.
- Accepted: a node receiving a multi-aspect commit after one delta was purged applies the rest, so it may briefly see an aspect combination no author produced.

## Design choices and why
- **Stamps.** HLC tiebreak lives in the dot's source, which also works for commit-form dots (the commit ID is unknown before signing). Commit-level writes share one delta stamp: saves 3–6 bytes per write and most intra-commit ordering questions; a delta still consumes at least one counter so frontiers cover every commit.
- **`>=` survival** lets a replace and the embeddings put content at the reset's own stamp.
- **Presence stamp**: an explicitly empty collection exists, one emptied by removals stays present, `remove_aspect` makes it absent. Only `W` is stored and the rest computed, so expiry can lower presence. `W` is always encoded; omitting it under a greater inner stamp would break un-merge.
- **Derived sources** give the register → text embedding one identity per character without a third dot form. A `Derived` record goes with its write, matching a node that only saw the value-less register.
- **Bag contributions are set elements**, so undo of an increment is an idempotent element reset. No bag GC: dropping non-extreme max/min elements or folding contributions changes the read under a later reset landing between the folded stamps, and under expiry of the extreme. Bag reads are order-independent (exact int sums clamped, float sums in dot order, IEEE totalOrder).
- **Enum payloads filed per case**: a writer editing case A's payload while another switched to B must not flip the value back to A with a half-written payload; the newer payload write stays hidden until a reset (spec/requirements.md, Data model).
- **Map tombstones live until the map is reset**, because an older nested write may still arrive and must lose. Same-key entries are not merged into one: the dots are different authors' identities, and joining at read time gives the same value with no rewrite.
- **No set/bag tombstone GC** (dropped for uniformity with maps). Received-range GC was sound (only a causally later undo can target an applied dot) but needed a `W` fold for presence, a "dot in received ranges with no record counts as tombstoned" join rule in every node, and made snapshots differ between nodes. The cost cannot be made opt-in "only when big": the join rule and fold are shared semantics, not a local trigger, and `replace` is no compaction tool (fresh dots lose concurrent removes, the reset drops concurrent older adds). Cost accepted: ~10 bytes per removal forever (spec/requirements.md, Scale); most sets never see a reset since the diff path emits none. If a real workload needs it: run-compressed tombstone records (contiguous dots, one reset stamp) are a representational, divergence-free wire change.
- **Text deletes by flag, lists by element reset.** Text content is immutable and has no stamp, so a flag plus undelete-with-char restores it exactly. A list element's content is a mergeable fragment: with a flag, a concurrent newer nested write stayed in local state but never reached the wire (deleted elements carry no content), so a snapshot "covered" the write's body while omitting it, a node bootstrapped from the snapshot never saw it, and an undelete then read differently on the two nodes. As a reset, the newer nested write survives and shows (as for maps; spec/requirements.md, Data model), snapshots carry it, and list undo re-inserts with a fresh dot like set and map undo. Both keep the anchor.
- **Sequence records are never pruned.** Dropping element records on reset would hide a concurrent newer insert anchored into the removed text until the next reset, violating "a newer write never loses to an older removal"; with bare anchors the insert lands after the new content, as in Yjs. Emptiness counts records, or anchor survival would depend on arrival order. Cost: a sequence's state never shrinks (spec/requirements.md, Scale), about one byte per run.
- **Creation write kept apart from the top-2 positions**: needed to encode runs and to give text content a stamp.
- **Cycle breaking** demotes the oldest move in the cycle, the one the other movers did not know about, keeping the newest intention. Falling back twice needs three or more concurrent moves over the same elements; END keeps content visible instead of hiding it.
- **Move** writes `pos` only for range roots (rewriting interior elements changes their sibling keys and reorders concurrent neighbours). The range spans deleted elements inside the selection; outside subtrees are re-anchored in reverse visual order. Delete is a flag, not a move to a trash position, which would drag concurrent inserts along.
- **Encoding slots.** Keeping the register as its own slot makes the state at a position a product of lattices, so the join laws hold across encodings (the model tests every association of three states). Cost: in a `string` → `text` upgrade the last register write is stored twice until a reset. Register edges are total so a value-less write embeds like its valued copy. Members do not copy the position's reset and are dropped once below the register's embedding: with copying and a grow-only member set, a member pruned away by a parent reset before it met its siblings vanished, while one that met them first survived holding only the reset, so nested positions joined order-dependently (found by crdt-core's differential tests).
- **Why join is a lattice**: the union of write sets with per-register maximum is a join-semilattice, and prune is a closure operator that commutes with it (a write a reset drops would be dropped by that reset after any later join); hence commutativity, associativity and idempotence.
- **Un-merge is defined by the held set.** A node that merged a later-revoked author's writes and one that never applied them hold the same bodies and must read the same, so the result is the join of retained bodies and residues less the author's writes (spec/crdt.md §4.6), not an in-place edit of the state. In place is exact for creations, flags, resets and elements; a register or position the author's write topped needs the retained bodies (position registers keep only the top-2). Residue: content the author's writes replaced under keep-at-most 0 is already dropped and deleted at servers; a writer that still holds it re-uploads it by convergence, and the author's own write revives value-less.
- **Death of a write** (spec/crdt.md §4.8) is what retention bounds measure from, per write rather than per delta: one surviving character must not keep a paragraph's deleted text alive under "no history", and a long-lived text must stay compactable under "30 days after replaced". Dropping a body is always possible locally (snapshot the aspect, drop), so keep-at-most never needs another node.
- **Purge is value erasure too**: a purged write is held value-less from the purge on, like an expired one, so a snapshot that carried its value is no longer covered-equal and gets dropped and re-made. Un-merge may revive a write whose body went under at-most 0; it revives value-less.
- **Expiry is value erasure, not a floor.** It changes no stamp or order, only whether a value is known, so it commutes with join and arrival order; a late older write still loses to the expired one. Dropping the commit's resets instead would let content they pruned survive on a node that received it after T. A floor at T diverges if applied only when the expired write wins (a write stamped between the commit and T wins on some nodes, loses on others), and expires others' newer writes if applied to every register the commit wrote.
- **Drift cap parks** commits from the future instead of holding the clock back, so a wrong clock harms only its owner's writes. Parking is silent: a device 90 minutes fast has its writes held by everyone for 90 minutes, and blind nodes cannot tell it. Hence the corrected clock (spec/sync.md §6): a device fixes its stamps at its first connection and later writes are not parked; only writes it stamped before that wait. A lying peer can shift a node's clock, which harms that node's own writes or admits writes a little early; estimate over several peers, preferring pinned servers. HLC receipt already pulls a slow clock forward.
- **Diff takes the writer's view**: without it an old writer's save of a `set<struct>` removed every element a newer writer had extended and added a stripped copy. The diff algorithm itself is not normative, only "kept elements keep their dot".
- **Second dot form** (commit ID, index): unlinkable, and collision-free when several devices sign with one key (per-device counters under a shared key let any holder reuse another's dot and knock out its edit). Its cost falls only on such commits: runs do not continue across commits, one 32-byte `Sources` entry per foreign commit, revoke frontiers list commits.
- **`Sources` lives in the delta**, not the header: a delta is then self-contained (projection, purge rewrite, import and hashing need no header context) and the order rule is well defined per delta; the header rule "first appearance in the canonical encoding" was circular across several deltas. Cost: a source repeated per delta of a multi-aspect commit.
- **`Derived` sources stay.** Dropping them (reset-only embedding of a register into text) was examined: an old app's string save concurrent with a newer text edit would then read as the edit alone, the string vanishing until someone writes; with embedded characters it reads as the string plus the edit, placed. The string→text upgrade is rare, but a vanishing value is the kind of wrinkle the design exists to avoid, and the model already tests the edge.
- **Expiry is per delta** (an aspect of a commit), since retention is; the blob prefix carries the expiry of the retention class it holds (projection by class).
- **Imports carry bare anchors** (spec/crdt.md §3.3 rule 7, was issues/import-bare-anchors.md): a snapshot keeps a bare anchor for an element whose writes a reset pruned, so later inserts anchored at it still place; a move imports from that snapshot, and dropping the anchors hid those inserts in the copy (unknown anchor, §6.1). An import may carry bare-anchor runs, counted against `MAX_DELTA_BARE` like its other content-less runs, so the copy is complete and places alike; the importer carries only the elements its shown ones need (below). Only snapshot origins produce them; a receiver cannot tell an origin's kind (the origins table has none), so rule 7 rejects them only in writer deltas (implementation and model alike). Rejected: re-anchoring imported edits at the nearest carried element (the copy's order could differ from the original's).
- **Imports carry only what the copy shows needs** (spec/permissions.md §7, was issues/import-over-max-delta-bare.md): a move of a text with many deleted characters (a compacted 300k delete: content-less elements in the snapshot; uncompacted: the typing commit's chars) imported them all, past `MAX_DELTA_BARE` or as dead weight, and the encoder did not even check the bound (receivers rejected the import). Now every origin's delta keeps of each sequence only the elements the importer's state shows plus, transitively, those their creation and position writes (both kept pos writes, §6.2) anchor at, a creation chain's earlier elements included (`Fragment::shown`, `keep_shown`); one rule for deleted elements and bare anchors. Kept elements the state does not show lose their content (a text creation goes value-less, §4.7), so a copy never carries erased text (review found "SECRETXYZ" in import bytes when shown text chained through it). Elements left out read the same in the copy (an element with an unknown anchor is hidden, and only unshown ones lose anchors); the copy's later writes only reference shown elements. Rejected: splitting an import (needs a rule for which elements go where and dots per piece) and exempting imports from the bound (a small delta could create many records). Residue: shown text typed after more than 2^18 deleted chars of one chain still needs them; the encoder now counts content-less runs (`Enc::note_bare`) so `move_thing` fails cleanly (test `move_over_max_delta_bare_fails_spec_perm_7`).
- **Every state element carries its dot**, so un-merge and revoke frontiers are uniform.
- **No commit DAG**: causality is intra-aspect only, tids may dangle.
- "Repair via listeners" only works if the repair is a deterministic function of state; otherwise two nodes ping-pong.
- Encoding IDs live in the delta, not in the header.

## Known anomalies (all convergent)
- A move displaces a concurrent insert made right after the moved range's predecessor (example below).
- An enum payload edit concurrent with a case change stays hidden (spec/requirements.md, Data model).
- A field write concurrent with a container removal resurrects the container with that field alone (spec/requirements.md, Data model).
- While a text aspect is in transition, every save by an old LWW app wipes concurrent older text edits; old code has no CRDT.
- The list diff pairs changed entries in order; a misaligned pair becomes delete+insert and loses concurrent edits to that entry. Apps editing list entries concurrently should use path ops.
- Un-merge restores values and positions the invalid author's writes had superseded only from retained bodies; a node that dropped them under keep-at-most reads them as absent until a peer re-supplies the body.
- Undo of a reset re-adds content with fresh dots (the old dots stay below the reset forever), so a later undo of an original element no longer cancels its restored copy; only out-of-order selective undo sees this. Bag undo re-adds contributions without a reset so concurrent newer contributions survive; other encodings' reset undo is a `replace` and wipes concurrent newer writes inside the value.
- Undo of a move writes the old anchors back with fresh stamps, so a moved element now sorts before siblings at its old anchor that were newer than its original position write; the read can differ from before the move.
- Undo chains on one position (§4.6): a register or position undo also writes when the winner is an undo-in-effect's write equal in value to the undone one and every later non-undo commit of the aspect is out of effect. Safe because it fires only where undos already restored this value and nothing later is live: no independent newer edit is clobbered (another writer's, or an own selective-undo target's later equal-valued edit; that case removed a live value under value equality alone). Judged at aspect level, so a live later edit of another field of the same aspect also blocks (conservative: `NotUndoable`). The node builds the undo relation lazily from the aspect's commits (`chain_judge`), walks it without recursion or a depth cap (a tree: an undo names an older commit by hash). Enum case writes are undone as resets. No wire change.

## Rejected
- Wall-clock staleness horizon for tombstones: nodes separated longer than the horizon diverge or lose edits; any independent reset-style compaction has the same problem.
- LWW-element sets/maps: the tombstone names a value hash or key (a fingerprint once the body is purged) and cannot be dropped without stability information.
- OR-set/OR-map with causal contexts: same add-wins semantics as dot addressing but a version vector in every state and delta. Possible later if map tombstones ever matter: stability-based GC (needs frontiers, stalls on offline members).
- Terminal reset / retire marker in the encoding lattice: representation changes are transitions to new IDs.
- Destructive join of unrelated encodings (later encoding wins, the loser becomes a reset): with eager embedding it is not associative, `(register ⊔ counter) ⊔ text` ends as a counter and `register ⊔ (counter ⊔ text)` as a text.
- Attributing state elements through commit headers instead of dots (zero bytes in state, history lookup at revocation): not uniform.
- Columnar or bit-packed encodings (20–30% gain, not worth leaving CBOR); dropping stamps from deletions (changes undo, and deletions are no longer the dominant cost).

## Implementation hints (non-normative)
- Linearization: cache the order and tree; a delta touching k elements re-places those k subtrees; a cycle recomputes only its strongly connected component.
- Large states page in the local store like snapshots (notes/local-store.md, Units). Very long texts (tens of MB) load fully for linearization; a subtree-count index is a later optimization.
- If a concurrent edit resurrects an element whose content this node dropped, request the specific blobs that carried it.
- Cut/paste: the client remembers the cut dot ranges beside the clipboard text; paste emits move + undelete if the clipboard still matches, else a diff. Optional osis clipboard MIME type with (aspect, ranges); the protocol has no clipboard concept.
- Undo stack is derived, not stored: the actor's own commits in scope (a set of aspects or a group) minus undone ones, plus undo commits for redo. Replicates for free, so undo works across devices. A node keeps its own bodies and pre-reset snapshots locally for the undo horizon.
- A list path op resolves index paths against local state at write time; deltas never carry indices.
- A commit has no size limit: any delta pages like a snapshot (§8), so a bulk `replace` of a huge map or an import is one atomic commit; the writer streams pages out, readers stream them in. Runs are capped at 2^16 elements so a page always fits.
- Commit floor: a minimal commit is about 300 bytes once nonce, framing, tag and padding count, plus a 49-byte wrap per label and a prefix of about 35 bytes. Fine for editing workloads; revisit only if huge commit volumes appear (owner).

## Implementation (`osis-crdt`)
- **Structures**: `Fragment` enum, one struct per encoding (`fragment.rs`), crate-private fields; collections are `BTreeMap<Dot, _>`, struct fields and enum payloads `BTreeMap<u64, _>`. Sequences: `seq.rs` (element state, join, prune, presence, read, strip, un-merge, text embedding), `seq_span.rs` (range records), `seq_wire.rs` (runs), `seq_ops.rs` (ops, net effect, undo), `seq_diff.rs` (diff, `edit`), `linearize.rs`; the generic code calls only the hooks re-exported from `seq.rs` and owns a sequence's reset and `W`. A text keeps the chars of deleted elements locally (undo and paste read them); a snapshot does not carry them, so a bootstrapped node's state differs only there.

- **Range records** (`seq_span.rs`; spec/requirements.md Scale: a snapshot run `[Dot, 2^16, [], [], [], []]` is 8 bytes): a `SeqElem` with `span > 1` stands for consecutive elements of one source that are uniform (no content, no position write but the creation, one deleted write or reset, no creation or a creation chain of one `ts`). Decode makes one per uniform stretch of a run (elements with content stand alone), so records are O(input). Join cuts an incoming record at the state's record starts after splitting state ranges at its bounds, and splits a chain a reset falls inside (`chain_cut`); nothing coalesces, so `Seq` equality is per element (`elems_eq`). Invariant: no record key inside another's span (a `Derived(S, c)` key splits an `S` range at `c + 1`), so `find` is the record at or before a dot. Deltas from ops and undo are expanded per element where convenient (`expand`: the format bounds them); a received state never is. Tests coalesce every model state into ranges (`testutil::frag`).
- **Slots**: every prune of a `Slots` re-embeds the register slot into each member, so a received `Slots` lacking the embedding converges with one built by join. A join into a `Slots` state that leaves its register and effective reset `E` as they are (`kept_reset`: no newer register write or reset, no member reset above `E`; the common join, sequence writes) joins only the delta's members under `E`, a new member with the embedding, so untouched members and the text member's placement cache stay (`join_slots_kept`; debug builds compare it with the whole join); anything else re-embeds and prunes the whole position. A lone non-register member is chosen without scanning (it holds the embedding, so beats the register). `Batch` layers a sequence op over the `Slots` member of its encoding when that member carries the position's reset (`seq_member`). Both decoders judge rule 7's "pruning would change it" with deleted chars dropped (the embedding restores a deleted embedded char that the wire never carries, rule 5) and return the pruned position, so a bootstrapped node holds such a char again and a content-less undelete of it reads it (`bootstrapped_undelete_of_embedded_char_spec_4_6`; returning the unpruned form let one writer make peers' states unencodable). Both reject a `Derived`-stamped write other than a text creation (and its position write); the generator sends content-less undeletes of embedded chars now and then. `crdt_model::gen` writes a string to a root register one time in three so the differentials reach embedded chars.
- **Interning**: `Source` is an `Arc<SourceKind>`; a stamp is `ts` + pointer + counter. Equality and order never depend on sharing; `Interner` dedupes per decode (a node may keep one per aspect).
- **Join** (`state.rs`) is delta-driven: `join_into(other, e_parent, changes)` walks only what `other` carries; existing children are pruned only when an own reset rises. Equals union-then-prune (lockstep tests against the model after every join). An empty state takes the other side pruned.
- **Change summary** (`Changes`): `is_changed` plus `Death { stamp, at }` for every write superseded (beaten register/case/reset, pruned write, late write dying on arrival). Writes sharing a delta stamp are reported per instance.
- **Wire** (`wire.rs`, `codec.rs`): values are built as `osis_base::Value` trees; encoding runs the fragment encoder twice (collecting pass for `Sources`/`Commits`). Decoding checks the grammar, ranges and rule 7, then re-encodes and requires the input bytes, with fetched pages replayed through a sink so the links match: every canonical rule, paging included, is that one comparison.
- **Paging**: `PageParams` (format: 64 KiB target, 16/256 KiB cuts, 512 fanout) come from the `PageSink`/`PageSource`; tests shrink them. `osis_base::PageCutter` cuts; link pages use the tree-node rule; a third level is refused. `page_array(sink, items)` is the public split of one element array (vectors); struct and enum field maps page the same way (`page_map`, a field = key and value bytes, pages are maps), so no delta outgrows a blob (spec/commits.md §1; `CommitBuilder::max_blob` shrinks the bound for tests). Decode records each position's pages after its items (`Dec::done`), i.e. in the encoder's put order, so equal page plaintexts (equal structs written in one commit) replay to their own links. Each put must be its own blob (a decode refuses a blob linked twice; the node's `LocalPages` derives a distinct ID per put).
- **Ops** (`ops.rs`, `batch.rs`): `diff`/`create`/`replace` match the model write for write under a `View`. A set element is one register holding the whole value whatever its type (`set_elem`; both decoders reject another fragment there, rule 7); a link fits only a register position. Compat: persisted states or deltas with nested set elements (old `/tenures` included) no longer decode; acceptable before a release. `Batch` makes a commit's net effect: ops resolve against state ⊔ batch-so-far, borrowing the state where the batch has no writes and copying the position where it has (`current`; map keys join only that key's entries, `key_lookup`). At a sequence position the batch already wrote (reached through fields and cases, or the list an index segment steps into) an op resolves against the state's sequence layered under the batch's records instead of a copy (`seq::Layered`: the batch's new records and every state record its writes meet, copied whole and then split where they land, so the layer shadows the state records it overlaps, plus the state's placement followed through them; sequence ops and `seq_diff::edit` read through `SeqRead`, the cache's plan/follow through `Recs`); where a batch reset lies above or the cache cannot follow, it copies as before. The view is kept (`Seen`, keyed by that path) for the next op at the same position, joined with each op's delta there while `prune(acc) ⊔ d` equals the overlay there (else dropped), checked at the op's elements only (`seq::Foot`, O(op · log n); an op dropping an anchor that named an element the commit made checks on copies), so a batch of N ops on one text costs O(N · (√n + log n)); any other op drops it. `seq::overlay` touches only the op's elements (splits acc's range records there, no whole expand) and looks for created-and-removed elements to omit only when the op removed one or dropped an anchor at one (acc never holds one to omit; debug-asserted). The debug check compares the kept view with what `current` would copy (and, in tests, its placement with a whole pass). Ops see state joined with the batch slot by slot (`member`), not the net effect's own slots: a batch writing a register at P and then a field of P resolves the field against the state's struct (the register is another slot), and the overlay of differing encodings keeps only the later write. `overlay` lets a later op override, drops a reset's earlier content, omits created-and-removed elements and then sets `W` if the collection would be left with no write (one-by-one ops would have left it present).
- **Undo** (`undo.rs`): per §4.6 over the original delta; `UndoBuffer::before(path)` gives pre-commit fragments (a pre-commit state implements it). Restores values, not absence: a collection emptied by undo stays present, a register that did not exist is not written (except at an aspect root, which is removed). A key removed with several entries returns as one entry of their joined value (separate re-adds share the undo stamp and tie). A nested edit under a map key is undone against the join of the key's live entries before the commit (`entry_frag`; the footprint keeps those entries). `undo_restores_spec_4_6` compares reads without the positions absent before the commit (`strip_absent`; issues/crdt-undo-absent-positions.md). `Undone::restored` is the node's judgment "written by an undo commit in effect, no later change of the aspect in effect" (osis-node `undo_in`, `chain_judge`); `steps_back` is the §4.6 condition shared by registers and position writes.
- **Un-merge** (`lifecycle.rs`): `unmerge(held, author)` joins bodies with `remove_author` applied; `unmerge_in_place` only when the author holds no register, case, reset or `W` write (`W` is max-joined, so the author's may hide another's) (`author_supersedes`; sequences conservatively always need bodies).
- **Linearization** (`linearize.rs`): whole state per call, by index into the dot-ordered records (a range record is one node, split after each element something anchors at and where a virtual `Derived` anchor sits between its elements in dot order, so hidden order matches the per-element order: inside a node each element is the only child of the one before or all are bare anchors on END, and the first element's edge has the chain's smallest stamp, so it places like its elements); `Placement` is per node (first and last element, span) (anchors by binary search after trying the node just before in dot order, which is where typing anchors; anchors naming nothing are collected in the same pass; sibling lists in one array, one walk); cycles: rounds of walks (first from every node, then from the victims), each node walked once per round, a persistent mark on nodes that reach HEAD, END or a hidden anchor; any walk demotes the cycle it closes. Linear on adversarial graphs. Cached per `Seq` of `LIN_MIN` = 64 records or more (1 under `cfg(test)`, so lockstep tests check it) (`seq_lin::Lin`, behind a `OnceLock<Arc<_>>`, not part of `Eq`): rows (node, last element, parent, chosen edge stamp, depth, shown, a visible text char) in blocks of about √n (at most 256 when built, split above twice that; 4 at least, so small test texts split), each `Arc` (a copy shares untouched blocks) with its visible count and least depth, plus a depth shift per block kept outside the `Arc` (a subtree's depths change without copying shared blocks); a subtree is the rows up to the next one no deeper (blocks all deeper skipped, O(√n)), plus a row-dot → block map built with the rows from the whole pass's dot-ordered nodes (no sort), in dot order (the row holding a dot is the one at or before it) as sorted chunks of about √n entries (at least 64), each an `Arc`, so a copy clones only the chunks it writes (the first chunk exists even when empty: a placement loaded from its stored top has it). Position, visible index and dot lookups and a splice cost O(√n): the block size rises with the row count (`cap = max(cap, min(√len, 256))` on insert), so a text grown by typing does not stay in small blocks. Every join follows it: `elems` is private, `elems_mut` drops the cache, `join_elems` plans each record before it joins and `Lin::follow` splices new runs where they place (after the anchor and past its children with greater edge stamps, each skipped with its subtree, 256 or more rebuild; at HEAD before the `END` rows; a cursor walks the blocks, never re-locating from the first; the anchor found in the placement, `Lin::placed`, its record only when not placed (an element of the same delta, or none); the newest of a delta's runs and moves, when above `Lin::newest`, a stamp at or above every position write kept with the placement and its stored top, goes right after its anchor without reading the children's records, which a placement held in part would load (not a move onto an element new in the delta: that element's run may go on with a newer stamp, `newest_move_onto_new_element_spec_6_1`): `newest_stamp_skips_children_records_spec_6_1`), re-places each single element whose chosen edge changed (moves, in write-stamp order so a mover's outside re-anchors come first: its subtree goes where it now places, as if cut out; if it lands where it was only depths shift, else the smaller of it and the rows it passes moves row by row, both big as whole blocks, so the dot map changes little), and flips visibility on flag/content writes, including a decoded record over several state records (`plan_pieces`: a plan per piece); a record whose join changed nothing (a duplicate, a `Slots` re-embedding) is not followed. A delta with more than max(√n, 64) runs, moves and row cuts, or whose placements look at more than max(n, 1024) rows and blocks (a sibling skipped counts 8), rebuilds, so hostile deltas cost about a whole pass (`hostile_moves_join_bounded_spec_6`, `hostile_cuts_join_bounded_spec_6`: each cut is charged with its subtree walk and depth shift, the budget checked after each). `take` merges a block left below half the block size with a neighbour, and `insert` splits an oversized block into pieces of about the block size (a long run used to leave one huge block). A write over part of a range record (decoded deletes and undeletes of a snapshot's deleted stretches, moves of bare anchors) or a new anchor inside one cuts the row where a whole pass cuts the node (`cut_row`, `Plan::Cut`: a chain's second piece becomes the only child of the first, its subtree one level deeper by `reshift`; pieces without creation sit side by side on END); a row's `parent` is the element its edge names (the parent node's last element), so a cut changes no child's row. A move rebuilds when it closes a cycle (the anchor inside the subtree, checked per step, so an intermediate cycle rebuilds too), touches an element on a cycle a demotion broke (`Lin::cyc`; otherwise the old demotions stay forced, §6.2), writes or drops an anchor naming an unknown element (an absent `Derived` one: a virtual anchor), or drops one inside a range record (the node may join the next again); anything else rebuilds too (resets, new `Derived` records). Flag and content writes carry their new visibility from the plan walk and are applied per block they touch (`flip`: one walk of each block, no per-row search). A join raising the sequence's own reset merges the records it left bare into range records (`seq::prune_reset` → `seq_span::coalesce_in`; elements equal, only the split changes), so the pass after a reset places one node per stretch of dots instead of one per old element. Only there: such a join is written whole (a paged state re-laid out), while `strip` and un-merge prune too but rewrite only the pages they touch, where a merge could leave a record spanning past its page (value-less chains of a stripped insert did: `seq_placement_differential_after_reset_spec_crdt_6` checks every stored page holds whole records). A reset raised by a parent (a map entry or list element reset, a struct reset) does not merge. Dot and source comparisons borrow: decoded deltas never share the state's source `Arc`s, so each lookup used to clone two. Held `Derived` elements and anchors at them are followed like any other, at a `Slots` position too (its join keeps the member's cache unless it re-embeds). Text `read` and `diff`/`edit` take the chars from the rows; a list `read` steps through the records in dot order alongside the visible rows, searching only where the order jumps (no per-row value cache: a list element's read can be any size, and every nested write would change it). ## Implementation (`osis-commit`)
- **Header** (`header.rs`): `Header` with every spec/wire.md §4 position; a list that goes by link keeps its root in `links` and is empty until `resolve(src, actor dedup)` reads the chunk tree. `decode` checks structure and canonical bytes (re-encode equals input); `validate` checks every rule a header shows (sort orders, indices, ranges, kind vs aspect class, roster snapshot = `/members`/`/tenures` of one thing, fixed retention, delete levels exactly the retention's, expiry, purge, frontier only on kind 1, origins iff import) and needs resolved lists. A higher format version is `UnknownVersion` (Parked) before the arity check.
- **Commit blob** (`blob.rs`): `CommitBlob { header, signature, parts }`, encoded by concatenation (header and delta bytes are already canonical items); decode re-encodes and compares. `missing()` = header deltas the blob lacks.
- **Retention** (`retention.rs`): fixed tables, `write_retention`/`write_expires` (fixed > override > schema default > untyped `author`), `snapshot_retention` (membership-class and `/created` keep the fixed one), `keep_at_least`/`keep_at_most`/`body_keep` (at most beats at least; the purge floor `ts + MEMBERSHIP_KEEP` beats both), `delete_levels`.
- **Delete keys** (`keys.rs`): the `Secrets` trait (dedup, and the public delete keys: admin, author-chain write, thing write); `delete_keys` lists every level the retention calls for (a missing key is `Build`); `DeleteKey { level, key }` in the header (validated as a point when decoded); `Prefix { salt, expiry, commitments }` is the prefix input osis-label lays out (`from_keys`: each key blinded by the blob's salt, one per level).
- **Builder** (`builder.rs`): `CommitBuilder` takes resolved per-aspect `AspectWrite`s (delta bytes encoded by the caller against `writer_ctx`, retention, expiry, schema, introduced chunks); sorts, hashes, builds the delete-key table and chunk list, validates (caller mistakes surface as `Build`), links lists above `CHUNK_THRESHOLD`, signs, checks every delta fits a blob alone. Header-list blobs: prefix expiry = max `expires` iff all aspects expire; the commit's level-2 commitment only (none for an import).
- **Chunk trees** (`tree.rs`, `pub mod tree`): the only implementation, re-exported by osis-label under the same names: streaming `TreeWriter`/`TreeReader` over `TreeSink`/`LinkSource` (errors are commit's `Error`: `Corrupt` for a content hash or level, `TooLarge` beyond the caller's bound, `Missing` retry-safe), `write_tree`/`read_tree`, `HashSink`, `node_plaintext`/`parse_node`. The reader takes an output bound and follows spec/wire.md §6 tree reader bounds (a non-final chunk below `CHUNK_MIN` is bad input; at most `max / CHUNK_MIN + 1` chunks visited). The visit cap is what bounds work: repeated links are legal (identical chunks share a blob), so a tree of empty or repeated chunks would otherwise cost hundreds of thousands of fetches for no output. osis-label converts errors both ways (`From` impls in its `error.rs`, class kept).
- **Header lists** (`lists.rs`): crate-root `write_list(bytes, dedup, sink, prefix)`/`read_list(root, dedup, src, max)` adapt `BlobSink`/`BlobSource` (prefix inputs in, plaintext out; own traits: crdt's `PageSink` computes the link hash from plaintext, which a tree node's hash is not, and takes no prefix) to the tree module with `ChunkParams::FORMAT`; `MAX_LIST_BYTES` = 64 × `CHUNK_THRESHOLD` (local policy: the format has no commit size limit); `Header::resolve`; `MemoryBlobs` (tests).
- **Verify** (`verify.rs`): `verify_part` (delta hash under the thing's dedup secret, then osis-crdt decode against `delta_ctx`: own source = author node or `Commit(id)`, header range, kind) and `verify_blob` (signature, `validate`, every part).
- **Projection** (`project.rs`): `project(commit, readers: Fn(ai) -> K)`; class = (K, retention, expiry, aspect delete-key indices), so distinct delete bases split classes; size split greedy in aspect order with exact blob sizes (prefix, Padmé, tag). `prefix_inputs(header, parts)` is what any blob of the commit must carry (label's prefix-vs-header check, rewrites). `rewrite` keeps header and signature.

## Reference model (`core/test/crdt-model/`)
A small, slow, obviously-correct implementation of spec/crdt.md: `State` (fully resolved stamps), join, prune, read, the ops, un-merge, the wire encoder/decoder (own canonical CBOR subset), embeddings, diff. Not the implementation; the implementation will be tested against it. Property tests (`tests/props.rs`):
- convergence under random delivery orders, duplication and omitted prefixes: equal reads and equal encoded states;
- join laws on random states, within and across encodings (every association and order of three states);
- single writer vs a sequential model after every op;
- wire round trip and byte-identical re-encode; decoder never panics on random or mutated input;
- embeddings commute with join; a register delta joined into a text equals its embedding joined;
- diff (`read(join(S, diff(S, v))) == v`) (undo is not modeled);
- expiry: random expiring commits stripped at random points, equal to join-then-strip; strip commutes with join and is idempotent; value-less registers embed like stripped valued ones;
- snapshots: round trip with frontiers, frontiers equal last counters, bootstrapping from a snapshot reads the same;
- the worked examples below;
- decoder strictness (`decoder_rejects_writer_rule_violations`, `decoder_rejects_rule_7_strict`): own-counter ranges and distinct counters (§2.3), foreign stamps in a writer's delta, nested register resets, maximal runs (re-derived from the decoded elements), a creation written as a `PosW`, more than the top-two position writes, overlapping or unmerged `FlagW` ranges, an empty text `Content` string, own (`Ci` 0) stamps in a snapshot, bare-anchor runs outside a snapshot, empty list element fragments (§4.2 Emptiness, at any depth), a `Slots` that pruning would change (members empty, below the register's embedding, or not holding it; §7).
Decoder differential (osis-crdt `tests_decoder.rs`): random histories' writer deltas and snapshots, mutated at the byte level (byte nudged, overwritten by a small CBOR item, inserted, removed, tail cut) and structurally (decoded to a value tree, an int nudged or set to a boundary, an array element dropped, duplicated or swapped, a map entry dropped, re-encoded canonically, so mutants reach the semantic checks), decode alike (accept/reject, and equal fragments) in the model and the implementation; it found the model lenient on the items above (later also on a writer run whose first dot is in range but whose last reaches `hi`: the model's range walk saw only a run's first dot; `run_past_counter_range_rejected_spec_2_3`) and the implementation on `Slots` (fixed in `codec.rs`: a decoded `Slots` must equal its pruned form, spec/crdt.md §3.3 rule 7). Value tags beyond set, tid and enum are not modeled (the implementation keeps unknown tags, spec/data-model.md §5): where the model rejects for a tag, the implementation must reject too or have decoded an unknown tag or a link. 48 cases per tier-1 run; a 2000-case release run is green.
Not modeled: the schema projection of the diff (the model's diff is untyped); un-merge by re-joining held bodies (the model removes writes in place, which the spec permits only where it gives the same result); writes below their own reset at a root position (both decoders accept them, the implementation by re-encoding).

Content is 105 KB and run records about 150 KB (6,000 runs at 25 bytes, the floor for this trace). The rest scales with commits (about 9 bytes of commit table plus 4 of run segment each) and deleting commits (about 8 bytes). Per-write timestamps are the design, so the client rule is one commit per editing pause, never per keystroke: at a 2 s cadence (about 10 edits) about 7x, at 20 s about 3x. Sizes in a foreign snapshot: a run about 20 bytes plus content, a segment about 4, a deleted range about 7, a commit table entry about 9.

Kept from tuning: deleted elements carry no content on the wire (182k → 6k runs), the per-delta commit table with bare indices (1–3 bytes per foreign stamp instead of 10), delta-coded table entries, runs spanning commits via segments, the shared delta stamp.

Accepted (spec/requirements.md, Scale): about 13 bytes per commit forever, so clients commit per editing pause. Stability-based GC (drop per-commit stamps once every writer acknowledged) would need every writer's frontier and stall on offline members, which the requirements forbid ("whether others are alive is never a protocol condition").

## Worked examples
Dots `a1`, `b3` (source letter, counter); stamps `(t, dot)`. Tests in `core/test/crdt-model/tests/props.rs` cite these.
- **Typing**: a at t=1 types `FOOBAR`: run `[1, 6, [0, [[0, 6]]], "FOOBAR", [], []]`. F=a1→HEAD, O₁=a2→a1, O₂=a3→a2, B=a4→a3, A=a5→a4, R=a6→a5.
- **Concurrent inserts at one anchor**: b at t=2 inserts `x` after O₂ (`[1, 1, [[1,3], [[0, 1]]], "x", [], []]`, sources `[a]`); c at t=3 inserts `y` after O₂. Children of O₂: y, x, B → FOOyxBAR.
- **Move with a concurrent insert**: from FOOBAR, b at t=2 inserts x after O₂ (x=b1→a3); a at t=3 moves FOO to the end: roots [F], pred HEAD, outside [B]. Writes B→HEAD (3,a7), F→R (3,a8). Read: BARFOOx.
- **Range with several roots**: abc built by inserting c, b, a at HEAD (t=1..3). Move `ab` after c (t=4): a→c, b→a. Read: cab.
- **Concurrent moves of one element**: from `abc`, a→c at t=5 and a→b at t=4. Read: bca; nothing duplicated.
- **Cycle**: from `acb` (a=a1→HEAD, c=a2→a1, b=a3→a2), B at t=5 moves a after b: c→HEAD (5,b1), a→b (5,b2); C at t=4 moves b after a: b→a (4,c1). Cycle a→b→a: b's edge (4) is oldest, b falls to prev (→c). Read: cba. Adjacent swaps do not cycle, since the mover re-anchors the outside successor to pred.
- **Reset against a newer insert**: from `abc` (t=1), A replaces with `xyz` at t=5 while B inserts `q` after b at t=6. a, b, c become bare anchors at END; q survives. Read: `xyzq` in either order. An insert at t=3 is dropped. `remove_aspect` at t=5 instead: absent until q arrives, then `q`.
- **Move displaces a concurrent insert**: from `abcd`, B at t=5 moves b to the end: c→a (5,b1), b→d (5,b2); C at t=4 inserts x after a. Children of a: c (5) before x (4). Read: `acdbx`; C intended `axcdb`. A move by position register cannot avoid rewriting the successor's anchor.
- **Delete vs move**: b deleted at t=4, moved after c at t=5. Read: ac; a later insert anchored at b appears after c.
- **Unknown anchor**: x arrives before FOOBAR: hidden until it arrives, even if FOOBAR was reset meanwhile.

## Research
- Loro's movable list and movable tree: production implementations of Kleppmann 2020 "Moving Elements in List CRDTs" and of tree cycle handling.
- Eg-walker (Gentle & Kleppmann 2024): op-based, but its text representation and size ideas transfer.
- Kleppmann & Beresford, "A Conflict-Free Replicated JSON Datatype": nested composition, key removal vs concurrent nested edit.
- Kleppmann & Brattli, "Undo and redo support for replicated registers and sets": matches dot-cancel undo.
- Almeida, Shoker, Baquero, "Delta State Replicated Data Types": the delta-state framework; its causal contexts are not used here.
- **`put_new` (`Op::Put`)**: at a map key a new entry whatever is live (invite grants' `/secrets` puts); at a register position a register write even when equal (chunk repair); refused elsewhere, since a composite would merge with what is there (union, second entry, second copy). A repair is a plain write with a fresh stamp: it overrides a concurrent unseen edit of that position and can bring back a map entry whose removal it has not seen; it is limited to the positions whose chunks are gone and rate-limited (notes/node.md, Dropped chunks). Two puts of one key in one commit share a stamp and do not net out like two commits; no writer does that.
