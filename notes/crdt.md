# CRDTs and commits: rationale
> Summary: Why spec/crdt.md and spec/commits.md look the way they do: Tess's decisions, design choices with reasons, known anomalies, rejected alternatives, how osis-crdt and osis-commit are built, the reference model `core/test/crdt-model/` and its tests, text size measurements, worked examples (cited by tests), research pointers.

Property (notes/test-design.md): what osis-crdt computes (join, read, wire, strip, un-merge) equals the reference model's, whose join is lawful. One randomized test checks it: `tests_model::crdt_equals_model`.

## Tess's decisions
- One conflict rule everywhere: every state element carries a timestamp and an author dot, later wins, removal is a reset. No causal contexts; no multi-value register.
- Collection elements are identified by creation dot; a removal resets the observed dots, so an add the remover never saw survives. Tombstones carry no content (no fingerprint): a map removal names its key only in role-class aspects, whose keys are public ids (below).
- **Removal is final** ("if something is deleted it stays deleted, no recreation as a side-effect of editing"): a nested write newer than an entry's or list element's removal stays in the state hidden until a reset sweeps it (spec/crdt.md §1, §5.6 Live, §5.7 Live).
- **Expiry takes only a commit's own values** (notes/expiry-creation-design.md): an element shows while it is not removed and holds a live value, its creation's or anyone's inside it, so a reaction outlives a disappearing message and a removal alone does not keep it. A map write carries its record's key as its own value, a list creation and `W` are value-carrying, an undelete's char is its own writer's. Accepted costs: an offline edit inside an entry someone else deleted is dropped without notice, and a `put` on an existing key writes into it, so it is lost the same way; a writer on a stale view reads its own write until the removal arrives. Undo of a removal re-adds with a fresh dot. Consequences in the engine: code reading a delta's fragment alone sees nothing of a write into another's entry, so link finding uses `Fragment::values` (`Engine::relink_field`, `linked_blobs`) and a history row `Fragment::read_written`.
- `set_aspect` diffs structurally by default; an explicit replace resets.
- Every composite merges recursively down to leaf registers; enum cases never merge with each other.
- The movable text/list CRDT ships in the MVP, as good as we can make it, with whatever fuzzing and testing that takes.
- Apps see plain values and listeners; no CRDT details reach the API. A lost concurrent write looks like any LWW loss.
- Authenticated malicious writers are out of scope (gaming the HLC to win LWW is not a concern).
- No tombstone compaction: worse merging after long separation is acceptable, discarding edits is not.
- Retention per delta (who may purge, keep bounds; spec/commits.md §5), purge per commit without batching, expiry (§6).
- Undo is per actor by default, plus an API listing every change in scope from which an admin may undo others' changes.
- Accepted: a node receiving a multi-aspect commit after one delta was purged applies the rest, so it may briefly see an aspect combination no author produced.
- Commit floor (below) is fine for editing workloads; revisit only if huge commit volumes appear.

## Design choices and why
- **Stamps.** The HLC tiebreak lives in the dot's source, which also works for commit-form dots (the commit ID is unknown before signing). Commit-level writes share one delta stamp: saves 3–6 bytes per write and most intra-commit ordering questions; a delta still consumes at least one counter so frontiers cover every commit.
- **`>=` survival** lets a replace and the embeddings put content at the reset's own stamp.
- **Presence stamp**: an explicitly empty collection exists, one emptied by removals stays present, `remove_aspect` makes it absent. Only `W` is stored and the rest computed, so expiry can lower presence. `W` is always encoded; omitting it under a greater inner stamp would break un-merge.
- **Derived sources** give the register → text embedding one identity per character without a third dot form. A `Derived` record goes with its write, matching a node that only saw the value-less register. Kept although the string→text upgrade is rare: with reset-only embedding an old app's string save concurrent with a newer text edit would read as the edit alone (the string vanishing until someone writes); with embedded characters it reads as the string plus the edit, placed.
- **Bag contributions are set elements**, so undo of an increment is an idempotent element reset. No bag GC: dropping non-extreme max/min elements or folding contributions changes the read under a later reset landing between the folded stamps, and under expiry of the extreme. Bag reads are order-independent (exact int sums clamped, float sums in dot order, IEEE totalOrder).
- **Enum payloads filed per case**: a writer editing case A's payload while another switched to B must not flip the value back to A with a half-written payload; the newer payload write stays hidden until a reset (spec/requirements.md, Data model).
- **A map entry record is identified by (dot, key)**: every record carries its key, each write in it as its own value. Removals are keyed only in role-class aspects, so a `secrets.0` removal's target (and role) is read from the delta alone and a snapshot's tombstones keep the key there. Elsewhere a removal is the dot's key-erased record (keyless), whose reset reaches every record of the dot: an app map key is user content and must not outlive the entry in a removal body or snapshot tombstone (spec/requirements.md Deletion); receivers refuse a keyed reset there (`osis_commit::check_entry_keys`). Writers pick the form by `Writer::keyed_removals`; the differential harnesses mix both (odd writers keyed). Why not dot-only identity: a node that dropped the creation (compaction) would not know what a removal removed, so validity of a writer's `secrets.0` removal would depend on which bodies a node held, and an equivocated creation key would give different roles at different nodes. A forged or equivocated key under one creation stamp: copies join part by part (spec/crdt.md §4.1), so every write of the dot sits under the greatest key among its copies, as the join of every copy, and only that key shows. The key never decides another part: expiry erases it, so one total copy order with the key first would let a key pick an anchor or value, and expiring before and after a join would differ (`tests_life::copies_under_two_keys_expire_alike_spec_4_7`).
  - **The records of a dot are one entry** (spec/crdt.md §5.6, `state::prune_dot`): every reset of the dot reaches each of its records (a removal also resets a forged second key: fine, it is the attacker's), and each write of the dot sits in one record: the greatest-keyed record holding a copy (the key-erased record lowest), so a lesser record yields it (`Fragment::without`), and each record takes its writes as the join of the dot's records holds them (`Fragment::restrict` of that join against the record, the map clause of §4.8 Which write applied to state). crdt-model states the same rule independently: it splits each record into its single writes (`writes::writes`), places each under its greatest key as the join of its copies, and keeps those the dot's join holds. A copy counts only as the copy the join holds, so a snapshot's value-less copy in the key-erased record goes beside the valued one in the keyed record, and a state holding both equals one holding the valued alone. So stripping a state equals joining the stripped delta (its leftover) with the rest: X creates `k` with `a = 1`, Y later sets `a = 2`; X's value-less `a = 1` in the key-erased record is beaten by Y's in the keyed one, whichever comes first. Not `winners` itself: it leaves out a sequence's `prev` position and a text creation under a delete, which a record must keep (cycle fallback, anchor), and "wins in this record" changes as writes arrive, so the result would depend on order. A keyed reset reaching only its own record made the rule order-dependent across a forged second key, hence dot-wide resets.
  - Expiry moves each expired write, value-less, from its keyed record to the dot's key-erased record (`Map::erase_keys`); others' writes stay under their own copy of the key. The key-erased record's fragment joins into each live record's read, so a snapshot carrying an expiring entry (value-less, keyless) plus the expiring delta read as the delta's holders do.
  - Cost: a dot with two records with content clones and joins them at each prune of the dot (`prune_dot`), O(entry) per join touching it: rare (expired co-writers, snapshot copies before T).
- **Map tombstones live until the map is reset**, because an older nested write may still arrive and must lose (and a newer one must stay hidden). Same-key entries are not merged into one: the dots are different authors' identities, and joining at read time gives the same value with no rewrite.
- **Removal keeps entry creations whose own dot stays** (`remove_dots`, `remove_writes`): an entry left with only its `created` stays in the result, and a `Slots` position is edited in place (not re-joined, which would prune those), so a join gives the stamp to the entry where another body holds content and prunes it otherwise; dropping it made `created` depend on arrival order. The creation is a write of its own: a record holding only its creation (content un-merged, or stripped as an invalid snapshot's copies) stays through prunes and on the wire (`[Dot, Ci, R, key, []]`), so content rejoining later finds the entry live again. A keyed record's creation counts toward `written` (§4.3), so a map of such shells is present and reads empty.
- **No set/bag tombstone GC** (uniform with maps). Received-range GC would be sound (only a causally later undo can target an applied dot) but needs a `W` fold for presence, a "dot in received ranges with no record counts as tombstoned" join rule in every node, and makes snapshots differ between nodes. It cannot be opt-in "only when big": the join rule and fold are shared semantics, not a local trigger, and `replace` is no compaction tool (fresh dots lose concurrent removes, the reset drops concurrent older adds). Cost accepted: ~10 bytes per removal forever (spec/requirements.md, Scale); most sets never see a reset since the diff path emits none. If a real workload needs it: run-compressed tombstone records (contiguous dots, one reset stamp) are a representational, divergence-free wire change.
- **Text deletes by flag, lists by element reset.** Text content is immutable, so a flag plus undelete-with-char restores it exactly; the undelete's char is its flag write's payload (never folded into the creation's copy: forged copies, below). The char is one register over the creation and the flag writes, by stamp: a flag below the creation (only a forged one) loses to it and prune drops it, so every held flag sits at or above its creation and a reset pruning the flag prunes the creation too. An undeleted element shows the undelete's own char, never the creation's, so whether a node still holds a flagged element's creation char (snapshots and paged states drop a deleted one, spec/crdt.md §5.7 lets a node drop it) never changes a read, and an undelete whose char expired or was purged hides the element. A list element's content is a mergeable fragment: with a flag, a concurrent newer nested write would stay in local state but never reach the wire (deleted elements carry no content), so a snapshot would cover the write's body while omitting it and an undelete would read differently on a node bootstrapped from it. As a reset, the newer nested write survives in the state (hidden: the element is live only while `created` is not below `R_elem`, judged at read since `created` is not pruned under `R_elem`, which must keep the anchor placed and encodable), snapshots carry it, and list undo re-inserts with a fresh dot like set and map undo. Both keep the anchor.
- **A list creation is value-carrying** (spec/crdt.md §4.7, §5.7 Live): held value-less it keeps its anchor, and the element shows while its content holds a live value. Without it a durable list element emptied by nested removals (a set losing its last tag) would vanish. Value-less is a bit on the creation (`SeqElem::valueless`), joined valued-wins like any copy and carried on the wire as a `Creation` marked `false`, so un-merge and resets cannot lose it (a mark encoded as a `FlagW` could). `W` likewise (`Meta::w_valueless`, `[Stamp, false]`): an expiring `{}` goes at T. One `strip` serves expiry, purge and snapshots: nothing ends at T, so a snapshot written before T reads as one after.
- **Hidden writes go by a sweep, not in the lattice** (spec/sync.md §7): `Engine::snapshot` first commits a reset of every record a removal ended (not live, a reset on it) that still holds a write (`Fragment::sweep`), so hidden writes die by the ordinary path: value and repeated key leave state and snapshots (a purge-on-replace body holding one is not covered: issues/swept-hidden-write-uncoverable.md). Skips records not live for want of a creation (a partial receipt) or of a value (an expired creation holding only removals: a valued write may still arrive and show it), role-class aspects and memory commits. Writer-side only, no read rule, so no model twin. Rejected: sweeping in the lattice (a record's reset is pruned by a parent reset, so "a reset drops what is under it" depends on order); a snapshot leaving out a non-live entry's content (the write would not be dead, the body not covered by the join rule, and the bytes would stay in the node's state). Not swept: an edit hidden by a parent's reset alone (`replace` of the map: no record reset, so it looks like a partial receipt), a non-current enum case's payload. Cost: a small commit per compaction that finds some, once per hidden write (`sweep_laws`); a removal so repeated stays when the first remover turns out invalid, as an honest snapshot's copy of the removal already does; a stale sweep's reset is a write, so a collection reset meanwhile by another writer reads empty rather than absent, as under any concurrent removal (§4.3).
- **Records with no write go**, in every collection (spec/crdt.md §4.2): a sequence record whose writes a reset pruned is placed exactly like a virtual anchor (on END by its dot, its children below it, §6.1), so dropping it changes no read or placement and holding a pruned record equals never having held it (`pruned_commit_leaves_nothing_spec_4_2`, `reset_drops_old_records_spec_4_2`). So a whole-value replace keeps only the new value's records (`replaces_keep_state_flat_spec_4_2`), no keyed map record holds a removed entry's sequence records (no key outlives its entry's content), a rebuild settled above a body's `ts` reads no older body (`settled_above`), and a text slot left with only the register's embedding goes (§7). Rejected: keeping write-less records as "bare anchors" so a newer insert anchored into removed content stays placed: a virtual anchor places it the same, and the records grew without bound under replaces and needed a key-erased home in maps.
- **A sequence's order comes from valid writes only** (Tess): un-merge and stripping a snapshot's copies (`remove_dots`, `remove_writes`) take an element's creation (anchor and char) with the writes, others' position and flag writes on it stay, and a record left with no write in a body goes. An anchor naming a dot with no record is a virtual anchor on END (spec/crdt.md §6.1), whether the record has not arrived, was invalid, or went with its value or ephemeral commit: one rule for every absent dot. So every read is a function of the valid writes held and dropping an invalid body equals never having received it (`tests_seq::valid_order`). Accepted cost: a valid element anchored at an invalid one lands at the end, not where its writer saw it (rare: a writer removed while others edit around it). Rejected: keeping an invalid creation as a hidden anchor (an ex-writer kept steering the order, its records kept an emptied aspect present, and dropping its body hid valid elements anchored on it); hiding an element whose anchor is unknown (a node that dropped a record would then read differently from one that never had it).
- **Deaths are computed, not reported** (`winners.rs`): the writes that win in a fragment, by position, kind and stamp (spec/crdt.md §4.8 Which write), are the one definition of supersession; a write of `a` is dead in `a ⊔ b` iff it wins in `a` and not in `a ⊔ b`. Three dead writes stay in the fragment and `winners` leaves them out: a position write beaten as `cur` (kept as `prev`), a text creation under a delete (embedded chars excepted: their death is their register write's), and a write beaten by one in another record of its map dot. Content of an entry or element sits below its record's writes (`Place::In`), so an entry reset prunes it while a value written there supersedes none of the record's own writes. `tests_winners` checks `winners` against a pairwise from-scratch definition over every write held. `Changes` only says whether the read may have changed. Supersession is not what a fragment carries: `Fragment::carried` (the same walk, its `Sink` counting) counts every write copy, those three included and a write in several records of a map dot once per record.
  - A text creation is judged by the element's winning flag: an undelete over the delete makes it win again. spec/crdt.md §4.8 has it dead from the delete on; judging by winners, a body holding it is dated later (kept longer), never earlier.
- **Interning**: `Source` is an `Arc<SourceKind>`; a stamp is `ts` + pointer + counter. Equality and order never depend on sharing; `Interner` dedupes per decode (a node may keep one per aspect). Dot and source comparisons borrow: decoded deltas never share the state's source `Arc`s.
- **Join** (`state.rs`) is delta-driven: `join_into(other, e_parent, changes)` walks only what `other` carries; existing children are pruned only when an own reset rises. Equals union-then-prune (`tests_model`: equal to the model after every join). An empty state takes the other side pruned.
- **Change summary** (`Changes`): whether the read may have changed (a write landed or went); which writes died is `winners` before and after.
- **Wire** (`wire.rs`, `codec.rs`, `stream.rs`): values are built as `osis_base::Value` trees, one element at a time; encoding runs the fragment encoder twice (collecting pass for `Sources`/`Commits`, which keeps no values). Every element array and field map goes through `codec::Pager`: held while its plain form fits the page target, then cut as elements come, each page put when it closes, so encoding holds about one page per open position (plus the links), not the delta's value tree (a 10^5-key map's delta: 13 MB above the delta, 2.4 MB of it the pages the test's sink keeps, against 129 MB for the whole encoder).
  - Decoding (`stream`) checks the grammar, ranges and rule 7, then re-encodes and requires the input bytes: every canonical rule, paging included, is that one comparison. The re-encode goes through the same `Pager` with the input's pages in its `Replay`: a page cut differently is not there, and the position's link list must come out as written. It streams: the root decodes into a skeleton with every paged collection reached through `Step`s (fields, payloads, map entries) left empty; the skeleton re-encodes against the root with the input's own tables (`Enc` check mode, `Dec::checker`); each such collection then decodes one leaf page at a time and re-encodes element by element (`Out`: seams must ascend, one open sequence run carried across pages); at the end the tables must be what a collecting pass builds (first appearances in table order, the root's appearances logged and replayed around its streamed positions, each commit's base its smallest counter). Paged positions inside a page, a `Slots` slot or a sequence's content decode whole. `stream_delta`/`stream_snapshot` hand over the skeleton, then one `Piece::Page` per leaf page; `decode_delta` puts them back together and prunes the whole (a decoded delta is its pruned form, spec §3.3 rule 5). The engine decodes whole (`decode_delta`); applying per page is step 3 of issues/durable-decode-bound.md.
  - Oracles: the whole encoder (every element held, cut at the end) is `codec::oracle::encode_*`; in this crate's tests every `encode_delta`/`encode_snapshot` also runs it into content-addressed sinks and requires the same root and pages (`oracle::twin`). The whole-delta decoder is `codec::oracle`; `tests_stream` mutates roots and pages and requires the same decisions.
  - Rule 1 quirk (list runs counted as if not closed by content size): the collecting pass cannot cut at `CHUNK_MAX`, since a run's content bytes depend on the `Ci` indices, which depend on the sorted `Commits` table the pass is building; so `Runs` defers the sources of a run's position and flag writes to the end of the uncut run in every mode (`Enc::defer`), and both passes and the check note in the rule's order.
  - Sequences: runs per §3.3 rule 3 over `Enc::sorted`; built incrementally (`Runs`: records pushed in wire order, one open run, so a streamed sequence re-encodes across pages); a list run with content is cut where its encoded fragments reach `CHUNK_MAX`, so a run and a page fit a blob; a segment's `Ci` is read off the encoded creation stamp. Decode claims own creations and position writes, rejects n = 0 or > `MAX_RUN`, bad indices, list undeletes, content length mismatches, segments of another source, `Derived` creation runs in a writer's delta, empty list element fragments, runs carrying no write (any delta), more than `MAX_DELTA_BARE` content-less elements in a writer delta (counted across pages on `Dec`, before allocating), writer `FlagW` stamps off the delta stamp; the re-encode check covers maximality and order. Decoding cuts each run where segments, position writes and flag writes change (overlapping flag writes are rejected up front) and never loops per element except over a writer's own counters (bounded by rule 7).
- **Paging**: `PageParams` (format: 64 KiB target, 16/256 KiB cuts, 512 fanout) come from the `PageSink`/`PageSource`; tests shrink them. `osis_base::PageCutter` cuts; link pages use the tree-node rule; a third level is refused. `page_array(sink, items)` is the public split of one element array (vectors); struct and enum field maps page the same way (`page_map`, a field = key and value bytes, pages are maps), so no delta outgrows a blob (spec/commits.md §1; `CommitBuilder::max_blob` shrinks the bound for tests). Decode records each position's pages after its items (`Dec::done`), i.e. in the encoder's put order, so equal page plaintexts (equal structs written in one commit) replay to their own links. Each put must be its own blob (a decode refuses a blob linked twice; the node's `LocalPages` derives a distinct ID per put).
- **Page items** (`MAX_PAGE_ITEMS` 2^21, spec/crdt.md §8; `codec::check_items`/`check_root`): counted from heads before `osis_base::decode`, one per CBOR item plus text bytes, so the count is at most the blob's bytes and blobs up to 2 MiB skip the walk. Not applied to ephemeral deltas (`PageParams::UNPAGED`, which have `decoded_bound` against the node cap instead). Why 2^21 and not 2^20: an honest page is under `CHUNK_MAX` bytes before its last element, plus that element, and the largest elements are (items at most bytes): a map entry, key up to 128 KiB plus a `Slots` fragment (a register value up to 128 KiB plus up to 9 slots whose arrays are each at most `PAGE_TARGET` inline: about 720 KiB); a list run, `Content` under `CHUNK_MAX` plus one such fragment plus about 33 items per element of position, flag and segment writes; a text run, up to about 36 items per element (two position writes with sibling keys, a flag write, a segment, 4 bytes of char). Measured: a text whose every char was moved twice and half deleted counts 16 items per element. At `MAX_RUN` 2^16 one such run alone would pass 2^21, hence `MAX_RUN` 2^12; the worst page is then about 256 KiB + 983 K + 135 K = 1.4 x 2^20 items, under 2^21 with a third to spare. 2^20 would hold for everything but the many-slot `Slots` corner (pages up to about 1.38 M items). The root's `Sources`/`Commits`/`Frontiers`/`Absorbed`/`Authors` are not counted (bounded by `MAX_BLOB`; they decode to small fixed records).
- **Ops** (`ops.rs`, `batch.rs`): `diff`/`create`/`replace` match the model write for write under a `View`. A set element is one register holding the whole value whatever its type (`set_elem`; both decoders reject another fragment there, rule 7); a link fits only a register position. `Batch` makes a commit's net effect: ops resolve against state ⊔ batch-so-far, borrowing the state where the batch has no writes and copying the position where it has (`current`; map keys join only that key's entries, `key_lookup`).
  - At a sequence position the batch already wrote, an op resolves against the state's sequence layered under the batch's records instead of a copy (`seq::Layered`: the batch's new records and every state record its writes meet, copied whole and then split where they land, plus the state's placement followed through them; sequence ops and `seq_diff::edit` read through `SeqRead`, the cache's plan/follow through `Recs`); where a batch reset lies above or the cache cannot follow, it copies. The view is kept (`Seen`, keyed by that path) for the next op at the same position, joined with each op's delta there while `prune(acc) ⊔ d` equals the overlay there (else dropped), checked at the op's elements only (`seq::Foot`, O(op · log n)), so a batch of N ops on one text costs O(N · (√n + log n)); any other op drops it. `seq::overlay` touches only the op's elements and looks for created-and-removed elements to omit only when the op removed one or dropped an anchor at one. The debug check compares the kept view with what `current` would copy.
  - Ops see state joined with the batch slot by slot (`slot`), not the net effect's own slots: a batch writing a register at P and then a field of P resolves the field against the state's struct (the register is another slot), and the overlay of differing encodings keeps only the later write. `overlay` lets a later op override, drops a reset's earlier content, omits created-and-removed elements and then sets `W` if the collection would be left with no write (one-by-one ops would have left it present).
- **Seq ops**: `Op::Insert/Delete/Move` by visible index (`Move.to` indexes the sequence without the range, like the model); `Op::Paste { dots, at }` (`cut_dots` gives the visible dots a cut removes; paste = move of the slice of the placement order they span + undelete; fails if a dot or its char is gone or visible text lies inside the remembered range, and the caller inserts); `Op::InsertAfter { anchor, items }` and `Op::DeleteDots { dots }` (index resolved by a caller keeping the placement apart; the node does not use them, its ops run through a placement held in part; the anchor must be a visible record of the state, each dot in a record, distinct; write for write the index ops', and the new elements land right after the anchor when the writer's `ts` is above every stamp of the sequence, which §2.2/§8 make true of a node's commits).
  - `Op::Edit { base, new }` (what `diff_values` emits for sequences): `seq_diff::edit` aligns `base` to the current read at base's own indices when the read has base's length and equals it over the changed middle widened by `CTX` = 32 elements each side, a stretch occurring nowhere else in base (else a concurrent shift can put same-content elements there in periodic text and the edit lands a period off); otherwise by exact LCS over the whole read. Deletes and insert anchors use exact matches only; a list element changed on both sides is edited in place (`diff_values` of its value through a nested `Batch`) only when it is the one unmatched element of its gap on each side. `window` is all a sequence held in part needs; `edit_window` gives a node that stretch; a whole pass over records held in part is told apart from a miss (`PlaceMisses::whole`, which the node counts).
  - Delete flags the whole range, hidden elements inside included (more than `MAX_DELTA_BARE` is refused: split across commits); undo of it undeletes only what the pre-commit state showed. Move reads only the range's rows: the `outside` nodes are the rows after it whose parent is in it, each skipped with its subtree (`Placement::hanging`), and `to` skips the range's visible count by rank, so a move op costs O(range + √n). Move writes each element of a range record without creation (flag-only) as its own root, chained, counted against `MAX_DELTA_BARE`; so move/insert equal the model's write for write whatever the record split.
- **Seq net effect** (`seq_ops::overlay`): later writes override; a list element reset in the commit drops the commit's earlier content of the element (same stamp would survive it); a deleted char is not carried; a text element the commit made carries no flag (the delta stamp is the commit's lowest, so the flag would lie below the creation and lose): removed, it is its creation without its char; a created-and-removed element is omitted only when nothing else in the commit anchors at it (spec §4.5).
- **Seq undo**: insert → flag/element reset; text delete → undelete with the char from the pre-commit state, only where that state shows the element visible; list delete → re-insert after the old element with a fresh dot; undelete → delete only where the pre-commit state had it deleted; position writes → old anchors and sibling keys with fresh counters in the old stamps' order, only while the element's `cur` has the undone write's anchor and sibling key; nested list content through `undo.rs` (a callback).
- **Diff** (`seq_diff.rs`): Myers after trimming the common prefix and suffix, giving up past 512 edits (the middle is then replaced: any script is valid, §9); inserts anchor after the preceding matched or paired element; opaque list elements are left out of the alignment.
- **Linearization** (`linearize.rs`): whole state per call, by index into the dot-ordered records. A range record is one node, split after each element something anchors at and where a virtual `Derived` anchor sits between its elements in dot order, so node order matches the per-element order; every dot an anchor names without a record is a virtual node on END (inside a node each element is the only child of the one before, or none has a position write and all sit on END). `Placement` is per node (first and last element, span); anchors are found by binary search after trying the node just before in dot order (where typing anchors); sibling lists in one array, one walk. Cycles: rounds of walks (first from every node, then from the victims), each node walked once per round, a persistent mark on nodes that reach HEAD or END; any walk demotes the cycle it closes. Linear on adversarial graphs.
- **Placement cache** (`seq_lin::Lin`, behind a `OnceLock<Arc<_>>`, not part of `Eq`), per `Seq` of `LIN_MIN` = 64 records or more (1 under `cfg(test)`, so the model differential checks it):
  - Rows (node, last element, parent, chosen edge stamp, depth, shown, a visible text char) in blocks of about √n (at most 256 when built, split above twice that; 4 at least), each an `Arc` (a copy shares untouched blocks) with its visible count and least depth, plus a depth shift per block outside the `Arc`. A subtree is the rows up to the next one no deeper (blocks all deeper skipped, O(√n)). A row-dot → block map, built with the rows, in dot order as sorted `Arc` chunks of about √n entries (at least 64), so a copy clones only the chunks it writes. Position, visible index and dot lookups and a splice cost O(√n); the block size rises with the row count (`cap = max(cap, min(√len, 256))` on insert). `take` merges a block left below half the block size with a neighbour; `insert` splits an oversized block.
  - Every join follows it: `elems` is private, `elems_mut` drops the cache, `join_elems` plans each record before it joins and `Lin::follow` splices new runs where they place (after the anchor and past its children with greater edge stamps, each skipped with its subtree; 256 or more rebuild; at HEAD before the `END` rows; a cursor walks the blocks). The newest of a delta's runs and moves, when above `Lin::newest` (a stamp at or above every position write), goes right after its anchor without reading the children's records, except a move onto an element new in the delta (that element's run may go on with a newer stamp). Single elements whose chosen edge changed (moves) are re-placed in write-stamp order so a mover's outside re-anchors come first; if one lands where it was only depths shift, else the smaller of it and the rows it passes moves. Flag and content writes carry their new visibility from the plan walk and are applied per block (`flip`), including a decoded record over several state records (`plan_pieces`). A record whose join changed nothing is not followed.
  - Rebuilds: a delta with more than max(√n, 64) runs, moves and row cuts, or whose placements look at more than max(n, 1024) rows and blocks (a sibling skipped counts 8; each cut charged with its subtree walk and depth shift, the budget checked after each), so hostile deltas cost about a whole pass (`hostile_moves_join_bounded_spec_6`, `hostile_cuts_join_bounded_spec_6`). A move rebuilds when it closes a cycle (checked per step), touches an element on a cycle a demotion broke (`Lin::cyc`; otherwise the old demotions stay forced, §6.2), writes or drops an anchor naming an unknown element (an absent `Derived` one), or drops one inside a range record; resets and new `Derived` records rebuild too.
  - A write over part of a range record or a new anchor inside one cuts the row where a whole pass cuts the node (`cut_row`, `Plan::Cut`: a chain's second piece becomes the only child of the first, its subtree one level deeper by `reshift`; pieces without creation sit side by side on END); a row's `parent` is the element its edge names, so a cut changes no child's row. A row the delta moves sits by its old chosen write's sibling key until re-placed (`sits`): the join may have replaced that write by a copy (§4.1) or put it below another write at that anchor, so `Sibs::key` reading the record would misplace a sibling slotted past it.
  - Held `Derived` elements and anchors at them are followed like any other, at a `Slots` position too. Text `read` and `diff`/`edit` take the chars from the rows; a list `read` steps through the records in dot order alongside the visible rows, searching only where the order jumps (no per-row value cache: a list element's read can be any size). Tests compare the cache with a whole pass after every join, and the dot map and counts with the rows (`testutil::check_lin`, which also checks `present()` against `written()`).
- **Held in part** (`seq_place.rs`, `SeqPlace`): the node keeps a paged sequence's placement in its store in this form (top, block rows by arena id, dot-map chunks by first dot; notes/engine-paged.md, Paged state) and loads it in part (`from_top`: every block and chunk a stub with its counts, least depth, first dot). Attached to a sequence whose records are held in part (`set_seq_place`, `cover` = the loaded pages' dot ranges), joins follow it and ops by index resolve through it as through a whole one; whatever reads a stub or a record outside the cover notes a miss (`seq_lin::Partial`, shared by copies; `Covered` wraps record lookups, also under `Layered`) and fails (the follow returns `false`, the op's result is void). Presence comes from a visible placed node, existence (`is_empty`) from any placed node, and the greatest stamp inside (`inner_max`, `written`) needs every record (`all`). A stored row keeps no text char (`fill_chars` sets them only on a whole load), so a text read takes a char a row lacks from its record (`Vis::chars`) and a list read notes records outside the cover: a read held in part returns the whole read once what it missed is loaded, never a silently short one. Neighbouring stubs are not merged. `dry_follow` follows a copy through a join over a copy of the records the delta touches (`Over`), so the node loads the misses before the join itself; `diff` lists what changed against the placement as stored (blocks by `Arc` identity, chunks by first dot). A node loads a sequence whole for `Set` (notes/engine-paged.md Paged state). `Fragment::visible_range` and `read_elems` read by index from the cache or from stored dots. What remains: issues/crdt-seq-linearization-cost.md.
- **Undo** (`undo.rs`): spec/crdt.md §4.6 states only constraints (rights, no revived value-less content, copy expiry, SHOULD restore the prior read); receivers never re-derive an undo, so this is one writer's choice. Cancel per dot over the original delta, walking it in step with the current state and the pre-commit state (`before`). A position absent before the commit (a composite, or the aspect root), under one present before, is reset (`remove_aspect`'s delta) when it reads now what the undone delta joined into the pre-commit state reads; else the per-write rules run. The reset also drops concurrent writes into it that arrive later (a reset at a position, like `remove_aspect`) and a held later write by anyone that left the read unchanged (re-adding an equal value), as the register rule overwrites a later equal edit; the engine runs an undo whose reset reaches a paged collection held in part again on the whole state (`undo_in`), since that collection holds others' entries on pages the delta does not touch (a reset elsewhere lies in a loaded page or the skeleton); a register absent before inside a present struct stays (no nested register reset). A key removed with several entries returns as one entry of their joined value (separate re-adds share the undo stamp and tie). A nested edit under a map key is undone against the join of the key's live entries before the commit (`entry_frag`). Two schemas on one AK: a pre-commit value that does not fit the view fails the undo (`Mismatch`).
- **Un-merge** (`lifecycle.rs`): defined per body (spec/crdt.md §4.6): the node joins its held bodies with `remove_dots(pred)` applied (an author's dots or one delta's), never on the joined state (a write of theirs may have superseded another's, and a record of theirs whose creation a reset pruned stays only where some body held another's write in it). `holds_dots` says whether there is anything to remove. `remove_writes` keeps others' writes nested in records they created (snapshots).
- **Access** (`access.rs`): `Map::entries()` and `Map::live(k)` read-only (node adapts `roles.0` entries into perm edge writes, reads `secrets.0` keys); `Fragment::at(path)` reads one position (a key with one live entry in place, O(log n); several are joined). `Batch` resolves a path through a map key with one live entry the batch has not written in place too (`key_lookup` borrows), so a nested write into a large inner map copies nothing of it. `present()` stops at the first presence-counting write (equal to `written().is_some()`).
- **Paging hooks** (`paging.rs`, for the node's paged states): `elem_count` (records), `elem_dots`, `elem_range` (the collection restricted to root records in a dot range), `touched_elems`, `Step` / `Paths` (positions below struct fields, enum payloads and map entries), `step`, `at_steps`, `wrap` (a fragment holding one piece at a path, entry keys and creations carried), `reduced` (paged collections cut to their reset and `W`), `collections`, `touched_paths` (what joining a delta can change per paged collection, and whether the rest; `None` for a reset at or above one).
- **Restores** (`undo::restores(undone)`): whether undoing a delta writes back content it replaced, by its writes' kinds alone (spec/crdt.md §4.6); the property tests check an undo that restores nothing by kind copies nothing back (`Writer::copied` empty).
- **Remap** (`remap.rs`): `Fragment::map_dots` maps every dot; `Fragment::writes` lists every write's origin dot with its `ts` for judging a snapshot's writes and ranking them. One read-only walk (`remap::walk`, a `Visit` over stamps and records, never expanding range records) drives `writes`, `holds_owned`, `holds_stamp` and `dots_in`.
- **Entry creation** (`Entry::created`, spec §3.2, §5.6): the creation stamp `(ts, entry dot)`, set by ops for fresh entries, implied when decoding a writer's own creations, carried as the entry's `Ci` by snapshots, pruned like any write and dropped with the content; kept through paging. **Authors** (`Snapshot::authors`, §8): per `Commit` source the node and `ts` its writes are judged as; omitted when empty. `has_reset`, `is_plain_struct`, `is_put_only_map` (`shape.rs`).
- **Key index**: `Map.keys` (key -> keyed records `Eid` carrying it, a superset; lookups check liveness, `Map::live_ids`; not part of `Eq`), kept by `join_entries`, `Map::new`, batch `overlay`, `map_dots`. Records are `entries: BTreeMap<Eid, Entry>` (`Eid { dot, key }`, `Key` ordered by canonical bytes); a dot's records are contiguous, the key-erased one first (`Map::of_dot`), pruned together (`state::prune_dot`). Index paths and `Remove` of a map key still scan or clone.
- **Left near-parallel on purpose** (merging them came out line-neutral): set element vs map entry join and overlay (state.rs `join_elems`/`join_entry`, batch.rs `overlay_elems`/map arm; the entry's creation prune sits between content prune and join, and `Changes` deaths are ordered); the mutating walks `map_dots`, `strip_values`, `remove_dots_in`.
- **Costs counted**: a received insert, delete or move into a text of 30 and 300 runs follows the cached placement, no whole pass (`small_joins_follow_cached_placement_spec_6`, `seq_lin::probe`); its placement work grows about with the square root of the runs (the block walk). A small change inside a huge value is O(change) at the node (osis-node `scale::`, notes/testing.md Scale checks).
- **Tests**: the property is `tests_model::crdt_equals_model` (a seed's mode by its index: the kitchen sink; writers of different encodings at one position, at the root or below struct fields; maps of texts and lists, lists of structs; twin writers sharing a source and clock, so same-stamp copies with differing payloads and one dot under two stamps; hostile single-record text and list writes with string register writes). Each history is joined twice in a random order with duplicates, state and read equal to the model's after every join, the cached placement a whole pass's; piece laws the model has no counterpart for (`part_at`, `contains`, an honest holder's copies; hostile: `part_judges_as_whole` and a placement held in part); every writer's delta and a snapshot after every delta byte-identical with the model's, decoded alike by both decoders, reading as the state (twins excepted: a forged dot under two stamps has no encoding) and back to the state as carried when honest; strip of the first writer's dots equal to the model's and commuting with join; un-merge of one author equal to the model's in any order; a coverage tally (every mode, every encoding including `Slots`) at every size. `Quick` (100 seeds, about 8 CPU-s) in the default tests; `crdt_equals_model_large` runs `Small` (1000) or `Large` (10,000, `OSIS_FULL=1`); `OSIS_CRDT_START`/`_SEEDS` pick seeds and one seed replays at any size (sizes differ only in count). Beside it: every rule 7 run rejection, the worked examples below as `*_spec_example` tests, random undelete, ops against a plain-string model, batch = one by one, convergence of replicas using these ops, undo, diff, `edit` rebase, cut/paste identity, list delete vs newer nested write, Derived anchors after expiry. ## Implementation (`osis-commit`)
- **Header** (`header.rs`): `Header` with every spec/wire.md §4 position; a list that goes by link keeps its root in `links` and is empty until `resolve(src, actor dedup)` reads the chunk tree. `decode` checks structure and canonical bytes (re-encode equals input); `validate` checks every rule a header shows (sort orders, indices, ranges, kind vs aspect class, one delta per aspect, fixed retention, delete levels exactly the retention's, expiry, purge, frontier only on kind 1) and needs resolved lists. A higher format version is `UnknownVersion` (Parked) before the arity check.
- **Header lists are read by shape** (`header.rs` `read_*` over `osis_base::Reader`, inline and linked; `tree::parse_node` too; `frontier_value` for a linked header or frontier): worst honest shape about 5 B of memory per list byte (purge at 21 B per item), where a whole-value `decode` costs up to about 56 B per byte. Items in strictly ascending bytes, checked in `Header::decode`, so a repeated chunk link is refused at its first repeat. `validate` still states each list's own order.
- **Header lists** (`lists.rs`): crate-root `write_list(bytes, dedup, sink, prefix)`/`read_list(root, dedup, src, max)` adapt `BlobSink`/`BlobSource` (prefix inputs in, plaintext out; own traits: crdt's `PageSink` computes the link hash from plaintext, which a tree node's hash is not, and takes no prefix) to the tree module with `ChunkParams::FORMAT`; `MAX_LIST_BYTES` = 64 MiB (format constant, spec/wire.md §2: a resolved header is in memory); `Header::resolve` (past it, bad input); `MemoryBlobs` (tests).
- **Commit blob** (`blob.rs`): `CommitBlob { header, signature, parts }`, encoded by concatenation (header and delta bytes are already canonical items); decode re-encodes and compares. `missing()` = header deltas the blob lacks.
- **Retention** (`retention.rs`): fixed tables, `write_retention`/`write_expires` (fixed > override > schema default > untyped `author_or_admin`), `snapshot_retention` (role-class and `created.0` keep the fixed one), `role_kept`, `purge_keep_until` (the purge floor `ts + ROLE_KEEP`), `delete_levels`; what a history keeps is the engine's door (notes/engine-retention.md History modes).
- **Delete keys** (`keys.rs`): the `Secrets` trait (dedup, and the public delete keys: admin, author-chain write, thing write); `delete_keys` lists every level the retention calls for (a missing key is `Build`); `DeleteKey { level, key }` in the header (validated as a point when decoded); `Prefix { salt, blind, expiry, keys }` is the prefix input; osis-label computes the commitments (`Prefix::for_delete_keys`: each key blinded by the blob's salt and the header's blind, one per level) and lays them out.
- **Builder** (`builder.rs`): `CommitBuilder` takes resolved per-aspect `AspectWrite`s (delta bytes encoded by the caller against `writer_ctx`, retention, expiry, schema, introduced chunks); sorts, hashes, builds the delete-key table and chunk list, validates (caller mistakes surface as `Build`), links lists above `CHUNK_THRESHOLD`, signs, checks every delta fits a blob alone. Header-list blobs: prefix expiry = max `expires` iff all aspects expire; the commit's level-2 commitment only.
- **Chunk trees** (`tree.rs`, `pub mod tree`): the only implementation, re-exported by osis-label under the same names: streaming `TreeWriter`/`TreeReader` over `TreeSink`/`LinkSource` (errors are commit's `Error`: `Corrupt` for a content hash or level, `TooLarge` beyond the caller's bound, `Missing` retry-safe), `write_tree`/`read_tree`, `HashSink`, `node_plaintext`/`parse_node`. The reader takes an output bound and follows spec/wire.md §6 tree reader bounds (a non-final chunk below `CHUNK_MIN` is bad input; at most `max / CHUNK_MIN + 1` chunks visited). The visit cap is what bounds work: repeated links are legal (identical chunks share a blob), so a tree of empty or repeated chunks would otherwise cost hundreds of thousands of fetches for no output. osis-label converts errors both ways (`From` impls in its `error.rs`, class kept).
- **Verify** (`verify.rs`): `verify_part` (delta hash under the thing's dedup secret, then osis-crdt decode against `delta_ctx`: own source = author node or `Commit(id)`, header range, kind) and `verify_blob` (signature, `validate`, every part).
- **Projection** (`project.rs`): `project(commit, readers: Fn(ai) -> K)`; class = (K, retention, expiry, aspect delete-key indices), so distinct delete bases split classes; size split greedy in aspect order with exact blob sizes (prefix, Padmé, tag). `prefix_inputs(header, parts)` is what any blob of the commit must carry (label's prefix-vs-header check, rewrites). `rewrite` keeps header and signature.

## Reference model (`core/test/crdt-model/`)
A small, slow, obviously-correct implementation of spec/crdt.md: `State` (fully resolved stamps), join, prune, read, the ops, un-merge (by origin dot, keeping the records a valid snapshots' join holds, §4.6), the wire encoder/decoder (own canonical CBOR subset), embeddings, diff; `death.rs` (a write's identity, winning writes, supersedes as "dead in the join with it", holds by dot, covers by canonical bytes, §4.7 value-less writes) and `origins.rs` (dot to commit by the headers' forms and ranges), stated over `writes::writes` and join. osis-crdt is tested against it; held-model takes its values from it. Property tests (`tests/props.rs`):
- convergence under random delivery orders, duplication and omitted prefixes: equal reads and equal encoded states;
- join laws on random states, within and across encodings (every association and order of three states);
- single writer vs a sequential model after every op;
- wire round trip and byte-identical re-encode; decoder never panics on random or mutated input;
- embeddings commute with join; a register delta joined into a text equals its embedding joined;
- forged copies (osis-crdt `tests_laws.rs` `forged_copies_*`: two writers share one source and clock, so their writes are same-stamp copies with differing payloads): join laws with `contains` and `part_at`, a cached placement followed against a fresh one (join and read against the model: `tests_model`'s twins);
- diff (`read(join(S, diff(S, v))) == v`);
- death and covering: a state holds and covers each of its writes; a write another supersedes alone is dead in any join holding both; with nothing expired a state holds no value-less write;
- expiry: random expiring commits stripped at random points, equal to join-then-strip; strip commutes with join and is idempotent; value-less registers embed like stripped valued ones;
- snapshots: round trip with frontiers, frontiers equal last counters, bootstrapping from a snapshot reads the same;
- the worked examples below;
- decoder strictness (`decoder_rejects_writer_rule_violations`, `decoder_rejects_rule_7_strict`): own-counter ranges and distinct counters (§2.3, every dot of a run, not only its first), foreign stamps in a writer's delta, nested register resets, maximal runs (re-derived from the decoded elements), a creation written as a `PosW`, more than the top-two position writes, overlapping or unmerged `FlagW` ranges, an empty text `Content` string, own (`Ci` 0) stamps in a snapshot, runs carrying no write, empty list element fragments (§4.2 Emptiness, at any depth), a `Slots` that pruning would change (slots empty, below the register's embedding, or not holding it; §7).

Undo (`undo.rs`, written from spec/crdt.md §4.6 and the §5 "Undo" lines alone, without reading osis-crdt's undo; its header lists the choices the spec leaves open). Differential in osis-crdt `tests_undo.rs`: random bases (absent, partial structs and enum payloads, after a few ops), writer 1's op, now and then writer 2's concurrent op stamped below d1, between d1 and the undo, or above the undo; undo, redo (undo of the undo) and undo of d1 again after the redo (exercising `restored`), each side its own deltas, reads compared; alone, undo and redo restore the read exactly, moves included (`exact_moves`); undo deltas with sibling keys also cross the wire byte-identically (`wire_alike`). `Stats` counts the rules hit (a coverage test asserts each).

Decoder differential (osis-crdt `tests_decoder.rs`): random histories' writer deltas and snapshots, mutated at the byte level (byte nudged, overwritten by a small CBOR item, inserted, removed, tail cut) and structurally (decoded to a value tree, an int nudged or set to a boundary, an array element dropped, duplicated or swapped, a map entry dropped, re-encoded canonically, so mutants reach the semantic checks), decode alike (accept/reject, and equal fragments) in the model and the implementation. Value tags beyond set, tid and enum are not modeled (the implementation keeps unknown tags, spec/data-model.md §5): where the model rejects for a tag, the implementation must reject too or have decoded an unknown tag or a link. 48 cases per default-test run; a 2000-case release run is green.

Not modeled: the schema projection of the diff (the model's diff is untyped); links (copy and key order by bytes is tested in osis-crdt `links_compare_by_bytes_spec_3_3`). The model's decoder checks the canonical-form rules (below) its own way: prune stability by comparing the stamps `walk` yields before and after a prune, read depth by a walk (`Frag::read_depth`), commit-level stamps by `levels_at`.

## Structural diff: the reference script
The spec fixes only the identity rule and `read(join(S, diff)) == v`; osis-crdt's script (`ops.rs`, `seq_diff.rs`; the model's `diff.rs`) is, per encoding, recursive:
- register: write iff `read(S) != v` (bit-exact for floats) or S absent.
- bag: counter: `inc(v - read(S))` if different; max/min: reset + contribution if `v != read(S)` (a max cannot go down otherwise).
- struct: per field of `v`: recurse into `S.fields[id]`. Fields present in S but not in `v` are left alone (open structs: the writer only knows its fields; a typed `v` always has all the writer's fields). A field absent in S whose value in `v` equals the field's declared default produces no write (defaults are never materialized).
- enum: same case → recurse into the payload; different case → `set_case`.
- set: adds for values in `v` whose `view` matches no live element; removes for live, non-opaque elements whose `view` is not in `v` (one reset stamp). Large values compare by keyed content hash.
- map: keys (under `view`) only in `v` → put; non-opaque keys only in S → remove; both → recurse with the key's read (the join of its live entries) as S, writing into the lowest live entry.
- list: opaque elements are removed from consideration first and keep their place; LCS (Myers) over the rest with equality = `view(read(elem)) == item` (deep); unmatched old elements and new items are then **paired in order** while both remain and recursed into (a changed entry is an edit, not delete+insert); leftover old → delete (element reset), leftover new → insert after the preceding matched/paired element.
- text: Myers diff over chars → deletes and inserts (no move detection). Equal strings → no writes.
- absent S: everything is a creation; composites with no content get an explicit `W`.

## Canonical form decisions
One rule throughout: what the decoder accepts re-encodes and re-prunes to itself, so a delta has one byte form and carries nothing its own join would drop.
- **Prune-stable deltas** (§3.3 rules 5, 7): a carried write its own resets prune (a register `[0, [R], S, v]` with R below S, a child or `W` below the delta's reset, a keyed map record under its dot's key-erased reset) is bad input, not "accepted, dropped at join". A dropped write is still a write for un-merge and frontiers (a snapshot carrying it under another author's reset would revive it when that author is revoked), so accepting it gives two meanings to one delta. Checked by pruning a copy and requiring every carried write copy to stay (`codec::prune_stable`, `Fragment::carried`, as the model counts stamps; not `winners`: a `prev` position write or a deleted text creation below the reset is carried too, and prune keeps a write held in several records of one map dot in one only, `write_copied_across_records_rejected_spec_3_3`; not fragment equality: what prune drops that is no write has its own rule 7 line, such as a record carrying no write, in any collection, `record_without_write_rejected_spec_3_3`). A streamed page is checked an element at a time (a map dot's records together; copying whole pages raises the stream's peak in `stream_memory_big_map` from about 45 to 83 MB) under the effective reset of its path (`stream::reset_at`), the previous page's last map dot carried into the next (`prune_page`; `map_dot_prunes_across_pages_spec_3_3`), so streaming and the whole-delta oracle agree. A creation and its position write are one write: a creation run implies the position write, and where the element's top-2 position writes leave it out (in a map, of the dot's records: `implied_creation_pos_decodes_back_spec_3_3`) pruning drops only that implied copy, the creation held, so it is no carried write dropped; decoders return the pruned form, so the decoded state is the canonical one.
- **Read depth, not a fragment nesting cap** (§3.3 rule 7): a fragment that would read deeper than 64 with every write live is rejected; the count follows `Value::depth` (struct, map, list +1; enum, set +2; map keys one below the map). A plain nesting cap lets a state read as a value no osis decoder accepts. Writers check the same count before resolving an op (`batch::out_of_profile`: a case step counts 2, set elements and list items one below the position). The count bounds the decoder's recursion across pages (every page level adds one); inside one blob the CBOR depth does.
- **Set/bag element value of the dot's source** (rule 7): only the element's creation writes the value register, so its stamp has the dot's source (a writer's delta stamp, or the embedded write itself, §7). Not the dot's own counter: a writer's element `k` holds a value at the delta stamp `lo`.
- **Commit-level writes at the delta stamp** (§2.3, rule 7): every reset, `W`, register value, case write, element reset and flag of a writer's delta, not only `FlagW`; the other counters of `[lo, hi)` belong to creations and position writes.
- **Links compare by bytes** in copy order and map key order (rule 2): `Value`'s order compares links by content hash, so `opt_value_cmp` compares encodings whenever either side holds a link.
- **Enum case ids at most 2^63 - 1** (spec/data-model.md §5): every other integer is i64 and `Value::uint` saturates, so a larger case would be written as `i64::MAX`.

## Text size

Target 1.5–3x the plain text. The table was measured before the §4.5 rule "omit a created-and-removed element only once nothing anchors at it" (which `text_bench` follows) and not re-measured; the trace is not in the repo. The rest scales with commits (about 9 bytes of commit table plus 4 of run segment each) and deleting commits (about 8 bytes). Per-write timestamps are the design, so the client rule is one commit per editing pause, never per keystroke: at a 2 s cadence (about 10 edits) about 7x, at 20 s about 3x. Sizes in a foreign snapshot: a run about 20 bytes plus content, a segment about 4, a deleted range about 7, a commit table entry about 9. Tombstones in a run-compressed snapshot: a deleted element 3-4 bytes; a state grows with the edit runs made since the last reset.

What buys the size: deleted elements carry no content on the wire (182k → 6k runs), the per-delta commit table with bare indices (1–3 bytes per foreign stamp instead of 10), delta-coded table entries, runs spanning commits via segments, the shared delta stamp.

Accepted (spec/requirements.md, Scale): about 13 bytes per commit forever, so clients commit per editing pause. Stability-based GC (drop per-commit stamps once every writer acknowledged) would need every writer's frontier and stall on offline nodes, which the requirements forbid ("whether others are alive is never a protocol condition").

## Worked examples
Dots `a1`, `b3` (source letter, counter); stamps `(t, dot)`. Tests in `core/test/crdt-model/tests/props.rs` cite these.
- **Typing**: a at t=1 types `FOOBAR`: run `[1, 6, [0, [[0, 6]]], "FOOBAR", [], []]`. F=a1→HEAD, O₁=a2→a1, O₂=a3→a2, B=a4→a3, A=a5→a4, R=a6→a5.
- **Concurrent inserts at one anchor**: b at t=2 inserts `x` after O₂ (`[1, 1, [[1,3], [[0, 1]]], "x", [], []]`, sources `[a]`); c at t=3 inserts `y` after O₂. Children of O₂: y, x, B → FOOyxBAR.
- **Move with a concurrent insert**: from FOOBAR, b at t=2 inserts x after O₂ (x=b1→a3); a at t=3 moves FOO to the end: roots [F], pred HEAD, outside [B]. Writes B→HEAD (3,a7), F→R (3,a8). Read: BARFOOx.
- **Range with several roots**: abc built by inserting c, b, a at HEAD (t=1..3). Move `ab` after c (t=4): a→c, b→a. Read: cab.
- **Concurrent moves of one element**: from `abc`, a→c at t=5 and a→b at t=4. Read: bca; nothing duplicated.
- **Cycle**: from `acb` (a=a1→HEAD, c=a2→a1, b=a3→a2), B at t=5 moves a after b: c→HEAD (5,b1), a→b (5,b2); C at t=4 moves b after a: b→a (4,c1). Cycle a→b→a: b's edge (4) is oldest, b falls to prev (→c). Read: cba. Adjacent swaps do not cycle, since the mover re-anchors the outside successor to pred.
- **Reset against a newer insert**: from `abc` (t=1), A replaces with `xyz` at t=5 while B inserts `q` after b at t=6. a, b, c lose every write and go; q sits at b's virtual anchor on END. Read: `xyzq` in either order. An insert at t=3 is dropped. `remove_aspect` at t=5 instead: absent until q arrives, then `q`.
- **Move displaces a concurrent insert**: from `abcd`, B at t=5 moves b to the end: c→a (5,b1), b→d (5,b2); C at t=4 inserts x after a. Children of a: c (5) before x (4). Read: `acdbx`; C intended `axcdb`. A move by position register cannot avoid rewriting the successor's anchor.
- **Delete vs move**: b deleted at t=4, moved after c at t=5. Read: ac; a later insert anchored at b appears after c.
- **Unknown anchor**: x (t=2) after O₂ arrives before FOOBAR: reads `x`, at O₂'s virtual place on END, until O₂ arrives. A reset of FOOBAR at t=5 prunes x; y (t=6) after O₂ survives it: `Zy`.
