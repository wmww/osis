# CRDTs and commits: rationale
> Summary: Why spec/crdt.md and spec/commits.md look the way they do: Tess's decisions, design choices with reasons, known anomalies, rejected alternatives, how osis-crdt and osis-commit are built, the reference model `core/test/crdt-model/` and its tests, text size measurements, worked examples (cited by tests), research pointers.

## Tess's decisions
- One conflict rule everywhere: every state element carries a timestamp and an author dot, later wins, removal is a reset. No causal contexts; no multi-value register.
- Collection elements are identified by creation dot; a removal resets the observed dots, so an add the remover never saw survives. Tombstones carry no content (no fingerprint): a map removal names its key only in role-class aspects, whose keys are public ids (below).
- **Removal is final** ("if something is deleted it stays deleted, no recreation as a side-effect of editing"; "anything written inside a disappearing entry disappears with it"): a map entry or list element reads only while its creation lives (spec/crdt.md §1, §5.6 Live, §5.7 Live); a nested write newer than the removal, or into an entry whose creating delta expired, stays in the state hidden until a reset sweeps it. Accepted costs: an offline edit inside an entry someone else deleted is dropped without notice, and a `put` on an existing key writes into it, so it is lost the same way; a writer on a stale view reads its own write until the removal arrives. Undo of a removal re-adds with a fresh dot. Consequences in the engine: an expiry and a keep-at-most bound due at one instant share a timer key, so `judge_at_most` sets no bound's timer at or past the expiry; code reading a delta's fragment alone sees nothing of a write into another's entry, so link finding uses `Fragment::values` (`Engine::relink_field`, `linked_blobs`) and a history row `Fragment::read_written`; the keep-at-most residue of spec/commits.md §5 (a dropped body's creation lost by an un-merge of its author, given back only by a copy) hides the entry and what was written into it at that node; an ephemeral `Set` into an expired entry is hidden with it.
- `set_aspect` diffs structurally by default; an explicit replace resets.
- Every composite merges recursively down to leaf registers; enum cases never merge with each other.
- The movable text/list CRDT ships in the MVP, as good as we can make it, with whatever fuzzing and testing that takes.
- Apps see plain values and listeners; no CRDT details reach the API. A lost concurrent write looks like any LWW loss.
- Authenticated malicious writers are out of scope (gaming the HLC to win LWW is not a concern).
- No tombstone compaction: worse merging after long separation is acceptable, discarding edits is not.
- Retention per delta (who may purge, keep bounds; spec/commits.md §5), purge per commit without batching, expiry (§6).
- Undo is per actor by default, plus an API listing every change in scope from which an admin may undo others' changes.
- Accepted: a node receiving a multi-aspect commit after one delta was purged applies the rest, so it may briefly see an aspect combination no author produced.
- Commit floor (below) is fine for editing workloads; revisit only if huge commit volumes appear.

## Design choices and why
- **Stamps.** The HLC tiebreak lives in the dot's source, which also works for commit-form dots (the commit ID is unknown before signing). Commit-level writes share one delta stamp: saves 3–6 bytes per write and most intra-commit ordering questions; a delta still consumes at least one counter so frontiers cover every commit.
- **`>=` survival** lets a replace and the embeddings put content at the reset's own stamp.
- **Presence stamp**: an explicitly empty collection exists, one emptied by removals stays present, `remove_aspect` makes it absent. Only `W` is stored and the rest computed, so expiry can lower presence. `W` is always encoded; omitting it under a greater inner stamp would break un-merge.
- **Derived sources** give the register → text embedding one identity per character without a third dot form. A `Derived` record goes with its write, matching a node that only saw the value-less register. Kept although the string→text upgrade is rare: with reset-only embedding an old app's string save concurrent with a newer text edit would read as the edit alone (the string vanishing until someone writes); with embedded characters it reads as the string plus the edit, placed.
- **Bag contributions are set elements**, so undo of an increment is an idempotent element reset. No bag GC: dropping non-extreme max/min elements or folding contributions changes the read under a later reset landing between the folded stamps, and under expiry of the extreme. Bag reads are order-independent (exact int sums clamped, float sums in dot order, IEEE totalOrder).
- **Enum payloads filed per case**: a writer editing case A's payload while another switched to B must not flip the value back to A with a half-written payload; the newer payload write stays hidden until a reset (spec/requirements.md, Data model).
- **A map entry is identified by (dot, key)**: every record carries its key and acts only on the record of its key. Removals are keyed only in role-class aspects, so a `secrets.0` removal's target (and role) is read from the delta alone and a snapshot's tombstones keep the key there. Elsewhere a removal is the dot's key-erased record (keyless), whose reset reaches every record of the dot: an app map key is user content and must not outlive the entry in a removal body or snapshot tombstone (spec/requirements.md Deletion); receivers refuse a keyed reset there (`osis_commit::check_entry_keys`). Writers pick the form by `Writer::keyed_removals`; the differential harnesses mix both (odd writers keyed). A keyless removal also resets a forged second key under the same dot: fine, it is the attacker's. Why not dot-only identity: a node that dropped the creation (compaction) would not know what a removal removed, so validity of a writer's `secrets.0` removal would depend on which bodies a node held, and an equivocated creation key would give different roles at different nodes. A forged or equivocated key is a second entry (pure union).
  - Expiry keeps the shape through the key-erased record: value erasure moves every record of the dot there (the key is the creation's value wherever repeated); its reset reaches every record of the dot and a keyed reset reaches it; it hides the dot while it alone holds the greatest creation; its fragment joins into each live record's read, so a snapshot carrying an expiring entry (value-less, keyless) plus the expiring delta read as the delta's holders do.
  - The records of one dot are one entry for deaths: `state::cross_deaths` reports, after every join touching the dot, the writes of a keyed record and the key-erased record that beat each other (a snapshot's value-less copy against a later put into the live entry). `make_valueless` marks a deaths recompute only when the `erase_keys` merge at expiry beats a write (`Fragment::expire_merging`; marking every expiry would recompute the aspect per tick, O(bodies), 8x the instructions at 200 expiring entries). `deaths::replay_all` plays residues and a valid snapshot's copies of an invalid delta's writes.
  - Cost: a state may hold an expiring entry's content twice (keyed from the delta, key-erased from a snapshot) until T; `join(a, strip(a))` equals `a` in read, not in state (the strip laws compare reads there). Rejected: per-key resets on a dot-identified entry (content pruned under one key's reset is lost when a forged copy later changes the entry's key: order-dependent).
- **Map tombstones live until the map is reset**, because an older nested write may still arrive and must lose (and a newer one must stay hidden). Same-key entries are not merged into one: the dots are different authors' identities, and joining at read time gives the same value with no rewrite.
- **Removal keeps entry creations whose own dot stays** (`remove_dots`, `remove_writes`, `strip_copies`): an entry left with only its `created` stays in the result, and a `Slots` position is edited in place (not re-joined, which would prune those), so a join gives the stamp to the entry where another body holds content and prunes it otherwise; dropping it made `created` depend on arrival order. The creation is a write of its own: a record holding only its creation (content un-merged, or stripped as an invalid snapshot's copies) stays through prunes and on the wire (`[Dot, Ci, R, key, []]`), so content rejoining later finds the entry live again. A keyed record's creation counts toward `written` (§4.3), so a map of such shells is present and reads empty.
- **No set/bag tombstone GC** (uniform with maps). Received-range GC would be sound (only a causally later undo can target an applied dot) but needs a `W` fold for presence, a "dot in received ranges with no record counts as tombstoned" join rule in every node, and makes snapshots differ between nodes. It cannot be opt-in "only when big": the join rule and fold are shared semantics, not a local trigger, and `replace` is no compaction tool (fresh dots lose concurrent removes, the reset drops concurrent older adds). Cost accepted: ~10 bytes per removal forever (spec/requirements.md, Scale); most sets never see a reset since the diff path emits none. If a real workload needs it: run-compressed tombstone records (contiguous dots, one reset stamp) are a representational, divergence-free wire change.
- **Text deletes by flag, lists by element reset.** Text content is immutable, so a flag plus undelete-with-char restores it exactly; the undelete's char is its flag write's payload (never folded into the creation's copy: forged copies, below). A list element's content is a mergeable fragment: with a flag, a concurrent newer nested write would stay in local state but never reach the wire (deleted elements carry no content), so a snapshot would cover the write's body while omitting it and an undelete would read differently on a node bootstrapped from it. As a reset, the newer nested write survives in the state (hidden: the element is live only while `created` is not below `R_elem`, judged at read since `created` is not pruned under `R_elem`, which must keep the anchor placed and encodable), snapshots carry it, and list undo re-inserts with a fresh dot like set and map undo. Both keep the anchor.
- **A list element ends at its creation's own stamp** (spec/crdt.md §4.7, §5.7 Live): when a node holds a creation's delta value-less (expiry, purge) it raises the element's reset to the creation's stamp (`Fragment::expire`, `seq::strip_values` with `at_node`), and `created <= R_elem` is not live. It takes any nested write with it, whole-replaced content and a `W`-only struct included. `strip` (no reset) is the value-less copy a snapshot carries of a delta before T and a residue: it ends nothing and loses to the valued copy; a snapshot from a node past T carries the reset as a foreign `FlagW true`, so a late node without the expired commit reads it alike. A holder of the body before T joins that reset like any write, so the element ends there too (waits.rs `list_element_end_carried_by_snapshot_*`). Monotone, a function of the held set and the value-less list: a purge that falls rebuilds the state without it. A post-purge snapshot holds the element down for its holders even once the purge falls (§5.2 copies replace). Rejected: a value-less mark on the creation (the wire would need a form beside others' content); it is the full fix for the one gap left, issues/list-element-snapshot-before-expiry.md.
- **Hidden writes go by a sweep, not in the lattice** (spec/sync.md §7): `Engine::snapshot` first commits a reset of every record not live with a reset of its own or a creation on the value-less list that still holds a write (`Fragment::sweep`), so hidden writes die by the ordinary path: bodies drop under keep at most, value and repeated key leave state and snapshots. Skips records merely lacking their creation (a partial receipt), value-less copies alone (a valued one may arrive), role-class aspects and memory commits. Writer-side only, no read rule, so no model twin. Rejected: sweeping in the lattice (a record's reset is pruned by a parent reset, so "a reset drops what is under it" depends on order); a snapshot leaving out a non-live entry's content (the write would not be dead, the body not covered by the join rule, and the bytes would stay in the node's state). Not swept: an edit hidden by a parent's reset alone (`replace` of the map: no record reset, so it looks like a partial receipt), a non-current enum case's payload. Cost: a small commit per compaction that finds some, once per hidden write (`sweep_laws`; bare anchors do not count, no reset takes them); a removal so repeated stays when the first remover turns out invalid, as an honest snapshot's copy of the removal already does; a stale sweep's reset is a write, so a collection reset meanwhile by another writer reads empty rather than absent, as under any concurrent removal (§4.3).
- **A map entry's bare anchors live in its key-erased record** (spec/crdt.md §5.6 Bare anchors, `bare.rs`): `prune_dot` cuts every record holding no write out of the keyed records (`take_bare`) into the dot's key-erased record, which drops one a record of the dot holds again (`drop_held`, matching nested map records by dot). A function of the records and their writes, so no memory of a removal is needed. Rejected: moving a whole write-less keyed record (a newer nested write arriving before or after the removal leaves the old anchors in different records); dropping anchors on a reset of the dot (a removal pruned by a later map reset keeps or loses them by order); an `ended` mark of the pruned creation stamp (permanent per removed entry, a wire change). Checked by `lockstep` (`keys_hold_writes` after every join) on `map_of_text` types and `join_laws_map_of_text_spec_5_6`. Cost: reads of a live entry with a nested text reset join its two records (`record_frag` clones).
- **Sequence records are never pruned.** Dropping element records on reset would hide a concurrent newer insert anchored into the removed text until the next reset, violating "a newer write never loses to an older removal"; with bare anchors the insert lands after the new content, as in Yjs. Emptiness counts records, or anchor survival would depend on arrival order. Cost: a sequence's state never shrinks (spec/requirements.md, Scale), about one byte per run.
- **Stripping an invalid snapshot's copies drops the records it empties** (`seq::drop_creations`, `Fragment::drop_creations` for the entry around them; `copies::given_by` lists the snapshot's records carrying no write too): records whose only writes were an invalid snapshot's copies, or bare anchors it carried, would otherwise exist in one arrival order and not another (a bare anchor and no record read differently for a write anchored there: END against hidden). Un-merge (`remove_dots`) keeps every record, as the spec says: the stripped delta joins its records as bare too, so the orders agree.
- **A text creation's death by arrival order** (`merge_elem`): the join dates what arrives in order (a delete raising the flag on a held creation, a creation arriving new to a deleted record) and reports anything out of order or already held (a flag no newer than a held undelete, a creation under an undelete or a copy of a held creation) as `Changes::undated`, on which the engine recomputes the aspect's deaths from the bodies (`mark_if_bounded` in `join_part`, `mark_deaths_due` in `note_copies`): the state does not remember a delete an undelete beat, nor whether a death was dated for a snapshot's copy or the body.
  - A creation a reset prunes dies by the reset (the check runs after `prune_fields`), as a replay of the bodies dates it. Embedded chars (`Derived`) are left out: their death is their register write's, and `prune_stable` re-joins the embedding on every decode.
  - A flag no newer than a held delete is not undated: the creation died at the held delete already. A recompute replays every body of the aspect, so two writers deleting the same chars of a kept text would cost O(history) per delete (2000 bodies: 108 ms against 4 ms in dev; `retention::older_duplicate_text_delete_dates_in_place_spec_commits_5`). A snapshot joining over deleted chars still recomputes (a copy of a held creation).
  - A creation dies once, at its earliest delete (spec/crdt.md §4.8): a delete over a held delete reports nothing; one over an undelete reports the death (`Death::element`) and is undated too, and `replay_all` keeps each element death's earliest. A record arriving new and already deleted (a snapshot carrying both writes) reports the death, at any depth: into an empty state (`join_into`'s shortcut), a new entry, field, slot or list content (`seq::report_deleted` after the prune; `deleted_creation_dies_in_any_order_spec_4_8`). Cost of the delete-over-undelete recompute: issues/text-redelete-recompute-cost.md.
  - A snapshot's copy of a creation whose own delta is not held plays at the snapshot in the recompute, after the element's deletes; the state shows only the last flag, so `replay_all` keeps the deletes it joined (`seq::TextDeletes`, per text path and element dot; a map entry is its dot, so two entries of one key are two texts and a dot's keyed and key-erased records one, §5.6) and dates such a copy at the earliest one newer than it, unless the stamp died earlier in the replay (a reset pruned it); that death is added beside the join's, never in `dead`, so it hides no other.
- **Creation write kept apart from the top-2 positions**: needed to encode runs and to give text content a stamp.
- **Cycle breaking** demotes the oldest move in the cycle, the one the other movers did not know about, keeping the newest intention. Falling back twice needs three or more concurrent moves over the same elements; END keeps content visible instead of hiding it.
- **Move** writes `pos` only for range roots (rewriting interior elements changes their sibling keys and reorders concurrent neighbours). The range spans deleted elements inside the selection; outside subtrees are re-anchored in reverse visual order. Delete is a flag, not a move to a trash position, which would drag concurrent inserts along.
- **Sibling keys** (Tess: exact undo): an undo's restoring position write carries the restored write's sibling key, so the element sorts among its old anchor's children where it was (`eab`, move `a`, undo gives `eab`, not `aeb`), and a concurrent insert there newer than the old write stays before it, as if the move never happened. The key is immutable payload of one write: join stays top-2 by stamp (copies tie-break on anchor, then key), the order a function of state; cycle breaking keeps using write stamps. Key `ts` strictly below the write's. Cost: a writer's delta may carry a commit table entry per commit its keys name (a few bytes; the only foreign stamps a writer's delta holds, rule 7). Rejected: anchoring the restore at the end of the preceding sibling's subtree (no wire change, but the state is not restored, the step-back test on anchors breaks, and several restored elements interact); cancel marks on the move's write (unbounded history per element). Not exact on a broken cycle: a moved element whose `cur` was demoted before the move comes back with a newer stamp and the move as `prev`, so it can demote differently (`xwyz`, concurrent x-after-y and y-after-x, then move x to the end and undo: `xywz` becomes `wzxy`).
- **Encoding slots.** Keeping the register as its own slot makes the state at a position a product of lattices, so the join laws hold across encodings (the model tests every association of three states). Cost: in a `string` → `text` upgrade the last register write is stored twice until a reset. Register edges are total so a value-less write embeds like its valued copy. Slots do not copy the position's reset and are dropped once below the register's embedding: with copying and a grow-only slot set, nested positions join order-dependently.
- **Why join is a lattice**: the union of write sets with per-register maximum is a join-semilattice, and prune is a closure operator that commutes with it (a write a reset drops would be dropped by that reset after any later join); hence commutativity, associativity and idempotence.
- **Un-merge is defined by the held set.** A node that merged a later-revoked author's writes and one that never applied them hold the same bodies and must read the same, so the result is the join of retained bodies, leftovers included, less the author's writes (spec/crdt.md §4.6), not an in-place edit of the state: every flip, drop, strip and re-arrival is `apply::rebuild` (issues/drop-rejoin-robust.md). Residue: content the author's writes replaced under keep-at-most 0 is already dropped and deleted at hosts; a writer that still holds it re-uploads it by convergence, and the author's own write revives value-less.
- **Death of a write** (spec/crdt.md §4.8) is what retention bounds measure from, per write rather than per delta: one surviving character must not keep a paragraph's deleted text alive under "no history", and a long-lived text must stay compactable under "30 days after replaced". Dropping a body is always possible locally (snapshot the aspect, drop), so keep-at-most never needs another node.
- **Purge is value erasure too**: a purged write is held value-less from the purge on, like an expired one, so a snapshot that carried its value is held stripped (its leftover) and re-made. Un-merge may revive a write whose body went under at-most 0; it revives value-less.
- **Expiry is value erasure, not a floor.** It changes no stamp or order, only whether a value is known, so it commutes with join and arrival order; a late older write still loses to the expired one. Dropping the commit's resets instead would let content they pruned survive on a node that received it after T. A floor at T diverges if applied only when the expired write wins (a write stamped between the commit and T wins on some nodes, loses on others), and expires others' newer writes if applied to every register the commit wrote. Expiry is per commit (the header's `expires`); the blob prefix carries it.
- **Drift cap parks** commits from the future instead of holding the clock back, so a wrong clock harms only that node's writes. Parking is silent: a node 90 minutes fast has its writes held by everyone for 90 minutes, and hosts cannot tell it. Hence the corrected clock (spec/sync.md §6): a node fixes its stamps at its first connection and later writes are not parked; only writes it stamped before that wait. A lying peer can shift a node's clock, which harms that node's own writes or admits writes a little early; estimate over several peers, preferring pinned hosts. HLC receipt already pulls a slow clock forward.
- **Diff takes the writer's view**: without it an old writer's save of a `set<struct>` removes every element a newer writer extended and adds a stripped copy. The diff algorithm itself is not normative, only "kept elements keep their dot".
- **Second dot form** (commit ID, index): unlinkable, and collision-free when several nodes sign with one key (per-node counters under a shared key let any holder reuse another's dot and knock out its edit). Its cost falls only on such commits: runs do not continue across commits, one 32-byte `Sources` entry per foreign commit, revoke frontiers list commits.
- **`Sources` and encoding IDs live in the delta**, not the header: a delta is then self-contained (projection, purge rewrite and hashing need no header context) and the order rule is well defined per delta; a header rule "first appearance in the canonical encoding" would be circular across several deltas. Cost: a source repeated per delta of a multi-aspect commit.
- **Every state element carries its dot**, so un-merge and revoke frontiers are uniform.
- **No commit DAG**: causality is intra-aspect only, tids may dangle.
- "Repair via listeners" only works if the repair is a deterministic function of state; otherwise two nodes ping-pong.
- **`put_new` (`Op::Put`)**: at a map key a new entry whatever is live (invite grants' `secrets.0` puts); at a register position a register write even when equal (chunk repair); refused elsewhere, since a composite would merge with what is there (union, second entry, second copy). A repair is a plain write with a fresh stamp: it overrides a concurrent unseen edit of that position and can bring back a map entry whose removal it has not seen; it is limited to the positions whose chunks are gone and rate-limited (notes/engine-paged.md, Dropped chunks). Two puts of one key in one commit share a stamp and do not net out like two commits; no writer does that.

## Known anomalies (all convergent)
- A move displaces a concurrent insert made right after the moved range's predecessor (worked example below).
- An enum payload edit concurrent with a case change stays hidden (spec/requirements.md, Data model).
- A field write concurrent with a reset of its struct, a struct field or the aspect (a `replace` or `remove_aspect`) shows that field alone: positions have no creation, so the later write wins there (spec/requirements.md, Data model). Inside a map entry or list element the removal wins instead: the concurrent edit stays hidden, and so does everything written into an entry whose creating delta expired.
- While a text aspect is in transition, every save by an old LWW app wipes concurrent older text edits; old code has no CRDT.
- The list diff pairs changed entries in order; a misaligned pair becomes delete+insert and loses concurrent edits to that entry. Apps editing list entries concurrently should use path ops.
- Un-merge restores values and positions the invalid author's writes had superseded only from retained bodies; a node that dropped them under keep-at-most reads them as absent until a peer re-supplies the body.
- Undo of a reset re-adds content with fresh dots (the old dots stay below the reset forever), so a later undo of an original element no longer cancels its restored copy; only out-of-order selective undo sees this. Bag undo re-adds contributions without a reset so concurrent newer contributions survive; other encodings' reset undo is a `replace` and wipes concurrent newer writes inside the value.
- Undo chains on one position: a register or position undo writes back the value before the undone commit while the position reads what the undone write wrote (value, or anchor and sibling key), whoever wrote it now. So undo steps back through repeated edits (the previous undo restored the value the next one compares with) and redo forward, with no judgment of which commits are in effect; a later edit to an equal value by anyone is overwritten (the read is the same). Enum case writes are undone as resets.
- Copies of one write that differ (forged; snapshots vouch, spec/permissions.md §5.2) join by the copy order of spec/crdt.md §4.1, total over every copy held, a held original's included (nothing is stripped for a snapshot, notes/permissions.md Snapshots and history): the attacker picks the outcome (a forged copy may compare greater), every holder agrees, which is all a writer gets by writing a new value anyway; the original's body stays held, as no snapshot holding another copy of a live write covers it (spec/commits.md §5 Covered), so a removal of the forger gives it back. Limit: a map dot created under two keys (only through a valid snapshot's differing copy): value erasure (expiry, purge) folds both into the key-erased record, whose reset prunes the other key's record too, so before `T` a node holding a post-erasure snapshot beside the valued records reads that key gone while one without the snapshot reads it live; converges at `T` (osis-crdt `tests_review::repro_forged_key_hidden_by_erased_reset`, ignored). Limit (forged snapshots only, accepted): a differing-key copy can leave a hidden key-erased record no body gives (`validity::differing_key_copy_keeps_no_other_record_spec_crdt_4_6`); reads alike. Two creations of one dot under other `ts` (only forged snapshots) are copies of one write: the greater wins whole (anchor and char) and the lesser is no position write, so a snapshot carries exactly the state (a `PosW` under the element's own dot has no wire form). Every char in a state is the payload of a stamped write, the creation's or an undelete's flag write's (spec/crdt.md §5.7; the wire tells them apart: `Content` against the `FlagW` string), so no char is re-attributed at join and the state is a product of LWW registers; the element reads the creation's copy, else the undelete's. Folding an undelete's char into the creation's copy diverges by arrival order when two creation stamps meet. Cost: a node bootstrapped from a snapshot (deleted chars not carried) that then joins an undelete holds the undelete's copy only, so it reads alike but snapshots differently from a full-history node (crdt-model `bootstrap_convergence_text` checks it holds nothing beyond the full one); honest undeletes repeat the creation's char, so the two copies agree. A map key is identity, so differing keys are two entries. A text slot's `Derived` records are re-fitted to the register's winning copy (`seq::fit_embedding`), else a holder that embedded the losing copy first keeps its chars.

## Rejected
- Wall-clock staleness horizon for tombstones: nodes separated longer than the horizon diverge or lose edits; any independent reset-style compaction has the same problem.
- LWW-element sets/maps: the tombstone names a value hash or key (a fingerprint once the body is purged) and cannot be dropped without stability information.
- OR-set/OR-map with causal contexts: same add-wins semantics as dot addressing but a version vector in every state and delta. Possible later if map tombstones ever matter: stability-based GC (needs frontiers, stalls on offline nodes).
- Terminal reset / retire marker in the encoding lattice: representation changes are transitions to new IDs.
- Hiding a purged delta's repeated map keys by moving creationless keyed records into the key-erased record at strip time: order-dependent (in place vs rebuild differ, `lattice_laws` break). "A record reads only while it holds its creation" closes the leak as a pure function of state.
- Destructive join of unrelated encodings (later encoding wins, the loser becomes a reset): with eager embedding it is not associative, `(register ⊔ counter) ⊔ text` ends as a counter and `register ⊔ (counter ⊔ text)` as a text.
- Attributing state elements through commit headers instead of dots (zero bytes in state, history lookup at revocation): not uniform.
- Columnar or bit-packed encodings (20–30% gain, not worth leaving CBOR); dropping stamps from deletions (changes undo, and deletions are not the dominant cost).

## Implementation hints (non-normative)
- Linearization: cache the order and tree; a delta touching k elements re-places those k subtrees; a cycle recomputes only its strongly connected component.
- Large states page in the local store like snapshots (notes/local-store.md, Units). Very long texts (tens of MB) load fully for linearization; a subtree-count index is a later optimization.
- Cut/paste (client behaviour, no protocol concept): `cut` deletes the range and remembers its dot ranges beside the clipboard text; `paste` moves the remembered roots to the destination and undeletes the range when the clipboard still matches them (`Op::Paste`), else inserts plainly. Optional osis clipboard MIME type with (aspect, ranges).
- Undo stack is derived, not stored: the actor's own commits in scope (a set of aspects or a group) minus undone ones, plus undo commits for redo. Replicates for free, so undo works across nodes. A node keeps its own bodies and pre-reset snapshots locally for the undo horizon.
- A list path op resolves index paths against local state at write time; deltas never carry indices.
- A commit is limited only by its header lists (`MAX_LIST_BYTES`): any delta pages like a snapshot (§8), so a bulk `replace` of a huge map is one atomic commit; the writer streams pages out, readers stream them in. Runs are capped at `MAX_RUN` = 2^12 elements so a page stays under `MAX_PAGE_ITEMS` (Page items below).
- **Commit floor**: a minimal commit is about 300 bytes once nonce, framing, tag and padding count, plus a 57-byte wrap per label and a prefix of about 35 bytes.

## Consequences of spec rules
Worth knowing, not extra rules.
- **Second session** (§2.1): an expired ephemeral commit is forgotten with its counters; under a session of its own it leaves no gap a snapshot frontier could not pass.
- **Expiring deltas and snapshots** (§4.7, §8): a delta with an expiry is not covered before T, so its content lives only in its own blob, which hosts drop at T; past T its leftover is covered like any body.
- **Slots read** (§7): every non-register slot holds the register's embedding, so a slot's greatest stamp is at least the register's: the register is chosen only when alone, and then the position is just that register. Two unrelated encodings read as "later writer wins", the other's history kept and readable again if it is written last later. Applying the embedding eagerly after every join equals applying it at read.
- **Page items** (§8): a blob counts at most its length in bytes.

## Implementation (`osis-crdt`)
- **Structures**: `Fragment` enum, one struct per encoding (`fragment.rs`), crate-private fields; collections are `BTreeMap<Dot, _>`, struct fields and enum payloads `BTreeMap<u64, _>`. Sequences: `seq.rs` (element state, join, prune, presence, read, strip, un-merge, text embedding), `seq_span.rs` (range records), `seq_wire.rs` (runs), `seq_ops.rs` (ops, net effect, undo), `seq_diff.rs` (diff, `edit`), `linearize.rs`, `seq_lin.rs` (placement cache), `seq_place.rs` (placement held in part); the generic code calls only the hooks re-exported from `seq.rs` and owns a sequence's reset and `W`. A text keeps the chars of deleted elements locally (undo and paste read them); a snapshot does not carry them, so a bootstrapped node's state differs only there.
- **Live** (`Map::is_live`, `seq::is_visible`): a keyed record is live iff it holds its creation, its fragment is present and its dot is not hidden by a key-erased creation; a list element iff `created` is held and above its reset (`SeqElem::reset`) and its content reads. Everything that shows, places by index or diffs goes through these two.
- **Range records** (`seq_span.rs`; spec/requirements.md Scale: a snapshot run `[Dot, 2^12, [], [], [], []]` is 8 bytes): a `SeqElem` with `span > 1` stands for consecutive elements of one source that are uniform (no content, no position write but the creation, one deleted write or reset, no creation or a creation chain of one `ts`). Decode makes one per uniform stretch of a run (elements with content stand alone), so records are O(input). Join cuts an incoming record at the state's record starts after splitting state ranges at its bounds, and splits a chain a reset falls inside (`chain_cut`); nothing coalesces except on a sequence's own reset (Linearization), so `Seq` equality is per element (`elems_eq`). Invariant: no record key inside another's span (a `Derived(S, c)` key splits an `S` range at `c + 1`), so `find` is the record at or before a dot. Deltas from ops and undo are expanded per element where convenient (`expand`: the format bounds them); a received state never is. Tests coalesce every model state into ranges (`testutil::frag`).
- **Slots**: every prune of a `Slots` re-embeds the register slot into each other slot, so a received `Slots` lacking the embedding converges with one built by join. A join that leaves the register and effective reset `E` as they are (`kept_reset`: no newer register write or reset, no slot reset above `E`; the common case, sequence writes) joins only the delta's slots under `E`, a new slot with the embedding, so untouched slots and the text slot's placement cache stay (`join_slots_kept`; debug builds compare it with the whole join); anything else re-embeds and prunes the whole position. A lone non-register slot is chosen without scanning (it holds the embedding, so beats the register). `Batch` layers a sequence op over the `Slots` slot of its encoding when that slot carries the position's reset (`seq_slot`). Both decoders judge rule 7's "pruning would change it" with deleted chars dropped (the embedding restores a deleted embedded char that the wire never carries, rule 5) and return the pruned position, so a bootstrapped node holds such a char again and a content-less undelete of it reads it (returning the unpruned form lets one writer make peers' states unencodable). Both reject a `Derived`-stamped write other than a text creation (and its position write). `crdt_model::gen` writes a string to a root register one time in three so the differentials reach embedded chars, and the generator sends content-less undeletes of embedded chars now and then.
- **Interning**: `Source` is an `Arc<SourceKind>`; a stamp is `ts` + pointer + counter. Equality and order never depend on sharing; `Interner` dedupes per decode (a node may keep one per aspect). Dot and source comparisons borrow: decoded deltas never share the state's source `Arc`s.
- **Join** (`state.rs`) is delta-driven: `join_into(other, e_parent, changes)` walks only what `other` carries; existing children are pruned only when an own reset rises. Equals union-then-prune (lockstep tests against the model after every join). An empty state takes the other side pruned.
- **Change summary** (`Changes`): `is_changed` plus `Death { stamp, at }` for every write superseded (beaten register/case/reset, pruned write, late write dying on arrival). Writes sharing a delta stamp are reported per instance.
- **Wire** (`wire.rs`, `codec.rs`, `stream.rs`): values are built as `osis_base::Value` trees, one element at a time; encoding runs the fragment encoder twice (collecting pass for `Sources`/`Commits`, which keeps no values). Every element array and field map goes through `codec::Pager`: held while its plain form fits the page target, then cut as elements come, each page put when it closes, so encoding holds about one page per open position (plus the links), not the delta's value tree (a 10^5-key map's delta: 13 MB above the delta, 2.4 MB of it the pages the test's sink keeps, against 129 MB for the whole encoder).
  - Decoding (`stream`) checks the grammar, ranges and rule 7, then re-encodes and requires the input bytes: every canonical rule, paging included, is that one comparison. The re-encode goes through the same `Pager` with the input's pages in its `Replay`: a page cut differently is not there, and the position's link list must come out as written. It streams: the root decodes into a skeleton with every paged collection reached through `Step`s (fields, payloads, map entries) left empty; the skeleton re-encodes against the root with the input's own tables (`Enc` check mode, `Dec::checker`); each such collection then decodes one leaf page at a time and re-encodes element by element (`Out`: seams must ascend, one open sequence run carried across pages); at the end the tables must be what a collecting pass builds (first appearances in table order, the root's appearances logged and replayed around its streamed positions, each commit's base its smallest counter). Paged positions inside a page, a `Slots` slot or a sequence's content decode whole. `stream_delta`/`stream_snapshot` hand over the skeleton, then one `Piece::Page` per leaf page; `decode_delta` puts them back together. The engine decodes whole (`decode_delta`); applying per page is step 3 of issues/durable-decode-bound.md.
  - Oracles: the whole encoder (every element held, cut at the end) is `codec::oracle::encode_*`; in this crate's tests every `encode_delta`/`encode_snapshot` also runs it into content-addressed sinks and requires the same root and pages (`oracle::twin`). The whole-delta decoder is `codec::oracle`; `tests_stream` mutates roots and pages and requires the same decisions.
  - Rule 1 quirk (list runs counted as if not closed by content size): the collecting pass cannot cut at `CHUNK_MAX`, since a run's content bytes depend on the `Ci` indices, which depend on the sorted `Commits` table the pass is building; so `Runs` defers the sources of a run's position and flag writes to the end of the uncut run in every mode (`Enc::defer`), and both passes and the check note in the rule's order.
  - Sequences: runs per §3.3 rule 3 over `Enc::sorted`; built incrementally (`Runs`: records pushed in wire order, one open run, so a streamed sequence re-encodes across pages); a list run with content is cut where its encoded fragments reach `CHUNK_MAX`, so a run and a page fit a blob; a segment's `Ci` is read off the encoded creation stamp. Decode claims own creations and position writes, rejects n = 0 or > `MAX_RUN`, bad indices, list undeletes, content length mismatches, segments of another source, `Derived` creation runs in a writer's delta, empty list element fragments, bare-anchor runs in a writer's delta, more than `MAX_DELTA_BARE` content-less elements in a writer delta (counted across pages on `Dec`, before allocating), writer `FlagW` stamps off the delta stamp; the re-encode check covers maximality and order. Decoding cuts each run where segments, position writes and flag writes change (overlapping flag writes are rejected up front) and never loops per element except over a writer's own counters (bounded by rule 7).
- **Paging**: `PageParams` (format: 64 KiB target, 16/256 KiB cuts, 512 fanout) come from the `PageSink`/`PageSource`; tests shrink them. `osis_base::PageCutter` cuts; link pages use the tree-node rule; a third level is refused. `page_array(sink, items)` is the public split of one element array (vectors); struct and enum field maps page the same way (`page_map`, a field = key and value bytes, pages are maps), so no delta outgrows a blob (spec/commits.md §1; `CommitBuilder::max_blob` shrinks the bound for tests). Decode records each position's pages after its items (`Dec::done`), i.e. in the encoder's put order, so equal page plaintexts (equal structs written in one commit) replay to their own links. Each put must be its own blob (a decode refuses a blob linked twice; the node's `LocalPages` derives a distinct ID per put).
- **Page items** (`MAX_PAGE_ITEMS` 2^21, spec/crdt.md §8; `codec::check_items`/`check_root`): counted from heads before `osis_base::decode`, one per CBOR item plus text bytes, so the count is at most the blob's bytes and blobs up to 2 MiB skip the walk. Not applied to ephemeral deltas (`PageParams::UNPAGED`, which have `decoded_bound` against the node cap instead). Why 2^21 and not 2^20: an honest page is under `CHUNK_MAX` bytes before its last element, plus that element, and the largest elements are (items at most bytes): a map entry, key up to 128 KiB plus a `Slots` fragment (a register value up to 128 KiB plus up to 9 slots whose arrays are each at most `PAGE_TARGET` inline: about 720 KiB); a list run, `Content` under `CHUNK_MAX` plus one such fragment plus about 33 items per element of position, flag and segment writes; a text run, up to about 36 items per element (two position writes with sibling keys, a flag write, a segment, 4 bytes of char). Measured: a text whose every char was moved twice and half deleted counts 16 items per element. At `MAX_RUN` 2^16 one such run alone would pass 2^21, hence `MAX_RUN` 2^12; the worst page is then about 256 KiB + 983 K + 135 K = 1.4 x 2^20 items, under 2^21 with a third to spare. 2^20 would hold for everything but the many-slot `Slots` corner (pages up to about 1.38 M items). The root's `Sources`/`Commits`/`Frontiers`/`Absorbed`/`Authors` are not counted (bounded by `MAX_BLOB`; they decode to small fixed records).
- **Ops** (`ops.rs`, `batch.rs`): `diff`/`create`/`replace` match the model write for write under a `View`. A set element is one register holding the whole value whatever its type (`set_elem`; both decoders reject another fragment there, rule 7); a link fits only a register position. `Batch` makes a commit's net effect: ops resolve against state ⊔ batch-so-far, borrowing the state where the batch has no writes and copying the position where it has (`current`; map keys join only that key's entries, `key_lookup`).
  - At a sequence position the batch already wrote, an op resolves against the state's sequence layered under the batch's records instead of a copy (`seq::Layered`: the batch's new records and every state record its writes meet, copied whole and then split where they land, plus the state's placement followed through them; sequence ops and `seq_diff::edit` read through `SeqRead`, the cache's plan/follow through `Recs`); where a batch reset lies above or the cache cannot follow, it copies. The view is kept (`Seen`, keyed by that path) for the next op at the same position, joined with each op's delta there while `prune(acc) ⊔ d` equals the overlay there (else dropped), checked at the op's elements only (`seq::Foot`, O(op · log n)), so a batch of N ops on one text costs O(N · (√n + log n)); any other op drops it. `seq::overlay` touches only the op's elements and looks for created-and-removed elements to omit only when the op removed one or dropped an anchor at one. The debug check compares the kept view with what `current` would copy.
  - Ops see state joined with the batch slot by slot (`slot`), not the net effect's own slots: a batch writing a register at P and then a field of P resolves the field against the state's struct (the register is another slot), and the overlay of differing encodings keeps only the later write. `overlay` lets a later op override, drops a reset's earlier content, omits created-and-removed elements and then sets `W` if the collection would be left with no write (one-by-one ops would have left it present).
- **Seq ops**: `Op::Insert/Delete/Move` by visible index (`Move.to` indexes the sequence without the range, like the model); `Op::Paste { dots, at }` (`cut_dots` gives the visible dots a cut removes; paste = move of the slice of the placement order they span + undelete; fails if a dot or its char is gone or visible text lies inside the remembered range, and the caller inserts); `Op::InsertAfter { anchor, items }` and `Op::DeleteDots { dots }` (index resolved by a caller keeping the placement apart; the node does not use them, its ops run through a placement held in part; the anchor must be a visible record of the state, each dot in a record, distinct; write for write the index ops', and the new elements land right after the anchor when the writer's `ts` is above every stamp of the sequence, which §2.2/§8 make true of a node's commits).
  - `Op::Edit { base, new }` (what `diff_values` emits for sequences): `seq_diff::edit` aligns `base` to the current read at base's own indices when the read has base's length and equals it over the changed middle widened by `CTX` = 32 elements each side, a stretch occurring nowhere else in base (else a concurrent shift can put same-content elements there in periodic text and the edit lands a period off); otherwise by exact LCS over the whole read. Deletes and insert anchors use exact matches only; a list element changed on both sides is edited in place (`diff_values` of its value through a nested `Batch`) only when it is the one unmatched element of its gap on each side. `window` is all a sequence held in part needs; `edit_window` gives a node that stretch; a whole pass over records held in part is told apart from a miss (`PlaceMisses::whole`, which the node counts).
  - Delete flags the whole range, hidden elements inside included (more than `MAX_DELTA_BARE` is refused: split across commits); undo of it undeletes only what the pre-commit state showed. Move reads only the range's rows: the `outside` nodes are the rows after it whose parent is in it, each skipped with its subtree (`Placement::hanging`), and `to` skips the range's visible count by rank, so a move op costs O(range + √n). Move writes each element of a range record without creation (bare anchors, flag-only) as its own root, chained, counted against `MAX_DELTA_BARE`; so move/insert equal the model's write for write whatever the record split.
- **Seq net effect** (`seq_ops::overlay`): later writes override; a list element reset in the commit drops the commit's earlier content of the element (same stamp would survive it); a deleted char is not carried; a created-and-removed element is omitted only when nothing else in the commit anchors at it (spec §4.5).
- **Seq undo**: insert → flag/element reset; text delete → undelete with the char from the pre-commit state, only where that state shows the element visible; list delete → re-insert after the old element with a fresh dot; undelete → delete only where the pre-commit state had it deleted; position writes → old anchors and sibling keys with fresh counters in the old stamps' order, only while the element's `cur` has the undone write's anchor and sibling key; nested list content through `undo.rs` (a callback).
- **Diff** (`seq_diff.rs`): Myers after trimming the common prefix and suffix, giving up past 512 edits (the middle is then replaced: any script is valid, §9); inserts anchor after the preceding matched or paired element; opaque list elements are left out of the alignment.
- **Linearization** (`linearize.rs`): whole state per call, by index into the dot-ordered records. A range record is one node, split after each element something anchors at and where a virtual `Derived` anchor sits between its elements in dot order, so hidden order matches the per-element order (inside a node each element is the only child of the one before, or all are bare anchors on END). `Placement` is per node (first and last element, span); anchors are found by binary search after trying the node just before in dot order (where typing anchors); sibling lists in one array, one walk. Cycles: rounds of walks (first from every node, then from the victims), each node walked once per round, a persistent mark on nodes that reach HEAD, END or a hidden anchor; any walk demotes the cycle it closes. Linear on adversarial graphs.
- **Placement cache** (`seq_lin::Lin`, behind a `OnceLock<Arc<_>>`, not part of `Eq`), per `Seq` of `LIN_MIN` = 64 records or more (1 under `cfg(test)`, so lockstep tests check it):
  - Rows (node, last element, parent, chosen edge stamp, depth, shown, a visible text char) in blocks of about √n (at most 256 when built, split above twice that; 4 at least), each an `Arc` (a copy shares untouched blocks) with its visible count and least depth, plus a depth shift per block outside the `Arc`. A subtree is the rows up to the next one no deeper (blocks all deeper skipped, O(√n)). A row-dot → block map, built with the rows, in dot order as sorted `Arc` chunks of about √n entries (at least 64), so a copy clones only the chunks it writes. Position, visible index and dot lookups and a splice cost O(√n); the block size rises with the row count (`cap = max(cap, min(√len, 256))` on insert). `take` merges a block left below half the block size with a neighbour; `insert` splits an oversized block.
  - Every join follows it: `elems` is private, `elems_mut` drops the cache, `join_elems` plans each record before it joins and `Lin::follow` splices new runs where they place (after the anchor and past its children with greater edge stamps, each skipped with its subtree; 256 or more rebuild; at HEAD before the `END` rows; a cursor walks the blocks). The newest of a delta's runs and moves, when above `Lin::newest` (a stamp at or above every position write), goes right after its anchor without reading the children's records, except a move onto an element new in the delta (that element's run may go on with a newer stamp). Single elements whose chosen edge changed (moves) are re-placed in write-stamp order so a mover's outside re-anchors come first; if one lands where it was only depths shift, else the smaller of it and the rows it passes moves. Flag and content writes carry their new visibility from the plan walk and are applied per block (`flip`), including a decoded record over several state records (`plan_pieces`). A record whose join changed nothing is not followed.
  - Rebuilds: a delta with more than max(√n, 64) runs, moves and row cuts, or whose placements look at more than max(n, 1024) rows and blocks (a sibling skipped counts 8; each cut charged with its subtree walk and depth shift, the budget checked after each), so hostile deltas cost about a whole pass (`hostile_moves_join_bounded_spec_6`, `hostile_cuts_join_bounded_spec_6`). A move rebuilds when it closes a cycle (checked per step), touches an element on a cycle a demotion broke (`Lin::cyc`; otherwise the old demotions stay forced, §6.2), writes or drops an anchor naming an unknown element (an absent `Derived` one), or drops one inside a range record; resets and new `Derived` records rebuild too.
  - A write over part of a range record or a new anchor inside one cuts the row where a whole pass cuts the node (`cut_row`, `Plan::Cut`: a chain's second piece becomes the only child of the first, its subtree one level deeper by `reshift`; pieces without creation sit side by side on END); a row's `parent` is the element its edge names, so a cut changes no child's row. A row the delta moves sits by its old chosen write's sibling key until re-placed (`sits`): the join may have replaced that write by a copy (§4.1) or put it below another write at that anchor, so `Sibs::key` reading the record would misplace a sibling slotted past it.
  - A join raising the sequence's own reset merges the records it left bare into range records (`seq::prune_reset` → `seq_span::coalesce_in`), so the pass after a reset places one node per stretch of dots. Only there: such a join is written whole (a paged state re-laid out), while `strip` and un-merge rewrite only the pages they touch, where a merge could leave a record spanning past its page (`seq_placement_differential_after_reset_spec_crdt_6` checks every stored page holds whole records). A reset raised by a parent does not merge.
  - Held `Derived` elements and anchors at them are followed like any other, at a `Slots` position too. Text `read` and `diff`/`edit` take the chars from the rows; a list `read` steps through the records in dot order alongside the visible rows, searching only where the order jumps (no per-row value cache: a list element's read can be any size). Tests compare the cache with a whole pass after every join, and the dot map and counts with the rows (`testutil::check_lin`, which also checks `present()` against `written()`).
- **Held in part** (`seq_place.rs`, `SeqPlace`): the node keeps a paged sequence's placement in its store in this form (top, block rows by arena id, dot-map chunks by first dot; notes/engine-paged.md, Paged state) and loads it in part (`from_top`: every block and chunk a stub with its counts, least depth, first dot). Attached to a sequence whose records are held in part (`set_seq_place`, `cover` = the loaded pages' dot ranges), joins follow it and ops by index resolve through it as through a whole one; whatever reads a stub or a record outside the cover notes a miss (`seq_lin::Partial`, shared by copies; `Covered` wraps record lookups, also under `Layered`) and fails (the follow returns `false`, the op's result is void). Presence comes from a visible placed node, existence (`is_empty`) from any placed node, and the greatest stamp inside (`inner_max`, `written`) needs every record (`all`). A stored row keeps no text char (`fill_chars` sets them only on a whole load), so a text read takes a char a row lacks from its record (`Vis::chars`) and a list read notes records outside the cover: a read held in part returns the whole read once what it missed is loaded, never a silently short one. Neighbouring stubs are not merged. `dry_follow` follows a copy through a join over a copy of the records the delta touches (`Over`), so the node loads the misses before the join itself; `diff` lists what changed against the placement as stored (blocks by `Arc` identity, chunks by first dot). A node loads a sequence whole for `Set` (notes/engine-paged.md Paged state). `Fragment::visible_range` and `read_elems` read by index from the cache or from stored dots. What remains: issues/crdt-seq-linearization-cost.md.
- **Undo** (`undo.rs`): spec/crdt.md §4.6 states only constraints (rights, no revived value-less content, copy expiry, SHOULD restore the prior read); receivers never re-derive an undo, so this is one writer's choice. Cancel per dot over the original delta, walking it in step with the current state and the pre-commit state (`before`). A position absent before the commit (a composite, or the aspect root), under one present before, is reset (`remove_aspect`'s delta) when it reads now what the undone delta joined into the pre-commit state reads; else the per-write rules run. The reset also drops concurrent writes into it that arrive later (a reset at a position, like `remove_aspect`) and a held later write by anyone that left the read unchanged (re-adding an equal value), as the register rule overwrites a later equal edit; the engine runs an undo whose reset reaches a paged collection held in part again on the whole state (`undo_in`), since that collection holds others' entries on pages the delta does not touch (a reset elsewhere lies in a loaded page or the skeleton); a register absent before inside a present struct stays (no nested register reset). A key removed with several entries returns as one entry of their joined value (separate re-adds share the undo stamp and tie). A nested edit under a map key is undone against the join of the key's live entries before the commit (`entry_frag`). Two schemas on one AK: a pre-commit value that does not fit the view fails the undo (`Mismatch`).
- **Un-merge** (`lifecycle.rs`): the node joins its held bodies with `remove_dots(pred)` applied (an author's dots or one delta's); in place (`remove_dots` on the state, then prune) only when `dots_supersede(pred)` is false: no register, case, reset, `W` (max-joined, so theirs may hide another's), flag or non-creation position write of theirs; `holds_dots` says whether there is anything to remove. `remove_writes` keeps others' writes nested in records they created (snapshots).
- **Access** (`access.rs`): `Map::entries()` and `Map::live(k)` read-only (node adapts `roles.0` entries into perm edge writes, reads `secrets.0` keys); `Fragment::at(path)` reads one position (a key with one live entry in place, O(log n); several are joined). `Batch` resolves a path through a map key with one live entry the batch has not written in place too (`key_lookup` borrows), so a nested write into a large inner map copies nothing of it. `present()` stops at the first presence-counting write (equal to `written().is_some()`).
- **Paging hooks** (`paging.rs`, for the node's paged states): `elem_count` (records), `elem_dots`, `elem_range` (the collection restricted to root records in a dot range), `touched_elems`, `Step` / `Paths` (positions below struct fields, enum payloads and map entries), `step`, `at_steps`, `wrap` (a fragment holding one piece at a path, entry keys and creations carried), `reduced` (paged collections cut to their reset and `W`), `collections`, `touched_paths` (what joining a delta can change per paged collection, and whether the rest; `None` for a reset at or above one).
- **Undo footprint** (`Fragment::footprint(delta)`): the part of a pre-commit state undoing the delta reads (struct fields it writes; of a map, set or bag without a reset only its dots, and for a nested edit the key's live entries along the edit's own paths; of a list or text the records holding the delta's dots, `Seq::footprint`); equal undo deltas are tested against the whole state.
- **Remap** (`remap.rs`): `Fragment::map_dots` maps every dot; `Fragment::writes` lists every write's origin dot with its `ts` for judging a snapshot's writes and ranking them. One read-only walk (`remap::walk`, a `Visit` over stamps and records, never expanding range records) drives `writes`, `holds_owned`, `holds_stamp` and `dots_in`.
- **Entry creation** (`Entry::created`, spec §3.2, §5.6): the creation stamp `(ts, entry dot)`, set by ops for fresh entries, implied when decoding a writer's own creations, carried as the entry's `Ci` by snapshots, pruned like any write and dropped with the content; kept through paging. **Authors** (`Snapshot::authors`, §8): per `Commit` source the node and `ts` its writes are judged as; omitted when empty. `has_reset`, `is_plain_struct`, `is_put_only_map` (`shape.rs`).
- **Key index**: `Map.keys` (key -> keyed records `Eid` carrying it, a superset; lookups check liveness, `Map::live_ids`; not part of `Eq`), kept by `join_entries`, `Map::new`, batch `overlay`, `map_dots`. Records are `entries: BTreeMap<Eid, Entry>` (`Eid { dot, key }`, `Key` ordered by canonical bytes); a dot's records are contiguous, the key-erased one first (`Map::of_dot`), pruned together (`state::prune_dot`). Index paths and `Remove` of a map key still scan or clone.
- **Left near-parallel on purpose** (merging them came out line-neutral): set element vs map entry join and overlay (state.rs `join_elems`/`join_entry`, batch.rs `overlay_elems`/map arm; the entry's creation prune sits between content prune and join, and `Changes` deaths are ordered); the mutating walks `map_dots`, `strip_values`, `remove_dots_in`.
- **Timing** (release, 16-core box under load; figures move with load, compare A/B at equal load). `budget_big_map_spec_4_1` (10^5-entry map): create 53 ms, join 43 ms, read 132 ms, encode 224 ms / 31 pages, decode 276 ms, one-entry join 0.3 µs. `budget_big_text_spec_6` (10^5-char text; received deltas are encoded and decoded before the timed join): build (1000 local commits of 100 chars) 0.27 s, read 0.45 ms, whole placement pass 23-60 ms, one op (`Batch`, encode, decode, own join) 0.09 ms, two-op batch on one text 0.12 ms, received insert 9-11 µs (also with no read since the last), 5-char delete join 6-8 µs, received older concurrent insert 27 µs, received move join 17-35 µs then read 0.2-0.6 ms, local move op 60-75 µs, hostile delta of 1000 moves to HEAD 20-21 ms against a 15-16 ms whole pass (300 such moves 27-28 ms: the work budget, then a rebuild), snapshot encode 40 ms, decode 85 ms. A join into a fresh copy of the state (a node keeping the pre-commit state) 42 µs mean, 0.1 ms max. On a text bootstrapped with a 100-char deleted stretch: received undelete of 10 chars inside it 89 µs join + 0.17 ms read; insert anchored inside it 20-27 µs + 0.15 ms. On a text upgraded from a 10^5-char string: received insert anchored at an embedded char 50 µs join, read after it 0.16 ms, two-op batch 0.17 ms. 10^5-element list read (100 runs of 1000 at random places) 7.5-13.7 ms. Received replace of the 10^5 text (a reset): join 12-20 ms (merging the bare records ~5 ms), read after it 21-31 µs. ## Implementation (`osis-commit`)
- **Header** (`header.rs`): `Header` with every spec/wire.md §4 position; a list that goes by link keeps its root in `links` and is empty until `resolve(src, actor dedup)` reads the chunk tree. `decode` checks structure and canonical bytes (re-encode equals input); `validate` checks every rule a header shows (sort orders, indices, ranges, kind vs aspect class, one delta per aspect, fixed retention, delete levels exactly the retention's, expiry, purge, frontier only on kind 1) and needs resolved lists. A higher format version is `UnknownVersion` (Parked) before the arity check.
- **Header lists are read by shape** (`header.rs` `read_*` over `osis_base::Reader`, inline and linked; `tree::parse_node` too; `frontier_value` for a linked header or frontier): worst honest shape about 5 B of memory per list byte (purge at 21 B per item), where a whole-value `decode` costs up to about 56 B per byte. Items in strictly ascending bytes, checked in `Header::decode`, so a repeated chunk link is refused at its first repeat. `validate` still states each list's own order.
- **Header lists** (`lists.rs`): crate-root `write_list(bytes, dedup, sink, prefix)`/`read_list(root, dedup, src, max)` adapt `BlobSink`/`BlobSource` (prefix inputs in, plaintext out; own traits: crdt's `PageSink` computes the link hash from plaintext, which a tree node's hash is not, and takes no prefix) to the tree module with `ChunkParams::FORMAT`; `MAX_LIST_BYTES` = 64 MiB (format constant, spec/wire.md §2: a resolved header is in memory); `Header::resolve` (past it, bad input); `MemoryBlobs` (tests).
- **Commit blob** (`blob.rs`): `CommitBlob { header, signature, parts }`, encoded by concatenation (header and delta bytes are already canonical items); decode re-encodes and compares. `missing()` = header deltas the blob lacks.
- **Retention** (`retention.rs`): fixed tables, `write_retention`/`write_expires` (fixed > override > schema default > untyped `author_or_admin`), `snapshot_retention` (role-class and `created.0` keep the fixed one), `keep_at_least`/`keep_at_most`/`body_keep` (at most beats at least; the purge floor `ts + ROLE_KEEP` beats both), `delete_levels`.
- **Delete keys** (`keys.rs`): the `Secrets` trait (dedup, and the public delete keys: admin, author-chain write, thing write); `delete_keys` lists every level the retention calls for (a missing key is `Build`); `DeleteKey { level, key }` in the header (validated as a point when decoded); `Prefix { salt, blind, expiry, keys }` is the prefix input; osis-label computes the commitments (`Prefix::for_delete_keys`: each key blinded by the blob's salt and the header's blind, one per level) and lays them out.
- **Builder** (`builder.rs`): `CommitBuilder` takes resolved per-aspect `AspectWrite`s (delta bytes encoded by the caller against `writer_ctx`, retention, expiry, schema, introduced chunks); sorts, hashes, builds the delete-key table and chunk list, validates (caller mistakes surface as `Build`), links lists above `CHUNK_THRESHOLD`, signs, checks every delta fits a blob alone. Header-list blobs: prefix expiry = max `expires` iff all aspects expire; the commit's level-2 commitment only.
- **Chunk trees** (`tree.rs`, `pub mod tree`): the only implementation, re-exported by osis-label under the same names: streaming `TreeWriter`/`TreeReader` over `TreeSink`/`LinkSource` (errors are commit's `Error`: `Corrupt` for a content hash or level, `TooLarge` beyond the caller's bound, `Missing` retry-safe), `write_tree`/`read_tree`, `HashSink`, `node_plaintext`/`parse_node`. The reader takes an output bound and follows spec/wire.md §6 tree reader bounds (a non-final chunk below `CHUNK_MIN` is bad input; at most `max / CHUNK_MIN + 1` chunks visited). The visit cap is what bounds work: repeated links are legal (identical chunks share a blob), so a tree of empty or repeated chunks would otherwise cost hundreds of thousands of fetches for no output. osis-label converts errors both ways (`From` impls in its `error.rs`, class kept).
- **Verify** (`verify.rs`): `verify_part` (delta hash under the thing's dedup secret, then osis-crdt decode against `delta_ctx`: own source = author node or `Commit(id)`, header range, kind) and `verify_blob` (signature, `validate`, every part).
- **Projection** (`project.rs`): `project(commit, readers: Fn(ai) -> K)`; class = (K, retention, expiry, aspect delete-key indices), so distinct delete bases split classes; size split greedy in aspect order with exact blob sizes (prefix, Padmé, tag). `prefix_inputs(header, parts)` is what any blob of the commit must carry (label's prefix-vs-header check, rewrites). `rewrite` keeps header and signature.

## Reference model (`core/test/crdt-model/`)
A small, slow, obviously-correct implementation of spec/crdt.md: `State` (fully resolved stamps), join, prune, read, the ops, un-merge, the wire encoder/decoder (own canonical CBOR subset), embeddings, diff. osis-crdt is tested against it. Property tests (`tests/props.rs`):
- convergence under random delivery orders, duplication and omitted prefixes: equal reads and equal encoded states;
- join laws on random states, within and across encodings (every association and order of three states);
- single writer vs a sequential model after every op;
- wire round trip and byte-identical re-encode; decoder never panics on random or mutated input;
- embeddings commute with join; a register delta joined into a text equals its embedding joined;
- forged copies (osis-crdt `tests_laws.rs` `forged_copies_*`: two writers share one source and clock, so their writes are same-stamp copies with differing payloads): join laws, impl join and read against the model's, a cached placement followed against a fresh one;
- diff (`read(join(S, diff(S, v))) == v`);
- expiry: random expiring commits stripped at random points, equal to join-then-strip; strip commutes with join and is idempotent; value-less registers embed like stripped valued ones;
- snapshots: round trip with frontiers, frontiers equal last counters, bootstrapping from a snapshot reads the same;
- the worked examples below;
- decoder strictness (`decoder_rejects_writer_rule_violations`, `decoder_rejects_rule_7_strict`): own-counter ranges and distinct counters (§2.3, every dot of a run, not only its first), foreign stamps in a writer's delta, nested register resets, maximal runs (re-derived from the decoded elements), a creation written as a `PosW`, more than the top-two position writes, overlapping or unmerged `FlagW` ranges, an empty text `Content` string, own (`Ci` 0) stamps in a snapshot, bare-anchor runs outside a snapshot, empty list element fragments (§4.2 Emptiness, at any depth), a `Slots` that pruning would change (slots empty, below the register's embedding, or not holding it; §7).

Undo (`undo.rs`, written from spec/crdt.md §4.6 and the §5 "Undo" lines alone, without reading osis-crdt's undo; its header lists the choices the spec leaves open). Differential in osis-crdt `tests_undo.rs`: random bases (absent, partial structs and enum payloads, after a few ops), writer 1's op, now and then writer 2's concurrent op stamped below d1, between d1 and the undo, or above the undo; undo, redo (undo of the undo) and undo of d1 again after the redo (exercising `restored`), each side its own deltas, reads compared; alone, undo and redo restore the read exactly, moves included (`exact_moves`); undo deltas with sibling keys also cross the wire byte-identically (`wire_alike`, `foreign_keys`). `Stats` counts the rules hit (a coverage test asserts each).

Decoder differential (osis-crdt `tests_decoder.rs`): random histories' writer deltas and snapshots, mutated at the byte level (byte nudged, overwritten by a small CBOR item, inserted, removed, tail cut) and structurally (decoded to a value tree, an int nudged or set to a boundary, an array element dropped, duplicated or swapped, a map entry dropped, re-encoded canonically, so mutants reach the semantic checks), decode alike (accept/reject, and equal fragments) in the model and the implementation. Value tags beyond set, tid and enum are not modeled (the implementation keeps unknown tags, spec/data-model.md §5): where the model rejects for a tag, the implementation must reject too or have decoded an unknown tag or a link. 48 cases per tier-1 run; a 2000-case release run is green.

Not modeled: the schema projection of the diff (the model's diff is untyped); un-merge by re-joining held bodies (the model removes writes in place, which the spec permits only where it gives the same result); links (copy and key order by bytes is tested in osis-crdt `links_compare_by_bytes_spec_3_3`). The model's decoder checks the canonical-form rules (below) its own way: prune stability by comparing the stamps `walk` yields before and after a prune, read depth by a walk (`Frag::read_depth`), commit-level stamps by `levels_at`.

## Structural diff: the reference script
The spec fixes only the identity rule and `read(join(S, diff)) == v`; osis-crdt's script (`ops.rs`, `seq_diff.rs`; the model's `diff.rs`) is, per encoding, recursive:
- register: write iff `read(S) != v` (bit-exact for floats) or S absent.
- bag: counter: `inc(v - read(S))` if different; max/min: reset + contribution if `v != read(S)` (a max cannot go down otherwise).
- struct: per field of `v`: recurse into `S.fields[id]`. Fields present in S but not in `v` are left alone (open structs: the writer only knows its fields; a typed `v` always has all the writer's fields). A field absent in S whose value in `v` equals the field's declared default produces no write (defaults are never materialized).
- enum: same case → recurse into the payload; different case → `set_case`.
- set: adds for values in `v` whose `view` matches no live element; removes for live, non-opaque elements whose `view` is not in `v` (one reset stamp). Large values compare by keyed content hash.
- map: keys (under `view`) only in `v` → put; non-opaque keys only in S → remove; both → recurse with the key's read (the join of its live entries) as S, writing into the lowest live entry.
- list: opaque elements are removed from consideration first and keep their place; LCS (Myers) over the rest with equality = `view(read(elem)) == item` (deep); unmatched old elements and new items are then **paired in order** while both remain and recursed into (a changed entry is an edit, not delete+insert); leftover old → delete (element reset), leftover new → insert after the preceding matched/paired element.
- text: Myers diff over chars → deletes and inserts (no move detection). Equal strings → no writes.
- absent S: everything is a creation; composites with no content get an explicit `W`.

## Canonical form decisions
One rule throughout: what the decoder accepts re-encodes and re-prunes to itself, so a delta has one byte form and carries nothing its own join would drop.
- **Prune-stable deltas** (§3.3 rules 5, 7): a carried write its own resets prune (a register `[0, [R], S, v]` with R below S, a child or `W` below the delta's reset, a keyed map record under its dot's key-erased reset) is bad input, not "accepted, dropped at join". A dropped write is still a write for un-merge and frontiers (a snapshot carrying it under another author's reset would revive it when that author is revoked), so accepting it gives two meanings to one delta. Checked by pruning a copy and requiring no deaths (`codec::prune_stable`; a copy because prune also drops what is no write, an undelete's chars without their creation). A streamed page is checked an element at a time (a map dot's records together; copying whole pages raises the stream's peak in `stream_memory_big_map` from about 45 to 83 MB) under the effective reset of its path (`stream::reset_at`), the previous page's last map dot carried into the next (`prune_page`; `map_dot_prunes_across_pages_spec_3_3`), so streaming and the whole-delta oracle agree.
- **Read depth, not a fragment nesting cap** (§3.3 rule 7): a fragment that would read deeper than 64 with every write live is rejected; the count follows `Value::depth` (struct, map, list +1; enum, set +2; map keys one below the map). A plain nesting cap lets a state read as a value no osis decoder accepts. Writers check the same count before resolving an op (`batch::out_of_profile`: a case step counts 2, set elements and list items one below the position). The count bounds the decoder's recursion across pages (every page level adds one); inside one blob the CBOR depth does.
- **Set/bag element value of the dot's source** (rule 7): only the element's creation writes the value register, so its stamp has the dot's source (a writer's delta stamp, or the embedded write itself, §7). Not the dot's own counter: a writer's element `k` holds a value at the delta stamp `lo`.
- **Commit-level writes at the delta stamp** (§2.3, rule 7): every reset, `W`, register value, case write, element reset and flag of a writer's delta, not only `FlagW`; the other counters of `[lo, hi)` belong to creations and position writes.
- **Links compare by bytes** in copy order and map key order (rule 2): `Value`'s order compares links by content hash, so `opt_value_cmp` compares encodings whenever either side holds a link.
- **Enum case ids at most 2^63 - 1** (spec/data-model.md §5): every other integer is i64 and `Value::uint` saturates, so a larger case would be written as `i64::MAX`.

## Text size
Benchmark `core/test/crdt-model/src/bin/text_bench.rs`: Kleppmann's automerge-paper trace (259,778 single-character edits, final text 104,852 bytes, 182k elements of which 77k deleted), one writer, net effect per commit, encoded as a foreign node's snapshot. Target 1.5–3x the plain text. The table was measured before the §4.5 rule "omit a created-and-removed element only once nothing anchors at it" (which `text_bench` follows) and not re-measured; the trace is not in the repo. The synthetic typist of osis-bench gives 2.89x and 6.73x under the rule.

| edits per commit | commits | commit table | runs | flag writes | snapshot | ratio |
|---|---|---|---|---|---|---|
| 1 | 259,778 | 2.47 MB | 6,288 | 77,463 | 4.64 MB | 44x |
| 10 | 25,931 | 243 KB | 6,062 | 12,721 | 687 KB | 6.6x |
| 100 | 2,598 | 24 KB | 6,000 | 5,431 | 331 KB | 3.2x |

Content is 105 KB and run records about 150 KB (6,000 runs at 25 bytes, the floor for this trace). The rest scales with commits (about 9 bytes of commit table plus 4 of run segment each) and deleting commits (about 8 bytes). Per-write timestamps are the design, so the client rule is one commit per editing pause, never per keystroke: at a 2 s cadence (about 10 edits) about 7x, at 20 s about 3x. Sizes in a foreign snapshot: a run about 20 bytes plus content, a segment about 4, a deleted range about 7, a commit table entry about 9. Tombstones in a run-compressed snapshot: a deleted element 3-4 bytes, a bare anchor about one byte per run; a state grows with the edit runs ever made, resets included.

What buys the size: deleted elements carry no content on the wire (182k → 6k runs), the per-delta commit table with bare indices (1–3 bytes per foreign stamp instead of 10), delta-coded table entries, runs spanning commits via segments, the shared delta stamp.

Accepted (spec/requirements.md, Scale): about 13 bytes per commit forever, so clients commit per editing pause. Stability-based GC (drop per-commit stamps once every writer acknowledged) would need every writer's frontier and stall on offline nodes, which the requirements forbid ("whether others are alive is never a protocol condition").

## Worked examples
Dots `a1`, `b3` (source letter, counter); stamps `(t, dot)`. Tests in `core/test/crdt-model/tests/props.rs` cite these.
- **Typing**: a at t=1 types `FOOBAR`: run `[1, 6, [0, [[0, 6]]], "FOOBAR", [], []]`. F=a1→HEAD, O₁=a2→a1, O₂=a3→a2, B=a4→a3, A=a5→a4, R=a6→a5.
- **Concurrent inserts at one anchor**: b at t=2 inserts `x` after O₂ (`[1, 1, [[1,3], [[0, 1]]], "x", [], []]`, sources `[a]`); c at t=3 inserts `y` after O₂. Children of O₂: y, x, B → FOOyxBAR.
- **Move with a concurrent insert**: from FOOBAR, b at t=2 inserts x after O₂ (x=b1→a3); a at t=3 moves FOO to the end: roots [F], pred HEAD, outside [B]. Writes B→HEAD (3,a7), F→R (3,a8). Read: BARFOOx.
- **Range with several roots**: abc built by inserting c, b, a at HEAD (t=1..3). Move `ab` after c (t=4): a→c, b→a. Read: cab.
- **Concurrent moves of one element**: from `abc`, a→c at t=5 and a→b at t=4. Read: bca; nothing duplicated.
- **Cycle**: from `acb` (a=a1→HEAD, c=a2→a1, b=a3→a2), B at t=5 moves a after b: c→HEAD (5,b1), a→b (5,b2); C at t=4 moves b after a: b→a (4,c1). Cycle a→b→a: b's edge (4) is oldest, b falls to prev (→c). Read: cba. Adjacent swaps do not cycle, since the mover re-anchors the outside successor to pred.
- **Reset against a newer insert**: from `abc` (t=1), A replaces with `xyz` at t=5 while B inserts `q` after b at t=6. a, b, c become bare anchors at END; q survives. Read: `xyzq` in either order. An insert at t=3 is dropped. `remove_aspect` at t=5 instead: absent until q arrives, then `q`.
- **Move displaces a concurrent insert**: from `abcd`, B at t=5 moves b to the end: c→a (5,b1), b→d (5,b2); C at t=4 inserts x after a. Children of a: c (5) before x (4). Read: `acdbx`; C intended `axcdb`. A move by position register cannot avoid rewriting the successor's anchor.
- **Delete vs move**: b deleted at t=4, moved after c at t=5. Read: ac; a later insert anchored at b appears after c.
- **Unknown anchor**: x arrives before FOOBAR: hidden until it arrives, even if FOOBAR was reset meanwhile.
