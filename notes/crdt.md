# CRDTs and commits: rationale
> Summary: Why spec/crdt.md and spec/commits.md look the way they do: the one conflict rule, Tess's decisions, design choices with reasons by area (stamps, join and death, writing, removal and hidden writes, map entries, sets and enums, sequences), known anomalies, rejected alternatives, how osis-crdt and osis-commit are built, the reference model `core/test/crdt-model/` and its tests, text size measurements, worked examples (cited by tests), research pointers.

Principle: **one conflict rule: every state element is a write carrying a stamp and its author's dot, later wins, and removal is a reset** (Tess's decisions). The state is the join of the writes held, so every read is a function of the valid writes held, in any arrival order and whatever is copied, stripped or un-merged.

Property (notes/test-design.md): what osis-crdt computes (join, read, wire, strip, un-merge) equals the reference model's, whose join is lawful; the property `tests_model::crdt_equals_model_plain` (and `_large`) checks it.

The spec states the rules; this note gives their reasons and how the code is built. Module docs (`//!`) of each file named below describe that file; they are not repeated here.

## Tess's decisions
- One conflict rule everywhere: every state element carries a timestamp and an author dot, later wins, removal is a reset. No causal contexts, no multi-value register.
- Collection elements are identified by creation dot; a removal resets the observed dots, so an add the remover never saw survives. Tombstones carry no content (no fingerprint): a map removal names its key only in role-class aspects, whose keys are public ids.
- **Removal is final** ("if something is deleted it stays deleted, no recreation as a side-effect of editing"): a nested write newer than an entry's or list element's removal stays hidden until a reset sweeps it (spec/crdt.md §1, §5.6 Live, §5.7 Live).
- **A gone write has no effect on the read (Tess)** (spec/crdt.md §4.7): an expired or purged delta's writes, every kind, are removed from each held body and the state is the join of what is left, at every node, body held or not. What it replaced shows again where held (delete the newest message: the previous one shows; a purged clear or delete brings content back); others' writes nested in a record it created read as at a node that never held it (a reaction goes with its disappearing message); what anchors at its sequence elements sits at their virtual anchors. Rejected: keeping a value-less leftover that still wins "later wins" (its effect comes from the body's structure, which a node missing the body lacks, so reads depended on arrival order for good); verifiable fetchable leftovers (wire, stores and kept structure against Deletion's no-fingerprint). Accepted: an offline edit inside an entry someone else deleted is dropped without notice, as is a `put` on an existing key (it writes into the entry); a writer on a stale view reads its own write until the removal arrives. Undo of a removal re-adds with a fresh dot. A delta's fragment alone shows nothing of a write into another's entry, so the engine finds links by `Fragment::values` (`relink_field`) and history rows by `Fragment::read_written`.
- A plain `set` diffs structurally; an explicit replace resets.
- Every composite merges recursively down to leaf registers; enum cases never merge with each other.
- The movable text/list CRDT ships in the MVP, as good as fuzzing and testing make it.
- Apps see plain values and listeners, no CRDT details. A lost concurrent write looks like any LWW loss.
- Authenticated malicious writers are out of scope (gaming the HLC to win LWW is not a concern).
- No tombstone compaction: worse merging after long separation is acceptable, discarding edits is not.
- Purge-by per delta, keep bounds per thing setting (spec/commits.md §5), purge per commit without batching, expiry (§6).
- Undo is per actor by default, plus an API listing every change in scope from which an admin may undo others'.
- Accepted: a node receiving a multi-aspect commit after one delta was purged applies the rest, so it may briefly see an aspect combination no author produced.
- The commit floor (Implementation (`osis-commit`)) is fine for editing workloads; revisit only if huge commit volumes appear.

## Design choices and why

### Stamps and identity
- **Second session** (spec/crdt.md §2.1): an expired ephemeral commit is forgotten with its counters; under a session of its own it leaves no gap a snapshot frontier could not pass.
- **Every state element carries its dot**, so un-merge and revoke frontiers are uniform. **No commit DAG**: causality is intra-aspect only, tids may dangle.
- **Stamps.** The HLC tiebreak lives in the dot's source, which works for commit-form dots too (the commit ID is unknown before signing). Commit-level writes share one delta stamp: 3-6 bytes saved per write and most intra-commit ordering questions gone; a delta still consumes at least one counter so frontiers cover every commit. `>=` survival lets a replace and the embeddings put content at the reset's own stamp.
- **Second dot form** (commit ID, index): unlinkable, and collision-free when several nodes sign with one key (per-node counters under a shared key would let any holder reuse another's dot and knock out its edit). Its cost falls only on such commits: runs do not continue across commits, one 32-byte `Sources` entry per foreign commit, revoke frontiers list commits.
- **`Sources` and encoding IDs live in the delta**, not the header: a delta is self-contained (projection, purge rewrite and hashing need no header) and its order rule is defined per delta; "first appearance across the commit" would be circular over several deltas. Cost: a source repeated per delta of a multi-aspect commit.
- **Derived sources** give the register → text embedding one identity per character without a third dot form. Kept although the string → text upgrade is rare: with reset-only embedding an old app's string save concurrent with a newer text edit would read as the edit alone; with embedded characters it reads as the string plus the edit, placed.

### Join, death and un-merge
- **Why join is a lattice**: the union of write sets with per-register maximum is a join-semilattice, and prune is a closure operator commuting with it (a write a reset drops would be dropped by that reset after any later join). **Encoding slots**: keeping the register as its own slot makes a position's state a product of lattices, so the laws hold across encodings; cost, in a `string` → `text` upgrade the last register write is stored twice until a reset.
- **Presence stamp**: only `W` is stored and the rest computed, so expiry can lower presence. `W` is always encoded; omitting it under a greater inner stamp would break un-merge.
- **Expiry and purge are un-merge, not a strip of the state.** Removing a write does not commute with join (what it pruned is back only from a body), so a node removes gone writes from each body before it joins (`Fragment::remove_gone`) and rebuilds the aspect; never in place. A snapshot without an expiry carries no write of an expiring delta, so it covers neither that delta nor what only it superseded: those bodies stay until T, and read again after.
- **Death of a write** (spec/crdt.md §4.8) is per write, not per delta: one surviving character must not keep a paragraph's deleted text alive under "no history", and a long-lived text must stay compactable under "30 days after replaced". Dropping a body is always possible locally (snapshot the aspect, drop), so purge on replace never needs another node.
- **Un-merge is defined by the held set** (§4.6): a node that merged a later-revoked author's writes and one that never applied them must read the same, so it is never an edit of the joined state: every flip, drop, strip and re-arrival is `apply::rebuild`.
- **Records with no write go**, in every collection (spec/crdt.md §4.2): a sequence record whose writes a reset pruned places exactly like a virtual anchor (§6.1), so dropping it changes no read or placement (`pruned_commit_leaves_nothing_spec_4_2`, `reset_drops_old_records_spec_4_2`, `replaces_keep_state_flat_spec_4_2`). A rebuild settled above a body's `ts` so reads no older body (`settled_above`). Rejected: keeping write-less records as bare anchors (a virtual anchor places a later insert the same; the records grew without bound under replaces).

### Writing
- **Diff takes the writer's view**: without it an old writer's save of a `set<struct>` removes every element a newer writer extended and adds a stripped copy. The diff algorithm is not normative, only "kept elements keep their dot".
- **`put_new` (`Op::Put`)** (rule: spec/crdt.md §5.6 Ops): used by may-grant grants' `secrets.0` puts and chunk repair. A repair is a plain write with a fresh stamp: it overrides a concurrent unseen edit and can bring back a map entry whose removal it has not seen, so it is limited to positions whose chunks are gone and rate-limited (notes/engine-paged.md, Freed links and repair). A repair via listeners must be a deterministic function of state, else two nodes ping-pong.

### Removal and hidden writes
- **A removal covers the adds the remover saw** (rule: spec/crdt.md §5.5; the writer's header-only ranges: `header_only_parts`). Why ranges: a removal must hide the tid alike whoever removes it, also where an add is held as a header only. Tids only: a header-only part cannot be named by dot (the counter is in the body), so the record names the value, and only a public id may sit in a tombstone; an app value's add held as a header only survives its removal, within the requirement. Hidden, not pruned (`winners` leaves the element out, `Place::Gone`), so join never prunes by value and stays lawful under forged copies, strip and un-merge. Reads and set ops skip hidden elements (`fragment::live_elems`); paging loads a tid's records through the value index when a delta names it (`PagedTouch::values`). Cost (`approx_bytes`, 1000 add/remove cycles of one tid): 219 KB without header-only parts, 477 KB with one per removal (the hidden element keeps its register until the set is reset). Rejected: a value-free range removal (hides the part's other members too); removal by value of every older add (drops unseen adds, spec/requirements.md Data model); prune by value in the join (joins stop commuting under copies of one dot under two values, or a removal pruned before the element arrives).
- **Map tombstones live until the map is reset**, because an older nested write may still arrive and must lose (and a newer one stay hidden). Same-key entries are not merged: the dots are different authors' identities, and joining at read time gives the same value with no rewrite.
- **Removal keeps entry creations whose own dot stays** (`remove_writes`): an entry left with only its `created` stays, and a `Slots` position is edited in place (re-joining would prune them), so a later join gives the stamp to the entry where another body holds content; dropping it made `created` depend on arrival order. A keyed record's creation counts toward `written` (§4.3): a map of such shells is present and reads empty.
- **Hidden writes go by a sweep, not in the lattice** (what is swept: spec/sync-compaction.md §1, Sweep). `Engine::snapshot` first commits the resets (`Fragment::sweep`, the engine's `apply::copies::reflected`), `MAX_DELTA_BARE` content-less elements per commit, until none is left (a commit taking nothing is an error, never a loop). A live record is judged as it reads, with its key-erased record (`Map::record_frag`), a key with several records record by record. Not swept, as something can still show them: a record lacking its creation whose delta is not reflected (a re-grant brings an invalid one back); a creation not live for want of a value (a valued write may arrive); a non-current enum case's payload (a case write stamped between reset and payload write shows it; it dies at the next case write); role-class aspects; memory commits. Writer-side only, so no model twin; `sweep_laws` checks a stale view's sweep changes no read at a node holding everything. Rejected: in the lattice (a record's reset is pruned by a parent reset, so order-dependent); a snapshot omitting a non-live entry's content (not dead, not covered, bytes still held); creation stamps from headers (a node may never hold the header). Cost: a lookup per record lacking its creation (`waits::sweep_counts_hidden_records_spec_sync_7`), past the cap a walk per `MAX_DELTA_BARE` (`sweep_is_bounded_and_finishes_spec_sync_7`, `waits::sweep_past_the_bare_cap_spec_sync_7`); a sweep's removal stays when the first remover turns out invalid, and its reset is a write, so a collection reset meanwhile reads empty, not absent.
- **Values as read** (`Fragment::each_read_value`, the engine's reference index): what `read` shows, never the writes a read hides that `each_value` names as written. A join changes them only within `Fragment::reach`/`reach_after` of the delta (their docs give the rule; invariant `tests_model::reach_holds_the_change`, over every history the generators make; the engine dates deaths by it, `Killed::note`), with value removals read from the copies as joined (`osis_crdt::Held`). A paged map's or set's join first loads every record of each key or reference-holding value whose read it may move (`PagedTouch::values`, `Fragment::dot_values`), else a same-key record on an unloaded page is outside the reach.

### Map entries
- **A map entry record is identified by (dot, key)** (spec/crdt.md §5.6). Removals are keyed only in role-class aspects, so a `secrets.0` removal's target (and role) is read from the delta alone; elsewhere an app map key is user content and must not outlive the entry (spec/requirements.md Deletion; receivers refuse a keyed reset there, osis-commit's `check_entry_keys`). Writers pick the form by `Writer::keyed_removals`; the differential harnesses mix both (odd writers keyed). Rejected: dot-only identity (a node that dropped the creation would not know what a removal removed, so a `secrets.0` removal's validity would depend on the bodies held, and an equivocated creation key would give different roles at different nodes). The key never decides another part of a copy (spec/crdt.md §4.1).
  - **The records of a dot are one entry** (§5.6, `state::prune_dot`): a keyed reset reaching only its own record is order-dependent across a forged second key. Each write sits in one record (`Fragment::without`, `Fragment::restrict`), not by `winners`: it leaves out a `prev` position and a text creation under a delete, which a record must keep, and "wins here" changes as writes arrive. `filter_by` matches records by dot whatever the key (else an inner write under the lesser outer key read as nothing); `state::fit_embedding` makes a slot's copy of a register write the embedding of its winning copy, copies told by stamp, not dot (`slot_copies_of_the_register_write_are_told_by_stamp_spec_7`). crdt-model states the rule independently (`writes::writes`, `death::key`). `tests_laws::entry_copies` checks laws, model, expiry and un-merge on random forged copies of one entry (`slot_embedding_sits_with_its_register_write_spec_7`, `slot_copy_of_the_register_write_is_its_embedding_spec_7` the smallest).
  - A dot may hold several keyed records, though honest writers give each entry one key: a valid snapshot's forged copy under another key joins beside the delta's. So no reader rule limits a dot to one key; a per-dot key at join would lose each write's own key, which expiry needs (`tests_life::one_dot_under_two_keys_by_join_spec_5_6`). Cost: a dot with two records with content clones and joins them at each `prune_dot`, O(entry) per join touching it: rare (expired co-writers, snapshot copies before T).
- **Writes into a key follow what they touch** (rule: spec/crdt.md §5.6 Ops; `ops::key_writes` here and in the model). Why: removing one record (by a node that saw only it) takes exactly what that remover saw plus edits into it: another record's deleted element stays deleted, an overwritten value stays overwritten, an insert made after the conflict survives in the other records; and the sweep may judge record by record. Undo joins a commit's records of one key and undoes them once, routed the same way (else a re-created element would come back twice).
  - A creation copied into several records keeps one dot, so a delta repeats a counter there. Readers never check counters for distinctness (§2.3): a repeated counter is a forged copy, which joins handle (`forged_copies_*`).
  - Cost: on a key with n live records (kept until the key is removed or its map replaced; no cap), writes to the whole key, new elements and later edits into them are written n times; edits into an element one record created go there only.
  - Paging: an op into a key never runs on a sequence held in part: `pages::walk` reaches one position per record, `pages::ensure_path` loads everything paged below each, `attach_ops` attaches only an op reaching one position (else the state loads whole); `Seq::holds` notes a stray miss.
  - Rejected: writing into the lowest live record (removing that record brought back an element deleted there); a creation into one chosen record (an insert's survival of a partial removal would depend on dot order); folding a conflicted key into one fresh entry (fresh dots lose concurrent edits and typing).

### Sets, bags and enums
- **Bag contributions are set elements**, so undo of an increment is an idempotent element reset. No bag GC: dropping non-extreme max/min elements or folding contributions changes the read under a later reset landing between the folded stamps, and under expiry of the extreme. Bag reads are order-independent (exact int sums clamped, float sums in dot order, IEEE totalOrder).
- **Enum payloads filed per case**: a writer editing case A's payload while another switched to B must not flip the value back to A with a half-written payload; the newer payload write stays hidden until a reset (spec/requirements.md, Data model).
- **No set/bag tombstone GC** (uniform with maps). A tombstone keeps a removal final against a late copy of the add from any node that held the add without the removal (spec/requirements.md, Ephemeral data: nothing is kept until everyone has seen it); it keeps no forgotten name (a reset carries no value, notes/engine-retention-purge.md). Cost: about 10 bytes per removal forever, against spec/requirements.md Scale (issues/zero-growth.md); the diff emits no resets, so most sets never see one. If a workload needs it: run-compressed tombstone records (contiguous dots, one reset stamp), a divergence-free wire change. Rejected: received-range GC (sound, but needs a `W` fold for presence and a "dot in received ranges with no record is tombstoned" join rule in every node, makes snapshots differ between nodes, and cannot be opt-in "only when big"); `replace` as compaction (fresh dots lose concurrent removes); dropping a tombstone under a covering snapshot (the node that would revive the element holds the add as a body of its own, which such a snapshot does not cover; only a causal context in the read would answer it, still growing per session).

### Sequences
- **Text deletes by flag, lists by element reset.** Text content is immutable, so a flag plus undelete-with-char restores it exactly. A list element's content is a mergeable fragment: a flag would leave a newer nested write in local state but off the wire (deleted elements carry no content), so nodes bootstrapped from a snapshot would read an undelete differently; as a reset the write survives hidden, snapshots carry it, and undo re-inserts with a fresh dot. Delete is never a move to a trash position, which would drag concurrent inserts along.
  - **No creation prunes a flag** (§5.7): a flag below its creation is beaten and held, as `prev` is. Why: a forged `Derived` creation above a delete expires whole (§4.7 Embedded character); had it pruned the delete, strip before and after the join differed (`tests_review::text_flag_below_creation_loses_spec_5_7`). A text range record lies on one side of its flag (`seq::flag_cut`; the decoder cuts there too). Rejected: sparing lower flags only for `Derived` creations (a carve-out); a flag always beating an embedded creation (a reset between them would show the char only where the node kept it). Cost: none for honest writers (a writer folds its commit's own flags into the creation; anyone else's delete is stamped above the creation it saw); over skewed-clock test histories about 2% of flags are beaten, +0.2% snapshot bytes, about 6 B each. A read shows the undelete's own char, so whether a node still holds a deleted creation's char never changes a read.
- **A sequence's order comes from valid writes only** (Tess; §4.6 Seq elements): dropping an invalid body equals never having received it (`tests_seq::valid_order`). Accepted: a valid element anchored at an invalid one lands at the end. Rejected: keeping an invalid creation as a hidden anchor (an ex-writer kept steering the order); hiding an element whose anchor is unknown (a node that dropped a record would read differently from one that never had it).
- **Moves and cycles.** A move writes `pos` only for range roots: rewriting interior elements changes their sibling keys and reorders concurrent neighbours. The creation write is kept apart from the top-2 positions (runs need it, and it gives text content a stamp). Cycle breaking demotes the oldest move in the cycle, the one the other movers did not know about, keeping the newest intention; falling back twice needs three or more concurrent moves over the same elements, and END keeps content visible instead of hiding it.
- **Sibling keys** (Tess: exact undo): an undo's restoring position write carries the restored write's sibling key, so the element sorts among its old anchor's children where it was (`eab`, move `a`, undo gives `eab`, not `aeb`), and a concurrent insert there newer than the old write stays before it, as if the move never happened. The key is immutable payload of one write: join stays top-2 by stamp, the order a function of state; cycle breaking uses write stamps. Cost: a writer's delta may carry a commit-table entry per commit its keys name (the only foreign stamps a writer's delta holds, rule 7). Rejected: anchoring the restore at the end of the preceding sibling's subtree (no wire change, but the state is not restored).
- **Small reasons behind spec/crdt.md rules**: a commit's creations and position writes take fresh counters because the counter is an element's identity and orders siblings one commit writes. An element created and removed in one commit but still named stays (re-anchoring what names it would reorder it among the anchor's other children, stamps not changing); a text one stays as its creation without its char, since a flag of the commit at the delta stamp would lie below the creation and lose to it. `pos` top-2 is a lattice: top-2 of a union is the top-2 of the union of top-2s. Every anchor cycle holds a move edge (only moves rewrite positions), and END breaks every cycle, so demotion terminates.

## Known anomalies
All convergent.
- A move displaces a concurrent insert made right after the moved range's predecessor (Worked examples).
- An enum payload edit concurrent with a case change stays hidden.
- A field write concurrent with a reset of its struct or the aspect (`replace`, `remove_aspect`) shows that field alone: positions have no creation, so the later write wins. Inside a map entry or list element the removal wins instead (removal is final).
- While a text aspect is in transition, every save by an old LWW app wipes concurrent older text edits.
- A changed list entry the diff does not pair becomes delete and insert, losing concurrent edits to it; apps editing list entries concurrently use path ops.
- Un-merge restores what the invalid author's writes superseded only from retained bodies; a node that dropped them under a cover that fell reads them absent until a peer re-supplies the body.
- Undo of a reset re-adds content with fresh dots, so a later undo of an original element does not cancel its restored copy (only out-of-order selective undo sees this). Bag undo re-adds contributions without a reset, so concurrent newer contributions survive; other encodings' reset undo is a `replace` and wipes concurrent newer writes inside the value.
- Undo chains on one position: a register or position undo writes back the value before the undone commit while the position reads what the undone write wrote, whoever wrote it now. So undo steps back through repeated edits and redo forward, with no judgment of which commits are in effect; a later edit to an equal value by anyone is overwritten. Enum case writes are undone as resets.
- Differing copies of one write (forged; snapshots vouch, spec/permissions.md §5.2) join by the copy order of spec/crdt.md §4.1: the attacker picks the outcome and every holder agrees, which is all a writer gets by writing a new value anyway; the original's body stays held (no snapshot holding another copy of a live write covers it, spec/commits.md §5), so removing the forger gives it back.

## Rejected
- A wall-clock staleness horizon for tombstones: nodes separated longer diverge or lose edits; any independent reset-style compaction has the same problem.
- LWW-element sets and maps: the tombstone names a value hash or key and cannot be dropped without stability information.
- OR-set/OR-map with causal contexts: dot addressing's add-wins semantics, plus a version vector in every state and delta.
- Stability-based GC of tombstones or per-commit stamps: needs every writer's frontier and stalls on offline nodes ("whether others are alive is never a protocol condition").
- A terminal reset or retire marker in the encoding lattice: representation changes are transitions to new IDs (notes/versioning.md).
- Destructive join of unrelated encodings (later encoding wins, the loser a reset): not associative with eager embedding (`(register ⊔ counter) ⊔ text` ends a counter, `register ⊔ (counter ⊔ text)` a text).
- Attributing state elements through commit headers instead of dots (zero bytes in state, history lookup at revocation): not uniform.
- Columnar or bit-packed encodings (20-30% gain, not worth leaving CBOR); dropping stamps from deletions (changes undo; deletions are not the dominant cost).

## Implementation (`osis-crdt`)
- **Structures**: `Fragment` enum, one struct per encoding (`fragment.rs`), crate-private fields; set and bag elements `BTreeMap<Dot, _>`, map records `BTreeMap<Eid, _>` (`Eid { dot, key }`, `Key` ordered by canonical bytes; a dot's records contiguous, the keyless one first, `Map::of_dot`), struct fields and enum payloads `BTreeMap<u64, _>`. Sequences: `seq.rs` (hooks the generic code calls), `seq_span.rs`, `seq_wire.rs`, `seq_ops.rs`, `seq_diff.rs`, `linearize.rs`, `seq_lin.rs`, `seq_place.rs`. A text keeps deleted elements' chars locally (undo and paste read them); snapshots do not carry them, so a bootstrapped node's state differs only there.
- **Live** (`Map::is_live`, `seq::is_visible`; spec/crdt.md §5.6, §5.7 Live): everything that shows, places by index or diffs goes through these two.
- **Key index** (`Map.keys`: key -> keyed records carrying it, a superset; lookups check liveness, `Map::live_ids`; not part of `Eq`), kept by `join_entries`, `Map::new` and delta `overlay`. Index paths and `Remove` of a map key still scan or clone.
- **Range records** (`seq_span.rs`; a snapshot run `[Dot, 2^12, [], [], [], []]` is 8 bytes, spec/requirements.md Scale): one record for consecutive uniform elements of one source, so a dead element (deleted, or kept by others' writes once its creation is gone: a late insert may still anchor at it, issues/seq-dead-records-grow.md) costs about what the wire holds, not a record each. Creations may differ in `ts` (never falling) and anchor (`SeqElem::each`: arrays shared by the pieces of one record; an element by element appender's chain costs 8 B, two writers taking turns 32 B per element), and a range holds no content. Decode (a page's records among themselves) and `Fragment::compact` make maximal ranges (`coalesce`), only of records next to each other in dot order, so a range never spans another record's key; the engine compacts a state it holds whole on a rebuild, never a paged one in place (records stay within their pages). Join cuts an incoming record at the state's record starts after splitting state ranges at its bounds, splits a chain a reset falls inside (`chain_cut`), and joins two ranges whole only when their creations agree and neither holds content (`whole_merge`), else element by element; joins never coalesce, so `Seq` equality is per element (`elems_eq`, `SeqElem`'s `eq` over the arrays). Linearization splits a range after elements something anchors at and before elements anchored elsewhere than at the one before (`linearize::nodes`: nodes stay creation chains). The wire carries each element's segment and run, so encoding pushes a range whose creations differ per element. Deltas from ops and undo are expanded per element where convenient (`expand`); a received state never is. Tests coalesce every model state into ranges (`testutil::frag`); `value_less_ranges_equal_model_spec_5_7` builds chains and interleaved appends by hand, and the differential's `Nested` mode opens half its histories with one writer appending alone (`gen::history_led`).
- **Slots**: every prune of a `Slots` re-embeds the register slot into each other slot, so a received `Slots` lacking the embedding converges with one built by join. A join leaving the register and effective reset as they are and writing no slot's `W` (`kept_reset`: the common case, sequence writes) joins only the delta's slots (`join_slots_kept`), so untouched slots and the text slot's placement cache stay. A lone non-register slot is chosen without scanning. `DeltaBuilder` layers a sequence op over the `Slots` slot of its encoding when that slot carries the position's reset (`seq_slot`). Both decoders judge rule 7's "pruning would change it" with deleted chars dropped and return the pruned position, so a bootstrapped node holds an embedded deleted char again (returning the unpruned form would let one writer make peers' states unencodable).
- **Deaths are computed, not reported** (`winners.rs`; which writes win: spec/crdt.md §4.8). **A write's identity is never its payload**: nothing copy order decides is in a `Won` (a set element's register sits at `In` whatever it holds, a value removal is `Place::Gone(dot)`, a register write counts as the reset its stamp implies, `Winners::minus`). Which removals hide an element is read from the copies as they join (each holder's copy in the write's row of `osis_crdt::Held`, core/crdt/src/held.rs), never per body, and never from the joined state: a reset pruning the write there would hide its removal, dating its death later the more a node holds (spec/commits.md §5). Invariant on `Held::dies`: a write that dies in a join is beaten or pruned by a held write. **An embedded char's creation is its register write** (§7): `collect`, the one walk behind `winners`, `held_writes` and `carried`, names a text record `(Derived(d), i)`'s creation as `(Value, (ts, d))` at the text's position, so a copy cut by copy order, or beaten in one record while another keeps one, is no death. Two rules make that hold without per-char bookkeeping:
  - The embedding's creations beat on their records only writes stamped with the register write's own stamp. A position or flag write on a `Derived(d)` record stamped with dot `d` is bad input (spec/crdt.md §3.3 rule 7); left in, it would be beaten by a creation no body need hold, and the state would depend on arrival order.
  - Judged alone (§4.8 When), a text copy of register write `s` is `s`, also in a text-only position (only forged snapshots carry one): it may date a forged history's writes earlier than the join prunes them, never later. Its superseded writes are read in the whole text (`Seq::embeds`: `footprint_of`, `touched_elems`).
  - Rejected: each embedded creation a write of its own (copies cut by copy order then die with no superseder, a `Corrupt` on an honest receive); position writes held apart from the creation (a seq state rewrite for a write no honest writer makes); a set element's write keyed by its reference (a forged copy with another value is a death with no superseder: the join fails for good).
  - `tests_winners` checks against a pairwise from-scratch definition. `Fragment::carried` (the same walk, counting) counts every write copy, beaten ones included, once per record of a map dot.
- **Interning**: `Source` is an `Arc<SourceKind>`; a stamp is `ts` + pointer + counter. Equality and order never depend on sharing; `Interner` dedupes per decode. Dot and source comparisons borrow: decoded deltas never share the state's source `Arc`s.
- **Join** (`state.rs`, `join_into`): equals union-then-prune (`tests_model`). An empty state takes the other side pruned.
- **Wire** (`wire.rs`, `codec.rs`, `stream.rs`): bytes are read and written in place, no `osis_base::Value` tree: `Enc` writes straight into the output (`cbor::put_*`); a decode checks each blob once against the CBOR profile (`cbor::check`; `CanonicalBytes` for pages) and walks `cbor::Item` views; only register values and map keys become `Value`s. Every element array and field map goes through `codec::Pager`, holding written bytes while they fit the page target, then cutting: about one page per open position plus links (a 10^5-key map's delta: 13 MB above the delta, against 129 MB for a whole encoder).
  - `cbor::check` keeps the tree decoder's verdicts (osis-base tests/cbor.rs asserts it at every decode); a blob is checked whole before any grammar rule or page fetch, so a profile violation is `Cbor` bad input first. `cbor::List` steps over checked items in one flat pass (`checked_len`): the recursive `Reader::item` walks each byte once per enclosing level.
  - Decode re-encodes and requires the input bytes (the `Pager` replays the input's pages, so a page cut differently is missing; `Enc` check mode, `Dec::checker`). `stream_delta`/`stream_snapshot` hand over the skeleton, then a `Piece::Page` per leaf page; `decode_delta` reassembles and prunes.
  - Checked once: `Checked` is made only by `Checked::verified`, in product code only by the engine's `apply::checked` (enforced by tools/policy.py); `stream_checked`, `decode_checked` read with `Deferred::order` (`tests_stream` requires equal pieces in equal order for every accepted input and mutant).
  - Oracles: the whole encoder is `codec::oracle::encode_*`; in this crate's tests every `encode_delta`/`encode_snapshot` also runs it into content-addressed sinks and requires the same root and pages (`oracle::twin`). The whole-delta decoder is `codec::oracle`; `tests_stream` mutates roots and pages and requires the same decisions.
  - Rule 1 quirk (list runs counted as if not closed by content size): the collecting pass cannot cut at `CHUNK_MAX`, since a run's content bytes depend on `Ci` indices from the `Commits` table it is building; so `Runs` defers the sources of a run's position and flag writes to the end of the uncut run in every mode (`Enc::defer`).
  - Root tables (`Sources`, `Commits`, `Frontiers`, `Absorbed`, `Facts`) page like element arrays (`Enc::put_table` through a `Pager`; `codec::table` reads either form, its pages under `LinkTree` and into `Dec::done` for the replay), so the root holds at most a page target per table besides its fragment, whatever the commits a snapshot names; a `Commits` entry carries its `Src` (`dwall` from the same `Src`'s previous entry), so one session's commits page too. A reader decodes the tables whole first (interned sources, a `CommitEntry` per commit), stable indices for every page; so a partial read (covering at some positions) still holds the whole tables, a multiple of their bytes (about 50 MB at 10^6 commits). Rejected for now: per-page tables (each leaf page carrying its own `Sources`/`Commits`, so a point read costs its path and no table), about 10-30% larger text and list snapshots and a rewrite of rule 1, the stream check and `PageIndex`; worth it only if covering memory at that scale matters. `root_tables_page_and_the_root_stays_bounded_spec_8` builds the shape (each write by a commit of its own) at small parameters.
  - Sequences: runs over `Enc::sorted`, built incrementally (`Runs`: one open run, so a streamed sequence re-encodes across pages); a segment's `Ci` is the creation stamp's commit index (`Enc::commit_of`); closed runs flush after each record, so pages are put in nested-page order. The `MAX_DELTA_BARE` count is taken across pages before allocating, and per-element loops run only over a writer's own counters (bounded by rule 7).
- **Paging**: `PageParams` (format: 64 KiB target, 16/256 KiB cuts, 512 fanout) come from the `PageSink`/`PageSource`; tests shrink them, `PageParams::set_test` every node plug's (`PageParams::wire`) on one thread (`tests_paged::deep_link_tree_compacts_syncs_and_reads_spec_crdt_8`). `osis_base::PageCutter` cuts; link pages use the tree-node rule (`codec::Levels`), walked depth first and iteratively (`codec::walk_tree`), each page checked by `LinkTree`, which sync's fetch walk shares (notes/decode-bounds.md, Link trees); a state read under other `PageParams` than it was written with fails it (cache a test world per params). A page's place is its path of link indices (`PageAt`, `Wanted::wants`). No collection size limit: a fixed depth would make a large collection (about 10 MB for a writer grinding link hashes, several GB honestly) unsnapshottable, and a limit on a merged state cannot be enforced (writers each under it pass it jointly). Field maps page like element arrays (`page_array`), so no delta outgrows a blob (`CommitBuilder::max_blob` shrinks it for tests) and a commit is limited only by its header lists (`MAX_LIST_BYTES`): a bulk `replace` of a huge map is one commit. Decode records each position's pages after its items (`Dec::done`), the put order, so equal page plaintexts replay to their own links; each put is its own blob (`LocalPages` derives a distinct ID per put).
- **Page items** (`MAX_PAGE_ITEMS` 2^21, spec/crdt.md §8; `codec::check_items`/`check_root`): counted at most one per blob byte, so blobs up to 2 MiB skip the walk; relay-only deltas never page (`PageParams::UNPAGED`). Why 2^21: an honest page is under `CHUNK_MAX` bytes plus its last element, and the largest elements are a map entry (key up to 128 KiB plus a `Slots` fragment: a 128 KiB register plus up to 9 slots each at most `PAGE_TARGET` inline, about 720 KiB), a list run (`Content` under `CHUNK_MAX`, about 33 items per element of position, flag and segment writes) and a text run (up to about 36 items per element; measured 16 for a text moved twice and half deleted). At `MAX_RUN` 2^16 one run would pass 2^21, hence `MAX_RUN` 2^12: the worst page is then about 256 K + 983 K + 135 K = 1.4 x 2^20 items. 2^20 would fail only the many-slot `Slots` corner (about 1.38 M). The root's tables are not counted (each at most `PAGE_TARGET` inline); their pages are, as any page.
- **Ops** (`ops.rs`, `delta.rs`): `diff`/`create`/`replace` match the model write for write under a `View`. A set element is one register holding the whole value (`set_elem`; both decoders reject another fragment there); a link fits only a register position. `DeltaBuilder` resolves ops against state ⊔ delta-so-far, borrowing the state where the delta has no writes and copying the position where it has (`current`; a map key joins only its entries, `key_lookup`, so a nested write into a large inner map copies nothing). A whole map's or set's `diff` finds stored keys and live elements by lookup: O(n log n) (`tests_ops::whole_collection_diff_is_linear_spec_9`, `ops::visited_probe`).
  - At a sequence position the delta already wrote, an op resolves against the state's sequence layered under the delta's records (`seq::Layered`, read through `SeqRead`, cache plan/follow through `Recs`); under a delta reset or where the cache cannot follow, it copies. The view is kept (`Seen`, by path) for the next op there while `prune(acc) ⊔ d` equals the overlay at the op's elements (`seq::Foot`), so N ops on one text cost O(N · (√n + log n)). A debug check compares the kept view with what `current` would copy.
  - Ops see state joined with the delta slot by slot (`slot`): a delta writing a register at P and then a field of P resolves the field against the state's struct. `overlay` (net effect, §4.5; sequences `seq_ops::overlay`) then sets `W` if the collection would be left with no write (one-by-one ops would have left it present).
- **Seq ops**: `Op::Insert/Delete/Move` by visible index (`Move.to` indexes the sequence without the range, like the model). `Op::Paste { dots, at }`: cut/paste is client behaviour, no protocol concept (`cut_dots`; `paste_out_of_clipboard_order_fails_spec_5_7`). `Op::InsertAfter { anchor, items }` and `Op::DeleteDots { dots }` serve a caller keeping the placement apart: write for write the index ops'.
  - `Op::Edit { base, new }` (what `diff_values` emits for sequences): `seq_diff::edit` aligns `base` to the current read at base's own indices when the read has base's length and equals it over the changed middle widened by `CTX` = 32 elements a side, a stretch unique in base (else in periodic text a concurrent shift lands the edit a period off); otherwise by exact LCS over the whole read. A list element changed on both sides is edited in place only when it is the one unmatched element of its gap on each side. `window`/`edit_window` give a sequence held in part that stretch (`PlaceMisses::whole`).
  - Delete flags the whole range, hidden elements included (over `MAX_DELTA_BARE` refused: split across commits); its undo undeletes only what showed before. Move reads only the range's rows plus the `outside` rows hanging from it (`Placement::hanging`), and `to` skips by rank: O(range + √n). Each flag-only element of a range record becomes its own chained root, so move/insert equal the model's write for write whatever the record split (`move_unplaced_record_converges_spec_5_7`).
  - Undo: insert → flag/element reset; text delete → undelete with the pre-commit char where that state showed it; list delete → re-insert after the old element with a fresh dot; undelete → delete; position writes → old anchors and sibling keys with fresh counters in the old stamps' order, only while `cur` has the undone write's anchor and key; nested list content through `undo.rs`.
  - Diff (`seq_diff.rs`): Myers after trimming the common prefix and suffix, giving up past 512 edits (the middle is then replaced: any script is valid, §9).
- **Linearization** (`linearize.rs`): anchors are found by binary search after trying the node just before in dot order (where typing anchors). Cycles: rounds of walks (from every node, then from the victims), each node once per round; a walk demotes the cycle it closes. Linear on adversarial graphs.
- **Placement cache** (`seq_lin::Lin`, behind a `OnceLock<Arc<_>>`, not part of `Eq`), per `Seq` of `LIN_MIN` = 64 records or more (1 under `cfg(test)`, so the model differential checks it). Blocks of about √n rows (4 to 256 when built, split above twice that, `take` merges one below half), a depth shift per block outside the `Arc`, a row-dot → block map in sorted `Arc` chunks; a copy clones only what it writes. `elems` is private, `elems_mut` drops the cache, `join_elems` plans each record before it joins and `Lin::follow` splices. The newest of a delta's runs and moves, above `Lin::newest`, goes right after its anchor without reading the children. A new element the delta also moves (an edit then a move of what it typed, in one commit) goes in at its creation and then moves like any element (`new_element_moved_in_its_delta_follows_spec_6_1`): every fallback costs a paged text a whole load to lay its stored placement out anew, so ordinary edits must not take one. A list `read` keeps no per-row value cache (a list element's read can be any size). Fallbacks: the module doc; the work cap makes hostile deltas cost about a whole pass (`hostile_moves_join_bounded_spec_6`, `hostile_cuts_join_bounded_spec_6`). `testutil::check_lin` compares the cache with a whole pass after every join.
- **Held in part** (`seq_place.rs`, `SeqPlace`; notes/engine-paged.md, Paged state): a read returns whole once its misses load, never short (`seq_lin::Partial`, shared by copies; `Covered` wraps record lookups, also under `Layered`). Presence needs a visible placed node, `is_empty` any placed node, `inner_max`/`written` every record (`all`). Stored rows keep no char (`fill_chars` only on a whole load; `Vis::chars` takes it from the record). `dry_follow` follows a copy over copies of the touched records (`Over`) so the node loads misses before the join. `Set` loads a sequence whole. `Fragment::visible_range` and `read_elems` read by index from the cache or stored dots. What remains: issues/crdt-seq-linearization-cost.md.
- **Undo** (`undo.rs`): §4.6 states only constraints; receivers never re-derive an undo, so this is one writer's choice. Cancel per dot over the original delta, walked with the current state and `before`. A position absent before the commit, under one present before, is reset (`remove_aspect`'s delta) when it reads now what the undone delta joined into `before` reads; else the per-write rules run. That reset also drops later concurrent writes into it, as the register rule overwrites a later equal edit; the engine runs it on the whole state when it reaches a paged collection held in part (`undo_in`: others' entries sit on untouched pages). A register absent before inside a present struct stays (no nested register reset). A key removed with several entries returns as one entry of their joined value (separate re-adds would tie on the undo stamp). A nested edit under a map key is undone against the join of the key's live entries before (`entry_frag`). A pre-commit value not fitting the view (two schemas on one AK) fails (`Mismatch`). `touch.rs` gives the positions undo reads (`touches`, `present_at`; notes/engine-retention-history.md Undo); `undo::restores` judges §4.6's restores, and the property tests check an undo restoring nothing copies nothing back (`Writer::copied` empty).
- **Un-merge** (`lifecycle.rs`): `remove_writes(pred)` on held bodies, never on the joined state; the same function strips a snapshot's copies.
- **Other modules**: `access.rs` (`Map::entries()`, `Map::live(k)`, `Fragment::at(path)`; `present()` stops at the first presence-counting write); `paging.rs` (the node's paged-state hooks: `elem_range`, `touched_elems`, `Step`/`Paths`, `wrap`, `reduced`, `touched_paths`); `walk.rs` (`walk::walk`, a `Visit` never expanding range records, behind `writes`, `live_writes`, `holds_owned` and lifecycle's `holds_stamp`, `origin_dots`, `keyed_resets`); `shape.rs` (`has_reset`, `is_plain_struct`, `is_put_only_map`). `Entry::created` is `(ts, entry dot)`, implied when decoding a writer's own creations, carried as `Ci` by snapshots.
- **Left near-parallel on purpose** (merging came out line-neutral): set element vs map entry join and overlay (state.rs `join_elems`/`join_entries`, delta.rs `overlay_elems`/map arm; the entry's creation prune sits between content prune and join); the mutating walk `remove_writes`.
- **Costs counted**: a received insert, delete or move into a text of 30 and 300 runs follows the cached placement, no whole pass (`small_joins_follow_cached_placement_spec_6`, `seq_lin::probe`); its placement work grows about with the square root of the runs, per record a move takes. A small change inside a huge value is O(change) in the engine (osis-engine `scale::`, notes/test-scale.md Scale checks).
- **Tests**: the history generators (random, honest, bulk, twins: `crdt_model::gen::history`; hostile sequence writes: `gen::hostile`) live in crdt-model, shared with osis-engine's forged-copies property. `tests_model::crdt_equals_model_plain` (module doc lists its modes and checks) runs `Plain` (100 fixed seeds, about 8 CPU-s); `crdt_equals_model_large` runs `Small` (1000) or `Large` (10,000, `OSIS_FULL=1`); `OSIS_CRDT_START`/`OSIS_CRDT_SEEDS` replay one seed at any size. Twins carry each delta as the snapshot wire does (one with no wire form is dropped as bad input: a forger's bytes are all a node sees); `part_judges_as_whole` is a piece law with no model counterpart. Beside it: every rule 7 run rejection, the worked examples as `*_spec_example` tests, `fuzz_seq::tests::random_scripts_replay_plain_spec_5_7`, the placement cache against a whole pass (`cached_placement_follows_moves_plain_spec_6_2`, about 80% of move joins followed; `seq_lin::probe` is a per-thread work counter, as default tests never time wall clock; `tests_seq::snapshot_then_edit`); held in part: `snapshot_edits_follow_cache_spec_6`, `index_ops_on_partial_placement_match_whole_spec_5_7`, `set_on_partial_text_matches_whole_spec_5_7`, `set_after_op_on_partial_matches_whole_spec_5_7`. Fuzz: `seq_follow`, `seq_ops` (`fuzz_seq.rs`). By hand: osis-bench `budget_text_snapshot_ratio` (synthetic typist or the automerge-paper trace via `OSIS_TEXT_TRACE`; figures in Text size).

## Implementation (`osis-commit`)
Each module's doc names its spec sections; only what they do not say is here.
- **Commit floor**: a minimal content commit (header plus one register delta) is about 300 bytes once nonce, framing, tag and padding count, plus a 57-byte wrap per sync ID and a prefix of about 35 bytes.
- **Header** (`header.rs`): a list that goes by link keeps its root in `links` and is empty until `resolve` reads the chunk tree. Encoded and read in place (`Header::encode_into`, `Header::read`); `decode` checks structure and canonical bytes (re-encode equals input), `decode_stored` reads a header this node verified without the re-encode and delete-key point checks; `validate` (`validate.rs`) needs resolved lists. A higher format version is `UnknownVersion` (Parked) before the arity check.
- **Header lists are read by shape** (`read_*` over `osis_base::Reader`, inline and linked; `tree::parse_node`; `frontier_ids` straight into sorted IDs): worst honest shape about 5 B of memory per list byte (purge at 21 B per item), where a whole-value `decode` costs up to about 56 B per byte. Items in strictly ascending bytes, checked in `Header::decode`, so a repeated chunk link is refused at its first repeat.
- **Linked lists** (`lists.rs`): `write_list`/`read_list` adapt `BlobSink`/`BlobSource` to the tree module with `ChunkParams::FORMAT`; own traits because crdt's `PageSink` computes the link hash from plaintext, which a tree node's hash is not, and takes no prefix. `MAX_LIST_BYTES` = 64 MiB (spec/wire.md §2: a resolved header is in memory); `MemoryBlobs` for tests.
- **Stored forms skip the re-encode**: `CommitBlob`'s and `Header`'s `decode_stored`, `read_part`/`read_part_whole` (`verify.rs`) read bytes this node checked in full. `record_blob.rs` and `thing_list.rs` need no re-encode check at all (`Item::parse` accepts canonical bytes only).
- **Retention** (`retention.rs`): `write_purge_by`/`write_expires` (fixed > override > schema default > untyped `admin`), `purge_keep_until` (`ts + ROLE_KEEP`); what a history keeps is the engine's door (notes/engine-retention-history.md). Delete-key commitments are osis-blob's (`Prefix::for_delete_keys`, spec/crypto.md §7). `CommitBuilder` (caller mistakes surface as `Build`) links lists above `CHUNK_THRESHOLD`; header-list blobs carry the commit's `expires` and its level-2 commitment only.
- **Chunk trees** (`tree.rs`; osis-blob's `Error` is commit's): the visit cap (`max / CHUNK_MIN + 1` chunks, spec/wire.md §6) is what bounds work: repeated links are legal (identical chunks share a blob), so a tree of empty or repeated chunks would otherwise cost hundreds of thousands of fetches for no output.

## Reference model (`core/test/crdt-model/`)
A small, slow, obviously-correct implementation of spec/crdt.md: `State` (fully resolved stamps), join, prune, read, the ops, un-merge, the wire encoder/decoder (own canonical CBOR subset), embeddings, diff; `death.rs` (a write's identity, winning writes, supersedes as "dead in the join with it", holds by dot, covers by canonical bytes) and `origins.rs` (dot to commit by the headers' forms and ranges), stated over `writes::writes` and join. osis-crdt is tested against it; held-model takes its values from it. Property tests (`tests/props.rs`): convergence under random delivery orders, duplication and omitted prefixes (equal reads and encoded states); join laws within and across encodings (every association and order of three states); a single writer against a sequential model; wire round trip, byte-identical re-encode, no decoder panic on random or mutated input; embeddings commute with join; diff (`read(join(S, diff(S, v))) == v`); death and covering (a state holds and covers each of its writes, a write another supersedes alone is dead in any join holding both); expiry (strip equals join-then-strip, commutes with join, idempotent); snapshots (frontiers equal last counters, a bootstrap reads the same); the worked examples below; decoder strictness (`decoder_rejects_writer_rule_violations`, `decoder_rejects_rule_7_strict`: the rule 7 and §2.3 rejections one by one). Forged copies (two writers sharing one source and clock) are osis-crdt's `tests_laws.rs` `forged_copies_*` (join laws with `part_at`, a followed placement against a fresh one) and, against the model, `tests_model`'s twins.

Decoder differential (osis-crdt `tests_decoder.rs`): random histories' writer deltas and snapshots, mutated at the byte level and structurally (decoded to a value tree, edited, re-encoded canonically, so mutants reach the semantic checks), decode alike in the model and the implementation (`decoder_matches_model_plain_spec_3_3`: 64 seeds, 8 mutations per commit, 40 with `OSIS_SLOW`). Value tags beyond set, tid and enum are not modeled (the implementation keeps unknown tags, spec/data-model.md §5): where the model rejects for a tag, the implementation must reject too or have decoded an unknown tag or a link.

Not modeled: the schema projection of the diff (the model's diff is untyped); links (copy and key order by bytes: osis-crdt `links_compare_by_bytes_spec_3_3`). The model's decoder checks the canonical-form rules its own way: prune stability by comparing the stamps `walk` yields before and after a prune, read depth by a walk (`Frag::read_depth`), commit-level stamps by `levels_at`.

## Structural diff: the reference script
The spec fixes only the identity rule and `read(join(S, diff)) == v` (§9); osis-crdt's script (`ops.rs`, `seq_diff.rs`; the model's `diff.rs`) is, per encoding, recursive:
- register: write iff `read(S) != v` (bit-exact for floats) or S absent.
- bag: counter: `inc(v - read(S))` if different; max/min: reset + contribution if `v != read(S)` (a max cannot go down otherwise).
- struct: per field of `v`, recurse (fields only in S are left alone: open structs).
- enum: same case → recurse into the payload; different case → `Op::Set` of the new value.
- set: adds for values in `v` whose `view` matches no live element; removes for live, non-opaque elements whose `view` is not in `v` (one reset stamp).
- map: keys only in `v` → put; non-opaque keys only in S → remove; both → recurse with the key's read as S, the writes going in by `key_writes` (§5.6 Ops).
- list: opaque elements keep their place; LCS (Myers) over the rest with deep equality on `view`; unmatched old elements and new items are **paired in order** while both remain and recursed into (a changed entry is an edit, not delete+insert); leftover old → delete, leftover new → insert after the preceding matched/paired element.
- text: Myers diff over chars → deletes and inserts (no move detection).
- absent S: everything is a creation; composites with no content get an explicit `W`.

## Canonical form decisions
One rule throughout: what the decoder accepts re-encodes and re-prunes to itself, so a delta has one byte form and carries nothing its own join would drop.
- **Prune-stable deltas** (§3.3 rules 5, 7): a carried write its own resets prune is bad input, not "accepted, dropped at join": a dropped write is still a write for un-merge and frontiers (a snapshot carrying it under another author's reset would revive it when that author is revoked), so one delta would have two meanings. Checked by pruning a copy and requiring every carried write copy to stay (`codec::prune_stable`, `Fragment::carried`; not `winners`, which leaves out carried `prev` writes and deleted text creations; not fragment equality: what prune drops that is no write has its own rule 7 line, `record_without_write_rejected_spec_3_3`; `write_copied_across_records_rejected_spec_3_3`). A streamed page is checked an element at a time (a map dot's records together; whole pages would raise `stream_memory_big_map`'s peak from 45 to 83 MB) under its path's effective reset (`stream::reset_at`), the last map dot carried into the next page (`prune_page`, `map_dot_prunes_across_pages_spec_3_3`). A creation implies its position write; where the top-2 leave it out, pruning drops only that implied copy (`implied_creation_pos_decodes_back_spec_3_3`).
- **Read depth, not a fragment nesting cap** (§3.3 rule 7): a plain nesting cap lets a state read as a value no osis decoder accepts. Writers check the same count before resolving an op (`delta::out_of_profile`). The count bounds the decoder's recursion across pages (every page level adds one); inside one blob the CBOR depth does.
- **Set/bag element value of the dot's source** (rule 7): not the dot's own counter, since a writer's element `k` holds a value at the delta stamp `lo`.
- **Commit-level writes at the delta stamp** (§2.3, rule 7): every reset, `W`, register value, case write, element reset and flag of a writer's delta, not only `FlagW`; the other counters of `[lo, hi)` belong to creations and position writes.
- **Links compare by bytes** in copy order and map key order (rule 2): `Value`'s order compares links by content hash, so `opt_value_cmp` compares encodings whenever either side holds a link.
- **Enum case ids at most 2^63 - 1** (spec/data-model.md §5): every other integer is i64 and `Value::uint` saturates, so a larger case would be written as `i64::MAX`.

## Text size
Benchmark `core/test/crdt-model/src/bin/text_bench.rs`: Kleppmann's automerge-paper trace (259,778 single-character edits, final text 104,852 bytes, 182k elements of which 77k deleted), one writer, net effect per commit, encoded as a foreign node's snapshot. Target 1.5-3x the plain text. The table does not apply the §4.5 rule "omit a created-and-removed element only once nothing anchors at it" (which `text_bench` follows); the trace is not in the repo, so the table is re-checked only by hand (`budget_text_snapshot_ratio` with `OSIS_TEXT_TRACE`). The synthetic typist of osis-bench gives 2.89x and 6.73x under the rule.

| edits per commit | commits | commit table | runs | flag writes | snapshot | ratio |
|---|---|---|---|---|---|---|
| 1 | 259,778 | 2.47 MB | 6,288 | 77,463 | 4.64 MB | 44x |
| 10 | 25,931 | 243 KB | 6,062 | 12,721 | 687 KB | 6.6x |
| 100 | 2,598 | 24 KB | 6,000 | 5,431 | 331 KB | 3.2x |

The commit table column leaves out each entry's `Src` byte (one per commit: about 2.73 MB, 269 KB, 27 KB).

Content is 105 KB and run records about 150 KB (6,000 runs at 25 bytes, the floor for this trace). The rest scales with commits (about 10 bytes of commit table plus 4 of run segment each) and deleting commits (about 8 bytes). Per-write timestamps are the design, so the client rule is one commit per editing pause, never per keystroke: at a 2 s cadence (about 10 edits) about 7x, at 20 s about 3x. In a foreign snapshot: a run about 20 bytes plus content, a segment about 4, a deleted range about 7, a commit table entry about 10; a deleted element in a run-compressed snapshot 3-4 bytes; a state grows with the edit runs made since the last reset.

What buys the size: deleted elements carry no content on the wire (182k → 6k runs), the per-delta commit table with bare indices (1-3 bytes per foreign stamp instead of 10), delta-coded table entries, runs spanning commits via segments, the shared delta stamp. Accepted (spec/requirements.md, Scale): about 14 bytes per commit forever, so clients commit per editing pause.

## Worked examples
Dots `a1`, `b3` (source letter, counter); stamps `(t, dot)`. Tests in `core/test/crdt-model/tests/props.rs` cite these.
- **Typing**: a at t=1 types `FOOBAR`: run `[1, 6, [0, [[0, 6]]], "FOOBAR", [], []]`. F=a1→HEAD, O₁=a2→a1, O₂=a3→a2, B=a4→a3, A=a5→a4, R=a6→a5.
- **Concurrent inserts at one anchor**: b at t=2 inserts `x` after O₂ (`[1, 1, [[1,3], [[0, 1]]], "x", [], []]`, sources `[a]`); c at t=3 inserts `y` after O₂. Children of O₂: y, x, B → FOOyxBAR.
- **Move with a concurrent insert**: from FOOBAR, b at t=2 inserts x after O₂ (x=b1→a3); a at t=3 moves FOO to the end: roots [F], pred HEAD, outside [B]. Writes B→HEAD (3,a7), F→R (3,a8). Read: BARFOOx.
- **Range with several roots**: abc built by inserting c, b, a at HEAD (t=1..3). Move `ab` after c (t=4): a→c, b→a. Read: cab.
- **Concurrent moves of one element**: from `abc`, a→c at t=5 and a→b at t=4. Read: bca; nothing duplicated.
- **Cycle**: from `acb` (a=a1→HEAD, c=a2→a1, b=a3→a2), B at t=5 moves a after b: c→HEAD (5,b1), a→b (5,b2); C at t=4 moves b after a: b→a (4,c1). Cycle a→b→a: b's edge (4) is oldest, b falls to prev (→c). Read: cba. Adjacent swaps do not cycle, since the mover re-anchors the outside successor to pred.
- **Reset against a newer insert**: from `abc` (t=1), A replaces with `xyz` at t=5 while B inserts `q` after b at t=6. a, b, c lose every write and go; q sits at b's virtual anchor on END. Read: `xyzq` in either order. An insert at t=3 is dropped. `remove_aspect` at t=5 instead: absent until q arrives, then `q`.
- **Move displaces a concurrent insert** (a known anomaly): from `abcd`, B at t=5 moves b to the end: c→a (5,b1), b→d (5,b2); C at t=4 inserts x after a. Children of a: c (5) before x (4). Read: `acdbx`; C intended `axcdb`. A move by position register cannot avoid rewriting the successor's anchor.
- **Delete vs move**: b deleted at t=4, moved after c at t=5. Read: ac; a later insert anchored at b appears after c.
- **Unknown anchor**: x (t=2) after O₂ arrives before FOOBAR: reads `x`, at O₂'s virtual place on END, until O₂ arrives. A reset of FOOBAR at t=5 prunes x; y (t=6) after O₂ survives it: `Zy`.

## Research
- Loro's movable list and movable tree: production implementations of Kleppmann 2020 "Moving Elements in List CRDTs" and of tree cycle handling.
- Eg-walker (Gentle & Kleppmann 2024): op-based, but its text representation and size ideas transfer.
- Kleppmann & Beresford, "A Conflict-Free Replicated JSON Datatype": nested composition, key removal vs concurrent nested edit.
- Kleppmann & Brattli, "Undo and redo support for replicated registers and sets": matches dot-cancel undo.
- Almeida, Shoker, Baquero, "Delta State Replicated Data Types": the delta-state framework; its causal contexts are not used here.
