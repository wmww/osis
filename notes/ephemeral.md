# Ephemeral data
> Summary: Design (proposal; owner direction of round 13 and two reviews) for ephemeral data: in-memory things and schema-declared aspects, an axis independent of sync, as much like ordinary data as possible. Local ephemeral writes cost about an in-memory structure today (about 5 us); the owner accepted "no disk I/O, well under a millisecond" for the unified design (issues/eph-unify.md). Synced ephemeral data is ordinary signed commits marked ephemeral, kept in memory instead of the store at nodes and hosts and carried by the normal sync machinery: it merges on reconnect, outlives contact with its author and is lost only when no node holds it. A value that should die with its author is an expiring write its author renews (`osis::KeepAlive`); `signal` aspects reach only currently connected devices and hold nothing. Every thing starts ephemeral and is persisted with its owner chain at its first durable write, keeping its tid; ephemeral placements are the core ephemeral aspect `placed.0~`, read with `group.0`. Covers the API delta, engine, wire, bounds, mechanism count, deletions, spec edits and a four-step plan (all four built); also kept: expiry and the all-nodes predicate. Tracking: issues/ephemeral-data.md.

## Owner direction (decided)
- Ephemeral = cheap and disposable, no never-touches-disk promise. Independent of sync: durable or ephemeral, local or synced. All of an app's state lives in osis; the UI drives and is driven by it.
- Like ordinary osis data in most ways; its history is "don't care" (neither purged nor kept). On one device it must be very cheap; some overhead is fine when synced, and anywhere when the alternative is special cases or API complexity. Reuse the ordinary commit, delta, validity, sync and host paths unless clearly worse.
- Both units: ephemeral things (creation record only in memory, same tid derivation and rights) and ephemeral aspects on durable things, declared in the schema. Flags `ephemeral` (a value) and `signal` (no lasting value).
- `create` takes no placement; group ops set groups (same batch for atomic create-and-place). Every thing starts ephemeral and is persisted at its first durable write together with its owner chain's creation records, keeping its tid. No persist call. A thing never given durable data vanishes when every node holding it forgets it. Ephemeral placements of ephemeral things approved.
- Synced ephemeral state is ordinary CRDT state held in memory by every holder: it survives while any holder keeps it, merges on reconnect (two people keep using a shared ephemeral window while one is offline; it merges when they reconnect), and a joiner gets it from any holder. A value that should die with its author is an expiring write its author renews (Values that live while their author is there).
- No exception to convergence: ephemeral state converges among the nodes holding it; author-tied values converge once every holder notices the departure (like expiry).

## Model
**Kinds of aspect.** The key decides, by its lifetime marker (spec/data-model.md §2): durable (none); `~` ephemeral (a value held in memory); `*` signal (an ephemeral write with no lasting value, delivered only to currently connected devices; anything a late joiner should see is ephemeral state, not a signal). The writer's key decides the path; merge needs no schema. Core aspects are durable, `placed.0~` aside (placements). Retention does not apply to ephemeral data; expiry does.

**Holders.** A node holds the ephemeral state of the things it writes or receives: every node syncing a label whose closure holds the thing, and that label's hosts, while they run. They keep it until they restart, stop syncing the label or lose read access. State is lost only when nobody keeps it; a restarted node gets it back by syncing.

**Ephemeral thing.** A thing whose creation record no durable commit holds at this node. Tid derivation, creation record and owner are as for any thing. `create(owner)` mints the record and keeps it in memory; nothing is written. Invariant: **the durable set is closed under owner**, so a durable thing never has an ephemeral owner.

**Persistence (promotion).** The first durable commit with a delta on an ephemeral thing T (a durable aspect of T, by any node that holds T's record and may write T) also carries `created.0` of T and of each ephemeral thing on T's owner chain, top down, and makes T's ephemeral placements durable (below). Same tid; ephemeral aspects stay ephemeral; ephemeral values never become durable: the app copies a draft's content into a durable aspect in the same batch (`set`). Reason: a durable write anchored at an ephemeral dot hides once nobody holds it, and a durable writer delta cannot carry foreign stamps. Two nodes persisting T concurrently both carry the same record (idempotent). An edge write on an ephemeral thing first persists it by its own content commit (role commits cannot carry `group.0`), then runs. A durable thing never becomes ephemeral again.

**Ephemeral placements.** `placed.0~` (of `group.0`'s type) is the one ephemeral core aspect (issues/eph-unify.md step 2; it replaced an ephemeral side of `group.0` joined at read): a group op (`place`, `unplace`, subgroup add or remove) whose item is ephemeral is a write into the group's `placed.0~`, held and synced like any ephemeral state, needing write on the group; raw writes of `placed.0~` are `Invalid`. `group.0` reads its durable state alone; `placed.0~` reads as the group its items and subgroups make (its adds carry no struct presence); the group index (`groups_of`, `groups.0`, `listed_in`) reads both, so the item shows in the group's members and in its `groups.0`, and the closure (spec/sync.md §3) includes it, so its ephemeral commits go under the group's labels. When the item persists, the persisting commit adds it durably (with the placement's expiry) and a reset removes it from `placed.0~`. An ephemeral thing can be a group of ephemeral items, a draft placed in a folder lands there at save, and nothing durable names a thing that never persisted. A group op on a durable item is a durable write and persists the group. Any later durable write of a durable thing converts its remaining ephemeral placements the same way, and a durable unplace also removes it from `placed.0~`. Side effects, all minor: an ephemeral `unplace` concurrent with the item's persistence loses to the durable add (add wins); a persisting node without write on the group cannot make that placement durable, so it stays ephemeral and a `PlacementNotPersisted` diagnostic names it (a writer of the group fixes it with `place`); a durable `group.0` naming an ephemeral tid (a raw path op) is a reference that may dangle.

**Rights and validity.** An ephemeral thing has no role-class aspects (writing one persists it), so a node's role on it is its role on a new thing owned by the nearest durable thing on its chain: the rule already used for things created in the same batch. Ephemeral writes need what the durable write would need; readers cannot write ephemeral data. Synced ephemeral commits are judged like compaction snapshots (spec/permissions.md §5.2: a part is valid iff its author could write the aspect at its `ts`, through the ordinary timeline), and un-merged like any commit on revocation.

**Reads and merge.** An aspect reads the join of its durable state and its ephemeral state (spec/crdt.md §4.1); normally one side is empty (both: `group.0`, or schemas that disagree; the join is defined). Own writes and every applied ephemeral commit join into the ephemeral state. `signal` aspects always read absent. Expiry follows spec/crdt.md §4.7. So ephemeral state converges among holders as any CRDT state does.

**Deletion.** `delete(T)` on an ephemeral thing writes the usual resets. A thing in no labeled closure is then freed at once (record, state, undo entries, the ephemeral things it owns; the tid reads unknown), so short-lived UI things cost nothing. A synced one keeps its record and tombstones while it is held, since dropping them would let an older copy revive the values.

## API delta (notes/api.md, applied with steps 1-2)
- `w.create(owner) -> Tid`; `Place`, `create_expiring` go (expiring placements stay `place_expiring`).
- Schema DSL: the key's marker is the lifetime, no flag: `aspect win:notes.0~: list<tid>;` `aspect doc:cursor.0~: map<tid, Cursor> [expires: 30s];` `aspect call:ring.0*: Ring;`. `AspectKey::lifetime()` reads it from any key, typed or untyped.
- Writes: unchanged calls. One `Write` may mix durable and ephemeral ops: validated as a whole, applied locally at once (one dispatch); the durable commit and the ephemeral commit travel separately, so a peer may see one without the other. `retention(..)` on an ephemeral write and any op but `set` on a signal aspect are `Invalid`. `commit()` returns `Committed { id: ChangeId, ts }`, `ChangeId = Commit(CommitId) | Ephemeral(EphemeralId)`; a batch with both halves is one change (one `ts`; revert of either reverts both).
- Watches: unchanged. Each signal reaches every `on_change` callback once (never coalesced, never in state; a `Watch` on a signal aspect stays `None`). `CommitInfo.id` becomes `ChangeId`; a remote ephemeral change names the ephemeral commit that carried it (its author, verifiable, notes/api.md Attribution).
- `created(t)`: `Stamp.commit: Option<CommitId>`, `None` while ephemeral (`ts`, `node`, `actor` from the creating batch or ephemeral commit, `received` from its arrival).
- Undo, redo, revert, query: own ephemeral batches of this session are changes (`CommitKind::Ephemeral`); ephemeral commits are transport, not listed. Thing and Group scopes cover durable aspects and ephemeral things; an ephemeral aspect of a durable thing (cursor, selection) is in scope only when named by `Scope::Aspects`, so document undo never steps through cursor moves. Remote ephemeral changes and own ones from before a restart have no log: revert is `Invalid`. `Config.ephemeral_history` (default 16 MiB) bounds the log; older batches are `NotUndoable{Compacted}`.
- Gone: `send_signal`, `on_signal`, `on_signal_in`, `Target`, `SignalEvent`, `Signal<T>`/`SignalKey`. Device targeting is dropped (no user; a value can name a device). A group-wide signal goes on the group thing.
- Errors: none new; `UnknownThing` for a vanished tid. Diagnostics: `EphemeralRefused { label }` (a cap was hit, below), `PlacementNotPersisted { item, group }`. `NotSynced` stays only for a durable placement into a closure with no label.
- Text sessions on an ephemeral `text` aspect apply each edit at once (no idle commit).

## Local engine
- Module `osis-engine` `ephemeral/`, owned by `Engine` beside `Core`; under the handle's one lock. `Eph { session: Session(node, nonce) per open, next counter per aspect, things: Tid → record, aspects: (Tid, Ak) → joined state, expiry classes, own writes, held parts; remote: unsent own deltas per aspect, held commits; log, timers }`.
- Local stamps: `ts` from the engine's HLC; dots of source `Session(node, nonce)` (spec/crdt.md §2.1; issues/eph-unify.md step 1: replaced a `Commit(random session)` source and the snapshot `Authors` array) with counters per aspect, contiguous from 1 in each session (`Eph::next`, taken when a write applies: a refused batch takes none; kept for the whole session, freed things included, since a freed thing can come back from a holder). Node-form counters are never used (they must survive restarts). Attribution is in the dot: a session names its node, so receivers keep a part's writes only under the commit author's sessions (`own_session`), and a node's earlier sessions are its own with no list. Ops resolve against the read view with the same `osis_crdt` code as durable writes. A local ephemeral write is an HLC tick, an op, a join and a watch event: no store transaction, signature, hash or encryption. This is the whole cost for a thing in no labeled closure.
- `Write` splits ops by key: durable ops into the `Mutation` (plus chain records and placement conversions of the ephemeral things it persists), ephemeral ops into an `EphBatch`. The mutation commits first; if it fails, nothing applies. Then the batch applies (cannot fail after validation) and the engine queues `Event::Ephemeral { changes, info, signals }` (replaces `Event::Signal`), dispatched like commit events. A batch touching a thing in a labeled closure also adds its deltas to `unsent`.
- Ephemeral commits (step 3, as built: Step 3 as built below): built with the ordinary commit builder and verified with the ordinary commit checks, but held in the ephemeral module's own in-memory records (`ephemeral/remote.rs` `Remote::held`), not the store or `Core`'s indexes: validity through the snapshot rule's timeline call, un-merge by rebuilding the aspect, sync through node-sync's ephemeral lane. Their deltas join the ephemeral state, not the durable one.
- Reads (`read.rs`): join the durable state with the ephemeral state when both exist; synthetic aspects and `groups_of` include ephemeral data; `created` reports records without a durable commit. Perm: an ephemeral thing's role through its nearest durable owner.
- Undo: the log keeps per own batch its deltas and the undo buffer of the positions it touched, captured at write time (register values, removed content, presence at the "absent before" position): O(change). Inverse writes follow spec/crdt.md §4.6 against the current state and apply as a new batch (sent like any). Past `ephemeral_history` the oldest entries go.
- Restart: everything ephemeral is gone locally and the next open draws a new session; syncing brings back what holders kept, own old-session writes included (as others' state). Writes made before a thing is in a labeled closure (after a restart, before its placement is back) go out when it enters one (`note_entered`): the writes without expiry in one class, each expiry class apart with its writes alone (a value-less record of another write in an expiring part strips that write at its expiry); expiring ones were once left out for good (churn seed 203).

## Synced ephemeral data: ordinary commits in memory
- **Ephemeral commit.** A commit with the header marker `ephemeral` (plain or relay-only; the sync engine puts signal deltas in their own commits, so a commit is one class), of snapshot form (spec/crdt.md §8: foreign stamps allowed, empty counter ranges), no `created.0` part: each part carries beside its delta the creation records of the ephemeral things it is on or its `placed.0~` delta places, with their ephemeral chains (wire `Part := [ai, di, delta, [creation*]]`, issues/eph-unify.md step 3; self-certifying, so unsigned and per blob: a projection carries only its parts' records), signed, encrypted, projected and wrapped as any commit. The engine builds them from `unsent` per (actor, expiry) and node-sync places each under the labels whose closure holds its things, when the label's connections can take it (Coalescing below: while one is in flight, new batches join into the next), and when a thing with ephemeral state enters a labeled closure (the node's own writes on it). Every node keeps ephemeral commits and their blobs in memory only; they are never persisted, never in bundles.
- **At hosts.** The blob prefix gets a class field: durable, `ephemeral` or `relay` (signals), from the commit's marker (projection keeps classes apart as it does retention classes, spec/sync.md §3). A host keeps ephemeral entries (blob, wrap, stamp, log event, tombstone) in memory only, under a per-label byte cap; past it, upload of that class is refused with the ordinary cap code. A restart loses them. Everything else is the ordinary path: upload by stamp, cursor sync, range reconciliation, subscriptions pushing new entries, expiry, delete keys.
- **Convergence and reconnect.** Ordinary (spec/sync.md §6): an ephemeral body a node holds is must-hold at the labels whose closure holds its things until covered; writers upload what a label lacks, readers relay stamped entries, so a holder bridging two hosts or a co-reader peer serving its own label carries ephemeral state across. The owner's example: both nodes keep writing while apart; on reconnect each uploads its new ephemeral commits and receives the other's; both read the merge. A joiner or restarted node gets the state by its ordinary first sync from any host or peer that holds it; if every host restarted, holders upload again. No poke, digest or join protocol.
- **Compaction.** Own covers (below, Own covers): only an author compacts, its own commits into one cover per actor, when they cost more than twice it; a host's cap refusal triggers nothing. History being "don't care", no keep bounds apply.
- **Signals.** A signal write is a delta in an ephemeral commit marked relay-only (the sync engine puts signal deltas in their own commits; prefix class `relay`). A host (or co-reader peer serving the label) accepts it by stamp like any upload, pushes it to the label's current subscribers and holds nothing: no entry, log event, tombstone or expiry, so it never reaches a later sync. A node verifies it like any commit, delivers each signal part to callbacks once and holds nothing (no state, no body, never relayed or re-uploaded). The same signal arriving over two hosts is delivered once: a node remembers delivered relay-only commit IDs until their `ts` is `MAX_DRIFT` old, and drops relay-only commits older than that (their only replay window). The blob's prefix expires at `ts + MAX_DRIFT`: hosts refuse it after, push each blob ID once until then, and rate-limit relays per label; receivers drop a blob seen before unopened. Within that hour a signal can arrive late (a delayed push), and a restarted node can see one again if a replayer uploads it to a host that forgot it (restarted, or past its bound).
- **Own stamps.** An own entry is stamped per upload under that connection's head write key (`eph_upload`). Refused 9 (built offline or before reading a rotation), or with no write key there while this node writes the label, it waits in `Lane::restamp` with the key tried and goes again once the connection's keys give another (`eph_restamp`, each step); dropped with one `EphemeralRefused` report per label once `role_on` is below Write (demoted, removed). An own entry under a label this node only reads (a thing also in a group it reads) is never sent there and never parked or reported. Covers and split covers take the same path (their replacements go back to `waiting` on the refusal and ride the re-upload). Waiting deletes are signed when made: every delete send (plain or carried) signs it again under the connection's current head keys (`eph_resign`; the level's delete-key signature does not depend on the head), else a cover carrying one made before a rotation was refused 9 under every later key and never landed (`ephemeral::cover_across_unread_rotation_lands_*`). A plain delete refused 9 (sent before the node read a rotation; the reply's head is taken) waits in `Lane::redelete` with the key tried and goes again once the connection's keys give another (`eph_redelete`, each step); rate limited (4), again at the periodic pass (`eph_retry`); any other code ends it. A plain delete whose label key the connection lacks waits there too (`Redo::Head(None)`: keys not established yet or roles uncovered come back) while the node keeps the role it is signed for (`eph_may_delete`: admin for the head delete key, else writer), else it is dropped; one waiting for a cover is not carried by it then (it would refuse the cover) and goes alone once the cover is held. Deletes are made by a level's delete key first (`eph_delete_item`): its label key stays with an admin demoted to writer. Other holders that are writers also delete what a cover absorbs, so a test of one node's delete needs the others to hold none (`ephemeral_bytes: 0`). Tests: `ephemeral::offline_entry_across_rotation_restamped_*`, `ephemeral::demoted_writer_entry_stops_*`, `ephemeral::delete_across_unread_rotation_retried_*`.
- **Trace.** `OSIS_EPH_TRACE=all` (or a hex prefix of a commit or blob ID) prints one stderr line per lane event of that commit on every node: arrival and its routing decision (drops with their reason, ingest outcome, kept), uploads and their statuses, peer wants, fetches, refetches, waits ending, forgets, deletes (`eph_trace`; add a line where a new decision is made). A blob not opened yet shows `commit -` and only `all` or its blob prefix matches it. Needs `-- --nocapture`.
- **Validity, ordering, replay**: ordinary commit rules (chains, parking past `MAX_DRIFT`, idempotent apply). A replayed old ephemeral commit only re-adds writes its stamps already lose to, or that holders still have.

## Expiry
- Expiry is death by timer (spec/crdt.md §4.8): the values die at T and the body follows, whatever the deltas' keep bounds. "Keep at least until T" is a retention bound (spec/commits.md §5), a different thing.
- Covers disappearing messages (write-based timer in core; read-based timers and earlier deletion are app writes; core expiry is the hard upper bound and lets a host wipe them unattended) and buffered events (a list aspect with a one-hour default). Cheaper than keep-at-most 0: nothing has to be deleted by hand, and the host does it unattended.
- Leak accepted by owner: a host learns which entries expire and when.
- Not provided: host-enforced minimum retention (legal hold). Keep-at-least binds honest nodes; a host deletes whatever a delete key or its label delete key tells it to.
- **Ephemeral expiry vanishes whole** (coordinator decision, round 13, option (a) of the deleted issue eph-churn-oracle-seeds; spec/crdt.md §4.7 Ephemeral data): at T an ephemeral delta's writes all go, resets and removals included, at every node and for its author, as if never applied; an expiring removal stops removing at T. Durable data keeps its value-less records. Why: value-less leftovers lived only in the state of nodes that held the commit at T (a rebuild, a late joiner or the author's own copy differed), and ephemeral data has no carrier for them (only an author covers, never expiring writes, and nobody may re-serve the body after T). Built: `EphAspect::own` holds the own writes per expiry class, joined apart; a class goes at its T, a held part at its T, and the aspect is rebuilt (`rebuild_aspect`: live own classes joined with the valid held parts). **Invariant**: two nodes holding the same ephemeral commits read the same, whatever expired when (`EphAspect` doc). Superseded writes (below) vanish the same way. A later own write repeating a record of an expired own write (an undo's re-add) has those dots taken out before it is joined or sent (`expired` ranges). Consequence: a write into an entry an expiring write created outlives that entry (the entry's record repeats the key, and a map record lives by its content, spec/crdt.md §5.6), so a writer gives such a write an expiry no later than T. Undo of an expired batch writes its inverse as usual (a removal re-added with a fresh dot, a register untouched since its write is not the winner): convergent. An undo copies back no expired content (`undo_expiring` strips it from the pre-state and reruns until none is copied: one strip let a `Set`'s undo restore a shadowed older entry's expired value at the key, churn seed 79, `undo_of_set_past_expiry_restores_no_shadowed_entry_spec_crdt_4_6`). Test `ephemeral::expired_removal_vanishes_everywhere_spec_crdt_4_7`.
- **Expiry never waits for a Tick** (durable too): a Tick comes late (`MIN_WAKE_MS` throttle, a suspended process; in the node test net an offline node gets no events at all), so the osis handle runs `SyncEngine::expire_due` before every call under its lock: when `Engine::timers_due` (in-memory: `Core::timer_floor`, a lower bound of the earliest durable timer, and the ephemeral timer map) it runs the Tick's engine part (live-drop snapshots, `tick`, `tick_ephemeral`). Pushed change events still come with the Tick (up to `MIN_WAKE_MS` late) or the next call: a subscriber's last value can show past T until then. Tests reading through the engine directly call `expire_due` first (`random_churn_run` checks every step that no value is read at or past its expiry; issue eph-expired-value-read-again, seed 7134: node 1 offline past T).
- On ephemeral writes expiry runs in memory (typing indicators: `expires_in(5 s).set(true)`); a value that lives while its author is there is one renewed by its author (below).
- Nothing is kept "until every receiver has seen it": the receiver set is open and nodes die. What must survive every holder forgetting it (restarts) is durable state: the inbox pattern (receiver-owned list, senders append, owner deletes, expiry as backstop) or a list with expiry.

## The all-nodes predicate
"All nodes a thing syncs to" is a state predicate computable at trusted nodes, never a protocol condition. Per label: the nodes with a valid chain that published `node.0` under the thing's label (not "every node of every holder", which needs rosters readers never see).
- Recency: each node places an expiring `seen.0` heartbeat under each label it tracks (spec/permissions.md §4); the live one's value is its last sync of L, absent means unknown. `seen.0` is one aspect of the node thing, so its joined read is "last seen anywhere"; the per-label answer comes from the sync layer's record of which heartbeat commits arrived under L, not from the aspect. (A `map<label ID, timestamp>` would give aspect semantics but leave a value-less entry record per expired heartbeat forever.) The heartbeat also carries `stranded`, the one signal a device that cannot open a label's current epoch, or cannot walk to the head because a claim set was dropped, can still send (it deposits without opening the label, under the newest established read secret it holds, which co-readers open by history boxes), and what triggers a re-seal; it is placed only after a complete pass at that host (the rotation commits are uploaded before the step, notes/sync.md, so "cannot open" means not boxed, never "not fetched yet"); it fails only when the deposit key changed under it (issues/reseal-triggers.md). The device list (the node card) and recency are separate aspects because an expired register winner reads as absent and the older write does not show through: an expiring re-put of `node.0` would drop the node from the device list when it lapsed.
- Why a durable heartbeat and not a node-card re-put or ephemeral data: a reader's re-put is a deposit that sits in the label's budget until a writer promotes it, so readers × cadence × promotion delay had to fit a budget the spec never sized, and a full budget refuses the deposits that matter (grants into the group, a reader's self-removal, a revoke only readers hold). Expiry frees the budget unattended (no tombstone, no delete, no writer), so a reader holds at most ceil(lifetime / interval) entries at once and the budget is sized from the claim set (spec/sync.md §5). Rejected: deposit new card plus token-delete the old one (a delete and a 30-day tombstone per refresh, reader-side delete flows, rate-limited deletes); ephemeral writes (the asker is rarely online with the reader, and readers cannot write ephemeral data); host arrival times (untrusted, per host).
- Leak accepted by owner: a host sees each reader's heartbeat rhythm per label (same class as deposit and expiry times it already sees). Clock skew between the heartbeat's writer and the asker shifts the reading by the skew; lifetimes are days, so no coarse policy notices.
- A trusted node keeps its own local record of the last heartbeat it saw per node, for policies wanting a longer memory than the lifetime; it is a lower bound, not knowledge of the gap.
- Uses: write a new schema form once every node reads it (fixes the read-only old app the header heuristic cannot see), drop old-form history after that, clean up an inbox once every own device has acked.
- Dead nodes: a lost phone's heartbeat lapses and it drops out of "all nodes seen recently" on its own; a policy that needs it gone from the device list too waits for an explicit node removal. Never gates deletion at hosts.
- "Buffer until all have seen it" = inbox pattern plus this predicate plus expiry as backstop. Fine as a core helper later; not sync machinery.

## Step 1 as built
Module `core/engine/src/ephemeral/` (`Eph` owned by `Engine` beside `Core`); `Engine::write` is the split (`Engine::commit` stays the durable-only path flows use). Tests: osis `tests/it/ephemeral.rs`; schema `parse::validation_rules`.
Decisions where the design was open:
- `ChangeId`/`EphemeralId` came with step 1 (an ephemeral-only batch needs a `Committed` id and a watch source); `revert` takes a `ChangeId` (ephemeral ones since step 2's undo log).
- Expiry classes: the own writes joined per expiry time (`EphAspect::own`) plus the session counter ranges of each; at T the class goes and the aspect is rebuilt (Expiry above); the ranges stay as expired, so a later own write repeating one of their records has it taken out.
- Timers: `Engine::tick_ephemeral` and `next_ephemeral_timer` beside `tick`/`next_timer` (retention/ untouched); node-sync's Tick calls both and `next_wake` includes it.
- Node-sync subscribes with `subscribe_durable` (no `Event::Ephemeral`), the osis handle skips `SyncEvent::Local` after ephemeral-only events, and node-sync ignores an Expiry `Changed` naming only ephemeral aspects: a local ephemeral write costs the sync engine nothing.
- `delete`: per aspect a durable remove when a durable delta is held, else an ephemeral reset (an aspect on both sides loses its durable side only); freeing scans the ephemeral things for owned ones (O(ephemeral things)).
- A new ephemeral thing needs the role its creation would need (checked at write, like `created.0`).
- `move_thing(tid, owner, groups)` persists an ephemeral tid or owner first; `grant`/`change_edge`, `make_link` and `sync` persist an ephemeral target first (`Osis::persist`, a content commit of its own).
- An ephemeral-keyed raw write of `group.0` stays `Invalid`; `placed.0~` is written by group ops only.
- The rights check (perm timeline role per write) is the largest cost part and trivially cacheable per (thing, roster generation) if a budget ever needs it.
- Not built in step 1 (still open): text sessions committing each edit at once on ephemeral aspects (they idle-commit like durable ones, harmless); requirements.md's Ephemeral data section (with step 3: it is about sync).
- Cost (release, `tools/icount`, `ephemeral::bench_*`, setup subtracted): a local ephemeral set through `db.write_with` on one aspect about 15.7k instructions (engine `write` alone about 14k: rights check about 4.6k, ops and join about 5k, events about 3k), a `BTreeMap` insert 316, a durable set 5.3M. So about 50x an in-memory map and 340x cheaper than a durable write; the rights check (perm timeline role) is the largest single part.

## Step 2 as built
Modules `core/engine/src/ephemeral/place.rs` (placements) and `log.rs` (undo log); osis `commits.rs` over both sources. Tests: osis `tests/it/ephemeral.rs` (placements), `tests/it/ephemeral_undo.rs`.
- Split (`Engine::place_plan`): durable-keyed `group.0` writes are taken out of the batch and split per op. A member add is durable iff the member is durable after the batch; a member remove iff member and group both are; any other op (`make_group`'s set, a raw root op) iff the group is; an op that is not durable goes to `placed.0~` (`make_group` skips a thing that has `group.0` or `placed.0~`: its set would clear the placements). What persists is a fixpoint: owner-chain closure of the things with durable aspects or `persist`, plus groups getting a durable add, plus groups the persisted things' ephemeral placements convert into (when the node may write them), until nothing grows.
- Conversion: per placement a durable add (items or subgroups) into the group's durable `group.0` delta, with the placement's expiry (found by stripping the aspect's expiry classes in turn until the element goes; a class already past its time skips the conversion), and a `placed.0~` remove, not logged for undo. Two conversions into one group with different expiries in one batch are `Invalid` (persist separately). An unplace of the item from that group in the persisting batch wins: only the ephemeral reset is written. A persisting thing that is a group ephemerally gets `Set(Group::default())` first in its durable `group.0` ops (groupness persists, its ephemeral items do not). A group the node may not write keeps the placement ephemeral: `DiagnosticKind::PlacementNotPersisted`, tids `[item, group]`, after the commit.
- Reads: `Eph.defs` caches each group's `placed.0~` read field by field; `Engine::groups_of` (and `groups.0`) is the union of the durable index and these, climbing subgroup edges of both; `durable_groups_of` is the durable side (node-sync's `groups_holding`). The closure sync uses stays durable-only until step 3. An ephemeral reset of a durable element (raw path op only) is not reflected in `groups_of`.
- Freeing a thing also removes its (and its owned things') ephemeral placements, by resets.
- Not reported: `NotSynced` for ephemeral items (filtered in osis `not_synced`).
- Undo log (`Eph.log`): per own batch with ephemeral writes (fast-path durable batches log nothing) its id (the commit for a mixed batch), `reverts`, actor, ts, and per aspect delta, counter range, `footprint` of the pre-write joined state, schema. Byte size = `Fragment::approx_bytes` of delta and footprint plus the entry's own size (encoding them cost about 31k instructions per write, `approx_bytes` a few hundred); `approx_bytes` counts heap structure (a `BTreeMap` node per small map, boxes), within a few percent of measured RSS growth per logged write (an int set about 1.9 KB, a two-entry map set about 12.5 KB; counting stamps and values only had it 6-16x low); past `Config.ephemeral_history` (osis `Config`, default 16 MiB, engine `Config` too) the oldest entries go; an ephemeral-only one is remembered per aspect (newest ts and id, and whether it was a revert), bounded by the aspects held. At 0 nothing is undoable.
- `Engine::revert_change(id, actor)`: the log entry's inverse writes (`osis_crdt::undo` against the joined state, the footprint as buffer, `restored` judged over the log), then for a commit the durable undo commit at the same `ts` (`undo_in` takes it), then one ephemeral batch logged with `reverts`. Returns `Reverted::{Written, Superseded, Compacted}`; an ephemeral id from another session or node is `Misuse` (osis `Invalid`). A mixed batch whose ephemeral half left the log reverts its durable half only (as after a restart).
- Commit query: entries keyed by `ChangeId`; a logged change joins its commit's entry or, ephemeral-only, is `CommitKind::Ephemeral` (changes and reverts alike; `reverts` tells). Relations (`reverted_by`, in effect, depth) over the related commits plus the whole log. `CommitQuery.reverts/reverted_by/after` and `CommitEntry.reverts/reverted_by` are `ChangeId` (builders take `impl Into<ChangeId>`); `Error::NotUndoable.commit` is a `ChangeId`. Redo's "no newer change" test uses depth > 0.
- Scope: `Thing`/`Group` cover held durable aspects plus `Engine::ephemeral_scope_keys` (every ephemeral key of an ephemeral thing; a durable thing's `placed.0~`). Undo first checks the newest dropped ephemeral batch in scope: newer than the chosen target is `NotUndoable{Compacted}` (redo: a dropped change gives `None`).
- Cost (release, `tools/icount`, `ephemeral::bench_ephemeral_sets`): a local ephemeral set about 19.8k instructions, was 15.7k before the log (footprint, delta copy, log entry, the placement split).
- Undoing a creation deletes (spec/crdt.md §4.6): log entries record the ephemeral things a batch made and deleted (`log::Making`); `revert_change` deletes what the change made (a commit's `created.0` things via `undo::unmake` in `undo_in`; their ephemeral side and a logged batch's still-ephemeral things via `unmake_ephemeral`: aspects reset, entries removed from `placed.0~`) and brings back what it deleted (`EphThing.deleted` cleared; it is never freed meanwhile, so redo can restore it). `ephemeral_log` lists `(t, created.0)` for made and deleted ephemeral things and `ephemeral_scope_keys` covers it, so a Thing scope sees the creation.
- Undoing a save returns the draft (exact undo: the draft existed before it). `Making.saved` records the drafts a batch saved (ephemeral things made earlier that it persists; a save always takes the logged path) and `undo_in` gets them as `Mutation::undo_keep` (not deleted). The conversion's ephemeral placement reset is logged, so the undo puts the ephemeral placement back. The record stays durable: the thing goes in `Eph::drafts` (memory only, one entry per own undone save, with a deleted flag), which makes it known (even without content), counts as ephemeral for the Thing scope (its ephemeral aspects and `created.0`) and for deleting it by undoing its ephemeral creation. Its next durable write saves it again (`Placed.saved`), and redo, a new save or `delete` takes it out of `drafts`. With no log entry for the save (another device, compacted, restarted) its undo deletes instead. Placements: `place_plan` converts the ephemeral placements of every durable thing a batch writes durably, not only persisting ones (a restored draft after a restart gets its ephemeral placement back from the host with no `drafts` entry; also a placement made ephemerally while the thing persisted elsewhere), and a durable unplace also removes the item's ephemeral element (exact: placing a durable thing is a durable add that persists the group, so every ephemeral placement of a durable thing was made while it was ephemeral, or restored by undo; test `durable_thing_into_ephemeral_group_persists_it`); `ephemeral_placements` scans `defs` per written thing, skipped when `defs` is empty. After a restart a restored draft reads like a deleted thing unless its group synced (then its ephemeral content and placement come back and it reads as a placed thing; node test `ephemeral_placement_of_durable_thing_converts`).
- A persisting ephemeral group's empty `group.0` set takes the expiry of the conversions into it (an empty group has no value for expiry to remove, spec/crdt.md §4.7); a placement that does not convert (unplaced by the batch, expired) persists no group.
- Open: node-sync treats an ephemeral expiry on a durable group's `group.0` (an expiring ephemeral placement) as a durable change (`only_ephemeral` is false there); harmless, a wasted check. Role ops still persist their target by a commit of its own first (`Osis::persist`), which now also converts its placements. The CLI refuses `create --in G`/`--group` without durable data (the thing would vanish at exit).

## Step 3 as built
Modules: osis-commit header field 14 `ephemeral: Option<EphClass>` (`Plain`, `Relay`) and its validation; osis-label `Class` (prefix byte 25); osis-engine `ephemeral/remote.rs` (unsent writes, building, ingesting, judging, compaction, relay-only delivery); osis-node `sync/ephemeral.rs` (the lane); osis-proto relay-only accept (`ServingOutput::Relay`, pushed as a `Push` of one add event at the subscription's cursor); osis-host in-memory ephemeral entries in `HostStore`. Tests: osis-node `tests/it/ephemeral.rs` (with `random_window_converges_*`: four writers, two hosts, random writes, partitions, restarts, a random host cap on odd seeds; tier 2 `random_window_converges_large`, `OSIS_EPH_START`/`OSIS_EPH_SEEDS`; `random_window_one_capped_host_*` the same on one capped host; the three tier-2 runs take about 11 min for 300 seeds together), `sync::signals_relay_only_spec_sync_5`, `hostile_host::replayed_signal_dropped_spec_sync_9`; osis `sync::remote_signal_spec_sync_5`; osis-host `hub::subscriptions_and_relays`, `hub::ephemeral_entries_in_memory`; proto `loopback::subscribe_push_and_relays`; vectors (ephemeral and relay-only commits, prefix classes).
Decisions where the design was open or turned out differently:
- **Not the `MemStore` beside the store** (the plan's wording): ephemeral commits never enter `Core`'s journaled indexes, the store's tables or `validity.rs`/`retention/` (concurrent work there, and every index would have had to learn "not persisted"). The engine keeps `Held { header, parts (fragment, absorbed, authors, valid), own, bytes }` per commit; node-sync keeps the blobs per label (`Lane`). Same wire, same host path, same verification and validity rule; separate bookkeeping.
- **Validity**: a part is judged as a compaction snapshot's delta of its author at the commit's key by commit ID (`tl.delta_valid(.., Dots::Commit, required_role)`), on an ephemeral thing through its nearest durable owner (an ephemeral owner that is the author: valid). Since own covers a part carries only its author's writes (receivers strip the rest, `HeldPart::only_of`), so it is exactly its author's delta. A demotion's frontier lists no ephemeral commit, so a demoted author's ephemeral writes all go. Re-judged when `Core::generation` moves (`rejudge_ephemeral`, O(held parts)); a flip rebuilds the aspect from `EphAspect::own` (own writes alone, kept once a remote part joined) and the valid held parts, own held commits included (an own compaction's cover carries others' writes; skipping it lost them, found by review).
- **Snapshot form**: every delta is a snapshot delta (writes under this node's sessions, the current one and earlier ones its own held commits carry; frontiers empty for now), retention `writer` with no bounds for every aspect, `created.0` included (validation exempts ephemeral commits from the fixed `created.0` retention), so a commit is one blob per (reader, expiry, delete keys) and writers delete with the level-3 key. An ephemeral thing's `created.0` is a register write under the session source minted once (`EphThing::created`); an own cover's joined record of a thing no longer ephemeral here goes as one minting (`one_minting`: copies can differ across a restart). Commits are built per (actor written for, expiry); a commit touching an ephemeral thing carries its record and its ephemeral owner chain's; each label's blob carries the chain records of the things inside it.
- **When**: the osis handle shows the sync engine a Local event when `Engine::has_unsent()` (own writes noted since the last take); node-sync's step builds (`take_ephemeral_if`) and sends, coalescing (Coalescing below).
- **Holders bring what a peer lacks**: the first Sync of a label on each connection lists the held lane entries as `gained` (≤ `MAX_GAINED`; more are reconciled first and only what the peer lacks goes up); the peer's want-list goes up. At most one upload of an entry is in flight per connection, and a status for a lane entry never reaches the sync records (a second status once marked a fetched ephemeral entry durably present, so the next restart's reconcile listed it as held and never got it back; found by the randomized differential). An entry received from one host or peer is uploaded at once to the others where the label is open and it is not known present (a writer stamps every entry it uploads with the connection's write key, others' included; a reader relays the stamp it got, and only one verifying under the head counts on arrival). A waiting entry verified later (`eph_promote`) counts as present only where `present` already says (marked at arrival, cleared by `eph_lost`): taking the host it waited on as present, and the old stamp as good, left a demoted-then-promoted author's commits at no host once both hosts had restarted (random churn 154 and six more seeds; invariant on `eph_spread`, test `ephemeral::promoted_after_hosts_restart_reaches_hosts_spec_sync_6`). No relay delay: every holder bridging two hosts sends it (duplicates answered OK, an open cost item).
- **Restart**: the first sync of a label at a host after a start reconciles the live sets (lane IDs and present entries) and keeps the cursor (`Lane::reconciled`, `reconciling`): the ephemeral entries the persisted cursor already passed come back as `need`. Not after a cursor-less replay, not on reconnects within one run. Marked done when the reply arrives (a connection ending first reconciles again; one ending with any of the reply's fetches unanswered too, and a refused one of them, `reconcile_fetches`, emptied as they are answered: nothing else names an ephemeral entry the cursor passed, so it was never asked again, inflight seed 100013; a durable reconciliation needs none, its cursor-less Sync records every entry); the reply counts as held there only the lane entries its set listed (`reconciling` keeps them): one kept meanwhile from another host goes up instead, and a Push during it keeps no cursor, as during a Sync (keeping it skipped the durable entries between the old cursor and the push for good when the connection ended before the Sync: sim `disappearing` 8124, `stranded_reseal` 8112, found by review).
- **Host**: ephemeral entries, their blobs, log records and tombstones in memory (`Ephemeral` in `HostStore`); log sequence numbers shared with the durable log, reserved on disk in blocks of `SEQ_BLOCK` (1024) in the label meta's `reserved`, so a restart never reuses one (a cursor ahead of the durable log stays valid). Caps `HostPolicy::ephemeral_bytes` (16 MiB per label) and `ephemeral_total` (1 GiB): code 12. Deposits of ephemeral or relay-only blobs: code 1. In-memory log trimmed at `EPH_LOG_KEEP` (2^16) records per label (cursors below get the live entries). `Rate::Signal` and the `signals` knob are gone; relays are rate-limited by `RelayGate` (security review fixes below).
- **Compaction**: replaced by own covers (below). Kept from this step: any node drops a held commit once valid held commits list it absorbed on every aspect (`drop_absorbed`); node-sync then forgets its blobs and, as a writer, deletes them where present (level-3 key; since own covers only once the cover is held there); every plain entry a host refused for its cap goes again there at each periodic pass (`resync_ms`, `eph_retry`): room others made (their compaction, or an expiry, which leaves no log record) reaches it (sim `ephemeral_capped` 14; a retry on the label's deletions with a doubling wait missed expiries and waits longer than the deletions that came).
- **Node cap**: `SyncConfig::ephemeral_bytes` (16 MiB) per label of memory held from others (each entry's `charge`, decoded size: counting encoded bytes let a label of tiny entries hold about 200 times the cap). The node gives the engine the room left under the cap (`ingest_ephemeral_within`): each part is decoded only while what the parts before it cost decoded plus its own bound fit (`part_bound`: `osis_crdt::decoded_bound`, `ITEM_BYTES` per CBOR item and per byte of a run's text content, a value B-tree node three times per map head and set tag (a map key's value is held three times), `BYTE_BYTES` per byte, found from the heads alone, nothing allocated; at least what `ephemeral_charge` counts once decoded), else `TooLarge`: nothing of it held or kept apart, handled as a blob over the cap (reported once until bytes drop, then the label is reconciled). A blob that can never fit (encoded past the whole cap, a part whose bound is, `Engine::ephemeral_bound`, or `TooLarge` with nothing else held there) is remembered per label (`Unfit`, at most `UNFIT_MAX` 2^12 per label, the oldest forgotten; forgotten when a host deletes it): not refetched at reconciles, its announcements skipped, reported once while the label has such blobs (it was fetched again, up to `MAX_BLOB`, after each drop; test `never_fitting_blob_not_fetched_again_spec_sync_9`). So a label passes its cap only by promotions (below, at most its waiting share) and no blob is decoded past it (admitting while under the cap let one 8 MiB blob of tiny entries decode to about 1.7 GB). The bound is loose per part (about 3 times the charge for tiny map entries, 5.5 for a map of small structs, 12 for one small struct, 13 for a small register part, 3 for strings), so a single part needs its bound, not its charge, in the room; a commit of many small parts is charged as decoded part by part. A blob kept apart (author's or thing's record missing: its waiting parts not decoded) is charged to the waiting share by its bound (at least its bytes; in blob bytes a writer queued a quarter of the cap of tiny-entry blobs, hundreds of times that decoded), keeps the most room a copy was given (`Waiting::room`, `Invalid::room`) and is retried within it (reported when past it). Once the engine holds it the node keeps and counts it even past the cap (`eph_promote`, the copy checked within its waiting charge; it was held uncounted: test `promoted_waiting_blob_counted_spec_sync_9`, checked in debug builds), so a label holds at most the cap plus its share. A big honest blob waiting needs its bound (about 6 times a string's bytes) within the share: one past it that lacks records (a split commit's later blob arriving first) is remembered with them (`share_refused`, `Engine::ephemeral_needs`) and fetched again from its host once one is here (`eph_refetch`, weighed only after `Engine::records_seen` changed; an author's record counts only durable, so an ephemeral key actor record cannot refetch it at every change; it was lost until a restart: test `commit_past_a_blob_splits_spec_sync_9` at a 64 MiB cap); one whose parts are all invalid is left to `refused_pending` (refetching at every durable change would download it each time). A held commit from another whose parts all turn invalid (a removal, a demotion) is let go at once (`take_unheld_ephemeral`, `eph_unhold`: no delete anywhere, its labels reconciled so it comes back to wait apart in `Remote::invalid` until valid; it was held, counted and listed as gained until restart). Absorbed lookups go through `Remote::absorbers` (listed ID to the held commits listing it, exact, checked in debug builds): an arrival weighs what it lists (and itself when listed), not every held commit (`scale::eph_absorb_lists_cost`). A replay judged contained compares a piece of the cover (`Fragment::contains`: the cover at the replay's positions; sound, checked against the whole join in debug builds) instead of joining into a copy of it (`scale::eph_replay_cost`: 293 ms to 0.2 ms against a 2.5 MiB cover).
- **Signals**: relay-only commits built per actor from the signal writes of the batch; hosts and co-reader peers push them, never store them; receivers deliver valid parts once (`delivered`, `MAX_DELIVERED` 2^16 with a floor per author, dropped past `MAX_DRIFT`; remembered per (commit, part): a commit whose parts have different readers goes as several blobs, and dedup by commit dropped all but the first, test `ephemeral::signal_commit_in_several_blobs_all_delivered_spec_sync_5`); a node's own fire locally as before. No targeting, no `on_signal_in` (a group-wide signal is a signal aspect of the group thing).
- **Pre-existing bug found**: the replay cursor's position (first 8 bytes of a blob ID) overflowed the wire's 2^63 integer limit for IDs starting at 0x80 or above and replayed a page twice; it is now the first 63 bits (spec/wire.md §11.2).
- **Security review fixes** (after step 3; report and fixes on branch `ephemeral-sync`): relay-only prefixes expire at `ts + MAX_DRIFT`, hosts and co-reader peers admit relays through `osis_proto::RelayGate` (expiry window, `MAX_RELAY_BLOB`, per-label rate, push once per blob); receivers drop relay blobs unopened when oversized, outside the window or seen (`RelaySeen`, floor past the bound). The host engine refuses unstamped ephemeral and relay-only blobs for every store (a co-reader peer's store did not). Host ephemeral memory counts per-entry, per-record and per-tombstone overhead, ephemeral deletes and replacements are rate-limited, due times are indexed (sweep budgeted), the label using most gives way at the total cap, and the durable log is trimmed by its own record count (ephemeral churn no longer sends durable cursors to reconciliation). - **Same-stamp substitution** (review M3): fixed by the copy order of spec/crdt.md §4.1 (notes/crdt.md, Known anomalies); forged map keys are two entries (spec/crdt.md §5.6), forged text creation `ts` copies of one creation (§5.7 Join; notes/crdt.md Known anomalies); a map residue case remains: issues/forged-key-erased-reset.md.

## Values that live while their author is there
Owner decision (round 13): presence is not a lifetime of its own. A value that should live only while its author is there (a cursor, a selection, an "online" mark) is an ephemeral aspect with a short default expiry (`~` key, `[expires: 30s]`) whose author rewrites it before it expires; when the author's device goes away the rewrites stop and the value is gone at every holder and host by its last write's expiry. Nobody needs to notice the departure: no connection tie at hosts, no source tracking or un-merge at holders, no lease or keep-alive constant.
- **Helper**: `osis::Osis::keep_alive(tid, key, path, &value) -> KeepAlive` writes the value and rewrites it every `expiry / REFRESH_DIVISOR` (2) of the key's default expiry on the database's runtime until the `KeepAlive` is dropped; `KeepAlive::set` writes a new value at once. The key must be ephemeral with a default expiry. A rewrite is a `Put` (a fresh entry at a map key, a fresh register write elsewhere): a `set` of an equal value writes nothing, and a write into an entry an expiring write created outlives that entry (Expiry above) unless it expires no later. `Replace` would not: at a live key it writes into the old entry and goes at that entry's expiry.
- **Cost**: each rewrite or `set` supersedes the write before it (Superseded expiring writes, below), so a holder and a host hold about one commit and entry per kept value, and one upload goes per value per half expiry or per round trip while it changes (`ephemeral::moving_cursor_one_entry_per_author_spec_sync_9`: 60 moves, one entry; was 60 before; 30 moves a second at a 30 s expiry was about 900 per author). Left: an expiry under the sync tick (1 s) still rewrites every half expiry, one upload per rewrite, while expiry is applied only per tick.
- Two devices keeping one path alive overwrite each other at every rewrite: key by device (`Osis::node`), not person. Nothing survives a restart: the app calls `keep_alive` again.
- **Choosing the expiry** (the schema's, per aspect): how long a departed author's value lingers against the rewrite traffic. 30 s suits cursors.
- **Write-level "until the author disconnects"** (owner idea, evaluated): it needs exactly what this replaced (a host tie per connection, holders tracking which host or peer still has the author's entry, un-merge when none does, a lease backstop for half-open connections), and "disconnected" is per path, so holders behind different hosts disagree. Not built.
- Tests: osis-node `ephemeral::refreshed_value_lives_while_author_present_spec_crdt_4_7`; osis `runtime::keep_alive_rewrites_until_dropped`; sim `ephemeral`/`ephemeral_capped` (random expiring cursors; `author_leaves`: a refreshed cursor at every connected holder before each refresh, gone past its expiry once the author is down).

## Own covers (as built)
Replaced the capped-host compaction rules (mvp-progress items 32, 44, 50; two open issues: cross-group and `created.0`-only commits no forced cover absorbed). Each of those patched one loop: a host refuses for its cap, holders compact, several holders' covers (each carrying everyone's writes) arrive concurrently, the host fits one, or holds a cover nobody's next cover absorbs, and refuses again. The race itself (k holders able to cover everyone, deciding concurrently) stayed.
- **Rule**: a cover is made only by the author of everything it covers (`Engine::compact_own_ephemeral`): per actor (several commits past inline header lists, below), per aspect the join of its own held plain commits without expiry (earlier sessions' ones it holds again included: their sessions name this node) and of its unsent writes without expiry, absorbing each on every aspect of its parts. A commit with an aspect no longer writable here is not covered. Covers obey `may_absorb` (same author, same class).
- **Trigger**: own held commits cost more than `COVER_FACTOR` (2) times the cover, each counted as delta bytes plus `PART_OVERHEAD` per part plus `ENTRY_CHARGE` (the cover the same: without the per-part term a holder of many small parts filled its cap before the cover came), two commits at least (one is what its cover would be again). Weighed only when the held cost passes the factor times the cover weighed last (`cover_est`, plus what could not be covered, so a stuck commit does not re-weigh every step): rebuilds cost O(1) per byte written. A cover's cost is measured by encoding the joined deltas (`cover_cost`). `eph_step` takes first, then compacts (the cover absorbs what was just built; that commit never goes). A small register compacts every two or three writes.
- **Why it converges**: covers form one chain per author and actor; a cover is the join of what it absorbs, so dropping what it absorbs never changes a holder's state, whatever the arrival order. Owner decision "state outlives its author and merges among holders" holds: holders keep, relay and re-upload an author's commits as before; a departed author's data stays at most about twice its state, since the rule ran at its last send.
- **Only own writes travel**: a commit carries its author's writes and, beside them, the records of the things it writes or its `placed.0~` deltas place, up their ephemeral chains (self-certifying); receivers strip every other write from every part, another session's or one under a node source (`HeldPart::only_of`; node sources were kept until review: a writer could pass a write off as another node's). No record-only commits; a thing entering a closure sends the node's own writes, not the whole state.
- **Host cap**: a refusal is reported once per entry (`Lane::capped`) and retried at the periodic pass; nothing else. Defined outcome (spec/sync.md §5, §9): what a full host lacks is what it refused. Tests and the sim check it exactly at quiescence: holders connected through hosts that keep nothing out read alike, where "keeps out" is an entry some up node holds that a host lacks and cannot fit (`HostStore::ephemeral_fits`); a node holding a window's record without its placement (the record rode in another commit, the placement did not fit) does not sync it (`ephemeral_synced`) and is no holder; each up node's own load is within the factor times its cover plus one commit (`own_ephemeral_load`). Caps are random, 0 and below one cover included. Room can appear only after the last periodic pass (deletes of what an entry accepted at that pass absorbs): the one-capped-host check runs further passes while an entry a node holds and the host lacks fits, at most one per entry (`random_window_one_capped_host` seed 173658). The sim's durable convergence check reads `group.0`'s durable side alone (`Engine::get_durable`).
- **Costs**: more host memory than cross-author covers: k authors overwriting one value keep k values; an author's own state keeps its text others deleted (projecting the state onto own dots would shrink it, but would turn a revoked writer's removal into the author's own). Expiring writes are never covered: each stays an entry until it expires or a later write of its author supersedes it (Superseded expiring writes).
- **Delete after the cover is there** (`Lane::waiting`, `eph_flush`): a writer deletes an absorbed entry at a host only once the cover (or what absorbed it since, `eph_cover`) is held there; orphans and replays of covered entries too. The upload of the cover that completes them names them as replaced instead (`eph_replaces`, `Lane::replacing`, back in `waiting` unless answered OK; at most 1024 per message, the rest by Delete): the host removes them as it admits the cover, the room they free counted, so a cover refused for the cap even so is only retried, never preceded by their deletes. The author whose cover is refused for the cap without carrying them deletes at once and re-uploads (room for it). Deleting first (the design's choice, for room at a full host) lost writes at a host for good when the author crashed between the delete and the cover's upload: holders kept the commits but the tombstones refused them (sim `ephemeral` 2601181, frequent once compaction runs every few writes; `author_crash_before_cover_lands_keeps_state_spec_sync_9`). That window on the cap-refusal path is closed by Replace when the cover's upload carries the deletes; left only when it does not (a split cover's other piece not held yet). Waiting deletes are bounded per (label, host) (`WAITING_MAX`, Bounds): a host that never comes back or never holds covers keeps at most that many. An upload refused for the rate (code 4; a cover's replacements count as deletes) goes again at the periodic pass like one refused 12 (`capped`; test `ephemeral::cover_refused_for_rate_retried_spec_sync_9`); one refused 1 is not retried on that connection.
- **Review fixes**: receivers also strip writes under node sources (above); a cover that cannot be built (then: a delta past the page target; since unpaged deltas: past a blob, issues/eph-unpaged-cover.md) keeps the unsent writes it joined (they were dropped, never sent) and is weighed again once the held commits double; `eph_step` no longer orders forgetting around placing (every absorbed entry's delete waits for its cover); the capped checks (sim `lossy_hosts`, `random_window` one capped host) count a refusal genuine only while the host keeps no plain entry that no (up) node holds, so a host filled with entries absorbed everywhere cannot excuse divergence. ## Superseded expiring writes (as built)
Covers never take expiring writes, so before this a cursor kept alive with `KeepAlive::set` (a fresh map entry per move, `Op::Put`) cost one commit, upload and entry per move until each expired (issues/eph-expiring-churn.md, deleted).
- **Rule** (spec/sync.md §9, `retention/memory.rs` `supersedes`; old path `remote.rs` `drop_superseded_by`, `eph_superseders`; Core memory class `drop_superseded`, issues/eph-unify.md Step A as built): a held plain commit whose parts all expire and carry no reset is dropped once each part is superseded by a valid held part of another plain commit of its author on the aspect: that part expires too, no earlier, carries no reset, each of its writes is stamped later than every write of the old part and none is a write into a record it did not create (a `Set` into the entry a move created goes with that entry), and the old part joined into it reads as it alone. Core keys alike: a `placed.0~` part is superseded as any (an exception there in `eph_superseders`, never in `note_written` nor the spec, read a placement placed again after an expiring unplace expired, where a conforming node did not: `placement_superseded_like_any_write_spec_sync_9`). Checked at every node when a commit is held (own builds included), each candidate costing a join and two reads of two small deltas; a received commit superseded on arrival is not held (`Dropped`).
- **Not death, but convergent** (spec/crdt.md §4.8; review): an older `put_new` entry at a key stays live in the CRDT, only shadowed in the read; the rule makes it expire early instead. Convergent because the drop is a function of the commits held, never of later writes: every node holding the newer part valid drops the older (at its arrival, at the newer one's, or when the newer turns valid, `rejudge_ephemeral`), and a later removal or undo of the newer entry kills only that entry everywhere. Two holes the review closed: the author kept the dropped writes in its own writes (and the unsent ones `note_written` dropped), so after a holder removed the newer entry only the author read the old one again (`superseded_stays_gone_when_newer_removed_spec_sync_9`); and a superseding part with a reset made the relation intransitive (q replaces the aspect over p, r later puts without the reset: r supersedes q but not p, so p was dropped or held by arrival order), so a part with any reset supersedes nothing (`Fragment::has_any_reset`). Review 2 (randomized `ephemeral::random_churn_converges_large`, 300 seeds) closed two more: a superseded part with a reset (a removal of another key beside the move) took its tombstones with it at holders but not at the author, so the removed entry read again everywhere but there; and a plain superseder was absorbed by a cover that supersedes nothing (it carries older writes of the aspect), so a node that got only the cover held the move and read it again once the plain entry was removed (`superseding_part_expires_spec_sync_9`). Now neither part carries a reset and the superseder expires (so no cover ever absorbs it). A `Set` into another's entry outliving it reads alike everywhere since an expired or superseded delta vanishes whole (spec/crdt.md §4.7): the `Set` reads alone as at a node that never held the entry (`set_into_expired_entry_reads_alike_spec_crdt_4_7`); the oracle writes `Set` again. Real death was weighed and rejected: each move would have to tombstone every own entry of the key not yet expired (about expiry / round trip of them per commit, 450 at 30 s and 66 ms), since dropping a commit drops its tombstones too. Left (as for covers, spec/commits.md §5 "a drop is final"): a superseder turning invalid later does not bring the dropped commit back. The ts order and the expiry guard keep the drop exact otherwise: a later write expiring sooner, or an older write with an equal value, supersedes nothing (`superseding_needs_later_stamps_and_no_reset_spec_sync_9`).
- **Holders and the author** drop the dropped commit's writes whole, from the own writes too, and rebuild the aspect (as at expiry; its timers go with it, so kept they would read again after the newer one expired or died).
- **Deletes**: only the author deletes a superseded commit's entries (`ephemeral_superseded`; every holder deleting would send one delete per holder and move, over the host's rate), as an absorbed one's: once the superseders are held there, or named as replaced in the superseder's upload (`ephemeral_absorbers` returns them until `take_dropped_ephemeral` hands the drop over). One the author fails to delete goes at its expiry.
- **Unsent**: a write noted while an upload is in flight drops the actor's earlier unsent writes of the aspect it supersedes (`note_written`), removing them from the author's own writes and state too, so the next take builds one commit, not one per expiry.
- Measured (tier-1 `Net`, 66 ms round trip, 10 authors moving every 33 ms for 1 s): 160 uploads, 0 deletes, the host's peak 43 KB of a cap scaled to 560 KB, one entry per author at the end; without the rule 224 entries (364 without the unsent part too); a simulated minute at the default policy (tier 2, 17 min dev at load 6-12): 9100 uploads, 0 deletes, peak 1.76 MB of the 16 MB cap.
- Tests: osis-node `ephemeral::{moving_cursor_one_entry_per_author, superseded_unsent_moves_one_commit, superseding_needs_later_expiry_and_own_records, superseding_needs_later_stamps_and_no_reset, superseding_part_expires, superseded_stays_gone_when_newer_removed, many_authors_under_host_rates}_spec_sync_9` (4 authors), `many_authors_under_host_rates_large` (tier 2: 10 authors for 1 s, then a simulated minute). `random_churn_converges_spec_sync_9` (4 seeds) and `random_churn_converges_large` (tier 2, `OSIS_EPH_START`/`OSIS_EPH_SEEDS`): random expiring and plain puts, removals, replaces, undos, demotions, partitions and restarts; holders never demoted read alike.
- eph-unify: the swap must keep this (step 5's at-most-0 retention judges §4.8 deaths, which a shadowed `put_new` entry never has).

## Coalescing (as built)
- Local policy (spec/sync.md §9 leaves when state writes go to the node): while every connection where a label is open has an upload of an own plain ephemeral entry under it unanswered, later writes of things that label's closure holds are not sent; they join what goes next, sent once one of those connections has none (answered, or the connection gone).
- Node-sync's `eph_busy`: the groups of labels where every connection the label is open on has an own plain entry upload unanswered (`Lane::uploads`). `Engine::take_ephemeral_if(busy)` leaves those things' unsent writes and records in place: later writes join `unsent` (deltas joined per aspect, actor and expiry: overwrites keep the latest). The step that handles an answer (or a connection's end, `eph_lost` clearing `uploads`) builds the next. No timer: about one own commit per label per round trip of the fastest connection. Compaction covers and signals are not held back; signals stay one relay-only commit per actor per write batch. A thing under several labels waits while any of them is busy.
- Review: the first version held back while an upload was unanswered on any connection, so one slow or silent host (a large Sync reply ahead of the answer, or a hostile one never answering) stopped every ephemeral write of the label from reaching the other hosts until its request timeout (2 min), again after each reconnect (`slow_host_holds_nothing_back_spec_sync_9`, both kinds). Releasing on the fastest answer then left every covered entry at the slow host (an entry forgotten while its upload was in flight was never deleted there: on main too, at every write): `Lane::orphans` keeps the delete for such an entry and sends it when the upload is answered OK; meanwhile the entry, coming back from that host (no held commit lists it absorbed past the newest cover), is not taken back.
- `Remote::noted`: `has_unsent` is true only for writes noted since the last take, so what was held back does not make every handle call feed a Local event; the answer that releases it arrives as an event anyway.
- Measured (tier-1 `Net`, 66 ms round trip, 30 moves a second per author): a cursor costs one commit and one upload per round trip, not per write: 10 authors for 1 s 160 uploads and 0 deletes since Replace (150 deletes before it; 300 and 290 before coalescing), for a simulated minute 9100 uploads (and 9090 deletes before Replace) (tier 2, 15 min at load 38: a node-sync step costs about 0.4 ms in dev); a burst of 20 moves during one upload: 2 commits. With a round trip under the write interval every write still goes alone.
- Tests: osis-node `ephemeral::slow_host_holds_nothing_back_spec_sync_9` (`Net::held_hosts`), `ephemeral::burst_coalesced_while_upload_in_flight_spec_sync_9`, `ephemeral::signals_not_held_back_spec_sync_9`, `ephemeral::random_window_inflight_*` (half the steps end after one hop, `Net::round`).
- Re-review: `Lane::orphans` holds at most one delete per upload in flight on a connection (bounded by the uploads a 2 min request timeout lets pile up on a silent host) and goes with the connection; then plain covered entries are deleted when the next connection announces them again (absorbed replay). A copy refused while an orphan is held has the same blob ID, so the same bytes: nothing newer is refused. An orphan answered with a code other than OK is dropped without a delete (a replacement refused by rate leaves the entry there until a replay or expiry). Tests: `ephemeral::covered_while_slow_deleted_{once_answered,after_reconnect}_spec_sync_9`.

## Memory snapshots in Core (eph-unify step B1, hidden path)
- `Engine::snapshot` of a `~` aspect writes a memory compaction snapshot (commit form, ephemeral marker, the whole state's writes of every author, frontiers over sessions, no expiring delta carried or covered); `ingest_memory` takes them; every holder drops the memory bodies a valid held one covers at once and forgets them (`retention::memory::drop_covered`). Replaces own covers once B2 swaps the lane over (issues/eph-unify.md Step B1 as built, Step B2): an author's covers become ordinary snapshots by the aspect's compactor, coalescing a snapshot of the unsent own commits.
