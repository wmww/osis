# Ephemeral data
> Summary: Design (Tess's direction of round 13 and two reviews) for ephemeral data: drafts and schema-declared aspects, an axis independent of sync, as much like ordinary data as possible. Local ephemeral writes are memory commits through Core (about 0.16 ms); synced ephemeral data is ordinary signed commits marked ephemeral, kept in memory instead of the store at nodes and hosts and carried by the ordinary sync path (node-sync's passes judge, place, upload and delete their bodies as durable ones, with the records about them in memory; eph-unify step C): it merges on reconnect, outlives contact with its author and is lost only when no node holds it. A value that should die with its author is an expiring write its author renews (`osis::KeepAlive`); `signal` aspects reach only currently connected devices and hold nothing. Every thing starts as a draft and is persisted with its owner chain at its first durable write, keeping its tid; ephemeral placements are the core ephemeral aspect `placed.0~`, read with `group.0`. Covers the API delta, engine, wire, bounds, deletions, spec edits; also kept: expiry and the all-nodes predicate. Tracking: issues/ephemeral-data.md.

Terms: a new thing not yet durably written is a **draft**. **Ephemeral** is for `~` aspects: shared with others, never stored. A draft has only ephemeral aspects, so it syncs like them once placed in a synced group (issues/draft-shared.md).

## Tess's direction (decided)
- Ephemeral = cheap and disposable, no never-touches-disk promise. Independent of sync: durable or ephemeral, local or synced. All of an app's state lives in osis; the UI drives and is driven by it.
- Like ordinary osis data in most ways; its history is "don't care" (neither purged nor kept). On one device it must be very cheap; some overhead is fine when synced, and anywhere when the alternative is special cases or API complexity. Reuse the ordinary commit, delta, validity, sync and host paths unless clearly worse.
- Both units: drafts (creation record only in memory, same tid derivation and rights) and ephemeral aspects on durable things, declared in the schema. Flags `ephemeral` (a value) and `signal` (no lasting value).
- `create` takes no placement; group ops set groups (same batch for atomic create-and-place). Every thing starts as a draft and is persisted at its first durable write together with its owner chain's creation records, keeping its tid. No persist call. A thing never given durable data vanishes when every node holding it forgets it. Ephemeral placements of drafts approved.
- Synced ephemeral state is ordinary CRDT state held in memory by every holder: it survives while any holder keeps it, merges on reconnect (two people keep using a shared ephemeral window while one is offline; it merges when they reconnect), and a joiner gets it from any holder. A value that should die with its author is an expiring write its author renews (Values that live while their author is there).
- No exception to convergence: ephemeral state converges among the nodes holding it; author-tied values converge once every holder notices the departure (like expiry).

## Model
**Kinds of aspect.** The key decides, by its lifetime marker (spec/data-model.md §2): durable (none); `~` ephemeral (a value held in memory); `*` signal (an ephemeral write with no lasting value, delivered only to currently connected devices; anything a late joiner should see is ephemeral state, not a signal). The writer's key decides the path; merge needs no schema. Core aspects are durable, `placed.0~` aside (placements). Retention does not apply to ephemeral data; expiry does.

**Holders.** A node holds the ephemeral state of the things it writes or receives: every node syncing a label whose closure holds the thing (spec/sync.md §3: `group.0` and `placed.0~`, as for durable data; a thing no group lists syncs no more), and that label's hosts, while they run. They keep it until they restart, stop syncing the label or lose read access. State is lost only when nobody keeps it; a restarted node gets it back by syncing.

**Draft.** A thing whose creation record no durable commit holds at this node. Tid derivation, creation record and owner are as for any thing. `create()` mints the record and keeps it in memory; nothing is written. Invariant: **the durable set is closed under owner**, so a durable thing never has a draft owner.

**Persistence (promotion).** The first durable commit with a delta on a draft T (a durable aspect of T, by any node that holds T's record and may write T) also carries `created.0` of T and of each draft on T's owner chain, top down, and makes T's ephemeral placements durable (below). Same tid; ephemeral aspects stay ephemeral; ephemeral values never become durable: the app copies a draft's content into a durable aspect in the same batch (`set`). Reason: a durable write anchored at an ephemeral dot hides once nobody holds it, and a durable writer delta cannot carry foreign stamps. Two nodes persisting T concurrently both carry the same record (idempotent). An edge write on a draft first persists it by its own content commit (role commits cannot carry `group.0`), then runs. A durable thing never becomes a draft again.

**Ephemeral placements.** `placed.0~` (of `group.0`'s type) is the one ephemeral core aspect (issues/eph-unify.md step 2; it replaced an ephemeral side of `group.0` joined at read): a group op (`place`, `unplace`, subgroup add or remove) whose item is a draft is a write into the group's `placed.0~`, held and synced like any ephemeral state, needing write on the group; raw writes of `placed.0~` are `Invalid`. `group.0` reads its durable state alone; `placed.0~` reads as the group its items and subgroups make (its adds carry no struct presence); the group index (`groups_of`, `groups.0`, `listed_in`) reads both, so the item shows in the group's members and in its `groups.0`, and the closure (spec/sync.md §3) includes it, so its ephemeral commits go under the group's labels. When the item persists, the persisting commit adds it durably (with the placement's expiry) and a reset removes it from `placed.0~`. A draft can be a group of drafts, a draft placed in a folder lands there at save, and nothing durable names a thing that never persisted. A group op on a durable item is a durable write and persists the group. Any later durable write of a durable thing converts its remaining ephemeral placements the same way, and a durable unplace also removes it from `placed.0~`. Side effects, all minor: an ephemeral `unplace` concurrent with the item's persistence loses to the durable add (add wins); a persisting node without write on the group cannot make that placement durable, so it stays ephemeral and a `PlacementNotPersisted` diagnostic names it (a writer of the group fixes it with `place`); a durable `group.0` naming an ephemeral tid (a raw path op) is a reference that may dangle.

**Rights and validity.** A draft has no role-class aspects (writing one persists it), so a node's role on it is its role on a new thing owned by the nearest durable thing on its chain: the rule already used for things created in the same batch. Ephemeral writes need what the durable write would need; readers cannot write ephemeral data. Synced ephemeral commits are judged like compaction snapshots (spec/permissions.md §5.2: a part is valid iff its author could write the aspect at its `ts`, through the ordinary timeline), and un-merged like any commit on revocation.

**Reads and merge.** An aspect reads the join of its durable state and its ephemeral state (spec/crdt.md §4.1); normally one side is empty (both: `group.0`, or schemas that disagree; the join is defined). Own writes and every applied ephemeral commit join into the ephemeral state. `signal` aspects always read absent. Expiry follows spec/crdt.md §4.7. So ephemeral state converges among holders as any CRDT state does.

**Deletion.** `delete(T)` on a draft writes the usual resets. A thing never kept under a label here (`MemorySync::kept`) and in no labeled closure is freed at once (record, state, undo entries, the drafts it owns; the tid reads unknown), so short-lived UI things cost nothing. One a commit on was kept under a label is deleted as a durable thing is: its resets go to the holders and it keeps its record and tombstone commits, marked deleted (`Eph::deleted`, reads unknown; an undo of the batch brings it back), until restart; dropping them would let a holder's copy revive the values (`deleted_synced_thing_keeps_tombstones_until_restart_spec_sync_9`, `deleted_thing_stays_deleted_at_holders_spec_sync_9`). A holder's later write on it shows alone, as after a durable delete.

## API delta (notes/api.md, applied with steps 1-2)
- `w.create() -> Tid`; `Place`, `create_expiring` go (expiring membership: `w.group(g).expires(e).add(m)`).
- Schema DSL: the key's marker is the lifetime, no flag: `aspect win:notes.0~: list<tid>;` `aspect doc:cursor.0~: map<tid, Cursor> [expires: 30s];` `aspect call:ring.0*: Ring;`. `AspectKey::lifetime()` reads it from any key, typed or untyped.
- Writes: unchanged calls. One `Write` may mix durable and ephemeral ops: validated as a whole, applied locally at once (one dispatch); the durable commit and the ephemeral commit travel separately, so a peer may see one without the other. `retention(..)` on an ephemeral write and any op but `set` on a signal aspect are `Invalid`. `commit()` returns `Committed { id: ChangeId, ts }`, `ChangeId = Commit(CommitId) | Ephemeral(EphemeralId)`; a batch with both halves is one change (one `ts`; revert of either reverts both).
- Watches: unchanged. Each signal reaches every `on_change` callback once (never coalesced, never in state). `CommitInfo.id` becomes `ChangeId`; a remote ephemeral change names the ephemeral commit that carried it (its author, verifiable, notes/api.md Attribution).
- `created(t)`: `Stamp.commit: Option<CommitId>`, `None` while a draft (`ts`, `node`, `actor` from the creating batch or ephemeral commit, `received` from its arrival).
- Undo, redo, revert, query: own ephemeral batches of this session are changes (`CommitKind::Ephemeral`); ephemeral commits are transport, not listed. Thing and Group scopes cover durable aspects and drafts; an ephemeral aspect of a durable thing (cursor, selection) is in scope only when named by `Scope::Aspects`, so document undo never steps through cursor moves. Remote ephemeral changes and own ones from before a restart have no log: revert is `Invalid`. `Config.ephemeral_history` (default 16 MiB) bounds the log; older batches are `NotUndoable{Compacted}`.
- Gone: `send_signal`, `on_signal`, `on_signal_in`, `Target`, `SignalEvent`, `Signal<T>`/`SignalKey`. Device targeting is dropped (no user; a value can name a device). A group-wide signal goes on the group thing.
- Errors: none new; `UnknownThing` for a vanished tid. Diagnostics: `EphemeralRefused { label }` (a cap was hit, below), `PlacementNotPersisted { item, group }`. `NotSynced` stays only for a durable placement into a closure with no label.
- Text sessions on an ephemeral `text` aspect apply each edit at once (no idle commit).

## Local engine
- Module `osis-engine` `ephemeral/`, owned by `Engine` beside `Core`, under the handle's one lock. Since eph-unify B2 the ephemeral half of a batch is memory commits in Core (Memory commits below): `Eph` keeps only the undo log, batch counter, undone saves (`drafts`), deleted things, unsent signals and delivered relay-only commits; no own state, next counters, held parts or timers of its own.
- Local stamps: `ts` from the engine's HLC; dots of source `Session(node, nonce)` (spec/crdt.md §2.1) with counters per aspect from the store's memory overlay (`counter(tid, ak, nonce)`), contiguous from 1 in each session. Two sessions per open: `Core::session` for plain writes, `Core::expiring` for expiring ones, its nonce the plain one's with the first bit flipped (one rng draw per open as before: a second draw moved every later tid and blind, and seed-pinned order tests and the judgment vectors depend on commit-ID ties) (coordinator decision 2 of B2: an expired delta's range is forgotten, and under the plain session it left a gap no snapshot frontier passed, so nothing later of the session was ever covered). Fresh sessions within an open (`Core::fresh_session`, from the validity pass in `apply/validity.rs` when an own session-form write of the current sessions falls, the `OwnWriteInvalid` case): the plain nonce's last 8 bytes step by one as a big-endian count (no rng draw), the expiring one follows by the flip; `later_sessions` counts them, so `own_plain`/`own_session` recognise every session of the open (batch IDs, `copied_expiry`, `own_memory_commit`) without a list. The undo log's `restored` matches a stamp to the logged write by its source alone (the log holds own writes only). Why: a write invalid for good (explicit demotion, no re-grant after it, spec/permissions.md §5.2) stops every snapshot frontier of its session below it, and later writes behind it were held uncovered at every holder until a restart (`memory_regranted_writer_covered_spec_sync_9`). A plain demote-then-grant re-grants (§5.2: the earlier writes turn valid again), so the hole needs a grant with `until` or similar; a fall that rises again still begins a session, harmlessly. Bound (review): a step needs a fallen write under the current sessions, so an admin flapping the node's role adds at most one session per write the node makes, and holders pay per session only through its writes (frontier entries, `ix.ranges`: as for a restart). Residual (spec/sync.md §9): writes made under the old session after the grant's key but before the node learned of its demotion. Attribution is in the dot: a session names its node.
- `Write` splits ops by key lifetime: durable ops into the `Mutation` (plus chain records and placement conversions of the drafts it persists), ephemeral ops into memory commits, one per (expiry class, thing) (per thing so a deleted thing's commits are unindexed whole by `free`; expiring all-or-none so a commit has one session). One `Engine::run` transaction does the durable `commit_in`, the memory `commit_in`s (`Tx::in_class(true)`: session form, ephemeral marker, retention `writer` without bounds, the records beside each part, no chunks or pages: a delta past a blob is `Misuse` and nothing of the batch applies) and the frees (`free::free` of things the batch deletes that nothing places, `freeable`). Then the undo log is fed from Core (`log_aspects`: the written aspects' fragments and `undo::remembered` footprints) and one `Event::Ephemeral` goes with `ChangeId::Commit` (a batch with a durable half) or `ChangeId::Ephemeral` (ephemeral only). Own memory commits fire no event of their own; received ones do (`apply_verified`, origin not `Local`).
- Reads (`read.rs`) come from Core state (`ephemeral_core_value`, `placed_value`); synthetic aspects and `groups_of` (over `Indexes::placed`, kept by `observe_state` of `placed.0~`) include ephemeral data; `created` reports memory records. Perm: a draft's role through its nearest durable owner (`role_with` over memory records); depth counts the whole chain (`too_deep` walks durable and memory records: `ephemeral_chain_depth_counts_durable_links_spec_permissions_1`).
- Undo: the log keeps per own batch its deltas and the undo buffer of the positions it touched, captured at write time: O(change). Inverse writes follow spec/crdt.md §4.6 against the current state and apply as new memory commits in one transaction (`revert_inner`, the log taken out and restored). Past `ephemeral_history` the oldest entries go. D (issues/eph-unify.md) replaces the log with undo over held bodies.
- Restart: everything ephemeral is gone locally and the next open draws new sessions; syncing brings back what holders kept, own old-session writes included (held like others' commits, compacted by the ordinary trigger).

## Synced ephemeral data: ordinary commits in memory
- **Ephemeral commit.** A commit with the header marker `ephemeral` (plain or relay-only), session form for a writer's own writes or commit form for a memory compaction snapshot (spec/commits.md §2), no `created.0` part: each part carries beside its delta the creation records of the drafts it is on or its `placed.0~` delta places, with their draft chains (self-certifying, unsigned, per blob), signed, encrypted, projected and wrapped as any commit. Every local ephemeral write is one; a batch's ephemeral writes are one commit per expiry class (a deletion's resets ride with the unplacing, as a durable batch's do). Every node keeps ephemeral commits in memory only (the store's memory overlay and Core's indexes, `Engine::holds_memory`); they are never persisted, never in bundles.
- **On the durable sync path** (step C, `core/node/src/sync/memory.rs`): node-sync's passes judge, place, upload, relay and delete memory bodies exactly as durable ones (`label_bodies_meta` lists memory commits; `place` seals with the header's class and stores the blob in the overlay; `Entry::memory`/`BlobRec::memory` keep every sync record about them out of `y/`; a memory commit marks itself changed like any). `Engine::closure(g)` is the closure through `group.0` and `placed.0~` (cached by `Core::placed_gen`). What stays particular (`memory.rs`): the node cap at the one ingest site (`ingest_memory_entry`: room, pending share `PENDING_SHARE`, `unfit`, refused entries fetched again once the label's bytes dropped below what they were at refusal), the restart reconcile (`Memory::reconciled`), presence of memory entries dropped when a connection ends (a restarted host lost them) and learned again by the first Sync's `gained` list (`memory_gained`/`memory_synced`: what the host does not want is present there), coalescing and hold-back before a send (`coalesce_own`: own bodies not yet placed wait while an own upload is unanswered, then two or more of this session's plain writes on one aspect go as one snapshot of their join; a snapshot among them, or a body the snapshot cannot cover, goes as it is: a whole-state re-snapshot each pass spun on a body behind an invalid one), carriers of a dropped memory part read from the engine (`carrier_of` follows `Dropped::covered_by` via `Engine::coverers_of` and forgotten coverers, since the engine's `drop_covered` sets no carrier row; without it a deleter snapshotted the aspect anew every pass), the headers of forgotten memory commits kept while their entries are known (`Memory::forgotten`: deletes at hosts are judged by them; a coverer forgotten before it was placed stands for what covers it, `carriers_of_forgotten`; a coverer the host refused for its cap goes up again replacing the covered entries), a memory entry's tombstone at `MAX_DRIFT` (an announcement of a tombstoned blob is nothing), an upload a host refused for its cap tried again once per resync while the body is held (`SyncEngine::capped` dirties the label at `timers`; durable too), relay-only commits (`relay_in`, `send_relay`, `RelaySeen`). The compaction trigger skips only a thing that was a label entry here and left every closure (a snapshot of it would go nowhere while the covered commit may still travel beside an unplacing); local-only things compact, else a rewritten UI value keeps every body. `freeable` goes by `MemorySync::synced` (a commit on the thing was a label entry here, set at `place` and at ingest). An entry is deleted for being outside the closure only by a node that judged or placed it inside (`State::memory_in_closure`; a restarted node's closure is what has arrived so far, and it deleted window bodies while the placement waited its relay delay, a storm until then: seed 9130016). Deleted: the lane (`sync/ephemeral.rs`: own stamps and restamp, redelete, waiting/orphans/replacing deletes, gained lists, present sets, `eph_*`), `MemorySync::{unsent, parked, kept, applied}`, `take_memory_commits`, the ephemeral closure (kept rows), `OSIS_EPH_TRACE`.
- **At hosts.** The blob prefix gets a class field: durable, `ephemeral` or `relay` (signals), from the commit's marker (spec/sync.md §3). A host keeps ephemeral entries (blob, wrap, stamp, log event, tombstone) in memory only, under a per-label byte cap; past it, upload of that class is refused with the ordinary cap code. A restart loses them. Everything else is the ordinary path: upload by stamp, cursor sync, range reconciliation, subscriptions pushing new entries, expiry, delete keys.
- **Convergence and reconnect.** Ordinary (spec/sync.md §6): a holder bridging two hosts or a co-reader peer serving its own label carries ephemeral state across (another node's body after the relay wait, as for durable). A joiner or restarted node gets the state by its ordinary first sync from any host or peer that holds it; if every host restarted, holders upload again (presence is per connection). Residual (spec/sync.md §9, as durable's spec/permissions.md §5.2): a write covered by a snapshot that fell invalid comes back only from a writer still holding it; readers lose their entry of it with the host's deletion.
- **Compaction.** Ordinary compaction snapshots of one `~` aspect, in memory (Memory commits below): any writer whose held bodies of the aspect cost more than `FACTOR` times a snapshot makes one; covered bodies are dropped at once by every holder, an author's own only by its own snapshots; a host's cap refusal triggers nothing.
- **Signals.** A signal write is a delta in an ephemeral commit marked relay-only (the sync engine puts signal deltas in their own commits; prefix class `relay`). A host (or co-reader peer serving the label) accepts it by stamp like any upload, pushes it to the label's current subscribers and holds nothing: no entry, log event, tombstone or expiry, so it never reaches a later sync. A node verifies it like any commit, delivers each signal part to callbacks once and holds nothing (no state, no body, never relayed or re-uploaded). The same signal arriving over two hosts is delivered once: a node remembers delivered relay-only commit IDs until their `ts` is `MAX_DRIFT` old, and drops relay-only commits older than that (their only replay window). The blob's prefix expires at `ts + MAX_DRIFT`: hosts refuse it after, push each blob ID once until then, and rate-limit relays per label; receivers drop a blob seen before unopened. Within that hour a signal can arrive late (a delayed push), and a restarted node can see one again if a replayer uploads it to a host that forgot it.
- **Validity, ordering, replay**: ordinary commit rules (chains, parking past `MAX_DRIFT`, idempotent apply). A replayed old ephemeral commit only re-adds writes its stamps already lose to, or that holders still have.

## Expiry
- Expiry is death by timer (spec/crdt.md §4.8): the values die at T and the body follows, whatever the deltas' keep bounds. "Keep at least until T" is a retention bound (spec/commits.md §5), a different thing.
- Covers disappearing messages (write-based timer in core; read-based timers and earlier deletion are app writes; core expiry is the hard upper bound and lets a host wipe them unattended) and buffered events (a list aspect with a one-hour default). Cheaper than keep-at-most 0: nothing has to be deleted by hand, and the host does it unattended.
- Leak accepted by Tess: a host learns which entries expire and when.
- Not provided: host-enforced minimum retention (legal hold). Keep-at-least binds honest nodes; a host deletes whatever a delete key or its label delete key tells it to.
- **Ephemeral expiry vanishes whole** (coordinator decision, round 13, option (a) of the deleted issue eph-churn-oracle-seeds; spec/crdt.md §4.7 Ephemeral data): at T an ephemeral delta's writes all go, resets and removals included, at every node and for its author, as if never applied; an expiring removal stops removing at T. Durable data keeps its value-less records. Why: value-less leftovers lived only in the state of nodes that held the commit at T (a rebuild, a late joiner or the author's own copy differed), and ephemeral data has no carrier for them (only an author covers, never expiring writes, and nobody may re-serve the body after T). Built in Core (`retention/memory.rs` `vanish`): a memory delta at T drops its body and the aspect is rebuilt without its writes (`rebuild_without`), its commit forgotten once spent. **Invariant** (module doc): a memory aspect's state is the join of its valid held parts, so two nodes holding the same ephemeral commits read the same, whatever expired when. Superseded writes (below) vanish the same way. Consequence: a write into an entry an expiring write created outlives that entry (the entry's record repeats the key, and a map record lives by its content, spec/crdt.md §5.6), so a writer gives such a write an expiry no later than T. Undo of an expired batch writes its inverse as usual (a removal re-added with a fresh dot, a register untouched since its write is not the winner): convergent. An undo copies back no expired content (`undo_expiring` strips it from the pre-state and reruns until none is copied: one strip let a `Set`'s undo restore a shadowed older entry's expired value at the key, churn seed 79, `undo_of_set_past_expiry_restores_no_shadowed_entry_spec_crdt_4_6`). Test `ephemeral::expired_removal_vanishes_everywhere_spec_crdt_4_7`.
- **Expiry never waits for a Tick** (durable too): a Tick comes late (`MIN_WAKE_MS` throttle, a suspended process; in the node test net an offline node gets no events at all), so the osis handle runs `SyncEngine::expire_due` before every call under its lock: when `Engine::timers_due` (in-memory: `Core::timer_floor`, a lower bound of the earliest durable timer, and the ephemeral timer map) it runs the Tick's engine part (live-drop snapshots, `tick`, `tick_ephemeral`). Pushed change events still come with the Tick (up to `MIN_WAKE_MS` late) or the next call: a subscriber's last value can show past T until then. Tests reading through the engine directly call `expire_due` first (`random_churn_run` checks every step that no value is read at or past its expiry; issue eph-expired-value-read-again, seed 7134: node 1 offline past T).
- On ephemeral writes expiry runs in memory (typing indicators: `expires_in(5 s).set(true)`); a value that lives while its author is there is one renewed by its author (below).
- Nothing is kept "until every receiver has seen it": the receiver set is open and nodes die. What must survive every holder forgetting it (restarts) is durable state: the inbox pattern (receiver-owned list, senders append, owner deletes, expiry as backstop) or a list with expiry.

## The all-nodes predicate
"All nodes a thing syncs to" is a state predicate computable at nodes that read the label, never a protocol condition. Per label: the nodes with a valid chain that published `node.0` under the thing's label (not "every node of every holder", which needs rosters readers never see).
- Recency: each node places an expiring `seen.0` heartbeat under each label it tracks (spec/permissions.md §4); the live one's value is its last sync of L, absent means unknown. `seen.0` is one aspect of the node thing, so its joined read is "last seen anywhere"; the per-label answer comes from the sync layer's record of which heartbeat commits arrived under L, not from the aspect. (A `map<label ID, timestamp>` would give aspect semantics but leave a value-less entry record per expired heartbeat forever.) The heartbeat also carries `stranded`, the one signal a device that cannot open a label's current epoch, or cannot walk to the head because a claim set was dropped, can still send (it deposits without opening the label, under the newest established read secret it holds, which co-readers open by history boxes), and what triggers a re-seal; it is placed only after a complete pass at that host (the rotation commits are uploaded before the step, notes/sync.md, so "cannot open" means not boxed, never "not fetched yet"); it fails only when the deposit key changed under it (issues/reseal-triggers.md). The device list (the node card) and recency are separate aspects because an expired register winner reads as absent and the older write does not show through: an expiring re-put of `node.0` would drop the node from the device list when it lapsed.
- Why a durable heartbeat and not a node-card re-put or ephemeral data: a reader's re-put is a deposit that sits in the label's budget until a writer promotes it, so readers × cadence × promotion delay had to fit a budget the spec never sized, and a full budget refuses the deposits that matter (grants into the group, a reader's self-removal, a revoke only readers hold). Expiry frees the budget unattended (no tombstone, no delete, no writer), so a reader holds at most ceil(lifetime / interval) entries at once and the budget is sized from the claim set (spec/sync.md §5). Rejected: deposit new card plus token-delete the old one (a delete and a 30-day tombstone per refresh, reader-side delete flows, rate-limited deletes); ephemeral writes (the asker is rarely online with the reader, and readers cannot write ephemeral data); host arrival times (untrusted, per host).
- Leak accepted by Tess: a host sees each reader's heartbeat rhythm per label (same class as deposit and expiry times it already sees). Clock skew between the heartbeat's writer and the asker shifts the reading by the skew; lifetimes are days, so no coarse policy notices.
- A node reading the label keeps its own local record of the last heartbeat it saw per node, for policies wanting a longer memory than the lifetime; it is a lower bound, not knowledge of the gap.
- Uses: write a new schema form once every node reads it (fixes the read-only old app the header heuristic cannot see), drop old-form history after that, clean up an inbox once every own device has acked.
- Dead nodes: a lost phone's heartbeat lapses and it drops out of "all nodes seen recently" on its own; a policy that needs it gone from the device list too waits for an explicit node removal. Never gates deletion at hosts.
- "Buffer until all have seen it" = inbox pattern plus this predicate plus expiry as backstop. Fine as a core helper later; not sync machinery.

## Step 1 as built
Module `core/engine/src/ephemeral/` (`Eph` owned by `Engine` beside `Core`); `Engine::write` is the split (`Engine::commit` stays the durable-only path flows use). Tests: osis `tests/it/ephemeral.rs`; schema `parse::validation_rules`.
Decisions where the design was open:
- `ChangeId`/`EphemeralId` came with step 1 (an ephemeral-only batch needs a `Committed` id and a watch source); `revert` takes a `ChangeId` (ephemeral ones since step 2's undo log).
- Expiry classes: the own writes joined per expiry time (`EphAspect::own`) plus the session counter ranges of each; at T the class goes and the aspect is rebuilt (Expiry above); the ranges stay as expired, so a later own write repeating one of their records has it taken out.
- Timers: `Engine::tick_ephemeral` and `next_ephemeral_timer` beside `tick`/`next_timer` (retention/ untouched); node-sync's Tick calls both and `next_wake` includes it.
- Node-sync subscribes with `subscribe_durable` (no `Event::Ephemeral`), the osis handle skips `SyncEvent::Local` after ephemeral-only events, and node-sync ignores an Expiry `Changed` naming only ephemeral aspects: a local ephemeral write costs the sync engine nothing.
- `delete`: per aspect a durable remove when a durable delta is held, else an ephemeral reset (an aspect on both sides loses its durable side only); freeing scans the drafts for owned ones (O(drafts)).
- A new draft needs the role its creation would need (checked at write, like `created.0`).
- `grant`, `make_link` and `sync` persist a draft target first (`Osis::persist`, a content commit of its own).
- An ephemeral-keyed raw write of `group.0` stays `Invalid`; `placed.0~` is written by group ops only.
- The rights check (perm timeline role per write) is the largest cost part and trivially cacheable per (thing, roster generation) if a budget ever needs it.
- Not built in step 1 (still open): text sessions committing each edit at once on ephemeral aspects (they idle-commit like durable ones, harmless); requirements.md's Ephemeral data section (with step 3: it is about sync).
- Cost (release, `tools/icount`, `ephemeral::bench_*`, setup subtracted): a local ephemeral set through a `write()` batch on one aspect about 15.7k instructions (engine `write` alone about 14k: rights check about 4.6k, ops and join about 5k, events about 3k), a `BTreeMap` insert 316, a durable set 5.3M. So about 50x an in-memory map and 340x cheaper than a durable write; the rights check (perm timeline role) is the largest single part.

## Step 2 as built
Modules `core/engine/src/ephemeral/place.rs` (placements) and `log.rs` (undo log); osis `commits.rs` over both sources. Tests: osis `tests/it/ephemeral.rs` (placements), `tests/it/ephemeral_undo.rs`.
- Split (`Engine::place_plan`): durable-keyed `group.0` writes are taken out of the batch and split per op. A member add is durable iff the member is durable after the batch; a member remove iff member and group both are; any other op (a raw root op) iff the group is; an op that is not durable goes to `placed.0~`. What persists is a fixpoint: owner-chain closure of the things with durable aspects or `persist`, plus groups getting a durable add, plus groups the persisted things' ephemeral placements convert into (when the node may write them), until nothing grows.
- Conversion: per placement a durable add (items or subgroups) into the group's durable `group.0` delta, with the placement's expiry (found by stripping the aspect's expiry classes in turn until the element goes; a class already past its time skips the conversion), and a `placed.0~` remove, not logged for undo. Two conversions into one group with different expiries in one batch are `Invalid` (persist separately). An unplace of the item from that group in the persisting batch wins: only the ephemeral reset is written. A persisting thing that is a group ephemerally gets `Set(Group::default())` first in its durable `group.0` ops (groupness persists, its drafts do not). A group the node may not write keeps the placement ephemeral: `DiagnosticKind::PlacementNotPersisted`, tids `[item, group]`, after the commit.
- Reads: `Eph.defs` caches each group's `placed.0~` read field by field; `Engine::groups_of` (and `groups.0`) is the union of the durable index and these, climbing subgroup edges of both; `durable_groups_of` is the durable side (node-sync's `groups_holding`). The closure sync uses stays durable-only until step 3. An ephemeral reset of a durable element (raw path op only) is not reflected in `groups_of`.
- Freeing a thing also removes its (and its owned things') ephemeral placements, by resets.
- Not reported: `NotSynced` for drafts (filtered in osis `not_synced`).
- Undo log (`Eph.log`): per own batch with ephemeral writes (fast-path durable batches log nothing) its id (the commit for a mixed batch), `reverts`, actor, ts, and per aspect delta, counter range, `footprint` of the pre-write joined state, schema. Byte size = `Fragment::approx_bytes` of delta and footprint plus the entry's own size (encoding them cost about 31k instructions per write, `approx_bytes` a few hundred); `approx_bytes` counts heap structure (a `BTreeMap` node per small map, boxes), within a few percent of measured RSS growth per logged write (an int set about 1.9 KB, a two-entry map set about 12.5 KB; counting stamps and values only had it 6-16x low); past `Config.ephemeral_history` (osis `Config`, default 16 MiB, engine `Config` too) the oldest entries go; an ephemeral-only one is remembered per aspect (newest ts and id, and whether it was a revert), bounded by the aspects held. At 0 nothing is undoable.
- `Engine::revert_change(id, actor)`: the log entry's inverse writes (`osis_crdt::undo` against the joined state, the footprint as buffer, `restored` judged over the log), then for a commit the durable undo commit at the same `ts` (`undo_in` takes it), then one ephemeral batch logged with `reverts`. Returns `Reverted::{Written, Superseded, Compacted}`; an ephemeral id from another session or node is `Misuse` (osis `Invalid`). A mixed batch whose ephemeral half left the log reverts its durable half only (as after a restart).
- Commit query: entries keyed by `ChangeId`; a logged change joins its commit's entry or, ephemeral-only, is `CommitKind::Ephemeral` (changes and reverts alike; `reverts` tells). Relations (`reverted_by`, in effect, depth) over the related commits plus the whole log. `CommitQuery.reverts/reverted_by/after` and `CommitEntry.reverts/reverted_by` are `ChangeId` (builders take `impl Into<ChangeId>`); `Error::NotUndoable.commit` is a `ChangeId`. Redo's "no newer change" test uses depth > 0.
- Scope: `Thing`/`Group` cover held durable aspects plus `Engine::ephemeral_scope_keys` (every ephemeral key of a draft; a durable thing's `placed.0~`). Undo first checks the newest dropped ephemeral batch in scope: newer than the chosen target is `NotUndoable{Compacted}` (redo: a dropped change gives `None`).
- Cost (release, `tools/icount`, `ephemeral::bench_ephemeral_sets`): a local ephemeral set about 19.8k instructions, was 15.7k before the log (footprint, delta copy, log entry, the placement split).
- Undoing a creation deletes (spec/crdt.md §4.6): log entries record the drafts a batch made and deleted (`log::Making`); `revert_change` deletes what the change made (a commit's `created.0` things via `undo::unmake` in `undo_in`; their ephemeral side and a logged batch's things still drafts via `unmake_ephemeral`: aspects reset, entries removed from `placed.0~`) and brings back what it deleted (`EphThing.deleted` cleared; it is never freed meanwhile, so redo can restore it). `ephemeral_log` lists `(t, created.0)` for made and deleted drafts and `ephemeral_scope_keys` covers it, so a Thing scope sees the creation.
- Undo over `placed.0~` and deletions (ephemeral-revert-diverges, `ephemeral::ephemeral_reverts_within_rights_alike_*`):
  - A revert's writes on several things are one memory commit, the only kind that spans things: its thing's reset rides beside the placement's removal (since step C every batch's memory commit spans its things); the pass places a commit's bodies under a label holding any of its things, each body the label's actor may read.
  - `placed.0~` never takes "Absent before": a root reset of it, reverted later, was a `replace` that threw out every item placed since, and those things then synced no more.
  - An undo whose deletion also writes the `placed.0~` its inverse writes continues that delta (`Writer::resume`): a second delta stamp was the `commit-level write off the delta stamp` refusal.
  - A revert flips a thing's deleted mark only if it changes it: reverting a second undo of a creation does not bring the thing back while the first stays in effect.
  - A commit on things in no labeled closure is held and goes nowhere until a closure holds one of them (the passes judge the closure's commits again when it moves, spec/sync.md §3); a thing no group lists any more syncs no more (kept rows, which kept it syncing under the labels a commit on it was kept under, went with step C).
- Undoing a save returns the draft (exact undo: the draft existed before it). `Making.saved` records the drafts a batch saved (made earlier, persisted by it; a save always takes the logged path) and `undo_in` gets them as `Mutation::undo_keep` (not deleted). The conversion's ephemeral placement reset is logged, so the undo puts the ephemeral placement back. The record stays durable: the thing goes in `Eph::drafts` (memory only, one entry per own undone save, with a deleted flag), which makes it known (even without content), counts as a draft for the Thing scope (its ephemeral aspects and `created.0`) and for deleting it by undoing its ephemeral creation. Its next durable write saves it again (`Placed.saved`), and redo, a new save or `delete` takes it out of `drafts`. With no log entry for the save (another device, compacted, restarted) its undo deletes instead. Placements: `place_plan` converts the ephemeral placements of every durable thing a batch writes durably, not only persisting ones (a restored draft after a restart gets its ephemeral placement back from the host with no `drafts` entry; also a placement made ephemerally while the thing persisted elsewhere), and a durable unplace also removes the item's ephemeral element (exact: placing a durable thing is a durable add that persists the group, so every ephemeral placement of a durable thing was made while it was a draft, or restored by undo; test `durable_thing_into_ephemeral_group_persists_it`); `ephemeral_placements` scans `defs` per written thing, skipped when `defs` is empty. After a restart a restored draft reads like a deleted thing unless its group synced (then its ephemeral content and placement come back and it reads as a placed thing; node test `ephemeral_placement_of_durable_thing_converts`).
- A persisting draft group's empty `group.0` set takes the expiry of the conversions into it (an empty group has no value for expiry to remove, spec/crdt.md §4.7); a placement that does not convert (unplaced by the batch, expired) persists no group.
- Open: node-sync treats an ephemeral expiry on a durable group's `group.0` (an expiring ephemeral placement) as a durable change (`only_ephemeral` is false there); harmless, a wasted check. Role ops still persist their target by a commit of its own first (`Osis::persist`), which now also converts its placements. The CLI refuses `create --in G`/`--group` without durable data (the thing would vanish at exit).

Decisions where the design was open or turned out differently:
- **When**: the osis handle shows the sync engine a Local event when `Engine::has_unsent()` (own writes noted since the last take); node-sync's step builds (`take_ephemeral_if`) and sends, coalescing (Coalescing below).
- **Holders bring what a peer lacks**: the first Sync of a label on each connection lists the held lane entries as `gained` (≤ `MAX_GAINED`; more are reconciled first and only what the peer lacks goes up); the peer's want-list goes up. At most one upload of an entry is in flight per connection, and a status for a lane entry never reaches the sync records (a second status once marked a fetched ephemeral entry durably present, so the next restart's reconcile listed it as held and never got it back; found by the randomized differential). An entry received from one host or peer is uploaded at once to the others where the label is open and it is not known present (a writer stamps every entry it uploads with the connection's write key, others' included; a reader relays the stamp it got, and only one verifying under the head counts on arrival). A waiting entry verified later (`eph_promote`) counts as present only where `present` already says (marked at arrival, cleared by `eph_lost`): taking the host it waited on as present, and the old stamp as good, left a demoted-then-promoted author's commits at no host once both hosts had restarted (random churn 154 and six more seeds; invariant on `eph_spread`, test `ephemeral::promoted_after_hosts_restart_reaches_hosts_spec_sync_6`). No relay delay: every holder bridging two hosts sends it (duplicates answered OK, an open cost item).
- **Restart**: the first sync of a label at a host after a start reconciles the live sets and keeps the cursor (`Memory::reconciled`, `reconciling`): the ephemeral entries the persisted cursor already passed come back as `need`. Not after a cursor-less replay, not on reconnects within one run. Marked done when the reply arrives (a connection ending first reconciles again; one ending with any of the reply's fetches unanswered too, and a refused one of them, `reconcile_fetches`: nothing else names an ephemeral entry the cursor passed, so it was never asked again, inflight seed 100013); a Push during it keeps no cursor, as during a Sync.
- **Host**: ephemeral entries, their blobs, log records and tombstones in memory (`Ephemeral` in `HostStore`); log sequence numbers shared with the durable log, reserved on disk in blocks of `SEQ_BLOCK` (1024) in the label meta's `reserved`, so a restart never reuses one (a cursor ahead of the durable log stays valid). Caps `HostPolicy::ephemeral_bytes` (16 MiB per label) and `ephemeral_total` (1 GiB): code 12. Deposits of ephemeral or relay-only blobs: code 1. In-memory log trimmed at `EPH_LOG_KEEP` (2^16) records per label (cursors below get the live entries). `Rate::Signal` and the `signals` knob are gone; relays are rate-limited by `RelayGate` (security review fixes below).
- **Signals**: relay-only commits built per actor from the signal writes of the batch; hosts and co-reader peers push them, never store them; receivers deliver valid parts once (`delivered`, `MAX_DELIVERED` 2^16 with a floor per author, dropped past `MAX_DRIFT`; remembered per (commit, part): a commit whose parts have different readers goes as several blobs, and dedup by commit dropped all but the first, test `ephemeral::signal_commit_in_several_blobs_all_delivered_spec_sync_5`); a node's own fire locally as before. No targeting, no `on_signal_in` (a group-wide signal is a signal aspect of the group thing).
- **Pre-existing bug found**: the replay cursor's position (first 8 bytes of a blob ID) overflowed the wire's 2^63 integer limit for IDs starting at 0x80 or above and replayed a page twice; it is now the first 63 bits (spec/wire.md §11.2).
- **Security review fixes** (after step 3; report and fixes on branch `ephemeral-sync`): relay-only prefixes expire at `ts + MAX_DRIFT`, hosts and co-reader peers admit relays through `osis_proto::RelayGate` (expiry window, `MAX_RELAY_BLOB`, per-label rate, push once per blob); receivers drop relay blobs unopened when oversized, outside the window or seen (`RelaySeen`, floor past the bound). The host engine refuses unstamped ephemeral and relay-only blobs for every store (a co-reader peer's store did not). Host ephemeral memory counts per-entry, per-record and per-tombstone overhead, ephemeral deletes and replacements are rate-limited, due times are indexed (sweep budgeted), the label using most gives way at the total cap, and the durable log is trimmed by its own record count (ephemeral churn no longer sends durable cursors to reconciliation). Node: only commits the engine verified and holds are kept, served and spread (far-future dropped; unknown authors wait apart, `PENDING_SHARE`); a replay of a covered commit is not held again and a writer deletes it; a removed holder's writes laundered by an honest compaction (fixed then by judging carried writes as their attributed node's; gone with own covers, which carry no other node's writes); parts on core aspects but `group.0` are invalid; pending commits are retried only when a record they wait for arrives; held entries beyond a Sync's `gained` list are reconciled instead of uploaded whole.
- **Final review fixes**: a relay-only blob is checked against `RelaySeen` before opening but recorded only once verified (a host's keyless junk past `RELAYS_REMEMBERED` raised the label's floor and dropped every real signal for two hours); the engine's delivered floor is per author (one flooding writer dropped every group's signals); another blob of a held commit has its signature and delta hashes checked before it is kept (a header with junk parts was kept and served); the capped-host compaction rules that followed (`forced`, `own_full`, the room condition, the stuck-entry no-churn rule) are replaced by own covers (below).
- **Routing point**: node-sync routes by the blob's prefix class in one place (`eph_added`, from `log_events`): a blob with ephemeral bytes is the lane's, and any sync record an earlier announcement without bytes made for it is dropped (`State::forget_ephemeral`; such a record made a restart count the entry as held). Statuses of lane uploads and deletes stay keyed by the lane's in-flight sets.
- **Co-reader peers and signals** (open question of the step 3 review, decided): a co-reader peer serving a label passes a verified new relay-only commit on (from a host to its sessions, from a session to its other sessions and the label's hosts), each blob once (`RelaySeen`); a device reachable only through a co-reader peer gets the signals and its own reach the host's devices.
- **Same-stamp substitution** (review M3): fixed by the copy order of spec/crdt.md §4.1 (notes/crdt.md, Known anomalies); forged map keys are two entries (spec/crdt.md §5.6), forged text creation `ts` copies of one creation (§5.7 Join; notes/crdt.md Known anomalies); a map residue case remains: issues/forged-key-erased-reset.md.
- Open (step 3 scope, deliberately not built): a node that stops syncing a label or loses read access keeps that label's ephemeral state until restart; ephemeral deltas are never paged and must fit a blob (8 MiB; a too large one is not sent, `EphemeralRefused`; issues/eph-unpaged-cover.md); relays are not delayed (duplicate uploads by every bridging holder).

## Values that live while their author is there
Tess's decision (round 13): presence is not a lifetime of its own. A value that should live only while its author is there (a cursor, a selection, an "online" mark) is an ephemeral aspect with a short default expiry (`~` key, `[expires: 30s]`) whose author rewrites it before it expires; when the author's device goes away the rewrites stop and the value is gone at every holder and host by its last write's expiry. Nobody needs to notice the departure: no connection tie at hosts, no source tracking or un-merge at holders, no lease or keep-alive constant.
- **Helper**: `db.at(t, k).path(p).keep_alive(&value) -> KeepAlive` writes the value and rewrites it every `expiry / REFRESH_DIVISOR` (2) of the key's default expiry on the handle's runtime until the `KeepAlive` is dropped; `KeepAlive::set` writes a new value at once. The key must be ephemeral with a default expiry. A rewrite is a `Put` (a fresh entry at a map key, a fresh register write elsewhere): a `set` of an equal value writes nothing, and a write into an entry an expiring write created outlives that entry (Expiry above) unless it expires no later. `Replace` would not: at a live key it writes into the old entry and goes at that entry's expiry.
- **Cost**: each rewrite or `set` supersedes the write before it (Superseded expiring writes, below), so a holder and a host hold about one commit and entry per kept value, and one upload goes per value per half expiry or per round trip while it changes (`ephemeral::moving_cursor_one_entry_per_author_spec_sync_9`: 60 moves, one entry; was 60 before; 30 moves a second at a 30 s expiry was about 900 per author). Left: an expiry under the sync tick (1 s) still rewrites every half expiry, one upload per rewrite, while expiry is applied only per tick.
- Two devices keeping one path alive overwrite each other at every rewrite: key by device (`Osis::node`), not person. Nothing survives a restart: the app calls `keep_alive` again.
- **Choosing the expiry** (the schema's, per aspect): how long a departed author's value lingers against the rewrite traffic. 30 s suits cursors.
- **Write-level "until the author disconnects"** (Tess's idea, evaluated): it needs exactly what this replaced (a host tie per connection, holders tracking which host or peer still has the author's entry, un-merge when none does, a lease backstop for half-open connections), and "disconnected" is per path, so holders behind different hosts disagree. Not built.
- Tests: osis-node `ephemeral::refreshed_value_lives_while_author_present_spec_crdt_4_7`; osis `runtime::keep_alive_rewrites_until_dropped`; sim `ephemeral`/`ephemeral_capped` (random expiring cursors; `author_leaves`: a refreshed cursor at every connected holder before each refresh, gone past its expiry once the author is down).

## Superseded expiring writes (as built)
Snapshots never carry expiring writes, so before this a cursor kept alive with `KeepAlive::set` (a fresh map entry per move, `Op::Put`) cost one commit, upload and entry per move until each expired (issues/eph-expiring-churn.md, deleted).
- **Rule** (spec/sync.md §9, `retention/memory.rs` `supersedes`, `drop_superseded`): a held plain commit whose parts all expire and carry no reset is dropped once each part is superseded by a valid held part of another plain commit of its author on the aspect: that part expires too, no earlier, carries no reset, each of its writes is stamped later than every write of the old part and none is a write into a record it did not create (a `Set` into the entry a move created goes with that entry), and the old part joined into it reads as it alone. Core keys alike: a `placed.0~` part is superseded as any (an exception there in `eph_superseders`, never in `note_written` nor the spec, read a placement placed again after an expiring unplace expired, where a conforming node did not: `placement_superseded_like_any_write_spec_sync_9`). Checked at every node when a commit is held (own builds included), each candidate costing a join and two reads of two small deltas; a received commit superseded on arrival is not held (`Dropped`).
- **Not death, but convergent** (spec/crdt.md §4.8; review): an older `put_new` entry at a key stays live in the CRDT, only shadowed in the read; the rule makes it expire early instead. Convergent because the drop is a function of the commits held, never of later writes: every node holding the newer part valid drops the older (at its arrival, at the newer one's, or when the newer turns valid, `rejudge_ephemeral`), and a later removal or undo of the newer entry kills only that entry everywhere. Two holes the review closed: the author kept the dropped writes in its own writes (and the unsent ones `note_written` dropped), so after a holder removed the newer entry only the author read the old one again (`superseded_stays_gone_when_newer_removed_spec_sync_9`); and a superseding part with a reset made the relation intransitive (q replaces the aspect over p, r later puts without the reset: r supersedes q but not p, so p was dropped or held by arrival order), so a part with any reset supersedes nothing (`Fragment::has_any_reset`). Review 2 (randomized `ephemeral::random_churn_converges_large`, 300 seeds) closed two more: a superseded part with a reset (a removal of another key beside the move) took its tombstones with it at holders but not at the author, so the removed entry read again everywhere but there; and a plain superseder was absorbed by a cover that supersedes nothing (it carries older writes of the aspect), so a node that got only the cover held the move and read it again once the plain entry was removed (`superseding_part_expires_spec_sync_9`). Now neither part carries a reset and the superseder expires (so no cover ever absorbs it). A `Set` into another's entry outliving it reads alike everywhere since an expired or superseded delta vanishes whole (spec/crdt.md §4.7): the `Set` reads alone as at a node that never held the entry (`set_into_expired_entry_reads_alike_spec_crdt_4_7`); the oracle writes `Set` again. Real death was weighed and rejected: each move would have to tombstone every own entry of the key not yet expired (about expiry / round trip of them per commit, 450 at 30 s and 66 ms), since dropping a commit drops its tombstones too. Left: a superseder turning invalid later does not bring the dropped commit back (a memory part's late copy is refused, `retention::takes_late`; durable keep-bound drops join again, spec/commits.md §5). The ts order and the expiry guard keep the drop exact otherwise: a later write expiring sooner, or an older write with an equal value, supersedes nothing (`superseding_needs_later_stamps_and_no_reset_spec_sync_9`).
- **Holders and the author** forget the superseded commit whole (`unindex_commit`, reported to the lane as `MemoryDrop::Superseded { by }`) and rebuild the aspect without it (as at expiry). An own commit superseded before the lane took it is forgotten the same way, never sent: a burst of moves during one upload goes up as the last one.
- **Deletes**: the lane deletes a superseded entry where a superseder is held (`eph_forget`, as a covered one's), else at its expiry.
- Measured (tier-1 `Net`, 66 ms round trip, 10 authors moving every 33 ms for 1 s): 160 uploads, 0 deletes, the host's peak 43 KB of a cap scaled to 560 KB, one entry per author at the end; without the rule 224 entries (364 without the unsent part too); a simulated minute at the default policy (tier 2, 17 min dev at load 6-12): 9100 uploads, 0 deletes, peak 1.76 MB of the 16 MB cap.
- Tests: osis-node `ephemeral::{moving_cursor_one_entry_per_author, superseded_unsent_moves_one_commit, superseding_needs_later_expiry_and_own_records, superseding_needs_later_stamps_and_no_reset, superseding_part_expires, superseded_stays_gone_when_newer_removed, many_authors_under_host_rates}_spec_sync_9` (4 authors), `many_authors_under_host_rates_large` (tier 2: 10 authors for 1 s, then a simulated minute). `random_churn_converges_spec_sync_9` (4 seeds) and `random_churn_converges_large` (tier 2, `OSIS_EPH_START`/`OSIS_EPH_SEEDS`): random expiring and plain puts, removals, replaces, undos, demotions, partitions and restarts; holders never demoted read alike.

## Memory commits (eph-unify B2, as built)
Replaced own covers, the lane's own machinery (`Remote`, `Eph` state, held parts, absorbed lists, containers, caught-up, restamp of covers) and the separate joined read: ephemeral data is Core's memory class end to end (issues/eph-unify.md Step B2 as built). What stays special: memory storage (the overlay), the second session for expiring writes, vanish-whole expiry and superseding (above), signals, the restart reconcile, the caps.
- **Writes** are memory commits (Local engine above). **Receiving**: the lane hands every ephemeral blob to `Engine::ingest_memory(bytes, room)` (`eph_added_with`) and routes on `Ingested`: `Applied` kept as an entry, `Duplicate` kept once `parts_genuine` (a copy carrying the held parts' bytes), `Pending` kept apart within the share (else `forget_pending_memory`), `TooLarge` refused and reported, `Parked` dropped. Charge per entry `memory_charge`, bound before decode `memory_bound`; parts are judged like durable ones (spec/permissions.md §5.2: validity by the author's timeline at `ts`, depth over the whole chain, class by the key's marker), applied atomically, un-merged by demotion.
- **Core reports to the lane** (`MemorySync`, drained each `eph_step`): `take_memory_applied` (every memory commit applied, for promotion of waiting blobs), `take_memory_commits(busy)` (own commits to place, hold-back and coalescing below), `take_memory_drops` (commits forgotten, with `MemoryDrop::{Covered { by }, Superseded { by }, Gone}`: the lane forgets their entries and, as a writer, deletes them per label once a coverer or superseder is held there, `waiting`/`orphans`/`replacing` as before; `Gone` deletes at once). `take_memory_invalidated` (aspects a held memory snapshot turned invalid on: a writer still holding a valid part writes a fresh snapshot of what it holds, which the lane uploads as a new commit (the authors' own writes, kept under others' snapshots, come back to hosts and readers this way: a demoted compactor's snapshot had covered everyone's entries at the host and writers deleted them there, and a re-upload of those would meet the host's delete tombstone; `compacted_write_of_removed_holder_stays_spec_permissions_5_2`; gated on a valid-to-invalid flip of a held snapshot, so only a role change triggers it, at most one snapshot per writer and aspect per step; an author that restarted or never held the fallen snapshot valid does not, and its covered write stays gone at readers until it writes again, stated in spec/sync.md §9), and the lane reconciles their labels so holders' copies of what it covered come back, `eph_reconcile_thing`). `take_memory_drops` also frees received memory things no commit is on any more (`free_unused_memory`: records do not pile up).
- **Snapshots and covering** (`retention/memory.rs` `drop_covered`, `retention/snapshot.rs`): a memory compaction snapshot is commit form, ephemeral marker, the aspect's whole state at that node (every author's writes, frontiers over every session, expiring deltas neither carried nor covered, `Absorbed` for by-ID commits), retention `writer` without bounds, records of its thing and the placed things beside it. **Covered drop rule** (code comment in `drop_covered`, coordinator decision 1): a body whose author is this node is dropped as covered only by this node's own snapshots; any other author's body drops under any valid held snapshot covering it. So a demoted compactor's snapshot falling invalid (its demotion lists no memory commit) loses at most the demoted author's own writes: every other author still holds its own bodies and re-uploads them when the lane reconciles (`memory_compactor_demoted_keeps_others_writes_spec_permissions_5_2`, `snapshot_invalidated_by_self_removal_reads_alike_spec_permissions_5_2`, the old eph-cover-invalidated hole). Of covered-equal snapshots the higher ID goes. `covered` checks the frontier before decoding (decision 5). No receipts for memory commits (decision 4). A snapshot turning invalid is durable's residual (spec/permissions.md §5.2): the copies come back by reconcile, a forgotten body not held elsewhere is gone.
- **Trigger** (`Engine::memory_compactions(force)`, each `eph_step` before taking): per memory aspect changed since last weighed (`MemorySync::dirty`), with two or more held non-snapshot, non-expiring bodies costing (`held_cost`: `part_weight` plus `ENTRY_CHARGE` each) more than `FACTOR` times the snapshot's cost (`snapshot_cost`, measured by encoding), `compaction_snapshot` if this node may write the aspect; weighed only when the held cost passes the factor times the cost last weighed (Bounds). Counted are only the bodies a snapshot built now would cover (`frontiers_now`): a session's bodies behind an invalid or missing one of it stop its frontier, so they are held uncovered (and not counted, else the trigger fires every step) until that body is valid and held here; one invalid for good makes its author begin fresh sessions (Local engine), so nothing later piles up behind it (spec/sync.md §9 states the residual). Snapshots are not counted as bodies (two writers each keeping their own snapshot under decision 1 otherwise re-snapshotted each other forever), nor bodies a snapshot built now would not reflect (`retention::frontiers_now`, the snapshot build's own frontier walk): a session's body behind an invalid one (a hole no frontier passes, spec/crdt.md §8: the snapshot does not carry its writes) stays held until that one turns valid, and counted it made the trigger fire on every step (`invalid_on_arrival_held_once_valid_spec_sync_9` hung). Any writer compacts: concurrent snapshots are covered-equal duplicates, dropped by rule. `force` (`compact_ephemeral_now`, tests) snapshots every memory aspect with a body.
- **Coalescing** (`coalesce_own`, before a pass sends under a label): own memory bodies not yet placed under the label wait while an own memory upload under it is unanswered on the connection; then two or more on one aspect go as one snapshot: of their join alone when all are this session's plain writes (`Engine::coalesce`: frontier `{own session: up to the last of their counters}`), of the whole state when a snapshot is among them (`Engine::snapshot`), covering them at every holder. Decision 3 asked for one delayed commit instead: not possible without restamping, since a writer delta's commit-level writes must carry the delta's stamp (spec/crdt.md §3.3 rule 7), and several commits' writes have several; a snapshot carries foreign stamps, and its frontier makes it exact. Expiring writes are never coalesced (superseding thins them). Signals are not held back. Measured as before: one entry per aspect per round trip.
- **Signals** (`ephemeral/signal.rs`): a batch's signal writes become one relay-only commit per actor (`take_signals`, snapshot deltas, records of the drafts beside); `ingest_relay` verifies, judges the author's write role through non-durable records (carried or held memory ones) and the durable thing's timeline, delivers valid signal parts once (`Delivered`: `MAX_DELIVERED`, per-author floors) and holds nothing.
- **Decode**: memory parts decode with `osis_crdt::Unpaged` everywhere (`judge_part`, `stream_stored`, `examine_stored`, pending strip, relay), so a value of any size up to a blob is inline; `MAX_PAGE_ITEMS` binds durable deltas only (spec/crdt.md §8).
- **API layer (osis)**: this session's own memory commits are never listed as commits (`held_commits`, history: `own_memory_commit`, own compaction snapshots included); the undo log lists the batches, and an own write covered by a snapshot is still an own write for it (`own_gone` judges by the state, `copied_expiry` by the write's session: a plain-session write never expires). `Scope::Thing`/`Group` take a durable thing's memory aspects (a cursor) only when named (`scope_aspects` filters `all_aspects` to durable keys, which now lists memory rows too). `Indexes::placed` follows every write of a `placed.0~` state (`Tx::placed_from`, so an un-merge rebuild keeps it). A freed thing's aspects go out as changed (watches see `None`). A batch's creation-only memory commits apply before the rest, so a commit placing a new thing carries its record. A memory part answers to no `required.0^` rule (`validity::under_required`, spec/commits.md §5). A batch touching a durable aspect and failing on its ephemeral half now fails inside its transaction (rolled back; the engine generation moves, so tests mark "nothing durable changed" by the commit count).
- **Growth**: `MemorySync`'s sets drain each step; `weighed`/`dirty` entries go with their thing (`free`); memory things and commits are bounded by the caps and forgotten once spent (`forget_if_spent`). Per session nothing is kept across restarts.
- Tests: osis-node `ephemeral::*` (110; cover-specific ones deleted, the rest mechanically over the new API), `memory_*` differentials (`memory_random_snapshots_demotion_redelivered_alike_spec_permissions_5_2` compares held sets per author across other nodes under decision 1), `random_window_*`, `random_churn_converges*`, `snapshot_survives_rebuild`, `delta_past_a_blob_refused_spec_commits_2` (two 5 MiB values on one aspect: refused whole; 1 MiB goes), `ephemeral_chain_depth_counts_durable_links_spec_permissions_1`; sim `ephemeral*`.
