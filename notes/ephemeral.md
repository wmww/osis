# Ephemeral data
> Summary: Design (proposal; owner direction of round 13 and two reviews) for ephemeral data: in-memory things and schema-declared aspects, an axis independent of sync, as much like ordinary data as possible. Local ephemeral writes cost about an in-memory structure. Synced ephemeral data is ordinary signed commits marked ephemeral, kept in memory instead of the store at nodes and servers and carried by the normal sync machinery: it merges on reconnect, outlives contact with its author and is lost only when no node holds it. `presence` ties values to the author's connection; `signal` aspects reach only currently connected devices and hold nothing. Every thing starts ephemeral and is persisted with its owner chain at its first durable write, keeping its tid; ephemeral placements are the ephemeral side of `/group`. Covers the API delta, engine, wire, bounds, mechanism count, deletions, spec edits and a four-step plan (all four built); also kept: expiry and the all-nodes predicate. Tracking: issues/ephemeral-data.md.

## Owner direction (decided)
- Ephemeral = cheap and disposable, no never-touches-disk promise. Independent of sync: durable or ephemeral, local or synced. All of an app's state lives in osis; the UI drives and is driven by it.
- Like ordinary osis data in most ways; its history is "don't care" (neither purged nor kept). On one device it must be very cheap; some overhead is fine when synced, and anywhere when the alternative is special cases or API complexity. Reuse the ordinary commit, delta, validity, sync and server paths unless clearly worse.
- Both units: ephemeral things (creation record only in memory, same tid derivation and rights) and ephemeral aspects on durable things, declared in the schema. Flags `ephemeral` (a value) and `signal` (no lasting value).
- `create` takes no placement; group ops set groups (same batch for atomic create-and-place). Every thing starts ephemeral and is persisted at its first durable write together with its owner chain's creation records, keeping its tid. No persist call. A thing never given durable data vanishes when every node holding it forgets it. Ephemeral placements of ephemeral things approved.
- Synced ephemeral state is ordinary CRDT state held in memory by every holder: it survives while any holder keeps it, merges on reconnect (two people keep using a shared ephemeral window while one is offline; it merges when they reconnect), and a joiner gets it from any holder. Dying with the author is opt-in per aspect (presence-like data).
- No exception to convergence: ephemeral state converges among the nodes holding it; author-tied values converge once every holder notices the departure (like expiry).
- Presence backstop: `MAX_LEASE` 20 min, keep-alive 15 min; no chatter while a path to the author exists; act at once when it drops.

## Model
**Kinds of aspect.** The key decides, by schema flag: durable (default); `ephemeral` (a value held in memory); `presence` (an `ephemeral` value that lives only while its author is connected); `signal` (an ephemeral write with no lasting value, delivered only to currently connected devices; anything a late joiner should see is ephemeral state, not a signal). The writer's key decides the path; merge needs no schema. Core aspects are durable, `/group` aside (placements). Retention does not apply to ephemeral data; expiry does.

**Holders.** A node holds the ephemeral state of the things it writes or receives: every node syncing a label whose closure holds the thing, and that label's servers, while they run. They keep it until they restart, stop syncing the label or lose read access. State is lost only when nobody keeps it; a restarted node gets it back by syncing.

**Ephemeral thing.** A thing whose creation record no durable commit holds at this node. Tid derivation, creation record and owner are as for any thing. `create(owner)` mints the record and keeps it in memory; nothing is written. Invariant: **the durable set is closed under owner**, so a durable thing never has an ephemeral owner.

**Persistence (promotion).** The first durable commit with a delta on an ephemeral thing T (a durable aspect of T, by any node that holds T's record and may write T) also carries `/created` of T and of each ephemeral thing on T's owner chain, top down, and makes T's ephemeral placements durable (below). Same tid; ephemeral aspects stay ephemeral; ephemeral values never become durable: the app copies a draft's content into a durable aspect in the same batch (`set`). Reason: a durable write anchored at an ephemeral dot hides once nobody holds it, and a durable writer delta cannot carry foreign stamps. Two nodes persisting T concurrently both carry the same record (idempotent). A membership operation on an ephemeral thing first persists it by its own content commit (membership commits cannot carry `/group`), then runs. A durable thing never becomes ephemeral again.

**Ephemeral placements.** `/group` is the one durable aspect with an ephemeral side: a group op (`place`, `unplace`, subgroup add or remove) whose item is ephemeral is an ephemeral write into the group's `/group`, held and synced like any ephemeral state, needing write on the group. The `/group` read is the join of both sides, so the item shows in the group and in its `/groups`, and the closure (spec/sync.md §3) includes it, so its ephemeral commits go under the group's labels. When the item persists, the persisting commit adds it durably (with the placement's expiry) and an ephemeral reset removes the ephemeral element. An ephemeral thing can be a group of ephemeral items, a draft placed in a folder lands there at save, and nothing durable names a thing that never persisted. A group op on a durable item is a durable write and persists the group. Any later durable write of a durable thing converts its remaining ephemeral placements the same way, and a durable unplace also removes the ephemeral element. Side effects, all minor: an ephemeral `unplace` concurrent with the item's persistence loses to the durable add (add wins); a persisting node without write on the group cannot make that placement durable, so it stays ephemeral and a `PlacementNotPersisted` diagnostic names it (a writer of the group fixes it with `place`); a durable `/group` naming an ephemeral tid (a raw path op) is a reference that may dangle.

**Rights and validity.** An ephemeral thing has no membership-class aspects (writing one persists it), so a node's role on it is its role on a new thing owned by the nearest durable thing on its chain: the rule already used for things created in the same batch. Ephemeral writes need what the durable write would need; readers cannot write ephemeral data, presence included. Synced ephemeral commits are judged like compaction snapshots (spec/permissions.md §5.2: a part is valid iff its author could write the aspect at its `ts`, through the ordinary timeline), and un-merged like any commit on revocation.

**Reads and merge.** An aspect reads the join of its durable state and its ephemeral state (spec/crdt.md §4.1); normally one side is empty (both: `/group`, or schemas that disagree; the join is defined). Own writes and every applied ephemeral commit join into the ephemeral state. A `presence` aspect's state is the join of the own writes and the deltas of the presence commits the node currently holds; a commit that goes (below) is un-merged (spec/crdt.md §4.6: its writes go, its sequence records stay as hidden anchors). `signal` aspects always read absent. Expiry follows spec/crdt.md §4.7. So ephemeral state converges among holders as any CRDT state does; presence converges once every holder has dropped the author's commits.

**Deletion.** `delete(T)` on an ephemeral thing writes the usual resets. A thing in no labeled closure is then freed at once (record, state, undo entries, the ephemeral things it owns; the tid reads unknown), so short-lived UI things cost nothing. A synced one keeps its record and tombstones while it is held, since dropping them would let an older copy revive the values.

## API delta (notes/api.md, applied with steps 1-2)
- `w.create(owner) -> Tid`; `Place`, `create_expiring` go (expiring placements stay `place_expiring`).
- Schema DSL: `aspect /win/notes: list<tid> [ephemeral];` `aspect /doc/cursor: map<tid, Cursor> [presence];` `aspect /call/ring: Ring [signal];` (`flag` cases 4 `ephemeral`, 5 `presence`, 6 `signal`; the old `signal` items, `signal_def` and schema field 4 go). `AspectDefaults` gains `lifetime: Lifetime::{Durable, Ephemeral, Presence, Signal}`; untyped keys `Untyped` from `ak.ephemeral()`, `ak.presence()`, `ak.signal()` (trait `Lifetimes`) for generic tools and the CLI.
- Writes: unchanged calls. One `Write` may mix durable and ephemeral ops: validated as a whole, applied locally at once (one dispatch); the durable commit and the ephemeral commit travel separately, so a peer may see one without the other. `retention(..)` on an ephemeral write and any op but `set` on a signal aspect are `Invalid`. `commit()` returns `Committed { id: ChangeId, ts }`, `ChangeId = Commit(CommitId) | Ephemeral(EphemeralId)`; a batch with both halves is one change (one `ts`; revert of either reverts both).
- Watches: unchanged. Each signal reaches every `on_change` callback once (never coalesced, never in state; a `Watch` on a signal aspect stays `None`). `CommitInfo.id` becomes `ChangeId`; a remote ephemeral change names the ephemeral commit that carried it (its author, verifiable, notes/api.md Attribution); a presence value going with its commit fires `Remote` naming that commit.
- `created(t)`: `Stamp.commit: Option<CommitId>`, `None` while ephemeral (`ts`, `node`, `actor` from the creating batch or ephemeral commit, `received` from its arrival).
- Undo, redo, revert, query: own ephemeral batches of this session are changes (`CommitKind::Ephemeral`); ephemeral commits are transport, not listed. Thing and Group scopes cover durable aspects and ephemeral things; an ephemeral aspect of a durable thing (cursor, selection) is in scope only when named by `Scope::Aspects`, so document undo never steps through cursor moves. Remote ephemeral changes and own ones from before a restart have no log: revert is `Invalid`. `Config.ephemeral_history` (default 16 MiB) bounds the log; older batches are `NotUndoable{Compacted}`.
- Gone: `send_signal`, `on_signal`, `on_signal_in`, `Target`, `SignalEvent`, `Signal<T>`/`SignalKey`. Device targeting is dropped (no user; a value can name a device). A group-wide signal goes on the group thing.
- Errors: none new; `UnknownThing` for a vanished tid. Diagnostics: `EphemeralRefused { label }` (a cap was hit, below), `PlacementNotPersisted { item, group }`. `NotSynced` stays only for a durable placement into a closure with no label.
- Text sessions on an ephemeral `text` aspect apply each edit at once (no idle commit).

## Local engine
- Module `osis-engine` `ephemeral/`, owned by `Engine` beside `Core`; under the handle's one lock. `Eph { session: Session(node, nonce) per open, next counter per aspect, things: Tid → record, aspects: (Tid, Ak) → joined state, expiry classes, own writes, held parts; remote: unsent own deltas per aspect, held commits; log, timers }`.
- Local stamps: `ts` from the engine's HLC; dots of source `Session(node, nonce)` (spec/crdt.md §2.1; issues/eph-unify.md step 1: replaced a `Commit(random session)` source and the snapshot `Authors` array) with counters per aspect, contiguous from 1 in each session (`Eph::next`, taken when a write applies: a refused batch takes none; dropped only for freed things). Node-form counters are never used (they must survive restarts). Attribution is in the dot: a session names its node, so receivers keep a part's writes only under the commit author's sessions (`own_session`), and a node's earlier sessions are its own with no list. Ops resolve against the read view with the same `osis_crdt` code as durable writes. A local ephemeral write is an HLC tick, an op, a join and a watch event: no store transaction, signature, hash or encryption. This is the whole cost for a thing in no labeled closure.
- `Write` splits ops by key: durable ops into the `Mutation` (plus chain records and placement conversions of the ephemeral things it persists), ephemeral ops into an `EphBatch`. The mutation commits first; if it fails, nothing applies. Then the batch applies (cannot fail after validation) and the engine queues `Event::Ephemeral { changes, info, signals }` (replaces `Event::Signal`), dispatched like commit events. A batch touching a thing in a labeled closure also adds its deltas to `unsent`.
- Ephemeral commits (step 3, as built: Step 3 as built below): built with the ordinary commit builder and verified with the ordinary commit checks, but held in the ephemeral module's own in-memory records (`ephemeral/remote.rs` `Remote::held`), not the store or `Core`'s indexes: validity through the snapshot rule's timeline call, un-merge by rebuilding the aspect, sync through node-sync's ephemeral lane. Their deltas join the ephemeral state, not the durable one.
- Reads (`read.rs`): join the durable state with the ephemeral state when both exist; synthetic aspects and `groups_of` include ephemeral data; `created` reports records without a durable commit. Perm: an ephemeral thing's role through its nearest durable owner.
- Undo: the log keeps per own batch its deltas and the undo buffer of the positions it touched, captured at write time (register values, removed content, presence at the "absent before" position): O(change). Inverse writes follow spec/crdt.md §4.6 against the current state and apply as a new batch (sent like any). Past `ephemeral_history` the oldest entries go.
- Restart: everything ephemeral is gone locally and the next open draws a new session; syncing brings back what holders kept, own old-session writes included (as others' state).

## Synced ephemeral data: ordinary commits in memory
- **Ephemeral commit.** A commit with the header marker `ephemeral` (plain, presence or relay-only; the sync engine puts presence and signal deltas in their own commits, so a commit is one class), of snapshot form (spec/crdt.md §8: foreign stamps allowed, empty counter ranges, `/created` of each thing it covers, so ephemeral things' and their chains' records travel with it; a received `/created` part must be exactly one minting of the record (`is_minted`), since honest nodes keep and carry it as is whoever minted it), signed, encrypted, projected and wrapped as any commit. The engine builds them from `unsent` per (actor, expiry) and node-sync places each under the labels whose closure holds its things, when the label's connections can take it (Coalescing below: while one is in flight, new batches join into the next), and when a thing with ephemeral state enters a labeled closure (the node's own writes on it). Every node keeps ephemeral commits and their blobs in memory only; they are never persisted, never in bundles.
- **At servers.** The blob prefix gets a class field: durable, `ephemeral`, or `presence` or `relay` (signals), from the commit's marker (projection keeps classes apart as it does retention classes, spec/sync.md §3). A server keeps ephemeral and presence entries (blob, wrap, stamp, log event, tombstone) in memory only, under a per-label byte cap; past it, upload of that class is refused with the ordinary cap code. A restart loses them. Everything else is the ordinary path: upload by stamp, cursor sync, range reconciliation, subscriptions pushing new entries, expiry, delete keys.
- **Convergence and reconnect.** Ordinary (spec/sync.md §6): an ephemeral body a node holds is must-hold at the labels whose closure holds its things until covered; writers upload what a label lacks, readers relay stamped entries, so a holder bridging two servers or a member peer serving its own label carries ephemeral state across. The owner's example: both nodes keep writing while apart; on reconnect each uploads its new ephemeral commits and receives the other's; both read the merge. A joiner or restarted node gets the state by its ordinary first sync from any server or peer that holds it; if every server restarted, holders upload again. No poke, digest or join protocol.
- **Compaction.** Own covers (below, Own covers): only an author compacts, its own commits into one cover per actor, when they cost more than twice it; a server's cap refusal triggers nothing. History being "don't care", no keep bounds apply.
- **Presence.** A server deletes a presence entry when every connection that uploaded it has closed (only the author uploads presence commits: they are must-hold for no one else, so nobody relays them; a member peer serving a label applies the same rule). A node drops a presence commit (un-merge) as soon as no server or peer it syncs the label with holds it: a pushed deletion, an expiry, or the loss of its connection to the last one. So a cursor goes the moment the author's path breaks, through a server or a member peer serving it, with no traffic while idle. Backstop: presence commits carry expiry `ts + MAX_LEASE` (20 min, in the header and the prefix, so servers drop them unattended), and an author with live presence values sends a fresh presence commit of its current presence state every `KEEPALIVE` (15 min); the old one expires. Limit: a client node bridging two servers does not carry presence across (it would keep a departed author's values up); a member peer serving the label carries it to its sessions, not from them to its servers (Step 4 as built).
- **Signals.** A signal write is a delta in an ephemeral commit marked relay-only (the sync engine puts signal deltas in their own commits; prefix class `relay`). A server (or member peer serving the label) accepts it by stamp like any upload, pushes it to the label's current subscribers and holds nothing: no entry, log event, tombstone or expiry, so it never reaches a later sync. A node verifies it like any commit, delivers each signal part to callbacks once and holds nothing (no state, no body, never relayed or re-uploaded). The same signal arriving over two servers is delivered once: a node remembers delivered relay-only commit IDs until their `ts` is `MAX_DRIFT` old, and drops relay-only commits older than that (their only replay window). The blob's prefix expires at `ts + MAX_DRIFT`: servers refuse it after, push each blob ID once until then, and rate-limit relays per label; receivers drop a blob seen before unopened. Within that hour a signal can arrive late (a delayed push), and a restarted node can see one again if a replayer uploads it to a server that forgot it (restarted, or past its bound).
- **Own stamps.** An own entry is stamped per upload under that connection's head write key (`eph_upload`). Refused 9 (built offline or before reading a rotation), or with no write key there while this node writes the label, it waits in `Lane::restamp` with the key tried and goes again once the connection's keys give another (`eph_restamp`, each step); dropped with one `EphemeralRefused` report per label once `role_on` is below Write (demoted, removed). An own entry under a label this node only reads (a thing also in a group it reads) is never sent there and never parked or reported (reported, it flooded at every presence write). Covers, split covers and presence take the same path (their replacements go back to `waiting` on the refusal and ride the re-upload). Waiting deletes are signed when made: every delete send (plain or carried) signs it again under the connection's current head keys (`eph_resign`; the level's delete-key signature does not depend on the head), else a cover carrying one made before a rotation was refused 9 under every later key and never landed (`ephemeral::cover_across_unread_rotation_lands_*`). A plain delete refused 9 (sent before the node read a rotation; the reply's head is taken) waits in `Lane::redelete` with the key tried and goes again once the connection's keys give another (`eph_redelete`, each step); rate limited (4), again at the periodic pass (`eph_retry`); any other code ends it. A plain delete whose label key the connection lacks waits there too (`Redo::Head(None)`: keys not established yet or roles uncovered come back) while the node keeps the role it is signed for (`eph_may_delete`: admin for the head delete key, else writer), else it is dropped; one waiting for a cover is not carried by it then (it would refuse the cover) and goes alone once the cover is held. Deletes are made by a level's delete key first (`eph_delete_item`): its label key stays with an admin demoted to writer. Other holders that are writers also delete what a cover absorbs, so a test of one node's delete needs the others to hold none (`ephemeral_bytes: 0`). Tests: `ephemeral::offline_entry_across_rotation_restamped_*`, `presence::offline_presence_across_rotation_restamped_*`, `ephemeral::demoted_writer_entry_stops_*`, `ephemeral::delete_across_unread_rotation_retried_*`.
- **Validity, ordering, replay**: ordinary commit rules (chains, parking past `MAX_DRIFT`, idempotent apply). A replayed old ephemeral commit only re-adds writes its stamps already lose to, or that holders still have.

Local ephemeral memory is the app's; no cap. State grows with edits and removals while held (tombstones), as durable state does.

### Leaks
A blind server learns which entries are ephemeral or presence, and that a presence entry belongs to a connection (it already knows the uploading connection). Nothing else new.

### Mechanism count
Own covers (later) made plain and presence covers one mechanism: a cover absorbs only its author's commits of its class; plain ones on the doubling trigger, presence ones at every write.
Before this pass (the second draft), synced-only mechanisms: a separate envelope format; message 24 with `to`, `from`, `pick`, `via`; a `Left` message; server handles and pick; route tags; the verbatim-forwarding rule; the digest/want join exchange with `skipped` retries; path-vector reachability; keep-alive bodies; per-session contributions; event dedup and queue; the writer outbox; sender growth caps; an acceptance window: 14. After: the `ephemeral` header marker with commits and blobs kept in memory at nodes and servers (1), the prefix class (2), presence entries tied to the uploader's connection and dropped when gone everywhere (3), relay-only commits for signals (pushed, never held; delivered without join) (4), building ephemeral commits from unsent batches (5). Signals lose their own path entirely (envelope, message 24, rate knob, domains). Local mechanisms unchanged: session stamps, persistence with chain records, the ephemeral side of `/group`, the in-memory undo log.

## Expiry
- Expiry is death by timer (spec/crdt.md §4.8): the values die at T and the body follows, whatever the deltas' keep bounds. "Keep at least until T" is a retention bound (spec/commits.md §5), a different thing.
- Covers disappearing messages (write-based timer in core; read-based timers and earlier deletion are app writes; core expiry is the hard upper bound and lets a server wipe them unattended) and buffered events (a list aspect with a one-hour default). Cheaper than keep-at-most 0: nothing has to be deleted by hand, and the server does it unattended.
- Leak accepted by owner: a blind node learns which entries expire and when.
- Not provided: server-enforced minimum retention (legal hold). Keep-at-least binds honest nodes; a blind node deletes whatever a delete key or its label delete key tells it to.
- On ephemeral writes expiry runs in memory (typing indicators: `expires_in(5 s).set(true)`); presence needs none: the `presence` lifetime covers it.
- Nothing is kept "until every receiver has seen it": the receiver set is open and nodes die. What must survive every holder forgetting it (restarts) is durable state: the inbox pattern (receiver-owned list, senders append, owner deletes, expiry as backstop) or a list with expiry.

## The all-nodes predicate
"All nodes a thing syncs to" is a state predicate computable at trusted nodes, never a protocol condition. Per label: the nodes with a valid chain that published `/node` under the thing's label (not "every node of every member", which needs rosters readers never see).
- Recency: each node places an expiring `/seen` heartbeat under each label it tracks (spec/permissions.md §4); the live one's value is its last sync of L, absent means unknown. `/seen` is one aspect of the node thing, so its joined read is "last seen anywhere"; the per-label answer comes from the sync layer's record of which heartbeat commits arrived under L, not from the aspect. (A `map<label ID, timestamp>` would give aspect semantics but leave a value-less entry record per expired heartbeat forever.) The heartbeat also carries `stranded`, the one signal a device that cannot open a label's current epoch, or cannot walk to the head because a claim set was dropped, can still send (it deposits without opening the label, under the newest established read secret it holds, which co-members open by history boxes), and what triggers a re-seal; it is placed only after a complete pass at that server (the rotation commits are uploaded before the step, notes/sync.md, so "cannot open" means not boxed, never "not fetched yet"); it fails only when the deposit key changed under it (issues/reseal-triggers.md). Membership (the node card) and recency are separate aspects because an expired register winner reads as absent and the older write does not show through: an expiring re-put of `/node` would drop the node from the membership view when it lapsed.
- Why a durable heartbeat and not a node-card re-put or ephemeral data: a reader's re-put is a deposit that sits in the label's budget until a writer promotes it, so readers × cadence × promotion delay had to fit a budget the spec never sized, and a full budget refuses the deposits that matter (grants into the group, a reader's self-removal, a revoke only readers hold). Expiry frees the budget unattended (no tombstone, no delete, no writer), so a reader holds at most ceil(lifetime / interval) entries at once and the budget is sized from the claim set (spec/sync.md §5). Rejected: deposit new card plus token-delete the old one (a delete and a 30-day tombstone per refresh, reader-side delete flows, rate-limited deletes); ephemeral writes (the asker is rarely online with the reader, and readers cannot write ephemeral data); server arrival times (untrusted, per server).
- Leak accepted by owner: a blind node sees each reader's heartbeat rhythm per label (same class as deposit and expiry times it already sees). Clock skew between the heartbeat's writer and the asker shifts the reading by the skew; lifetimes are days, so no coarse policy notices.
- A trusted node keeps its own local record of the last heartbeat it saw per node, for policies wanting a longer memory than the lifetime; it is a lower bound, not knowledge of the gap.
- Uses: write a new schema form once every node reads it (fixes the read-only old app the header heuristic cannot see), drop old-form history after that, clean up an inbox once every own device has acked.
- Dead nodes: a lost phone's heartbeat lapses and it drops out of "all nodes seen recently" on its own; a policy that needs it gone from membership too waits for an explicit node removal. Never gates deletion at blind nodes.
- "Buffer until all have seen it" = inbox pattern plus this predicate plus expiry as backstop. Fine as a core helper later; not sync machinery.

## Step 1 as built
Module `core/engine/src/ephemeral/` (`Eph` owned by `Engine` beside `Core`); `Engine::write` is the split (`Engine::commit` stays the durable-only path flows use). Tests: osis `tests/it/ephemeral.rs`; schema `parse::validation_rules`.
Decisions where the design was open:
- `ChangeId`/`EphemeralId` came with step 1 (an ephemeral-only batch needs a `Committed` id and a watch source); `revert` takes a `ChangeId` (ephemeral ones since step 2's undo log).
- Expiry classes: one joined state per aspect plus, per expiry time, the session counter ranges of the writes expiring then; at T those dots are stripped (`Fragment::strip`) and the ranges kept as expired, so a later join that repeats one of their records is stripped again. Step 3 (remote parts with other sources) generalizes the ranges to owned dots per part.
- Timers: `Engine::tick_ephemeral` and `next_ephemeral_timer` beside `tick`/`next_timer` (retention/ untouched); node-sync's Tick calls both and `next_wake` includes it.
- Node-sync subscribes with `subscribe_durable` (no `Event::Ephemeral`), the osis handle skips `SyncEvent::Local` after ephemeral-only events, and node-sync ignores an Expiry `Changed` naming only ephemeral aspects: a local ephemeral write costs the sync engine nothing.
- `delete`: per aspect a durable remove when a durable delta is held, else an ephemeral reset (an aspect on both sides loses its durable side only); freeing scans the ephemeral things for owned ones (O(ephemeral things)).
- A new ephemeral thing needs the role its creation would need (checked at write, like `/created`).
- `move_thing(tid, owner, groups)` persists an ephemeral tid or owner first; `grant`/`change_edge`, `make_link` and `sync` persist an ephemeral target first (`Osis::persist`, a content commit of its own).
- An ephemeral-keyed raw write of `/group` stays `Invalid`; its ephemeral side is written by group ops only (step 2).
- The rights check (perm timeline role per write) is the largest cost part and trivially cacheable per (thing, roster generation) if a budget ever needs it.
- Not built in step 1 (still open): text sessions committing each edit at once on ephemeral aspects (they idle-commit like durable ones, harmless); requirements.md's Ephemeral data section (with step 3: it is about sync).
- Cost (release, `tools/icount`, `ephemeral::bench_*`, setup subtracted): a local ephemeral set through `db.write_with` on one aspect about 15.7k instructions (engine `write` alone about 14k: rights check about 4.6k, ops and join about 5k, events about 3k), a `BTreeMap` insert 316, a durable set 5.3M. So about 50x an in-memory map and 340x cheaper than a durable write; the rights check (perm timeline role) is the largest single part.

## Step 2 as built
Modules `core/engine/src/ephemeral/place.rs` (placements) and `log.rs` (undo log); osis `commits.rs` over both sources. Tests: osis `tests/it/ephemeral.rs` (placements), `tests/it/ephemeral_undo.rs`.
- Split (`Engine::place_plan`): durable-keyed `/group` writes are taken out of the batch and split per op. A member add is durable iff the member is durable after the batch; a member remove iff member and group both are; any other op (`make_group`'s set, a raw root op) iff the group is. What persists is a fixpoint: owner-chain closure of the things with durable aspects or `persist`, plus groups getting a durable add, plus groups the persisted things' ephemeral placements convert into (when the node may write them), until nothing grows.
- Conversion: per placement a durable add (items or subgroups) into the group's durable `/group` delta, with the placement's expiry (found by stripping the aspect's expiry classes in turn until the element goes; a class already past its time skips the conversion), and an ephemeral remove resolved against the ephemeral side alone, not logged for undo. Two conversions into one group with different expiries in one batch are `Invalid` (persist separately). An unplace of the item from that group in the persisting batch wins: only the ephemeral reset is written. A persisting thing that is a group ephemerally gets `Set(Group::default())` first in its durable `/group` ops (groupness persists, its ephemeral items do not). A group the node may not write keeps the placement ephemeral: `DiagnosticKind::PlacementNotPersisted`, tids `[item, group]`, after the commit.
- Reads: `Eph.defs` caches each group's ephemeral side read field by field (an add into a durable group carries no struct presence); `Engine::groups_of` (and `/groups`) is the union of the durable index and these, climbing subgroup edges of both; `durable_groups_of` is the durable side (node-sync's `groups_holding`). The closure sync uses stays durable-only until step 3. An ephemeral reset of a durable element (raw path op only) is not reflected in `groups_of`.
- Freeing a thing also removes its (and its owned things') ephemeral placements, by resets.
- Not reported: `NotSynced` for ephemeral items (filtered in osis `not_synced`).
- Undo log (`Eph.log`): per own batch with ephemeral writes (fast-path durable batches log nothing) its id (the commit for a mixed batch), `reverts`, actor, ts, and per aspect delta, counter range, `footprint` of the pre-write joined state, schema. Byte size = `Fragment::approx_bytes` of delta and footprint plus the entry's own size (encoding them cost about 31k instructions per write, `approx_bytes` a few hundred); `approx_bytes` counts heap structure (a `BTreeMap` node per small map, boxes), within a few percent of measured RSS growth per logged write (an int set about 1.9 KB, a two-entry map set about 12.5 KB; counting stamps and values only had it 6-16x low); past `Config.ephemeral_history` (osis `Config`, default 16 MiB, engine `Config` too) the oldest entries go; an ephemeral-only one is remembered per aspect (newest ts and id, and whether it was a revert), bounded by the aspects held. At 0 nothing is undoable.
- `Engine::revert_change(id, actor)`: the log entry's inverse writes (`osis_crdt::undo` against the joined state, the footprint as buffer, `restored` judged over the log), then for a commit the durable undo commit at the same `ts` (`undo_in` takes it), then one ephemeral batch logged with `reverts`. Returns `Reverted::{Written, Superseded, Compacted}`; an ephemeral id from another session or node is `Misuse` (osis `Invalid`). A mixed batch whose ephemeral half left the log reverts its durable half only (as after a restart).
- Commit query: entries keyed by `ChangeId`; a logged change joins its commit's entry or, ephemeral-only, is `CommitKind::Ephemeral` (changes and reverts alike; `reverts` tells). Relations (`reverted_by`, in effect, depth) over the related commits plus the whole log. `CommitQuery.reverts/reverted_by/after` and `CommitEntry.reverts/reverted_by` are `ChangeId` (builders take `impl Into<ChangeId>`); `Error::NotUndoable.commit` is a `ChangeId`. Redo's "no newer change" test uses depth > 0.
- Scope: `Thing`/`Group` cover held durable aspects plus `Engine::ephemeral_scope_keys` (every ephemeral key of an ephemeral thing; the ephemeral side of a durable thing's `/group`). Undo first checks the newest dropped ephemeral batch in scope: newer than the chosen target is `NotUndoable{Compacted}` (redo: a dropped change gives `None`).
- Cost (release, `tools/icount`, `ephemeral::bench_ephemeral_sets`): a local ephemeral set about 19.8k instructions, was 15.7k before the log (footprint, delta copy, log entry, the placement split).
- Undoing a creation deletes (spec/crdt.md §4.6): log entries record the ephemeral things a batch made and deleted (`log::Making`); `revert_change` deletes what the change made (a commit's `/created` things via `undo::unmake` in `undo_in`; their ephemeral side and a logged batch's still-ephemeral things via `unmake_ephemeral`: aspects reset, entries removed from ephemeral `/group` sides) and brings back what it deleted (`EphThing.deleted` cleared; it is never freed meanwhile, so redo can restore it). `ephemeral_log` lists `(t, /created)` for made and deleted ephemeral things and `ephemeral_scope_keys` covers it, so a Thing scope sees the creation.
- Undoing a save returns the draft (exact undo: the draft existed before it). `Making.saved` records the drafts a batch saved (ephemeral things made earlier that it persists; a save always takes the logged path) and `undo_in` gets them as `Mutation::undo_keep` (not deleted). The conversion's ephemeral placement reset is logged, so the undo puts the ephemeral placement back. The record stays durable: the thing goes in `Eph::drafts` (memory only, one entry per own undone save, with a deleted flag), which makes it known (even without content), counts as ephemeral for the Thing scope (its ephemeral aspects and `/created`) and for deleting it by undoing its ephemeral creation. Its next durable write saves it again (`Placed.saved`), and redo, a new save or `delete` takes it out of `drafts`. With no log entry for the save (another device, compacted, restarted) its undo deletes instead. Placements: `place_plan` converts the ephemeral placements of every durable thing a batch writes durably, not only persisting ones (a restored draft after a restart gets its ephemeral placement back from the server with no `drafts` entry; also a placement made ephemerally while the thing persisted elsewhere), and a durable unplace also removes the item's ephemeral element (exact: placing a durable thing is a durable add that persists the group, so every ephemeral placement of a durable thing was made while it was ephemeral, or restored by undo; test `durable_thing_into_ephemeral_group_persists_it`); `ephemeral_placements` scans `defs` per written thing, skipped when `defs` is empty. After a restart a restored draft reads like a deleted thing unless its group synced (then its ephemeral content and placement come back and it reads as a placed thing; node test `ephemeral_placement_of_durable_thing_converts`).
- A persisting ephemeral group's empty `/group` set takes the expiry of the conversions into it (an empty group has no value for expiry to remove, spec/crdt.md §4.7); a placement that does not convert (unplaced by the batch, expired) persists no group.
- Open: node-sync treats an ephemeral expiry on a durable group's `/group` (an expiring ephemeral placement) as a durable change (`only_ephemeral` is false there); harmless, a wasted check. Membership ops still persist their target by a commit of its own first (`Osis::persist`), which now also converts its placements. The CLI refuses `create --in G`/`--group` without durable data (the thing would vanish at exit).

## Step 3 as built
Modules: osis-commit header field 15 `ephemeral: Option<EphClass>` (`Plain`, `Relay`; presence comes with step 4) and its validation; osis-label `Class` (prefix byte 25); osis-engine `ephemeral/remote.rs` (unsent writes, building, ingesting, judging, compaction, relay-only delivery); osis-node `sync/ephemeral.rs` (the lane); osis-proto relay-only accept (`ServerOutput::Relay`, pushed as a `Push` of one add event at the subscription's cursor); osis-server in-memory ephemeral entries in `BackendStore`. Tests: osis-node `tests/it/ephemeral.rs` (with `random_window_converges_*`: four writers, two servers, random writes, partitions, restarts, a random server cap on odd seeds; tier 2 `random_window_converges_large`, `OSIS_EPH_START`/`OSIS_EPH_SEEDS`; `random_window_one_capped_server_*` the same on one capped server; the three tier-2 runs take about 11 min for 300 seeds together), `sync::signals_relay_only_spec_sync_5`, `hostile_server::replayed_signal_dropped_spec_sync_9`; osis `sync::remote_signal_spec_sync_5`; osis-server `hub::subscriptions_and_relays`, `hub::ephemeral_entries_in_memory`; proto `loopback::subscribe_push_and_relays`; vectors (ephemeral and relay-only commits, prefix classes).
Decisions where the design was open or turned out differently:
- **Not the `MemStore` beside the store** (the plan's wording): ephemeral commits never enter `Core`'s journaled indexes, the store's tables or `validity.rs`/`retention/` (concurrent work there, and every index would have had to learn "not persisted"). The engine keeps `Held { header, parts (fragment, absorbed, authors, valid), own, bytes }` per commit; node-sync keeps the blobs per label (`Lane`). Same wire, same server path, same verification and validity rule; separate bookkeeping.
- **Validity**: a part is judged as a compaction snapshot's delta of its author at the commit's key by commit ID (`tl.delta_valid(.., Dots::Commit, required_role)`), on an ephemeral thing through its nearest durable owner (an ephemeral owner that is the author: valid). Since own covers a part carries only its author's writes (receivers strip the rest, `HeldPart::only_of`), so it is exactly its author's delta. A demotion's frontier lists no ephemeral commit, so a demoted author's ephemeral writes all go. Re-judged when `Core::generation` moves (`rejudge_ephemeral`, O(held parts)); a flip rebuilds the aspect from `EphAspect::own` (own writes alone, kept once a remote part joined) and the valid held parts, own held commits included (an own compaction's cover carries others' writes; skipping it lost them, found by review).
- **Snapshot form**: every delta is a snapshot delta (writes under this node's sessions, the current one and earlier ones its own held commits carry; frontiers empty for now), retention `writer` with no bounds for every aspect, `/created` included (validation exempts ephemeral commits from the fixed `/created` retention), so a commit is one blob per (reader, expiry, delete keys) and writers delete with the level-3 key. An ephemeral thing's `/created` is a register write under the session source minted once (`EphThing::created`); an own cover's joined record of a thing no longer ephemeral here goes as one minting (`one_minting`: copies can differ across a restart). Commits are built per (actor written for, expiry); a commit touching an ephemeral thing carries its record and its ephemeral owner chain's; each label's blob carries the chain records of the things inside it.
- **When**: the osis handle shows the sync engine a Local event when `Engine::has_unsent()` (own writes noted since the last take); node-sync's step builds (`take_ephemeral_if`) and sends, coalescing (Coalescing below).
- **Holders bring what a peer lacks**: the first Sync of a label on each connection lists the held lane entries as `gained` (≤ `MAX_GAINED`; more are reconciled first and only what the peer lacks goes up); the peer's want-list goes up. At most one upload of an entry is in flight per connection, and a status for a lane entry never reaches the sync records (a second status once marked a fetched ephemeral entry durably present, so the next restart's reconcile listed it as held and never got it back; found by the randomized differential). An entry received from one server or peer is uploaded at once to the others where the label is open and it is not known present (stamped entries only; own ones stamped with the connection's write key). No relay delay: every holder bridging two servers sends it (duplicates answered OK, an open cost item).
- **Restart**: the first sync of a label at a server after a start reconciles the live sets (lane IDs and present entries) and keeps the cursor (`Lane::reconciled`, `reconciling`): the ephemeral entries the persisted cursor already passed come back as `need`. Not after a cursor-less replay, not on reconnects within one run. Marked done when the reply arrives (a connection ending first reconciles again); the reply counts as held there only the lane entries its set listed (`reconciling` keeps them): one kept meanwhile from another server goes up instead (counting it held left another's presence held for good once its author left: inflight seed 153497), and a Push during it keeps no cursor, as during a Sync (keeping it skipped the durable entries between the old cursor and the push for good when the connection ended before the Sync: sim `disappearing` 8124, `stranded_reseal` 8112, found by review).
- **Server**: ephemeral entries, their blobs, log records and tombstones in memory (`Ephemeral` in `BackendStore`); log sequence numbers shared with the durable log, reserved on disk in blocks of `SEQ_BLOCK` (1024) in the label meta's `reserved`, so a restart never reuses one (a cursor ahead of the durable log stays valid). Caps `Policy::ephemeral_bytes` (16 MiB per label) and `ephemeral_total` (1 GiB): code 12. Deposits of ephemeral or relay-only blobs: code 1. In-memory log trimmed at `EPH_LOG_KEEP` (2^16) records per label (cursors below get the live entries). `Rate::Signal` and the `signals` knob are gone; relays are rate-limited by `RelayGate` (security review fixes below).
- **Compaction**: replaced by own covers (below). Kept from this step: any node drops a held commit once valid held commits list it absorbed on every aspect (`drop_absorbed`); node-sync then forgets its blobs and, as a writer, deletes them where present (level-3 key; since own covers only once the cover is held there); every plain entry a server refused for its cap goes again there at each periodic pass (`resync_ms`, `eph_retry`): room others made (their compaction, or an expiry, which leaves no log record) reaches it (sim `ephemeral_capped` 14; a retry on the label's deletions with a doubling wait missed expiries and waits longer than the deletions that came).
- **Node cap**: `SyncConfig::ephemeral_bytes` (16 MiB) per label of memory held from others (each entry's `charge`, decoded size: counting encoded bytes let a label of tiny entries hold about 200 times the cap). The node gives the engine the room left under the cap (`ingest_ephemeral_within`): each part is decoded only while what the parts before it cost decoded plus its own bound fit (`part_bound`: `osis_crdt::decoded_bound`, `ITEM_BYTES` per CBOR item and per byte of a run's text content, a value B-tree node three times per map head and set tag (a map key's value is held three times), `BYTE_BYTES` per byte, found from the heads alone, nothing allocated; at least what `ephemeral_charge` counts once decoded), else `TooLarge`: nothing of it held or kept apart, handled as a blob over the cap (reported once until bytes drop, then the label is reconciled). A blob that can never fit (encoded past the whole cap, a part whose bound is, `Engine::ephemeral_bound`, or `TooLarge` with nothing else held there) is remembered per label (`Unfit`, at most `UNFIT_MAX` 2^12 per label, the oldest forgotten; forgotten when a server deletes it): not refetched at reconciles, its announcements skipped, reported once while the label has such blobs (it was fetched again, up to `MAX_BLOB`, after each drop; test `never_fitting_blob_not_fetched_again_spec_sync_9`). So a label passes its cap only by promotions (below, at most its waiting share) and no blob is decoded past it (admitting while under the cap let one 8 MiB blob of tiny entries decode to about 1.7 GB). The bound is loose per part (about 3 times the charge for tiny map entries, 5.5 for a map of small structs, 12 for one small struct, 13 for a small register part, 3 for strings), so a single part needs its bound, not its charge, in the room; a commit of many small parts is charged as decoded part by part. A blob kept apart (author's or thing's record missing: its waiting parts not decoded) is charged to the waiting share by its bound (at least its bytes; in blob bytes a writer queued a quarter of the cap of tiny-entry blobs, hundreds of times that decoded), keeps the most room a copy was given (`Waiting::room`, `Invalid::room`) and is retried within it (reported when past it). Once the engine holds it the node keeps and counts it even past the cap (`eph_promote`, the copy checked within its waiting charge; it was held uncounted: test `promoted_waiting_blob_counted_spec_sync_9`, checked in debug builds), so a label holds at most the cap plus its share. A big honest blob waiting needs its bound (about 6 times a string's bytes) within the share: one past it that lacks records (a split commit's later blob arriving first) is remembered with them (`share_refused`, `Engine::ephemeral_needs`) and fetched again from its server once one is here (`eph_refetch`, weighed only after `Engine::records_seen` changed; an author's record counts only durable, so an ephemeral key actor record cannot refetch it at every change; it was lost until a restart: test `commit_past_a_blob_splits_spec_sync_9` at a 64 MiB cap); one whose parts are all invalid is left to `refused_pending` (refetching at every durable change would download it each time). A held commit from another whose parts all turn invalid (a removal, a demotion) is let go at once (`take_unheld_ephemeral`, `eph_unhold`: no delete anywhere, its labels reconciled so it comes back to wait apart in `Remote::invalid` until valid; it was held, counted and listed as gained until restart). Absorbed lookups go through `Remote::absorbers` (listed ID to the held commits listing it, exact, checked in debug builds): an arrival weighs what it lists (and itself when listed), not every held commit (`scale::eph_absorb_lists_cost`). A replay judged contained compares a piece of the cover (`Fragment::contains`: the cover at the replay's positions; sound, checked against the whole join in debug builds) instead of joining into a copy of it (`scale::eph_replay_cost`: 293 ms to 0.2 ms against a 2.5 MiB cover).
- **Signals**: relay-only commits built per actor from the signal writes of the batch; servers and member peers push them, never store them; receivers deliver valid parts once (`delivered`, `MAX_DELIVERED` 2^16 with a floor per author, dropped past `MAX_DRIFT`; remembered per (commit, part): a commit whose parts have different readers goes as several blobs, and dedup by commit dropped all but the first, test `ephemeral::signal_commit_in_several_blobs_all_delivered_spec_sync_5`); a node's own fire locally as before. No targeting, no `on_signal_in` (a group-wide signal is a signal aspect of the group thing).
- **Pre-existing bug found**: the replay cursor's position (first 8 bytes of a blob ID) overflowed the wire's 2^63 integer limit for IDs starting at 0x80 or above and replayed a page twice; it is now the first 63 bits (spec/wire.md §11.2).
- **Security review fixes** (after step 3; report and fixes on branch `ephemeral-sync`): relay-only prefixes expire at `ts + MAX_DRIFT`, servers and member peers admit relays through `osis_proto::RelayGate` (expiry window, `MAX_RELAY_BLOB`, per-label rate, push once per blob); receivers drop relay blobs unopened when oversized, outside the window or seen (`RelaySeen`, floor past the bound). The server engine refuses unstamped ephemeral and relay-only blobs for every store (a member peer's store did not). Server ephemeral memory counts per-entry, per-record and per-tombstone overhead, ephemeral deletes and replacements are rate-limited, due times are indexed (sweep budgeted), the label using most gives way at the total cap, and the durable log is trimmed by its own record count (ephemeral churn no longer sends durable cursors to reconciliation). Node: only commits the engine verified and holds are kept, served and spread (far-future dropped; unknown authors wait apart, `PENDING_SHARE`); a replay of a covered commit is not held again and a writer deletes it; a removed member's writes laundered by an honest compaction (fixed then by judging carried writes as their attributed node's; gone with own covers, which carry no other node's writes); parts on core aspects but `/group` are invalid; pending commits are retried only when a record they wait for arrives; held entries beyond a Sync's `gained` list are reconciled instead of uploaded whole.
- **Final review fixes**: a relay-only blob is checked against `RelaySeen` before opening but recorded only once verified (a server's keyless junk past `RELAYS_REMEMBERED` raised the label's floor and dropped every real signal for two hours); the engine's delivered floor is per author (one flooding writer dropped every group's signals); another blob of a held commit has its signature and delta hashes checked before it is kept (a header with junk parts was kept and served); the capped-server compaction rules that followed (`forced`, `own_full`, the room condition, the stuck-entry no-churn rule) are replaced by own covers (below).
- **Routing point**: node-sync routes by the blob's prefix class in one place (`eph_added`, from `log_events`): a blob with ephemeral bytes is the lane's, and any sync record an earlier announcement without bytes made for it is dropped (`State::forget_ephemeral`; such a record made a restart count the entry as held). Statuses of lane uploads and deletes stay keyed by the lane's in-flight sets.
- **Member peers and signals** (open question of the step 3 review, decided): a member peer serving a label passes a verified new relay-only commit on (from a server to its sessions, from a session to its other sessions and the label's servers), each blob once (`RelaySeen`); a device reachable only through a member peer gets the signals and its own reach the server's devices.
- **Same-stamp substitution** (review M3): fixed by the copy order of spec/crdt.md §4.1 (notes/crdt.md, Known anomalies); forged map keys and forged text creation `ts` remain: issues/forged-creation-copies.md.
- Open (step 3 scope, deliberately not built): a node that stops syncing a label or loses read access keeps that label's ephemeral state until restart; ephemeral deltas are never paged and must fit a blob (8 MiB; a too large one is not sent, `EphemeralRefused`; issues/eph-unpaged-cover.md); relays are not delayed (duplicate uploads by every bridging holder).

## Step 4 as built
Modules: osis-commit `EphClass::Presence` (header field 15 value 2), osis-label `Class::Presence` (prefix byte 3; `blob_expiry` gives `ts + MAX_LEASE`), osis-base `MAX_LEASE_MS`/`KEEPALIVE_MS`; engine `ephemeral/remote.rs` (`take_presence`, `tick_presence`, `drop_ephemeral_presence`, `may_absorb`); node `sync/ephemeral.rs` (`eph_presence`, `served_src`, `eph_served_gone`); proto `ServerConnection::presence`, `LabelStore::untie` (ties in the store, `Put::tie`); server `Hub::closed(now, id)` returns outputs (every harness carries them), `BackendStore` presence entries. Tests: osis-node `tests/it/presence.rs` (author leaves, two servers, holder reconnects, member peer, peer link, half-open lease, keep-alive and idle traffic, non-author, replay, restart, no expiry); presence cursors in `random_window_*` (own random stream; every holder reads exactly the live cursors); osis-server `hub::presence_entries_tied_to_connection_spec_sync_5`; vectors (presence commit, class 3); schema `parse::validation_rules`.
Decisions where the design was open:
- **A presence commit is a cover**: per actor, the author's whole own state (`EphAspect::own`, else the state) of every presence aspect last written for that actor (`Remote::presence`), absorbing every held presence commit it authored for that actor (this session's and an earlier session's alike), so holders keep one per author; built after each write batch, when a thing enters a labeled closure, and at `KEEPALIVE` while a value is present (`presence_sent` per actor); an aspect with no own write is left out (a node that never wrote a cursor sent an empty presence commit, an entry for nobody, once a thing entered a closure holding others' presence). A cover absorbs only its author's commits of its class (`may_absorb`).
- **No expiry inside**: presence writes with an expiry (written or a schema default) are refused (engine `Misuse`, schema checker); the lease is implied by the marker (`ts + MAX_LEASE`, like relay-only's `ts + MAX_DRIFT`), so a keep-alive's lease never strips the dots it shares with the commit it replaces. A dropped presence commit is un-merged (`rebuild_aspect`), never stripped by dot.
- **Author only**: a presence part's writes under another node's session are not joined (`only_of`); nodes never spread, list as gained or upload another's presence entry (`LaneEntry::foreign_presence`); blind nodes never replicate them. Anyone holding the stamped entry (a reader, a blind server) can upload it on a connection of its own: a replay keeps a departed author's values up at most until its lease (servers cannot tell the uploader from the author). A writer can no longer carry the author's values in its own presence commits: a session names its node (spec/crdt.md §2.1). A writer deleting the author's entry at a server (level-3 key) drops the values at holders with no other source until the author's next write or keep-alive (the author does not re-upload on a deletion: a server at its total cap evicting presence would then ping-pong); writers can reset others' presence values by writing anyway.
- **Sources at a node**: a server or peer is a source while `present` holds an entry of the commit there; a served session while it is open (`served_src`). `eph_presence` runs every step and drops what has none (and so a bundle-delivered one at once). On losing a connection the node forgets which labels' entries were present there and reconciles them on its next connection to that server (`reconciled` cleared), since its cursor passed them.
- **Server**: the tie lives in the store (`EphEntry::ties`, connection IDs); `ServerConnection::presence` lists what a connection uploaded (pruned of gone entries at `PRESENCE_PRUNE`), and `Hub::remove` unties each, deleting an entry no connection is tied to any more (log record, no tombstone, pushed as a deletion: its author uploads it again on reconnect); one deleted or replaced is tombstoned until its prefix expiry (at most 20 min of tombstones per author's update rate, charged to the node total), so a reader that kept an author's replaced entries cannot put them back (issues/eph-presence-replay-pin, deleted; test `store::tests::replaced_presence_tombstoned_until_expiry`). Presence memory is charged apart (`presence_bytes`): sharing the label's ephemeral cap, entries nobody can compact crowded out the covers holders make to fit (seed 20009 of `random_window_converges_large`: an upload/delete storm), so a presence refusal also no longer triggers compaction. Their log records too, since own covers (a presence deletion's record, trimmed at once for a full plain cap before its push, left a departed author's cursor up at holders).
- **Cover before delete**: an own presence commit a newer one covers goes at a server with the cover's upload, which names it as replaced by the connection's tie (spec/sync.md §5 Replace; `eph_replaces`, `Lane::tied`): the server logs the cover's add, then the deletion, so a holder applies the cover (dropping the old one as absorbed) before it sees the deletion; deleting first made every update drop the value at holders and bring it back (two remote changes per write; found by review, `presence::update_never_flaps_spec_sync_9`). An update is one Upload (`presence::update_is_one_upload_spec_sync_5`); an old entry the server took on an earlier connection goes by its level-3 delete proof in the same replace list.
- **Member peers**: a member peer serves what it holds to its sessions (a server device's cursor reaches a device behind the peer; a session's reaches the peer and its other sessions) but uploads no other's presence to its servers (it could not delete it there when the session leaves: a level-3 delete key is not every member's). So a device reachable only through a member peer sees the server devices' presence and they do not see its. A delete by the peer when the session leaves would also be wrong: a delete removes the entry whatever other connection uploaded it, so a session that moved from the peer to the server itself would lose its own entry there; the release operation exists now (an upload's tie-only replacement unties the connection, spec/sync.md §5), but a standalone release for a departing session's entry (no new entry to upload) and the policy for when a peer uploads others' presence stay an owner call.
Open: `eph_report` for a presence cap refusal fires per refusal.

## Own covers (as built)
Replaced the capped-server compaction rules (mvp-progress items 32, 44, 50; two open issues: cross-group and `/created`-only commits no forced cover absorbed). Each of those patched one loop: a server refuses for its cap, holders compact, several holders' covers (each carrying everyone's writes) arrive concurrently, the server fits one, or holds a cover nobody's next cover absorbs, and refuses again. The race itself (k holders able to cover everyone, deciding concurrently) stayed. Presence never had these bugs: its covers were its author's alone.
- **Rule**: a cover is made only by the author of everything it covers (`Engine::compact_own_ephemeral`): per actor (several commits past inline header lists, below), per aspect the join of its own held plain commits without expiry (earlier sessions' ones it holds again included: their sessions name this node) and of its unsent writes without expiry, absorbing each on every aspect of its parts. A commit with an aspect no longer writable here is not covered. Presence keeps its every-write cover; both obey `may_absorb` (same author, same class).
- **Trigger**: own held commits cost more than `COVER_FACTOR` (2) times the cover, each counted as delta bytes plus `ENTRY_CHARGE`, two commits at least (one is what its cover would be again). Weighed only when the held cost passes the factor times the cover weighed last (`cover_est`, plus what could not be covered, so a stuck commit does not re-weigh every step): rebuilds cost O(1) per byte written. A cover's cost is measured by encoding the joined deltas (`cover_cost`). `eph_step` takes first, then compacts (the cover absorbs what was just built; that commit never goes). A small register compacts every two or three writes.
- **Why it converges**: covers form one chain per author and actor; a cover is the join of what it absorbs, so dropping what it absorbs never changes a holder's state, whatever the arrival order. Owner decision "state outlives its author and merges among holders" holds: holders keep, relay and re-upload an author's commits as before; a departed author's data stays at most about twice its state, since the rule ran at its last send.
- **Only own writes travel**: a commit carries its author's writes and `/created` records (of the things it writes or its `/group` deltas place, up their ephemeral chains, minted by whoever: self-certifying, never stripped); receivers strip every other write from every part, another session's or one under a node source (`HeldPart::only_of`; node sources were kept until review, presence's too: a writer could pass a write off as another node's). No record-only commits; a thing entering a closure sends the node's own writes, not the whole state.
- **Server cap**: a refusal is reported once per entry (`Lane::capped`) and retried at the periodic pass; nothing else. Defined outcome (spec/sync.md §5, §9): what a full server lacks is what it refused. Tests and the sim check it exactly at quiescence: holders connected through servers that keep nothing out read alike, where "keeps out" is an entry some up node holds that a server lacks and cannot fit (`BackendStore::ephemeral_fits`); a node holding a window's record without its placement (the record rode in a presence commit, the placement did not fit) does not sync it (`ephemeral_synced`) and is no holder; with a server keeping something out, holders read at most the expected cursors; each up node's own load is within the factor times its cover plus one commit (`own_ephemeral_load`). Caps are random, 0 and below one cover included. Room can appear only after the last periodic pass (deletes of what an entry accepted at that pass absorbs): the one-capped-server check runs further passes while an entry a node holds and the server lacks fits, at most one per entry (`random_window_one_capped_server` seed 173658). The sim's durable convergence check reads `/group`'s durable side alone (`Engine::get_durable`).
- **Costs**: more server memory than cross-author covers: k authors overwriting one value keep k values; an author's own state keeps its text others deleted (projecting the state onto own dots would shrink it, but would turn a revoked writer's removal into the author's own). Expiring writes stay uncompacted entries until they expire.
- **Delete after the cover is there** (`Lane::waiting`, `eph_flush`): a writer deletes an absorbed entry at a server only once the cover (or what absorbed it since, `eph_cover`) is held there; orphans and replays of covered entries too. The upload of the cover that completes them names them as replaced instead (`eph_replaces`, `Lane::replacing`, back in `waiting` unless answered OK; at most 1024 per message, the rest by Delete): the server removes them as it admits the cover, the room they free counted, so a cover refused for the cap even so is only retried, never preceded by their deletes. The author whose cover is refused for the cap without carrying them deletes at once and re-uploads (room for it). Deleting first (the design's choice, for room at a full server) lost writes at a server for good when the author crashed between the delete and the cover's upload: holders kept the commits but the tombstones refused them (sim `ephemeral` 2601181, frequent once compaction runs every few writes; `author_crash_before_cover_lands_keeps_state_spec_sync_9`). That window on the cap-refusal path is closed by Replace when the cover's upload carries the deletes; left only when it does not (a split cover's other piece not held yet). Waiting deletes are bounded per (label, server) (`WAITING_MAX`, Bounds): a server that never comes back or never holds covers keeps at most that many. An upload refused for the rate (code 4; a cover's replacements count as deletes) goes again at the periodic pass like one refused 12 (`capped`; test `ephemeral::cover_refused_for_rate_retried_spec_sync_9`); one refused 1 is not retried on that connection.
- **Review fixes**: receivers also strip writes under node sources (above); a cover that cannot be built (then: a delta past the page target; since unpaged deltas: past a blob, issues/eph-unpaged-cover.md) keeps the unsent writes it joined (they were dropped, never sent) and is weighed again once the held commits double; `eph_step` no longer orders forgetting around placing (every absorbed entry's delete waits for its cover); the capped checks (sim `lossy_servers`, `random_window` one capped server) count a refusal genuine only while the server keeps no plain entry that no (up) node holds, so a server filled with entries absorbed everywhere cannot excuse divergence. Past a refusal, holders holding the same plain commits must still read alike (re-review: about half the refused `random_window` capped runs then compare some holders; a node's state is its own commits joined with the valid received ones).
- **Records go with their commit's other parts** (issues/eph-expired-created-held, deleted): a held commit whose non-`/created` parts all expired is dropped (`tick_remote`, `live_parts`), one received already so is not held, and a received ephemeral thing's record goes once nothing here uses it (`free_unused_records`: no held part on it, no state, no own unsent or presence write, no pending commit waiting for it, no ephemeral thing it owns; never a thing this session made), also after a presence drop. A record is no state of its own (`knows` is false without content, no record-only commits): every commit about the thing or placing it carries the record, so dropping it loses nothing and "state outlives its author" is untouched. A thing entering a closure sends no part for an aspect with only expiring writes (`note_entered`: `own_unexpiring` kept their value-less records, a non-expiring part that carried the record forever). Test `ephemeral::expired_commit_leaves_no_records_spec_sync_9`.
- **Redundant on arrival, not by lists** (issues eph-replay-absorbed, eph-forged-cover-diverges, deleted): lists are not transitive (a cover of a cover lists only covers), so a replay from two covers back (a reader's re-upload, a blind server serving what it kept) was held, counted toward the cap and spread again. Now a received plain commit is not held when held commits of its author contain it (`eph_containers`): on each non-`/created` part, one unexpiring valid part that contains it (`contains`: join changes nothing) and lists it or, for a take (lists nothing), is a later cover. Stamps do not order an author's sessions: by stamp alone a restarted author's re-cover stamped below its earlier session's cover of the same content was taken as redundant at holders of the old one, while the author dropped the old one under the new: both were deleted at servers (random_window_converges 5327166, review); lists form no cycle, so a cover is redundant only by a list (a cover replayed from two covers back is held again until its author lists it). Exact without lists: a cover's chain contains whatever earlier covers took in; a commit a cover missed (an earlier session's, not held when it covered) is not contained and stays. Lists still drive drops of held commits, but each listing part must contain what it lists (`drop_absorbed` joins them into a copy of the cover part once per drop; one that does not has its list cleared): a writer's "cover" omitting its commit's writes made holders that had it and late joiners diverge. Costs: a clone of the cover part per check, only for arrivals older than a held cover on an aspect (honest new writes skip it) and per real drop. A commit whose received non-`/created` parts are all invalid is not held or counted (`Remote::invalid`, node-side as a pending entry under its share): judged again at each durable change, ingested once one part is valid (test `invalid_on_arrival_held_once_valid_spec_sync_9`). A label whose node cap refused something reconciles at its next periodic pass once bytes drop under the cap (`eph_forget` clears `reconciled`, `timers` re-syncs an unreconciled label). Presence: a received presence commit older (ts, ID) than a held one of its author and actor is not held, and holding one un-merges the older ones (a presence commit is its author's whole presence state for that actor). Tests `ephemeral::{replay_from_covers_back_not_held, cover_without_its_commits_drops_nothing, capped_label_reconciles_once_room}_spec_sync_9`, `presence::replayed_older_presence_not_held_spec_sync_9`.
- **Rejected** (design analysis, deleted issue eph-cap-design): servers evicting at the cap (a blind server cannot tell authors apart, holders re-uploading ping-pong with it, late joiners silently miss state); stopping the label at the cap (one heavy writer stops everyone's sharing); caps per author (a blind server cannot count per author); finishing the special cases (open-ended).
- **Unpaged deltas** (issues/eph-unpaged-cover.md): ephemeral deltas never page (`osis_crdt::Unpaged`: page target infinite, a link is bad input; encode, decode and verify of every ephemeral part, and `cover_cost`), so one aspect's own state covers up to a blob (`MAX_BLOB` 8 MiB) instead of 64 KiB, and a commit past a blob already splits into several blobs per label (projection). Chosen over paging (page blobs would need lane entries, server ephemeral entries, fetch-before-apply and deletes of their own) and over covers split by aspect for size (projection already splits a commit past a blob; covers split by aspect came later for header lists, Past inline lists below). `own_ephemeral_load` measures the cover even when it cannot be built. Test `ephemeral::cover_past_page_target_bounded_spec_sync_9` (400 KiB on one aspect: the author's held commits, a holder's lane and the server stay within a few covers; a restarted holder gets it back); crdt `unpaged_ephemeral_deltas_spec_8`. Review: a commit split into several blobs can carry a thing's record in one blob and its parts in another; a holder getting the second first kept it waiting until the durable set changed (`rejudge_ephemeral` only), so a restarted holder read nothing of that thing: records an ephemeral commit brings now retry what waits (`retry_waiting`), and waiting blobs of one commit merge (`Waiting`: every distinct signature and part not failing a known record's delta hash, several copies per `(ai, di)` while the record is missing; the retry takes the first verifying signature and per part the first matching copy, `sift_waiting`: first-wins let a junk copy with the real header evict the real part, test `junk_copy_of_waiting_commit_evicts_nothing_spec_sync_9`; copies are distinct blobs, each counted in the node's pending share, so a flood of junk copies is bounded by `PENDING_SHARE`; review: a lane blob of a commit held meanwhile is checked again on promotion (`eph_promote` re-runs `eph_added`: it kept every pending blob of a held commit, junk copies included, test `junk_copy_of_waiting_commit_not_kept_once_held_spec_sync_9`); a blob with a part waiting for its thing's record is `Pending` even when its other parts verified and are held (it held the commit with no part verified and kept the blob unchecked; `eph_promote` skips while `pending_ephemeral`, then checks the blob again, test `junk_copy_waiting_on_thing_not_kept_spec_sync_9`)) (test `commit_past_a_blob_splits_spec_sync_9`: two 5 MiB aspects, a split cover, deletes, a restarted holder). Cost (release, loaded box): a write that triggers a cover at 650 KiB own state took 160 ms locally and 500 ms for the whole round (author, holder, server), mostly per-absorbed-entry bookkeeping (about 10 store transactions per absorbed commit across the nodes), not encoding (cover_cost 7 ms, build 31 ms); amortized 2 ms per write; covers come at each doubling. `eph_held_at` counts a cover held at a server once any of its blobs under the label is: with a split cover a delete may go before the other blob lands (only the cap-refusal path, which deletes at once anyway).
- **Past inline lists or a blob** (issues/eph-unpaged-cover.md): a plain commit (take or cover) whose header lists would not fit inline (`CHUNK_THRESHOLD`, about 1000-1500 aspects; ephemeral commits link no list) or with a delta past a blob splits into halves in aspect order, recursively (`build_fitting`: exact, the builder decides; the common case builds once). - **Only what it can place** (sim `ephemeral_seed_21054`): a cover absorbs only own held commits whose content aspects are on things in a labeled closure here now (`coverable`). After a restart, an earlier session's commit fetched back before the one placing its window was covered; `eph_place` put the cover's window parts under no label, the absorbed commit was deleted at the servers, and a reader kept the cover without them.

## Coalescing (as built)
- Node-sync's `eph_busy`: the groups of labels where every connection the label is open on has an own plain entry upload unanswered (`Lane::uploads`), and the actors whose own presence uploads are unanswered on every connection of every label their in-flight commits went under. `Engine::take_ephemeral_if(busy, busy_presence)` leaves those things' unsent writes and records, and those actors' due presence commits, in place: later writes join `unsent` (deltas joined per aspect, actor and expiry: overwrites keep the latest) or just leave the actor due (a presence commit carries the whole own state). The step that handles an answer (or a connection's end, `eph_lost` clearing `uploads`) builds the next. No timer: about one own plain commit per label and one presence commit per actor per round trip of the fastest connection. Compaction covers and signals are not held back; signals stay one relay-only commit per actor per write batch. A thing under several labels waits while any of them is busy.
- Review: the first version held back while an upload was unanswered on any connection, so one slow or silent server (a large Sync reply ahead of the answer, or a hostile one never answering) stopped every ephemeral write of the label from reaching the other servers until its request timeout (2 min), again after each reconnect (`slow_server_holds_nothing_back_spec_sync_9`, both kinds). Releasing on the fastest answer then left every covered entry at the slow server (an entry forgotten while its upload was in flight was never deleted there: on main too, at every write): `Lane::orphans` keeps the delete for such an entry and sends it when the upload is answered OK; meanwhile the entry, coming back from that server (no held commit lists an old presence commit absorbed past the newest cover), is not taken back.
- `Remote::noted`: `has_unsent` is true only for writes noted since the last take, so what was held back does not make every handle call feed a Local event; the answer that releases it arrives as an event anyway.
- Server: deletes of presence entries are not counted against the label's delete rate (`Policy::deletes`): they and their tombstones (until the entry's expiry) cost what the upload did, which no rate bounds (when an author still deleted its previous entry per update, 12+ authors at 30 moves a second hit the 20 000 a minute limit and left entries behind). Since Replace an update deletes nothing: the cover's upload unties the old entry.
- Measured (tier-1 `Net`, 66 ms round trip, 30 moves a second per author): a cursor costs one commit and one upload per round trip, not per write: 10 authors for 1 s 160 uploads and 0 deletes since Replace (150 deletes before it; 300 and 290 before coalescing), for a simulated minute 9100 uploads (and 9090 deletes before Replace) (tier 2, 15 min at load 38: a node-sync step costs about 0.4 ms in dev); a burst of 20 moves during one upload: 2 commits. With a round trip under the write interval every write still goes alone.
- Tests: osis-node `presence::burst_coalesced_while_upload_in_flight_spec_sync_9`, `presence::many_authors_under_server_rates_spec_sync_9` (tier 2 `_large`: a simulated minute), `{ephemeral,presence}::slow_server_holds_nothing_back_spec_sync_9` (`Net::held_servers`), `ephemeral::burst_coalesced_while_upload_in_flight_spec_sync_9`, `ephemeral::signals_not_held_back_spec_sync_9`, `ephemeral::random_window_inflight_*` (half the steps end after one hop, `Net::round`); osis-server `store::tests::presence_deletes_not_rate_limited`.
- Re-review: `Lane::orphans` holds at most one delete per upload in flight on a connection (bounded by the uploads a 2 min request timeout lets pile up on a silent server) and goes with the connection; then plain covered entries are deleted when the next connection announces them again (absorbed replay), presence ones by the server's close rule. A copy refused while an orphan is held has the same blob ID, so the same bytes: nothing newer is refused. An orphan answered with a code other than OK is dropped without a delete (a replacement refused by rate leaves the entry there until a replay or expiry). Unlimited presence deletes: each needs the level-3 key (a writer of the thing) and removes an entry an upload made (its tombstone lasts at most the entry's expiry; a missing entry is refused before the store), so their cost is bounded by uploads, and churn by presence uploads with short expiries was already unbounded by any rate.
