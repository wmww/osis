# Ephemeral data
> Summary: Ephemeral data as built: `+` aspects on durable things, an axis independent of sync, as much like ordinary data as possible. Local ephemeral writes are memory commits through Core; synced ephemeral data is ordinary signed commits marked ephemeral, held in memory instead of the store at every node holding them and carried by node-sync's ordinary passes: it merges on reconnect, outlives contact with its author and is lost only when no node holds it. A value that should die with its author is an expiring write its author renews (`osis::KeepAlive`); `+~` ephemeral signals (no current value) reach only connected nodes and are held by none. Every thing is durable from its creation. Covers the API, engine, wire, caps and full peers, deletion, undo, expiry, restarts and lost access, convergence and its limits, and the all-nodes predicate.

Terms: **ephemeral** is for `+` aspects: shared with others, never stored. The rules are in spec/sync.md §9; this note says how they are built and why.

## Principle (Tess)
Ephemeral data has the same semantics as durable data, just held in memory, with no exceptions. Every ephemeral rule is the durable rule, or follows from "held in memory": lost on a restart (sessions, counters and spent commits' headers live in memory and go with it; a restarted node gets state back from holders like a joiner), bounded by memory caps per label (node and host, with a defined refusal), never in a store or bundle, not kept at hosts past a restart. What follows from memory is listed below with its reason; the one rule kept beyond it is Superseded expiring writes; the differences still to remove are in issues/eph-parity.md.

**Tess's direction**:
- Ephemeral = cheap and disposable, no never-touches-disk promise; independent of sync (durable or ephemeral, local or synced). All of an app's state lives in osis.
- Very cheap on one node; some overhead is fine when synced, and anywhere when the alternative is special cases or API complexity. Reuse the ordinary commit, delta, validity, sync and host paths unless clearly worse.
- The unit is the ephemeral aspect on a durable thing, declared in the schema. `create` takes no membership; group ops set groups (same write for atomic create-and-add).
- Synced ephemeral state is ordinary CRDT state held in memory by every holder: it survives while any holder keeps it, merges on reconnect (two people keep using a shared ephemeral window while one is offline), and a joiner gets it from any holder.
- Presence is not a lifetime of its own: a value that should die with its author is an expiring write its author renews (Values that live while their author is there).
- No exception to convergence: ephemeral state converges among the nodes holding it; author-tied values converge once their last write expires.

## What follows from memory
- **Spent commits are forgotten whole, header included** (spec/sync.md §9 Forgetting, `forget_if_spent`): memory is bounded by the caps, never by the number of writes made. Durable forgets a commit only once a held cover covers every part of it (spec/commits.md §5 Forgetting), so a holder would otherwise keep a header for every write of an author that stopped or restarted before any cover came, outside any live state, until it restarts. So a copy of a forgotten commit arriving again applies and goes again, as one never received; a snapshot turning invalid leaves no record of what it covered (Convergence); a forgotten commit is unknown to `revert` (`Invalid`), and undo of a write no setting keeps is `NotUndoable{NotKept}` before that anyway.
- **An invalid memory part drops as a durable one** (spec/permissions.md §6, `retention::goes_invalid`, `drop_invalid`), its commit kept known with no body (`retention::kept_invalid`, the durable rule): a copy is not taken while it stays invalid (`takes_late`); valid again it is missing and fetched (`valid_again`, `Changed::undropped`), its commit known until the part is back (`Missing::ToFetch`), so another part superseded or dropped meanwhile does not spend it (`superseded_part_beside_one_valid_again_fetched_spec_permissions_6`). A cover drop of a part `goes_invalid` takes drops it as invalid (`drop_part_for`), else one invalid on arrival, forgotten as covered, would never be fetched once valid. Such a commit is forgotten by the durable path (`Engine::forgettable`, `forget_forgettable`) once node-sync knows no entry of it and no delete of one within the tombstone. It costs no cap (`ingest_memory_entry` charges nothing and drops the bytes; a commit turning so later has its charge released, `State::forget_due`): a held invalid part let a reader fill a holder's cap until restart (`reader_flood_takes_no_cap_spec_permissions_6`).
- **Own bodies under own covers, replaced ones too** (Memory commits, covered drop rule): durable keeps only its own live deltas so (notes/engine-retention-covers.md Own live bodies); memory keeps every own body, since a fallen memory snapshot leaves no record of what it covered to fetch back, and what brings covered writes back after the fall (`take_fallen`, `relist_fallen`) relies on each author still holding its own (`memory_compactor_demoted_keeps_others_writes_spec_permissions_5_2`). Not a body under purge on replace: nothing keeps it, and its author drops it under the replacer's cover as every holder does (`replace::settle_none`, `purge_on_replace_of_ephemeral_write_spec_commits_5`); `settle_none` drops a memory body only so, so an own snapshot still carrying live writes stays (`purge_on_replace_keeps_own_live_ephemeral_snapshot_spec_sync_9`).
- **Retention `writer`**: any writer compacts, and the right to drop a body under a snapshot is the purge right (spec/permissions.md §6), so every ephemeral delta is purgeable by `writer`; the schema declares none. What history keeps is the thing's setting, as for durable aspects; kept history lasts while held.
- **Presence per connection** (spec/sync.md §9 Held at a peer that cannot read L): a restarted peer lost its entries, so presence is learned anew from each join's listing of live memory entries. Relearning per connection rather than per peer run is not forced: issues/eph-parity.md Presence at a host.
- **Demotions, rotations, addenda and listings** name ephemeral commits as durable ones (spec/permissions.md §5.1, §5.2, §5.5): a demotion invalidates only the demoted node's ephemeral commits its author had not received, so one stamped after its author restarted, before they came back, invalidates them all (`demoted_writer_received_ephemeral_write_stays_spec_permissions_5_2`).

## Model
**Kinds of aspect.** The key's markers decide, each independent (spec/data-model.md §2): `+` ephemeral (writes held in memory) or durable; `~` a signal (no current value, only written) or a value (`.`). `+.` is an ephemeral value; `+~` an ephemeral signal, delivered only to currently connected nodes (anything a late joiner should see is ephemeral state); `~` alone is a signal written in durable commits (notes/api.md Signals). The writer's key decides the path; merge needs no schema. Core aspects are durable. Ephemeral deltas carry retention `writer`; expiry applies as to durable data.

**New things are durable.** `create()` puts the creation record in the write's durable commit. Rejected: drafts (a new thing held in memory until its first durable write): nothing needs them (every create in app, chat and CLI writes durable data at once), while they cost a membership split, records in memory parts, a persistence fixpoint, freeing and draft undo.

**Holders.** A node holds the ephemeral state of the things it writes or receives: every node syncing a label whose closure holds the thing (spec/sync.md §3; a thing no group lists syncs no more), and that label's hosts, while they run. State is lost only when nobody keeps it; when a holder lets go is in Restarts and lost access.

**Rights and validity.** Ephemeral writes need what the durable write would need; readers cannot write ephemeral data. Synced ephemeral commits are judged like compaction snapshots (spec/permissions.md §5.2: a part is valid iff its author could write the aspect at its `ts`, through the ordinary timeline), and un-merged like any commit on revocation. Parts on core aspects are invalid. A part on a thing whose record is not held waits for it.

**Reads and merge.** An aspect reads the join of its durable and its ephemeral state (spec/crdt.md §4.1); normally one side is empty (both: schemas that disagree; the join is defined). Own writes and every applied ephemeral commit join into the ephemeral state; `signal` aspects always read absent.

## Deletion
`delete(T)` resets T's content and removes its memberships in one durable commit, which also carries a purge request naming each of T's `+` value aspects that may hold content (`write::delete_purges`, `read::purged_aspects`: named by a held header, present here or with a valid part not received yet, as `deleted_aspects` judges the durable ones), placed by a `purge.0` write on T when nothing else of the commit is on T (spec/sync.md §9 Delete). Every node applying it, the deleter in the same transaction, holds T's ephemeral writes stamped before it value-less by the one purge path (the right is write on T, `write::check_delete`). By stamp, not arrival, so every holder judges alike: a later write stands, as after a durable reset, and so does a concurrent write on an aspect the deleter held no header of. The commit reaches every holder through T's labels where T stays in a closure, else through the labels of the groups its removals are on.
- Why a purge request: a durable commit carries no ephemeral writes (a part's class is its key's marker, spec/commits.md §2), and an ephemeral reset commit would have parts on T only, placed under no label once T left every closure; a request is header-level and durable, so a copy of a purged write arriving later (from a holder that missed the delete, a restarted node fetching) is stripped too.
- A delete writes no memory content commit (a holder's purge snapshot aside, spec/commits.md §5 Purge), so a `Write` stays one commit. `purge.0` is not content (`core_types::deletable`): a delete neither resets it nor counts it for `has_content`, and undo skips its parts (a purge is never undone). Undoing a delete restores T's durable state only; undoing a creation deletes as a delete does, the undo commit carrying the request (`undo::undo_in`, `unmake_ops`). Listeners hear the change from the delete's commit.
- Tests: osis-node `ephemeral::delete_*_spec_sync_9`, `undo_of_creation_reaches_holders_spec_crdt_4_6`; osis `ephemeral::delete_*`.

## API
- `w.create() -> Tid`; an expiring membership is `w.group(g).expires(e).add(m)`. `created(t)`: the creating commit (`ThingStamp.id`), always durable.
- Schema DSL: the key's markers, spelled again by keywords: `ephemeral aspect win:notes+.0: list<tid>;` `expires(30s) ephemeral aspect doc:cursor+.0: map<tid, Cursor>;` `ephemeral signal call:ring+~0: Ring;`. `Ak::ephemeral()`, `Ak::signal()` read them from any key, typed or untyped.
- Writes: a `Write` is one commit (notes/api.md Writes), so durable beside ephemeral writes is `Clash` (a peer could see one without the other), and so is a `+` write on a thing created in the same `Write`. A signal takes one `fire` per commit; a value op on it is `Invalid`. `retention(..)` asking other than `writer` is `Misuse`; the thing's setting rules history, purge on replace included. `purge` on an ephemeral aspect writes a durable request (`Purge::All` writes `purge.0`, no removal), so beside an ephemeral write it is `Clash` (notes/engine-retention-purge.md).
- Watches: each ephemeral signal write reaches the signal's `on_fire` once, its commit as fired (no read finds it); `on_change` hears nothing of it. A remote ephemeral change's `Origin::Remote(Stamp)` names the ephemeral commit that carried it (notes/api.md Attribution); a local one's `Origin::Local` its own commit, a revert's the undo commit, a delete's or undone creation's purge its commit's, each heard once (osis `local_ephemeral_changes_reach_listeners_once_spec_data_model_1`). No node targeting (a value can name a node); a group-wide ephemeral signal goes on the group thing.
- Undo: ephemeral commits are listed and reverted by their ids like any (own ones as `Content`/`Revert`). Thing and Group scopes cover durable aspects; an ephemeral aspect is in scope only when named by `Scope::Aspects`, so document undo never steps through cursor moves.
- Errors: none of their own. Diagnostics: `EphemeralRefused { things }` (a cap was hit).
- Text sessions on an ephemeral `text` aspect idle-commit like durable ones (committing each edit at once is not built).

## Local engine
- Module `osis-engine` `ephemeral/`, owned by `Engine` beside `Core`, under the handle's one lock. Ephemeral writes are memory commits in Core; `Eph` keeps only unsent and delivered relay-only commits. Reads come from Core state as for any aspect.
- Local stamps: `ts` from the engine's HLC; dots of source `Session(node, nonce)` (spec/crdt.md §2.1) with counters per aspect from the store's memory overlay, contiguous from 1 in each session. Two sessions per open: `Core::session` for plain writes, `Core::expiring` for expiring ones, its nonce the plain one's with the first bit flipped (one rng draw per open). Why two: an expired or superseded delta's range is forgotten, and under the plain session it would leave a gap no snapshot frontier passes, so nothing later of the session would be covered.
- **Fresh sessions** (spec/sync.md §9 New sessions; `Core::fresh_session`, from `apply/validity.rs` when an own session-form write of the current sessions falls, `OwnWriteInvalid`): the plain nonce's last 8 bytes step by one as a big-endian count, the expiring one follows by the flip; `later_sessions` counts them, so `own_plain` recognises every session of the open without a list. Why: a write invalid for good (explicit demotion, no re-grant after it) stops every snapshot frontier of its session below it, so later writes would be held uncovered at every holder until a restart (`memory_regranted_writer_covered_spec_sync_9`). A fall that rises again still begins a session, harmlessly. Bound: at most one session per write the node makes, however an admin flaps its role; holders pay per session only through its writes (frontier entries, `ix.ranges`), as for a restart.
- `Engine::write` sorts ops by the key's `+` marker and refuses what asks for two kinds (`Error::Clash`; creates and deletes count as durable): durable ops go to `commit_in` (a delete's purge request with them), ephemeral ops into one memory commit per expiry class (refused when there would be two). The memory `commit_in` runs in `Tx::in_class(true)`: session form, ephemeral marker, retention `writer` keeping the history the write or schema asks or none, no records, large values chunked and deltas paged as durable ones (Memory commits, Paging); a commit still past a blob is `Misuse` and nothing of the batch applies. Every applied memory commit, own or received, queues one `Event::Ephemeral` with the aspects it changed, as a durable commit queues `Event::Applied`.
- Node-sync subscribes with `subscribe_durable` (no `Event::Ephemeral`), and the osis handle shows it `SyncEvent::Local` after ephemeral-only events only when `has_memory_changes()`.
- Cost: a local ephemeral set's rights check is the largest part of its own work, trivially cacheable per (thing, roster generation) if a budget needs it.
- Local ephemeral memory is the app's; no cap. State grows with edits and removals while held (tombstones), as durable state does.

## Undo
- One mechanism with durable undo (`undo::undo_in`, notes/api.md Commits): an ephemeral commit is reverted by an ephemeral undo commit (`Engine::revert_inner`) whose inverse is computed from kept history: the held valid parts before the target that are in the read or within their keep bound, here in memory. Without a `keep` entry for the aspect in its thing's `retention^.0` no undo there works (`NotUndoable{NotKept}`); with it bodies stay held to their bound, live ones while live (spec/commits.md §5 Kept while live: `drop_covered` waits for `part_keep`, superseding leaves a part keeping history alone, the trigger weighs no kept body). An ephemeral commit forgotten here (never received, or gone with a restart or a cover) is unknown: revert is `Invalid`.
- A copied expiring value is written back under the expiring session (spec/crdt.md §2.1); one copying back values of different expiries (or expiring beside lasting) is `Clash` (`undo::copy_expiry`); a session write no held commit carries counts as gone for copying (`copied_expiry`). An undo copies back no expired content: `undo_expiring` strips everything expired by the undo's `ts` from the pre-state (`undo_of_set_past_expiry_restores_no_shadowed_entry_spec_crdt_4_6`).
- Undoing a creation deletes (spec/crdt.md §4.6): `revert_commit` of a commit carrying `created.0` deletes those things durably (`undo::unmake_ops`: durable aspects reset, memberships removed in groups the writers may write), their ephemeral state purged by the undo commit as a delete's (Deletion). Its redo writes the memberships back from `group.0`'s kept history.
- A revert's writes on several things are one memory commit (every memory commit spans its things; the pass places a commit's bodies under a label holding any of its things, each body the label's actor may read; `ephemeral::ephemeral_reverts_within_rights_alike_*`). A commit on things in no labeled closure is held and goes nowhere until a closure holds one of them (spec/sync.md §3).

## Synced ephemeral data
- **Ephemeral commit**: header marker `ephemeral` (field 13, `EphClass::Plain` or `Relay`), a content commit or content snapshot in the form a durable one would use (spec/commits.md §3: session form for a node's own writes, commit form for snapshots and for a key actor used from several nodes, `commit_form_ephemeral_commit_spec_commits_3`), no `created.0` part and no records, signed, encrypted, projected and wrapped as any commit. Held in memory only (the store's memory overlay and Core's indexes, `Engine::holds_memory`), never persisted or bundled.
- **On the durable sync path** (`core/node/src/sync/memory.rs`): node-sync's passes judge, place, relay and delete memory bodies exactly as durable ones (`label_bodies_meta` lists memory commits; `place` seals with the header's class into the overlay; `Entry::memory`/`BlobRec::memory` keep every sync record about them out of `y/`); `Engine::closure(g)` is the durable closure; node-sync routes by the blob's prefix class in one place. Particular to `memory.rs`: caps and full peers (below); presence per connection (`memory_lost`; an entry with no body here that the first listing since the join lacks goes once held nowhere, untombstoned, `stream_read`: nothing deleted it, and a tombstone would keep a part valid again from arriving; so a reader's flood no peer carried clears then); coalescing; carriers of a dropped memory part read from the engine (`carrier_of` follows `Dropped::covered_by` via `Engine::coverers_of`, since `drop_covered` sets no carrier row; without it a deleter snapshots the aspect anew every pass); forgotten headers; pages and chunks charged on arrival (`ingest_memory_blob`) and deleted at hosts by their forgotten commit's freed links; tombstones at `MAX_DRIFT`; relay-only commits (`relay_in`, `send_relay`, `RelaySeen`).
- **Forgotten headers** (`Memory::forgotten`): a forgotten memory commit's header is kept while its entries or its pages' entries are known, so deletes at hosts of a commit not held are judged by it; a coverer forgotten before it was placed stands for what covers it (`carriers_of_forgotten`). One held again (its cover fallen, its author's copy back) is judged by the join like any held body, never by the record of what covered it when forgotten, or a holder deletes the author's every re-placement (`held_again_judged_by_the_join_not_its_forgotten_cover_spec_sync_9`).
- An entry outside the closure is deleted as a durable one is: by a node holding its body once its view is settled and its closure whole (closures are durable data, persisted across a restart; notes/sync-convergence.md Never judged).
- Only commits the engine verified and holds are kept, served and spread (spec/sync.md §9 Verification; `Ingested::Awaits` keeps nothing and is fetched again); another blob of a held commit has its signature and delta hashes checked before it is kept. Validity, ordering and replay are the ordinary commit rules: a replayed old ephemeral commit only re-adds writes its stamps already lose to, or that holders still have; a replay of a covered commit is not held again and a writer deletes it.
- **At hosts**: the blob prefix has a class (byte 25, osis-label `Class`: durable, `ephemeral`, `relay`), from the commit's marker (spec/sync.md §3). A node that cannot read L keeps L's ephemeral entries (blob, wrap, stamp, tombstone) and their log events in memory only (`Ephemeral` in `HostStore`), under a per-label byte cap and a total (Bounds), code 12 past them; an ephemeral deposit counts toward the label's one deposit budget too (`EphLabel::dep_n`); a relay-only blob passes the relay gate and is not held. Ephemeral deletes are rate-limited, due times indexed (sweep budgeted). The rest is the ordinary path: entries taken by stamp from what it pulls, served by the stream (each join lists the live ephemeral entries, spec/sync.md §10), expiry, delete keys. Leak: a host learns which entries are ephemeral; nothing else.
- **Ephemeral signals** (spec/sync.md §9 Relay-only commits): one relay-only commit per write, built and signed by the write (`ephemeral/signal.rs` `fire`, snapshot deltas), never paged (`osis_crdt::Unpaged`), told to the writer's own commit listeners at once; `take_signals` hands node-sync those on a synced thing. A host or co-reader peer accepts it by stamp, pushes it to the label's current subscribers (`SessionOutput::Relay`, a `Push` of one add event at the subscription's cursor) and holds nothing (no entry, log event, tombstone or expiry), admitting it through `osis_proto::RelayGate` (expiry window, `MAX_RELAY_BLOB`, per-label rate, push once per blob). `ingest_relay` verifies, judges the author's write role through the thing's timeline, tells each valid signal part to commit listeners once (`CommitChange::fired`) and holds nothing. Dedup (`Delivered`) is per (commit, part): a commit whose parts have different readers goes as several blobs. The floor past `MAX_DELIVERED` is per author (a shared floor would let one flooding writer drop every group's signals). `RelaySeen` is checked before opening but recorded only once verified, so keyless junk cannot raise the floor.
- Tests: osis-node `tests/it/ephemeral.rs` (`random_window_converges_*`: four writers, two hosts, random writes, partitions, restarts, a random host cap on odd seeds; properties `random_window_converges_large`, `random_window_one_capped_host_*`, seeds by `OSIS_EPH_START`/`OSIS_EPH_SEEDS`), `memory_*` differentials, `random_churn_converges*`; osis `tests/it/ephemeral.rs`; osis-host `hub::relays_are_held_by_nobody`, `hub::ephemeral_entries_in_memory`; vectors; sim `ephemeral*`.

## Memory commits
Ephemeral data is Core's memory class end to end. What is special: memory storage (the overlay), forgetting spent commits, the second session and superseding, ephemeral signals, the caps.
- **Receiving**: every ephemeral blob goes to `Engine::ingest_memory(bytes, room)`, routed on `Ingested`: `Applied` kept as an entry, `Duplicate` kept once `parts_genuine` (a copy carrying the held parts' bytes), `Pending` kept and charged its bytes (`Memory::waiting`, applied by `Engine::apply_waiting_memory` within the room then; `reexamine` never applies a memory commit), `TooLarge` refused and reported, `Parked` dropped. Parts are judged like durable ones (spec/permissions.md §5.2), applied atomically, un-merged by demotion.
- **Each step** node-sync drains the engine: `take_fallen` (Convergence, A snapshot turning invalid), then `take_memory_drops` (commits forgotten, `MemoryDrop::{Covered { by }, Superseded { by }, Gone}`: the lane forgets their entries and, as a writer, deletes them per label once a coverer or superseder is held there, or at a full peer as Caps and full peers says; `Gone` deletes at once).
- **Snapshots and covering** (`retention/memory.rs` `drop_covered`, `retention/snapshot.rs`): a memory compaction snapshot is commit form, the aspect's whole state at that node (every author's writes, frontiers over every session, expiring values value-less, `retention::snapshot_state`), retention `writer` without bounds. **Covered drop rule**: a body whose author is this node drops as covered only under this node's own snapshots; any other author's body drops under any valid held snapshot covering it (why: What follows from memory, Own bodies under own covers). Of covered-equal snapshots the higher ID goes. `covered` judges a held body by the join (notes/engine-validity-uncover.md The chain of covers); per pair it reads the body, the snapshot's root and the pages at the body's positions, flat in the snapshot's size past one page; the aspect rebuilds once for all of a round's drops (`run_batched`). No receipts for memory commits. A forgotten body not held elsewhere is gone, as durable's residual (spec/permissions.md §5.2).
- **Trigger**: the one compaction trigger for durable and ephemeral aspects (notes/engine-retention-trigger.md, `retention/compact.rs`), local-only aspects too (else a rewritten UI value keeps every body); a part weighs its root plus the pages it links (`body_bytes`). Its sizing doubles as a cap bound: a host cap of `FACTOR` times the sum of the authors' snapshots holds every entry. `Engine::compact_memory_now` (tests, through `compact_ephemeral_now`) snapshots every memory aspect with a body. A host's cap refusal triggers nothing.
- **Coalescing** (`coalesce_own`, spec/sync.md §9 Coalescing): own unplaced memory bodies wait while an own memory entry under the label is not yet pulled on the connection, then go as one snapshot per aspect: of their join alone when all are this session's plain writes (`Engine::coalesce`), of the whole state when a snapshot is among them (`Engine::snapshot`); none coalesce where the aspect keeps live bodies (the snapshot would drop none). Why a snapshot, not one delayed plain commit: that needs restamping, since a writer delta's commit-level writes carry the delta's stamp (spec/crdt.md §3.3 rule 7); a snapshot carries foreign stamps and its frontier makes it exact. Expiring writes are thinned by superseding instead; signals are not held back. Measured: one entry per aspect per round trip, whatever the write rate.
- **Paging and large values** (spec/crdt.md §8, spec/data-model.md §6): chunk trees and pages exactly as durable ones, through the one framing with class `Ephemeral`; pages and chunks are memory blobs (`TxBlobs` memory, the hub store's `engine_mem`), found by walking what a commit links (`apply::reach`, Caps and full peers). Why paging: valid commits from others can grow an aspect's state past a blob, so no writer check could keep snapshots unpaged. A forgotten commit's links join its things' freed sets as memory rows (`unindex_commit`, `retention::freed`), judged as a durable drop's: a freed piece's bytes go (charge released) and it is deleted at hosts by the keys its link names; its bytes arriving again are not kept. Tests: osis-node `large_value_chunks_syncs_and_goes_spec_data_model_6` (20 MiB, its tree gone everywhere once covered), `grown_past_a_blob_compacts_spec_sync_9`, `pages_count_against_the_cap_spec_sync_9` and their neighbours in `ephemeral.rs`.
- **Growth**: `MemorySync`'s sets drain each step; the trigger keeps an estimate per aspect of two bodies or more written since the open (`Trigger::est`), bounded by the aspects held; memory commits are bounded by the caps and forgotten once spent.

## Caps and full peers
- **Decode rule** (spec/sync.md §9 At a node): nothing of a memory commit from others is decoded before its header lists resolve and every page and value root its parts link is held (`apply::reach::walk`: a tree node is a root, not followed; anything else linked is a page, followed), and its bound fits the room its label's cap leaves (`apply::memory::memory_gate`, given `Core::memory_room`): `new_parts_bound` = `decoded_bound` of each part and of each page or link page it reaches, plus what its roots' lengths claim of their trees not held (`reach::unheld_bytes`; a held node below a root counts none). So a value past the room is refused at its root, before any chunk is wanted (`value_past_the_room_refused_at_its_root_spec_sync_9`); chunks are charged on arrival as entries, and a root lying short is bad input at its first mismatched chunk (`osis_commit::tree` `lengths_checked_spec_wire_6`). Admitted and applied, the rest of its trees is wanted at once (`Walks::trees`: a node held when first reached below a root is taken as whole, so an edit reusing a value fetches only what it changed, `edit_of_a_large_value_walks_what_it_changed_spec_sync_9`). Checked at arrival (`ingest_memory`) and whenever a waiting one applies (`apply_waiting` each step, counting the entry's own waiting charge as room; one still lacking a blob, its `ts` or epoch is not tried, `still_waits`). Only a commit whose author signed it waits so; one whose author is not held is unjudgeable and nothing is kept. `MAX_PAGE_ITEMS` bounds one page's decode too.
- **Refused and fetched again**: a node-cap refusal (`ingest_memory_entry`, `apply_waiting`: room, `unfit`) is fetched again once the label's bytes drop below what they were at refusal, a never-fitting one not at all; a page or chunk refused waits with its commit (`fetch_waiting` skips it). A host's refusal: the entry reaches no holder through that host until room appears; the writer reports `EphemeralRefused` and retries at the periodic pass (`resync_ms`).
- **Full peer** (spec/sync.md §9 Full host, §10 Full): at a peer full for the label, a writer deletes a forgotten commit's entries, covered or superseded, without waiting for its carrier there, which waits for the room those entries hold (`carried`, `At::full`). Else the peer keeps entries every holder forgot, taking room held entries need (`full_peer_frees_what_every_holder_forgot_spec_sync_9`), and one with room for one refresh of a cursor and not two keeps the old one to its expiry (`refresh_reaches_a_peer_with_room_for_one_spec_sync_9`). Not once an entry of it left that peer since this node forgot it (`Forgotten::left`, its own delete included): a holder lacking the carrier placed it again, and deleting again loops with the next placement (`full_peer_keeps_what_a_holder_placed_again_spec_sync_9`); so it deletes there at once at most once per peer. The writer judges by its own forgetting alone: a reader reaching the label only through that peer lacks those writes until the snapshot fits there or a holder places them again (writes past a peer's cap stay with their writers). Rejected: the full peer giving room that grew to what it refused before anything new (a carrier larger than the room freed is refused again and the loop goes on).

## Restarts and lost access
- **Restart**: everything ephemeral is gone locally and the next open draws new sessions; nothing per session is kept. Syncing brings back what holders kept, own old-session writes included (held like others' commits, compacted by the trigger). A host restart loses its ephemeral entries; holders log them again, since presence is per connection.
- **Failed store writes** restart node sync in place but keep its memory class (notes/node-sync.md Failed writes): the engine keeps its memory commits through a failed write.
- **Lost read access**: forgetting what a node lost (notes/engine-lost-access.md Forgetting) takes the memory class too: the lost things' ephemeral state, entries and charges go, and a memory blob holding a forgotten part loses key and bytes, its entries under kept labels shredded, as a stored one; the memory records of labels still synced stay (`losing_one_label_keeps_ephemeral_entries_of_another_spec_sync_9`, `partly_forgotten_ephemeral_commit_keeps_no_key_of_the_lost_part_spec_permissions_3`).
- **Open** (issues/eph-parity.md Leaving a closure): a node that stops syncing a label while it still reads the things keeps their ephemeral state until restart, under no cap.

## Convergence
Ordinary (spec/sync.md §6): a holder bridging two hosts or a co-reader peer serving its own label carries ephemeral state across; a joiner or restarted node gets the state by its first sync from any host or peer holding it; if every host restarted, the hosts pull it again from the holders.
- **A snapshot turning invalid** (spec/sync.md §9; `take_fallen`, `relist_fallen`, one rule for both classes): on a held snapshot's valid-to-invalid flip (a role change; at most one snapshot per writer and aspect per step) what it covered is missing again. A memory commit forgotten under it left no record, so node-sync takes the entries of the commits it forgot as covered or superseded on that aspect: lifts its own tombstones of them (durable alike, `compaction::fallen_own_snapshot_lifts_own_tombstone_spec_sync_7`), sets them unopened and has every stream carrying the labels list its memory entries again (`stream_relist`), so a peer's copies come back. For those a host deleted, a writer still holding a valid part writes a fresh snapshot of what it holds: logging the covered entries again would meet the host's tombstone (`compacted_write_of_removed_holder_stays_spec_permissions_5_2`). One forgotten with its deleted thing (`Gone`) is not asked for again. Tests: `fallen_snapshot_fetches_covered_back_spec_sync_9`, `fallen_snapshot_lifts_own_tombstone_spec_sync_9`, `snapshot_invalidated_by_self_removal_fetched_back_spec_permissions_5_2`.
- Limits (spec/sync.md §9, as durable's spec/permissions.md §5.2):
  - A write covered by a snapshot that fell comes back only from a writer still holding it (its own it kept). One no such writer holds (its author restarted, or never held that snapshot valid: it learned of the demotion first) stays gone at the hosts and readers that dropped it until its author writes the aspect again.
  - New sessions: what a node wrote under the old session after the grant's key and before it learned of its demotion stays held uncovered, within the caps, until it restarts (a body invalid for good has no later body of its node behind it).
  - A superseder turning invalid later does not bring the commit it dropped back (a memory part's late copy is refused, `retention::takes_late`; durable keep-bound drops join again, spec/commits.md §5).
  - Relay-only: within `MAX_DRIFT` of its `ts` a signal can arrive late (a delayed push), and a restarted node can see one again if a replayer sends it to a host that forgot it.
  - Relays are not delayed, so every bridging holder logs a duplicate (answered OK).

## Expiry
- Expiry is death by timer (spec/crdt.md §4.8): the values die at T and the body follows, whatever the deltas' keep bounds. "Keep at least until T" is a retention bound (spec/commits.md §5), a different thing.
- Uses: disappearing messages (read-based timers and earlier deletion are app writes; core expiry is the hard upper bound a host enforces unattended) and buffered events (a list aspect with a one-hour default). Leak accepted by Tess: a host learns which entries expire and when. Not provided: host-enforced minimum retention (legal hold).
- **Ephemeral expiry is durable expiry** (spec/crdt.md §4.7): at T an ephemeral delta's value-carrying writes go value-less and its other writes (resets, removals) stay; the body is held as its leftover (`make_leftover`, the overlay's `w/` row) until a later write of its author supersedes it (`superseded_rest`) or a held valid snapshot covers it (the join judges it like any body; before T it covers one only once none of its values lives, `dead_expiring_ephemeral_write_covered_before_expiry_*`); then it drops and its commit is forgotten (`unindex_commit` also takes its writes off the value-less list, so a copy arriving later applies as new and goes again). A copy arriving after T joins value-less as the leftover. A snapshot carries the leftover's writes value-less, so a node that missed the delta (offline at T, restarted) gets its resets from the next compaction; until then it may read what the delta removed, as for durable data (`expired_removal_stays_spec_crdt_4_7`), at most until a writer holding the leftover has been quiet for `QUIET_MS` (notes/engine-retention-trigger.md Cover once quiet).
- **Memory cost**: one held leftover commit (about 3 KiB as the trigger weighs it) per expired ephemeral commit until a snapshot covers it; leftovers count in the trigger, so any writer holding them compacts, and a holder that may not write drops them under a writer's snapshot. The snapshot keeps each list element's value-less anchor (about 1.15 KB charged each, never collected), so an expiring list's lifetime elements at a holder are bounded by its cap (issues/eph-expired-anchors-fill-cap.md). Measured by `memory::eph_leftover_memory` (release, by hand): 2000 expiring list elements, one per commit, expire in 0.16 s (6000: 0.6 s), writing them costs more (5 s, 27 s: each write re-encodes the aspect's unpaged state); RSS does not shrink as the heap frees.
- **Expiry cost**: linear in the expiries (`ephemeral::expiry_round_work_linear`): each strips the state in place (`apply::strip_state`, notes/expiry-creation-design.md Expiry in place), a round rebuilds each aspect once (`apply::run_batched`), the value-less list is searched per dot (`retention::sorted_owns`).
- **Expiry never waits for a Tick** (durable too): a Tick comes late (`MIN_WAKE_MS` throttle, a suspended process), so the osis handle runs `SyncEngine::expire_due` before every call: when `Engine::timers_due` (`Core::timer_floor` and the ephemeral timer map) it runs `Engine::tick`; every sync step starts the same way. Pushed change events still wait for the Tick or the next call, so a subscriber's last value can show past T until then. Tests reading through the engine call `expire_due` first (`random_churn_run` checks no value is read at or past its expiry).
- Nothing is kept "until every receiver has seen it": the receiver set is open and nodes die. What must survive every holder forgetting it is durable state: the inbox pattern (a list the receiver holds, senders append, the receiver deletes, expiry as backstop) or a list with expiry.

## Values that live while their author is there
Tess's decision: a value that should live only while its author is there (a cursor, a selection, an "online" mark) is an ephemeral aspect with a short default expiry (`+` key, `expires(30s)`) whose author rewrites it before it expires; when the author's node goes away the rewrites stop and the value is gone at every holder by its last write's expiry. Nobody needs to notice the departure: no connection tie at hosts, no source tracking or un-merge at holders, no lease constant.
- **Helper**: `db.at(t, k).path(p).keep_alive(&value) -> KeepAlive` writes the value and rewrites it every `expiry / REFRESH_DIVISOR` (2) of the key's default expiry on the handle's runtime until dropped; `KeepAlive::set` writes a new value at once. The key must be ephemeral with a default expiry. A rewrite is a `Put` (a fresh entry at a map key, a fresh register write elsewhere): a `set` of an equal value writes nothing, and a write into an entry an expiring write created outlives that entry unless it expires no later. `Replace` would not: at a live key it writes into the old entry and goes at that entry's expiry.
- **Cost**: each rewrite supersedes the write before it (Superseded expiring writes), so a holder and a host hold about one commit and entry per kept value, and one entry is logged per value per half expiry or per round trip while it changes. An expiry under the sync tick (1 s) still rewrites every half expiry while expiry is applied only per tick.
- Two nodes keeping one path alive overwrite each other: key by node (`Osis::node`), not account. Nothing survives a restart: the app calls `keep_alive` again. The schema's expiry is how long a departed author's value lingers against the rewrite traffic; 30 s suits cursors.
- Rejected: write-level "until the author disconnects" (Tess's idea, evaluated). It needs a host tie per connection, holders tracking which host or peer still has the author's entry, un-merge when none does and a lease backstop for half-open connections, and "disconnected" is per path, so holders behind different hosts disagree.
- Tests: osis-node `ephemeral::refreshed_value_lives_while_author_present_spec_crdt_4_7`; osis `runtime::keep_alive_rewrites_until_dropped`; sim `ephemeral`/`ephemeral_capped` (`author_leaves`: a refreshed cursor is owed only through nodes whose clocks are before its expiry, and gone past it once the author is down; `net::a_cursor_dead_at_its_only_carrier_is_owed_to_nobody_spec_sync_9`).

## Superseded expiring writes
The one rule beyond the durable ones and memory's (spec/sync.md §9 Superseded parts): a drop that is neither cover, expiry nor purge. No general rule covers it: no snapshot carries an expiring value before it expires (spec/crdt.md §8), and a rewrite at a map key (`KeepAlive::set`, a cursor map) is `Op::Put`, a fresh entry beside the old one, which stays live in the CRDT (shadowed only in the read) until its expiry. Without it a renewed value costs one commit and entry at every holder and host per rewrite until each expires: about 450 per author at 30 s and 66 ms, a cursor per author filling a host's default cap (`moving_cursor_one_entry_per_author_spec_sync_9`: 60 moves, one entry). A move as removal plus `Put` would leave a map tombstone per move in every holder's state. Built for memory only: a durable expiring value rewritten often stores one body per rewrite until expiry. Alternatives: issues/retention-modes.md (Ephemeral), issues/connection-lived-data.md.
- **Rule** (spec/sync.md §9's conditions; `retention/memory.rs` `supersedes`, `superseder`, `drop_superseded`): judged per part by the two parts alone, since a commit-level rule would make the author and holders differ through the covered drop rule's own-author exception (`superseded_part_goes_whatever_its_commit_holds_spec_sync_9`). Checked when a commit is held, own builds included (`drop_superseded_by`, against only its author's commits), when a part goes value-less at its expiry (`superseded_rest`) and when parts turn valid (`drop_superseded`). Cost: a new commit decodes each held expiring commit of its author on its aspects expiring no later, unless it is a sequence, a bag or carries a reset (a burst of `n` expiring map puts by one author costs `n²/2` small decodes; lists none). A received commit all of whose parts are superseded on arrival is not held (`Dropped`).
- **Not death, but convergent** (spec/crdt.md §4.8): the drop is a function of the commits held, never of later writes: every node holding the newer part valid drops the older, and a later removal or undo of the newer entry kills only that entry everywhere. Each condition closes an order dependence:
  - the author drops the superseded writes from its own state and unsent writes too, else after a holder removes the newer entry only the author reads the old one again (`superseded_stays_gone_when_newer_removed_spec_sync_9`);
  - neither part carries any reset (`Fragment::has_any_reset`): a superseder with a reset makes the relation intransitive (q replaces the aspect over p, r later puts without it: r supersedes q but not p, so p is dropped or held by arrival order), and a superseded part with a reset takes its tombstones with it at holders but not at the author;
  - the superseder expires, so no cover ever absorbs it (a node that got only the cover would read the move again once the plain entry is removed; `superseding_part_expires_spec_sync_9`);
  - the ts order and the expiry guard: a later write expiring sooner, or an older write with an equal value, supersedes nothing (`superseding_needs_later_stamps_and_no_reset_spec_sync_9`).
- Rejected: real death. Each move would have to tombstone every own unexpired entry of the key (about 450 per commit), since dropping a commit drops its tombstones too.
- **Holders and the author** drop the superseded part and rebuild the aspect without it (`memory::vanish`), recording its superseder (`Dropped::superseded_by`, in memory); once no part is held the commit is forgotten, reported as `MemoryDrop::Superseded { by }` if any part was superseded. An own commit superseded before it was placed is forgotten the same way, never sent: a burst of moves before one pull goes up as the last one. The lane deletes a superseded entry where a superseder is held, else at its expiry.
- Measured (`many_authors_under_a_peers_rates`, 10 authors moving every 33 ms for 1 s at a 66 ms round trip): 160 entries logged, 0 deletes, the host's peak 43 KB, one entry per author at the end; without the rule 224. Its `_by_hand` simulated minute at the default policy: 9100 entries, 0 deletes, peak 1.76 MB of the 16 MB cap.
- Tests: osis-node `ephemeral::superseded*`, `superseding*`; `random_churn_converges_spec_sync_9` and the property `random_churn_converges_large` (random expiring and plain puts, removals, replaces, undos, demotions, partitions, restarts: every holder reads alike).

## The all-nodes predicate
"All nodes a thing syncs to" is a state predicate computable at nodes that read the label, never a protocol condition. Per label: the nodes with a valid chain that published `node.0` under the thing's label (not "every node of every holder", which needs rosters readers never see).
- Recency: no group data says when another node last synced (nothing per node goes in groups, issues/account-signing.md); a node's last sync is its own record (`last_sync`). A recency predicate needs a new source (own nodes under the account's sync ID, or a peer's word over a connection).
- Uses: write a new schema form once every node reads it, drop old-form history after that, clean up an inbox once every own node has acked. "Buffer until all have seen it" = inbox pattern plus this predicate plus expiry as backstop: a core helper later, not sync machinery.
