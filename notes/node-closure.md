# The node closure (engine)
> Summary: How the engine holds spec/sync-set.md §1-§2: the node root, the closure as one spanning tree over (context, thing) vertices followed per edge, what sync units and the sync set read of it, tickets in the walk (what a held ticket does, which things are independent here, the account's tickets, sync IDs several things own), the making rule, work counts, and what a strong to a thing whose record is lacking fetches again.

Spec: spec/sync-set.md, spec/sync-inbox.md §5 (tickets). Model: notes/closure-model.md (held-model `closure`). Code: core/engine/src/sync/units.rs, sync/tickets.rs, flows/roots.rs, sync/set.rs, retention/release.rs. Fires and deposits: notes/sync-inbox.md.

**Principle:** a node holds exactly what its node root reaches by strongs, sync unit by sync unit; the structure is kept by edits, each costing what it changed.

## Design rules (Tess)
- **A strong grants nothing.** It says the target belongs to this closure; anyone knowing a tid may write one. Permission is a separate act by someone who may grant, and removing a reference revokes nothing.
- **A thing goes when its last reference goes** (spec/sync-set.md §3). That is the intended result, never a risk to design around: nothing is kept because a release might be a mistake.
- **Core holds only what cannot be built correctly on top of it.** Home, which invitations to accept, contact lists and "what is on my other nodes" are the app's.
- **Lean on osis for storing data.** Node and account state are ordinary things and aspects. No aspect is exempt from sync; what is local is local by where it sits.
- **A weak keeps nothing.** What a node keeps outside its closure is only what held things need (spec/commits.md §5 What a held thing needs). A contact is a strong to its profile.
- **One mechanism.** A ticket is the one way to say "here is how to sync this", wherever it is stored; core never copies one.
- **Nothing grows only.** No set of everything ever seen, accepted or granted. Storage: issues/storage-owners.md.

Why a sync unit stops where its root has no read access: a closure granted read on a large thing carries just what it references of it, so one row of a table syncs without the table and without keys per cell (spec/requirements.md, no unit synced whole). So Alice's A, admin of T, references T; Bob, a reader of A, adds a strong to T from his B; Alice removes hers: B never carried T (Bob reads T, B does not), so T is gone for both, unless Alice shared T with Bob or with B (sync `holding::the_last_reference_gone_the_thing_is_gone_for_everyone_*`).

An edit of a thing carried under two sync IDs reaches a node syncing only one of them through a node that syncs both (notes/closure-model.md (d)); in an admin dispute the sides differ on what is valid, and so on what belongs.

Kept, each following from a rule above (don't simplify them away): the refused removals of the node root's and D's strongs (Roots); D's tickets only for what is entered outside the local part; release's one wait (an own self-removal); the retained copy (an option keeping its property); an independent thing as its own inbox; nothing before the strong, so a grant counts only at a strong; a grant naming a holder in the holder's required set, needs and fire (one fact in three places); fetching again at a new strong (rare-path brute force); a stranded notice acted on whatever the history setting.

## Roots
- The node root is made at the node's first start (`Engine::make_node_root`, local record `records::NODE_ROOT`), mint admin the node; the node writes it and each of its dependents as itself (`Core::nodes_own`: the record chain reaches the node; `made_nodes_own` for things a commit makes): no account holds a role there.
- The account's creation writes D's strongs to the profile and the inbox, and the node root's to D, in its transaction; pairing writes the node root's strong to D (`Engine::paired`). No strong reaches a node thing: the walk enters no key actor, and retention keeps every node the account's chain names, a removed one too, as the minter of rotations it follows (`retention::needed`, `AccountView::named_device`).
- A local commit after which the node root no longer strongly references D, or D the profile or the inbox, is refused however it was written (remove, whole set, removed aspect, undo, purge): `commit_in` compares those strongs in the index before and after (`roots::kept`, `still_kept`), O(1).

## The structure (`Closure`, an index: journaled, built again by an open)
- A vertex is (context, thing). A context is `Local` (the node root's local part), `Read(T)`, `Unread(T)` (T's sync unit entered read or kept unread) or `Ticket(T)` (Tickets below). The root is (Local, node root).
- A vertex's edge to each target of its thing's strongs (current values', and held history's where the setting says so: notes/engine-refs.md History holds) gives (`given_by`): in Local, a dependent target; in `Read(T)`, a target T's keys open (`Core::keys_open`: on the record chain of its independent, or T's role there read or above); from either, an independent target the context does not follow enters `Read(y)`/`Unread(y)` by the secrets the node holds of it (`Core::enter`), and so does an independent target inside a read unit (it holds nothing more, but `units_holding` names every sync ID carrying a thing). Kept unread is its root alone. A key actor gives nothing.
- The local part follows a dependent thing only when the node opens it (`Core::opens_plain`: a read secret of the independent thing its secrets derive from, or the keys of the key actor they derive from); a tid with no record held opens nothing, so a strong to it holds nothing and `NotCarried` names it.
- `sync_unit(T)` is the members of `Read(T)` (read whole: listings, whole derivations); `Closure::unit_holds(T, t)` asks one member, stamped per (context, thing), and `member_feed` gives members as they come, so per-commit judgements (`BodyCtx::holds`) and own commits move with what entered or left, never with the unit's size; `units_holding(t)` gives the `Read` contexts holding t; the node closure is every thing of any context.
- Followed per edge: an `Effects` key per (held vertex, strong target) records what `given_by` read (independence, roles, secrets, records); the reference index tells strong rows appearing or going (`Closure::note_row` from `refs::note`), since store table reads stamp a whole table. A settle at each transaction's end (`units::settle`) applies due edges and noted rows; an open's reload settles it. Only a rollback of a transaction whose settle ran resets the follower (`Follow::rolled_back`: every held vertex's edges followed afresh, O(closure)); a step or write refused before the settle leaves it right, since what a rollback restores stamps what it read.
- Two trees over the same out-lists (`Tree`, one detach and one `spread` for both): the node closure's, and the sync set's (`Closure::synced`), where an edge into a thing sourced elsewhere (`cut`, spec/sync-set.md §5) leads nowhere. The sync set's tree follows the edges that moved (`moved`) at each settle's end, and the cut as `Engine::set_sourced` sets it (a reload keeps the cut). `in_sync_things` and `things_entered` read it per thing and by feed; `sync_things` is the whole, for listings.
- Removing a tree edge runs two searches in step (the target's other referrers up their tree paths; the target's subtree), stopping at the first answer; a subtree found whole re-attaches what a held referrer outside reaches and drops the rest (`detach`). A thing out of the node closure at a settle's end is noted in `left` with every context it was dropped from in that transaction, until `released` (notes/sync-leave.md).
- Work counts (`closure:` costs), engine `closure::removal_costs_what_it_held_spec_sync_set_2` at n = 6 and 60: a non-tree referrer of a target with fan-in n, 1 / 1; that target's tree edge with referrers outside, 1 / 1; a tree edge with a shallow alternative over a subtree of n, 7 / 7; one whose alternative is n deep, 5 / 5; a subtree of n released, 3n. With A sourced elsewhere (`closure::a_sourced_thing_costs_what_is_below_it_spec_sync_set_5`, n = 6 / 60): a thing entering, 6 / 6; leaving, 13 / 13; moving A away, 43 / 43 over a closure of n, 76 / 670 over n below A; home, 19 / 19 and 34 / 304.
- Checked: `units::check_whole` walks the node closure afresh by `given_by`, and again with edges into cut things leading nowhere, and compares each tree's held vertices and parents (`Engine::check_closure`, inside `check_index`; the closure tests run it after every edit). It shares `given_by`, so `given_by`'s own rules need behaviour tests (`units_holding`, `not_carried`).

## Tickets (spec/sync-set.md §2, spec/sync-inbox.md §5)
A ticket says how to sync, never caps the node's role.
- **Found** by target in the ticket rows of the reference index (`refs::tickets_to`: a state's per aspect, a signal's per fire, so a lookup reads the target's tickets alone; `sync::tickets::held_in`) and opened as a `secrets.0` box of the target to its holder (`Core::open_ticket`).
- **Judged** at every held strong to a thing its context cannot follow while the node holds no established read secret of its own of it (`sync::units::judge`, `Core::reads_established`; not one derived from its mint admin's, as a paired node reads the profile before its keyset arrives). A ticket's epoch is its maker's to choose, so a forged ticket taken first must not keep the honest one out: a ticket row appearing or going, or a removal notice arriving, judges each held strong to its target again (`Closure::rejudge`).
- **The node's role** (`sync::tickets::role_on`, the one place): the best of what the held edge writes on the thing show (`rotation::role_here`) and, while a held strong reaches it (`Closure::accepted`), each opened ticket's word (`Closure::ticket_words`, noted by `take_in` before it takes any secret) where the held role commits cannot decide: a sync word (kept unread: only certificate-brought role commits, which reach the account through other holders without its own grant, holding::a_sync_ticket_beside_a_removed_holders_role_commits_keeps_the_thing_unread), and a read word while its holder is not upstream of the thing (`Held::upstream`, the engine's path search over held edge writes and records). So a reader by chain whose chain is cut loses its D ticket's read word (holding::a_removal_reaches_a_reader_opening_the_holder_through_a_second_thing). Rejected: a read word dropped once any role commit of the thing is held (a reader holding other holders' commits but not yet its chain lost bodies: full-size differential seed 24), and D's tickets never counting (past the inbox fire's lifetime they keep a thing kept unread, spec/sync-set.md §1; siblings read by them). A ticket supplies its sync ID and secret up to the lower of its role and that one (`take_in`, through `learn_secret` and `rotation::may_learn`); `given_by` reads `role_on` too, so a role change judges the edge again. The lost-access trigger judges by the same role (`rotation::lost` `holds_at`, `over_held`: a sync secret is over-held below sync, any other below read): a ticket taken while the trigger drops its secret would undo itself every settle.
- **What judges it stays**: a held strong needs its target (`retention::needed` `Need::Strong`), entered or not, so the thing's record and role commits stay through lost access and release and not entering changes no input of the rule; once no held strong reaches it, it goes whole, and accepting again is a first accept. Without it a release forgot the removal and the stale ticket counted again. `Closure::accepted` (per target, the held vertices whose strong reaches it with a ticket opening here) roots nothing: it gates the ticket's word (`role_on`) and notes a lost need as its last vertex goes.
- **Carried commits** (spec/sync-inbox.md §5): one taker, `Engine::take_fire` from `follow` through `Closure::fires_due` (records, chain, commit, each only where valid, pending on what it lacks; only while the commit is not held whole, so judging again retakes nothing). Due at a strong reaching the thing with a read ticket opening (`tickets::take_in`: its ticket fires' `grant`, `fire_untaken`, and `flows::inbox::removals_due`, the notices on the account's inbox naming it: O(the notices the inbox keeps), as a notice names its thing only inside its commit); a removal notice also once the thing's roster is held, as it arrives (`Engine::notice_arrives`, which also re-judges the thing's strongs) or as the roster comes (`owe_removal_notices`: a role commit on the account's own edge there, `removals_due`). Each trigger is needed: a holder removed before accepting is refused by every peer, so the fires at the strong are all it learns its role by; a notice can come before the roster (a new node of the account takes the inbox first, the roster comes later with a chain through the thing, sync `holding::a_removal_notice_taken_before_its_roster_acts_once_the_roster_comes_*`). Rejected: a grant taken by the roster too (a role by chain through a thing never accepted then counts: sync `holding::a_role_by_chain_through_an_unaccepted_thing_counts_nothing_*`); every notice taken as it arrives, leaving the roster to ordinary pending (a declined grant's notice applies with the records it carries, and its thing's record and commit stay unneeded: sync `growth::a_declined_grant_returns_storage_to_a_fresh_worlds_*`). A sync ticket's fire is not taken at the strong: it enters at sync at most, and taking it at every start cost commits per thing kept unread.
- **A holder fire's `grant`** is taken by H's readers as the fire arrives, outside the gate: it is in H's own sync ID's required set (spec/sync-judgement.md §2), not a commit the holder takes for its role on T, so a node reading H logs it there whether or not it holds T.
- **Independent** (`Core::keyed`): a thing is independent here by role commits held or an established secret of its own; a ticket's secret establishes nothing (a forged one must make no dependent thing independent). A thing not independent here is entered on its tickets' word at their entry role (`units::given_by`): a read ticket enters `Ticket(T)`, a sync one `Unread(T)`. `Ticket(T)` is a root alone, in both trees (so `sync_things` and `in_sync_things` see it); its tickets' sync IDs are synced (`sync_ids::actors::ticket_hints`: hints with no path, every one while no held `sync.0` owns one, never one another thing owns here); `Closure::holds` skips it, so none of its data is held for it and a thing held so alone releases; its sections open, as it syncs the thing's sync IDs (`Closure::reaches`, notes/whole-commits.md Sealed sections). Once its role commits arrive it is independent and entered `Read(T)`. Its tickets' sync IDs and roles are kept per thing (`Closure::ticket_ids`, by sync ID `naming_ticket_id`), set at each judgement that takes tickets and cleared at the settle's end once no vertex of the thing is held: a thing moving from `Ticket(T)` to `Read(T)` is dropped from one before it is held in the next, and its tickets' sync IDs are what its `sync.0` still has to arrive by.
- **Openers** are an input of the ticket step: per thing, the holders its held tickets are boxed to, opened or not (`Closure::openers`, by holder `by_opener`), set and cleared with its ticket IDs. A holder that can open more (a key actor or the account taken up, `flows::take_up_opener`; a thing whose secrets grew, `reopen_dependents`) re-judges the edges into those things alone (`Closure::opener_moved`). Counted (engine `closure::a_take_up_costs_what_the_opener_opens_spec_sync_set_2`, 5 / 50 independent things held): a key actor taken up, 0 / 0; `create_link`, 11 / 11.
- **S's things** (`Engine::sync_things_of`, spec/sync-inbox.md §5): every thing owning S (by `sync.0`, destruction, link, or held tickets naming it); the sync set's entry is all of them (`rows::fold`: read while any reads it), never one by tid. Per-S rules run for each: `read_things_of`/`opening_things` (opening, credentials, opening secrets, bodies joined by `join_body`, own scope, lists, records), `body_thing` (the one whose body of a commit S carries: sealing, logging, promotion), `judge_peer` the best of each, caps the largest. Path rules (signers, steps, stranding, register) use `recorded_owner`/`read_sync_id`: hints have no path. Several things claim S only while S is a hint (`ticket_hints` drops one another thing's `sync.0` records), so the genuine `sync.0` arriving under S ends a forged claim.
- **The account's tickets** (spec/sync-set.md §1; `flows::inbox::account_ticket_due`): due while the walk enters the thing from a vertex outside the local part (`Closure::entered_outside`) and D holds no ticket to the account of that role, per sync ID, at an epoch it holds the thing by there (`held_by`): read, a current (established) one, so a ticket accepted by its read secret alone is written once the thing's role commits arrive; kept unread, the newest n among the held sync secrets a step of S's stored path bears the key of (`Cipher::bears`, read through the store's row stamps, so a step arriving moves the `Effects` key). So a forged ticket's made-up epoch never reaches D and a genuine rotation's replaces the old one once the next step registers; boxing every held secret instead would grow D by every rotation and keep forged ones as long as the strong. Writing one removes D's tickets of that role naming that sync ID at a lower epoch only, so siblings seeing different epochs, or two sides of a fork, never undo each other. Release removes D's tickets for what it drops in the same transaction. On `LocalPeer` (no paths) a thing kept unread gets no D ticket: its tests are osis-sync's (`tickets::ds_ticket_for_a_thing_kept_unread_*`).

## Writing and making a thing
- **A node writes only what it holds; it fires at what it does not.** Every thing (not a key actor) a transaction's own commits make, and every thing they write that the node closure did not hold as written, must be in the node closure at the transaction's end (`Core::wrote_on`, `units::check_written` after the settle), else `Error::NotHeld` (osis `Invalid`) and nothing applies. Checked as written, so accepting and writing in one transaction, or a write that releases its thing, passes. A sealed fire is built, never applied, and not checked; a hostile writer (`skip_writer_rules`) is not checked. Without the rule a node could write a thing it was granted but never accepted and read its own write there for good, out of every closure, never released.
- Owed writes follow it: an open fire goes as a write only on a thing held and read (`inbox::fire`, else sealed); `write::writable_now` (addenda, listings) waits while a thing is not held, judged after the settle. Without it an owed addendum on an unheld thing failed every ingest transaction.
- `publish_reach` writes the profile's dial entry only once the profile is held.
- A thing a local commit mints with an account as mint admin is made independent (`Core::own_keys_due`): before the first content write on it (`write::keyed_first`: its record in the rotation, notes/thing-cost.md The record in the rotation; `rotation::own_secrets_new`, as `Engine::mint_actor` mints; then the rest of the commit under its own secrets), else at its creating transaction's end (`rotation::own_keys_due`). Role writes go first as they are, so a thing its maker makes independent itself (a link's K, its sync ID listing L) is not given secrets twice. Content under derived keys would otherwise be re-encrypted, chunks and all, by the first write after the rotation.
- Making the next thing costs what it changed, at n and 10n held (osis `making::`, every counted kind, the least of three makes so a compaction's spike is spread): no per-thing or per-sync-ID memo reads a whole unit, the account root's `tickets.0`, a whole permission component (`Timelines::on`/`role`, `Core::bound_to_horizon`), a whole store table, or every sync ID's body of a commit (`Engine::sync_body` per pair; `Live::may_log` tries S's own entries first). Certificate records are followed per record (`CertRecords`, `Engine::cert_carriers`, counted `certificate records: judged`), and a new leaf's record judges no component's key access (`Changed::leaves`, counted `keys: grants judged for key access`). What a thing costs: notes/thing-cost.md. Things an app keeps account-wide and dependent are minted with the account root as admin.
- Test helpers hold what they make where it lives (`Engine::hold_where_it_lives`: from the admin where held, else the account root, else the node root): `Engine::new_thing`, `create_with_admin`, `held_record` (the strong committed first, so the making commit is on the thing alone); osis tests use `common::Held`. `LocalPeer::hold`/`hold_at` write a strong from the receiving peer's node root, so a peer keeps another's thing only as a real node would: held, opened (a grant by the flow, not a raw edge write) and needed (spec/commits.md §5 What a held thing needs). Engine `tests/it`: `common::new_thing` holds the thing at every peer, `set_edge` grants by the flow (`edge_write` for a bare edge), `net` peers know each other's accounts (`net_apart`: strangers); an observer is a reader (`common::reader`, copied per fresh node by `fresh_copy`) or a node of the maker's account (`net_one`, `pair_into`), given its access before what it reads, since content a node cannot yet open goes at the next need-judgement. A node of an account writes as the account, so a commit cannot mix the node root with account-written things.

## Not carried
The write path's warning reads the strongs the write's ops name (`osis_engine::strongs_in`, `Engine::not_carried_among`): O(the write). `Engine::not_carried` lists the whole node closure's, O(its strongs).

## Fetched again
- A strong newly followed in a read unit (an edge `units::judge` finds new: not followed before this settle nor before a rollback's refollow; an open's first settle counts none, as the mark below was durable before the strong's transaction) to a thing whose record the node lacks and no ticket here opens (`units::refetch`): the commits it holds minting the thing lose their own tombstones and each sync ID the node holds the unit by (`sync_ids::actors::held_sync_ids`, the sync set's own rule: a ticket's or followed link's hint while no `sync.0` of it is held) is pulled anew from every source, through the ciphertext door in the engine's transaction (`Cipher::unreceived`, `Cipher::refetch`: the sync store's `N/` mark), and the sync store's follower opens the entries parked under it again. So a thing released and reached again, or a creation opened before the strong arrived, is fetched (sync `holding::a_thing_left_by_one_view_is_logged_again_by_one_still_holding_it_spec_sync_set_3`).
- A node this node's account's chain names whose record the node lacks (`flows::account::fetch_devices`, at each judging of the account's epochs): D's sync IDs, which carry every named node's card, are pulled anew by the same door (`flows::sync_ids::pull_anew`). A card that arrived before the chain could name its node (nothing named it at the pass's end, so it went) comes again, as one arriving after (`closure::a_device_named_after_its_card_went_is_fetched_again_spec_commits_5`). Test peers see each pull anew (`Wakes::pulled_anew`, `local_peer::Peer::pulled_anew`) and deliver what it brings themselves (the custody property sends the missing cards).
- Forgetting as never received (`apply::unindex_unreceived`, `retention::forget::unreceive`) ends the node's own tombstones of the commit's blobs: a forgotten body leaves nothing keeping it out.
- Cost: a pull anew lists the unit's sync IDs whole at each source, once per such new edge; it also fires where nothing comes of it (a strong to a gone thing; an account root's strong whose ticket arrives later). Rare-path brute force by intent; if it shows in counts, narrow the trigger.
