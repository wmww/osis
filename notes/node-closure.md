# The node closure (engine)
> Summary: How the engine holds spec/sync-set.md §1-§2: the node root, the closure as one spanning tree over (context, thing) vertices followed per edge, what sync units and the sync set read of it, the making rule, the roots' kept strongs, the work counts of edits, and what a strong to a thing whose record is lacking fetches again.

Spec: spec/sync-set.md. Model: notes/closure-model.md (held-model `closure`). Code: core/engine/src/sync/units.rs, flows/roots.rs, sync/set.rs, retention/release.rs.

**Principle:** a node holds exactly what its node root reaches by strongs, sync unit by sync unit; the structure is kept by edits, each costing what it changed.

## Roots
- The node root is made at the node's first start (`Engine::make_node_root`, local record `records::NODE_ROOT`), first admin the node; the node writes it and every thing made under it as itself (`Core::nodes_own`: the record chain reaches the node; `made_nodes_own` for things a commit makes), as its node thing: no account holds a role there.
- The account's creation writes D's strongs to the profile, the inbox and the node thing, and the node root's to D, in its transaction; pairing writes the new node's strong to D (`Engine::paired`).
- A local commit after which the node root no longer strongly references D, or D the profile or the inbox, is refused, however it was written (a remove, a whole set, a removed aspect, an undo, a purge): `commit_in` compares those strongs in the index before and after (`roots::kept`, `still_kept`), O(1).

## The structure (`Closure`, an index: journaled, built again by an open)
- A vertex is (context, thing). A context is `Local` (the node root's local part), `Read(T)` or `Unread(T)` (T's sync unit entered read or kept unread). The root is (Local, node root).
- A vertex's edge to each target of its thing's strongs (its current values', and its held history's where its setting says so: notes/engine-refs.md History holds) gives (`given_by`): in Local, a plain target; in `Read(T)`, a target T's keys open (`Core::keys_open`: on the record chain of its secret actor, or T's role there read or above); from either, a target with own keys the context does not follow enters `Read(y)`/`Unread(y)` by the secrets the node holds of it (`Core::enter`), and so does a target with own keys inside a read unit (its unit is part of the one it is in: holds nothing more, but `units_holding` names every sync ID carrying a thing). Kept unread is its root alone (the node cannot read what it holds). A key actor gives nothing.
- The local part follows a plain thing only when the node opens it (`Core::opens_plain`: a read secret of the thing with own keys its secrets derive from, or the keys of that key actor); a tid with no record held opens nothing, so a strong to it holds nothing and `NotCarried` names it.
- So `sync_unit(T)` is the members of `Read(T)` (a read of them whole: listings, whole derivations); `Closure::unit_holds(T, t)` asks one member, stamped per (context, thing), and `member_feed` gives members as they come, so per-commit judgements (`BodyCtx::holds`) and own commits move with what entered or left, never with the unit's size; `units_holding(t)` the `Read` contexts holding t; the node closure every thing of any context.
- Followed per edge: an `Effects` key per (held vertex, strong target) records what `given_by` read (own keys, roles, secrets, records); the reference index tells strong rows appearing or going (`Closure::note_row` from `refs::note`), since store table reads stamp a whole table. A settle at each transaction's end (`units::settle`) applies due edges and noted rows; an open's reload settles it. Only a rollback of a transaction whose settle ran (a failure past it) resets the follower (`Follow::rolled_back`: every held vertex's edges followed afresh, O(closure)); a step or write refused before the settle leaves it right, since what a rollback restores stamps what it read.
- Two trees over the same out-lists (`Tree`, one detach and one `spread` for both): the node closure's, and the sync set's (`Closure::synced`), where an edge into a thing sourced elsewhere (`cut`, spec/sync-set.md §5) leads nowhere. The sync set's tree follows the out-list edges that moved (`moved`) at each settle's end, and the cut as `Engine::set_sourced` sets it (a reload keeps the cut). `in_sync_things` and `things_entered` read it per thing and by feed; `sync_things` is the whole, for listings.
- Removing a tree edge runs two searches in step (the target's other referrers up their tree paths; the target's subtree), stopping at the first answer; a subtree found whole re-attaches what a held referrer outside reaches and drops the rest (`detach`). A thing out of the node closure at a settle's end is noted in `left`, with every context it was dropped from in that transaction (the sync units that carried it when it left), until `released`.
- Work counts (`closure:` costs), engine `closure::removal_costs_what_it_held_spec_sync_set_2` at n = 6 and 60: a non-tree referrer of a target with fan-in n, 1 / 1; that target's tree edge with referrers outside, 1 / 1; a tree edge with a shallow alternative over a subtree of n, 7 / 7; one whose alternative is n deep, 5 / 5; a subtree of n released, 3n (edges, steps, drops).
- With A sourced elsewhere (`closure::a_sourced_thing_costs_what_is_below_it_spec_sync_set_5`, `closure:` and sync set costs, n = 6 / 60): a thing entering, 6 / 6; leaving, 13 / 13; moving A away, 43 / 43 over a closure of n, 76 / 670 over n below A; home, 19 / 19 and 34 / 304.
- Checked: `units::check_whole` walks the node closure afresh by `given_by`, and again with edges into cut things leading nowhere, and compares each tree's held vertices and parents (`Engine::check_closure`; in `check_index`, so sampled in debug builds; the closure tests run it after every edit). It shares `given_by`, so `given_by`'s own rules need behaviour tests (`units_holding`, `not_carried`).

## Writing and making a thing
- A node writes only what it holds; it fires at what it does not. Every thing (not a key actor) a transaction's own commits make, and every thing they write that the node closure did not hold as it was written, must be in the node closure at the transaction's end (`Core::wrote_on`, `units::check_written` after the settle), else `Error::NotHeld` (osis `Invalid`) and nothing applies. Checked as written, so accepting and writing in one transaction, or a write that releases its thing (a destruction), passes. A sealed fire is built, never applied, and not checked. A hostile writer (`skip_writer_rules`) is not checked: it is a writer's rule. Without it a node wrote a thing it was granted but never accepted and read its own write there for good, out of every closure, never released (OSIS_FULL seeds 6, 40, 75).
- Owed writes follow it: an open fire goes as a write only on a thing held and read (`inbox::fire`, else sealed); `write::writable_now` (addenda, listings) waits while a thing is not held, judged after a closure settle at the transaction's end. Without these an owed addendum on an unheld thing failed every ingest transaction for good (OSIS_FULL seed 7's storm).
- `publish_reach` writes the profile's dial entry only once the profile is held (a node paired a moment ago lists itself at a later call).
- Test helpers hold what they make where it lives (`Engine::hold_where_it_lives`: from the admin where held, else the account root, else the node root): `Engine::new_thing`, `Engine::create_with_admin`, `Engine::held_record` (the strong committed first, so the making commit is on the thing alone); osis tests use `internals::Held`. A receiving test peer holds what it is handed: `LocalPeer::hold`/`hold_at` write a strong from its node root, so a peer keeps another's thing only as a real node would, held, opened (a grant by the flow, not a raw edge write) and needed (spec/commits.md §5 What a held thing needs). Engine `tests/it` helpers: `common::new_thing` holds the thing at every peer, `set_edge` grants by the flow (`edge_write` for a bare edge: a holder no peer is, an edge between things), `net` peers know each other's accounts (`net_apart`: strangers); an observer is a reader (`common::reader`, a template copied per fresh node by `fresh_copy`) or a node of the maker's account (`net_one`, `pair_into`), and is given its access before what it reads (a grant may wait for the record: it applies with it), since content a node cannot yet open goes at the next need-judgement. A node of an account writes as the account, so a commit cannot mix the node root with account-written things.
- A thing a local commit makes under an account is due own keys (`Core::own_keys_due`): before the first content write on it (`write::keyed_first`: its record in the rotation where that commit makes it, `rotation::own_secrets_new`, as `Engine::mint_actor` mints; then the rest of the commit under its own keys), else at its creating transaction's end (`rotation::own_keys_due`). Role writes go first as they are, so a maker keying it itself (a link's K, its sync ID listing L) is not keyed twice. Content under derived keys would be re-encrypted, chunks and all, by the first write after the rotation.
- Making the next thing costs what it changed, at n and 10n held (osis `making::`, every counted kind, the least of three makes so a compaction's spike is spread): no per-thing or per-sync-ID memo reads a whole unit, the account root's `tickets.0`, a whole permission component (`Timelines::on`/`role`, `Core::horizon` over what reaches the actors), a whole store table, or every sync ID's body of a commit (`Engine::sync_body` per pair; `Live::may_log` tries S's own entries first).
- Cost per such thing (engine `thing_cost::what_a_thing_costs`, breakdown in notes/thing-cost.md): 3 commits and about 24 KB stored against 1 commit and 1.8 KB for a plain thing under the account root; the same as any thing pays at its first grant. Things an app keeps account-wide and plain go under the account root.

## Not carried
- The write path's warning reads the strongs the write's ops name (`osis_engine::strongs_in`, `Engine::not_carried_among`): O(the write), never the written thing's other strongs. `Engine::not_carried` lists the whole node closure's, O(its strongs).

## On a ticket's word
- A context `Ticket(T)` (root alone, like kept unread) for a thing without own keys here that a read ticket enters (notes/inbox.md Own keys; a sync one enters `Unread(T)`): in both trees, so `sync_things` and `in_sync_things` see it; `Closure::holds` skips it, so a thing held so alone has left and releases. Its tickets' sync IDs and roles are kept per thing (`Closure::ticket_ids`, by sync ID `naming_ticket_id`), set at each judgement that takes tickets and cleared at the settle's end once no vertex of the thing is held: a thing moving between contexts (`Ticket(T)` to `Read(T)` as its role commits make it keyed) is dropped from one before it is held in the next, and its tickets' sync IDs are what its `sync.0` still has to arrive by.
- The ticket step's openers are an input of it: per thing, the holders its held tickets are boxed to, opened or not (`Closure::openers`, by holder `by_opener`), set and cleared with its ticket IDs. A holder that can open more (a key actor or the account taken up, `flows::take_up_opener`; an actor whose secrets grew, `reopen_dependents`) re-judges the edges into those things alone (`Closure::opener_moved`), never the whole closure. Counted (engine `closure::a_take_up_costs_what_the_opener_opens_spec_sync_set_2`, `closure:` and `reopen:` costs, 5 / 50 things with own keys held): a key actor taken up, 0 / 0; `create_link`, 11 / 11.

## Fetched again
- A strong newly followed in a read unit (an edge `units::judge` finds new: not followed before this settle, nor before a rollback's refollow; an open's first settle counts none, as the mark below was durable before the strong's transaction) to a thing whose record the node lacks and that no ticket here opens (`units::refetch`): the commits it holds minting the thing lose their own tombstones and each sync ID of the unit is pulled anew from every source, through the ciphertext door in the engine's transaction (`Cipher::unreceived`, `Cipher::refetch`: the sync store's `N/` mark), and the sync store's follower opens the entries parked under it again. So a thing released and reached again, or a creation opened and not taken before the strong arrived, is fetched (sync `holding::a_released_thing_reached_again_is_fetched_again_spec_sync_judgement_3`).
- Forgetting as never received (`apply::unindex_unreceived`, a partial `retention::forget::unreceive`) ends the node's own tombstones of the commit's blobs: a forgotten body leaves nothing keeping it out.
- Cost: a pull anew lists the unit's sync IDs whole at each source, once per such new edge. It also fires where nothing comes of it: a strong to a thing that is gone, and an account root's strong whose ticket arrives later (an accept seen at a sibling first). Rare-path brute force by intent; if it shows in counts, narrow the trigger.
