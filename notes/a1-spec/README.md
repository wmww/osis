21. **A thing detached from its folder**: settled by the direct mark (spec/permissions.md §1 Hops, Direct mark). A record edge is an edge like any, so a descent through a removed record edge gives nothing; a hop from a mint ancestor two or more record edges up is a descent unless the path marks it direct, when it is that ancestor's direct grant. S, detaching T from its folder G after taking admin on T, writes T by `[]` with hop 0 marked.
    - **One encoding**: a mark only on a hop otherwise read as a descent of two steps or more; elsewhere the part applies nowhere, so each list of edges has one statement. Marked and unmarked paths are both valid only where they state different edges (a party with two grants), each judged along its own. Rejected: reading the hop by what is held: any admin of T, by granting the ancestor a lesser direct role, would turn its earlier writes by descent into writes through that edge (`a_hop_read_by_the_direct_edges_held_lets_another_admin_void_a_mint_ancestors_writes`); listing every thing (no descent): 16 B per nesting level on every commit.
    - **Bytes** (spec/wire.md §4 `marks`): a trailing byte string in `Path`, bit j for hop j, absent where nothing is marked, else 2 B for hops 0 to 7; a byte string, not a uint, because a path has up to `MAX_PATH_THINGS` + 1 = 65 hops. A split entry carries its thing's marks inside its list.
    - **Interactions**: a marked final hop is the path's last edge (the last-admin rule and the path's may-grant read the direct edge); a self-removal's grant is the write's own, so no mark reaches it; in one `Path` the mark at the hop past the end marks every thing past Ak and the end has no such hop (the writer then states the split form, `Path::one_of`). The engine (`View::ways_to`: fewest edges, then fewest marked hops) states a far mint ancestor's direct edge, marked, before the descent where it gives the need.

## Role paths
Every role-class commit the engine writes states one path in the clear (never the split form; one path serves every thing it writes, debug-asserted), purge index 0, the shortest by edges giving what the write needs (`View::ways_to` with `Need::Role` or `Need::MayGrant`, memoized per (thing, need); `engine::write::role_path`). How the edge writes reach their target is read off what they write (`role_way`): a write lowering a grant that is the signer's own, or the one its admin rests on alone, is a self-removal; a grant put by a signer holding no admin there is a may-grant grant.

| commit (engine site) | path | oracle (roles-model `paths`) |
|---|---|---|
| grant, raise, removal, demotion by an admin, several holders under one frontier, a cut grant with its read rotation (`flows::edges::grant_history`, `demote_in`) | the signer's role on the target: admin (`role_with`, `path_with`) | `World::push` (members, `joins`); `a_write_by_descent_is_judged_along_the_record_edges` |
| a grant the signer gives itself on a thing it reaches by descent | the path to the mint admin, then the mint admin (the empty path would end at the holder: a self-removal) | `World::push` (`leave` by path end) |
| self-removal (a removal of a grant never held lowers, spec/permissions.md §2; removing the holder the signer's only admin rests on is one) | empty where the holder is the signer, else the admin path to the holder, then the holder | `a_self_removal_by_path_end_audits_nothing`, `a_self_removal_raises_nothing` |
| may-grant grant (`grant_history` without admin) | r on each edge, the last giving admin or carrying the flag (`Need::MayGrant`) | `a_may_grant_grant_applies_by_its_paths_flag` |
| finalize (`finalize_in`) | the signer's role on the target (write at least, and at least each ended grant's: `finalizable`) | `a_finalize_ends_an_ended_grant_and_a_may_grant_grant_follows_it` |
| link redemption (`redeem_in`: the grant, and single use L's own removal) | L's grant on K: the empty path; the leave part, on the path's last edge, ordered last (Open 14) | `a_link_redemption_grants_once_and_ends_the_link` |
| `keys.0`, `secrets.0`, `sync.0`, `listing.0`, `account.0` | the signer's role on the thing (a rotation rotates every role up to it, `rotation::may_rotate`) | none: judged like content (spec/permissions.md §5.1 lead) |
| role compaction snapshot (`retention::snapshot`) | `snapshot_role` (admin) | none |
| records alone (a role commit carrying `created.0` only) | the mint admin's path, then its record edge (`path_with`) | `World::push` (descent) |
| an account's rotation, a seed re-seal | empty, `[0]` (spec/wire.md §4 fields 15, 16) | none |
| a key actor's own record and keys | empty: the signer is the thing | none |

## Why MAX_PATH_THINGS is 64
A resource bound against hostile input (class R, notes/arbitrary-values.md): past it a writer refuses the path and a decoder rejects the header, alike everywhere. At 0 no write could go through a holder, so the bound must be at least the deepest nesting of holders anyone builds: a few levels (account, organization, a holder within it). Unbounded, one commit's path costs every reader a point query per hop (each up to a descent of `MAX_CHAIN_DEPTH` record edges) and, while unjudgeable, a wait on a record per listed thing: a junk path of n made-up things parks a commit on n records, n set by the writer alone. 64 keeps a path's hops, and so a part's waits and point queries, at most 64 and a `Path` at most about 1 KiB; it hurts only a holder nested 65 deep, which no design here builds. Any value well above real nesting serves; 64 matches `MAX_CHAIN_DEPTH`, the like bound on a record chain.
