1. **What a removal's result names** (notes/path-model-findings.md 19): the members a kept lowering of the remover by X dropped, beside those X lowered. (a) Only X's own lowerings (*taken*: no spec text; it is the `osis` result): a co-admin's loss is not shown. (b) Also every part a lowering the list keeps dropped: the remover's walk computes it, one diff of two readings. (c) The writers' rule leaves out a lowering of the remover even where R applies with it: reopens the key-order class (control `-key-order`). The spec is unaffected in (a) and (b). **Settles**: the coordinator, at brief 5 (the `osis` result); (a) is safe to build on, (b) adds to it later without a spec change.
2. **The void check's cost** (notes/path-model-findings.md 17): k void lowerings at the end of a chain of k grants cost k² setters read, all forced by one party's own 2k role writes. (a) Cap nothing and state the cost (*taken*: the spec caps nothing; brief 7 counts it). (b) Memoize chain reads across checks with the same drops on the chain: linear for this attack, not in general; an implementation choice, no spec text. (c) A cap on the depth `keeps` reads: the verdict would depend on the cap, which notes/arbitrary-values.md rejects. **Settled** as (a), (b) left to the implementation. Within one check the walk caches, per (edge, position), the setter deciding a scan below it, so one check reads each edge position once (`counts::a_void_check_reads_each_setter_once`): m grants chased through an edge of m dropped grants cost about 2m setters, k such lowerings k·m from one party's own 2m + k writes (the model rescans: m²).
3. **Detecting disputes at a node that trusts nothing** (notes/path-model-findings.md Open 0): the rule is a walk with each candidate trusted, so k held candidates cost k walks of their component per change. (a) The spec defines the dispute and leaves when it is computed to the node (*taken*). (b) Narrow the candidates to lowerings the walk leaves without a verdict or applies with drops that dropped a lowering or a grant a lowering applied under (the classes of findings 16 and 21). (c) Compute only on demand, when a thing's roles are shown: a fight on a thing nobody views is never reported, against spec/requirements.md Permissions ("reports the dispute"). Never part of validity in any option. **Settles**: a model run for (b) (`disputes` narrowed, property `dispute` at full size: every reach-back still shown; control: the unnarrowed rule giving the same set); until then the engine computes (a) per change for candidates on things in its node closure, counted in brief 7.

21. **A thing detached from its folder**: SETTLED by the direct mark, built end to end. Marked and unmarked paths are both valid only where they state different edges: two claims (a party with two grants), judged each along its own; the writer's choice is its statement and no reader checks it. Reading the hop by what is held instead is rejected: any admin of T, by granting the ancestor a lesser direct role (backdated or not), would turn its earlier writes by descent into writes through that edge (`a_hop_read_by_the_direct_edges_held_lets_another_admin_void_a_mint_ancestors_writes`); listing every thing (no descent) costs 16 B per nesting level on every commit.

Tests: model and perm hand worlds; engine `role_paths::a_detached_things_owner_states_a_marked_hop_both_walks_apply_spec_wire_4` (content and grant state `[]` marked, today's walk and the new walk apply them), `finding_a_marked_path_does_not_grow_with_history_spec_wire_4`; `new_walk_differs_only_by_design`'s detached world shows no difference.

## Why MAX_PATH_THINGS is 64
A resource bound against hostile input (class R, notes/arbitrary-values.md): past it a writer refuses the path and a decoder rejects the header, alike everywhere. At 0 no write could go through a holder, so the bound must be at least the deepest nesting of holders anyone builds: a few levels (account, organization, team). Unbounded, one commit's path costs every reader a point query per hop (each up to a descent of `MAX_CHAIN_DEPTH` record edges) and, while unjudgeable, a wait on a record per listed thing: a junk path of n made-up things parks a commit on n records, n set by the writer alone. 64 keeps a path's hops, and so a part's waits and point queries, at most 64 (each hop's descent bounded on its own by `MAX_CHAIN_DEPTH`) and a `Path` at most about 1 KiB; it hurts only a holder nested 65 deep, which no design here builds. Any value well above real nesting serves; 64 matches `MAX_CHAIN_DEPTH`, the like bound on a record chain.

## Bytes per commit
A tid is 15 bytes, 16 encoded. Today's `author` and `actor` are 32 bytes. A1's `signer`, `path` and `remains` for a commit whose things are all written along one path (whatever their number): signer 16, `path` `[i, A1..Ak]` 2 + 16k, `remains` `[]` 1: 19 bytes with the empty path (every commit at A1, accounts unchanged: 13 fewer than today), 35 with one listed thing (an account, from A4: 3 more), 51 with two (19 more). A path marking a hop direct (Open 21) adds `marks`, 2 bytes for hops 0 to 7. A commit no one path serves states the split form: 3 bytes, an entry per thing of 117 bytes up to four listed things (padded, room for every hop marked), and 16 more for a purge author other than the signer (notes/path-form.md, Bytes); sections carry no path.
