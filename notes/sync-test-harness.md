# Sync test harness
> Summary: The one harness osis-sync's tests run on (core/sync/tests/it/harness): nodes stepped deterministically in one process behind the same link seam as QUIC, relay and LAN, shared fixtures copied per test, real crypto and store, faults, lies, scripts and shrinking, the differential, and the test layers with their instruction budget (the whole sync suite budgeted at about 1,200 G instructions).

Principle: the marginal test is cheap. A test pays only for the changes it makes on a world someone already built; everything a test does runs the product's sync code byte for byte.

## Architecture
- **One world, one process, one thread per world.** `World` holds nodes, a link fabric, one manual clock (per-node skew) and a seeded rng. Seeds are 0 in rule tests (notes/testing.md, Conventions); random layers draw from the run's seed.
- **One node type.** A world node is exactly what the product runs: engine, store, sync. No test node. A node keeping S unread is an ordinary node granted sync on S through the ordinary grant flow.
- **Hostile peers are scripted nodes.** A `Scripted` peer owns real keys from the fixture and speaks the wire through the real encoder; it does what its script says (lie in its own log, withhold entries, hold requests open, send malformed frames). It can sign only with its own keys. A lying honest node is an honest node whose outgoing frames pass through a script; no knob in the fabric changes content. Reason: hostile behaviour lives in a library of scripts, not in 40 harness fields.
- **Every output is applied, in one place.** The sync crate's own `apply` (below) is the only code that carries a node's outputs out; the world calls it and nothing else. Tests act through world methods (write, grant, partition, crash, step, run); no test calls a node's `handle` and drops what it returns. An offline node's dials are answered `Down`.
- **Determinism.** A world is a function of its seed: every rng is seeded from it, and no order comes from a hash seed (sync's product code keeps no hashed collection: tools/policy.py `sync_hashed`: a hashed collection iterated into an action order reorders rng draws, so the bytes sent). The sync differential plays a share of its seeds twice and requires identical traces: a source of order reorders any history on its path. Reason: a failure must replay and shrink.
- **Time jumps to the next wake.** `run` delivers until the queue is empty, then jumps the clock to the earliest `Wake` and goes on, until quiet (no queue, no wake before a horizon) or a step cap (the storm guard: panics naming what still flows). `advance(ms)` exists only for tests about time. Reason: no hand-tuned retry advances; idle costs nothing but its wakes.
- **Scripts, seeds, shrinking from day one.** Every random layer generates a `Vec<Step>` (a `Debug` enum printed as Rust), and one `play(world, &[Step])` runs it. A failure prints the seed, the script as Rust and the replay call. `OSIS_SYNC_SHRINK=1` shrinks (`osis_base::testenv::shrink`; with `OSIS_SHRINK_MATCH=<text>` a candidate fails only when its panic message contains the text, so a seed failing two ways keeps the one studied): drop chunks ddmin-style (halves down to single steps), then simplify each step (`Step::simpler`), to a fixpoint or `SHRINK_CANDIDATES` (150) candidates, counted, never timed. Each candidate plays once, silent (converge's play-twice determinism check runs on the original and the shrunk run only), capped at `SHRINK_STORM` (3) times the most deliveries any world of the original run made: past it a candidate counts as not failing (a storm the shrink made; `capped`). Each smaller failing script prints as found, past capture, so a shrink cut short (the seed timeout) keeps its progress. A 46-step differential failure shrinks to 3 steps in about 30 candidates, about 30 CPU-s in debug. The shrunk script is a debugging aid for understanding the bug (replay it with `OSIS_SYNC_TRACE`), never the test: the reproducer is a new hand-written test holding only what triggers the bug, on a fixture (`contacts`, `two_nodes`, ...) or a fake ground at seed 0, the corner constructed (notes/principles.md, Never pin a seed), checked to fail with the fix undone.
- **Replaying a script.** A differential history is a function of its seed, but whether it fails is not: worlds and commit IDs come from commit bytes, so any byte change moves which seeds fail. The unit of work is the shrunk script, kept in its issue; replay it in a scratch test (never committed) as `differential::worlds("scratch", |_| vec![..])` (`use crate::harness::script::*`; under `OSIS_FULL=1` when it names a fourth node): each world seed of `OSIS_SYNC_START`/`OSIS_SYNC_SEEDS` plays it, the runner reports the failing ones, so a reproduction rate over 50-80 worlds says whether a class is still open on today's main. With `OSIS_SYNC_SHRINK=1` on one failing world it shrinks on from where a seed timeout cut it (`OSIS_SEED_TIMEOUT_SECS` raises the cap).

## The seam (transports)
The rebuilt sync core is sans-IO: `Node::handle(Input) -> Outputs`.
- Inputs and outputs: `osis_sync::types::{Input, Out}` (notes/sync-driver.md, The step).
- `trait Links { fn dial(&mut self, conn, &Address); fn send(&mut self, conn, &[u8]); fn close(&mut self, conn); fn wake(&mut self, at); }`, synchronous; results come back as Inputs. `sync::apply(outputs, &mut impl Links)` is the one place outputs are carried out, with its ordering rules.
- Implementations: `TransportLinks<T: osis_transport::Transport>` (tokio; QUIC, P2P with relays, LAN and unix through `Multi`) for the product, and the harness's `NodeLinks` over the world's `Net`: a deterministic queue of real encoded frames between world nodes, routed by the reachability model (`tests/it/harness/reach.rs`), so address choice (direct, relayed, LAN) runs as in the product. The model is not a packet machine: each node has LAN segments and an uplink (public address, a NAT, none); `route(from, to, url, blocked)` is the best item of a `peer://` URL: a LAN address on a shared segment (rank 0), the target's public address or a punch (`osis_transport::nat::punch_opens`) (rank 1), or a relay both reach (rank 2). A relayed link ends with its relay, a punched one does not. Partitions are the world's. Sync never knows which it runs on.
- Fabric faults, content-blind: drop, duplicate, delay (reorders across connections, never within one), cut (both ends told), partition and heal, a node's power loss.
- Not exercised by the fabric: the async driver and the transports themselves. A few driver tests run `TransportLinks` over QUIC and `peer://` on loopback.

## Built (core/sync/tests/it/harness)
- `World::new(seed)`; `add_node` (engine with an account of its own, sync `Node` over a fresh `Store`, LAN segment 0 and a public address, a fresh dialable key, its address published), `pair(i)` (a new node of node i's account by the product's `Engine::pair`/`paired`, the reply handed over outside sync as the product's direct pairing connection carries it) and `add_bare_node` (no account, nothing published); fixtures (`fixture`, `fixture_with` for a build that names what it made; a fixture may be built on another) `two_nodes`, `contacts`, `siblings` (contacts plus node 2 paired to node 1's account); `address(i)`; `engine(i)` for reads, `write(i, f)` for writes (then `Input::Wrote`), `status(i)`. No test reaches a node's `handle`: `World::deliver` is the one place a node is stepped and its outputs go to `osis_sync::apply` into `Net`.
- `run` to quiet (queue empty, no wake or held-back input within `horizon_ms`), `flush`, `advance(ms)`; `partition(a, b)`, `cut(a, b)` (connections reset, both ends told, may dial again), `heal`, `power_off(i)` (connections cut, in-flight and held-back inputs and wake lost, the disks power-cut and the node reopened over them: nothing in memory survives), `power_on(i)`; `net.deaf` / `net.mute` (bytes to, or from, those nodes are lost; the transport still takes them: silent peers); `trace` records every delivery in `seen` (`Seen`, bytes by length and digest); `deliveries` against `cap` (`RULE_CAP`; `STORM_CAP` 30,000 for differential, simulation and flow worlds, about 5x the most a default seed makes; panics naming what still flows); settle rounds per step against `ROUND_CAP` (`Node::rounds`); `net.bytes`; `World::store(i)` (`Node::store`, read-only).
- A rule that acts at once is checked after `flush`, not `run`: with a peer unreachable, `run` jumps through an hour of 30 s dial ticks (about 500-850 deliveries) before it is quiet. The cap counts deliveries over the world's whole life, not per `run`, and its panic does not say so: a test with two runs while partitioned, a long `advance` with a node partitioned or powered off (redials count), or a restart and a heal storms with nothing looping (read `d<n>` in a trace before hunting a storm). Power off every node that would dial across a long wait, or read the outcome off the state instead of advancing.
- `run` jumps the clock to every wake inside `horizon_ms` (an hour): a test of an `until` or keep bound puts it beyond the horizon (or lowers `w.horizon_ms`), else the duty fires before the test looks. A by-time rule's test cuts the node off before the `until`, else a peer that keeps talking wakes it and the clock's wake is never tested.
- A test of one node's duty in a world of peers sharing it silences the others (`Lie::Withhold`): otherwise the first sibling to act hides whether this one would.
- Network faults, content-blind (`net.loss: Loss`, per send of bytes, in thousandths, drawn by splitmix from the world's seed in send order; all zero draws nothing): `drop` loses the send and resets its connection (an ordered stream never delivers past a hole; both ends told); `dup` delivers it, then resets its connection (the sender cannot tell it arrived and sends it again on a later connection: the one way a message repeats over an ordered stream; a frame never repeats within one); `delay` holds it back 1..=`delay_ms`, later bytes and the close of that connection queued behind it (reorders across connections, never within one). `net.faulted` counts each.
- Clock skew: each node reads the world clock through its `NodeClock` (`skew(i, ms)`); it is ticked in its own time and its wakes are converted to world time.
- Devices seen from outside: `World::record` set before nodes are added makes their disks record every row and blob (`osis_store::MemoryBackend::record_history`; a copy keeps the recording); `forensic(i)` runs `Engine::forensic` over node i's two disks (notes/test-security.md: hundreds of G instructions in debug, so by hand), `recorded(i)` gives its store disk's rows ever written, live rows and blobs, `disk_use(i)` rows and bytes held per disk (growth counts).
- Device faults: each node's four stores (engine and sync store, backend and root) share one `osis_store::Faults`; `disk_fault(i, n, DiskFault::{Fail, Unsynced, Crash})` at its n-th durable write from now. A crash is a power loss at that write: the world restarts the node in place (`crashes` counts). Restart in place after a failed write is the driver's (notes/sync-driver.md, Failures), never the world's.
- Hostile peers (`lies.rs`): `lie(i, Some(Lie))` passes node i's outgoing frames after its Hello through the lie and the real encoder, and shows it what it hears: `Hold` (no reply ever), `Withhold` (no added entry in its stream or pull replies), `Forget` (added shown as deleted), `Full` (event `full` per S on each connection it is shown an entry of S), `RefuseRoles` (refuses each role entry it is shown, judged by any world store's `Entry::role`). The node itself stays honest and keeps what it takes.
- `Step` (world steps, faults, lies, and the differential's writes) and `play(world, steps, replay)`, which returns the `Script` so a failed check after it prints the script too (`use crate::harness::script::*` compiles a printed one; `Script::note` records what a step did); `shrinking(run, replay)` with `OSIS_SYNC_SHRINK=1` (`replay(steps, last)`: `last` false for a candidate, which may skip checks of the run itself); `Step::simpler` shrinks times, rates, skews, device faults (to `Fail`, earlier) and grants (to a lesser role).
- `World::parks` (the differential's worlds): after each script step no node on has an entry left unparked whose commit the engine knows but neither holds nor pends (`Node::lost_parks`, a full scan of its entries, per step: per delivery it cost a seventh of a history). Entries that never opened (no commit known, the usual wait for a read secret) are outside it, and the 20 faulted seeds produce no entry it looks at: parking itself is tested by (issues/sync-parks-check.md).
- The differential (`history.rs`, notes/test-properties.md Reference-graph differential): `world_of(seed, accounts, nodes)` (contacts by card redeem, `introduce`, then pairs; built once per (seed, shape) per process and copied, under a setup cap of `RULE_CAP` per node; nodes then find each other only by `Engine::dial_peers`, no discovery); history steps through the engine's own flows, each commit a step writes handed to the reference as written (`Made::handed`), what sync wrote handed at the check, every node's copy (a certificate copy carries some parts only; the engine joins the rest from a later copy); `history(seed, n, accounts, len, faults)`; `check`, from the history only: the reference is `local_peer::Peer` (a bare engine) taking every handed commit again while one applies; held-model `closure` over a `Model` of the history (kinds, grants from the reference's rosters, strongs from its `holds.0`) says what each node reads, syncs read or unread and stores; the excuse comes from `Made::know` (what each node surely received: its own events, shared across runs on a clean network); a value write a release lost (spec/sync-set.md §3: no other node of an account holding the thing at the end surely received it before the writer's account next took a strong away or lowered a role, `Made::froze`, and no node holds the commit) is not handed to the reference (`lost_writes`), nor its author's compaction snapshots of that value no node holds (`snapshots_lost`: they carry it); the commit of each held value is held by some node; no node keeps an entry of a body it judges invalid.
- A failing `check` first prints, per thing, the value and roster size the reference and each online node read, and per node how many of the commits handed to the reference it lacks.
- Not built: the differential's "fresh reader through a node keeping S unread" is a simulation, not an oracle clause.

## Trace
`OSIS_SYNC_TRACE=<nodes>[:<only>]` (harness/trace.rs) prints, for each delivery to a named node, what it received and sent (each message decoded, after any lie; Hello, up, closed, dial, close), and what the step applied: store entries (`held_ids`' entries) and engine commits gained or lost against its last traced step, plus `step k: <Step>` for each script step. `<nodes>`: `all` or indices joined by `,`; `<only>`: tokens joined by `,`, a line kept when it holds any: `t<k>` stands for thing k's Tid and sync IDs, any other token is text (`S1a2b3c`, `B..`, `Pull`). Lines are compact (`SyncId` as `S` + 6 hex, `BlobId` `B..`, `CommitId` `C..`, byte lists as `[N b]`, never cut; `c<n>` a dialed connection end, `a<n>` an accepted one) and a function of the seed (`d<delivery> +<ms since start>`). It also prints what the engine and node decided with no frame or change of its own, noted to `osis_base::trace` (debug builds: a per-thread line sink, on only while a world traces, taken after each step as that node's, `n?` for lines noted outside a step such as a check's reads), one line each:
- `verdict S.. C..: <old> -> <new> (<reason>)`: a body's verdict at S moving (`read::Read` settling; the reason is the clause of `judge::classify` or `judge::body` that decided it, such as `covered by a held snapshot`, `must-hold but not loggable here`, `S is not read here`);
- `lost access <tid>: secrets dropped <role>[<epochs>]..` with `, sync kept (unread)` or `, read-only copy kept via <holders>` (`rotation::lost::drop_actors`; `?` marks a reading-only secret);
- `tx rolled back at <file>:<line>: <error>`: an `Engine::run` that returned an error (NotHeld, Permission, a store fault, a probe that always rolls back such as `rotated_already`), at its caller; lines noted inside it end `(rolled back)`.
Filter them with `<only>` tokens (`verdict`, `lost access`, `rolled back`, `-> MustNot`, `Must -> May`). Off, a world holds no tracer: one branch per delivery. Shrink candidates and converge's second play print nothing. Use with one seed and `--nocapture`, read from the start of the connection in question (a stall can be set up while `world_of` builds, at +0 ms, long before step 0). What it does not show: other decisions that leave no frame and no store or engine change (an `Awaits` commit dropped); trace those by hand where needed, or note them to `osis_base::trace`. A role or read clause of the differential that fails prints `World::why_role` (notes/test-harnesses.md, Why kept and row dumps); `OSIS_NO_END_CHECKS=1` replays a seed without the checks at quiet, to inspect its world. Frame census: `net.frames` counts each node pair's frames and bytes per message kind (`Hello`, a `Msg` variant) beside `net.between`'s bytes; `Net::census` prints it, a traced world at its drop and the differential's failure output (`at_check`) included. The quiet check "must-hold bodies a caught-up reader lacks" prints, for its first lost body, the holder's and the reader's verdict, read facts and missing parts, and per blob each one's store entry and held body (`World::lost_body`).

## Mutation probes
`python3 tools/mutate.py FILE OLD NEW -- <cargo test args> [-- <test filter>]` makes one row of a mutation table: OLD must occur once, NEW non-empty; it builds the tests with the edit, writes the file back from its text read before (never git; left alone, with a copy beside it, if someone edited it during the build), then runs copies of the binaries built for it (cargo's args, cwd and env, through tools/heavy's recording runner, so a rebuild meanwhile reaches nothing it runs) and prints `| mutation | failing tests or none |`; each mutation's whole test output goes to `mutant-<i>.log` (in `MUTATE_OUT`, else a fresh temp dir), its path and each failing test's panic message on stderr. Several `FILE OLD NEW` triples build once (each OLD an expression, switched on `OSIS_MUTANT`; a method-call suffix `.f(..)` or a statement `..;` is refused before building: include the receiver) and run the binaries once per mutation: an engine edit relinks osis-sync's `it` for minutes, so batch a table's rows. Set `OSIS_SEED_TIMEOUT_SECS` to a few times a seed's normal cost: a mutation that storms runs each seed to the 600 CPU-s default. Mutate on a seed range that passes unmutated.

## Measured layers
- Instructions by `tools/icount`, the binary in one process (`tools/icount BIN -q`; per module `tools/icount BIN -q <module>::`, whose filter is a substring: `read::` takes `unread::` too; a `tools/pertest.py` sum is higher, about 1.6x: each test in its own process rebuilds the cached worlds): the default tests about 860 G; the differential and the sims, `_plain` properties, about 100 CPU-s together at the gate's size. A differential world (3 nodes, contacts by cards: about 800 deliveries; every pair's first dials cross, and the Twin exchange leaves one connection per pair, spec/sync-opens.md §1) is about a quarter of a fresh seed's cost, built once per (seed, n) per process and shared by the differential and the simulations; read's settle (engine reads, issues/test-time.md) is under half of a history. Every fourth differential seed plays twice (the determinism check, Principles).
- A run while a peer is unreachable or holds requests open passes the whole horizon of 30 s redials (about 900 deliveries a run): a simulation writes back to back and runs once while one is.
- The differential's users: each account every other's contact by contact cards before any history; `New` mints the thing with its maker's D as admin (`NewIn` with another thing as admin) and holds it from there in the same commit; accepting is its own step (a strong from D), drawn after grants, and declining is drawing none (`Grant` is give-then-accept for rule tests). A grant or removal refused with its outcome unknown (an unsynced durable write) counts as made when the writer reads it standing after (`history::stands`), as the API tells a user to read before repeating. Every node publishes its address as the product's `listen` does (`World::publish`: `reach.0` and its profile's `dial^.0` entry); `World::discover` is for LAN-discovery tests only.

## Making the marginal test cheap
| choice | saves | risk | guard |
|---|---|---|---|
| **Fixtures built once per process, copied per test** (`osis_base::copying::cached`): a catalog of small quiet worlds keyed by shape (accounts with one or two nodes, contacts exchanged, a shared thing with each role, S kept unread at a node, an inbox), built lazily, each through the product's own flows | the setup of a quiet world per test (about half a median test when measured); a copy is 1.5% of a build | every test sees the same IDs, keys and tie-breaks, so an order-dependent bug can hide | the differential builds fresh worlds per seed with drawn IDs; fixtures are built by the same flows tests use, never by planting rows; two live copies of one fixture in one test are refused (one node twice reuses nonces) |
| **Real crypto everywhere** | nothing; about a quarter of a test | cost | after fixtures take keygens and boxes, and the product verifies once per node, crypto is roughly a tenth of a marginal test. Rejected: a cheap fake suite. A feature builds another copy of the tree (notes/build.md); a runtime suite switch is a product carve-out; and every hostile test is about signature, wrap and proof checks, so a fake that accepts too much hides exactly what they test |
| **Real store over the in-memory device** with `osis_store::Faults` | device I/O is already 0.9% | none | store failures and crashes in place are injected through `Faults`, so the same stack is the one that fails |
| **Clock jumps to the next wake** | idle time and retry waits | a test passes because time never moved | quiet is defined as "no wake before the horizon", and the differential's run ends past every timer the spec names |
| **Many small tests on one fixture** | setup | tests coupled through a shared builder | a fixture's shape is in its key; changing a shape is changing its key |
| **Table-driven rule families** (one plain `#[test]` fn per row calling a shared `case(...)`) | writing, not runtime | none | rows stay individual fns so `tools/spec_map.py` sees each name and citation |
| **Debug checks stay on** (`check_rebuilt` per transaction, `check_index` at each engine's end) | none | cost | they are the incremental-against-from-scratch oracle in every test, at every size (notes/test-harnesses.md, Debug checks) |

## Layers and budget
The sync crate's one `tests/it` binary: its default tests (spec rules, scale, driver) budgeted at about 450 G instructions, the differential and the simulations (seed runners: `_plain` properties the gate selects for osis-sync and the crates below it, notes/testing.md, When tests run) at 750 G. The default tests run at about 860 G (Measured layers); `growth::` and `holding::` dominate.

| layer | what | budget |
|---|---|---|
| spec rules | one `#[test]` per spec rule, on a fixture copy: a few writes, the observable checked. Named `<rule>_spec_<file>_<N>`, cited `// spec/sync.md §N (anchor): ...` (tools/spec_map.py); `--gaps` lists the rules with no test | 300 G; median under 0.15 G, cap 1 G a test |
| differential | random histories (writes, grants, removals, partitions, restarts, losses, a node keeping S unread) on fresh worlds per seed; heal, run to quiet. Oracle, from the history only: every reader of S reads as a reference engine handed every commit written directly (sync's property is perfect delivery; the engine's own read rules are held-model's and the order harness's), and a fresh reader that syncs only through a node keeping S unread reads alike too. One function, size knob | 400 G at small size (about 100 histories of 40 steps); large in release checks |
| simulations | named scenarios as scripts with fault schedules: lost and duplicated messages, a peer lying in its own log, full peers (caps), crashes and restarts in place, store failures; each old bug-scenario is one of these or a rule test (those still missing: issues/sync-tests-owed.md). Checks at quiet: the differential's oracle plus the scenario's stated outcome | 350 G (about 8 scenarios x 8 seeds) |
| scale | work counted at n and 10n (deliveries, bytes, store rows, verifies, engine transactions per change), from the fabric's and `costs`' counters; never time | 100 G |
| driver | `TransportLinks` over loopback QUIC and `peer://` | 50 G |

Enforcement:
- Per test, deterministic: the world counts deliveries and node calls and panics past the layer's cap (a rule test 2,000 deliveries), so a test that storms or grows fails in the worker's own run, not in a profile weeks later.
- Per layer and whole: a `sync-tests` row in notes/time-limits.md, Limits (a share of `default-tests`), checked by the gate like every stage; `tools/icount` over the binary per module (`<layer>::`) is the comparable number, and a branch that raises it by more than 5% says why in its review. The test optimizer compares `tools/pertest.py` profiles.
