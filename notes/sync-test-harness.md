# Sync test harness
> Summary: The one harness osis-sync's tests run on (core/sync/tests/it/harness): nodes stepped deterministically in one process behind the same link seam as QUIC, relay and LAN, shared fixtures copied per test, real crypto and store, faults, lies, scripts and shrinking, the differential, and the test layers with their instruction budget (the whole sync suite budgeted at about 1,200 G instructions).

Principle: the marginal test is cheap. A test pays only for the changes it makes on a world someone already built; everything a test does runs the product's sync code byte for byte.

## Architecture
- **One world, one process, one thread per world.** `World` holds nodes, a link fabric, one manual clock (per-node skew) and a seeded rng. Seeds are 0 in rule tests (notes/testing.md, Conventions); random layers draw from the run's seed.
- **One node type.** A world node is exactly what the product runs: engine, store, sync. No `Host` type, no test node. A node keeping S unread is an ordinary node granted sync on S through the ordinary grant flow.
- **Hostile peers are scripted nodes.** A `Scripted` peer owns real keys from the fixture and speaks the wire through the real encoder; it does what its script says (lie in its own log, withhold entries, hold requests open, send malformed frames). It can sign only with its own keys. A lying honest node is an honest node whose outgoing frames pass through a script; no knob in the fabric changes content. Reason: hostile behaviour lives in a library of scripts, not in 40 harness fields.
- **Every output is applied, in one place.** The sync crate's own `apply` (below) is the only code that carries a node's outputs out; the world calls it and nothing else. Tests act through world methods (write, grant, partition, crash, step, run); no test calls a node's `handle` and drops what it returns. An offline node's dials are answered `Down`.
- **Determinism.** A world is a function of its seed: every rng is seeded from it, and no order comes from a hash seed (sync's product code keeps no hashed collection: tools/policy.py `sync_hashed`: a hashed collection iterated into an action order reorders rng draws, so the bytes sent). `convergence::converge` plays each history twice and requires identical traces (every delivery, its bytes' digest included), so every differential seed checks it. Reason: a failure must replay and shrink.
- **Time jumps to the next wake.** `run()` delivers until the queue is empty, then jumps the clock to the earliest `Wake` and goes on, until quiet (no queue, no wake before a horizon) or a step cap (the storm guard: panics naming what still flows). `advance(ms)` exists only for tests about time. Reason: no hand-tuned retry advances; idle costs nothing but its wakes.
- **Scripts, seeds, shrinking from day one.** Every random layer generates a `Vec<Step>` (a `Debug` enum printed as Rust), and one `play(world, &[Step])` runs it. A failure prints the seed, the script as Rust and the replay call. `OSIS_SYNC_SHRINK=1` shrinks: drop chunks (halves down to single steps), then simplify each step (`Step::simpler`), to a fixpoint, replays silent. The shrunk script pasted into a test is the minimal reproducer (never a pinned seed).

## The seam (transports)
The rebuilt sync core is sans-IO: `Node::handle(Input) -> Outputs`.
- Inputs and outputs: `osis_sync::types::{Input, Out}` (notes/sync-driver.md, The step).
- `trait Links { fn dial(&mut self, conn, &Address); fn send(&mut self, conn, &[u8]); fn close(&mut self, conn); fn wake(&mut self, at); }`, synchronous; results come back as Inputs. `sync::apply(outputs, &mut impl Links)` is the one place outputs are carried out, with its ordering rules.
- Implementations: `TransportLinks<T: osis_transport::Transport>` (tokio; QUIC, P2P with relays, LAN, unix, and `InProcess` through `Multi`) for the product, and the harness's `NodeLinks` over the world's `Net`: a deterministic queue of real encoded frames between world nodes, routed by the reachability model (`tests/it/harness/reach.rs`), so address choice (direct, relayed, LAN) runs as in the product. The model is not a packet machine: each node has LAN segments and an uplink (public address, a NAT, none); `route(from, to, url, blocked)` is the best item of a `peer://` URL: a LAN address on a shared segment (rank 0), the target's public address or a punch (`osis_transport::nat::punch_opens`) (rank 1), or a relay both reach (rank 2). A relayed link ends with its relay, a punched one does not. Partitions are the world's. Sync never knows which it runs on.
- Fabric faults, content-blind: drop, duplicate, delay (reorders across connections, never within one), cut (both ends told), partition and heal, a node's power loss.
- Not exercised by the fabric: the async driver and the transports themselves. A few driver tests run `TransportLinks` over `osis_transport::InProcess` and `P2p<MemUdp>` (in process, deterministic, the real P2P and relay code); QUIC on localhost stays by hand.

## Built (core/sync/tests/it/harness)
- `World::new(seed)`; `add_node()` (engine with an account of its own, sync `Node` over a fresh `Store`, LAN segment 0 and a public address, a fresh dialable key, its address published) and `add_bare_node()` (no account, nothing published); `address(i)`; `engine(i)` for reads, `write(i, f)` for writes (then `Input::Wrote`), `status(i)`. No test reaches a node's `handle`: `World::deliver` is the one place a node is stepped and its outputs go to `osis_sync::apply` into `Net`.
- `run()` to quiet (queue empty, no wake or held-back input within `horizon_ms`), `flush()`, `advance(ms)`; `partition(a, b)`, `cut(a, b)` (connections reset, both ends told, may dial again), `heal()`, `power_off(i)` (connections cut, in-flight and held-back inputs and wake lost, the disks power-cut and the node reopened over them: nothing in memory survives), `power_on(i)`; `net.deaf` / `net.mute` (bytes to, or from, those nodes are lost; the transport still takes them: silent peers); `trace` records every delivery in `seen` (`Seen`, bytes by length and digest); `deliveries` against `cap` (`RULE_CAP`, panics naming what still flows); settle rounds per step against `ROUND_CAP` (`Node::rounds`); `net.bytes`; `World::store(i)` (`Node::store`, read-only).
- Network faults, content-blind (`net.loss: Loss`, per send of bytes, in thousandths, drawn by splitmix from the world's seed in send order; all zero draws nothing): `drop` loses the send and resets its connection (an ordered stream never delivers past a hole; both ends told); `dup` delivers it, then resets its connection (the sender cannot tell it arrived and sends it again on a later connection: the one way a message repeats over an ordered stream; a frame never repeats within one); `delay` holds it back 1..=`delay_ms`, later bytes and the close of that connection queued behind it (reorders across connections, never within one). `net.faulted` counts each.
- Clock skew: each node reads the world clock through its `NodeClock` (`skew(i, ms)`); it is ticked in its own time and its wakes are converted to world time.
- Device faults: each node's four stores (engine and sync store, backend and root) share one `osis_store::Faults`; `disk_fault(i, n, DiskFault::{Fail, Unsynced, Crash})` at its n-th durable write from now. A crash is a power loss at that write: the world restarts the node in place (`crashes` counts). Restart in place after a failed write is the driver's (notes/sync-driver.md, Failures), never the world's.
- Hostile peers (`lies.rs`): `lie(i, Some(Lie))` passes node i's outgoing frames after its Hello through the lie and the real encoder, and shows it what it hears: `Hold` (no reply ever), `Withhold` (no added entry in its stream or pull replies), `Forget` (added shown as deleted), `Full` (event `full` per S on each connection it is shown an entry of S), `RefuseRoles` (refuses each role entry it is shown, judged by any world store's `Entry::role`). The node itself stays honest and keeps what it takes.
- `Step` (world steps, faults, lies, and the differential's writes) and `play(world, steps, replay)`, which returns the `Script` so a failed check after it prints the script too (`use crate::harness::script::*` compiles a printed one; `Script::note` records what a step did); `shrinking(run, replay)` with `OSIS_SYNC_SHRINK=1`; `Step::simpler` shrinks times, rates, skews, device faults (to `Fail`, earlier) and grants (to a lesser role).
- The differential (`history.rs`): `world(seed, n)` (fresh nodes, each account every other's contact by `introduce`: each node makes a contact card, a read link to its profile, every other redeems it and files the profile in its D; built once per (seed, n) per process and copied, under a setup cap of `RULE_CAP` per node; nodes then find each other only by `Engine::dial_peers`, no discovery); history steps `New`, `Write`, `Grant` (`Gives::{Syncs, Reads, Writes}`), `Remove`, `Rotate` through the engine's own flows, each commit a step writes handed to the reference as written (`Made::handed`), what sync wrote handed at the check, every node's copy (a certificate copy carries some parts only; the engine joins the rest from a later copy); `history(seed, n, len, faults)`; `check`, from the history only: the reference is `local_peer::Peer` (a bare engine) taking every handed commit again while one applies; every node whose account reads a thing per the reference (and its maker) reads its value and roster as the reference; every other node reads no value if its account was never granted read (a node keeping the thing unread included), and no value written by a writer that held its removal and did not count it a reader (`Made::hidden`; a grant again clears it; spec/requirements.md Permissions); the commit of the value the reference reads is held by some node. `reads_as(w, r, k, i)` for one node. `hand(w, from, to)` / `hand_all` deliver plaintext by hand (an engine reads what it is handed: keeping content from non-readers is sync's alone), for testing the oracle: generated histories handed to every node pass `check_readers`, and selective delivery plants each fault `check` must catch.
- Not built: the differential's "fresh reader through a node keeping S unread" is a simulation (`sims::a_reader_through_a_node_keeping_it_unread`), not an oracle clause.

## Measured layers
- Instructions by `tools/icount` (one process): a differential world (3 nodes, contacts by cards) about 25 G to build (about 950 deliveries; 4 nodes about 2,450), once per (seed, n); a history on it costs about 2.5x one on hand-made contacts at the same deliveries (each card adds its link actor's sync ID at every node, and read re-judges every (S, commit) at nearly every step: issues/sync-read-rejudges-every-step.md). Defaults: `convergence::{clean_histories_converge, histories_converge}` 20 seeds each (200 under `OSIS_FULL=1`), each simulation 6 seeds (60): `convergence::` 3,490 G, `sims::` 1,910 G, `flows::` 830 G, the binary 6,060 G (about 990 CPU-s) against the 1,200 G budget.
- The differential's users: `introduce` makes every account every other's contact by contact cards (each account's own profile is in its D from its creation) before any history; `New` files the thing in its maker's D in the same commit; every grantee's user accepts (`history::accept`: the granted thing filed as a subgroup of its D, again after a lost write). A grant or removal refused with its outcome unknown (an unsynced durable write) counts as made when the writer reads it standing after (`history::stands`), as the API tells a user to read before repeating; without it the reference counts a grantee that never accepted as a reader. Every node publishes its address as the product's `listen` does (`World::publish`: `reach.0` and its profile's `dial^.0` entry); `World::discover` is for LAN-discovery tests only.

## Making the marginal test cheap
| choice | saves | risk | guard |
|---|---|---|---|
| **Fixtures built once per process, copied per test** (`osis_base::copying::cached`): a catalog of small quiet worlds keyed by shape (accounts with one or two nodes, contacts exchanged, groups with each role, S kept unread at a node, an inbox), built lazily, each through the product's own flows | the setup of a quiet world per test (about half a median test when measured); a copy is 1.5% of a build | every test sees the same IDs, keys and tie-breaks, so an order-dependent bug can hide | the differential builds fresh worlds per seed with drawn IDs; fixtures are built by the same flows tests use, never by planting rows; two live copies of one fixture in one test are refused (one node twice reuses nonces) |
| **Real crypto everywhere** | nothing; about a quarter of a test | cost | after fixtures take keygens and boxes, and the product verifies once per node, crypto is roughly a tenth of a marginal test. Rejected: a cheap fake suite. A feature builds another copy of the tree (notes/build.md); a runtime suite switch is a product carve-out; and every hostile test is about signature, wrap and proof checks, so a fake that accepts too much hides exactly what they test |
| **Real store over the in-memory device** with `osis_store::Faults` | device I/O is already 0.9% | none | store failures and crashes in place are injected through `Faults`, so the same stack is the one that fails |
| **Clock jumps to the next wake** | idle time and retry waits | a test passes because time never moved | quiet is defined as "no wake before the horizon", and the differential's run ends past every timer the spec names |
| **Many small tests on one fixture** | setup | tests coupled through a shared builder | a fixture's shape is in its key; changing a shape is changing its key |
| **Table-driven rule families** (one plain `#[test]` fn per row calling a shared `case(...)`) | writing, not runtime | none | rows stay individual fns so `tools/spec_map.py` sees each name and citation |
| **Debug checks stay on** (`check_rebuilt`, sampled `check_index`) | none (about 11%) | cost | they are the incremental-against-from-scratch oracle in every test; keep their sampling |

## Layers and budget
The whole sync suite (the sync crate's one `tests/it` binary) is budgeted at about 1,200 G instructions: about 430 CPU-s, a minute of wall on fastbox-0 at the usual load. With contacts made by cards it costs about 6,000 G (1,335 CPU-s, 160 s wall at load 55: `convergence::` 763 CPU-s, `sims::` 368, `flows::` 177, every rule-test module under 10), issues/sync-read-rejudges-every-step.md.

| layer | what | budget |
|---|---|---|
| spec rules | one `#[test]` per spec rule, on a fixture copy: a few writes, the observable checked. Named `<rule>_spec_<file>_<N>`, cited `// spec/sync.md §N (anchor): ...` (tools/spec_map.py); `--gaps` lists the rules with no test | 300 G; median under 0.15 G, cap 1 G a test |
| differential | random histories (writes, grants, removals, partitions, restarts, losses, a node keeping S unread) on fresh worlds per seed; heal, run to quiet. Oracle, from the history only: every reader of S reads as a reference engine handed every commit written directly (sync's property is perfect delivery; the engine's own read rules are held-model's and the order harness's), and a fresh reader that syncs only through a node keeping S unread reads alike too. One function, size knob | 400 G at small size (about 100 histories of 40 steps); large in release checks |
| simulations | named scenarios as scripts with fault schedules: lost and duplicated messages, a peer lying in its own log, full peers (caps), crashes and restarts in place, store failures; each old bug-scenario is one of these or a rule test (those still missing: issues/sync-rewrite.md, Phase 4). Checks at quiet: the differential's oracle plus the scenario's stated outcome | 350 G (about 8 scenarios x 8 seeds) |
| scale | work counted at n and 10n (deliveries, bytes, store rows, verifies, engine transactions per change), from the fabric's and `costs`' counters; never time | 100 G |
| driver | `TransportLinks` over `InProcess` and `P2p<MemUdp>` | 50 G |

Enforcement:
- Per test, deterministic: the world counts deliveries and node calls and panics past the layer's cap (a rule test 2,000 deliveries), so a test that storms or grows fails in the worker's own run, not in a profile weeks later.
- Per layer and whole: a `sync-tests` row in notes/build.md Time limits (a share of `default-tests`), checked by the gate like every stage; `tools/icount` over the binary per module (`<layer>::`) is the comparable number, and a branch that raises it by more than 5% says why in its review. The test optimizer compares `tools/pertest.py` profiles.
