# Removing immutable owners: reasoning
> Summary: Why owners went (built: every thing's first admin is an ordinary admin, notes/owner-removal-plan.md step 2) and why disputes are settled per node (option F, chosen with Tess): what an owner did and what replaced it, the limit on any conflict rule, the options compared, the dispute rules, model results, review findings, the optional recovery key. The build plan is notes/owner-removal-plan.md.

## What an owner did, and what replaced it
1. Fixed the tid (the creation record commits to it), so nobody can publish a competing creation. Needs only a genesis, not an owner.
2. Inheritance: a role on an actor reached what it owned, so a million things need no edges.
3. Plain things derived secrets from the owner and stored none.
4. Irremovable top authority: the only thing that settled a backdating fight between admins (issues/ownerless-first-admin-backdate.md).

**Common base of every option: the first admin (built).** Every record names a first admin; its edge is implicit, costs no bytes and is removable. Walks follow these edges while they stand, so 1-3 keep working: same tid forever, plain things stay free and derive secrets until they get another holder, then rotate. A move is grant then remove; a large set moves by handing over a shared actor. Key actors stay: a node is its key, not an owned thing. Verifiers must see a record edge's removal, with the eventual reach of any edge.

## The limit on any conflict rule
An ex-holder signs two conflicting writes and controls everything in them (stamps, hashes, frontiers). A rule reading only signed data has three outcomes: the signer picks the winner (any tiebreak), nobody wins (burn), or someone else's signature decides (quorum, witness). Age cannot bound it without breaking "state is a function of held data".

## Options
- A. Admins only, earliest stamp wins (today's ownerless rule everywhere). An ex-admin can steal back.
- B. Admins only, a mutual removal neither side listed removes both. An ex-admin can only burn; a stolen node can wipe out every admin of an account.
- C. Owner as a mutable role above admin (zero or many holders, B's rule at the top). A stolen node loses to a recovery key holding the role; an ex-owner burns the top tier only. Two concurrent hand-offs make two co-owners. An admin of P must still act fully on things P holds, or an account's nodes lose power over its things.
- D. Majority of the other admins on contested removals: a thief loses 2 to 1. Falls back to B below 3 admins; sock-puppet grants need a baseline. An add-on.
- E. An optional witness a thing names, ordering its role changes. The only real prevention; conflicts with "no trusted coordinator" unless opt-in; the witness needs its own hand-off.
- **F (Tess's idea, chosen): admins only; a fight goes to each user.** Touches spec/requirements.md Permissions (three concepts, fixed owner), Deterministic and API.

## F: disputes
- **Dispute**: an admin removal R of X, and a write W by X not listed in R's frontier that would void R. Every other conflict keeps today's rules, so honest histories prompt only when two admins really remove each other (or knock out the other's grantor).
- **Trust set**: a node's local choices, each a demotion of the loser with a frontier, applied only in its own view as one more input to the walk. State is a function of held data plus the trust set. Published, so the user's other nodes and others can follow it.
- **Defaults**: a node's own or its account's choice; else the side it received first. Always warn when possible. A new or long-offline node gets both writes with no memory of order: it takes the side where its own grant counts, else host log order (the limit on new nodes). Nodes that saw the removal cannot be taken over.
- **Kicked admin**: a contest that lists its own removal is no dispute; one that omits it raises one, and only the kicked node sides with itself.
- **Erase and come back** (Tess, as for purge races): a node removed under its default side erases as today, no holding period; if that turns around it re-syncs; data with no copy left is lost (accepted). No exception to forward security or remote wipe. A node that wrote its own removal first holds it first, so stays on its own side and keeps its data. Needs one rule: a removal whose frontier drops another's removal of G goes to G's inbox, like a grant, because G stopped syncing the label.
- **Costs**: users choosing differently split one tid until someone switches (a social fork); contacts judge an account's dispute out of band, like a safety-number warning; tests need convergence "given equal trust sets".

## Model results
`core/test/roles-model` `trust` (commands and rules: the `trust` paragraph of its `src/lib.rs`). Trust sets on the `edges` walk (one thing: `until` with finalizes, invites, links, read, write, admin, receipts skewed up to 2 units around the stamp) and the `joint` walk (several actors, actor holders, mutual roles), both in the post-owner shape: first admin as an edge before every write, removable, no owner authority. About 25M histories: exhaustive edge tiers (2.0M) and 2M random per shape. Hard properties, 0 failures: an empty trust set reads as today's walk; nobody offline raises no dispute; equal trust sets read alike in any write order; T, then T', then T reads as T; a choice changes nothing outside its target's reach.
- **Rule**: R (A lowering X) seeds D with X's writes ordered before R that R's frontier does not list, X's writes on its own edges excepted. Trusted ops that turn void lose their seeds and stay out, all at once ("shrink"), D rebuilt from scratch: at most 3 shrink rounds, at most 4 rounds of a node choosing each new dispute at random; a choice never left its own dispute open. Failed variants (prototype): fixed seeds backfire; re-judging "void" each round loops on 1.6% of random histories; removing void ops one at a time depends on order.
- **Seeds stop at R**: seeding every unlisted write of X whenever stamped changed the state when trusting a demotion that applies anyway (1.7% edges, 14% joint), dropped X's writes after a re-grant by a third admin for good, and raised extra disputes from X's later demotions. Stopping at R: 0.02-0.05% (edges), 2.7% (joint, from the static victim set). The price: "a choice rejects the author" no longer holds.
- **X's own-edge writes are no seeds**: a self-removal never contests R. Seeded, they raised false disputes and kept X in place.
- **Joint victims**: nodes that ever reach the holder by admin edges, the demoter excluded (a static over-approximation; read members cannot contest).
- **Disputes key on (R, X)**: a lone ex-admin signing more writes makes one dispute per pair; k admins all removing each other make at most k(k-1)/2. A choice can reveal or hide others (0.8-1.8% of histories with a dispute), so the list is recomputed per trust set.
- **Disputes raised** (histories with one): one remover 0; strict rank 0; rank with free full-admin grants 1 in 2M online, 24 offline; anyone removes anyone 12 in 2M online, 0.52% offline; joint 0.57%. Without a mutual removal: 8 in 2M (edges), 4 (joint), all real fights (an accomplice: X grants Q unseen, Q removes A, A removes X). At most 3 disputes per edge history, 4 per joint one.
- **Switching** is a pure function only with D rebuilt. Defaults recorded while on another side change the result (about 3% of adversarial switches): drop or redo them on a switch (untested).
- **First received** (prototype): late backdating loses at 100% of honest nodes, instant backdating at 86-89%; a thief acting first wins (accepted); feeding W first to chosen nodes fools exactly those.
- **Hole: an accomplice that is a current admin raises nothing.** Y removes X listing X's grant of Q; Q, a current admin, removes Y stamped earlier. Y's removal is void, X is back, nobody is warned; earliest stamp decides. Y can answer with a new removal of Q omitting that write, which raises one. Widening detection costs 10-12% false alarms on removal-rank histories against 0.07-0.16%. Accepted (Tess): Y should have removed Q too.
- Not modelled: invites, `until` and finalizes across several actors; holder actors in `edges`; defaults, first-received order, following published choices, recovery keys.

## Review findings carried into the plan
Disputed label actors split hosts (the largest item: steps and deposits under a disputed head; per-side labels both sides can find): step 6. Delete and re-upload loops between sides: no deletes at hosts resting on a disputed party's write (step 6). Cover only under snapshots valid on both sides. A part sealed under a rejected epoch counts as held. Leave both parties out of new keys, or accept the wrong-default leak (accepted). No synced choice decides a dispute about its own author or account.

## Optional recovery key (Tess's idea; documented, not built)
Having none must be a fully valid way to use osis, and a thief with an unlocked device taking control is accepted (the alternatives are no irrevocable actions for legit users, or a recovery system, which stays optional). So nobody gets one by default and it is not in the first build. Losing all nodes needs no new role: a recovery card can be a key actor holding a plain admin edge, listed by static entry as link keys are (spec/permissions.md §7); a thief can remove it. If built, it is a section nothing else reads; every rule and test works with none.
- At most one key actor per thing, none by default. It holds boxes like an admin (it must see the log to write frontiers, seal to new admins and register steps), so "only changes grants" is a client rule. No admin can remove it; its role writes always apply and settle disputes, so a split tid converges again. It acts on the named thing only, not on things below by path.
- **Hand-off**: names a successor, then burns. **Burn**: a signed list of its writes that count; any other write of it is void; several burns intersect, so a thief with the key can only cancel recovery. **Threshold**: split the seed outside the protocol.
- **Must be addable later** (Tess: nothing users may want to change is baked into a thing). An ex-admin could claim to have added one, stamped in the past, or void the honest grant by removing its granter earlier, so an added key is only as strong as a normal admin write. Accepted if built. Adds back one small rule; not modelled.
