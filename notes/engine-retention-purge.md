# Engine: leftovers and purge
> Summary: Value-less leftovers of expired and purged bodies, purge requests (rights, re-snapshots, naming by stamp without the header, forgetting purged leftovers, the frontier stop) and waiting parts at expiry or purge (`retention/leftover.rs`, `purge.rs`, `pending.rs`; spec/commits.md §5 Purge, §6, spec/permissions.md §6).

## Leftovers (`retention/leftover.rs`, `w/`)
- An expired or purged part, a snapshot carrying purged values, or a waiting part a request names is held as its leftover (`make_leftover`, `Hold::Leftover`): a held body for every reader (`each_held_piece`, `held_parts_at`, `stores_part`), no body for node-sync (`Meta::body_gone`). It holds stamps, dots, resets, flags and positions, never a value.
- **Invariant** (`strip_leftover`, the one strip of purge, expiry and arrival): no held body holds a listed write's value, and none loses a value of a write not listed, so a rebuild reads the same. A body carrying a copy of a listed write (a snapshot's; a key or undelete char is its own writer's value) is held as its leftover with only the copies value-less (`strip_carried`; `rebuild` when the list changed, `drop_gone` on arrival). A leftover still holding own values (`Hold::Leftover::valued`) is a body for keep bounds (`Meta::bare`); node-sync deletes its blob as a dropped body with live writes.
- The value-less list `v/` is the one join-time predicate (`apply::strip_valueless`): a snapshot's stale copy joins stripped, and `drop_gone` then only stores the snapshot as its leftover, rebuilding nothing (`review::late_snapshot_of_purged_value_reads_nothing_spec_crdt_4_7` fails, by the rebuild check, without the strip). Deriving it per join would walk the aspect. A late part of a known commit whose own writes are listed is also held value-less and rebuilt by `on_late` (`hold_valueless`), so the strip is not what keeps those right.
- A part dropped as covered and then purged takes its leftover from its valid coverers' copies. A part missing when purged has only the list (a copy joins stripped and becomes the leftover, `drop_gone`).
- **On its purge's fall** a part stripped of its own values counts as never received: its writes leave the list, it is missing with its leftover row set aside (`unstrip`), the aspect is rebuilt and the node refetches (`refetch`). A copy joins whole (`forget_joined_leftovers`); held value-less again first (a rise, its expiry), `make_leftover` adopts the row, so it holds what a node that never saw the fall does. An expired part's writes never leave the list. A body stripped only for carrying others' values stays held through the fall: its value-less copies only hide, the valued copy wins wherever one joins (spec/crdt.md §4.7 Join), and a whole copy replaces it (`takes_late`). Making it missing instead lost the other writes a carrying snapshot covered.

## Purge requests (`retention/purge.rs`)
- Every question comes down to two: does the request name a delta (`names`: an item on its aspect reaches it, stamped before the request), and has it the right? Two readings of the right: `holds_right` by the role timeline (demotion frontiers included, so a backdated request by a removed admin drops nothing), which what a request drops follows (`stands`, `rejudge_purges`); and `signers_could`, by roles of any validity at any time (`Held::ever_*`), for what must not turn on arrival (`could_stand`, `counts_as_purged`). A header never names role-class deltas.
- Requests are kept per aspect or per named stamp (`p/`, `pn/`), listed before the request's commit joins (`note_requests`), so later deltas are purged on arrival and a body killed by the request's own commit is purged, not dropped: its leftover is bare, so no cover drops it (`kill_and_purge_in_one_commit_keeps_leftover_*`). A request by name costs other deltas nothing; an aspect-wide one costs one walk of the aspect per class and actor.
- **A role change flipping a verdict** (`rejudge_purges`): a part a request comes to drop is purged as on arrival; one held value-less for a request that no longer stands counts as never received; a body stripped for carrying others' values stays held. Each aspect is rebuilt once per re-judge, after its flips and every verdict (`validity::rejudge_once`, one `run_batched`): a rebuild per request cost O(requests x bodies) (`scale::purge_rejudge_is_linear_in_requests_spec_permissions_6`).
- **Re-snapshot** (spec/commits.md §5 Purge): a node that never held a purged write has no leftover, so it reads what the write replaced where a holder reads the leftover (the requirements limit). A writer's re-snapshot carrying the write value-less repairs it: `purge::apply_request` hands node-sync each named aspect where the request dropped something here (`Changed::purges`; a refused or no-op request writes nothing, tombstone.rs `a_refused_purge_writes_no_snapshot_*`), and node-sync writes a snapshot where it may write, unless it holds a valid snapshot the purge left whole covering every named body (`purge_resnapshots`, `Engine::holds_valid_snapshot`); with no named body applied any whole valid snapshot will do, and with none it writes one (a vacuous skip let a fresh node read an older value, order seed 632724249436). Tests: deletion.rs `purged_delta_never_held_reads_as_purger_spec_commits_5`, `purge_covered_by_held_snapshot_no_resnapshot_spec_commits_5`, `purge_resnapshot_by_writer_without_schema_spec_commits_5` (the order harness cannot show it: its hosts keep purged bodies, notes/test-properties.md). It is apart from `snapshot_first` (spec/sync.md §7 No carrier, for expiry as for purge), which then finds the re-snapshot as the carrier. Rejected: purging writes out of every state (trades this for the larger invalid-delta limit); fetching purged bodies to form leftovers (races the purger's host deletes).
- **Named by stamp, judged without the header** (`purge::Target`, `rejudge_carried`; spec/commits.md §5 Purge, Without the header; spec/crdt.md §8 `Facts`): an item names a commit's `(ts, own source)`, never its ID, so a node that forgot the header or never got it still finds the copies. Purgeable-by and actor come from each snapshot's facts (`snapshot::facts_of`). `rejudge_carried` lists the copies' dots as `Owned::Dots` where a request stands under every held snapshot's facts, on a request's apply, a snapshot's join, `rejudge_purges` and `forget_commits`, and asks for a re-snapshot when it lists more. Tests: tombstone.rs `a_purge_reaches_copies_of_a_forgotten_commit_spec_commits_5`, retention `tests_carried`.
  - Trust: facts are the snapshot writer's word, as its copies are. A cover counts only if it states what the body does for every commit both carry, a left-out fact as the narrowest (`covered_join`), and a request must stand under each held snapshot's facts. So a lie never widens a purge; it can block one at nodes without the header. Accepted: a writer can keep any value it reads alive by writing it again anyway (`tests_carried::a_wider_fact_never_covers_spec_commits_5`).
  - Rejected: the request carrying the named commit's facts (the purger's word would let any writer erase others' compacted writes wherever the header is gone); keeping headers of every live covered write (undoes compaction); the request carrying the named header itself (no help for by-author or aspect items).
- A purge that dropped a permanent delta is noted (`z/`, `retention::lasting`): a new node needs the request to hold the delta's copy as purged. Noted, not walked: an aspect-wide request naming nothing would walk the aspect each pass.
- **Purged leftovers are forgotten** (`retention::kept_purged`, either class): a content commit holding nothing but purged leftovers (not past expiry, no permanent or `created.0` delta) is `forgettable` once no entry of it is known and no delete is within its tombstone. `Engine::forget_commits` takes every due commit in one transaction, each aspect rebuilt once (`tombstone::forgetting_purged_leftovers_rebuilds_once_spec_commits_5`). Why: a purged leftover never drops as covered (the frontier stops below it), so each write-purge-delete round would leave a header and leftover for good. A fall then finds nothing, as for a write never received; a held re-snapshot keeps reads unchanged.
- **Frontier below a purged body** (`retention::held_purged`, in `write_snapshot` and the trigger's `candidates`; spec/crdt.md §1, §8): a snapshot's own walk stops below a part held value-less for a purge (not past its expiry), as below an invalid or missing one; inherited frontiers pass it. Cost: that session's later bodies are not reflected, so an own write purged starts fresh sessions (`purge_one`, `Core::fresh_session`). Covering no longer needs the stop; whether to drop it: issues/frontier-stop-below-purge.md.
- Memory class alike (notes/ephemeral.md Principle): a purged memory part is a memory leftover, a fall unstrips it (`Missing::ToFetch`) and the lane fetches it again. Tests: retention.rs `fallen_purge_of_ephemeral_write_comes_back_spec_perm_6`, `purge_of_waiting_ephemeral_part_reads_alike_spec_commits_5`, `purge_on_replace_of_ephemeral_write_spec_commits_5`.

## Waiting parts at expiry or purge (`retention/pending.rs`; spec/commits.md §5 Keep bounds)
- **Expiry**: a part pending at its expiry goes at T (`pending_drops`, `strip_pending`; parked copies included) and counts as never received; the commit is examined again without it. Ticks don't matter: before any ingest or `reexamine` reads a stored pending copy, its parts past T go as their timers would (`apply::expire_stored`, `retention::expire_waiting`). A part waiting aside (`pend_aside`) is judged alike and flags only its aspect (`Why::PendingExpiry`). Expiry does not strip: the whole part is past T.
- **Purge**: a pending part a held request names is held value-less, not dropped (`strip_purged`, `purge_pending`). Once its thing's record is held it is stripped and kept as the part's leftover, its pending slot holding an empty-list delta (`retention::emptied`; `examine` trusts it only with the leftover row, `Parts::stripped`); once joined, `stripped_joined` holds it as its leftover, so every arrival order holds the same state (`shred::purge_of_a_waiting_part_reads_alike_spec_commits_5`, `purge_of_a_part_waiting_aside_reads_alike_spec_commits_5`). With a page away or parked it cannot be stripped: it goes at once, flagged `Why::Uncovered`, refetched by `fetch_fallen` if the request falls before the commit applies.
- A waiting snapshot part carrying a listed value is stripped the same way (`strip_carried_waiting`), judged by a memo (`Core::waiting_carries`), so it is decoded when stored and when the list changes, never by a look with nothing changed (`shred::waiting_snapshots_judged_only_when_their_list_changes_spec_commits_5`). Its leftover keeps frontiers, `Absorbed` and facts and joins as a carrier (`apply::leftover_part`, `hold_carrier`); one not readable yet is stripped when it joins (`drop_gone`). Memory commits alike.
- node-sync forgets the blobs of an expired or stripped part at once (`Engine::spent_copy`). A blob also holding another part is kept only while it holds a true copy the engine lacks; junk holds no checkable slot, since `examine` checks hashes before storing a pending copy (spec/commits.md §4 Copies).
- **No purge needs a record it cannot have**: a part on a thing whose record is away is held nowhere (spec/commits.md §4 Unjudgeable): `apply::throw_out_parts` takes it out of a pending copy (`Waits::awaits_records`, `waits::wake` redelivers when the record comes), and node-sync keeps no blob holding it (`Engine::copy_awaits`; an applied commit's blob is fetched again by `reopen_undropped` when the record comes, which is also how a destroyed actor's record is taken again, spec/commits.md §5 Destruction). Test `shred::pending_part_awaiting_its_record_keeps_no_byte_spec_commits_4`.
- Limit (spec/commits.md §5): a pending commit whose header lists are not resolved cannot be judged by a request; its parts keep their values until the lists come or its last carrier leaves.
