# Engine: covers
> Summary: How bodies drop as covered (`retention/snapshot.rs`, `replace.rs`, sync `drop_covered`; spec/commits.md §5, spec/sync-compaction.md §1): the cover rule per part, own live bodies, purge on replace as the replacing writer's cover, a cover lasting as long as what it covers, frontiers and covering by the join, own replaces, forgetting and its accepted losses.

## Principle
Covering is the join and nothing else: a cover drops a body when it carries every live write of it and the body is past its keep bound, judged per part. Every duty to write a cover (purge on replace, own live bodies) only decides who writes one; the drop is always this test.

## The cover rule
- A cover drops a body when it carries every live write of it and the body is past its keep bound, judged per part (`drop_part_for`). Per commit would not do: a creation commit's live parts would keep its replaced purge-on-replace part, and writers without the right would re-cover it for good.
- One rule for durable and ephemeral, live or replaced (Tess: durable compaction on). A live delta's keep bound is its aspect's `history::Kept::live_until` (`bounds::live_keep`; spec/commits.md §5 Kept while live): a kept aspect's current parts are kept history (listings and undo read them) and pay their storage; an unkept aspect's live writes merge into snapshots.
- Cost accepted (spec/commits.md §5 Covered): a snapshot cannot give back what it dropped, so a purge that later falls, or a cover that later counts for nothing, restores no live write of an unkept aspect once every holder dropped it (the author keeps its own, below).
- Every covered-drop path asks the keep bound after the cover: sync's `drop_covered`, `own_covers_every_part`, `settle_none` (replaced bodies only, `replace::replaced`; a live part is the trigger's), memory's `drop_covered`.
- Out of history a drop needs only a held valid writer's snapshot covering the body (`Engine::drop_from`, no right asked). The purge right counts only where a promise is kept: purge on replace's duty (`replace::coverer`), deleting at other nodes, purge requests (`purge::snapshot_right`).
- Tests: engine it `covered`, `own_replaces`, `setting`.

## Own live bodies (spec/sync-compaction.md §1 own bodies)
A node drops a delta it wrote none of whose writes is dead only under its own covers. Why: another writer's snapshot can later count for nothing (a demotion whose frontier does not list it), and once every holder dropped the write nothing brings it back; the author still holding it logs it again as must-hold. Cost: an author holds its live writes until it writes a cover (the trigger counts them). Replaced bodies drop under any writer's cover: nothing visible rests on them.

## Purge on replace (`retention/replace.rs`)
- **The writer's cover** (Tess): at the end of every transaction (`settle_none`), over the aspects whose purge-on-replace bodies or snapshots changed (`Core::none_due`: commits on such aspects, rebuilds, setting changes, and timeline changes, since a grant can make this node a writer owing a cover), a node that may write a snapshot (`snapshot::may_snapshot`) writes a cover from its whole state (at most one per aspect and end per transaction) when a held body under purge on replace (the current setting's entry or the floor, `under_purge`) is replaced and no held valid snapshot holding the right over it covers it (`coverer`). Every covered body out of history then drops, at every node. The cover is written in a `Tx::step` (`Step::Cover`): a failure leaves the body to other writers, is reported (`OwnWriteFailed`) and never fails a receive.
- **Replaced** (`replaced`): the body is valid, a write of it is dead (`bounds::dead`: superseded by a held write lasting at least as long, spec/crdt.md §4.8, from the held writes, O(part)), and it joins into the state with its canonical bytes unchanged: not un-merged under an invalid record (a snapshot then cannot cover it, and one would be written every transaction). Not "has a dead write" alone (notes/engine-retention.md, Decided: Replaced). The spec judges the join against the state a snapshot ending with the body carries (without the writes ending sooner, joined with what only they superseded); the state as it is gives the same answer once deadness is lifetime-aware: a write ending sooner keeps a body's write from the state only where it supersedes it, and a write only such writes supersede is not dead for the body, so it is no death and joins nothing new. Debug builds check every judgment against that whole judging state (`replace::replaced_judged`, `snapshot::outlived`, O(state)). One judge of deadness, `osis_crdt::Held` (notes/engine-retention-dating.md, Which writes died and When): `snapshot::outlived` serves only what reads a whole state anyway (a snapshot's liveness, a delta not held, the cover's own state) and the debug checks.
- **A cover lasts as long as what it covers** (`snapshot::expiry_covers`, `write_cover`): a snapshot ending at T covers only bodies ending by T, so a cover never outlives what it vouches for nor drops a body that outlives it. The cover owed for a body ending at T (its commit's expiry; none: lasting) is a snapshot ending at T carrying the writer's state as it reads just before T: the state a write ending then dies in (`snapshot_state(ends)`, the one `replaced` judges by), so it covers every replaced body ending then by construction, an expiring write outlasted by another expiring one included (no lasting snapshot carries either). Written latest end first, each only while a body ending then is still uncovered: an outlasted cover ending earlier is covered by the next one, so a stream of renewed expiring writes keeps one expiring cover, not one per renewal still ahead. Its tables claim nothing (as `write_expiring`'s).
- The edit's own body drops under the same snapshot (purge on replace keeps no live write), so the aspect holds one snapshot at the writer after each transaction. Readers keep replaced bodies until a writer's snapshot arrives; with no writer online they keep them.
- **No useless covers**: a writer whose own snapshot would hold no right over the body (`purge::would_hold_right`) owes none while another held valid snapshot covers it. Else, under a narrow purge set, every plain writer writes a useless cover per replacement (headers kept for good, a node over its state bound).
- **Waiting to write** (`MayWrite::Later`: role held, minting, setting or the epoch a carried write was read under not here yet): the thing waits in `Indexes::cover_waits` under every thing on its record chain (journaled, so a rollback gives back a wait it ended). `replace::wake_covers` reads the transaction's journals of key-bearing commits, secrets, own keys and delete hints, and re-judges only the waiting things under those; roles, record grants and epochs come through `Core::timelines_changed`. So whichever of body, replacement, role and keys arrives last triggers the cover (retention.rs `writer_covers_once_its_thing_turns_independent_in_any_order_*`). O(what changed); memory only (the first transaction after an open settles every held purge-on-replace aspect). Rejected: marking every such aspect below a base whose keys changed (O(the base's aspects) per rotation).
- **Cost** (spec/requirements.md Scale, the cost the app chooses): a snapshot of the aspect per replacing edit, in practice by the editor alone: it logs the snapshot with the edit, so other writers find the body covered (notes/growth.md).
- Privacy: erased data persists in its body at a writer for no transaction, at a reader until a writer's snapshot arrives, at a node keeping S unread until a right holder next syncs. The read state loses it at the kill.
- Rejected for now: writer-side purge per edit, Tess's fallback if this proves costly (notes/engine-retention.md, Decided).
- Tests: held-model `spec_commits.rs` `none_*`, engine `setting.rs`, `held.rs`, `own_replaces.rs`.

## Frontiers and covering (`retention/snapshot.rs`)
- **Frontiers** list the sessions occurring in the state (`osis_crdt::sources_of`; a 0 entry for a session with no contiguous prefix applied, spec/crdt.md §8), each covering its counters applied and valid on the aspect (`snapshot::frontiers_now`): from the held valid snapshots' frontiers on, then held commits while they join without a hole, a held valid own whole replace passing a hole below it. Why both: a commit forgotten once covered takes its counter range with it, and a walk from counter 1 would stop at that hole for good. A part gone for a purge is passed: the snapshot carries none of its writes, and `covered_join` alone keeps a node lacking the body from counting it covered by that copy (spec/commits.md §5 Covered).
- **`covered`** judges a held body by the join, with the snapshot's copies under the body's dots stripped first so a differing copy never covers. Comparisons must stay on canonical bytes, not `Fragment ==`: a deleted text element's char survives a join in memory but not in canonical bytes.
- An expiring delta held is covered once the join says so (a cover carries none of its writes, spec/crdt.md §8). One not held and not gone is not covered, though the frontier alone would say it is.
- **A body not held** (a part a strip left out, never received) drops as covered like a held one (`covered_drops`, past its keep bound): it reads as received and dropped under the cover, and `uncover` makes it missing again (notes/whole-commits.md Strip). It is covered by tables alone. So a writer applying a purge that names a body it dropped as covered re-snapshots even where another's whole snapshot holds the body's other writes (`Engine::purge_resnapshots`).

## Own replaces (`own_*` in `retention/snapshot.rs`; spec/commits.md §5 Own replaces)
- A plain whole replace (root reset or register write) is its own cover. `Indexes::own_held` and `own_replaces` key held plain parts by (thing, aspect, author), so finding covers never walks the aspect. It takes two valid held own replaces later than the body: one late replace that later counts for nothing loses nothing.
- A commit goes only whole (`own_covers_every_part`): a reader cannot rewrite a blob, so dropping one part would leave it unable to relay the rest. Such a commit stays while any part is uncovered (issues/zero-growth.md Left). Out of history the author needs no purge right, so a single writer of an `admin` aspect stays flat.

## Forgetting (`Engine::forgettable`, `forget_commits`; spec/commits.md §5 Forgetting)
- A cover that turns invalid, drops other than as covered, or goes missing at its purge's fall gives back what it alone covered (`uncover`, notes/engine-validity.md), until the body is forgotten.
- A node forgets a content commit or snapshot, ID included, once every part dropped as covered, by any writer's cover, and no entry or delete within its tombstone names a blob of it (`Engine::forgettable`). Else each write another writer compacts leaves a header for good. osis-sync's read forgets by events (`judge::local`, once no entry of the commit is known), asking `forgettable` alone. A coverer forgotten before a body dropped under it keeps its covers while anything names it (`retention::handed`, notes/engine-validity.md), so the chain of covers stays whole.
- Forgetting reads as never having received: a removal frontier cannot list a forgotten commit, and the cover stands for it; the remover's own cover (spec/permissions.md §5.1, written only where something was forgotten) then carries its live writes from the remover's state, so another writer's cover falling with that writer loses nothing a removal's remover held (notes/revocation.md, One rule for both layers). Only its writer drops under an own cover (`retention::others_own_cover`, by its header's marker, so also before the removal arrives): it stands on its removal, which may fall. held-model reads the marker alike (`Commit::own_cover`): another node's own cover is no cover of a held body there, so a reader holding only such a cover keeps a replaced purge-on-replace body (`own_cover_drops_a_held_body_only_at_its_writer_spec_commits_5`). A snapshot is forgotten under the next that covers it, whoever wrote it.
- **Accepted losses** (Tess: permission changes over inconsistent connections cannot all work out): a cover that reaches a node before a removal naming none of it and counts for nothing after loses the writes only it carried, its predecessors' content included (others' live writes come back from their authors); a cover standing only on an addendum that later falls; a hostile node's snapshot claiming a sibling's edit without its value.
- Rejected, both against a loss that needs a late cover whose author is removed: keeping the previous snapshot (twice every compacted aspect's state at every node); a receipt per commit another writer covers (about 50 B per write).
