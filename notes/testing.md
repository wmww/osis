# Testing
> Summary: How osis is tested and how to run each layer: principles, tiers and when each runs, conformance vectors and their freeze policy, fuzzing, size budgets and benches, coverage, policy checks, the spec-to-test map, build hygiene (notes/build.md), and the conventions every crate follows when it adds tests, vectors, fuzz targets or benches.

Strategy items not built (a 10^4-seed sweep, GUI smoke tests) are in issues/tests-unbuilt.md.

## Principles
- The spec is the oracle: every MUST has a test that fails without it, and every test cites the spec section it checks, so `grep` (or notes/testing-map.md) answers "what checks §X".
- Determinism: seeded randomness, injected clocks, in-process transport. A failure is a seed; a flake is a bug.
- Peer bytes never panic: every parser is fuzzed; decoders take limits.
- Models (core/test/crdt-model, core/test/roles-model, core/test/tla) are independent oracles; the implementation never depends on them and they are never patched to match it.

## Tiers
Everything runs locally; there is no CI service.

| tier | what | how | when |
|---|---|---|---|
| 1 | unit, small proptest (`PROPTEST_CASES=32`), vectors | `cargo test --workspace` (about 40 s warm); one area: `cargo test --workspace --test it <module>::[name]` | every gate |
| 2 | `#[ignore]` tests: oracles at size, large property runs; networking tests | by name: the oracles below, when the branch touches their area; the whole set `PROPTEST_CASES=256 cargo test --workspace -- --include-ignored --skip scale:: --skip bench:: --skip budget --skip sweep --skip repro_` as a periodic check; networking: `cargo test-net -- --ignored` | reviewers per branch; periodic |
| 3 | sim seed sweeps, fuzz, big model instances, TLC, benches, coverage, timing budgets (`scale::`, `bench::`, `budget*`, release only) | the gate runs every sim scenario at 5 seeds for sim/engine/node/perm/crdt changes (20 s); the periodic checks below; the rest by hand | gate; periodic; by hand |

**Periodic checks** (notes/coordination.md: the seed-breadth runs, in the background in a spare worktree, roughly every six times their own duration of coordinator work, offsets rotating): `cargo run --bin sim-sweep -- --seeds 150 --from <F> --budget-secs 3600`, `OSIS_ORDER_START=<S> OSIS_ORDER_SEEDS=300 cargo test --workspace --test it order::arrival_order_alike_large_spec_permissions_5_2 -- --ignored` (2 min) and `OSIS_ORDER_START=<E> OSIS_ORDER_SEEDS=200 ... order::arrival_order_exhaustive_large_spec_crdt_4_8` (13 min), `OSIS_PERM_SEED=<P> cargo test -p osis-perm`, `OSIS_CRDT_SEED=<C> cargo test -p osis-crdt -- --include-ignored --skip repro_ --skip budget --skip bench:: --skip scale:: --skip hostile_moves --skip shrink_script` (without the skips `budget_big_text_spec_6` runs for 30+ min in dev), `core/test/tla/run.sh small`. Why: every bug caught by a generated input in the last coordinator session came from a seed or range nobody had run, never from re-running the default ranges; breadth is cheap when batched and wasted when paid per branch. Not yet possible: rotating proptest's seed.

Integration tests are one binary per crate: `tests/it/main.rs` with a module per former test file (`tests/it/<module>.rs`; notes/architecture.md, Conventions), so a test's name is `<module>::<fn>` and `cargo test <fn>` filters still match. Single-file crates (osis-base, osis-vectors, crdt-model) keep `tests/<file>.rs` (`--test cbor`, `--test vectors`, `--test props`).

How to replay a failing sim seed: `sim-sweep` prints `osis_sim::replay("<scenario>", <seed>)`; call it from a test (`cargo test --workspace --test it`) or add it as an ignored `<scenario>_seed_<n>` test naming its issue (Phase C, Blocked). `OSIS_SIM_TRACE=1` prints every trace line. `sim-sweep --help` lists its flags. ## Models (core/test/: crdt-model, roles-model, tla)
- `core/test/crdt-model` and `core/test/roles-model`: Rust reference models (notes/crdt.md, notes/permissions.md); the roles model's exhaustive tiers and random samples are tier 3.
- Roles model API (core/test/roles-model/src/lib.rs): per model `walk(h)` (pure), `random_hist`, `quiescent(h)` (each node's walk over the writes in its delivery order equals the canonical one; a search counter and a tier-1 test) and a `Display` trace; `shrink::shrink` reduces a failing history one step at a time (fewer writes, ops, nodes and actors, lower roles and edges, receipts dropped, times and commit IDs renumbered) to a 1-minimal one. The searches and osis-perm's differential runs print counterexamples shrunk, as traces. The joint walk's code follows §5.1 step by step. `roles-model -- N digest` hashes every verdict of N random histories per model (std `DefaultHasher`, stable within one toolchain); a refactor keeps it: at 1,000,000 joint 066c5ca679110a2a, edges f745031e1747beda, edges-prov def8459f68ebe872, snapshot 6ca6ac3f0f823467 (since ownerless actors joined `joint::random_hist`, which shares the rng, so every model's histories moved).
- Differentials against models: crdt join and wire (osis-crdt `tests_seq`, `tests_join`), the crdt decoder (osis-crdt `tests_decoder.rs`: mutated writer deltas and snapshots of random histories accepted or rejected alike, accepted ones decoding to equal fragments; notes/crdt.md, Reference model), perm (osis-perm `tests/it/differential.rs`).
- `core/test/tla/sync` and `core/test/tla/rotation`: TLA+ models written from spec/ alone, checked with TLC. Sync covers one label at one host: upload, download, deposit and promotion, deletes by delete key (blob-ID carrier tiebreak) and timed deletes (snapshot first when writes stay live), expiry, compaction, purge and rewrite, due snapshots (also before a live drop), tombstones, offline nodes, a dropping/replaying/reordering host; properties: no live write leaves the label uncarried, must-hold bodies converge to the host, must-not-hold bodies and duplicates do not persist, entries settle, deposits get promoted, purges reach every node, holders end up holding a carrier for their live state. Rotation covers read-role rotation of one actor: established epochs, forced and eager rotation, forks, removal carried in its rotation, grants, registration steps after the rotation chain is uploaded, claims and claim-set drops, stranded heartbeats (also on a refused claim), deposit-seed refresh, re-seal after a complete pass (by inbox and under the label, so other nodes learn its boxes), rotation by inbox to holders without a box at the epoch before, per-node box knowledge, co-reader peers, and an adversary planting boxes (secrets from pending or invalid commits are reading-only); properties: no departed holder reads content written with its departure known, no departed holder holds an epoch that did not box it, nothing is encrypted under a planted secret (a negative control with the rule removed fails in 4 states), every current holder eventually opens every current epoch and reads everything. `core/test/tla/roles` (written from spec/, checked against osis-perm where the text was subtle) covers the role walk and tenure ledger (permissions §1–§2, §5.1, §5.2, §6): owner chains, B as a holder on A, `until`, self-removals, explicit demotions with frontiers, the demoter's kept standing, several-edge removals, layer-2 content, the depth cap, ledger production and replay; a state is a history (any ts, any frontier subset); properties: drop order does not matter, roster snapshots at every point are neutral, a removed holder's later writes are invalid, demoters keep and are audited on their standing, owner-chain authority confers write within the depth cap. Instances: 12, every one as expected; the passing ones run 9 s to 12 min at 1 worker (snapshot neutrality is the costly check: `MC_snapA` 72k states 9 min, `MC_snapB` 73k 12 min, `MC_until` 108k 10 min). Each README gives the instances with results, state counts and times; each AMBIGUITIES.md the findings (all resolved but residue 2 of issues/reseal-triggers.md, `MC_drop_refresh`; roles M2 sticky drops `MC_sticky`, `MC_sticky_snap`; M1 (`MC_forge`) and M3 (same-key commits, `MC_samets`: keys carry the commit ID) fixed). **Confidentiality over `LocalPeer`**: `Package`/`deliver`/`sync` hand over plaintext commits, so a peer that lost access still reads whatever it is sent: no "who can read" claim holds there. Plaintext stays right for pairing/setup and for tests of what an engine does with what arrives (order, validity). Inbox blobs are real either way (`carry`, `accept_inbox`).

## Simulator (core/test/sim/, crate osis-sim)
- Shape: `Sim::new(name, seed, Config)` boots `nodes` real engines, each over its own `MemoryBackend` + `MemoryRoot` sharing one `osis_store::Faults` plan, a `ManualClock` and a seeded rng; all randomness comes from one `Dice` seeded by the run seed. `Config`: per-node `ClockSpec { skew_ms, drift_ppm }` (wall = T0 + elapsed + skew + elapsed·drift/10^6), `NetFaults { drop_pct, dup_pct, max_delay_ms, reorder }`, scheduler `Weights { write, gossip, deliver, tick, crash, restart }`, `max_tick_ms`, `check_every_step`.
- `step()` picks one event: a random write (1–3 random ops of `workload`, a schema with one aspect per encoding, on things in `sim.things` the node may write), gossip (node → random peer: packages of every applied commit the receiver lacks — an oracle standing in for reconciliation until node-sync's `SyncEngine`; each through drop/dup/delay), delivery of a due message (earliest, or any under reorder; to a down node it is lost), a tick (time passes, clocks set, `Engine::tick`), a crash (immediate, or at one of the node's next durable writes via `Faults::at(n, Crash)`: mid-write), a restart (`Peer::restart` over the same backend). `run(n)`, `run_until_quiescent(max_rounds)` (no new writes or crashes, every node up, everything delivered, pairwise sync without faults, time advanced 10 min at a time while commits pend). Setup helpers: `create_thing`, `grant`, `revoke`, `commit`, `deliver`, `sync_all`, `advance`, `set_clock`, `read`, `engine`.
- Invariants (`check`): per step, every group of up nodes holding the same applied commits reads the same values (every stored aspect); per applied event, own `ts` strictly increasing across restarts and within `MAX_DRIFT` (+1 ms) of the wall clock, no remote commit applied more than `MAX_DRIFT` ahead, no node-form counter range of one author overlapping another commit's on one aspect; at quiescence, every node holds the same commits and nothing pends. Engine errors on honest input (BadInput on an honest package, any error on a node not crashed) and panics (caught per run) are failures.
- Failures carry scenario, seed, step and the last 40 trace lines, and print `osis_sim::replay("<scenario>", <seed>)`, which reruns it exactly (a test checks a run twice gives the same `Report`, digest included). A failing sweep seed becomes a tier-1 test with a one-line description.
- Scenarios (`SCENARIOS`): `two_devices` (person actor owned by device 0, device 1 admin, a data thing the person owns), `three_random` (two shared things, all faults, skew ±5 min, drift ±200 ppm), `crash_restart` (plus crashes), `drift_parks` (a node jumps 2 h ahead: its commit pends with `Drift`, unread, until the receiver's clock is within `MAX_DRIFT`), `revoke_while_writing` (a writer removed while writing). Tier 1 runs seed 1 of two_devices, three_random and drift_parks, the others are tier 2; `OSIS_SIM_SEEDS=N [OSIS_SIM_ONLY=a,b] cargo test --workspace sweep -- --ignored` is a small sweep (every unblocked scenario, or the named ones); the nightly one is `sim-sweep` (Phase C).

### API world (core/test/sim/src/world.rs)
`World`: `osis::Osis` handles on `Runtime::Manual` and osis-host `Hub`s over in-memory queues under one `ManualClock` (core/test/sim/src/world.rs; the osis crate's tests use it): `add_host`, `cfg`/`person`, `run`, `advance`, `until(future, step, n)` (panics if it does not resolve), `set_online` (offline databases still tick), `diagnostics`/`trace`, `traffic` (bytes per database) and `start_tally`/`tally` (upstream frames by message kind); a storm (`STORM` rounds in one settle) panics naming what it carries.

### Phase B: sync engines and hosts (core/test/sim/src/net)
- `NetSim::new(name, seed, NetConfig)`; `add_host` (osis-host `Hub` over `HostStore` on a `MemoryBackend` and `MemoryRoot` with their own `Faults`, true time), `replicate(a, b)` (hosts dial each other: `Hub::peer_up` on the dialer, `accept` with the dialer's static key on the other, for echo suppression), `add_node(hosts, ClockSpec)` (`SyncEngine` over an `Engine` on `MemoryBackend`+`MemoryRoot` sharing a `Faults`, its own skewed `ManualClock`). Actions are carried engine to engine: `Dial` makes a link (or a `Down` if the host is down or the pair blocked), `Send` queues bytes on the stream, `Close` drops it, `Wake` is fired when the node's clock reaches it; hub outputs the same way. Connections are ordered byte streams: `LinkFaults { cut_pct, dup_pct, max_delay_ms, reorder }`: a lost message cuts its connection (both ends told), delays keep per-stream order, reorder picks any due stream head, duplication repeats a message (a protocol violation the receiver must survive).
- Scheduler (`NetWeights`): write (random ops on `groups[..].items` the node may write), deliver, tick (time, wakes, hub ticks when `next_due`, host redials), node crash (now or at a durable write) and restart over its store, host crash (now or mid-write) and restart, partition / heal of a (node, host) or (host, host) pair. Also `sever` (a pair never connects), `wipe_host` (data loss), `lose_disk` (node gone for good), `reconnect_all`. Setup is calm (no faults): flows helpers `person`, `pair` (card direct, `Engine::pair`, `take_direct` delivered, `paired`), `introduce` (cards direct), `group` (+ `create_label`), `grant`, `remove` (demotion), `item`, `carry` (`carry_out` + direct packages), `quiet(max)` (settle until idle and unchanged); `run(n)` turns faults on, `run_until_quiescent(max)` heals, restarts everything, settles a resync interval (61 s) at a time until idle and unchanged for two rounds, then checks.
- Quiescent invariants (`net/check.rs`): convergence by held deltas (projections: two nodes holding the same deltas of an aspect read it the same); nothing pends; holder liveness (every device of a person on an admin's roster, or of the owner, reads the group) and agreement (they read the same items); per host and label: no live entry tombstoned or back after a tombstone, every body a writer judges must-hold (`SyncEngine::verdicts`, the pass's own judgment) in a live entry (a known blob of that commit with a superset of the parts; `known` maps blob IDs to commits from nodes' `entries`), no entry a node may delete as must-not-hold still live, deposited entries promoted by writers that applied them; purged bodies at no host and no honest node (`holds_blob`); state size (spec/requirements.md Scale): a node's stored bytes (its `MemoryBackend` dump) ≤ 2 × must + 2 KiB × entries + 16 KiB × labels + 64 KiB, where must and entries are the bytes and count of the live entries of its labels at the fullest honest host (never its own holdings, so junk or pending commits raise no bound; `net/check.rs` `STATE_*`; release sweep of seeds 0..3 of every scenario: nodes stored at most 2.11x must and 0.47 of the bound; each node's numbers are trace lines); no ping-pong (three more resync rounds add or delete nothing). A run that never settles reports the churn (what the rounds added/deleted, with commits and aspects); a settle of more than 5000 deliveries is a message storm. Phase A's per-event checks (HLC, counters) run on every node. `OSIS_SIM_TRACE=1` prints every trace line with the proto messages.
- Work sets against full passes (`core/test/sim/tests/it/work_sets.rs`, notes/sync.md Work sets): `net::with_full_passes(f)` makes every node added in `f` judge everything at each pass (`SyncConfig::full_passes`); a scenario run both ways must give the same `Report`, whose digest covers every host log record in order and each node's local sync state (`SyncEngine::state_digest`: entries, stamps, presence, carriers, blob records, held bytes; without it a compaction that kept dropped bodies' keys went unseen). `full_passes` is the new pass with everything in scope, not main's code: the harness guards that the work sets miss no trigger, not that the judging helpers are right (the sweep's invariants do that). Tier 1: scenario `keep_at_most` seed 1 (the two runs on two threads); tier 2: scenario `work_sets` seed 1 (two replicating hosts, three writers, compactions, keep-at-most and expiring writes, a purge, a demotion, an hour on; about 20 s per run in debug) and every scenario, seeds `OSIS_SIM_SEEDS` (20) from `OSIS_SIM_FROM` (0; `OSIS_SIM_ONLY` narrows).
- Waivers (`NetSim::waivers`, constants in `net/mod.rs`) switch one invariant off for a scenario while its issue is open (none now); `excused` nodes (removed, lost) are left out of liveness, agreement and purge checks.
- Scenarios (`core/test/sim/tests/it/net.rs`; tier 1 keeps the quickest, see Phase C): `two_devices_host` (pairing, crashes mid-write), `three_persons_two_hosts` (replication, grants by inbox, host crashes, partitions), `removed_writer` (removal, then a writer without the delete key purges the removed writer's body: deleted by delete key), `reader_relays` (writer severed from s1, a reader carries its stamped entries there; the readers' opens race the grants' registrations), `stranded_reseal` (a device off past `ROLE_KEEP` across two rotations is refused, then re-paired), `host_loses_data` (writers re-register and re-upload), `offline_rotation` (a reader off across two removals walks the steps; removed holders hold no later epoch), replay exactness. `compaction` (two writers compact while writing; covered bodies deleted, then a purge), `disk_loss` (a device recovered from the card writes and converges)., `grant_lost_on_crash` (a grant's inbox deposit survives the granter's crash), `large_edits` (two devices edit an 8 MiB blob in turn through a host; bytes sent per edit within 1.2x of the changed chunks plus the root node and 32 KiB; `NetNode::sent_bytes`).

## Arrival-order differential (osis-node `tests/it/order.rs`)
Validity, un-merge and state must be functions of the held set (spec/requirements.md Decentralization). Generated steps are `Step::Aim`ed: at play time the author and thing are pointed at ones that can write it (`aim`), so 22% of commit steps make no commit (63% before, 69% of writes: untyped sequence ops, counters and removals never wrote), and most writes are `Typed` (the schema's key, `fit`ted offsets); a quarter stay untyped for the `Slots` positions (`Write`, ops in `UNTYPED`). `Forged` (`commit_hostile`): an invalid write, a commit on two things, a role commit on two things, a raised own edge, a roster it likes, over things its author may have no chain to (`NewTop`). Each step's outcome is tallied (`Tally`); `run` asserts floors (`Seen::floors`: half of commit steps commit, over 20+ of them; 20+ seeds must reach an invalid part, and `history` of 60+ steps also `WaitDeltas`, every sequence shape and `MissingChain`; a floor must not fail on a lucky seed range: `focused_history` reaches `WaitDeltas` on 3% of seeds, so it has no such floor). `OSIS_ORDER_STATS=1` prints them. Fresh nodes sync things by `seed % 3` (`with_syncs`, only under `run`: pinned histories do not): none; `Syncs::Early` (half the things from the start, half the multi-aspect commits held in part for good, others synced for a stretch); `Syncs::Late` (things start, some stop and restart, at points per order). Known bugs the harness steps around, each named with its issue: `plain_state` drops a deleted char from the compared states, which spec/crdt.md §5.7 leaves to the node. Each held set goes to fresh nodes (one seed, one clock) in several orders: as made (the reference), reversed, every order after the setup when the whole set is held and small, random shuffles; the first two again with late parts (`deliver_split`: every multi-aspect commit, roster snapshots included, first with one seeded aspect's parts, the rest at the end; `Nested` with `also` makes the put a two-aspect commit). ## Seed runners (`osis_base::testenv`)
`run_seeds(name, seeds, visible, replay, f)` (and `Seeds::run`, which announces an env range first) runs `f(seed)` for every seed on a thread per core (`OSIS_SEED_THREADS` overrides, one variable for every harness), a panic as its seed's failure (`caught`), results in seed order; it panics on an empty seed list. Each failing seed prints with its replay command as it fails, a progress line every 60 s, then a summary line (seeds run, failing, hung, threads, wall time), then a panic listing every failure in seed order. A seed whose thread has used `OSIS_SEED_TIMEOUT_SECS` (default 600) CPU-seconds on it, or no CPU at all for that many seconds (blocked), is marked hung and a new thread takes its place (CPU time read from `/proc/<tid>/schedstat`; wall time where there is none). Only the seed's own thread counts: a seed that waited on threads it spawned would read as blocked (none do today: seeds are single-threaded). Not wall time: periodic run 12 (`nice 19`, load 30-50, three variants of 16 threads each) took 701 s wall for `random_window` seed 253018, a 5 CPU-s seed, and called it hung; the same run did 36 seeds per variant in its first 13 min and about 950 in the next 13 as the load fell, while CPU-s per seed was unchanged since before item 179 (16 seeds one at a time: 46.2 CPU-s at item 178, 50.1 at 189, 49.6 after 191). No process-wide thread budget: concurrent runs oversubscribing the cores stretch each seed's wall time, not the CPU the run needs; its thread prints its backtrace (`std::backtrace`) at its next `testenv::checkpoint()` (called by `LocalPeer::sync` and the node test `Net::run`, so every LocalPeer or net harness passes one per sync; a seed stuck below them prints its last checkpoint location instead). A hung thread cannot be stopped or joined: when the rest is done with hung seeds still running, or as many seeds hang as there are threads, the runner prints every failure and hung seed and exits the process (101). `par_map`/`caught`/`threads` are the building blocks; the order harness uses them for its own shrinking runner.

Rule: a seed-ranged harness's tier-1 test runs fixed seeds and reads no environment; its `#[ignore]` `_large` twin reads the `OSIS_*_START`/`_SEEDS` range (`--ignored --exact <name>_large`), and every printed replay line names the twin. So `--ignored --exact` on a harness name either runs it or matches nothing (`0 passed`), never a silent default run.

## Forensic attack (`osis_store::attack`, `Engine::forensic`)
The definition of "forensically clean" (spec/requirements.md, Deletion). Evidence: the keys the current store tree yields, the label read secrets the node's code computes now (`Engine::forensic` adds them), and every row and blob the backend was ever given (`MemoryBackend::record_history`: `history`, `blob_history` with frees; `fork` copies a recording device). To a fixpoint it reads every row and blob raw (clear rows `r`, `p`, `j`; a blob stored in clear), opens rows with store keys (tree nodes yield more), takes every random-looking 32 bytes (at least 16 distinct byte values) of anything recovered as a candidate key on every blob (link keys, node-sync `y/b` keys, anything), and for entries keyed by a blob ID (store wraps, node-sync `y/e`; table pages decoded by the store's own `forensic_leaf`, overflow values joined) tries the value's leading wrap under every candidate as a read secret. Each find says where (`Source`: row, raw row, blob opened by key or by wrap, raw blob).
- Not covered: keys inside a blob stored in clear (raw blobs and raw rows are not harvested: ciphertext would flood the candidates; clear rows are); a wrap not at the start of a blob-keyed entry's value; secrets only derivable from dropped ones (the attack never runs KDF chains over old secrets); memory, swap, the root store's past records; non-memory backends (redb: `file_backend_holds_no_plaintext` greps the file). Markers find content; a dropped map key's keyed index hash is checked as an extra needle where it matters (`expired_entry_paged_*`).
- "Random-looking" misses a real random key with probability about 2^-55 (fewer than 16 distinct values in 32 random bytes); a false positive costs time only.
- Cost: about 40K candidates × 17 blobs (and their wraps) on a synced `Net` node, 1.5-2.5 s CPU per attack, one thread per blob (about 0.3 s wall on a free 16-core box); crash loops fork one set-up device per crash point instead of setting up again. Solo wall: `purged_synced_body_crash_safe` 3.7 s, `removal_erasure_crash_safe` 5.3 s.
- Row lengths: `shredded_small_drop_keeps_unit_lengths_within_a_class_step` checks a shredded small drop leaves each rewritten unit's padded length equal or one Padmé class step away.
- Tests: store `tests/it/shred.rs` (units, wraps, blob keys and wraps, clear rows), node `shred.rs` (engine purge, expiry, keep-at-most, paged, chunked), `shred_sync.rs` (a synced node's purge online and offline, and a crash at every write of the purge and node-sync's forget: fails with the store-audit fix reverted), `flows.rs` (removal erasure, crash-safe), host `hygiene.rs`, `metadata.rs`, osis `hosting.rs` (host stores: rows only).

## Conventions for every crate
- **Spec citations**: put `// spec/<file>.md §N[.M]: <what>` right above each `#[test]` (inside `proptest!` too); a bare `§N` refers to the last file named in that comment. A test without its own citation inherits the file's `//!` header citations. Infrastructure tests with no spec section say `// spec: none (<why>)`.
- **Network in tests**: tier 1 uses `osis_transport::{Net, Sched}` (in-process, virtual steps, seeded faults and scheduling; no tokio); real-socket tests (QUIC on localhost) are tier 2.
- **Tiers**: tier-2 tests are `#[ignore]` (optionally also gated on `OSIS_SLOW=1`); a crate's tier 1 stays under about 10 s.
- **Seed loops**: a loop over consecutive seeds gives each its own run: `rng(seed | 1)` made seeds 2k and 2k+1 the same history in osis-crdt (half of `model_order_independent_*`, `seq_differential_large_*` and the follow-cache tests repeated work); now odd seeds via `step_by(2)`; the paged-apply harness seeds `seed << 1 | 1`. Harmless `| 1` left: crdt-model `tests/props.rs` (proptest draws random seeds), osis-node `it/walks.rs` (seeds multiplied by an odd constant first). A multi-seed tier-2 run goes through `testenv::run_seeds` (a thread per core, `OSIS_SEED_THREADS`), not a serial loop.
- **Vectors**: in the plan step that lands an encoding: write a generator `fn() -> VecFile` in `core/test/vectors/src/subjects/<subject>.rs` from fixed inputs (32 repeated bytes per seed), register it in `subjects::get`, add the crate as an osis-vectors dependency, flip the MANIFEST line to `provisional`, run `gen-vectors`, and add the file to `vector_files!` in core/test/vectors/tests/vectors.rs. Hand-written vectors get a checker instead. Rejections use rule IDs documented in core/test/vectors/README.md. Toplevel review freezes them (FC entry).
- **Fuzz**: a target per parser of peer or disk bytes (core/test/fuzz/README.md, "Adding a target"), seeds in `corpus.rs`; a crash becomes a regression test in the owning crate citing the spec section and `fuzz: <target>`.
- **Budgets and benches**: in osis-bench as above; a new external dependency for them needs its line in notes/architecture.md §5.

## Performance budgets
Coordinator-owned targets (owner delegated; prefer simple and verifiable code that meets them over faster intricate code). Beyond them, one aspect at 10^5 and 10^6 commits: Scale checks, long aspect. At 10^4 commits per aspect and 10^4 things per group, release, a quiet box: a single local write, read or received commit under 50 ms; node open under 1 s; one sync pass after one new write under 100 ms; a late or out-of-order commit under 500 ms (a whole replay of one aspect is acceptable here). Rare events (revocation, a roster snapshot, a move) under a few seconds. Work beyond these is not pursued without a realistic scenario missing them; issues that only chase speed below them are closed as within budget.

Host (osis-host on its own `Store`, redb and a file root, release, a laptop disk; `file::host_throughput_budget`, by hand): 1 KiB entries at least 1000/s uploaded and 1000/s deleted in 64-entry hub batches (a 1024-entry message in about a second); one single-entry upload batch plus one single-entry delete batch under 20 ms (the delete's shredding commit: two backend commits and the root's two fsynced slot writes, about 4 fsyncs). Measured at load 6, medians of 5 against main before the move (rows on `Backend`, lazy commits, one fsync per batch): uploads 2160/s (main 2590), deletes 2220/s (main 3170), the single-entry pair 13.9 ms (main 2.6 ms: the extra fsyncs of shredding). Whole-space Reconcile reads decrypt pages: about 125 ms at 10^5 live entries, 1.06 s at the 2^20 per-label cap (main 35-60 ms and 0.5 s; notes/sync.md Hub stall bounds).
