# Testing
> Summary: How osis is tested and how to run each layer: principles, tiers and when each runs, conformance vectors and their freeze policy, fuzzing, size budgets and benches, coverage, policy checks, the spec-to-test map, build hygiene (notes/build.md), and the conventions every crate follows when it adds tests, vectors, fuzz targets or benches.

Strategy items not built (a 10^4-seed sweep, GUI smoke tests) are in issues/tests-unbuilt.md.

## Principles
- The spec is the oracle: every MUST has a test that fails without it, and every test cites the spec section it checks, so `grep` (or notes/testing-map.md) answers "what checks §X".
- Determinism: seeded randomness, injected clocks, in-process transport. A failure is a seed; a flake is a bug.
- Peer bytes never panic: every parser is fuzzed; decoders take limits.
- Models (core/test/crdt-model, core/test/roles-model, core/test/tla) are independent oracles; the implementation never depends on them and they are never patched to match it.

## Tiers
Everything runs locally; there is no CI service.

| tier | what | how | when |
|---|---|---|---|
| 1 | unit, small proptest (`PROPTEST_CASES=32`), vectors | `cargo test --workspace` (about 40 s warm); one area: `cargo test -p <crate> --test it <module>::[name]` | every gate |
| 2 | `#[ignore]` tests: oracles at size, large property runs; networking tests | by name: the oracles below, when the branch touches their area; the whole set `PROPTEST_CASES=256 cargo test --workspace -- --include-ignored --skip scale:: --skip bench:: --skip budget --skip sweep --skip repro_` as a periodic check; networking: `cargo test-net -- --ignored` | reviewers per branch; periodic |
| 3 | sim seed sweeps, fuzz, big model instances, TLC, benches, coverage, timing budgets (`scale::`, `bench::`, `budget*`, release only) | the gate runs every sim scenario at 5 seeds for sim/engine/node/perm/crdt changes (20 s); the periodic checks below; the rest by hand | gate; periodic; by hand |

**Store-contents differential** (a refactor that must not change stored bytes or write order; engine-simplify review): seeded `LocalPeer`/`MemoryBackend` stores are byte-deterministic, rng-sealed rows included, once the persisted index tag is pinned (`index.rs` `VERSION` folds in `OSIS_INDEX_RULES`, a hash of the sources, so every row set differs between builds otherwise). Throwaway patch, applied to main and the branch alike: in `MemoryBackend::commit` fold each batch's ops into a running hash, and in a `Drop for Data` append `thread-name trace-hash final-hash batches rows` to `$OSIS_DUMP_FILE` (and add `OSIS_DUMP_FILE` to core/base/testenv-known.txt, or the harnesses refuse it); set `VERSION` to a constant; run tier 1 plus the order oracles on each, sort, diff. About 12,400 stores (tier 1 plus `order::arrival_order_alike_large_*`); the order harness's workers name no thread, fine as sorted lines. Tests that differ run to run on one build (crash, store, runtime, driver, cli, some notes/sync/encodings tests, `apply::tests_paged`'s three paged-snapshot tests, osis `api::created_reads_through_run_time_key_*`: async, OS randomness) differ between builds too; rerun those on one build to rule them out. A store dropped on another thread (`osis-dispatch`) moves its line to that name between runs: compare the lines without names too.

**Periodic checks** (notes/coordination.md: the seed-breadth runs, in the background in a spare worktree, roughly every six times their own duration of coordinator work, offsets rotating): `cargo run --bin sim-sweep -- --seeds 150 --from <F> --budget-secs 3600`, `OSIS_ORDER_START=<S> OSIS_ORDER_SEEDS=300 cargo test -p osis-node --test it -- --ignored order::arrival_order_alike_large_spec_permissions_5_2` (2 min) and `OSIS_ORDER_START=<E> OSIS_ORDER_SEEDS=200 ... order::arrival_order_exhaustive_large_spec_crdt_4_8` (13 min), `OSIS_PERM_SEED=<P> cargo test -p osis-perm`, `OSIS_CRDT_SEED=<C> cargo test -p osis-crdt -- --include-ignored --skip repro_ --skip budget --skip bench:: --skip scale:: --skip hostile_moves --skip shrink_script` (without the skips `budget_big_text_spec_6` runs for 30+ min in dev), `core/test/tla/run.sh small`. Why: every bug caught by a generated input in the last coordinator session came from a seed or range nobody had run, never from re-running the default ranges; breadth is cheap when batched and wasted when paid per branch. Not yet possible: rotating proptest's seed.

Integration tests are one binary per crate: `tests/it/main.rs` with a module per former test file (`tests/it/<module>.rs`; notes/architecture.md, Conventions), so a test's name is `<module>::<fn>` and `cargo test <fn>` filters still match. Single-file crates (osis-base, osis-vectors, crdt-model) keep `tests/<file>.rs` (`--test cbor`, `--test vectors`, `--test props`).

The merge gate (tier 1) and every canonical command: notes/build.md (`-p <crate>` for one crate's dev loop; the sim sweep is `cargo run --bin sim-sweep -- --seeds 5 --budget-secs 900`, run by the gate for any change in the simulator or a crate it depends on: the 10^4-seed sweep after production round 1 caught a `stranded_reseal` regression that tier 1 and the targeted tier-2 runs had missed on every seed). Nothing in it requires nextest, nightly or cargo-fuzz; nextest works if installed. Tier 1 never sleeps or touches the network. osis-crdt's seeded random tests (every `testutil::rng(seed)`, fixed-seed loops and proptest cases alike) sample other runs with `OSIS_CRDT_SEED=<n>`: a splitmix hash of n xor'ed into each run's seed (hashed: a small n xored into a loop's consecutive seeds only reorders them); unset, the committed seeds. A panicking test prints the effective seed. `fuzz_seq::random_scripts_replay_spec_5_7` replays random `seq_ops` scripts the same way; `OSIS_SHRINK=<loop seed> cargo test --workspace -- --ignored shrink_script` (with the same `OSIS_CRDT_SEED`) drops steps and ops of a failing one while it fails and prints it.

osis-perm's random runs (`roster`, `differential`, `queries`, `incremental`) sample other histories with `OSIS_PERM_SEED=<n>` (xor'ed into each run's seed); each tier-2 run is `common::sharded`: 16 shards on scoped threads, shard i seeded `seed ^ i << 40` (fixed count, so a failing seed reproduces anywhere; the panic names the shard's seed). A shard runs only while it holds one of a process-wide pool of permits, a thread per core (`OSIS_PERM_THREADS` overrides), so the 15 concurrent tier-2 tests keep about 16 busy threads instead of 240. Tier-2 set at `OSIS_PERM_SEED=7`, box at load 15-30 from others: unbounded 130-137 s wall, 1860-2015 CPU-s, load 85; pooled 142 s, 1880 CPU-s, load about 30 (the wall difference is mostly the share taken from other processes). Sample counts keep the counted paths (appended, placed, restored) well over their asserted floors; `append_shapes_*` costs about 1.2 CPU-s a sample, so it has 384.

How to replay a failing sim seed: `sim-sweep` prints `osis_sim::replay("<scenario>", <seed>)`; call it from a test (`cargo test -p osis-sim --test it`) or add it as an ignored `<scenario>_seed_<n>` test naming its issue (Phase C, Blocked). `OSIS_SIM_TRACE=1` prints every trace line. `sim-sweep --help` lists its flags. A "read differently" failure ends with a divergence dump: per node, every commit naming the differing aspect with its part's status (dropped, missing, valid, covered by) and the aspect's state (`Engine::aspect_dump`); `SyncEngine::ephemeral_dump(label)` prints a node's ephemeral lane the same way.

## Simulator (core/test/sim/, crate osis-sim)
- Shape: `Sim::new(name, seed, Config)` boots `nodes` real engines, each over its own `MemoryBackend` + `MemoryRoot` sharing one `osis_store::Faults` plan, a `ManualClock` and a seeded rng; all randomness comes from one `Dice` seeded by the run seed. `Config`: per-node `ClockSpec { skew_ms, drift_ppm }` (wall = T0 + elapsed + skew + elapsed·drift/10^6), `NetFaults { drop_pct, dup_pct, max_delay_ms, reorder }`, scheduler `Weights { write, gossip, deliver, tick, crash, restart }`, `max_tick_ms`, `check_every_step`.
- `step()` picks one event: a random write (1–3 random ops of `workload`, a schema with one aspect per encoding, on things in `sim.things` the node may write), gossip (node → random peer: packages of every applied commit the receiver lacks, wholly or by a part the sender holds — an oracle standing in for reconciliation; each through drop/dup/delay), delivery of a due message (earliest, or any under reorder; to a down node it is lost), a tick (time passes, clocks set, `Engine::tick`), a crash (immediate, or at one of the node's next durable writes via `Faults::at(n, Crash)`: mid-write), a restart (`Peer::restart` over the same backend). `run(n)`, `run_until_quiescent(max_rounds)` (no new writes or crashes, every node up, everything delivered, pairwise sync without faults, time advanced 10 min at a time while commits pend). Setup helpers: `create_thing`, `grant`, `revoke`, `commit`, `deliver`, `sync_all`, `advance`, `set_clock`, `read`, `engine`.
- Invariants (`check`): per step, every group of up nodes holding the same parts of the same applied commits reads the same values (every stored aspect; phase A nodes are asked to sync nothing, so a part on a thing whose creation is away waits alone, spec/commits.md §4, and its commit applies and relays without it); per applied event, own `ts` strictly increasing across restarts and within `MAX_DRIFT` (+1 ms) of the wall clock, no remote commit applied more than `MAX_DRIFT` ahead, no counter range of one session overlapping another commit's on one aspect; at quiescence, every node holds the same parts and nothing pends. Engine errors on honest input (BadInput on an honest package, any error on a node not crashed) and panics (caught per run) are failures.
- Failures carry scenario, seed, step and the last 40 trace lines, and print `osis_sim::replay("<scenario>", <seed>)`, which reruns it exactly (a test checks a run twice gives the same `Report`, digest included). A failing sweep seed becomes a tier-1 test with a one-line description.
- Scenarios (`SCENARIOS`): `two_devices` (person actor owned by device 0, device 1 admin, a data thing the person owns), `three_random` (two shared things, all faults, skew ±5 min, drift ±200 ppm), `crash_restart` (plus crashes), `drift_parks` (a node jumps 2 h ahead: its commit pends with `Drift`, unread, until the receiver's clock is within `MAX_DRIFT`), `revoke_while_writing` (a writer removed while writing). Tier 1 runs seed 1 of two_devices, three_random and drift_parks, the others are tier 2; `OSIS_SIM_SEEDS=N [OSIS_SIM_ONLY=a,b] cargo test --workspace sweep -- --ignored` is a small sweep (every unblocked scenario, or the named ones); the nightly one is `sim-sweep` (Phase C). `grant_to_group` (a grant to a group with its admin away, a later reader, a removal, then a grant of an unlabeled thing: `Engine::unrouted` at the granter and a reader until `create_label`, whose `label.0` blob the admin copies, spec/sync.md §2-§3).

### API world (core/test/sim/src/world.rs)
`World`: `osis::Osis` handles on `Runtime::Manual` and osis-host `Hub`s over in-memory queues under one `ManualClock` (core/test/sim/src/world.rs; the osis crate's tests use it): `add_host`, `cfg`/`person`, `run`, `advance`, `until(future, step, n)` (panics if it does not resolve), `set_online` (offline databases still tick), `diagnostics`/`trace`, `traffic` (bytes per database) and `start_tally`/`tally` (upstream frames by message kind); a storm (`STORM` rounds in one settle) panics naming what it carries.

### Phase B: sync engines and hosts (core/test/sim/src/net)
- `NetSim::new(name, seed, NetConfig)`; `add_host` (osis-host `Hub` over `HostStore` on a `MemoryBackend` and `MemoryRoot` with their own `Faults`, true time), `replicate(a, b)` (hosts dial each other: `Hub::peer_up` on the dialer, `accept` with the dialer's static key on the other, for echo suppression), `add_node(hosts, ClockSpec)` (`SyncEngine` over an `Engine` on `MemoryBackend`+`MemoryRoot` sharing a `Faults`, its own skewed `ManualClock`). Actions are carried engine to engine: `Dial` makes a link (or a `Down` if the host is down or the pair blocked), `Send` queues bytes on the stream, `Close` drops it, `Wake` is fired when the node's clock reaches it; hub outputs the same way. Connections are ordered byte streams: `LinkFaults { cut_pct, dup_pct, max_delay_ms }`, none of them looking at what is sent: each link direction releases at random moments of the network clock (one per `max_delay_ms`, keyed by link, direction and bucket; streams overtake each other, each keeps its order), a link is cut at keyed moments, what is on its way lost with it (both ends told), a release may arrive twice; compared runs (`with_arrivals`) deliver all that is due in a deliver step, any other run one message a step, so events and cuts fall inside a burst (seen: bursts split across steps 19% of multi-message ones, 0.5% without this, 15% with); only deliver steps move the network clock (ticks do not, so messages stay in flight across events), each step has its own `Dice`, boots theirs. Duplication repeats a message (a protocol violation the receiver must survive).
- Scheduler (`NetWeights`): write (random ops on `groups[..].items` the node may write), deliver, tick (time, wakes, hub ticks when `next_due`, host redials), node crash (now or at a durable write) and restart over its store, host crash (now or mid-write) and restart, partition / heal of a (node, host) or (host, host) pair. Also `sever` (a pair never connects), `wipe_host` (data loss), `lose_disk` (node gone for good), `reconnect_all`. Setup is calm (no faults): flows helpers `person`, `pair` (card direct, `Engine::pair`, `take_direct` delivered, `paired`), `introduce` (cards direct), `group` (+ `create_label`), `grant`, `remove` (demotion), `item`, `carry` (`carry_out` + direct packages), `quiet(max)` (settle until idle and unchanged); `run(n)` turns faults on, `run_until_quiescent(max)` heals, restarts everything, settles a resync interval (61 s) at a time until idle and unchanged for two rounds, then checks.
- Quiescent invariants (`net/check.rs`): convergence by held deltas (projections: two nodes holding the same deltas of an aspect read it the same); nothing pends; no certificate copy still waits (`SyncEngine::deferred`); holder liveness (every device of a person on an admin's roster, or of the owner, reads the group) and agreement (they read the same items); per host and label: no live entry tombstoned or back after a tombstone, every body a writer judges must-hold (`SyncEngine::verdicts`, the pass's own judgment) in a live entry (a known blob of that commit with a superset of the parts; `known` maps blob IDs to commits from nodes' `entries`), no entry a node may delete as must-not-hold still live, deposited entries promoted by writers that applied them; purged bodies at no host and no honest node (`holds_blob`); state size (spec/requirements.md Scale): a node's stored bytes (its `MemoryBackend` dump) ≤ 2 × must + 2 KiB × entries + 16 KiB × labels + 64 KiB, where must and entries are the bytes and count of the live entries of its labels at the fullest honest host (never its own holdings, so junk or pending commits raise no bound; `net/check.rs` `STATE_*`; release sweep of seeds 0..3 of every scenario: nodes stored at most 2.11x must and 0.47 of the bound; each node's numbers are trace lines); no ping-pong (three more resync rounds add or delete nothing). A run that never settles reports the churn (what the rounds added/deleted, with commits and aspects); a settle of more than 5000 deliveries is a message storm. Phase A's per-event checks (HLC, counters) run on every node. `OSIS_SIM_TRACE=1` prints every trace line with the proto messages.
- Work sets against full passes (`core/test/sim/tests/it/work_sets.rs`, notes/sync.md Work sets): `net::with_full_passes(f)` makes every node added in `f` judge everything at each pass (`SyncConfig::full_passes`); a scenario run both ways may differ in messages only (a pass the work sets leave out saves what it would send again, so work sets may send no more, checked only between runs alike to the bit: another seal order alone moves the count by up to a hundred messages), with no tolerance: the counters of faults and writes, when each upload, deposit and registration first reached each host (`net::with_arrivals`: a missed trigger shows as a later arrival, 61 s at a quiet round) and when a delete took a host's last copy of a commit ('G'; not each delete, whose number and targets are the luck below), and `Report::parts` (what each node and host ends up with, named: commits, reads, `SyncEngine::state_digest` with entries, presence, carriers, blob records and held bytes, without which a compaction that kept dropped bodies' keys went unseen). Arrivals and parts name a blob by commit and parts, never by ID, and go by what, not under which label: an ID, wrap, salt, stamp, the log order inside a batch and which copy of a commit stays (the lower ID, so its holder and label) are the luck of which seal drew first from the node's random stream, and a pass over labels in another order draws in another order (`compared_runs_ignore_the_random_stream`: the same run on another stream is no difference; before these were left out, 65-82 state lines differed). For the same reason a deposit's relay wait hashes its commit, not its ID. Compared runs do not drift (`add_node_with`): a clock corrected by pings moves with when they went, and they go when a session has been quiet, so a pass more moved commit timestamps by up to a quarter second and with them every commit ID after. The dice cannot see what a pass sends (`net/mod.rs` head): a parted run is a real difference, read its lines. A passing run writes its counts past the test's capture (`N runs, M parted, failed both ways [...]`); a scenario failing both ways is the sweep's to report. 1073 s for all at 100 seeds on 16 cores, 0 of 5300 parted. `honest_flows_wait_for_no_resync` is the same comparison with no faults (100 seeds: 760 s). `full_passes` is the new pass with everything in scope, not main's code: the harness guards that the work sets miss no trigger, not that the judging helpers are right (the sweep's invariants do that). Tier 1: scenario `keep_at_most` seed 1 (the two runs on two threads); tier 2: scenario `work_sets` seed 1 (two replicating hosts, three writers, compactions, keep-at-most and expiring writes, a purge, a demotion, an hour on; about 20 s per run in debug) and every scenario, seeds `OSIS_SIM_SEEDS` (20) from `OSIS_SIM_FROM` (0; `OSIS_SIM_ONLY` narrows).

## Arrival-order differential (osis-node `tests/it/order.rs`)
Validity, un-merge and state must be functions of the held set (spec/requirements.md Decentralization). Generated steps are `Step::Aim`ed: at play time the author and thing are pointed at ones that can write it (`aim`), so 22% of commit steps make no commit (63% before, 69% of writes: untyped sequence ops, counters and removals never wrote), and most writes are `Typed` (the schema's key, `fit`ted offsets); a quarter stay untyped for the `Slots` positions (`Write`, ops in `UNTYPED`). `Forged` (`commit_hostile`): an invalid write, a commit on two things, a role commit on two things, a raised own edge, a roster it likes, over things its author may have no chain to (`NewTop`). Each step's outcome is tallied (`Tally`); `run` asserts floors (`Seen::floors`: half of commit steps commit, over 20+ of them; 20+ seeds must reach an invalid part, and `history` of 60+ steps also `WaitDeltas`, every sequence shape and `MissingChain`; a floor must not fail on a lucky seed range: `focused_history` reaches `WaitDeltas` on 3% of seeds, so it has no such floor). `OSIS_ORDER_STATS=1` prints them. Fresh nodes sync things by `seed % 3` (`with_syncs`, only under `run`: pinned histories do not): none; `Syncs::Early` (half the things from the start, half the multi-aspect commits held in part for good, others synced for a stretch); `Syncs::Late` (things start, some stop and restart, at points per order). Known bugs the harness steps around, each named with its issue: `plain_state` drops a deleted char from the compared states, which spec/crdt.md §5.7 leaves to the node. Random histories on three `LocalPeer`s (0 owns G, 1 writes, 2 admin): content writes on every encoding including writes inside map entries, struct fields and texts in map entries, grants and re-grants, demotions (removal or to read) with frontiers before, inside and after the holder's writes, self-removals, roster and compaction snapshots, things created under things in later commits, `Nested` (one peer puts an entry, another, sent it alone, writes inside and maybe compacts), undo, expiry (`t:brief.0`, and ops 27-29: register, map and text writes expiring after 1 s or 30 min; hours pass), bounded keeps (kept and keep-at-most registers, keep-at-most-0 register and map whose bodies drop as they die, a kept set, a kept nested map write; ops 30 and 31 under an absolute keep at most 1 s or 30 min ahead, a list insert and a register also under a relative one, `retention_of`; every delivery ends with a `tick`, as node-sync's `expire_due` before every read), partial syncs and single sends. Every commit made is a package; held sets are the whole set plus partial ones (alternately without one writer's commits after the setup, as a node that never heard from it, and a random two thirds). Each held set goes to fresh nodes (one seed, one clock) in several orders: as made (the reference), reversed, every order after the setup when the whole set is held and small, random shuffles; the first two again with late parts (`deliver_split`: every multi-aspect commit, roster snapshots included, first with one seeded aspect's parts, the rest at the end; `Nested` with `also` makes the put a two-aspect commit). Compared: the index digest (`IndexDigest`, typed per commit, snapshot and thing, other indexes as text by name; `IndexDigest::diff` lists differing fields, the tolerated ones are `order::index_exempt`), reads as text and states of every aspect, rosters, pending reasons, timelines (as held and from scratch); the reference must also equal itself after a reopen and after a rebuild (each then re-examined, as an open does). Clock mode (`Cfg::clock` orders per held set, as made and reversed first, the rest spread evenly over the others: 2 in SMALL/LARGE, 24 in EXHAUST; `OSIS_ORDER_CLOCK=n` overrides, 0 off, 720 every order): the order's first 1..all commits arrive at an earlier clock (`clock_of`, seeded apart from the main stream: just after or just before the prefix's last `ts`, up to an hour after, or anywhere from an hour before the first commit, so drift parks), then the clock moves to the end (`tick`) and the rest arrive; judged like any order against the reference (dating, `alike_exchanged`); the node is made at the end time and its clock set back, so its own things match; `alike` ignores commits' received times (`unreceived`). `Seen::floors` asserts, for the `alike` and `exhaustive` runs, that some move changed a state or a body's facts (about 7% of moves in `alike_large`, 1% in `exhaustive_large`, whose cut histories rarely end past a bound). Cost: about +12% CPU on `alike_large`; on `exhaustive_large` every order clocked was +50% (363 to 549 CPU-s for 8 seeds side by side), 24 per held set about +0-10%. Stepped around: a commit applied by a part before its expiry vs pending whole (found by this mode, seed 731018; spec/requirements.md Deterministic): `alike` leaves that commit's pending line out (`parted`). Runner (`run`): one seed per task on a thread per core (`OSIS_ORDER_THREADS` overrides); a seed's history and orders depend only on the seed, the length and the test, so `OSIS_ORDER_SEED=n` replays exactly; a panicking check counts as a failure of its seed; every failing seed is shrunk (dropping steps) and reported, each with its replay command, the shrunk `h = vec![..]` for `check(seed, &h, CFG)`, the two orders (#0 as made, want, against the one that differs, got) and the first differing line; the summary line prints seeds, orders, failures, wall time and every `OSIS_ORDER_*` setting. Tests: tier 1 `arrival_order_alike_small_*` (4 seeds of 8 steps, all orders of up to 4 commits, 2 shuffles, 1 partial set; about 1 s) and `arrival_order_exhaustive_small_*` (3 focused histories of up to 5 commits after the setup: every order of the whole set and of 1 partial set, each also with late parts and reopened; about 280 orders, 2.5 s wall, 25 CPU-s), plus the found histories; tier 2 `arrival_order_alike_large_*` (60 seeds of 60 steps, 8 shuffles, 4 partial sets) and `arrival_order_exhaustive_large_*` (EXHAUST: 40 seeds from 2023, histories cut to at most 6 commits, every order of the whole set and 2 partial sets, up to 720 orders each; 2000..2200 took 13 min, 12400 CPU-s, and failed 6 seeds, the dropped-superseder family that per-node death dating made moot). Reversing what follows the setup with the setup first (exhaustive order #2) is what found them: 300 random seeds at 8300 found none. Focused histories (`focused_history`): two bounded aspects per history (keep-at-most ones written by the owner, keep-at-least ones mostly by the others), their compactions, undo, demotions and grants, `Nested`, one clock pulled ahead (late writes), sends and syncs, cut to a prefix within the commit bound. "Every order" keeps the setup first (reversed order #1 moves it) and splits each order's multi-aspect commits once, by a seeded pick; the held sets are the whole set and 1 or 2 partial ones (without one peer's commits, often all of them and then dropped, and a random two thirds); `OSIS_ORDER_ALL_HELD=1` tries every subset of what follows the setup (2.3x: 40 default seeds 62.6k orders, 349 s, 4170 CPU-s, green). A seed's orders run in parallel when there are fewer seeds than cores (a replay), else one seed per thread. `OSIS_ORDER_SEED`, `OSIS_ORDER_START`, `OSIS_ORDER_SEEDS`, `OSIS_ORDER_LEN` narrow or widen either kind; `OSIS_ORDER_STATS=1` prints each history and per held set how many commits have an invalid part and how many carried groups hold invalid writes (without partial sets almost none did: carried invalid writes need a node lacking their commit).
Orders compare by `alike`: reads, states, rosters, pending sets and timelines at the fresh nodes' time, and reads and states two hours later (`later`: every bound and expiry past), exact. Which bodies a node holds and how it dates deaths are per node and are not compared: a seed where bodies or dates differ but reads agree and the per-node checks hold is not an issue. Bodies dropped before a validity flip are given to both nodes again before comparing (`alike_exchanged`: `drop_flips`, a keep-at-most body held at one node whose own write or a later-stamped write of its aspect is invalid; `both_dropped_flips`, keep-at-most or snapshots on an aspect a purge request names, dropped at both on an aspect read apart that flipped on the way, `flipped`, spec/crdt.md §4.6; `purge_flips`, parts a fallen purge took); `facts_text` feeds it and is not compared. One node's reopen compares exactly, facts included, and its reopened index against a rebuild's (`IndexDigest::first_diff`); a rebuild reads by `alike`. Per-node checks against a fresh node keeping every body (`oracle`, `Engine::keep_bodies`; `Seen::judged` floors them): (a) `body_past_bound` two hours later (`later_than`; past every bound the ops draw), no applied body under a keep at most held past its bound: an absolute one, valid or not; first death plus D plus grace, live writes or not; none under a relative one without a live write and with a death; no death means no bound only for a body whose killers went with dropped bodies, never for a write invalid here or one an un-merge took (they count dead from their fall), and `bound_kept_now`, a dead body under at most 0 is gone at once and none went before the keep-everything node's earliest superseder plus D; (b) `live_write_lost` later: reads as the keep-everything node with no body given again, on an aspect where nothing fell, flipped or was purged; given every body again reads as it and holds every write live there; a `PendingExpiry` flag names an aspect some commit writes with an expiry; (c) `value_past_end`, now and later, no value of a delta past its expiry or that a standing purge request drops in the state, a held body or a waiting copy (`Engine::pending_value_past_end`); values only, keys of expired entries are issues/expired-entry-key-kept.md. Mutants that fail them: never dropping at the bound, a body with a live write kept past it, a bound 12 h late, a lost keep-at-most timer, dropping before the bound, a keep-at-most drop taking a live value, ignoring a copy of a dropped body, a no-op expiry timer, a past-expiry part kept waiting, a purge holding nothing value-less. A body with a live write at its bound is rare in generated histories (about 1 in 40 seeds): `live_write_outlives_its_body_at_the_bound` pins it. Still not caught: a map entry key kept past expiry (no read check on keys), anything limited to an aspect flagged `PendingExpiry` until a compaction. `arrival_order_settled_*` (history, or `_purges`: `purge_history`; full sync, no commit held in part, every writer compacts every aspect): all orders read alike, the "until a writer next compacts" of the Deterministic exceptions (whole held set, reads only, aspects a writer compacted; `alike_repaired` gives a node flagging an aspect its compactions again, standing in for the repair snapshot: the compaction itself may have reached it before the flip; `settled_large` 60 seeds about a minute). Not reached: every writer dropped what a reader kept, the stated limit (spec/requirements.md Deterministic), pinned by `flip_after_drop_only_a_reader_holds_it_lasts_to_the_next_write_spec_sync_7`; the real repair path by `flip_after_drop_mended_by_a_writer_holding_it_spec_sync_7`. A part held pending at its expiry (flag `PendingExpiry`, spec/requirements.md Deterministic): that aspect's reads and states are not compared; with an early clock a commit such a part applied at one node only has its pending line left out (`parted`). `OSIS_ORDER_SHRINK=0` reports a failing seed unshrunk. `OSIS_ORDER_DUMP=1` prints, on an order's failure, the packs (index: id, author peer, kind, aspects), each of the two orders' reads as they change after every ingest (with the pending count), both nodes' flag sets and every judged part (`dump_orders`); every failing check prints, the shrink's too, so use it on a pinned history or with `OSIS_ORDER_SHRINK=0`. `Engine::body_fragment` (no caller: a triage hook) gives a held body as a fragment (a snapshot's copies, value-less and key-erased records included) where `body_page` gives only its read.
Found and fixed: `holder_keys` took the first held record of a `roles.0` entry as its base, so an edge change by structural diff arriving before its grant kept a partial base (now an edge change is remove + put and a nested `roles.0` write bad input, `edge_change_is_remove_and_put_spec_perm_2`); carried groups listed in arrival order; a snapshot carrying an invalid entry creation after another's write nested in that entry had joined (`entry_created_after_demotion_write_first_spec_perm_5_1`, `arrival_order_found_histories_spec_crdt_4_6`); an open left unresolved an edge write `ts`-ordered before the record it needs (another node's clock), which a fresh apply had resolved (same test, seed 1558); an invalid commit's unheld or late parts skipped the un-merge of others' writes under their creations (`late_invalid_part_unmerges_alike_spec_crdt_4_6`).

## Seed runners (`osis_base::testenv`)
`run_seeds(name, seeds, visible, replay, f)` (and `Seeds::run`, which announces an env range first) runs `f(seed)` for every seed on a thread per core (`OSIS_SEED_THREADS` overrides, one variable for every harness), a panic as its seed's failure (`caught`), results in seed order; it panics on an empty seed list. Each failing seed prints with its replay command as it fails, a progress line every 60 s, then a summary line (seeds run, failing, hung, threads, wall time), then a panic listing every failure in seed order. A seed whose thread has used `OSIS_SEED_TIMEOUT_SECS` (default 600) CPU-seconds on it, or no CPU at all for that many seconds (blocked), is marked hung and a new thread takes its place (CPU time read from `/proc/<tid>/schedstat`; wall time where there is none). Only the seed's own thread counts: a seed that waited on threads it spawned would read as blocked (none do today: seeds are single-threaded). Not wall time: periodic run 12 (`nice 19`, load 30-50, three variants of 16 threads each) took 701 s wall for `random_window` seed 253018, a 5 CPU-s seed, and called it hung; the same run did 36 seeds per variant in its first 13 min and about 950 in the next 13 as the load fell, while CPU-s per seed was unchanged since before item 179 (16 seeds one at a time: 46.2 CPU-s at item 178, 50.1 at 189, 49.6 after 191). No process-wide thread budget: concurrent runs oversubscribing the cores stretch each seed's wall time, not the CPU the run needs; its thread prints its backtrace (`std::backtrace`) at its next `testenv::checkpoint()` (called by `LocalPeer::sync` and the node test `Net::run`, so every LocalPeer or net harness passes one per sync; a seed stuck below them prints its last checkpoint location instead). A hung thread cannot be stopped or joined: when the rest is done with hung seeds still running, or as many seeds hang as there are threads, the runner prints every failure and hung seed and exits the process (101). `par_map`/`caught`/`threads` are the building blocks; the order harness uses them for its own shrinking runner.

Rule: a seed-ranged harness's tier-1 test runs fixed seeds and reads no environment; its `#[ignore]` `_large` twin reads the `OSIS_*_START`/`_SEEDS` range (`--ignored --exact <name>_large`), and every printed replay line names the twin. So `--ignored --exact` on a harness name either runs it or matches nothing (`0 passed`), never a silent default run.

## Forensic attack (`osis_store::attack`, `Engine::forensic`)
The definition of "forensically clean" (spec/requirements.md, Deletion). Evidence: the keys the current store tree yields, the label read secrets the node's code computes now (`Engine::forensic` adds them), and every row and blob the backend was ever given (`MemoryBackend::record_history`: `history`, `blob_history` with frees; `fork` copies a recording device). To a fixpoint it reads every row and blob raw (clear rows `r`, `p`, `j`; a blob stored in clear), opens rows with store keys (tree nodes yield more), takes every random-looking 32 bytes (at least 16 distinct byte values) of anything recovered as a candidate key on every blob (link keys, node-sync `y/b` keys, anything), and for entries keyed by a blob ID (store wraps, node-sync `y/e`; table pages decoded by the store's own `forensic_leaf`, overflow values joined) tries the value's leading wrap under every candidate as a read secret. Each find says where (`Source`: row, raw row, blob opened by key or by wrap, raw blob).
- Not covered: keys inside a blob stored in clear (raw blobs and raw rows are not harvested: ciphertext would flood the candidates; clear rows are); a wrap not at the start of a blob-keyed entry's value; secrets only derivable from dropped ones (the attack never runs KDF chains over old secrets); memory, swap, the root store's past records; non-memory backends (redb: `file_backend_holds_no_plaintext` greps the file). Markers find content; a dropped map key's keyed index hash is checked as an extra needle where it matters (`expired_entry_paged_*`).
- "Random-looking" misses a real random key with probability about 2^-55 (fewer than 16 distinct values in 32 random bytes); a false positive costs time only.
- Cost: about 40-60K candidates × the unopened blobs (and their wraps), and every store key × every row; a try first decrypts only the last plaintext byte (`aead::last_plain_byte`: padded plaintexts end in 0x80 or 0x00), so a wrong key costs one ChaCha block instead of a MAC pass over the blob (that pass was most of the shredding tests' CPU). Under a second per attack; one thread per blob; crash loops fork one set-up device per crash point instead of setting up again.
- Row lengths: `shredded_small_drop_keeps_unit_lengths_within_a_class_step` checks a shredded small drop leaves each rewritten unit's padded length equal or one Padmé class step away.
- Tests: store `tests/it/shred.rs` (units, wraps, blob keys and wraps, clear rows), node `shred.rs` (engine purge, expiry, keep-at-most, paged, chunked), `shred_sync.rs` (a synced node's purge online and offline, and a crash at every write of the purge and node-sync's forget: fails with the store-audit fix reverted), `flows.rs` (removal erasure, crash-safe), host `hygiene.rs`, `metadata.rs`, osis `hosting.rs` (host stores: rows only).

## Conventions for every crate
- **Spec citations**: put `// spec/<file>.md §N[.M]: <what>` right above each `#[test]` (inside `proptest!` too); a bare `§N` refers to the last file named in that comment. A test without its own citation inherits the file's `//!` header citations. Infrastructure tests with no spec section say `// spec: none (<why>)`.
- **Network in tests**: tier 1 uses `osis_transport::{Net, Sched}` (in-process, virtual steps, seeded faults and scheduling; no tokio); real-socket tests (QUIC on localhost) are tier 2.
- **Tiers**: tier-2 tests are `#[ignore]` (optionally also gated on `OSIS_SLOW=1`); a crate's tier 1 stays under about 10 s.
- **Seed loops**: a loop over consecutive seeds gives each its own run: `rng(seed | 1)` made seeds 2k and 2k+1 the same history in osis-crdt (half of `model_order_independent_*`, `seq_differential_large_*` and the follow-cache tests repeated work); now odd seeds via `step_by(2)`; the paged-apply harness seeds `seed << 1 | 1`. Harmless `| 1` left: crdt-model `tests/props.rs` (proptest draws random seeds), osis-node `it/walks.rs` (seeds multiplied by an odd constant first). A multi-seed tier-2 run goes through `testenv::run_seeds` (a thread per core, `OSIS_SEED_THREADS`), not a serial loop.
- **Vectors**: in the plan step that lands an encoding: write a generator `fn() -> VecFile` in `core/test/vectors/src/subjects/<subject>.rs` from fixed inputs (32 repeated bytes per seed), register it in `subjects::get`, add the crate as an osis-vectors dependency, flip the MANIFEST line to `provisional`, run `gen-vectors`, and add the file to `vector_files!` in core/test/vectors/tests/vectors.rs. Hand-written vectors get a checker instead. Rejections use rule IDs documented in core/test/vectors/README.md. Toplevel review freezes them (FC entry).
- **Fuzz**: a target per parser of peer or disk bytes (core/test/fuzz/README.md, "Adding a target"), seeds in `corpus.rs`; a crash becomes a regression test in the owning crate citing the spec section and `fuzz: <target>`.
- **Budgets and benches**: in osis-bench as above; a new external dependency for them needs its line in notes/architecture.md §5.

## Performance budgets
Coordinator-owned targets (Tess delegated; prefer simple and verifiable code that meets them over faster intricate code). Beyond them, one aspect at 10^5 and 10^6 commits: Scale checks, long aspect. At 10^4 commits per aspect and 10^4 things per group, release, a quiet box: a single local write, read or received commit under 50 ms; node open under 1 s; one sync pass after one new write under 100 ms; a late or out-of-order commit under 500 ms (a whole replay of one aspect is acceptable here). Rare events (revocation, a roster snapshot, a move) under a few seconds. Work beyond these is not pursued without a realistic scenario missing them; issues that only chase speed below them are closed as within budget.

Host (osis-host on its own `Store`, redb and a file root, release, a laptop disk; `file::host_throughput_budget`, by hand): 1 KiB entries at least 1000/s uploaded and 1000/s deleted in 64-entry hub batches (a 1024-entry message in about a second); one single-entry upload batch plus one single-entry delete batch under 20 ms (the delete's shredding commit: two backend commits and the root's two fsynced slot writes, about 4 fsyncs).
