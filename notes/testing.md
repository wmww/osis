# Testing
> Summary: How osis is tested and how to run each layer: principles, tiers and when each runs, conformance vectors and their freeze policy, fuzzing, size budgets and benches, coverage, policy checks, the spec-to-test map, build hygiene (canonical cargo commands, seeded worktrees, sweeps), and the conventions every crate follows when it adds tests, vectors, fuzz targets or benches.

Strategy items not built (a 10^4-seed sweep, GUI smoke tests) are in issues/tests-unbuilt.md.

## Principles
- The spec is the oracle: every MUST has a test that fails without it, and every test cites the spec section it checks, so `grep` (or notes/testing-map.md) answers "what checks §X".
- Determinism: seeded randomness, injected clocks, in-process transport. A failure is a seed; a flake is a bug.
- Peer bytes never panic: every parser is fuzzed; decoders take limits.
- Models (models/) are independent oracles; the implementation never depends on them and they are never patched to match it.

## Tiers
Everything runs locally; there is no CI service.

| tier | what | how | when |
|---|---|---|---|
| 1 | unit, small proptest (`PROPTEST_CASES=32`), vectors | `cargo test --workspace`; one area: `cargo test --workspace --test it <module>::[name]` | before every merge to main |
| 2 | `#[ignore]` tests: large property runs, size budgets, differential at size | `OSIS_SLOW=1 PROPTEST_CASES=1024 cargo test --release --workspace -- --include-ignored`; networking: `cargo test-net -- --ignored` | before merging risky changes; periodically |
| 3 | fuzz, sim seed sweeps, big model instances, TLC, benches, coverage | see below | periodically, by hand |

Integration tests are one binary per crate: `tests/it/main.rs` with a module per former test file (`tests/it/<module>.rs`; notes/architecture.md, Conventions), so a test's name is `<module>::<fn>` and `cargo test <fn>` filters still match. Single-file crates (osis-core, osis-label, osis-vectors, crdt-model) keep `tests/<file>.rs` (`--test cbor`, `--test scale`, `--test vectors`, `--test props`). tools/merge_tests.py did the move (re-runnable: consolidates any crate with several top-level test files). ## Models (models/)
- `models/crdt` and `models/membership`: Rust reference models (notes/crdt.md, notes/permissions.md); the membership model's exhaustive tiers and random samples are tier 3.
- Membership model API (models/membership/src/lib.rs): per model `walk(h)` (pure), `random_hist`, `quiescent(h)` (each node's walk over the writes in its delivery order equals the canonical one; a search counter and a tier-1 test) and a `Display` trace; `shrink::shrink` reduces a failing history one step at a time (fewer writes, ops, nodes and actors, lower roles and edges, receipts dropped, times and commit IDs renumbered) to a 1-minimal one. The searches and osis-perm's differential runs print counterexamples shrunk, as traces. The joint walk's code follows §5.1 step by step. `membership-model -- N digest` hashes every verdict of N random histories per model (std `DefaultHasher`, stable within one toolchain); a refactor keeps it: at 1,000,000 joint 49ebdbc60d0eb968, edges 3a3f61da583af52a, edges-prov a006fee636c8aa3d, snapshot dd45be1f78bb2d91.
- Differentials against models: crdt join and wire (osis-crdt `tests_seq`, `tests_join`), the crdt decoder (osis-crdt `tests_decoder.rs`: mutated writer deltas and snapshots of random histories accepted or rejected alike, accepted ones decoding to equal fragments; notes/crdt.md, Reference model), perm (osis-perm `tests/it/differential.rs`).
- `models/tla/sync` and `models/tla/rotation`: TLA+ models written from spec/ alone, checked with TLC. Sync covers one label at one blind server: upload, download, deposit and promotion, deletes by delete key (blob-ID carrier tiebreak) and timed deletes (snapshot first when writes stay live), expiry, compaction, purge and rewrite, due snapshots (also before a live drop), tombstones, offline nodes, a dropping/replaying/reordering server; properties: no live write leaves the label uncarried, must-hold bodies converge to the server, must-not-hold bodies and duplicates do not persist, entries settle, deposits get promoted, purges reach every node, members end up holding a carrier for their live state. Rotation covers read-role rotation of one actor: established epochs, forced and eager rotation, forks, removal carried in its rotation, grants, registration steps after the rotation chain is uploaded, claims and claim-set drops, stranded heartbeats (also on a refused claim), deposit-seed refresh, re-seal after a complete pass (by inbox and under the label, so other nodes learn its boxes), rotation by inbox to members without a box at the epoch before, per-node box knowledge, member peers, and an adversary planting boxes (secrets from pending or invalid commits are reading-only); properties: no departed member reads content written with its departure known, no departed member holds an epoch that did not box it, nothing is encrypted under a planted secret (a negative control with the rule removed fails in 4 states), every current member eventually opens every current epoch and reads everything. `models/tla/membership` (written from spec/, checked against osis-perm where the text was subtle) covers the membership walk and tenure ledger (permissions §1–§2, §5.1, §5.2, §6): owner chains, B as a member of A, `until`, self-removals, explicit demotions with frontiers, the demoter's kept standing, several-edge removals, layer-2 content, the depth cap, ledger production and replay; a state is a history (any ts, any frontier subset); properties: drop order does not matter, roster snapshots at every point are neutral, a removed member's later writes are invalid, demoters keep and are audited on their standing, owner-chain authority confers write within the depth cap. Instances: 12, every one as expected; the passing ones run 9 s to 12 min at 1 worker (snapshot neutrality is the costly check: `MC_snapA` 72k states 9 min, `MC_snapB` 73k 12 min, `MC_until` 108k 10 min). Each README gives the instances with results, state counts and times; each AMBIGUITIES.md the findings (all resolved but residue 2 of issues/reseal-triggers.md, `MC_drop_refresh`; membership M2 sticky drops `MC_sticky`, `MC_sticky_snap`; M1 (`MC_forge`) and M3 (same-key commits, `MC_samets`: keys carry the commit ID) fixed). Minor readings settled: R10, R13, M4–M7, M10 by spec edits stating what osis-node/osis-perm do; R11 by an earlier edit; R12 a modeling limit; R14, R15, M8, M9 decided by the text; S17 settled by a spec edit (a must-not-hold blob holds nothing; node-sync and the model follow). `run.sh small` after: 14 instances as expected.
- TLC is tier 3, not part of the merge gate. `models/tla/run.sh small|all [filter]` downloads the jar to `~/.cache/tla` if missing and runs the listed instances with 1 worker (`TLC_WORKERS` overrides); `small` (about two minutes) is `sync/deposit`, `sync/mostabs`, `rotation/MC_live`, `MC_grant`, `MC_plant`, `MC_safety`, `MC_fork`, `membership/MC_core`, `MC_multi` and the membership expected failures; `all` adds instances of up to about 20 minutes each, run by hand. Instances that reproduce an open finding (`MC_drop_refresh`, membership `MC_sticky`, `MC_sticky_snap`) and the negative control `MC_keepoff` are listed in the script as expected failures: the script exits non-zero on any other violation, on an expected failure that passes (update the docs), or on a TLC error.
- **Not covered by the TLA+ models**: several labels or servers, projections and certificate copies, retagging, parked bodies and unfetched pages, clock skew, range reconciliation details, delete levels, `nobody`/`admin`/`author` purge rights, nodes offline past `MEMBERSHIP_KEEP`, connections and timeouts, signals; write and admin rotation, keysets and departures inside a member, demotion and `until` in rotation, step-tree branches, steps without rotation, entry boxes and key actors, `/label` and `/secrets` compaction (so snapshot-established epochs), the stale-view carrier race; in the membership model invites and links, read-level tenures, a second snapshot, more than two things, and epoch-start rounds and exclusions (one snapshot is made the start at a time and judged in its own settled walk). The models are oracles for the spec, never patched to match code; a spec change that touches their sections updates and re-runs them.
- **Method for a new TLA+ target**: a fresh agent given spec/ and the target's sections only (never notes/ or code) writes the model under `models/tla/<target>/` with a README (instances, results, times), an assumptions list and an ambiguity list (the findings); crypto is access (secrets as set membership, boxes as edges); 2–3 nodes, 1–2 servers, tiny bounds, symmetry sets; safety as invariants, liveness under weak fairness of honest steps; each property cites its spec sentence. Findings go to spec first, then the model is updated to the fixed text and rerun. TLA+ when notation independence matters and the state is small; stateright when an actor-shaped model would also serve the simulator.

## Conformance vectors (vectors/, crate osis-vectors)
- Format, subjects and rule IDs: vectors/README.md (language-neutral, ships with the spec). `.vec` text files of `key: value` records; every case has `case` and `spec`; `pending: <reason>` marks a case not yet checked.
- `vectors/MANIFEST` lists every required file (subjects: vectors/README.md): `pending` (crate not landed), `provisional`, or `frozen <blake3> <FC-n>`. **Nothing is frozen before the first stable release (owner): no format-change log is kept until then.** The freeze tooling stays for the release: a frozen file then changes only with a `## FC-n` entry in vectors/FORMAT_CHANGES.md naming it and `gen-vectors freeze <path> FC-n`; the `manifest_policy` test enforces this.
- Generated files (all but `cbor/` and `padme/`) must equal a fresh `cargo run --bin gen-vectors`; hand-written files have a checker that re-derives each case. Fixed inputs: seeds are 32 repeated bytes, randomness injected (each generator in `vectors/src/subjects/` states its inputs).
- State (MANIFEST is the source): all provisional. `cbor/values.vec` and `padme/padme.vec` are hand-written; `tid/thing.vec` and `chunker/gear.vec` boundaries were cross-checked by an independent Python implementation. Still waiting on owner calls: `blob/blobs.vec` (the commit blob case), `inbox/inbox.vec`.

## Fuzzing (fuzz/, outside the workspace)
fuzz/README.md: running, the target table (live and planned per crate), crash handling. Seeds come from the vectors via `gen-vectors corpus` (osis-vectors `corpus.rs`). Nightly fuzzes every target `cargo fuzz list` prints for `fuzz_seconds` (default 300). Never commit `fuzz/artifacts/` or run output; corpora stay small.
- Hardening panic audit: all 15 targets 120 s each (`-max_total_time=120`, two at a time on a shared 4-core box), no crash, leak or timeout; 0.2–27 M executions per target (slowest `box` 0.2 M, `schema_dsl` 0.34 M, `bundle` 0.46 M). `delta` and `box` were added then; still planned: `join` (needs `arbitrary`) and `page`. `cargo clippy --workspace --all-targets -- -D warnings` is clean, so the workspace deny of `unwrap_used`, `expect_used`, `panic` and `indexing_slicing` holds in every library crate (allowed only in tests, the cli binary crate, and two commented one-line exceptions: the chunker's u8 index into its 256-entry table, a whole-slice zeroize). Casts on peer numbers checked by hand: every `as usize`/`as u32` in decoders widens (frame lengths, u32 record fields, u8 table indices) or narrows a bounded local length; fuzzing runs with overflow checks on.

## Simulator (sim/, crate osis-sim)
- Shape: `Sim::new(name, seed, Config)` boots `nodes` real engines, each over its own `MemoryBackend` + `MemoryRoot` sharing one `osis_store::Faults` plan, a `ManualClock` and a seeded rng; all randomness comes from one `Dice` seeded by the run seed. `Config`: per-node `ClockSpec { skew_ms, drift_ppm }` (wall = T0 + elapsed + skew + elapsed·drift/10^6), `NetFaults { drop_pct, dup_pct, max_delay_ms, reorder }`, scheduler `Weights { write, gossip, deliver, tick, crash, restart }`, `max_tick_ms`, `check_every_step`.
- `step()` picks one event: a random write (1–3 random ops of `workload`, a schema with one aspect per encoding, on things in `sim.things` the node may write), gossip (node → random peer: packages of every applied commit the receiver lacks — an oracle standing in for reconciliation until node-sync's `SyncEngine`; each through drop/dup/delay), delivery of a due message (earliest, or any under reorder; to a down node it is lost), a tick (time passes, clocks set, `Engine::tick`), a crash (immediate, or at one of the node's next durable writes via `Faults::at(n, Crash)`: mid-write), a restart (`Peer::restart` over the same backend). `run(n)`, `run_until_quiescent(max_rounds)` (no new writes or crashes, every node up, everything delivered, pairwise sync without faults, time advanced 10 min at a time while commits pend). Setup helpers: `create_thing`, `grant`, `revoke`, `commit`, `deliver`, `sync_all`, `advance`, `set_clock`, `read`, `engine`.
- Invariants (`check`): per step, every group of up nodes holding the same applied commits reads the same values (every stored aspect); per applied event, own `ts` strictly increasing across restarts and within `MAX_DRIFT` (+1 ms) of the wall clock, no remote commit applied more than `MAX_DRIFT` ahead, no node-form counter range of one author overlapping another commit's on one aspect; at quiescence, every node holds the same commits and nothing pends. Engine errors on honest input (BadInput on an honest package, any error on a node not crashed) and panics (caught per run) are failures.
- Failures carry scenario, seed, step and the last 40 trace lines, and print `osis_sim::replay("<scenario>", <seed>)`, which reruns it exactly (a test checks a run twice gives the same `Report`, digest included). A failing sweep seed becomes a tier-1 test with a one-line description.
- Scenarios (`SCENARIOS`): `two_devices` (person actor owned by device 0, device 1 admin, a data thing the person owns), `three_random` (two shared things, all faults, skew ±5 min, drift ±200 ppm), `crash_restart` (plus crashes), `drift_parks` (a node jumps 2 h ahead: its commit pends with `Drift`, unread, until the receiver's clock is within `MAX_DRIFT`), `revoke_while_writing` (a writer removed while writing). Tier 1 runs seed 1 of two_devices, three_random and drift_parks, the others are tier 2; `OSIS_SIM_SEEDS=N [OSIS_SIM_ONLY=a,b] cargo test --release --workspace sweep -- --ignored` is a small sweep (every unblocked scenario, or the named ones); the nightly one is `sim-sweep` (Phase C).

### API world (sim/src/world.rs)
`World`: `osis::Osis` handles on `Runtime::Manual` and osis-server `Hub`s over in-memory queues under one `ManualClock` (the pattern of crates/osis/tests/it/common/world.rs, which the osis crate keeps its own copy of): `add_server`, `cfg`/`person`, `run`, `advance`, `until(future, step, n)`, `set_online` (offline databases still tick), `traffic` (bytes per database) and `start_tally`/`tally` (upstream frames by message kind), `max_pump` (storm bound). The example apps' e2e tests use it (notes/testing.md).

### Phase B: sync engines and blind servers (sim/src/net)
- `NetSim::new(name, seed, NetConfig)`; `add_server` (osis-server `Hub` over `BackendStore<MemoryBackend>` with its own `Faults`, true time), `replicate(a, b)` (servers dial each other: `Hub::peer_up` on the dialer, `accept` with the dialer's static key on the other, for echo suppression), `add_node(servers, ClockSpec)` (`SyncEngine` over an `Engine` on `MemoryBackend`+`MemoryRoot` sharing a `Faults`, its own skewed `ManualClock`). Actions are carried engine to engine: `Dial` makes a link (or a `Down` if the server is down or the pair blocked), `Send` queues bytes on the stream, `Close` drops it, `Wake` is fired when the node's clock reaches it; hub outputs the same way. Connections are ordered byte streams: `LinkFaults { cut_pct, dup_pct, max_delay_ms, reorder }`: a lost message cuts its connection (both ends told), delays keep per-stream order, reorder picks any due stream head, duplication repeats a message (a protocol violation the receiver must survive).
- Scheduler (`NetWeights`): write (random ops on `groups[..].items` the node may write), deliver, tick (time, wakes, hub ticks when `next_due`, server redials), node crash (now or at a durable write) and restart over its store, server crash (now or mid-write) and restart, partition / heal of a (node, server) or (server, server) pair. Also `sever` (a pair never connects), `wipe_server` (data loss), `lose_disk` (node gone for good), `reconnect_all`. Setup is calm (no faults): flows helpers `person`, `pair` (card direct, `Engine::pair`, `take_direct` delivered, `paired`), `introduce` (cards direct), `group` (+ `create_label`), `grant`, `remove` (demotion), `item`, `carry` (`carry_out` + direct packages), `quiet(max)` (settle until idle and unchanged); `run(n)` turns faults on, `run_until_quiescent(max)` heals, restarts everything, settles a resync interval (61 s) at a time until idle and unchanged for two rounds, then checks.
- Quiescent invariants (`net/check.rs`): convergence by held deltas (projections: two nodes holding the same deltas of an aspect read it the same); nothing pends; member liveness (every device of a person on an admin's roster, or of the owner, reads the group) and agreement (they read the same items); per server and label: no live entry tombstoned or back after a tombstone, every body a writer judges must-hold (`SyncEngine::verdicts`, the pass's own judgment) in a live entry (a known blob of that commit with a superset of the parts; `known` maps blob IDs to commits from nodes' `entries`), no entry a node may delete as must-not-hold still live, deposited entries promoted by writers that applied them; purged bodies at no server and no honest node (`holds_blob`); state size (spec/requirements.md Scale): a node's stored bytes (its `MemoryBackend` dump) ≤ 2 × must + 2 KiB × entries + 16 KiB × labels + 64 KiB, where must and entries are the bytes and count of the live entries of its labels at the fullest honest server (never its own holdings, so junk or pending commits raise no bound; `net/check.rs` `STATE_*`; release sweep of seeds 0..3 of every scenario: nodes stored at most 2.11x must and 0.47 of the bound; each node's numbers are trace lines); no ping-pong (three more resync rounds add or delete nothing). A run that never settles reports the churn (what the rounds added/deleted, with commits and aspects); a settle of more than 5000 deliveries is a message storm. Phase A's per-event checks (HLC, counters) run on every node. `OSIS_SIM_TRACE=1` prints every trace line with the proto messages.

## Arrival-order differential (osis-node `tests/it/order.rs`)
Validity, un-merge and state must be functions of the held set (spec/requirements.md Decentralization). Random histories on three `LocalPeer`s (0 owns G, 1 writes, 2 admin): content writes on every encoding including writes inside map entries, struct fields and texts in map entries, grants and re-grants, demotions (removal or to read) with frontiers before, inside and after the member's writes, self-removals, roster and compaction snapshots, things created under things in later commits, `Nested` (one peer puts an entry, another, sent it alone, writes inside and maybe compacts), undo, expiry (`/t/brief`, hours pass), partial syncs and single sends. Every commit made is a package; held sets are the whole set plus partial ones (alternately without one writer's commits after the setup, as a node that never heard from it, and a random two thirds). Each held set goes to fresh nodes (one seed, one clock) in several orders: as made (the reference), reversed, every order after the setup when the whole set is held and small, random shuffles. Compared as text: the index digest without `held` lines (per-commit verdicts, invalid parts, carried writes, member keys, ...), reads and states of every aspect, rosters, pending reasons, timelines (as held and from scratch); the reference must also equal itself after a reopen and after a rebuild (each then re-examined, as an open does). A failure is shrunk by dropping steps and printed as a `vec![..]` of steps for `check(seed, &steps, ..)`. Tier 1 `arrival_order_alike_small_*` (4 seeds of 8 steps, all orders of up to 4 commits, 2 shuffles, 1 partial set: about 3 s; plus the found histories); tier 2 `arrival_order_alike_large_*` (60 seeds of 60 steps, 8 shuffles, 4 partial sets). `OSIS_ORDER_SEED`, `OSIS_ORDER_SEEDS`, `OSIS_ORDER_LEN` narrow or widen a run; `OSIS_ORDER_STATS=1` prints per held set how many commits have an invalid part and how many carried groups hold invalid writes (without partial sets almost none did: carried invalid writes need a node lacking their commit).
Compared per body too: first and last deaths and liveness of keep-at-most bodies (every body with `OSIS_ORDER_DEATHS=1`: issues/deaths-arrival-order.md). Fresh nodes save every walk (`set_walk_cache_min(1)`), every order is also reopened, and each partial set followed by the rest (both ways) must end where the whole set does. A new step shape: a `Step` variant, its arm in `play` (ignore refusals; return the acting peer so its commits are collected), and a weight in `random_step`.
Found and fixed: `member_keys` took the first held record of a `/members` entry as its base, so an edge change by structural diff arriving before its grant kept a partial base (now an edge change is remove + put and a nested `/members` write bad input, `edge_change_is_remove_and_put_spec_perm_2`); carried groups listed in arrival order; a snapshot carrying an invalid entry creation after another's write nested in that entry had joined (`entry_created_after_demotion_write_first_spec_perm_5_1`, `arrival_order_found_histories_spec_crdt_4_6`); an open left unresolved an edge write `ts`-ordered before the record it needs (another node's clock), which a fresh apply had resolved (same test, seed 1558).

## Spec-to-test map

## Conventions for every crate
- **Spec citations**: put `// spec/<file>.md §N[.M]: <what>` right above each `#[test]` (inside `proptest!` too); a bare `§N` refers to the last file named in that comment. A test without its own citation inherits the file's `//!` header citations. Infrastructure tests with no spec section say `// spec: none (<why>)`.
- **Network in tests**: tier 1 uses `osis_transport::{Net, Sched}` (in-process, virtual steps, seeded faults and scheduling; no tokio); real-socket tests (QUIC on localhost) are tier 2.
- **Tiers**: tier-2 tests are `#[ignore]` (optionally also gated on `OSIS_SLOW=1`); a crate's tier 1 stays under about 10 s.

- **Budgets and benches**: in osis-bench as above; a new external dependency for them needs its line in notes/architecture.md §5.

## Build hygiene
cargo never deletes artifacts, and every new combination of `-p` subset, features, env or flags compiles and keeps another copy of the affected crates and everything above them. These are the only command forms (older result records below and elsewhere may name `-p` runs).
- **Debug, tier 1**: `cargo test --workspace` (`--no-run` to build; narrow with `--test <name>` and name filters, never `-p`). `cargo build --workspace --all-targets` and `cargo run --bin gen-vectors` (no `-p`) reuse its artifacts.
- **Lint**: `cargo clippy --workspace --all-targets -- -D warnings` (the tests' features, no `--all-features`) and `cargo clippy-net -- -D warnings` (alias: release, the networking features below; a small check-only set, about 0.3 GB and 18 s cold, sharing test-net's build scripts and proc macros).
- **Release, tier 2**: `cargo test --release --workspace -- --ignored [filters]`; sim sweeps `cargo run --release --bin sim-sweep -- ...` (no `-p`: it reuses tier 2's artifacts; `-p osis-sim` recompiled 35 crates).
- **Networking tier 2** (QUIC, iroh, LAN, relay): only `cargo test-net -- --ignored [filters]` (alias in .cargo/config.toml: release, workspace, `osis/lan,osis-node/quic,osis-node/relay`, the superset every such test needs). A second release set: about 2 GB, 20+ min cold on a loaded box. Enabling these features in every dev build was measured at +157 s and +13 GB on a cold debug build, so they stay opt-in; never pass another `--features` combination.
- **Never per command**: `-p`, `CARGO_INCREMENTAL` (`incremental = false` is in .cargo/config.toml; one build without the old per-command `CARGO_INCREMENTAL=0` added 8 GB in 28 s), `RUSTFLAGS`, `CARGO_TARGET_DIR`.
- **Merge gate**: `tools/gate.sh` runs it in order, failing fast, and ends with a sweep of the build dir (fresh artifacts, so it compiles nothing and only stale ones go) (`--sweep-seeds N` sets the sim sweep's seeds, 0 skips it): `cargo build --workspace --all-targets --locked`, `cargo test --workspace --locked`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, `cargo clippy-net --locked -- -D warnings`, `python3 tools/policy.py`, `python3 tools/spec_map.py --uncited` and `--gaps`, `cargo deny check`; changes in osis-node, osis-perm, osis-commit or osis-crdt add `cargo run --release --locked --bin sim-sweep -- --seeds 30 --budget-secs 900`. Repeating the sequence (with `cargo test-net --no-run`) compiles nothing; with one test binary per crate it leaves 5.3 GB after a sweep (debug 3.0, release with test-net and clippy-net 2.3); the old forms and binaries reached 15-26 GB.
- **Worktrees**: each checkout builds into its own in-tree `target/` (cargo's default). Never share a target dir between checkouts: cargo hashes path crates by workspace-relative path, so they overwrite each other's artifacts. Once per clone: `git config core.hooksPath .githooks`; `git worktree add` then runs `tools/seed-target.py`, which seeds the new `target/` from the main checkout's (dependencies hardlinked, path crates left to build; same filesystem only; measured: seed 15 s, first `cargo test --workspace --no-run` 34 s vs 76 s cold, the path crates' test binaries then about 8.5 GB, before one binary per crate). For a worktree made otherwise, run `python3 tools/seed-target.py` in it before the first build. Remove finished worktrees with `git worktree remove` (their `target/` goes with them).
- **Sweep**: `tools/sweep.sh [--dry-run]` (tools/sweep-target.py plus both clippy runs and, if built, `test-net`) deletes every artifact no canonical command uses. `tools/gate.sh` ends with it; run it by hand after toolchain, profile or dependency changes.
- **Targets**: `test = false` on bins and libs with no unit tests, `doctest = false` on libs with no doctests; `tools/policy.py` fails if such a target gains one.
