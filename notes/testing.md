# Testing
> Summary: How osis is tested and how to run each layer: principles, tiers and the reviewer set, what finds bugs, models, conformance vectors, fuzzing, the simulator, the arrival-order differential, seed runners, size budgets and scale checks (work counted at n and 10n), the forensic attack, policy checks, the spec-to-test map, conventions every crate follows, security reviews' checked-sound lists, performance budgets. Build commands and costs: notes/build.md.

Not built: a 10^4-seed sim sweep per scenario (a quiet 16-core box for about 6 h, `sim-sweep --seeds 10000`), GUI smoke tests of the app.

## Principles
- The spec is the oracle: every MUST has a test that fails without it, and every test cites the spec section it checks, so `grep` (or notes/testing-map.md) answers "what checks §X".
- Determinism: seeded randomness, injected clocks, in-process transport. A failure is a seed; a flake is a bug.
- Peer bytes never panic: every parser is fuzzed; decoders take limits.
- Models (core/test/crdt-model, core/test/roles-model, core/test/held-model, core/test/tla) are independent oracles; the implementation never depends on them and they are never patched to match it.

## What finds bugs
Over about 200 merged tasks: reading in review, audits and simplification passes found about 180 product bugs; a new targeted test or differential for the branch about 45; per-branch tier-2 oracles at default size (fresh offsets) about 25; larger ranges, periodic runs and wide sweeps 15-19; dogfooding about 10; tier 1 2; TLA none new. Re-running already-run ranges found about 4 (all regressions). Of the e3cdd005f periodic run's six bugs, three were per-branch-list gaps (a plain-size or deterministic tier-2 test no branch's list named) and three breadth-only. Of about 38 classified seed-found bugs, about 14 were slips against a clear rule and about 24 had no rule yet: the fix wrote a new spec sentence, a stated limit or a redesign. They clustered (arrival order × retention × validity, epochs and rotation, ephemeral), and each chase ended with a study that found one root shape, never with more seeds. Hence (notes/coordination.md): per-branch oracle sizes a tenth of full, breadth only in periodic runs, never rerun old ranges, one all-core run at a time per box, a study after the second seed fix in an area, and time spent on reviews that read, audits, dogfooding and targeted differentials.

## Tiers
Everything runs locally; there is no CI service.

| tier | what | how | when |
|---|---|---|---|
| 1 | unit, small proptest (`PROPTEST_CASES=32`), vectors | `cargo test` (about 6.5 min, 4700 CPU-s built, alone at load 15-20: Tier-1 cost); one area: `cargo test -p <crate> --test it <module>::[name]` | every gate |
| 2 | `#[ignore]` tests: properties at size, networking tests, by-hand checks | a branch's properties: `tools/test_select.py` (Reviewer set below); the whole set `OSIS_FULL=1 PROPTEST_CASES=256 cargo test -- --include-ignored --skip sweep --skip repro_ --skip _probe --skip judgment_vectors_write --skip memory:: --skip multi_gb_value_streams` as a periodic check; networking: `tools/heavy cargo test --tests -- --ignored driver:: runtime:: quic relay lan --skip repro_` | reviewers per branch; periodic |
| 3 | sim seed sweeps, fuzz, big model instances, TLC, benches, coverage, benches and memory checks (release, by hand) | the gate runs every sim scenario at 5 seeds for sim/engine/node/perm/crdt changes; the periodic checks below; the rest by hand | gate; periodic; by hand |

Sizes: a property's range or sample count below is its full size; a plain run takes a tenth (`osis_base::testenv::large`, at least one seed), the reviewer's size; `OSIS_FULL=1` runs the full size (periodic checks only); explicit `OSIS_*_START`/`_SEEDS` override both. A property that takes over 5 minutes alone at plain size on a quiet box gets an issue to be made shorter.

**Reviewer set** (`tools/test_select.py`): a branch's checks, computed from the paths it changed since its merge base with main. `tools/test_select.py` prints the selection and the commands; `tools/test_select.py --run` builds, then runs them under `tools/heavy` (all at plain size, on one random offset: every `OSIS_*_START` and the xor'ed `OSIS_CRDT_SEED`, `OSIS_PERM_SEED`). `--offset N` repeats one; `--paths P...` asks about paths without a diff.
- What it selects: every property test of the crates the paths touch and of their dependents in the Cargo graph (`cargo metadata`), and every sim scenario at 15 seeds (a tenth of a periodic sweep) if osis-sim is among them. A normal or build edge carries on to that crate's dependents; a dev edge selects the one crate and stops (a dev dependency reaches only its own crate's tests, so a change to held-model, roles-model or crdt-model selects the crates testing against it). A sim scenario belongs to no single crate, so a selected osis-sim runs them all.
- A property test is an `#[ignore]` test whose name ends in a size word, `_large`, `_tier2`, `_plain` or `_exhaustive`, before any `_spec_*` suffix; a `repro_` never is. Name a new one that way and it is selected; there is no list. The scan reads source lines, so an `#[ignore]` it cannot name (a macro's `fn $name`) is printed as `not read`, never dropped quietly. An `#[ignore]` test with no size word (a scripted tier-2 example, a real-socket, memory or budget test) is not in the set. Name a by-hand property `_by_hand`.
- Paths outside a crate: `Cargo.toml`, `Cargo.lock`, `.cargo/` and `rust-toolchain` select every crate; a `schema/*.osis` selects the crates whose Rust names that file, and their dependents; `notes/`, `spec/`, `issues/`, `docs/` and `tools/` select nothing, while `libs/kit/` and `app/` are crates like any other (with no `#[ignore]` tests; the gate's GUI steps test them). `core/test/tla/` selects nothing and says to run `core/test/tla/run.sh <module>`. Anything else selects nothing and is printed as not classified.
- A change to a crate low in the graph (osis-base, osis-crypto, osis-store, osis-crdt, osis-perm, osis-engine) selects nearly everything, and the tool says so. That is the graph's answer: don't trim it by hand.
- Not in the set, run by the branch that needs them: the networking tier 2 (the command in the table above, for a node sync, link or transport change), osis-cli `localhost::` (`cargo test -p osis-cli --test it -- --ignored localhost::`, 5 real-socket tests, about 2 min at load, not seeded, so any failure is a bug), osis-crdt `stream_memory_big_map` (alone, `--exact`: one child process per step), the sim `work_sets_match_full_passes` comparison (use `OSIS_SIM_SEEDS=2`), osis-node `ephemeral::many_authors_under_host_rates_by_hand` (a simulated minute of 10 authors: 12 min in dev). Scale is checked by counting work in tier 1 (Scale checks), never by timing.

**Periodic checks** (before a release, or one area's after a design step there; every tier-2 test with `OSIS_FULL=1` unless it names its own range; alone on the box, offsets drawn at random, notes/coordination.md): `cargo run --bin sim-sweep -- --seeds 150 --from <F> --budget-secs 3600`; `OSIS_FULL=1 OSIS_ORDER_START=<S> cargo test -p osis-node --test it -- --ignored order::held_set_decides_` (plain and exhaustive at 80 seeds each); `OSIS_PERM_SEED=<P> cargo test -p osis-perm`; `OSIS_CRDT_SEED=<C> cargo test -p osis-crdt -- --include-ignored --skip repro_ --skip hostile_moves --skip shrink_script`. Not TLC (Models below). Proptest's seed cannot be rotated.

**Rebuild check** (debug builds, `apply::atomic::check_rebuilt`, run by `Engine::run` before the index persists): after every transaction, each touched aspect's state must equal `rebuilt` (exactly the join of held bodies, leftovers among them, invalid writes removed, spec/crdt.md §4.6), compared encoded, creation chars §5.7 leaves to the node dropped from both. Every change but a valid join is that rebuild (issues/drop-rejoin-robust.md), so there it checks a fixpoint, and the incremental joins against it. Touched: an aspect where a held part's status (valid, dropped, missing) changed or a new part arrived not valid and whole, or whose state was written and no new commit names it, always; one only new valid whole parts joined, when its held commits pass a power of four in the transaction (a wrong state stays wrong, so a later sample still sees it; crossing, not landing on, so a batch arrival is not skipped). Invisible to the tests: costs are paused (`costs::paused`) and the state cache restored. A test hook writing a state no body gives sets `Core::unchecked_tx` (`damage_index`, `unindex::memory_state_row_follows_key`, the forged keys snapshot of `writer_snapshot_of_keys_invalid_spec_perm_5_2`). A failure panics with the differing Debug lines; a test it finds a bug in becomes `#[ignore] repro_...` naming the issue. Cost: about +16% of tier 1's CPU (every touched aspect at every commit would be about +40%), mostly `rebuilt` decoding commit records.

**Index check** (debug builds, `Engine::check_index`, run by `Engine::run` after a durable transaction commits; G2, notes/test-design.md): an open from the persisted index and a rebuild from the commit records, each into a fresh `Core` in a store transaction that is dropped, must give the running node's `index_digest` (held set included) and `perm_digest`; the open decodes no header and judges every part as held (`misjudged`), and its `node/edges` rows are what their records read (`apply::load`). So every test is an open-equals-rebuild test. Sampled: per open, counting the durable transactions that changed a state or a part (`check_rebuilt`'s `TxChange`), it runs when that count, or the count of those that changed more than valid joins, reaches a power of four (a wrong row stays wrong, so a later sample still sees it). Skipped after a transaction that left the index stale (`index::invalidate`: a forget; the reload follows). Its work is invisible to scale checks (`costs::paused`, `osis_perm::uncounted`). A test that edits an index in memory past the store sets `Engine::index_poked` (engine lib tests only). A reproducer whose point is one moment calls `check_index` there (`retention::uncovered_part_judged_anew`, `caches::crash_at_every_write_keeps_caches_exact`); the damage, crash and restore rules a check cannot reach are `caches::`. Cost: about 12% of osis-node `it` CPU by cpuprof (two loads per check, a third of it formatting digests and the rebuild's signature checks); at a power of two of both counts it was about twice that.

**Store-contents differential** (a refactor that must not change stored bytes or write order): seeded `LocalPeer`/`MemoryBackend` stores are byte-deterministic, rng-sealed rows included, once the persisted index tag is pinned (`index.rs` `VERSION` folds in `OSIS_INDEX_RULES`, a hash of the sources). Throwaway patch, applied to main and the branch alike: in `MemoryBackend::commit` fold each batch's ops into a running hash, and in a `Drop for Data` append `thread-name trace-hash final-hash batches rows` to `$OSIS_DUMP_FILE` (add `OSIS_DUMP_FILE` to core/base/testenv-known.txt, or the harnesses refuse it); set `VERSION` to a constant; run tier 1 plus the order oracles on each, sort, diff. About 12,400 stores. Tests that differ run to run on one build (crash, store, runtime, driver, cli, some notes/sync/encodings tests, `apply::tests_paged`'s three paged-snapshot tests, osis `api::created_reads_through_run_time_key_*`: async, OS randomness) differ between builds too; rerun those on one build to rule them out. A store dropped on another thread (`osis-dispatch`) moves its line to that name between runs: compare the lines without names too.

Integration tests are one binary per crate: `tests/it/main.rs` with a module per file (`tests/it/<module>.rs`; notes/architecture.md, Conventions), so a test's name is `<module>::<fn>`. Single-file crates (osis-base, osis-vectors, crdt-model) keep `tests/<file>.rs` (`--test cbor`, `--test vectors`, `--test props`). Nothing requires nextest, nightly or cargo-fuzz. Tier 1 never sleeps or touches the network. Tier 3 by hand: `cargo +nightly fuzz run --fuzz-dir . <target> -- -max_total_time=300` per target in `core/test/fuzz/` (crash inputs land in `core/test/fuzz/artifacts/`), `sim-sweep` (`--out <dir>` writes failing seeds), `cargo run --bin roles-model` plus `-- 2000000 joint|edges|disputes`, `-- 1000000 addenda` (4 min on 16 threads), `-- 0 addenda-exh` (11 min), `-- 1000000 epochs` (about 15 min), `-- 0 epochs-exh` (sizes and results in core/test/roles-model/README.md), `core/test/tla/run.sh <module>`, `cargo bench`, `cargo llvm-cov --lcov --output-path lcov.info`.

**Tier-1 cost** (main 5f1db6e1f, warm): `cargo test` about 13,000 G user instructions (3448 tests listed, ignored included); 4700 CPU-s and 380-390 s wall built, alone under the lock at load 15-20 (the gate's tier-1 step: 6.5 min held). Instruction counts are the measure to compare: a test's count repeats to under 0.1% run to run, its CPU-s by 20-40% and its wall more (load, SMT, clocks). By binary (G instructions): osis-node `it` 6560, osis `it` 3080, engine lib 1280, osis-sim `it` 430, held-model 350, chat 320; the rest under 300 together. 137 tests take over 5 CPU-s each and hold half the CPU; 12 take over 10 s alone (below). The run is CPU-bound, not tail-bound: each big binary keeps 13-15 of 16 cores busy to its end; the smaller ones (chat, held-model) end on one test for 9-10 s.

Only less work shortens it.
- In place: osis-crypto at `opt-level = 2` in dev; smaller data where the property is relative; tier 2 for sizes; a fill batch of 8 where a fill part way is the point (node `fill.rs` `SyncConfig::fill_batch`, osis `Knobs::fill_batch`); one setup copied per order where a test plays many orders from one start (`local_peer::Peer::fork`); debug cache cross-checks compared once per `Engine::point` (`Engine::recheck`: `labels_of`, `labels`, `inbox_candidates`, `inbox_actors`, `holders_named`, `head_keys`, `check_unchanged`, `vet_inbox_hints`), since a fresh read repeats itself until a commit, the indexes or the clock move; `LocalPeer::sync_all` stops after a round of duplicates (a fixpoint) and does not repeat a delivery that came back a duplicate and moved nothing; the forensic attack's last-byte key test (below). A test is a whole multi-node signed, encrypted sync, so 50-200 ms alone is the normal floor, not a slow test.
- Where osis-node `it`'s CPU goes (cpuprof over the binary, 8 threads; shares overlap): ingest 29%, node-sync passes 28%, `check_index` 16%, `order::check_orders` 14%, `check_rebuilt` 13%, `CommitBlob::decode_as` 15%, the forensic attack 6%. osis `it`: node-sync passes 69% (`judge_label` 26%, `ensure_rotated` from `usable_keys` 12%, `body_keeps` 12%), ingest 14%, the two debug checks 12%.
- Per test, every test: tier 1's binaries from `cargo test --no-run --message-format=json` (the `executable` of each test-profile artifact), each listed test (`--list`) run as its own process `--exact <name> --test-threads=1` from its package dir under `tools/icount`, with the child's rusage for CPU-s; 8 at a time takes about 8 min. The same against an older revision: a second worktree (`wt claim <name> <rev>`), its binaries run interleaved with the current ones, then compared by test name.
- Per-test times: run a test binary with `RUSTC_BOOTSTRAP=1 <binary> -Z unstable-options --report-time` from its package dir; CPU per test with `/usr/bin/time <binary> --exact <name>`. Where a test's CPU goes: `tools/cpuprof OUT <test binary> --exact <name>` (an LD_PRELOAD SIGPROF sampler: no perf or gdb here; inclusive and self shares per function); over a whole binary (`--test-threads=8`) it shows what all tests share. A test binary run outside cargo runs proptests at 256 cases: set `PROPTEST_CASES=32` as `.cargo/config.toml` does.

osis-crdt's seeded random tests (every `testutil::rng(seed)`, fixed-seed loops and proptest cases alike) sample other runs with `OSIS_CRDT_SEED=<n>`: a splitmix hash of n xor'ed into each run's seed; unset, the committed seeds. A panicking test prints the effective seed. `fuzz_seq::random_scripts_replay_spec_5_7` replays random `seq_ops` scripts the same way; `OSIS_SHRINK=<loop seed> cargo test -p osis-crdt --lib -- --ignored shrink_script` (with the same `OSIS_CRDT_SEED`) drops steps and ops of a failing one while it fails and prints it.

osis-perm's random runs (`differential`, `queries`, `incremental`) sample other histories with `OSIS_PERM_SEED=<n>`; each tier-2 run is `common::sharded`: 16 shards on scoped threads, shard i seeded `seed ^ i << 40` (fixed count, so a failing seed reproduces anywhere; the panic names the shard's seed). A shard runs only while it holds one of a process-wide pool of permits, a thread per core (`OSIS_PERM_THREADS` overrides), so the 15 concurrent tests keep about 16 busy threads instead of 240. `incremental::incremental_equals_from_scratch` takes its eight shapes in turn, so every size of at least eight samples reaches each, and asserts the counted paths (appended, placed, restored) are reached; tier 1 runs 16 samples, `_large` 8000 (plain 800: about 240 CPU-s at load 30).

How to replay a failing sim seed: `sim-sweep` prints `osis_sim::replay("<scenario>", <seed>)`; call it from a test (`cargo test -p osis-sim --test it`) then reduce it to a small reproducer of the broken property; never pin the seed (notes/coordination.md, Testing). `OSIS_SIM_TRACE=1` prints every trace line. A "read differently" failure ends with a divergence dump: per node, every commit naming the differing aspect with its part's status (dropped, missing, valid, covered by) and the aspect's state (`Engine::aspect_dump`).

What nothing covers: the scale properties with no counter (Scale checks), the TLA+ "Not covered" list, the not-built items above, QUIC and P2P tests over real sockets outside the networking tier 2 (Tiers above), browsers, real networks beyond localhost.

## Models (core/test/: crdt-model, roles-model, held-model, tla)
- `core/test/crdt-model` and `core/test/roles-model`: Rust reference models (notes/crdt.md, notes/permissions.md); the roles model's exhaustive tiers and random samples are tier 3.
- Roles model API (core/test/roles-model/src/lib.rs): per model `walk(h)` (pure), `random_hist`, `quiescent(h)` (each node's walk over the writes in its delivery order equals the canonical one; a search counter and a tier-1 test) and a `Display` trace; `shrink::shrink` reduces a failing history to a 1-minimal one (fewer writes, ops, nodes and actors, lower roles and edges, receipts dropped, times and commit IDs renumbered). The searches print counterexamples shrunk, as traces; osis-perm's differential runs print them as made (`OSIS_PERM_SHRINK=1` shrinks them). The joint walk's code follows §5.1 step by step. `roles-model -- N digest` hashes every verdict of N random histories per model (std `DefaultHasher`, stable within one toolchain); a refactor keeps it: at 1,000,000 joint e29ad7c11da132ca, edges d51880160a427893, edges-prov 609e565eb98bc3c8.
- `core/test/held-model`: what a node holding a body set reads, written from spec/ alone (history modes, purge, expiry, validity, apply), its values crdt-model fragments (join, prune, read, un-merge, strip, death, covering: one model of values, every encoding); the reference of `held_set_decides` (Held-set property, held-model comparison). Its AMBIGUITIES.md is the rule backlog. It models the retention design of issues/retention-modes.md (every drop a cover, purge or expiry); the comparison judges only what users observe.
- Differentials against models: crdt join, wire, strip and un-merge (osis-crdt `tests_model`, the one property test, notes/crdt.md Tests), the crdt decoder (osis-crdt `tests_decoder.rs`; notes/crdt.md, Reference model), perm (osis-perm `tests/it/differential.rs`: the walk, the walk under trust sets with its disputes against `roles_model::trust::side`, and layer 2 with addenda against `roles_model::addenda` (`addenda_model_agrees`, forged addenda included); the account epoch rule against `roles_model::epochs` at every observer and receipt prefix (`epochs::epochs_model_agrees`, `_large` 300,000 worlds at full size, about 50 s)).
- `core/test/tla/sync` and `core/test/tla/rotation`: TLA+ models written from spec/ alone, checked with TLC. Sync covers one label at one host: upload, download, deposit and promotion, deletes by delete key (blob-ID carrier tiebreak), expiry, compaction, purge on replace (the writer's cover), purge and rewrite, due snapshots, tombstones, offline nodes, a dropping/replaying/reordering host; properties: no live write leaves the label uncarried, must-hold bodies converge to the host, must-not-hold bodies and duplicates do not persist, entries settle, deposits get promoted, purges reach every node, holders end up holding a carrier for their live state. Rotation covers read-role rotation of one actor: established epochs, forced and eager rotation, forks, removal carried in its rotation, grants, registration steps after the rotation chain is uploaded, claims and claim-set drops, stranded heartbeats (also on a refused claim), re-seal after a complete pass (by inbox and under the label), rotation by inbox to holders without a box at the epoch before, per-node box knowledge, co-reader peers, and an adversary planting boxes (secrets from pending or invalid commits are reading-only); properties: no departed holder reads content written with its departure known, no departed holder holds an epoch that did not box it, nothing is encrypted under a planted secret (a negative control with the rule removed fails in 4 states), every current holder eventually opens every current epoch and reads everything. The rotation directory also holds Depth0.tla (depth-0 sealing of holder actors: seal, stale, merge, rule 4 and taint, possession, blocked, first admin), Finalize.tla (timed grants and finalizes), Cover.tla (which epochs cover a departure) and Lockout.tla (rotating needs only the right to rotate). Each README gives the instances with results, state counts and times; each AMBIGUITIES.md the findings.
- TLC is tier 3, not part of the merge gate and not periodic (models read no code, so rerunning an unchanged model finds nothing): the branch that edits a model or its spec sections runs its module, `core/test/tla/run.sh <module>` (`sync`, `sides`, `rotation`, `depth0`, `lockout`, `finalize`, `cover`; each under 3 min at one worker on a quiet box, `TLC_WORKERS` overrides). It downloads the jar to `~/.cache/tla` if missing. Each module checks its design's safety on every listed instance and liveness on one (fairness makes liveness 10-1000 times slower; sync and sides keep theirs, cheap there), and keeps one negative control (or an open finding) that must fail, so its checks are seen to bite; the script exits non-zero on any other result or a TLC error. Larger instances run by hand, by name (`run.sh <module> <cfg>...`); their README rows record their last run.
- `core/test/tla/sides`: a design exploration (notes/ at hand, not written from spec/ alone) of hosts during an admin dispute, nodes on two sides of one label, step 6 candidates as modes (notes/disputes-plan.md step 6); `matrix.sh` runs every scenario under every mode.
- **Not covered by the TLA+ models**: record edges removed by their own admins (their keys are Depth0's `D0_fa_*`), several labels or hosts, sections and certificate copies (but a grant of a holder actor held as its grant alone, rotation `MC_c3_proj`), retagging, parked bodies and unfetched pages, clock skew, range reconciliation details, delete levels, purge classes, nodes offline past `ROLE_KEEP`, connections and timeouts, signals; write and admin rotation, keysets and departures inside a holder, demotion and `until` in rotation, step-tree branches, steps without rotation, entry boxes and key actors, `label.0` and `secrets.0` compaction (so snapshot-established epochs), the stale-view carrier race. A spec change that touches their sections updates and re-runs them.
- **Method for a new TLA+ target**: a fresh agent given spec/ and the target's sections only (never notes/ or code) writes the model under `core/test/tla/<target>/` with a README (instances, results, times), an assumptions list and an ambiguity list (the findings); crypto is access (secrets as set membership, boxes as edges); 2–3 nodes, 1–2 hosts, tiny bounds, symmetry sets; safety as invariants, liveness under weak fairness of honest steps; each property cites its spec sentence. Findings go to spec first, then the model is updated to the fixed text and rerun. TLA+ when notation independence matters and the state is small; stateright when an actor-shaped model would also serve the simulator.

**Confidentiality over `LocalPeer`**: `Package`/`deliver`/`sync` hand over plaintext commits, so a peer that lost access still reads whatever it is sent: no "who can read" claim holds there. Such claims use the sealed mode: `LocalPeer::sealed` (rotates first as node-sync's `uncovered` does, then `Engine::seal_package`: each body sealed and wrapped under its reader's secret, none under an uncovered read role) and `deliver_sealed` (`Engine::open_package`, as node-sync opens an entry; retried while one opens). flows.rs `sealed_write` asserts a peer that does not read the write opened none of its bodies; `spread_sealed` is `spread` sealed. Plaintext stays right for pairing/setup and for tests of what an engine does with what arrives (order, validity). Inbox blobs are real either way (`carry`, `accept_inbox`).

## Conformance vectors (core/test/vectors/, crate osis-vectors)
- Format, subjects and rule IDs: core/test/vectors/README.md (language-neutral, ships with the spec). `.vec` text records of `key: value` lines; every case has `case` and `spec`; `pending: <reason>` marks a case not yet checked.
- Only `cbor/values.vec` and `padme/padme.vec` are files: hand-written, each with a checker that re-derives every case. Every other subject is a generator (`core/test/vectors/src/subjects/`, fixed inputs: seeds are 32 repeated bytes, randomness injected) run in memory by its test, so its asserts check the implementation; `crdt/deltas` also runs `crdt::check` on what it builds. `tid/thing` and `chunker/gear` boundaries were cross-checked by an independent Python implementation. Waiting on Tess's calls: `blob/blobs` (the pending commit blob case), `inbox` (its commit is a stand-in).
- No generated output is tracked (Tess): before the wire format is stable, a committed vector only compares the implementation with its own earlier output and gets regenerated on every change, so it detects nothing. The generators stay so a stable release can write files out to catch breakage.
- Judgment vectors (`judgment/`, format in core/test/vectors/README.md): a bundle of the labels' bodies and referenced blobs, the read secrets, the clock and an arrival order in; per body validity, held/dropped/missing, covering snapshots and deaths, rosters, D, state and read digests out. Generated in osis-node `tests/it/judgment.rs` (histories by `order::play`, all with seed 1038 so a file's bundles share one `setup` header); `judgment_vectors_spec_permissions_5_2` checks each generated file's shape (osis-vectors `judgment::check`) and replays it from its text through a fresh engine, about 3 s; `judgment_vectors_can_fail` (ignored) checks a changed verdict or shorter order fails. `models` plays the roles model's reference scenarios; `rules` one per family (frontier coverage, re-grant, cover drop and uncover, keep-at-most finality, un-merge, `until`, invite grant; `order::Step::Grant` makes `until`/invite grants, scripted only), then `bounds()` (dead purge-on-replace bodies dropped at one node and held at another, expired puts' value-less records). A file's header lists once the expected lines every case shares.

## Simulator (core/test/sim/, crate osis-sim)
- Shape: `Sim::new(name, seed, Config)` boots `nodes` real engines, each over its own `MemoryBackend` + `MemoryRoot` sharing one `osis_store::Faults` plan, a `ManualClock` and a seeded rng; all randomness comes from one `Dice` seeded by the run seed. `Config`: per-node `ClockSpec { skew_ms, drift_ppm }` (wall = T0 + elapsed + skew + elapsed·drift/10^6), `NetFaults { drop_pct, dup_pct, max_delay_ms, reorder }`, scheduler `Weights { write, gossip, deliver, tick, crash, restart }`, `max_tick_ms`, `check_every_step`.
- `step()` picks one event: a random write (1–3 random ops of `workload`, a schema with one aspect per encoding), gossip (node → random peer: packages of every applied commit the receiver lacks, an oracle standing in for reconciliation; each through drop/dup/delay), delivery of a due message (earliest, or any under reorder; to a down node it is lost), a tick, a crash (immediate, or at one of the node's next durable writes via `Faults::at(n, Crash)`), a restart (`Peer::restart` over the same backend). `run(n)`, `run_until_quiescent(max_rounds)`. Setup helpers: `create_thing`, `grant`, `revoke`, `commit`, `deliver`, `sync_all`, `advance`, `set_clock`, `read`, `engine`.
- Invariants (`check`): per step, every group of up nodes holding the same parts of the same applied commits reads the same values; per applied event, own `ts` strictly increasing across restarts and within `MAX_DRIFT` (+1 ms) of the wall clock, no remote commit applied more than `MAX_DRIFT` ahead, no counter range of one session overlapping another commit's on one aspect; at quiescence, every node holds the same parts and nothing pends. Engine errors on honest input and panics (caught per run) are failures.
- Failures carry scenario, seed, step and the last 40 trace lines, and print `osis_sim::replay("<scenario>", <seed>)`, which reruns it exactly. A failing sweep seed is reduced to a minimal reproducer, never pinned.
- Phase A scenarios: `two_nodes`, `three_random` (all faults, skew ±5 min, drift ±200 ppm), `crash_restart`, `drift_parks` (a node jumps 2 h ahead: its commit pends with `Drift` until the receiver's clock is within `MAX_DRIFT`; needs hand delivery), `revoke_while_writing`, `grant_to_group` (a grant to a group with its admin away, a later reader, a removal, then a grant of an unlabeled thing: `Engine::unrouted` until `create_label`, spec/sync.md §2-§3). `OSIS_SIM_SEEDS=N [OSIS_SIM_ONLY=a,b] cargo test sweep -- --ignored` is a small sweep.

### API world (core/test/sim/src/world.rs)
`World`: `osis::Osis` handles on `Runtime::Manual`, osis-host `Hub`s and peer links (Reachability model: `place`, `lan_announce`, `set_peer_reachable`, `set_relay_up`, `peer_routes`, `restart` over the same store) over in-memory queues under one `ManualClock` (`cfg_clocked`: a node on a clock of its own, skewed or drifting) (the osis crate's tests use it): `add_host`, `cfg`/`account`, `run`, `advance`, `until(future, step, n)` (panics if it does not resolve), `set_online` (offline nodes still tick), `diagnostics`/`trace`, `traffic` (bytes per node) and `start_tally`/`tally` (upstream frames by message kind); a storm (`STORM` rounds in one settle) panics naming what it carries.

### Reachability model (core/test/sim/src/reach.rs)
`Reach`: one model for both sims, not a packet machine. Each node has LAN segments and an uplink (public address, a NAT, none); `route(from, to, url, blocked)` is the best item of a `peer://` URL: a LAN address on a shared segment, the target's public address, a punch (`osis_transport::nat::punch_opens`, the rule `punch_by_nat_type` holds the packet machine to) or a relay both reach (a relay on the pair's own segment punches over the LAN). A relayed link ends with its relay, a punched one does not. The node's items are what the driver would list (public address and relays; a LAN address only comes from an announcement). Partitions are the caller's (`blocked`), so each sim keeps its own. A peer that cannot read stays a node's hub (`NetSim`'s `add_host`, `World::add_host`) until issues/net-one-peer.md.

### Phase B: sync engines and hosts (core/test/sim/src/net)
- `NetSim::new(name, seed, NetConfig)`; `add_peer` (osis-host `Hub` over `HostStore` on a `MemoryBackend` and `MemoryRoot` with their own `Faults`), `replicate(a, b)`, `add_node(hosts, ClockSpec)` (`SyncEngine` over an `Engine`, its own skewed `ManualClock`). Actions are carried engine to engine: `Dial` makes a link (or a `Down`), `Send` queues bytes on the stream, `Close` drops it, `Wake` is fired when the node's clock reaches it. `peer://` dials go through the Reachability model to the target's `SyncEngine::accept` (`listen_peer` publishes a node's `reach.0` and listens; `lan_announce`, droppable, `Action::Reach` relistens). Link faults, crashes and restarts apply to peer links as to any link. Connections are ordered byte streams: `LinkFaults { cut_pct, dup_pct, max_delay_ms }`, none looking at what is sent: each link direction releases at random moments of the network clock (keyed by link, direction and bucket; streams overtake each other, each keeps its order), a link is cut at keyed moments, what is on its way lost with it (both ends told), a release may arrive twice; compared runs (`with_arrivals`) deliver all that is due in a deliver step, any other run one message a step, so events and cuts fall inside a burst; only deliver steps move the network clock. Duplication repeats a message (a protocol violation the receiver must survive).
- Scheduler (`NetWeights`): write, deliver, tick (time, wakes, hub ticks, host redials), node crash (now or at a durable write) and restart, host crash and restart, partition / heal of a (node, host) or (host, host) pair. Also `sever`, `wipe_host` (data loss), `lose_disk`, `reconnect_all`. Setup is calm (no faults): flows helpers `person`, `pair`, `introduce`, `group` (+ `create_label`), `grant`, `remove`, `item`, `carry`, `quiet(max)`; `run(n)` turns faults on, `run_until_quiescent(max)` heals, restarts everything, settles a resync interval (61 s) at a time until idle and unchanged for two rounds, then checks.
- Quiescent invariants (`net/check.rs`): convergence by held deltas (two nodes holding the same deltas of an aspect read it the same); nothing pends; no certificate copy still waits (`SyncEngine::deferred`); holder liveness (every node of an account on an admin's roster the model keeps connected to the admin reads the group: `check::Connected`, every host a holder reaches, replication, peer routes between holders; another reader joins a part without bridging it; a holder cut off for good is left out and counted in `Report::unjudged`, and `finish` fails a run that left any: a scenario that cuts a holder off on purpose lists it in `excused`) and agreement (they read the same items, per connected part); per host and label: no live entry tombstoned or back after a tombstone, every body a writer judges must-hold (`SyncEngine::verdicts`, the pass's own judgment) in a live entry (a known blob of that commit with a superset of the parts), no entry a node may delete as must-not-hold still live, deposited entries promoted by writers that applied them; purged bodies at no host and no honest node (`holds_blob`); state size (spec/requirements.md Scale): a node's stored bytes ≤ 2 × must + 2 KiB × entries + 16 KiB × labels + 64 KiB, where must and entries are the bytes and count of the live entries of its labels at the fullest honest host, or of every commit made under a label no host names (`net/check.rs` `STATE_*`; measured at most 2.11x must and 0.47 of the bound); no ping-pong (three more resync rounds add or delete nothing). A run that never settles reports the churn; a settle of more than 5000 deliveries is a message storm. Phase A's per-event checks run on every node. `OSIS_SIM_TRACE=1` prints every trace line with the proto messages.
- Work sets against full passes (`core/test/sim/tests/it/work_sets.rs`, notes/node-sync-work-sets.md): `net::with_full_passes(f)` makes every node added in `f` judge everything at each pass (`SyncConfig::full_passes`); a scenario run both ways may differ in messages only (work sets may send no more, checked only between runs alike to the bit), with no tolerance on: the counters of faults and writes, when each upload, deposit and registration first reached each host (`net::with_arrivals`: a missed trigger shows as a later arrival) and when a delete took a host's last copy of a commit, and `Report::parts` (what each node and host ends up with: commits, reads, `SyncEngine::state_digest` with entries, presence, carriers, blob records and held bytes). Arrivals and parts name a blob by commit and parts, never by ID, and go by what, not under which label: an ID, wrap, salt, stamp, the log order inside a batch and which copy of a commit stays are the luck of which seal drew first from the node's random stream (`compared_runs_ignore_the_random_stream`); for the same reason a deposit's relay wait hashes its commit, not its ID. Compared runs do not drift (`add_node_with`): a clock corrected by pings would move with when they went. A parted run is a real difference: read its lines. A passing run writes its counts past the test's capture. `honest_flows_wait_for_no_resync` is the same comparison with no faults. `full_passes` is the new pass with everything in scope: the harness guards that the work sets miss no trigger, not that the judging helpers are right (the sweep's invariants do that). Tier 1: `work_sets_purge_on_replace` (scenario `purge_on_replace`, one seed); tier 2: every scenario at `OSIS_SIM_SEEDS` (20) from `OSIS_SIM_FROM` (0; `OSIS_SIM_ONLY` narrows): 1073 s for all at 100 seeds on 16 cores.
- Waivers (`NetSim::waivers`, constants in `net/mod.rs`) switch one invariant off for a scenario while its issue is open (none now); `excused` nodes (removed, lost) are left out of liveness, agreement and purge checks.
- Scenarios (`core/test/sim/src/net/scenarios.rs`; `osis_sim::SCENARIOS` lists every scenario): `two_nodes_host` (pairing, crashes mid-write), `three_accounts_two_hosts` (replication, grants by inbox, host crashes, partitions), `removed_writer` (removal, then a writer without the delete key purges the removed writer's body), `reader_relays` (writer severed from s1, a reader carries its stamped entries there), `stranded_reseal` (a node off past `ROLE_KEEP` across two rotations is refused, then re-paired), `host_loses_data` (writers re-register and re-upload), `offline_rotation` (a reader off across two removals walks the steps; removed holders hold no later epoch), replay exactness, `compaction` (two writers compact while writing; covered bodies deleted, then a purge), `grant_lost_on_crash`, `large_edits` (two nodes edit an 8 MiB blob in turn through a host; bytes sent per edit within 1.2x of the changed chunks plus the root node and 32 KiB), `no_host` (three holders with no host: one LAN, public addresses, relayed behind symmetric NATs or punched behind cone NATs, by seed), `no_host_chain` (two LANs joined only by a holder on both). A hostless label's state bound counts every commit made under it (`net/check.rs` `written`): an upper bound from what was written, since no host says what must be held.

### Phase C: scenario library, adversaries, version skew (core/test/sim/src/net/{library, adversary, skew, rogue}.rs)
- Library (setup by flows, a faulty `run` around the story's moment, the story's outcome, then the quiescent invariants): `revocation_bob`, `revocation_carol` (X and Y invalid at Alice and Carol; a re-grant restores those a host holds, `hosted_commits` from the hosts' live blobs), `demotion_synced` / `demotion_unsynced` (the pre-sync keeps the late edit; `Unsynced { proceed }` loses it), `link_redeem`, `link_race` (single use; the loser, rotated out of K, is excused), `chat_join_leave` (design E: participants write the chat itself; a removed one holds no later epoch), `team_reads_member_thing` (each member's own thing read by the team; a member removed from the team keeps writing its thing: the team holds its newest epoch; counting the node's own departure failed about 2% of seeds), `folders` (a folder actor, first admin of a subfolder shared separately), `label_replacement`, `label_replacement_offline` (the old label keeps role-class commits and certificates only), `bundles` (a label exported and imported by hand to a node cut off from hosts), `disappearing` (expiring notes under crashes: gone from nodes and hosts), `purge_on_replace` (replaced bodies gone after the bound), `concurrent_writers` (an admin, three writers and two readers granted at once: each body the admin wrote goes up once, by the admin; rarely a second upload by a lagging writer; `NetSim::count_uploads`). - Ephemeral (`net/ephemeral.rs`, scenarios `ephemeral`, `ephemeral_capped`): random ephemeral (map, string, an expiring flag, an expiring cursor keyed by node, `Put` like `osis::KeepAlive`) and signal writes on windows placed ephemerally in a group and on a durable item; faults add slow hosts (`NetWeights.slow`) and per-host caps (`add_host_with`: `ephemeral_capped` and odd `ephemeral` seeds give s0 a random cap: 0, below one snapshot, about the snapshots, twice them, plenty). `ephemeral::check` (in `quiescent`, first), the defined outcome past a cap made exact: a host is "lossy" when it lacks an entry an up node holds and cannot fit it (`ephemeral_fits`) while every plain entry it keeps is held by some up node; holders connected through non-lossy hosts read durable items' ephemeral state alike; a window synced by all of such a group or none; holders equal, expired flags and cursors absent; each up node's held commits within `COVER_FACTOR` times their cover plus one commit; host ephemeral charge within its cap and total. Signals: at most once per node over the run. After quiescence: `author_leaves` and `signal_reaches` (exactly once at every holder sharing a host with the sender). The durable checks skip `e:` aspects. Trace: `held_detail`.
- Adversaries: hand-driven `ClientSession`s straight into a `Hub` (`NetSim::rogue(s)`, `rogue_do(r, Command) -> events`, `rogue_raw`, `rogue_close`; `label_keys(n, s, g)`). `evil_host` (`NetHost.evil = Evil { drop_pct, hold_pct, replay_pct }`; `NetSim::dishonest` hosts are skipped by the label checks), `evil_host_drops`, `removed_replayer` (stale step refused, purged blob not back, post-removal write never read; colluding with the host, its secrets open no body written after its author held the removal), `malformed_blobs`, `deposit_flood` (bounded by the deposit budget), `equivocating_writer` (a writer's key signs a second commit reusing its counters on one aspect: every node holds both and reads neither; `NetSim::equivocation` exempts it from the honest-counter check), `tombstone_liar` (after a purge the host re-announces the purged entries, `NetSim::host_says`: no node takes the body back or re-uploads it). Expected outcomes are in each doc comment. A stolen pairing offer is out of scope (osis crate tests).
- Version skew: `future_format` (a commit rewritten to `FORMAT_VERSION + 1`: parked everywhere, `NetSim::parked_ok`, relayed, kept through an old writer's compaction), `newer_schema` (version 2 adds a struct field with a default and an aspect; the old node's write and compaction keep both).

Known-failing repros of open issues (any crate) are named `repro_*` with `#[ignore = "issues/<name>.md"]`; every `--include-ignored` periodic command adds `--skip repro_`, and the fix renames the test (or un-ignores it).

## Held-set property (osis-node `tests/it/order.rs`, `held_set_decides`)
Property: what a node shows is a function of the commits it holds (spec/requirements.md Deterministic). One test, one generator, sizes as a knob; each node is judged against the node holding the same commits and keeping every body, and against held-model, so orders agree because each node equals them.
- **Generator** (`generate`): random histories on three `LocalPeer`s (0 is G's first admin, 1 writes, 2 admin). Seven feature groups, each drawing from its own rng stream so a change to one leaves the others' steps as they were: general (`random_step`: content writes on every encoding, typed and untyped, inside map entries, struct fields and nested texts; grants, demotions with frontiers before, inside and after the holder's writes, self-removals, compactions, things made under things, `Nested`, undo, expiry, hostile `Forged` commits, `NewTop`, syncs, sends, clock steps), purges (messages, signals, purges by name, wide and by author), keeps (keep-at-least after replaced and until T, `retention_of`), required retention (`Require`, `Breaking`), record-only things (`RecordOnly`, `GrantFlow`, `RemoveFlow`), sequences (expiring list elements, texts, `Old` writers predating the undo expiry rule) and parts (`Mixed` two-body commits, commits on two things, `TwoEdges`, `BadPart`, `BigDemote`, compactions). Steps are `Step::Aim`ed at an author and thing that can write them (`aim`). The seed picks an emphasis (`Emphasis`, seed % 8: purges, keeps, required, record-only, lists, parts away, settled, addenda): its group's share five times, a start that reaches its outcome (a fallen and a broken required setting, a first admin's record edge removed, a replaced register kept until T and compacted, purges by name and author, Bob's write vouched for by an addendum, two two-part commits by G's first admin and its snapshots covering them, given to every peer), and for the last three the whole history: parts away (`Cfg::away`: fresh nodes sync things and hold the first multi-part commit and half the rest in part for good, `with_syncs`, and the whole set is also given without what its snapshots cover, `covered_away`), settled (`settled`: every writer compacts every aspect last), addenda (the writers answer removals, `play_with`; the fresh nodes judging never do). Other seeds sync by `seed % 3` (`with_syncs`). Every history ends in `Removals` (its own stream; last, so the exhaustive cap keeps random prefixes): on a new thing of one writer's own, one aspect per commit (no part withheld), it deletes a list element and chars, another writer later and without the delete writes into that element (hidden above its reset) and removes a present tag, and the first undoes its deletes (chars undeleted, the element's value inserted again).
- **Orders** (`ORDERS`, one config): held sets are the whole set, a first sync part way (half and three quarters), and partial sets (without one writer's commits, a random two thirds). Each held set goes to fresh nodes as made, reversed, as fetched (`fill_order`), every order after the setup when the whole set is small, shuffles; two orders again with late parts (`deliver_split`) and two in part at an earlier clock (`clock_of`: just after or before the prefix's last `ts`, up to an hour after, or from an hour before the first commit, so drift parks; then the clock moves to the end). A partial set then the rest ends as the whole set's node. The whole set's first two orders are also delivered reopening after every ingest (`reopens_alike`: two nodes under test, no excuse). Sizes (`Size`): `quick` (tier 1: seeds 0..8 of 32 steps, and 100..108 capped to 4 commits after the setup in every order of every held set; no environment), `plain` (80 seeds of 60 steps at `OSIS_FULL=1`, a tenth by default), `exhaustive` (80 seeds capped at 6 commits, every order of every held set, all with late parts, 24 clocked, a seed's orders on a thread each). `OSIS_ORDER_START`, `_SEEDS`, `_SEED` (one seed alone), `_LEN`, `_CLOCK` set a tier-2 run; `OSIS_ORDER_SHRINK=1` shrinks each failure (a check per dropped step, slow); `OSIS_ORDER_STATS=1` prints each history and the tallies; `OSIS_ORDER_DUMP=1` prints a failing order's packs and reads as they change (`dump_order`).
- **Oracle** (`node_checks`): from the API only (`shown`): every aspect's read (or error) and every thing's roster, now and two hours later (every bound and expiry past), after the node's sync exchange (`fetch_missing`: every held commit the node itself counts a part of missing comes again from the history's packs, as node-sync's refetch; a node that fails to count a body missing never gets it back). The one excuse, from the history: an aspect a part may have waited at its expiry on (`waited_at_expiry`). Before the exchange a node may rightly show less (Deterministic's limits), so the pre-exchange view is compared only in settled histories, on the aspects some writer compacted last (`Played::settled_last`; rosters always), and every order of a settled history delivers its compactions last, as made (`Played::settle_from`): a compaction dropped while it did not count (received before the role commits that make it valid) repairs nothing (`compaction_dropped_while_invalid_repairs_nothing`). Every delivered node takes the walk's side in each dispute it detected before every judgment, held-model's after every ingest included (`deliver_with`): its default side is first received and held-model has no trust set. Also per node: P3 `value_past_end` before and after the exchange, the permission index against its walk from scratch (`perm_digest`), held-model (below), and every plain order judged anew alike after a reopen (`misjudged`). Which bodies a node holds, states, pending sets and death dates are its own and compared nowhere: **a seed where bodies or states differ but what nodes show agrees is not an issue.**
- **Coverage tally** (`Seen::floors`, derived from the run's size): every run judged nodes against both references; each emphasis that ran outside the exhaustive cap reached its outcome; a run with every emphasis reached a commit of every step kind, half the commit steps committing, an invalid part, a waiting commit, a signal judged by held-model, a clock move that changed something, purged or expired deltas judged, a reopen after every ingest and a sync exchange bringing content back. Every emphasis's seeds reach, as held-model judged them (`held::REMOVALS`), a list element reset, a list write above its reset, a winning text undelete and a set value removed.
- **Cost** (load 15-40): tier 1 95-110 CPU-s (10-14 s wall); plain (8 seeds) 85-220 CPU-s; exhaustive (8 seeds) 530-790 CPU-s.
- **Scripted examples** beside it are minimal reproducers in named orders (`NAMED`: as made, reversed, as fetched; or explicit ones), each naming the rule it pins; open issues' replays are `repro_*` (`WIDE`: the long-history order counts their seeds were found with).

**held-model comparison** (`tests/it/held.rs`, `Cfg::model`): every node `held_set_decides` judges (now and later, before its exchange, and after every ingest of its clocked deliveries) is also converted into held-model's input and compared on in-scope aspects, on what a user observes only: applied commits (role commits too), validity, which edge writes apply, every known thing's roster (`roles.0` as read: edges alive now, `tied` dropped), reads, no forbidden value held, no purge-on-replace body held that a right holder's held snapshot covers (the purge-on-replace promise, internal like P3), and promised history: every body the node dropped whose keep-at-least bound is an absolute time still ahead (kept until T, or for good), given back from the keep-everything `Oracle::bodies`, is one the model lets go. Which other bodies are held, and death dates, are not compared; keep for D's dating rule is checked by the scripted `held::keep_for_d` (`kept_snapshot_replaced_at_latest_death_any_order`, `kept_text_snapshot_replaced_at_the_re_delete`, named orders). Every difference is tallied by kind (`Coverage::differs`); the first fails the test. Input: every held commit and known creation record, undo, acting, invites, `until`, self-removals, finalizes, `required^.0` and addenda as the node's role input holds them (`ix.held`; an addendum's entries from its held body, a stripped one listing nothing); author ids in tid order; bodies as crdt-model fragments decoded from the engine's wire bytes, every header's dot form and counter ranges as `Held::dots`; reads compared as values by their canonical bytes; wire retention as the model's history mode (purge on replace is `PurgeOnReplace`, keep history is keep-at-least, none given convenient); a body dropped for its bounds is fed as missing, one dropped as covered as `Body::Dropped(cover)`. Scope: every content aspect (`core_types::is_content`), of every encoding; the coverage tally counts the compared aspects by each encoding their model state holds at any depth (quick: register, struct, map, text, list, set; counters at plain). Left out, counted by reason: paged, ephemeral, waits for blobs or parked, a part that may have waited at its expiry, the node's own writes from outside the history (never parked where the harness sets the clock back before them), and every aspect when the role input is outside the model (a role-class snapshot, a role frontier not inline, a role commit outside the model as above). A role commit's parts off `roles.0` (`keys.0`, `secrets.0`, `label.0`, `created.0`) change no role and are placeholders. Missing parts, and parts waiting alone in an applied commit, are fed as missing. Not compared as reads: `keys.0`, `secrets.0`, `label.0` (no crypto or labels in the model), `created.0` (the records are the model's input), `required^.0` and `addenda.0` (the model takes them as rules and entries, not fragments: issues/held-model-setting-reads.md). Sabotage at `quick` (each in every quick seed, through held-model): reversed list reads; a held text delete beating a later undelete (`seq.rs` `join_flag`); a list element shown above its reset (`is_visible`); a set element's content kept under its own reset (the reopen check sees the non-canonical state first); a roster showing write as read.

## Rotation property (osis-engine `rotation::tests_property`)
The one randomized test of rotation (spec/crypto.md §4, spec/permissions.md §2-§3): no departed holder reads later content, every holder ends reading everything. `rotation_holds_spec_crypto_4` (tier 1, seeds 8..16, no environment; about 14 CPU-s) and `rotation_holds_tier2_spec_crypto_4` (plain: 100 seeds, `OSIS_FULL=1` 1000, `OSIS_ROTATION_START`/`_SEEDS`) run `rotation_history` per seed.
- **Generator**: five peers, actor G (peer 0's) with every other peer at a random role; with holder actors (seed mod 4 = 3, else one seed in six) one or two more actors, some peer 2's, granted roles on each other around a cycle (synced after each grant or only at the end). Rounds of random actions on random actors: removals and demotions, self-removals (a writer forging as `tests_departs::Forge`, after which its node is hostile and acts no more), compactions of `secrets.0`, grants, `until`s soon (the clock moves on), re-grants, rotations leaving random members out or boxing nobody (no honest rotation does: a vandal, hostile from then on; never the actor's first admin); partial or full syncs between rounds, so rotations fork and rotators demoted unaware make invalid rotations. Then an admin X gets everything but some lowering commits (and a few others) and re-seals and rotates every actor. Then an honest admin of each actor removes every hostile peer and every actor whose first admin is hostile (the Lockouts recovery, notes/crypto.md: a hostile node's epochs otherwise stay current, and a hostile-owned holder actor never gets a knowing keyset). Then everything syncs; every node takes the walk's side in each admin dispute (as the order harness does: a default side is first received, and only nodes under one trust set read alike); a history with no lowering and no rotation of an actor holding a role on another settles by re-seals alone first (nobody writes, so nobody rotates) and is checked (a holder actor's new keyset makes the epochs boxing or proving its old one stale, so blocked: they take no history add until their due rotation); then every node re-seals and makes its due rotations until nothing is written (16 rounds bound) and everything is checked. The seed's emphasis (seed mod 4: forks, departures, forgeries, holder actors) only weights the action draw. `tally` asserts every shape (forked, departed, forged, holder actors, withheld, invalid rotation) reached in any run of 8 seeds or more.
- **Oracle**, on each actor at its first admin (after rotating, unless the first admin is hostile: nothing recovers its lockouts; the rest after either settling): nothing blocked and every holder with key access boxed; every holder counts the current epochs the first admin does, each established there; each current epoch a holder that may rotate holds is held by every holder of its role, and every earlier superseded secret any holder of a current epoch holds is held by all its holders. Leaks: a peer without access to role r of the actor at the end (its key role, directly or through holder actors it reads at r) opens, from every secret it held or made at any point and the final boxes, neither the epoch a remaining writer encrypts under (unless blocked there) nor any epoch whose rotator held its departure (the last write on its own edge) and saw it below r (recorded where every holder is a peer; a peer reading a holder actor the epoch boxes or proves at r is not below it: a step may remove that actor after its cascade rotated; and where the rotator held no secret of a boxed actor, the stated limit for an epoch whose secret the sealer lacks, the peer must not open the epoch without that box). No other excuses. A failure prints the history's steps and when the peer first held the secret.
- **Seen to bite** (each sabotage alone, 200 seeds against 3 failing unsabotaged): re-seal trigger looking only at the newest fork 13 failing; history adds off 47 (and tier 1); establishment without names met 5 (the two extra are leaks); an invalid rotation's epochs kept established 16 (and tier 1). Not caught: coverage by any author's entry (`Held::holds` true) and the blocked walk ignoring stale and keyless holder-actor boxes (neither caught by the seven harnesses this replaced, at plain size), entries covering without a keyset publishing them. The `tests_members` examples catch the blocked walk; no rotation test catches the first (`publishes` also asks that the author hold the role).

## Seed runners (`osis_base::testenv`)
`run_jobs(name, jobs, threads, visible, label, f)` is the runner (jobs of any type, results as `Result` per job, hung ones `Err`); sim-sweep and `work_sets_match_full_passes` use it directly, so a livelocked sim seed is named. `run_seeds(name, seeds, visible, replay, f)` (and `Seeds::run`, which announces an env range first) runs `f(seed)` for every seed on a thread per core (`OSIS_SEED_THREADS` overrides, one variable for every harness), a panic as its seed's failure (`caught`), results in seed order; it panics on an empty seed list. Each failing seed prints with its replay command as it fails, a progress line every 60 s, then a summary line, then a panic listing every failure in seed order. A seed whose thread has used `OSIS_SEED_TIMEOUT_SECS` (default 600) CPU-seconds, or no CPU at all for that many seconds (blocked), is marked hung and a new thread takes its place (CPU time from `/proc/<tid>/schedstat`). Not wall time: under heavy load a 5 CPU-s seed can take 700 s wall. Only the seed's own thread counts (seeds are single-threaded). A hung thread prints its backtrace at its next `testenv::checkpoint()` (called by `LocalPeer::sync`, the node test `Net::run` and the sim's `Sim::step`). A hung thread cannot be stopped or joined: when the rest is done with hung seeds still running, or as many seeds hang as there are threads, the runner prints every failure and hung seed and exits the process (101). `par_map`/`caught`/`threads` are the building blocks; the order harness uses them for its own shrinking runner.

Rule: tier 1 replays no pinned seed (a failing seed becomes a hand-written example or a `repro_*`, or nothing). A seed-ranged harness's tier-1 test runs fixed seeds and reads no environment; its `#[ignore]` `_large` twin reads the `OSIS_*_START`/`_SEEDS` range (`--ignored --exact <name>_large`); a printed replay line names the twin where it checks a seed as the tier-1 test does, else the tier-1 test itself. `held_set_decides` has no twins: its sizes are one function (`Size`), `quick` in tier 1 and `plain`/`exhaustive` as `#[ignore]` entry points. So `--ignored --exact` on a harness name either runs it or matches nothing (`0 passed`), never a silent default run.

## Scale checks
Tier 1, against spec/requirements.md (Scale): each test runs one operation at a size n and at 10n and counts its work, never time (notes/coordination.md, Testing). `flat` (at 10n at most 2x + 2 the count at n) is O(change); `linear` (at most 15x + 15) allows O(n) or O(n log n), never quadratic. What is counted: engine cost spans by count (`osis_node::costs`: pages and placement blocks loaded and written, commits ingested, examined, re-judged, bodies rebuilt; paused inside debug-only checks), engine counters (`death_walks`, `replaced_reads`, `examined`), `osis_perm::commits_walked`, node-sync `PassStats` (passes, full passes, bodies and entries judged), store rows and bytes (`MemoryBackend::io`; reads there include debug-only checks, so tests count reads by spans and use the store for rows and bytes written; rows are the sharper count, as each write's 20-40 KB of fixed bytes hides a per-commit term under about 100 B at these sizes), `commits_walked` counts in debug builds only (it panics in release), and byte sizes. A paged state needs 64 KiB (`PAGE_TARGET`), so paged checks use long values to stay small. A failing count names the phase and both counts. A known violation is an ignored `repro_*` naming its issue.

## Forensic attack (`osis_store::attack`, `Engine::forensic`)
The definition of "forensically clean" (spec/requirements.md, Deletion). Evidence: the keys the current store tree yields, the label read secrets the node's code computes now (`Engine::forensic` adds them), and every row and blob the backend was ever given (`MemoryBackend::record_history`: `history`, `blob_history` with frees; `fork` copies a recording device). To a fixpoint it reads every row and blob raw (clear rows `r`, `p`, `j`; a blob stored in clear), opens rows with store keys (tree nodes yield more), takes every random-looking 32 bytes (at least 16 distinct byte values) of anything recovered as a candidate key on every blob (link keys, node-sync `y/b` keys, anything), and for entries keyed by a blob ID (store wraps, node-sync `y/e`; table pages decoded by the store's own `forensic_leaf`, overflow values joined) tries the value's leading wrap under every candidate as a read secret. Each find says where (`Source`: row, raw row, blob opened by key or by wrap, raw blob).
- Not covered: keys inside a blob stored in clear (raw blobs and raw rows are not harvested: ciphertext would flood the candidates; clear rows are); a wrap not at the start of a blob-keyed entry's value; secrets only derivable from dropped ones (the attack never runs KDF chains over old secrets); memory, swap, the root store's past records; non-memory backends (redb: `file_backend_holds_no_plaintext` greps the file). Markers find content; a dropped map key's keyed index hash is checked as an extra needle where it matters (`expired_entry_paged_*`).
- "Random-looking" misses a real random key with probability about 2^-55 (fewer than 16 distinct values in 32 random bytes); a false positive costs time only.
- Cost: about 40-60K candidates × the unopened blobs (and their wraps), and every store key × every row; a try first decrypts only the last plaintext byte (`aead::last_plain_byte`: padded plaintexts end in 0x80 or 0x00, so any other byte rules the key out; exact, the MAC pass still decides), so a wrong key costs one ChaCha block instead of a MAC pass over the blob. A section tries a candidate as its own key only when its first two plaintext bytes can begin one (`Section::may_open_with`: an array of parts, each a 3-array), and a section once opened is not tried again; each wrong candidate still costs a wrap's AEAD open per unopened section and blob. Under a second per attack; one thread per blob; crash loops fork one set-up device per crash point instead of setting up again; `shred` tests attack once per state (`common::recovered` checks several markers).
- Row lengths: `shredded_small_drop_keeps_unit_lengths_within_a_class_step` checks a shredded small drop leaves each rewritten unit's padded length equal or one Padmé class step away.
- Tests: store `tests/it/shred.rs` (units, wraps, blob keys and wraps, clear rows), node `shred.rs` (engine purge, expiry, purge on replace, paged, chunked), `shred_sync.rs` (a synced node's purge online and offline, and a crash at every write of the purge and node-sync's forget), `flows.rs` (removal erasure, crash-safe), host `hygiene.rs`, `metadata.rs`, osis `hosting.rs` (host stores: rows only).

## Spec-to-test map
`python3 tools/spec_map.py` writes notes/testing-map.md: per numbered spec section, the tests and live vector cases citing it; the rule checklist; then gaps and uncited tests. Regenerate at integration (freshness is not part of the merge gate, since concurrent branches would conflict on it); `--check` tests freshness, `--uncited` (merge gate) fails on a test in core/ or cli/ (models exempt) that cites nothing, `--gaps` (merge gate) fails on a rule with neither a test nor an issue, or a MUST sentence no rule anchors.
- **Rules**: every MUST / MUST NOT sentence of spec/*.md plus the refusal rules of spec/permissions.md and spec/sync.md ("cannot", "refused"), each a `RULES` entry (file, §, anchor, a substring of the sentence) in the script. A test or an issue covers a rule by citing `spec/<file>.md §N (anchor)`; a new MUST sentence fails `--gaps` until it gets an entry. `VACUOUS` lists rules nothing can test yet (no batch verification; format version 1 only).
- **Not covered by the map**: SHOULDs (listed in the map, not gated), policy (budgets, rate limits, caps: osis-host tests cite them as `spec: none` or by section), declarative normative text with no MUST (covered only at section level), spec/requirements.md (no numbered sections or MUSTs; its items are covered by reviews), and the out-of-scope list of spec/requirements.md.
- **Metadata tests** (core/node/tests/it/metadata.rs, real engines over an osis-host hub): stored bytes hold no value, map key, tid, AK, node tid or signing key, or role secret (a label-ID control proves the search works); every stored blob's padded length is a Padmé length and 48 value lengths fall in at most 5 size classes (Padmé leaks O(log log n) bits by design); two labels share no blob ID, salt or wrap; claim sets of 3 and 4 readers are both 4, of 5 readers 8, shuffled; heartbeats write only `seen.0` on their node. Harness note: `Net::group` seeds every rotation with 1, so two groups of one admin get equal secrets and one label ID: use `group_seeded`.
- **Negative tests**: host refusals live in osis-host tests/it/limits.rs and hub.rs and osis-proto tests/it/loopback.rs (the host session); perm refusals in osis-perm tests/it/scenarios.rs; node ones in osis-node tests/it/flows.rs, peers_review.rs, negative.rs (keep at least); QUIC mutual auth and no 0-RTT in osis-transport `quic::tests` (tier 2, `--ignored`).

## Conventions for every crate
- **Spec citations**: put `// spec/<file>.md §N[.M]: <what>` right above each `#[test]` (inside `proptest!` too); a bare `§N` refers to the last file named in that comment. A test without its own citation inherits the file's `//!` header citations. Infrastructure tests with no spec section say `// spec: none (<why>)`.
- **Network in tests**: tier 1 uses `osis_transport::{Net, Sched}` (in-process, virtual steps, seeded faults and scheduling; no tokio); real-socket tests (QUIC on localhost) are tier 2. `peer://` in process runs the real P2P code: a node on a host of a nat.rs net (`Internals.host`) names a route (an item, a relay, a LAN address), with no route no dial succeeds. Under tokio, `Net::run_on_tokio` runs the net with one model ms per wall ms, so the transport's timers and the engine's reactions share a clock; a test whose dials must fail sets `Net::set_dial_ms` (`0`: one packet). The driver's LAN loop runs over the model too: `MemUdp::on_lan` puts a host on a LAN segment at an address of its own there, `Transport::lan` gives the driver a `MemLan` socket, broadcasts reach that segment, `Net::set_lan_loss` loses them (core/node/tests/it/driver.rs `driver_lan_*`); negatives count announcements heard, never waits. `driver_relayed_becomes_direct_spec_sync_10` is the driver-level switch: `partition` holds the punch back until the relayed sessions are up, `connections_between` shows the switch.
- **The real LAN**: tests run side by side on one box, so none binds port 47380 or announces on the real network (tools/policy.py enforces the shapes). A node a test builds starts from `internals::Opening` (`Lan::Off`), or uses the nat.rs model (`MemLan`) to test LAN behaviour; the `osis` binary under test runs with `--no-lan`; a real-socket LAN test takes an OS-picked free port and loopback targets (`driver_lan_loop_*`, `lan::tests`). The one exception is `announce_v6_every_interface_spec_sync_10`: sending on every real link is its point (a free port no node listens on; tier 2, through `tools/heavy`).
- **Tiers**: tier-2 tests are `#[ignore]` (optionally also gated on `OSIS_SLOW=1`); a crate's tier 1 stays under about 10 s.
- **Seed loops**: a loop over consecutive seeds gives each its own run: `rng(seed | 1)` makes seeds 2k and 2k+1 the same history; use odd seeds via `step_by(2)` (the paged-apply harness seeds `seed << 1 | 1`). Harmless `| 1` left: crdt-model `tests/props.rs` (proptest draws random seeds), osis-node `it/walks.rs` (seeds multiplied by an odd constant first). A multi-seed tier-2 run goes through `testenv::run_seeds`, not a serial loop.
- **Vectors**: in the change that lands an encoding: write a generator `fn() -> VecFile` in `core/test/vectors/src/subjects/<subject>.rs` from fixed inputs (32 repeated bytes per seed), asserting what it computes, add it to `subjects::GENERATED` and `generated!` in core/test/vectors/tests/vectors.rs, and the crate as an osis-vectors dependency. Hand-written vectors get a checker instead. Rejections use rule IDs documented in core/test/vectors/README.md.
- **Fuzz**: a target per parser of peer or disk bytes (core/test/fuzz/README.md, "Adding a target"), seeds in `corpus.rs`; a crash becomes a regression test in the crate the code lives in, citing the spec section and `fuzz: <target>`.
- **Budgets and benches**: in osis-bench as above; a new external dependency for them needs its line in notes/architecture.md §5.

## Performance budgets
Coordinator-owned targets (Tess delegated; prefer simple and verifiable code that meets them over faster intricate code). At 10^4 commits per aspect and 10^4 things per group, release, a quiet box: a single local write, read or received commit under 50 ms; node open under 1 s; one sync pass after one new write under 100 ms; a late or out-of-order commit under 500 ms (a whole replay of one aspect is acceptable here). Rare events (revocation) under a few seconds. Work beyond these is not pursued without a realistic scenario missing them; issues that only chase speed below them are closed as within budget.

Host (osis-host on its own `Store`, redb and a file root, release, a laptop disk): 1 KiB entries at least 1000/s uploaded and 1000/s deleted in 64-entry hub batches; one single-entry upload batch plus one single-entry delete batch under 20 ms (the delete's shredding commit: two backend commits and the root's two fsynced slot writes, about 4 fsyncs). Counted in tier 1: `file::host_batch_writes_do_not_grow_with_entries` (Scale checks).
