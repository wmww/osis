# Testing
> Summary: How osis is tested and how to run each layer: principles, tiers and CI, conformance vectors and their freeze policy, fuzzing, size budgets and benches, coverage, policy checks, the spec-to-test map, and the conventions every crate follows when it adds tests, vectors, fuzz targets or benches.

Strategy items not yet built (differential tests, simulator phases B and C, security suites, app-level tests) stay in plans/testing.md and plans/sim.md until they land.

## Principles
- The spec is the oracle: every MUST has a test that fails without it, and every test cites the spec section it checks, so `grep` (or notes/testing-map.md) answers "what checks §X".
- Determinism: seeded randomness, injected clocks, in-process transport. A failure is a seed; a flake is a bug.
- Peer bytes never panic: every parser is fuzzed; decoders take limits.
- Models (models/) are independent oracles; the implementation never depends on them and they are never patched to match it.

## Tiers and CI
| tier | what | how | where |
|---|---|---|---|
| 1 | unit, small proptest (`PROPTEST_CASES=32`), vectors | `cargo test -p <crate>`; `cargo test --workspace` at integration | `ci.yml`, every push |
| 2 | `#[ignore]` tests: large property runs, size budgets, differential at size | `OSIS_SLOW=1 PROPTEST_CASES=1024 cargo test --workspace --release -- --include-ignored` | `nightly.yml` `slow` |
| 3 | fuzz, sim seed sweeps, big model instances, TLC, benches, coverage | see below | `nightly.yml` |

`ci.yml` jobs: `test` (build, tier 1, vectors, clippy `-D warnings`), `policy` (tools/policy.py, `tools/spec_map.py --uncited`), `deny`. Nothing requires nextest, nightly or cargo-fuzz; nextest works if installed. Tier 1 never sleeps or touches the network. `nightly.yml` uploads proptest regressions, fuzz crash inputs and failing sim seeds as artifacts; its `sim-sweep` step is a placeholder until plans/sim.md adds `sim/src/bin/sim-sweep.rs`; its `models` job sets up Java and runs `models/tla/run.sh small` (below).

Tier-1 wall time per crate (`cargo test -p <crate>` after a warm build, 4 shared cores, wave 2 integration): crdt-model 3.7 s, osis-crdt 1.7, osis-perm 1.5, osis-proto 1.5, osis-store 1.4, osis-vectors 0.7, osis-core 0.3, osis-schema 0.3, osis-label 0.3, every other member ≤ 0.2 (node, server, transport, osis, cli, sim still stubs). `cargo test --workspace` 11 s warm, about 55 s to build the tests. No crate is near the 10 s line.

## Models (models/)
- `models/crdt` and `models/membership`: Rust reference models (notes/crdt.md, notes/permissions.md); the membership model's exhaustive tiers and random samples run in nightly `models`.
- `models/tla/sync` and `models/tla/rotation`: TLA+ models written from spec/ alone (plans/tla-models.md), checked with TLC. Sync covers one label at one blind server: upload, download, deposit and promotion, token deletes (blob-ID carrier tiebreak) and timed deletes (snapshot first when writes stay live), expiry, compaction, purge and rewrite, due snapshots (also before a live drop), tombstones, offline nodes, a dropping/replaying/reordering server; properties: no live write leaves the label uncarried, must-hold bodies converge to the server, must-not-hold bodies and duplicates do not persist, entries settle, deposits get promoted, purges reach every node, members end up holding a carrier for their live state. Rotation covers read-role rotation of one actor: established epochs, forced and eager rotation, forks, removal carried in its rotation, grants, registration steps after the rotation chain is uploaded, claims and claim-set drops, stranded heartbeats (also on a refused claim), deposit-seed refresh, re-seal by inbox after a complete pass, member peers; properties: no departed member reads content written with its departure known, no departed member holds an epoch that did not box it, every current member eventually opens every current epoch and reads everything. Each README gives the instances with results, state counts and times; each AMBIGUITIES.md the findings (all resolved but residue 2 of issues/reseal-triggers.md, `MC_drop_refresh`, and minor readings S16, R10–R12).
- **CI decision**: TLC runs nightly, not per push. `models/tla/run.sh small|all [filter]` downloads the jar to `~/.cache/tla` if missing and runs the listed instances with 1 worker (`TLC_WORKERS` overrides); `small` (under a minute) is `sync/deposit`, `sync/mostabs`, `rotation/MC_live`, `MC_grant`, `MC_safety`, `MC_fork`; `all` adds instances of up to about 20 minutes each, run by hand. Instances that reproduce an open finding (now only `MC_drop_refresh`) are listed in the script as expected failures: the script exits non-zero on any other violation, on an expected failure that passes (update the docs), or on a TLC error.
- **Not covered by the TLA+ models**: several labels or servers, projections and certificate copies, retagging, parked bodies and unfetched pages, clock skew, range reconciliation details, token levels, `nobody`/`admin`/`author` purge rights, nodes offline past `MEMBERSHIP_KEEP`; write and admin rotation, keysets and departures inside a member, demotion and `until`, step-tree branches, steps without rotation, entry boxes and key actors, `/label` and `/secrets` compaction (so snapshot-established epochs), the stale-view carrier race. The models are oracles for the spec, never patched to match code; a spec change that touches their sections re-runs them (plans/tla-models.md lists what the last round of edits changes).

## Conformance vectors (vectors/, crate osis-vectors)
- Format, subjects and rule IDs: vectors/README.md (language-neutral, ships with the spec). `.vec` text files of `key: value` records; every case has `case` and `spec`; `pending: <reason>` marks a case not yet checked.
- `vectors/MANIFEST` lists every file required by plans/test-infra.md: `pending` (crate not landed), `provisional`, or `frozen <blake3> <FC-n>`. A frozen file changes only with a `## FC-n` entry in vectors/FORMAT_CHANGES.md naming it (toplevel review) and `gen-vectors freeze <path> FC-n`; the `manifest_policy` test enforces this.
- Generated files (all but `cbor/` and `padme/`) must equal a fresh `cargo run -p osis-vectors --bin gen-vectors`; hand-written files have a checker that re-derives each case. Fixed inputs: seeds are 32 repeated bytes, randomness injected (plans/test-infra.md, "Vectors required").
- State: `cbor/values.vec` (hand-written), `tid/thing.vec`, `chunker/gear.vec` frozen (FC-1; chunker boundaries cross-checked by an independent Python implementation of spec/wire.md §6). Provisional, awaiting toplevel freeze: `padme/padme.vec` (hand-written), `tid/key-actor.vec`, `kdf/`, `keys/`, `box/`, `wrap/`, `token/`, `sign/` (osis-crypto), `commit/headers.vec` (osis-commit); `blob/`, `chunker/tree.vec`, `chunker/pages.vec` (page rule re-derived in the generator), `step/`, `inbox/`, `signal/`, `link/`, `bundle/` (osis-label; the commit blob case and the inbox payload's commit wait for osis-commit; the tree vector was reproduced independently by the reviewer). Every other file pending its crate.

## Fuzzing (fuzz/, outside the workspace)
fuzz/README.md: running, the target table (live and planned per crate), crash handling. Seeds come from the vectors via `gen-vectors corpus` (osis-vectors `corpus.rs`). Nightly fuzzes every target `cargo fuzz list` prints for `fuzz_seconds` (default 300). Never commit `fuzz/artifacts/` or run output; corpora stay small.

## Simulator (sim/, crate osis-sim; plans/sim.md)
- Shape: `Sim::new(name, seed, Config)` boots `nodes` real engines, each over its own `MemoryBackend` + `MemoryRoot` sharing one `osis_store::Faults` plan, a `ManualClock` and a seeded rng; all randomness comes from one `Dice` seeded by the run seed. `Config`: per-node `ClockSpec { skew_ms, drift_ppm }` (wall = T0 + elapsed + skew + elapsed·drift/10^6), `NetFaults { drop_pct, dup_pct, max_delay_ms, reorder }`, scheduler `Weights { write, gossip, deliver, tick, crash, restart }`, `max_tick_ms`, `check_every_step`.
- `step()` picks one event: a random write (1–3 random ops of `workload`, a schema with one aspect per encoding, on things in `sim.things` the node may write), gossip (node → random peer: packages of every applied commit the receiver lacks — an oracle standing in for reconciliation until node-sync's `SyncEngine`; each through drop/dup/delay), delivery of a due message (earliest, or any under reorder; to a down node it is lost), a tick (time passes, clocks set, `Engine::tick`), a crash (immediate, or at one of the node's next durable writes via `Faults::at(n, Crash)`: mid-write), a restart (`Peer::restart` over the same backend). `run(n)`, `run_until_quiescent(max_rounds)` (no new writes or crashes, every node up, everything delivered, pairwise sync without faults, time advanced 10 min at a time while commits pend). Setup helpers: `create_thing`, `grant`, `revoke`, `commit`, `deliver`, `sync_all`, `advance`, `set_clock`, `read`, `engine`.
- Invariants (`check`): per step, every group of up nodes holding the same applied commits reads the same values (every stored aspect); per applied event, own `ts` strictly increasing across restarts and within `MAX_DRIFT` (+1 ms) of the wall clock, no remote commit applied more than `MAX_DRIFT` ahead, no node-form counter range of one author overlapping another commit's on one aspect; at quiescence, every node holds the same commits and nothing pends. Engine errors on honest input (BadInput on an honest package, any error on a node not crashed) and panics (caught per run) are failures.
- Failures carry scenario, seed, step and the last 40 trace lines, and print `osis_sim::replay("<scenario>", <seed>)`, which reruns it exactly (a test checks a run twice gives the same `Report`, digest included). A failing sweep seed becomes a tier-1 test with a one-line description.
- Scenarios (`SCENARIOS`): `two_devices` (person actor owned by device 0, device 1 admin, a data thing the person owns), `three_random` (two shared things, all faults, skew ±5 min, drift ±200 ppm), `crash_restart` (plus crashes), `drift_parks` (a node jumps 2 h ahead: its commit pends with `Drift`, unread, until the receiver's clock is within `MAX_DRIFT`), `revoke_while_writing` (a writer removed while writing). Tier 1 runs seed 1 of each (about 2–5 s each: node code is unoptimized in test builds); `OSIS_SIM_SEEDS=N cargo test --release -p osis-sim sweep -- --ignored` sweeps.

## Size budgets and benches (crates/osis-bench)
- Budgets: `crates/osis-bench/tests/budgets.rs`, each `#[test] #[ignore] fn budget_<name>()` calling `assert_budget(name, actual, budget)` with the source number plus a margin (about 10%), citing its source. They use public APIs only (osis-bench is layer 9 and may depend on any crate).
- Live: `budget_creation_record`, `budget_minimal_commit` (commit blob plaintext of a header plus one register delta: 288 B against about 300, notes/crdt.md Commit floor), `budget_text_snapshot_ratio` (notes/crdt.md, Text size).
- Pending budgets (add when the crate lands): removal from an N-member roster (no source number yet: set it from the first measurement); roster snapshot of N members, membership boxes about 1.2 KB per member and role (notes/crypto.md); revoke frontier after a long tenure (osis-perm, osis-commit).
- Benches: `crates/osis-bench/benches/<crate>.rs` with `harness = false`, calling `osis_bench::bench(name, bytes, f)` (prints median ns/iter and MB/s; `OSIS_BENCH_MS` sets the sample time). Run `cargo bench -p osis-bench`; nightly records the output as an artifact. Not gated. No criterion: a 40-line harness keeps the dependency tree and builds small.

## Coverage
Nightly `coverage` job: `cargo llvm-cov --workspace`, lcov and summary as artifacts, `continue-on-error`. Measured, never gated; read it for untested decoder branches. Locally: `cargo llvm-cov -p <crate>` if cargo-llvm-cov is installed.

## Policy checks
- `python3 tools/policy.py`: every workspace member has `[lints] workspace = true` (models: `[lints.rust] unsafe_code = "forbid"`), every crate root under crates/, vectors/, sim/ has `#![forbid(unsafe_code)]`, no `unsafe` block, fn, impl or trait anywhere in the workspace, and every external dependency has a backticked line in notes/architecture.md §5. fuzz/ is exempt (libfuzzer's macro uses `unsafe`).
- `cargo deny check` (deny.toml): licence allowlist (MIT, Apache-2.0, BSD, ISC, Zlib, CC0, Unicode-3.0), duplicate versions denied (a forced duplicate gets a `skip` with a reason), advisories, crates.io only. Members are `publish = false`.

## Spec-to-test map
`python3 tools/spec_map.py` writes notes/testing-map.md: per numbered spec section, the tests and live vector cases citing it, then gaps and uncited tests. Regenerate at integration (it is not checked for freshness in CI, since concurrent branches would conflict on it); `--check` tests freshness, `--uncited` (CI) fails on a test in crates/, vectors/ or sim/ that cites nothing. Gaps are treated like issues by hardening-signoff.

## Conventions for every crate
- **Spec citations**: put `// spec/<file>.md §N[.M]: <what>` right above each `#[test]` (inside `proptest!` too); a bare `§N` refers to the last file named in that comment. A test without its own citation inherits the file's `//!` header citations. Infrastructure tests with no spec section say `// spec: none (<why>)`.
- **Network in tests**: tier 1 uses `osis_transport::{Net, Sched}` (in-process, virtual steps, seeded faults and scheduling; no tokio); real-socket tests (QUIC on localhost) are tier 2.
- **Tiers**: tier-2 tests are `#[ignore]` (optionally also gated on `OSIS_SLOW=1`); a crate's tier 1 stays under about 10 s.
- **Vectors**: in the plan step that lands an encoding: write a generator `fn() -> VecFile` in `vectors/src/subjects/<subject>.rs` from the fixed inputs of plans/test-infra.md, register it in `subjects::get`, add the crate as an osis-vectors dependency, flip the MANIFEST line to `provisional`, run `gen-vectors`, and add the file to `vector_files!` in vectors/tests/vectors.rs. Hand-written vectors get a checker instead. Rejections use rule IDs documented in vectors/README.md. Toplevel review freezes them (FC entry).
- **Fuzz**: a target per parser of peer or disk bytes (fuzz/README.md, "Adding a target"), seeds in `corpus.rs`; a crash becomes a regression test in the owning crate citing the spec section and `fuzz: <target>`.
- **Budgets and benches**: in osis-bench as above; a new external dependency for them needs its line in notes/architecture.md §5.
