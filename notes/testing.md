## Principles
- The spec is the oracle: every MUST has a test that fails without it, and every test cites the spec section it checks, so `grep` (or notes/testing-map.md: notes/gate.md, Spec-to-test map) answers "what checks §X".
- Determinism: seeded randomness, injected clocks, in-process transport. A failure is a seed; a flake is a bug. The default tests never sleep, assert on wall time or touch the network.
- Peer bytes never panic: every parser is fuzzed; decoders take limits.
- Models are independent oracles: the implementation never depends on them and they are never patched to match it.
- Design rules for tests (one property test per property, oracles compare what users observe, never pin a seed): notes/test-design.md and notes/coordination.md, Design principles.

## What finds bugs
Over about 200 merged tasks: reading in review, audits and simplification passes found about 180 product bugs; a new targeted test or differential for the branch about 45; per-branch properties at small size about 25; larger ranges, release checks and wide sweeps 15-19; dogfooding about 10; the default tests 2; TLA none new; re-running already-run ranges about 4 (all regressions). Of about 38 classified seed-found bugs, about 14 were slips against a clear rule and about 24 had no rule yet (the fix wrote a new spec sentence, a stated limit or a redesign); they clustered (arrival order × retention × validity, epochs and rotation, ephemeral), and each chase ended with a study that found one root shape, never with more seeds. Hence (notes/coordination.md, Test budget): per-branch sizes a tenth of large, breadth only in release checks, never rerun old ranges, one all-core run at a time per box, a study after the second seed fix in an area, and time spent on reviews that read, audits, dogfooding and targeted differentials.

## When tests run
Everything runs locally; there is no CI. Tests are organised by when they run, not by kind.

| when | what | how |
|---|---|---|
| the gate, once per branch | the default tests (every test not `#[ignore]`: unit, small proptest, vectors, scale counts) plus the properties and sim scenarios the branch's changes reach, at small size | `tools/gate.sh` (notes/gate.md) |
| release checks | the same properties and scenarios at large size on fresh seeds; when Tess asks and in the release process | notes/coordination.md, Release checks |
| by hand | fuzz, TLA+, roles-model searches, benches and memory checks, coverage, real-network tests, `#[ignore]` tests without a size word | By hand, below, by a branch that touches the area |

**A worker** runs the default tests of each crate it touched (`cargo test -p <crate>`), plus `cargo test -p osis --test it` when it changed engine judgment (validity, keys, rotation, ending: the osis crate holds the cross-crate flows, and reviews failed on it after workers ran only engine and node) and `-p held-model` when it changed crdt-model; clippy; and the instant checks (`python3 tools/policy.py`, `python3 tools/spec_map.py --uncited --gaps`). The gate is the branch's one full run (notes/coordination.md, Test budget).

**Sizes**: a property's documented range or sample count is its large size (`OSIS_FULL=1`, release checks only); its small size, the gate's, is a tenth (`osis_base::testenv::large`, at least one seed); explicit `OSIS_*_START`/`_SEEDS` override both. Sim scenarios: 15 seeds small, 150 large. A property taking over 5 minutes alone at small size on a quiet box gets an issue to make it shorter. Scale is checked by counting work in the default tests, never by timing (notes/test-scale.md).

**By hand**, alone under `tools/heavy` when it uses every core:
- TLA+ when a model or its spec sections change: `core/test/tla/run.sh <module>` (notes/test-properties.md, Models).
- Networking, for a node sync, link or transport change: the networking command (notes/build.md, Profile and command forms); osis-cli `cargo test -p osis-cli --test it -- --ignored localhost::` (real sockets, about 2 min, not seeded, so any failure is a bug).
- Slow or special `#[ignore]` tests, by name (`cargo test -p <crate> --test it -- --ignored <name>`): osis-crdt `stream_memory_big_map` (alone, `--exact`), sim `work_sets_match_full_passes` (try `OSIS_SIM_SEEDS=2`), osis-node `ephemeral::many_authors_under_a_peers_rates_by_hand` (12 min in dev).
- Fuzz (notes/test-properties.md, Fuzzing); roles-model searches (notes/test-properties.md, Models); sim seeds beyond the gate's (`sim-sweep`, notes/test-sim.md); `cargo bench` and memory checks (notes/test-scale.md); coverage: `cargo llvm-cov --lcov --output-path lcov.info` if installed (measured, never gated; read it for untested decoder branches).

## Conventions
- **One test binary per crate**: `tests/it/main.rs` with a module per file, so a test's name is `<module>::<fn>`. Single-file crates (osis-base, osis-vectors, crdt-model) keep `tests/<file>.rs` (`--test cbor`, `--test vectors`, `--test props`). Nothing requires nextest, nightly or cargo-fuzz.
- **Spec citations**: `// spec/<file>.md §N[.M]: <what>` right above each `#[test]` (inside `proptest!` too); a bare `§N` refers to the last file named in that comment; a test without its own inherits the file's `//!` header citations; infrastructure tests say `// spec: none (<why>)`. `tools/spec_map.py --uncited` enforces it.
- **Ignored tests**: a property is named with a size word (notes/gate.md, The selection); a by-hand test says why (`#[ignore = "by hand: ..."]`); a known-failing reproducer is `#[ignore = "issues/<name>.md"] repro_*`. A crate's default tests stay under about 10 s each.
- **Seeds are 0**: a test writes the behaviour it intends; a world or rng seed is 0, and a case the seed happened to reach is constructed (draw tids until one sorts as wanted, try values until the case shows). Distinct numbers stay only where distinctness is the point: node identities, opens of one store, rotations of things whose secrets must differ, seals that must not share a nonce. The default tests replay no pinned seed: a failing seed becomes a hand-written example, a `repro_*`, or nothing.
- **Network**: the default tests use `osis_transport::{Net, Sched}` (in-process, virtual steps, seeded faults and scheduling; no tokio); real-socket tests (QUIC on localhost) are by hand. `peer://` in process runs the real P2P code over the nat.rs model (`Internals.host`): with no route no dial succeeds. Under tokio, `Net::run_on_tokio` runs the net with one model ms per wall ms; a test whose dials must fail sets `Net::set_dial_ms` (`0`: one packet). The driver's LAN loop runs over the model (`MemUdp::on_lan`, `Transport::lan`, `Net::set_lan_loss`; core/node/tests/it/driver.rs `driver_lan_*`); negatives count announcements heard, never wait. `Net::punches` counts punch packets.
- **The real LAN**: tests run side by side on one box, so none binds port 47380 or announces on the real network (tools/policy.py enforces the shapes). A node a test builds starts from `internals::Opening` (`Lan::Off`) or uses `MemLan`; the `osis` binary under test runs with `--no-lan`; a real-socket LAN test takes an OS-picked free port and loopback targets. The one exception is `announce_v6_every_interface_spec_sync_10` (by hand, through `tools/heavy`).
- **A node away running on its own** (osis-node `it`): `net.offline_handle(n, ev)` after `set_online(n, false)`, never `net.sync(n).handle(ev)` with its actions dropped: a dropped `Action::Dial` is never answered (`Up` or `Down` is the driver's promise), so the node waits on it and never dials again once back online.
- **Setting up access** (osis-node `it`): on a `Net`, `Net::grant` (secrets in the same commit; it needs `net.pair(holder, granter)` first and a granter holding the target's secrets). A bare edge write (`set_edge`) leaves the holder to node-sync's repair at the next complete pass, so on a `Net` it stays only where that repair or a keyless roster is what the test checks, or a hand-built rotation right after boxes the holder, each with a comment saying which. `LocalPeer` runs no sync passes, so its `common::set_edge` stays the tool for edge semantics.
- **Vectors, fuzz targets, budgets**: notes/test-properties.md (Conformance vectors, Fuzzing), notes/test-scale.md.

## Default-test cost
**Default-test cost**: `cargo test`, built, in the gate's hold (main 5c2b0348c): 1130-1200 CPU-s, 114-159 s wall at load 15-22 on fastbox-0; 2490-3200 CPU-s on ostrich (notes/time-limits.md, Patterns). Instruction counts (main 5f1db6e1f, warm): about 13,000 G user instructions (3448 tests listed, ignored included). Instruction counts are the measure to compare: a test's count repeats to under 0.1% run to run, its CPU-s by 20-40% and its wall more (load, SMT, clocks). Each default binary alone under `tools/icount` (16 threads, every test of it, test-optimizer-1's tip): 6420 G; osis-node `it` 3489, osis `it` 1205, engine lib 497, crdt lib 244, osis-sim `it` 209, held-model 178, perm 156, chat 140, the other 26 binaries 302 together. Every test alone summed is about 15% more (cached setups lost): node `it` 3942 G (1475 tests, median 0.98 G), osis `it` 1479 G (550, median 1.15 G). 137 tests take over 5 CPU-s each and hold half the CPU; 5 take over 10 CPU-s alone (below). The run is CPU-bound, not tail-bound: each big binary keeps 13-15 of 16 cores busy to its end; the smaller ones (chat, held-model) end on one test for 9-10 s.
- What makes it large (`tools/cpuprof` over every default binary, shares of all samples, overlapping): node-sync passes (`SyncEngine::handle`, 36%; issues/derived-state-recomputed.md), crypto 19% (product paths, the forensic attack's AEAD), ingest 13%, the debug checks (`check_index` 6.5%, `misjudged` 2%, `check_rebuilt` 1.3%), a stored part read again decode-only at every join (`crdt::stream::stream` 9%, 7 of it `stream_checked`/`decode_checked`), the work every `Engine::run` does around its closure (persisting the index, the journal, `leave_if_removed`, the store commit: about 9%, read-only lookups such as `has_blob` included), `order::held_set_decides` (283 G, the costliest test) and a few dozen 20-55 G scripted every-order, scale and setup-heavy tests.
- Over the `test` limit alone (10 CPU-s or 15 s wall; `tools/limits.py tests`, load 8-11: 3690 tests, 2058 CPU-s at 8 jobs): 5, each multi-threaded: `order::held_set_decides` 144 CPU-s / 11 s wall, `net_records::no_connection_resumes_a_record_without_proof_and_a_shared_r_spec_sync_10` 15 / 1 (12 seeds), held-model `props::arrival_orders_read_alike_after_repair_spec_commits_5` 12 / 1 and `props::late_commit_converges_after_repair_spec_commits_5` 10 / 1, `shred::past_expiry_and_purge_alike_spec_commits_5` 10 / 1 (84% the forensic attack, which is the property). No test takes over 11 s wall alone. The slowest single-threaded ones (under 8 s) are node-sync passes, e.g. osis `sync::redeem_held_joins_nothing_spec_none` (`judge_label` 43%, `part_keeps` 26%: issues/derived-state-recomputed.md). A test looping over fixed seeds or cases runs them on the seed runner (`stream::stream_differential_*`, osis `port_clients::client_session_differential_against_grants`), and cases sharing a setup copy it (`retention::purge_rights`: `LocalPeer::cached`).
- Measured not to help: every binary at once, osis-node `it` beside the others in series, harness inner threads at 1, opt-level 2 for the workspace crates (one-line edit builds 15-20% slower), selecting default-test crates by the diff (node and engine take most commits: 15% at best, opens a gap). Only less work shortens it.
- In place: osis-crypto at `opt-level = 2` in dev; smaller data where the property is relative; properties for sizes; a fill batch of 8 where a fill part way is the point (node `fill.rs` `SyncConfig::fill_batch`, osis `Knobs::fill_batch`); one setup copied per order where a test plays many orders from one start (`local_peer::Peer::fork`); debug cache cross-checks compared once per state of the store and indexes (`Engine::recheck`, `Tx::recheck`: commit records, `leaving`, `vet_inbox_hints`; memo hits compared with a fresh run, `osis_base::memo` `Checks`), since a fresh read repeats itself until a commit or the indexes move; the clock is not part of that state (a running clock moves at nearly every hit, so every hit compared), and a check whose answer moves with time names the time (`vet_inbox_hints`); decoded commit records and parts (`engine/decoded.rs`) checked at every hit by comparing the bytes each was decoded from with those read now (the record's stored bytes, the part in it), never decoded again: decoding is a pure function of those bytes, so a stale or misfiled entry shows as differing bytes (a re-decode per state of the store would cost 8% of sim `member_churn`'s instructions); engine reads (`Engine::read`: a store transaction dropped after and its in-memory changes undone) do none of a transaction's end work, and a debug build asserts each changed nothing (the store, blobs, or anything `Core::rollback_to` restores: indexes, sides, events, work lists; a read that writes would have its change undone, and every cache dropped, at every call); `LocalPeer::sync_all` stops after a round of duplicates (a fixpoint) and does not repeat a delivery that came back a duplicate and moved nothing; the forensic attack's last-byte key test (below). A test is a whole multi-node signed, encrypted sync, so 50-200 ms alone is the normal floor, not a slow test.
- Where osis-node `it`'s CPU goes (cpuprof over the binary, 8 threads; shares overlap): ingest 29%, node-sync passes 28%, `check_index` 16%, `order::check_orders` 14%, `check_rebuilt` 13%, `CommitBlob::decode` 15%, the forensic attack 6%. osis `it`: node-sync passes 69% (`judge_label` 26%, `ensure_rotated` from `usable_keys` 12%, `part_keeps` 12%), ingest 14%, the two debug checks 12%.
- Per test, every test: `tools/pertest.py run OUT` builds the default tests, copies their binaries aside, then (under `tools/heavy`, taken after the build, so editing while it waits changes nothing measured) runs each listed default test as its own process `--exact <name> --test-threads=1` from its package dir under `tools/icount`, writing name, instructions, CPU-s and exit code per line: 3953 tests at 16 jobs in about 4.5 min of the lock. `tools/pertest.py top OUT` lists per-binary totals and the costliest tests; `compare OLD NEW` the moves by test (crdt-model's and osis-keys' proptests draw fresh seeds per run and move 7-8% between identical runs: noise; a test failing only at pertest's load may be a KNOWN flake, tools/known_failures.txt). A compare against the last profile is also a cheap check for a storm that landed passing (a test 20x its old count). Against an older revision: `run` in a second worktree (`wt claim <name> <rev>`), `compare` here. Each test is its own process, so a cached setup is built by every test using it: a cached setup's saving shows only over a whole binary or module in one process (`tools/icount BIN -q <module>::`).
- Per-test times: run a test binary with `RUSTC_BOOTSTRAP=1 <binary> -Z unstable-options --report-time` from its package dir; CPU per test with `/usr/bin/time <binary> --exact <name>`. Where a test's CPU goes: `tools/cpuprof OUT <test binary> --exact <name>` (an LD_PRELOAD SIGPROF sampler: no perf or gdb here; inclusive and self shares per function); over a whole binary (`--test-threads=8`) it shows what all tests share. The sampler's own work counts in `tools/icount` (about 3.5% of a binary), so count without it; it kills the perm `it`, crypto lib and transport binaries ("Profiling timer expired"). A test binary run outside cargo runs proptests at 256 cases: set `PROPTEST_CASES=32 PROPTEST_DISABLE_FAILURE_PERSISTENCE=1` as `.cargo/config.toml` does.

## Not covered
The scale properties with no counter (notes/test-scale.md), the TLA+ "not covered" list (notes/test-properties.md, Models), QUIC and P2P over real sockets outside the by-hand networking check, browsers, real networks beyond localhost, GUI smoke tests of the app, and a 10^4-seed sim sweep per scenario (about 6 h on a quiet 16-core box).
