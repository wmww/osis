# Engine: paged state and large values
> Summary: How the engine keeps big states and big values at O(change): which collections are paged and how a session loads them lazily, paged sequences through the stored placement, streamed apply and streamed readers of held parts, what is still a whole rewrite, large values (chunking with reuse, reads, `edit`), freed links (deleting a dropped body's pieces by link) and their re-encryption repair, and the measured costs. Code: `engine/pages.rs`, `engine/large.rs`, `apply/atomic.rs`; store layouts: notes/engine-store.md; wire paging and large values: spec/crdt.md §8, spec/data-model.md §6, notes/data-model.md. Not here: the store's units and key tree (notes/local-store.md), osis-crdt's placement (notes/crdt.md Held in part).

## Paged state (`engine/pages.rs`)
- A state above `PAGE_TARGET` pages every collection of at least 64 elements (`MIN_PAGED`) encoding to more than 8 KB, at any depth below struct fields, enum payloads and map entries (`Step`, `Paths`; inside a paged collection's elements too). List elements and `Slots` slots are not stepped into: a list element's position needs the sequence's placement and its record's anchors, a `Slots` slot the register embedding, both osis-crdt work tied to the sequences item of issues/node-sequences-not-paged.md. The rest is the skeleton (`Fragment::reduced`). Pages are size-split rows of the aspect's table 0, not content-defined: local pages need no history independence.
- **Lazy in memory**: a session loads the skeleton, then what it needs:
  - a read at a path (`Engine::get_at` → `Tx::ensure_paths`): the pages of the map keys along it through the index, the first page of each paged collection passed (it restores the entries the skeleton reduced away), of a paged sequence the element's block and page through the stored placement (`step_index`; without one every page), everything paged below its end;
  - a write whose ops address map keys, fields or set values only (`pages::op_paths`: an add or remove by value addresses the value as a key step, found through the index; a key or value with struct or map parts anywhere on the path loads whole, since the crdt matches it as the writer's type projects it; a large key or value, held as a link, is looked up by its link's content hash, `large::lookup_form`, also in `get_at`; `chunk_op` writes a large added element whole, matches a large removed one by hash and puts the held link (else a new tree) for a large key on a path);
  - a join (`ensure_touch`: the pages holding the delta's dots; of a sequence the pages its records span);
  - anything else loads every page (`Tx::load`).
- **Writes**: `Tx::set_state_touched` rewrites only the touched pages (`touch_of` = `Fragment::touched_paths`; a reset at or above a paged collection, a case change above it or another encoding writes whole) and the skeleton when it changed (whole once it passes `PAGE_TARGET`), splitting a page past 16 KB (pieces written shredded), dropping an emptied one, re-laying out when one element outgrows `PAGE_TARGET`. Everything else (`Tx::set_state`: every rebuild, so every validity flip, body drop, expiry, purge or strip, notes/engine-validity-rebuild.md) writes the whole state, the old pages dropped shredded (`pages::write_full`).
- Table 1 (map keys and set values: set ID ‖ keyed hash ‖ dot) is a superset, rebuilt with the layout: rows of entries left keyless or elements left value-less stay until the next whole write.
- A cached state is `None` exactly when the whole state is empty, as a rebuild leaves it (`Tx::kept`): an empty loaded part loads every page first (rare: an un-merge emptying all that is loaded). Cheaper rules are wrong: the skeleton drops a record holding only paged content, so an empty loaded part need not reach a collection whose pages hold elements (a rogue's lone unpaged key un-merged would drop a valid paged map), and an emptied first page stays (seed 262094).

## Paged sequences
- A paged text or list keeps its placement in table 2 (layout: the comment above `Place` in `pages.rs`): the crdt's cached placement in its stored form (`osis_crdt::SeqPlace`: every node with its span, creation, parent, HEAD flag, visibility and depth, in blocks with their visible counts, least depths and shifts listed in group rows beside the top; the dot → block map in chunks keyed by first dot; waiting anchors, broken-cycle nodes and a stamp at or above every position write's in the top). Exact when present: a write it does not follow removes the top, and a read finding it missing (or a row damaged) lays it out anew (`rebuild_placement`).
- A session reads the top, groups and chunk list once (`held`) and the blocks and chunks an operation misses (`fill_place`): a placement held in part attached to the sequence held in part (`attach`, its cover the loaded pages' dot ranges) notes what it misses (stub blocks and chunks, records outside the cover, and any whole pass over the records held, which the sequence notes even after dropping the placement: `Seq::part`) and fails; the caller loads that and runs again.
- Reads by index (`Engine::get_range` → `pages::seq_range`) read the blocks covering the range and the pages holding their dots. Joins (`ensure_touch`): the pages the delta's records span, then up to `PREFETCH` (8) dry runs of the follow (`Fragment::dry_follow`, about one pass of follow work in all) loading what each missed, then the placement is attached and the join follows it.
- Ops by index (insert, delete, move, paste, several in one commit), an `Op::Edit` (what `osis::text` writes; `seq_diff::edit` resolves it at base's indices when the read matches base over the changed middle and 32 elements each side, else it looks at every record: loaded whole; a list's whose items have large parts loads the elements at its window up front, `attach_ops` → `load_range`, and resolves only when the list lends their links there) and any op inside an element at an index (`step_index` loads the element up front, so `chunk_ops` finds a large value held) run on the pages loaded (`attach_ops` from `commit_in`) and run again after loading what they missed (`absorb`, up to `OP_RUNS` (8), then whole). Each whole load is counted in a cost span (`paged op whole: whole pass` for a layered follow or placement failing other than by a miss, `: every record` for an edit or presence looking at every record, `: runs` past `OP_RUNS`); the paged tests assert none.
- A local insert's follow takes its anchor from the placement (`Lin::placed`, not the anchor's record) and, stamped above the placement's newest position write (`newest`, kept with the top: a node's own commits), places right after the anchor without its children's edge stamps (`slot`), so a cold insert loads only the page its new record goes to.
- Sequence pages target 3 KB (`SEQ_PAGE_BYTES`, other collections 8 KB): an op decodes and rewrites each page it touches whole, one record per visible element, so at 8 KB (about 8000 chars) page decode and join are most of a cold edit's time (8 KB pages cost about twice the time per op); above the store's 2 KB inline limit, so a page write leaves its neighbours' leaf alone. The placement keeps two levels (top and groups, then blocks): a one-level summary above the inline limit goes to its own unit on every edit (12 → 30 KB per edit).
- A whole load (`ensure_set`, `load_all` → `place_whole`) loads every block and chunk and makes the stored placement the sequence's cache, so a whole session's ops and joins follow it; not while a change is under way (`pending`, from `ensure_touch` to `write_touched`: then a whole pass). `write_touched` writes what the followed placement changed against the stored one (`SeqPlace::diff`: blocks, gone blocks, chunks, chunk list, changed groups, top), a whole one not descended from it whole, and anything else (a reset, a strip, a shred, a rebuild, a follow fallback or miss) removes the top (`invalidate_placement`). The stored order equals a whole pass whenever present; its node split may be finer than a whole pass of the records as reloaded (pages drop deleted chars, so decoding merges their records into range records), which leaves the order and the ops' writes as they are. A move's follow finds the end of moved subtrees by depth, which after many moves can read most blocks.
- Still whole: a list edit whose window the list does not lend, an edit whose base no longer matches the read near its change, a `Slots` text.
- Oracles: `seq_placement_differential_{text,list}_spec_crdt_6`, `..._after_reset_...` (every stored page holds whole records), `seq_cold_edits_keep_placement_spec_crdt_6_1` (cold ops, two-op commits, received concurrent deltas; deltas equal the whole state's), `seq_whole_session_and_hostile_delta_spec_crdt_6_2`, `seq_placement_damaged_rows_spec_crdt_6`, the crdt's `snapshot_edits_follow_cache_spec_6`, `index_ops_on_partial_placement_match_whole_spec_5_7` and `partial_placement_skew_piles_and_joins_spec_6_1` (skewed clocks, sibling piles).

## Streamed apply (`apply/atomic.rs` `joins`)
- `examine` decodes whole only role-class and `created.0` parts (`Parts::whole`: perm, rotations and creation records read them whole); every other part is checked by `osis_commit::stream_part` with a callback keeping nothing (carried writes stamped after the commit are refused there) and streamed again at apply, decode-only (`each_piece`, `osis_commit::read_part` of a `Checked` delta: the transaction shared through a `RefCell` between the page source and the join; a failure then is `Corrupt`, a local error). Each piece joins (`join_into_state`) and its state pages are evicted (`Tx::evict_pages`: written already; not while the aspect pages a sequence, kept whole for its placement).
- A piece resetting or re-encoding a paged collection joins a page at a time (`pages::join_reset`: skeleton joined, each reached page joined under the two spines along its path, `Fragment::spine`/`reaches`); re-laid out whole only when a collection changed encoding with elements left or lost its position (pruned by the reset: no set may outlive its position, seed 262014), an element outgrew a page or the skeleton the unit; whole for paged sequences, collections paged inside another's elements, or another encoding above a paged collection.
- Per part across pieces: a valid snapshot's vouching, its deaths (marking the bodies they may replace where a body has a relative bound). An invalid delta joins nothing: the aspect is rebuilt once the commit is stored (notes/engine-validity-rebuild.md).
- A record on a paged collection's path whose content is all paged keeps its creation only in the set's keyed path (the skeleton drops it); every write of the set takes the path again from the joined state, a page of each touched set loaded to hold it (`PageSet::path`, also for an element-less `W` delta), else a creation arriving after the content (a delayed fill) would be lost to the store. Rejected: keeping the path's records in the skeleton instead. As plain crdt data a record whose loaded content is only an emptied collection is crdt-empty, so `prune(None)` (every un-merge and strip) drops it and a join into its struct replaces the empty stub, both while the pages still hold its elements; it would need a non-lattice "paged" marker in osis-crdt (codec, equality, prune, clearing) or a page loaded under every record an op touches, neither simpler than the re-take.
- Piece order is immaterial to the state (joins commute). Skipping a piece's page write is caught in the reset path by asserting the stored pages hold nothing their skeleton prunes (`Engine::stale_page_writes`: loading prunes again, so reads hide it).
- Oracle: the pre-streaming join (`apply/oracle.rs`, `Core::whole_apply`), swapped in for the join alone inside `atomic::join_part`, so every other decision of a part's apply (own whole replaces, cover candidates, deaths noted) has one place in both worlds; `apply/tests_paged.rs` runs random histories in both (the default test one seed; `paged_apply_matches_whole_large_spec_crdt_8` 24 seeds, each state also reloaded from the store after every step: the cache can hide what the store lost), plus hostile paged snapshots (late carried write, keyed removal, unknown encoding, missing pages: the same error or outcome as whole), ones copying held writes otherwise, an invalid paged delta, and an apply failing midway after spilling (`Core::piece_fault`: nothing left).

## Streamed readers
- What reads a held part again goes through `apply::each_held_piece` (the stored part, or its leftover, decoded again a piece at a time, decode-only, `atomic::stream_stored`, shared with apply's `each_piece`; per part a snapshot's frontiers and `Absorbed`), and a piece read against the state through `Tx::state_at` (the skeleton and the pages the piece's dots reach, evicted after; all pages where the piece resets a paged collection).
- **Checked once.** A stored record holds only parts `examine` checked in full (bad, junk, unjudged and waiting parts leave the blob before it is stored; a rewrite only removes parts), so every read of a stored part is decode-only: `stream_stored` and `examine_stored` (whole: `held_parts_at`, edges, the open) take `osis_crdt::Checked`, made only where that holds: `apply::checked`, the engine's one `Checked::verified` (tools/policy.py refuses others in product code), used by `each_piece` after `examine`, by `each_held_piece` and `examine_stored` on stored records, and by `state::decode` on stored states, state pages and leftover bodies (this node's own `state::encode` output, canonical as written). The store backs it: records and pages are AEAD units under the key tree, and pages are also checked against their link hash on every read, so bytes that changed on disk fail to open, and a decode-only read still enforces the grammar and structural limits (an error, never trust). Bytes not yet checked (received, pending, parked: `examine`, `retention::pending`, `rotation::lost::authentic`) go through `stream_part`/`verify_part`.
- Streamed: retention (`drop_part`'s shredding, `make_leftover`, `covered`'s snapshot side, `live`, `snapshot_live`), `rebuilt`'s bodies, and an open rebuilding the index.
- **Read at positions** (`apply::held_part_at`, `covered`'s snapshot side): the part's skeleton and only the leaf pages holding the given fragment's positions, named by the part's page index (`osis_crdt::PageIndex`: per paged position, each leaf's first element and, for a sequence, the furthest dot a run up to it covers; leaves ascend by element, checked at the seams when the part is first examined, so these bound what each holds; a run can cover dots of another source's record sorting inside it, so a next leaf's first does not end a sequence leaf). The first read streams the whole part and builds the index, kept in `Core::decoded` per write of the record (about 30-60 B per leaf). Where `part_at` takes a collection whole (below a map entry, an enum, encodings that differ) every leaf of it is read. So a cover judgment costs the root, the body's pages and the body, flat in the snapshot's size (`decoded::tests::cover_judgments_read_the_bodys_pages_spec_commits_5`); a stripped part (its leftover) is read whole. Law: crdt `stream_check_matches_whole_spec_8` (the named pages give the part every page gives). Rejected: keeping the snapshot decoded whole for many judgments (memory O(state) per held snapshot, or a cap above which the cost returns). Not kept in `ix.snapshots` beside the carried-valued bound: that bound is index state rebuilt and checked with the index (`check_rebuilt`), the page index only a cache of the record's bytes that any read rebuilds.
- Left whole: `replaced_at`'s judged part and each held body of its aspect read into `HeldWrites` (`deaths`, `read_held_writes`: winners are taken over a whole part, a map dot's records and a range record's elements together; dead writes being a set of positions, streaming them is possible), role-class bodies (`keys`/`secrets` readers, `drop_part`'s role bodies), `covered`'s body (both sides streamed needs a pull decoder walking them side by side), the writer paths (undo's before state, large values' links), and what is a whole state by nature (`rebuilt`, copy indexes: O(part)).
- Oracle: `retention/oracle.rs` (the whole readers) checks `covered`, `delta_live` and `replaced_at`'s `deaths` (the state's pages at the part's positions against the whole state) in the engine's own tests only (`cfg(test)`: osis-node's oracles do not reach it, and their values are too small to page; `tests_paged::covered_paged_fill_purged_*` drives a leftover from a coverer's pieces).

## Whole rewrites (O(aspect state) or more)
Every rebuild (a validity flip, a body dropped at its bound or as covered, a purge, a strip, a re-arrival: also O(aspect history), every held body re-joined; notes/engine-validity-rebuild.md); a reset of a paged collection or of a position above it where `join_reset` does not apply (a paged sequence, nested paged collections, another encoding above one); a page whose one element outgrew `PAGE_TARGET` and a skeleton outgrowing it (both re-lay out once); any op neither addressing map keys, fields or set values nor served by a sequence's stored placement (loads every page, e.g. a `set` of a whole value at the root: O(value) anyway; a whole load attaches the stored placement); `Engine::get` of a whole value. The persisted index is rebuilt from every commit record once per build (notes/engine-store.md). issues/node-sequences-not-paged.md lists what remains.

## Large values (`engine/large.rs`)
- **Writing**: `chunk_ops` chunks the large positions of `set`/`replace`/`add` values and list `insert` and `edit` items before the ops resolve, one `BlobWriter` per position, framed like the delta. A text's items are characters. An `edit` item the list lends keeps its link, `base` items become hash-only links that match the list's read; the list lends the links its read holds at the edit's window (`osis_crdt::edit_window`) when it has base's length and reads there as base by content hash (`large::window_links`), else every link it holds; at the window base's and new's common items outside it take base's form, so the crdt trims them alike (`large::list_edits` hashes the items once per commit). An `edit` writes only the trees of items not held. `build_and_apply` releases the fresh blobs the encoded delta does not link (`delta_links`).
- **Reuse**: a `set`/`replace` position whose state holds a link builds the new tree `BlobWriter::reusing` a `Reuse::index` of that tree (up to `MAX_REUSE`, 16 GiB): equal chunks keep blob and key unless `Framing::keeps` says re-encrypt (under each old link's link blind: no header needed, notes/crypto.md Delete keys), a chunk not held is written afresh; a reused blob keeps its link verbatim (salt and Del included) and nothing lists it. Edit cost (format constants, about 100-250 KB chunks): blobs written and uploaded = the changed chunks plus the root node (`write.rs` `large_edit_reuses_chunks_spec_sync_1`, within 1.03-1.1x of the new-chunk bytes). Local CPU stays O(value): the new value is hashed, every reused chunk read and compared, the old tree's nodes indexed.
- **Reading**: `read_large` reads whole up to `MAX_READ` (1 GiB; `read_large_max` with a caller's bound); streaming only through `next_chunk`. API seeks past the end clamp to the end (`io::Seek`).

## Freed links and repair
- **Freed sets** (`retention/freed.rs`, spec/sync.md §7 Freed links; design: notes/chunk-links.md): a body dropping (`drop_part_for`, not as invalid; a delta going to its leftover, `put_leftover`; a memory commit forgotten, `unindex_commit`) puts the links its deltas hold (`freed::part_links`: `delta_roots` of the stored delta, value roots and pages; a leftover's value roots) into rows `fl/` + blob + tid, in the body's class, and notes each new row in `Core::freed_due`. Every transaction ends by judging those rows and the waiting rows of their things (`settle_due`, after rebuilds; a dropped source may be what they waited for): a link `tree_refs` finds reached is removed (kept); one not reached, held, whose prefix does not bear its Del under its thing blind (`tree::bears`) is removed with nothing dropped (a link copied from another thing, a false Del); else it is judged: a node or page is walked (`large::kids_of`, without the dedup check for a thing whose record went) and its links added, the key zeroed (only blob, salt, Del, thing blind, author stay: the drop's shredding holds, `shred::` tests), `borne` set if its bytes were held. A held source's node not held (`Trees::missing`) or a freed node not held leaves the links waiting, keys kept, indexed by that node in `Core::freed_waits` (memory only; a start judges every row). Links judged freed go to `Core::freed_new` (a waiting row judged again included: no pass may have it in scope); a part dropping marks its links due even when their rows exist, so the waits of its thing are judged again. A woken row judged freed is handed on as fresh (`Judgment::fresh`: its entries touched, so its own label's pass deletes it, whichever pass woke it). **Judged by blob, never the whole set**: a judgment reads only the rows it is given (`Engine::judge_freed`: the rows of some blobs, plus the rows waiting on a node held now), so its cost is what changed. node-sync (`SyncEngine::freed_now`) judges the blobs `freed_new` names (from `forget_dropped`) and, in each pass, the scope's blobs whose delete is not in flight (a resend's turn), just before it sends; at start or a full judgment it judges every row a store page at a time (`freed_sweep`, `Engine::judge_freed_page`). First judged: bytes still held go (`delete_blobs`, memory charge released), entries touched and labels marked, so their passes take them in scope; node blobs waited for are fetched where present (`Engine::freed_wants`), deletes go by the label key when `borne` else by level (`freed_delete`, `Engine::freed_delete_secrets`: levels 1 and 3 along the thing's chain, 2 along the body author's), and a judged link no entry names leaves the set (`Engine::freed_done`). A judged blob arriving is not stored (`Engine::is_freed`). Lost access: `freed::lost` drops the thing's rows and waits and releases what the forgotten parts reach that nothing kept reaches and whose prefix bears its link.
- `engine/tree_refs.rs`: each source's trees (a held commit's parts on the thing, an aspect's state) are a memo (`Core::tree_refs`, notes/engine.md Derived values), read again only when its record, leftovers, meta, state or the thing's dedup secret moved; a question lists the thing's sources and asks each (a memo hit), then looks up each candidate. No hand-placed marks: the stamps the other memos rest on cover every input but blob presence, which has no stamp; node blobs are immutable, so a kept walk differs only where a node it lacked (`missing`) is held now, which the question checks and then `Memo::forget`s that answer. Debug builds compare every question's answer with a fresh read of every source (a wrong answer loses a held chunk). A body source's roots are its stored deltas' links, pages included (`freed::part_links`). Scale: `scale::chunk_drop_judgment_is_flat`, `freed::tests::an_edits_drop_frees_flat_in_value_size_spec_sync_7` (parts read and tree blobs walked; memo hits per question still grow with the thing's sources).
- The pass also uploads, with each body a writer places, the held blobs its own deltas link (`body_blobs` → `Engine::body_links`: the trees of its values and its pages, through held node and page blobs; cached per body once complete): at a peer that lost the label, or under a label new to the body, a reused chunk or a snapshot's value would otherwise be linked and absent. Only what the body links: the live state of other things the commit touches may lie outside the label's closure.
- Residue: a tree (of the live state or any held body) whose node blobs no reachable host or peer holds keeps its thing's freed links waiting for good, and their keys with them. A piece is judged from the sources held, so a co-writer's concurrent reuse can lose it at a host (tombstoned, so never re-uploaded by ID; repair below). A body dropped as invalid frees nothing (it stays at hosts as a refetch source, notes/engine-retention.md Invalid bodies), and a later drop of that part by a right does not free it either: its pieces wait for their expiry. Cost: a judgment reads the rows of what changed or what it sends (`deletion::unrelated_writes_judge_no_waiting_freed_link_spec_sync_7`: 0 rows for ten writes beside a waiting purge of 17 or 134 pieces; `freed_judgment_linear_in_pieces_spec_sync_7`); memory per judgment is its batch (a pass's scope, a store page, a drop's walk). `freed_waits` holds the waiting rows, plus any judged by another path meanwhile (a pass's scope, a drop of their thing) under a node not held yet: they leave when it comes or at a restart, so only a node no host holds keeps them. Rows last until every host acks, about 12 000 for a dropped 1 GB value. A drop past a host's delete rate is resent whole every `RESEND_MS` and judged with each send (issues/delete-resend-past-rate.md). Lost access (`freed::lost`, rare) scans every row's key to find the lost things'.
- **Repair** (spec/sync.md §1): a `LogEvent::Deleted` of a non-commit blob gone from every host of the label queues it under the label (`relink_pending`; with one host per label that host alone decides; each pass first drops the queued blobs no longer held, so the queue stays within the store however long the label waits). The label's next pass judges it (`SyncEngine::relink_lost`), after the batch that brought the delete is applied and with the label settled, as deletes are judged: nothing while an entry of the label is unopened (a body announced without bytes, a commit pending), no aspect a pending commit touches (it waits for a later pass). So a purge or role commit arriving with the deletes it justifies counts (`deletion::chunk_deletes_judged_after_their_batch_applies_spec_sync_1`); judged inside the batch it revived the purged value. `relink_lost` calls `Engine::relink`, which looks for each held queued blob among the things of the closure of the pass's group: the aspects of a thing whose live states' trees link one (`tree_refs::state_refs_in`, the tree memo; every thing of the closure is asked, a rare path) are the candidates, and, per field (`relink_field`; a field that fails, e.g. a blob not held, is skipped, the rest go), needs write on the thing and an own content commit whose valid delta's trees hold it, takes retention, expiry and schema from the newest held commit linking it (the thing's required retention governs instead when one is in force), and writes only the large positions of the current value whose tree holds it (`osis_schema::link_positions`) with `Op::Put` (a register write, no reset) and `Mutation::fresh` (`Reuse::exclude` re-encrypts it and the nodes above). One commit, if any.
- The repair is a plain write with a fresh stamp: it overrides a concurrent unseen edit of that one position and can bring back an entry whose removal it has not seen (notes/crdt.md); bounded to the affected positions and rate-limited. Back-off per aspect (`relink_backoff`, `RELINK_BACKOFF_MS` 1 h doubling to `RELINK_BACKOFF_MAX_MS` 7 days) in memory only: a restart allows one more immediate repair per aspect. The queue is memory only too: a restart drops what waits (issues/relink-queue-lost-at-restart.md). An aspect held back keeps its blobs queued, the label not judged again before the back-off passes (unless new blobs are lost), and `Event::Tick` passes the label then (`relink_due`). Not repaired: set elements and map keys holding links, values whose own delta was compacted, an expired commit's values; with no schema registered for the AK the current value is read untyped (`Type::Any`).

## Costs counted
osis-node `scale::` (default tests, notes/testing.md Scale checks), each at n and 10n:
- A map entry edit (500 / 5000 entries of 200 B, at the root or in a map entry): 30 / 40 KB of store writes; a new session's first read of one key loads 2 pages, its first edit loads 3 and writes 1.
- Set ops by value, each in a new session (10^3 / 10^4 elements): 1-3 pages loaded, 0-1 written (the value index).
- A text by index, each op in a new session (80k / 800k chars, 3 KB sequence pages; by hand): a read of 100 chars 2-3 pages; an insert, a delete, a text session's `Op::Edit`, an undo: 3 pages and placement blocks loaded, 4-5 written, 40 / 70 KB of store writes. A move loads every placement block (issues/text-move-loads-placement.md). Store rows per cold insert: the placement table's leaf with the top and groups (about 5.8 KB) and the block's leaf (4-6 KB), the page, the commit record and index leaves (about 9 KB), the unit, a key-tree node.
- A read+write rotation (20 / 200 writers): 2.76 KB per remaining holder (budget in notes/chat.md); one more `secrets.0` entry afterwards writes the same few KB at both (the box map paged, only the skeleton rewritten).
- Snapshot joins and validity flips: notes/engine-validity-snapshots.md, notes/engine-validity-rebuild.md; keep bounds: notes/engine-retention-dating.md; open and first sync: notes/engine-store.md, notes/engine-apply.md.
