# Engine: paged state and large values
> Summary: How the engine keeps big states and big values at O(change): which collections are paged and how a session loads them lazily, paged sequences through the stored placement, streamed apply and streamed readers of held parts, what is still a whole rewrite, large values (chunking with reuse, reads, `edit`), freed links (deleting a dropped body's pieces by link) and their re-encryption repair, and the measured costs. Code: `engine/pages.rs`, `engine/large.rs`, `apply/atomic.rs`, `retention/freed.rs`; store layouts: notes/engine-store.md; wire paging and large values: spec/crdt.md §8, spec/data-model.md §6, notes/data-model.md. Not here: the store's units and key tree (notes/local-store.md), osis-crdt's placement (notes/crdt.md Held in part).

## Paged state (`engine/pages.rs`)
- A state above `PAGE_TARGET` pages every collection of at least `MIN_PAGED` (64) elements encoding to more than `PAGE_BYTES` (8 KB), at any depth below struct fields, enum payloads and map entries (`Step`, `Paths`; inside a paged collection's elements too). List elements and `Slots` slots are not stepped into: a list element's position needs the sequence's placement and its record's anchors, a slot the register embedding (issues/node-sequences-not-paged.md). The rest is the skeleton (`Fragment::reduced`). Pages are size-split rows of the aspect's table 0, not content-defined: local pages need no history independence. Table layouts: notes/engine-store.md.
- **Lazy in memory**: a session loads the skeleton, then what it needs:
  - a read at a path (`Engine::get_at` → `Tx::ensure_paths`): the pages of the map keys along it through the index, the first page of each paged collection passed (it restores the entries the skeleton reduced away), of a paged sequence the element's block and page through the stored placement (`step_index`; without one every page), everything paged below its end;
  - a write whose ops address map keys, fields or set values only (`pages::op_paths`: an add or remove by value addresses the value as a key step, found through the index; a key or value with struct or map parts anywhere on the path loads whole, since the crdt matches it as the writer's type projects it). A large key or value, held as a link, is looked up by its link's content hash (`large::lookup_form`, also in `get_at`); `chunk_op` writes a large added element whole, matches a large removed one by hash, and puts the held link (else a new tree) for a large key on a path;
  - a join (`ensure_touch`): the pages holding the delta's dots; of a sequence the pages its records span;
  - anything else loads every page (`Tx::load`).
- **Writes**: `Tx::set_state_touched` rewrites only the touched pages (`touch_of` = `Fragment::touched_paths`; a reset at or above a paged collection, a case change above it or another encoding writes whole) and the skeleton when it changed (whole once it passes `PAGE_TARGET`), splitting a page grown past twice its target (pieces written shredded), dropping an emptied one, re-laying out when one element outgrows `PAGE_TARGET`. `Tx::set_state` (every rebuild: validity flip, body drop, expiry, purge, strip; notes/engine-validity-rebuild.md) writes the whole state, the old pages dropped shredded (`pages::write_full`).
- Table 1 (paged map keys and set values) is a superset: rows of entries left keyless or elements left value-less stay until the next whole write.
- A cached state is `None` exactly when the whole state is empty, as a rebuild leaves it (`Tx::kept`): an empty loaded part loads every page first (rare: an un-merge emptying all that is loaded). Cheaper rules are wrong: the skeleton drops a record holding only paged content, so an empty loaded part need not reach a collection whose pages hold elements (a rogue's lone unpaged key un-merged would drop a valid paged map), and an emptied first page stays (seed 262094).

## Paged sequences
- A paged text or list keeps its placement in table 2: the crdt's cached placement in stored form (`osis_crdt::SeqPlace`: every node with its span, creation, parent, HEAD flag, visibility and depth, in blocks with their visible counts, least depths and shifts listed in group rows beside the top; the dot → block map in chunks keyed by first dot; waiting anchors, broken-cycle nodes and a stamp at or above every position write's in the top). Exact when present: a write it does not follow removes the top, and a read finding it missing (or a row damaged) lays it out anew (`rebuild_placement`).
- A session reads the top, groups and chunk list once (`held`) and the blocks and chunks an operation misses (`fill_place`): a placement held in part, attached to the sequence held in part (`attach`, its cover the loaded pages' dot ranges), notes what it misses (stub blocks and chunks, records outside the cover, and any whole pass over the records held, which the sequence notes even after dropping the placement: `Seq::part`) and fails; the caller loads that and runs again.
- Reads by index (`Engine::get_range` → `pages::seq_range`) read the blocks covering the range and the pages holding their dots. Joins (`ensure_touch`): the pages the delta's records span, then up to `PREFETCH` (8) dry runs of the follow (`Fragment::dry_follow`, about one pass of follow work in all) loading what each missed; then the placement is attached and the join follows it.
- Ops by index (insert, delete, move, paste, several in one commit), an `Op::Edit` and any op inside an element at an index run on the pages loaded (`attach_ops` from `commit_in`) and again after loading what they missed (`absorb`, up to `OP_RUNS` (8), then whole). An `Op::Edit` (what `osis::text` writes) resolves by `seq_diff::edit` at base's indices when the read matches base over the changed middle and 32 elements each side, else it looks at every record (loaded whole); a list's edit whose items have large parts loads the elements at its window up front (`attach_ops` → `load_range`) and resolves only when the list lends their links there. `step_index` loads an element at an index up front, so `chunk_ops` finds a large value held.
- Each whole load is counted in a cost span (`paged op whole: whole pass` for a layered follow or placement failing other than by a miss, `: every record` for an edit or presence looking at every record, `: runs` past `OP_RUNS`); the paged tests assert none.
- A local insert's follow takes its anchor from the placement (`Lin::placed`, not the anchor's record) and, stamped above the placement's newest position write (`newest`, kept with the top: a node's own commits), places right after the anchor without its children's edge stamps (`slot`), so a cold insert loads only the page its new record goes to.
- Sequence pages target `SEQ_PAGE_BYTES` (3 KB): an op decodes and rewrites each page it touches whole, one record per visible element, so at 8 KB page decode and join are most of a cold edit's time (about twice the time per op). 3 KB is above the store's 2 KB inline limit, so a page write leaves its neighbours' leaf alone. The placement keeps two levels (top and groups, then blocks): a one-level summary above the inline limit goes to its own unit on every edit (12 → 30 KB per edit).
- A whole load (`ensure_set`, `load_all` → `place_whole`) loads every block and chunk and makes the stored placement the sequence's cache, so a whole session's ops and joins follow it; not while a change is under way (`pending`, from `ensure_touch` to `write_touched`: then a whole pass). `write_touched` writes what the followed placement changed against the stored one (`SeqPlace::diff`: blocks, gone blocks, chunks, chunk list, changed groups, top), a whole one when not descended from it; anything else (a reset, a strip, a shred, a rebuild, a follow fallback or miss) removes the top (`invalidate_placement`). The stored order equals a whole pass whenever present; its node split may be finer than a whole pass of the records as reloaded (pages drop deleted chars, merging their records into range records), which changes neither the order nor the ops' writes. A move's follow finds the end of moved subtrees by depth, which after many moves can read most blocks.
- Still whole: a list edit whose window the list does not lend, an edit whose base no longer matches the read near its change, a `Slots` text.
- Oracles: `seq_placement_differential_{text,list}_spec_crdt_6`, `..._after_reset_...` (every stored page holds whole records), `seq_cold_edits_keep_placement_spec_crdt_6_1` (cold ops, two-op commits, received concurrent deltas; deltas equal the whole state's), `seq_whole_session_and_hostile_delta_spec_crdt_6_2`, `seq_placement_damaged_rows_spec_crdt_6`, the crdt's `snapshot_edits_follow_cache_spec_6`, `index_ops_on_partial_placement_match_whole_spec_5_7` and `partial_placement_skew_piles_and_joins_spec_6_1` (skewed clocks, sibling piles).

## Streamed apply (`apply/atomic.rs` `joins`)
- `examine` decodes whole only role-class and `created.0` parts (`Parts::whole`: perm, rotations and creation records read them whole); every other part is checked by `osis_commit::stream_part` with a callback keeping nothing (carried writes stamped after the commit are refused there) and streamed again at apply, decode-only (`each_piece`, `osis_commit::read_part` of a `Checked` delta, the transaction shared through a `RefCell` between the page source and the join; a failure then is `Corrupt`, a local error). Each piece joins (`join_into_state`) and its state pages are evicted (`Tx::evict_pages`: written already; not while the aspect pages a sequence, kept whole for its placement).
- A piece resetting or re-encoding a paged collection joins a page at a time (`pages::join_reset`: skeleton joined, each reached page joined under the two spines along its path, `Fragment::spine`/`reaches`). Re-laid out whole only when a collection changed encoding with elements left or lost its position (pruned by the reset: no set may outlive its position, seed 262014), or an element outgrew a page or the skeleton the unit; whole for paged sequences, collections paged inside another's elements, or another encoding above a paged collection.
- Per part across pieces: a valid snapshot's vouching, its deaths (marking the bodies they may replace where a body has a relative bound). An invalid delta joins nothing: the aspect is rebuilt once the commit is stored (notes/engine-validity-rebuild.md).
- A record on a paged collection's path whose content is all paged keeps its creation only in the set's keyed path (the skeleton drops it); every write of the set takes the path again from the joined state, a page of each touched set loaded to hold it (`PageSet::path`, also for an element-less `W` delta), else a creation arriving after the content (a delayed fill) would be lost to the store. Rejected: keeping the path's records in the skeleton. As plain crdt data a record whose loaded content is only an emptied collection is crdt-empty, so `prune(None)` (every un-merge and strip) drops it and a join into its struct replaces the empty stub, both while the pages still hold its elements; it would need a non-lattice "paged" marker in osis-crdt (codec, equality, prune, clearing) or a page loaded under every record an op touches, neither simpler.
- Piece order is immaterial (joins commute). A skipped page write is caught in the reset path by asserting the stored pages hold nothing their skeleton prunes (`Engine::stale_page_writes`: loading prunes again, so reads hide it).
- Oracle: the pre-streaming join (`apply/oracle.rs`, `Core::whole_apply`), swapped in for the join alone inside `atomic::join_part`, so every other decision of a part's apply has one place in both worlds; `apply/tests_paged.rs` runs random histories in both (the default test one seed; `paged_apply_matches_whole_large_spec_crdt_8` 24 seeds, each state also reloaded from the store after every step: the cache can hide what the store lost), plus hostile paged snapshots (late carried write, keyed removal, unknown encoding, missing pages: the same error or outcome as whole), ones copying held writes otherwise, an invalid paged delta, and an apply failing midway after spilling (`Core::piece_fault`: nothing left).

## Streamed readers
- What reads a held part again goes through `apply::each_held_piece` (the stored part, or its leftover, decoded again a piece at a time, decode-only, `atomic::stream_stored`, shared with apply's `each_piece`; per part a snapshot's frontiers and `Absorbed`), and a piece read against the state through `Tx::state_at` (the skeleton and the pages the piece's dots reach, evicted after; all pages where the piece resets a paged collection).
- **Checked once.** A stored record holds only parts `examine` checked in full (bad, junk, unjudged and waiting parts leave the blob before it is stored; a rewrite only removes parts), so every read of a stored part is decode-only: `stream_stored` and `examine_stored` (whole: `held_parts_at`, edges, the open) take `osis_crdt::Checked`, made only by `apply::checked`, the engine's one `Checked::verified` (tools/policy.py refuses others in product code), used by `each_piece` after `examine`, by `each_held_piece` and `examine_stored` on stored records, and by `state::decode` on stored states, state pages and leftover bodies (this node's own canonical `state::encode` output). The store backs it: records and pages are AEAD units under the key tree, pages also checked against their link hash on every read, so changed bytes fail to open; a decode-only read still enforces the grammar and structural limits (an error, never trust). Bytes not yet checked (received, pending, parked: `examine`, `retention::pending`, `rotation::lost::authentic`) go through `stream_part`/`verify_part`.
- Streamed: retention (`drop_part`'s shredding, `make_leftover`, `covered`'s snapshot side, `live`, `snapshot_live`), `rebuilt`'s bodies, and an open rebuilding the index.
- **Read at positions** (`apply::held_part_at`, `covered`'s snapshot side): the part's skeleton and only the leaf pages holding the given fragment's positions, named by the part's page index (`osis_crdt::PageIndex`: per paged position, each leaf's first element and, for a sequence, the furthest dot a run up to it covers; leaves ascend by element, checked at the seams when the part is first examined; a run can cover dots of another source's record sorting inside it, so a next leaf's first does not end a sequence leaf). The first read streams the whole part and builds the index, kept in `Core::decoded` per write of the record (about 30-60 B per leaf). Where `part_at` takes a collection whole (below a map entry, an enum, encodings that differ) every leaf of it is read. So a cover judgment costs the root, the body's pages and the body, flat in the snapshot's size (`decoded::tests::cover_judgments_read_the_bodys_pages_spec_commits_5`); a stripped part (its leftover) is read whole. Law: crdt `stream_check_matches_whole_spec_8`. Rejected: keeping the snapshot decoded whole (memory O(state) per held snapshot, or a cap above which the cost returns). The page index is not kept in `ix.snapshots` beside the carried-valued bound: that bound is index state, rebuilt and checked with the index (`check_rebuilt`); the page index is only a cache of the record's bytes.
- **Left whole**: `replaced_at`'s judged part and each held body of its aspect read into `HeldWrites` (`deaths`, `read_held_writes`: winners are taken over a whole part, a map dot's records and a range record's elements together; dead writes being a set of positions, streaming them is possible), role-class bodies (`keys`/`secrets` readers, `drop_part`'s role bodies), `covered`'s body (streaming both sides needs a pull decoder walking them side by side), the writer paths (undo's before state, large values' links), and what is whole by nature (`rebuilt`, copy indexes: O(part)).
- Oracle: `retention/oracle.rs` (the whole readers) checks `covered`, `delta_live` and `replaced_at`'s `deaths` in the engine's own tests only (`cfg(test)`: osis-node's values are too small to page; `tests_paged::covered_paged_fill_purged_*` drives a leftover from a coverer's pieces).

## Whole rewrites (O(aspect state) or more)
Every rebuild (also O(aspect history): every held body re-joined); a reset of a paged collection or above it where `join_reset` does not apply; a page whose one element, or a skeleton, outgrew `PAGE_TARGET` (re-laid out once); any op neither addressing map keys, fields or set values nor served by a sequence's stored placement (e.g. a `set` of a whole value at the root: O(value) anyway); `Engine::get` of a whole value. The persisted index is rebuilt from every commit record once per build (notes/engine-store.md). issues/node-sequences-not-paged.md lists what remains.

## Large values (`engine/large.rs`)
- **Writing**: `chunk_ops` chunks the large positions of `set`/`replace`/`add` values and list `insert` and `edit` items before the ops resolve, one `BlobWriter` per position, framed like the delta. A text's items are characters. An `edit` item the list lends keeps its link, `base` items become hash-only links matching the list's read; the list lends the links its read holds at the edit's window (`osis_crdt::edit_window`) when it has base's length and reads there as base by content hash (`large::window_links`), else every link it holds; at the window base's and new's common items outside it take base's form, so the crdt trims them alike (`large::list_edits` hashes the items once per commit). An `edit` writes only the trees of items not held. `build_and_apply` releases the fresh blobs the encoded delta does not link (`delta_links`).
- **Reuse**: a `set`/`replace` position whose state holds a link builds the new tree `BlobWriter::reusing` a `Reuse::index` of that tree (up to `MAX_REUSE`, 16 GiB): equal chunks keep blob and key unless `Framing::keeps` says re-encrypt (under each old link's link blind: no header needed, notes/crypto.md Delete keys), a chunk not held is written afresh; a reused blob keeps its link verbatim (salt and Del included). Edit cost (chunks about 100-250 KB): blobs written and uploaded = the changed chunks plus the root node (`write.rs` `large_edit_reuses_chunks_spec_sync_1`, within 1.03-1.1x of the new-chunk bytes). Local CPU stays O(value): the new value is hashed, every reused chunk read and compared, the old tree's nodes indexed.
- **Reading**: `read_large` reads whole up to `MAX_READ` (1 GiB; `read_large_max` with a caller's bound); streaming only through `next_chunk`. API seeks past the end clamp to the end (`io::Seek`).

## Freed links and repair
- **Freed sets** (`retention/freed.rs`, spec/sync-compaction.md §1 freed links; design: notes/chunk-links.md): a body dropping (`drop_part_for`, not as invalid; a delta going to its leftover, `put_leftover`; a memory commit forgotten, `unindex_commit`) puts the links its deltas hold (`freed::part_links`: `delta_roots` of the stored delta, value roots and pages; a leftover's value roots) into rows `fl/` + blob + tid, in the body's class, noting each new row in `Core::freed_due`.
- **Judging**: every transaction ends by judging those rows and the waiting rows of their things (`settle_due`, after rebuilds; a dropped source may be what they waited for):
  - a link `tree_refs` finds reached is removed (kept);
  - one not reached, held, whose prefix does not bear its Del under its thing blind (`tree::bears`) is removed with nothing dropped (a link copied from another thing, a false Del);
  - else it is judged freed: a node or page is walked (`large::kids_of`, without the dedup check for a thing whose record went) and its links added, the key zeroed (only blob, salt, Del, thing blind, author stay: the drop's shredding holds, `shred::` tests), `borne` set if its bytes were held;
  - a held source's node not held (`Trees::missing`) or a freed node not held leaves the links waiting, keys kept, indexed by that node in `Core::freed_waits` (memory only; a start judges every row).
  Links judged freed go to `Core::freed_new` (a waiting row judged again included: no pass may have it in scope). A part dropping marks its links due even when their rows exist, so its thing's waits are judged again. A woken row judged freed is handed on as fresh (`Judgment::fresh`: its entries touched, so its own label's pass deletes it, whichever pass woke it).
- **Judged by blob, never the whole set**: a judgment reads only the rows it is given (`Engine::judge_freed`: the rows of some blobs, plus those waiting on a node held now), so its cost is what changed. node-sync (`SyncEngine::freed_now`) judges the blobs `freed_new` names (from `forget_dropped`) and, in each pass, the scope's blobs whose delete is not in flight, just before it sends; at start or a full judgment every row, a store page at a time (`freed_sweep`, `Engine::judge_freed_page`). First judged: bytes still held go (`delete_blobs`, memory charge released), entries touched and labels marked, so their passes take them in scope; node blobs waited for are fetched where present (`Engine::freed_wants`); deletes go by the label key when `borne`, else by level (`freed_delete`, `Engine::freed_delete_secrets`: levels 1 and 3 along the thing's chain, 2 along the body author's); a judged link no entry names leaves the set (`Engine::freed_done`). A judged blob arriving is not stored (`Engine::is_freed`). Lost access: `freed::lost` (notes/engine-lost-access.md, Forgetting).
- **`engine/tree_refs.rs`**: counted by what moved, never walked whole. Per thing two reaches (`Core::tree_reach`: its live states', its held bodies'; a weighing asks the states' alone), each a count per link of the times it is linked from a source's roots and from counted nodes (a node's links count while a non-chunk link to it does; chunks are never read). A link is counted by what opens it (blob, hash, key): a second link to a blob by a wrong key, counted first, would otherwise hide the tree the right one opens (`freed::tests::a_wrong_key_link_to_a_live_node_keeps_its_tree_spec_sync_7`). Each source's roots (the links a held commit's parts on the thing or an aspect's state hold) are a memo (`Core::tree_roots`, notes/engine.md Derived values), read again only when its record, leftovers, meta, state or the thing's dedup secret moved. A question lists the thing's sources, counts the roots of each one whose memo moved since counted (the old down, the new up), and below them a level at a time, the changes summed per blob first (a new node's links shared with the node it replaced in the same question move nothing): a node first counted is read and its links counted up, one no longer counted has its kept links counted down. A node is immutable, so an unchanged subtree's count moves only at its top: an edit costs its changed tree path's nodes, each its links (at most `TREE_FANOUT`), and a memo hit per source, whatever the value's size (`compaction::trigger_work_flat_in_value_size_spec_sync_7`, `scale::chunk_drop_judgment_is_flat`; per question it still grows with the thing's sources). A node not held when read is `missing` until held, checked each question. Memory: a counted entry per tree blob of a thing asked about, until it is destroyed or the node restarts (issues/tree-reach-memory.md). Rollback: the roots self-correct (each question diffs against what it counted); a failed step or transaction drops the reaches its questions took (`Core::reach_log`), which may have read blobs it held. Debug builds compare every answer with a fresh walk of every source (a wrong answer loses a held chunk), also the lost-access question's answer (`kept_refs_in`, rare).
- The pass also uploads, with each body a writer places, the held blobs its own deltas link (`body_blobs` → `Engine::body_links`: the trees of its values and its pages, through held node and page blobs; cached per body once complete): at a peer that lost the label, or under a label new to the body, a reused chunk or a snapshot's value would otherwise be linked and absent. Only what the body links: the live state of other things the commit touches may lie outside the label's closure.
- Residue: a tree whose node blobs no reachable host or peer holds keeps its thing's freed links waiting for good, keys with them. A piece is judged from the sources held, so a co-writer's concurrent reuse can lose it at a host (tombstoned, never re-uploaded by ID; repair below). A body dropped as invalid frees nothing (it stays at hosts as a refetch source, notes/engine-retention.md Invalid bodies), nor does a later drop of that part by a right: its pieces wait for their expiry.
- Cost: a judgment reads the rows of what changed or what it sends (`deletion::unrelated_writes_judge_no_waiting_freed_link_spec_sync_7`: 0 rows for ten writes beside a waiting purge of 17 or 134 pieces; `freed_judgment_linear_in_pieces_spec_sync_7`); memory per judgment is its batch. `freed_waits` holds the waiting rows, plus any judged by another path meanwhile under a node not held yet: they leave when it comes or at a restart, so only a node no host holds keeps them. Rows last until every host acks, about 12 000 for a dropped 1 GB value. A drop past a host's delete rate is resent whole every `RESEND_MS` and judged with each send (issues/delete-resend-past-rate.md). Lost access scans every row's key to find the lost things'.
- **Repair** (spec/sync-ids.md §1): a `LogEvent::Deleted` of a non-commit blob gone from every host of the label queues it under the label (`relink_pending`; with one host per label that host alone decides; each pass first drops the queued blobs no longer held, so the queue stays within the store). The label's next pass judges it (`SyncEngine::relink_lost`) after the batch that brought the delete is applied and with the label settled, as deletes are judged: nothing while an entry of the label is unopened, no aspect a pending commit touches. So a purge or role commit arriving with the deletes it justifies counts (`deletion::chunk_deletes_judged_after_their_batch_applies_spec_sync_1`); judged inside the batch, it revived the purged value.
  - `Engine::relink` looks for each held queued blob among the things of the closure of the pass's group: the aspects whose live states' trees link one (`tree_refs::state_refs_in`; every thing of the closure is asked, a rare path) are the candidates. Per field (`relink_field`; one that fails, e.g. a blob not held, is skipped) it needs write on the thing and an own content commit whose valid delta's trees hold the blob, takes retention, expiry and schema from the newest held commit linking it (the thing's required retention governs when in force), and writes only the large positions of the current value whose tree holds it (`osis_schema::link_positions`) with `Op::Put` (a register write, no reset) and `Mutation::fresh` (`Reuse::exclude` re-encrypts it and the nodes above). One commit, if any.
  - A plain write with a fresh stamp: it overrides a concurrent unseen edit of that one position and can bring back an entry whose removal it has not seen (notes/crdt.md); bounded to the affected positions and rate-limited. Back-off per aspect (`relink_backoff`, `RELINK_BACKOFF_MS` 1 h doubling to `RELINK_BACKOFF_MAX_MS` 7 days) in memory only: a restart allows one more immediate repair per aspect. The queue is memory only too: a restart drops what waits (issues/relink-queue-lost-at-restart.md). An aspect held back keeps its blobs queued, the label not judged again before the back-off passes (unless new blobs are lost), and `Event::Tick` passes the label then (`relink_due`).
  - Not repaired: set elements and map keys holding links, values whose own delta was compacted, an expired commit's values; with no schema registered for the AK the current value is read untyped (`Type::Any`).

## Costs counted
osis-node `scale::` (default tests, notes/test-scale.md Scale checks), each at n and 10n:
- A map entry edit (500 / 5000 entries of 200 B, at the root or in a map entry): 30 / 40 KB of store writes; a new session's first read of one key loads 2 pages, its first edit loads 3 and writes 1.
- Set ops by value, each in a new session (10^3 / 10^4 elements): 1-3 pages loaded, 0-1 written (the value index).
- A text by index, each op in a new session (80k / 800k chars; by hand): a read of 100 chars 2-3 pages; an insert, a delete, a text session's `Op::Edit`, an undo: 3 pages and placement blocks loaded, 4-5 written, 40 / 70 KB of store writes. A move loads every placement block (issues/text-move-loads-placement.md). Store rows per cold insert: the placement table's leaf with the top and groups (about 5.8 KB) and the block's leaf (4-6 KB), the page, the commit record and index leaves (about 9 KB), the unit, a key-tree node.
- A read+write rotation (20 / 200 writers): 2.76 KB per remaining holder (budget in notes/chat.md); one more `secrets.0` entry afterwards writes the same few KB at both (the box map paged, only the skeleton rewritten).
- Elsewhere: snapshot joins and validity flips (notes/engine-validity-snapshots.md, notes/engine-validity-rebuild.md), keep bounds (notes/engine-retention-dating.md), open and first sync (notes/engine-store.md, notes/engine-apply.md).
