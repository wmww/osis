# Rust API
> Summary: The designed shape of the `osis` crate: a synchronous local data API (typed aspect keys, `at`, RAII subscriptions, a `Write` batch with `set`/`edit`/`overwrite`/`remove` and path ops, the acting actor as first admin, membership by `w.group(g)`, ephemeral things and aspects in memory, rights checked locally, bounded materialization), signals, an aspect's history (pages and a per-commit watch), the commit query with undo, redo and revert, text sessions, minimal queries, the sharing and sync surface (async only where another node is waited on), diagnostics; Tess's fixed directions; the footguns the shape closes and why; rejected shapes. Shape is the plan's target, to be refined with the example apps (Tess left it open).

## Rules
How to judge this shape, and the standing rules: notes/api-design.md. Planned changes: issues/api-refactor.md.
- Explicit choices today: the read limit (`HandleConfig::read_limit`), catching up before lowering a role (`SyncFirst`). Membership is a group op (a thing in no synced group gets `NotSynced`).
- Callbacks run on one dispatcher per database, in commit order; driven by its own thread (default) or the app's (`Dispatcher::Pump`, Watching).
- Undo: per actor by default, plus a view of all available changes in scope from which an admin may remove others' (notes/crdt.md).
- Async futures resolve by a channel from the handle's background runtime (tokio by default, or a `Handle` the app passes). A browser build later gets the same sync API over a worker-backed store.
- Vocabulary: thing, aspect, group, holder (of a group), actor, role, holder (of a role), device, host. CRDT internals, labels, blobs, epochs, keys and hosts' innards stay out, except in diagnostics and sync status.
- Internals: `osis::internals` (doc-hidden; the CLI's `inspect`, tests, sim and benches, never the app or chat): trait `Internals` on `Osis`, `ManualNet` for the doc-hidden `Runtime::Manual`, `node` = osis-node, `schema` = osis-schema, `core_types` (every core key), `Knobs` for `HandleConfig.internals` (test clock, seed, `connection_wait`, `transport`: in-process endpoints), `Opening` and its `create`/`open`/`pair`/`restore`/`connect*` for test harnesses that build store, hosts and config in one helper, implementation numbers (`HISTORY_PAGE`, `STREAM_CHUNK`, ...), socket helpers, `Ts`, `CommitId`, `LabelId`, `CreationRecord`, `Clock`, `ManualClock`, traits `ChangeRaw` (`.commit()` of a `ChangeId`), `Exact` (`.ts()`), `MemStoreMeasures`, `kept_writes`, `joining_node`, `host_limit`, `host_limits_unshown`, `socket_path_under`. Generated code has its own narrow path, `osis::generated` (`use osis::generated as osis_schema;`). A feature gate is ruled out (notes/build.md Feature unification).

## Handle and lifecycle
- the hosts given with `Runtime::None` is `Invalid` at `create`, `open`, `restore`, `pair`: nothing would sync and nothing would say so. A store's own hosts with `Runtime::None` stay allowed: the CLI's local commands, whose writes go out with the next networked one.
- `Osis: Clone + Send + Sync`; clones share one database, which closes with the last handle (drop is fine; `close() -> Result<Close>` returns `Close::Closed` once it is closed and its sync driver, host included, is gone, or `Close::StillOpen{handles}` at once while other user handles exist, a normal outcome: clones, upgraded `WeakOsis`, value streams, text sessions, a `Joining`). One person per database; a second person is a second store directory.
- `Osis::create(Store, &[HostAddr], Config) -> (Osis, Option<RecoveryCard>)`: new node, new person actor (recovery key owns it, this node is its admin), home group (the person itself, spec/sync.md §2) labeled on the hosts given. The recovery seed exists only in the returned card (none without hosts: nothing to restore from); the app shows or stores it, osis keeps none of it.
- `Osis::open(Store, Config) -> Osis` (existing store: its hosts are the stored ones); `async Osis::restore(Store, &[HostAddr], &RecoveryCard, Config)`; `Osis::pair(Store, &[HostAddr], &PairOffer, Config) -> Joining` (new device, offer made on an existing one; see Devices).
- `Store::{Memory(MemStore), Dir(PathBuf)}`. `Config { handle: HandleConfig, runtime: Runtime::None | Tokio(Handle) | Own, peers, relays: Vec<Url>, ephemeral_undo_bytes }`, `HandleConfig { read_limit (default 64 MiB), idle_commit (text sessions, default 2 s), dispatch: Dispatcher::Thread | Pump(wake), internals (hidden) }`, all defaulted: how one handle behaves, whichever kind. No transport to choose: QUIC, and in-process endpoints only for tests (`Knobs.transport`). A thin client takes `HandleConfig` alone, sync and undo logs being its node's. Without a runtime everything local works; calls that wait for another node fail `Network`; hosts given with no runtime are `Invalid`.
- A **client** is anything using the client protocol; a **thin client** is one with no store or keys; a node may be a client too (`connect_node`). `db.has_store()`. Nothing ties machine, transport and actor together. The default policy: a unix socket offers the protocol to the node's own user, unauthenticated, as the node's main actor (no security boundary there); a localhost or network listener lets a client act only as actors it has authenticated for. A credential naming its actor, the main one included, may come later: `NodeLogin` grows, and the node already says who a client is (`WHOAMI`), so nothing else moves. `async Osis::connect_socket(store_dir, HandleConfig) -> Osis` (notes/client-port.md; `store_dir` names the node by its store, the socket path hashed from it, symlinks followed, stays inside): tid-addressed calls go there (`Source::Remote`), `me`/`node` are the node's, process-wide calls the port does not carry are `Unsupported` (the sharing calls on a thing, `sync`/`unsync`/`sync_now` and `wait_synced` are carried; `wait_synced` waits at the node with its outcomes); `listen_socket()` serves it (needs a runtime; a store in memory has no socket, `Invalid`; test harnesses: `Internals::listen_socket_at(path)`).
- Clients with an actor of their own (notes/client-port.md §3): `db.add_client(until) -> (Tid, ClientSecret)` (mints the client's actor in the home group and writes `clients.0^`; the secret is shown only here), `db.clients() -> Vec<Client { actor, until }>`, `db.remove_client(actor) -> bool` (sessions end, roles removed with rotations, entry gone; sync and takes no options: all a client wrote went through this node, so there is nothing to catch up on), `db.rotate_client_secret(actor) -> ClientSecret`; local or the main actor's. Grants to the actor (`db.grant(g, actor, role, ..)`) are what the client reaches. `async Osis::connect(&[NodeLogin { addr, secret }], HandleConfig)`: a thin client at those nodes (all answering as one actor; no login is `Invalid`): `me()` its actor, what it may not read is unknown, writes by its rights; sharing, sync and process-wide calls `Unsupported`, but for `holders` and `leave` of its own actor's grant (both within what it may read).
- Sources per group (notes/client-port.md §6, §8): `async db.connect_node(&NodeLogin)` (`Ok` once the first attempt ended and the connection stays, up or not: `status` says, and it keeps trying; `Refused`, `Invalid`: nothing stays; dropped meanwhile, it stays as if returned), `db.disconnect_node(&addr) -> bool` (ends the connection for whoever holds it: what waits on it hears so); `async db.group_source(g, GroupSource::Local | Remote(addr))`, `db.routes() -> map<Tid, HostAddr>`; `Status.remotes: Vec<RemoteStatus { address: HostAddr, connected }>`; `Status.two_sources` (things reading at a connected node and also in a group carrying them to another source: writes refused `Invalid`, §8 of notes/client-port.md). A disconnected source is `Network`, never another's answer. Client listener: `db.client_listen(&[url]) -> Vec<HostAddr>`, `db.rotate_client_address() -> Vec<HostAddr>`. `Url` (checked by `FromStr`; `Hosting.listen`, `Config.relays`, `client_listen`), `HostAddr::new(&Url, key)`, `url()`, `key()`.
- Identity: `node() -> Tid` (this device), `me() -> Tid` (the person actor). An account is a group: `me()` is also its home group.
- `now() -> Result<Time>` (`Time`: milliseconds since the epoch, the one public time type, `osis_base::WallMs` by another name): the corrected clock commits are stamped with (spec/sync.md §6), for app timestamps; on a thin client its node's, `Network` when it cannot be reached (it used to fall back to this process's clock, unsaid).

## Keys: typed aspects and signals
- `trait RawKey { type T; fn ak(&self) -> &str; fn schema(&self) -> Option<&Schema>; fn decode(&self, &Value) -> Result<T, PathError>; fn encode(&self, &T) -> Value }` plus provided `ty`, `defaults` (retention, expiry, lifetime), `validate`: osis-schema's, doc-hidden, what the engine takes (`Ak` too). `AspectKey: RawKey` is what the API takes: generated keys and `Key`, not a bare name. `Key` (typed by a schema registered at run time, `Osis::key`) says what an app needs without the schema: `name()`, `value_type() -> Option<ValueType>`, `type_name()`, `default_retention()`.
- `ValueType` (`core/osis/src/value_type.rs`): a plain description for code handling aspects it was not generated for (the app's forms, the CLI's value text): `String`, `Text`, `Bytes`, `Bool`, `Int`, `Float`, `Thing`, `Time`, `Duration`, `Date`, `LocalTime`, `Any`, `Optional`, `Cases(Vec<TypeCase>)`, `Record(Vec<RecordField>)`, `List`, `Set`, `Map`, `Counter`, `Max`, `Min`. Types may be recursive, so what is nested is a `NestedType` (`get()` the shape, `name()` the declared name), one level per ask. `Schema` itself is not API.
- Untyped: `Ak` is an `AspectKey` with `T = Value` and no schema (writes go out untyped: no validation, core default retention). Typed: constants generated from a `.osis` file (`notes::BODY: Aspect<Markdown>`, `notes::TASKS: Aspect<Vec<Task>>`) carrying AK, schema, defaults and codec. A read through a typed key cannot be mistyped; a write through one is validated against the writer's schema (every declared field required, spec/versioning.md §5). Nothing about the schema goes on the wire.
- Lifetime (notes/ephemeral.md): the key's marker, typed or untyped (`AspectKey::lifetime() -> Lifetime::{Durable, Ephemeral, Signal}`: none, `~`, `*`); no schema flag. A value that lives while its author is there: `at(t, k).path(p).keep_alive(&v) -> KeepAlive` (or `at(t, k).keep_alive(&v)` for the whole aspect, typed) on an ephemeral key with a default expiry (notes/ephemeral.md Values that live while their author is there).
- `osis::core`: only what apps truly read and write by key: `NAME`, `BODY`, `TAG`/`Tag`, `REQUIRED`/`Required`/`RequiredRules`. The rest (`GROUP`, `ROLES`, `CREATED`, ...) is through calls (`members`, `grants`, `created`), and `internals::core_types` for tests.
- Typed reads map `string`/`markdown`/`text` to `String`, `blob` to `Vec<u8>`, `tid` to `Tid`, `timestamp`/`duration` to osis time types; records to generated structs and enums with `TryFrom<&Value>`/`From<&T> for Value`.

## Reads
- `db.at(tid, key) -> AspectRef<T>` with `.get() -> Result<Option<T>>`, `.path(p).get::<U>()` (`U = Value` for untyped; a typed key's whole stored value: an untyped key; per-path reads skip one bad element of a large collection), `.path(p).len()` (canonical size), `.stream() -> impl Read + Seek` (large string or blob), `.on_change(f)`.
- Every read below returns `Result` (a node that cannot answer is `Network`, never a default). `db.aspects(tid) -> Vec<Ak>` (what reads as present: a register whose live write was purged is listed by what it then reads), `db.knows(tid) -> bool` (the thing has content here: its creation held, or ephemeral here, and some aspect a `Write` sets present; `false` for an unknown tid and for a thing with no content, which is both a deleted one and one never written, so `!knows && created.is_some()` reads "empty", issues/api-knows-empty.md; an actor with only role-class data, a link key or a contact before any data, reads `false`; writes and grants need only the creation held), `db.members(g) -> Vec<Member>` (`Member::{Item, Subgroup}`, items then subgroups, tid order, `group.0` and `placed.0~`, the reverse of `groups_of`'s `item_of`, `subgroup_of`; a tid both ways appears twice; round-trips with `w.group(g).add`/`remove`; empty when it never had a member; `at(g, db.key("group.0")?).get()` tells a group from a thing that never had a member and durable members from ephemeral), `db.groups_of(tid) -> GroupsOf { item_of, subgroup_of, within }` (the groups whose `group.0` lists it as an item, those listing it as a subgroup, and `groups.0`: every group holding it as an item directly or through subgroup lists, what sync follows for its own aspects, not the groups it is only a subgroup of; `group.0` and `placed.0~`, from the in-memory group index rebuilt from the definitions at open, nothing scanned), `db.grants(thing) -> Grants` (the timeline's roster, spec/permissions.md §2; `db.holders(thing)` looks through holder actors), `db.role_on(tid) -> Option<Role>` (this node's effective role; UIs grey out what it cannot do), doc-hidden `db.owner_of(tid) -> Option<Tid>` (goes with owners). A thing's times, both `Option<ThingStamp { id: Option<ChangeId> (None for an ephemeral thing's creation), actor, node, written, received }>`, shown and sorted by `shown() = min(written, received)` (one skew rule: an author's clock may run ahead, by at most `MAX_DRIFT` before its commit is parked, and `received` is this node's clock; no app-written time field): `db.created(tid)`, the oldest valid commit carrying the thing's `created.0` that is no compaction snapshot (snapshots carry `created.0` too; `created.0` is kept forever, so it arrives wherever the thing does, and until then, only a snapshot here, `None`); `db.changed(tid)`, its last content change: of the held changes and reverts validly writing its aspects other than `created.0`, `group.0` and role-class ones (placement and sharing are no content change, of the item or of the group), the one with the latest `shown()`, else its creation (so never before `created`; a delete counts; ephemeral writes do not, so an ephemeral thing reports its creation; a change known only from a snapshot is not seen, Attribution, so after compaction on a new device it may read older than the truth). From the in-memory commit index: newest `ts` first per aspect, stopping once `ts` is at or below the best `shown()`.
- Stored data never fails a read on typed grounds (Typed reads below): a value that does not decode through the key reads as `None` and reports a `Mismatch` diagnostic. `Error::Type { path, reason }` is for what the caller passes: a typed write's value, a path the key's schema does not have.
- **Read limit**: a value whose canonical size exceeds `HandleConfig::read_limit` returns `Error::TooLarge { limit }` (the bound; a length is unknown without reading) from `get` and from any typed read; read it by `stream()` or by path (a path read into a huge map or list costs O(entry) and never loads the whole). Explicit failure beats an out-of-memory.
- Values are snapshots: plain `Value` or generated structs, nothing reactive hidden inside.
- `Path`: steps `Field(id) | Case(id) | Key(Value) | Index(usize) | Elem(Value)`; `p![..]` builds one from literals and generated field/case constants (`task::DONE`). Typed path builders from codegen are not built (optional).

## Watching
- `db.at(tid, key).on_change(|db, c: Change<T>|) -> Result<Subscription>`: taken atomically with the current value, so no change is missed between read and subscribe: the callback runs once with that value (`Source::Initial`) through the dispatcher like every later call, then on every change. Async code forwards it to a channel of its runtime and awaits that (crate docs); no second watch type (Tess). `db.on_thing_change(tid)` for all aspects of a thing (`Change<Value>` names the AK); a delete, local or remote, reaches it as its aspects going absent, and `knows(tid)` in the callback then reads `false` (no separate deletion event: a thing is deleted exactly when it holds no content). `db.on_grants_change(thing, ..)` (its callback takes `Result<Grants>`: a lost connection is told), `db.on_status_change()`; each `Result<Subscription>`, `Network` for a thing or its grants at a node that cannot be reached now.
- `Change<T> { ak, value: Result<Option<T>>, source: Source }` with `Source::Initial | Local(Stamp) | Remote(Stamp) | Derived(ChangeReason)` (`ChangeReason::{ValidityChanged, Expired, Purged, Arrived, LostAccess}`: what changed a read when no new change did) and `Stamp { id: ChangeId, actor, node, written: Time, received: Time }`. `ChangeId` is opaque (`Display`/`FromStr`, a commit or an ephemeral batch inside; a mixed batch is its commit). `Stamp`, `ThingStamp`, `Committed` hold the exact hybrid time privately for ordering. A signal aspect's set reaches each `on_change`/`on_thing_change` callback once (never coalesced). Display time for feeds is `min(written, received)` (a sender's skewed clock).
- `Subscription` is RAII: dropping it unsubscribes; `detach()` keeps it for the database's life. No ids to remember.
- Who runs callbacks (`HandleConfig.dispatch`): `Dispatcher::Thread` (default), a thread the database starts; `Dispatcher::Pump(wake)`, the thread that calls `db.settle()`, so a UI applies changes on its own thread with no cross-thread hop. `wake: Arc<dyn Fn() + Send + Sync>` is called once when callbacks become due after the last `settle` began, from whatever thread queued them, after it released the database lock (so calling the database there cannot deadlock): it should only schedule a `settle` (a UI loop event). `settle` is the one call for both: with a thread it waits for it (tests), with a pump it runs everything due (including what callbacks it runs cause), on the calling thread (after another thread's pump in progress). Inside a callback it returns at once. One dispatch implementation (`Pump::step` in `watch`) with two drivers.
- Coalescing: a callback that falls behind sees every commit's effect but not necessarily one call per commit. A slow callback delays later callbacks, never writes or sync. A watch on a value above the bound delivers `Err(TooLarge)` per change and the app re-reads by stream or path.

## Writes
```
let mut w = db.write();
let note = w.create()?;                                      // first admin: the acting actor; ephemeral until a durable write
w.group(folder).add(Member::Item(note))?;
w.at(note, notes::TITLE).set(&title)?;                       // make equal: structural diff against current state
w.at(note, notes::TASKS).edit(&shown, &edited)?;             // apply only what the user changed since `shown`
w.at(note, notes::TASKS).path(p![2, task::DONE]).set(&true)?; // path op
w.at(note, notes::BODY).overwrite(&body)?;                   // always a write, of the whole value
w.at(note, notes::VIEWS).path(p![]).contribute(&1)?;
w.at(msg, chat::BODY).expires(Expiry::In(DAY)).set(&text)?;  // retention and expiry per aspect write
w.at(note, key).remove()?;
w.group(other_group).expires(Expiry::In(DAY)).add(Member::Item(note))?;
w.group(folder).remove(Member::Item(note))?;
w.group(g).add(Member::Subgroup(sub))?;
w.delete(note)?;
let done: Committed = w.commit()?;
```
- Whole-value ops: `set(&v)` makes the aspect read `v` (the spec's structural diff against the current state, spec/crdt.md §9: concurrent edits inside the value survive, but a field the app did not touch is written back if it differs from the current state); `edit(&base, &new)` writes only the difference between what the app showed and what the user produced, as path ops against the current state (struct fields, enum case, map keys, set elements, bag values exactly; sequence edits rebased onto the current sequence by matching `base` to it, notes/crdt.md Implementation), so a remote change to another field during editing is never overwritten; `overwrite(&v)` writes the whole value, always, discarding concurrent changes inside it (an equal value still counts as a write, so a log such as a chat takes it: `set` of an equal value writes nothing; a map overwritten on a long aspect costs O(writes so far), a scalar stays flat); `remove()`. `edit` or path ops are the rule for anything a user edits while remote changes may arrive; `set` is for "the value must be exactly this" (imports, derived data). `replace` was renamed `overwrite`: it said nothing against `set`, and `TextSession::replace` means a range. Internals keep `Op::Replace`.
- Path ops at `.path(p)`, the empty path being the whole value (`at(k).set(&K::T)`, `overwrite` and `keep_alive` differ only by checking the type at compile time; `at(k).remove()` is the root's, the one shorthand, as removal is an aspect's usual end; `at` holds nothing else a path has): `set`, `overwrite`, `set_stream`, `remove` (the aspect at the empty path; a map entry, set element or list element: `p![k]`); list or text `splice(range, items)` (`SpliceItems`: a slice in a list, `&str` in text, `()` for nothing: a `&str` on a typed list is `Invalid`, an item of the wrong type `Type`, a backward range `Invalid`, nothing to do writes nothing), `move_range(range, to)`; set `add(v)`; bags `contribute(v)` (a counter's amount, a max or min's observation: one op). A map entry is `path(p![k]).set(v)`, an enum case a `set` of a `Value::Enum`. Index paths resolve against local state at commit time. A path op into a map key with no live entry creates the entry (spec/crdt.md §5.6): the first reaction to a message is `path(p![msg]).add(&emoji)`, and two devices doing it concurrently both count; a path on through a struct field or enum case is refused (`Invalid`: it would write a partial record; `set` the whole value). An entry created by an expiring write goes at T with everything later written into it (spec/crdt.md §4.7). `group.0` field ids are `core::group::{ITEMS, SUBGROUPS}`.
- `create() -> Tid`: a new thing, the acting actor its first admin (today: its owner, `self.actor` at the call, so after `act_as` that actor). `create_with_admin(admin) -> Tid`: the same with `admin` as first admin (today: its owner, needing write on it): a thin client's way to create, whose own actor goes with it, and a thing made for a group's holders. Owners going: doc-hidden `create_owned_by(owner)` for trees of things (needs write on `owner`, checked locally; an owner the same batch creates counts through its own owner, so a tree of new things is one commit), doc-hidden `db.create_ownerless(admin)`, doc-hidden `owner_of`. On a thin client's handle `create()` is `Invalid` at commit (its actor goes with it, notes/client-port.md §3), which leaves it `create_owned_by(g)` until owners go. The thing is ephemeral (record in memory, gone at restart) until its first durable write, which persists it with its ephemeral owner chain and makes its memberships durable in that commit, same tid (notes/ephemeral.md). Membership is `w.group(g).add(Member::Item(t))` in the same batch; adding an ephemeral thing is an ephemeral write of the group (it lists there and in `groups.0`, locally), adding a durable thing to an ephemeral group persists the group; a membership in a group the persisting node may not write stays ephemeral (`PlacementNotPersisted`). **A thing becomes a group with its first member** (no `make_group`): the batch's first add to a thing with neither `group.0` nor `placed.0~` writes an empty `group.0` first (`Write::first_member`; a `group.0` holding one field decodes as none, so a bare `Add` lost the member silently). So the first ephemeral member of a durable thing makes one durable write of the group; once a group, always (emptying it leaves `group.0` present). An empty durable group takes any durable write, as any thing does; `sync` and `grant` persist on their own. A shared space with its own label (a chat, a team) is created, given data and `sync`ed, not placed in the home group: the owner's devices find it through the home label's `label.0` cross-publish, while placing it in home copies every commit touching it (rotations with their boxes, messages) under the home label too (measured 8 KB per chat removal at 4 holders, the rotation's boxes at scale). The app's choice, not an API default. A group's items sync only through groups listing it as a subgroup (its members are its items and its subgroups' members, not its items' items), so a group meant to sync with home is both an item of home (its own aspects) and a subgroup (its items). The mistake is loud: a commit after which a placed durable thing reaches no synced group while the target group's own aspects sync (an item of a synced group, no subgroup of one) fails `Invalid` naming the fix, before anything applies (`Mutation::require_synced`, checked against the state the commit leaves, so the same batch may add the subgroup edge; also for the item placements a persisting write makes durable, a draft placed while ephemeral). Removing a subgroup edge that leaves existing items in that state is not checked. A durable thing placed only into groups that do not sync at all (device-local data, deliberate) is allowed and gets a `NotSynced` diagnostic after commit (spec/requirements.md, Offline and network). `w.group(g).expires(e).add(m)`: the membership expires too, item or subgroup (a disappearing message leaves its group by itself); `ExpiringGroupWrite` has only `add`, so an expiring removal does not compile (it would come back at T with its grant gone). A batch's writes of one aspect are one delta with one expiry, so all group ops on one `g` in a batch must agree on the expiry, and so a removal beside an expiring add is `Invalid`; the expiring `At(t)` and `In(d)` are different asks, equal or not in time.
- `db.create_ownerless(admin) -> Tid`: an ownerless thing (spec/permissions.md §1): no owner, so nobody ever acts through an owner chain on it; its admins are edges, all equal, the first `admin` (`me()`, or an actor this device administers) fixed by its tid. Durable at once, with secrets of its own; `sync` it for a label (`admit own` hosts do not take it), or place it. Its grants never compact and with no admin left nothing changes it; things it owns are ordinary (`create(o)`), their rosters compact. `Permission`, `UnknownActor` (no `keys.0` of `admin`); through a socket as Owner.
- `delete(tid)`: removes every aspect the node knows (not `created.0`, `required.0^` or role-class ones) and its placements and subgroup edges in every group this node may write (`groups_of`'s `item_of` and `subgroup_of`); a group it may not write keeps listing the tid, which reads deleted there. Afterwards `knows` is `false` here and wherever the delete arrives (unless a concurrent write left content). Tids never die and a later write recreates the thing; no wire concept. An ephemeral thing never synced under a label here is freed at once with the ephemeral things it owns (its tid reads unknown); one that was keeps its record and tombstones until restart, as a durable thing does.
- Rights are checked locally before signing: `Error::Permission { tid, needs: Role }` when the acting actor lacks write (admin for role-class aspects) on a touched thing; `Error::UnknownThing` when its `created.0` is not held. A write is never emitted to be un-merged elsewhere.
- `commit()` is one atomic commit over every touched thing, any owners and reader sets, of any size (deltas page, spec/crdt.md §8), plus the batch's ephemeral ops applied in memory after it (all or nothing). A commit has one expiry, and a `nobody` delta shares a commit only with `nobody` deltas (a thing's record and `required.0^` aside, spec/commits.md §5, §6): a batch mixing them is one commit per class, under one transaction and one `ts`, the one carrying the batch's thing records first (creating a thing with expiring content takes two). `required.0^` must share its commit with the batch's other writes on its thing (else `Invalid`). Returns `Committed { id: ChangeId, written: Time, also: Vec<ChangeId> }` (`pos()` its place in a history): `id` the first commit, `also` the others, each a change of its own to history, undo and revert. Two fields, not one `changes` list: a batch has at least one, and nearly every caller wants that one. Own watches fire after the commit is durable. Ephemeral ops take no `retention` or `purge` (`Invalid`); a signal aspect takes one root `set`.
- `Write` is `#[must_use]`; dropped uncommitted it discards its ops (debug log). Reads inside a `Write` see committed state only; pending ops are invisible until commit.
- The node acts through `me()`; `Write::act_as` sets the header's actor, under the node's rights; the node must hold write on that actor (else `Permission`), as receivers judge a commit invalid otherwise (spec/permissions.md §5.2), so a valid commit's actor is trustworthy. A thin client's rows run on `Osis::act_as` (crate-internal), held to the actor's own rights (notes/client-port.md §3); anonymous writing (notes/permissions.md) is later.
- Retention and expiry per aspect write: `.expires(Expiry::{At(T), In(d)})` (not calling it: the key's default) / `.retention(Retention)` on `AspectWrite`, defaults from the key; validated at the op (`Error::Invalid`, also for a time not in the future).
- Role-class aspects (`roles.0`, `keys.0`, `secrets.0`, `label.0`, `tenures.0`) are written only through the sharing and sync calls below; a `Write` op on them fails with `Error::Invalid`. `group.0` is written only by `Write::group` (it checks sync and cleans up tied edges), `Invalid` otherwise, also in a batch from a client.

## Text editing sessions
- `db.at(t, k).path(p).edit_text() -> TextSession` (`p![]` for the whole aspect): a buffer the UI edits (`text()`, `splice(range, s)`, `cut(range)`, `paste(at)` with remembered ranges so a paste is a move plus undelete when the clipboard still matches, notes/crdt.md); remote edits are merged into the buffer and reported through `on_remote(|text, edits: &[Splice]|)` (`Splice { at, del, text }` in chars, each at the text before it, from a char diff of the buffer and the merged text; `Splice::map(pos)` moves a caret: an insert at the caret goes after it) so the UI can map cursors; commits on `commit()`, after `idle_commit` of inactivity, and on drop. A session whose thing was deleted (locally or remotely) since it was known here (at open or a commit of its own) never recreates it: `commit()` fails `UnknownThing` with the edits kept (they commit if the thing comes back, e.g. an undo of the delete), and drop (which then loses them), the idle commit and a remote merge report an `Uncommitted` diagnostic. This owns the "one commit per editing pause, never per keystroke" rule (spec/requirements.md, Generality); apps never commit per keystroke by accident because the session is the only path that makes keystroke-granular changes convenient.

## Signals
A signal aspect (key marker `*`) holds nothing: `w.at(t, key).set(&v)` (one root `set`) fires every `on_change`/`on_thing_change` callback on it once, here and on the connected nodes that read the thing, best effort (notes/ephemeral.md). Needs write on the thing. Event-style signals should carry a sender sequence in their value (a node on several relays may see one twice).

## History (an aspect's commits, not its state)
- **Read**: `db.at(t, key).history(from: HistoryFrom, limit) -> Result<HistoryPage<T>>`, `HistoryFrom::{Newest, Oldest, Before(pos), After(pos)}`, in that direction (Newest, Before: towards older), neither bound counting itself; `HistoryPos` is opaque (`Ord`, `Display`/`FromStr`; `at()` its time, `change()` its change, none at a time's): an entry's `pos()`, a batch's `Committed::pos()`, `HistoryPos::time(t)` a time (`Before` it: stamped earlier; `After` it: from there on). `HistoryPage { entries, more, complete }`. A page ends early past an internal cap or the read limit, and `more` says so. An unknown thing, or one the caller may not read, has an empty page.
- **Entry**: `HistoryEntry<T> { commit: Stamp (id, actor, node, written, received), kind: CommitKind, valid, body }`, one per commit with a delta on the aspect, memory commits too, by `(ts, ID)`. `body`: `Held(Option<T>)` (read from that commit's own body, so a superseded one reads as written; `None`: a removal, or not a whole value of the key's type: a `Mismatch` diagnostic as for any typed read, the untyped key shows it), `TooLarge { limit }`, `Purged { by, actor }` (a tombstone, `actor` the request's verified actor: earliest request by `(ts, ID)`; lasting for a permanent delta, spec/commits.md §5), `Gone` (expiry, keep bound, compaction), `NotFetched` (header here, body not). `commit.actor` is verified exactly when `valid` (spec/permissions.md §5.2); an invalid body still reads, and the app chooses. A `CommitKind::Summary` (a compaction snapshot) is an entry of its kind (Attribution); a chat shows `Change`s.
- **A gap**: `complete: false` means a label carrying the thing has not finished a pass here (or the thing is held for receipts only), so entries may yet arrive anywhere in the history: not fetched, not absent. A new device's first sync (spec/sync.md §6) is this state: role commits, then newest first, so `HistoryFrom::Newest` reads real entries at once and `Before` pages older ones as they arrive; status `Syncing` until done. A device that chooses not to fetch (not built: issues/partial-history-fetch.md) would say the same. It does not bring what compaction replaced before this node held it: that is the snapshot's entry.
- **Watch**: `at.on_history(|db, HistoryEvent<T>|) -> Subscription`: `Commit { id, entry: Option<HistoryEntry<T>> }` per commit whose entry reads otherwise, read when delivered (a new message, a late older one, turning invalid or valid, a body arriving, purged, dropped; `None`: no entry any more, a memory commit gone). `Reread`: events may have been missed (the connection to a node dropped or came back, an entry did not fit a Notify): read the pages shown again. `Ended(e)`: over (the source moved, a lapse): subscribe again. No initial call: subscribe, then read pages; an event repeating what a page showed is harmless. Own ephemeral batches leaving the undo log past `Config.ephemeral_undo_bytes` are not told.
- **Delete for everyone**: `w.at(t, key).purge(Purge::Change(id))`; **by author**: `.purge(Purge::Author(actor))`; `.purge(Purge::All)` the whole aspect's, with its removal. Each judged per delta by the purge rights (spec/permissions.md §7), no override: under `author` or `nobody` an admin's request drops nothing, under `nobody` a flood stays (Tess; why it is not the default). A wide request's order independence has a known gap outside the chat's class: issues/wide-purge-order.md. `Purge::Author` names deltas stamped before the request, in any arrival order; later writes stay, so remove the member too. `actor` is one header actor: a person's devices share theirs, each of its thin clients has its own, so a member's writes through a client take their own request. An invalid commit is named by the actor it claims. Under a required expiry `Purge::All` and a `set` beside a request are refused (a commit with a request carries no `expires`); `Purge::Change` and `Purge::Author` alone work, as `purge.0` has fixed retention. A request needs write on the thing (`Permission` otherwise: no class gives a right without it) and carries a `purge.0` write, as its commit needs a delta to go under the thing's labels (spec/commits.md §5); so it adds no entry to the purged aspect and resets nothing: purging the live write of a register leaves it reading absent, `set` in the same batch for a value.
- **As built**: `engine::history`, `ephemeral::history`, `osis::history`. A page walks a range of `by_aspect`, O(log n + page); validity, author, time come from `Meta`, no decode but the page's. A memory aspect gathers its held commits and own batches (both bounded by the ephemeral caps). No index of its own, so none to keep exact. The watch is `Core::history_changes` at the end of a transaction, from the journal of `ix.commits`: which commits' parts changed `(valid, dropped, missing)`, O(commits changed), one place whichever path changed them, plus what the meta does not show (`history_named`: a dropped part now named by a request). Off until the first `on_history` of an open (`Engine::watch_history`, sticky). Purge requests are stored per aspect only when they name more than one delta; by name under `pn/` + aspect + commit, so a delete costs other deltas nothing and an entry's purge state is O(aspect-wide requests + its own).
- **Not `commits`**: the commit query lists every kind over a scope with relations, O(scope), for undo; history is one aspect's bodies, paged.

## Commits: query, undo, redo, revert (Tess: one model)
- **Query**: `db.commits(&CommitQuery) -> Result<Vec<CommitEntry>>` over the held commits, anyone's, and this session's own ephemeral changes (notes/ephemeral.md Step 2 as built), newest first by `(ts, ID)`. `CommitQuery` is a plain struct with `Default`; empty fields match all: `scope: Scope::{Thing, Aspects, Group}` (resolved when used, nothing stored; `Thing`/`Group` cover durable aspects, ephemeral things and `placed.0~`; an ephemeral aspect of a durable thing only when named by `Aspects`), `actors`, `kinds: CommitKind::{Change, Revert, Role, Summary, Ephemeral}` (`Ephemeral`: an ephemeral-only batch, change or revert), `reverts`, `reverted_by`, `in_effect`, `since`/`until` (`Time`), `after` (paging), `limit`. `CommitEntry { commit: Stamp (the watch's type: id, actor, node, written, received), kind, reverts: Option<ChangeId>, reverted_by: Vec<ChangeId>, in_effect, aspects (valid, in scope; a mixed batch's ephemeral ones too), content_gone, purged: Vec<(Tid, Ak, ChangeId)> }` (`purged`: of `aspects`, those a held purge request dropped, with the earliest request: the entry is a tombstone there, shown or not by the app; for a permanent delta it stays and reaches new devices, spec/commits.md §5; a thin client reads it under the same scope rule, `aspects` and `purged` of what it may read only): signed-header facts only (Attribution); commits valid on no aspect in scope are left out. Relations are judged over every held commit touching the entries' aspects (a revert touches its target's aspects; undoing a creation resets every held aspect of the thing, the creation's among them). `db.undo_target(&scope)`, `db.redo_target(&scope) -> Result<Option<CommitEntry>>`: the change `undo`/`redo` would revert now (fails `NotUndoable` as the call would): what a UI labels or disables its buttons by. `undo`/`redo` take exactly that, then revert.
- **Revert**: `db.revert(id: ChangeId) -> Result<Committed>` (a batch with both halves reverts as one; an own ephemeral change from the in-memory log, bounded by `Config.ephemeral_undo_bytes`, 16 MiB, older ones `NotUndoable{ContentGone}`; another node's or a pre-restart one `Invalid`): a content commit naming its target (wire `undoes`) with the inverse writes (spec/crdt.md §4.6: parts superseded since are skipped; a dropped body or nothing to write is `NotUndoable{ContentGone|Superseded}`; role commits and snapshots are `Invalid`). In effect: no revert in effect reverts it. Revert depth: 0 for a change, +1 per revert (odd = an undo, even > 0 = a redo).
- **Undo/redo** (this actor, any device, under one lock): `undo(&scope)` reverts the newest own in-effect change or redo (even depth); `redo(&scope)` reverts the newest own in-effect undo (odd depth) unless a newer own change (depth 0) is in scope (a new change clears redo). `None` when nothing qualifies; `NotUndoable` when the chosen one cannot be reverted (nothing older instead). A revert of someone else's change counts as an undo of the reverter's: the reverter's redo reverts it, their undo skips it; the reverted change's author can no longer undo it (out of effect) and cannot redo it (not their undo).
- Undoing a creation deletes the thing (Tess; spec/crdt.md §4.6): the batch that created it (a commit carrying its `created.0` when created and persisted in one batch, else the ephemeral batch); its revert also does `delete`'s writes (every aspect, both sides, and its placements and subgroup edges in every group the node may write; `Permission` when the node may not write the thing, never a partial revert), so redo (or `revert` of that revert) brings the thing back with content and placements. A deleted ephemeral thing keeps its record (redo needs it) and reads unknown. Saving a draft (the commit persisting an earlier ephemeral thing) is no creation: undoing it reverts its writes and returns the draft (ephemeral content, ephemeral placements, known), a further undo deletes the draft, redo saves it again (notes/ephemeral.md). In a thing's scope, creating an ephemeral thing is the oldest change.
- Exact undo (spec/crdt.md §4.6 "Absent before"): undoing the first write into a spot that did not exist resets the spot when no one else's live value is in it (seen writes block it; concurrent ones arriving later are wiped); a register in a present struct stays (no nested register reset). A node without the whole pre-commit state (older bodies dropped, a later snapshot) skips it.

## Large values
- Typed and untyped reads materialize up to `read_limit`; above it `stream()` (`Read + Seek`, lazily fetching chunks, memory bounded to a chunk plus the tree path), `len()`, and path reads. Writes: `set_stream(impl Read)` on a `blob`/`string` position builds the chunk tree without materializing (plans/large-values.md); `set`/`edit` accept in-memory values of any size the caller has. Equality is by content; links never appear in values the API returns (`Value::Link` is replaced by the materialized value, or the read fails `TooLarge`; a link that cannot be read, its blob not held or failing verification, reads as absent at its position with an `Unreadable` diagnostic, spec/data-model.md §6; history bodies read `NotFetched` instead). A read that missed a blob notes the aspect, a history read the (aspect, commit) (`Engine::missed_blob`, `Core::missed`); the next blob stored re-delivers every noted aspect to its watches (`Cause::Fetched`) and every noted entry as `Event::History`, and a read still missing one notes it again.

## Queries (minimal in the MVP; a design pass later)
Per-aspect reads are not enough for any list-like UI. Expect most of a slow, not very feature-rich database to grow over the local store, over time; nothing of it touches the wire. MVP shape, enough for the example apps:
- `db.query(Query::in_group(g).with(key).order(Order::Time | Order::Field(path)).page(n)) -> Live<Vec<Hit<T>>>`, things in the group (transitive) carrying the aspect, paged, with `Hit { tid, value: Result<Option<T>>, ts, received }` and a watch on the result for changes in the visible range (a chat timeline, a feed, an inbox).
- `db.backlinks(tid) -> Live<Vec<(Tid, Ak)>>`: things whose values reference the tid.
- Later: filters over values (unread, by actor, by tag) and counts, live; text search. Indexes are local, rebuildable, sharded per aspect (notes/local-store.md).

## Sharing and roles
Synchronous unless noted; each is one role commit made locally (spec/permissions.md §2), delivered by the sync layer. Nothing here assumes a role has one answer forever (dispute calls, issues/api-refactor.md Decided).
- `db.grant(target, holder, role, GrantOpts { until, invite })`: adds, raises, or changes `until`/`invite` (what `opts` leaves out goes). Never waits, never lowers: a role below the holder's present one is `Invalid`, naming `set_role`, and so, for an admin, is one below a role it lost with no explicit write since (`Engine::lost_role`: a grant that ended, finalized or not, or a self-removal). Spec/permissions.md §5.1 step 4: that write audits against the edge as restored, and a grant carries no frontier, so it would undo all the holder ever wrote there, everywhere; one over an edge still in the state would also lack its rotation. `set_role` removes first (a commit of its own, frontier and rotation, a failure between leaves the holder with no role, as it had), then grants; the removal says keep or erase by the thing's default, harmless: the role lost already dropped or kept the copy, and the new role ends a copy and brings the data back. An invite grant audits nothing: it goes through once the edge is out of the state, and until then is `Permission` (receivers refuse it without a rotation it cannot write; spec/permissions.md §2 "an expired edge counts as none" holds only after the finalize). Needs the holder's `keys.0` held (contact card, a shared group, pairing), else `Error::UnknownActor`; admin, else `Permission`. Records the permission and nothing else (Tess's decision): no label is made, and nothing is refused for lack of a route. The one overlap with `set_role`, stated at its definition: the call that does not block and takes no role away, and the only setter of `until`/`invite`. A lower `invite` does undo the holder's invite grants (issues/grant-audits-without-frontier.md). The first non-owner holder of a plain thing gives it secrets of its own (about 2.6 KB of boxes per holder: share sets through one actor, notes/permissions.md Patterns). The holder's admins learn of it through its inbox; a group holder's readers through the copy its admins place under its label (an ownerless group's inbox is its own label, so they read it there too). **Route** (spec/sync.md §2): the holder reads the target only through a live label it can open that carries it: the target's own, or one of a synced group whose closure holds the target and whose actor the holder may read; with none it holds the role and reads nothing, shown as `SyncState::NoRoute` (below) at the granter's node and the holder's alike, until `sync(target)` (its first label is delivered to its holders) or a membership in a synced group it reads gives it one. Made after the grant, so a holder who is no contact never finds this device's `reach.0` under it (no rotation). `make_link` is the one composite: it syncs the target when it has no label (K reads that label alone, nowhere else to live). Every other label is `sync`'s, or infrastructure with no thing of the app's behind it (a person's home, a contact profile, K's own, a replacement's successor of a label that was there, `group_source` taking a group home).
- `async db.set_role(target, holder, Option<Role>, SetRoleOpts { sync: SyncFirst, keep })`: raises, lowers or (`None`) removes. A role not changing writes nothing. No current role: `Some` is `grant` with default options (after removing a lost grant above it, with `sync`, see `grant`), `None` writes nothing. Keeps `until` and `invite` (`invite` capped at the new role). A raise makes no pre-sync and does not wait; lowering and removing run the pre-sync first, as `SyncFirst::{Required (default), Try(Duration), Skip, Backdate(t)}` says: `Required` waits until synced or dropped and fails `Error::Unsynced { groups }` on a group stranded or with no hosts, or with no runtime, `Try(d)` gives the call `d`, however many ways in it removes (at 0 one look, at `Duration::MAX` no end), and proceeds with a diagnostic, `Skip` stamps now (stolen device), `Backdate` stamps with the frontier as of `t`, no pre-sync. `keep` (spec/permissions.md §2, §3: `required.0^`'s `keep`, written as any required rule, no call of its own; `None` filling from the default) with `Some` is `Invalid`. A removal follows `holders` until the holder reaches `target` no more (a holder both granted and joined by a link loses both). A joiner by a link of this account is removed with the link key in one commit (`revoke_joiner` in the engine, one rotation): the link stops working for everyone who has not redeemed it yet, K's other joiners stay (the joiner may keep the seed, spec/permissions.md §8). That is chat's kick and the one route to remove a joiner. A joiner's role cannot be set (it could act as the link key), and a holder reaching `target` through another actor (a team, a link of another account) is `Invalid` with the actor named. `Unsupported` on a routed thing, raises too (`grant` goes through the route). `db.kept_copies()`, for a thin client those it reads, notes/client-port.md §3; `db.drop_kept(actor)`, the owner's.
- `async db.repudiate(target, holder, Option<Role>, SetRoleOpts)`: `set_role`'s lowering or removal, also undoing the holder's rotations this device cannot open (spec/permissions.md §3, §5.1): only after a lockout. A direct grant only; cannot raise; `keep` as for `set_role`.
- `db.leave(holder, target)`: removes a holder's own grant, no pre-sync, as a self-removal: no rotation (the target's next writer or admin rotates). `holder` is `me()`, or a group or actor this node administers (`Permission` otherwise; for such an actor, `Invalid` when this node is an admin of the target: `set_role`, with its pre-sync). `me()` with this node also an admin of the target is an explicit removal with no pre-sync, and rotates. No such grant and no other way in writes nothing; a holder still in through another actor is `Invalid`, naming it (a joiner leaves the link's actor), since nothing would change. Owner only: the flow runs on the node's authority, not a client's actor. A give-up call belongs with it (issues/api-leaving-give-up.md).
- Tied grants (spec/permissions.md §2, notes/tags.md Sharing a tag): `db.add_with_grant(Member::{Item, Subgroup}(t), group, role)`: adds the member and grants the group, tied, so the grant goes when the membership goes (`Permission` before writing when it may not grant; a grant at `role` or above is kept as is; to add without granting: `w.group(g).add(..)`). `GroupWrite::remove` removes the tied grant after the commit when that is a self-removal (`Osis::untie_now`), else node-sync's obligation does. `Grant.with_membership: bool` in `grants` (the stored tie names the membership's element, spec/permissions.md §2); `grant` keeps a tie, a new grant has none; `add_with_grant` on a tied grant whose element is gone ties it to the live one. Members with no grant: `groups_of` minus `grants`. A `with_membership` grant whose thing is no longer a member is on its way out.
- `db.holders(target) -> Vec<Holder { actor, role, until, through }>`: everyone holding through the grants below `target`, breadth first; one entry per grant that makes the actor a holder, by the shortest way to that grant (`role` the least along it, `until` the earliest), and again by a longer way that gives more (a higher role or later end than each before it), so the actor's best role and end are among its entries. Owner only for now (`Reader` hides what the actor may not read, so it could be a client row). O(grants below × distinct ways that beat each other): a crafted lattice has at most one per role per distinct `until`, nothing per path. Who holds through K: `holders(K)`, or `through.contains(k)` here; `LinkId::actor()` gives K. Replaced `reach` (`groups_of` + `grants`), `holder_path` (one entry), `Share`, `GroupReach`.
- Devices: pairing is transport-agnostic, the app carries three texts: `db.pair_offer() -> PairOffer` (short-lived, one-time secret); on the new device `Osis::pair(Config, &offer) -> Joining` with `joining.request()`; back on the first `db.pair_accept(&request) -> (node, PairReply)`; then `joining.finish(&reply) -> Osis`. Request and reply are authenticated by the offer's secret. A direct-connection convenience over this is later. `db.devices() -> Vec<Device>`; `async db.remove_device(node, SetRoleOpts) -> Vec<LinkInfo>`: `set_role(me, node, None, ..)`, kept for what it returns: the person's working links, whose seeds the device keeps (notes/permissions.md Links). Stated at its definition.
- Links: `db.make_link(target, role, LinkOpts { until, single_use, direct }) -> ShareLink` (text; `direct`, opt-in and required without hosts: the link carries this device's dialable key and relays, never `reach.0`, so a redeemer with no common host reaches it; the key rotates when the link ends; notes/networking.md First contact); `async db.redeem(link) -> Tid` (grants only once K's edge on the target is here; a link known to have ended, K off the target included, fails `Invalid` at once; anything else waits until dropped, a read of K's label to its end included, as the edge may be on its way from the maker's node (a link naming the wrong target waits too: an app's timeout says "could not confirm, retrying is safe"); `import_contact` asks the same edge, the same way); `db.links() -> Vec<LinkInfo>` (the person's, whichever device made them; filter by `target`; `Unsupported` on a thin client, so a node attached with a client secret adds none); `LinkInfo.id: LinkId` is opaque (`Display`/`FromStr`, `actor()`); `async db.revoke_link(id, SyncFirst)` (its joiners keep their roles on K; a bearer may have kept the seed, spec/permissions.md §8). One joiner: `set_role(target, joiner, None, ..)`, above. Single use is in the link (`flags`, spec/wire.md §10): the redemption removes the link key and node-sync on any sharer device finalizes it, and an expired link, after a complete pass of K's labels (`SyncEngine::finalize_links`; the seed thing is placed in the home group so every device holds it); a second redeemer is told it ended (`Invalid`). Waiting calls (`redeem`, `import_contact`, `restore`) remove their waiter when dropped and forget the held key on every outcome; `restore` fails `Invalid` on a refused key and `Unsynced` on a stranded home (at once, for now: another holder may yet let it back in). Bearer read (`async Osis::open_link(Config, link)`) slipped (issues/api-deferred.md).
- Invite requests (spec/sync.md §3): `db.invite_requests() -> Vec<InviteId>` (an invite from a sender with no known connection: nothing it names is fetched or dialed yet; nothing about sender or thing is shown, both would be the sender's unverified word), `db.accept_invite(id)` (applies the grant, joins as any invite), `db.decline_invite(id)` (forgotten for good, re-sends included); both `Invalid` when no such request waits. Not watchable yet: an app polls (e.g. on status changes).
- Contact cards: `db.contact_card() -> ContactCard` (a read link to a profile thing whose label carries the person's `created.0` and `keys.0`, spec/sync.md §3; made once); `async db.import_contact(&card) -> Tid` (the person actor, then usable in `grant`).
- Entitlement: holders read what the group (or an actor in it) owns; a thing owned by `me()` and placed in a shared group stays unshared (notes/sync.md). Shared things take the group as owner.

## Sync configuration and status
- `HostAddr` = transport URL plus the host's key (`FromStr`/`Display`; a `quic://` URL without a port is kept as `:4040`, so one host has one address); `db.hosts() -> Vec<HostAddr>`, `add_host`, `remove_host`. The person's `keys.0` inbox and the labels whose host list equals the database's list (as a set) follow the change (`label.0` writes first, then the saved list, then the `keys.0` write; the sync engine registers a label's path at a new host), so a database created without hosts gets a reachable home label. Only the home label and groups the person owns (directly or through its actors) that this node administers: not groups owned by others, not link actors or the contact card's profile (their text names their hosts), and a group with holders besides the person's devices never loses its last host. A link or card made on another device is recognized only by its key-actor holder (a card's profile is not: a gap).
- `db.sync(group, &[HostAddr])` makes a group synced (its own label, the group given secrets of its own first; admin of the group; empty list: the database's hosts; a no-op when it has a label, unless the list names other hosts: `Invalid`); `db.unsync(group)`; `db.set_sync_options(group, SyncOptions { share_address: ShareAddress::{Auto, Always, Never}, mode: SyncMode::{Full, LogOnly} }) -> Result<()>` (stored, the whole policy: change one field from `db.sync_options(group)?`; `Unsupported` on an attached handle, as `sync_options` and `rotate_address`; `LogOnly`: this device holds none of the group's content, a demotion reads its headers only; `Auto`: `reach.0` only where every reader is this person, its own or a contact, notes/networking.md; `import_contact` marks contacts; a group excluded while its labels hold the current `reach.0`, and a direct link ending, rotate it; `db.rotate_address()` rotates by hand; per-group heartbeats not built: issues/api-deferred.md). The person's home group is synced at `create`.
- `db.status() -> Status { connected, groups: map<Tid, GroupSync { state: Synced | Syncing | Unreachable | NoHosts | Refused | Stranded | LogOnly | NotCarried, last_sync, refused_by, leaving, not_carried_to }> }` (`leaving`: this device left the group and keeps it until a host has its removal (node-sync `drop_left`), set for good while none takes it), `on_status_change()`. `NotCarried` (`Engine::unrouted`, one rule at every node): a thing with no label of its own whose roster has a holder that reads no live label carrying it, as this node knows labels, `not_carried_to` naming those holders: this person when it is the one granted and cut off, the holders a granter shared with and nothing carries to (its own clients on its own things are left out: they read what it holds). A label of a group this node does not read is not known here, so a granter may list a holder another node sees routed. It clears when the thing gets a label (`sync`) or a synced group the holder reads takes it in, and comes back when that label is replaced without a successor (`unsync`), the thing leaves the group, or the holder loses the group but keeps the edge. `Refused`: a host of one of its labels does not admit it (yet; code 14) and no other host has it open, `refused_by` names those hosts (also when another has it); `wait_synced` waits on it and fails `Unsynced` at its deadline. `Stranded` means this device waits for a re-seal (spec/permissions.md §3); `LogOnly`: the app set `SyncMode::LogOnly`, what this device holds of the group is stale (not updated); `wait_synced` leaves such groups out.
- `async db.wait_synced(scope: SyncScope::{Thing(tid), All})`: resolves once every local commit in scope is at a host and a pass changed nothing, and every pending delivery in scope (inbox deposits, a non-writer's deposits) was taken; `db.sync_now()` nudges: a label not live at a host syncs, a live one only judges again, and a connection quiet for `retry_ms` gets a ping so a dead one is found (`SyncEngine::refresh`; polling is harmless: a Sync of every label costs a round trip per two, issues/sync-rounds-per-label.md, and a poller kept `Syncing` and `wait_synced` waiting). `wait_synced` and the pre-sync sync every label (`SyncEngine::sync_now`). One rule over labels: `Group(t)` covers every label of the groups holding `t` and fails `Unsynced` on a hostless or stranded one (a replaced hostless label beside another of its group is left out: it takes nothing until it retires; nothing holding `t`: `Unsynced{t}`, at once unless a route may still arrive: an accepted grant named its label, or this node does not administer `t` and one of its labels is still syncing, as on a new device; a grant not yet accepted is not on its way), plus the deliveries about `t`, a thing it holds or one of those groups (a grant names its target; a non-writer's deposit its label's group); `All` covers every label with hosts (a hostless label is skipped, whatever its group's other labels; a stranded one fails) and every delivery. Never `Ok` while something in scope is known undeliverable. A `Refused` label or delivery, and a host out of reach, may yet resolve: it waits, `status` shows them. CLI and tests use these; apps mostly watch status.
- Hosting (notes/sync.md Hosting in the node): `db.set_hosting(Option<Hosting { listen, admit: Own | Open, admitted: set<AdmissionId>, replicate, policy: HostPolicy, caps: map<AdmissionId, HostCaps> }>)` writes the node's `host.0^` (none: stop; a limit it cannot run by fails `Invalid`). `HostPolicy` is the plain limits (`group_entries`, `group_bytes`, `groups`, `entries`, `bytes`, `connections`), wrapped at this boundary; the host's other knobs are `internals::host_limit`, by name (the doc-hidden field is `pub` only so that `..Default::default()` works, and its type shows nothing). `AdmissionId` is a label ID by what it does, opaque text, kept to this one purpose: `db.admission_ids(group)` is the only way to ask (a routed group's at its node; `Unsupported` for a client with its own actor), `status` says nothing of it, `db.hosting()` reads it, `db.host_address() -> Result<Option<HostAddr>>` once the host listens (`Network` when it could not), `db.host_key()` its key without listening (made when `host.0^` is first set, shredded when hosting stops; `HostAddr::new(listen_url, key)` for a fixed port). With `Own`, the node hosts the groups its person owns (owner chain through the person; no role edge counts, since grants need no consent) once their hosts name its address (`add_host`, `sync`); someone else's group, even one it reads or administers, or one under an actor someone made it admin of, takes `Open` or its id in `admitted`. No other way to start a host: the CLI's `serve` is these calls.
- Bundles: `db.export_bundle(&[groups], impl Write)`, `db.import_bundle(impl Read)`. P2P and LAN need no configuration: `Config.peers` (default on) listens with the dialable key and publishes `reach.0` (with `Config.relays`); features `iroh` (co-readers over iroh beside QUIC hosts) and `lan` (the LAN loop). Without `iroh` no such node is dialed.

## Diagnostics (decided; shape is proposal)
A place to dump problems such as a colliding record from a peer, rejected writes from a revoked actor, a thing created into an unsynced group, a demotion that proceeded without its pre-sync. Apps may log, surface or ignore it; correctness never depends on anyone seeing it.
- `db.on_diagnostic(|db, d: Diagnostic|) -> Subscription`. `Diagnostic` (`core/osis/src/diagnostic.rs`, translated from the engine's kinds, which the port keeps carrying) is an enum with named fields per kind: what an app can act on (`NotSynced`, `MembershipNotSaved`, `Uncommitted`, `OwnWriteInvalid`, `Mismatch`, `Unreadable`, `LostAccess`, `RoleLoweredUnsynced`, `Stranded`, `EphemeralRefused`, `Storage`, `Callback`, `SyncStopped`, `Parked`: a commit from a newer format, so an app can tell its user to update, issues/parked-diagnostic.md) and `Handled { things, commit, peer, detail }` for the rest (bad, parked, pending, colliding, misstated, repaired data: log material, its engine kind leading `detail`). `#[non_exhaustive]`, `Display`.
- A peer must not be able to flood it: dedupe per (kind, tid), rate-limit per peer.
- Must include: "this device was removed from actor X by node N at time T" (a stolen device's backdated removal otherwise looks like a silent lockout; the recovery card is the remedy) and "stranded on group G" (also in status).

## Errors
`Error::{UnknownThing{tid}, UnknownActor{tid}, Permission{tid, needs}, Type{path, reason} (a typed write's value, or a path outside the key's schema), TooLarge{limit}, NotUndoable{commit: ChangeId, reason}, Unsynced{groups}, Invalid(reason) (a malformed link, card or value; a write growing an ephemeral aspect whose own state no longer fits a blob, notes/ephemeral.md Past inline lists or a blob), Storage(..), Network(..), Unsupported(..) (this kind of handle does not carry this call), Refused(..) (the node will not take this session: its secret or uid, or an address with no client port), Closed}`. Peer-caused problems never surface as errors to the app; they are diagnostics.

## Typed reads (decided; spec/versioning.md §5)
A typed read (`at().get()`, `on_change`, path reads) of a stored value with an unknown enum case (a newer version's), a type mismatch or a missing required field reads as `None` and reports `Diagnostic::Mismatch` (the thing; detail: AK, path, reason; deduped per (kind, tid) like every diagnostic). Tess's direction (api-asks-2): synced data is other writers' input and an app cannot act on an error, so one odd thing must not fail a screen read with `?`; one read call, no lenient variant. Per-path reads let an app read the good elements of a collection with one bad element. The untyped `Value` API always shows what is stored. App types are views over the wire type, generated or hand-written; transitions and the form-choice policy are codegen conventions (notes/versioning.md). Codegen warns on `list<struct>` aspects (records edited concurrently belong in `map<K, struct>` or get path ops: the list diff pairs changed entries in order and a misaligned pair loses concurrent edits).

## Attribution (Tess's decision)
The API reports only verifiable authorship: who wrote something and when comes from the signed header of a commit held here, never from a claim another commit makes (a compaction snapshot vouches for its carried writes without naming their authors). No API type carries an "unverified" flag; what cannot be verified is not reported.
- The commit query lists the commits held here, each with its own header's author and `ts` (a snapshot as itself); changes known only from a compaction snapshot have no entry. A watch's `Source` names the commit applied: a snapshot arriving is reported as itself (its author, ID and `ts`). A valid snapshot's copy governs a held original it misstates (spec/permissions.md §5.2): the read changes with the snapshot as `Source`, while the commit query and `changed` still name the original's commit as the change it was (snapshots are no change); the node reports the snapshot (`DiagnosticKind::Misstated`).
- No per-write attribution call exists yet; any future one follows this rule: a value known only from a snapshot reports the snapshot or nothing.
- Required retention: `w.at(t, core::REQUIRED).set(&rules)` (an admin; `BTreeMap<prefix, Required>`), `osis set T required.0^ V`, no API of its own. A prefix (`chat:msgs:`, empty for every aspect) covers per-year names. After it the writer's node fills that retention and expiry and an override errors. A writer that has not seen a change writes under the old rule and its delta turns invalid once it arrives: its node reports `DiagnosticKind::OwnWriteInvalid` (the app writes again: osis-chat `resend`). At most `MAX_REQUIRED_ENTRIES` entries. Set it before granting anyone: a member from before a change can backdate below it.
- Provable authorship of every change (audit trails): give the aspect keep at least forever (`Retention.at_least`, `abs` forever); its bodies are then never compacted away, so each change keeps its signed original.

## Demotion and the pre-sync (decided)
A demotion's frontier is the demoting node's own receipts (notes/permissions.md, Revocation), so osis syncs every group below before stamping it (spec/permissions.md §5.3); in the common case there is no tradeoff. The sync fails when a group is unreachable, the node is stranded on it, the tree is too big for the device, or the app will not wait (a hostile holder or lost device: reverting their unseen work is then wanted). The app chooses by `SetRoleOpts.sync`; a UI may route the choice to a user, osis never requires a human. Partial sync is partial protection (the frontier is per aspect). A group this device holds for receipts only (`SyncMode::HeadersOnly`, e.g. a phone holding part of an organization) is read for receipts in the pre-sync (its commit headers, notes/sync.md Receipts-only reads), so its holders' unseen edits are kept without the device holding the tree; what remains is hosts it cannot reach and peer-only edits (issues/revoke-needs-whole-tree.md). Rejected: a "cut access only" removal (`until` = now by an admin) leaves a permanent backdating window until a real demotion follows; third-party receipts fail the fixpoint model.

## Footguns closed (keep them closed)
- Read-modify-write clobber (a form saved with `set` wipes a tag another device added meanwhile): `edit(base, new)` and path ops; docs steer every interactive edit there.
- Out of memory on an unexpectedly large value: the materialization bound fails explicitly; streaming and path reads exist.
- A thing that never syncs: membership a group op, a member of a group whose own aspects sync but whose items would not fails, `NotSynced` diagnostic for device-local placements.
- A member lost silently: a thing becomes a group with its first member.
- `set` losing a repeated message on a log: its doc says so, and `overwrite` is named for always writing.
- A deleted thing reading as present (an editor left open on it): `knows` is false once no content is left; deletion is derived, never a flag.
- A forgotten unsubscribe: RAII `Subscription`.
- Missed change between read and subscribe, and a callback invoked on the registering thread once and the dispatcher thread later: atomic `watch`, initial call through the dispatcher.
- Writes a node is not allowed to make, emitted and un-merged elsewhere later: rights checked locally at commit.
- `async` reads forcing a runtime into GUI apps and hiding that nothing waits: synchronous data API.
- Per-keystroke commits (13 bytes forever each): the text session.
- A role lowered without syncing what the holder wrote: `SyncFirst::Required` is the default; skipping is spelled out.
- Concurrently edited records in a `list<struct>`: codegen warning, path ops.
- Deadlock or reentrancy inside callbacks: no callback under a lock, any API usable from a callback.
- Secrets in the API: none; the recovery seed only in the card at creation, the link seed only in the link.

## Rejected shapes
- Everything `async` (the earlier sketch): local operations never wait, and every GUI would carry a runtime; browsers are served later by a worker-backed synchronous store.
- `ListenerId` cancellation and a callback invoked before `listen` returns.
- An entity/ORM layer typing whole things: aspects belong to different schemas and apps; per-aspect typed keys fit the model.
- Auto-subscribing reactive reads (reads inside a computation register listeners): hidden magic; `on_change` covers it explicitly.
- `set` diffing against the app's last read implicitly (state hidden in the handle): `edit` takes the base explicitly.
- Exposing links or a `Value::Large` variant in untyped values: the bound plus `stream()` keeps values plain.
- A default membership.

## Open
- The query design pass (which filters and indexes, live counts, text search).
- Typed path builders from codegen; a serde layer `Value <-> app types` as a convenience.
- Bearer read and anonymous-writing conveniences may slip from the MVP (notes/overview.md, MVP scope).
- Browser build: the sync API over a worker-backed store (SharedArrayBuffer + Atomics.wait), not in the MVP.

## Implementation
Module map (`core/osis/src`): `handle` (`Osis`, `Config`, `Store`, `MemStore`, the lock and `after`, schema registration), `internals` (doc-hidden: the `Internals` trait on `Osis` with `engine`, `sync_engine`, `waiting`, `take_actions`, `feed`, plus `ManualNet` and the `node` re-export, for the CLI's `inspect`, the sim and tests), `net` (`Runtime`, `SyncOptions`, `Net`, the driver host, `Waiter`/`Pending`), `change` (`ChangeId`, `HistoryPos`, `HistoryFrom`, opaque over the engine's), `value_type` (`ValueType`), `person` (`restore`, pairing), `share` (grants, demotions and the pre-sync, links, cards, devices, hosts, group sync, status, bundles), `read`, `write`, `large` (`ValueStream`, `len`, `set_stream`), `text` (`TextSession`), `watch`, `commits`, `history`, `signal`, `keys`, `error`.
- **Handle and sync**: one mutex over `Locked { sync: SyncEngine (owns the engine), events, seq, waiters, status, offers, links }`. Every call under it ends in `after`: engine events go to the dispatcher in commit order; if the call (not the driver) caused events, `SyncEngine::handle(Event::Local)` runs; then direct-link upkeep (rotate the dialable key when one ended), the status (a `Msg::Status` to watchers when it changed, a `Stranded` diagnostic on a new stranding) and the waiters. Network actions leave through `Net` under the lock (FIFO, so frames keep their order): `Off` drops them, `Manual(ManualNet)` queues them for a test harness (`Internals::take_actions`/`feed`), `Driver` sends `Control::Apply` to osis-node's `sync::driver::run_shared` running on the app's or osis's own tokio runtime with the handle as its `Shared` (a weak reference; the driver stops when the database closes). `close()` fails `Invalid` from a callback and `StillOpen` while other user handles exist (`Life` counts them; osis's own short-lived holders, the dispatcher running a callback, a driver engine call, timers, use uncounted handles: `Osis::internal`, `WeakOsis::hold`), else waits uncapped until the store is closed (each such holder ends on its own); dropping `Net` sends the driver `Shutdown`. Engine calls run in `block_in_place`, which a runtime shutdown does not wait for: the task polled on after one would hit a timer of the shut-down runtime and tokio panics. So the driver task holds a drop guard: osis's own runtime (`Runtime::Own`) is shut down by an `osis-sync-stop` thread once the guard dropped (at most 5 s, then `shutdown_timeout` 5 s; the drop itself may run inside that call, hence the thread; the store is already closed: `Inner` drops `eng` first), and `close` waits for that thread (so every task on it, the host's too, is gone and `host.redb` is free for a reopen); on the app's multi-thread runtime `close` waits (uncapped, in place when inside it; on a current-thread one not at all: no engine call runs in `block_in_place` there, and the host store may stay locked until the app drives that runtime again) for the guard (the driver awaits the host task's end on `Shutdown`), so the app may shut its runtime down next; and the driver polls no timer while a control message waits, so a `Shutdown` queued by a drop before the runtime's shutdown is seen first (an app dropping the runtime while the database is open can still hit the panic). Wake timers hold a weak sender and are armed only for a waiter that did not resolve at once. A driver task that panics (or that its runtime drops unfinished while the database is open) ends sync for the handle's life (`net::Watched` around the task, `driver_died`): under the lock it sets `Net::died` and fails every waiter with `Network("sync driver panicked: <msg>")` (else they hung: their wake timer sends to a closed channel); later waits fail the same way at once, `listen`/`client_listen` too; then a `SyncStopped` diagnostic (best effort: the engine may be what panicked); the panic goes on to the runtime. `osis serve` (and `diag --follow`) exit 6 on that diagnostic; the app shows it. A thin client's connection thread (`port::client::Io`) fails its calls and closes its subscriptions in `Drop`, so a panic there does not hang a `remote_task` either.
- **Write and sources**: a `Write` records its API ops (`WriteOp`: create, group ops, path ops at a key-table index, expiry as wall time, retention, purge, delete) with each call's checks done as it is recorded, and builds the engine `Mutation` at `commit` under the lock (`delete` expands against the state held then; its expiry conflicts surface there); the op list is a remote batch's request (notes/client-port.md). Every call addressed by a tid, group or scope starts with `let Source::Local = self.route(..)` (one variant, a constant: adding `Remote` makes each site a compile error until it is handled).
- **Futures**: no call takes a timeout (Tess): a future cancels on drop, a caller wraps it in its own runtime's timeout. `wait_until(late, check)` registers a check on the sync engine and status, run after every change (and on any call, so `late` passes offline too; a driver wake, `Net::timer`, looks at it): `SyncFirst::Try` gives up at `late`. A link naming no host on a node that dials nobody directly (`Inner.dials_peers`) is `Network` at once; `restore` on a home label gone `Stranded` is `Unsynced` at once (issues/restore-head-moved.md: nothing there recovers it). A waiter whose future was dropped is removed; held link and recovery keys go with a guard on every outcome; `restore` writes the `person` record only on success; a waiter dropped unanswered answers `Closed`. A driver gone answers `Network` (`driver_died`), a database closing answers port rows `Closed` (`Job::Closing`). `Pending` resolves through a slot with the stored waker: runtime-agnostic (tests poll with a no-op waker or a park/unpark waker). Without a runtime they fail `Network` at once. **Connecting**: `async` too. A thin client (`connect`, `connect_socket`) needs its node for `me()` and all else, so it returns connected or fails with why its one attempt did not, leaving nothing; a node's `connect_node` keeps the connection and retries, `status` showing it, as the node can work without it. `CONNECTION_WAIT` bounds one attempt and a sync write across a drop, which has no future to drop.
- **Person**: `create` runs flows' `create_person` (the sync engine is built first so it sees every event), writes an empty `group.0` on the person (home = person), records `person` and `hosts` app records. `open` refuses a person without `keys.0` (a pre-flows store, `Invalid`). `restore` holds the card's key, `follow`s the home label, waits until the person is known and its group `Synced`, then `recover`. Pairing messages are CBOR `[1, ...]` in base64url with `osis://pair/`, `osis://pair-request/`, `osis://pair-reply/` prefixes; MACs are `kdf(purpose, secret, body)`; the request carries the new node's commits, the reply the grant id and the packages `take_direct_for(node)` returns (the grant or re-seal, the person's certificates and `label.0` commits: about 20 KB, whatever the person holds); offers live in memory (`OFFER_LIFETIME_MS`).
- **Sharing**: each call is a flow plus `carry_out`. `grant` maps a missing `keys.0` to `UnknownActor` and `Permission` to `needs: Admin`. The pre-sync syncs every synced group whose closure holds a thing `presync_scope` names (`sync_now`, then all `Synced`). `sync(group)` gives the group secrets of its own before its label: a label whose genesis is at the owner's derived epochs cannot be verified by a holder reaching it through a link actor (issues/node-sync-gaps.md). Links: K → (L, target, single_use, direct, ended) in memory and the `links` app record; single use is the link's `flags` bit (FC-3): the redeemer removes L in its redemption; finalization is node-sync's. A self-removal (`leave`) is sealed and uploaded before the leaver drops what it lost (`Done::drop_lost`). `contact_card` makes profile P (owned by me, a group of itself, labeled), places the person's `created.0`/`keys.0` commits under P's label as certificates, makes a read link to P and keeps its text (`contact` record). `import_contact` holds L, follows K's label, waits for P's owner's `keys.0`, drops L.
- **Signals** go through `SyncEngine::signal_as` (the person as actor, write role checked); local listeners hear them through `Event::Signal` like remote ones; a signal targeted at another node is not delivered locally.
- **Status**: from `SyncEngine::label_status` per label, plus `Engine::unrouted` for the `NoRoute` rows (things this node has a role on, with rosters and no live label; kept in `Core::unrouted` until a role, label or placement is written, so an edge expiring shows at the next such write; 10^4 things a group carries 90 ms a recompute, 10^4 with no route 1.4 s, `scale::unrouted_cost`; `Engine::routed` is the per-holder rule `share` uses): no hosts; stranded (a failed open); `Synced` when every connection holding it open finished a pass with nothing outstanding; `Syncing` when connected or open; else `Unreachable`. A group shows its worst label. `wait_synced` judges each label (`label_state`, the check `share::synced`), not the group's worst state; `Group(t)` scopes the synced groups whose closure holds t. Deliveries: `SyncEngine::pending_about` lists what each pending one is about (an inbox delivery's `SentInbox::things`, a deposit's label group; the outbox is stored, so a restart sends it again, and a queued deposit's host is dialed until it takes it, `wanted_hosts`); a demotion's pre-sync waits for none. `pending_uploads` of the shape is not built.
- **Diagnostics** added: `NotSynced` (after a commit placing a thing whose groups include no labeled group), `Unsynced` (a `Try` demotion that proceeded), `Stranded`; `Engine::report` dedups them.
- **Large values**: `stream` walks the chunk tree one chunk per call (`Engine::next_chunk` under the lock); `len` reads the CBOR head of the first chunk; a seek fetches nothing, the next read fetches the root and the nodes on the path to the target chunk (`TreeReader::seek`, lengths in tree nodes). `set_stream` reads the value whole, then sets it (issues/api-deferred.md).
- **Text sessions**: buffer plus base; `commit` writes `Op::Edit { base, new }` on a `text` position (rebased by the crdt; a paged text resolves it on the pages around the change when the text there still matches `base`, notes/node.md Paged state) or `Set` on a string register; a remote change commits the local edits first, then reloads and calls `on_remote` with `osis_crdt::changes` (the gaps of the Myers LCS over chars) as splices; the first edit after a commit arms a timer on the database's runtime (`Net::after`: a tokio sleep, then a blocking task) that commits once the session has been idle `idle_commit` (re-armed for the rest otherwise); without a runtime the next edit after `idle_commit` commits; drop commits (a failure reported as `Uncommitted`); `known` (the thing read known at open or after a commit) makes the flush's write check `knows` under the commit's lock (`Write::alive`, so a delete ingested between the check and the write is seen): false fails `UnknownThing` and the buffer keeps the edits. A commit that fails (lost write access, storage) reports an `Uncommitted` diagnostic and keeps the edits in the buffer for the next try; a remote merge after a failed commit drops them.
- **Writes, reads, watching, undo** as in the first half: writes act as `me()` (`act_as`); `commit` returns `Option<Committed>`; reads materialize with a budget; the dispatcher coalesces per aspect; undo, redo and the query read `Engine::held_commits`; a register edited twice undoes twice (spec/crdt.md §4.6).
- **Sharing helpers**: `holders` is a breadth-first walk over rosters. `set_role` loops over its first way for the holder: a direct grant goes through `lower` (or `grant` for a raise), a path through a link actor of a seed thing held (`held_links`, ended ones included) through `remove_joiner` (the engine's `revoke_joiner`: one commit, so no half-removal on a failed pre-sync or dropped future), anything else is refused. `add_host`/`remove_host`: `follow_labels` (one commit of `label.0` host-list sets) before the list is saved, then `follow_inbox`.
- **Signals in a group**: `Filter::SignalIn(g, kind)`; the dispatcher reads `groups_of(signal tid)` when a signal arrives.
- **Not built** (issues/api-deferred.md): queries and backlinks, `undelete` and cut/paste in text sessions, `set_sync_options` heartbeats, bearer `open_link`, streaming writes, `pending_uploads`, a direct-connection pairing convenience.
- **Standard data**: the scenario tests (core/osis/tests/it: notes, tags, contact, event) use this API end to end (notes/std.md).
- **Tests**: core/osis/tests: `api`, `watch`, `commits` (query, undo/redo/revert, exact undo, two devices, another actor's revert), `sync` (tier 1: `World` in core/test/sim/src/world.rs drives `Runtime::Manual` databases and osis-host `Hub`s under one `ManualClock`; futures polled with a no-op waker), `sharing` (more sharing and status through `World`), `runtime` (tokio driver over `InProcess` against the host driver: a restore and a link redemption; QUIC tier 2, ignored). Doc examples per concept in lib.rs.
