# Rust API
> Summary: The shape of the `osis` crate as it stands: a synchronous local data API (typed aspect keys, `at`, RAII subscriptions, a `Write` that is one commit or refused (a durable write's memory half a second), `set`/`edit`/`overwrite`/`remove` and path ops, the acting actor as first admin, membership by `w.group(g)`, drafts and ephemeral aspects in memory, rights checked locally, bounded materialization), signals, an aspect's history, the commit query with undo, redo and revert, text sessions, the sharing and sync surface (async only where another node is waited on), serving, diagnostics; why each is so; rejected shapes.

## Rules
How to judge this shape, and the standing rules: notes/api-design.md.
- Vocabulary (spec/requirements.md Terms): thing, aspect, group, member (what a group contains), holder (who has a role), actor, role, node, peer, serving, account. Below the API, "label" is a sync ID and "host" a saved peer; neither appears in anything public. Engine, `osis-host` and spec rule text keep theirs (issues/node-host-unify.md); every old word left is in issues/deprecated-terms.md.
- Decided words (Tess): a new thing not yet durably written is a **draft**, shared or not, and **ephemeral** stays for `~` aspects. `Tid` and `Ak` stay, and an aspect key is the whole string; a domain word plus a generic one is fine (one concept under two terms is not). "Keep" splits: a removed holder's copy is retained, `keep_alive`, `Retention::at_most`. "Invite" is an incoming request from a stranger; a grant's is `may_grant`. A role says who may, `sync` where the data goes (`grant` and `share` not bundled: revisit if the app finds it awkward).
- Explicit choices: the read limit (`AppConfig::read_limit`), catching up before lowering a role (`set_role` waits, `set_role_now` does not). Membership is a group op (a thing in no synced group gets `NotSynced`).
- Callbacks run on one dispatcher per node, in commit order, on its own thread (default) or the app's (`Dispatcher::Pump`).
- Undo: per actor by default, plus a view of all available changes in scope from which an admin may remove others' (notes/crdt.md).
- Async futures resolve by a channel from the handle's background runtime (tokio by default, or a `Handle` the app passes). A browser build later gets the same sync API over a worker-backed store.
- Internals: `osis::internals` (doc-hidden; the CLI's `inspect`, tests, sim and benches, never the app or chat): trait `Internals` on `Osis`, `ManualNet` for the doc-hidden `Runtime::Manual`, `node` = osis-node, `schema` = osis-schema, `core_types` (every core key), `Knobs` for `AppConfig.internals` (test clock, seed, `connection_wait`, `transport`: in-process endpoints), `Opening` and its `create`/`open`/`pair`/`connect*` for test harnesses that build store, saved peers and config in one helper, implementation numbers (`HISTORY_PAGE`, `STREAM_CHUNK`, ...), socket helpers, `Ts`, `CommitId`, `LabelId`, `CreationRecord`, `Clock`, `ManualClock`, traits `CommitRaw` (`.commit()` of a `CommitId`), `Exact` (`.ts()`), `MemStoreMeasures`, `kept_writes`, `joining_node`, `host_limit`, `host_limits_unshown`, `socket_path_under`. Generated code has its own narrow path, `osis::generated` (`use osis::generated as osis_schema;`). A feature gate is ruled out (notes/build.md Feature unification).

## Handle and lifecycle
- `Osis: Clone + Send + Sync`; clones share one node, which closes with the last handle (drop is fine; `close() -> Result<Close>` returns `Close::Closed` once closed and its sync driver is gone, or `Close::StillOpen{handles}` at once while other user handles exist: clones, upgraded `WeakOsis`, value streams, text sessions, a `Joining`). One account per store.
- `Osis::create(Store, &[Address], Config) -> Osis`: new node, new account (this node its admin), its home group synced with the peers given. No recovery: removed until a design exists (issues/recovery-redesign.md); an account is reached again only through another of its nodes.
- `Osis::open(Store, Config)`; `Osis::pair(Store, &[Address], &PairOffer, Config) -> Joining` (Nodes, below).
- `Store::{Memory(MemStore), Dir(PathBuf)}`. `Config { app: AppConfig, runtime: Runtime::None | Tokio(Handle) | Own, direct_sync, relays: Vec<Address>, ephemeral_undo_bytes }`, `AppConfig { read_limit (default 64 MiB), idle_commit (text sessions, default 2 s), dispatch: Dispatcher::Thread | Pump(wake), internals (hidden) }`, all defaulted. `direct_sync` (default on) listens, tells other readers how to reach this node and relays for them; off, it syncs with saved peers alone (tests use that). `relays`: nodes relaying for this one, each `peer://<ip>:<port>#<key>` (a relay is a node at an address, so `Address`; other forms `Invalid`). No transport to choose: QUIC, in-process endpoints only for tests. A thin client takes `AppConfig` alone. Without a runtime everything local works; calls that wait for another node fail `Network`; peers given with no runtime are `Invalid` (a store's own saved peers stay allowed: the CLI's local commands, whose writes go out with the next networked one).
- A **client** is anything using the client protocol; a **thin client** is one that is no node; a node may be a client too (`connect_node`). `db.has_store()`. Machine, transport and actor are independent. The default policy: a unix socket offers the protocol to the node's own user, unauthenticated, as the node's main actor; a localhost or network listener lets a client act only as actors it has authenticated for. A credential naming its actor may come later: `NodeLogin` grows, and the node already says who a client is (`WHOAMI`). `async Osis::connect_socket(store_dir, AppConfig)` (notes/client-port.md): `me`/`node` are the node's, tid-addressed calls go there, process-wide calls the port does not carry are `Unsupported`; `listen_socket()` serves it (needs a runtime; a store in memory has no socket, `Invalid`; test harnesses: `Internals::listen_socket_at(path)`).
- Clients with an actor of their own (notes/client-port.md §3): `db.add_client(until) -> (Tid, ClientSecret)`, `db.clients() -> Vec<Client { actor, until }>`, `db.remove_client(actor) -> bool` (sync, no options: all a client wrote went through this node), `db.rotate_client_secret(actor)`. Grants to the actor are what the client reaches. `async Osis::connect(&[NodeLogin { addr, secret }], AppConfig)`: a thin client at those nodes (answering as one actor; no login is `Invalid`): `me()` its actor, what it may not read is unknown, writes by its rights; sharing, sync and process-wide calls `Unsupported`, but for `holders` and `leave` of its own actor's grant.
- Group sources (notes/client-port.md §6, §8): `async db.connect_node(&NodeLogin)` (`Ok` once the first attempt ended and the connection stays, up or not: `status` says, and it keeps trying; `Refused`, `Invalid`: nothing stays), `db.disconnect_node(&addr) -> bool`; `async db.group_source(g, GroupSource::Local | Node(addr))`, `db.group_sources() -> map<Tid, Address>`; `Status.node_connections: Vec<NodeConnection { address, connected }>`; `Status.two_sources` (things read at a connected node and also in a group carrying them to another source: writes refused `Invalid`, notes/client-port.md §8). A disconnected source is `Network`, never another's answer. Client listener: `db.client_listen(&[url]) -> Vec<Address>`, `db.rotate_client_address() -> Vec<Address>`. `Url` (checked by `FromStr`), `Address::new(&Url, key)`, `url()`, `key()`.
- Identity: `node() -> Tid`, `me() -> Tid` (the account, also its home group).
- `now() -> Result<Time>` (`Time`: milliseconds since the epoch, the one public time type): the corrected clock commits are stamped with; on a thin client its node's, `Network` when it cannot be reached.

## Keys: typed aspects and signals
- `AspectKey` is what the API takes: generated `Aspect<T>` constants and `DynamicAspectKey`, not a bare name; `RawKey` beneath it is osis-schema's, doc-hidden, what the engine takes (`Ak` too). `DynamicAspectKey` (`Osis::aspect_key(name)`, typed by a schema registered at run time; `DynamicAspectKey::untyped(ak)`: never typed) says what an app needs without the schema: `name()`, `value_type() -> Option<NestedType>` (`get()` its shape, `name()` its declared name), `default_retention()`.
- `ValueType` (`core/osis/src/value_type.rs`): a plain description for code handling aspects it was not generated for (the app's forms, the CLI's value text): `String`, `Text`, `Bytes`, `Bool`, `Int`, `Float`, `Thing`, `Time`, `Duration`, `Date`, `LocalTime`, `Any`, `Optional`, `Cases(Vec<TypeCase>)`, `Record(Vec<RecordField>)`, `List`, `Set`, `Map`, `Counter`, `Max`, `Min`. Types may be recursive, so what is nested is a `NestedType` (`get()` the shape, `name()` the declared name), one level per ask. `Schema` itself is not API.
- Untyped: `DynamicAspectKey::untyped`: `T = Value` and no schema (writes go out untyped: no validation, core default retention). Typed: constants generated from a `.osis` file (`notes::BODY: Aspect<Markdown>`, `notes::TASKS: Aspect<Vec<Task>>`) carrying AK, schema, defaults and codec. A read through a typed key cannot be mistyped; a write through one is validated against the writer's schema (every declared field required, spec/versioning.md §5). Nothing about the schema goes on the wire.
- Lifetime (notes/ephemeral.md): the key's marker, typed or untyped (`AspectKey::lifetime() -> Lifetime::{Durable, Ephemeral, Signal}`: none, `~`, `*`); no schema flag. A value that lives while its author is there: `at(t, k).path(p).keep_alive(&v) -> KeepAlive` (or `at(t, k).keep_alive(&v)` for the whole aspect, typed) on an ephemeral key with a default expiry (notes/ephemeral.md Values that live while their author is there).
- `osis::core`: only what apps truly read and write by key: `NAME`, `BODY`, `TAG`/`Tag`, `REQUIRED`/`Required`/`RequiredRules`. The rest (`GROUP`, `ROLES`, `CREATED`, ...) is through calls (`members`, `grants`, `created`), and `internals::core_types` for tests.
- Typed reads map `string`/`markdown`/`text` to `String`, `blob` to `Vec<u8>`, `tid` to `Tid`, `timestamp`/`duration` to osis time types; records to generated structs and enums with `TryFrom<&Value>`/`From<&T> for Value`.

## Reads
- `db.at(tid, key) -> AspectRef<T>` with `.get() -> Result<Option<T>>`, `.path(p).get::<U>()` (`U = Value` for untyped; a typed key's whole stored value: an untyped key; per-path reads skip one bad element of a large collection), `.path(p).byte_len()` (canonical size in bytes), `.path(p).stream() -> impl Read + Seek` (large string or blob), `.on_change(f)`.
- Every read below returns `Result` (a node that cannot answer is `Network`, never a default). `db.aspects(tid) -> Vec<Ak>` (what reads as present: a register whose live write was purged is listed by what it then reads), `db.has_content(tid) -> bool` (the thing has content here: its creation held, or ephemeral here, and some aspect a `Write` sets present; `false` for an unknown tid and for a thing with no content, which is both a deleted one and one never written, so `!has_content && created.is_some()` reads "empty": deleted and never written are not told apart; an actor with only role-class data, a link key or a contact before any data, reads `false`; writes and grants need only the creation held), `db.members(g) -> Vec<Member>` (`Member::{Item, Subgroup}`, items then subgroups, tid order, `group.0` and `ephemeral_group.0~`, the reverse of `groups_of`'s `item_of`, `subgroup_of`; a tid both ways appears twice; round-trips with `w.group(g).add`/`remove`; empty when it never had a member; `at(g, db.aspect_key("group.0")?).get()` tells a group from a thing that never had a member and durable members from ephemeral), `db.groups_of(tid) -> GroupsOf { item_of, subgroup_of, within }` (the groups whose `group.0` lists it as an item, those listing it as a subgroup, and `groups.0`: every group holding it as an item directly or through subgroup lists, what sync follows for its own aspects, not the groups it is only a subgroup of; `group.0` and `ephemeral_group.0~`, from the in-memory group index rebuilt from the definitions at open, nothing scanned), `db.grants(thing) -> Grants` (the timeline's roster, spec/permissions.md §2, the first admin's record edge among them while it stands; `db.holders(thing)` looks through holder actors; no call reads a thing's first admin: it is history, and gives no power once its edge goes), `db.role_on(tid) -> Option<Role>` (this node's effective role; UIs grey out what it cannot do). A thing's times, both `Option<ThingStamp { id: Option<CommitId> (None for a draft's creation), actor, node, written, received }>`, shown and sorted by `shown() = min(written, received)` (one skew rule: an author's clock may run ahead, by at most `MAX_DRIFT` before its commit is parked, and `received` is this node's clock; no app-written time field): `db.created(tid)`, the oldest valid commit carrying the thing's `created.0` that is no compaction snapshot (snapshots carry `created.0` too; `created.0` is kept forever, so it arrives wherever the thing does, and until then, only a snapshot here, `None`); `db.changed(tid)`, its last content change: of the held changes and reverts validly writing its aspects other than `created.0`, `group.0` and role-class ones (membership and sharing are no content change, of the item or of the group), the one with the latest `shown()`, else its creation (so never before `created`; a delete counts; ephemeral writes do not, so a draft reports its creation; a commit known only from a snapshot is not seen, Attribution, so after compaction on a new node it may read older than the truth). From the in-memory commit index: newest `ts` first per aspect, stopping once `ts` is at or below the best `shown()`.
- Stored data never fails a read on typed grounds (Typed reads below): a value that does not decode through the key reads as `None` and reports a `Mismatch` diagnostic. `Error::Type { path, reason }` is for what the caller passes: a typed write's value, a path the key's schema does not have.
- **Read limit**: a value whose canonical size exceeds `AppConfig::read_limit` returns `Error::TooLarge { limit }` (the bound; a length is unknown without reading) from `get` and from any typed read; read it by `stream()` or by path (a path read into a huge map or list costs O(entry) and never loads the whole). Explicit failure beats an out-of-memory.
- Values are snapshots: plain `Value` or generated structs, nothing reactive hidden inside.
- `Path`: steps `Field(id) | Case(id) | Key(Value) | Index(usize) | Elem(Value)`; `p![..]` builds one from literals and generated field/case constants (`task::DONE`). Typed path builders from codegen are not built (optional).

## Watching
- `db.at(tid, key).on_change(|db, c: Change<T>|) -> Result<Subscription>`: taken atomically with the current value, so no change is missed between read and subscribe: the callback runs once with that value (`Origin::Initial`) through the dispatcher like every later call, then on every change. Async code forwards it to a channel of its runtime and awaits that (crate docs); no second watch type (Tess). `db.on_thing_change(tid)` for all aspects of a thing (`Change<Value>` names the AK); a delete, local or remote, reaches it as its aspects going absent, and `has_content(tid)` in the callback then reads `false` (no separate deletion event: a thing is deleted exactly when it holds no content). `db.on_grants_change(thing, ..)` (its callback takes `Result<Grants>`: a lost connection is told), `db.on_status_change()`; each `Result<Subscription>`, `Network` for a thing or its grants at a node that cannot be reached now.
- `Change<T> { tid, ak, value: Result<Option<T>>, origin: Origin }` with `Origin::Initial | Local(Stamp) | Remote(Stamp) | Derived(DerivedFrom)` (`DerivedFrom::{ValidityChanged, Expired, Purged, Arrived, LostAccess}`: what changed a read when no new commit did) and `Stamp { id: CommitId, actor, node, written: Time, received: Time }`. `CommitId` is opaque (`Display`/`FromStr`), ephemeral commits included. `on_change` and `Change<T>` keep the word: they are about a value changing, whatever did it (`Derived`, `Initial`), not about commits. `Stamp`, `ThingStamp`, `Commit` hold the exact hybrid time privately for ordering. A signal aspect's set reaches each `on_change`/`on_thing_change` callback once (never coalesced). Display time for feeds is `min(written, received)` (a sender's skewed clock).
- `Subscription` is RAII: dropping it unsubscribes; `detach()` keeps it for the node's life. No ids to remember.
- Who runs callbacks (`AppConfig.dispatch`): `Dispatcher::Thread` (default), a thread the node starts; `Dispatcher::Pump(wake)`, the thread that calls `db.settle()`, so a UI applies changes on its own thread with no cross-thread hop. `wake: Arc<dyn Fn() + Send + Sync>` is called once when callbacks become due after the last `settle` began, from whatever thread queued them, after it released the node lock (so calling the node there cannot deadlock): it should only schedule a `settle` (a UI loop event). `settle` is the one call for both: with a thread it waits for it (tests), with a pump it runs everything due (including what callbacks it runs cause), on the calling thread (after another thread's pump in progress). Inside a callback it returns at once. One dispatch implementation (`Pump::step` in `watch`) with two drivers.
- Coalescing: a callback that falls behind sees every commit's effect but not necessarily one call per commit. A slow callback delays later callbacks, never writes or sync. A watch on a value above the bound delivers `Err(TooLarge)` per change and the app re-reads by stream or path.

## Writes
```
let mut w = db.write();
let note = w.create()?;                                      // first admin: the acting actor; ephemeral until a durable write
w.group(folder).add(Member::Item(note))?;
w.at(note, notes::TITLE).set(&title)?;                       // make equal: structural diff against current state
w.at(note, notes::TASKS).edit(&shown, &edited)?;             // apply only what the user changed since `shown`
w.at(note, notes::TASKS).path(p![2, task::DONE]).set(&true)?; // path op
w.at(note, notes::BODY).overwrite(&body)?;                   // always a write, of the whole value
w.at(note, notes::VIEWS).path(p![]).contribute(&1)?;
w.at(note, key).retention(r).remove()?;                      // retention per aspect
w.group(folder).remove(Member::Item(note))?;
w.group(g).add(Member::Subgroup(sub))?;
w.delete(note)?;
let done: Option<Commit> = w.commit()?;                      // one commit (two: below), or Invalid naming what clashed

let mut w = db.write();
w.expires(Expiry::In(DAY));                                  // the commit's
w.at(msg, chat::BODY).set(&text)?;
w.group(other_group).add(Member::Item(note))?;
w.commit()?;
```
- Whole-value ops: `set(&v)` makes the aspect read `v` (the spec's structural diff against the current state, spec/crdt.md §9: concurrent edits inside the value survive, but a field the app did not touch is written back if it differs from the current state); `edit(&base, &new)` writes only the difference between what the app showed and what the user produced, as path ops against the current state (struct fields, enum case, map keys, set elements, bag values exactly; sequence edits rebased onto the current sequence by matching `base` to it, notes/crdt.md Implementation), so a remote change to another field during editing is never overwritten; `overwrite(&v)` writes the whole value, always, discarding concurrent changes inside it (an equal value still counts as a write, so a log such as a chat takes it: `set` of an equal value writes nothing; a map overwritten on a long aspect costs O(writes so far), a scalar stays flat); `remove()`. `edit` or path ops are the rule for anything a user edits while remote changes may arrive; `set` is for "the value must be exactly this" (imports, derived data). Not named `replace`: it says nothing against `set`, and `TextSession::replace` means a range. Internals keep `Op::Replace`.
- Path ops at `.path(p)`, the empty path being the whole value (`at(k).set(&K::T)`, `overwrite` and `keep_alive` differ only by checking the type at compile time; `at(k).remove()` is the root's, the one shorthand, as removal is an aspect's usual end; `at` holds nothing else a path has): `set`, `overwrite`, `set_stream`, `remove` (the aspect at the empty path; a map entry, set element or list element: `p![k]`); list or text `splice(range, items)` (`SpliceItems`: a slice in a list, `&str` in text, `()` for nothing: a `&str` on a typed list is `Invalid`, an item of the wrong type `Type`, a backward range `Invalid`, nothing to do writes nothing), `move_range(range, to)`; set `add(v)`; bags `contribute(v)` (a counter's amount, a max or min's observation: one op). A map entry is `path(p![k]).set(v)`, an enum case a `set` of a `Value::Enum`. Index paths resolve against local state at commit time. A path op into a map key with no live entry creates the entry (spec/crdt.md §5.6): the first reaction to a message is `path(p![msg]).add(&emoji)`, and two nodes doing it concurrently both count; a path on through a struct field or enum case is refused (`Invalid`: it would write a partial record; `set` the whole value). An entry created by an expiring write goes at T with everything later written into it (spec/crdt.md §4.7). `group.0` field ids are `core::group::{ITEMS, SUBGROUPS}`.
- `create() -> Tid`: a new thing, the acting actor its first admin (`self.actor` at the call, so after `act_as` that actor). `create_with_admin(admin) -> Tid`: the same with `admin` as first admin (needing write on it): a thin client's way to create, whose own actor goes with it, a thing made for a group's holders, and a tree of things (write on `admin` is checked locally; a first admin the same commit creates counts through its own, so a tree of new things is one commit). A new thing is plain, deriving its secrets from its first admin's, until its first grant or `sync` gives it secrets of its own; removing the last admin of a plain thing is `Invalid` (spec/permissions.md §1). On a thin client's handle `create()` is `Invalid` at commit (its actor goes with it, notes/client-port.md §3), which leaves it `create_with_admin(g)`. The thing is ephemeral (record in memory, gone at restart) until its first durable write, which persists it with its ephemeral record chain and makes its memberships durable in that commit, same tid (notes/ephemeral.md). Membership is `w.group(g).add(Member::Item(t))` in the same commit; adding a draft is an ephemeral write of the group (it lists there and in `groups.0`, locally), adding a durable thing to an ephemeral group persists the group; a membership in a group the persisting node may not write stays ephemeral (`MembershipNotSaved`). **A thing becomes a group with its first member** (no `make_group`): the commit's first add to a thing with neither `group.0` nor `ephemeral_group.0~` writes an empty `group.0` first (`Write::first_member`; a `group.0` holding one field decodes as none, so a bare `Add` would lose the member silently). So the first ephemeral member of a durable thing makes one durable write of the group; once a group, always (emptying it leaves `group.0` present). An empty durable group takes any durable write, as any thing does; `sync` and `grant` persist on their own. A shared space with its own label (a chat, a team) is created, given data and `sync`ed, not added to the home group: its first admin's nodes find it through the home label's `label.0` cross-publish, while adding it to home copies every commit touching it (rotations with their boxes, messages) under the home label too (measured 8 KB per chat removal at 4 holders, the rotation's boxes at scale). The app's choice, not an API default. A group's items sync only through groups listing it as a subgroup (its members are its items and its subgroups' members, not its items' items), so a group meant to sync with home is both an item of home (its own aspects) and a subgroup (its items). The mistake is loud: a commit after which an added durable thing reaches no synced group while the target group's own aspects sync (an item of a synced group, no subgroup of one) fails `Invalid` naming the fix, before anything applies (`Mutation::require_synced`, checked against the state the commit leaves, so the same commit may add the subgroup; also for the item memberships a persisting write makes durable, a draft added while ephemeral). Removing a subgroup that leaves existing items in that state is not checked. A durable thing added only to groups that do not sync at all (node-local data, deliberate) is allowed and gets a `NotSynced` diagnostic after commit (spec/requirements.md, Offline and network). An add in an expiring commit makes the membership expire, item or subgroup (a disappearing message leaves its group by itself). A removal or `delete` in an expiring commit is `Invalid` at commit. (Not because it would come back at T: it would not, a reset outlives its expiry; the refusal only keeps the rule simple and could go.)
- `delete(tid)`: removes every aspect the node knows (not `created.0`, `required.0^` or role-class ones) and its memberships, as item and as subgroup, in every group this node may write (`groups_of`'s `item_of` and `subgroup_of`); a group it may not write keeps listing the tid, which reads deleted there. Afterwards `has_content` is `false` here and wherever the delete arrives (unless a concurrent write left content). Tids never die and a later write recreates the thing; no wire concept. A draft never synced here is freed at once with the drafts under it (its tid reads unknown); one that was keeps its record and tombstones until restart, as a durable thing does.
- Rights are checked locally before signing: `Error::Permission { tid, needs: Role }` when the acting actor lacks write (admin for role-class aspects) on a touched thing; `Error::UnknownThing` when its `created.0` is not held. A write is never emitted to be un-merged elsewhere.
- **`commit()` makes one commit** over every touched thing, of any reader sets, of any size (deltas page, spec/crdt.md §8), or fails `Invalid` before anything applies, naming what clashed; the app writes several commits if it means to (Tess: never a quiet split). The exception makes two commits, durable then memory (below, issues/commit-memory-half.md). Returns `Option<Commit { id: CommitId, written: Time }>` (`pos()` its place in a history; `None`: nothing to write). What clashes:
  - **Expiry**: a commit has one. `w.expires(Expiry::{At(T), In(d)})` is the commit's (a later call replaces it; `Invalid` at commit when not in the future), else the keys' defaults, which must agree (a plain key beside a `[expires: 30d]` one clashes), and a thing's `required.0^` expiry stands. A write going into a value expiring sooner (spec/crdt.md §4.7) expires with it, or clashes beside writes that must outlast it.
  - Judged on what the ops ask, not on what they turn out to write: `set` of the value already there counts.
  - **`nobody`**: a `nobody` delta shares a commit only with `nobody` deltas, a thing's record and `required.0^` aside (spec/commits.md §5). Other retention differs per aspect freely.
  - **A thing's record, `required.0^`, a purge request** never expire, so an expiring commit cannot carry them. The commit first keeping a thing therefore has no expiry: a thing with expiring content takes two commits, the first with some durable write that does not expire (`w.at(t, k).remove()` is enough: the commit holds the record and a reset, no value), or `sync` or a grant, which keep the thing (no `create_thing` helper: neither chat, whose messages are writes on the chat thing, nor the app has a caller; issues/creation-record-ordinary.md would make it one commit). A draft added with an expiry refuses the commit that keeps it (`w.group(g).remove` first, add it back after).
  - **Durable beside ephemeral beside signal** (`~`, `*` keys): different commits on the wire, a peer could see one alone. A draft's membership counts as ephemeral. The exception, two commits: what a durable write does in memory without asking (`delete` ending a thing's memory side too, a kept thing's memberships leaving `ephemeral_group.0~`, a durable `remove` of a member also in `ephemeral_group.0~`) is a second, memory commit under the durable one's `ts`; a peer may hold one without the other (issues/commit-memory-half.md). `Commit` names the durable one; revert takes both and makes two again. A draft with only ephemeral writes, expiring too, is one memory commit, its record beside it (spec/commits.md §2); with no write at all, no commit, but an id (`CommitId` is opaque).
  - A **`delete`** answers to its thing's `required.0^` like any write (each reset must carry its rule's retention and expiry), so a thing whose aspects or groups fall under different rules refuses it, saying to remove those first; every disappearing chat does (issues/delete-required-rules.md).
  - A write copying an expiring value (a key into an expiring entry, an undelete) takes that expiry (spec/crdt.md §4.7 copy expiry); one also writing what would outlast it (another aspect, another op of the aspect, an op building on another) is `Invalid`, nothing applied: write the lasting values in a commit of their own.
  - An **undo** is one commit too (two when it reverts a write that made two). It expires with the values it copies back, never at a key's default; one copying back values of different expiries (or expiring beside lasting) is `Invalid`, nothing applied, until the sooner ones have expired and there is nothing of theirs to copy back (spec/crdt.md §4.6), so a lasting value never takes another's expiry. An ephemeral undo that copies back an expiring value vanishes whole at its T, its removals and deletions too (spec/crdt.md §4.7 Ephemeral data).
  - Own watches fire after the commit is durable. Ephemeral ops take no `retention` or `purge` (`Invalid`); a signal aspect takes one root `set`.
- `Write` is `#[must_use]`; dropped uncommitted it discards its ops (debug log). Reads inside a `Write` see committed state only; pending ops are invisible until commit.
- The node acts through `me()`; `Write::act_as` sets the header's actor, under the node's rights; the node must hold write on that actor (else `Permission`), as receivers judge a commit invalid otherwise (spec/permissions.md §5.2), so a valid commit's actor is trustworthy. A thin client's rows run on `Osis::act_as` (crate-internal), held to the actor's own rights (notes/client-port.md §3); anonymous writing (notes/permissions.md) is later.
- Retention per aspect: `.retention(Retention { by, at_least: Bound, at_most: Bound })` on `AspectWrite`, default from the key; checked at commit. `Bound { until: Option<Time>, after_replaced: Option<Duration> }` (at most: `after_replaced` only zero, only `PurgeBy::Writer`; a `Duration` past `u64` ms saturates, which every check refuses), `Bound::FOREVER`: the API's own types (`retention.rs`) over the engine's millisecond `osis_schema::Retention`.
- Role-class aspects (`roles.0`, `keys.0`, `secrets.0`, `label.0`) are written only through the sharing and sync calls below; a `Write` op on them fails with `Error::Invalid`. `group.0` is written only by `Write::group` (it checks sync and cleans up tied grants), `Invalid` otherwise, also in a write from a client.

## Text editing sessions
- `db.at(t, k).path(p).edit_text() -> TextSession` (`p![]` for the whole aspect): a buffer the UI edits (`text()`, `splice(range, s)`; cut and paste with remembered ranges not built, notes/crdt.md); remote edits are merged into the buffer and reported through `on_remote(|text, edits: &[Splice]|)` (`Splice { at, del, text }` in chars, each at the text before it, from a char diff of the buffer and the merged text; `Splice::map(pos)` moves a caret: an insert at the caret goes after it) so the UI can map cursors; commits on `commit()`, after `idle_commit` of inactivity, and on drop. A session whose thing was deleted (locally or remotely) since it was known here (at open or a commit of its own) never recreates it: `commit()` fails `UnknownThing` with the edits kept (they commit if the thing comes back, e.g. an undo of the delete), and drop (which then loses them), the idle commit and a remote merge report an `Uncommitted` diagnostic. This owns the "one commit per editing pause, never per keystroke" rule (spec/requirements.md, Generality); apps never commit per keystroke by accident because the session is the only path that makes keystroke-granular changes convenient.

## Signals
A signal aspect (key marker `*`) holds nothing: `w.at(t, key).set(&v)` (one root `set`) fires every `on_change`/`on_thing_change` callback on it once, here and on the connected nodes that read the thing, best effort (notes/ephemeral.md). Needs write on the thing. Event-style signals should carry a sender sequence in their value (a node on several relays may see one twice).

## History (an aspect's commits, not its state)
- **Read**: `db.at(t, key).history(from: HistoryFrom, limit) -> Result<HistoryPage<T>>`, `HistoryFrom::{Newest, Oldest, Before(pos), After(pos)}`, in that direction (Newest, Before: towards older), neither bound counting itself; `HistoryPos` is opaque (`Ord`, `Display`/`FromStr`; `at()` its time, `commit()` its commit, none at a time's): an entry's `pos()`, a `Commit::pos()`, `HistoryPos::time(t)` a time (`Before` it: stamped earlier; `After` it: from there on). `HistoryPage { entries, more, complete }`. A page ends early past an internal cap or the read limit, and `more` says so. An unknown thing, or one the caller may not read, has an empty page.
- **Entry**: `HistoryEntry<T> { commit: Stamp (id, actor, node, written, received), kind: CommitKind, valid, body }`, one per commit with a delta on the aspect, memory commits too, by `(ts, ID)`. `body`: `Held(Option<T>)` (read from that commit's own body, so a superseded one reads as written; `None`: a removal, or not a whole value of the key's type: a `Mismatch` diagnostic as for any typed read, the untyped key shows it), `TooLarge { limit }`, `Purged { by, actor }` (a tombstone, `actor` the request's verified actor: earliest request by `(ts, ID)`; lasting for a permanent delta, spec/commits.md §5), `Gone` (expiry, keep bound, compaction), `NotFetched` (header here, body not). `commit.actor` is verified exactly when `valid` (spec/permissions.md §5.2); an invalid body still reads, and the app chooses. A `CommitKind::Snapshot` (a compaction snapshot) is an entry of its kind (Attribution); a chat shows `Content`s.
- **A gap**: `complete: false` means a label carrying the thing has not finished a pass here (or the thing is held for receipts only), so entries may yet arrive anywhere in the history: not fetched, not absent. A new node's first sync (spec/sync.md §6) is this state: role commits, then newest first, so `HistoryFrom::Newest` reads real entries at once and `Before` pages older ones as they arrive; status `Syncing` until done. A node that chooses not to fetch (not built: issues/partial-history-fetch.md) would say the same. It does not bring what compaction replaced before this node held it: that is the snapshot's entry.
- **Watch**: `at.on_history(|db, HistoryEvent<T>|) -> Subscription`: `Commit { id, entry: Option<HistoryEntry<T>> }` per commit whose entry reads otherwise, read when delivered (a new message, a late older one, turning invalid or valid, a body arriving, purged, dropped; `None`: no entry any more, a memory commit gone). `Reread`: events may have been missed (the connection to a node dropped or came back, an entry did not fit a Notify): read the pages shown again. `Ended(e)`: over (the source moved, a lapse): subscribe again. No initial call: subscribe, then read pages; an event repeating what a page showed is harmless. Own ephemeral commits leaving the undo log past `Config.ephemeral_undo_bytes` are not told.
- **Delete for everyone**: `w.at(t, key).purge(Purge::Commit(id))`; **by author**: `.purge(Purge::Author(actor))`; `.purge(Purge::All)` the whole aspect's, with its removal. Each judged per delta by the purge rights (spec/permissions.md §6), no override: under `author` or `nobody` an admin's request drops nothing, under `nobody` a flood stays (Tess; why it is not the default). Outside the chat's class a wide request's arrival-order differences are in held bodies, not reads (what the order oracle checks, notes/testing.md). `Purge::Author` names deltas stamped before the request, in any arrival order; later writes stay, so remove the member too. `actor` is one header actor: an account's nodes share theirs, each of its thin clients has its own, so a member's writes through a client take their own request. An invalid commit is named by the actor it claims. Under a required expiry `Purge::All` and a `set` beside a request are refused (a commit with a request carries no `expires`); `Purge::Commit` and `Purge::Author` alone work, as `purge.0` has fixed retention. A request needs write on the thing (`Permission` otherwise: no class gives a right without it) and carries a `purge.0` write, as its commit needs a delta to go under the thing's labels (spec/commits.md §5); so it adds no entry to the purged aspect and resets nothing: purging the live write of a register leaves it reading absent, `set` in the same commit for a value.
- **As built**: `engine::history`, `ephemeral::history`, `osis::history`. A page walks a range of `by_aspect`, O(log n + page); validity, author, time come from `Meta`, no decode but the page's. A memory aspect gathers its held commits and own batches (both bounded by the ephemeral caps). No index of its own, so none to keep exact. The watch is `Core::history_changes` at the end of a transaction, from the journal of `ix.commits`: which commits' parts changed `(valid, dropped, missing)`, O(commits changed), one place whichever path changed them, plus what the meta does not show (`history_named`: a dropped part now named by a request). Off until the first `on_history` of an open (`Engine::watch_history`, sticky). Purge requests are stored per aspect only when they name more than one delta; by name under `pn/` + aspect + commit, so a delete costs other deltas nothing and an entry's purge state is O(aspect-wide requests + its own).
- **Not `commits`**: the commit query lists every kind over a scope with relations, O(scope), for undo; history is one aspect's bodies, paged.

## Commits: query, undo, redo, revert (Tess: one model)
- **Query**: `db.commits(&CommitQuery) -> Result<Vec<CommitEntry>>` over the held commits, anyone's, and this session's own ephemeral commits (notes/ephemeral.md Undo), newest first by `(ts, ID)`. `CommitQuery` is a plain struct with `Default`; empty fields match all: `scope: Scope::{Thing, Aspects, Group}` (resolved when used, nothing stored; `Thing`/`Group` cover durable aspects, drafts and `ephemeral_group.0~`; an ephemeral aspect of a durable thing only when named by `Aspects`), `actors`, `kinds: CommitKind::{Content, Revert, Role, Snapshot, Ephemeral}` (`Ephemeral`: an own ephemeral commit, a revert too), `reverts`, `reverted_by`, `in_effect`, `since`/`until` (`Time`), `after` (paging), `limit`. `CommitEntry { commit: Stamp (the watch's type: id, actor, node, written, received), kind, reverts: Option<CommitId>, reverted_by: Vec<CommitId>, in_effect, aspects (valid, in scope; those of the memory commit following it too), content_gone, purged: Vec<(Tid, Ak, CommitId)> }` (`purged`: of `aspects`, those a held purge request dropped, with the earliest request: the entry is a tombstone there, shown or not by the app; for a permanent delta it stays and reaches new nodes, spec/commits.md §5; a thin client reads it under the same scope rule, `aspects` and `purged` of what it may read only): signed-header facts only (Attribution); commits valid on no aspect in scope are left out. Relations are judged over every held commit touching the entries' aspects (a revert touches its target's aspects; undoing a creation resets every held aspect of the thing, the creation's among them). `db.undo_target(&scope)`, `db.redo_target(&scope) -> Result<Option<CommitEntry>>`: the commit `undo`/`redo` would revert now (fails `NotUndoable` as the call would): what a UI labels or disables its buttons by. `undo`/`redo` take exactly that, then revert.
- **Revert**: `db.revert(id: CommitId) -> Result<Commit>` (an own ephemeral commit from the in-memory log, bounded by `Config.ephemeral_undo_bytes`, 16 MiB, older ones `NotUndoable{ContentGone}`; another node's or a pre-restart one `Invalid`): a content commit naming its target (wire `undoes`) with the inverse writes (spec/crdt.md §4.6: parts superseded since are skipped; a dropped body or nothing to write is `NotUndoable{ContentGone|Superseded}`; role commits and snapshots are `Invalid`). In effect: no revert in effect reverts it. Revert depth: 0 for a commit, +1 per revert (odd = an undo, even > 0 = a redo).
- **Undo/redo** (this actor, any node, under one lock): `undo(&scope)` reverts the newest own in-effect commit or redo (even depth); `redo(&scope)` reverts the newest own in-effect undo (odd depth) unless a newer own commit (depth 0) is in scope (a new commit clears redo). `None` when nothing qualifies; `NotUndoable` when the chosen one cannot be reverted (nothing older instead). A revert of someone else's commit counts as an undo of the reverter's: the reverter's redo reverts it, their undo skips it; the reverted commit's author can no longer undo it (out of effect) and cannot redo it (not their undo).
- Undoing a creation deletes the thing (Tess; spec/crdt.md §4.6): the commit that created it (one carrying its `created.0` when created and persisted at once, else the ephemeral one); its revert also does `delete`'s writes (every aspect, both sides, and its memberships, as item and as subgroup, in every group the node may write; `Permission` when the node may not write the thing, never a partial revert), so redo (or `revert` of that revert) brings the thing back with content and memberships. A deleted draft keeps its record (redo needs it) and reads unknown. Saving a draft (the commit persisting an earlier draft) is no creation: undoing it reverts its writes and returns the draft (ephemeral content, ephemeral memberships, known), a further undo deletes the draft, redo saves it again (notes/ephemeral.md). In a thing's scope, creating a draft is the oldest commit.
- Undo restores the read before the undone commit where only undos changed it since (spec/crdt.md §4.6 SHOULD): undoing the first write into a spot that did not exist resets the spot when it reads just what that write made it (concurrent writes arriving later are wiped); a register in a present struct stays (no nested register reset).

## Large values
- Typed and untyped reads materialize up to `read_limit`; above it `stream()` (`Read + Seek`, lazily fetching chunks, memory bounded to a chunk plus the tree path), `len()`, and path reads. Writes: `set_stream(impl Read)` on a `blob`/`string` position builds the chunk tree without materializing (plans/large-values.md); `set`/`edit` accept in-memory values of any size the caller has. Equality is by content; links never appear in values the API returns (`Value::Link` is replaced by the materialized value, or the read fails `TooLarge`; a link that cannot be read, its blob not held or failing verification, reads as absent at its position with an `Unreadable` diagnostic, spec/data-model.md §6; history bodies read `NotFetched` instead). A read that missed a blob notes the aspect, a history read the (aspect, commit) (`Engine::missed_blob`, `Core::missed`); the next blob stored re-delivers every noted aspect to its watches (`Cause::Fetched`) and every noted entry as `Event::History`, and a read still missing one notes it again.

## Queries (not built: a design pass first, issues/api-deferred.md)
Per-aspect reads are not enough for any list-like UI; meanwhile apps list group items with `members(g)` plus per-thing reads. Expect most of a slow, not very feature-rich node to grow over the local store, over time; nothing of it touches the wire. The sketched shape:
- `db.query(Query::in_group(g).with(key).order(Order::Time | Order::Field(path)).page(n)) -> Live<Vec<Hit<T>>>`, things in the group (transitive) carrying the aspect, paged, with `Hit { tid, value: Result<Option<T>>, ts, received }` and a watch on the result for changes in the visible range (a chat timeline, a feed, an inbox).
- `db.backlinks(tid) -> Live<Vec<(Tid, Ak)>>`: things whose values reference the tid.
- Later: filters over values (unread, by actor, by tag) and counts, live; text search. Indexes are local, rebuildable, sharded per aspect (notes/local-store.md).

## Sharing and roles
Synchronous unless noted; each is one role commit made locally (spec/permissions.md §2), delivered by the sync layer. Nothing here assumes a role has one answer forever: admin disputes are settled per node (below).
- `db.grant(target, holder, role, GrantOpts { until, may_grant })`: adds, raises, or changes `until`/`may_grant` (what `opts` leaves out goes). Never waits, never lowers: a role below the holder's present one is `Invalid`, naming `set_role`, and so, for an admin, is one below a role it lost with no explicit write since (`Engine::lost_role`: a grant that ended, finalized or not, or a self-removal). Spec/permissions.md §5.1 step 4: that write audits against the edge as restored, and a grant carries no frontier, so it would undo all the holder ever wrote there, everywhere; one over an edge still in the state would also lack its rotation. `set_role` removes first (a commit of its own, frontier and rotation, a failure between leaves the holder with no role, as it had), then grants; the removal says retain or erase by the thing's default, harmless: the role lost already dropped or kept the copy, and the new role ends a copy and brings the data back. An invite grant audits nothing: it goes through once the edge is out of the state, and until then is `Permission` (receivers refuse it without a rotation it cannot write; spec/permissions.md §2 "an expired edge counts as none" holds only after the finalize). Needs the holder's `keys.0` held (contact card, a shared group, pairing), else `Error::UnknownActor`; admin, else `Permission`. Records the permission and nothing else (Tess's decision): no label is made, and nothing is refused for lack of a route. The one overlap with `set_role`, stated at its definition: the call that does not block and takes no role away, and the only setter of `until`/`may_grant`. A lower `may_grant` does undo the grants the holder made by it (issues/grant-audits-without-frontier.md). The first holder of a plain thing besides its first admin gives it secrets of its own (about 2.6 KB of boxes per holder: share sets through one actor, notes/permissions.md Patterns). The holder's admins learn of it through its inbox; a group holder's readers through the copy its admins put under its label (a group with a label of its own has it as its inbox, so they read it there too). **Route** (spec/sync.md §2): the holder reads the target only through a live label it can open that carries it: the target's own, or one of a synced group whose closure holds the target and whose actor the holder may read; with none it holds the role and reads nothing, shown as `SyncState::NoRoute` (below) at the granter's node and the holder's alike, until `sync(target)` (its first label is delivered to its holders) or a membership in a synced group it reads gives it one. Made after the grant, so a holder who is no contact never finds this node's `reach.0` under it (no rotation). `make_link` is the one composite: it syncs the target when it has no label (K reads that label alone, nowhere else to live). Every other label is `sync`'s, or infrastructure with no thing of the app's behind it (an account's home, a contact profile, K's own, a replacement's successor of a label that was there, `group_source` taking a group home).
- `async db.set_role(target, holder, Option<Role>, SetRoleOpts { retain_copy })` and `db.set_role_now(..)` (same arguments, synchronous): raises, lowers or (`None`) removes. A role not changing writes nothing. No current role: `Some` is `grant` with default options (after removing a lost grant above it, see `grant`), `None` writes nothing. Keeps `until` and `may_grant` (capped at the new role). A raise waits for nothing. Lowering and removing: `set_role` first catches up (Demotion and catching up, below), then writes; `set_role_now` writes at once (`PreSync::Unsynced { proceed: true }`), for any caller that will not wait. A limit is the caller's: its runtime's timeout around `set_role`, falling back to `set_role_now` (crate docs, Sharing). The scope is computed before waiting over every way in it will remove (`role_scope`), so its refusals (a joiner's role, another actor's way) come before any wait; the writes are one shared synchronous body (`change_role`). `retain_copy` (spec/permissions.md §2, §3: `None` fills from `RequiredRules::retain_copies`, written as any required rule, no call of its own) with `Some` is `Invalid`. A removal follows `holders` until the holder reaches `target` no more (a holder both granted and joined by a link loses both). A joiner by a link of this account is removed with the link key in one commit (`revoke_joiner` in the engine, one rotation): the link stops working for everyone who has not redeemed it yet, K's other joiners stay (the joiner may keep the seed, spec/permissions.md §7). That is chat's kick and the one route to remove a joiner. A joiner's role cannot be set (it could act as the link key), and a holder reaching `target` through another actor (a team, a link of another account) is `Invalid` with the actor named. `Unsupported` on a routed thing, raises too (`grant` goes through the route). `db.retained_copies()`, for a thin client those it reads, notes/client-port.md §3; `db.drop_retained_copy(actor)`, the main actor's.
- `db.leave(holder, target)`: removes a holder's own grant, no pre-sync, as a self-removal: no rotation (the target's next writer or admin rotates). `holder` is `me()`, or a group or actor this node administers (`Permission` otherwise; for such an actor, `Invalid` when this node is an admin of the target: `set_role`, with its pre-sync). `me()` with this node also an admin of the target is an explicit removal with no pre-sync, and rotates. No such grant and no other way in writes nothing; a holder still in through another actor is `Invalid`, naming it (a joiner leaves the link's actor), since nothing would change. The main actor's only: the flow runs on the node's authority, not a client's actor. A give-up call belongs with it (issues/api-leaving-give-up.md).
- Tied grants (spec/permissions.md §2, notes/tags.md Sharing a tag): `db.add_with_grant(Member::{Item, Subgroup}(t), group, role)`: adds the member and grants the group, tied, so the grant goes when the membership goes (`Permission` before writing when it may not grant; a grant at `role` or above is kept as is; to add without granting: `w.group(g).add(..)`). `GroupWrite::remove` removes the tied grant after the commit when that is a self-removal (`Osis::untie_now`), else node-sync's obligation does. `Grant.with_membership: bool` in `grants` (the stored tie names the membership's element, spec/permissions.md §2); `grant` keeps a tie, a new grant has none; `add_with_grant` on a tied grant whose element is gone ties it to the live one. Members with no grant: `groups_of` minus `grants`. A `with_membership` grant whose thing is no longer a member is on its way out.
- `db.holders(target) -> Vec<Holder { actor, role, until, through }>`: everyone holding through the grants below `target`, breadth first; one entry per grant that makes the actor a holder, by the shortest way to that grant (`role` the least along it, `until` the earliest), and again by a longer way that gives more (a higher role or later end than each before it), so the actor's best role and end are among its entries. The main actor's only for now (`Reader` hides what the actor may not read, so it could be a client row). O(grants below × distinct ways that beat each other): a crafted lattice has at most one per role per distinct `until`, nothing per path. Who holds through K: `holders(K)`, or `through.contains(k)` here; `LinkId::actor()` gives K.
- Nodes: pairing is transport-agnostic: the app carries three texts: `db.pair_offer() -> PairOffer` (short-lived, one-time secret); on the new node `Osis::pair(Store, &[Address], &offer, Config) -> Joining` with `joining.request()`; back on the first `db.pair_accept(&request) -> (node, PairReply)`; then `joining.finish(&reply) -> Osis`. Request and reply are authenticated by the offer's secret. A direct-connection convenience over this is later. `db.nodes() -> Vec<AccountNode { node, role }>`; `async db.remove_node(node, SetRoleOpts) -> Vec<LinkInfo>`: `set_role(me, node, None, ..)`, kept for what it returns: the account's working links, whose seeds the node keeps (notes/permissions.md Links). No `_now` twin: a lost or stolen node is `set_role_now(me, node, None, ..)` then `links()` (the CLI's `node rm --now`).
- Links: `db.make_link(target, role, LinkOpts { until, single_use, direct }) -> ShareLink` (text; `direct`, opt-in and required with no saved peers: the link carries this node's dialable key and relays, never `reach.0`, so a redeemer with no common peer reaches it; the key rotates when the link ends; notes/networking.md First contact); `async db.redeem(link) -> Tid` (grants only once K's edge on the target is here; a write or admin link returns once the target's delete keys are held, so the first write builds (a direct link's grant comes under K's label with no inbox hint, the target's `keys.0` after it); a link known to have ended, K off the target included, fails `Invalid` at once; anything else waits until dropped, a read of K's label to its end included, as the edge may be on its way from the maker's node (a link naming the wrong target waits too: an app's timeout says "could not confirm, retrying is safe"); `import_contact` asks the same edge, the same way); `db.links() -> Vec<LinkInfo>` (the account's, whichever node made them; filter by `target`; `Unsupported` on a thin client, so a client with a secret of its own adds none); `LinkInfo.id: LinkId` is opaque (`Display`/`FromStr`, `actor()`); `async db.revoke_link(id)` (catches up first, no `_now` twin: a join not received is undone; its joiners keep their roles on K; a bearer may have kept the seed, spec/permissions.md §7). One joiner: `set_role(target, joiner, None, ..)`, above. Single use is in the link (`flags`, spec/wire.md §10): the redemption removes the link key and node-sync on any sharer node finalizes it, and an expired link, after a complete pass of K's labels (`SyncEngine::finalize_links`; the seed thing is an item of the home group so every node holds it); a second redeemer is told it ended (`Invalid`). Waiting calls (`redeem`, `import_contact`) remove their waiter when dropped and forget the held key on every outcome. Bearer read (`async Osis::open_link(Config, link)`) slipped (issues/api-deferred.md).
- Invite requests (spec/sync.md §3): `db.invite_requests() -> Vec<InviteId>` (an invite from a sender with no known connection: nothing it names is fetched or dialed yet; nothing about sender or thing is shown, both would be the sender's unverified word), `db.accept_invite(id)` (applies the grant, joins as any invite), `db.decline_invite(id)` (forgotten for good, re-sends included); both `Invalid` when no such request waits. Not watchable yet: an app polls (e.g. on status changes).
- Contact cards: `db.contact_card() -> ContactCard` (a read link to a profile thing whose label carries the account's `created.0` and `keys.0`, spec/sync.md §3; made once); `async db.import_contact(&card) -> Tid` (the account actor, then usable in `grant`).
- Disputes (spec/permissions.md §5.1 Trust set; notes/disputes-plan.md step 4): two admins removed each other without having seen the other's removal, and each node settles it for itself. `db.disputes() -> (Vec<Dispute { id: DisputeId, target, author, holder, commit, side: Side::{Author, Holder}, chosen }>, unexamined)`: the fights this node knows and the side it stands on in each, taken by default when the fight was found (the side its own role exists on, else whichever removal it held first) or by `db.choose_side(id, Side)`, which stays until chosen again (switching re-reads what the thing reaches; slow on a long history; `Invalid` for a removal not held). `db.on_dispute(|db, d|) -> Subscription` fires once per fight found, with the default taken. Finding one costs a walk of the role history per contestable removal, so a hostile flood leaves some unexamined (the count; the list examines at most 64). Plain calls on `Osis`, per node, never a data write and nothing on `Write`; `Unsupported` on a thin client. `DisputeId` is opaque text (`Display`, `FromStr`). CLI: `disputes ls`, `disputes choose ID author|holder`.
- Entitlement: holders read what the group (or an actor in it) holds a role on, record edges included; a thing whose first admin is `me()` added to a shared group stays unshared (notes/sync.md). Shared things take the group as first admin.

## Sync configuration and status
- `Address` = transport URL plus a node's key (`FromStr`/`Display`; a `quic://` URL without a port is kept as `:4040`, so one node has one address).
- **Saved peers**: `db.saved_peers() -> Vec<Address>`, `add_peer`, `remove_peer`: nodes serving at a fixed address (`serving_address`; a plain node has none to name, and a saved peer is what a label's hosts are underneath: two kinds of peer, issues/node-host-unify.md). What syncs from now on syncs with them. The account's inbox and the sync of groups whose list equals the saved list follow a change (written first: the list, then the inbox): the home group and groups made under the account (their record chain reaches it) that this node administers; not others' groups, link actors or the card's profile (their text names their peers), and a group with holders besides the account's nodes never loses its last one.
- `db.peers(group) -> Vec<Address>`: whom a group syncs with as this node knows: the group's saved peers (its live sync IDs' host lists, `label.0`), then those it would dial directly: readers' published addresses (`reach.0`) and a link's sharer (`SyncEngine::group_peers`, `peer://` addresses, at most `max_peers_per_label`). Not those that dialed this node and are not known otherwise. A saved peer is a fixed address a group's admins wrote; a node is reachable as one only at a stable address (issues/node-host-unify.md, spec needing a concept change).
- `db.sync(group, &[Address])` makes a group synced (its own sync ID, the group given secrets of its own first; admin of the group; empty list: the saved peers; a no-op when it syncs, unless the list names others: `Invalid`); `db.unsync(group)`; `db.set_sync_options(group, SyncOptions { share_address: ShareAddress::{Auto, Always, Never}, mode: SyncMode::{Full, LogOnly} })` (stored, the whole policy; `Unsupported` on a client's handle, as `sync_options` and `rotate_peer_address`; `LogOnly`: this node holds none of the group's content, a demotion reads its headers only; `Auto`: publishes `reach.0` only where every reader is this account, its own or a contact, notes/peers.md; a group excluded while its labels hold the current `reach.0`, and a direct link ending, rotate it; `db.rotate_peer_address()` by hand). The home group is synced at `create`.
- `db.status() -> Status { connected, groups: map<Tid, GroupSync { state, last_sync, refused_by, leaving, not_carried_to }>, node_connections, two_sources }`, `on_status_change()`. `connected`: sync connections up, whichever side dialed (a client's session is none). States, worst of a group's sync IDs:
  - `Synced`, `Syncing`; `Unreachable` (no saved peer answers); `Refused` (a saved peer does not admit it, yet, code 14, and no other has it open; `refused_by` names those, also when another has it; `wait_synced` waits on it and fails `Unsynced` at its deadline); `Stranded` (waiting for a re-seal, spec/permissions.md §3).
  - `NoPeers`: no saved peer and no other node has it open with this one now. `Connected`: no saved peer, but co-readers have it open, dialed or served (`LabelStatus::peers_connected`): true, and says nothing of whether they hold everything. Waits treat the two alike (issues/no-server-audit.md rows 13-18: `Unsynced`, no catching up, `complete` true).
  - `LogOnly` (the app set it: what is here is stale; `wait_synced` leaves it out). `NotCarried` (`Engine::unrouted`): a thing with no sync of its own whose roster has a holder that reads no live sync carrying it, as this node knows, `not_carried_to` naming them (this account's own clients on its own things left out). It clears when the thing syncs or a synced group the holder reads takes it in, and comes back when that sync is replaced without a successor, the thing leaves, or the holder loses the group but keeps the grant.
  - `leaving`: this node left the group and keeps it until a saved peer has its removal (`drop_left`), set for good while none takes it.
- `async db.wait_synced(SyncScope::{Thing(tid), AllWithSavedPeers})`: resolves once every local commit in scope reached a saved peer and a pass changed nothing, and every pending delivery in scope (inbox deposits, a non-writer's deposits) was taken. `Thing(t)` covers every sync ID of the groups holding `t` and fails `Unsynced` on one with no saved peer or stranded (a replaced one beside another of its group is left out; nothing holding `t`: `Unsynced{t}`, at once unless a route may still arrive: an accepted grant named it, or this node does not administer `t` and something it syncs has more to bring), plus the deliveries about `t`, a thing it holds or one of those groups. `AllWithSavedPeers` covers every sync ID with a saved peer (a stranded one fails) and every delivery: named so because a group with no saved peer is left out, and `Ok` then says nothing about what was written there. The CLI's `sync` and `wait` print those groups on stderr. A `Refused` sync or delivery, and a peer out of reach, may yet resolve: it waits, `status` shows them. `wait_synced` and the pre-sync sync every label (`SyncEngine::sync_now`).
- `db.nudge_sync()`: a label not live syncs, a live one only judges again, a connection quiet for `retry_ms` gets a ping (`SyncEngine::refresh`; polling is harmless).
- Serving (notes/serving.md Hosting in the node): `db.set_serving(Option<Serving { listen, admit: Own | Open, admitted: set<SyncId>, replicate, policy: ServingPolicy, caps: map<SyncId, ServingCaps> }>)` writes the node's `host.0^` (none: stop; a limit it cannot run by fails `Invalid`). `ServingPolicy` is the plain limits (`group_entries`, `group_bytes`, `groups`, `entries`, `bytes`, `connections`); the others are `internals::host_limit`, by name. `SyncId` is an opaque label ID kept to this one purpose: `db.sync_ids(group)` is the only way to ask (a group sourced elsewhere at its node; `Unsupported` for a client with its own actor), `db.serving()` reads it, `db.serving_address() -> Result<Option<Address>>` once it listens (`Network` when it could not), `db.serving_key()` its key without listening (made when serving first starts, shredded when it stops; `Address::new(listen_url, key)` for a fixed port). With `Own`, the node serves its account's own groups (record chain through the account; no grant counts, since grants need no consent) once their saved peers name its address; someone else's group, even one it reads or administers, takes `Open` or its id in `admitted`. The CLI's `serve` is these calls.
- Bundles: `db.export_bundle(&[groups], impl Write)`, `db.import_bundle(impl Read)`. Feature `lan` (the LAN loop).

## Diagnostics (decided; shape is proposal)
A place to dump problems such as a colliding record from a peer, rejected writes from a revoked actor, a thing created into an unsynced group, a thing whose sync is stranded. Apps may log, surface or ignore it; correctness never depends on anyone seeing it.
- `db.on_diagnostic(|db, d: Diagnostic|) -> Subscription`. `Diagnostic` (`core/osis/src/diagnostic.rs`, translated from the engine's kinds, which the port keeps carrying) is an enum with named fields per kind: what an app can act on (`NotSynced`, `MembershipNotSaved`, `Uncommitted`, `OwnWriteInvalid`, `Mismatch`, `Unreadable`, `LostAccess`, `Stranded`, `EphemeralRefused`, `Storage`, `Callback`, `SyncStopped`, `Parked`: a commit from a newer format, so an app can tell its user to update; never constructed yet, issues/parked-diagnostic.md) and `Handled { things, commit, peer, detail }` for the rest (bad, parked, pending, colliding, misstated, repaired data: log material, its engine kind leading `detail`). `#[non_exhaustive]`, `Display`.
- A peer must not be able to flood it: dedupe per (kind, tid), rate-limit per peer.
- Must include: "this node was removed from actor X by node N at time T" (a stolen node's removal otherwise looks like a silent lockout) and "stranded on group G" (also in status).

## Errors
`Error::{UnknownThing{tid}, UnknownActor{tid}, Permission{tid, needs}, Type{path, reason} (a typed write's value, or a path outside the key's schema), TooLarge{limit}, NotUndoable{commit: CommitId, reason}, Unsynced{groups}, Invalid(reason) (a malformed link, card or value; a write growing an ephemeral aspect whose own state no longer fits a blob, notes/ephemeral.md Synced ephemeral data), Storage(..), Network(..), Unsupported(..) (this kind of handle does not carry this call), OutcomeUnknown (a write through another node whose reply was lost), Refused(..) (the node will not take this session: its secret or uid, or an address with no client port), Closed}`. Peer-caused problems never surface as errors to the app; they are diagnostics.

## Typed reads (decided; spec/versioning.md §5)
A typed read (`at().get()`, `on_change`, path reads) of a stored value with an unknown enum case (a newer version's), a type mismatch or a missing required field reads as `None` and reports `Diagnostic::Mismatch` (the thing; detail: AK, path, reason; deduped per (kind, tid) like every diagnostic). Tess's direction: synced data is other writers' input and an app cannot act on an error, so one odd thing must not fail a screen read with `?`; one read call, no lenient variant. Per-path reads let an app read the good elements of a collection with one bad element. The untyped `Value` API always shows what is stored. App types are views over the wire type, generated or hand-written; transitions and the form-choice policy are codegen conventions (notes/versioning.md). Codegen warns on `list<struct>` aspects (records edited concurrently belong in `map<K, struct>` or get path ops: the list diff pairs changed entries in order and a misaligned pair loses concurrent edits).

## Attribution (Tess's decision)
The API reports only verifiable authorship: who wrote something and when comes from the signed header of a commit held here, never from a claim another commit makes (a compaction snapshot vouches for its carried writes without naming their authors). No API type carries an "unverified" flag; what cannot be verified is not reported.
- The commit query lists the commits held here, each with its own header's author and `ts` (a snapshot as itself); commits known only from a compaction snapshot have no entry. A watch's `Origin` names the commit applied: a snapshot arriving is reported as itself (its author, ID and `ts`). A valid snapshot's copy governs a held original it misstates (spec/permissions.md §5.2): the read changes with the snapshot as `Origin`, while the commit query and `changed` still name the original's commit as the change it was (snapshots are no change); the node reports the snapshot (`DiagnosticKind::Misstated`).
- No per-write attribution call exists yet; any future one follows this rule: a value known only from a snapshot reports the snapshot or nothing.
- Required retention: `w.at(t, core::REQUIRED).set(&rules)` (an admin; `RequiredRules { rules: BTreeMap<prefix, Required { retention, expires: Option<Duration> }>, retain_copies }`, wrappers over `core_types` with one wire form), `osis set T required.0^ V`, no API of its own. A prefix (`chat:msgs:`, empty for every aspect) covers per-year names. After it the writer's node fills that retention and expiry and an override errors. A writer that has not seen a change writes under the old rule and its delta turns invalid once it arrives: its node reports `DiagnosticKind::OwnWriteInvalid` (the app writes again: osis-chat `resend`). At most `MAX_REQUIRED_ENTRIES` entries. Set it before granting anyone: a member from before a change can backdate below it.
- Provable authorship of every write (audit trails): give the aspect `Retention { at_least: Bound::FOREVER, .. }`; its bodies are then never compacted away, so each write keeps its signed original.

## Demotion and catching up (decided)
A demotion's frontier is the demoting node's own receipts (notes/permissions.md, Revocation), so `set_role` catches up on every group below before stamping it (spec/permissions.md §5.3, `Osis::catch_up`). No node can know it has everything (issues/revocation-without-arbiter.md), so "caught up" means: with whoever is reachable now (Tess). Per label in scope (`caught_up` in share.rs):
- With saved peers: `SyncState::Synced` (every host connection has it open and its last pass ended with nothing outstanding), waited for as long as it takes, a peer out of reach or refusing included.
- Other readers on a connection this node dialed with the label open (`LabelStatus::peers_open`/`peers_idle`): their last pass ended with nothing outstanding, judged as they are connected at each look (one that drops out leaves the set, one that connects joins it). A reader that dialed this node (served session) is not judged: nothing here says what it still holds.
- Nobody reachable: done at once (no saved peer and no dialed reader), with no runtime too. A label with saved peers and no runtime fails `Network` (`wait_until`).
- Receipts-only groups (`SyncMode::LogOnly`) are read for receipts at their hosts; one with no host has nobody to read from and is done (`receipts_read`).
- `Stranded` (a host refuses every key here), and a receipts read no key opens, fail `Unsynced` at once, nothing written: the one known-never case; the standing rule (a wait sure never to finish fails) holds, and `set_role_now` is the way past it.
Which calls have a `_now` twin: those a node must be able to finish with nobody answering, its usual case being a lost or stolen node, a hostile holder or a leaked link: `set_role_now`, `revoke_link_now`, chat `kick_now`; `remove_node` composes (`set_role_now(me, node, None)`, then `links`).
With nobody reachable nothing says the result keeps what the holder wrote elsewhere; `status` shows such groups `NoPeers`/`Connected`. Partial sync is partial protection (the frontier is per aspect). What remains is hosts it cannot reach and peer-only edits of readers not connected (issues/revoke-needs-whole-tree.md). Rejected: `Try(d)` (a timeout in the API: the caller's runtime does it), `Backdate` (complexity nobody asked for), `Skip` (`set_role_now`); a "cut access only" removal (`until` = now by an admin) leaves a permanent backdating window until a real demotion follows; third-party receipts fail the fixpoint model.

## Footguns closed (keep them closed)
- Read-modify-write clobber (a form saved with `set` wipes a tag another node added meanwhile): `edit(base, new)` and path ops; docs steer every interactive edit there.
- Out of memory on an unexpectedly large value: the materialization bound fails explicitly; streaming and path reads exist.
- A thing that never syncs: membership a group op, a member of a group whose own aspects sync but whose items would not fails, `NotSynced` diagnostic for node-local memberships.
- A member lost silently: a thing becomes a group with its first member.
- `set` losing a repeated message on a log: its doc says so, and `overwrite` is named for always writing.
- A deleted thing reading as present (an editor left open on it): `has_content` is false once no content is left; deletion is derived, never a flag.
- A forgotten unsubscribe: RAII `Subscription`.
- Missed change between read and subscribe, and a callback invoked on the registering thread once and the dispatcher thread later: atomic `on_change`, initial call through the dispatcher.
- Writes a node is not allowed to make, emitted and un-merged elsewhere later: rights checked locally at commit.
- `async` reads forcing a runtime into GUI apps and hiding that nothing waits: synchronous data API.
- Per-keystroke commits (13 bytes forever each): the text session.
- A role lowered without syncing what the holder wrote: `set_role` catches up; not waiting is `set_role_now`, spelled out.
- Concurrently edited records in a `list<struct>`: codegen warning, path ops.
- Deadlock or reentrancy inside callbacks: no callback under a lock, any API usable from a callback.
- Secrets in the API: none; the link seed only in the link.

## Rejected shapes
- Everything `async`: local operations never wait, and every GUI would carry a runtime; browsers are served later by a worker-backed synchronous store.
- `ListenerId` cancellation and a callback invoked before `listen` returns.
- An entity/ORM layer typing whole things: aspects belong to different schemas and apps; per-aspect typed keys fit the model.
- Auto-subscribing reactive reads (reads inside a computation register listeners): hidden magic; `on_change` covers it explicitly.
- `set` diffing against the app's last read implicitly (state hidden in the handle): `edit` takes the base explicitly.
- Exposing links or a `Value::Large` variant in untyped values: the bound plus `stream()` keeps values plain.
- A default membership.
