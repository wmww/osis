# Rust API
> Summary: The designed shape of the `osis` crate (the only crate apps use): a synchronous local data API (typed aspect keys, `get`/`at`, RAII watches, a `Write` batch with `set`/`edit`/`replace`/`remove` and path ops, explicit owner, placement by group ops, ephemeral things and aspects in memory, rights checked locally, bounded materialization), signals, the commit query with undo, redo and revert, text sessions, minimal queries, the sharing and sync surface (async only where another node is waited on), diagnostics; the owner's fixed directions; the footguns the shape closes and why; rejected shapes. Shape is the plan's target, to be refined with the example apps (owner left it open).

## Fixed directions (owner)
- Plain values and listeners, no CRDT concepts (notes/crdt.md). A lost concurrent write looks like any LWW loss.
- Large values: getting a string as one `String` is allowed; there must also be tools to read, edit and listen to a large value without materializing it.
- Undo: per actor by default; plus a view of all available changes in scope from which an admin may remove others' (notes/crdt.md).
- Listeners fire for local changes too: a committed write fires matching aspect listeners and a sent signal fires matching signal listeners on the same node, including those of the app and handle that made the change.

## Design rules
- **Local and synchronous.** Every data operation completes against the local store with nobody online (spec/requirements.md, Offline), so reads, writes, watches, undo, sending signals and membership writes are plain synchronous calls. Only operations that wait for another node are `async`: redeem a link, pair a device, restore from a card, a demotion's pre-sync, "wait until synced". Those futures are runtime-agnostic (resolved by a channel from the handle's own background runtime, which is tokio by default or a `Handle` the app passes). A browser build later gets the same sync API over a worker-backed store; nothing in the shape assumes blocking is impossible.
- **Explicit where a wrong default is silent**: the owner of a new thing, the materialization bound, waiting for the pre-sync before a demotion. Placement is a group op (a thing placed nowhere synced gets `NotSynced`).
- **One `Error` enum** with stable categories; an absent aspect or unknown tid reads as `None`, never as an error.
- **No callback under a lock.** Callbacks run on one dispatcher per database, in commit order, after the commit is durable; any API call is allowed inside a callback. The dispatcher is driven by its own thread (default) or by the app's thread (`Dispatcher::Pump`, Watching).
- Nothing about CRDT internals, labels, blobs, epochs, keys or servers' innards reaches the API except in diagnostics and sync status. Vocabulary: thing, aspect, group, actor, member, role, device, server.
- Every tid that enters or leaves the API is resolved through moves (below).
- **Engine access is not app API**: the CLI's `inspect`, the sim and test harnesses reach the engine through the doc-hidden `osis::internals` (trait `Internals` on `Osis`, `ManualNet` for the doc-hidden `Runtime::Manual`, `node` = osis-node); nothing else of osis-node is exported except the plain data types the API hands out (`Diagnostic`, `DiagnosticKind`, `Cause` in `Source::Derived`, `ChangeId`, `EphemeralId`). A feature gate is ruled out (notes/build.md Feature unification).

## Handle and lifecycle
- `Osis: Clone + Send + Sync`; clones share one database, which closes with the last handle (drop is fine; `close()` returns once it is closed, or fails `StillOpen{handles}` while other user handles exist: clones, upgraded `WeakOsis`, value streams, text sessions, a `Joining`). One person per database; a second person is a second store directory.
- `Osis::create(Config) -> (Osis, Option<RecoveryCard>)`: new node, new person actor (recovery key owns it, this node is its admin), home group (the person itself, spec/sync.md §2) labeled on `Config.servers`. The recovery seed exists only in the returned card (none without servers: nothing to restore from); the app shows or stores it, osis keeps none of it.
- `Osis::open(Config) -> Osis` (existing store); `async Osis::restore(Config, &RecoveryCard)`; `Osis::pair(Config, &PairOffer) -> Joining` (new device, offer made on an existing one; see Devices).
- `Config { store: Memory | Dir(PathBuf), runtime: Runtime::None | Tokio(Handle) | Own, transport: Option<Transport> (QUIC by default; `InProcess` for tests), servers: Vec<ServerAddr>, materialize_limit: usize (default 64 MiB), idle_commit: Duration (text sessions, default 2 s), dispatch: Dispatcher::Thread | Pump(wake) }`. `servers` seeds `create`, `restore` and `pair`; an opened database keeps its stored list (`add_server`). Without a runtime everything local works; calls that wait for another node fail `Network`.
- Identity: `node() -> Tid` (this device), `me() -> Tid` (the person actor). Apps pass `me()` or a team/folder actor as the owner of what they create.
- `now() -> WallMs`: the corrected clock commits are stamped with (spec/sync.md §6), for app timestamps.

## Keys: typed aspects and signals
- `trait AspectKey { type T; fn ak(&self) -> &str; fn schema(&self) -> Option<&Schema>; fn decode(&self, &Value) -> Result<T, PathError>; fn encode(&self, &T) -> Value }` plus provided `ty`, `schema_ref`, `defaults` (retention, expiry, lifetime), `validate`. Defined in osis-schema, re-exported. `Key` (typed by a schema registered at run time, `Osis::key`) has no inherent `ak`/`schema` of its own: one name per concept, the trait's.
- Untyped: `Ak` is an `AspectKey` with `T = Value` and no schema (writes go out untyped: no schema index, core default retention). Typed: constants generated from a `.osis` file (`notes::BODY: Aspect<Markdown>`, `notes::TASKS: Aspect<Vec<Task>>`) carrying AK, (schema ID, revision), defaults and codec. A read through a typed key cannot be mistyped; a write through one is validated against the writer's schema (every declared field required, spec/versioning.md §5) and carries its schema index.
- Lifetime (notes/ephemeral.md): `AspectDefaults.lifetime: Lifetime::{Durable, Ephemeral, Presence, Signal}` from the schema flags `[ephemeral]`, `[presence]` (acts as ephemeral until presence is built), `[signal]`; untyped keys of those lifetimes are `Untyped`, made by `ak.ephemeral()`, `ak.presence()`, `ak.signal()` (trait `Lifetimes`).
- Core aspects as typed constants in `osis::core` (`GROUP`, `MEMBERS`, `CREATED`, `MOVED`, `WAS`, ...).
- Typed reads map `string`/`markdown`/`text` to `String`, `blob` to `Vec<u8>`, `tid` to `Tid`, `timestamp`/`duration` to osis time types; records to generated structs and enums with `TryFrom<&Value>`/`From<&T> for Value`.

## Reads
- `db.get(tid, key) -> Result<Option<T>>`; `db.at(tid, key) -> AspectRef<T>` with `.get()`, `.path(p).get::<U>()` / `.get_value()` (per-path typed or untyped read, so one bad element of a large collection is skippable), `.len()` (canonical size), `.stream() -> impl Read + Seek` (large string or blob), `.watch()`, `.on_change(f)`.
- `db.read(|r| ...)`: a consistent view across several reads (the engine's read lock, no store-level snapshot needed). `db.aspects(tid) -> Vec<Ak>`, `db.knows(tid) -> bool` (the thing is here: its creation held, or ephemeral here, and some aspect a `Write` sets present; `false` for an unknown tid and for a deleted thing, which `created` still reports, so `!knows && created.is_some()` reads deleted; an actor with only membership data, a link key or a contact before any data, reads `false`; writes, grants and moves need only the creation held), `db.groups_of(tid) -> GroupsOf { item_of, subgroup_of, within }` (the groups whose `/group` lists it as an item, those listing it as a subgroup, and `/groups`: every group holding it as an item directly or through subgroup lists, what sync follows for its own aspects, not the groups it is only a subgroup of; both sides of `/group`, from the in-memory group index rebuilt from the definitions at open, nothing scanned), `db.roster(actor) -> Roster` (the timeline's roster, spec/permissions.md §2), `db.role_on(tid) -> Option<Role>` (this node's effective role; UIs grey out what it cannot do), `db.owner_of(tid) -> Option<Tid>`. A thing's times, both `Option<Stamp { commit: Option<CommitId> (None for an ephemeral thing's creation), ts, node, actor, received }>`, shown and sorted by `shown() = min(ts, received)` (one skew rule: an author's clock may run ahead, by at most `MAX_DRIFT` before its commit is parked, and `received` is this node's clock; no app-written time field): `db.created(tid)`, the oldest valid commit carrying the thing's `/created` that is no compaction snapshot (snapshots carry `/created` too; `/created` is kept forever, so it arrives wherever the thing does, and until then, only a snapshot here, `None`); `db.changed(tid)`, its last content change: of the held changes, reverts and imports validly writing its aspects other than `/created`, `/group` and membership-class ones (placement and sharing are no content change, of the item or of the group), the one with the latest `shown()`, else its creation (so never before `created`; a delete counts; ephemeral writes do not, so an ephemeral thing reports its creation; a change known only from a snapshot is not seen, Attribution, so after compaction on a new device it may read older than the truth). From the in-memory commit index: newest `ts` first per aspect, stopping once `ts` is at or below the best `shown()`. Like every call they follow moves, so a moved thing reports its copy's (the move, then imports). `CreationRecord` is re-exported.
- Stored data never fails a read on typed grounds (Typed reads below): a value that does not decode through the key reads as `None` and reports a `Mismatch` diagnostic. `Error::Type { path, reason }` is for what the caller passes: a typed write's value, a path the key's schema does not have.
- **Materialization bound**: a value whose canonical size exceeds `materialize_limit` returns `Error::TooLarge { limit }` (the bound; a length is unknown without reading) from `get` and from any typed read; read it by `stream()` or by path (a path read into a huge map or list costs O(entry) and never loads the whole). Explicit failure beats an out-of-memory.
- Values are snapshots: plain `Value` or generated structs, nothing reactive hidden inside.
- `Path`: steps `Field(id) | Case(id) | Key(Value) | Index(usize) | Elem(Value)`; `p![..]` builds one from literals and generated field/case constants (`task::DONE`). Typed path builders from codegen are not built (optional).

## Watching
- `db.at(tid, key).watch() -> Watch<T>`: taken atomically with the current value, so no change is missed between read and subscribe. `current() -> Result<Option<T>>`, `async changed()`, `changed_timeout(d)`, `on_change(f) -> Subscription`.
- `db.at(tid, key).on_change(|c: Change<T>|) -> Subscription` = watch plus callback: the callback runs once with the current value (`Origin::Initial`) through the dispatcher like every later call, then on every change. `db.watch_thing(tid)` for all aspects of a thing (`Change<Value>` names the AK); a delete, local or remote, reaches it as its aspects going absent, and `knows(tid)` in the callback then reads `false` (no separate deletion event: a thing is deleted exactly when it holds no content). `db.watch_roster(actor)`, `db.watch_status()`.
- `Change<T> { ak, value: Result<Option<T>>, source: Source }` with `Source::Initial | Local(CommitInfo) | Remote(CommitInfo)` and `CommitInfo { id: ChangeId, actor, node, ts, received }` (`ChangeId::{Commit, Ephemeral(EphemeralId)}`; a mixed batch is its commit). A signal aspect's set reaches each `on_change`/`watch_thing` callback once (never coalesced); a `Watch` on it stays `None`. Display time for feeds is `min(ts, received)` (a sender's skewed clock).
- `Subscription` is RAII: dropping it unsubscribes; `detach()` keeps it for the database's life. No ids to remember.
- Who runs callbacks (`Config.dispatch`): `Dispatcher::Thread` (default), a thread the database starts; `Dispatcher::Pump(wake)`, the thread that calls `db.settle()`, so a UI applies changes on its own thread with no cross-thread hop. `wake: Arc<dyn Fn() + Send + Sync>` is called once when callbacks become due after the last `settle` began, from whatever thread queued them, after it released the database lock (so calling the database there cannot deadlock): it should only schedule a `settle` (a UI loop event). `settle` is the one call for both: with a thread it waits for it (tests), with a pump it runs everything due (including what callbacks it runs cause), on the calling thread (after another thread's pump in progress). Inside a callback it returns at once. One dispatch implementation (`Pump::step` in `watch`) with two drivers.
- Coalescing: a watch holds only the latest value; a callback that falls behind sees every commit's effect but not necessarily one call per commit. A slow callback delays later callbacks, never writes or sync. A watch on a value above the bound delivers `Err(TooLarge)` per change and the app re-reads by stream or path.

## Writes
```
let mut w = db.write();
let note = w.create(db.me())?;                               // ephemeral until a durable write
w.place(note, folder)?;
w.at(note, notes::TITLE).set(&title)?;                       // make equal: structural diff against current state
w.at(note, notes::TASKS).edit(&shown, &edited)?;             // apply only what the user changed since `shown`
w.at(note, notes::TASKS).path(p![2, task::DONE]).set(&true)?; // path op
w.at(note, notes::BODY).replace(&body)?;                     // reset, then the value
w.at(note, notes::VIEWS).inc(1)?;
w.at(msg, chat::BODY).expires_in(DAY).set(&text)?;           // retention and expiry per aspect write
w.at(note, key).remove()?;
w.place(note, other_group)?; w.unplace(note, folder)?; w.add_subgroup(g, sub)?; w.delete(note)?;
let done: Committed = w.commit()?;
```
- Whole-value ops: `set(&v)` makes the aspect read `v` (the spec's structural diff against the current state, spec/crdt.md §9: concurrent edits inside the value survive, but a field the app did not touch is written back if it differs from the current state); `edit(&base, &new)` writes only the difference between what the app showed and what the user produced, as path ops against the current state (struct fields, enum case, map keys, set elements, bag values exactly; sequence edits rebased onto the current sequence by matching `base` to it, notes/crdt.md Implementation), so a remote change to another field during editing is never overwritten; `replace(&v)` resets then writes; `remove()`. `edit` or path ops are the rule for anything a user edits while remote changes may arrive; `set` is for "the value must be exactly this" (imports, derived data).
- Path ops at `.path(p)`: `set`, `replace`, `remove`, `set_case(id, payload)`; list `insert(i, items)`, `delete(range)`, `move(range, to)`; text `splice(range, str)`; set `add(v)`, `remove_elem(v)`; map `put(k, v)`, `remove_key(k)`; bags `inc(n)`, `observe(v)`. Index paths resolve against local state at commit time. A path op into a map key with no live entry creates the entry (spec/crdt.md §5.6): the first reaction to a message is `path(p![msg]).add(&emoji)`, and two devices doing it concurrently both count; a path on through a struct field or enum case is refused (`Invalid`: it would write a partial record; `put` the whole value). An entry created by an expiring write goes at T with everything later written into it (spec/crdt.md §4.7). `/group` field ids are `core::group::{ITEMS, SUBGROUPS}`.
- `create(owner) -> Tid`: owner explicit and fixed forever; needs write on `owner` (checked locally; an owner the same batch creates counts through its own owner, so a tree of new things is one commit). The thing is ephemeral (record in memory, gone at restart) until its first durable write, which persists it with its ephemeral owner chain and makes its placements durable in that commit, same tid (notes/ephemeral.md). Placement is `place` in the same batch; placing an ephemeral thing is an ephemeral write of the group (it lists there and in `/groups`, locally), placing a durable thing into an ephemeral group persists the group; a placement into a group the persisting node may not write stays ephemeral (`PlacementNotPersisted`). A shared space with its own label (a chat, a team) is created, given data and `sync`ed, not placed in the home group: the owner's devices find it through the home label's `/label` cross-publish, while placing it in home copies every commit touching it (rotations with their boxes, messages) under the home label too (notes/chat.md Costs measured 8 KB per chat removal at 4 members, the K rotation's boxes at scale). The app's choice, not an API default. A group's items sync only through groups listing it as a subgroup (its members are its items and its subgroups' members, not its items' items), so a group meant to sync with home is both an item of home (its own aspects) and a subgroup (its items). The mistake is loud: a commit after which a placed durable thing reaches no synced group while the target group's own aspects sync (an item of a synced group, no subgroup of one) fails `Invalid` naming the fix, before anything applies (`Mutation::require_synced`, checked against the state the commit leaves, so the same batch may add the subgroup edge; also for the item placements a persisting write makes durable, a draft placed while ephemeral). Removing a subgroup edge that leaves existing items in that state is not checked. A durable thing placed only into groups that do not sync at all (device-local data, deliberate) is allowed and gets a `NotSynced` diagnostic after commit (spec/requirements.md, Offline and network). `place_expiring(tid, g, Option<Duration>)`: the placement expires too (a disappearing message leaves its group by itself); expiry is per aspect delta, so the group calls (`make_group`, `place*`, `unplace`, subgroups) on one `g` in a batch must agree on the expiry (else `Invalid`); `at(g, GROUP).expires*` is the app's own business.
- `delete(tid)`: removes every aspect the node knows (not `/created` or membership-class ones) and its placements and subgroup edges in every group this node may write (`groups_of`'s `item_of` and `subgroup_of`); a group it may not write keeps listing the tid, which reads deleted there. Afterwards `knows` is `false` here and wherever the delete arrives (unless a concurrent write left content). Tids never die and a later write recreates the thing; no wire concept. An ephemeral thing is freed at once with the ephemeral things it owns (its tid reads unknown).
- Rights are checked locally before signing: `Error::Permission { tid, needs: Role }` when the acting actor lacks write (admin for membership-class aspects) on a touched thing; `Error::UnknownThing` when its `/created` is not held. A write is never emitted to be un-merged elsewhere.
- `commit()` is one atomic commit over every touched thing, any owners and reader sets, of any size (deltas page, spec/crdt.md §8), plus the batch's ephemeral ops applied in memory after it (all or nothing). Returns `Committed { id: ChangeId, ts }`. Own watches fire after the commit is durable. Ephemeral ops take no `retention` or `purge` (`Invalid`); a signal aspect takes one root `set`.
- `Write` is `#[must_use]`; dropped uncommitted it discards its ops (debug log). `db.write_with(|w| ...) -> Result<R>` commits on `Ok` and returns the closure's value (a created tid); the `Committed` comes from `write()`/`commit()`. Reads inside a `Write` see committed state only; pending ops are invisible until commit.
- The node always acts through `me()`; acting as another actor (anonymous writing, notes/permissions.md) is a later `Write::acting_as`.
- Retention and expiry per aspect write: `.expires_at(T)` / `.expires_in(d)` / `.expires(Option<Duration>)` (`None`: the key's default) / `.retention(Retention)` on `AspectWrite`, defaults from the key; validated at the op (`Error::Invalid`).
- Membership-class aspects (`/members`, `/keys`, `/secrets`, `/label`, `/tenures`, `/moved`, `/was`) are written only through the sharing and sync calls below; a `Write` op on them fails with `Error::Invalid`. `/group` is ordinary (`place` and friends are path ops on it).

## Text editing sessions
- `db.edit_text(tid, key, path) -> TextSession`: a buffer the UI edits (`text()`, `insert(at, s)`, `delete(range)`, `replace(range, s)`, `cut(range)`, `paste(at)` with remembered ranges so a paste is a move plus undelete when the clipboard still matches, notes/crdt.md); remote edits are merged into the buffer and reported through `on_remote(|text, edits: &[Splice]|)` (`Splice { at, del, text }` in chars, each at the text before it, from a char diff of the buffer and the merged text; `Splice::map(pos)` moves a caret: an insert at the caret goes after it) so the UI can map cursors; commits on `commit()`, after `idle_commit` of inactivity, and on drop. A session whose thing was deleted (locally or remotely) since it was known here (at open or a commit of its own) never recreates it: `commit()` fails `UnknownThing` with the edits kept (they commit if the thing comes back, e.g. an undo of the delete), and drop (which then loses them), the idle commit and a remote merge report an `Uncommitted` diagnostic. This owns the "one commit per editing pause, never per keystroke" rule (spec/requirements.md, Generality); apps never commit per keystroke by accident because the session is the only path that makes keystroke-granular changes convenient.

## Signals
- `db.send_signal(tid, key, &value, Target::All | Target::Node(tid)) -> Result<()>`: needs write on the thing; never stored; local listeners fire; connected nodes receive best effort (notes/ephemeral.md).
- `db.on_signal(tid, key, |s: SignalEvent<T>|) -> Subscription`; `SignalEvent { tid, value, actor, node, ts }`. `db.on_signal_in(group, key, f)`: signals about the group or anything in its closure when the signal arrives (participants joining later included). Event-style signals should carry a sender sequence in their value (a node on several relays may see one twice).

## Commits: query, undo, redo, revert (owner: one model)
- **Query**: `db.commits(&CommitQuery) -> Result<Vec<CommitEntry>>` over the held commits, anyone's, and this session's own ephemeral changes (notes/ephemeral.md Step 2 as built), newest first by `(ts, ID)`. Filters (builder or fields, empty = all): `scope: Scope::{Thing, Aspects, Group}` (resolved when used, nothing stored; `Thing`/`Group` cover durable aspects, ephemeral things and the ephemeral side of `/group`; an ephemeral aspect of a durable thing only when named by `Aspects`), `actors`, `kinds: CommitKind::{Change, Revert, Membership, Snapshot, Import, Ephemeral}` (`Ephemeral`: an ephemeral-only batch, change or revert), `reverts(c)`, `reverted_by(c)`, `in_effect`, `since`/`until` (ts), `after(c)` (paging; all three take a `ChangeId` or `CommitId`), `limit`. `CommitEntry { commit: CommitInfo (the watch's type: id, actor, node, ts, received), kind, reverts: Option<ChangeId>, reverted_by: Vec<ChangeId>, in_effect, aspects (valid, in scope; a mixed batch's ephemeral ones too), dropped }`: signed-header facts only (Attribution); commits valid on no aspect in scope are left out. Relations are judged over every held commit touching the entries' aspects (a revert touches its target's aspects; undoing a creation resets every held aspect of the thing, the creation's among them). `next(Next::Undo | Next::Redo)` keeps only the change `undo`/`redo` of the scope would revert now (none or one; needs a scope, not with `after`; fails `NotUndoable` as the call would): what a UI labels or disables its buttons by. `undo`/`redo` run exactly that query, then revert.
- **Revert**: `db.revert(id: ChangeId) -> Result<Committed>` (a batch with both halves reverts as one; an own ephemeral change from the in-memory log, bounded by `Config.ephemeral_history`, 16 MiB, older ones `NotUndoable{Compacted}`; another node's or a pre-restart one `Invalid`): a content commit naming its target (wire `undoes`) with the inverse writes (spec/crdt.md §4.6: parts superseded since are skipped; a dropped body or nothing to write is `NotUndoable{Compacted|Superseded}`; membership, snapshots, imports are `Invalid`). In effect: no revert in effect reverts it. Revert depth: 0 for a change, +1 per revert (odd = an undo, even > 0 = a redo).
- **Undo/redo** (this actor, any device, under one lock): `undo(&scope)` reverts the newest own in-effect change or redo (even depth); `redo(&scope)` reverts the newest own in-effect undo (odd depth) unless a newer own change (depth 0) is in scope (a new change clears redo). `None` when nothing qualifies; `NotUndoable` when the chosen one cannot be reverted (nothing older instead). A revert of someone else's change counts as an undo of the reverter's: the reverter's redo reverts it, their undo skips it; the reverted change's author can no longer undo it (out of effect) and cannot redo it (not their undo).
- Undoing a creation deletes the thing (owner; spec/crdt.md §4.6): the batch that created it (a commit carrying its `/created` when created and persisted in one batch, else the ephemeral batch); its revert also does `delete`'s writes (every aspect, both sides, and its placements and subgroup edges in every group the node may write; `Permission` when the node may not write the thing, never a partial revert), so redo (or `revert` of that revert) brings the thing back with content and placements. A deleted ephemeral thing keeps its record (redo needs it) and reads unknown. Saving a draft (the commit persisting an earlier ephemeral thing) is no creation: undoing it reverts its writes and returns the draft (ephemeral content, ephemeral placements, known), a further undo deletes the draft, redo saves it again (notes/ephemeral.md). In a thing's scope, creating an ephemeral thing is the oldest change.
- Exact undo (spec/crdt.md §4.6 "Absent before"): undoing the first write into a spot that did not exist resets the spot when no one else's live value is in it (seen writes block it; concurrent ones arriving later are wiped); a register in a present struct stays (no nested register reset). A node without the whole pre-commit state (older bodies dropped, a later snapshot) skips it.

## Large values
- Typed and untyped reads materialize up to `materialize_limit`; above it `stream()` (`Read + Seek`, lazily fetching chunks, memory bounded to a chunk plus the tree path), `len()`, and path reads. Writes: `set_stream(impl Read)` on a `blob`/`string` position builds the chunk tree without materializing (plans/large-values.md); `set`/`edit` accept in-memory values of any size the caller has. Equality is by content; links never appear in values the API returns (`Value::Link` is replaced by the materialized value or the read fails `TooLarge`).

## Queries (minimal in the MVP; a design pass later)
Per-aspect reads are not enough for any list-like UI. Expect most of a slow, not very feature-rich database to grow over the local store, over time; nothing of it touches the wire. MVP shape, enough for the example apps:
- `db.query(Query::in_group(g).with(key).order(Order::Time | Order::Field(path)).page(n)) -> Live<Vec<Hit<T>>>`, things in the group (transitive) carrying the aspect, paged, with `Hit { tid, value: Result<Option<T>>, ts, received }` and a watch on the result for changes in the visible range (a chat timeline, a feed, an inbox).
- `db.backlinks(tid) -> Live<Vec<(Tid, Ak)>>`: things whose values reference the tid, resolved through moves.
- Later: filters over values (unread, by actor, by tag) and counts, live; text search. Indexes are local, rebuildable, sharded per aspect (notes/local-store.md).

## Sharing and membership
Synchronous unless noted; each is one membership commit made locally (spec/permissions.md §2), delivered by the sync layer.
- `db.grant(target, member, role, EdgeOpts { until, invite })`: needs the member's `/keys` held (contact card, a shared group, pairing), else `Error::UnknownActor`. The first non-owner member of a plain thing gives it secrets of its own (about 2.6 KB of boxes per member: share sets through one actor, notes/permissions.md Patterns).
- `db.member_path(target, actor) -> Vec<(Tid, Tid)>`: the (thing, member) edges of a shortest chain through which `actor` reaches `target` (`[(target, K), (K, joiner)]` for a link joiner); empty when it is none.
- `db.change_edge(target, member, Edge)` for `until`/`invite` or a higher role. `async db.demote(target, member, Role | Remove, Demotion { sync: WaitForSync::Required | Try(timeout) | Skip, backdate: Option<Timestamp> })` for anything lowering a role: the pre-sync (below) runs first; `Required` fails with `Error::Unsynced { groups }` when a group cannot be synced (stranded, no servers, or not synced within `PRESYNC_WAIT`), `Try` proceeds after the timeout with a diagnostic, `Skip` stamps now (stolen device). A removal follows `member_path` until the member reaches `target` no more (a member both granted and joined by a link loses both); removing a non-member writes nothing. A joiner by a link made on this device is removed with the link key in one commit (`revoke_joiner`, one rotation): the link stops working for everyone who has not redeemed it yet, K's other joiners stay (the joiner may keep the seed, spec/permissions.md §9). A joiner's role cannot be lowered (it could act as the link key), and a member reaching `target` through another actor (a team, a link made on another device, which keeps the link record) is `Invalid` with the actor named: demote or revoke there. `db.leave(target)` is a self-removal.
- Devices: pairing is transport-agnostic, the app carries three texts: `db.pair_offer() -> PairOffer` (short-lived, one-time secret); on the new device `Osis::pair(Config, &offer) -> Joining` with `joining.request()`; back on the first `db.pair_accept(&request) -> (node, PairReply)`; then `joining.finish(&reply) -> Osis`. Request and reply are authenticated by the offer's secret. A direct-connection convenience over this is later. `db.devices() -> Vec<Device>`; `async db.remove_device(node, Demotion)`.
- Links: `db.make_link(target, role, LinkOpts { until, single_use, direct }) -> ShareLink` (text; `direct`, opt-in and required without servers: the link carries this device's dialable key and relays, never `/reach`, so a redeemer with no common server reaches it; the key rotates when the link ends; notes/networking.md First contact); `async db.redeem(link) -> Tid` (resolves once the target is here); `db.links(target) -> Vec<LinkInfo>`; `async db.revoke_link(id, Demotion)` (its joiners stay members of K; a bearer may have kept the seed, spec/permissions.md §9); `async db.revoke_joiner(id, joiner, Demotion)` removes one joiner and ends the link in one commit with one rotation of K (a multi-use link's joiner may keep the seed; the chat's removal). Single use is in the link (`flags`, spec/wire.md §10): the redemption removes the link key and node-sync on any sharer device finalizes it, and an expired link, after a complete pass of K's labels (`SyncEngine::finalize_links`; the seed thing is placed in the home group so every device holds it); a second redeemer is refused (`Network` after `wait_timeout`). Waiting calls (`redeem`, `import_contact`, `restore`) fail `Network` after `Config::wait_timeout` (60 s), remove their waiter when dropped and forget the held key on every outcome. Bearer read (`async Osis::open_link(Config, link)`) slipped (issues/api-deferred.md).
- Invite requests (spec/sync.md §3): `db.invite_requests() -> Vec<InviteId>` (an invite from a sender with no known connection: nothing it names is fetched or dialed yet; nothing about sender or thing is shown, both would be the sender's unverified word), `db.accept_invite(id)` (applies the grant, joins as any invite), `db.decline_invite(id)` (forgotten for good, re-sends included); both `Invalid` when no such request waits. Not watchable yet: an app polls (e.g. on status changes).
- Contact cards: `db.contact_card() -> ContactCard` (a read link to a profile thing whose label carries the person's `/created` and `/keys`, spec/sync.md §3; made once); `async db.import_contact(&card) -> Tid` (the person actor, then usable in `grant`).
- Entitlement: members read what the group (or an actor in it) owns; a thing owned by `me()` and placed in a shared group stays unshared (notes/sync.md). Shared things take the group as owner.
- Moving: `db.move_thing(tid, new_owner, groups: &[Tid]) -> Tid` (persists an ephemeral thing or owner first) (copy with imported history, `/was`; `/moved` on the old thing when this node may write it). `db.same_thing(a, b)` is the only explicit resolution call.

## Sync configuration and status
- `ServerAddr` = transport URL plus the server's key (`FromStr`/`Display`); `db.servers() -> Vec<ServerAddr>`, `add_server`, `remove_server`. The person's `/keys` inbox and the labels whose server list equals the database's list (as a set) follow the change (`/label` writes first, then the saved list, then the `/keys` write; the sync engine registers a label's path at a new server), so a database created without servers gets a reachable home label. Only the home label and groups the person owns (directly or through its actors) that this node administers: not groups owned by others, not link actors or the contact card's profile (their text names their servers), and a group with members besides the person's devices never loses its last server. A link or card made on another device is recognized only by its key-actor member (a card's profile is not: a gap).
- `db.sync(group, &[ServerAddr])` makes a group synced (its own label, the group given secrets of its own first; admin of the group; empty list: the database's servers); `db.unsync(group)`; `db.sync_policy(group, GroupPolicy { publish_reach: Option<bool> })` (stored; `None`: `/reach` only where every reader is this person, its own or a contact, notes/networking.md; `import_contact` marks contacts; a group excluded while its labels hold the current `/reach`, and a direct link ending, rotate it; `db.rotate_reach()` rotates by hand; per-group heartbeats not built: issues/api-deferred.md). The person's home group is synced at `create`.
- `db.status() -> Status { connected, groups: map<Tid, GroupSync { state: Synced | Syncing | Unreachable | Stranded | NoServers, last_sync }> }`, `watch_status()`. `Stranded` means this device waits for a re-seal (spec/permissions.md §3).
- `async db.wait_synced(scope: Group(tid) | All, timeout)`: resolves once every local commit in scope is at a server and a pass changed nothing; `db.sync_now()` nudges. CLI and tests use these; apps mostly watch status.
- Bundles: `db.export_bundle(&[groups], impl Write)`, `db.import_bundle(impl Read)`. P2P and LAN need no configuration: `Config.peers` (default on) listens with the dialable key and publishes `/reach` (with `Config.relays`); features `iroh` (co-readers over iroh beside QUIC servers) and `lan` (the LAN loop). Without `iroh`, `Transport::Quic` dials no co-reader.

## Diagnostics (decided; shape is proposal)
A place to dump problems such as a colliding record from a peer, a move with several claimants, rejected writes from a revoked actor, a thing created into an unsynced group, a demotion that proceeded without its pre-sync. Apps may log, surface or ignore it; correctness never depends on anyone seeing it.
- `db.on_diagnostic(|d: Diagnostic|) -> Subscription`; structured (kind, tids, peer, time). Default sink is the log.
- A peer must not be able to flood it: dedupe per (kind, tid), rate-limit per peer.
- Must include: "this device was removed from actor X by node N at time T" (a stolen device's backdated removal otherwise looks like a silent lockout; the recovery card is the remedy) and "stranded on group G" (also in status).

## Errors
`Error::{UnknownThing{tid}, UnknownActor{tid}, Permission{tid, needs}, Type{path, reason} (a typed write's value, or a path outside the key's schema), TooLarge{limit}, NotUndoable{commit: ChangeId, reason}, Unsynced{groups}, Invalid(reason) (a malformed link, card or value; a write growing an ephemeral aspect whose own state no longer fits a blob, notes/ephemeral.md Past inline lists or a blob), Storage(..), Network(..), Closed, StillOpen{handles} (`close` while other handles keep the database open)}`. Peer-caused problems never surface as errors to the app; they are diagnostics.

## Typed reads (decided; spec/versioning.md §5)
A typed read (`get`, `at().get()`, watches, `on_change`, path reads) of a stored value with an unknown enum case (a newer revision's), a type mismatch or a missing required field reads as `None` and reports `DiagnosticKind::Mismatch` (tids: the thing; detail: AK, path, reason; deduped per (kind, tid) like every diagnostic). Owner direction (api-asks-2): synced data is other writers' input and an app cannot act on an error, so one odd thing must not fail a screen read with `?`; one read call, no lenient variant. Per-path reads let an app read the good elements of a collection with one bad element. The untyped `Value` API always shows what is stored. App types are views over the wire type, generated or hand-written; transitions and the form-choice policy are codegen conventions (notes/versioning.md). Codegen warns on `list<struct>` aspects (records edited concurrently belong in `map<K, struct>` or get path ops: the list diff pairs changed entries in order and a misaligned pair loses concurrent edits).

## Tids and moves (spec/permissions.md §7)
A thing never changes tid or owner; moving it makes a copy with a new tid (`/was` on the copy, `/moved` on the old thing if its owner cooperates).
- Every call that takes a tid resolves moves internally by the §7 rule; watches registered under an old tid keep firing. Roster reads resolve `/members` keys too.
- Values returned have known old tids replaced by the resolved one (typed tids and `osis://` links in markdown), so tids read from osis compare equal. Resolution is a read-time view: stored bytes are untouched, and `set`/`edit` diff against the resolved view, so writing a value back never rewrites references. An app pins a reference by writing it explicitly.
- `same_thing(a, b)` only for identity of a tid the app kept (memory, config, URL) against one read later; `Tid` equality is plain bits.
- Attribution of imported writes: see Attribution.

## Attribution (owner decision)
The API reports only verifiable authorship: who wrote something and when comes from the signed header of a commit held here, never from a claim another commit makes (an ephemeral commit's `Authors`, an import's origins table: internal; a compaction snapshot vouches for its carried writes without naming their authors). No API type carries an "unverified" flag; what cannot be verified is not reported.
- The commit query lists the commits held here, each with its own header's author and `ts` (a snapshot or import as itself); changes known only from a compaction snapshot have no entry. A watch's `Source` names the commit applied: a snapshot or import arriving is reported as itself (its author, ID and `ts`). A valid snapshot's copy governs a held original it misstates (spec/permissions.md §5.2): the read changes with the snapshot as `Source`, while the commit query and `changed` still name the original's commit as the change it was (snapshots are no change); the node reports the snapshot (`DiagnosticKind::Misstated`).
- Imported writes after a move: the origin commit's author and `ts` only where that commit is held here, else the import's (importer, `ts`). (No per-write attribution call exists yet; any future one follows this rule: a value known only from a snapshot reports the snapshot or nothing.)
- Provable authorship of every change (audit trails): give the aspect keep at least forever (`Retention.at_least`, `abs` forever); its bodies are then never compacted away, so each change keeps its signed original.

## Demotion and the pre-sync (decided)
A demotion's frontier is the demoting node's own receipts (notes/permissions.md, Revocation), so osis syncs every group below before stamping it (spec/permissions.md §5.3); in the common case there is no tradeoff. The sync fails when a group is unreachable, the node is stranded on it, the tree is too big for the device, or the app will not wait (a hostile member or lost device: reverting their unseen work is then wanted). The app chooses by `Demotion.sync`; a UI may route the choice to a user, osis never requires a human. Partial sync is partial protection (the frontier is per aspect). Organizations demote from a node that tracks the tree (an admin node holding the company actor's secrets). Rejected: a "cut access only" removal (`until` = now by an admin) leaves a permanent backdating window until a real demotion follows; third-party receipts fail the fixpoint model.

## Footguns closed (keep them closed)
- Read-modify-write clobber (a form saved with `set` wipes a tag another device added meanwhile): `edit(base, new)` and path ops; docs steer every interactive edit there.
- Out of memory on an unexpectedly large value: the materialization bound fails explicitly; streaming and path reads exist.
- A thing that never syncs: owner explicit at creation, placement a group op, a placement into a group whose own aspects sync but whose items would not fails, `NotSynced` diagnostic for device-local placements.
- A deleted thing reading as present (an editor left open on it): `knows` is false once no content is left; deletion is derived, never a flag.
- A thing owned by the device (never shareable): owner is always passed; `me()` is the common answer.
- A forgotten unsubscribe: RAII `Subscription`.
- Missed change between read and subscribe, and a callback invoked on the registering thread once and the dispatcher thread later: atomic `watch`, initial call through the dispatcher.
- Writes a node is not allowed to make, emitted and un-merged elsewhere later: rights checked locally at commit.
- `async` reads forcing a runtime into GUI apps and hiding that nothing waits: synchronous data API.
- Per-keystroke commits (13 bytes forever each): the text session.
- Demotion stamped without syncing what the member wrote: `WaitForSync::Required` is the default; skipping is spelled out.
- Tid comparison across moves: resolution inside every call and in returned values; one explicit `same_thing`.
- Concurrently edited records in a `list<struct>`: codegen warning, path ops.
- Deadlock or reentrancy inside callbacks: no callback under a lock, any API usable from a callback.
- Secrets in the API: none; the recovery seed only in the card at creation, the link seed only in the link.

## Rejected shapes
- Everything `async` (the earlier sketch): local operations never wait, and every GUI would carry a runtime; browsers are served later by a worker-backed synchronous store.
- `ListenerId` cancellation and a callback invoked before `listen` returns.
- An entity/ORM layer typing whole things: aspects belong to different schemas and apps; per-aspect typed keys fit the model.
- Auto-subscribing reactive reads (reads inside a computation register listeners): hidden magic; `Watch` covers it explicitly.
- `set` diffing against the app's last read implicitly (state hidden in the handle): `edit` takes the base explicitly.
- Exposing links or a `Value::Large` variant in untyped values: the bound plus `stream()` keeps values plain.
- A default owner (`me()`) or default placement.

## Open
- The query design pass (which filters and indexes, live counts, text search).
- Typed path builders from codegen; a serde layer `Value <-> app types` as a convenience.
- Bearer read and anonymous-writing conveniences may slip from the MVP (notes/overview.md, MVP scope).
- Browser build: the sync API over a worker-backed store (SharedArrayBuffer + Atomics.wait), not in the MVP.

## Implementation
Module map (`core/osis/src`): `handle` (`Osis`, `Config`, `StoreAt`, `MemStore`, the lock and `after`, schema registration), `internals` (doc-hidden: the `Internals` trait on `Osis` with `engine`, `sync_engine`, `waiting`, `take_actions`, `feed`, plus `ManualNet` and the `node` re-export, for the CLI's `inspect`, the sim and tests), `net` (`Runtime`, `Transport`, `Net`, the driver host, `Waiter`/`Pending`), `person` (`restore`, pairing), `share` (grants, demotions and the pre-sync, links, cards, devices, servers, group sync, status, bundles, `move_thing`), `read`, `write`, `large` (`ValueStream`, `len`, `set_stream`), `text` (`TextSession`), `watch`, `commits`, `signal`, `keys`, `error`.
- **Handle and sync**: one mutex over `Locked { sync: SyncEngine (owns the engine), events, seq, waiters, status, offers, links }`. Every call under it ends in `after`: engine events go to the dispatcher in commit order; if the call (not the driver) caused events, `SyncEngine::handle(Event::Local)` runs; then direct-link upkeep (rotate the dialable key when one ended), the status (a `Msg::Status` to watchers when it changed, a `Stranded` diagnostic on a new stranding) and the waiters. Network actions leave through `Net` under the lock (FIFO, so frames keep their order): `Off` drops them, `Manual(ManualNet)` queues them for a test harness (`Internals::take_actions`/`feed`), `Driver` sends `Control::Apply` to osis-node's `sync::driver::run_host` running on the app's or osis's own tokio runtime with the handle as its `Host` (a weak reference; the driver stops when the database closes). `close()` fails `Invalid` from a callback and `StillOpen` while other user handles exist (`Life` counts them; osis's own short-lived holders, the dispatcher running a callback, a driver engine call, timers, use uncounted handles: `Osis::internal`, `WeakOsis::hold`), else waits uncapped until the store is closed (each such holder ends on its own); dropping `Net` sends the driver `Shutdown`. Engine calls run in `block_in_place`, which a runtime shutdown does not wait for: the task polled on after one would hit a timer of the shut-down runtime and tokio panics. So the driver task holds a drop guard: osis's own runtime (`Runtime::Own`) is shut down by an `osis-sync-stop` thread once the guard dropped (at most 5 s, then `shutdown_timeout` 5 s; the drop itself may run inside that call, hence the thread; the store is already closed: `Inner` drops `eng` first); on the app's multi-thread runtime `close` waits (uncapped, in place when inside it; on a current-thread one not at all: no engine call runs in `block_in_place` there) for the guard, so the app may shut its runtime down next; and the driver polls no timer while a control message waits, so a `Shutdown` queued by a drop before the runtime's shutdown is seen first (an app dropping the runtime while the database is open can still hit the panic). Wake timers hold a weak sender and are armed only for a waiter that did not resolve at once.
- **Futures**: `wait_until(timeout, check)` registers a check on the sync engine and status, run after every change (and on any call, so deadlines pass offline too); a deadline is looked at after a driver wake (`Net::timer`). `redeem`, `import_contact` and `restore` wait at most `Config::wait_timeout` (60 s) per wait; a waiter whose future was dropped is removed; held link and recovery keys go with a guard on every outcome; `restore` writes the `person` record only on success. `Pending` resolves through a slot with the stored waker: runtime-agnostic (tests poll with a no-op waker or a park/unpark waker). Without a runtime they fail `Network` at once.
- **Person**: `create` runs flows' `create_person` (the sync engine is built first so it sees every event), writes an empty `/group` on the person (home = person), records `person` and `servers` app records. `open` refuses a person without `/keys` (a pre-flows store, `Invalid`). `restore` holds the card's key, `follow`s the home label, waits until the person is known and its group `Synced`, then `recover`. Pairing messages are CBOR `[1, ...]` in base64url with `osis://pair/`, `osis://pair-request/`, `osis://pair-reply/` prefixes; MACs are `kdf(purpose, secret, body)`; the request carries the new node's commits, the reply the grant id and the packages `take_direct_for(node)` returns (the grant or re-seal, the person's certificates and `/label` commits: about 20 KB, whatever the person holds); offers live in memory (`OFFER_LIFETIME_MS`).
- **Sharing**: each call is a flow plus `carry_out`. `grant` maps a missing `/keys` to `UnknownActor` and `Permission` to `needs: Admin`. The pre-sync syncs every synced group whose closure holds a thing `presync_scope` names (`sync_now`, then all `Synced`). `sync(group)` gives the group secrets of its own before its label: a label whose genesis is at the owner's derived epochs cannot be verified by a member reaching it through a link actor (issues/node-sync-gaps.md). Links: K → (L, target, single_use, direct, ended) in memory and the `links` app record; single use is the link's `flags` bit (FC-3): the redeemer removes L in its redemption; finalization is node-sync's. A self-removal (`leave`) is sealed and uploaded before the leaver drops what it lost (`Done::drop_lost`). `contact_card` makes profile P (owned by me, a group of itself, labeled), places the person's `/created`/`/keys` commits under P's label as certificates, makes a read link to P and keeps its text (`contact` record). `import_contact` holds L, follows K's label, waits for P's owner's `/keys`, drops L.
- **Signals** go through `SyncEngine::signal_as` (the person as actor, write role checked); local listeners hear them through `Event::Signal` like remote ones; a signal targeted at another node is not delivered locally.
- **Status**: from `SyncEngine::label_status` per label: no servers; stranded (a failed open); `Synced` when every connection holding it open finished a pass with nothing outstanding; `Syncing` when connected or open; else `Unreachable`. A group shows its worst label. `wait_synced(Group(t))` scopes the synced groups whose closure holds t. `wait_synced` also waits until no inbox deposit is unanswered (`SyncEngine::deliveries_pending`; the outbox is stored, so a restart sends it again); a demotion's pre-sync does not. `pending_uploads` of the shape is not built.
- **Diagnostics** added: `NotSynced` (after a commit placing a thing whose groups include no labeled group), `Unsynced` (a `Try` demotion that proceeded), `Stranded`; `Engine::report` dedups them.
- **Large values**: `stream` walks the chunk tree one chunk per call (`Engine::next_chunk` under the lock); `len` reads the CBOR head of the first chunk; a seek fetches nothing, the next read fetches the root and the nodes on the path to the target chunk (`TreeReader::seek`, lengths in tree nodes). `set_stream` reads the value whole, then sets it (issues/api-deferred.md).
- **Text sessions**: buffer plus base; `commit` writes `Op::Edit { base, new }` on a `text` position (rebased by the crdt; a paged text resolves it on the pages around the change when the text there still matches `base`, notes/node.md Paged state) or `Set` on a string register; a remote change commits the local edits first, then reloads and calls `on_remote` with `osis_crdt::changes` (the gaps of the Myers LCS over chars) as splices; the first edit after a commit arms a timer on the database's runtime (`Net::after`: a tokio sleep, then a blocking task) that commits once the session has been idle `idle_commit` (re-armed for the rest otherwise); without a runtime the next edit after `idle_commit` commits; drop commits (a failure reported as `Uncommitted`); `known` (the thing read known at open or after a commit) makes the flush's write check `knows` under the commit's lock (`Write::alive`, so a delete ingested between the check and the write is seen): false fails `UnknownThing` and the buffer keeps the edits. A commit that fails (lost write access, storage) reports an `Uncommitted` diagnostic and keeps the edits in the buffer for the next try; a remote merge after a failed commit drops them.
- **Writes, reads, watching, undo** as in the first half: writes act as `me()` (`act_as`); `commit` returns `Option<Committed>`; reads materialize with a budget; the dispatcher coalesces per aspect and follows moves; undo, redo and the query read `Engine::held_commits`; a register edited twice undoes twice (spec/crdt.md §4.6).
- **Sharing helpers**: `member_path` is a breadth-first walk over rosters. `demote` loops over `member_path`: a direct edge goes through `demote_edge`, a path through a link actor in the `links` record (ended ones included) through `revoke_joiner` (one commit, so no half-removal on a failed pre-sync or dropped future), anything else is refused. `add_server`/`remove_server`: `follow_labels` (one commit of `/label` server-list sets) before the list is saved, then `follow_inbox`.
- **Signals in a group**: `Filter::SignalIn(g, kind)`; the dispatcher reads `groups_of(signal tid)` when a signal arrives.
- **Not built** (issues/api-deferred.md): queries and backlinks, `undelete` and cut/paste in text sessions, `sync_policy` heartbeats, bearer `open_link`, streaming writes, `pending_uploads`, a direct-connection pairing convenience.
- **Standard data**: the scenario tests (core/osis/tests/it: notes, tags, contact, event) use this API end to end (notes/std.md).
- **Tests**: core/osis/tests: `api`, `watch`, `commits` (query, undo/redo/revert, exact undo, two devices, another actor's revert), `sync` (tier 1: `World` in tests/it/common/world.rs drives `Runtime::Manual` databases and osis-server `Hub`s under one `ManualClock`; futures polled with a no-op waker), `sharing` (more sharing and status through `World`), `runtime` (tokio driver over `InProcess` against the server driver: a restore and a link redemption; QUIC tier 2, ignored). Doc examples per concept in lib.rs.
