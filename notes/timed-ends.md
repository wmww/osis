# Timed ends and finalizes
> Summary: Why a grant past its `until` is no key departure until a writer finalizes it (Tess: any writer finalizes), how a finalize is judged (a frontier-less removal naming the write it ends, spec/permissions.md §2), the holes checked, and the accepted fallback. Model: core/test/tla/rotation/Finalize.tla.

Principle: **keys read no clock**: a timed end becomes a departure only through a signed finalize, which every node judges alike.

- **A timed end is finalized** (Tess: any writer finalizes): a grant past its `until` is no key departure (`Core::key_holders`, `rotation::key_role`: every applied write in effect, `until` disregarded; the `until` 0 keep value is no grant). A node with write about to encrypt under T (`ensure_rotated` → `finalize_due`) first writes a finalize of each ended grant on T of role at most its own: a removal with no frontier carrying the rotation (`flows::edges::finalize_in`). A renewal or removal of the grant itself is not finalized first (`ensure_rotated_but`).
- The timeline applies a frontier-less removal of another's grant only as a finalize (perm `judge`, `Attr::Finalize`: grant past `until` at its `ts`, author with write and at least the grant's role; no class, never audited), so a renewal ordered first wins and an admin's racing finalize cannot turn into an empty-frontier revoke; test harnesses give explicit removals an empty frontier for that reason. At the guest a finalize counts as its `until` (`Timeline::role_unfinalized`, `lost_by_time`): it hears out.
- **A finalize names the write it ends** (spec/crypto.md §4 Met): a role commit resetting an entry whose creation the node does not hold applies none of its edge writes until it does (`ix.unresolved`), and a name is met only for a commit so resolved (`NamesHeld::resolved`); otherwise a node holding a finalize without the `until` write it ends counted the departure as met (`finalize_without_its_until_unmet_spec_crypto_4`). A commit resetting an entry the node never gets never applies there. Rejected: met once each lowering edge write it makes applies (an erasing finalize derives no write, so nothing is asked, and leaks; beside a renewal every rotation names the finalize and none is established); known writes of such a commit applying alone (a name then covers a holder its other write had not yet removed); rotating instead of re-sealing a holder a name removes (leaks through the new history box).
- **Every edge write resets the holder's current entry**, the one the write in force in the writer's walk created (`flows::edges::reset_current`, `Timeline::in_force`), not what the `roles.0` state shows live: a void finalize resets the state's entry while the grant stands on the timeline, and a later removal must still name it (`an_explicit_removal_after_a_void_finalize_removes_spec_permissions_2`). One reset per write, so a holder's k-th write carries one (`validity::holder_churn_resets_are_flat_spec_perm_2`); resetting every entry ever seen gave k. Only a removal's resets are read (the waiting rule; a reset beside a put decides nothing).
- Holes checked: a writer removing an unexpired edge (invalid: no admin, edge alive at its `ts`); a dishonest writer finalizing early (at most `MAX_DRIFT`, as a fast clock does; a writer can already rotate leaving anyone out); a renewal raced by a finalize (the timeline order decides; a guest left out by a void finalize is re-sealed); concurrent finalizes fork, as concurrent rotations do. Self-removal stays a normal departure: it is a stamped commit, not clock-based.
- Fallback Tess accepts if this hits trouble: only admins finalize (the guest then reads new content until an admin node is online after `until`).
- Tests: core/engine/tests/it/finalize.rs; `forks_with_ended_edge_finalize_after_reseal_spec_permissions_2`, `finalize_without_secret_rotates_history_added_spec_permissions_2`.
