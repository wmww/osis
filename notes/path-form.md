# Path form
> Summary: How a commit states the path each thing it writes is judged along (built; spec/wire.md §4 field 2, spec/crypto.md §5 Path entry): one path in the clear where every thing's own path is read off it and it tells no reader a roster fact it could not read; else the split form, one purge author in the clear and each thing's path sealed under its independent's read roles secret, each entry committing to its key, the key in every encryption of the thing's parts (padded entries). Who reads a path, per consumer; the engine's choice; the clear-form rule and its argument; padding and what stays visible; `act_as` (Open 16); bytes; what is left; what needs Tess.

**Principle: a thing's path is header data, readable exactly by the nodes that judge that thing's parts.** A write is never refused or split for its paths (the owner's rule): one commit may write things its signer reaches through different holders.

## Who reads a path
A thing T's path is read by every node that judges T's parts: T's holders, who hold the read roles secrets of T's independent (spec/crypto.md §3, §4: derived, boxed, or below a floor from history entries). A node holding the header but no secret of T's independent at the entry's epoch and no encryption of T's parts never needs T's path: T's content applies nothing there (spec/commits.md §4 Outside the node closure).

| class | judges T's parts | opens T's entry |
|---|---|---|
| reader, writer, admin of T or of a holder of T; reader of a sync ID whose unit holds T | yes | yes |
| holder of a floor on T's independent, epochs below it | role parts, lasting requests | yes: history entries carry the independent's earlier roles secrets (why the key is the independent's, not a dependent thing's derived one) |
| holder lacking the entry's epoch | once it holds a part | by the key in any encryption of T's parts (a re-encryption under a later epoch, a copy); with none, T's parts are judged invalid until a key or the epoch comes (`apply::paths::refresh`) |
| reader of another thing of the commit, a store, a keyless holder | no | no |
| node needing a destroyed T | the destroying request | by the key in the request's header-only copy |

## One path
- A `Path` `[i, A1, …, Ak]` writes its end Ak along A1..Ak−1, and every other thing one hop past Ak (the things the end holds a direct grant on, or descending from it by record edges). `osis_commit::Path::to` reads a thing's holders off it; `Path::one_of` finds the one path serving every thing's own path, if any.
- **What it tells other readers** (For Tess 3): every thing's chain up to the end is a prefix of each reader's own path. On the empty path every thing hangs off the signer, which "written by the signer" shows already (a reading of the requirement: strictly, that the signer's role is its own edge and not through a holder is a roster fact; reading it so would split every multi-thing write of own things). On a longer path, a thing T one hop past the end shows its last edge (the end holds a role on T) to the readers of every other thing W written. The clear form is used only where each such W's readers read that edge already:
  - T derives its read secret from W (W on T's record chain up to T's independent): W's readers read T whole, roster and record; or
  - T's last hop is by record edges (T made under the end) and W's record chain holds T (W made under T): W's readers hold W's record chain, T's record on it.
  - Otherwise, a grant by the end on T, or T independent of W, the commit goes split though one path would serve. A creation of a dependent thing under a granted parent D (`[D]`) and under the account root (`[0]`) stay clear; a creation of an independent thing under a granted D writing D's `holds.0` goes split (D's readers do not read T's record).
  - `engine::write::clear_tells_nothing`. "Independent" there is the node's (`independent_in`: held independent, or a key actor, spec/crypto.md §3): a thing a content commit makes is dependent in it, since only a role commit writing `keys.0` makes a thing independent, and a role commit states no split path.

## The split form
`Split := [Opt(tid), [bytes+]]`: the purge author (absent: the signer), then one entry per thing written in aspect order. Entry of T: `kdf("path commit", key, "")` (32 B, `osis_commit::key_commitment`), then XChaCha20-Poly1305, nonce zero, empty AD, under T's path key `kdf("path", read roles secret of T's independent at the epoch T's sections go under, blind ‖ tid)`, of the canonical `[tid*]` T is written along (T last where it is the purge author), zero-padded. The decoder refuses two entries with one commitment (one key per entry: the zero nonce is safe only so).
- **One key per entry** (the key commitment): a thing's path key reaches readers by several routes (derived from a roles secret of the independent; carried in each encryption of its parts, a copy's too; in a destroying request's header-only copy), and XChaCha20-Poly1305 commits to no key: a writer choosing two keys builds one ciphertext opening under both (Poly1305 is linear: one equation over its field for one block, about a thousand tries; `validity::entry_under_two_keys`), so without the commitment two readers holding different encryptions read different paths, and a reader keeping one key per (commit, thing) read the one that came last. A reader takes a key for an entry only if the entry commits to it (`Split::open`: `None`, no key of the entry, before decrypting), on every route; so each entry has one key (two need a BLAKE3 collision: 256-bit output for 128-bit collision resistance, since the writer picks both keys), every reader opening it reads one plaintext, and `merge_parts` joins keys that are equal (debug-asserted). A key the entry commits to that opens nothing makes the entry bad, alike everywhere. Tests: `osis_commit` `an_entry_accepts_only_the_key_it_commits_to` (header, own section, copy, header-only copy, stored form); engine `validity::an_entry_opening_under_two_keys_judges_alike_in_any_order_spec_wire_4` (a real two-key entry; without the commitment the later encryption's key replaced D's and voided D's write in one order), `a_roles_secret_opens_an_entry_only_as_its_committed_key_spec_wire_4` (the roles route; an entry no held key commits to waits).
  - Rejected: a salted hash of the path beside the entry (binds the plaintext, not the key: the salt must be secret from non-readers or they test guessed paths, and a secret salt is key material again: the same 32 B with a check after decrypting instead of before); the padding fix (32 zero bytes leading the plaintext: also 32 B, its binding resting on ChaCha20 outputs not colliding across chosen keys, a property ChaCha20 does not claim); dropping Poly1305's tag beside the commitment (16 B a thing less: the committed key fixes the plaintext and the signature the bytes) keeps one AEAD for every sealed field.
- **Every encryption of T's parts carries T's path key** (`Contents := [[Part*], [PathKey*]]` in a split commit): sections, re-encryptions, copies; a header-only copy of a split commit destroying T carries T's key in a section of no part (`osis_commit::seal_header_only`). One encoding: an encryption carries exactly its parts' things' keys (a header-only copy's section, keys of destroyed things only); a key beyond them, or one its entry does not commit to, makes the encryption hold nothing (`osis_commit::Envelope::open`, `keys_exact`; read once the aspect list resolves, so a copy opened before a linked aspect list resolves is checked against the entries alone).
- **Bad entries** (its committed key opening nothing, a list breaking `Path`'s rules, T listed other than last, the purge author not among T's members): T's parts hold nothing at every reader of T (`CommitBlob::settle_paths` drops them once the aspect list resolves; `View::paths` records `false`). An encryption carrying a key the entry does not commit to (an entry swapped with another, sealed under another key) holds nothing; with no committed key held anywhere, T's parts are never valid anywhere; other things stand (`osis_commit` `a_forged_entry_harms_only_its_own_thing`; engine `validity::hostile_split_commits_harm_only_their_forged_things_alike_everywhere_spec_wire_4`: eight forgeries, three orders of sections, two readers). A creation under a bad or unopenable entry: its `created.0` part holds nothing like its other parts, so no reader holds a minting and the thing is unknown, while the other things' writes (a strong to it) stand (`validity::a_creation_under_a_forged_entry_makes_nothing_spec_wire_4`); `Judge::part` takes a held `created.0` without its path because a held part always carries its key and a record proves itself by its tid. Nothing is settled before the aspect list resolves (`validity::a_split_commit_with_its_aspect_list_by_link_waits_for_it_spec_commits_4`).
- **Padding** (For Tess 3; `osis_commit::ENTRY_CLASSES`, arbitrary-values: at 0 classes (no padding) the size shows the count of holders exactly; at infinity (`[MAX_PATH_THINGS]` alone) about 1 KiB a thing, too much for every split commit): each entry is padded to the smallest of 4, 16, 64 listed things at or above its count, 113, 305 or 1074 bytes with its commitment. Real paths list 0 to 3 things, so every realistic entry is 113 B and shows nothing; what stays visible: that a thing's path lists more than 4 (or 16) things, and, to every reader, that the commit is split (its things' paths are not one `Path` the clear-form rule allowed). Options for Tess: accept the clear form and the split bit (drop the rule in `clear_tells_nothing` too, saving bytes on rare commits), pad (built), or always seal multi-thing commits (about 115 B a thing on every such commit).

## Per consumer
- **Judging**: the old walk (Interim) reads the one purge author (`View::acting`) on every thing; a split commit's part on a thing whose path is not known here (`View::paths`: `true` known, `false` bad, absent while it opens nowhere) is invalid (`validity::Judge::part`). A held part always carries its key, so only parts not held can be undecided; `Indexes::paths_unknown` lists those commits (journaled), each followed by what may open its entries (`apply::paths::Wait`, a `memo::Effects` over `openers`: the held roles secrets of the things up each undecided thing's record chain, accounts' seeds, the records) and opened again only when that moves (`paths::refresh` in `rejudge_all`, after `flows::retake` in `atomic::rejudged`, at load); a late encryption's key decides at once (`atomic::join_late`). An open, reload or rollback builds the wait again from `paths_unknown` without opening anything (no header decoded at open): the first refresh after it walks the openers of every waiting commit once (a rollback drops every cache alike; a rare path). Every split commit a node reads only some things of waits so (the things it does not read), so `paths_unknown` grows with such commits held, attributable to the sync IDs carrying them. Debug builds check after every durable transaction and at the drop that no waiting entry opens to a fresh attempt (`apply::paths::missed`). A commit's thing whose entry no key will ever open waits for good, costing a settle per move of its chain's secrets (notes/sync-facade.md Pending).
- **Waits**: a commit awaits its purge author's record (as one clear path's actor); no per-part pending wait (held parts always know their path; unheld ones wait as above).
- **Purge, level-2 keys, cover facts, listings, stamps, signals**: the one purge author, in the clear (`Header::purge_author`).
- **Undo**: a part not held on a thing whose path is not known here: the commit is not undone there (`undo::undone_parts`, `NotKept`).
- Role commits state one path in the clear (a `Split` on kind 1 or 3 is bad input): `write::role_path`, one `Path` serving every thing a role commit writes (several only where all hang off one path: an account's creation, its root and records off the empty path; debug-asserted), notes/a1-spec/README.md step 3, Role paths.

## Whom a write is by (`act_as`, a1-spec Open 16)
- One purge author per commit; it must be among each thing's members in a split commit (else that thing's entry is bad).
- Built (Open 16 undecided): `act_as(X)` with X on every thing's path states the real paths with X as purge author; where some thing's path does not go through X, the engine states the Interim `[X]` for the whole commit (`engine::write::stated_paths`, marked Open 16), as main's Acting check accepts it. Proposed: refuse it (`Permission`); the owner has not agreed.

## The engine's choice
Each thing's own shortest path (`write::path_with`, memoized per (thing, role)), through X where acting for X; the clear form where they are read off one `Path` and `clear_tells_nothing` holds; else split. Never a longer route for one thing so one path serves all (a part rests on its stated path's edges alone). Role commits: `write::role_path` (one path, notes/a1-spec/README.md step 3); an account's rotation and seed re-seal state `[0]`. Interim `interim_path`: a commit where no path gives the role (a fire valid by its setting; a role commit, a1-spec Open 20), the Open 16 case. `validity::every_stated_path_is_a_chain_of_held_edges_spec_wire_4` checks honest paths are held chains.

## Bytes
`signer` 16, `path`, `remains` 1 (from `thing_cost` and `osis_commit` tests):
| commit | path bytes (+ signer and remains: 17) |
|---|---|
| own things (`[0]`) | 2 |
| dependent creation under the account root (`[0]`) | 2 |
| dependent creation under a granted parent (`[0, D]`) | 18 |
| at or under the last of k holders | 2 + 16k |
| a write of D (by grant from the end) and a thing D holds by grant (clear rule refuses) | split: 3 + 2 · 115 = 233 (author the signer), each section +38 (its key) |
| two paths | 233; +16 with a purge author other than the signer |
| n paths | 3 + 115n for paths of at most 4 holders (n ≥ 24: +1 head byte); 308 / 1077 per entry past 4 / 16 holders |
Each entry's key commitment is 32 of those bytes (83, 276, 1045 without it).
A copy of a split commit carries 38 B per thing whose parts it holds. Sections of one-path commits carry no key list.

## Where a write can fail on its paths
Every error stating paths can raise, against what main accepts in one commit:
| site | when | status |
|---|---|---|
| `write::path_secret` | the writer holds no current read epoch of a thing's independent (a holder left unboxed at the current epoch, spec/crypto.md §4 Low floor) | fixed: the newest roles secret held, else a fresh random key the thing's encryptions carry (`flows::a_writer_left_unboxed_writes_through_different_actors_in_one_commit_spec_crypto_5`); no content commit makes a thing independent (a role commit writing `keys.0` does, and states no split path), so a new thing's epochs are never what is missing |
| `write::stated_paths` | a thing's own path lists more than `MAX_PATH_THINGS` holders | for Tess (4) |
| `CommitBuilder::build`, `COMMIT_PAST_BLOB` / `TooLarge` | a commit near `MAX_BLOB` (an ephemeral one near its blob) that fits in the clear form: the split form adds 3 B, 115 B (to 1077 B) a thing in the header and 38 B a section | for Tess (5) |
| `CommitBuilder::build`, `check_paths` (a part without its thing's path), `Split::read` (fewer than two entries, author the signer) | an honest split whose entry opens bad, or a split of one thing | unreachable: `stated_paths` splits only where each path goes through the purge author, never one thing (`Path::one_of` serves any single thing) |
| no path gives the role, or `act_as(X)` with X off some thing's path | | Interim `[X]` (main's behaviour; Open 16) |

The engine takes a sealed commit's keys from what each reader opens (`validity::a_sealed_split_commit_gives_each_reader_its_own_things_keys_spec_wire_4`, `LocalPeer::sealed`); `LocalPeer`'s plaintext packages carry every key (`osis_commit::rewrite` keeps them).
- A path waiting on an account's epochs (a no-content thing minted by an account beside a write reached another way): its wait reads the account's held seeds; a node paired later takes them before any commit, untested.

## Rejected
- **Refuse or split a multi-path write**: the owner's rule.
- **A salted hash per thing, each path in its sections**: a path is header data; in a section it is missing exactly where header readers need it.
- **A path key from the thing's own derived roles secret**: a floor holder holds only the independent's earlier roles secrets.
- **The key in the header alone**: a re-encryption under a later epoch reaches readers lacking the entry's epoch.
- **One search for a path serving every thing**: rests a part on a longer route than its own.
- **A purge author per thing**: a level-2 key per author names a holder on another thing's chain.

## For Tess
1. Proposed property (spec/requirements.md): "A write may span things reached through different actors; it is one commit."
2. Open 16, `act_as(X)` where X is not on every thing's path (X holds no role on a thing written, or the write is of X itself), at `engine::write::stated_paths` (the Interim fallback):
   | | main | built | proposed |
   |---|---|---|---|
   | stated | actor X | Interim `[X]` for the whole commit | refused, `Permission` |
   | judged | the old walk as X on every thing, the Acting check (signer holds write on X) | the same | nothing written |
   | reader learns | X | X | nothing |
   Built keeps main's capability; the proposal removes it (a requirements change).
3. What a reader of one thing learns of another written with it. Built: the clear form only where it tells nothing (`clear_tells_nothing`), else the split form, entries padded to 4, 16 or 64 listed things (113, 305, 1074 B with the key commitment). The empty path is read as "by whom": it shows that the signer holds a role on every thing written, which "written by the signer" is taken to show already; strictly, that the signer's role is its own edge and not through a holder is a roster fact, and reading it so would split every multi-thing write of own things (about 3 + 115n B more on each, n the things). What stays visible: that a commit is split (its things' paths are not one `Path` the rule allows), and that a thing's path lists more than 4 (or 16) things. Options: accept the clear form and the split bit (drop the rule, fewer bytes on rare commits), pad (built), or always seal multi-thing commits (115 B a thing on every such commit).
4. `MAX_PATH_THINGS` (64) refuses a write through 65 holders or more (`validity::a_path_holds_at_most_max_path_things_spec_wire_2`, by hand): main writes it (it stated no path), so this removes a capability: a user nested 65 holders deep under what they write cannot write it. Lifting it costs, for every reader of such a commit, a point query per hop and, while unjudgeable, a wait per listed record, set by the writer alone; a split entry past 64 needs another padding class (or entries of any length, showing the count). Why 64: notes/a1-spec/README.md, Why MAX_PATH_THINGS is 64.
5. The split form's bytes count against `MAX_BLOB` (and an ephemeral commit's blob): a commit that fits in the clear form by less than 3 B + 115 B a thing (up to 1077 B a thing past 16 holders) + 38 B a section is refused in the split form. A bound on bytes, so the same write fits or not by how it is stated; the alternative is stating the paths outside the commit's blob.
