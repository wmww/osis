# Networking: transport, discovery, reachability
> Summary: Decided with owner. The sync protocol runs over any ordered, bidirectional byte stream behind our own transport abstraction; direct server connections (QUIC/TLS/WebSocket) need no iroh; iroh 1.0 is the P2P transport (LAN, hole punching, relays, later BLE), used without n0's infrastructure; we run an official blind server and relays. Addresses and relays are osis data, server addresses pin the server's key; transport keys are separate from node signing keys. Push wake-ups are a proposal; Tor a future option.

## What osis needs from the network (spec/requirements.md)
- Long-lived connections with server push (subscriptions, relay-only signals), several labels per connection, one round trip for the common case.
- Blind always-on nodes are the backbone; client-to-server reachability matters most. Direct P2P adds LAN, offline and no-server sync.
- No required coordinator: any helper is replaceable and self-hostable; osis works without it (LAN, any blind node, a known address).
- A blind node must not learn authorship or membership. It learns client IPs (accepted), not node identities.
- Authorization is application-level (node signatures, label role keys), so the transport only needs confidentiality and a stable peer key to dial.

## Decisions (owner)
1. **Own transport abstraction.** Sync is framed messages over ordered streams; nothing depends on QUIC or iroh. Implementations: direct server connections (QUIC or TLS/TCP, WebSocket for browsers) without iroh; iroh for P2P; in-process for tests; file bundles for sneakernet (spec/sync.md §11).
2. **iroh for P2P.** Dial by public key, QUIC multipath, hole punching with relay fallback, Rust-native, MIT/Apache-2.0; 1.0 has a stable wire protocol and API.
3. **Official infrastructure, never required.** We run an official blind server (cheap services free, storage for paying accounts) and `iroh-relay`. Anyone may run their own; any blind node may relay. n0's public relays and DNS discovery are not used: n0 would see every node's key and IP.
4. **Reachability is osis data.** A node's dialable key and preferred relays live in `/reach`, published under every label it tracks so co-readers can dial it; blind nodes see nothing of it. Direct addresses are never published: they are IPs, and iroh exchanges them with the specific peer during hole punching. Apps exclude `/reach` from labels whose audience is open (public or bearer-read), where strangers dialing the device is the concern (notes/permissions.md, Public content). LAN discovery uses our own announcement (rotating tag from the `/reach` lan secret plus a per-network transport key, spec/sync.md §10), not iroh's mDNS, which announces the stable endpoint key on every network and lets anyone track the device; the announced address goes to iroh as a dial hint (no discovery service). A co-reader removed from every label still knows the dialable key and lan secret: the node rotates both when a label holding its current `/reach` stops qualifying, and the app may rotate them at will (`Osis::rotate_reach`). Mainline-DHT discovery opt-in.
5. **Transport keys are not node signing keys**, or every blind node and relay learns which device uploaded what. Clients dial blind nodes with an ephemeral key per connection (blind nodes never dial out). A node's dialable P2P key is separate, published only in `/reach`, rotatable at will.
6. **Server addresses pin a key**: a transport URL plus the server's static public key, so a self-hosted server needs no certificate authority and a middlebox cannot pose as the server.

## First contact
A link (and so a contact card) may carry the sharer node's dialable key and relays (spec/wire.md §10): a redeemer sharing no server with the sharer dials that node, which serves K's label as a member peer (spec/sync.md §5). No new mechanism; redemption then needs the sharer online, as any P2P exchange does. Relay defaulting to the official server is client policy.
- Decided (coordinator): a link carries the dialable key and relays only, never `/reach` (the lan secret goes only to co-readers of qualifying groups); nothing is placed under K for the link.
- Sharer (osis `make_link`): `LinkOpts.direct` is explicit opt-in; without servers a non-direct link is an error, and a direct one needs a published `/reach`. The link is created first and carried out (K joining the target can rotate `/reach`: the target stops qualifying), then the link text gets the key from `own_reach()`, so it is the key listened on. `MadeLink { direct, ended }` (links record): `upkeep_links` (K roster change, open, a timer at `until`) rotates `/reach` once a direct link ends (L gone from K's roster: revoked, `revoke_joiner`; or its edge expired), except a single-use link finalized by its redemption (decided: its one possible user is now a member and keeps the direct path).
- Redeemer (`follow_link`): servers go into K's hint, the link's peers into `follow_link_peer` (`y/l`: K, target, `peer://` addresses; inbox hints and `/label` server lists never dial `peer://`). `link_routes` dials them as peer connections (ephemeral key, `peer_retry_ms`) for K's hinted label and the synced labels of K and the target only; no member proof (`Try::Member` only for co-readers in `peers()` of a group that publishes `/reach`), so the sharer sees the redeemer's IP, never its dialable key. The follow is kept after a redemption; when it fails or the key guard drops (`KeyGuard.link`), `forget_link` drops the record and K's hint. K opens there by L's static entry like at a server.
- A sharer that syncs K and the target with nobody (no server, no other device) serves them through local passes (Implementation (node peers), Serving).

## Local and offline transports
Owner wants "just works" across LAN, Bluetooth and similar. LAN works in iroh today. Custom transports (BLE, WiFi Aware, mixnets) use an iroh API that is unstable and outside 1.0 guarantees; the only BLE crate is experimental and AGPL, so BLE means our own transport on that API (owner's license call if the crate is used instead). Not MVP. Low-bandwidth links suit small commits and signals; large bodies wait for a fast path (chunk fetch is lazy, spec/sync.md §6). Recheck the iroh state before relying on any of this.

## Future option: Tor
Hides IPs from blind nodes, relays and peers. Not needed now (owner). Paths: iroh custom transport, or a direct-server transport over Arti (onion services were not production-ready at last check).

## Risks
- **Single vendor.** iroh's NAT traversal is an n0 Internet-Draft on n0's own QUIC fork; open code, stable wire, no multi-implementation standard. Mitigated by decision 1; rust-libp2p is the fallback.
- **Browsers are relay-only** in iroh. Browsers use the WebSocket server transport instead.
- **Relays see metadata** (IPs, timing, volume, endpoint IDs). Same class as a blind node; ephemeral client keys limit linkability.
- Mobile background limits: sync through blind nodes in background, P2P in foreground.

## Alternatives considered
- **rust-libp2p**: most decentralized (spec'd, many implementations, DHT, circuit relays, browser transports). Large surface, mostly unneeded since peers come from group state. Fallback if the single-vendor risk materializes.
- **Veilid**: private routing plus its own storage model, overlaps osis's data layer. Not a base.
- **Willow/WGPS, Syncthing BEP, Hyperswarm**: sync protocols or JS-only stacks, not transports. Syncthing's community relays plus self-hostable discovery are the precedent for decision 3.

## Proposal: push wake-ups from blind nodes
Mobile notifications need the server to wake a device with no live connection (spec/sync.md §8 pushes only on subscriptions). A push token (APNs, FCM) is a stable device identifier, so registering one token for several labels would link them at the server beyond the accepted overlap leak. Not in the spec; nothing is needed before the initial implementation.
- **Wake handles**: per label the device registers a sealed box to a push proxy's public key holding the push token plus fresh randomness, so the server sees unrelated handles. On a new log event the server hands the handle to the proxy, which opens it and sends an empty push; the device syncs. The server learns handle counts per label and wake timing; the proxy learns tokens and timing, never labels; both together can link labels by timing.
- **UnifiedPush**: the server posts to per-label endpoint URLs directly, no proxy; an osis server can itself be a distributor. iOS needs APNs through the official proxy.
- Rate limits: at most one wake per handle per short interval; events batch into one wake.
- **Priority** (which writes wake): a per-upload wake bit (server learns which entries matter), a separate wake label per chat (overlap shows its pairing), or wake on everything with client-side filtering (battery). Undecided.
- Owner calls when it comes up: official proxy beside the official server or separately operated; priority; who pays (accounts deferred, notes/sync.md Open).
- Constraints to keep while implementing: per-entry upload-time attributes stay outside the hashed blob prefix (as the deposit flag does), so a wake bit never touches blob IDs; local-store root keys must be readable after first unlock while the device is locked, or a woken app cannot present the sync key.

## Implementation (osis-transport)
- Traits: `Transport`/`Listener`/`Connection`/`SendStream`/`RecvStream` (notes/architecture.md §2). `Address { url, key }` mirrors the schema's `address`; the URL scheme picks the transport, an unknown scheme is `Error::UnknownScheme` (Parked). Error classes: key mismatch, bad URL, protocol = BadInput; unreachable, closed, I/O = Local.
- Stream contract (both impls): the peer's `accept_stream` sees a stream once data or finish is sent on it; `finish` resolves once the peer's transport has everything (quinn `stopped`); dropping a send half finishes it; `close` is abrupt (unread data lost). Graceful end: the dialer finishes, reads the peer to its end and closes (`close_gracefully`); the accepting side finishes and waits for that close, since closing first can cut the dialer's read.
- `InProcess`: endpoints on a shared `Net`; virtual steps; faults `latency`, seeded `jitter` (reorders deliveries across streams only, never within one), `bandwidth` per stream direction per step, `partition` (dials fail, data waits until `heal`), `disconnect`, `kill`; `Net::sleep(steps)` virtual timers. A listener's key is the Ed25519 key of its secret, as for `Quic` and `Iroh` (so a dialable key verifies LAN announcements in tier-1 tests); dialers get seeded random ephemeral keys (`dial_as`: the same derivation of their secret). Closing a listener resets the connections it has not accepted. `Sched` polls ready tasks in seeded order and steps the net when all are blocked: same seed, same interleaving, no tokio. Writes never block (unbounded buffers).
- `Quic` (spec/sync.md §10 `quic://host:port`): quinn 0.11 + rustls 0.23 (ring), TLS 1.3 only, ALPN `osis`, no 0-RTT, no session tickets, no SNI, RFC 7250 raw Ed25519 keys both ways: the listener's key pair comes from its 32-byte secret (an Ed25519 seed, hand-built PKCS#8), a client's from OS randomness per dial (or the given secret for `dial_as`); custom verifiers pin the server key (mismatch -> `KeyMismatch`) and accept any Ed25519 client key. Peer protocol/TLS failures -> `Protocol` (not retried by `connect`). Each dial binds its own UDP socket, so a server cannot link a client's connections by source port. Handshakes have no deadline (any link speed connects): QUIC's idle timeout ends a silent one, both sides; listener handshakes run concurrently (`Handshakes`, `iroh` too), at most 1024 in progress, the oldest aborted past that, so a silent client blocks nobody. A dial to an unreachable address fails after the 60 s idle timeout. Per-connection memory is bounded: 16 bidi streams, no uni streams or datagrams, stream window 1 MiB, connection window 4 MiB (the reader drains frames incrementally; `iroh` shares these settings); idle timeout 60 s, keep-alive 15 s (all provisional). Why QUIC over Noise-over-TCP: native multiplexed streams, flow control, migration and keep-alive without our own mux; same stack as iroh. Cost: build time (behind the feature) and ring's C/asm.
- Helpers (`manage`): `Backoff` (seeded jitter in `[d/2, d]`, 500 ms doubling to 60 s, provisional), `connect` (retries only `Local` errors, sleep injected so tests use `Net::sleep`), `close_gracefully`. One connection serves many labels through proto's message ids on one session stream; no stream-per-label scheme.
- `link` (tokio): a session = one stream as a `Link` (`peer_key`, `LinkTx` with a not-yet-written byte count and cap, `LinkRx` read-ahead 16 × 64 KiB so flow control holds the peer) with two pump tasks. `link::dial(t, addr, Option<&StaticSecret>, wait)`: one stream, the dialer closes after finishing. `link::serve(listener, idle, wait, out, max)`: at most `max` connections at once; every stream a dialer opens is a session; the accepting side finishes its side, closes only after the dialer closed or `idle` without sessions. The server and node drivers use it.
- `peer://` (`PEER_SCHEME`, `peer_url(hints)`, `peer_relays(url)`): a node dialed by `Address::key`; the URL lists hints separated by single spaces: relay URLs, and socket addresses (LAN announcement, loopback tests). `InProcess` dials `peer://` by finding the listener with that key.
- `Iroh` (feature `iroh`): iroh 1.3 (`default-features = false`, `tls-ring`; needs Rust 1.91, above the workspace's 1.88, only with the feature). Built from `presets::Minimal`: no address lookup, relays disabled unless given, so nothing touches n0. Key = Ed25519 of the 32-byte static secret (same as `Quic`). A listener registers at the relays its URL lists (and binds the socket addresses it lists), nowhere else: the dialable listener lists the `/reach` relays, a LAN listener none (a relay would link its fresh key to the dialable key by public IP); a dial uses the URL's relays and direct addresses; hole punching is iroh's. ALPN `osis`, 0-RTT off (no TLS tickets), 16 bidi streams, no uni, windows as `Quic`. `dial` binds a fresh endpoint per connection (closed with it); `dial_as` reuses this transport's listening endpoint of that key and fails without one (a second endpoint with a listener's key could take its relay registration; nodes never `dial_as` co-readers). Listener URL `peer://` + socket addresses to bind; its `address()` lists the bound sockets and relays. Peer key checked against `Address::key` (iroh's handshake pins it). Tier 2: loopback test in `iroh.rs`, two node drivers over iroh (osis-node `--features iroh --test it driver:: -- --ignored`).
- Cost of `iroh` (tried, accepted behind the feature): ~190 extra crates (reqwest/hyper, noq (n0's quinn fork), RustCrypto 0.11 with ed25519-dalek 3 beside our dalek 2, netlink, ICU); about 4 minutes cold build of osis-transport tests on the shared 4 cores; `cargo deny` needs one `skip-tree` (iroh), licence exceptions (CDLA-Permissive-2.0 for webpki roots; Unlicense for three wasm-only crates) and `RUSTSEC-2024-0436` (paste, compile-time). The API fit the traits without adapters. Default builds of every crate compile no iroh.
- LAN (`lan`): `Announce { tag, key, port, sig }` datagram `"osis lan 1"` || tag || key || port (be16) || sealed signature, 124 bytes (spec/sync.md §10, provisional); `signed()` = tag || key || port; `Announce::address(sender socket address)` = `peer://ip:port` (an IPv6 link-local source keeps its `%scope`, which `SocketAddr` parses back); `is_local(ip)`; `broadcast(port)`, `multicast(port)` (`[ff02::1]:port`). `Lan` (feature `lan`): an IPv4 UDP socket bound to the port (`lan::PORT` 47380, provisional) with broadcast on, and where the host has IPv6 an IPv6-only socket (socket2 `set_only_v6`) at the same port in ff02::1; `announce(to)` picks the socket by `to`'s family; ff02::1 with no scope goes out each up interface with an IPv6 link-local address, as `ff02::1%<index>` (`targets`, `link_scopes`; `v6_scopes()` asks netwatch's interface list at each announcement, so `lan` depends on netwatch too), nothing joined per interface (every IPv6 interface is in ff02::1, and Linux's `IPV6_MULTICAST_ALL`, on by default, delivers it to the unconnected socket; not verifiable here: the dev VM drops looped-back multicast); every scoped send failing, or no interface known: the default one, `recv()` polls both (skips other datagrams and non-local sources) and returns the source socket address. `route_ip()`: the local addresses of the IPv4 and IPv6 routes out (UDP sockets connected to documentation prefixes, no packet sent). `NetWatch` (feature `lan`): `changed()` resolves at a network change: the routes' local addresses polled every `ROUTE_POLL` (5 s), and with feature `iroh` netwatch's monitor (netlink etc.): a change of the default route's interface, its up flag, its addresses (IPv6 by /64 prefix, `network_of`: temporary addresses rotate within a network; the IPv6 route too), or a wake from sleep (netwatch debounces 250 ms). `recv` alternates which socket it polls first. Another Wi-Fi with the same addressing is seen only through netwatch (the interface goes down and up while reassociating).
- `Multi` (`multi.rs`): one transport over `mem`/`quic`/`iroh` by URL scheme (`peer://` to iroh when present, else to `InProcess`, which finds a `peer://` listener by key); a scheme without its transport is `UnknownScheme`. The osis handle's driver runs on it.
- `relay` feature: `iroh::TestRelay::spawn()`, a self-hosted `iroh-relay` on localhost (plain HTTP) for tier-2 tests; a listener registers there by listing its URL.
- Not yet: a WebSocket transport for browsers; backpressure in `InProcess`.

## Implementation (node peers)
- `/reach` (`sync/peers.rs`): `dialable_secret()` (random, local record `y/r`, shredded), `rotate_reach()` (osis `rotate_reach`: new dialable and lan secrets, `/reach` written at once with the new secret's Ed25519 key and the old relays, `Action::Reach` to the driver), `publish_reach(dialable key, relays)` writes `/reach` on the node thing when changed (the listener's key; every transport's key is the Ed25519 key of its secret); the node card carries it under a synced label only where `publishes_reach(group)`: the group's stored policy (`set_reach_policy`, `y/n`; osis `sync_policy(g, GroupPolicy { publish_reach })`), else contacts-only: its reader actor is this node's own (an actor the node is a member of: its person, or itself in node-level tests), or each member is own, a contact (`set_contact`, `y/a`; osis `import_contact` marks the person) or a thing an own actor owns whose members pass the same test (a link's K holds the key actor L, so groups shared by link are excluded). Policy and contact setters return actions (a `handle`). `check_reach` (at start, after a membership or roster change, a policy or contact change): when a synced label whose group no longer qualifies holds the current `/reach` commit (`state.certs` has (label, newest `/reach` commit)) it rotates; the next passes place the new one only where it qualifies (the old one stays where it was, reaching nothing). Not caught: a reader removed from a group that still qualifies keeps the key until a rotation. Co-readers are dialed only for labels whose group publishes `/reach` (a link's sharer: First contact). `#[must_use]` on the setters and `rotate_reach`.
- Co-readers: node things other than this one with a held `/reach` that `may_read` a synced label's group, at most `max_peers_per_label` (8) per label and `max_peers` (64) in all, newest `/seen` first; dialed (`SyncConfig.peers`, default on) at a LAN candidate, else a proven LAN address, else `peer://` + their relays; `Conn.server` is the dialable key (presence, cursors), the session pins the address key (a LAN address presents its per-network key). Redial pause `peer_retry_ms` (60 s). Co-readers are dialed with an ephemeral transport key like servers (relays see no stable source key); the node proves itself inside the session with open proof 3 (`Try::Member`, last on co-reader connections, only for a group that publishes `/reach`: a signature under `"osis v1 member open"` by the dialable key over the served side's challenge and static key). Connections to co-readers no longer wanted are closed (`drop_unwanted_peers`); `Config.peers = false` and a driver without a `peer://` transport turn `SyncConfig.peers` off (`set_peers`). Co-readers and the `/reach` holders are cached until the engine's generation changes (`Core::generation`, bumped by every changing transaction) or a minute passes (edges expire).
- LAN binding (decided): the announcement carries an Ed25519 signature by the dialable key over BLAKE3(tag || key || be16 port) (domain `"osis v1 lan announce"`), XORed with a 64-byte keystream `kdf_xof("lan sig", lan secret, le64(window) || digest)` (bound to the digest, so another key or port in the window never reuses it) (osis-crypto `seal_lan_sig`/`open_lan_sig`), so checking it needs both the lan secret and the dialable key. Plain, the signature let every holder of the dialable key (relays the dialable listener registers at, co-readers) recognise the device's announcements across networks and windows. Chosen over a MAC under the lan secret (any co-reader of any label shared with the node knows that secret and could pose as the node on the LAN) and over a signature inside the first stream message (a protocol change, known only after connecting). Cost: dialable and LAN keys must be Ed25519 (every transport here). Vector: `core/test/vectors/lan/announce.vec` (provisional).
- LAN (`sync/peers.rs`): `lan_tag(secret, ms)`; `lan_secret()` (a fresh transport secret per join); `lan_announcement(key, port)` (None until `/reach` holds the dialable secret's key); `lan_seen(&Announce, from socket address)`: ignores non-local sources, looks the tag up in a per-window cache of the co-readers' tags (current and adjacent windows), opens and verifies the sealed signature under the matched lan secret, window and dialable key (the last verified announcement per peer is kept, a repeat is not verified again), counts the source among up to 4 verified addresses per peer (`heard`), then sets the address as the co-reader's candidate (`LanRoute`) at most once per `LAN_CHANGE_MS` (5 s); a candidate that fails falls back to the most heard other address (a spoofed replay that won the candidate costs one failed dial); a repeat only refreshes it, and `handle` runs only when a dial can follow (no retry pause and no connection to the peer, or only one through a relay). Routes: the proven route first, else the candidate, else `peer://` + relays; a candidate never displaces a running connection before it is up: `connect` dials the LAN route beside a single running non-LAN connection (`lan_probe`; two `Conn`s share the peer key meanwhile), and when it comes up and is the proven route (`lan_up` true) the others close (`lan_switched`: cleaned up as lost, the retry entry dropped; labels resume on the LAN connection from their cursors; queued deposits in flight record their connection, `Outgoing::sent`, so only the closed one's go again); `lan_up` also proves a verified source (`heard`) the candidate moved away from while its dial ran; a connection through a LAN address that comes up proves it (`lan_up`); one that fails before coming up backs off that address (`lan_failed`), and the next route is dialed at once (the relay connection, if any, just stays). `peer_routes()` lists co-reader connections (key, address, up). A new candidate ends the peer's retry pause at most once per `peer_retry_ms` (`LanRoute.cut`): without it a node whose relay dial failed waited the full pause; unbounded, replays from many sources would loop dials.
- Member node (spec/sync.md §5): open proof 3 (`Proof::Member`, osis-label; `OpenKey::Member`, osis-proto) carries the dialable key and its signature; blind nodes refuse it; `ServerConnection` checks the signature and asks the store (`LabelStore::member_open(dialable, label)`), and records the key (`member()`). `PeerStore::member_open`: the key names exactly one node thing among held `/reach` (`reach_nodes`: a key two node things claim matches neither) whose `may_read` the label's group holds. Budgets are charged to the proven dialable key; other sessions to the label the bytes went under (`charge_key`: dialer keys are fresh per connection, so strangers with a link share K's budget instead of filling the node's total). `served_members()` lists proven keys. On a membership or roster change (`members_changed`) served sessions whose proven node no longer reads an opened label are closed. A link's sharer is dialed for first contact (First contact above).
- Serving (`sync/serve.rs`): `accept(local key, peer key)` starts a `ServerConnection` (static key = the listener's key, which open signatures bind) over `PeerStore`, a `LabelStore` over the sync state's entries and the engine's blobs: served labels are the synced ones at the deepest recorded step (plus at most 64 steps per label peers registered, in memory), cached until a `/label` or membership commit, a roster change or a peer step; an entry is live while this node holds its blob; log in memory (`Feed`, fed by `State::set_entry`/`remove_entry`, 4096 records per label, fresh log ID per start, so peers replay after a restart); accepted uploads and deposits go through `log_events` like downloads; entries this node dropped (server deletion, own delete, must-not-hold drop) are tombstoned (`y/x`, corrected wall ms) and refused with code 6 for `TOMBSTONE_LIFETIME`; a peer's delete or timed delete hides the entry from peers only (expiring with the same lifetime); registrations of new labels refused. Budget: bytes accepted from peers count against the proven member key, else the label (`charge_key`, `peer_bytes`, 64 MiB each) and all peers (`peer_total_bytes`, 1 GiB) while the entry is held, unopened and at no server or peer; over it uploads get code 12, deposits code 5; the reply budget reports what is left. At most `max_served` (64) sessions: a new one evicts the oldest that has opened nothing, else is closed (dialer keys are ephemeral, so a per-key cap would bind nothing; silent LAN hosts cannot starve members) and, in the driver, as many connections (`link::serve`); a session silent for `serve_idle_ms` (120 s) is closed. Grown logs push to subscribed sessions after each `handle`. A session that opened nothing within `serve_open_ms` (30 s) is closed. Signals from a peer fire locally and go to other peer sessions. A label synced with nobody (no non-`peer://` server in its `/label`) gets a local pass (`local_passes`, pass.rs; on every change that marks labels dirty and every `resync_ms`, only while `/reach` is published: a node nobody can dial pays nothing; one label's error is a diagnostic). It shares the server pass's pieces: `step_due` (then `issue_step` from a head recorded in `/label`, and the pass goes on under the new step, as `reregister` would at a server), `body_sends` (must-hold bodies and their linked blobs, placed; inbox copies, certificates, the heartbeat; what it placed is stamped when it writes), `keep_at_most_due` (a covering snapshot before a relative keep-at-most bound, the server pass's carrier step; there are no timed deletes locally: the engine drops the body at the bound and the deletion step removes it once carried), and `deletable` (judge, carrier, `may_delete`, delete item; the server pass and `verdicts` use it too). `local_deletions`, over entries no server or peer holds: commit entries go as `deletable` says, even blobless ones (a dropped body with live writes waits for its carrier, a snapshot asked for), expired ones outright; other entries go when their bytes are gone or their prefix expiry passed (read once, `local_expiry`); chunks of dropped deltas go; bytes no other entry names are deleted. Not done locally: chain completion and promotion (deposits stay unstamped), deleting the blobs a gone certificate copy linked (issues/node-sync-gaps.md). Snapshots under the label (its own included) drop the bodies they cover, as in the server pass (`drop_label_covered`). Deposits to such a label (inbox blobs, own membership writes) are logged locally (`local_inbox`, through `log_events` like a peer's deposit). Chosen over a loopback session (a `Conn` to its own served store): that needs presence and cursors against itself for nothing a peer sees. Without it a sharer with no server or other device handed a direct-link redeemer an empty K label (osis `redeem_direct_no_server_in_process_spec_permissions_9`). Costs: blob sizes are cached in memory (`blob_sizes`, pruned at ticks); charges keep running sums per charge key and in all, pruned at each tick and, at most once a second, after a budget refusal.
- Complete pass (spec/permissions.md §3): `complete_pass` also waits for each co-reader X the node received the label's entries from (dialed sessions, or served uploads with a member proof; `peer_received`) while X is a co-reader of that label, a connection to X is up and has the label started (`pass_peers`, computed at the end of each `handle`), and at most `peer_pass_wait_ms` (5 min) after the actor's last remote membership commit (`membership_at`); a membership change drops X from labels it no longer reads. So a removed co-reader, or one that stalls on purpose, cannot hold re-seals back.
- Driver (`sync/driver.rs`): dials always ephemerally; listeners come with `run_serving`, `Control::Reach { url, relays, reply }` (listen with the dialable secret at `url`, which for iroh lists the relays, and `publish_reach`; remembered, with the listener's key) and the LAN loop. `Action::Reach` (a rotation): after the current event the driver drops the old dialable listener (awaited: an in-process URL is free only once it is dropped; the sessions a listener accepted, `served_by`, close with it, as an iroh endpoint's do), listens again at the remembered URL with the new secret (a failure is logged and retried every `RELISTEN_RETRY`, 5 s: `/reach` already names the new key), and rejoins the LAN at once. `Control::Lan(LanConfig { port, to, listen, watch })` (feature `lan`): binds the announcement sockets, starts a `NetWatch` task (unless `watch` is off, tests) whose changes and `Control::LanRejoin` (an app's OS callback) make it rejoin at most every `LanConfig.rejoin_min` (`LAN_REJOIN_MIN` 30 s; the LAN timer runs a deferred one), rotations at once: drop the old LAN listener (awaited), listen at `listen` (default `peer://0.0.0.0:0 [::]:0`, IPv4 only if that fails) with `lan_secret()` and announce at once, then every `LAN_ANNOUNCE` (30 s, looked at every `LAN_CHECK` 5 s) to each of `to` (default broadcast and ff02::1 at 47380), each family's announcement with the listener's port on that family (iroh binds separate ports); datagrams heard (bounded queue, a flood is dropped) go to `lan_seen`. The osis handle's driver runs on `Multi` (`Transport::InProcess`: mem; `Transport::Quic`: QUIC plus iroh with feature `iroh`), sends `Reach` (iroh: `peer_url(Config.relays)`; in process: `mem://<endpoint>-peer`) when `Config.peers` (default on) and `Lan(default)` with feature `lan`; without a `peer://` transport (QUIC without `iroh`) it turns peers off. Tier 2: node driver tests over iroh with the LAN loop on localhost, IPv4 and IPv6 (`--features iroh,lan`), through a `TestRelay` (`--features relay`), and relay plus LAN loop ending on the LAN route (`--features relay,lan`). Tier 1 (osis tests/it/runtime.rs): first contact by a direct link with the server partitioned from the redeemer; a rotation listened on without a restart.
