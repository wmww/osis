# Networking: transport, discovery, reachability
> Summary: Decided with owner. The sync protocol runs over any ordered, bidirectional byte stream behind our own transport abstraction; direct server connections (QUIC/TLS/WebSocket) need no iroh; iroh 1.0 is the P2P transport (LAN, hole punching, relays, later BLE), used without n0's infrastructure; we run an official blind server and relays. Addresses and relays are osis data, server addresses pin the server's key; transport keys are separate from node signing keys. Push wake-ups are a proposal; Tor a future option.

## What osis needs from the network (spec/requirements.md)
- Long-lived connections with server push (subscriptions, signals), several labels per connection, one round trip for the common case.
- Blind always-on nodes are the backbone; client-to-server reachability matters most. Direct P2P adds LAN, offline and no-server sync.
- No required coordinator: any helper is replaceable and self-hostable; osis works without it (LAN, any blind node, a known address).
- A blind node must not learn authorship or membership. It learns client IPs (accepted), not node identities.
- Authorization is application-level (node signatures, label role keys), so the transport only needs confidentiality and a stable peer key to dial.

## Decisions (owner)
1. **Own transport abstraction.** Sync is framed messages over ordered streams; nothing depends on QUIC or iroh. Implementations: direct server connections (QUIC or TLS/TCP, WebSocket for browsers) without iroh; iroh for P2P; in-process for tests; file bundles for sneakernet (spec/sync.md §11).
2. **iroh for P2P.** Dial by public key, QUIC multipath, hole punching with relay fallback, Rust-native, MIT/Apache-2.0; 1.0 has a stable wire protocol and API.
3. **Official infrastructure, never required.** We run an official blind server (cheap services free, storage for paying accounts) and `iroh-relay`. Anyone may run their own; any blind node may relay. n0's public relays and DNS discovery are not used: n0 would see every node's key and IP.
4. **Reachability is osis data.** A node's dialable key and preferred relays live in `/reach`, published under every label it tracks so co-readers can dial it; blind nodes see nothing of it. Direct addresses are never published: they are IPs, and iroh exchanges them with the specific peer during hole punching. Apps exclude `/reach` from labels whose audience is open (public or bearer-read), where strangers dialing the device is the concern (notes/permissions.md, Public content). LAN discovery uses our own announcement (rotating tag from the `/reach` lan secret plus a per-network transport key, spec/sync.md §10), not iroh's mDNS, which announces the stable endpoint key on every network and lets anyone track the device; the announced address goes to iroh as a dial hint (no discovery service). A co-reader removed from every label still knows the lan secret; rotate it with `/reach` now and then. Mainline-DHT discovery opt-in.
5. **Transport keys are not node signing keys**, or every blind node and relay learns which device uploaded what. Clients dial blind nodes with an ephemeral key per connection (blind nodes never dial out). A node's dialable P2P key is separate, published only in `/reach`, rotatable at will.
6. **Server addresses pin a key**: a transport URL plus the server's static public key, so a self-hosted server needs no certificate authority and a middlebox cannot pose as the server.

## First contact
A link (and so a contact card) may carry the sharer node's dialable key and relays (spec/wire.md §10): a redeemer sharing no server with the sharer dials that node, which serves K's label as a member peer (spec/sync.md §5). No new mechanism; redemption then needs the sharer online, as any P2P exchange does. Relay defaulting to the official server is client policy.

## Local and offline transports
Owner wants "just works" across LAN, Bluetooth and similar. LAN works in iroh today. Custom transports (BLE, WiFi Aware, mixnets) use an iroh API that is unstable and outside 1.0 guarantees; the only BLE crate is experimental and AGPL, so BLE means our own transport on that API (owner's license call if the crate is used instead). Not MVP. Low-bandwidth links suit small commits and signals; large bodies wait for a fast path (chunk fetch is lazy, spec/sync.md §6). Recheck the iroh state before relying on any of this.

## Future option: Tor
Hides IPs from blind nodes, relays and peers. Not needed now (owner). Paths: iroh custom transport, or a direct-server transport over Arti (onion services were not production-ready at last check).

## Risks
- **Single vendor.** iroh's NAT traversal is an n0 Internet-Draft on n0's own QUIC fork; open code, stable wire, no multi-implementation standard. Mitigated by decision 1; rust-libp2p is the fallback.
- **Browsers are relay-only** in iroh. Browsers use the WebSocket server transport instead.
- **Relays see metadata** (IPs, timing, volume, endpoint IDs). Same class as a blind node; ephemeral client keys limit linkability.
- Mobile background limits: sync through blind nodes in background, P2P in foreground.

## Alternatives considered
- **rust-libp2p**: most decentralized (spec'd, many implementations, DHT, circuit relays, browser transports). Large surface, mostly unneeded since peers come from group state. Fallback if the single-vendor risk materializes.
- **Veilid**: private routing plus its own storage model, overlaps osis's data layer. Not a base.
- **Willow/WGPS, Syncthing BEP, Hyperswarm**: sync protocols or JS-only stacks, not transports. Syncthing's community relays plus self-hostable discovery are the precedent for decision 3.

## Proposal: push wake-ups from blind nodes
Mobile notifications need the server to wake a device with no live connection (spec/sync.md §8 pushes only on subscriptions). A push token (APNs, FCM) is a stable device identifier, so registering one token for several labels would link them at the server beyond the accepted overlap leak. Not in the spec; nothing is needed before the initial implementation.
- **Wake handles**: per label the device registers a sealed box to a push proxy's public key holding the push token plus fresh randomness, so the server sees unrelated handles. On a new log event the server hands the handle to the proxy, which opens it and sends an empty push; the device syncs. The server learns handle counts per label and wake timing; the proxy learns tokens and timing, never labels; both together can link labels by timing.
- **UnifiedPush**: the server posts to per-label endpoint URLs directly, no proxy; an osis server can itself be a distributor. iOS needs APNs through the official proxy.
- Rate limits: at most one wake per handle per short interval; events batch into one wake.
- **Priority** (which writes wake): a per-upload wake bit (server learns which entries matter), a separate wake label per chat (overlap shows its pairing), or wake on everything with client-side filtering (battery). Undecided.
- Owner calls when it comes up: official proxy beside the official server or separately operated; priority; who pays (accounts deferred, notes/sync.md Open).
- Constraints to keep while implementing: per-entry upload-time attributes stay outside the hashed blob prefix (as the deposit flag does), so a wake bit never touches blob IDs; local-store root keys must be readable after first unlock while the device is locked, or a woken app cannot present the sync key.

## Implementation (osis-transport)
- Traits: `Transport`/`Listener`/`Connection`/`SendStream`/`RecvStream` (notes/architecture.md §2). `Address { url, key }` mirrors the schema's `address`; the URL scheme picks the transport, an unknown scheme is `Error::UnknownScheme` (Parked). Error classes: key mismatch, bad URL, protocol = BadInput; unreachable, closed, I/O = Local.
- Stream contract (both impls): the peer's `accept_stream` sees a stream once data or finish is sent on it; `finish` resolves once the peer's transport has everything (quinn `stopped`); dropping a send half finishes it; `close` is abrupt (unread data lost). Graceful end: the dialer finishes, reads the peer to its end and closes (`close_gracefully`); the accepting side finishes and waits for that close, since closing first can cut the dialer's read.
- `InProcess`: endpoints on a shared `Net`; virtual steps; faults `latency`, seeded `jitter` (reorders deliveries across streams only, never within one), `bandwidth` per stream direction per step, `partition` (dials fail, data waits until `heal`), `disconnect`, `kill`; `Net::sleep(steps)` virtual timers. A listener's key is the Ed25519 key of its secret, as for `Quic` and `Iroh` (so a dialable key verifies LAN announcements in tier-1 tests); dialers get seeded random ephemeral keys (`dial_as`: the same derivation of their secret). Closing a listener resets the connections it has not accepted. `Sched` polls ready tasks in seeded order and steps the net when all are blocked: same seed, same interleaving, no tokio. Writes never block (unbounded buffers).
- `Quic` (feature `quic`, spec/sync.md §10 `quic://host:port`): quinn 0.11 + rustls 0.23 (ring), TLS 1.3 only, ALPN `osis`, no 0-RTT, no session tickets, no SNI, RFC 7250 raw Ed25519 keys both ways: the listener's key pair comes from its 32-byte secret (an Ed25519 seed, hand-built PKCS#8), a client's from OS randomness per dial (or the given secret for `dial_as`); custom verifiers pin the server key (mismatch -> `KeyMismatch`) and accept any Ed25519 client key. Peer protocol/TLS failures -> `Protocol` (not retried by `connect`). Each dial binds its own UDP socket, so a server cannot link a client's connections by source port. Listener handshakes run concurrently, each under a 5 s deadline (at most 1024 in progress), so a silent client blocks nobody. Per-connection memory is bounded: 16 bidi streams, no uni streams or datagrams, stream window 2 × MAX_MESSAGE, connection window 4 × MAX_MESSAGE; idle timeout 60 s, keep-alive 15 s (all provisional). Why QUIC over Noise-over-TCP: native multiplexed streams, flow control, migration and keep-alive without our own mux; same stack as iroh. Cost: build time (behind the feature) and ring's C/asm.
- Helpers (`manage`): `Backoff` (seeded jitter in `[d/2, d]`, 500 ms doubling to 60 s, provisional), `connect` (retries only `Local` errors, sleep injected so tests use `Net::sleep`), `close_gracefully`. One connection serves many labels through proto's message ids on one session stream; no stream-per-label scheme.
- `link` (feature `link`, tokio): a session = one stream as a `Link` (`peer_key`, `LinkTx` with a not-yet-written byte count and cap, `LinkRx` read-ahead 16 × 64 KiB so flow control holds the peer) with two pump tasks. `link::dial(t, addr, Option<&StaticSecret>, wait)`: one stream, the dialer closes after finishing. `link::serve(listener, idle, wait, out)`: every stream a dialer opens is a session; the accepting side finishes its side, closes only after the dialer closed or `idle` without sessions. The server and node drivers use it.
- `peer://` (`PEER_SCHEME`, `peer_url(hints)`, `peer_relays(url)`): a node dialed by `Address::key`; the URL lists hints separated by single spaces: relay URLs, and socket addresses (LAN announcement, loopback tests). `InProcess` dials `peer://` by finding the listener with that key.
- `Iroh` (feature `iroh`): iroh 1.3 (`default-features = false`, `tls-ring`; needs Rust 1.91, above the workspace's 1.88, only with the feature). Built from `presets::Minimal`: no address lookup, relays disabled unless given, so nothing touches n0. Key = Ed25519 of the 32-byte static secret (same as `Quic`). A listener registers at the relays its URL lists (and binds the socket addresses it lists), nowhere else: the dialable listener lists the `/reach` relays, a LAN listener none (a relay would link its fresh key to the dialable key by public IP); a dial uses the URL's relays and direct addresses; hole punching is iroh's. ALPN `osis`, 0-RTT off (no TLS tickets), 16 bidi streams, no uni, windows from MAX_MESSAGE as `Quic`. `dial` binds a fresh endpoint per connection (closed with it); `dial_as` reuses this transport's listening endpoint of that key and fails without one (a second endpoint with a listener's key could take its relay registration; nodes never `dial_as` co-readers). Listener URL `peer://` + socket addresses to bind; its `address()` lists the bound sockets and relays. Peer key checked against `Address::key` (iroh's handshake pins it). Tier 2: loopback test in `iroh.rs`, two node drivers over iroh (osis-node `--features iroh --test driver -- --ignored`).
- Cost of `iroh` (tried, accepted behind the feature): ~190 extra crates (reqwest/hyper, noq (n0's quinn fork), RustCrypto 0.11 with ed25519-dalek 3 beside our dalek 2, netlink, ICU); about 4 minutes cold build of osis-transport tests on the shared 4 cores; `cargo deny` needs one `skip-tree` (iroh), licence exceptions (CDLA-Permissive-2.0 for webpki roots; Unlicense for three wasm-only crates) and `RUSTSEC-2024-0436` (paste, compile-time). The API fit the traits without adapters. Default builds of every crate compile no iroh.
- LAN (`lan`): `Announce { tag, key, port, sig }` datagram `"osis lan 1"` || tag || key || port (be16) || sealed signature, 124 bytes (spec/sync.md §10, provisional); `signed()` = tag || key || port; `Announce::address(sender ip)` = `peer://ip:port`; `is_local(ip)`; `broadcast(port)`. `Lan` (feature `lan`): a UDP socket bound to the port (`lan::PORT` 47380, provisional) with broadcast on, `announce(to)`, `recv()` (skips other datagrams and non-local sources); `route_ip()` (the local address of the route out, found by connecting a UDP socket to TEST-NET-1, no packet sent) tells a network change.
- `Multi` (`multi.rs`): one transport over `mem`/`quic`/`iroh` by URL scheme (`peer://` to iroh when present, else to `InProcess`, which finds a `peer://` listener by key); a scheme without its transport is `UnknownScheme`. The osis handle's driver runs on it.
- `relay` feature: `iroh::TestRelay::spawn()`, a self-hosted `iroh-relay` on localhost (plain HTTP) for tier-2 tests; a listener registers there by listing its URL.
- Not yet: a WebSocket transport for browsers; backpressure in `InProcess`; iroh's own network-change detection (netwatch) instead of polling `route_ip`.

## Implementation (node peers)
- `/reach` (`sync/peers.rs`): `dialable_secret()` (random, local record `y/r`, shredded), `rotate_reach()` (new secret; new lan secret at the next publish), `publish_reach(dialable key, relays)` writes `/reach` on the node thing when changed (the listener's key; every transport's key is the Ed25519 key of its secret); the node card carries it under a synced label only where `publishes_reach(group)`: the group's stored policy (`set_reach_policy`, `y/n`; osis `sync_policy(g, GroupPolicy { publish_reach })`), else contacts-only: its reader actor is this node's own (an actor the node is a member of: its person, or itself in node-level tests), or each member is own, a contact (`set_contact`, `y/a`; osis `import_contact` marks the person) or a thing an own actor owns whose members pass the same test (a link's K holds the key actor L, so groups shared by link are excluded). A `/reach` already placed under a label stays (issues/p2p-followups.md). Co-readers are dialed only for labels whose group publishes `/reach`.
- Co-readers: node things other than this one with a held `/reach` that `may_read` a synced label's group, at most `max_peers_per_label` (8) per label and `max_peers` (64) in all, newest `/seen` first; dialed (`SyncConfig.peers`, default on) at a LAN candidate, else a proven LAN address, else `peer://` + their relays; `Conn.server` is the dialable key (presence, cursors), the session pins the address key (a LAN address presents its per-network key). Redial pause `peer_retry_ms` (60 s). Co-readers are dialed with an ephemeral transport key like servers (relays see no stable source key); the node proves itself inside the session with open proof 3 (`Try::Member`, last on peer connections: a signature under `"osis v1 member open"` by the dialable key over the served side's challenge and static key). Connections to co-readers no longer wanted are closed (`drop_unwanted_peers`); `Config.peers = false` and a driver without a `peer://` transport turn `SyncConfig.peers` off (`set_peers`). Co-readers and the `/reach` holders are cached until the engine's generation changes (`Core::generation`, bumped by every changing transaction) or a minute passes (edges expire).
- LAN binding (decided): the announcement carries an Ed25519 signature by the dialable key over BLAKE3(tag || key || be16 port) (domain `"osis v1 lan announce"`), XORed with a 64-byte keystream `kdf_xof("lan sig", lan secret, le64(window))` (osis-crypto `seal_lan_sig`/`open_lan_sig`), so checking it needs both the lan secret and the dialable key. Plain, the signature let every holder of the dialable key (relays the dialable listener registers at, co-readers) recognise the device's announcements across networks and windows. Chosen over a MAC under the lan secret (any co-reader of any label shared with the node knows that secret and could pose as the node on the LAN) and over a signature inside the first stream message (a protocol change, known only after connecting). Cost: dialable and LAN keys must be Ed25519 (every transport here). Vector: `vectors/lan/announce.vec` (provisional).
- LAN (`sync/peers.rs`): `lan_tag(secret, ms)`; `lan_tag_now()`; `lan_secret()` (a fresh transport secret per join); `lan_announcement(key, port)` (None until `/reach` holds the dialable secret's key); `lan_seen(&Announce, from ip)`: ignores non-local sources, looks the tag up in a per-window cache of the co-readers' tags (current and adjacent windows), opens and verifies the sealed signature under the matched lan secret, window and dialable key (the last verified announcement per peer is kept, a repeat is not verified again), then sets the address as the co-reader's candidate (`LanRoute`) at most once per `LAN_CHANGE_MS` (5 s); a repeat only refreshes it, and `handle` runs only when a dial can follow (no connection to the peer, no retry pause). Routes: the proven route first, else the candidate, else `peer://` + relays; a candidate never displaces a running connection; a connection through a LAN address that comes up proves it (`lan_up`); one that fails before coming up backs off that address (`lan_failed`), and the next route is dialed at once. A new candidate ends the peer's retry pause at most once per `peer_retry_ms` (`LanRoute.cut`): without it a node whose relay dial failed waited the full pause; unbounded, replays from many sources would loop dials.
- Member node (spec/sync.md §5): open proof 3 (`Proof::Member`, osis-label; `OpenKey::Member`, osis-proto) carries the dialable key and its signature; blind nodes refuse it; `ServerConnection` checks the signature and asks the store (`LabelStore::member_open(dialable, label)`), and records the key (`member()`). `PeerStore::member_open`: the key names exactly one node thing among held `/reach` (`reach_nodes`: a key two node things claim matches neither) whose `may_read` the label's group holds. Budgets are charged to the proven dialable key. On a membership or roster change (`members_changed`) served sessions whose proven node no longer reads an opened label are closed. Not yet: dialing a link's sharer for first contact (the link's `peers` field is decoded but unused).
- Serving (`sync/serve.rs`): `accept(local key, peer key)` starts a `ServerConnection` (static key = the listener's key, which open signatures bind) over `PeerStore`, a `LabelStore` over the sync state's entries and the engine's blobs: served labels are the synced ones at the deepest recorded step (plus at most 64 steps per label peers registered, in memory), cached until a `/label` or membership commit, a roster change or a peer step; an entry is live while this node holds its blob; log in memory (`Feed`, fed by `State::set_entry`/`remove_entry`, 4096 records per label, fresh log ID per start, so peers replay after a restart); accepted uploads and deposits go through `log_events` like downloads; entries this node dropped (server deletion, own delete, must-not-hold drop) are tombstoned (`y/x`, corrected wall ms) and refused with code 6 for `TOMBSTONE_LIFETIME`; a peer's delete or timed delete hides the entry from peers only (expiring with the same lifetime); registrations of new labels refused. Budget: bytes accepted from peers count against the uploading peer key (`peer_bytes`, 64 MiB) and all peers (`peer_total_bytes`, 1 GiB) while the entry is held, unopened and at no server or peer; over it uploads get code 12, deposits code 5; the reply budget reports what is left. At most `max_served` (64) sessions and `max_served_per_key` (4) per dialer transport key (more closed on accept) and, in the driver, as many connections (`link::serve_max`); a session silent for `serve_idle_ms` (120 s) is closed. Grown logs push to subscribed sessions after each `handle`. A session that opened nothing within `serve_open_ms` (30 s) is closed. Signals from a peer fire locally and go to other peer sessions. Costs: blob sizes are cached in memory (`blob_sizes`, pruned at ticks); charges keep running sums per peer key and in all, pruned at each tick and, at most once a second, after a budget refusal.
- Complete pass (spec/permissions.md §3): `complete_pass` also waits for each co-reader X the node received the label's entries from (dialed sessions, or served uploads with a member proof; `peer_received`) while X is a co-reader of that label (cached `peers()`), a connection to X is up and has the label started, and at most `peer_pass_wait_ms` (5 min) after the actor's last remote membership commit (`membership_at`); a membership change drops X from labels it no longer reads. So a removed co-reader, or one that stalls on purpose, cannot hold re-seals back.
- Driver (`sync/driver.rs`): dials always ephemerally; listeners come with `run_serving`, `Control::Reach { url, relays, reply }` (listen with the dialable secret at `url`, which for iroh lists the relays, and `publish_reach`) and the LAN loop; `Control::Lan(LanConfig { port, to, listen })` (feature `lan`): binds the announcement socket, checks `route_ip` every `LAN_CHECK` (5 s), on a change (or first) drops the old LAN listener, listens at `listen` with `lan_secret()` and announces at once, then every `LAN_ANNOUNCE` (30 s) to each of `to` (default the broadcast address at 47380); datagrams heard (bounded queue, a flood is dropped) go to `lan_seen`. The osis handle's driver runs on `Multi` (`Transport::InProcess`: mem; `Transport::Quic`: QUIC plus iroh with feature `iroh`), sends `Reach` (iroh: `peer_url(Config.relays)`; in process: `mem://<endpoint>-peer`) when `Config.peers` (default on) and `Lan(default)` with feature `lan`; without a `peer://` transport (`quic` without `iroh`) it turns peers off. Tier 2: node driver tests over iroh with the LAN loop on localhost (`--features iroh,lan`) and through a `TestRelay` (`--features relay`).
