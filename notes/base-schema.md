# osis-base and osis-schema: rules the signatures do not show
> Summary: What the two crates everything builds on promise beyond their signatures and doc comments: osis-base (Value ordering, decode bounds, unknown tags, one record-chain walk, what `format` excludes, error classes) and osis-schema (typed-read rules, link placement, retention types, codegen build cycle). Crate map and rules: notes/architecture.md; schema evolution: notes/versioning.md; the DSL and data model reasons: notes/data-model.md.

## osis-base
- `ValueMap`/`ValueSet` are sorted vectors (collect, not random-order insert, for a big one).
- **Order rule**: `Ord` is computed structurally and equals bytewise order of canonical encodings (proptest-checked), so maps and sets hold canonical order and uniqueness by construction. Exception: `Eq`/`Ord`/`Hash` compare a `Link` by content hash only (spec/data-model.md §4, §6: two writes of one large value are equal; canonical order is unchanged since the hash leads); the decoder rejects a set or map holding two links of one hash (`EqualLinks`). So `Ord` matches byte order only for values without such links, and `encode` sorts the encodings of a set or map that holds a link. Compare `Link` structs when exact identity matters.
- **Decode memory**: at most about 56 B per input byte for any input, with no picked limit: every item is at least a byte, so the heads' promised items may not exceed the input (`Decoder::promise`; only invalid input is refused). A path decoding a blob twice frees the first decode first (`InboxPayload::split`). `cbor::Reader` reads items one at a time for callers that cannot pay for a whole decode of hostile bytes.
- `Float`: bit pattern; `new` normalizes NaN, `from_bits` rejects other NaNs. `Unknown::new(tag, CanonicalBytes)` refuses tags this build knows (`is_known_tag`); the reserved STRUCT tag counts as unknown. An unknown CBOR tag is no error: it decodes to `Value::Unknown`, and parking happens where a typed read fails.
- `cbor::CanonicalBytes` is bytes proven canonical; `head`/`head_len` are for callers that splice pre-encoded items (osis-commit's commit blobs, osis-label's large strings). Decoding is recursive with a depth cap; claimed lengths are checked against remaining input before allocating.
- `record_chain` (`chain.rs`: `RecordLink`, `ChainStep`, `RecordChain`): every walk up creation records goes through it, so the stop rules and `MAX_CHAIN_DEPTH` live in one place.
- `format` (spec/wire.md §2, §13) holds only fixed format constants; `MAX_MESSAGE` (protocol v1) and `TOMBSTONE_LIFETIME_MS` (policy) are not format constants.
- Errors: every error type has an `ErrorClass` (`BadInput`, `Parked`, `Local`), through `Classified`.
- `testenv` is doc-hidden and tests only; it reads the environment. Every `OSIS_*` variable is in core/base/testenv-known.txt, policy.py-checked (notes/testing.md, Seed runners).

## osis-schema
- Types (spec/data-model.md §3): `Type` (mirrors §10 `type_expr`: scalars, `Text`, `List`/`Set`/`Map`, `Struct(StructType)`, `Enum(EnumType)`, `Counter`/`Max`/`Min`, `Named(name, args)` incl. `option`/`markdown`/`timestamp`/`duration`, `Param`), `Field`, `Case`.
- `Schema { revision, types, aspects: BTreeMap<AK, AspectDef>, doc }`; `AspectDef { ty, retention: Retention, expires, flags: BTreeSet<Flag>, succeeds, doc }`. A write's: `Retention { by: PurgeBy }` (`Default` = untyped: `author_or_admin`; `refusal`: `nobody` is for `created.0` and fixed retention alone). `History::{Keep { until, after }, PurgeOnReplace}` (ms; `History::FOREVER`) is a thing's setting's entry (`core_types::RetentionEntry`), never a write's; `AspectDefaults { retention: Retention, expires }` (`Schema::defaults(ak)`, what a write under the schema carries). Methods: `expand` (named types to a structure), `encoding(&Type) -> Option<Encoding>` (`None` = any), `default_of(&Field)` (declared, or `none` for option), `defaults(ak)`, `view(ak) -> SchemaView`, `validate`, `to_value`/`from_value`/`canonical_bytes`.
- Typed access (spec/versioning.md §5): `typed_read(schema, v, ty) -> Result<Value, PathError>` (projection: known fields, defaults filled; links pass for large values), `type_at`, `value_at`, `validate_write` (every declared field, nothing undeclared, depth). `Path(Vec<Step>)`, `Step::{Field, Case, Key, Index, Elem}`, `FieldId`, `CaseId`, `p![..]`; `PathError { path, kind: PathErrorKind }` (UnknownCase/UnknownTag parked, Schema local, the rest BadInput).
- Diff: `SchemaView` implements `osis_crdt::View` (project = typed read at the position, `None` = opaque). `large_positions(schema, v, ty) -> Vec<Large { path, map_key }>`: atomic positions above `CHUNK_THRESHOLD`; `link_positions`: positions holding links (chunk repair). Links stand only where the type takes one (`typed.rs` `takes_link`: blob/string, or atomic and not a small type); `misplaced_link` finds others for `Reader::get`/`get_path`, which read them as `Mismatch` before materializing. osis-commit's `check_types` refuses a core-aspect delta that does not fit the core type (`Fragment::fits`: encodings, values by `View::project`, declared enum cases), beside `check_entry_keys`.
- Keys: `trait RawKey { type T; ak, schema, decode, encode; ty, defaults, ephemeral, admin_only, signal, validate }`, implemented by `Ak` (untyped, `T = Value`) and `Aspect<T>` (const, `Aspect::new(ak, &STATIC_SCHEMA)`); `AspectKey: RawKey` marks the typed keys (`Aspect<T>` only). `Codec` (to/from `Value`; std impls incl. `Option` = option enum, `Vec<u8>` = blob, `[u8; N]` fixed blobs, ids, `Role`, `Ts`, `WallMs`), `codec_struct!`, `codec_enum!`, `named_type!` (`TryFrom<&Value>` by the schema's typed read, `From<&T> for Value`).
- Codegen: `generate(schema, file, src) -> Generated { code, warnings }`, `generate_file(path)` (reads and parses; for build.rs), bin `osis-schema-gen`. Output: `SCHEMA` (a `StaticSchema`), each struct/enum as a `codec_struct!`/`codec_enum!` invocation plus its field/case id module and `named_type!`, one `Aspect` constant per AK. No output is tracked: core/osis/build.rs generates schema/*.osis and the fixture core/schema/tests/example.osis into `OUT_DIR` and osis's `it` binary compiles and exercises them (`schemas`, `codegen::`); osis-schema cannot run its own codegen in its own build (a cycle).
