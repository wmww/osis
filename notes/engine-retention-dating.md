# Engine: when a body was replaced
> Summary: How the engine dates a body's replacement for keep-for-D, a function of the held set kept as the body's history row, from the aspect's held writes kept in rows (`osis_crdt::Held`, `retention/bounds.rs`, `leaving.rs`; spec/commits.md §5 Bodies and deaths, spec/crdt.md §4.8): which writes died and when, the rows and why they stay exact, why a covered drop moves no date, dating only where history is kept, the unread delete margin, costs.

## Principle
- Tess: a body under keep-for-D is not dropped until D after the earliest valid replacing write the node holds. The date is a function of the held bodies (`bounds::held_date`), never of arrival order or of how a part is paged. On a dated aspect it is kept as the body's history row (Rows below), which every reader reads (sync's `part_keeps`, `drop_from` before a compaction drop, `Engine::replaced_at`, listing, undo).
- Rejected: dates recorded by arrival (death records, replays, crediting, recomputes after flips: the class of bugs a function of the held set removes); dating at the superseder the state holds now (a register changing within D keeps its old bodies for good); deaths reported by the join (a stamp names many writes, so per-stamp reports dated snapshots early); dating by the superseder's header (a header names the aspect, not the writes); walking the later bodies per judgment, joining each against the part (a pass quadratic in the aspect's bodies and their sizes); keeping a covered-dropped body while it dates a held write (purge on replace drops it at once).

## Which writes died
- The part's winning writes (`Fragment::winners`, spec/crdt.md §4.8: by position, kind and stamp, never stamp alone, since one op stamps many writes) that a held valid write supersedes (`osis_crdt::Held` keeps when each held write died). Winners, not absence: a position write beaten as `cur` stays as `prev`, a deleted text creation stays in its record, a write beaten in another record of its map dot stays in its own. `winners` is checked against a pairwise from-scratch definition (osis-crdt `tests_winners`). The part's own superseded writes are not its winners. None dead: past a relative bound. The two agree because a copy of a register write's embedding carries the reset that write implies (spec/crdt.md §3.3 rule 7, a reader rule): a forged embedded char without it is refused, so the join prunes what the held writes say the copy supersedes (osis-crdt `an_embedding_copy_carries_its_register_writes_reset_*`). Debug builds check it against the state: the winners that do not win once the part joins a copy of the state at its positions (`bounds::deaths`, `whole_date`, at each row written; a dead write with no held superseder is `Error::Corrupt`).

## When (`osis_crdt::Held`; spec/crdt.md §4.8 When)
- A dead write dies at the earliest `ts` among held valid writes superseding it alone (osis-crdt `supersedes`, as held-model's `replaced_at`), read from any held valid body other than the part's own. Always the write's own stamp, never the holding body's: a valid snapshot's copy of a write whose delta is held invalid here (vouched) counts as the write itself. Rejected: dating it at its snapshot (a later cover's drop would redate it and bring a body out of history back: setting.rs `vouched_copy_dates_at_its_write_*`). A writer stamping early shortens what history keeps: storage reclaim only, never erasure (notes/deletion.md).
- A text element's creation dies only by a delete stamped after the latest held undelete of the element (`Held::item_death`), so dropping the first delete of delete, undelete, delete moves nothing.
- Every body dates at the latest death of its writes, deltas too: a body drops only after every dead write it alone holds has left history. A snapshot first leaves out the dead writes a later held valid snapshot holds as winners (`Cell::dated`: that one keeps their history; holding one as `prev` or deleted keeps none). Rejected: counting every carried write (it keeps every snapshot of an aspect whose long-lived writes keep dying within D, so held snapshots grow with the edit count, not the window: held-model `snapshot_replaced_at_last_death_no_later_snapshot_carries_*`). Holding more bodies dates no later; holding the same dates alike.
- The held writes (`osis_crdt::Held`, core/crdt/src/held.rs): every write the aspect's held valid bodies hold, winning there or not (`Fragment::held_writes`: a deleted text creation still supersedes position writes below it), by position, each with when it died and its holders (which bodies, whether it wins in each, each one's copy of what decides hiding, spec/crdt.md §5.5); per body, how many of the writes it dates died at each date, so its date is the latest without reading it; per body its own writes, so it leaves unread. Rows in an ordered store, a function of the bodies joined whatever the order (crdt `tests_winners`: `incremental_check`, `changes_check`: row for row what joining the held set from nothing gives; deaths against the pairwise definition, `first_superseding_check`). A write dies at the least stamp superseding it (stamps order by `ts` first), read at its own position and those above it.
- Late arrival: a body arriving after its earliest superseder dropped is dated later, by what is held, and may show where a node holding both would not: an arrival (Tess: what a node holds decides; held-model's any-order property allows exactly that).
- A snapshot dropped while a later one carried its dead writes is not brought back if that later one turns invalid before their D passes: those writes' history goes with it.

## Invariant: a valid covered drop moves nothing
A valid covered drop never changes whether any held body is in history, nor its listing, nor the keep bound of a held body in history, nor the replaced-at of a part in history (a part out of history may redate, staying out); only arrivals (bodies, settings, validity changes) and the clock do. A drop is valid only past the body's keep bound (`drop_from <= now`); `Engine::drop_body` skips the bound and is outside it. Why a drop of body B (out: `out(r_B) <= now`) moves no date (`out` keeps replaced order), per date read:
- a superseder's `ts`: a live write of B stays in the cover with its stamp; a write W only a dead write d of B dated redates to at most death(d) <= r_B (supersession is transitive), so W was out and stays out;
- a snapshot's dead writes a later snapshot S carries: S dropping adds back deaths <= r_S; a body in history has r > r_S;
- a text creation's latest undelete: an undelete's body drops only once the undelete is dead, by a delete no earlier than the creation's date, so the creation was out and only dates earlier;
- the state (`deaths`, `delta_live`): a cover carries every live write of B;
- headers, which outlive every drop (a fire's `ts`, the purge floor, a purged part's request `ts`, `kept_whenever_replaced`, undo's bound), the current setting (a cover of a setting body carries its newest write, so reads the same setting) and the clock (`at_clock`).

Each argument is per aspect. Forgetting a header is outside it: undo then counts the forgotten `ts` (notes/engine-retention-history.md Undo).

Tests: setting.rs `covered_drops_move_nothing_*` (random histories, covered drops in random order), `an_unkept_part_dates_no_other_part_*`, `vouched_copy_dates_at_its_write_*`, `a_covered_drop_redates_nothing_*`, `a_body_dies_at_its_latest_death_*`, `text_creation_dies_at_delete_after_undelete_*`.

## Dated only where history is kept (spec/commits.md §5 Keep bounds)
- A covered drop needs the body out of history on the node's clock, `out(r) <= now`, and `out(r) >= r`, so a replacement dated after the clock waits for the clock (`bounds::at_clock` adds `r` to the drop bound: `part_keep`, `part_keeps`, so `drop_from`, `settle_none`, memory drops).
- Per part: a part is dated only where the current setting keeps history for its own aspect (`bounded`, in `part_replaced_at`), by its own writes, kept by that aspect's entry; elsewhere it adds no bound, ahead of the clock or not. Rejected: dating per thing (an aspect waited on unrelated aspects) or a commit's parts at the latest death of all of them (a covered drop on an unkept aspect redated another part and brought a body out of history back: `an_unkept_part_dates_no_other_part_*`).
- Listing reads `body_history_keep` (the part's own history and the purge floor alone: purge on replace and no history list nothing, held-model AMBIGUITIES 68).
- A wall clock set back is not noticed, so sync's cached keeps judged before it stand.

## Unread delete margin
`MAX_DRIFT` applies to deletes at nodes keeping S unread only (spec/commits.md §5). A local drop changes only this node's reads, which follow its clock, so it happens at the keep bound; a right holder deletes at those nodes `MAX_DRIFT` later, once every clock agrees. `drop_part_for` records it as `Dropped::hosts_from` (the keep bound judged while the body is held, plus `MAX_DRIFT`; 0 when it had none). No timer or row of its own. The facade gives it as `BodyFacts::hosts_from` (a held part's keep bound plus `MAX_DRIFT`); osis-sync's read sends a covered-and-dropped body's Delete only once its clock reaches it (a memo clock read: a wake), the own log dropping it at once (`read::covered_delete_waits_max_drift_spec_commits_5`).

## Rows (`leaving::date_due`)
- Invariant: at every transaction's end each held valid part with values on a dated aspect has its row at `held_date` (none when nothing of it is dead), and no other part has one; inside a transaction a date on an aspect it changed is read from the held writes brought up to date (`leaving::dating_due`, two lookups: the aspects of the commits the commits index's journal holds, `Commits::changed_on`; and those it rebuilt, `ToDate`). Debug builds check each row a pass writes against the state (`leaving::check_row`, `bounds::whole_date`), and at the end of the engine's history every row of every dated aspect against dates from held writes built from nothing, which the kept rows must equal row for row (`leaving::rows_exact`, `bounds::index_exact`, notes/test-harnesses.md Debug checks). Built from nothing at once: every body placed (`Held::place`: rows, holders, tops, no death moved), then each write dated once by the rows (`Held::date_every`), so the check is an independent derivation of the deaths the joins moved, and costs the aspect's writes once, not each join's redating; crdt `incremental_check` holds joins one by one to it.
- Safe direction, per reader: a date later than the true one keeps a body longer (covered drops, memory drops, sync's must-hold, listing show it longer: storage only), an earlier one, or none where a write of it is dead (read as live: droppable under a cover), drops or stops promising a body still in history (data loss). Exactness gives both: never early, and alike at every node holding the same bodies, in any arrival order (spec/commits.md §4).
- What moves a date: the aspect's held valid bodies. `bounds::settle_index` follows the commits index's changes in order (`Commits::changed_from`: every change, one changed twice twice) and the parts whose leftover was written (`Core::bodies_rewritten`): a commit joined in another form than it is held now (`bounds::Form`, the tag it joined with), or rewritten, leaves and joins as it is held. A join reads its own body whole; a leave reads none (the body's own writes are rows). Each moves the deaths of the writes it supersedes or no longer does (`Held::moved_by`: the write itself; per kind at each position at or below, the greatest write stamped no later, since every lower one is superseded by it no later; every write of a sequence bucket there; a value removal's set elements; none stamped before the write's floor, the greatest reset or register write at or above its position stamped before it), found through each position's greatest stamp at or below it and its steps down by theirs, so a text written whole each commit redates the body before, not every earlier one (`scale::a_whole_write_redates_only_what_it_replaces_spec_commits_5`, `listing::a_kept_write_rederives_only_what_it_replaces_spec_sync_2`, `setting::a_body_leaving_redates_what_it_replaced_*`). Each death moved moves its holders' counts by date; the bodies whose counts moved are rowed again (`Core::dates_moved`). An aspect turned dated, or whose rows were forgotten, has every part rowed again (`Core::to_date`), and held writes built from every held body where it keeps none.
- A transaction's end dates twice (before the settings' walks and once everything held has settled, after purge-on-replace drops and carriers): the held writes say which bodies they hold in which form, so the later pass follows what changed since the earlier (`order::a_part_held_and_dropped_in_one_transaction_is_dated_out_*`). An aspect a setting kept dated with no cursor yet turned dated in this transaction before `settings_changed` gave it one: rowed whole (`order::a_register_turning_dated_beside_its_replacing_write_dates_its_bodies_*`).
- A superseder judged invalid later: its part turns invalid and leaves the held writes, and its victims' dates move later or go (`order::a_superseder_turning_invalid_*`).
- Rows are durable (`hr/`; the held writes in the aspect's table 3), so a restart dates nothing and reads no body; a rollback restores them with the store's savepoint. A memory transaction writes no durable aspect's held writes (it changes no durable body, and its rows are memory's).
- Where held writes are kept: on a dated aspect from its first death. While no held write supersedes another every date is none and nothing is kept, so a join that supersedes nothing writes nothing: a thing's role aspects at its creation and an aspect only added to cost no row (`thing_cost::what_a_thing_costs`). A join that supersedes says so (`Core::died`, from `retention::Killed`: the state's winners it killed, or its own it brought dead). That is every case: while none is superseded every held write wins in the state, since a write the state holds dead is superseded by a live one, which a held body or a cover carries, and supersession is transitive. Where the state was rebuilt or the aspect turned dated (`ToDate::pushed`, or kept with no cursor yet) the held bodies are read to see. The first death builds the rows from every held valid body at once (placed, then dated: as the check), in memory, and writes them once: the one read of an aspect's held bodies, in no later session (`scale::text_edits_are_flat`: the delete of a text written whole reads its body once, every later step none). Also kept on any aspect from its first held expiring part (`bounds::follow`: built at once, nothing dead or not, marked by a `FOLLOWED` row), for expiry in place (below). Dropped when its aspect is forgotten or its last valid body leaves, never on turning undated (an expiry-followed aspect relies on them). Debug builds check an aspect keeping none has no dead write (`leaving::rows_exact`: its rows against dates from the held bodies). Rejected: a bound under which a small aspect is read whole each pass (two picked numbers, and scale checks straddling it); rows from an aspect's first write (a thing's role aspects cost several times their bodies: 58 KB against 15 KB).
- Sequences: an element's own writes (creation, position, flags, element reset) are one row per bucket of `osis_crdt::BUCKET` counters of a source, run-length coded, so a text written in one commit costs a row per bucket (crdt `a_run_is_held_by_bucket_and_dated_by_element_spec_4_8`).
- Keys and pages: a position's rows are keyed by a 16-byte hash per step of its path (hashed once, where the step is made: `held::Step`), so they lie in path order (its own rows, then those of the positions below) and a key's length is bounded per step; a body's by its commit. The rows are packed into pages of 1 KB as stored, split past twice that (`osis_crdt::PagedRows`: a row of table 3 of the aspect's unit holding consecutive rows, shared key prefixes left out and repeated bytes written once (`row_pages::pack`), keyed within its level by a chunk of its first key: a page whose rows share one chunk, a subtree about six steps below its level's prefix, holds them in the level below, so pages split by key range at any depth and a page key stays within the table's key bound, `bounds::PAGE_KEY`; row_pages `deep_edit_is_flat`). The table is there from the first death and goes with the aspect. A join or leave holds the pages it changes and writes each once. So a write, what it supersedes and the tops above it share pages.
- Reads: the pages a transaction reads stay decoded (`osis_crdt::PageCache`, `Tx::held_pages`), each with the key of the stored page after it once known: a directory, so a row read in a page whose next is known reads no store row (row_pages `paged_rows_read_as_plain_rows`); a page found by a store seek learns its next with one more. Every page write keeps it exact; a rollback (`Tx::step`) or a table other than the one read (dropped, made since) empties it. Rejected: seeking the store per row read, or decoding a page per `Held` (a join's lookups are tens per write: most of the dating's cost); keeping it past the transaction (a store change outside it would need noticing).

## Costs
- A write on a kept aspect reads the rows of the positions it writes and of the writes it supersedes, in any session: no body but its own (`a_join_decodes_its_own_body_not_the_aspects`, `scale::a_body_joining_or_leaving_dates_only_what_it_moves_spec_commits_5`, `scale::text_edits_are_flat`, by hand: an insert, move or edit of an 80k / 800k-char text written in one commit reads no blob; the delete, its first death, reads the body once). A part's keep bound reads its row (`replaced_bound_judged_once_per_change_of_its_aspect_spec_commits_5`). A transaction waking n and 10n commits on a dated aspect reads each change of its commits once (`scale::a_dated_read_in_a_transaction_reads_no_change_log_spec_commits_5`).
- What the rows cost: about 90 B a write as stored (itself, its position's top, its step, its body's record of it: 480 B before a page's repeats go). A read grant's first death on `secrets.0` is 4,460 B at each side for 50 writes (`thing_cost::what_a_reader_costs`, notes/thing-cost.md). One more `secrets.0` entry on a roster of 20 / 200 holders writes 22.5 / 29.1 KB of store bytes (`scale::roster_removal_is_linear`); an edit of a kept text of 80k / 800k chars writes 3-6 held-writes pages (`scale::text_edits_are_flat`). Role-class aspects are dated as any: a replaced role body is kept `ROLE_KEEP` after replaced (spec/commits.md §5 Fixed retention), which no evidence rule decides.
- A join walks its body a fixed number of times for its writes (`retention::tests::reset_judged_walks_parts_once_*`, `Core::death_walks`), decoded whole, O(body) memory (notes/engine-paged.md Streamed readers, Left whole); judging every body of an aspect reads no body (`scale::judging_every_body_reads_each_once_spec_commits_5`).
- A kept, frequently edited aspect holds snapshots within its D window (3 at 8 and at 80 edits; `scale::kept_snapshots_stay_within_their_window_spec_commits_5`). A late delta older than n and 10n held commits costs flat (`scale::late_delta_deaths_are_flat_spec_crdt_4_8`).
- Tests: the independent truth is held-model's `replaced_at`: engine order.rs `kept_snapshot_replaced_at_latest_death_any_order_*`, `replaced_alike_in_any_order_*`, `text_redelete_*`, `snapshot_after_late_dated_death_not_credited_*`. The multi-node dating tests (deaths never early against a node keeping every body, skewed clocks) await sync tests (issues/sync-tests-owed.md).

## Expiry in place
An expired delta's writes leave the state in place (`apply::remove_in_place`, O(the delta)) when no held snapshot may carry them (`snapshot::carried_meets`) and no held write revives: the held writes are settled before the delta's body leaves them and again after, and `osis_crdt::Held::take_revived` (a held write's death going to none, counted in `Core::revivals`) says whether one only the gone writes superseded is back (spec/crdt.md §4.8 Revival). Else the aspect is rebuilt. Kept on dated aspects anyway; on others from the first expiring part, so "none kept" on an undated aspect means unknown (rebuild). Rejected: held writes on every aspect from its first death (the first death on a large one-body value reads and rows it whole: `scale::map_edit_is_flat`). Purges and late copies still rebuild.
