# Node (osis-engine, osis-node)
> Summary: Module layout and ownership of `osis-engine` and `osis-node`, the hook between them, the engine's public surface, what it keeps in the store and in memory, and the readings node-core fixed (pending, validity, bodies, receipts, counters). The plans that built it are done; the origin column says which part of the spec each module serves.

## Modules and ownership
Every module below is in osis-engine (`core/engine`) except `sync/`, which is osis-node (`core/node`); osis-node re-exports the engine's modules and root items at the same paths, so dependents name only `osis_node`. The engine knows nothing of sync, with one hook: `engine::SyncRecords` (`note_unsent`: the inbox delivery a flow's commit owes, written in that commit's transaction; `forget`: the `y/` records `retention::forget` drops), implemented by `sync::state::Records` and installed by `SyncEngine::new` (`Engine::set_sync_records`, kept across a reload; an engine never wrapped writes and drops no sync records, like `Core::changed`). The sync layer reaches into `Engine::core` (`Core` is `#[doc(hidden)] pub`) and `Engine::run`; narrowing that to accessors is open. The index tag (`engine::index`, `core/engine/build.rs`) hashes the engine's sources and its dependencies', not sync's.

## Public surface (engine)
- Lifecycle: `Engine::create(backend, root, Config, clock, rng)` (new identity, node thing with `/created` + `/node`, then `/keys`), `Engine::open(..)` (reload, re-examine pending), `tid`, `identity`, `now` (corrected clock), `set_clock_offset`, `subscribe() -> Receiver<Event>`.
- Writing: `Mutation` (`create(record)`, `set`/`replace`/`remove_aspect`/`op` through any `AspectKey`, `retention`, `expires`, `purge`, `frontier`, `act_as`, `commit_form`); `Engine::new_thing(&mut m, owner)`, `Engine::commit(m) -> Option<CommitId>`.
- Receiving: `ingest(bytes, blobs)` / `ingest_from(.., peer)` -> `Ingested::{Applied, Duplicate, Pending(reason), Parked}`; `reexamine`, `set_syncing(tid, on)`, `tick` (expiry, keep-at-most, drift), `pending()`.
- Relaying: `commit_ids`, `header`, `commit_bytes`, `blob`, `package`.
- API layer: `DiagnosticKind::Callback` (an app callback panicked), `app_record`/`set_app_record` (local `u/` records the `osis` crate keeps: person, home group), `Mutation::undo(target)` (undo acting as the mutation's actor).
- Reads: `get`, `get_at` (a paged state loads the pages on the path only), `get_full`, `read_large`, `read_large_max` (fails `TooLarge` past a bound), `get_typed`, `aspects`, `groups_of`, `roster`, `role_on`, `resolve`, `state`, `knows`, `all_aspects`.
- Retention: `snapshot(tid, ak)`, `covered(snapshot, body, tid, ak)`, `drop_body`, `body_keep`, `body_live` (a dot the body's deltas own survives in the state), `deaths`, `holds_body` (node-sync judges deletions and re-snapshots from the commit index; no queue).
- Undo: `undo(id)`, `undo_stack(actor, scope)`, `changes(scope)`.
- Membership inputs: `receipt(tid, ak)`, `frontier(scope, as_of)`, `epochs(actor)`, `register_schema`.
- Labeling: `group_actor`, `may_read`, `closure`, `labeled_groups`, `group_labels`, `bodies`, `label_bodies` (`label_bodies_meta` without plaintexts, cached per commit in `Core::bodies`; `body_plaintext`), `latest_by` (newest valid applied write on an aspect, optionally by an author), `partial_bodies`, `part_bodies`, `linked_blobs`, `wrap_secret`, `stranded_secret`, `deposit_seed`, `head_keys`, `tokens_of`, `certificates`, `revoke_certificates`, `aspect_commit`, `tree_missing` (a large value's node and chunk blobs not held) (notes/sync.md, Implementation (osis-node sync)).
- Move: `move_thing(t, owner) -> (copy, imports)`; `/moved` is an ordinary write by T's admins; reads resolve tids (except in `/tid`, `/created`, `/was`, `/moved`) through `/was` standing then `/moved`.
- Flows (each returns `Done { commits, deliveries }`; node-sync carries out the `Delivery` values: `Inbox` blob for an actor's inbox label (with the `Resend` that seals it again), `Direct` commits to a node, `First` placements before any other upload of the sync, `Certificate` copies under a home label, `Deposit` under a label the author does not write): `create_person(servers) -> (Person { person, card }, Done)`, `pair(person, node)` (grant, or re-seal of a member, plus the commits it needs, as one `Direct`), `paired(person, grant)`, `recover(card, lost, presync)`; `grant`/`grant_as(signer, ..)` (admin or invite grant; own secrets first; boxes), `demote`/`demote_as(signer, target, Demotion { member, new, presync })` (explicit demotion with frontier, or self-removal; the target's rotation in the same commit), `presync_scope(target, member, new)`, `PreSync::{Synced, Unsynced { proceed }, Backdated(t)}`; `accept_inbox(blob) -> (things, Done)`; `create_link(sharer, LinkSpec) -> (ShareLink, seed thing, Done)`, `redeem(link, grantee, single_use)`, `bear(link)`, `finalize_link(k, l)`, `revoke_joiner(k, l, joiner, presync)`; `create_label(group, servers)`, `replace_label(group, old)`, `issue_step(group, label, head, fresh)`, `label_of`; `roster_snapshot(thing, signer)`, `roster_snapshot_due`; `move_to(t, owner)`, `refresh_deposit_seed(actor)`; `hold_key_actor(seed) -> tid`, `drop_key_actor`.
- API hooks (osis second half): `report(diagnostic)` (deduped like the engine's; kinds `NotSynced`, `Unsynced`, `Stranded` added), `owner(tid)`, `next_chunk(tid, &mut TreeReader)` (one chunk of a large value per call: the API's `stream`); `Event::Signal { tid, kind, from, actor, ts, target, value }` for sent and received signals; `SyncEngine::{label_status, connected, set_servers, signal_as}`; the tokio driver runs over a `Host` (`run_host`: the osis handle keeps the engine behind its lock and hands actions over as `Control::Apply`; `run` owns it).
- Rotation: `ensure_rotated(actor) -> (Done, roles still uncovered)` (labeling calls it before wrapping, stamping or boxing under the actor; it must not encrypt under the roles returned), `rotate_eagerly`, `departures(actor)`, `give_own_secrets(thing)`, `reseal_due(actor, &dyn SyncState)` (node-sync implements `SyncState::complete_pass`), `reshare(actor, member)` (manual), `drop_lost_secrets()`, `lost_due()`, `drop_lost_due()`.

## Store records
Local records (`*_local`): `y/` sync state (notes/sync.md), `seed`, `hlc`, `c/`+ID commit records (head: received, origin, dropped parts (`engine::index::record_head`, version 1; version 2 heads of earlier builds carry part bytes, skipped); then the current blob), `t/`+tid creation records, `r/` receipts, `v/` value-less deltas, `p/` purge requests per aspect, `x/`+T timers, `s/` synced things, `o/` voided commits, `k/`+tid opened epochs, `l/`+tid the lost-access work list, `w/` `/secrets` writes waiting for removed keys, `n/` linked frontiers, `u/` API records, `a/` aspect index, `i/v` the persisted index's rules tag. Store index tables `node/*` (rebuildable, `engine::index`): per commit one byte per part (valid, the rotation role it needs, a grant's overreach), box keys, keyed boxes per member, epoch introductions, first box writes, own keys, snapshots per aspect with frontiers, writes carried by snapshots without their commit, perm's reading of each membership commit (`node/edges`), saved walks (`node/walks`). Store kinds: aspect units (state = snapshot grammar with its pages inline, or for a paged state `[6, skeleton, [[set ID, path, encoding]*]]` (an earlier build's `[1]` / `[2, skeleton]` / `[3, ...]` (unkeyed key index) / `[4, ...]` (no set values indexed, link keys hashed with their blob) / `[5, ...]` (no sequence placement) layout is read whole and laid out anew at its first load, `pages::legacy`; duplicate entries or elements an earlier build wrote after an index miss (a large key or value looked up raw) stay: ordinary lattice state, reads merge them): the state with its paged collections reduced to their reset and `W`; undo = what undoing each of the last local commits reads, `Fragment::footprint`), aspect table 0 (state pages: row key = set ID ‖ order-preserving bytes of the page's first dot, the first page the set ID alone; value `[first dot, next page's first dot, page]`), aspect table 1 (index of paged maps by key and paged sets by value: set ID ‖ keyed BLAKE3 of the key or value, links by content hash (`pages::ident`; key `Core::key_salt`, derived from the node seed) ‖ entry or element dot; a superset, rows of entries left keyless or elements left value-less by expiry or purge, and of those a keep-at-most drop takes out of the store, removed shredded, `pages::unindex`; rebuildable: written with the layout, the unit tag names its rules), aspect table 2 (placement of paged sequences, the whole placement order with hidden elements: layout in the comment above `Place` in `pages.rs`, unit tag 7; exact when present: a write it does not follow removes the top, and a read finding it missing (or a row damaged) lays it out anew; rebuildable like table 1), counters, death records (body ID = commit ID), pending/parked commits, blob ciphertexts (pages, chunks, header-list trees).
In memory (`Core`, rebuilt by `apply::load` at open and after forgetting; a failed transaction that changed nothing keeps the derived caches): states cache with page indexes (`engine::pages::PageIndex`: paged collections by path, which of their pages are loaded), the journaled indexes (`Core::ix`, an `Indexes` whose commit and rollback the `indexes!` macro derives from its field list; `engine::journal`: `JMap`, `JSet`, `JSetMap`, `JNested`; `Groups` and the held set journal themselves): commit metas with validity and dropped parts, per-aspect and per-thing commit indexes, node-form ranges, parts invalid here per aspect, perm's held set (`engine::held::Held`: by target, by member, by commit ID, owner -> owned, the things touched since perm last looked) + `Timelines`, pending reasons, value-less lists, secrets, `/was` (both ways), `/moved`, groups (`engine::groups`), `/members` entry keys, box keys and boxes per member, epoch introductions, held snapshots with frontiers, writes snapshots carry without their commit.

## Readings fixed here
- **Counters**: reserved in the same transaction that applies the signed commit; nothing signed leaves the node before it is durable, so no counter is reused and no gap is left by a crash.
- **HLC**: a writer exhausting `logical` within one ms moves to the next ms instead of waiting.
- **Pending "chain certificates missing"** (decided): the author's or an owner chain's `/created` is missing, or the author is not on the touched thing's owner chain and no path of held edge writes and owner links leads from it to a thing on that chain (`validity::reaches`: searched backward from the chain, from a thing to its owner and its named members (`Held::members_of`), as perm's `roles_to_any`, so the author's owned things never enter it; a new record of a named member or of an owner of held things bumps `Held::edges`, so record waits re-examine). Revoked authors keep their certificates, so their commits apply, judged invalid; re-grant re-merges.
- **Owner depth** (spec/permissions.md §1): `validity::too_deep` makes every delta but `/created` invalid on a thing whose chain is not known to reach its key actor within `MAX_OWNER_DEPTH` links (deeper, or a record on it not held: forgetting a record never makes a deep delta valid); per delta, from creation records alone, so nodes holding different parts agree; `examine` stops waiting for the chain there. The writer refuses such a commit. Upgrade: a store holding deeper things (none known) quietly loses their non-`/created` writes on rebuild, and perm gives them no ownership authority (`Owners::chain` returns `None`).
- **Prefix vs header** (spec/commits.md §4 last rule) is checked by node-sync where blobs are opened, for linked header lists once resolved (the pass); `ingest` takes plaintext.
- **Body** (decided) = one projection class of a commit: deltas sharing the reader actor (the thing if it has secrets of its own, else its owner), retention, expiry and delete-key indices. Its ID = BLAKE3(commit ID ‖ first aspect index of the class) keys the death records; first death = earliest, last = latest over its deltas; keep-at-most drops the whole class. Expiry and purge still drop single deltas (the commit is kept without them).
- **Validity**: re-judged, after a held-set change, only for the deltas on things whose timeline changed (`Core::stale_things`, `rejudge_all`; with the commits whose void, required-role or overreach inputs changed, `stale_commits`, and everything after a rebuild at open, `stale_all`; a rollback restores validity flags with the journal): perm's `Timelines::update_touched` re-partitions around the things whose held inputs changed (`Held::take_touched`; a commit naming only things of its component skips that and continues the walk, `Timelines::append`) and reports the components evaluated anew (all their things) and those whose walk only went on or that only gained new leaves (`/created` of things nothing names): for those, only the things authority flows to from the touched ones (`Held::reach`: owned things and targets of their edges, transitively). Writing a new thing re-judges that thing's deltas only; so does a grant to a member new to every walk (perm `Timelines::append` joins it: scale `one grant with 10^4 commits held` 12 -> 0.8 ms). The re-judge (`Judge`) takes each commit once under the first re-judged thing among its aspects, looks owner depth and the timeline up once per thing, and answers an author's deltas from its standing tenure on (perm `Timeline::valid_from`, `delta_valid`'s re-grant case, asked once per (thing, author, role)) without a per-delta query: one grant at 10^4 content commits 26 -> 12 ms (same session, load about 15; 11-13 ms at load 15-20). A voided commit is re-judged alone. Un-merge is by invalid delta, not by author: every body (the current state counting as one) is stripped of the writes owned by deltas invalid here (`Fragment::remove_dots` with `Owned::owns`: node-form counter range or commit ID) before it joins, on apply as well as on rebuild, so another writer's nested write under an invalid creation goes on every node alike. Validity follows the held set, not arrival order (was issues/late-member-backdated-revoke.md: a member offline through a revoke whose frontier missed a write applied the demotion before the item's `/created`, which perm took as a new leaf and kept the walk, so the item had no demotion recorded and the write stayed valid there; now a new leaf takes its owner's demotion records, notes/permissions.md Implementation; tests: `apply/tests_order.rs` every arrival order, perm `incremental` late leaves, timed_dead.rs `late_member_judges_backdated_revoke_alike_*`). **Un-merge cost**: where validity only fell (a re-judge with no part valid again and no carried write valid again on the aspect, a delta arriving invalid, a snapshot new here carrying invalid writes), `atomic::unmerge_fell` removes every invalid delta's writes from the state in place when none of them supersedes a write in it (`Fragment::dots_supersede`: a register, case, reset, `W`, flag or non-creation position write of theirs present in the state; the content of records they created goes whole either way, others' nested writes with it), loading and rewriting only the pages holding the fallen deltas' dots (their bodies, when held whole; a carried change loads the whole state); exact since the state is the join of the held bodies under the old judgments, so a write only they superseded is the only thing a rebuild could add. A part arriving invalid, on apply or late (`join_late`), first joins its body stripped (its sequence records stay as hidden anchors, as a flip leaves them), then un-merges in place (`atomic::arrived_invalid`; `unmerge_paged_matches_fresh_spec_crdt_4_6` compares with a fresh node); an invalid commit's aspect whose part is not held un-merges too (from the state, `fell` = `None`: others' writes under its creations go; was: skipped, so they stayed when they joined first, `late_invalid_part_unmerges_alike_spec_crdt_4_6`). Otherwise, and wherever something became valid again (re-merging needs the bodies: a register's earlier value, another's write nested under a revalidated creation, come back only from them), the aspect is rebuilt from every held body (O(aspect history)). A debug build checks every in-place un-merge against a rebuild; osis-crdt `unmerge_spec_4_6` checks it per delta on random histories. `scale.rs validity_flip_cost_spec_permissions_5_2` (release, 16 cores at load about 10, set of 10^4 one-element commits): a revoke flipping one add invalid 719 -> 40 ms (the rest is re-judging the component's 10^4 deltas; 28 ms with the re-judge above), an invalid add arriving 704 -> 4-6 ms.
- **Snapshots vouch for nothing** (spec/permissions.md §5.2): a compaction snapshot merges whoever wrote it; every write it carries whose own commit is not held is judged as its author's at the `ts` the snapshot carries for it: stamps at theirs, element creations at their creation's (a map entry's creation `Ci`, a set or bag element's value register, a sequence segment), commit-form writes as their commit per the held claim at its `ts` (`Core::authors`, keyed by thing and commit: C itself if held commit-form there, else the least held import, else the least held snapshot `Authors` entry by (`ts`, node); a snapshot entry naming another claim is not refused, one lacking an entry or dating a held commit's dot otherwise is bad input, `validity::note_authors`; a claim change marks the thing stale so `rejudge_all` re-judges its carried groups and rebuilds what rose or fell). Recorded per snapshot for every held snapshot in every path (`Core::carried`, `validity::carried_of`; kept sorted by (snapshot, source, author, `ts`), so arrival order does not show in the index): one group per (source, author, `ts`) with exact counters, each counter judged on its own (the frontier split found by a binary search, `carried_invalid`), exactly the invalid dots stripped (`Owned::Dots`). A snapshot arriving with invalid carried writes rebuilds its aspect once stored (`atomic::unmerge_carried`): the state may already hold them from another body (another writer's write nested in an entry repeats the entry's key and dot), and the snapshot's own join strips only itself (was issues/unmerge-nested-write-order.md: the write first kept the entry, the snapshot first dropped it; `entry_created_after_demotion_write_first_spec_perm_5_1`). Cost: O(aspect history) per such snapshot, rare (a compactor unaware of a demotion). A commit arriving drops the carried counters it owns (`uncarry`). Ownership is per aspect (`validity::owns_source`): a `Commit(C)` source belongs to C only where C has the aspect, else to any held import of the aspect listing C (`Core::imports`, by (thing, origin)), and an import arriving uncarries its origins' sources; was issues/carried-import-order.md (the moved thing's origin commit, held on the old thing, hid the copy's carried writes in a rebuild but not when it arrived after the snapshot; `carried_imports_alike_in_both_orders`, and `walks::open_equals_rebuild_random_histories_moves`, moves weighted up, which caught it about one seed in ten against one in 200). The order divergence only showed in the index and `retention::deaths::playing_copies` (an extra snapshot played): a carried import write is judged at the same point as the import itself. The old rule also left such writes unjudged at a node holding C but not the import, showing an invalid import's writes there (`carried_imports_judged_without_the_import_spec_perm_5_2`). Two imports of one origin on a thing (hostile, spec/permissions.md §7): `Core::authors` takes C itself if held there, else the least import by (`ts`, ID) in `imports`, re-derived on each arrival (was last-arrived; `double_import_alike_in_both_orders_spec_perm_7`, `_moves` with `Engine::reimport`). A snapshot whose `Authors` names a losing claim was refused only where the winner was already held (fixed in the double-import review, same test, peers 4 and 5; the dot `ts` refusal is still order-dependent: issues/snapshot-ts-refusal-order.md). An invalid import strips its origins' writes from every body, honest ones included: issues/invalid-import-strips-origin.md. Records with no `ts` (tombstones, bare anchors) carry nothing to judge. Tests: `hostile_snapshot_strips_only_its_dots_spec_perm_5_2`, `entry_created_after_demotion_spec_perm_5_2`, `commit_form_carried_writes_judged_spec_perm_5_2`, `snapshot_before_grant_then_valid_spec_perm_5_2`, `demoted_compactor_fresh_node_spec_perm_5_2`. Stores written before map entries kept their creation stamp hold entries without one until rebuilt from their bodies.
- **Membership content rules** are writer-side only: a received commit breaking them is applied and perm judges each edge write at its point.
- **`/created` gate** (spec/commits.md §4): only things whose delta the commit blob holds or that the node syncs make it pending on an unknown `/created` or chain; a thing neither held nor synced (another's private thing in a mixed commit) is skipped and its delta, if it comes later, joins late.
- **Late deltas** (`late_parts`, `join_late`): a late delta that waits (its `/created`, chain, pages) is kept pending under the commit's ID (listed by `pending()` though the commit applied) and joined once it can be; an invalid one joins and un-merges as on apply (Validity); late `/created` records and `/members`/`/tenures` deltas reach perm as on apply (the commit's edge writes re-added from every held part), then held deltas are re-judged. Late `/secrets` deltas are opened (observe_state) but do not establish.
- **Re-examination** (`apply/waits.rs`): `reexamine` (after every applied commit, at open, on `set_syncing`, ticks) examined every pending commit again (read, decode, signature): a first sync where commits wait for their thing's `/created` or a body's other part was O(commits × pending), 540 of 580 s at 10^4 (`scale.rs first_sync_cost`). Now a pending commit's examination is kept (`Core::waits`, a cache: dropped by a rollback that changed anything, a clock offset change, a reload) when it waits for a record (`UnknownCreated`, `MissingChain`) or deltas (`WaitDeltas`), its header is inline and it carries no `/secrets` part, within byte bounds (`MAX_WAIT_BYTES` 64 KiB each, `MAX_WAITS_BYTES` 16 MiB in all; a record wait keeps its order key and things only, since `MissingChain(author)` comes before the signature check and junk from a peer gets there; a delta wait, signed and certified, keeps its header). `waits::candidates` takes only what may have changed: commits without a kept examination, woken ones (a receipt or purge record of a missing delta's aspect), record waits whose record was added (`Held::take_records`), delta waits after any held-set change (perm judges purge rights) or once an expiry passed; every pending commit when the held edges changed (`Held::edges`: certificates; `validity::reaches` is capped) or the clock is below the latest one any wait was judged at (drift). `set_syncing` of a thing drops the waits of commits on it (examined in full: a thing whose delta is not held gates the commit only if synced). A delta wait is judged again from its missing deltas alone (`still_waits`); a record wait is examined. Candidates keep the (membership first, `ts`) order. Debug builds examine every commit left out in a rolled-back transaction and assert it still waits for the same reason (`Engine::check_unchanged`); that examination can emit diagnostics (sent at once, not rolled back), so rate-limit slots differ between debug and release. Tests: tests/it/waits.rs (syncing on, clock back, 1000 junk commits bounded), receive.rs `pending_not_reexamined_while_unchanged_spec_commits_4`. Remaining costs: any held-edge change re-examines every pending commit in full (O(membership commits × pending)); every new `/created` re-judges every delta wait through `still_waits` (O(creations × delta waits); refinement: on held changes re-judge only delta waits whose missing aspects have a purge record); commits pending for other reasons (drift, blobs, parked, `/secrets` parts, past the byte bounds) are examined at every `reexamine`, as before.
- **Atomic wait**: missing deltas that expired, or that a held purge request names with the right, count as held; a part whose bytes miss its delta hash is dropped alone (diagnostic) and the commit waits for, or applies without, it.
- **Rollback**: every in-memory index is journaled (each change records what it replaced; the deaths caches `first_bounded` and `lasts` too); a failed transaction undoes its own changes newest first and evicts the states it wrote (O(changes), was a copy of every index per changing transaction). The timelines follow the restored held set (`update_touched` around what the undo touched).
- **Open** (`apply::load`): with the persisted index of these rules (`engine::index`, tag `i/v`: a hash of every workspace crate's `src` from `build.rs`): the commit record heads and header bytes (their extent found by `osis_base::item_prefix`, nothing decoded; no part decoded, nothing re-judged), the `node/metas` rows (per commit a byte per part, validity, rotation role, overreach, then the header's `View`: ts, kind, form, author, actor, whether a list goes by link, per aspect tid, ak, range, relative keep bound, the chunk list's blobs, a membership commit's frontier; `node/parts`, the part bytes alone, is earlier builds' layout, read only by `old_judgments`), the parts table and the derived index tables, perm's inputs from `node/edges` (below), `/was`, `/moved` and `/group` states; `/secrets` and `/keys` states are not read (epochs and own keys persist). - **Snapshots**: frontiers cover node-form counters contiguously applied and valid on the aspect; retention takes the schema's default bounds from a registered schema (`Engine::register_schema`; local typed writes register theirs). Deaths (`retention::carriers`): a dying write's death is recorded in its own commit's body and in every held snapshot taken before the death whose frontier holds it (also where the write's own body was never held); dropped bodies get none. Commit-form writes in snapshots are not attributed (no frontier).
- **Deaths are order-independent** (spec/crdt.md §4.8: a write dies at the earliest `ts` among the applied commits superseding it; was issues/deaths-arrival-order.md, sim `keep_at_most` seed 445). A join reports deaths against the state, so taken alone they depend on arrival order (X < Y < Z with Z first kills X at Z; a write arriving after its earliest superseder was pruned dies at the later winner; a late snapshot's copy of a dead write dies again at the current winner); nodes then kept bounds apart (one deleted at the server what the other re-uploaded). Design (`retention/deaths.rs`): only bodies with a relative keep bound get death records. A valid writer delta with a `ts` above every other held commit of its aspect takes its join's deaths (`note_deaths`, after the commit's record is written: a write dead on arrival may drop its own body; a `ts` tie replays, since a stamp orders ties by dot, not ID; a killed write stamped at or after `first_bare` whose own commit does not play it replays whole: it played only with the state and may have dated a body that a replay now dates later, strays seed 21812). Any other delta on an aspect with a held bounded body, every validity flip and an invalid delta arriving (it un-merges others' writes under its creations) mark the aspect (`e/`; `Core::deaths_due` holds what to judge: `Due::Full`, or for a late writer delta `Late` plus `Killed` (carriers of the writes its join killed, its own dead-on-arrival ones too) and `Hint` (the latest death it dated); an open reads a mark as `Full`); the transaction ends with one replay per marked aspect, except while `Engine::defer_deaths` is on (node-sync steps; reads of deaths or bounds settle first). `check_at_most` skips bodies of a marked aspect and leaves a `Recheck`. **Window** (`window`, late writer deltas only): a write dies only at a greater stamp, so late L changes only bodies sorting at or before it whose last death is after its `ts` or whose live write its join killed, and L itself; every new death is at most u = max(their last deaths, the late `ts`, the hints). Except where a replay plays a write after its stamp (`strays_from`: a snapshot's or import's copy after the late delta whose own commit does not play it, never held or dropped without a residue, or a residue-less drop's live write, played with the state): it may have dated a body's death before the late `ts` that the late delta, playing first, now claims, so bodies whose last death is at or after the lowest such stamp are judged too (a dropped snapshot after it: its residue's stamps; an import after it, or a snapshot or import dropped without a residue from the first held bounded body: every body; was walks seed 7204, `late_delta_preempts_carried_superseder_*`, `late_delta_preempts_state_played_copy_*`; the replay dates such a body later than the earliest superseder, never earlier, like issues/deaths-dropped-superseder.md); a held bounded snapshot between the lowest stray stamp and the last late `ts` may gain a death (a write the stray dated before it, the late delta after it): whole replay; a stray at or below a hint may be the winner the late join met, which a replay meets later: the window plays every body after its start. Residue-less drops at or after the first held bounded body exist only after an older bounded body arrives (a drop keeps a residue, empty ones too, when a held bounded body sorts at or before it), so their lowest stamp is cached (`Core::first_bare`, journaled; narrowed when the first bounded body moves back, dropped when it moves past it; was a scan of every commit from the first bounded body per window, +5-7 ms for a recent late delta at 10^4; now the first window of an aspect per session pays it once, about 5 ms at 10^4, and the recent late delta is 1.5-1.7 ms against 2.6-3.3 before the branch, release, load 10-15). Differential: retention.rs `late_deltas_windowed_alike_random_*` (seeds 1018, 2392 found the gain and hint cases, on main too). The bodies dying after the late `ts` come from the last-death rows (`node/last deaths`, a rebuildable store index: aspect key + last death + `ts` + ID, written with the death records in `note_deaths`, `set_deaths` and drops, so a failed transaction undoes them with the store; `index::write_all` rebuilds them from the records, and a window meeting a row that does not parse rebuilds that aspect's rows; was `Core::lasts`, loaded from every held bounded body's record once per aspect per session and kept in memory); under 64 bodies before the last late delta their records are read instead (the rows also hold every body after it). It replays the bodies (held, or residues) from the first such body through u, then the snapshots and imports after u (`Core::copies`, per aspect: a copy's own commit may be one never held, with a stamp in the window), playing their copies as `replay_all` does, except a snapshot that can date none of the judged writes (`playing_copies`, from in-memory indexes, no body read): its copies their own commit plays are removed anyway, and one stamped before the window's start supersedes no judged write (a write dies only at a greater stamp), so it is skipped unless it may carry a copy stamped at or after the start of a commit never held (`Core::carried`, per snapshot and `ts`), of a node-form commit of the aspect dropped without a residue between the start and it, or of a commit-form source of the thing at or after the start (`Core::authors`) other than the thing's own commit on another aspect (imports always play; a debug build reads every skipped snapshot and checks it holds no such write), then the state if a dropped body there has no residue, and rewrites only the judged bodies' records. It falls back to the whole replay when a snapshot or import is among the judged bodies, or sorts at or after the window's start with a last death after the first late `ts`: such a one carries older writes, and a late delta sorting before it may date one earlier than it, so it loses that death (a snapshot's record spans every write it carries, from before any window: judging it needs all of them). One with no death after that `ts` has none to lose; one at or before it the late delta kills a write of is `Killed`. A debug build checks every window against the whole replay (`check_window`, in `settle_due`, also a window that judged nothing). **Whole replay** (`replay_all`): held bodies and residues in `(ts, ID)` order (invalid writes removed; from a snapshot or import the copies of writes whose own commit is held or has a residue, so copies play at their own commit (`Fragment::remove_writes`: exactly those writes; others' writes nested in an entry or list element such a commit created stay: un-merge's `remove_dots` dropped the content with the creation, so a carried put into a held commit's entry superseded nothing in a window, order seed 7233, and a whole replay found it only through the state); a content delta is never stripped: main stripped its nested writes inside another held commit's map entry, losing their supersession), then the state (live writes of residue-less dropped bodies); a snapshot's copy of a write already dead in the replay is not dated again (two snapshots carrying a dropped commit's write pushed the first one's last death to a later winner; only a write the snapshot holds stamped so, `Fragment::holds_stamp`: a record keyed by the dot, such as an entry the snapshot removed, let a write sharing a dead write's stamp go undated, order seed 7855, `copy_kills_write_sharing_a_dead_stamp_*`). **Residues** (`keep_residue`, local `d/` + aspect key + `ts` + ID): a dropping body's writes kept value-less (`Fragment::strip`, no app data, spec/crdt.md §4.7; a snapshot's or import's without the copies a replay plays at their own commit, else each held the aspect's state, kept even when empty; about 110 bytes for a one-element add) while a held bounded body of the aspect sorts at or before it (only those can it date); residues no held bounded body sorts at or before go when the first held bounded body drops (`Core::first_bounded`, cached per aspect, kept by `index_commit` and drops, a journaled `JMap`): O(1) amortized per drop. Local records, not rebuildable from commit records (the body is gone); a store from an earlier build has none for what it dropped (state stands in for live writes, deaths may be late as before); forget drops them with the aspect. Residue (issues/deaths-dropped-superseder.md): a body arriving older than every held bounded body after a residue went may die later than at a node that held it before the drop. Rejected: per-write death records (a write is not identified by its stamp: a delta's commit-level writes share one, so the max over writes of the min over superseders needs path identities or a replay), lowering only first deaths (`last` feeds keep at least), cached decoded bodies (memory O(history)). Cost (scale.rs `late_delta_deaths_cost_spec_crdt_4_8`, release, 16 cores; a set of N one-element commits, late adds older than all, then one 5 commits late): N = 10^4 keep-at-least: a late delta 380 ms (whole replay, load 6-10) -> 6 ms (load 30-50; unbounded: 1.5 ms), 5 in one batch 380 -> 15 ms (load 6-10; 35 ms at 30-50), the recent one 2 ms at load 6-10 (7 ms at 30-50; the 110 ms first load of the old in-memory `Lasts` is gone); compacted after the N commits: was 170-240 ms each, 210-290 ms for 5 in a batch (the window played the snapshot's 10^4 copies; load 30-58), now 6-8 ms each, 12 ms for 5 (load 9-22; the snapshot skipped, the window's in-memory scan of the 10^4 bodies after the late delta remains); N = 3000: 115-165 -> 4 ms. - **Keep at most and live writes** (spec/commits.md §5, was issues/at-most-zero-snapshots.md and keep-at-most-partial-bodies.md): dropping a body that still had a live write at its bound (at most 0: at the kill) forced a whole-aspect carrier snapshot on every edit erasing part of an older commit or snapshot (O(state) per change, against spec/requirements.md Scale). Now one rule for every body: under a relative keep at most D (0 included) the bound is first death plus D, plus `AT_MOST_GRACE` (1 h, a format constant) while the body has a live write; the next compaction usually drops it first (covered, `drop_covered`); no timed delete for it (`sync/pass.rs` `keep_at_most_due`: deaths and bound first, then `body_live`). A deleted text element's creation stays in the state as its anchor, so a text body fully erased is live too and keeps to the grace (coordinator decision: one rule; at most one carrier snapshot per grace per aspect instead of an O(state) snapshot per erase). Cost: liveness is `Fragment::holds_owned` with `Owned::owns_range` (stops at the first hit, never expands range records), cached per body and forgotten per aspect when its state changes (`Core::forget_live` drops every body with a delta on the changed aspect: a body's liveness spans its class, whichever aspect was asked; keying by the asked aspect alone left stale answers, test `body_live_spans_its_class_spec_commits_5`). A reader drops a live body at its bound with no carrier (spec/sync.md §5: the bound wins). Bounds follow liveness: a validity flip re-runs `check_at_most` for the aspect (`recheck_at_most`), and a due keep-at-most timer re-judges instead of dropping (a body that turned live keeps to its grace bound); a timed delete already sent cannot be withdrawn: a window, not a loss (timed_dead.rs `revived_body_uploaded_again_after_timed_delete_spec_commits_5`): the server deletes the revived body at the plain bound, and a right holder re-uploads it (fresh encryption, must-hold: live and uncovered) at its next resync (`resync_ms`, 60 s, while online; the server's sweep pushes nothing that marks the label dirty) or next sync; the flip replays the aspect's deaths (below), so a write revived because its only superseder turned invalid has no death and its body no keep-at-most bound, as at a node that never held that superseder valid. Readers see no gap: they hold the body or the state; a member offline throughout judges the revoked writer's write alike when it returns (same test, `late_member_judges_backdated_revoke_alike_*`). Before a due timer drops a live body, the sync engine writes its carrier (`Engine::due_live_drops`, `snapshot_first`), so a server-less label never lacks a copy of the live write. A body with no live write keeps the plain bound and needs no carrier; when the last live write of a partly erased body dies, its plain bound has usually passed and it drops in that transaction. Liveness is judged on the current state (`retention::live`, the tx form of `Engine::body_live`), not frozen at first death (a flag would add a state and depend on arrival order): the state is the join of the applied valid, non-undone deltas, so nodes that applied the same commits agree (dropped bodies leave their live writes in the state). Nodes holding different commits can disagree for a while (one already has the last kill and deletes at the server; the other judges the body live and must-hold); the killing commit goes up before the delete in the same pass, so the other node applies it on its next read. Privacy (spec/commits.md §5 says so): under keep at most, erased data (a deleted word, a whole erased text) persists in its body up to its bound (first death plus D plus `AT_MOST_GRACE`), or to the next compaction if sooner, at the writer and every reader holding it (and in the erasing edit's undo buffer, cleared when a body of the aspect drops), and at a server until a right holder next syncs after the drop; a writer going offline right after an erasing edit leaves the body at the server until a right holder syncs past the bound. Main dropped a fully erased body at the kill; now it waits for the grace (test `text_fully_erased_kept_to_grace_bound_spec_commits_5`). The read state loses it at the kill, and the drop shreds like any. `body_live` of a snapshot: held, a carried write is in the state (by dot, ts-less writes such as tombstones included); dropped, a state write stamped at or before the snapshot's `ts` (ts-less ones not counted: it dropped with none live, or carried or covered). A drop removes the snapshot from `Core::snapshots` and `Core::carried` (`apply::forget_snapshot`; spec/commits.md §5: index entries derived from a dropped body go; a rebuild cannot read them; was issues/rebuild-drops-snapshot-index.md, order seed 1291: the frontier stayed incrementally, gone after a rebuild; test order.rs `dropped_snapshot_rebuilds_alike_*`). Tests: deletion.rs `erasing_edit_then_compaction_*`, `live_body_goes_at_grace_bound_*`, `text_partly_erased_kept_to_compaction_*`, shred.rs `at_most_zero_live_body_dropped_at_bound_*`, local_serve.rs `keep_at_most_body_carried_on_local_label_*`.

- **`/secrets` ingestion** (`atomic::observe_touched`, `Core::ingest_keyed`): a join reads only the box and history-box entries its delta touched (`secrets::touched_keys`; a reset of the value, a field or a map reads the whole state), then the history box of every epoch with a secret held, repeatedly (what `open_histories` reaches over the whole state). - **`/groups`** (`engine::groups`): a `/group` change unlists and relists the changed group and the groups above it (O(their reach)); open sets every definition, then derives once.
- **Established epochs** (`apply/keys.rs`, spec/crypto.md §4): an applied valid commit's `/secrets` write calls `SecretsWrite::applied` with its `/keys` write (whole keysets: flows replace the field) and the keysets held before; a removal is a keyless reset, so box keys come from an index of held keyed entries, and a write whose removed keys are unknown waits (persisted under `w/`) until they arrive, so a rotation received before the one it supersedes is not established. A held `/secrets` compaction snapshot calls `snapshot_keyed`; a delta found invalid `unset_applied` + `establish`, valid again re-applies (keysets before taken as the current `/keys`). Epochs persist `established`, `applied`, `snapshot` (`k/`), never re-inferred. `/secrets` compaction is gated on `may_compact_secrets`. `Engine::epochs(actor)` exposes the view.
- **`/secrets` and `/keys`** deltas need the highest role they rotate or box (at least write): admin for an admin box, history key or keyset, and for any delta that is not a plain struct (`Fragment::is_plain_struct`: a register write or root reset replaces every field); such a `/secrets` delta gets no invite-grant exemption.
- **Edge writes from `/members` deltas** (spec/permissions.md §2: an edge change is remove + put): an entry the delta creates (it owns the entry's dot) sets the edge it reads; a reset of a known entry dot removes it (keys learned from the creating deltas, `member_keys`); a delta writing inside an entry it did not create is bad input (`check_members_parts`, in `examine`, so the writer refuses it too). A reset whose key is unknown (its creation not held) names no member: the commit's other writes go to perm and the commit stays in `unresolved`, derived again when keys arrive and once after an open has read every commit (it reads them in `ts` order). `flows::put_edge` always writes remove + put, so a grant over an entry the walk dropped (still live in the state) resets it (`regrant_over_dropped_entry_spec_perm_2`). Was: nested field writes overlaid the entry's creation, so two changes composed wrongly (a role raise lost an `until`) and a grant over a dropped entry wrote into it, leaving the grantee unresolved for good.
- **Purge**: judged by perm `may_purge` at the request's point; kept per aspect so deltas arriving later are purged on arrival.
- **Undo buffer**: what undoing each of the last 16 local commits per aspect reads (`Fragment::footprint`: struct fields written, the elements a map, set or bag delta writes and the live entries of keys it edits into, along the edit's paths; of a list or text the records holding the delta's dots); cleared (shredded) whenever a body of the aspect drops. Undo reads the current state in place. Undoing another node's commit (admin view) takes the pre-state as the join of the held valid bodies ordered before it (O(aspect history)).
- **Writer-side membership rules**: at most one `/members` edge per membership commit (excepted: a redemption's grant plus self-removal; an explicit removal of several others' edges on one target with a frontier, `revoke_joiner`); a frontier only on a commit that lowers an edge; a removal or demotion of another member on a thing with a `/keys` keyset carries `/secrets` and `/keys` deltas of it. A local commit breaking them, or with any delta invalid at this node, fails before it leaves.
- **Import**: one import commit per origin commit (header kind 4 has one delta per aspect, each carrying its origin delta's retention and schema table entry, `Resolved::schema_ref`). Each write comes from one origin (`moves::carriers`, `imported`): the newest held, valid, not dropped compaction snapshot S of its aspect where S covers it (node form: S's frontier holds its counter; commit form: S carries writes of its commit) and carries it (stamps and element identities, `Fragment::writes`; dot `(Commit(S), rank)`, rank from 1 by (source, counter) over all S carries), else its own commit C (`(Commit(C), ctr)`); a write S carries beyond its frontier comes from C where C's part is held, valid and kept (`from_own`), else from S. References (anchors, reset stamps) map alike. A frontier is not trusted alone: of a commit S claims whole, the writes the current state holds that S does not carry are imported from C (test `inflated_frontier_keeps_write_in_move_spec_perm_7`). Expiring, value-less, invalid and dropped writes are not imported (stripped from a snapshot origin). Of each sequence every origin gives only the elements the current state shows and those they anchor at (`Fragment::shown`/`keep_shown`, notes/crdt.md); an import still over `MAX_DELTA_BARE` fails the move (accepted, notes/permissions.md; compaction is the remedy). An invalid import un-merges its origins' re-sourced writes. Only the copy's creator imports into it: `move_thing` writes the copy's creation record with `creator` (this node, `Engine::new_copy`), and `apply::examine` refuses an import whose author the record does not name (bad input; was issues/invalid-import-strips-origin.md: any reader of a copy could strip its imported writes with one import, or take the carried-writes claim); `Engine::reimport` (tests) turns the writer-side rules off so a foreign import can be built. `rebuild` joins the current state with the bodies, so an un-merge is always a dot predicate (`invalid_of`): a body once joined cannot be dropped by rebuilding. Carried writes judged per an import claim use that import's ID in the point (`carried_invalid`), so a demotion's frontier listing the import covers them as it covers the import.

- **Lost access** (`retention/forget.rs`, spec/permissions.md §3): an actor is lost when the node holds a secret of it (reading-only included; epochs observed without one are not access), neither the node nor a held key actor has a role on it now (timeline, any path, `until` honoured), and no held unapplied membership commit (pending, readable parked, late parts) boxes secrets to the node, a held key actor or an actor the node reads now on an actor whose role reaches it (itself, its owner chain, or one with a role on it): a grant not yet applied, whose secrets may already be read (spec/crypto.md §4), is never a loss. **Trigger** (`rotation::drop_lost_due`): applying a received membership commit (or its late `/members` parts) adds its `/members`/`/tenures` targets to the `l/` work list in the apply's transaction, and so does dropping a pending membership commit as bad input (its aspects' things: the reading-only secrets its boxes gave go unless something else reads them); local commits never do (a self-removal drops once uploaded, below). node-sync runs the trigger at the end of every `handle` step (after the step's applies and re-examination) until the list is empty: one transaction takes the list and drops the held actors a role on a listed thing reaches that are lost. Idempotent; a restart in between finds the list (`load`). `drop_lost_secrets` (and node-sync's `SyncEngine::drop_lost`, which self-removals call once uploaded) evaluates every held actor and empties the list. Either drops the lost actors' `k/` and, in the same transaction, forgets every thing whose secret actor is one of them and that neither the node nor a held key actor may read now (`Core::may_read`). Of such a thing only `/created` and the membership-class aspects other than `/secrets` stay (certificate material perm judges others' writes by: edges, ledger, public keysets, `/label`, moves). Shredded: aspect units (`drop_aspect`: state, undo, pre-reset snapshots, tables, deaths), its parts in `c/` records (a commit left with no part is deleted, so a re-grant fetches it again; others keep their readable parts, not marked dropped, so the forgotten ones join late if they return), pending parts, `a/` `r/` `v/` `p/` `s/`, timers and `w/` waits of forgotten parts, sync records (`sync::state::forget_records`: everything about the forgotten groups' labels, blob records holding forgotten parts, certificates and carriers of deleted commits, hints) and the ciphertexts nothing kept names; `y/f` lists the things whose opened inbox blobs node-sync then deletes (`forget_inbox`, also at open: a grant's inbox blob opens under the node's own keys). Event `Changed { cause: LostAccess }`. Not triggered: an edge expiring by `until` with no membership commit applied (the next trigger touching it, or an explicit call, drops it).
- **Self-removal**: flows return `Done::drop_lost` instead of dropping in the commit's transaction; `carry_out` sets `SyncEngine::drop_when_idle` and drops the lost secrets once every label is idle (a crash before that leaves them until the next trigger or explicit call).
- **Own self-removals in the cover check** (`rotation::departures_placing`, node-sync's `placing` under `uncovered`/`uncovered_now`, spec/crypto.md §4): a departure whose newest edge write (on the innermost actor of its way) is a self-removal made here (signed by the node or a held key actor: a single-use redemption's removal of L from K) holds back nothing, after any rotation the node may make, until that commit is `placed` (sync state: entries, presence, outbox); derived from stored state, so a restart keeps it. Bounded by placement, not by rotation: the departed party's other holders (L's link holders, other members of an actor X the node removed from G while staying in G itself) would otherwise read all the node's later writes under the old epoch. A self-removal on things with no label here counts as placed at once (its copies elsewhere are then held back: rare).
- **Move**: a labeled thing's copy gets secrets of its own and a label at the thing's servers before the re-grants (the inbox payloads name it; members sync and write the copy whatever of the new owner they read). An unlabeled thing's copy gets none (the app places it in a group).
- **Edge changes**: the writer-side rules take a remove + put of one edge as its new edge (a raise carries no rotation).
- **Late parts** (`join_late`): edge writes re-enter perm from every held part, and `/secrets` parts establish epochs with the commit's `/keys` (held parts) like a whole commit's.
- **Flows readings**: departures are recomputed from the timeline (applied lowering edge writes, an expired edge's removal counting as its role's departure, edges past `until`) and from state (a box at a current epoch whose holder holds less than that role now), members re-granted since dropped, recursively inside member and owner actors with secrets of their own; an epoch first boxed by a commit of a departed party (or a node acting through it) does not cover its departure. - **Erasure root cause**: lost access dropped only `k/`; plaintext states, `c/` records, wraps and blob keys of unreadable things stayed under live keys. Fixed by the forgetting above.
- **Trigger root cause**: forgetting ran only on an explicit call or after a self-removal, since a naive "role none now" test also counts secrets read from a not-yet-applied grant as lost. Fixed by the work list plus the pending-grant guard above; wiring it exposed the stale-push cursor bug (fixed in node-sync).
- **Flows root causes fixed**: single-use link race winner stranded: the sharer's second rotation boxed the winner, who held no box at the loser's epoch that commit is wrapped under, so the box was unreachable and the re-seal trigger saw it boxed; a rotation now also goes by inbox to every member it boxes that held no box at a current read epoch (`rotation::unreached`). A re-seal of such a member wrote its box as a nested write into the rotation's entry, which the member never held; `put_secrets` writes boxes as remove + put like history boxes.
- Move into an owner without secrets of its own: the copy's own-secrets rotation boxed nobody, so `/secrets` had no boxes field and its typed read failed (`MissingField(0)`): the re-grant carried no history boxes and the member never opened the rotation. `engine::secrets::secrets_value` (used by `flows::secrets_in` and atomic apply's observe) reads a never-written map field as empty; `apply/keys.rs` snapshot and compaction gates use it too.
- Late parts (`join_late`): `note_required` judges a late `/secrets` part with the commit's held parts, and the late parts' validity is recomputed before they join (other aspects' flips go through the re-judge with `invalidated`/`revalidated`) (an overreaching invite grant whose `/members` part came first was joined with the validity computed while its `/secrets` part was absent).
- Rotation loop (a sharer's second device after a link joiner's removal): the device got a redemption's `/members` part by a certificate copy and its `/secrets` part later; `join_late` judged the late part alone (`note_required`: no grantee, so `grant_overreach`), the redemption's `/secrets` went invalid and `keys::invalidated` unset `applied` of every epoch its history boxes named, i.e. K's epoch another commit introduced; K's removal rotation never established, and `rotation_helps` kept predicting that a fresh rotation of the target (its box naming K's newest `/keys` keyset) would cover the departures inside K, which the covers rule judges by K's newest held epoch. Fixed: `note_required` judges every held part and clears the mark when the whole commit fits; `invalidated` unsets only the rotations the commit made (its `/keys` sets the keyset); `rotation_helps` requires the epoch the fresh box names to be M's newest held one.
- No rotation after a departure inside an actor this node holds no secret of: epochs observed for it (boxes, an old keyset) put it in `held_actors` as held, judged by those stale epochs, so its newer `/keys` (from a revoke copy) never covered the departure. `held_actors` now judges an actor with own keys and no held secret by its `/keys` keysets and the `/secrets` boxes held of it; on top of those, a member that left it counts as boxed at a keyset epoch unless the keyset was set by the departure's own commit (`Core::epoch_intro` records the introducing commit) or the held `/secrets` delta of the commit that set it boxes no such member (`presumed_boxes`, spec/crypto.md §4; times are the authors' word: a backdated self-removal or a rotation made unaware of a departure decided nothing): a self-removal or an expiry inside such an actor otherwise counted as covered while the leaver still read through its old epoch.
- Rotation loop (chat, second link): a writer of C holding no K1 secret judged a departure inside K1 never covered and rotated C without end; `held_actors` now gives an unheld actor its newest `/keys` keysets with no boxes, and `ensure_rotated` skips roles a fresh rotation would not cover (`rotation_helps`). Residue: such a node trusts K1's newest keyset, so after a self-removal from K1 not yet rotated it encrypts under C's epoch the leaver can reach through K1 (the same as before K1's admins rotate). `place_certificate_in` still calls `ensure_rotated` (labeling).

- **Large values** (`engine/large.rs`): `chunk_ops` chunks the large positions of `set`/`replace`/`add` values and list `insert` and `edit` items (a text's are characters; an `edit` item the list lends keeps its link, `base` items become hash-only links that match the list's read; the list lends the links its read holds at the edit's window, `osis_crdt::edit_window`, when it has base's length and reads there as base by content hash, `large::window_links`, else every link it holds; at the window base's and new's common items outside it take base's form, so the crdt trims them alike; `large::list_edits` hashes the items once per commit for this) before the ops resolve, one `BlobWriter` per position, framed like the delta. A `set`/`replace` position whose state holds a link now builds the new tree `BlobWriter::reusing` a `Reuse::index` of that tree (up to `MAX_REUSE`, 16 GiB): equal chunks keep blob and key unless `Framing::keeps` says re-encrypt, a chunk not held is written afresh, reused blobs are not in the chunk list. Edit cost (FORMAT constants, about 100-250 KB chunks): blobs written and uploaded = the changed chunks plus the root node (`write.rs` `large_edit_reuses_chunks_spec_sync_1`, within 1.03-1.1x of the new-chunk bytes; was the whole value). Local CPU stays O(value): the new value is hashed, every reused chunk read and compared, the old tree's nodes indexed.
- **Dropped chunks** (`sync/pass.rs` `dropped_chunks`): a chunk of dropped deltas is deleted (at servers, then locally) only if no live tree of the listing commit's things links it (`Engine::live_trees(tid)` → `LiveTrees { blobs, missing }`: blob IDs under the links in the things' current states, walking held node blobs; `missing` node blobs keep every candidate of the thing and go to `SyncEngine::tree_wants`, which the pass fetches from its server, so a lazy node judges once they arrive; cached in `Core::live_trees`, cleared by `touch`/`rollback`, incomplete entries also by `put_blobs`). The pass also uploads, with each body a writer places, the held blobs its own deltas link (`body_blobs` → `Engine::body_links`: the trees of its values and its pages, through held node and page blobs; cached per body once complete, `SyncEngine::body_links`), not only the commit's listed chunks: under a new label (replacement, a move) a reused chunk or a snapshot's value would otherwise be linked and absent. Only what the body links: the live state of other things the commit touches may lie outside the label's closure. Residue: a tree whose node blobs no reachable server or peer holds keeps its thing's dropped chunks for good (the judgment waits for nodes that never come). A chunk is judged dead from the commits held, so a co-writer's concurrent reuse can lose it at a server (tombstoned, so never re-uploaded by ID). Repair (spec/sync.md §1): a `LogEvent::Deleted` of a non-commit blob gone from every server of the label queues it (`relink_pending`; with one server per label that server alone decides); `SyncEngine::relink_lost` calls `Engine::relink`, which takes the aspects of commits listing a held queued blob and, per field (`relink_field`; a field that fails, e.g. a blob not held, is skipped, the rest go), needs an own content commit whose delta trees hold it, takes retention, expiry and schema from the newest held commit linking it (the value rewritten), and writes only the large positions of the current value whose tree holds it (`osis_schema::link_positions`) with `Op::Put` (a register write, no reset) and `Mutation::fresh` (`Reuse::exclude` re-encrypts it and the nodes above). The repair is a plain write with a fresh stamp: it overrides a concurrent unseen edit of that one position and can bring back an entry whose removal it has not seen (notes/crdt.md); bounded to the affected positions and rate-limited. Back-off per aspect (`relink_backoff`, 1 h doubling to 7 days) in memory only: a restart allows one more immediate repair per aspect. An aspect held back keeps its blobs queued and `Event::Tick` retries when it passes. Not repaired: set elements and map keys holding links, values whose own delta was compacted, unregistered typed schemas.
