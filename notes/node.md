# Node (osis-node)
> Summary: Module layout and ownership of `osis-node`, the engine's public surface, what it keeps in the store and in memory, and the readings node-core fixed (pending, validity, bodies, receipts, counters). The plans that built it are done; the origin column says which part of the spec each module serves.

## Modules and ownership
| module | origin | contents |
|---|---|---|

| `apply/` | node-core | `ingest`, `examine` (verification, pending reasons, parking), atomic apply (`atomic.rs`), perm adaptation and validity (`validity.rs`), receipt record (`receipt.rs`), established epochs from applied `/secrets` writes (`keys.rs`), `load` (index rebuild) |

| `identity/` | node-core | node seed, keys, creation records |
| `events/` | node-core | `Event`, `Diagnostic`, subscriber channels |

## Public surface (engine)
- Lifecycle: `Engine::create(backend, root, Config, clock, rng)` (new identity, node thing with `/created` + `/node`, then `/keys`), `Engine::open(..)` (reload, re-examine pending), `tid`, `identity`, `now` (corrected clock), `set_clock_offset`, `subscribe() -> Receiver<Event>`.
- Writing: `Mutation` (`create(record)`, `set`/`replace`/`remove_aspect`/`op` through any `AspectKey`, `retention`, `expires`, `purge`, `frontier`, `act_as`, `commit_form`); `Engine::new_thing(&mut m, owner)`, `Engine::commit(m) -> Option<CommitId>`.
- Receiving: `ingest(bytes, blobs)` / `ingest_from(.., peer)` -> `Ingested::{Applied, Duplicate, Pending(reason), Parked}`; `reexamine`, `set_syncing(tid, on)`, `tick` (expiry, keep-at-most, drift), `pending()`.
- Relaying: `commit_ids`, `header`, `commit_bytes`, `blob`, `package`.
- API layer: `DiagnosticKind::Callback` (an app callback panicked), `app_record`/`set_app_record` (local `u/` records the `osis` crate keeps: person, home group), `Mutation::undo(target)` (undo acting as the mutation's actor).
- Reads: `get`, `get_full`, `read_large`, `read_large_max` (fails `TooLarge` past a bound), `get_typed`, `aspects`, `groups_of`, `roster`, `role_on`, `resolve`, `state`, `knows`, `all_aspects`.
- Retention: `snapshot(tid, ak)`, `covered(snapshot, body, tid, ak)`, `drop_body`, `body_keep`, `deaths`, `holds_body`, `deletions(from, limit)`.
- Undo: `undo(id)`, `undo_stack(actor, scope)`, `changes(scope)`.
- Membership inputs: `receipt(tid, ak)`, `frontier(scope, as_of)`, `epochs(actor)`, `register_schema`.
- Labeling: `group_actor`, `may_read`, `closure`, `labeled_groups`, `group_labels`, `bodies`, `label_bodies`, `partial_bodies`, `wrap_secret`, `stranded_secret`, `deposit_seed`, `head_keys`, `tokens_of`, `certificates` (notes/sync.md, Implementation (osis-node sync)).
- Move: `move_thing(t, owner) -> (copy, imports)`; `/moved` is an ordinary write by T's admins; reads resolve tids (except in `/tid`, `/created`, `/was`, `/moved`) through `/was` standing then `/moved`.
- Flows (each returns `Done { commits, deliveries }`; node-sync carries out the `Delivery` values: `Inbox` blob for an actor's inbox label, `Direct` commits to a node, `First` placements before any other upload of the sync, `Certificate` copies under a home label, `Deposit` under a label the author does not write): `create_person(servers) -> (Person { person, card }, Done)`, `pair(person, node)` (grant, or re-seal of a member, plus the commits it needs, as one `Direct`), `paired(person, grant)`, `recover(card, lost, presync)`; `grant`/`grant_as(signer, ..)` (admin or invite grant; own secrets first; boxes), `demote`/`demote_as(signer, target, Demotion { member, new, presync })` (explicit demotion with frontier, or self-removal; the target's rotation in the same commit), `presync_scope(target, member, new)`, `PreSync::{Synced, Unsynced { proceed }, Backdated(t)}`; `accept_inbox(blob) -> (things, Done)`; `create_link(sharer, LinkSpec) -> (ShareLink, seed thing, Done)`, `redeem(link, grantee, single_use)`, `bear(link)`, `finalize_link(k, l)`, `revoke_joiner(k, l, joiner, presync)`; `create_label(group, servers)`, `issue_step(group, label, head, fresh)`, `label_of`; `roster_snapshot(thing, signer)`, `roster_snapshot_due`; `move_to(t, owner)`, `refresh_deposit_seed(actor)`; `hold_key_actor(seed) -> tid`, `drop_key_actor`.
- API hooks (osis second half): `report(diagnostic)` (deduped like the engine's; kinds `NotSynced`, `Unsynced`, `Stranded` added), `owner(tid)`, `next_chunk(tid, &mut TreeReader)` (one chunk of a large value per call: the API's `stream`); `Event::Signal { tid, kind, from, actor, ts, target, value }` for sent and received signals; `SyncEngine::{label_status, connected, set_servers, signal_as}`; the tokio driver runs over a `Host` (`run_host`: the osis handle keeps the engine behind its lock and hands actions over as `Control::Apply`; `run` owns it).
- Rotation: `ensure_rotated(actor) -> (Done, roles still uncovered)` (labeling calls it before wrapping, stamping or boxing under the actor; it must not encrypt under the roles returned), `rotate_eagerly`, `departures(actor)`, `give_own_secrets(thing)`, `reseal_due(actor, &dyn SyncState)` (node-sync implements `SyncState::complete_pass`), `reshare(actor, member)` (manual), `drop_lost_secrets()`.

## Store records
Local records (`*_local`): `y/` sync state (notes/sync.md), `seed`, `hlc`, `c/`+ID commit records (received, origin, dropped parts, current blob), `t/`+tid creation records, `r/` receipts, `v/` value-less deltas, `p/` purge requests per aspect, `x/`+T timers, `s/` synced things, `o/` voided commits, `k/`+tid opened epochs, `a/` aspect index; logs `deletions`, `resnapshot`. Store kinds: aspect units (state = snapshot grammar with its pages inline, or for a root map, set, bag, list or text above `PAGE_TARGET` a marker, the state then living as pages of consecutive elements by dot, about 8 KB each, in aspect table 0; undo = what undoing each of the last local commits reads, `Fragment::footprint`), counters, death records (body ID = commit ID), pending/parked commits, blob ciphertexts (pages, chunks, header-list trees).
In memory (`Core`, rebuilt by `apply::load` at open and after any failed transaction): states cache (whole fragments; a paged state loads all its pages on first access) with page indexes (`engine::state::PageIndex`: first dot -> page ID), parts invalid here per aspect (`Core::invalid`, `index_validity`), perm `MemoryHeldSet` + `Timelines`, commit headers with validity and dropped parts, per-aspect commit index, node-form ranges, pending reasons, value-less lists, secrets, `/was`/`/moved`/group indexes, `/members` entry keys.

## Readings fixed here
- **Counters**: reserved in the same transaction that applies the signed commit; nothing signed leaves the node before it is durable, so no counter is reused and no gap is left by a crash.
- **HLC**: a writer exhausting `logical` within one ms moves to the next ms instead of waiting.
- **Pending "chain certificates missing"** (decided): the author's or an owner chain's `/created` is missing, or the author is not on the touched thing's owner chain and no held edge writes lead from it (as member, through member actors) to a thing on that chain. Revoked authors keep their certificates, so their commits apply, judged invalid; re-grant re-merges.
- **Prefix vs header** (spec/commits.md §4 last rule) is checked by node-sync where blobs are opened, for linked header lists once resolved (the pass); `ingest` takes plaintext.
- **Body** (decided) = one projection class of a commit: deltas sharing the reader actor (the thing if it has secrets of its own, else its owner), retention, expiry and token indices. Its ID = BLAKE3(commit ID ‖ first aspect index of the class) keys the death records; first death = earliest, last = latest over its deltas; keep-at-most drops the whole class. Expiry and purge still drop single deltas (the commit is kept without them).
- **Validity**: re-judged for every held delta whenever the perm held set changes (O(held deltas)). Un-merge is by invalid delta, not by author: every body (the current state counting as one) is stripped of the writes owned by deltas invalid here (`Fragment::remove_dots` with `Owned::owns`: node-form counter range or commit ID) before it joins, on apply as well as on rebuild, so another writer's nested write under an invalid creation goes on every node alike. An invalid delta arriving rebuilds its aspect. Compaction snapshots are bodies stripped the same way.
- **Membership content rules** are writer-side only: a received commit breaking them is applied and perm judges each edge write at its point.
- **`/created` gate** (spec/commits.md §4): only things whose delta the commit blob holds or that the node syncs make it pending on an unknown `/created` or chain; a thing neither held nor synced (another's private thing in a mixed commit) is skipped and its delta, if it comes later, joins late.
- **Late deltas** (`late_parts`, `join_late`): a late delta that waits (its `/created`, chain, pages) is kept pending under the commit's ID (listed by `pending()` though the commit applied) and joined once it can be; late `/created` records and `/members`/`/tenures` deltas reach perm as on apply (the commit's edge writes re-added from every held part), then held deltas are re-judged. Late `/secrets` deltas are opened (observe_state) but do not establish.
- **Atomic wait**: missing deltas that expired, or that a held purge request names with the right, count as held; a part whose bytes miss its delta hash is dropped alone (diagnostic) and the commit waits for, or applies without, it.
- **Rollback**: a failed transaction restores the indexes from a copy taken at the transaction's first change (`Core::touch`) and evicts the states it wrote; no reload from the store (cost: one copy of the indexes per changing transaction).
- **Snapshots**: frontiers cover node-form counters contiguously applied and valid on the aspect; retention takes the schema's default bounds from a registered schema (`Engine::register_schema`; local typed writes register theirs).
- **Moves** run in one store transaction (spec/permissions.md §7 edit).
- **Established epochs** (`apply/keys.rs`, spec/crypto.md §4): an applied valid commit's `/secrets` write calls `SecretsWrite::applied` with its `/keys` write (whole keysets: flows replace the field) and the keysets held before; a removal is a keyless reset, so box keys come from an index of held keyed entries, and a write whose removed keys are unknown waits (persisted under `w/`) until they arrive, so a rotation received before the one it supersedes is not established. A held `/secrets` compaction snapshot calls `snapshot_keyed`; a delta found invalid `unset_applied` + `establish`, valid again re-applies (keysets before taken as the current `/keys`). Epochs persist `established`, `applied`, `snapshot` (`k/`), never re-inferred. `/secrets` compaction is gated on `may_compact_secrets`. `Engine::epochs(actor)` exposes the view.
- **`/secrets` and `/keys`** deltas need the highest role they rotate or box (at least write): admin for an admin box, history key or keyset.
- **Edge writes from `/members` deltas**: a keyed entry sets the edge it reads; a reset of a known entry dot removes it (keys learned from held keyed entries; a commit whose removed key is unknown waits in `unresolved` and is re-derived when keys arrive); nested field writes overlay the entry's created value. Flows should write a change as remove + put.
- **Purge**: judged by perm `may_purge` at the request's point; kept per aspect so deltas arriving later are purged on arrival.
- **Undo buffer**: pre-commit states of the last 16 local commits per aspect; cleared (shredded) whenever a body of the aspect drops. Undoing another node's commit (admin view) takes the pre-state as the join of the held valid bodies ordered before it.
- **Writer-side membership rules**: at most one `/members` edge per membership commit (a redemption's grant plus self-removal excepted); a frontier only on a commit that lowers an edge; a removal or demotion of another member on a thing with a `/keys` keyset carries `/secrets` and `/keys` deltas of it. A local commit breaking them, or with any delta invalid at this node, fails before it leaves.
- **Import**: one import commit per origin commit (header kind 4 has one delta per aspect and each delta carries its origin's retention); a write of origin C on T maps to `(Commit(C), ctr)`, foreign dots it references to `(Commit(creator), ctr)` via the node-form range index; expiring, value-less, invalid and dropped deltas are skipped. An invalid import un-merges its origins' re-sourced writes.

- **Flows hooks in node-core** (membership-flows): `Core::key_actors` (held recovery or link keys, in memory: `Mutation::sign_as` signs as one in commit form, `Core::epochs` derives from it, `ingest_secrets` opens its boxes); `Mutation::roster` (roster-snapshot kind); `Mutation::dead_resets` (map tombstones for entry dots whatever their liveness, `osis_crdt::reset_entries`: a removal of an absent edge); `observe_state` calls `flows::reopen_dependents` when secrets of an actor are learned (boxes sealed to it in other actors' `/secrets` open then; actors found through `Core::box_keys`); `DiagnosticKind::Removed`. Writer-side rules (`apply/validity.rs`): a frontier is allowed on a removal of an absent or expired edge; a removal or demotion carries the target's rotation unless it is a self-removal (`validity::self_removal`: the author's own edge, or admin on the member with no admin on the target without the member's edge).
- **Commit form encoding**: own writes of a commit-form delta are re-sourced to a commit placeholder before encoding (`build_and_apply`), so entries order as a reader decoding with the real commit source orders them (own commit first, spec/crdt.md §3.2); encoding them under the signer's node source broke canonical bytes when foreign dots shared a map (a link redemption re-writing history boxes).
- **Self-removal**: flows return `Done::drop_lost` instead of dropping in the commit's transaction; `carry_out` places the removal under the left things' labels with the leaver's own departure ignored by the cover check (`SyncEngine::leaving`) and drops the lost secrets once every label is idle.
- **Key actor departures** (`Done::departed`): a single-use redemption removes L from K in the redemption commit; node-sync ignores that departure in the cover check while placing the flow's commits (the deposit under K), as for a node's own self-removal; the sharer rotates K.
- **Move**: a labeled thing's copy gets secrets of its own and a label at the thing's servers before the re-grants (the inbox payloads name it; members sync and write the copy whatever of the new owner they read). An unlabeled thing's copy gets none (the app places it in a group).
- **Edge changes**: the writer-side rules take a remove + put of one edge as its new edge (a raise carries no rotation).
- **Late parts** (`join_late`): edge writes re-enter perm from every held part, and `/secrets` parts establish epochs with the commit's `/keys` (held parts) like a whole commit's.
- **Flows readings**: departures are recomputed from the timeline (applied lowering edge writes, an expired edge's removal counting as its role's departure, edges past `until`) and from state (a box at a current epoch whose holder holds less than that role now), members re-granted since dropped, recursively inside member and owner actors with secrets of their own; an epoch first boxed by a commit of a departed party (or a node acting through it) does not cover its departure. Rotation authority is the signer's (`who`: the node, or a held key actor). A self-removal carries no rotation and the leaver drops what it lost; an explicit demotion runs the cascade on the target, then carries the target's rotation. Every encrypting path runs the cascade first (`require_covered`): grants, re-seals, own secrets (the owner's epochs), `create_label`, `issue_step`, `roster_snapshot` (refused while anything stays uncovered). A rotation boxes the timeline's current members whose keys are held; inbox blobs of removals carry the `/members` parts only; re-seal commits go by inbox and under the actor's labels (later removals reset their box entries). `put_secrets` writes history boxes as remove + put, so a grant or re-seal re-writing them unchanged (spec/crypto.md §4) still carries them: an inbox grantee reads pre-grant content, from the pending grant already (`read_pending_boxes`).

- **Flows root causes fixed**: single-use link race winner stranded: the sharer's second rotation boxed the winner, who held no box at the loser's epoch that commit is wrapped under, so the box was unreachable and the re-seal trigger saw it boxed; a rotation now also goes by inbox to every member it boxes that held no box at a current read epoch (`rotation::unreached`). A re-seal of such a member wrote its box as a nested write into the rotation's entry, which the member never held; `put_secrets` writes boxes as remove + put like history boxes.
- Move into an owner without secrets of its own: the copy's own-secrets rotation boxed nobody, so `/secrets` had no boxes field and its typed read failed (`MissingField(0)`): the re-grant carried no history boxes and the member never opened the rotation. `engine::secrets::secrets_value` (used by `flows::secrets_in` and atomic apply's observe) reads a never-written map field as empty; `apply/keys.rs` still decodes `/secrets` strictly in its snapshot and compaction gates (switch them to `secrets_value`).
- Rotation loop (chat, second link): a writer of C holding no K1 secret judged a departure inside K1 never covered and rotated C without end; `held_actors` now gives an unheld actor its newest `/keys` keysets with no boxes, and `ensure_rotated` skips roles a fresh rotation would not cover (`rotation_helps`). Residue: such a node trusts K1's newest keyset, so after a self-removal from K1 not yet rotated it encrypts under C's epoch the leaver can reach through K1 (the same as before K1's admins rotate). `place_certificate_in` still calls `ensure_rotated` (labeling).

## Open (issues/node-core-gaps.md, issues/flows-gaps.md)
- Large values: positions of root and path `set`/`replace`/`add` values are chunked (osis-label `chunk_value`, framed like the delta's pages, blobs in the store); no chunk reuse from the current tree yet (`Reuse`), no streaming reads (`read_large` reads whole); sequence `Insert` items are not chunked.
- Cost: open replays all commit records; every membership change re-judges every delta; a paged state loads all its pages on first access per session; nested large collections (a big map inside a struct field or map entry) and sequence undo buffers are not paged.
- **Paged state** (`engine/state.rs`): `join_into_state` joins in place (no copy), strips the delta instead of the state (stripping commutes with join), and `Tx::set_state_touched` rewrites only the pages holding the delta's root dots (`Fragment::touched_elems`; a root reset or another encoding writes whole), splitting a page past 16 KB and dropping an emptied one; below 64 root elements or `PAGE_TARGET` a state is one unit as before. `observe_state` reads only the aspects it indexes. `Engine::get_at(tid, ak, path)` reads one position (`Fragment::at`). Measured: one entry edit at 10^6 keys 1.1 ms, 54 KB written (was 8.6 s, 94.6 MB).
