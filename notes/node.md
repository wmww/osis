# Node (osis-node)
> Summary: Module layout and ownership of `osis-node`, the engine's public surface, what it keeps in the store and in memory, and the readings node-core fixed (pending, validity, bodies, receipts, counters). The plans that built it are done; the origin column says which part of the spec each module serves.

## Public surface (engine)
- Lifecycle: `Engine::create(backend, root, Config, clock, rng)` (new identity, node thing with `/created` + `/node`, then `/keys`), `Engine::open(..)` (reload, re-examine pending), `tid`, `identity`, `now` (corrected clock), `set_clock_offset`, `subscribe() -> Receiver<Event>`.
- Writing: `Mutation` (`create(record)`, `set`/`replace`/`remove_aspect`/`op` through any `AspectKey`, `retention`, `expires`, `purge`, `frontier`, `act_as`, `commit_form`); `Engine::new_thing(&mut m, owner)`, `Engine::commit(m) -> Option<CommitId>`.
- Receiving: `ingest(bytes, blobs)` / `ingest_from(.., peer)` -> `Ingested::{Applied, Duplicate, Pending(reason), Parked}`; `reexamine`, `set_syncing(tid, on)`, `tick` (expiry, keep-at-most, drift), `pending()`.
- Relaying: `commit_ids`, `header`, `commit_bytes`, `blob`, `package`.
- API layer: `DiagnosticKind::Callback` (an app callback panicked), `app_record`/`set_app_record` (local `u/` records the `osis` crate keeps: person, home group), `Mutation::undo(target)` (undo acting as the mutation's actor).
- Reads: `get`, `get_at` (a paged state loads the pages on the path only), `get_full`, `read_large`, `read_large_max` (fails `TooLarge` past a bound), `get_typed`, `aspects`, `groups_of`, `roster`, `role_on`, `resolve`, `state`, `knows`, `all_aspects`.
- Retention: `snapshot(tid, ak)`, `covered(snapshot, body, tid, ak)`, `drop_body`, `body_keep`, `body_live` (a dot the body's deltas own survives in the state), `deaths`, `holds_body` (node-sync judges deletions and re-snapshots from the commit index; no queue).
- Undo: `undo(id)`, `undo_stack(actor, scope)`, `changes(scope)`.
- Membership inputs: `receipt(tid, ak)`, `frontier(scope, as_of)`, `epochs(actor)`, `register_schema`.
- Labeling: `group_actor`, `may_read`, `closure`, `labeled_groups`, `group_labels`, `bodies`, `label_bodies` (`label_bodies_meta` without plaintexts, cached per commit in `Core::bodies`; `body_plaintext`), `latest_by` (newest valid applied write on an aspect, optionally by an author), `partial_bodies`, `part_bodies`, `linked_blobs`, `wrap_secret`, `stranded_secret`, `deposit_seed`, `head_keys`, `tokens_of`, `certificates`, `revoke_certificates`, `aspect_commit`, `tree_missing` (a large value's node and chunk blobs not held) (notes/sync.md, Implementation (osis-node sync)).
- Move: `move_thing(t, owner) -> (copy, imports)`; `/moved` is an ordinary write by T's admins; reads resolve tids (except in `/tid`, `/created`, `/was`, `/moved`) through `/was` standing then `/moved`.
- Flows (each returns `Done { commits, deliveries }`; node-sync carries out the `Delivery` values: `Inbox` blob for an actor's inbox label (with the `Resend` that seals it again), `Direct` commits to a node, `First` placements before any other upload of the sync, `Certificate` copies under a home label, `Deposit` under a label the author does not write): `create_person(servers) -> (Person { person, card }, Done)`, `pair(person, node)` (grant, or re-seal of a member, plus the commits it needs, as one `Direct`), `paired(person, grant)`, `recover(card, lost, presync)`; `grant`/`grant_as(signer, ..)` (admin or invite grant; own secrets first; boxes), `demote`/`demote_as(signer, target, Demotion { member, new, presync })` (explicit demotion with frontier, or self-removal; the target's rotation in the same commit), `presync_scope(target, member, new)`, `PreSync::{Synced, Unsynced { proceed }, Backdated(t)}`; `accept_inbox(blob) -> (things, Done)`; `create_link(sharer, LinkSpec) -> (ShareLink, seed thing, Done)`, `redeem(link, grantee, single_use)`, `bear(link)`, `finalize_link(k, l)`, `revoke_joiner(k, l, joiner, presync)`; `create_label(group, servers)`, `replace_label(group, old)`, `issue_step(group, label, head, fresh)`, `label_of`; `roster_snapshot(thing, signer)`, `roster_snapshot_due`; `move_to(t, owner)`, `refresh_deposit_seed(actor)`; `hold_key_actor(seed) -> tid`, `drop_key_actor`.
- API hooks (osis second half): `report(diagnostic)` (deduped like the engine's; kinds `NotSynced`, `Unsynced`, `Stranded` added), `owner(tid)`, `next_chunk(tid, &mut TreeReader)` (one chunk of a large value per call: the API's `stream`); `Event::Signal { tid, kind, from, actor, ts, target, value }` for sent and received signals; `SyncEngine::{label_status, connected, set_servers, signal_as}`; the tokio driver runs over a `Host` (`run_host`: the osis handle keeps the engine behind its lock and hands actions over as `Control::Apply`; `run` owns it).
- Rotation: `ensure_rotated(actor) -> (Done, roles still uncovered)` (labeling calls it before wrapping, stamping or boxing under the actor; it must not encrypt under the roles returned), `rotate_eagerly`, `departures(actor)`, `give_own_secrets(thing)`, `reseal_due(actor, &dyn SyncState)` (node-sync implements `SyncState::complete_pass`), `reshare(actor, member)` (manual), `drop_lost_secrets()`, `lost_due()`, `drop_lost_due()`.

## Store records
Local records (`*_local`): `y/` sync state (notes/sync.md), `seed`, `hlc`, `c/`+ID commit records (head: received, origin, dropped parts (`engine::index::record_head`, version 1; version 2 heads of earlier builds carry part bytes, skipped); then the current blob), `t/`+tid creation records, `r/` receipts, `v/` value-less deltas, `p/` purge requests per aspect, `x/`+T timers, `s/` synced things, `o/` voided commits, `k/`+tid opened epochs, `l/`+tid the lost-access work list, `w/` `/secrets` writes waiting for removed keys, `n/` linked frontiers, `u/` API records, `a/` aspect index, `i/v` the persisted index's rules tag. Store index tables `node/*` (rebuildable, `engine::index`): per commit one byte per part (valid, the rotation role it needs, a grant's overreach), box keys, keyed boxes per member, epoch introductions, first box writes, own keys, snapshots per aspect with frontiers, writes carried by snapshots without their commit, perm's reading of each membership commit (`node/edges`), saved walks (`node/walks`). Store kinds: aspect units (state = snapshot grammar with its pages inline, or for a paged state `[5, skeleton, [[set ID, path, encoding]*]]` (an earlier build's `[1]` / `[2, skeleton]` / `[3, ...]` (unkeyed key index) / `[4, ...]` (no set values indexed, link keys hashed with their blob) layout is read whole and laid out anew at its first load, `pages::legacy`; duplicate entries or elements an earlier build wrote after an index miss (a large key or value looked up raw) stay: ordinary lattice state, reads merge them): the state with its paged collections reduced to their reset and `W`; undo = what undoing each of the last local commits reads, `Fragment::footprint`), aspect table 0 (state pages: row key = set ID ‖ order-preserving bytes of the page's first dot, the first page the set ID alone; value `[first dot, next page's first dot, page]`), aspect table 1 (index of paged maps by key and paged sets by value: set ID ‖ keyed BLAKE3 of the key or value, links by content hash (`pages::ident`; key `Core::key_salt`, derived from the node seed) ‖ entry or element dot; a superset, rows of entries left keyless or elements left value-less by expiry or purge, and of those a keep-at-most drop takes out of the store, removed shredded, `pages::unindex`; rebuildable: written with the layout, the unit tag names its rules), counters, death records (body ID = commit ID), pending/parked commits, blob ciphertexts (pages, chunks, header-list trees).
In memory (`Core`, rebuilt by `apply::load` at open and after forgetting; a failed transaction that changed nothing keeps the derived caches): states cache with page indexes (`engine::pages::PageIndex`: paged collections by path, which of their pages are loaded), the journaled indexes (`engine::journal`: `JMap`, `JSet`, `JSetMap`, `JNested`; `Groups` and the held set journal themselves): commit metas with validity and dropped parts, per-aspect and per-thing commit indexes, node-form ranges, parts invalid here per aspect, perm's held set (`engine::held::Held`: by target, by member, by commit ID, owner -> owned, the things touched since perm last looked) + `Timelines`, pending reasons, value-less lists, secrets, `/was` (both ways), `/moved`, groups (`engine::groups`), `/members` entry keys, box keys and boxes per member, epoch introductions, held snapshots with frontiers, writes snapshots carry without their commit.

## Readings fixed here
- **Counters**: reserved in the same transaction that applies the signed commit; nothing signed leaves the node before it is durable, so no counter is reused and no gap is left by a crash.
- **HLC**: a writer exhausting `logical` within one ms moves to the next ms instead of waiting.
- **Pending "chain certificates missing"** (decided): the author's or an owner chain's `/created` is missing, or the author is not on the touched thing's owner chain and no path of held edge writes and owner links leads from it to a thing on that chain (`validity::reaches`: searched backward from the chain, from a thing to its owner and its named members (`Held::members_of`), as perm's `roles_to_any`, so the author's owned things never enter it; a new record of a named member or of an owner of held things bumps `Held::edges`, so record waits re-examine). Revoked authors keep their certificates, so their commits apply, judged invalid; re-grant re-merges.
- **Owner depth** (spec/permissions.md §1): `validity::too_deep` makes every delta but `/created` invalid on a thing whose chain is not known to reach its key actor within `MAX_OWNER_DEPTH` links (deeper, or a record on it not held: forgetting a record never makes a deep delta valid); per delta, from creation records alone, so nodes holding different parts agree; `examine` stops waiting for the chain there. The writer refuses such a commit. Upgrade: a store holding deeper things (none known) quietly loses their non-`/created` writes on rebuild, and perm gives them no ownership authority (`Owners::chain` returns `None`).
- **Prefix vs header** (spec/commits.md §4 last rule) is checked by node-sync where blobs are opened, for linked header lists once resolved (the pass); `ingest` takes plaintext.
- **Body** (decided) = one projection class of a commit: deltas sharing the reader actor (the thing if it has secrets of its own, else its owner), retention, expiry and delete-key indices. Its ID = BLAKE3(commit ID ‖ first aspect index of the class) keys the death records; first death = earliest, last = latest over its deltas; keep-at-most drops the whole class. Expiry and purge still drop single deltas (the commit is kept without them).
- **Validity**: re-judged, after a held-set change, only for the deltas on things whose timeline changed (`Core::stale_things`, `rejudge_all`; with the commits whose void, required-role or overreach inputs changed, `stale_commits`, and everything after a rebuild at open, `stale_all`; a rollback restores validity flags with the journal): perm's `Timelines::update_touched` re-partitions around the things whose held inputs changed (`Held::take_touched`) and reports the components evaluated anew (all their things) and those whose walk only went on or that only gained new leaves (`/created` of things nothing names): for those, only the things authority flows to from the touched ones (`Held::reach`: owned things and targets of their edges, transitively). Writing a new thing re-judges that thing's deltas only; a grant to a member new to the component (it joins the component) re-evaluates the component and re-judges every delta on it (perm's walk granularity, issues/perm-eval-cost.md). A voided commit is re-judged alone. Un-merge is by invalid delta, not by author: every body (the current state counting as one) is stripped of the writes owned by deltas invalid here (`Fragment::remove_dots` with `Owned::owns`: node-form counter range or commit ID) before it joins, on apply as well as on rebuild, so another writer's nested write under an invalid creation goes on every node alike. Validity follows the held set, not arrival order (was issues/late-member-backdated-revoke.md: a member offline through a revoke whose frontier missed a write applied the demotion before the item's `/created`, which perm took as a new leaf and kept the walk, so the item had no demotion recorded and the write stayed valid there; now a new leaf takes its owner's demotion records, notes/permissions.md Implementation; tests: `apply/tests_order.rs` every arrival order, perm `incremental` late leaves, timed_dead.rs `late_member_judges_backdated_revoke_alike_*`). An invalid delta arriving rebuilds its aspect (re-joining every held body of the aspect: O(aspect history), as re-merging needs the bodies: a register's earlier value comes back only from them).
- **Snapshots vouch for nothing** (spec/permissions.md §5.2): a compaction snapshot merges whoever wrote it; every write it carries whose own commit is not held is judged as its author's at the `ts` the snapshot carries for it: stamps at theirs, element creations at their creation's (a map entry's creation `Ci`, a set or bag element's value register, a sequence segment), commit-form writes as their commit per the snapshot's `Authors` (`Core::authors`, keyed by thing and commit; held commit-form commits and imports set it, a snapshot naming another author or `ts` than a held commit, lacking an author, or dating a held commit's dot otherwise is bad input, `validity::note_authors`). Recorded per snapshot for every held snapshot in every path (`Core::carried`, `validity::carried_of`): one group per (source, author, `ts`) with exact counters, each counter judged on its own (the frontier split found by a binary search, `carried_invalid`), exactly the invalid dots stripped (`Owned::Dots`). A commit arriving drops the carried counters it owns (`uncarry`). Records with no `ts` (tombstones, bare anchors) carry nothing to judge. Tests: `hostile_snapshot_strips_only_its_dots_spec_perm_5_2`, `entry_created_after_demotion_spec_perm_5_2`, `commit_form_carried_writes_judged_spec_perm_5_2`, `snapshot_before_grant_then_valid_spec_perm_5_2`, `demoted_compactor_fresh_node_spec_perm_5_2`. Stores written before map entries kept their creation stamp hold entries without one until rebuilt from their bodies.
- **Membership content rules** are writer-side only: a received commit breaking them is applied and perm judges each edge write at its point.
- **`/created` gate** (spec/commits.md §4): only things whose delta the commit blob holds or that the node syncs make it pending on an unknown `/created` or chain; a thing neither held nor synced (another's private thing in a mixed commit) is skipped and its delta, if it comes later, joins late.
- **Late deltas** (`late_parts`, `join_late`): a late delta that waits (its `/created`, chain, pages) is kept pending under the commit's ID (listed by `pending()` though the commit applied) and joined once it can be; late `/created` records and `/members`/`/tenures` deltas reach perm as on apply (the commit's edge writes re-added from every held part), then held deltas are re-judged. Late `/secrets` deltas are opened (observe_state) but do not establish.
- **Re-examination** (`apply/waits.rs`): `reexamine` (after every applied commit, at open, on `set_syncing`, ticks) examined every pending commit again (read, decode, signature): a first sync where commits wait for their thing's `/created` or a body's other part was O(commits × pending), 540 of 580 s at 10^4 (`scale.rs first_sync_cost`). Now a pending commit's examination is kept (`Core::waits`, a cache: dropped by a rollback that changed anything, a clock offset change, a reload) when it waits for a record (`UnknownCreated`, `MissingChain`) or deltas (`WaitDeltas`), its header is inline and it carries no `/secrets` part, within byte bounds (`MAX_WAIT_BYTES` 64 KiB each, `MAX_WAITS_BYTES` 16 MiB in all; a record wait keeps its order key and things only, since `MissingChain(author)` comes before the signature check and junk from a peer gets there; a delta wait, signed and certified, keeps its header). `waits::candidates` takes only what may have changed: commits without a kept examination, woken ones (a receipt or purge record of a missing delta's aspect), record waits whose record was added (`Held::take_records`), delta waits after any held-set change (perm judges purge rights) or once an expiry passed; every pending commit when the held edges changed (`Held::edges`: certificates; `validity::reaches` is capped) or the clock is below the latest one any wait was judged at (drift). `set_syncing` of a thing drops the waits of commits on it (examined in full: a thing whose delta is not held gates the commit only if synced). A delta wait is judged again from its missing deltas alone (`still_waits`); a record wait is examined. Candidates keep the (membership first, `ts`) order. Debug builds examine every commit left out in a rolled-back transaction and assert it still waits for the same reason (`Engine::check_unchanged`); that examination can emit diagnostics (sent at once, not rolled back), so rate-limit slots differ between debug and release. Tests: tests/it/waits.rs (syncing on, clock back, 1000 junk commits bounded), receive.rs `pending_not_reexamined_while_unchanged_spec_commits_4`. Remaining costs: any held-edge change re-examines every pending commit in full (O(membership commits × pending)); every new `/created` re-judges every delta wait through `still_waits` (O(creations × delta waits); refinement: on held changes re-judge only delta waits whose missing aspects have a purge record); commits pending for other reasons (drift, blobs, parked, `/secrets` parts, past the byte bounds) are examined at every `reexamine`, as before.
- **Atomic wait**: missing deltas that expired, or that a held purge request names with the right, count as held; a part whose bytes miss its delta hash is dropped alone (diagnostic) and the commit waits for, or applies without, it.
- **Rollback**: every in-memory index is journaled (each change records what it replaced); a failed transaction undoes its own changes newest first and evicts the states it wrote (O(changes), was a copy of every index per changing transaction). The timelines follow the restored held set (`update_touched` around what the undo touched).
- **Open** (`apply::load`): with the persisted index of these rules (`engine::index`, tag `i/v`: a hash of every workspace crate's `src` from `build.rs`): the commit record heads and headers (decoded once: the header bytes must hash to the record's ID, no re-encode; no part decoded, nothing re-judged), the parts table and the derived index tables, perm's inputs from `node/edges` (below), `/was`, `/moved` and `/group` states; `/secrets` and `/keys` states are not read (epochs and own keys persist). A store tagged with other rules, one a forget changed below the indexes (`index::invalidate`), or one whose index fails to decode or lacks a row (`Engine::reload` retries as a rebuild), rebuilds from every commit record once, re-judging every delta, and writes the index (`write_all`: store index tables dropped shredded first). **`node/edges`**: per membership-kind commit (`Kind::is_membership`), what perm's adaptation reads of its held `/members` and `/tenures` parts (`validity::EdgeParts`: each `/members` entry's dot, key and value read, each tenure set element); a pure function of the commit record, written by `Tx::put_commit` with the record, every time the record is (first apply, late parts in `join_late`, which reuses the row as its edge writes, `drop_part`, forget; same transaction, same shred flag; `Tx::remove_commit` removes it shredded), all of them by `write_all`; a debug build checks every row against its record at each fast open. No tag of its own: the index's rules tag covers it, the store's AEAD makes damaged bytes an open error (`Error::Store`, not a rebuild), and a row that decodes badly or is missing rebuilds. Each row duplicates the decoded `/members` values and tenures of its commit (a large roster snapshot roughly doubles its stored size). Membership snapshots (`Kind::MembershipSnapshot`) reach perm on a fast open too now (main's fast path took only membership and roster-snapshot commits; apply and rebuild already took every membership kind). `Core::snapshots` keeps each aspect's snapshots in (`ts`, ID) order (was arrival order: a fast open and a rebuild listed them differently). The adaptation itself (`member_keys`, unresolved removals, linked tenure frontiers from `n/`) runs at every open over the rows, oldest first as a rebuild does, so the result is what a rebuild gives (`tests/it/walks.rs`). Commit records stay read at open: `Core::commits` holds every header in memory (validity, retention, labeling and sync read them), and the record is where the header lives; a header copy in the index would only skip the part bytes. Perm's timelines come from the saved walks (`node/walks`, osis-perm `cache.rs`; `index::update_timelines_saved`): a component resumes a walk saved under any of its things (root first) whose tag matches these rules and its held inputs, continued as at run time over new leaf things and commits added since; else evaluated; a unit that does not match or read is evaluated anew, never an error. Walks are written in the transaction that persists the index, after it (`index::write`: `Timelines::to_save`, components of at least `WALK_CACHE_MIN` = 64 commits grown by a quarter), shredded, so none runs ahead of its commits; `Timelines::saved` marks them only once the transaction is durable (`Engine::run`); `write_all` saves every component of the minimum; an open that evaluated a component saves it in one more transaction (failure ignored). The table is a rebuildable index table: a forget or a rules change drops it with the others. Measured (`--test it scale::membership_change_and_open_cost`, box at load 25-45, before and after in the same session): 10^4 content commits: open 96 -> 62-70 ms; plus 10^4 edge writes by the node on its 100 things: open 0.39-0.54 s -> 0.28-0.30 s (headers 79 ms of which decoding 53, metas 43, `node/edges` rows 18, adaptation 69 of which `edge_of` 29, walk restore 57; before: headers 85 plus re-encoding and hashing 35, decoding membership bodies 200); 10^4 edge writes by 5 admins with demotions reaching the owner in batches: the owner's open 0.21 -> 0.10-0.16 s restored, 0.32 -> 0.17-0.29 s evaluated anew. Still O(commits) at open: every header decoded into `Core::commits`, every membership commit adapted, the saved walk's inputs re-gathered for its tag (issues/node-core-gaps.md).
- **Snapshots**: frontiers cover node-form counters contiguously applied and valid on the aspect; retention takes the schema's default bounds from a registered schema (`Engine::register_schema`; local typed writes register theirs). Deaths (`retention::carriers`): a dying write's death is recorded in its own commit's body and in every held snapshot taken before the death whose frontier holds it (also where the write's own body was never held); dropped bodies get none. Commit-form writes in snapshots are not attributed (no frontier).
- **First death is order-independent** (spec/crdt.md §4.8, sim `keep_at_most` seed 445): a join reports deaths against the state only, so a write's death depended on arrival order (A, C, B: C pruned A, B arrived dead and never touched A; or the earliest superseder pruned before a late write arrived). Two nodes had keep-at-most bounds minutes apart; the earlier one deleted the body at the server, the other judged it must-hold and re-uploaded a fresh encryption each pass (a storm). Now applying a delta under a relative keep at most also joins it alone with each held body of the aspect under a pending keep-at-most timer (`retention::note_earlier_deaths`) and lowers recorded first deaths (never `last`). Residue: a body already dropped is not consulted (a write arriving more than D after its superseder died); the scan reads every timer record (cost per such delta: pending timers).
- **Keep at most and live writes** (spec/commits.md §5, was issues/at-most-zero-snapshots.md and keep-at-most-partial-bodies.md): dropping a body that still had a live write at its bound (at most 0: at the kill) forced a whole-aspect carrier snapshot on every edit erasing part of an older commit or snapshot (O(state) per change, against spec/requirements.md Scale). Now one rule for every body: under a relative keep at most D (0 included) the bound is first death plus D, plus `AT_MOST_GRACE` (1 h, a format constant) while the body has a live write; the next compaction usually drops it first (covered, `drop_covered`); no timed delete for it (`sync/pass.rs` `keep_at_most_due`: deaths and bound first, then `body_live`). A deleted text element's creation stays in the state as its anchor, so a text body fully erased is live too and keeps to the grace (coordinator decision: one rule; at most one carrier snapshot per grace per aspect instead of an O(state) snapshot per erase). Cost: liveness is `Fragment::holds_owned` with `Owned::owns_range` (stops at the first hit, never expands range records), cached per body and forgotten per aspect when its state changes (`Core::forget_live` drops every body with a delta on the changed aspect: a body's liveness spans its class, whichever aspect was asked; keying by the asked aspect alone left stale answers, test `body_live_spans_its_class_spec_commits_5`). A reader drops a live body at its bound with no carrier (spec/sync.md §5: the bound wins). Bounds follow liveness: a validity flip re-runs `check_at_most` for the aspect (`recheck_at_most`), and a due keep-at-most timer re-judges instead of dropping (a body that turned live keeps to its grace bound); a timed delete already sent cannot be withdrawn: a window, not a loss (timed_dead.rs `revived_body_uploaded_again_after_timed_delete_spec_commits_5`): the server deletes the revived body at the plain bound, and a right holder re-uploads it (fresh encryption, must-hold: live and uncovered) at its next resync (`resync_ms`, 60 s, while online; the server's sweep pushes nothing that marks the label dirty) or next sync; past the extended bound it drops behind a carrier snapshot as usual. Readers see no gap: they hold the body or the state; a member offline throughout judges the revoked writer's write alike when it returns (same test, `late_member_judges_backdated_revoke_alike_*`). Before a due timer drops a live body, the sync engine writes its carrier (`Engine::due_live_drops`, `snapshot_first`), so a server-less label never lacks a copy of the live write. A body with no live write keeps the plain bound and needs no carrier; when the last live write of a partly erased body dies, its plain bound has usually passed and it drops in that transaction. Liveness is judged on the current state (`retention::live`, the tx form of `Engine::body_live`), not frozen at first death (a flag would add a state and depend on arrival order): the state is the join of the applied valid, non-undone deltas, so nodes that applied the same commits agree (dropped bodies leave their live writes in the state). Nodes holding different commits can disagree for a while (one already has the last kill and deletes at the server; the other judges the body live and must-hold); the killing commit goes up before the delete in the same pass, so the other node applies it on its next read. Privacy (spec/commits.md §5 says so): under keep at most, erased data (a deleted word, a whole erased text) persists in its body up to its bound (first death plus D plus `AT_MOST_GRACE`), or to the next compaction if sooner, at the writer and every reader holding it (and in the erasing edit's undo buffer, cleared when a body of the aspect drops), and at a server until a right holder next syncs after the drop; a writer going offline right after an erasing edit leaves the body at the server until a right holder syncs past the bound. Main dropped a fully erased body at the kill; now it waits for the grace (test `text_fully_erased_kept_to_grace_bound_spec_commits_5`). The read state loses it at the kill, and the drop shreds like any. `body_live` of a snapshot (by dot, ts-less writes such as tombstones included): held, a carried write is in the state; dropped, a state write within its frontiers or of commit form. Tests: deletion.rs `erasing_edit_then_compaction_*`, `live_body_goes_at_grace_bound_*`, `text_partly_erased_kept_to_compaction_*`, shred.rs `at_most_zero_live_body_dropped_at_bound_*`, local_serve.rs `keep_at_most_body_carried_on_local_label_*`.

- **Trigger root cause**: forgetting ran only on an explicit call or after a self-removal, since a naive "role none now" test also counts secrets read from a not-yet-applied grant as lost. Fixed by the work list plus the pending-grant guard above; wiring it exposed the stale-push cursor bug (fixed in node-sync).
- **Flows root causes fixed**: single-use link race winner stranded: the sharer's second rotation boxed the winner, who held no box at the loser's epoch that commit is wrapped under, so the box was unreachable and the re-seal trigger saw it boxed; a rotation now also goes by inbox to every member it boxes that held no box at a current read epoch (`rotation::unreached`). A re-seal of such a member wrote its box as a nested write into the rotation's entry, which the member never held; `put_secrets` writes boxes as remove + put like history boxes.

- **Large values** (`engine/large.rs`): `chunk_ops` chunks the large positions of `set`/`replace`/`add` values and list `insert` and `edit` items (a text's are characters; an `edit` item the list holds already keeps its link, `base` items become hash-only links that match the list's read) before the ops resolve, one `BlobWriter` per position, framed like the delta. A `set`/`replace` position whose state holds a link now builds the new tree `BlobWriter::reusing` a `Reuse::index` of that tree (up to `MAX_REUSE`, 16 GiB): equal chunks keep blob and key unless `Framing::keeps` says re-encrypt, a chunk not held is written afresh, reused blobs are not in the chunk list. Edit cost (FORMAT constants, about 100-250 KB chunks): blobs written and uploaded = the changed chunks plus the root node (`write.rs` `large_edit_reuses_chunks_spec_sync_1`, within 1.03-1.1x of the new-chunk bytes; was the whole value). Local CPU stays O(value): the new value is hashed, every reused chunk read and compared, the old tree's nodes indexed.
- **Dropped chunks** (`sync/pass.rs` `dropped_chunks`): a chunk of dropped deltas is deleted (at servers, then locally) only if no live tree of the listing commit's things links it (`Engine::live_trees(tid)` → `LiveTrees { blobs, missing }`: blob IDs under the links in the things' current states, walking held node blobs; `missing` node blobs keep every candidate of the thing and go to `SyncEngine::tree_wants`, which the pass fetches from its server, so a lazy node judges once they arrive; cached in `Core::live_trees`, cleared by `touch`/`rollback`, incomplete entries also by `put_blobs`). The pass also uploads, with each body a writer places, the held blobs its own deltas link (`body_blobs` → `Engine::body_links`: the trees of its values and its pages, through held node and page blobs; cached per body once complete, `SyncEngine::body_links`), not only the commit's listed chunks: under a new label (replacement, a move) a reused chunk or a snapshot's value would otherwise be linked and absent. Only what the body links: the live state of other things the commit touches may lie outside the label's closure. Residue: a tree whose node blobs no reachable server or peer holds keeps its thing's dropped chunks for good (the judgment waits for nodes that never come). A chunk is judged dead from the commits held, so a co-writer's concurrent reuse can lose it at a server (tombstoned, so never re-uploaded by ID). Repair (spec/sync.md §1): a `LogEvent::Deleted` of a non-commit blob gone from every server of the label queues it (`relink_pending`; with one server per label that server alone decides); `SyncEngine::relink_lost` calls `Engine::relink`, which takes the aspects of commits listing a held queued blob and, per field (`relink_field`; a field that fails, e.g. a blob not held, is skipped, the rest go), needs an own content commit whose delta trees hold it, takes retention, expiry and schema from the newest held commit linking it (the value rewritten), and writes only the large positions of the current value whose tree holds it (`osis_schema::link_positions`) with `Op::Put` (a register write, no reset) and `Mutation::fresh` (`Reuse::exclude` re-encrypts it and the nodes above). The repair is a plain write with a fresh stamp: it overrides a concurrent unseen edit of that one position and can bring back an entry whose removal it has not seen (notes/crdt.md); bounded to the affected positions and rate-limited. Back-off per aspect (`relink_backoff`, 1 h doubling to 7 days) in memory only: a restart allows one more immediate repair per aspect. An aspect held back keeps its blobs queued and `Event::Tick` retries when it passes. Not repaired: set elements and map keys holding links, values whose own delta was compacted, unregistered typed schemas.
