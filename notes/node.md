# Node (osis-engine, osis-node)
> Summary: Module layout and ownership of `osis-engine` and `osis-node`, the hook between them, the engine's public surface, what it keeps in the store and in memory, and the readings node-core fixed (pending, validity, bodies, receipts, counters). The plans that built it are done; the origin column says which part of the spec each module serves.

## Modules and ownership
Every module below is in osis-engine (`core/engine`) except `sync/`, which is osis-node (`core/node`); osis-node re-exports the engine's modules and root items at the same paths, so dependents name only `osis_node`. The engine knows nothing of sync, with one hook: `engine::SyncRecords` (`note_unsent`: the inbox delivery a flow's commit owes, written in that commit's transaction; `forget`: the `y/` records `retention::forget` drops), implemented by `sync::state::Records` and installed by `SyncEngine::new` (`Engine::set_sync_records`, kept across a reload; an engine never wrapped writes and drops no sync records, like `Core::changed`). The sync layer reaches into `Engine::core` (`Core` is `#[doc(hidden)] pub`) and `Engine::run`; narrowing that to accessors is open. The index tag (`engine::index`, `core/engine/build.rs`) hashes the engine's sources and its dependencies', not sync's.

## Public surface (engine)
- Lifecycle: `Engine::create(backend, root, Config, clock, rng)` (new identity, node thing with `created.0` + `node.0`, then `keys.0`), `Engine::open(..)` (reload, re-examine pending), `tid`, `identity`, `now` (corrected clock), `set_clock_offset`, `subscribe() -> Receiver<Event>`.
- Writing: `Mutation` (`create(record)`, `set`/`replace`/`remove_aspect`/`op` through any `AspectKey`, `retention`, `expires`, `purge`, `frontier`, `act_as`, `commit_form`); `Engine::new_thing(&mut m, owner)`, `Engine::commit(m) -> Option<CommitId>`.
- Receiving: `ingest(bytes, blobs)` / `ingest_from(.., peer)` -> `Ingested::{Applied, Duplicate, Pending(reason), Parked}`; `reexamine`, `set_syncing(tid, on)`, `tick` (expiry, keep-at-most, drift), `pending()`.
- Relaying: `commit_ids`, `header`, `commit_bytes`, `blob`, `package`.
- API layer: `DiagnosticKind::Callback` (an app callback panicked), `app_record`/`set_app_record` (local `u/` records the `osis` crate keeps: person, home group), `Mutation::undo(target)` (undo acting as the mutation's actor).
- Reads: `get`, `get_at` (a paged state loads the pages on the path only), `get_full`, `read_large`, `read_large_max` (fails `TooLarge` past a bound), `get_typed`, `aspects`, `groups_of`, `roster`, `role_on`, `resolve`, `state`, `knows`, `all_aspects`.
- Retention: `snapshot(tid, ak)`, `covered(snapshot, body, tid, ak)`, `drop_body`, `body_keep`, `body_live` (a dot the body's deltas own survives in the state), `deaths`, `body_not_dropped` (true for a missing part too) (node-sync judges deletions and re-snapshots from the commit index; no queue).
- Revert: `revert(id)` (an undo commit, §4.6); `held_commits(scope)` lists held commits with header and per-aspect body-held for the `osis` commit query (stacks, scopes, redo live there).
- Role inputs: `receipt(tid, ak)`, `frontier(scope, as_of)`, `epochs(actor)`, `register_schema`.
- Labeling: `group_actor`, `may_read`, `closure`, `labeled_groups`, `group_labels`, `bodies`, `label_bodies` (`label_bodies_meta` without plaintexts, cached per commit in `Core::bodies`; `body_plaintext`), `latest_by` (newest valid applied write on an aspect, optionally by an author), `partial_bodies`, `part_bodies`, `linked_blobs`, `wrap_secret`, `stranded_secret`, `deposit_seed`, `head_keys`, `tokens_of`, `certificates`, `revoke_certificates`, `aspect_commit`, `tree_missing` (a large value's node and chunk blobs not held) (notes/sync.md, Implementation (osis-node sync)).
- Move: `move_thing(t, owner) -> (copy, imports)`; `moved.0` is an ordinary write by T's admins; reads resolve tids (except in `tid.0`, `created.0`, `was.0`, `moved.0`) through `was.0` standing then `moved.0`.
- Flows (each returns `Done { commits, deliveries }`; node-sync carries out the `Delivery` values: `Inbox` blob for an actor's inbox label (with the `Resend` that seals it again), `Direct` commits to a node, `First` placements before any other upload of the sync, `Certificate` copies under a home label, `Deposit` under a label the author does not write): `create_person(hosts) -> (Person { person, card }, Done)`, `pair(person, node)` (grant, or re-seal of a holder, plus the commits it needs, as one `Direct`), `paired(person, grant)`, `recover(card, lost, presync)`; `grant`/`grant_as(signer, ..)` (admin or invite grant; own secrets first; boxes), `demote`/`demote_as(signer, target, Demotion { holder, new, presync })` (explicit demotion with frontier, or self-removal; the target's rotation in the same commit), `presync_scope(target, holder, new)`, `PreSync::{Synced, Unsynced { proceed }, Backdated(t)}`; `accept_inbox(blob) -> (things, Done)`; `create_link(sharer, LinkSpec) -> (ShareLink, seed thing, Done)`, `redeem(link, grantee, single_use)`, `bear(link)`, `finalize_link(k, l)`, `revoke_joiner(k, l, joiner, presync)`; `create_label(group, hosts)`, `replace_label(group, old)`, `issue_step(group, label, head, fresh)`, `label_of`; `roster_snapshot(thing, signer)`, `roster_snapshot_due`; `move_to(t, owner)`, `refresh_deposit_seed(actor)`; `hold_key_actor(seed) -> tid`, `drop_key_actor`.
- API hooks (osis second half): `report(diagnostic)` (deduped like the engine's; kinds `NotSynced`, `Unsynced`, `Stranded` added), `owner(tid)`, `next_chunk(tid, &mut TreeReader)` (one chunk of a large value per call: the API's `stream`); `Event::Ephemeral` for local and remote ephemeral changes and fired signal aspects; `SyncEngine::{label_status, connected, set_hosts}`; the tokio driver runs over a `Shared` (`run_shared`: the osis handle keeps the engine behind its lock and hands actions over as `Control::Apply`; `run` owns it).
- Rotation: `ensure_rotated(actor) -> (Done, roles still uncovered)` (labeling calls it before wrapping, stamping or boxing under the actor; it must not encrypt under the roles returned), `rotate_eagerly`, `departures(actor)`, `give_own_secrets(thing)`, `reseal_due(actor, &dyn SyncState)` (node-sync implements `SyncState::complete_pass`), `reshare(actor, holder)` (manual), `drop_lost_secrets()`, `lost_due()`, `drop_lost_due()`.

## Store records
Local records (`*_local`): `y/` sync state (notes/sync.md), `seed`, `hlc`, `c/`+ID commit records (head: received, origin, dropped parts with what each keeps (`Meta::dropped`, `engine::index::record_head`, version byte 1); then the current blob), `t/`+tid creation records, `r/` receipts, `v/` value-less deltas, `p/` purge requests per aspect, `x/`+T timers, `s/` synced things, `o/` voided commits, `k/`+tid opened epochs, `g/`+tid+commit the `keys.0` parts whose held body wrote a keyset, any validity (`ix.keyset_parts`; kept when the body drops or goes missing, removed with the commit): `own_keys` = things with such a part valid (`apply::keys::refresh_own_keys`, on noting, validity flips, load), so an uncover keeps it and an invalid rotation drops it; a plain thing's leftover epochs in `k/` are reading-only overlays on its derived ones (`Core::own_epochs`/`epochs`), `l/`+tid the lost-access work list, `w/`+aspect key+commit+part the value-less residue of a delta whose body went at expiry or purge (`retention::make_valueless`, from its coverers' copies when the body was dropped as covered; joined by `rebuilt` beside the state, so an un-merge of a later write that superseded it in the state gives it back, order seed 24111; a part missing at expiry or purge has none: dropped, it reopens for a late copy, which joins value-less and drops again with its residue, `retention::takes_late`), `b/`+commit+tid pending boxes kept sealed by forgetting, `n/` linked frontiers, `u/` API records, `d/`+AK the local schema of each app AK (canonical form), `a/` aspect index, `i/v` the persisted index's rules tag. Store index tables `node/*` (rebuildable, `engine::index`): per commit one byte per part (valid, the rotation role it needs, a grant's overreach), box keys, keyed boxes per holder, epoch introductions, first box writes, snapshots per aspect with frontiers, writes carried by snapshots without their commit, perm's reading of each role commit (`node/edges`), saved walks (`node/walks`). Store kinds: aspect units (state = snapshot grammar with its pages inline, or for a paged state `[1, skeleton, [[set ID, path, encoding]*]]`: the state with its paged collections reduced to their reset and `W`; undo = what undoing each of the last local commits reads, `Fragment::footprint`), aspect table 0 (state pages: row key = set ID ‖ order-preserving bytes of the page's first dot, the first page the set ID alone; value `[first dot, next page's first dot, page]`), aspect table 1 (index of paged maps by key and paged sets by value: set ID ‖ keyed BLAKE3 of the key or value, links by content hash (`pages::ident`; key `Core::key_salt`, derived from the node seed) ‖ entry or element dot; a superset, rows of entries left keyless or elements left value-less by expiry or purge, and of those a keep-at-most drop takes out of the store, removed shredded, `pages::unindex`; rebuildable: written with the layout, the unit tag names its rules), aspect table 2 (placement of paged sequences, the whole placement order with hidden elements: layout in the comment above `Place` in `pages.rs`; exact when present: a write it does not follow removes the top, and a read finding it missing (or a row damaged) lays it out anew; rebuildable like table 1), counters, death records (body ID = commit ID), pending/parked commits, blob ciphertexts (pages, chunks, header-list trees).
In memory (`Core`, rebuilt by `apply::load` at open and after forgetting; a failed transaction that changed nothing keeps the derived caches): states cache with page indexes (`engine::pages::PageIndex`: paged collections by path, which of their pages are loaded), the journaled indexes (`Core::ix`, an `Indexes` whose commit and rollback the `indexes!` macro derives from its field list; `engine::journal`: `JMap`, `JSet`, `JSetMap`, `JNested`; `Groups` and the held set journal themselves): commit metas with validity and dropped parts, per-aspect and per-thing commit indexes, node-form ranges, parts invalid here per aspect, perm's held set (`engine::held::Held`: by target, by holder, by commit ID, owner -> owned, the things touched since perm last looked) + `Timelines`, pending reasons, value-less lists, secrets, `was.0` (both ways), `moved.0`, groups (`engine::groups`), `roles.0` entry keys, box keys and boxes per holder, epoch introductions, held snapshots with frontiers, writes snapshots carry without their commit.

## Readings fixed here
- **Counters**: reserved in the same transaction that applies the signed commit; nothing signed leaves the node before it is durable, so no counter is reused and no gap is left by a crash. Restored stores (spec/crdt.md §2.1): `SyncEngine::new` marks every labeled group unsure and `counters_step` (each step) keeps those whose labels have not passed completely (`label_passed`, since 0, peer wait from the start) in `Core::counters_unsure`; `Core::counters_sure` gates node form in `commit` (things created by the commit exempt) and `undo_in` (commit form there runs counters across deltas, which is why `unmake_one` joins its ops right after the undo's delta of that aspect). Adoption: `apply::examine` raises the counter to `hi` for every verified own node-form header (`Store::raise_counter`), `join_part` to own frontier `ctr + 1` for valid snapshots. A writer's lying frontier can raise it to the wire's 2^63 - 1, so `write::node_form_ok` also turns an aspect past `MAX_NODE_COUNTER` (2^62) to commit form (validity `lying_frontier_leaves_writes_spec_crdt_2_1`); the gap such a lie leaves stays: later node-form writes there are never received contiguously, so a revoke frontier never covers them and covers never drop them. Residual: an own lost commit whose header lists go by link raises nothing until its pages arrive, after the pass (`fetch_waiting`). A bare `Engine` (no sync layer) is always sure. Tests (each fails with its part off): osis `sync::restored_store_reuses_no_counter_spec_crdt_2_1` (gate and header adoption; a commit-form undo of a creation), node `crash::restored_counter_from_snapshot_frontier_spec_crdt_2_1` (frontier adoption), sim `restore_backup` (the checker flags counter reuse). Rejected: a per-open random source for durable writes (revoke frontiers grow per launch), restore detection by a store-instance id (hosts keep nothing per client), counters off local state (contiguity is what frontiers count). Commit form costs one `Absorbed` entry per commit in later snapshots, so the gated window must stay short: hosts down for long keep their labels' things in commit form.
- **HLC**: a writer exhausting `logical` within one ms moves to the next ms instead of waiting.
- **Pending "chain certificates missing"** (decided): the author's or an owner chain's `created.0` is missing, or the author is not on the touched thing's owner chain and no path of held edge writes and owner links leads from it to a thing on that chain (`validity::reaches`: searched backward from the chain, from a thing to its owner and its named holders (`Held::holders_of`), as perm's `roles_to_any`, so the author's owned things never enter it; a new record of a named holder or of an owner of held things bumps `Held::edges`, so record waits re-examine). Revoked authors keep their certificates, so their commits apply, judged invalid; re-grant re-merges.
- **Owner depth** (spec/permissions.md §1): `validity::too_deep` makes every delta but `created.0` invalid on a thing whose chain is not known to reach its key actor within `MAX_OWNER_DEPTH` links (deeper, or a record on it not held: forgetting a record never makes a deep delta valid); per delta, from creation records alone, so nodes holding different parts agree; `examine` stops waiting for the chain there. A deep thing's `roles.0` and roster snapshot writes never reach perm (`add_role_commit_in`). The writer refuses such a commit. Upgrade: a store holding deeper things (none known) quietly loses their non-`created.0` writes on rebuild, and perm gives them no ownership authority (`Owners::chain` returns `None`).
- **Prefix vs header** (spec/commits.md §4 last rule) is checked by node-sync where blobs are opened, for linked header lists once resolved (the pass); `ingest` takes plaintext.
- **Body** (decided) = one projection class of a commit: deltas sharing the reader actor (the thing if it has secrets of its own, else its owner), retention, expiry and delete-key indices. Its ID = BLAKE3(commit ID ‖ first aspect index of the class) keys the death records; first death = earliest, last = latest over its deltas; keep-at-most drops the whole class. Expiry and purge still drop single deltas (the commit is kept without them).
- **Validity**: re-judged, after a held-set change, only for the deltas on things whose timeline changed (`Core::stale_things`, `rejudge_all`; with the commits whose void, required-role or overreach inputs changed, `stale_commits`, among them parts `retention::uncover` made missing during the re-judge's own rebuild, so `rejudge_all` passes again while anything is stale; and everything after a rebuild at open, `stale_all`; a rollback restores validity flags with the journal): perm's `Timelines::update_touched` re-partitions around the things whose held inputs changed (`Held::take_touched`; a commit naming only things of its component skips that and continues the walk, `Timelines::append`) and reports the components evaluated anew (all their things) and those whose walk only went on or that only gained new leaves (`created.0` of things nothing names): for those, only the things authority flows to from the touched ones (`Held::reach`: owned things and targets of their edges, transitively). Writing a new thing re-judges that thing's deltas only; so does a grant to a holder new to every walk (perm `Timelines::append` joins it: scale `one grant with 10^4 commits held` 12 -> 0.8 ms). The re-judge (`Judge`) takes each commit once under the first re-judged thing among its aspects, looks owner depth and the timeline up once per thing, and answers an author's deltas from its standing tenure on (perm `Timeline::valid_from`, `delta_valid`'s re-grant case, asked once per (thing, author, role)) without a per-delta query: one grant at 10^4 content commits 26 -> 12 ms (same session, load about 15; 11-13 ms at load 15-20). A voided commit is re-judged alone. Un-merge is by invalid delta, not by author: every body (the current state counting as one) is stripped of the writes owned by deltas invalid here (`Fragment::remove_dots` with `Owned::owns`: node-form counter range or commit ID) before it joins, on apply as well as on rebuild, so another writer's nested write under an invalid creation goes on every node alike. Validity follows the held set, not arrival order (was issues/late-member-backdated-revoke.md: a holder offline through a revoke whose frontier missed a write applied the demotion before the item's `created.0`, which perm took as a new leaf and kept the walk, so the item had no demotion recorded and the write stayed valid there; now a new leaf takes its owner's demotion records, notes/permissions.md Implementation; tests: `apply/tests_order.rs` every arrival order, perm `incremental` late leaves, timed_dead.rs `late_holder_judges_backdated_revoke_alike_*`). **Un-merge cost**: where validity only fell (a re-judge with no part valid again and no snapshot part flipped on the aspect, a delta arriving invalid, a valid snapshot's body dropped), `atomic::unmerge_fell` removes every invalid delta's writes no held valid snapshot vouches for (`atomic::Unmerge`) from the state in place when none of them supersedes a write in it (`Fragment::dots_supersede`: a register, case, reset, `W`, flag or non-creation position write of theirs present in the state; the content of records they created goes whole either way, others' nested writes with it), loading and rewriting only the pages holding the fallen deltas' dots (their bodies, when held whole), or the whole state when a paged collection lies below a map entry a fallen delta created (it goes with every page, others' nested writes in pages without the fallen dots too: `PageIndex::below_entry_of`, seed 131013); exact since the state is the join of the held bodies under the old judgments, so a write only they superseded is the only thing a rebuild could add. A part arriving invalid, on apply or late (`join_late`), first joins its body stripped (its sequence records stay as hidden anchors, as a flip leaves them), then un-merges in place (`atomic::arrived_invalid`; `unmerge_paged_matches_fresh_spec_crdt_4_6` compares with a fresh node); an invalid commit's aspect whose part is not held un-merges too (from the state, `fell` = `None`: others' writes under its creations go; was: skipped, so they stayed when they joined first, `late_invalid_part_unmerges_alike_spec_crdt_4_6`). A valid snapshot held (on apply or late) carrying writes of invalid deltas rebuilds the aspect (they count again, others' writes nested under them with them; `note_snapshot_part`). Otherwise, and wherever something became valid again (re-merging needs the bodies: a register's earlier value, another's write nested under a revalidated creation, come back only from them), the aspect is rebuilt from every held body (O(aspect history)). A debug build checks every in-place un-merge against a rebuild; osis-crdt `unmerge_spec_4_6` checks it per delta on random histories. `scale.rs validity_flip_cost_spec_permissions_5_2` (release, 16 cores at load about 10, set of 10^4 one-element commits): a revoke flipping one add invalid 719 -> 40 ms (the rest is re-judging the component's 10^4 deltas; 28 ms with the re-judge above), an invalid add arriving 704 -> 4-6 ms.
- **Snapshot authority** (spec/permissions.md §5.2): a compaction snapshot's part is valid iff its author could write the aspect at it (`Judge::part`: `delta_valid` at its point, `Dots::Commit`, `required_role(ak)`, never the rotation role; `created.0` always). An invalid snapshot gives nothing: not joined on apply or late, left out of `rebuilt`, of deaths replays and of death carriers (`validity::invalid_snapshot`; walks moves seed 51999), covers nothing (`covered` -> `Some(false)`), its frontiers and `Absorbed` count as not received: the receipt record holds only commits' own counters and IDs, and `receipt::received` adds the held valid snapshots' frontiers at read time (demotion frontiers), only on counters of node-form commits whose header is held and `Absorbed` commits whose header is held, from the later of the part's and header's receipt (`validity::inflated_snapshot_claims_count_nothing_spec_crdt_8`); a delta wait counts a missing part as dropped when a held snapshot of any validity stamped after its commit lists it (frontier reaching a node-form part's counters, or `Absorbed` naming the commit; `receipt::listed`; owner decision (a), round 13: a forged snapshot can make a commit show partly until the part arrives, never wrong data), so the wait does not depend on validity flips or arrival order (`validity::listed_part_alike_in_any_order_*`, `part_listed_by_invalid_snapshot_applies_*`; sim `coverer_revoked`: a part W dropped under C's S2 and deleted never reaches A, which removed C first); frontiers stay valid-only for receipts (`validity::flipped_snapshot_frontiers_not_received_alike_spec_perm_5_2`); a snapshot dropped other than as covered (bound, purge, expiry) keeps its frontiers and `Absorbed` in its commit record (`Dropped::gives`, indexed by `ix.dropped_snapshots`), counted while the part is valid, dropped and not missing again; one dropped as covered keeps none (its covers reach them; `uncover` makes it missing when none carries it; a coverer dropped other than as covered carries while valid: its writes stay in the state, `bound_dropped_coverer_still_carries_spec_commits_5`) (`validity::dropped_snapshot_frontiers_count_spec_commits_5`). Purge keeps them too: the purged writes stay in the state value-less, so they are still received. A valid one vouches for every write it carries (owner decision "Snapshots vouch", notes/permissions.md): nothing is judged per claimed author.
- **Carried writes and vouching** (spec/permissions.md §5.2). A write's own delta is the one owning its dot (`validity::any_owner`: the node-form range holding it; for `Commit(C)` on thing N, C if commit-form with the aspect, else any held import of N listing C, `Core::imports`). Three cases:
  - **Valid snapshot copies govern** (owner decision round 13, notes/permissions.md Snapshots and history, was "a received delta supplies its own writes"): a valid snapshot's copies always join (no stripping on apply, late parts or in `rebuilt`; `covered` strips only an invalid snapshot body's copies of valid received deltas). Where a held delta and a held valid snapshot disagree under one of the delta's dots (`validity::misstated_in`, `CopyIndex::misstated`: `Fragment::copies_outside` but a value-less copy matches only when the delta expires, a deleted char always), `rebuilt` strips the delta's writes under that dot (`strip_forged`) and the snapshots' copies join by the copy order; under a dot any held snapshot (any validity) misstates it first strips the current state, so the held bodies give it again; it returns the misstating valid snapshots, which `rebuild_without` reports (`DiagnosticKind::Misstated`, deduped per snapshot and thing). Triggers: a valid snapshot part joining whose copies differ from the state under held-owner dots (`atomic::misstates_held`, a cheap check against the state: the state holds the delta's write unless a valid snapshot misstated it already; the rebuild judges per delta); a delta arriving after valid snapshots took copies of its writes (`uncarry` names them, `differing_copies`, `refill` rebuilds); a validity flip (rejudge rebuild); a valid snapshot's body dropped (`drop_part_as` computes `misstated_by` first and rebuilds without those writes: the held deltas give theirs again). Converges: every node holding the same valid snapshots reads the same, whatever deltas it holds (`walks::open_equals_rebuild_random_histories_forged` drops covered bodies too, seeds 961728, 961118; `validity::forged_copy_governs_held_original_alike_*`). A snapshot's copies dying on arrival die for it alone, as a deaths replay does: of a snapshot join's deaths only those of writes the state held before go to `note_deaths` (`atomic::held_deaths`, the state cloned first, only where a body has a relative bound; filtering by the snapshot's stamps dropped real deaths, order seeds 81002, 81023), `note_copies` dates the rest. Cost: a valid snapshot joining loads and walks the whole state to compare copies (`misstates_held`): measured (`scale::snapshot_join_cost_*`, 10^5-element set, one held delta, release, review) about +30% over main's join of the same snapshot (unbounded 290 to 375 ms, keep-at-least 590 to 725 ms; main's apply stripped the copies, so its join was near free), O(state) like the join and `note_copies` already were; within the rare-event budget, not pursued. Only valued misstatements are reported (a value-less copy is what an honest snapshot after a purge not yet seen here carries). - **Role-class content rules** are writer-side only: a received commit breaking them is applied and perm judges each edge write at its point.
- **`created.0` gate** (spec/commits.md §4): only things whose delta the commit blob holds or that the node syncs make it pending on an unknown `created.0` or chain; a thing neither held nor synced (another's private thing in a mixed commit) is skipped and its delta, if it comes later, joins late.
- **`created.0` minting** (spec/commits.md §2): `carried_records` refuses a durable commit whose `created.0` part is not exactly one minting (`write::is_minting`: one source, one stamp, equal to `mint_created` under the `creation` view); several commits' mintings join (two nodes persisting one ephemeral thing). Header validation refuses `created.0` in a durable snapshot or import, and `Engine::snapshot` refuses it, so no junk can enter a state kept forever. A writer delta already cannot carry slots or foreign stamps (codec); what the minting rule adds is refusing resets and untyped structure.
- **Late deltas** (`late_parts`, `join_late`): a late delta that waits (its `created.0`, chain, pages) is kept pending under the commit's ID (listed by `pending()` though the commit applied) and joined once it can be; an invalid one joins and un-merges as on apply (Validity); late `created.0` records and `roles.0`/`tenures.0` deltas reach perm as on apply (the commit's edge writes re-added from every held part), then held deltas are re-judged. Late `secrets.0` deltas are opened (observe_state) but do not establish.
- **Ephemeral kept apart past T** (spec/crdt.md §4.7): commits kept apart (`Remote::pending`, `invalid`) keep no part past its T: `keep_unexpired` skips those and sets a `remote.timers` entry for the rest, whose firing drops them (`expire_apart`). Durable pending records still keep expired values (issues/pending-past-expiry.md).
- **Cover residues**: a part dropped as covered and then made value-less takes its residue from its valid coverers' copies; `uncover` deletes that residue when the part goes missing again (the coverer turned invalid), so a later rebuild does not join writes no valid route gives (order.rs `cover_residue_goes_with_cover`). Such a node then reads as one that never received the body (it is purged, so no host serves it again); one that held the body at the purge (S invalid on arrival) keeps the body's value-less residue, so the two differ as any node missing a body at its purge differs from one that held it (spec/commits.md §5, spec/permissions.md §5.2 "counts as never received").
- **Re-examination** (`apply/waits.rs`): `reexamine` (after every applied commit, at open, on `set_syncing`, ticks) examined every pending commit again (read, decode, signature): a first sync where commits wait for their thing's `created.0` or a body's other part was O(commits × pending), 540 of 580 s at 10^4 (`scale.rs first_sync_cost`). Cost: liveness is `Fragment::holds_owned_write` (a set element's or map entry's tombstone, keyed by the creator's dot, holds no write of it: counting it kept an undone keep-at-most-0 entry's body to its grace bound, order seed 64197) with `Owned::owns_range` (stops at the first hit, never expands range records), cached per body and forgotten per aspect when its state changes (`Core::forget_live` drops every body with a delta on the changed aspect: a body's liveness spans its class, whichever aspect was asked; keying by the asked aspect alone left stale answers, test `body_live_spans_its_class_spec_commits_5`). A reader drops a live body at its bound with no carrier (spec/sync.md §5: the bound wins). Bounds follow liveness: a validity flip re-runs `check_at_most` for the aspect (`recheck_at_most`), and a due keep-at-most timer re-judges instead of dropping (a body that turned live keeps to its grace bound); a timed delete already sent cannot be withdrawn: a window, not a loss (timed_dead.rs `revived_body_uploaded_again_after_timed_delete_spec_commits_5`): the host deletes the revived body at the plain bound, and a right holder re-uploads it (fresh encryption, must-hold: live and uncovered) at its next resync (`resync_ms`, 60 s, while online; the host's sweep pushes nothing that marks the label dirty) or next sync; the flip replays the aspect's deaths (below), so a write revived because its only superseder turned invalid has no death and its body no keep-at-most bound, as at a node that never held that superseder valid. Readers see no gap: they hold the body or the state; a holder offline throughout judges the revoked writer's write alike when it returns (same test, `late_holder_judges_backdated_revoke_alike_*`). Before a due timer drops a live body, the sync engine writes its carrier (`Engine::due_live_drops`, `snapshot_first`), so a host-less label never lacks a copy of the live write. A body with no live write keeps the plain bound and needs no carrier; when the last live write of a partly erased body dies, its plain bound has usually passed and it drops in that transaction. Liveness is judged on the current state (`retention::live`, the tx form of `Engine::body_live`), not frozen at first death (a flag would add a state and depend on arrival order): the state is the join of the applied valid, non-undone deltas, so nodes that applied the same commits agree (dropped bodies leave their live writes in the state). Nodes holding different commits can disagree for a while (one already has the last kill and deletes at the host; the other judges the body live and must-hold); the killing commit goes up before the delete in the same pass, so the other node applies it on its next read. Privacy (spec/commits.md §5 says so): under keep at most, erased data (a deleted word, a whole erased text) persists in its body up to its bound (first death plus D plus `AT_MOST_GRACE`), or to the next compaction if sooner, at the writer and every reader holding it (and in the erasing edit's undo buffer, cleared when a body of the aspect drops), and at a host until a right holder next syncs after the drop; a writer going offline right after an erasing edit leaves the body at the host until a right holder syncs past the bound. Main dropped a fully erased body at the kill; now it waits for the grace (test `text_fully_erased_kept_to_grace_bound_spec_commits_5`). The read state loses it at the kill, and the drop shreds like any. `body_live` of a snapshot (`snapshot_live`) uses the same notion as `Fragment::live_writes` (no element or entry tombstone; counting them kept a snapshot of a since-removed entry to its grace bound, retention.rs `snapshot_of_removed_entry_no_live_write_*`): held, a carried live write is in the state by dot; dropped, Dropped snapshot liveness above. Residue: a tree whose node blobs no reachable host or peer holds keeps its thing's dropped chunks for good (the judgment waits for nodes that never come). A chunk is judged dead from the commits held, so a co-writer's concurrent reuse can lose it at a host (tombstoned, so never re-uploaded by ID). Repair (spec/sync.md §1): a `LogEvent::Deleted` of a non-commit blob gone from every host of the label queues it (`relink_pending`; with one host per label that host alone decides); `SyncEngine::relink_lost` calls `Engine::relink`, which takes the aspects of commits listing a held queued blob and, per field (`relink_field`; a field that fails, e.g. a blob not held, is skipped, the rest go), needs an own content commit whose delta trees hold it, takes retention, expiry and schema from the newest held commit linking it (the value rewritten), and writes only the large positions of the current value whose tree holds it (`osis_schema::link_positions`) with `Op::Put` (a register write, no reset) and `Mutation::fresh` (`Reuse::exclude` re-encrypts it and the nodes above). The repair is a plain write with a fresh stamp: it overrides a concurrent unseen edit of that one position and can bring back an entry whose removal it has not seen (notes/crdt.md); bounded to the affected positions and rate-limited. Back-off per aspect (`relink_backoff`, 1 h doubling to 7 days) in memory only: a restart allows one more immediate repair per aspect. An aspect held back keeps its blobs queued and `Event::Tick` retries when it passes. Not repaired: set elements and map keys holding links, values whose own delta was compacted, unregistered typed schemas.

## Open
- Large values: `read_large` reads whole (streaming only through `next_chunk`). Writing: an `edit` hashes its new items first (one tree per distinct item, held ones keep their link) and writes only those not held; `build_and_apply` drops from the chunk list (and the store) the fresh blobs the encoded delta does not link (`delta_links`). API seeks past the end clamp to the end (`io::Seek`); `StringReader::seek` refuses them.
- **Paged state** (`engine/pages.rs`): a state above `PAGE_TARGET` pages every collection of at least 64 elements encoding to more than 8 KB, at any depth below struct fields, enum payloads and map entries (`Step`, `Paths`; inside a paged collection's elements too); list elements and `Slots` slots are not stepped into (not a small extension: a list element's position needs the sequence's placement and its record's anchors, a `Slots` slot the register embedding, both osis-crdt work tied to the sequences item of issues/node-sequences-not-paged.md). The rest is the skeleton (`Fragment::reduced`). Lazy in memory: a session loads the skeleton, then what it needs: a read at a path (`Engine::get_at` → `Tx::ensure_paths`: the pages of the map keys along it through the index, the first page of each paged collection passed (it restores the entries the skeleton reduced away), of a paged sequence an index steps into the element's block and page through the stored placement, attached (`step_index`; without one every page), everything paged below its end), a write whose ops address map keys, fields or set values only (`pages::op_paths`: an add or remove by value addresses the value as a key step, found through the index; a key or value with struct or map parts anywhere on the path loads whole, since the crdt matches it as the writer's type projects it; a large key or value (above `CHUNK_THRESHOLD`, held as a link) is looked up by its link's content hash, `large::lookup_form`, also in `get_at`; `chunk_op` writes a large added element whole, matches a large removed one by hash and puts the held link (else a new tree) for a large key on a path), a join (`ensure_touch`: the pages holding the delta's dots; of a sequence the pages its records span, below); anything else loads every page (`Tx::load`). `Tx::set_state_touched` rewrites only the touched pages (`touch_of` = `Fragment::touched_paths`; a reset at or above a paged collection, a case change above it or another encoding writes whole) and the skeleton when it changed (whole once it passes `PAGE_TARGET`), splitting a page past 16 KB (pieces written shredded), dropping an emptied one, re-laying out when one element outgrows `PAGE_TARGET`. A dropped body (`Tx::shred_bodies`) and an expiry or purge (`Tx::strip_bodies`) rewrite shredded only the pages holding the delta's dots and the skeleton. Set ops by value in a 10^5-element set, each in a new session (`scale.rs big_set_by_value_cost`): 240 pages, 0.25 s before the value index; 1-2 pages, 0.8-2.4 ms after. A paged text or list keeps its placement in the aspect's table 2 (layout: the comment above `Place` in `pages.rs`): the crdt's cached placement in its stored form (`osis_crdt::SeqPlace`: every node with its span, creation, parent, HEAD flag, visibility and depth, in blocks with their visible counts, least depths and shifts listed in group rows beside the top; the dot → block map in chunks keyed by first dot; waiting anchors, broken-cycle nodes and a stamp at or above every position write's in the top). A session reads the top, groups and chunk list once (`held`) and the blocks and chunks an operation misses (`fill_place`): a placement held in part attached to the sequence held in part (`attach`, its cover the loaded pages' dot ranges) notes what it misses (stub blocks and chunks, records outside the cover, and any whole pass over the records held, which the sequence notes even after dropping the placement: `Seq::part`) and fails, the caller loads that and runs again. Reads by index (`Engine::get_range` → `pages::seq_range`) read the blocks covering the range and the pages holding their dots; a missing or damaged placement reads whole and lays it out anew (`rebuild_placement`). Joins (`ensure_touch`): the pages the delta's records span, then up to `PREFETCH` dry runs of the follow (`Fragment::dry_follow`, about one pass of follow work in all) loading what each missed, then the placement is attached and the join follows it. Ops by index (insert, delete, move, paste, several in one commit), an `Op::Edit` (what `osis::text` writes; `seq_diff::edit` resolves it at base's indices when the read matches base over the changed middle and 32 elements each side, else it is a look at every record: loaded whole; a list's whose items have large parts loads the elements at its window up front, `attach_ops` → `load_range`, and resolves only when the list lends their links there, Large values; else whole) and any op inside an element at an index (`step_index` loads the element up front, so `chunk_ops` finds a large value held) run on the pages loaded (`attach_ops` from `commit_in`) and run again after loading what they missed (`absorb`, up to `OP_RUNS`, then whole; each such whole load is counted in a cost span, `paged op whole: whole pass` for a layered follow or placement failing other than by a miss, `: every record` for an edit or presence looking at every record, `: runs` past `OP_RUNS`; the paged tests assert none). A local insert's follow takes its anchor from the placement (`Lin::placed`, not the anchor's record) and, stamped above the placement's newest position write (`newest`, kept with the top: a node's own commits), places right after the anchor without its children's edge stamps (`slot`), so a cold insert loads only the page its new record goes to (`text_range_and_edit_cost`, release: local insert 2 → 1 pages, 2 placement blocks read instead of 1, 4.2-5.3 ms at load 24-35 against 5.1-5.3 ms at load 9 before; a received insert 2 → 1 pages; rows and bytes written unchanged, the top 34 B larger). A sequence's pages target 3 KB (`SEQ_PAGE_BYTES`, other collections 8 KB): an op decodes and rewrites each page it touches whole, one record per visible element, so at 8 KB (about 8000 chars) page decode and join were most of a cold edit's time; above the store's 2 KB inline limit, so a page write leaves its neighbours' leaf alone. A whole load (`ensure_set`, `load_all` → `place_whole`) loads every block and chunk and makes the stored placement the sequence's cache (its text's chars set), so a whole session's ops and joins follow it; not while a change is under way (`pending`, from `ensure_touch` to `write_touched`: then a whole pass). `write_touched` writes what the followed placement changed against the stored one (`SeqPlace::diff`: blocks, gone blocks, chunks, chunk list, changed groups, top), a whole one not descended from it whole, and anything else (a reset, a strip, a shred, an un-merge, a follow fallback or miss) removes the top (`invalidate_placement`). The stored order equals a whole pass whenever present; its node split may be finer than a whole pass of the records as reloaded (pages drop deleted chars, so decoding merges their records into range records), which leaves the order and the ops' writes as they are. Oracles: `seq_placement_differential_{text,list}_spec_crdt_6`, `..._after_reset_...` (every stored page holds whole records), `seq_cold_edits_keep_placement_spec_crdt_6_1` (cold ops, two-op commits, received concurrent deltas; deltas equal the whole state's), `seq_whole_session_and_hostile_delta_spec_crdt_6_2`, `seq_placement_damaged_rows_spec_crdt_6`, the crdt's `partial_placement_follows_like_whole_spec_6`, `index_ops_on_partial_placement_match_whole_spec_5_7` and `partial_placement_skew_piles_and_joins_spec_6_1` (skewed clocks, sibling piles). Costs at 10^5 chars, each in a new session (`text_range_and_edit_cost`, release, a loaded box): received insert 94 → 9 ms (13 → 2 pages), read by index after edits 150 → 11 ms (nothing laid out anew), local insert 2-7 → 8-16 ms, delete 7 → 2-8 ms, move about 200 → 20 ms, undo 8.6 ms (1 page); store bytes per cold edit about doubled (12-23 → 28-37 KB: the dot-map chunk and block sit in other store units than the top; a move 45-50 KB). Later (seq-edit; release, one binary per page size run alternately, load about 22): a text session's edit (`Op::Edit`, 2 chars replaced) in a new session about 200 ms whole → 23 ms, 2 pages; 8 → 3 KB sequence pages: local insert 34 → 17 ms, delete 30 → 12 ms, move 65 → 30 ms, edit 41 → 23 ms, first whole read unchanged (0.39 s); store bytes insert 30.5 → 32.4 KB, delete 30.9 → 29.4, move 47.3 → 44.0, edit 43.2 → 40.0. Store rows per cold insert (`OSIS_SCALE_ROWS=1` prints them): the placement table's leaf with the top and groups (about 5.8 KB) and the block's leaf (4-6 KB; a chunk's when the dot map changes, a move several group rows and blocks), the page, the commit record and index leaves (about 9 KB, as before the placement), the unit, a key-tree node. Still whole: a list edit whose window the list does not lend, an edit whose base no longer matches the read near its change, a `Slots` text.
- **Streamed apply** (`apply/atomic.rs` `joins`, issues/durable-decode-bound.md step 3): `examine` decodes whole only role-class and `created.0` parts (`Parts::whole`: perm, rotations and creation records read them whole); every other part is checked by `osis_commit::stream_part` with a callback keeping nothing (carried writes stamped after the commit are refused there) and streamed again at apply (`each_piece`: the transaction shared through a `RefCell` between the page source and the join; a failure then is `Corrupt`, a local error). Each piece joins (`join_into_state`) and its state pages are evicted (`Tx::evict_pages`: written already; not while the aspect pages a sequence, kept whole for its placement). A piece resetting or re-encoding a paged collection joins a page at a time (`pages::join_reset`: skeleton joined, each reached page joined under the two spines along its path, `Fragment::spine`/`reaches`; re-laid out whole only when a collection changed encoding with elements left or lost its position (pruned by the reset: no set may outlive its position, seed 262014), an element outgrew a page or the skeleton the unit; whole as before for paged sequences, collections paged inside another's elements, or another encoding above a paged collection). Per part across pieces: carried writes, a valid snapshot's vouching (writes of invalid deltas; misstatements against the state before the part, `copies_before`: a second read of the snapshot, and the whole state only when it may copy a held delta's write), deaths (kept only where a body has a relative bound; a snapshot's filtered by the stamps of the state as loaded for each piece), an invalid delta's join and un-merge per piece (the debug check against a rebuild runs after its last piece: before it, valid writes nested under its creations may still sit in pages a later piece loads, seed 262035); a local commit's undo footprint is the join of its pieces' (`undo::footprint`, a pass before the join). The pre-streaming join is the test oracle (`apply/oracle.rs`, `Core::whole_apply`); `apply/tests_paged.rs` runs random histories in both (tier 1 one seed; `paged_apply_matches_whole_large_spec_crdt_8` 24 seeds, each state also reloaded from the store after every step: the cache can hide what the store lost). A record on a paged collection's path whose content is all paged keeps its creation only in the set's keyed path (the skeleton drops it); every write of the set takes the path again from the joined state, a page of each touched set loaded to hold it (`PageSet::path`; an element-less `W` delta wiped it before that), else a creation arriving after the content (a delayed fill) was lost to the store, in both worlds. Piece order is immaterial to the state (joins commute); skipping a piece's page write is caught, in the reset path by asserting the stored pages hold nothing their skeleton prunes (`Engine::stale_page_writes`: loading prunes again, so reads hide it). `tests_paged` also runs hostile paged snapshots (late carried write, keyed removal, unknown encoding, missing pages: the same error or outcome as whole), misstating ones, an invalid paged delta, and an apply failing midway after spilling (`Core::piece_fault`: nothing left). A cached state is `None` exactly when the whole state is empty, as a rebuild leaves it (`Tx::kept`): an empty loaded part loads every page first (rare: an un-merge emptying all that is loaded). Cheaper rules were wrong: the skeleton drops a record holding only paged content, so an empty loaded part need not reach a collection whose pages hold elements (a rogue's lone unpaged key un-merged dropped a valid paged map, review of paged-failures), and an emptied first page stays (seed 262094). Keeping the path's records in the skeleton instead of `PageSet::path` does not work as plain crdt data (paged-skeleton, rejected): a record whose loaded content is only an emptied collection is crdt-empty, so `prune(None)` (every un-merge and strip) drops it, and a join into its struct replaces the empty stub (`join_into` on an empty self), both while the pages still hold its elements; it needs a non-lattice "paged" marker in osis-crdt (codec, equality, prune, clearing) or a page loaded under every record an op touches, neither simpler than the re-take.
