# Chat
> Summary: Chat as built on design E (notes/chat-designs/e.md): crate `osis-chat` (core/chat) over the `osis` API, and `osis chat`: one ownerless actor per chat, members hold write, a message is one kept write on `chat:msgs:y<year>.0`, the sender the verified actor. What is built, what the app layer decided, what is left out, costs. Kept from the old pattern: rotation costs and the owner's decision on them.

## As built
- **Create** (`create`, one flow): `create_ownerless(me)`, `required.0^` (`chat:msgs:` the message rule; the empty prefix the plain default, so `nobody` junk on another aspect is invalid; `keep` true), `chat:settings.0^` (name, edit mode), `make_group`, `sync`. A host must take it by label or `--admit open`: `admit own` does not.
- **Members**: `add` is `share`; a link is `make_link`, `join` is `redeem` (a link joiner holds through K: `members` lists K, not them). Moderator: `Role::Admin`; all admins equal. `kick` is `demote`, keep filled from the default, `Some(false)` erases; `purge_member` is `purge_author` per year. `leave` removes every edge the person holds the chat through (a link joiner's is on K); the admin's following removal that audits backdated posts is not automated. Kicking a link joiner ends the link for those who have not redeemed it (`revoke_joiner`): make a new one.
- **Message**: `replace`, never `set` (an equal `set` writes nothing), of one scalar: CBOR bytes of a map, `0` text, `1` original, `2` prior, `3` name, `4` reply-to (a `replace` of a map leaves state per entry, so writes on a long aspect grow: 0.5 to 1.2 ms over 4000 writes, flat with a scalar). An id is `YEAR/TS/COMMIT`: the aspect and the place, so a reference needs no scan. Retention and expiry come from the rule, filled by the node.
- **Name**: in the signed body, per message: the sender's own word, nobody can name another's messages; no registry. Tid beside it is what is verified. CLI: `--from` or `OSIS_CHAT_NAME`.
- **Read**: `entries` merges the years (creation's to next year's) by `(ts, ID)` both ways, no tie of year to stamp. `Timeline::older` goes from the newest: it has then seen every edit of what it reaches, so a page back costs the distance from the newest, not a lookup per message. `since(after)` goes by arrival at this node (`received`, then `(ts, ID)`), not by stamp: a post made offline is stamped before what the reader has seen and still comes after the cursor. It reads the whole history each call (no arrival index; about 0.2 s at 10^4 messages), so it is for a reader that comes and goes: an app showing a timeline uses `watch`. An edit of an older message comes as that message again under its id; a deletion of an older message moves no cursor (use `watch`). Limits: an entry arriving in the cursor's millisecond with a lesser ID, or after the node's clock jumped back past the cursor, is missed. `cursor` is this node's: not to be carried to another. `find` reads back to the original. Others' invalid writes are hidden; one's own show `valid: false` with the text, for a re-send.
- **Edit**: a new message naming the original and every earlier version; honored only if the original is here, is no edit itself and has the same verified sender, else it is a message of its own. Newest by `(ts, ID)` wins. Under `EditMode::Purge` a second commit purges the old (a commit with a request carries no expiry, so never the same commit). Named versions' tombstones are the message's, so an edited message shows once.
- **Delete**: `purge_commit` of every version known, one commit. Refused locally without the right (a request without it drops nothing). Tombstones of permanent deltas reach new devices and newcomers. Purge sets from `Options::purge`.
- **Disappearing**: per chat, the rule's expiry; `set_disappearing` writes `required.0^` whole. Leaves kept copies too.
- **Told**: `on_rejected` is `OwnWriteInvalid` per commit.
- **Thin client**: reads and watches over the port; with its own write edge it is its own sender, so it cannot edit what its person's device sent.

## Left out
- Unbuilt core: adding without history (issues/history-less-grant.md), stopping a fetch short of old messages (issues/partial-history-fetch.md; a label does fill newest first, so old messages reach a new device late, each past a cursor), a kick past about 2.4×10^5 messages of one member (frontier heads), factions.
- Not done here: reactions, read marker, typing, hidden set, `chat:next.0^` segments, attachments, the leave audit, listing link joiners in `members`, who deleted (a tombstone has the request's commit ID; nothing looks up its author but the commit query), `osis chat join` and `kick` through a daemon (`redeem`, `demote` not carried: stop `serve`; issues/cli-proxy.md).
- Known and small: an edited message deleted leaves a tombstone per version (the link was in the purged bodies). A watch hears an edit under `Purge` as an edit and then a deletion of the old version: a read tells them apart. A concurrent edit landing after a delete brings the text back on the versions it did not purge. Re-adding a member revives posts it made while kicked (a design E forced answer; `kicked_while_offline` asserts it). A kicked person's new device gets nothing, its own messages included.

## Costs
On the sim (`--release`, every node in one process, `scale_long`, `scale_small`, `scale_post_read`):
- 10^4 messages, 1 member: 624 B up per message; a local post at the end 8.8 ms, its pass included; newest 50 read 1.5 ms; all 10^4 by pages 0.2 s; `find` 5000 back 0.36 s; a new member's fetch 23 s, 6 MB down; a kick 3 s.
- 20 members: joining took 17 s; 2000 messages did not finish in 10 minutes. 100 members: joining alone passed 20 minutes. Per-pass cost grows with members and people met: issues/held-actors-per-pass.md.

## Rotation costs (kept from the old pattern)
- A read+write rotation costs 2.7 KB per remaining holder (`scale.rs` `roster_removal_cost`: 272 KB at 100 writers, 2.70 MB at 1000; 1.05 s to commit at 1000). Downloads multiply by the holder count, only on removals.
- **Owner decision: accepted; keep the simple format.** Cheaper only by wire-format changes, both declined: the header once per commit (a second fetch per message); one KEM key per actor and one box per holder for all roles (done plainly gives read-only holders write and admin secrets; the safe variants make role separation classical-only, or delay reads after a lower-role grant). Removals are rare, groups of hundreds are rare, simplicity and the post-quantum promise win.
