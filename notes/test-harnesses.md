# Test harnesses
> Summary: How to run and replay seeded tests (env vars through `osis_base::testenv`, seed runners, replay lines, the property list), copied worlds and cached setups, the debug rebuild, index and verdict checks every test runs, why a thing is kept and row dumps, delivery by sync ID and sealed `LocalPeer` delivery, loop guards, the store-contents differential, measuring old against new (icount, cpuprof, callgrind), the default-test cost (what is in place, per-test profiles), the reference-graph mutation audit, and harness footguns.

## Env vars and seeds
- Harness env vars (`OSIS_*_START`/`_SEEDS`, `OSIS_PERM_SEED`, ...) are read through `osis_base::testenv`, which panics on an unparsable value, zero seeds, or any set `OSIS_*` variable not in core/base/testenv-known.txt (policy.py keeps that list equal to what the sources name: add a new variable there; read at run time, so adding one rebuilds nothing). A throwaway probe variable is `OSIS_PROBE_*`, exempt from the list and refused by policy.py while left in.
- A set variable and an overridden range are echoed past libtest's capture, so they show on a passing run: check that line, not only `1 passed`. Per-seed output needs `-- --nocapture`.
- `OSIS_FULL=1` runs a property's large size (release checks only); its small size, the gate's, is a tenth (`testenv::large`, at least one seed); explicit `_START`/`_SEEDS` override both.
- **Every property and its variable**: `python3 tools/test_select.py --all` lists every property test by crate and prints the command with every `OSIS_*` start variable the gate sets. Each harness prints its own replay line for a failing seed; use it as printed.
- **`_plain` and `_large`**: a seed runner is a property, never a default test (notes/testing.md, When tests run). Its `_plain` runs a fixed sample (a covering set where one was chosen by planted faults) and reads no environment: the quick check of a change to it; its `_large` reads the range (`--ignored --exact <name>_large`). The replay line names the `_large` where it checks a seed as the `_plain` does, else the `_plain`. `held_set_decides_plain` reads the range itself (its `plain` size), beside `held_set_decides_exhaustive`.
- Engine lib harnesses: `cargo test -p osis-engine --lib <path> -- --ignored --exact`; a copied binary from `tools/bin-at REV OUT --lib osis-engine`, run from `core/engine`.

Crate-wide seeds:
- **osis-crdt**: every `testutil::rng(seed)` (fixed-seed loops and proptest cases alike) samples other runs with `OSIS_CRDT_SEED=<n>` (a splitmix hash of n xor'ed into each run's seed; unset, the committed seeds); a panicking test prints the effective seed. Its `_large` properties take `OSIS_CRDT_START`/`_SEEDS`. `OSIS_SHRINK=<loop seed> cargo test -p osis-crdt --lib -- --ignored shrink_script` (with the same `OSIS_CRDT_SEED`) shrinks a failing `fuzz_seq::random_scripts_replay_spec_5_7` script and prints it.
- **osis-perm**: `differential`, `queries`, `incremental` sample other histories with `OSIS_PERM_SEED=<n>`; each property run is 16 shards on scoped threads, shard i seeded `seed ^ i << 40` (fixed count, so a failing seed reproduces anywhere; the panic names the shard's seed). Its runs print counterexamples as made; `OSIS_PERM_SHRINK=1` shrinks them.
- **order harness** (`held_set_decides`): `OSIS_ORDER_START`, `_SEEDS`, `_SEED` (one seed), `_LEN`, `_CLOCK`; `OSIS_ORDER_SHRINK=1` shrinks each failure (`order::shrink`: ddmin chunks, halves first, at most `SHRINK_CANDIDATES` candidates, each stopping at its first failing check; a candidate counts only when it fails as the original did, `failure_class`: the check and what differed, orders and numbers aside, so it cannot drift to another bug, whose first line it prints once per kind; `OSIS_SHRINK_MATCH=<text>` keeps to failures containing the text instead, `OSIS_SHRINK_ANY=1` to any; a `settled` history's tail stays whole, so such a shrink still replays its settling in every candidate), and prints the history as Rust a scripted test compiles (`rust_of`), `OSIS_ORDER_STATS=1` prints each history and the tallies, `OSIS_ORDER_DUMP=1` explains a failing node: the packs with each header's purge list (a `Commit` item names the packs it matches), per ingest of the failing order each read that changed or went absent and each commit whose index entry changed (a part dropped while invalid shows its `Invalid` drop before it reads `missing`), and index differences against the keep-everything node (notes/test-properties.md, Held-set property). For a node-holds-or-drops difference, a dump of the shrunk history usually names the cause; probing the drop decision beats shrinking further.
- **sim**: notes/test-sim.md, Replaying a seed.

## Seed runners (`osis_base::testenv`)
- `run_seeds(name, seeds, visible, replay, f)` (and `Seeds::run`, which announces an env range first) runs `f(seed)` for every seed on a thread per core (`OSIS_SEED_THREADS` overrides, one variable for every harness), a panic counting as its seed's failure. Each failing seed prints with its replay command as it fails, a progress line every 60 s, a summary, then a panic listing every failure in seed order. A multi-seed run goes through it, not a serial loop.
- **Hung seeds**: a seed whose thread used `OSIS_SEED_TIMEOUT_SECS` (default 600) CPU-seconds, or no CPU for that long (blocked), is marked hung and a new thread takes its place. CPU time, not wall: under load a 5 CPU-s seed can take 700 s wall. A lower value (`OSIS_SEED_TIMEOUT_SECS=60`) names a hung seed early in quick runs (ephemeral churn). A hung thread prints its backtrace at its next `testenv::checkpoint()` (`LocalPeer::sync`, the sim's step loop). It cannot be stopped: when the rest is done with hung seeds still running, or as many hang as there are threads, the runner prints everything and exits the process (101).
- `run_jobs(name, jobs, threads, visible, label, f)` is the general runner (sim-sweep and `run_seeds` use it, so a livelocked sim seed is named). `par_map`/`caught`/`threads` are the building blocks. `Cpu::now()`/`secs_since` reads the CPU spent on a thread's work, the threads `par_map` and `run_jobs` ran for it included (a test's own cost beside others in one process); `run_jobs`' summary line ends with its jobs' CPU-s, which the gate's summary lists per property (notes/gate.md, The summary). `Permit` is one of the process's permits (a thread per core); `pooled_map(items, threads, f)` is `par_map` with each call holding one, so concurrent tests and a run's seeds and their parts share the cores (osis-perm's shards, the order harness's seeds and orders).

## Copied worlds
A setup many tests share is built once per test process and each test gets an exact in-memory copy of the live world: it goes on as the original would (same next commit IDs, rng draws, connections, queues, memo hits), so a test cannot tell it from one it built. Reopening stores is not a copy (every node restarts, reconnects and syncs again).
- **Adding a cached setup**: wrap the builder in `LocalPeer::cached(key, || (peer, extra))` (or `osis_base::copying::cached` for another world type).
- **Mechanism**: `osis_base::copying::copying` scopes one world copy (`copying_reseeded(salt, f)` reseeds its generators, for the sim's shared setups); inside it `remap` gives every shared `Arc` one new handle, so the copy's parts share what the original's did and nothing points back.
- **Hooks** (test-only, `#[doc(hidden)]`; policy.py keeps them out of product sources, because two live copies are one node twice and reuse nonces, counters and commit IDs): `Engine::test_copy(clock)`, osis-store's (`Store`, the cipher store, roots, pager), `Store::test_copy` over `Backend`/`RootStorage::test_copy_boxed` (memory ones only), `NodeRng::test_copy`. Plain `Clone` is derived on data; the types owning identity, rng or a live store copy only through these hooks. Harness copies: `Peer::copy`, `LocalPeer::copy`. Engine event receivers are subscribed again with the unread events (`Engine::test_subscribe_with`); commit listeners are not copied.
- No `osis` handle copy: no osis-level harness shares a setup. A setup that closes and reopens a node is not cached. Real-runtime tests are never copied.
- Differentials: osis-engine it `copies`.

## Debug checks
These checks run inside every debug-build test, so every test is also an incremental-equals-from-scratch test (notes/test-design.md). None samples: each runs at every size, and every engine's history ends checked. A whole check (one costing O(everything held)) runs once at the end of the history, never per transaction, where it would make a test's cost grow with n squared; per transaction runs only what costs about what the transaction did. All are invisible to scale counts (`costs::paused`, `osis_perm::uncounted`).
- **Rebuild check** (`apply::atomic::check_rebuilt`, run by `Engine::run` before the index persists; the comparison is `check_states`): a touched aspect's state must equal `rebuilt` (exactly the join of held bodies, invalid writes removed, spec/crdt.md §4.6), compared encoded, with the caches derived from it (value-less list, snapshot bounds, references). Checked in the transaction: an aspect where a held part's status changed, a part arrived not valid and whole, or the state was written with no new commit naming it (each such change is a rebuild, so the check costs what the change did). An aspect only valid whole joins or covered drops touched (`shred_covered`, the state left as it was) waits in `Core::unchecked_states` for the end of the engine's history (a check per join would cost O(the aspect) per commit); a later rebuild of the aspect rewrites a wrong state unseen (Cost, below). A test hook writing a state no body gives sets `Core::unchecked_tx` (nothing it touched is checked). A failure panics with the differing Debug lines.
- **Index check** (`Engine::check_index`): an open from the persisted index and a rebuild from the commit records, each into a fresh `Core` on a clock stopped at the last transaction (the index is as of then: a timer due since has not run), in a dropped store transaction, must equal the running node's index (`Core::same_index`, held set and role timelines included), after the node closure walked afresh (`check_closure`) and the states left unchecked; the open reads no blob and judges every part as held (`misjudged`). It also asserts that an open decodes no commit header: judging anything at load from headers (`LazyHeader::arc()` decodes at once; clone the `LazyHeader` and deref only where the record is held) fails it, often only in node properties or the sim. The fresh cores borrow the node's decoded records (`Core::decoded`: a decode is a function of the record's bytes, compared at every hit), so the rebuild judges everything again without decoding it again.
- **Verdict checks** (`Engine::checked_verdicts`, at the end of history after any transaction, and inside the index check): every held commit's flags are what judging it now gives (`validity::misjudged`), then every re-grant bound a role timeline memoizes, carried over `extend` or asked by that judging, is what a search at every change finds (`Timeline::check_first_held`). Per re-judge only the touched part (`misjudged_on`): the commits on the things whose inputs that re-judge took (`stale_things`, `stale_under`), which catches a verdict wrong only for a while (later healed, so the end never sees it; an addendum's thing left out of the re-judged set failed 4 tests only this way).
- **The end of history** is the engine's drop (`impl Drop for Engine`, debug builds): the verdict checks, then the index check if a durable transaction changed a state or a part since it last ran, else the states left unchecked. Not under `OSIS_NO_END_CHECKS=1` (Why kept and row dumps), nor while a panic unwinds, a load is half done (`Engine::loading`), a write's outcome is unknown, or the store fails (a crash test's: `Error::Store` ends it quietly). A copy (`Engine::test_copy`) starts checked: its original checks their shared past. An engine lib test editing an index in memory sets `Engine::index_poked`. `Engine::check_every_tx` (tests, by hand) runs the index check after every changing transaction, to find the one that diverged; a reproducer whose point is one moment calls `check_index` there.
- **Cost** (instruction counts): the rebuild from the commit records is about 15% of the engine lib default tests, the open about 5%; the rebuild re-judges each engine's whole history once, so properties of many short multi-peer histories pay most (`deep_departure_holds_large`, `nothing_before_a_cut_reaches_its_holder_plain`: 6-peer worlds, each peer checked): issues/index-check-rebuild-cost.md. Rejected: sampling by transaction counts (1, 16, 256 per open, joins past powers of four from 4, covered drops at the 1st, 2nd, 4th ...): it checked most short histories and copies only at their first transaction, so no small test saw a fault that grows. Checking an aspect's first deferred change at once as well: +4% more on the properties, for faults a later rebuild hides. Checking per transaction only the index rows it wrote, against a derivation of those rows: blind to a row the transaction should have written and did not, the class the rebuild finds (an exact from-scratch derivation per transaction, compared on every index table the transaction changed, caught originals left out in 17 tests of the rebuild's 37, a stale `by_epoch` entry in 24 of 50).
- **Planted faults** (`tools/mutate.py`, engine lib and `it` default tests, tests failing with no index check / the open alone / open and rebuild): unindexing a rotation leaving its `by_epoch` entry 1 / 50 / 50; an edit's place left out of `originals` 16 / 16 / 37; an addendum's thing not judged again 22 / 24 / 24; an account's moved epochs' commits not judged again 38 / 38 / 38; an overlapping counter's other commit not judged again 10 / 10 / 10; a covered drop wiping the state (the rebuild check) 84. Caught by no test: a forgotten addendum's thing not judged again, a dropped part missing again not judged again.
- **Planted verdict faults** (`tools/mutate.py`, engine lib and `it`, perm `it`; tests failing with the end check alone / with the touched check too): commits acting for a re-judged thing left out 2 / 2; an addendum's thing below a moved timeline left out 0 / 4; commits acting for a moved thing left out 1 / 1; commits whose author's role moved left out 65 / 119; their parts on things below left out 64 / 119; `first_held` always from the beginning 456; its replay never raising a role 447; never searching again at an expiry or a narrowing 1 each (perm `regrant_replay_equals_search` alone). Caught by no test: a carried re-grant answer kept at or past the first change that differs (`Kept::carry`, `inserted`, `extend` and `add_leaves` keeping answers on new things), a replay's raise ignoring the holder's own level.
- What the checks have caught, each incremental-vs-from-scratch on an unusual path: by the rebuild check, a fallen purge's register keeping an older value-less write, a snapshot's hidden-anchor copy not vouching at join, an invalid text delta leaving an empty record, a forged snapshot's key-erased remnant, paged states dropping chars the crdt keeps; by the index check, equivocating commits of one range kept by arrival order (`validity::overlapping_counters_spec_commits_4`), a node's own rotation not reading the history box its secrets open, derived-epoch adoption by arrival order, an account switch's epoch residue, a destruction's dropped keysets not rebuilt.
- Not covered: a `node/perm` row left stale when a destruction rewrites a role commit's record (no reopen follows a destruction's rewrite).

## Why kept and row dumps
Debug builds only (`#[cfg(debug_assertions)]`), for a count, retention, role or read test that fails.
- `Engine::why_kept(t)` (osis-sync: `World::why_kept(i, t)`): why `t` is still held, read from the retention rule's own walk (`retention::needed::search` over `needs` and `rooted`, the functions `settle` uses, so it cannot drift from the rule): rooted (in the node closure, with its tree path of strongs from the node root and each step's context), or the chain of needs (a strong from where, a held or pending commit it signed, a missing part, a holder, a profile) to the first rooted thing, or that nothing rooted needs it and it goes at the next pass end.
- `Engine::rows(prefix, tid)` (osis-sync: `World::rows(i, prefix, tid)`, the engine's and the sync store's local rows): each row's family (as `local_census`), key decoded (known tids `t:`, held commit IDs `c:`, text, hex), the tids it names (directly or by a held commit's things) and bytes, filtered by family prefix and by tid. `Engine::describe_rows` describes another store's rows by the same engine.
- `Engine::why_role(t)` (osis-sync: `World::why_role(i, t)`): the node's role on `t` and its secrets, read from the rule's own code: the role `tickets::role_on` gives and the role commits' (`rotation::role_here`); per identity of the node (its account, itself, held key actors) its `role_now` and `keyed_role_now` and the widest current path to `t` (direct, chain, account), each edge by the role commit in force (`c:<hex>`) or the record edge; each held ticket's word, whether it counts and why (accepted, a sync word, or no held role commit reaching its holder: `Held::upstream`); with a dependent thing, the same for its independent; then `lost_due`'s clauses for that independent thing without its side effects (`rotation::lost::explain_due`: held secrets per role and epoch, `?` reading-only; over-held, loss seen, judged lost, by an `until` alone, own self-removals waiting; DUE or the clause that holds it off).
- S1 (`growth::releasing_own_things_*`, the grant arms) prints on a mismatch the rows of the differing families a fresh world's node lacks (same seed, so the same roots) and `why_kept` of each thing they name that the fresh node does not (`growth::leaked`). The sync differential's role and read clauses (`history::closure_clauses`: a node reading a thing unlike the model or the reference, its sync set holding it unlike the model) print `why_role` of the failing node and thing.
- **Replaying without the end checks**: `OSIS_NO_END_CHECKS=1` (`testenv::end_checks`; by hand only) skips the sync differential's checks at quiet (`history::check`, so `differential::holds` and every scenario calling `check` return their world, and `World::run`'s own, `sources_are_members` and `unlogged_must_holds`) and each engine's end-of-history check at its drop, so a scratch test replaying a failing seed can inspect the world (`why_role`, `why_kept`, `rows`) instead of panicking first. It prints `history::check skipped` past capture. Never set it while shrinking: a candidate whose failure is the check then passes.

## Loop guards
A fixpoint loop that a bug could keep going forever panics in a debug build instead of hanging (ostrich has no gdb): `osis_base::loop_guard::LoopGuard`, fed each round's progress, panics past a bound derived from the loop's size, naming the loop and its last 4 rounds. Guarded: node-sync's settle (`Node::settle`, the modules acting per round; 12 × (sync IDs + connections + 1)) and `LocalPeer::wake` (the commits each round ingested and whether the engine moved; (entries kept + 1)²). The sync `World`'s own loops (`run`, `advance`, `flush`, `step_or_wake`) each deliver per round, so its delivery cap (`World::cap`: `RULE_CAP`, `STORM_CAP`) bounds them, and it checks each step's settle rounds against `ROUND_CAP` after the step. `LocalPeer::sync_all` stops at n rounds; `deliver_sealed` ends when a round opens nothing.

## Delivery by sync ID over `LocalPeer`
A node takes content only of things in its node closure; content of another thing waits under Pending storage (spec/commits.md §4 Outside the node closure), and a `LocalPeer` carrier never goes. So `LocalPeer::sync`/`sync_all` send what the sync IDs the receiver syncs carry, decided at the sender by the product's own rule (`packages_for`/`packages_under` over `Engine::carried_under`, `sync_bodies`), again under the sync IDs it comes to sync in the pass (a grant or rotation moves them). A sender's packages are built once per state of its engine (`SyncMemo::whole`: each commit packaged and decoded once), and each set of sync IDs only trims those (`sent_parts`, a rewrite where parts go): building them per receiver, with a decode per package, cost 40-50% of `deep_departure_holds_large` and `rotation_holds_large`. Certificate parts (`Engine::certificate_parts`) go to every node: they stand for the routes the harness does not play (contact cards, links, ticket fires, a grant under its holder's sync ID, pairing), and a node keeps of them only what it needs. Hand deliveries pick the same: `packages_for(from, to)` (the receiver's sync set as it stands; engine `it`: `common::packages_for`, `package_for` for one commit, panicking when nothing the receiver syncs carries it), `LocalPeer::packages_to` (its sync set after a sync, on a copy of the world: a grant among the packages moves it; a fresh reader's sync set too, which its grant alone does not move), `packages_to_peer` (a node apart, on a copy), `common::packages_for_peer` (a node apart, its sync set as it stands: an observer from `reader`), `common::packages_reading` (a fresh reader given its grant alone: its sync set plus its thing's sync IDs, which it syncs once it holds the record; `packages_to` without the copy), `packages_of(from, t)`, `trimmed`, `common::give_carried` (a net apart), `flows::send_carried`; `LocalPeer::commit_ids` where only IDs are read (and to pick, later, a fresh node's packages among what was held at a point). An observer is an account granted read and holding the thing (`common::reader`, `LocalPeer::fresh_reader`, `fresh_net`, `share`); a role-less node holding a thing by a node-root strong keeps none of its content, so a test comparing what such a node reads compares nothing. A copy per call (`packages_to`, `packages_to_peer`) costs about what the test's own deliveries do: in a per-seed or per-order loop use the copy-free forms, and one reader's list for every fresh reader of an order loop (the sync IDs of one thing are alike for each). A test's receive of forged or partial input for a node under test goes through `common::unless_refused` (a refusal is fine, a local error fails the test, as `Peer::receive` panics on `Corrupt`), never `let _ =`. `Engine::package` hand deliveries are still whole: what they bring outside the closure waits for good (issues/engine-harness-whole-packages.md, with the certificate broadcast and the sim's sender-defined quiescence).
- A fresh reader's seed must not be a net peer's (`net(n, s)` seeds `s*1000+i`): the same seed is the same account, and its grant re-grants that peer.

## Confidentiality over `LocalPeer`
`Package`/`deliver`/`sync` hand over plaintext commits, so a peer that lost access still reads whatever it is sent: no "who can read" claim holds there. Such claims use the sealed mode: `LocalPeer::sealed` (makes the rotations due before encrypting first, then `Engine::seal_package`) and `deliver_sealed` (`Engine::open_package`). flows.rs `sealed_write` asserts a peer that does not read the write opened none of its bodies; `spread_sealed` is `spread` sealed. Plaintext stays right for setup and for what an engine does with what arrives (order, validity).

## Store-contents differential
For a refactor that must not change stored bytes or write order. Seeded `LocalPeer`/`MemoryBackend` stores are byte-deterministic once the persisted index tag is pinned (`index.rs` `VERSION` folds in `OSIS_INDEX_RULES`, a hash of the sources). Throwaway patch, on main and the branch alike: in `MemoryBackend::commit` fold each batch's ops into a running hash, and in a `Drop for Data` append `thread-name trace-hash final-hash batches rows` to a file named by an `OSIS_PROBE_*` variable; set `VERSION` to a constant; run the default tests plus the order properties on each, sort, diff (about 12,400 stores). Tests that differ run to run on one build (crash, store, runtime, driver, cli, some sync and encodings tests, `apply::tests_paged`'s paged-snapshot tests, osis `api::created_reads_through_run_time_key_*`: async, OS randomness) differ between builds too: rerun those on one build to rule them out. A store dropped on another thread moves its line to that thread's name: compare without names too.

## Measuring
Compare old and new code by instruction counts, never wall time on a loaded box; no timing runs inside a task (scaling: notes/test-scale.md).
- `tools/icount CMD...` prints `INSTR <n>` on stderr (user-space instructions via perf_event_open; needs `kernel.perf_event_paranoid` <= 2, which /etc/sysctl.d/60-perf.conf sets; builds icount.c into ~/.cache/osis on first use). Counts repeat to under 0.1%; CPU-s vary 20-40%. Old binary: `tools/bin-at <rev> <out> -p <crate>` (notes/build.md).
- `tools/cpuprof OUT <test binary> --exact <name>`: an LD_PRELOAD SIGPROF sampler, inclusive and self shares per function; `tools/cpuprof --report OUT.<pid> [N] [FILTER]` reprints. CPU-time samples skew with the box's load: `CPUPROF_INSTR=N` samples every N user-space instructions of each thread instead (2000000 is about 2 ms), so shares compare across runs and a sample is a fixed number of instructions (per make: samples × N / makes). Stacks keep 160 frames, so FILTER can name an outer frame (a measured phase run on its own thread, as `making::probe` style tests do). Over a whole binary (`--test-threads=8`) it shows what all tests share. Its own work counts in icount (about 3.5%), so count without it; it kills the perm `it`, crypto lib and transport binaries ("Profiling timer expired"). Over a whole binary it can write a second `OUT.<pid>` (a child process's): the larger file is the test binary's. Its stacks mislead for spawned threads and deep frames (unrelated callers shown): confirm a suspect with `tools/icount` on an env-gated variant before changing code.
- Exact call counts and split by caller (valgrind is on fastbox-0, not ostrich): `valgrind --tool=callgrind` on one test (`--test-threads=1`, about 50x slower), `callgrind_annotate --tree=caller`; a recursive function's inclusive cost (`name'2`) counts each level again. `perf record` is refused here.
- Every default test, or every module, alone under `tools/icount`: `tools/pertest.py` (Default-test cost). An `--exact` run of one test counts its fixture too (a 4-node world can be most of it): for a fixture-free delta compare in-process module counts (`tools/icount BIN -q <module>::`).
- Which commit grew a test: a background script running `tools/bin-at` and `tools/icount` over a commit list, every 5th commit, then the window.
- Per-test wall times: run a test binary with `RUSTC_BOOTSTRAP=1 <binary> -Z unstable-options --report-time` from its package dir (the binary, not `cargo test`: `RUSTC_BOOTSTRAP` through cargo changes the fingerprint and builds a second artifact set); CPU per test with `/usr/bin/time <binary> --exact <name>`. A test binary run outside cargo runs proptests at 256 cases: set `PROPTEST_CASES=32 PROPTEST_DISABLE_FAILURE_PERSISTENCE=1` as `.cargo/config.toml` does.
- A multi-threaded property's instruction count moves with thread timing (which of two alike nodes is met first): compare at `OSIS_SEED_THREADS=1`.
- In code: `osis_base::costs` spans (`costs::span(name)` in the engine, `costs::take()` in a test).

## Default-test cost
Compare by instruction counts (Measuring); totals come from `tools/pertest.py top`. The gate's figures: notes/time-limits.md; where the time goes: issues/test-time.md. Under `tools/pertest.py` each test is its own process, so a test pays its process's cached fixtures (`world_of`, `LocalPeer::cached`): most of a median osis-sync or rotation test's count, and a cached setup's saving shows only over a whole binary or module in one process (`tools/icount BIN -q <module>::`).
- Figures (per test process; the last profile, 8,553 G over 3,994 tests, less the 31 seed-runner samples that are `_plain` properties): 3,963 default tests, about 7,860 G, 2,200 CPU-s (osis-sync `it` 2,595 G, engine lib 2,058, engine `it` 2,034, osis `it` 346, osis-perm `it` 221, held-model `it` 222, osis-crdt lib 129, the rest 232). Where the engine modules go (one process, one thread, cpuprof): the drop's index check 18-23% (its rebuild about 10%: issues/index-check-rebuild-cost.md), `LocalPeer::packages_hashed` 4-9% (issues/test-time.md, Levers 0).
- Measured not to help: the order harness's oracle starting from a kept copy of the setup-given node (1.4% of `order::*`, not worth its cache), every binary at once, harness inner threads at 1, opt-level 2 for the workspace crates (one-line edit builds 15-20% slower), selecting default-test crates by the diff (engine takes most commits: 15% at best, opens a gap). Only less work shortens it.
- In place:
  - osis-crypto at `opt-level = 2` in dev; smaller data where the property is relative; properties for sizes.
  - Shared setups: one setup copied per order where a test plays many orders from one start (`local_peer::Peer::fork`); cases sharing a setup copy it (`LocalPeer::cached`); every arrival order of a set walked as a tree of copies (osis-engine it `apply_order::each_order`: a prefix is received once); the judgment vectors' replays start from a copy of the node that received the file's setup (`judgment::replay`).
  - Tests looping over fixed seeds or cases run them on the seed runner (`stream::stream_differential_*`).

## Harness footguns
- `Engine::local_census` keys keep the family's trailing `/` (`"pc/"`): a lookup by the bare prefix reads no rows, and an "is zero" assert passes vacuously. Probe every row-count assert with its mechanism off.
- `Engine::fires_owed` is in `FireId` order: `.last()` is the highest id, not the newest fire (a grant's sealed ticket is owed too); diff the owed set before and after.
- `Hlc::peek` jumps to every received `ts`: a wait "until R's `ts`" against it ends the moment R arrives. A rule "as of its wall clock" reads `Hlc::wall`, and a wait on wall time sets a wake.
- `LocalPeer::receive` wakes and re-examines after every ingest, so a wake a shortcut skips is invisible there: probe equivalence of an ingest path through `Engine::ingest`.
- `osis_perm::commits_walked` deltas around a step settle "who can force many walks" questions quickly (k against 10k).
- A role commit past `grant`'s refusal needs `m.unchecked` plus `skip_writer_rules`.
- `costs::take` counts per thread: in a `LocalPeer` test it mixes every peer's work; scope the window to one peer's applies.
- A test on what a store holds keeps history on the aspects it probes: a store otherwise follows its own judgment (an automatic compaction), and a probe leaning on an entry kept for lack of a key fails for reasons unrelated to what it tests. A test meant to isolate one mechanism checks that it fails with that mechanism alone disabled: a test passing by either of two mechanisms isolates neither, and a plant a later backstop hides (the next transaction undoing what a dropped abort-undo left) needs a check between the two.
- A mutation that changes nothing (a `set` of the current value, a set `Add` of a live value) writes no delta, and a commit with no delta is not made (`commit_tx` returns `None`): a re-put meant to carry something silently commits nothing.
- `Engine::run` rolled back restores the store, not every in-memory map of `Core` (`Core::accounts` keeps what the trial cached): derive secrets from the store record, never from a cache filled inside a trial.
- `Meta::missing_parts` counts parts whose body is absent, not parts the node cannot open: test readability by value (`engine.get`). `LocalPeer` hands parts over in the clear, so "can it open" is a check of held secrets, not of reads.
- Sync `World`: `run` moves the world clock by its dial ticks (about an hour on `contacts`), so an `until` a minute ahead has passed before the grantee reads; an engine's `now()` lags the world clock until that node steps; `advance` over a long wait (`LOST_HEARD_WAIT_MS`) takes minutes of dial ticks: `skew` one node's clock instead. `RULE_CAP` is per world: `history::world` scales it by n, a hand-built world does not (`w.cap = n * RULE_CAP`).
- A per-process `--exact` run of one sync test rebuilds its cached fixtures (2-4 s for a `contacts` test, a third of that in-process).
- A proptest failure reproduces across runs only under `PROPTEST_RNG_SEED=N`; without it each run draws new cases.
- A count taken inside a `measured` closure (`osis_base::costs::take`) zeroes what the closure is measured by: every n/10n check then passes at 0. Probe outside the measured region.
- A memo kept by a key's stamp, read before that key is inserted, computes again at the next look: a cost test looks once before counting.
- An n/10n count through a real world needs an event that moves inputs alone: most events (a redeem, a register) also bring new keys.
- `Engine::seal_package` writes a `dw/` row at the maker: seal after taking a census.
- `LocalPeer::sync` carries no ephemeral commit: an engine test hands one over with `memory_blob` and `ingest_memory`.
- A sync world that waits out `PASS_WAIT_MS` with a node away costs 7-10 GB, mostly dial ticks toward the absent node.
- A loop over consecutive seeds with `rng(seed | 1)` makes seeds 2k and 2k+1 the same history: use odd seeds via `step_by(2)`.
- A count test built on the sync `history::world` turns the memo debug comparisons off before counting (`idle::exact`): the history world turns them on for its thread, and their reads count.
- `LocalPeer::pulled_anew` fills only at `receive`/`reexamine` (`LocalPeer::wake`): an engine commit's pull anew waits in the engine's wakes, so a test clearing `pulled_anew` after a copy sees the setup's pulls at the next receive: `reexamine` first.
- A thing re-entering the node closure usually rejoins the sync set by its own sync ID, pulled from the start anyway, so a re-entry test passes with `refetch` broken: only a dependent thing in a unit whose sync ID never left exercises it.
- `order.rs`'s and `parts.rs`'s `FRESH` are one account (one seed), granted by the base; the judgment vectors' judge is that account too (`order::judge_at`).
- A cost test varying only what the node closure holds cannot see a pass judging every held thing when the filter to things outside it is uncounted: count what is due before filtering.
- A drop path that marks commits stale needs a test where the drop happens in the end-of-transaction tail: only the end-of-transaction debug assert ("stale validity left unjudged") catches a re-judge marker set after the transaction's last re-judge.
- roles-model `family_run(stride)`: a stride sharing a factor with a dimension's size fixes that dimension (every 50th world: `h_t1` always false); strides of mixed-radix families are coprime with every radix.
- A hand-again-until-quiet loop must not count every non-`Duplicate` result as progress: a commit kept pending, handed again, comes back `Pending` every round (at a lookup's cost, `apply::rearrival`), so the loop runs its full bound (osis-sync `history::reference`: 319 rounds instead of 2, 5x the sims' and differential's cost). Stop once a round applies nothing and leaves `Engine::pending` as it was.
- The order harness's `fetch_missing` never delivers what a node pulls anew (`pulled_anew`): a node relying on a pull anew fails `held_set_decides` with no hint.
- roles-model: probe a failing world by printing it and its reference, never by shrinking it first (one `vouches` shrink ran past 10 minutes on one core). Two readings of one world (a mutant against the rule) go in one process with a thread-local switch: an env var read in the walk cannot switch per call across `on_every_core` threads.
- held-model `gen::shuffle` reorders commits, records and frontiers but not `Held::dots`, and `Dots::commit` takes the first range holding a dot: an order test over overlapping ranges shuffles `dots` itself (`props_overlap::reorder`).
- osis-perm tests: `World::nodes(n)` returns the same nodes on every call; fresh nodes per loop step come from one `nodes_salted` call, or the components silently merge.
- Sync `World::step_or_wake` keeps returning true while any node dials a partitioned peer (its horizon moves with the clock): bound such a loop by world time. A test reading what a peer was served after `run()` misses entries the peer dropped on learning it no longer holds the thing: check after each delivery.
- Streams harness: a body opened as `Opening::Taken` (the `Table` default) leaves no store entry though the pull worked: check `knows`. A late message harms only a member already at the stream (one joining from the start is listed whatever the cursor says), so a late-reply probe on a first join passes with its rule disabled.
- A world test of a change made while a peer is away passes with the in-place judgement removed: the first reconnect after first contact judges every member. Mutation-check it with the peer away and back once first, and mutate to the old behaviour (unfollow), not to a bare return that leaves the memo key due.
- A `rejects` case asserting only the error class passes on any earlier rejection (a crdt overlap case was refused for its arity before any run decoded): print the error once (`--nocapture`) when writing one.
- A redb store's clean close commits its allocator state, most of any `FileDevice` test that closes a written store; `std::mem::forget` of a store as a power cut fails the reopen (the file lock stays held).
- held-model `unit`: `Net::deliver` decides by the truth which units a writer syncs, so a writer that cannot know a sync ID (a forked promotion's greater one) still gets commits under it; a gap there needs delivery by hand.
- A differential's exclusion (a predicate excusing a disagreement) is counted over every world it covers, printed beside the failures: applied to failing worlds only, one excused 38% of the paths content worlds unseen.
- A differential mapping model flags to wire shapes (`finalize` to a missing frontier) never emits a shape its mapping lacks, so a mutant of that shape's rule survives every agreement test: a shape rule needs a test that builds the wire input directly (roles-model `paths/shapes.rs`, osis-perm's).
- A generator may build in-memory states no encoder writes (a crdt position write stamped with its element's dot): before fixing a rule for one, check it decodes from bytes; a decoder test of such bytes hand-patches an encoding (decode to `Value`, change it, re-encode). `DeltaBuilder` `Add v` of a value already live writes nothing (`finish` is `None`): a forged copy adds a value the base lacks.
- `Debug` of a crdt `Seq` expands range records per element, so a printed state never shows whether a join split or kept a range: count `elems().len()` or spans. Text ranges exist only content-less (a delete-only delta, or deletes held without their creations).
- A late-order test says which copy it delivers: a node's copy of a commit it purged is header-only, so delivering it tests "never held the body", not "the body arrived late".
- A world built under `PageParams::set_test` (thread-local small pages) must not go into `LocalPeer::cached`: other tests would read its small-page states.
- A new `osis_base::costs` count shows in every test comparing all spans (osis `making::`, engine `closure::` assert exact equality): a counter one scale test reads goes outside the shared table (as `osis_store::bytes_handed`).
- The engine harness's `vouch` helper commits through the writer rules: a hostile voucher (no role in its own reading) needs the vouch inlined with `skip_writer_rules` and `unchecked`.
- A module name may exist in several crates' `it` (`destruction::`: osis-engine's and osis-sync's): a brief or command names the crate with it.
- roles-model `paths::World::lowers` counts every edge write below admin, a fresh grant of write included: it is not "a removal" (the evidence model defines its own `removes`, below write).
- `Core::timer_floor = 0` does not wake a sync daemon: node-sync wakes at `next_timer` (`Node::next_wake`), and only the osis handle's `expire_due` reads `timers_due`; "make a tick due" means making `next_timer` say now.
