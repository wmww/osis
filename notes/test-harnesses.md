# Test harnesses
> Summary: How to run and replay seeded tests (env vars through `osis_base::testenv`, seed runners, replay lines, the property list), copied worlds and cached setups, the debug rebuild and index checks every test runs, sealed `LocalPeer` delivery, the store-contents differential, measuring old against new (icount, cpuprof, callgrind), and harness footguns.

## Env vars and seeds
- Harness env vars (`OSIS_*_START`/`_SEEDS`, `OSIS_PERM_SEED`, ...) are read through `osis_base::testenv`, which panics on an unparsable value, zero seeds, or any set `OSIS_*` variable not in core/base/testenv-known.txt (policy.py keeps that list equal to what the sources name: add a new variable there; read at run time, so adding one rebuilds nothing). A throwaway probe variable is `OSIS_PROBE_*`, exempt from the list and refused by policy.py while left in.
- A set variable and an overridden range are echoed past libtest's capture, so they show on a passing run: check that line, not only `1 passed`. Per-seed output needs `-- --nocapture`.
- `OSIS_FULL=1` runs a property's large size (release checks only); its small size, the gate's, is a tenth (`testenv::large`, at least one seed); explicit `_START`/`_SEEDS` override both.
- **Every property and its variable**: `python3 tools/test_select.py --all` lists every property test by crate and prints the command with every `OSIS_*` start variable the gate sets. Each harness prints its own replay line for a failing seed; use it as printed.
- **Default test vs `_large` twin**: a seed-ranged harness's default test runs fixed seeds and reads no environment; its `#[ignore]` `_large` twin reads the range (`--ignored --exact <name>_large`). The replay line names the twin where it checks a seed as the default test does, else the default test. `held_set_decides` has no twins: `quick` in the default tests, `plain`/`exhaustive` as `#[ignore]` entry points. So `--ignored --exact` on a harness name either runs it or matches nothing (`0 passed`).
- Engine lib harnesses: `cargo test -p osis-engine --lib <path> -- --ignored --exact`; a copied binary from `tools/bin-at REV OUT --lib osis-engine`, run from `core/engine`.

Crate-wide seeds:
- **osis-crdt**: every `testutil::rng(seed)` (fixed-seed loops and proptest cases alike) samples other runs with `OSIS_CRDT_SEED=<n>` (a splitmix hash of n xor'ed into each run's seed; unset, the committed seeds); a panicking test prints the effective seed. Its `_large` properties take `OSIS_CRDT_START`/`_SEEDS`. `OSIS_SHRINK=<loop seed> cargo test -p osis-crdt --lib -- --ignored shrink_script` (with the same `OSIS_CRDT_SEED`) shrinks a failing `fuzz_seq::random_scripts_replay_spec_5_7` script and prints it.
- **osis-perm**: `differential`, `queries`, `incremental` sample other histories with `OSIS_PERM_SEED=<n>`; each property run is 16 shards on scoped threads, shard i seeded `seed ^ i << 40` (fixed count, so a failing seed reproduces anywhere; the panic names the shard's seed). Its runs print counterexamples as made; `OSIS_PERM_SHRINK=1` shrinks them.
- **order harness** (`held_set_decides`): `OSIS_ORDER_START`, `_SEEDS`, `_SEED` (one seed), `_LEN`, `_CLOCK`; `OSIS_ORDER_SHRINK=1` shrinks each failure (slow: passes dropping one step at a time until a whole pass drops none; a removal redraws the seed's orders and held sets, so one pass alone stops far short), `OSIS_ORDER_STATS=1` prints each history and the tallies, `OSIS_ORDER_DUMP=1` explains a failing node: the packs with each header's purge list (a `Commit` item names the packs it matches), reads as they change per order, and index differences against the keep-everything node (notes/test-properties.md, Held-set property).
- **sim**: notes/test-sim.md, Replaying a seed.

## Seed runners (`osis_base::testenv`)
- `run_seeds(name, seeds, visible, replay, f)` (and `Seeds::run`, which announces an env range first) runs `f(seed)` for every seed on a thread per core (`OSIS_SEED_THREADS` overrides, one variable for every harness), a panic counting as its seed's failure. Each failing seed prints with its replay command as it fails, a progress line every 60 s, a summary, then a panic listing every failure in seed order. A multi-seed run goes through it, not a serial loop.
- **Hung seeds**: a seed whose thread used `OSIS_SEED_TIMEOUT_SECS` (default 600) CPU-seconds, or no CPU for that long (blocked), is marked hung and a new thread takes its place. CPU time, not wall: under load a 5 CPU-s seed can take 700 s wall. A lower value (`OSIS_SEED_TIMEOUT_SECS=60`) names a hung seed early in quick runs (ephemeral churn). A hung thread prints its backtrace at its next `testenv::checkpoint()` (`LocalPeer::sync`, the node test `Net::run`, `Sim::step`). It cannot be stopped: when the rest is done with hung seeds still running, or as many hang as there are threads, the runner prints everything and exits the process (101).
- `run_jobs(name, jobs, threads, visible, label, f)` is the general runner (sim-sweep and `work_sets_match_full_passes` use it, so a livelocked sim seed is named). `par_map`/`caught`/`threads` are the building blocks. `Permit` is one of the process's permits (a thread per core); `pooled_map(items, threads, f)` is `par_map` with each call holding one, so concurrent tests and a run's seeds and their parts share the cores (osis-perm's shards, the order harness's seeds and orders).

## Copied worlds
A setup many tests share is built once per test process and each test gets an exact in-memory copy of the live world: it goes on as the original would (same next commit IDs, rng draws, connections, queues, memo hits), so a test cannot tell it from one it built. Reopening stores is not a copy (every node restarts, reconnects and syncs again).
- **Adding a cached setup**: wrap the builder in `LocalPeer::cached(key, || (peer, extra))` (or `osis_base::copying::cached` for another world type).
- **Mechanism**: `osis_base::copying::copying` scopes one world copy (`copying_reseeded(salt, f)` reseeds its generators, for the sim's shared setups); inside it `remap` gives every shared `Arc` one new handle, so the copy's parts share what the original's did and nothing points back.
- **Hooks** (test-only, `#[doc(hidden)]`; policy.py keeps them out of product sources, because two live copies are one node twice and reuse nonces, counters and commit IDs): `Engine::test_copy(clock)`, the ciphertext store's `test_copy`, osis `Osis::test_copy` (core/osis/src/testing.rs), `Store::test_copy` over `Backend`/`RootStorage::test_copy_boxed` (memory ones only), `NodeRng::test_copy`. Plain `Clone` is derived on data; the types owning identity, rng or a live store copy only through these hooks. Harness copies: `Peer::copy`, `LocalPeer::copy`. Engine event receivers are subscribed again with the unread events (`Engine::test_subscribe_with`); commit listeners are not copied.
- **The `osis` handle** copies whole but for a fresh dispatcher (no subscription, no commit listener). Refused: `Dispatcher::Pump`, a runtime other than `None`/`Manual`, a store in a directory, in-process transport, a `text_save` hook, a thin client, a waiting call, a connection to another node, a client port that ran. A setup that closes and reopens a node is not cached. Real-runtime tests are never copied.
- Differentials: osis-engine `tests_copy`.

## Debug checks
Two checks run inside every debug-build test, so every test is also an incremental-equals-from-scratch test (notes/test-design.md). Both are invisible to scale counts (`costs::paused`, `osis_perm::uncounted`). Together they cost about an eighth of osis-node `it`'s instructions.
- **Rebuild check** (`apply::atomic::check_rebuilt`, run by `Engine::run` before the index persists): after every transaction, each touched aspect's state must equal `rebuilt` (exactly the join of held bodies, invalid writes removed, spec/crdt.md §4.6), compared encoded. Always checked: an aspect where a held part's status changed, a part arrived not valid and whole, or the state was written with no new commit naming it. An aspect that only joined new valid whole parts is checked when its held commits cross a power of four from 4 (4, 16, 64: a wrong state stays wrong, so a later sample still sees it). A test hook writing a state no body gives sets `Core::unchecked_tx`. A failure panics with the differing Debug lines.
- **Index check** (`Engine::check_index`, after a durable transaction commits): an open from the persisted index and a rebuild from the commit records, each into a fresh `Core` in a dropped store transaction, must equal the running node's index (`Core::same_index`, held set and role timelines included); the open reads no blob and judges every part as held (`misjudged`). Sampled per open: it runs when the count of durable transactions changing a state or part, or of those changing more than valid joins, reaches a power of 16 (1, 16, 256). Skipped after a transaction that left the index stale (`index::invalidate`). An engine lib test editing an index in memory sets `Engine::index_poked`. A reproducer whose point is one moment calls `check_index` there. It also asserts that an open decodes no commit header: judging anything at load from headers (`LazyHeader::arc()` decodes at once; clone the `LazyHeader` and deref only where the record is held) fails it, often only in node properties or the sim, never the default tests.
- **Changing their sampling**: keep each count's first check (status changes cluster there; most of what the checks find in the default tests is there) and judge the change by re-introducing past bugs, not by default-test time alone. Measured, rejected: the index check at each count's first transaction only (1, not 16, 256) costs 4.2% fewer instructions in node `it` and 2.8% in osis `it` (powers of 16 without 256 and on: 0.2%), but a planted fault growing over an engine's life (unindexing a rotation leaves its `by_epoch` entry) fails 27 tests instead of 61 (node, osis, engine lib); faults on the incremental epoch paths (an `epochs_due` or a changed `named` not noted) fail the same tests either way. The second check is where faults that accumulate show. Caught so far, each incremental-vs-from-scratch on an unusual path: by the rebuild check, a fallen purge's register keeping an older value-less write, the group index not following a member gone by retention, a snapshot's hidden-anchor copy not vouching at join, an invalid text delta leaving an empty record, a forged snapshot's key-erased remnant, paged states dropping chars the crdt keeps, a churn cursor state lacking a write (`OSIS_FULL=1` seeds, cause untraced, not reproducing); by the index check, equivocating commits of one range kept by arrival order (fails `validity::overlapping_counters_spec_commits_4`, `validity::revoked_writer_forging_into_covered_counters_spec_perm_5_1`), a node's own rotation not reading the history box its secrets open, derived-epoch adoption by arrival order, an account switch's epoch residue, a destruction's dropped keysets not rebuilt. Past bugs re-introduced at the current sampling: the group index (revert ab739e2dd) fails 8 default tests through the checks (4 node, 4 osis; 2 without them; with the rebuild check off the index check alone fails 4 node tests, 1 when each count's first check is skipped); the own-rotation history box (db142a2a1) fails only its own test; the hidden-anchor vouch (e3ccc875a) fails no default test, only `held_set_decides_plain` seed 3 by its read oracle.
- Not covered: a `node/edges` row left stale when a destruction rewrites a role commit's record (no reopen or sampled check follows `destruction::` tests' rewrites).

## Confidentiality over `LocalPeer`
`Package`/`deliver`/`sync` hand over plaintext commits, so a peer that lost access still reads whatever it is sent: no "who can read" claim holds there. Such claims use the sealed mode: `LocalPeer::sealed` (rotates first as node-sync's `uncovered` does, then `Engine::seal_package`) and `deliver_sealed` (`Engine::open_package`). flows.rs `sealed_write` asserts a peer that does not read the write opened none of its bodies; `spread_sealed` is `spread` sealed. Plaintext stays right for setup and for what an engine does with what arrives (order, validity). Inbox blobs are real either way.

## Store-contents differential
For a refactor that must not change stored bytes or write order. Seeded `LocalPeer`/`MemoryBackend` stores are byte-deterministic once the persisted index tag is pinned (`index.rs` `VERSION` folds in `OSIS_INDEX_RULES`, a hash of the sources). Throwaway patch, on main and the branch alike: in `MemoryBackend::commit` fold each batch's ops into a running hash, and in a `Drop for Data` append `thread-name trace-hash final-hash batches rows` to a file named by an `OSIS_PROBE_*` variable; set `VERSION` to a constant; run the default tests plus the order properties on each, sort, diff (about 12,400 stores). Tests that differ run to run on one build (crash, store, runtime, driver, cli, some sync and encodings tests, `apply::tests_paged`'s paged-snapshot tests, osis `api::created_reads_through_run_time_key_*`: async, OS randomness) differ between builds too: rerun those on one build to rule them out. A store dropped on another thread moves its line to that thread's name: compare without names too.

## Measuring
Compare old and new code by instruction counts, never wall time on a loaded box; no timing runs inside a task (scaling: notes/test-scale.md).
- `tools/icount CMD...` prints `INSTR <n>` on stderr (user-space instructions via perf_event_open; needs `kernel.perf_event_paranoid` <= 2, which /etc/sysctl.d/60-perf.conf sets; builds icount.c into ~/.cache/osis on first use). Counts repeat to under 0.1%; CPU-s vary 20-40%. Old binary: `tools/bin-at <rev> <out>` (notes/build.md).
- `tools/cpuprof OUT <test binary> --exact <name>`: an LD_PRELOAD SIGPROF sampler, inclusive and self shares per function; `tools/cpuprof --report OUT.<pid> [N] [FILTER]` reprints. Over a whole binary (`--test-threads=8`) it shows what all tests share. Its own work counts in icount (about 3.5%), so count without it; it kills the perm `it`, crypto lib and transport binaries ("Profiling timer expired"). Over a whole binary it can write a second `OUT.<pid>` (a child process's): the larger file is the test binary's.
- Exact call counts and split by caller (valgrind is on fastbox-0, not ostrich): `valgrind --tool=callgrind` on one test (`--test-threads=1`, about 50x slower), `callgrind_annotate --tree=caller`; a recursive function's inclusive cost (`name'2`) counts each level again. `perf record` is refused here.
- Every default test alone under `tools/icount`: `tools/pertest.py` (notes/testing.md, Default-test cost). Per binary, wall, the whole-suite profile: the same section. A test binary run outside cargo needs `PROPTEST_CASES=32 PROPTEST_DISABLE_FAILURE_PERSISTENCE=1`.
- In code: `osis_node::costs` spans (`costs::span(name)` in the engine, `costs::take()` in a test).

## Harness footguns
- Node `Net`: an offline node (`set_online(n, false)`) gets no events, ticks included: drive it by hand with `net.offline_handle(n, ev)`, which answers its dials `Down`, never `let _ = net.sync(n).handle(ev)` (a dropped `Dial` is never answered, so the node never dials again once back online; notes/testing.md, Conventions). To cut one host off use `net.blocked.insert((n, s))` with `net.drop_link(n, s)`; after `set_online(n, true)`, `run()` does not reconnect until a retry tick: `advance` tens of seconds. `store.put`/`plant_inbox` notify no subscriber and skip the host's prefix check (go offline, then reconnect, or the test passes for nothing). `Net` auto-accepts requests; a 1 h `tick` closes the connection by ping timeout; `hold_blobs` holds listing pages naming the blob too; the first `advance` after a clock jump only clamps.
- A role commit past `grant`'s refusal needs `m.unchecked` plus `skip_writer_rules`.
- Node `Net`: `hide_blobs` hides announcements for good (lifting it never lists again what went by), and a node handed a commit whose blobs are hidden places its own copies: to give it the blob later hand it the package (`Engine::package` + `ingest`). An explicit demotion's frontier is what its author holds when it writes: an author brought online and run first lists the cover, so hide the cover from it too.
- `costs::take` counts per thread: in a `LocalPeer` test it mixes every peer's work; scope the window to one peer's applies.
- A test on what a store holds keeps history on the aspects it probes: a store otherwise follows its own judgment (an automatic `group.0` compaction), and a probe leaning on an entry kept for lack of a key fails for reasons unrelated to what it tests. A test meant to isolate one mechanism checks that it fails with that mechanism alone disabled: a test passing by either of two mechanisms isolates neither, and a plant a later backstop hides (the next transaction undoing what a dropped abort-undo left) needs a check between the two.
- Node `Net`: two `net.hosts[s].hub.store()` calls in one statement (both inside one `eprintln!`) deadlock with no output: the first guard lives to the statement's end. `hosted_nodes` accounts have inboxes listing no host and no direct links, so every delivery to them stays pending (a grant handed over by `pair` hides it); use `home_at_hosts` when a test depends on deliveries.
- A new node test that loops shows nothing through `| tail` until it exits (`Net::settle`'s round guard misses loops inside one step): run it first with `--nocapture` to a log.
- Sim trace: `link N -> Hub(..): Stream` names the receiving end (hosts pull nodes' logs, so it reads like a host push); a send's line is followed later by its `delivers` line (by message kind; `sent twice` marks a `dup_pct` copy, `link gone: lost` a delivery onto a cut link); a node sync restart in place after an injected store fault shows only as a diagnostic.
- A loop over consecutive seeds with `rng(seed | 1)` makes seeds 2k and 2k+1 the same history: use odd seeds via `step_by(2)`.
