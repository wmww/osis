# Test harnesses
> Summary: How to run and replay seeded tests (env vars through `osis_base::testenv`, seed runners, replay lines, the property list), copied worlds and cached setups, the debug rebuild and index checks every test runs, why a thing is kept and row dumps, sealed `LocalPeer` delivery, loop guards, the store-contents differential, measuring old against new (icount, cpuprof, callgrind), the default-test cost (what is in place, per-test profiles), and harness footguns.

## Env vars and seeds
- Harness env vars (`OSIS_*_START`/`_SEEDS`, `OSIS_PERM_SEED`, ...) are read through `osis_base::testenv`, which panics on an unparsable value, zero seeds, or any set `OSIS_*` variable not in core/base/testenv-known.txt (policy.py keeps that list equal to what the sources name: add a new variable there; read at run time, so adding one rebuilds nothing). A throwaway probe variable is `OSIS_PROBE_*`, exempt from the list and refused by policy.py while left in.
- A set variable and an overridden range are echoed past libtest's capture, so they show on a passing run: check that line, not only `1 passed`. Per-seed output needs `-- --nocapture`.
- `OSIS_FULL=1` runs a property's large size (release checks only); its small size, the gate's, is a tenth (`testenv::large`, at least one seed); explicit `_START`/`_SEEDS` override both.
- **Every property and its variable**: `python3 tools/test_select.py --all` lists every property test by crate and prints the command with every `OSIS_*` start variable the gate sets. Each harness prints its own replay line for a failing seed; use it as printed.
- **Default test vs `_large` twin**: a seed-ranged harness's default test runs fixed seeds and reads no environment; its `#[ignore]` `_large` twin reads the range (`--ignored --exact <name>_large`). The replay line names the twin where it checks a seed as the default test does, else the default test. `held_set_decides` has no twins: `quick` in the default tests, `plain`/`exhaustive` as `#[ignore]` entry points. So `--ignored --exact` on a harness name either runs it or matches nothing (`0 passed`).
- Engine lib harnesses: `cargo test -p osis-engine --lib <path> -- --ignored --exact`; a copied binary from `tools/bin-at REV OUT --lib osis-engine`, run from `core/engine`.

Crate-wide seeds:
- **osis-crdt**: every `testutil::rng(seed)` (fixed-seed loops and proptest cases alike) samples other runs with `OSIS_CRDT_SEED=<n>` (a splitmix hash of n xor'ed into each run's seed; unset, the committed seeds); a panicking test prints the effective seed. Its `_large` properties take `OSIS_CRDT_START`/`_SEEDS`. `OSIS_SHRINK=<loop seed> cargo test -p osis-crdt --lib -- --ignored shrink_script` (with the same `OSIS_CRDT_SEED`) shrinks a failing `fuzz_seq::random_scripts_replay_spec_5_7` script and prints it.
- **osis-perm**: `differential`, `queries`, `incremental` sample other histories with `OSIS_PERM_SEED=<n>`; each property run is 16 shards on scoped threads, shard i seeded `seed ^ i << 40` (fixed count, so a failing seed reproduces anywhere; the panic names the shard's seed). Its runs print counterexamples as made; `OSIS_PERM_SHRINK=1` shrinks them.
- **order harness** (`held_set_decides`): `OSIS_ORDER_START`, `_SEEDS`, `_SEED` (one seed), `_LEN`, `_CLOCK`; `OSIS_ORDER_SHRINK=1` shrinks each failure (slow: passes dropping one step at a time until a whole pass drops none; a removal redraws the seed's orders and held sets, so one pass alone stops far short), `OSIS_ORDER_STATS=1` prints each history and the tallies, `OSIS_ORDER_DUMP=1` explains a failing node: the packs with each header's purge list (a `Commit` item names the packs it matches), reads as they change per order, and index differences against the keep-everything node (notes/test-properties.md, Held-set property).
- **sim**: notes/test-sim.md, Replaying a seed.

## Seed runners (`osis_base::testenv`)
- `run_seeds(name, seeds, visible, replay, f)` (and `Seeds::run`, which announces an env range first) runs `f(seed)` for every seed on a thread per core (`OSIS_SEED_THREADS` overrides, one variable for every harness), a panic counting as its seed's failure. Each failing seed prints with its replay command as it fails, a progress line every 60 s, a summary, then a panic listing every failure in seed order. A multi-seed run goes through it, not a serial loop.
- **Hung seeds**: a seed whose thread used `OSIS_SEED_TIMEOUT_SECS` (default 600) CPU-seconds, or no CPU for that long (blocked), is marked hung and a new thread takes its place. CPU time, not wall: under load a 5 CPU-s seed can take 700 s wall. A lower value (`OSIS_SEED_TIMEOUT_SECS=60`) names a hung seed early in quick runs (ephemeral churn). A hung thread prints its backtrace at its next `testenv::checkpoint()` (`LocalPeer::sync`, the sim's step loop). It cannot be stopped: when the rest is done with hung seeds still running, or as many hang as there are threads, the runner prints everything and exits the process (101).
- `run_jobs(name, jobs, threads, visible, label, f)` is the general runner (sim-sweep and `run_seeds` use it, so a livelocked sim seed is named). `par_map`/`caught`/`threads` are the building blocks. `Permit` is one of the process's permits (a thread per core); `pooled_map(items, threads, f)` is `par_map` with each call holding one, so concurrent tests and a run's seeds and their parts share the cores (osis-perm's shards, the order harness's seeds and orders).

## Copied worlds
A setup many tests share is built once per test process and each test gets an exact in-memory copy of the live world: it goes on as the original would (same next commit IDs, rng draws, connections, queues, memo hits), so a test cannot tell it from one it built. Reopening stores is not a copy (every node restarts, reconnects and syncs again).
- **Adding a cached setup**: wrap the builder in `LocalPeer::cached(key, || (peer, extra))` (or `osis_base::copying::cached` for another world type).
- **Mechanism**: `osis_base::copying::copying` scopes one world copy (`copying_reseeded(salt, f)` reseeds its generators, for the sim's shared setups); inside it `remap` gives every shared `Arc` one new handle, so the copy's parts share what the original's did and nothing points back.
- **Hooks** (test-only, `#[doc(hidden)]`; policy.py keeps them out of product sources, because two live copies are one node twice and reuse nonces, counters and commit IDs): `Engine::test_copy(clock)`, osis-store's (`Store`, the cipher store, roots, pager), `Store::test_copy` over `Backend`/`RootStorage::test_copy_boxed` (memory ones only), `NodeRng::test_copy`. Plain `Clone` is derived on data; the types owning identity, rng or a live store copy only through these hooks. Harness copies: `Peer::copy`, `LocalPeer::copy`. Engine event receivers are subscribed again with the unread events (`Engine::test_subscribe_with`); commit listeners are not copied.
- No `osis` handle copy: no osis-level harness shares a setup. A setup that closes and reopens a node is not cached. Real-runtime tests are never copied.
- Differentials: osis-engine `tests_copy`.

## Debug checks
Two checks run inside every debug-build test, so every test is also an incremental-equals-from-scratch test (notes/test-design.md). Neither samples: each runs at every size, and every engine's history ends checked. Both are invisible to scale counts (`costs::paused`, `osis_perm::uncounted`).
- **Rebuild check** (`apply::atomic::check_rebuilt`, run by `Engine::run` before the index persists; the comparison is `check_states`): a touched aspect's state must equal `rebuilt` (exactly the join of held bodies, invalid writes removed, spec/crdt.md §4.6), compared encoded, with the caches derived from it (value-less list, snapshot bounds, references). Checked in the transaction: an aspect where a held part's status changed, a part arrived not valid and whole, or the state was written with no new commit naming it (each such change is a rebuild, so the check costs what the change did). An aspect only valid whole joins or covered drops touched (`shred_covered`, the state left as it was) waits in `Core::unchecked_states` for the end of the engine's history (a check per join would cost O(the aspect) per commit); a later rebuild of the aspect rewrites a wrong state unseen (Cost, below). A test hook writing a state no body gives sets `Core::unchecked_tx` (nothing it touched is checked). A failure panics with the differing Debug lines.
- **Index check** (`Engine::check_index`): an open from the persisted index and a rebuild from the commit records, each into a fresh `Core` on a clock stopped at the last transaction (the index is as of then: a timer due since has not run), in a dropped store transaction, must equal the running node's index (`Core::same_index`, held set and role timelines included), after the node closure walked afresh (`check_closure`) and the states left unchecked; the open reads no blob and judges every part as held (`misjudged`). It also asserts that an open decodes no commit header: judging anything at load from headers (`LazyHeader::arc()` decodes at once; clone the `LazyHeader` and deref only where the record is held) fails it, often only in node properties or the sim. The fresh cores borrow the node's decoded records (`Core::decoded`: a decode is a function of the record's bytes, compared at every hit), so the rebuild judges everything again without decoding it again.
- **The end of history** is the engine's drop (`impl Drop for Engine`, debug builds): the index check if a durable transaction changed a state or a part since it last ran, else the states left unchecked. Not while a panic unwinds, a load is half done (`Engine::loading`), a write's outcome is unknown, or the store fails (a crash test's: `Error::Store` ends it quietly). A copy (`Engine::test_copy`) starts checked: its original checks their shared past. An engine lib test editing an index in memory sets `Engine::index_poked`. `Engine::check_every_tx` (tests, by hand) runs the index check after every changing transaction, to find the one that diverged; a reproducer whose point is one moment calls `check_index` there.
- **Cost** (instruction counts): the rebuild from the commit records is about 15% of the engine lib default tests, the open about 5%; the rebuild re-judges each engine's whole history once, so properties of many short multi-peer histories pay most (`deep_departure_holds`, `nothing_before_a_cut_reaches_its_holder`: 6-peer worlds, each peer checked): issues/index-check-rebuild-cost.md. Rejected: sampling by transaction counts (1, 16, 256 per open, joins past powers of four from 4, covered drops at the 1st, 2nd, 4th ...): it checked most short histories and copies only at their first transaction, so no small test saw a fault that grows. Checking an aspect's first deferred change at once as well: +4% more on the properties, for faults a later rebuild hides. Checking per transaction only the index rows it wrote, against a derivation of those rows: blind to a row the transaction should have written and did not, the class the rebuild finds (an exact from-scratch derivation per transaction, compared on every index table the transaction changed, caught originals left out in 17 tests of the rebuild's 37, a stale `by_epoch` entry in 24 of 50).
- **Planted faults** (`tools/mutate.py`, engine lib and `it` default tests, tests failing with no index check / the open alone / open and rebuild): unindexing a rotation leaving its `by_epoch` entry 1 / 50 / 50; an edit's place left out of `originals` 16 / 16 / 37; an addendum's thing not judged again 22 / 24 / 24; an account's moved epochs' commits not judged again 38 / 38 / 38; an overlapping counter's other commit not judged again 10 / 10 / 10; a covered drop wiping the state (the rebuild check) 84. Caught by no test: a forgotten addendum's thing not judged again, a dropped part missing again not judged again.
- What the checks have caught, each incremental-vs-from-scratch on an unusual path: by the rebuild check, a fallen purge's register keeping an older value-less write, a snapshot's hidden-anchor copy not vouching at join, an invalid text delta leaving an empty record, a forged snapshot's key-erased remnant, paged states dropping chars the crdt keeps; by the index check, equivocating commits of one range kept by arrival order (`validity::overlapping_counters_spec_commits_4`), a node's own rotation not reading the history box its secrets open, derived-epoch adoption by arrival order, an account switch's epoch residue, a destruction's dropped keysets not rebuilt.
- Not covered: a `node/edges` row left stale when a destruction rewrites a role commit's record (no reopen follows a destruction's rewrite).

## Why kept and row dumps
Debug builds only (`#[cfg(debug_assertions)]`), for a count or retention test that fails.
- `Engine::why_kept(t)` (osis-sync: `World::why_kept(i, t)`): why `t` is still held, read from the retention rule's own walk (`retention::needed::search` over `needs` and `rooted`, the functions `settle` uses, so it cannot drift from the rule): rooted (in the node closure, with its tree path of strongs from the node root and each step's context), or the chain of needs (a strong from where, a held or pending commit it signed, a missing part, a holder, a profile) to the first rooted thing, or that nothing rooted needs it and it goes at the next pass end.
- `Engine::rows(prefix, tid)` (osis-sync: `World::rows(i, prefix, tid)`, the engine's and the sync store's local rows): each row's family (as `local_census`), key decoded (known tids `t:`, held commit IDs `c:`, text, hex), the tids it names (directly or by a held commit's things) and bytes, filtered by family prefix and by tid. `Engine::describe_rows` describes another store's rows by the same engine.
- S1 (`growth::releasing_own_things_*`, the grant arms) prints on a mismatch the rows of the differing families a fresh world's node lacks (same seed, so the same roots) and `why_kept` of each thing they name that the fresh node does not (`growth::leaked`).

## Loop guards
A fixpoint loop that a bug could keep going forever panics in a debug build instead of hanging (ostrich has no gdb): `osis_base::loop_guard::LoopGuard`, fed each round's progress, panics past a bound derived from the loop's size, naming the loop and its last 4 rounds. Guarded: node-sync's settle (`Node::settle`, the modules acting per round; 12 × (sync IDs + connections + 1)) and `LocalPeer::wake` (the commits each round ingested and whether the engine moved; (entries kept + 1)²). The sync `World`'s own loops (`run`, `advance`, `flush`, `step_or_wake`) each deliver per round, so its delivery cap (`World::cap`: `RULE_CAP`, `STORM_CAP`) bounds them, and it checks each step's settle rounds against `ROUND_CAP` after the step. `LocalPeer::sync_all` stops at n rounds; `deliver_sealed` ends when a round opens nothing.

## Confidentiality over `LocalPeer`
`Package`/`deliver`/`sync` hand over plaintext commits, so a peer that lost access still reads whatever it is sent: no "who can read" claim holds there. Such claims use the sealed mode: `LocalPeer::sealed` (makes the rotations due before encrypting first, then `Engine::seal_package`) and `deliver_sealed` (`Engine::open_package`). flows.rs `sealed_write` asserts a peer that does not read the write opened none of its bodies; `spread_sealed` is `spread` sealed. Plaintext stays right for setup and for what an engine does with what arrives (order, validity).

## Store-contents differential
For a refactor that must not change stored bytes or write order. Seeded `LocalPeer`/`MemoryBackend` stores are byte-deterministic once the persisted index tag is pinned (`index.rs` `VERSION` folds in `OSIS_INDEX_RULES`, a hash of the sources). Throwaway patch, on main and the branch alike: in `MemoryBackend::commit` fold each batch's ops into a running hash, and in a `Drop for Data` append `thread-name trace-hash final-hash batches rows` to a file named by an `OSIS_PROBE_*` variable; set `VERSION` to a constant; run the default tests plus the order properties on each, sort, diff (about 12,400 stores). Tests that differ run to run on one build (crash, store, runtime, driver, cli, some sync and encodings tests, `apply::tests_paged`'s paged-snapshot tests, osis `api::created_reads_through_run_time_key_*`: async, OS randomness) differ between builds too: rerun those on one build to rule them out. A store dropped on another thread moves its line to that thread's name: compare without names too.

## Measuring
Compare old and new code by instruction counts, never wall time on a loaded box; no timing runs inside a task (scaling: notes/test-scale.md).
- `tools/icount CMD...` prints `INSTR <n>` on stderr (user-space instructions via perf_event_open; needs `kernel.perf_event_paranoid` <= 2, which /etc/sysctl.d/60-perf.conf sets; builds icount.c into ~/.cache/osis on first use). Counts repeat to under 0.1%; CPU-s vary 20-40%. Old binary: `tools/bin-at <rev> <out> -p <crate>` (notes/build.md).
- `tools/cpuprof OUT <test binary> --exact <name>`: an LD_PRELOAD SIGPROF sampler, inclusive and self shares per function; `tools/cpuprof --report OUT.<pid> [N] [FILTER]` reprints. Over a whole binary (`--test-threads=8`) it shows what all tests share. Its own work counts in icount (about 3.5%), so count without it; it kills the perm `it`, crypto lib and transport binaries ("Profiling timer expired"). Over a whole binary it can write a second `OUT.<pid>` (a child process's): the larger file is the test binary's.
- Exact call counts and split by caller (valgrind is on fastbox-0, not ostrich): `valgrind --tool=callgrind` on one test (`--test-threads=1`, about 50x slower), `callgrind_annotate --tree=caller`; a recursive function's inclusive cost (`name'2`) counts each level again. `perf record` is refused here.
- Every default test alone under `tools/icount`: `tools/pertest.py` (Default-test cost).
- Per-test wall times: run a test binary with `RUSTC_BOOTSTRAP=1 <binary> -Z unstable-options --report-time` from its package dir; CPU per test with `/usr/bin/time <binary> --exact <name>`. A test binary run outside cargo runs proptests at 256 cases: set `PROPTEST_CASES=32 PROPTEST_DISABLE_FAILURE_PERSISTENCE=1` as `.cargo/config.toml` does.
- In code: `osis_base::costs` spans (`costs::span(name)` in the engine, `costs::take()` in a test).

## Default-test cost
Compare by instruction counts (Measuring); totals come from `tools/pertest.py top`. The gate's figures: notes/time-limits.md; where the time goes: issues/test-time.md. Under `tools/pertest.py` each test is its own process, so a test pays its process's cached fixtures (`world_of`, `LocalPeer::cached`): most of a median osis-sync or rotation test's count, and a cached setup's saving shows only over a whole binary or module in one process (`tools/icount BIN -q <module>::`).
- Measured not to help: every binary at once, harness inner threads at 1, opt-level 2 for the workspace crates (one-line edit builds 15-20% slower), selecting default-test crates by the diff (engine takes most commits: 15% at best, opens a gap). Only less work shortens it.
- In place:
  - osis-crypto at `opt-level = 2` in dev; smaller data where the property is relative; properties for sizes.
  - Shared setups: one setup copied per order where a test plays many orders from one start (`local_peer::Peer::fork`); cases sharing a setup copy it (`LocalPeer::cached`); every arrival order of a set walked as a tree of copies (osis-engine `tests_order::each_order`: a prefix is received once).
  - Tests looping over fixed seeds or cases run them on the seed runner (`stream::stream_differential_*`).
  - Debug checks that cost a compare, never a recompute: memo hits compared with a fresh run (`osis_base::memo` `Checks`); decoded commit records and parts (`engine/decoded.rs`) checked at every hit by comparing the bytes each was decoded from with those read now (decoding is a pure function of those bytes); engine reads (`Engine::read`: a store transaction dropped after, its in-memory changes undone) do none of a transaction's end work, and a debug build asserts each changed nothing.
  - `LocalPeer` delivery does no repeat work: `sync_all` stops after a round of duplicates; `sync` offers a package the receiver dropped at a pass end (things outside its node closure) again only once which of its things the receiver needs (`retention::needed::needs`) moved (else every pass delivered other accounts' roots again, to drop them at its end: 94% of `deep_departure_holds`' applies); it repeats no delivery that came back a duplicate and moved nothing, nor sends again one that came back a duplicate while the receiver holds every body of it (`Engine::holds_whole`: a copy can bring it nothing). A planted error on a third of duplicate ingests failed 17 engine lib tests with these skips, 20 without (the 3 rotation naming tests whose oracles read no duplicate).
  - The forensic attack's last-byte key test (notes/test-security.md).
- `tools/pertest.py run OUT` builds the default tests, copies their binaries aside, then (under `tools/heavy`, taken after the build, so editing while it waits changes nothing measured) runs each listed default test as its own process `--exact <name> --test-threads=1` from its package dir under `tools/icount`, writing name, instructions, CPU-s and exit code per line. `top OUT` lists per-binary totals and the costliest tests; `compare OLD NEW` the moves by test (crdt-model's and osis-keys' proptests draw fresh seeds per run and move 7-8% between identical runs: noise; a test failing only at pertest's load may be a KNOWN flake, tools/known_failures.txt). A compare against the last profile is also a cheap check for a storm that landed passing (a test 20x its old count). Against an older revision: `run` in a second worktree (`wt claim <name> <rev>`), `compare` here. The `test` limit alone (10 CPU-s or 15 s wall): `tools/limits.py tests`.

## Harness footguns
- A role commit past `grant`'s refusal needs `m.unchecked` plus `skip_writer_rules`.
- `costs::take` counts per thread: in a `LocalPeer` test it mixes every peer's work; scope the window to one peer's applies.
- A test on what a store holds keeps history on the aspects it probes: a store otherwise follows its own judgment (an automatic compaction), and a probe leaning on an entry kept for lack of a key fails for reasons unrelated to what it tests. A test meant to isolate one mechanism checks that it fails with that mechanism alone disabled: a test passing by either of two mechanisms isolates neither, and a plant a later backstop hides (the next transaction undoing what a dropped abort-undo left) needs a check between the two.
- A mutation that changes nothing (a `set` of the current value, a set `Add` of a live value) writes no delta, and a commit with no delta is not made (`commit_tx` returns `None`): a re-put meant to carry something silently commits nothing.
- `Engine::run` rolled back restores the store, not every in-memory map of `Core` (`Core::accounts` keeps what the trial cached): derive secrets from the store record, never from a cache filled inside a trial.
- `Meta::missing_parts` counts parts whose body is absent, not parts the node cannot open: test readability by value (`engine.get`). `LocalPeer` hands parts over in the clear, so "can it open" is a check of held secrets, not of reads.
- Sync `World`: `run` moves the world clock by its dial ticks (about an hour on `contacts`), so an `until` a minute ahead has passed before the grantee reads; an engine's `now()` lags the world clock until that node steps; `advance` over a long wait (`LOST_HEARD_WAIT_MS`) takes minutes of dial ticks: `skew` one node's clock instead. `RULE_CAP` is per world: `history::world` scales it by n, a hand-built world does not (`w.cap = n * RULE_CAP`).
- A per-process `--exact` run of one sync test rebuilds its cached fixtures (2-4 s for a `contacts` test, a third of that in-process).
- A proptest failure reproduces across runs only under `PROPTEST_RNG_SEED=N`; without it each run draws new cases.
- A count taken inside a `measured` closure (`osis_base::costs::take`) zeroes what the closure is measured by: every n/10n check then passes at 0. Probe outside the measured region.
- A loop over consecutive seeds with `rng(seed | 1)` makes seeds 2k and 2k+1 the same history: use odd seeds via `step_by(2)`.
