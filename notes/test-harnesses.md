# Test harnesses
> Summary: How to run and replay seeded tests (env vars through `osis_base::testenv`, seed runners, coverage floors), copied worlds, the debug rebuild, index and verdict checks every test runs, why-kept and row dumps, loop guards, `LocalPeer` delivery by sync ID and sealed delivery, the store-contents differential, measuring (icount, cpuprof, callgrind, pertest), the default-test cost, mutation probes, and harness footguns.

## Env vars and seeds
- Harness env vars (`OSIS_*_START`/`_SEEDS`, `OSIS_PERM_SEED`, ...) are read through `osis_base::testenv`, which panics on an unparsable value, zero seeds, or any set `OSIS_*` variable not in core/base/testenv-known.txt (policy.py keeps that list equal to what the sources name: add a new variable at its end; read at run time, so adding one rebuilds nothing). Probe variables: notes/build.md, Footguns.
- A set variable and an overridden range are echoed past libtest's capture: check that line on a passing run, not only `1 passed`. Per-seed output needs `-- --nocapture`. Sizes (`OSIS_FULL=1`, the gate's a tenth): notes/testing.md, Sizes.
- **Every property and its variable**: `python3 tools/test_select.py --all` lists every property test by crate with every `OSIS_*` start variable the gate sets. Each harness prints its own replay line for a failing seed: use it as printed.
- **`_plain` and `_large`**: a seed runner is a property, never a default test (notes/testing.md, When tests run). Its `_plain` runs the gate-sized sample: a fixed covering set chosen by planted faults (reading no environment), or a seed range the gate offsets (`OSIS_*_START`/`_SEEDS`); its `_large` reads the range at full size (`--ignored --exact <name>_large`). The replay line names the `_large` where it checks a seed as the `_plain` does, else the `_plain`.
- Engine lib harnesses: `cargo test -p osis-engine --lib <path> -- --ignored --exact`; a copied binary from `tools/bin-at REV OUT --lib osis-engine`, run from `core/engine`.

Crate-wide seeds:
- **osis-crdt**: every `testutil::rng(seed)` samples other runs with `OSIS_CRDT_SEED=<n>` (hashed into each run's seed; unset, the committed seeds); a panicking test prints the effective seed. Properties take `OSIS_CRDT_START`/`_SEEDS` (`testutil::crdt_seeds`) and draw from `testutil::fixed`, so the printed replay line is the whole replay. `OSIS_SHRINK=<seed> cargo test -p osis-crdt --lib -- --ignored shrink_script` shrinks a failing `fuzz_seq::tests::random_scripts_replay_plain_spec_5_7` script. `OSIS_CRDT_SHRINK=1` on a `crdt_equals_model` replay line shrinks the seed's deltas while the differential still fails (`osis_base::testenv::shrinking`; `OSIS_SHRINK_MATCH` keeps to one failure).
- **osis-perm**: `differential`, `queries`, `incremental` sample other histories with `OSIS_PERM_SEED=<n>`; each run is 16 shards seeded `seed ^ i << 40` (a fixed count, so a failing seed reproduces anywhere; the panic names the shard's seed).
- **order harness** (`held_set_decides`): `OSIS_ORDER_START`, `_SEEDS`, `_SEED` (one seed), `_LEN`, `_CLOCK`.
  - `OSIS_ORDER_SHRINK=1` shrinks each failure (`order::shrink`, at most `SHRINK_CANDIDATES` candidates) and prints the history as Rust a scripted test compiles (`rust_of`). A candidate counts only when it fails as the original did (`failure_class`), so it cannot drift to another bug; `OSIS_SHRINK_MATCH=<text>` keeps to failures containing the text instead, `OSIS_SHRINK_ANY=1` to any. A `settled` history's tail stays whole.
  - `OSIS_ORDER_STATS=1` prints each history and the tallies; `OSIS_ORDER_DUMP=1` explains a failing node (what it prints: its readers' docs in order.rs).
  - For a node-holds-or-drops difference a dump of the shrunk history usually names the cause; probing the drop decision beats shrinking further.
- **sim**: notes/test-sim.md, Running and replaying.

## Seed runners (`osis_base::testenv`)
- `run_seeds` (and `Seeds::run`, which announces an env range first) runs a seed per thread per core (`OSIS_SEED_THREADS` overrides, for every harness); `run_jobs` is the general runner (sim-sweep uses it). Their docs give the output and exit. A multi-seed run goes through them, not a serial loop.
- **Hung seeds**: `OSIS_SEED_TIMEOUT_SECS` (default 600) is CPU time, not wall: under load a 5 CPU-s seed can take 700 s wall. A lower value names a hung seed early in quick runs. A hung thread prints its backtrace at its next `testenv::checkpoint()` (`LocalPeer::sync`, the sim's step loop).
- `Cpu::now()`/`secs_since` reads the CPU spent on a thread's work, the threads `par_map` and `run_jobs` ran for it included; `run_jobs`'s summary ends with its jobs' CPU-s, which the gate's summary lists per property (notes/gate.md, The summary). `pooled_map` is `par_map` holding a `Permit` per call, so concurrent tests and a run's seeds and their parts share the cores.
- **Coverage floors**: a property over a seed range checks what its seeds reached with `testenv::reach_floor` at every size and offset, never only at the default range nor above some seed count.
  - The rate is at most what any one seed reaches (under 1 where a seed may reach none) and, where seeds vary, about a quarter of the mean or less, so offset ranges meet it; set it from runs at offsets, never from the default seeds alone.
  - A case the seed draws on purpose (a seed class: `seed % 8 < 2` large values) is asserted per seed instead, and a ratio per seed with the fewest seen in mind.
  - A `_plain` running a fixed covering set asserts its set reaches each case exactly; its `_large` twin carries the rates (rotation `tests_property::SHAPES`).
  - A case too rare for any rate to prove at the gate's size gets more default seeds (`purge_by_id_*_plain_*`: 8) or a draw on purpose, never a floor of 0. The order harness's floors are per emphasis present and per whole emphasis cycle (`Seen::floors`).
- **Converting a fixed-seed loop to a range**: the seed may index nothing but an RNG or a modulus. A value sized by the raw seed (`honest_values_*_plain` asked for 44 TB at the gate's offset of about 4e11) aborts the whole property binary, leaving every later property in it unrun; a loop index turned seed keeps everything it fed (crdt edit-window rounds stamped changes at `10 + round * 10`, above the local edit's stamp at an offset). A thread-local setting (`PageParams::set_test`) is set inside the per-seed closure, or `Seeds::run`'s threads run at defaults and pass for the wrong reason. Before committing, run the converted property once at a gate-sized offset (`OSIS_*_START=<random below 10^12>`).

## Copied worlds
A setup many tests share is built once per test process and each test gets an exact in-memory copy of the live world: it goes on as the original would (same next commit IDs, rng draws, connections, queues, memo hits), so a test cannot tell it from one it built. Reopening stores is not a copy (every node restarts, reconnects and syncs again).
- **Adding a cached setup**: `LocalPeer::cached(key, || (peer, extra))`, `LocalPeer::cached_world` for a world holding peers beside state that is not `Clone` (rotation tests_property's `Run`), or `osis_base::copying::cached` (the mechanism: its module doc) for another world type. Not cached: a setup that closes and reopens a node, real-runtime tests; no osis-level harness shares a setup.
- **Hooks** (test-only, `#[doc(hidden)]`; policy.py keeps them out of product sources, because two live copies are one node twice and reuse nonces, counters and commit IDs): `Engine::test_copy(clock)`, osis-store's (`Store::test_copy` over `Backend`/`RootStorage::test_copy_boxed`, memory ones only), `NodeRng::test_copy`; harness copies `Peer::copy`, `LocalPeer::copy`. Plain `Clone` is derived on data; the types owning identity, rng or a live store copy only through these hooks. Engine event receivers are subscribed again with the unread events (`Engine::test_subscribe_with`); commit listeners are not copied. Differentials: osis-engine it `copies`.
- **Adding a cache to a test**: a test that passes built fresh and fails on a newly cached setup has found a copy that is not its original: rerun it on the fresh build with `lp.copy()` before suspecting the edit. Each cached builder has its own key (one key holding two value types hands back the wrong one), and a thread-local filled beside the setup (rotation `tests_signing`'s `SETUP_HEADS`) is stored with the cache and set again on every copy (`world_then`).
- **A copy's gap** may be a state a production path reaches too: a copy leaving the path wait unset matches what a rollback leaves, so fixing only the copy hides the rollback bug. Before fixing a copy, ask which product path reaches the same state; a differential of such a fix keeps the copy's change while undoing the rest.

## Debug checks
Every debug-build test runs these, so every test is also an incremental-equals-from-scratch test (notes/test-design.md). None samples. A whole check (O(everything held)) runs once at the end of the history, never per transaction (a test's cost would grow with n squared); per transaction runs only what costs about what the transaction did. All are invisible to scale counts (`costs::paused`, `osis_perm::uncounted`).
- **Rebuild check** (`apply::atomic::check_rebuilt`, its doc says which aspects are checked when): a touched aspect's state must equal `rebuilt` (spec/crdt.md §4.6), compared encoded with the caches derived from it. A deferred aspect (`Core::unchecked_states`) a later rebuild rewrites is never seen wrong. A test hook writing a state no body gives sets `Core::unchecked_tx`. A failure panics with the differing Debug lines.
- **Index check** (`Engine::check_index`, its doc): on a clock stopped at the last transaction (a timer due since has not run), after the node closure walked afresh (`check_closure`), compared by `Core::same_index`. It asserts that an open decodes no commit header: judging anything at load from headers (`LazyHeader::arc()` decodes at once; clone the `LazyHeader` and deref only where the record is held) fails it, often only in node properties or the sim. The fresh cores borrow the node's decoded records (`Core::decoded`, compared at every hit), so the rebuild judges everything again without decoding again.
- **Verdict checks** (`Engine::checked_verdicts`, at the end of history and inside the index check): every held commit's flags are what judging it now gives (`validity::misjudged`), then every re-grant bound a role timeline memoizes is what a search at every change finds. Per re-judge only the touched part (`misjudged_on`: the commits on `stale_things`, `stale_under`), which catches a verdict wrong only for a while.
- **Row check** (`retention::leaving::rows_exact`, in the index check; notes/engine-retention-dating.md Rows). `Core::unchecked_rows` is recorded where that is decided independently of the dating's own choices (a row written or removed, an aspect of a commit the transaction changed, a setting change, a forgotten aspect). Per pass, each row written is checked against the state (`leaving::check_row`: `held_date` against `whole_date`); at the end the kept held writes are compared row for row with those built from the held bodies (`bounds::index_exact`), so a join or leave a pass missed is found there, and each row with its date from those. The built held writes are shared by the process's engines, keyed by a hash of what they are built of (`bounds::BUILT`): the order harness's orders of one held set and a synced world's peers build them once (gate-size `held_set_decides_plain`: 48,000 checks, 600 distinct sets). Rejected: every row of each aspect checked per pass (O(the aspect's history) per transaction, n squared over a history).
- **The end of history** is the engine's drop (`impl Drop for Engine`, debug builds): the verdict checks, then the index check if a durable transaction changed a state or a part, or a transaction rolled back, since it last ran, else the states left unchecked. A reload runs a due index check first (`check_before_reload`), since it would replace what a rollback left wrong. Skipped under `OSIS_NO_END_CHECKS=1`, while a panic unwinds, a load is half done (`Engine::loading`), a write's outcome is unknown, or the store fails (`Error::Store` ends a crash test quietly). A copy starts checked: its original checks their shared past. An engine lib test editing an index in memory sets `Engine::index_poked`. `Engine::check_every_tx` (by hand) runs the index check after every changing transaction, to find the one that diverged; a reproducer whose point is one moment calls `check_index` there.
- **Cost**: the rebuild is about 15% of the engine lib default tests, the open about 5%; properties of many short multi-peer histories pay most (issues/index-check-rebuild-cost.md). Rejected: sampling by transaction counts (it checked most short histories and copies only at their first transaction, so no small test saw a fault that grows); checking an aspect's first deferred change at once as well (+4% on the properties, for faults a later rebuild hides); checking per transaction only the index rows it wrote (blind to a row it should have written, the class the rebuild finds).
- **Planted faults** no default test catches (`tools/mutate.py` over the engine lib and `it`, perm `it`): a forgotten addendum's thing not judged again; a dropped part missing again not judged again; a rebuilt aspect not dated whole (`bounds::mark_bounded`; the change that rebuilds it is also a noted body leaving, which `date_due` dates whole on its own). **Planted verdict faults**: a replay's raise ignoring the holder's own level.
- Not covered: a `node/perm` row left stale when a destruction rewrites a role commit's record (no reopen follows a destruction's rewrite).

## Why kept and row dumps
Debug builds only, for a count, retention, role or read test that fails; each reads the rule's own code, so it cannot drift from it (their docs in `engine/explain.rs`). osis-sync's `World` has each per node.
- `Engine::why_kept(t)`: rooted (with its path of strongs from the node root), or the chain of needs to the first rooted thing, or that it goes at the next pass end.
- `Engine::rows(prefix, tid)` (osis-sync `World::rows` covers the sync store's rows too): each row's family (as `local_census`), key decoded (`t:` known tids, `c:` held commit IDs), the tids it names and bytes. `Engine::describe_rows` describes another store's rows by the same engine.
- `Engine::why_role(t)`: roles, paths, secrets and `lost_due`'s clauses (`rotation::lost::explain_due`). Its `kept copy` line is the retain decision (`retention::forget`). A role dump of the unshrunk history shows words and grants a shrink drops, which once pointed a diagnosis at the wrong cause.
- `Engine::describe_commit(c)` names a trace's `C..` (osis-sync marks node and account tids `(n<j>)`).
- `World::sync_ids_of(t)` (any build): how each node syncs `t`, so a sync ID fork shows in one call.
- Printed on failure: S1 (`growth::releasing_own_things_*`) prints the rows of the differing families a fresh world's node lacks and `why_kept` of each thing they name (`growth::leaked`); the sync differential's role and read clauses (`history::closure_clauses`) print `why_role`.
- **Replaying without the end checks**: `OSIS_NO_END_CHECKS=1` (`testenv::end_checks`; by hand only) also skips `World::run`'s own quiet checks (`sources_are_members`, `unlogged_must_holds`, `wanted_blobs_in_reach`), so `differential::holds` and every scenario calling `check` return their world for inspection. It prints `history::check skipped` past capture. Never set it while shrinking: a candidate whose failure is the check then passes.

## Loop guards
A fixpoint loop that a bug could keep going forever panics in a debug build instead of hanging (ostrich has no gdb): `osis_base::loop_guard::LoopGuard` panics past a bound derived from the loop's size, naming the loop and its last 4 rounds. Guarded: `Node::settle` (12 × (sync IDs + connections + 1)) and `LocalPeer::wake` ((entries kept + 1)²); `Engine::run`'s end loops. The sync `World`'s own loops each deliver per round, so its delivery cap (`World::cap`: `RULE_CAP`, `STORM_CAP`) bounds them, and it checks each step's settle rounds against `ROUND_CAP`. `LocalPeer::sync_all` stops at n rounds; `deliver_sealed` ends when a round opens nothing.
- The bound is a closure so a release build never computes it: compute the size inside the closure (a `things().count()` taken before the call costs every release round a walk of the node closure).
- A loop deciding "something entered" from a cloned `Feed` checks the key is still present: `Feed::added` keeps keys a failed step's rollback took out again, and such a loop spins to its guard.

## Delivery by sync ID over `LocalPeer`
A node takes content only of things in its node closure (spec/commits.md §4 Outside the node closure), and a `LocalPeer` carrier never goes. So `LocalPeer::sync`/`sync_all` send what the sync IDs the receiver syncs carry, decided at the sender by the product's own rule (`packages_under` over `Engine::carried_under`, `sync_bodies`), again under the sync IDs it comes to sync in the pass.
- A sender's packages are built once per state of its engine (`SyncMemo::whole`) and trimmed per set of sync IDs (`sent_parts`); built per receiver they cost 40-50% of the rotation properties. Certificate parts (`Engine::certificate_parts`) go to every node: they stand for the routes the harness does not play (contact cards, links, grant fires, pairing).
- No repeat work: `sync_all` stops after a round of duplicates; `sync` offers a package the receiver dropped at a pass end again only once `retention::needed::needs` moved (else every pass delivers other accounts' roots again, to drop them: most of `deep_departure_holds_large`'s applies); it repeats no delivery that came back a duplicate and moved nothing, nor one the receiver holds whole (`Engine::holds_whole`).
- **Hand deliveries** pick the same (each documented where defined): `packages_for(from, to)` (engine `it`: `common::packages_for`; `package_for` for one commit), `LocalPeer::packages_to`/`packages_to_peer` (on a copy), `common::packages_for_peer`, `common::packages_reading` (a fresh reader given its grant alone), `packages_of(from, t)`, `trimmed`, `common::give_carried`, `flows::send_carried`; `LocalPeer::commit_ids` where only IDs are read. A copy per call costs about what the test's own deliveries do: in a per-seed or per-order loop use the copy-free forms, and one reader's list for every fresh reader of an order loop.
- An observer is an account granted read and holding the thing (`common::reader`, `LocalPeer::fresh_reader`, `fresh_net`, `share`); a role-less node holding a thing by a node-root strong keeps none of its content, so comparing what it reads compares nothing. A fresh reader's seed must not be a net peer's (`net(n, s)` seeds `s*1000+i`): the same seed is the same account, and its grant re-grants that peer.
- A test's receive of forged or partial input goes through `common::unless_refused` (a refusal is fine, a local error fails the test), never `let _ =`.
- `Engine::package` hand deliveries are still whole: what they bring outside the closure waits for good (issues/engine-harness-whole-packages.md).

## Confidentiality over `LocalPeer`
`Package`/`deliver`/`sync` hand over plaintext commits, so a peer that lost access still reads whatever it is sent: no "who can read" claim holds there. Such claims use the sealed mode (`LocalPeer::sealed`, `deliver_sealed`): flows.rs `sealed_write` asserts a peer that does not read the write opened none of its bodies; `spread_sealed` is `spread` sealed. Plaintext stays right for setup and for what an engine does with what arrives (order, validity).

## Store-contents differential
For a refactor that must not change stored bytes or write order. Seeded `LocalPeer`/`MemoryBackend` stores are byte-deterministic once the persisted index tag is pinned (`index.rs` `VERSION` folds in `OSIS_INDEX_RULES`, a hash of the sources). Throwaway patch, on main and the branch alike: in `MemoryBackend::commit` fold each batch's ops into a running hash, and in a `Drop for Data` append `thread-name trace-hash final-hash batches rows` to a file named by an `OSIS_PROBE_*` variable; set `VERSION` to a constant; run the default tests plus the order properties on each, sort, diff. Tests that differ run to run on one build (crash, store, runtime, driver, cli, some sync and encodings tests, `apply::tests_paged`'s paged-snapshot tests, osis `api::created_reads_through_run_time_key_*`) differ between builds too: rerun those on one build to rule them out. A store dropped on another thread moves its line to that thread's name: compare without names too.

## Measuring
Compare old and new code by instruction counts, never wall time on a loaded box; no timing runs inside a task (scaling: notes/test-scale.md). Usage is in each tool's header.
- `tools/icount CMD...` prints `INSTR <n>` (needs `kernel.perf_event_paranoid` <= 2, which /etc/sysctl.d/60-perf.conf sets). Counts repeat to under 0.1%; CPU-s vary 20-40%. Old binary: `tools/bin-at <rev> <out> -p <crate>` (notes/build.md). `tools/icount BIN -q <filter>` prints the count, not whether the tests passed: run the filter first.
- After `git rebase origin/main`, compare against a binary built from the rebased main's test files (`git checkout origin/main -- <crate>/tests/it`, build, copy aside, `git checkout HEAD -- <crate>/tests/it`), never the pre-rebase baseline.
- A multi-threaded property's count moves with thread timing: compare at `OSIS_SEED_THREADS=1`.
- An `--exact` run of one test counts its fixture too (a 4-node world can be most of it): for a fixture-free delta compare in-process module counts (`tools/icount BIN -q <module>::`); judge a shared-fixture change by the whole binary (`tools/icount BIN -q`), which a gate pays once.
- Where a cost re-derives everything: the `Effects` cause counts (notes/engine.md, Why a key went due). Product cost against oracle cost: `tools/cpuprof` with `CPUPROF_INSTR` on a copied binary, filtered on the oracle function.
- `tools/cpuprof`: CPU-time samples skew with load; `CPUPROF_INSTR=N` samples every N user-space instructions per thread instead (2000000 is about 2 ms), so shares compare across runs. It keeps the first 120,000 samples only (past that the report says TRUNCATED, and a share reads the run's start): N above the run's instructions / 100,000 (a gate-size `held_set_decides` size, about 1,900 G: 20000000). Stacks keep 160 frames, so FILTER can name an outer frame. Over a whole binary it may write a second `OUT.<pid>` (a child's): the larger is the test binary's. Its own work counts in icount (about 3.5%). Its SIGPROF mode kills the perm `it`, crypto lib and transport binaries ("Profiling timer expired"; `CPUPROF_INSTR` runs perm `it`). Its stacks mislead for spawned threads and deep frames: confirm a suspect with `tools/icount` on an env-gated variant before changing code.
- Exact call counts by caller (valgrind is on fastbox-0, not ostrich): `valgrind --tool=callgrind` on one test (`--test-threads=1`, about 50x slower), `callgrind_annotate --tree=caller`; a recursive function's inclusive cost (`name'2`) counts each level again. `perf record` is refused here.
- Which commit grew a test: `tools/bin-at` plus `tools/icount` over every 5th commit in the background, then the window.
- Per-test wall times: `RUSTC_BOOTSTRAP=1 <binary> -Z unstable-options --report-time` from its package dir (the binary, not `cargo test`: `RUSTC_BOOTSTRAP` through cargo builds a second artifact set); CPU per test with `/usr/bin/time <binary> --exact <name>`. Outside cargo set the proptest env (notes/build.md, Footguns); `tools/icount` and `tools/cpuprof` set it themselves.
- Round-count claims read the `costs` counts the sync `World` and `Node::settle` keep (`settle rounds`, `settle rounds most`, `settle follows moved`), no logger.
- Named order tests (`order::check`) print each passing history's `Seen` under `--nocapture`: diff two revisions' outputs for "outputs identical".
- **Every default test, or every module, alone** (`tools/pertest.py`, its header): `--modules` is what a gate pays and where to cut, per test which test moved. In `compare`, crdt-model's and osis-keys' proptests draw fresh seeds per run and move 7-8% between identical runs (noise); a test failing only at pertest's load may be a KNOWN flake. A compare against the last profile is also a cheap check for a storm that landed passing (a test 20x its old count). The `test` limit alone (10 CPU-s or 15 s wall): `tools/limits.py tests`.

## Default-test cost
Totals from `tools/pertest.py top`; each binary's count, which the gate holds it to: tools/test_cost.txt (notes/gate.md, The summary: Test cost); the gate's figures: notes/time-limits.md; where the time goes and the levers left: issues/test-time.md. Only less work shortens the default tests.
- Profiles under `/home/ai/osis-profiles/` (start a test-speed job from the newest with `tools/pertest.py compare` instead of profiling again); the newest whole one is `pertest-5e3055f83` (binaries in `pertest-5e3055f83.bins/`), and `pertest-test-cost-5` the engine's two, osis's and osis-sync's `it` with the fix below.
- At 5e3055f83: 3,639 default tests, 8,545 G and 2,928 CPU-s per test process (osis-sync `it` 2,628 G, engine lib 2,383, engine `it` 2,258, osis `it` 671, held-model `it` 313, osis-cli 70, osis-perm `it` 33, osis-crdt lib 32, the rest 158). Three tests had grown 11-38x (a 2,500-part commit judged once per part; an account root's certificate search reaching every thing it minted); with that fixed the four binaries take 7,114 G (osis-sync `it` 2,443, engine lib 2,074, engine `it` 2,245, osis `it` 352), about 7,720 G in all. The per-test excess over a whole-binary run is fixtures each test process builds again. In engine tests the drop's index check is 4-7% of the costliest tests and 18-23% of whole engine modules.
- Measured not to help: the order harness's oracle starting from a kept copy of the setup-given node (1.4% of `order::*`), every binary at once, harness inner threads at 1, opt-level 2 for the workspace crates (one-line edit builds 15-20% slower), selecting default-test crates by the diff (engine takes most commits: 15% at best, opens a gap).
- Patterns that keep a test cheap (follow them in new tests):
  - Shared setups: one setup copied per order (`local_peer::Peer::fork`); cases sharing a setup copy it (Copied worlds); every arrival order walked as a tree of copies (osis-engine it `apply_order::each_order`); the judgment vectors' replays start from a copy (`judgment::replay`); a written history (`order::play`, `check`) starts from a copy of the node that took the setup, kept per process (`order::after_setup`: about 230 MB more peak memory for `order::*`), while a drawn one (`play_with`, `check_on`) keeps none, its clock drawn anew so a cache would grow with the seeds; a sweep from one store copies its closed files per point (osis-store `FileDevice::copy`).
  - A random generator looped over fixed seeds is a `_plain` property (Env vars and seeds).
  - A size bound checked at its real constant with a fixture the bound counts cheaply: a text string counts one item per byte (osis-crdt `page_items_cap_spec_8`, `MAX_PAGE_ITEMS`), a range record stands for many elements (`sweep_is_bounded_and_finishes_spec_sync_7`, `MAX_DELTA_BARE`): about 30 M instructions each instead of 10-12 G. A setup reaching a bound built as records instead of commits (osis-crdt `hostile_moves_join_bounded_spec_6`), the bound checked at its count and one past it.
  - A random property's rare case drawn on purpose, then histories run until a coverage tally is met, never a fixed seed list (osis-crdt `snapshot_then_edit`, `snapshot_edits_follow_cache_spec_6`, `large_text_batch_is_net_effect_spec_4_5`). Tally the path a test's name claims: a builder test said its view was a layer while no op held one.
  - Debug checks that cost a compare, never a recompute: memo hits compared with a fresh run (`Checks`); `Effects` comparisons only on a thread that turns them on (`memo::check_effects`: random-history worlds, `history::world_of`), since a comparison's settle warms caches and counted tests would move; decoded records checked at every hit by comparing their bytes (`engine/decoded.rs`); engine reads do none of a transaction's end work, and a debug build asserts each changed nothing.
  - Smaller data where the property is relative.
  - Independent work in one test runs in parallel, as the gate bounds each test's wall: separate tests per independent piece (the judgment vectors, one test per file), or its parts on the process's permits (a named order check's held sets and deliveries, as a drawn one's: `order::check`; each walk branch of n ways makes n - 1 copies however its tasks interleave, `order::At`, so `Seen` stays diffable).

## Mutation probes
`tools/mutate.py` (usage in its doc) plants a fault, builds once, runs the given tests and prints which failed; a plant no test fails is a test gap: add a focused test, or an issue. For many plants: `MUTATE_HEAVY=1 MUTATE_PER_HOLD=2`. Reference-graph rules, where caught at all, are caught by focused tests, never by a differential or sim alone. Open gaps: Debug checks (Planted faults); issues/strip-rule-gaps.md.

## Harness footguns
**Engine and `LocalPeer`**
- `Engine::local_census` keys keep the family's trailing `/` (`"pc/"`): a lookup by the bare prefix reads no rows, and an "is zero" assert passes vacuously. Probe every row-count assert with its mechanism off.
- `Engine::fires_owed` is in `FireId` order: `.last()` is the highest id, not the newest fire; diff the owed set before and after.
- `Hlc::peek` jumps to every received `ts`: a wait "until R's `ts`" against it ends the moment R arrives. A rule "as of its wall clock" reads `Hlc::wall`, and a wait on wall time sets a wake.
- `local_peer::Peer::receive` wakes and re-examines after every ingest, so a wake a shortcut skips is invisible there: probe an ingest path through `Engine::ingest`.
- `local_peer::Peer::pulled_anew` fills only at `receive`/`reexamine`: a test clearing it after a copy sees the setup's pulls at the next receive (`reexamine` first). The order harness's `fetch_missing` never delivers what a node pulls anew: a node relying on one fails `held_set_decides` with no hint.
- `LocalPeer::sync` carries no ephemeral commit: hand one over with `memory_blob` and `ingest_memory`.
- A role commit past `grant`'s refusal needs `m.unchecked` plus `skip_writer_rules`.
- A mutation that changes nothing (a `set` of the current value, a set `Add` of a live value) writes no delta, and a commit with no delta is not made (`commit_tx` returns `None`).
- `Engine::run` rolled back keeps what a trial cached in some `Core` maps (`Core::accounts`): derive secrets from the store record, never from a cache filled inside a trial.
- `Meta::missing_parts` counts parts whose body is absent, not parts the node cannot open: test readability by value (`engine.get`); `LocalPeer` hands parts over in the clear.
- `Engine::seal_package` writes a `dw/` row at the maker: seal after taking a census.
- A test on what a store holds keeps history on the aspects it probes: a store otherwise compacts by its own judgment, and a probe leaning on an entry kept for lack of a key fails for unrelated reasons.
- A thing re-entering the node closure usually rejoins by its own sync ID, pulled from the start anyway, so a re-entry test passes with `refetch` broken: only a dependent thing in a unit whose sync ID never left exercises it.
- A drop path that marks commits stale needs a test where the drop happens in the end-of-transaction tail: only the debug assert "stale validity left unjudged" catches a marker set after the last re-judge.
- A late-order test says which copy it delivers: a node's copy of a commit it purged is header-only, so delivering it tests "never held the body", not "the body arrived late".
- A test handing a grant's packages to a node before it holds the thing loses what lies outside its node closure: accept first, then deliver.
- A kept copy syncs nothing: a node holding only a kept copy never sees a later flip of the way; a test of a recorded holder leaving uses an ended way whose holder the node still syncs.
- A hand-again-until-quiet loop must not count every non-`Duplicate` result as progress: a commit kept pending comes back `Pending` every round, so the loop runs its full bound (osis-sync `history::reference`: 319 rounds instead of 2, 5x the sims' and differential's cost). Stop once a round applies nothing and leaves `Engine::pending` as it was.
- `order.rs`'s and `parts.rs`'s `FRESH` are one account, granted by the base; the judgment vectors' judge is that account too (`order::judge_at`).
- A world built under `PageParams::set_test` must not go into `LocalPeer::cached`: other tests would read its small-page states.
- `Core::timer_floor = 0` does not wake a sync daemon: node-sync wakes at `next_timer` (`Node::next_wake`); "make a tick due" means making `next_timer` say now.

**Sync `World`**
- `run` moves the world clock by its dial ticks (about an hour on `contacts`), so an `until` a minute ahead has passed before the grantee reads; an engine's `now()` lags the world clock until that node steps; `advance` over a long wait (`LOST_HEARD_WAIT_MS`) takes minutes of dial ticks: `skew` one node's clock instead. `RULE_CAP` is per world: `history::world_of` scales it by its nodes, a hand-built world does not (`w.cap = n * RULE_CAP`).
- `power_off` starts the node's monotonic clock again from 0 (`NodeClock::boot`) while its wall clock and every other node's run on: a value dated on the monotonic clock that outlives a restart reads as far in the future.
- A storm panic in a hand world with partitions is often dial ticks toward the cut-off peers (`world_of(0, 2, 3)` with two partitioned runs passes `RULE_CAP` on them alone): raise `w.cap` before reading it as a loop.
- No World lever splits a rotation from its step or one fetch over two sources: deliver such a race by hand inside the `w.write` closure, before `Input::Wrote` lets the node settle; content arriving before its keysets goes to the engine (`LocalPeer`, with `Engine::seal_body` and `open_entry`, whose blobs the engine notes: a `LocalPeer::sealed` package notes none).
- A world that waits out `PASS_WAIT_MS` with a node away costs 7-10 GB, mostly dial ticks toward the absent node.
- `step_or_wake` keeps returning true while any node dials a partitioned peer: bound such a loop by world time. A test reading what a peer was served after `run()` misses entries the peer dropped on learning it no longer holds the thing: check after each delivery.
- The quiet checks (`unlogged_must_holds`, `unreached_must_holds`, `wanted_blobs_in_reach`: no commit waits for a blob its own sync store or a connected source holds) run at the end of every `World::run`, a partitioned mid-script one included: read which step's run panicked first. A pass begun late in a run can be under way at quiet: `run` then runs once more to `PASS_WAIT_MS` past quiet before the checks. A test that wants a pass still under way after `run` steps by hand (`step_or_wake`).
- A per-process `--exact` run of one sync test rebuilds its cached fixtures (2-4 s for a `contacts` test, a third of that in-process).
- Streams harness: a body opened as `Opening::Taken` (the `Table` default) leaves no store entry though the pull worked: check `knows`. A late message harms only a member already at the stream, so a late-reply probe on a first join passes with its rule disabled.
- A world test of a change made while a peer is away passes with the in-place judgement removed: the first reconnect after first contact judges every member. Mutation-check it with the peer away and back once first, and mutate to the old behaviour (unfollow), not to a bare return that leaves the memo key due.
- A count test built on `history::world_of` turns the memo debug comparisons off before counting (`idle::exact`): their reads count.

**Counting**
- `costs::take` counts per thread: in a `LocalPeer` test it mixes every peer's work; scope the window to one peer's applies.
- `testenv::Cpu` counts only threads `testenv`'s `par_map`/`run_jobs` ran: work on other threads (osis-store forensic's own `par_map`, any `thread::scope`) is missing. Count such work with `tools/icount`.
- `icount` of one `--exact` sync test reads its cached fixture too (most `world_of(0, 4, 4)` tests 30-40 G each, in-binary 2-10 G): rank by module or whole-binary counts.
- A memo's `try_settle` returns `None` for an unchanged answer: count `Some` returns against total runs.
- A count taken inside a `measured` closure (`osis_base::costs::take`) zeroes what the closure is measured by: every n/10n check then passes at 0. Probe outside the measured region.
- A new `osis_base::costs` count shows in every test comparing all spans (osis `making::`, engine `closure::` assert exact equality): a counter one scale test reads goes outside the shared table (as `osis_store::bytes_handed`).
- `osis_perm::commits_walked` deltas around a step settle "who can force many walks" questions quickly (k against 10k).
- A memo kept by a key's stamp, read before that key is inserted, computes again at the next look: a cost test looks once before counting.
- An n/10n count through a real world needs an event that moves inputs alone: most events (a redeem, a register) also bring new keys.
- A cost test varying only what the node closure holds cannot see a pass judging every held thing when the filter to things outside it is uncounted: count what is due before filtering.
- `read: judged` counts twice per judgement (the `Effects` span plus `judge::body`'s own). An env-gated dump inside a `Cutoff` derivation also prints the debug comparison runs: read growth from `costs` counts, not dump lines.
- A churn helper taking a start key: keep its range far from the keys the test reads.
- A count test with a tolerance (charged within 1.25x of held) passes with a whole term dropped: mutate each term before trusting a tolerance, and make the check exact where every term can be written down.

**Models and generators**
- roles-model `family_run(stride)`: a stride sharing a factor with a dimension's size fixes that dimension (every 50th world: `h_t1` always false); strides of mixed-radix families are coprime with every radix.
- roles-model: probe a failing world by printing it and its reference, never by shrinking it first (one shrink ran past 10 minutes on one core). Two readings of one world (a mutant against the rule) go in one process with a thread-local switch: an env var cannot switch per call across `on_every_core` threads.
- roles-model `paths::World::lowers` counts every edge write below admin, a fresh grant of write included: it is not "a removal" (the evidence model defines its own `removes`).
- held-model `gen::shuffle` does not reorder `Held::dots`, and `Dots::commit` takes the first range holding a dot: an order test over overlapping ranges shuffles `dots` itself (`props_overlap::reorder`).
- A generator may build in-memory states no encoder writes (a crdt position write stamped with its element's dot): before fixing a rule for one, check it decodes from bytes; a decoder test of such bytes hand-patches an encoding (decode to `Value`, change it, re-encode). `DeltaBuilder` `Add v` of a value already live writes nothing: a forged copy adds a value the base lacks.
- `Debug` of a crdt `Seq` expands range records per element, so a printed state never shows whether a join split a range: count `elems().len()` or spans. Text ranges exist only content-less.
- A loop over consecutive seeds with `rng(seed | 1)` makes seeds 2k and 2k+1 the same history: use odd seeds via `step_by(2)`.
- A proptest failure reproduces across runs only under `PROPTEST_RNG_SEED=N`.

**Oracles and isolation**
- A test meant to isolate one mechanism checks that it fails with that mechanism alone disabled: a test passing by either of two mechanisms isolates neither, and a plant a later backstop hides needs a check between the two.
- An oracle choosing its subjects by an internal flag (`HeldKeyset::demotions`) breaks across a refactor of that index and cannot run on the code before a fix: choose by a stable fact.
- A differential's exclusion (a predicate excusing a disagreement) is counted over every world it covers, printed beside the failures: applied to failing worlds only, one excused 38% of the paths content worlds unseen.
- A differential mapping model flags to wire shapes never emits a shape its mapping lacks, so a mutant of that shape's rule survives every agreement test: a shape rule needs a test that builds the wire input directly (roles-model `paths/shapes.rs`, osis-perm's).
- A test whose comment claims a state asserts or tallies it: unasserted, a setup change silently makes it test something else (`pending()` names a wait). The forensic `recoverable` sees nothing of a pending copy outside the node closure: assert the value recoverable before the step that should remove it.
- A count read from a process-wide counter (`memo::writes`) moves with other tests' threads: count per thread.
- Each failure kind of a property panics with its own text: two kinds sharing one make a known_failures pattern for one hide the other.
- A shrunk script (`OSIS_SYNC_SHRINK=1`) of a debug-check failure may shrink to another panic: compare the panic before treating it as the reproducer.
- `git checkout <base> -- core/` also reverts a scratch test under core/: keep scratch tests outside the swapped paths.
- A `rejects` case asserting only the error class passes on any earlier rejection: print the error once (`--nocapture`) when writing one.

**Other**
- A redb store's clean close commits its allocator state, most of any `FileDevice` test that closes a written store; `std::mem::forget` of a store as a power cut fails the reopen (the file lock stays held).
- A module name may exist in several crates' `it` (`destruction::`): a brief or command names the crate with it.
- A probe printing from every engine of a world prefixes each line with the node's tid; several test threads writing one file write each line with one `write_all` (`writeln!` interleaves).
- osis-perm's `paths/hand*.rs` mirror roles-model's hand worlds by name (`paths::rows`): grep `core/` too before renaming or merging a model test. A helper swapped for a "superset" one can pass the default tests and fail a `_plain` property: run the crate's `_plain` properties after a helper change.
- Ephemeral bodies do not survive a restart: a restart case of an ephemeral rule needs a durable aspect. A scale test's small size must page as its large size does.
