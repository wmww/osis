# Test harnesses
> Summary: How to run and replay seeded tests (env vars through `osis_base::testenv`, seed runners, coverage floors), copied worlds, the debug rebuild, index and verdict checks every test runs, why-kept and row dumps, loop guards, `LocalPeer` delivery by sync ID and sealed delivery, the store-contents differential, measuring (icount, cpuprof, callgrind, pertest), the default-test cost, mutation probes, and harness footguns.

## Env vars and seeds
- Harness env vars (`OSIS_*_START`/`_SEEDS`, `OSIS_PERM_SEED`, ...) are read through `osis_base::testenv`, which panics on an unparsable value, zero seeds, or any set `OSIS_*` variable not in core/base/testenv-known.txt (policy.py keeps that list equal to what the sources name: add a new variable at its end; read at run time, so adding one rebuilds nothing). Probe variables: notes/build.md, Footguns.
- A set variable and an overridden range are echoed past libtest's capture, so they show on a passing run: check that line, not only `1 passed`. Per-seed output needs `-- --nocapture`.
- Sizes (`OSIS_FULL=1`, the gate's a tenth): notes/testing.md, Sizes.
- **Every property and its variable**: `python3 tools/test_select.py --all` lists every property test by crate and prints the command with every `OSIS_*` start variable the gate sets. Each harness prints its own replay line for a failing seed: use it as printed.
- **`_plain` and `_large`**: a seed runner is a property, never a default test (notes/testing.md, When tests run). Its `_plain` runs a fixed sample (a covering set where one was chosen by planted faults) and reads no environment; its `_large` reads the range (`--ignored --exact <name>_large`). The replay line names the `_large` where it checks a seed as the `_plain` does, else the `_plain`. `held_set_decides_plain` reads the range itself, beside `held_set_decides_exhaustive`.
- Engine lib harnesses: `cargo test -p osis-engine --lib <path> -- --ignored --exact`; a copied binary from `tools/bin-at REV OUT --lib osis-engine`, run from `core/engine`.

Crate-wide seeds:
- **osis-crdt**: every `testutil::rng(seed)` (fixed-seed loops and proptest cases alike) samples other runs with `OSIS_CRDT_SEED=<n>` (a splitmix hash of n xor'ed into each run's seed; unset, the committed seeds); a panicking test prints the effective seed. Its properties take `OSIS_CRDT_START`/`_SEEDS` (`testutil::crdt_seeds`) and draw from `testutil::fixed`, so the printed replay line is the whole replay. `OSIS_SHRINK=<seed> cargo test -p osis-crdt --lib -- --ignored shrink_script` shrinks a failing `fuzz_seq::tests::random_scripts_replay_plain_spec_5_7` script and prints it.
- **osis-perm**: `differential`, `queries`, `incremental` sample other histories with `OSIS_PERM_SEED=<n>`; each property run is 16 shards on scoped threads, shard i seeded `seed ^ i << 40` (a fixed count, so a failing seed reproduces anywhere; the panic names the shard's seed). Counterexamples print as made; `OSIS_PERM_SHRINK=1` shrinks them.
- **order harness** (`held_set_decides`): `OSIS_ORDER_START`, `_SEEDS`, `_SEED` (one seed), `_LEN`, `_CLOCK`.
  - `OSIS_ORDER_SHRINK=1` shrinks each failure (`order::shrink`: ddmin chunks, halves first, at most `SHRINK_CANDIDATES` candidates, each stopping at its first failing check) and prints the history as Rust a scripted test compiles (`rust_of`). A candidate counts only when it fails as the original did (`failure_class`: the check and what differed, orders and numbers aside), so it cannot drift to another bug, whose first line it prints once per kind; `OSIS_SHRINK_MATCH=<text>` keeps to failures containing the text instead, `OSIS_SHRINK_ANY=1` to any. A `settled` history's tail stays whole.
  - `OSIS_ORDER_STATS=1` prints each history and the tallies; `OSIS_ORDER_DUMP=1` explains a failing node: the packs with each header's purge list (a `Commit` item names the packs it matches), per ingest of the failing order each read that changed or went absent and each commit whose index entry changed (a part dropped while invalid shows its `Invalid` drop before it reads `missing`), and index differences against the keep-everything node.
  - For a node-holds-or-drops difference a dump of the shrunk history usually names the cause; probing the drop decision beats shrinking further.
- **sim**: notes/test-sim.md, Running and replaying.

## Seed runners (`osis_base::testenv`)
- `run_seeds(name, seeds, visible, replay, f)` (and `Seeds::run`, which announces an env range first) runs `f(seed)` for every seed on a thread per core (`OSIS_SEED_THREADS` overrides, for every harness), a panic counting as its seed's failure. Each failing seed prints with its replay command as it fails, a progress line every 60 s, a summary, then a panic listing every failure in seed order. A multi-seed run goes through it, not a serial loop.
- **Hung seeds**: a seed whose thread used `OSIS_SEED_TIMEOUT_SECS` (default 600) CPU-seconds, or no CPU for that long (blocked), is marked hung and a new thread takes its place. CPU time, not wall: under load a 5 CPU-s seed can take 700 s wall. A lower value (`OSIS_SEED_TIMEOUT_SECS=60`) names a hung seed early in quick runs. A hung thread prints its backtrace at its next `testenv::checkpoint()` (`LocalPeer::sync`, the sim's step loop). It cannot be stopped: when the rest is done with hung seeds still running, or as many hang as there are threads, the runner prints everything and exits the process (101).
- `run_jobs(name, jobs, threads, visible, label, f)` is the general runner (sim-sweep and `run_seeds` use it, so a livelocked sim seed is named); its summary line ends with its jobs' CPU-s, which the gate's summary lists per property (notes/gate.md, The summary). `par_map`/`caught`/`threads` are the building blocks. `Cpu::now()`/`secs_since` reads the CPU spent on a thread's work, the threads `par_map` and `run_jobs` ran for it included (a test's own cost beside others in one process). `Permit` is one of the process's permits (a thread per core); `pooled_map(items, threads, f)` is `par_map` with each call holding one, so concurrent tests and a run's seeds and their parts share the cores (osis-perm's shards, the order harness's seeds and orders).
- **Coverage floors**: a property over a seed range (the gate offsets every range; a replay runs one seed) checks what its seeds reached (pages, rejections, a branch taken) with `testenv::reach_floor(what, per_seed, per, over)`: the per-seed tallies sum to at least `per` per `over` seeds, rounded down, at every size and offset, never only at the default range nor above some seed count.
  - The rate is at most what any one seed reaches (under 1 where a seed may reach none: then one seed asks nothing) and, where seeds vary, about a quarter of the mean or less, so offset ranges meet it; set it from runs at offsets, never from the default seeds alone.
  - A case the seed draws on purpose (a seed class: `seed % 8 < 2` large values, an emphasis) is asserted per seed instead, and a ratio (followed of joins) per seed with the fewest seen in mind.
  - A `_plain` running a fixed covering set (no range) asserts its set reaches each case exactly; its `_large` twin carries the rates (rotation `tests_property::SHAPES`).
  - A case too rare for any rate to prove at the gate's size gets more default seeds (`purge_by_id_*_plain_*`: 8) or a draw on purpose, never a floor of 0 there. The order harness's floors are per emphasis present and per whole emphasis cycle (`Seen::floors`), its own form of the same rule.
- **Converting a fixed-seed loop to a range**: the seed may index nothing but an RNG or a modulus. A value sized by the raw seed (`honest_values_*_plain` asked for 44 TB at the gate's offset of about 4e11) aborts the whole property binary, and every property after it in that binary goes unrun; a loop index turned seed keeps everything it fed (crdt edit-window rounds stamped changes at `10 + round * 10`, above the local edit's stamp at an offset). A thread-local setting (`PageParams::set_test`) is set inside the per-seed closure, or `Seeds::run`'s threads run at defaults and pass for the wrong reason. Before committing, run the converted property once at a gate-sized offset (`OSIS_*_START=<random below 10^12>`): fixed seeds can miss a whole branch that fails at every offset reaching it.

## Copied worlds
A setup many tests share is built once per test process and each test gets an exact in-memory copy of the live world: it goes on as the original would (same next commit IDs, rng draws, connections, queues, memo hits), so a test cannot tell it from one it built. Reopening stores is not a copy (every node restarts, reconnects and syncs again).
- **Adding a cached setup**: wrap the builder in `LocalPeer::cached(key, || (peer, extra))` (or `osis_base::copying::cached` for another world type). Not cached: a setup that closes and reopens a node, real-runtime tests; no osis-level harness shares a setup, so there is no `osis` handle copy.
- **Mechanism**: `osis_base::copying::copying` scopes one world copy; inside it `remap` gives every shared `Arc` one new handle, so the copy's parts share what the original's did and nothing points back.
- **Hooks** (test-only, `#[doc(hidden)]`; policy.py keeps them out of product sources, because two live copies are one node twice and reuse nonces, counters and commit IDs): `Engine::test_copy(clock)`, osis-store's (`Store`, the cipher store, roots, pager), `Store::test_copy` over `Backend`/`RootStorage::test_copy_boxed` (memory ones only), `NodeRng::test_copy`. Plain `Clone` is derived on data; the types owning identity, rng or a live store copy only through these hooks. Harness copies: `Peer::copy`, `LocalPeer::copy`. Engine event receivers are subscribed again with the unread events (`Engine::test_subscribe_with`); commit listeners are not copied.
- Differentials: osis-engine it `copies`.

## Debug checks
These run inside every debug-build test, so every test is also an incremental-equals-from-scratch test (notes/test-design.md). None samples: each runs at every size, and every engine's history ends checked. A whole check (O(everything held)) runs once at the end of the history, never per transaction, where it would make a test's cost grow with n squared; per transaction runs only what costs about what the transaction did. All are invisible to scale counts (`costs::paused`, `osis_perm::uncounted`).
- **Rebuild check** (`apply::atomic::check_rebuilt`, run by `Engine::run` before the index persists; the comparison is `check_states`): a touched aspect's state must equal `rebuilt` (exactly the join of held bodies, invalid writes removed, spec/crdt.md §4.6), compared encoded, with the caches derived from it (value-less list, snapshot bounds, references). Checked in the transaction: an aspect where a held part's status changed, a part arrived not valid and whole, or the state was written with no new commit naming it (each such change is a rebuild, so the check costs what the change did). An aspect only valid whole joins or covered drops touched (`shred_covered`, the state left as it was) waits in `Core::unchecked_states` for the end of the engine's history (a check per join would cost O(the aspect) per commit); a later rebuild of the aspect rewrites a wrong state unseen. A test hook writing a state no body gives sets `Core::unchecked_tx` (nothing it touched is checked). A failure panics with the differing Debug lines.
- **Index check** (`Engine::check_index`): an open from the persisted index and a rebuild from the commit records, each into a fresh `Core` on a clock stopped at the last transaction (the index is as of then: a timer due since has not run), in a dropped store transaction, must equal the running node's index (`Core::same_index`, held set and role timelines included), after the node closure walked afresh (`check_closure`) and the states left unchecked; the open reads no blob and judges every part as held (`misjudged`). It also asserts that an open decodes no commit header: judging anything at load from headers (`LazyHeader::arc()` decodes at once; clone the `LazyHeader` and deref only where the record is held) fails it, often only in node properties or the sim. The fresh cores borrow the node's decoded records (`Core::decoded`: a decode is a function of the record's bytes, compared at every hit), so the rebuild judges everything again without decoding again.
- **Verdict checks** (`Engine::checked_verdicts`, at the end of history after any transaction, and inside the index check): every held commit's flags are what judging it now gives (`validity::misjudged`), then every re-grant bound a role timeline memoizes, carried over `extend` or asked by that judging, is what a search at every change finds (`Timeline::check_first_held`). Per re-judge only the touched part (`misjudged_on`): the commits on the things whose inputs that re-judge took (`stale_things`, `stale_under`), which catches a verdict wrong only for a while (later healed, so the end never sees it).
- **The end of history** is the engine's drop (`impl Drop for Engine`, debug builds): the verdict checks, then the index check if a durable transaction changed a state or a part since it last ran, else the states left unchecked. Skipped under `OSIS_NO_END_CHECKS=1` (Why kept and row dumps), while a panic unwinds, a load is half done (`Engine::loading`), a write's outcome is unknown, or the store fails (a crash test's: `Error::Store` ends it quietly). A copy (`Engine::test_copy`) starts checked: its original checks their shared past. An engine lib test editing an index in memory sets `Engine::index_poked`. `Engine::check_every_tx` (tests, by hand) runs the index check after every changing transaction, to find the one that diverged; a reproducer whose point is one moment calls `check_index` there.
- **Cost**: the rebuild from the commit records is about 15% of the engine lib default tests, the open about 5%; properties of many short multi-peer histories pay most (issues/index-check-rebuild-cost.md). Rejected: sampling by transaction counts (it checked most short histories and copies only at their first transaction, so no small test saw a fault that grows); checking an aspect's first deferred change at once as well (+4% on the properties, for faults a later rebuild hides); checking per transaction only the index rows it wrote (blind to a row it should have written and did not, the class the rebuild finds).
- **Planted faults** no default test catches (`tools/mutate.py` over the engine lib and `it`, perm `it`): a forgotten addendum's thing not judged again; a dropped part missing again not judged again. **Planted verdict faults**: a carried re-grant answer kept at or past the first change that differs (issues/first-held-carry-untested.md); a replay's raise ignoring the holder's own level.
- Not covered: a `node/perm` row left stale when a destruction rewrites a role commit's record (no reopen follows a destruction's rewrite).

## Why kept and row dumps
Debug builds only (`#[cfg(debug_assertions)]`), for a count, retention, role or read test that fails.
- `Engine::why_kept(t)` (osis-sync: `World::why_kept(i, t)`): why `t` is still held, read from the retention rule's own walk (`retention::needed::search` over `needs` and `rooted`, the functions `settle` uses, so it cannot drift from the rule): rooted (in the node closure, with its tree path of strongs from the node root and each step's context), or the chain of needs (a strong from where, a held or pending commit it signed, a missing part, a holder, a profile) to the first rooted thing, or that nothing rooted needs it and it goes at the next pass end.
- `Engine::rows(prefix, tid)` (osis-sync: `World::rows(i, prefix, tid)`, the engine's and the sync store's local rows): each row's family (as `local_census`), key decoded (known tids `t:`, held commit IDs `c:`, text, hex), the tids it names (directly or by a held commit's things) and bytes, filtered by family prefix and by tid. `Engine::describe_rows` describes another store's rows by the same engine.
- `Engine::why_role(t)` (osis-sync: `World::why_role(i, t)`): the node's role on `t` and its secrets, read from the rule's own code: the role `tickets::role_on` gives and the role commits' (`rotation::role_here`); per identity of the node (its account, itself, held key actors) its `role_now` and `keyed_role_now` and the widest current path to `t` (direct, chain, account), each edge by the role commit in force (`c:<hex>`) or the record edge; each held ticket's word, whether it counts and why (accepted, a sync word, or no held role commit reaching its holder: `Held::upstream`); with a dependent thing, the same for its independent; then `lost_due`'s clauses for that independent thing without side effects (`rotation::lost::explain_due`: held secrets per role and epoch, `?` reading-only; over-held, loss seen, judged lost, by an `until` alone, own self-removals waiting; DUE or the clause that holds it off).
- Printed on failure: S1 (`growth::releasing_own_things_*`, the grant arms) prints the rows of the differing families a fresh world's node lacks (same seed, so the same roots) and `why_kept` of each thing they name that the fresh node does not (`growth::leaked`). The sync differential's role and read clauses (`history::closure_clauses`) print `why_role` of the failing node and thing.
- **Replaying without the end checks**: `OSIS_NO_END_CHECKS=1` (`testenv::end_checks`; by hand only) skips the sync differential's checks at quiet (`history::check`, so `differential::holds` and every scenario calling `check` return their world, and `World::run`'s own, `sources_are_members` and `unlogged_must_holds`) and each engine's end-of-history check, so a scratch test replaying a failing seed can inspect the world (`why_role`, `why_kept`, `rows`) instead of panicking first. It prints `history::check skipped` past capture. Never set it while shrinking: a candidate whose failure is the check then passes.

## Loop guards
A fixpoint loop that a bug could keep going forever panics in a debug build instead of hanging (ostrich has no gdb): `osis_base::loop_guard::LoopGuard`, fed each round's progress, panics past a bound derived from the loop's size, naming the loop and its last 4 rounds. Guarded: node-sync's settle (`Node::settle`, the modules acting per round; 12 × (sync IDs + connections + 1)) and `LocalPeer::wake` (the commits each round ingested and whether the engine moved; (entries kept + 1)²). The sync `World`'s own loops (`run`, `advance`, `flush`, `step_or_wake`) each deliver per round, so its delivery cap (`World::cap`: `RULE_CAP`, `STORM_CAP`) bounds them, and it checks each step's settle rounds against `ROUND_CAP` after the step. `LocalPeer::sync_all` stops at n rounds; `deliver_sealed` ends when a round opens nothing.
- The bound is a closure so a release build, where the guard counts nothing, never computes it: compute the size inside the closure (a `things().count()` taken before the call cost every release round a walk of the node closure).
- A loop deciding "something entered" from a cloned `Feed` checks the key is still present: `Feed::added` keeps keys a failed step's rollback took out again, and such a loop spun to its guard.

## Delivery by sync ID over `LocalPeer`
A node takes content only of things in its node closure; content of another thing waits under Pending storage (spec/commits.md §4 Outside the node closure), and a `LocalPeer` carrier never goes. So `LocalPeer::sync`/`sync_all` send what the sync IDs the receiver syncs carry, decided at the sender by the product's own rule (`packages_for`/`packages_under` over `Engine::carried_under`, `sync_bodies`), again under the sync IDs it comes to sync in the pass (a grant or rotation moves them).
- A sender's packages are built once per state of its engine (`SyncMemo::whole`: each commit packaged and decoded once), and each set of sync IDs only trims those (`sent_parts`, a rewrite where parts go); built per receiver they cost 40-50% of the rotation properties.
- Certificate parts (`Engine::certificate_parts`) go to every node: they stand for the routes the harness does not play (contact cards, links, ticket fires, a grant under its holder's sync ID, pairing), and a node keeps only what it needs.
- No repeat work: `sync_all` stops after a round of duplicates; `sync` offers a package the receiver dropped at a pass end (things outside its node closure) again only once which of its things the receiver needs (`retention::needed::needs`) moved (else every pass delivers other accounts' roots again, to drop them at its end: most of `deep_departure_holds_large`'s applies); it repeats no delivery that came back a duplicate and moved nothing, nor one that came back a duplicate while the receiver holds every body of it (`Engine::holds_whole`).
- **Hand deliveries** pick the same:
  - `packages_for(from, to)`: the receiver's sync set as it stands (engine `it`: `common::packages_for`; `package_for` for one commit, panicking when nothing the receiver syncs carries it);
  - `LocalPeer::packages_to`: its sync set after a sync, on a copy of the world (a grant among the packages moves it; a fresh reader's sync set too, which its grant alone does not move); `packages_to_peer`: a node apart, on a copy;
  - `common::packages_for_peer`: a node apart, its sync set as it stands (an observer from `reader`);
  - `common::packages_reading`: a fresh reader given its grant alone (its sync set plus its thing's sync IDs, which it syncs once it holds the record; `packages_to` without the copy);
  - `packages_of(from, t)`, `trimmed`, `common::give_carried` (a net apart), `flows::send_carried`; `LocalPeer::commit_ids` where only IDs are read (and to pick, later, a fresh node's packages among what was held at a point).
  - A copy per call (`packages_to`, `packages_to_peer`) costs about what the test's own deliveries do: in a per-seed or per-order loop use the copy-free forms, and one reader's list for every fresh reader of an order loop (the sync IDs of one thing are alike for each).
- An observer is an account granted read and holding the thing (`common::reader`, `LocalPeer::fresh_reader`, `fresh_net`, `share`); a role-less node holding a thing by a node-root strong keeps none of its content, so a test comparing what such a node reads compares nothing. A fresh reader's seed must not be a net peer's (`net(n, s)` seeds `s*1000+i`): the same seed is the same account, and its grant re-grants that peer.
- A test's receive of forged or partial input for a node under test goes through `common::unless_refused` (a refusal is fine, a local error fails the test, as `Peer::receive` panics on `Corrupt`), never `let _ =`.
- `Engine::package` hand deliveries are still whole: what they bring outside the closure waits for good (issues/engine-harness-whole-packages.md, with the certificate broadcast and the sim's sender-defined quiescence).

## Confidentiality over `LocalPeer`
`Package`/`deliver`/`sync` hand over plaintext commits, so a peer that lost access still reads whatever it is sent: no "who can read" claim holds there. Such claims use the sealed mode: `LocalPeer::sealed` (makes the rotations due before encrypting, then `Engine::seal_package`) and `deliver_sealed` (`Engine::open_package`). flows.rs `sealed_write` asserts a peer that does not read the write opened none of its bodies; `spread_sealed` is `spread` sealed. Plaintext stays right for setup and for what an engine does with what arrives (order, validity).

## Store-contents differential
For a refactor that must not change stored bytes or write order. Seeded `LocalPeer`/`MemoryBackend` stores are byte-deterministic once the persisted index tag is pinned (`index.rs` `VERSION` folds in `OSIS_INDEX_RULES`, a hash of the sources). Throwaway patch, on main and the branch alike: in `MemoryBackend::commit` fold each batch's ops into a running hash, and in a `Drop for Data` append `thread-name trace-hash final-hash batches rows` to a file named by an `OSIS_PROBE_*` variable; set `VERSION` to a constant; run the default tests plus the order properties on each, sort, diff. Tests that differ run to run on one build (crash, store, runtime, driver, cli, some sync and encodings tests, `apply::tests_paged`'s paged-snapshot tests, osis `api::created_reads_through_run_time_key_*`: async, OS randomness) differ between builds too: rerun those on one build to rule them out. A store dropped on another thread moves its line to that thread's name: compare without names too.

## Measuring
Compare old and new code by instruction counts, never wall time on a loaded box; no timing runs inside a task (scaling: notes/test-scale.md).
- `tools/icount CMD...` prints `INSTR <n>` on stderr (user-space instructions via perf_event_open; needs `kernel.perf_event_paranoid` <= 2, which /etc/sysctl.d/60-perf.conf sets; builds icount.c into ~/.cache/osis on first use). Counts repeat to under 0.1%; CPU-s vary 20-40%. Old binary: `tools/bin-at <rev> <out> -p <crate>` (notes/build.md).
- A multi-threaded property's count moves with thread timing (which of two alike nodes is met first): compare at `OSIS_SEED_THREADS=1`.
- An `--exact` run of one test counts its fixture too (a 4-node world can be most of it): for a fixture-free delta compare in-process module counts (`tools/icount BIN -q <module>::`). A module's count still pays fixtures other modules share (`world(0, 4)`), which a gate's one process per binary pays once: judge a fixture change by the whole binary (`tools/icount BIN -q`).
- `tools/cpuprof OUT <test binary> --exact <name>`: an LD_PRELOAD SIGPROF sampler, inclusive and self shares per function; `tools/cpuprof --report OUT.<pid> [N] [FILTER]` reprints. CPU-time samples skew with the box's load: `CPUPROF_INSTR=N` samples every N user-space instructions of each thread instead (2000000 is about 2 ms), so shares compare across runs (per make: samples × N / makes). Stacks keep 160 frames, so FILTER can name an outer frame (a measured phase run on its own thread, as `making::probe` style tests do). Over a whole binary (`--test-threads=8`) it shows what all tests share, and may write a second `OUT.<pid>` (a child process's): the larger file is the test binary's. Its own work counts in icount (about 3.5%), so count without it; it kills the perm `it`, crypto lib and transport binaries ("Profiling timer expired"). Its stacks mislead for spawned threads and deep frames (unrelated callers shown): confirm a suspect with `tools/icount` on an env-gated variant before changing code.
- Exact call counts and split by caller (valgrind is on fastbox-0, not ostrich): `valgrind --tool=callgrind` on one test (`--test-threads=1`, about 50x slower), `callgrind_annotate --tree=caller`; a recursive function's inclusive cost (`name'2`) counts each level again. `perf record` is refused here.
- Which commit grew a test: a background script running `tools/bin-at` and `tools/icount` over a commit list, every 5th commit, then the window.
- Per-test wall times: run a test binary with `RUSTC_BOOTSTRAP=1 <binary> -Z unstable-options --report-time` from its package dir (the binary, not `cargo test`: `RUSTC_BOOTSTRAP` through cargo changes the fingerprint and builds a second artifact set); CPU per test with `/usr/bin/time <binary> --exact <name>`. Outside cargo set the proptest env (notes/build.md, Footguns).
- In code: `osis_base::costs` spans (`costs::span(name)` in the engine, `costs::take()` in a test).
- **Every default test, or every module, alone** (`tools/pertest.py`): `run OUT` builds the default tests, copies their binaries aside, then (under `tools/heavy`, taken after the build, so editing while it waits changes nothing measured) runs each default test as its own process `--exact <name> --test-threads=1` from its package dir under `tools/icount`, writing name, instructions, CPU-s and exit code per line. `--modules` runs each binary's top-level modules instead, one process each (`MODULE::*` rows), so a cached fixture is paid once per module as in a gate (per test, osis-sync's four `first::` tests read 17.8 G each where the module is 17.8 G). `top OUT` lists per-binary totals and the costliest tests or modules; `compare OLD NEW` the moves by test (crdt-model's and osis-keys' proptests draw fresh seeds per run and move 7-8% between identical runs: noise; a test failing only at pertest's load may be a KNOWN flake, tools/known_failures.txt). A compare against the last profile is also a cheap check for a storm that landed passing (a test 20x its old count). Against an older revision: `run` in a second worktree (`wt claim <name> <rev>`), `compare` here. The `test` limit alone (10 CPU-s or 15 s wall): `tools/limits.py tests`.

## Default-test cost
Measure by instruction counts (Measuring); totals from `tools/pertest.py top`. The gate's figures: notes/time-limits.md; where the time goes and the levers left: issues/test-time.md. Only less work shortens the default tests.
- Under `tools/pertest.py` each test is its own process, so it pays its process's cached fixtures (`world_of`, `LocalPeer::cached`): most of a median osis-sync or rotation test's count; a cached setup's saving shows only over a whole binary or module in one process.
- Figures (per test process, the last profile): 3,963 default tests, about 7,860 G, 2,200 CPU-s (osis-sync `it` 2,595 G, engine lib 2,058, engine `it` 2,034, osis `it` 346, osis-perm `it` 221, held-model `it` 222, osis-crdt lib 129, the rest 232). In the engine modules (one process, one thread, cpuprof): the drop's index check 18-23% (its rebuild about 10%: issues/index-check-rebuild-cost.md), `LocalPeer::packages_hashed` 4-9% (issues/test-time.md, Levers 0).
- Measured not to help: the order harness's oracle starting from a kept copy of the setup-given node (1.4% of `order::*`, not worth its cache), every binary at once, harness inner threads at 1, opt-level 2 for the workspace crates (one-line edit builds 15-20% slower), selecting default-test crates by the diff (engine takes most commits: 15% at best, opens a gap).
- Patterns that keep a test cheap (follow them in new tests):
  - Shared setups: one setup copied per order where a test plays many orders from one start (`local_peer::Peer::fork`); cases sharing a setup copy it (`LocalPeer::cached`, Copied worlds); every arrival order of a set walked as a tree of copies (osis-engine it `apply_order::each_order`: a prefix is received once); the judgment vectors' replays start from a copy of the node that received the file's setup (`judgment::replay`); a sweep whose every point starts from one store copies that store's closed files per point (osis-store `FileDevice::copy`).
  - A random generator looped over fixed seeds is a `_plain` property (Env vars and seeds; Seed runners).
  - A size bound checked at its real constant with a fixture the bound counts cheaply: a text string counts one item per byte (osis-crdt `page_items_cap_spec_8`, `MAX_PAGE_ITEMS`), a range record stands for many elements (`sweep_is_bounded_and_finishes_spec_sync_7`, `MAX_DELTA_BARE`): about 30 M instructions each instead of 10-12 G. A setup reaching a bound built as records instead of commits (osis-crdt `hostile_moves_join_bounded_spec_6`: its 250 HEAD siblings joined as one delta, not 250 commits each checked by a whole pass), and the bound checked at its count and one past it.
  - A random property's rare case drawn on purpose, then histories run until a coverage tally is met, never a fixed seed list (osis-crdt `snapshot_then_edit` anchors half its inserts at a range record's inside or an embedded char; `snapshot_edits_follow_cache_spec_6` stops once both were followed three times; `large_text_batch_is_net_effect_spec_4_5` draws ops until each kind was drawn four times). Tally the path a test's name claims: a builder test said its view was a layer while no op held one.
  - Debug checks that cost a compare, never a recompute: memo hits compared with a fresh run (`osis_base::memo` `Checks`); on a thread that turns them on (`memo::check_effects`: random-history worlds, `history::world_of`), `Effects` keys whose reads did not move settled again on the same power schedule and compared, which finds a read without its stamp (a module's plain field) in the big runs (off elsewhere: a comparison's settle warms caches and runs owners' functions, so counted tests would move); decoded commit records and parts (`engine/decoded.rs`) checked at every hit by comparing the bytes each was decoded from with those read now; engine reads (`Engine::read`: a store transaction dropped after, its in-memory changes undone) do none of a transaction's end work, and a debug build asserts each changed nothing.
  - Smaller data where the property is relative.
  - osis-crypto at `opt-level = 2` in dev.

## Mutation probes
`tools/mutate.py` (usage in its doc) plants a fault, builds once, runs the given tests and prints which failed; a plant no test fails is a test gap: add a focused test, or an issue. For many plants: `MUTATE_HEAVY=1 MUTATE_PER_HOLD=2 python3 tools/mutate.py ...` (one build, two plants per hold of the lock). Reference-graph rules, where caught at all, are caught by focused tests, never by a differential or sim alone. Open gaps: Debug checks (Planted faults); issues/strip-rule-gaps.md.

## Harness footguns
**Engine and `LocalPeer`**
- `Engine::local_census` keys keep the family's trailing `/` (`"pc/"`): a lookup by the bare prefix reads no rows, and an "is zero" assert passes vacuously. Probe every row-count assert with its mechanism off.
- `Engine::fires_owed` is in `FireId` order: `.last()` is the highest id, not the newest fire (a grant's sealed ticket is owed too); diff the owed set before and after.
- `Hlc::peek` jumps to every received `ts`: a wait "until R's `ts`" against it ends the moment R arrives. A rule "as of its wall clock" reads `Hlc::wall`, and a wait on wall time sets a wake.
- `LocalPeer::receive` wakes and re-examines after every ingest, so a wake a shortcut skips is invisible there: probe equivalence of an ingest path through `Engine::ingest`.
- `LocalPeer::pulled_anew` fills only at `receive`/`reexamine` (`LocalPeer::wake`): an engine commit's pull anew waits in the engine's wakes, so a test clearing `pulled_anew` after a copy sees the setup's pulls at the next receive: `reexamine` first. The order harness's `fetch_missing` never delivers what a node pulls anew: a node relying on one fails `held_set_decides` with no hint.
- `LocalPeer::sync` carries no ephemeral commit: an engine test hands one over with `memory_blob` and `ingest_memory`.
- A role commit past `grant`'s refusal needs `m.unchecked` plus `skip_writer_rules`.
- A mutation that changes nothing (a `set` of the current value, a set `Add` of a live value) writes no delta, and a commit with no delta is not made (`commit_tx` returns `None`): a re-put meant to carry something silently commits nothing.
- `Engine::run` rolled back restores the store, not every in-memory map of `Core` (`Core::accounts` keeps what the trial cached): derive secrets from the store record, never from a cache filled inside a trial.
- `Meta::missing_parts` counts parts whose body is absent, not parts the node cannot open: test readability by value (`engine.get`). `LocalPeer` hands parts over in the clear, so "can it open" is a check of held secrets, not of reads.
- `Engine::seal_package` writes a `dw/` row at the maker: seal after taking a census.
- A test on what a store holds keeps history on the aspects it probes: a store otherwise follows its own judgment (an automatic compaction), and a probe leaning on an entry kept for lack of a key fails for reasons unrelated to what it tests.
- A thing re-entering the node closure usually rejoins the sync set by its own sync ID, pulled from the start anyway, so a re-entry test passes with `refetch` broken: only a dependent thing in a unit whose sync ID never left exercises it.
- A drop path that marks commits stale needs a test where the drop happens in the end-of-transaction tail: only the end-of-transaction debug assert ("stale validity left unjudged") catches a re-judge marker set after the transaction's last re-judge.
- A late-order test says which copy it delivers: a node's copy of a commit it purged is header-only, so delivering it tests "never held the body", not "the body arrived late".
- A hand-again-until-quiet loop must not count every non-`Duplicate` result as progress: a commit kept pending, handed again, comes back `Pending` every round (at a lookup's cost, `apply::rearrival`), so the loop runs its full bound (osis-sync `history::reference`: 319 rounds instead of 2, 5x the sims' and differential's cost). Stop once a round applies nothing and leaves `Engine::pending` as it was.
- `order.rs`'s and `parts.rs`'s `FRESH` are one account (one seed), granted by the base; the judgment vectors' judge is that account too (`order::judge_at`).
- A world built under `PageParams::set_test` (thread-local small pages) must not go into `LocalPeer::cached`: other tests would read its small-page states.
- `Core::timer_floor = 0` does not wake a sync daemon: node-sync wakes at `next_timer` (`Node::next_wake`), and only the osis handle's `expire_due` reads `timers_due`; "make a tick due" means making `next_timer` say now.

**Sync `World`**
- `run` moves the world clock by its dial ticks (about an hour on `contacts`), so an `until` a minute ahead has passed before the grantee reads; an engine's `now()` lags the world clock until that node steps; `advance` over a long wait (`LOST_HEARD_WAIT_MS`) takes minutes of dial ticks: `skew` one node's clock instead. `RULE_CAP` is per world: `history::world` scales it by n, a hand-built world does not (`w.cap = n * RULE_CAP`).
- A world that waits out `PASS_WAIT_MS` with a node away costs 7-10 GB, mostly dial ticks toward the absent node.
- `step_or_wake` keeps returning true while any node dials a partitioned peer (its horizon moves with the clock): bound such a loop by world time. A test reading what a peer was served after `run()` misses entries the peer dropped on learning it no longer holds the thing: check after each delivery.
- The quiet checks (`unlogged_must_holds`, `unreached_must_holds`) run at the end of every `World::run`, a partitioned mid-script one cut at its horizon included: read which step's run panicked before reading the end state.
- A per-process `--exact` run of one sync test rebuilds its cached fixtures (2-4 s for a `contacts` test, a third of that in-process).
- Streams harness: a body opened as `Opening::Taken` (the `Table` default) leaves no store entry though the pull worked: check `knows`. A late message harms only a member already at the stream (one joining from the start is listed whatever the cursor says), so a late-reply probe on a first join passes with its rule disabled.
- A world test of a change made while a peer is away passes with the in-place judgement removed: the first reconnect after first contact judges every member. Mutation-check it with the peer away and back once first, and mutate to the old behaviour (unfollow), not to a bare return that leaves the memo key due.
- A count test built on `history::world` turns the memo debug comparisons off before counting (`idle::exact`): the history world turns them on for its thread, and their reads count.

**Counting**
- `costs::take` counts per thread: in a `LocalPeer` test it mixes every peer's work; scope the window to one peer's applies.
- A count taken inside a `measured` closure (`osis_base::costs::take`) zeroes what the closure is measured by: every n/10n check then passes at 0. Probe outside the measured region.
- A new `osis_base::costs` count shows in every test comparing all spans (osis `making::`, engine `closure::` assert exact equality): a counter one scale test reads goes outside the shared table (as `osis_store::bytes_handed`).
- `osis_perm::commits_walked` deltas around a step settle "who can force many walks" questions quickly (k against 10k).
- A memo kept by a key's stamp, read before that key is inserted, computes again at the next look: a cost test looks once before counting.
- An n/10n count through a real world needs an event that moves inputs alone: most events (a redeem, a register) also bring new keys.
- A cost test varying only what the node closure holds cannot see a pass judging every held thing when the filter to things outside it is uncounted: count what is due before filtering.
- A count test with a tolerance (charged within 1.25x of held) passes with a whole term dropped: mutate each term before trusting a tolerance, and make the check exact where every term can be written down.

**Models and generators**
- roles-model `family_run(stride)`: a stride sharing a factor with a dimension's size fixes that dimension (every 50th world: `h_t1` always false); strides of mixed-radix families are coprime with every radix.
- roles-model: probe a failing world by printing it and its reference, never by shrinking it first (one shrink ran past 10 minutes on one core). Two readings of one world (a mutant against the rule) go in one process with a thread-local switch: an env var read in the walk cannot switch per call across `on_every_core` threads.
- roles-model `paths::World::lowers` counts every edge write below admin, a fresh grant of write included: it is not "a removal" (the evidence model defines its own `removes`, below write).
- held-model `gen::shuffle` reorders commits, records and frontiers but not `Held::dots`, and `Dots::commit` takes the first range holding a dot: an order test over overlapping ranges shuffles `dots` itself (`props_overlap::reorder`).
- held-model `unit`: `Net::deliver` decides by the truth which units a writer syncs, so a writer that cannot know a sync ID (a forked promotion's greater one) still gets commits under it; a gap there needs delivery by hand.
- osis-perm tests: `World::nodes(n)` returns the same nodes on every call; fresh nodes per loop step come from one `nodes_salted` call, or the components silently merge.
- A generator may build in-memory states no encoder writes (a crdt position write stamped with its element's dot): before fixing a rule for one, check it decodes from bytes; a decoder test of such bytes hand-patches an encoding (decode to `Value`, change it, re-encode). `DeltaBuilder` `Add v` of a value already live writes nothing (`finish` is `None`): a forged copy adds a value the base lacks.
- `Debug` of a crdt `Seq` expands range records per element, so a printed state never shows whether a join split or kept a range: count `elems().len()` or spans. Text ranges exist only content-less (a delete-only delta, or deletes held without their creations).
- A loop over consecutive seeds with `rng(seed | 1)` makes seeds 2k and 2k+1 the same history: use odd seeds via `step_by(2)`.
- A proptest failure reproduces across runs only under `PROPTEST_RNG_SEED=N`; without it each run draws new cases.

**Oracles and isolation**
- A test meant to isolate one mechanism checks that it fails with that mechanism alone disabled: a test passing by either of two mechanisms isolates neither, and a plant a later backstop hides (the next transaction undoing what a dropped abort-undo left) needs a check between the two.
- An oracle choosing its subjects by an internal flag (`HeldKeyset::demotes`) breaks across a refactor of that index and cannot run on the code before a fix: choose by a stable fact (which commit wrote the keyset).
- A differential's exclusion (a predicate excusing a disagreement) is counted over every world it covers, printed beside the failures: applied to failing worlds only, one excused 38% of the paths content worlds unseen.
- A differential mapping model flags to wire shapes (`finalize` to a missing frontier) never emits a shape its mapping lacks, so a mutant of that shape's rule survives every agreement test: a shape rule needs a test that builds the wire input directly (roles-model `paths/shapes.rs`, osis-perm's).
- A `rejects` case asserting only the error class passes on any earlier rejection (a crdt overlap case was refused for its arity before any run decoded): print the error once (`--nocapture`) when writing one.

**Other**
- A redb store's clean close commits its allocator state, most of any `FileDevice` test that closes a written store; `std::mem::forget` of a store as a power cut fails the reopen (the file lock stays held).
- A module name may exist in several crates' `it` (`destruction::`: osis-engine's and osis-sync's): a brief or command names the crate with it.
