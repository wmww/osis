# Reference index
> Summary: The engine's local, rebuildable index of references in held readable data (`engine/refs.rs`): rows (target, source thing, AK, kind) with a count, what counts as a reference (strongs, weaks, tickets), how every state change keeps the rows in its own transaction, large values read once per link, the paged read and change event backlinks use, costs and checks; and its sibling for strongs in held history (`refs/kept.rs`, `history_holds_targets`). Serves backlinks (notes/api.md Backlinks), the closure walk and the ticket lookup (spec/data-model.md §8 Known references).

## Principle
A row says exactly what the source's held state on that aspect holds: it changes in the transaction that changes the state and never outlives the value it came from.

## Rows
- Store index tables (rebuildable, dropped and refilled from every state by `index::write_all`): `node/refs to` (target ‖ AK ‖ 0 ‖ source ‖ kind, empty: one aspect's rows naming a target are one range) and `node/refs from` (source ‖ AK length ‖ AK ‖ target ‖ kind, the count as u64). The kind is `RefKind` (0 strong, 1 weak, 2 ticket): one source and AK may hold a strong and a weak to one target, two rows. The 0 after the AK keeps `to` rows in (AK, source, kind) order (no AK holds a 0 byte), so a page resumes past a row by appending a 0 to its key. Whether a source holds a strong to a target (`refs::strong_from`, the closure's) is one seek and one probe per aspect referencing the target, never its other referrers (aspect names are static). A removed row is shredded. No in-memory copy: an open loads nothing; a read is a prefix scan (`Engine::references_to`, `references_from`, `refs::Reference`).
- Class by AK: an ephemeral (`+`) aspect's rows are memory rows, as its state is (live ephemeral), the rest durable.
- Indexed: every aspect with a state (`refs::indexed`), core aspects included: a creation record's `admin` and `link`, a roster's holders, box keys' holders are weaks (spec/data-model.md §9), so they are backlinks and hold nothing.
- Counted: every strong, weak and ticket (`refs::references`) at any depth of a value as the state reads it (`Fragment::each_read_value`: register and slot values, a set's distinct live values once (equal elements added concurrently are one value), visible list items, each map key whose live records' join reads with that join's values, an enum's live case's payload; at a position written in several encodings, the slot the read chooses alone, so a value of another shape replacing one leaves none of the old one's), map keys, enum payloads and unknown tags' content included; a write the read hides (inside a map entry removed or under a later shape at its key, an enum payload whose case a reset took, a list element deleted concurrently) holds none; a ticket counts once, as a ticket to its target (the tids inside it are no references). A large value (a link, spec/data-model.md §6) counts as its content's references, read from its row (Large values below). Not counted: a value-less write (the state holds none), an invalid write (un-merged), a tid spelled in a string, text chars.
- Fires: a durable signal has no state; its rows are what its held valid fires hold (spec/data-model.md §8 Known references), so a ticket in a `ticket@~0` fire is found by its target as any. An ephemeral signal's fires are held by none: not indexed.
- Ticket rows (`node/refs tickets`: target ‖ source ‖ AK ‖ 0 ‖ fire commit ID, none for a state, the tickets there with their counts, `TicketCounts`): finding a target's tickets (`refs::tickets_to`, what `held_in` and the account's tickets read) reads its ticket rows alone, never the source's state, its other references or a signal's other fires; kept by `note` beside the rows above, a signal's per fire (`fire` given by the join and the drop of a fire, `resync_fires` rewriting them per fire). Work counted as `tickets: rows read` (engine `tickets::a_ticket_lookup_reads_the_targets_tickets_alone_at_n_and_10n`: the last of n tickets arriving for an accepted target reads the same at n and 10n).

## Large values
Rule: a link counts as the references of the value it reads as, once the node holds its chunks (spec/data-model.md §6); they are read when the link is first read by `(source, AK)` and kept in its row, never read again.
- Rows (store index tables, rebuilt with the rest): `node/refs links` (source ‖ AK length ‖ AK ‖ content hash: a link to it, how many times the state or held fires read it, and its references or the blob they wait for, `LinkRow`); `node/refs waits` (blob ‖ the links key, empty).
- `Delta` counts each link read (`Value::each_reference_or_link`, by content hash: equal large values are one value) beside the references; `note` moves its row (`move_link`): made on its first read with `large::link_references` (the content at any depth, links inside read likewise, each distinct one once; a byte or text string told by its first chunk, the rest unread; unreadable otherwise: none, as it reads absent), its references added once per read, taken off from the row as reads go, the row gone with the last. A whole write (`resync`, `resync_fires`) sets the rows to the reads it counts (`set_links`): only a link new to the aspect is read.
- A blob missing: the row holds no references and a wait on that blob. `Tx::store_blobs` looks each stored blob up in the waits (one seek, `refs::fetched`): the link is read again, and once whole its references count for every read (a signal's ticket rows per fire afresh, `resync_fires`); else it waits on the next missing blob. A row still waiting tries each new link of its content a delta brings (one re-encrypted by `relink` reads where the old never will).
- The reach must hold equal elements of a set whose value holds a link as it does for references (`Elem::references`, `holds_reference_or_link`), since equal values read once.
- Cost: a large value's content is read once per aspect reading it (and at an index rebuild), O(its size); its removal and every rebuild read its row alone (`refs: large value read`, `refs::a_chunked_elements_references_are_read_once_spec_data_model_6`: adding one to a set of n reads one, removing reads none, at n and 10n). A row per large value per aspect, blobs and strings included.
- Checked: `check_links` in `refs::check` (debug): the rows' counts are the reads, each row's references a fresh read's, a waiting row's link still not whole and its wait there.
- Held history (`kept`, below) does not read large values: issues/history-holds-in-large-values.md.

## Reading it
- `Engine::references_page(target, aspect, after, n)`: up to n `(source, AK, kind)` after a cursor, on one aspect where given, by a range read of `node/refs to`, O(n) rows (cost span `refs: row read`); backlinks pages over it.
- `Event::References((target, AK) pairs)`: queued by `refs::note` when a row appears or goes (a count staying above zero is no change), in the transaction, so a rollback drops it; only once `Engine::watch_references` turned it on for the open (sticky, as `watch_commits`): a resync of a fall of an aspect would otherwise list every target with no one to tell.

## Keeping it
- A join (`atomic::join_into_state`, the oracle's): the tids at the delta's reach (`Fragment::reach`, all a join can change) before and after (`reach_after`, given the reach before), the difference noted (`refs::note`). In a map the reach takes every record sharing a key with those the delta reaches, to a fixpoint over the records of their dots (a key reads as its records' join), the same keys before and after. In a set it takes every element whose value holding a reference (or a value removal's reference) equals one the delta's records, or the state's records at their dots, name: equal values read once (values without references need no such records: the reach serves the references). O(the reach): a path write reads the entries it writes and replaces and the records of their keys, no other.
- A paged reset joined page by page (`pages::join_reset`): the skeleton and each page it rewrites, before (as a load reads it) and after; laid out whole instead, as a whole write.
- A whole write (`Tx::set_state`: every rebuild, so validity flips, un-merges, purge, a part dropped, destruction): the whole state against the stored rows (`refs::resync`). `Tx::write_state` is the same write without it, for a join's caller that noted its difference; an expiry in place (`apply::strip_state`) notes the difference at its delta's reach as a join does.
- A dropped aspect (destruction, forgetting): its rows cleared before `drop_aspect`.
- A fire: joined valid (`atomic::join_part`), its references noted, O(the fire); dropped (`retention::drop_part_for`: its keep bound, purge, cover, invalid), its references read from the held body before it goes and taken off, O(the fire), no rebuild; expired, held as its value-less leftover with no state to strip (`retention::make_leftover`), its references off likewise; any other change of which fires count (a validity flip, a forget) reaches the signal's `rebuild`, which resyncs its rows from every held valid fire (`refs::resync_fires`), the cost a state aspect's rebuild pays (batched as those are).
- Rollback: the store's savepoint, like any row.
- Check: `apply::check_rebuilt` (debug, end of transaction, sampled like the state check) asserts each checked aspect's rows equal its whole state's count (`refs::check`), a signal's its held valid fires' (`refs::check_fires`).

## History holds (`refs/kept.rs`; spec/data-model.md §8 Held history)
Rule: on a thing whose newest held valid setting has `history_holds_targets`, every strong in a held valid body (as written, `Fragment::each_value`: its writes inside another's elements included) of a counted aspect (durable, not a signal, no fixed retention: `kept::counted`) is an edge and a need while the body is held. Live bodies count too (their strongs are also the state's): one rule, no replaced-at judgement, so the hold is a function of the held set, never of the leaving schedule.
- Why held bodies, not exactly the promised history: a body in history is never dropped by a cover (Keep bounds), so the promise is the lower bound; ending the hold exactly at the history bound would hang it on `leaving` rows, which are a schedule that may fire late by arrival order (notes/engine-retention-history.md Leaving history), making the closure differ by arrival order. Past the bound the hold lasts until a cover drops the body (a writer's compaction, or its snapshot reaching a reader), so the setting bounds a hostile writer's pin from below and an admin's purge, or the flag off, ends it at once.
- Rows (store index tables, rebuilt by `kept::write_all`): `node/refs kept parts` per held part (source ‖ AK ‖ 0 ‖ commit ‖ part: its strongs by target with counts), the bare source tid as the marker (rows kept for it); `node/refs kept from` (source ‖ target ‖ AK, the count) and `node/refs kept to` (target ‖ source ‖ AK). Not backlinks: they feed the closure (`units::strongs_from`, `strong_to`, the ticket rejudge) and `needed` (`Need::Strong`).
- Kept by `kept::settle`, first thing in every `units::settle`: the parts in `Core::kept_due` (noted by `put_meta`, `take_meta`, `index_validity`, `put_commit` and leftover writes, only on things the setting marks) each read once and diffed with their row: O(the bodies that moved). `Core::kept_things_due` (every thing `settings_changed` pops) compares the setting with the marker: on, every held part of it marked due (O(its history), once); off, its rows scanned and dropped.
- Interactions, all by the one rule (a body's strongs hold while it is held): a purge holds the body as its value-less leftover, an expiry likewise, so its strongs go then; a cover drops a body only past its keep bounds, so the hold ends at the drop, never before the history bound; a release forgets the thing's bodies, so its rows go in that transaction and what only they held is judged lost; `needed` takes each row as a strong. Name: the setting says what it does to the closure (`history_holds_targets`), not to history.
- Cost per kept version: one parts row per held body holding a strong (about 24 B a target) plus a count row per distinct target; a body read when it arrives and when it changes or drops.
- Ephemeral aspects are not counted: their bodies are memory, as their rows would have to be, and their settle runs in memory transactions that skip `units::settle`.
- Checked: `kept::check` in `apply::check_rebuilt` (each checked aspect's parts rows equal its held valid bodies' strongs, the counts their sum, the marker the setting). Tests: engine `closure::a_strong_in_held_history_holds_its_target_until_the_body_goes_spec_data_model_8` (held past the removal, gone with the covered body or the flag off; fails with `counted` false), sync S1 `growth::releasing_held_history_returns_storage_to_a_fresh_nodes_spec_data_model_8`. Not modelled in held-model: its generator never sets the flag.
