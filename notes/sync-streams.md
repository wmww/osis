# Sync: streams
> Summary: osis-sync's `streams` module (core/sync/src/streams/): serving and pulling each shared sync ID over the peer's node log, joins, bodies, `known` (what each source holds); its state and where each part lives, the messages it takes, reports and caught up, durability (places, refusals, full and room marks, fetching anew, head moves), presence and listings, closed members, failures, the shred rule, remaining O(members) costs and what is not built.

Spec: spec/sync-streams.md §3-§5, spec/wire.md §11.2 (Pull, PullReply, Stream, Applied, Fetch), spec/sync-judgement.md §3 `known`. Model: core/test/tla/net/NetStream.tla (each `SN_*` rule names its function). Overview: notes/sync.md.

**Principle** (the module doc of core/sync/src/streams/mod.rs): every node pulls each member of a connection's shared set from its peer by one stream over that peer's node log; a push only continues a pull, and a gap is repaired by reading again, never by trusting order. A position is stored only once what it covers is applied, so a lost or replayed message costs a re-read, never a wrong view.

## Shape
- **Serve** (`serve.rs`): Pulls from the node log filtered by the shared set now, pages by `max_reply`, joins in pages, ephemeral listings, pushes under `follow` with `seq`, Fetches, reported positions.
- **Pull** (`pull.rs`): one Pull out, received vs stored cursors, joins by generation, messages in hand applied in order once their bodies settle, gaps read again; Full and Refused at a node keeping S unread; relay-only entries in Streams with no cursor (`relay.rs`, notes/ephemeral.md In osis-sync); `refetch`: a body read finds missing, queued outside any message from a source that showed it (`Streams::ask`, `Ask::Entry`).
- **Bodies** are fetched one source at a time in fill order, only what the store lacks:
  - A Fetch carries one fill class's bodies whatever sync IDs they are under, a blob once per Fetch (a reply item names its blob alone), so a first sync of n sync IDs fetches in O(bodies / `MAX_FETCH_IDS`) round trips (`first::a_first_sync_of_n_sync_ids_takes_the_same_round_trips_spec_sync_streams_4`).
  - A body opening to a held commit is kept as it came (`Opening::Held`), so it is never fetched again while held or tombstoned. An announced entry whose bytes the store holds under another sync ID (a certificate copy wrapped under each sync ID needing it) is taken with them at once, and so is one whose bytes arrive while it waits in the queue, keeping the announcement's wrap and stamp (`first::a_blob_is_fetched_once_per_holding_whatever_sync_ids_carry_it_spec_sync_streams_4`). Once per holding: a raise pulls S anew and what the old member's sources showed goes with it, so a record blob a stub opened and dropped (it lost) is not counted and is fetched again by the reader; a rare path, and keeping it across the raise would be a carve-out to the member-lifetime rule.
  - A blob asked anywhere, under another sync ID on the same connection included, waits for that answer: else a reader that cannot wrap under S, which never logs it itself, holds it must-hold with no entry forever.
  - What a source failed to give (a Fetch answered without it, wrong bytes) is failed per (S, blob), as owed, until that entry is announced again. Keyed by blob alone, an announcement under another sync ID would clear it, and a message in hand owing it under S would wait forever, holding the stream at `REPORT_WINDOW` (`streams::a_failed_body_stays_failed_when_announced_under_another_sync_id_spec_sync_streams_4`).
- **A keys source** (class 2: a peer holding S's thing for keys, spec/sync-streams.md §4): served S's role entries alone, in replies, pushes and Fetch answers, and no ephemeral or relay-only entry; Deleted and head events as to any member (`serve::for_keys`, `role_entry`).
- **A source** is a peer's record, else the connection (`store::Source`). Per source a `Place` (stored cursor, members at the stream, joins with their cursors, where members stopped), held in memory as long as opens holds the record (`Streams::record_left` as it leaves opens' memory; a record-less peer's with its connection), so a take (`Moved::Taken`) reads no row of it: a member at the stream stays there across a release and a take, and a released connection's pull goes at once (a late reply on it must not move the record's cursor).
- **`Known`** (`known.rs`): heads, full, refusals and presence per source, all of it the source's rows (`store::source`): one mechanism whatever the source, a record's durable in its record, a connection's (and what holds only while an ephemeral entry does) in the store's memory part. No copy of them lives in streams. Presence (and a deletion seen, `Store::saw_deleted`) is kept only for entries held or tombstoned here, or whose body was taken (`Opening::Taken`: pieces, records, lists) while the message was in hand, or a record or list blob the engine counts (`Ground::counted`: opened before, never fetched again), when the message applies (`pull::concerns`): a hostile source listing made-up IDs grows nothing, and a body whose fetch failed at a source counts as not held there (spec/sync-streams.md §4 Reading).
  - The store stamps each row (a point read per row, `present`/`shown_at` by the row index per (S, tag, blob), a listing per (source, S) prefix), so read, unread, status and inbox follow it by key. `Streams::new(store)`: `Known` keeps the store handle so its `&self` reads need no store argument (a world copy resets it, `set_store`).
  - A server inlines no blob the requester is known to hold under any sync ID naming it here, nor one it inlined on the connection in a message not reported applied yet (`peer_holds_blob`, `Serve::inlined`): a blob several sync IDs carry (a key record, a commit under its thing's unit and its admin's) crosses a connection once, the requester taking the other entries with the bytes it holds. A push racing the apply of a body the peer just gave may carry it back once (bytes only).
  - `Known::shown` adds every entry a message in hand shows present, owed or not (`in_hand`, stamped per (S, blob); spec/permissions.md §4: a record blob counts while a message showing it is in hand): the certificate judgement keeps a record blob counted while the message showing it waits to apply behind an owed body, whether it just opened it or counted it before and skipped the fetch. Else it forgets the blob's row, the message then records no presence (`concerns`), and a writer that dropped its own losing blob never deletes it at the store that showed it (`streams::a_message_in_hand_shows_each_entry_it_lists_spec_permissions_4`). A row forgotten anyway (the store's showing came later) costs a fetch: a record blob not counted is fetched where shown, judged and deleted there as any.
- **Members** come by `Moved` from opens (a kept record's all at once: `Taken`, `Released`); ended members are known by `Moved::Until`, so serving reads the shared set per event and checks `until` only for ended members: a push costs its events, not the members. Reported positions go back to opens as `Reported` after each message, move and settle; streams reads them through `Shared::reported`.
- **Seams**: the core runs over `streams::Ctx { store, ground: &mut dyn Ground, wire: &mut dyn Wire, shared: &dyn Shared, now, reported }` (`Ground`: `open`, `rank` from the engine; `Wire`: sessions; `Shared`: opens' `members`, `agreed`, `record`, `reported`), so core/sync/tests/it/streams.rs runs two sides over real stores with scripted opens and engine.

## State
One rule: what the connection is doing (a Pull out, a reply in hand, the follow, what it owes or was owed) is the connection's and goes with it; what the peer HAS and where this node STANDS in its log (its place, what it showed of S, the class it keeps S as) is the record's, kept across its connections and in its rows, so a reconnect touches nothing per member (spec/sync-streams.md §4 Joining). A restart changes nothing a user sees: connection state is rebuilt by the next Pull (the stored cursor covers only what was applied), the record's is its rows. Keys: P a peer (only what the shared set or this node's own log admits), E the engine or opens, N this node.

## Messages received
spec/wire.md §11.2. Nothing of S is served to or taken from a peer before the digests agree (`Shared::agreed`: a Pull is answered DECLINED, none is sent) nor for an S not in the shared set now, which opens closes in the step a right ends, connected or not (spec/sync-opens.md §6), so a removed peer back after a change is served nothing of S.
- **Pull**: P chooses the cursor (another history or below the horizon: a whole listing), joins (a non-member's answered "not shared", telling only that), `inline_limit`, `max_reply` (pages ≤ `REPLY_BUDGET`), `follow`, `ephemeral`. The reply tells the peer the shared members' events after its position, and its cursor (a fresh nonce each time: equal positions tell nothing of other sync IDs). A Pull's cursor reports nothing.
- **Stream** (push): applied only in `seq` order, else a gap read again; with no cursor only Full, Refused and relay-only events of members are kept.
- **PullReply**: as a Stream, plus the joins' cursors.
- **Applied**: a position of this node's log only, reported to opens per connection (an unproven peer's makes one `Serve`, bounded by the connection); for caught up it counts only by the exact cursor of a message this node sent asking a report, covering that message and those before it. A peer naming a later cursor than it applied (or a Pull cursor past what it holds) only makes this node count it caught up on what it lacks, which a peer can always do by holding less; an Applied also counts held at the peer what the messages it covers carried (Sends counted, below), which a peer can claim only of what this node sent it, as it could by its stream; a too-high Pull cursor costs the peer the events it skips.
- **Fetch**: judged per (sync ID, blob): answered only for a member's entries held here, up to an ended member's `until`; anything else, a blob held under a sync ID not shared or another than the one asked included, answers "none" and tells nothing (`one_fetch_asks_the_bodies_of_several_sync_ids_spec_wire_11_2`); at most `MAX_FETCH_IDS` blob IDs in all its groups, each once.
- **FetchReply**: only IDs asked are taken; wrong bytes or a reply with none fail that (S, blob) at that source until announced again.

Clocks: monotonic (`Ctx::mono`, each wake in `next_wake`) for `asked` (`ASKED_MS`, a stalled source's blob asked elsewhere), `retry_at` (`RESYNC_MS` after a refused Pull), `rejoin_at` (`RESYNC_MS` after a refused join). Wall (`Ctx::now`): a relay-only entry's expiry and `ts` (`RelayGate::admit`), judged as it arrives (no wake). The store's room clock (refused expiries) wakes through `Store::next_wake`.

## Reports and caught up
- **A Pull's cursor** is the last one received and kept (`Pulling::recv`, messages in hand included), so pages and joins go on while bodies are fetched (fill order spans a whole listing, spec/sync-streams.md §5); it reports nothing applied. Only an Applied does: sent once the message's owed entries are taken under their own sync IDs (`drain`; bytes held under another sync ID are taken with them by `fetch` first, so a failed take leaves the message in hand and its cursor unstored: `streams::an_owed_body_settles_only_once_taken_under_its_sync_id_spec_sync_streams_4`). An Applied goes after each step of applying that applied a message asking one, a listing's pages included (`stored` false: no cursor stored, so no position reported, spec/sync-opens.md §6), and nothing applies while it is owed and not sent: what one Applied reports is what one step applied (`nothing_applies_while_an_applied_waits_spec_sync_streams_4`). Cost: one Applied per step, not per member (`first::probe_first` counts deliveries).
- Rejected: a Pull naming the stored cursor (one cursor for both reading and acknowledgement): a listing from the start stores none until its end, so each page would be read again, and waiting for a page's bodies before the next breaks order 0 first across the listing.
- **Report cursors**: the server numbers each message asking a report (`Serve::sent`) and seals its cursor afresh (`serve::fresh`), so an Applied names one message by its bytes (`reported_by`), covering it and every earlier one. Sealing afresh costs two store rows per message (the log's meta, read to open and to seal), flat in messages served (`a_fresh_cursor_per_message_costs_the_same_at_n_and_10n_spec_sync_streams_4`). `asked` keeps every cursor an Applied may name: no message asking a report goes while `REPORT_WINDOW` are not reported applied (a push waits, a Pull is refused), and a requester holds no more in hand, so both sides count the same window by construction (`pushes_wait_while_the_report_window_is_full_spec_sync_streams_4`; NetStream `SN_reportwin`). Rejected: keeping only the newest N at the server alone (a long listing, or pushes past what the requester holds, left the server counting fewer sends than the requester). Positions cannot serve: an ephemeral-only push stands at the position the log already stood at, and a listing from the start goes back to lower positions. A message with a cursor asks a report while one served is not reported with `stored` (`Serve::owed`, `Serve::stored`), so the last is answered whatever it carries and the position the requester stored is reported (`a_later_report_covers_what_was_served_spec_sync_status_1`). Cursors are sealed afresh for this, and so equal bytes never show the peer the log did not move.
- **Late members**: a member that joined after the peer's first Pull is busy (`unjoined`) until a reply merges the peer's join of it or reads from the start. The requester joins every member that opens on the connection, one at the stream's cursor from that cursor (the server takes no position for it until a join names it, spec/sync-opens.md §6 Lost); only a taken record's members at the stream go without a join. One its place holds at the stream that is no member when the first Pull goes stops at that Pull's cursor (`send_pull`) and joins from there once it opens (`a_member_at_the_stream_opened_after_the_first_pull_joins_spec_sync_streams_4`).
- **Ephemeral entries** go only in a message with a cursor; a log naming no position holds them back (busy) and reads them again only once the log moves (`ephemeral_entries_held_back_are_not_read_at_every_tick_spec_sync_streams_4`). A product node never meets it: a node holding an entry of S has S's head logged (`first::a_node_holding_an_entry_of_s_has_its_head_logged_spec_sync_streams_4`).
- Tests (streams.rs, status rules): the five busy causes (`another_sync_ids_traffic_leaves_s_caught_up_*`, `caught_up_needs_the_peers_applied_*`, `an_until_cleared_makes_s_busy_*`, `an_ephemeral_write_not_listed_keeps_s_busy_*`, `a_join_left_in_pages_keeps_s_busy_*`), `a_pull_while_a_body_is_owed_reports_nothing_applied_*`, `a_later_report_covers_what_was_served_*`, `a_member_joined_after_the_pull_waits_for_its_join_*`, `an_ephemeral_push_waits_for_its_applied_*`, `ephemeral_entries_wait_for_a_log_position_*`; the random histories of the property `caught_up_matches_what_each_side_holds_plain_spec_sync_status_1` (`OSIS_CAUGHT_START`/`_SEEDS`).

## Durability
- **Rows**: a record source's rows (tags `c` cursor, `a` at the stream, `j` where a member not at it joins from: joining from it or stopped there, one row; `k` present per blob, `h` head, `r` a refusal it sent that stands; `t` the head of S this node last told it a refusal under, `Place::told`) are written by `save`: one transaction per applied message that moved something (what it showed, the cursor it stores, the members whose position moved; after its bodies were taken in their own transactions), per join or leave that moves a member's position, per Refused, per lift (`serve::offered`). A join started writes its cursor, so a restart joins from it whatever opens wrote (a load reads the row as stopped there).
- **A member's position is what is written, not its form** (`Place::effective`): at the stream means the stream's cursor. A leave or join that keeps it (at the stream, then stopped at the cursor; stopped, then joining from there) writes nothing, so a reconnect moves no member. The member is kept in `Place::stale` and written with the next cursor that moves, before the stored "at the stream" could mean another position. An Applied goes only once that transaction committed.
- **Cursors** are sealed with a fresh nonce each time (osis-store `nodelog`), so equal positions have unequal bytes and a requester stores each reply's cursor: a reconnect with nothing new writes one cursor row per side, no member row (`streams::a_reconnect_after_a_restart_costs_the_same_at_10n_spec_sync_streams_4`). Opens writes its record per connection (taken: `used`; the reconnect's filter generation and its acknowledgement), a constant per connection. Rejected: answering a read that moved no position with the cursor given (saves that row): equal bytes tell a peer polling Pulls when the server takes or writes anything, for things it does not share (spec/requirements.md, Confidentiality between readers).
- A connection's `Known` (ephemeral entries, record-less peers) is memory rows. An evicted record's place goes from memory as opens lets it go (`record_left`), and its rows go with it.

### Refusals received
spec/sync-streams.md §4 Refused. A refusal stands only on its ground, and every end is an event this node sees:
- the entry served again to that source (`Streams::offered` after each reply and push: one `r` row read per sync ID carried, a write only where one stood; a listing from the start lifts all of S there, which also covers an entry that left while the source was away past the deletion horizon);
- the source's stream showing it present (`Op::Add`: a refusal racing a new stamp that the source then took);
- the head its stream names moving (`Op::Head`: all of (source, S));
- the entry leaving this node, however it left (an expiry, a give-way or a dropped copy serves no event): `store::entries::remove` drops the record rows in the entry's own transaction (the row index by (S, tag, blob)).

An ephemeral entry's refusal is a memory row under its source whatever the source (a durable row would outlive the entry at a restart), and a connection's refusals are memory rows; a memory refusal goes when the store's entry feed shows the entry gone (`Known::settle`, each tick, O(entries changed): a durable entry's removal is a durable transaction, which cannot reach the memory part). A record's durable ops reach its memory refusals after their transaction (`known::memory_lift`). So `refusing` reads both parts for a record; rows are at most one per entry held here and source. The refusal's stamp and head are not kept: no read compares them.

### Full and room marks
spec/sync-streams.md §4 Full. The node keeps no memory per refused entry: a mark says "this place passed something refused", and every rule below follows from keeping that true.
- **Received**, Full is a fact of the connection (a memory row under `Source::Conn`, whatever the source), ended by `full` false, S leaving the connection (`left`) or the connection.
- **Sent**: the store keeps S full durably per cap that refused (`store::Cap`: S's own, the durable total, S's memory part, the memory total; row `R/`, the bytes the least entry it refused needs under it and the latest expiry of one), `Store::waits_room`, and a **room mark** per source whose place passes the refused entry (`take_stamped`'s `from`: every connection holding S, which `take_body` settles it at): a source row under tag `f` owned by the store (`store::source`: a record's durably, a connection's in the memory part), written with the take, before any place can pass the entry. Each owner forgets its own tags as a connection goes (`Known::forget_source` its own), so the mark lasts until `Store::gone` judges it.
- **`R/` stands only while some mark does**: each mark that goes (`Inner::unmark`) ends full in its own transaction when it was the last, reported at the next `room_grew` (filtered by "not full again since").
- **A mark goes** when its source lists S from the start (`Store::listed_from_start`, judged as the reply arrives, before its bodies: the listing re-shows the source's set and what it refuses re-marks it; what a message still in hand on that connection settled of S without taking it is asked again then, `on_pull_reply`, else its place passes the refused entry with no mark and after a growth never fetches it); when streams moves its place to the start (`Store::reset_anew`, the place rows in the same transaction); with its connection (`Store::gone`); with its record (eviction: every full S judged again, a rare path); and a connection's at a restart (`Store::open` drops `R/` of an S no record marks).
- **A mark becomes owed** (value `ROOM_OWED`) when its source's stream shows the deletion of an entry neither held, tombstoned nor taken here outside a listing from the start (`Streams::apply` -> `Store::refused_may_be_gone`, before the message's cursor is stored), and every mark of S does when room grows or the latest refused expiry passes (`room_grew` -> `end_full`, with the `R/` rows going). Either writes the `N/` mark `ANEW_SOME` (over none) in the same transaction, and `pull_anew` resets exactly the owed sources (and those told a refusal under another head). An owed mark still counts for full: it goes with the reset. A refusal at a source already owed leaves it owed (its listing re-shows the entry anyway; marking it standing would skip the reset and leave older refused entries it passed unfetched after a growth).
- So a sign from one source costs that source's stream alone (`streams::a_sign_at_one_source_pulls_anew_there_alone_spec_sync_streams_4`): a hostile peer's made-up deletions relist S at that peer only, and a record-less peer's listing at each connection costs nothing more (its new connection holds no mark). What stays: each deletion of a refused entry relists S at the source that showed it (removing that needs per-entry refusal memory). An entry refused for room is fetched again if another source shows it before room grew (refused again).
- **Telling**: streams tells `full` true where it refused and on each connection S joins while full (`Pulling::told_full`), and `full` false on each connection for each S `room_grew` reports (`untell_full`). A shred ends S's wait with its rows and marks; streams tells `full` false for each shredded S (`forget_shredded`), in case S stays shared.
- **Room**: a total cap refuses only what give-way cannot make room for (path bytes, tombstones; role entries count toward no cap). `Store::room_grew` (each tick) judges once a refusing cap has room for one more entry of that least need (`room_fits`; an entry left anywhere it counts, the cap rose; the memory part is empty after a restart), every refused entry expired (a memo `Clock` in the store; its `next` is a wake in `next_wake`) or S is no longer kept unread. A growth too small for any refused entry pulls nothing, so each pull anew refetches the refused bodies once per growth that admits at least one.
- Room is judged as the take judges it (`room_now`): a total's room counts what give-way frees, so the durable total's room is the cap less the bytes no give-way frees (tombstones and path steps: `Usage::fixed`, summed in the cached `Total`), and the memory total's is the cap itself (every memory byte gives way). Judging free bytes instead keeps S full forever once another sync ID fills the freed room with entries S's take would push out.
- Each full key is an `Effects` key (`Inner::room_fx`) whose settle reads stamped values only: S's usage row (Own), S's memory listing (Memory), the caps (stamp `CAPS`, `set_caps`), the unread fixed bytes (stamp `UNREAD_FIXED`, written by `put_usage` when an unread S's fixed bytes move and by a holding move), S's holding and its need; so a tick with nothing moved judges nothing.
- Rejected: keeping refused blob IDs (unbounded: every new entry past the cap is refused); one mark for S as a whole (any sign then pulls S anew at every source); ending full at the next complete pass with no refusal in it (a stream with a cursor never shows a refused entry again, so it ends full while the entry is still there, and the pull anew refuses it again, once per pass); refusing an entry larger than a whole cap as "too large" (it would need its own refetch when the cap rises; full covers that, and ends once the entry leaves); fetching refused bodies only while the new room lasts (needs per-entry refusal memory or a spec rule stopping the refetch, for a cost already bounded per growth).

### Fetched anew
`pull_anew`: a kept-unread S back within its keys or raised to read (`Store::set_unheld` false while marked, its `anew` feed; spec/sync-judgement.md §6 Stops), and any S raised from kept unread to read (`Store::set_holdings`: what it refused unread, stamped under no key of its head then, its sources show no more; §6 Read and unread move), pull S from the start at every source pulling it and at every source holding a place of S, stored ones included (`records_with_row` over the place tags): each moves to `joining` from the start, in one transaction with clearing the store's one durable "pull anew" mark (`N/`, `Store::reset_anew`) and every room mark of S. The copy dropped while stranded is behind every stored position (refused entries settle and the place passes them), and a node raised to read keeps nothing else to fetch it by.
- The mark is written with the drop (empty value: S takes nothing until judged again; loaded at open into `unheld`, so it is fetched anew once judged read or back within its keys) or with a raise (`ANEW_RAISED`, not over a drop's mark; every `anew_feed` starts with the raised marks it reads, so a module restart's new feed owes them too), so a restart anywhere before the reset changes nothing.
- A drop's mark stays out of the feed: it waits for judgement, and `pull_anew` does nothing while S is `unheld` (a head move or a room mark owed meanwhile feeds S; pulling then would clear the drop's mark while S takes nothing, and a restart before the regain would lose the fetch).

### A head move shows refusals again
spec/sync-streams.md §4 Refused. Each code 1 refusal this node tells (a stamp under no key it knows, `pull::head_may_lift`) keeps, in the source's place, the head of S it was told under (`Place::told`, row `t`, one per (source, S)). A tombstone, expiry, malformed bytes or an earlier key (9) do not turn on the head: counting them would pull S whole per head move from every source listing a tombstoned entry.
- A registered step that moves the head feeds `anew`, and writes `ANEW_SOME` (unless a mark stands) when some record holds a `t` row of S (`path::register`; a connection's told heads are lost with it anyway). `pull_anew` under that mark pulls S from the start only at the sources whose told head is not the head now (and those whose room mark is owed), dropping their told rows with the reset. Once per (source, S) per head move; a refusal told after the move but before the pull keeps its row.
- A pull from the start also re-shows entries held with stamps under an older key: `Store::take_stamped` takes an entry held with the same wrap and stamp unjudged (0), else it would tell the source a refusal (9) of an entry it holds.
- Head moves are steps verified under the head's step key: no peer drives them.

## Sends counted
No entry crosses a connection twice: what a requester takes is never streamed back (spec/sync-streams.md §4 Reports; model `S_echo`, `S_echorestore`, `S_echowait`, controls `SN_echotold`, `SN_echocount`, `SN_echodurable`, `SN_echoanchor`, `SN_echocheck`, `SN_echowait`). Rule: both sides count the same sends, and a count stands only on an anchor checked on the connection that counts it.
- **Server**: `Serve::asked` keeps each message's `Added` entries with its cursor; an Applied (`on_applied`, `reported_by`) counts the covered ones held at the peer less those it told (`Serve::told`: refusals since its last Applied of entries `asked` carries): `count_applied` writes `Op::Add` (a record's rows, an ephemeral entry's the connection's), after the last message in hand from that peer if one is (`Batch::after`: a listing that message ends would otherwise drop them). A connection's end drops those messages, the Applieds deferred behind them and every later message together, and the peer's filter of what it counts goes with its side of the connection, so no cursor stored passes an event left out for a count that never stood. A Pull drops from `asked` the Streams sent since the last reply after the message its cursor names, all of them where it names none (`Serve::pulled_at`, `Asked::stream`): its reply reads them again, and the requester reports none it passed over in a gap or applied while that Pull was out (it stages those with `report` false). So the gap needs no bookkeeping either side (`a_gap_is_counted_from_the_reply_that_reads_it_again_spec_sync_streams_4`).
- **Requester**: `Pulling::reporting` holds the entries held here that `Added` events of the messages the next Applied covers carried, each with a mark (`serve::At`: log end, or memory counter for an ephemeral one) where held as sent at its apply. One not held at its apply is told at once (14, unless a refusal of it was told since the last Applied), so `reporting` stays within entries held here whatever a source sends. `told_now` keeps every refusal and 14 told since the last Applied, so the next counts none of them, as the server's `Serve::told` does (`a_refusal_told_before_an_earlier_apply_stands_for_the_report_spec_sync_streams_4`); it stays within what the messages in hand and one step applied carry. Before the Applied goes (`run`) each one no longer held is told; the Applied waits while a tell does; once it goes the held ones' marks join `Serve::counted`, and `Serve::counts` leaves their events at or below the mark out of everything served that peer but a listing from the start (`Serve::listing`: a whole reply until its stream part ends, a join from the start until it merges). Marks go once the peer's Applied passes them (one at or below its applied position is never served again on the connection). A stamp the requester logged on taking (other than the one sent) is no match: its event goes, so the server learns the stamp as the echo taught it.
- **Anchor** (`Place::anchor`, row `ANCHOR`): an Applied counting any entry (one in `reporting`, held and not told) carries the requester's log end; a store error reading it fails the step rather than send the Applied bare, and an Applied without one counts nothing on a record (`count_now`). The server holds it at once where none is held or a reply on the connection checked the held one (`Pulling::checked`); else it waits in `Pulling::waiting` with the counts of the Applieds since, which stand only once that check comes (less what the checking reply shows gone, `apply`) and end with the connection (`a_count_waiting_on_an_unchecked_anchor_ends_with_its_connection_spec_sync_streams_4`). Pulls name the held anchor until checked; a server whose history lacks it answers from the start (`serve.rs` `reply`), and that listing's end replaces presence, spending the held anchor where none waits (one held since that Pull went came from an Applied sent before the reply, whose cursor and listing cover it). A record-less peer has no anchor: its counts go with the connection.

## Presence and listings
A listing read from the start to its end (a whole reply and its pages: no cursor, one naming no position, or trimmed; a join from the start) replaces what that source is known to hold of each member it covers (spec/sync-streams.md §4 Applying). Until its end it stores no cursor (a join keeps its stored start) and owes no Applied, so one cut short by a lost connection or a restart is listed from the start again.

Its end, applied once every body it owed was settled (`drain`), is S's first sync ending here (spec/sync-streams.md §5): `Store::set_first_synced` (row `F/`, stamped, gone with S's shred). Past the first sync once one ended at any source, until S is left.

## Closed members
**Presence follows membership**: a source's word on S lasts exactly as long as opens keeps S a member of its record (or a stop on the connection up), so whatever ends a membership (notes/sync-opens.md, Judging: a credential no longer admissible, S left) ends the word, and an away member keeps it (offline and forks are normal). What decides is opens' judgement of the credential on what this node holds, read alike by every node holding the same. A reader's member ended at a node keeping S unread by a head move keeps what it showed until its next connection closes it, an away member to the store.
- Hostile pass: a peer keeps its word alive only by being a member (proof it may hold S, or a session up), and its presence counts only for entries held or tombstoned here (`concerns`); no peer reaches another's word: rows live in that peer's record (pair key), moved only by that record's stream, its membership (this node's own judgement) or `RECORD_BUDGET` eviction (a defined outcome: the peer is read from the start at its next connection).

What a record source showed of S (presence, head, refusals) goes with its place of S: `left` with `Leaving::Forgot` (or S not held), `Moved::Forgot` (`forgot`), or the connection ending. A member closed keeping its stop (`Leaving::Kept`) stays in the place, marked `closed` (row `CLOSED`, written at once): `closed(conn)` queues the closed stops of a place it drops (`unkept`), and the next tick forgets them (place rows and `known` rows in one transaction); `Moved::Forgot` from opens' `release` comes after `closed(conn)` and finds no pull. A start (`Streams::new`, every record's `CLOSED` rows, O(records)) forgets those a crash left. Rejoining (`joined`) clears the mark. A place moved to joining from the start since (a fetch anew) stands over a Lost's cursor opens names in `Rejoin::From`; else a dropped copy's entries are lost.

## Failures
- A store read of a source's rows that fails answers as if nothing were shown, which only holds back acts (held elsewhere, Leave, Register all need presence); the one read whose absence would act, the presence a listing replaces, fails the step (`Known::list`).
- A body the store or engine fails to take stays owed and fails the step: it is never settled, so no cursor passes it. A failed step sends nothing it queued (notes/sync-driver.md, Failures).

## Shred
A shred of S takes S's place rows in the store's transaction and S out of every place in memory before any place is next read (`Streams::place` drains the store's shred feed). A member leaving S later in that step would otherwise write its pre-shred position back, and S read again would rejoin past entries it no longer holds.

## Costs left in O(members)
A Pull's reply builds the members map (per Pull: joins, gaps, pages, not per event); `inline_check` scans a connection's members when a member gains or loses a source; a push lists the memory part only of the members with memory events since its mark (the store's node-wide memory index, `memory_since`).

`INLINE_LIMIT` (bodies inline up to it), `FETCHES_OUT`, `RESYNC_MS` (types.rs, shared with opens: before a refused Pull goes again or a refused join is joined again), `ASKED_MS` (the stall timeout, a blob asked of one source); the spec's `REPORT_WINDOW` (osis-proto `limits`: messages in hand, and messages asking a report unreported).
