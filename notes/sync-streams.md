# Sync: streams
> Summary: osis-sync's `streams` module (core/sync/src/streams/): serving and pulling each shared sync ID over the peer's node log, joins, bodies, `known` (what each source showed); its durable place per source, presence and listings, failure handling, the shred rule, remaining O(members) costs and what is not built.

Spec: spec/sync-streams.md §3-§6, spec/wire.md §11.2 (Pull, PullReply, Stream, Applied, Fetch), spec/sync-judgement.md §3 `known`. Model: core/test/tla/net/NetStream.tla (each `SN_*` rule names its function). Principle and state: the module doc of core/sync/src/streams/mod.rs. Overview: notes/sync.md.

## Shape
- Both sides serve (`serve.rs`: Pulls from the node log filtered by the shared set now, pages by `max_reply`, joins in pages, ephemeral listings, pushes under `follow` with `seq`, Fetches, reported positions) and pull (`pull.rs`: one Pull out, received vs stored cursors, joins by generation, messages in hand applied in order once their bodies settle, gaps read again, bodies one source at a time in fill order (only what the store lacks: a body opening to a held commit is kept as it came, `Opening::Held`, so it is never fetched again while held or tombstoned; an announced entry whose bytes the store holds under another sync ID, a certificate copy wrapped under each sync ID needing it, is taken with them at once: else a reader that cannot wrap under S, which never logs it itself, holds it must-hold with no entry forever), Full and Refused at a node keeping S unread; relay-only entries in Streams with no cursor (`relay.rs`, notes/ephemeral.md In osis-sync); `refetch`: a body read finds missing, queued outside any message from a source that showed it, `Streams::fetch_again`).
- A **source** is a peer's record, else the connection (`store::Source`). Per source a `Place` (stored cursor, members at the stream, joins with their cursors, where members stopped), held in memory while a connection pulls from the source.
- `Known` (`known.rs`): heads, full, refusals and presence per source, presence (and a deletion seen, `Store::saw_deleted`) kept only for entries held or tombstoned here, or whose body was taken (`Opening::Taken`: pieces, records, inbox blobs) while the message was in hand, when the message applies (`pull::concerns`): a hostile source listing made-up IDs grows nothing, and a body whose fetch failed at a source counts as not held there, as spec/sync-streams.md §4 Reading says. A server inlines no body the requester's own stream showed present (`Serve::shown_by_peer`, reading `Known`): no per-connection memory of bodies sent, and an echo of a body a peer just gave is avoided once its message is applied (a push racing that apply may carry it back once: bytes only); stamped per (source, S, blob), per (S, blob) for `present`, per (source, S) for listing, so read, unread, status and inbox follow it by key. `Streams::new(store)`: `Known` keeps the store handle so its `&self` reads need no store argument (a world copy resets it, `set_store`).
- Members come by `Moved` from opens; ended members are known by `Moved::Until`, so serving reads the shared set per event and checks `until` only for ended members: a push costs its events, not the members. Reported positions go back to opens as `Reported` after each message, move and settle; streams reads them through `Shared::reported`.
- The core runs over `streams::Ctx { store, ground: &mut dyn Ground, wire: &mut dyn Wire, shared: &dyn Shared, now, reported }` (`Ground`: `open`, `rank` from the engine; `Wire`: sessions; `Shared`: opens' `members`, `agreed`, `record`, `reported`), so core/sync/tests/it/streams.rs runs two sides over real stores with scripted opens and engine.

## Durability
- A record source's rows (tags `c` cursor, `a` at the stream, `j` where a member not at it joins from: joining from it or stopped there, one row; `k` present per blob, `h` head, `r` a refusal it sent that stands; `t` the head of S this node last told it a refusal under, `Place::told`) are written by `save`: one transaction per applied message that moved something (what it showed, the cursor it stores, the members whose position moved; after its bodies were taken in their own transactions), per join or leave that moves a member's position, per Refused, per lift (`serve::offered`). A join started writes its cursor, so a restart joins from it whatever opens wrote (a load reads the row as stopped there: no connection is up).
- A member's position is what is written, not its form (`Place::effective`): at the stream means the stream's cursor. A leave or join that keeps it (at the stream, then stopped at the cursor; stopped, then joining from there) writes nothing, so a reconnect writes no row per member. The member is kept in `Place::stale` and written with the next cursor that moves (`save` with the cursor), before the stored "at the stream" could mean another position. An Applied goes only once that transaction committed.
- A cursor is sealed with a fresh nonce each time (osis-store `nodelog`), so equal positions have unequal bytes and a requester stores each reply's cursor: a reconnect with nothing new writes one cursor row per side, no member row (`streams::a_reconnect_after_a_restart_costs_the_same_at_10n_spec_sync_streams_4` counts it). Opens writes its record per connection (taken: `used`; the reconnect's filter generation and its acknowledgement), a constant per connection.
- Rejected: a server answering a read that moved no position with the cursor it was given (saves that cursor row). Equal bytes tell the requester the server's log did not move at all, any sync ID's: a peer polling Pulls learns when the server takes or writes anything, for things it does not share (spec/requirements.md, Confidentiality between readers).
- A connection's `Known` (ephemeral entries, record-less peers) stays in memory. An evicted record needs no call: streams keeps nothing in memory for a record no connection holds, and its rows go with it.
- **Refusals received** (spec/sync-streams.md §4 Refused) stand only on their ground, and every end is an event this node sees: the entry served again to that source (`Streams::offered` after each reply and push: one `r` row read per sync ID carried, a write only where one stood; a listing from the start lifts all of S there, which also covers an entry that left while the source was away past the deletion horizon), the source's stream showing it present (`Op::Add`: a refusal racing a new stamp that the source then took), and the head its stream names moving (`Op::Head`: all of (source, S)). The entry leaving this node ends every source's refusal of it, however it left (an expiry, a give-way or a dropped copy serves no event): `store::entries::remove` drops the record rows in the entry's own transaction (the row index by (S, tag, blob)). An ephemeral entry's refusal is kept in memory under its source whatever the source (`Known::refused_here`; a durable row would outlive the entry at a restart), and memory refusals go when the store's entry feed shows the entry gone (`Known::settle`, each tick, O(entries changed)); a record's lifts reach its memory refusals through `Known::wrote_record`. So `refusing` is "some row or memory refusal stands"; rows are at most one per entry held here, gone with the record. The refusal's stamp and head are not kept: no read compares them.
- **Full** (spec/sync-streams.md §4 Full): received, it is a fact of the connection (in memory under `Source::Conn`, whatever the source), ended by `full` false, S leaving the connection (`left`) or the connection; no row. Sent: the store keeps S full durably per cap that refused (`store::Cap`: S's own, the durable total, S's memory part, the memory total; row `R/`, the bytes the least entry it refused needs under it and the latest expiry of one, written by `take_stamped` before the place can pass the entry), `Store::waits_room`. Streams tells `full` true where it refused and on each connection S joins while full (`Pulling::told_full`), and `full` false on each connection for each S `room_grew` reports (`untell_full`). A total cap refuses only what give-way cannot make room for (path bytes, tombstones; role entries count toward no cap). `Store::room_grew` (each tick) ends S's wait once a refusing cap has room for one more entry of that least need (`room_fits`; an entry left anywhere it counts, the cap rose; the memory part is empty after a restart) or S is no longer kept unread, writing the `N/` mark `ANEW_ROOM` in the same transaction: the pull anew then goes as every other. A growth too small for any refused entry pulls nothing, so each pull anew refetches the refused bodies once per growth that admits at least one. Room is judged as the take judges it (`room_now`): a total's room counts what give-way frees, so the durable total's room is the cap less the bytes no give-way frees (tombstones, path steps and claim sets: `Usage::fixed`, summed in the cached `Total`), and the memory total's is the cap itself (every memory byte gives way); judging free bytes instead keeps S full forever once another sync ID fills the freed room with entries S's take would push out. Each full key is an `Effects` key (`Inner::room_fx`) whose settle reads stamped values only: S's usage row (Own), S's memory listing (Memory), the caps (stamp `CAPS`, `set_caps`), the unread fixed bytes (stamp `UNREAD_FIXED`, written by `put_usage` when an unread S's fixed bytes move and by a holding move), S's holding and its need; so a tick with nothing moved judges nothing. Full also ends when what it refused may be gone, the node keeping no memory per refused entry: the latest expiry passed (read through a memo `Clock` in the store, `room_fits`; its `next` is a wake in `next_wake`); a source's stream shows the deletion of an entry neither held, tombstoned nor taken here outside a listing from the start (`Streams::apply`); or a source lists S from the start (a whole reply, a join from the start) other than for this node's pull anew (`Pulling::anew`, set by `pull_anew`, kept while that listing lasts), judged as the reply arrives, before its bodies are (`on_pull_reply`): a listing shows no deletion past the horizon, and a connection source lists S whole at each connection. Both stream triggers call `Store::refused_may_be_gone`, which ends S's wait durably (`end_full`, the same `R/` removal and `ANEW_ROOM` mark as `room_grew`) before the message's cursor is stored, and the next `room_grew` reports S. A trigger while S is not full does nothing, so a pull anew under way absorbs the triggers that come during it. Without the `anew` exclusion a pull anew whose listing arrives after another source's refusal ends full again, and with two sources holding refused entries that repeats forever. Cost: one listing of S per source plus a refetch of the still-refused bodies per trigger, and at most one trigger per deletion event shown, per connection (a whole listing) and per join from the start not asked by a pull anew. Rejected: keeping refused blob IDs (unbounded: every new entry past the cap is refused); ending full at the next complete pass (spec/sync-status.md §1) with no refusal in it (a stream with a cursor never shows a refused entry again, so it ends full while the entry is still there, and the pull anew then refuses it again, once per pass); refusing an entry larger than a whole cap as "too large" instead of full (it would need its own refetch when the cap rises; full covers that, and ends once the entry leaves). A shred ends S's wait with its rows; streams tells `full` false for each shredded S (`forget_shredded`), in case S stays shared. Rejected: fetching refused bodies only while the new room lasts (stopping the fill at the first refusal): cheaper per growth, but needs per-entry refusal memory or a spec rule stopping the refetch, for a cost already bounded per growth. An entry refused for room is fetched again if another source shows it before room grew (refused again; no memory per refused entry).
- **Fetched anew** (`pull_anew`): room grown at a full S (`ANEW_ROOM`, written over none or a head move's mark, which it covers), a kept-unread S back within its keys or raised to read (`Store::set_unheld` false while marked, its `anew` feed; spec/sync-judgement.md §6 Stops), and any S raised from kept unread to read (`Store::set_holdings`: what it refused unread, stamped under no key of its head then, its sources show no more; §6 Read and unread move) pull S from the start at every source pulling it and at every source holding a place of S, stored ones included (`records_with_row` over the place tags): each moves to `joining` from the start, in one transaction with clearing the store's one durable "pull anew" mark (`N/`, `Store::clear_anew`). The copy dropped while stranded is behind every stored position (refused entries settle and the place passes them), and a node raised to read keeps nothing else to fetch it by. The mark is written with the drop (empty value: S takes nothing until judged again; loaded at open into `unheld`, so it is fetched anew once judged read or back within its keys) or with a raise (`ANEW_RAISED`, not over a drop's mark; every `anew_feed` starts with the raised marks it reads, so a module restart's new feed owes them too), so a restart anywhere before the reset (of the modules or of the store) changes nothing. A drop's mark stays out of the feed: it waits for judgement, and `pull_anew` does nothing while S is `unheld` (a head move or room grown meanwhile feeds S; pulling then would clear the drop's mark while S takes nothing, and a restart before the regain would lose the fetch).
- **A head move shows refusals again** (spec/sync-streams.md §4 Refused): each code 1 refusal this node tells (a stamp under no key it knows, `pull::head_may_lift`; a tombstone, expiry, malformed bytes or an earlier key (9) do not turn on the head, and counting them would pull S whole per head move from every source listing a tombstoned entry) keeps, in the source's place, the head of S it was told under (`Place::told`, row `t`, one per (source, S)). A registered step that moves the head feeds `anew`, and writes `ANEW_HEAD` (unless a mark stands) when some record holds a `t` row of S (`path::register`: a connection's told heads are lost with it anyway); `pull_anew` under that mark pulls S from the start only at the sources whose told head is not the head now (the rest of a place untouched), dropping their told rows with the reset. Once per (source, S) per head move; a refusal told after the move but before the pull keeps its row. A pull from the start also re-shows entries held with stamps under an older key: `Store::take_stamped` takes an entry held with the same wrap and stamp unjudged (0), else it would tell the source a refusal (9) of an entry it holds. Head moves are steps verified under the head's step key: no peer drives them.

## Presence and listings
A listing read from the start to its end (a whole reply and its pages: no cursor, one naming no position, or trimmed; a join from the start) replaces what that source is known to hold of each member it covers (spec/sync-streams.md §4 Applying). Until its end it stores no cursor (a join keeps its stored start) and owes no Applied, so one cut short by a lost connection or a restart is listed from the start again.

Its end, applied once every body it owed was settled (`drain`), is S's first sync ending here (spec/sync-streams.md §5): `Store::set_first_synced` (row `F/`, stamped, gone with S's shred), read by inbox's suspect lists. Reading: past the first sync once one ended at any source, until S is left (written into the spec).

## Failures
- A store read of a record's rows that fails answers as if nothing were shown, which only holds back acts (held elsewhere, Leave, Register all need presence); the one read whose absence would act, the presence a listing replaces, fails the step (`Known::list`).
- A body the store or engine fails to take stays owed and fails the step: it is never settled, so no cursor passes it.
- A failed step sends nothing it queued (notes/sync-driver.md): a frame might tell of what the failure undid; the peers see a dropped connection.

## Shred
A shred of S takes S's place rows in the store's transaction and S out of every place in memory before any place is next read (`Streams::place` drains the store's shred feed). A member leaving S later in that step would otherwise write its pre-shred position back, and S read again would rejoin past entries it no longer holds.

## Costs left in O(members)
A Pull's reply builds the members map (per Pull: joins, gaps, pages, not per event); `inline_check` scans a connection's members when a member gains or loses a source; every connection's ephemeral listing reads each listed member's memory part when any ephemeral entry moves (issues/streams-ephemeral-scan.md).

## Constants
`INLINE_LIMIT` (16 KiB), `PENDING_CAP` (64 messages in hand), `FETCHES_OUT` (2), `RESYNC_MS` (30 s, before a refused Pull goes again or a refused join is joined again), `ASKED_MS` (the stall timeout, a blob asked of one source).

## Not built
issues/sync-unbuilt.md (streams): the engine's linked blobs (`Engine::wants`: pages and header lists before apply); bundle import (`Streams::import` answers `NotBuilt`; `Node::export_bundle` is built); `Rank::Never` from the engine (a keyset without history: the facade has no call for it).
