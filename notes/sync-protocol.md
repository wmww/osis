# Sync protocol: wire choices, osis-proto, osis-label
> Summary: Why the sync wire is laid out as it is (fixed prefix, Padmé marker, request/reply framing, what opens bind), and how osis-proto (frames, Hello, messages and their decode caps, the serving and client engines, relay-only gate, client port) and osis-label (blobs, chunk trees, large values, steps, proofs, bundles) are built. Not here: reply caps, windows and stall bounds (notes/flow-control.md); the host's store and policy (notes/serving.md); node sync (notes/node-sync.md). Layouts: spec/wire.md.

## Wire choices
- The blob prefix is a fixed byte layout so a host parses it without a CBOR decoder; the AEAD binds it as AD so a reader cannot re-prefix a ciphertext (new expiry or commitments) under a fresh blob ID.
- Padmé length recovery: a `0x80` marker then zeros inside the ciphertext (ISO 7816-4 style). One byte, no length field, and canonical because the padded length must equal `padme(len + 1)`.
- Header lists, the delete-key list and purge go by link above `CHUNK_THRESHOLD` (128 KiB) up to `MAX_LIST_BYTES` (64 MiB); header-list chunks carry the level-2 commitments only (notes/crypto.md).
- Request/reply by id over length-prefixed frames; both Hellos go out at once, so negotiation costs no round trip; per-entry status, so a batch partly succeeds; a Status names a stale key (9) but never carries the head (notes/label-access.md).
- Opens bind the opened side's Hello challenge and static key (no replay elsewhere); stamps, deposits and deletes do not, so stamped entries and deletes stay relayable.
- Retired wire kinds (10, 12, 13, 15-18, 21-23) and status codes (10, 15) decode as unknown; their numbers are never reused.

## osis-proto
- Modules: `frame` (`FrameDecoder`, `encode_frame`); `hello` (Hello, `negotiate`, `estimate_offset`: median of per-sample offsets, Hello counting as one sample, reported after three pongs; samples with a round trip over 10 s are ignored, as pings held across a suspend); `msg` (`Message`, one variant per kind over osis-label's `Step`, `ClaimSet`, `Proof`, `DeleteItem` and the `SecretBox` entry box; `decode` enforces every cap of spec/wire.md §11.2; `Rejected::code` gives the Error code); `dec` (typed reads of decoded arrays); `prove` (connection proofs, bound to role, challenge and listener key); `filter` (the shared set's Golomb-Rice beacon filters, spec/wire.md §11.2 Beacons); `store` (`LabelStore`, `MemoryLabelStore`); `serving` (`ServingSession`); `client` (`ClientSession`); `relay` (`RelayGate`); `api` (client-port messages); `bundle` (`BundleImport` over osis-label's reader and importer, yielding `Imported` paths and events); `examples` (a fixed label and one message per kind, for tests and vectors).
- Decoder rules beyond the layouts: id 0 only on Error and pushes (kind 24 is Auth); a step at most `MAX_STEP_BYTES` (323). Message nesting depth 6. Both sides take only a Hello-sized first frame (`MAX_HELLO_BYTES`, 256).

### Serving engine (`ServingSession`)
- `handle(now, &mut dyn LabelStore, ServingInput) -> Vec<ServingOutput>`: it answers Ping, Register and Delete (only for a label node sync opened there: `ServingInput::Open`/`Shut`) from the store and hands node kinds and client-port requests up; nothing crosses connections. The store rules node sync applies to what it pulls or is offered (`put_stamped`, `pulled`, `deposit`) live beside it.
- **Nothing reads the path per request.** The store keeps indexes per step added (`LabelStore::step_with_sync`, the newest step per sync key; `child`, genesis as the child of none; osis-host's `V`/`W` rows), so node sync answers a Behind item with index lookups, a child lookup and step read per step crossed, plus the step's shared claim set for a claim or static entry (`unread_behind`); a static entry's grant loads only the head's set (`LabelStore::claim_set`, a shared `Arc`). Stamps, deposits and keyed deletes check the head's key, then the `OLDER_KEYS` (8) newest distinct earlier keys (code 9), else code 1, from `LabelStore::head_keys`, which the store keeps per head (`HeadKeys::child`; osis-host's `K` row), so these checks never read the path either.
- A delete by level of an entry no longer held is refused (the prefix cannot be checked); a held one's prefix comes from `LabelStore::blob_prefix` (osis-host keeps it in the blob's `R` row), never the whole blob.
- The store applies policy: caps (the ephemeral cap included), the deposit budget, delete rate limits (`delete` return codes); ephemeral entries (prefix class) go to `Put::ephemeral`; an entry taken again changes nothing and logs nothing.
- **Relay-only** (`relay`, `RelayGate`, in memory per store): admitted by prefix expiry and size, counted against a per-label rate (`RelayLimits`: 6000 relays and 32 MiB per minute; host policy `relays`, `relay_bytes`), passed on once per blob within its expiry window (a repeat passes nowhere); at most `MAX_RELAY_SEEN` (2^16) pairs remembered, past which the earliest-expiring is forgotten and a replay of it is pushed again.

### Client engine (`ClientSession`)
- `handle(now, ClientInput) -> Vec<ClientOutput>`; commands are batched under the caps.
- **Node kinds** (`Message::for_node`): Prove, Resume, Stranded, Suspect, the shared set's and the stream's kinds, and any id in the node's range (`NODE_IDS`) go to the upper layer (`ServingOutput::Peer`, `ClientEvent::Peer`), which answers by `ServingInput::Peer` / `Command::Peer`; sessions keep no proof or record state. Proved and Resumed go by id: a dialing `ClientSession`'s own Prove and Resume (`Command::Prove`, `Command::Resume`) carry its ids and it takes their answers (until issues/net-one-peer.md build 3i).
- **Client port** (kinds 24-29, notes/client-port.md §2, module `api`): `ServingSession` hands Auth/Call/Sub out as `ServingOutput::Request` and answers by `ServingInput::Reply` (bounded by the request's `max_reply`); Notifies go as `ServingInput::Notify` after `WantRoom` → `Room { budget }` (the push rule, `room`). The session itself answers Call/Sub before an answered Auth (1), a reused live Sub id (2), past `MAX_SUBS` (4096; code 4) and every Unsub (every listener serves the port: spec/sync.md §10, One key). `ClientSession` takes `Command::{Auth, Call, Sub, Unsub}` with caller tokens and reports `ClientEvent::{Reply, Notify}`; a live Sub's id is never taken by another request. Allowances: `max_reply` for Call/Sub, `SMALL_REPLY` for Auth/Unsub (`client::allowance`). Tests: tests/it/port.rs.
- Co-reader peers use one engine per direction, not both on one stream: the dialer runs `ClientSession`, the acceptor `ServingSession`; co-readers each dial the other (notes/peers.md).

## osis-label
- Modules: `blob` (the prefix with its class, `Class`: durable, ephemeral, relay-only; frame/open; blob ID; `host_prefix`; `Prefix::for_keys`/`for_delete_keys`, the one place commitments are computed; prefix/header agreement `Prefix::agrees`; the blinded key at a level `Prefix::key_at`; `unwrap_any` newest first); `tree`; `chunks`; `step` (`Step`, `StepId`, `StepKeys`, `register` (genesis or child; claim set and entry boxes; a step without rotation passes the parent's keys), `verify_path`, `path_to`, `ClaimSet`, `open_entry_box`, `match_secret`, `genesis_label`); `auth` (`Proof`, `evaluate_open`, stamps, deposits, `DeleteItem`: `sign` by the label delete key, `sign_by` a level's delete key plus `key_for_levels`' label key, `verify`); `inbox`; `addr` (strict `address` values and their text form; base64url is osis-base's); `labels` (`label.0` records to verified steps); `link` (`ShareLink`); `bundle` (`BundleWriter`, `BundleReader`, `Importer` yielding `BundleEvent`s).
- `tree` re-exports osis-commit's chunk trees (streaming `TreeWriter`/`TreeReader` over `TreeSink`/`LinkSource`; errors are `osis_commit::Error`, converted by `From`). The reader is retry-safe: a `Missing` blob can be fetched and the call repeated; it checks every length it passes and `seek`s by node lengths, fetching only the path; `HashSink` gives shape and hashes without encryption. `BlobWriter`/`BlobReader` frame chunk, node, page and link-page blobs under a `Framing` (dedup secret, expiry, delete keys, each blob blinded by its own link blind; `keeps(prefix, blind)` is the re-encryption rule) and implement osis-crdt's `PageSink`/`PageSource`; `Written { id, blind }` names each blob written; `Reuse::index` plus `BlobWriter::reusing` dedup by reuse; `BlobSink`/`BlobFetch`, `BlobStore`, `MemoryBlobs`.
- `chunks` (large atomic values): `LargeParams`; `chunk_value` (inline at or below the threshold, else the canonical bytes as a tree); `read_value` (whole, lazy, rejects a chunked value at or below the threshold); `string_head` (a large blob or string's length from its first bytes). Streams of large values walk the tree with `TreeReader` (osis `ValueStream`).
- `label.0`, `address`, `step_record` and `box` codecs are osis-schema core types, re-exported. From osis-commit label uses only the chunk trees and their `Error`: the inbox payload carries the commit as its `CommitBlobPlaintext` value, and prefix agreement takes the header's `(level, delete key)` pairs, its blind and the expiry.
- Limits: a prefix has at most one commitment per level (3); expiry 0 means none (a `Some(0)` expiry is refused); blobs `MAX_BLOB` (8 MiB); tree nodes 1..=512 links, level 1..=48, the root always interior (an empty value is one empty chunk); claim sets a power of two up to `MAX_CLAIMS` (65 536), every entry box key among the claims, boxes strict `box` values; steps, claim sets, inbox payloads and bundle frames decode with depth 512 and `MAX_MESSAGE` bytes; links and cards 8 addresses, 4 peers, 4 relays, 256-byte URLs; bundle frames 1..=`MAX_MESSAGE`.
- Importer rules beyond the spec: an entry must follow its blob in the bundle and a stamped entry its label's path (the writer emits them in that order); deletions pass through unverified, like a peer's log events.
- The address text form `<url>#<base64url key>` is provisional and client-side only.
