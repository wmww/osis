# Simulator
> Summary: The deterministic simulator (core/test/sim, osis-sim): engine-to-engine runs (phase A), sync engines and hosts over a reachability model (`NetSim`), the API world (`World`), shared setups, the invariants checked at every step and at quiescence, the work-sets comparison, the scenario library, adversaries and version skew, `sim-sweep`, and how to replay a failing seed.

## Running and replaying
- `cargo run --bin sim-sweep -- --seeds N [--from S] [--setup U] [--only a,b] [--blocked] [--budget-secs T] [--jobs J] [--out DIR] [--list]` (dev profile, about 1.3x the release time). Runs seed-major across scenarios on J threads until done or out of budget; prints failures per scenario with each failing seed's replay; `--out` writes `DIR/failing-seeds.txt`; exits 1 on any failure. Its `N failing` summary leaves out KNOWN failures: a script judging a sweep greps `failing: osis_sim`, never ` 0 failing`. A seed past `OSIS_SEED_TIMEOUT_SECS` CPU-seconds fails as hung, and one still running at the end exits the process (101) after naming it. A sweep cut by its budget says so only in its per-scenario seed counts. The gate runs every scenario at 15 seeds, a release check at 150 (notes/coordination.md, Release checks).
- **Replaying a seed**: a failure prints `osis_sim::replay("<scenario>", <setup>, <seed>)` and the same run as `sim-sweep --seeds 1 --from <seed> --setup <setup> --only <scenario>`. Call it from a test (`cargo test -p osis-sim --test it`), then reduce it to a minimal reproducer of the broken property (often in osis-node, on `Net`). Never pin the seed (notes/coordination.md, Design principles).
- Tracing: `OSIS_SIM_TRACE=1` prints every trace line with the proto messages; `OSIS_SIM_TRACE_FULL=1` keeps frames, diagnostics and divergence reads whole (cut to 140-200 characters by default). A "read differently" failure ends with a divergence dump: per node, every commit naming the differing aspect with its part's status and the aspect's state (`Engine::aspect_dump`). Failures carry scenario, setup seed, seed, step and the last 40 trace lines.
- A small in-test sweep: `OSIS_SIM_SEEDS=N [OSIS_SIM_FROM=S] [OSIS_SIM_ONLY=a,b] cargo test -p osis-sim --test it sweep -- --ignored` (an empty `OSIS_SIM_ONLY=` runs nothing).
- `osis_sim::SCENARIOS` lists every scenario; `osis_sim::BLOCKED` maps a scenario to the issue that breaks it (sweeps skip it; empty). Known-failing repros of open issues (any crate) are `#[ignore = "issues/<name>.md"] repro_*`; every `--include-ignored` release command adds `--skip repro_`, and the fix renames the test.
- The gate's sweep is CPU-bound and balanced, so only less work per seed shortens it; a seed's CPU is mostly node-sync passes and ingest (`SyncEngine::handle` about 70%).

## Phase A: engines (`Sim`)
`Sim::new(name, seed, Config)` boots real engines, each over its own `MemoryBackend` + `MemoryRoot` sharing one `osis_store::Faults` plan, a `ManualClock` and a seeded rng; all randomness comes from one `Dice` seeded by the run seed. `Config`: per-node `ClockSpec { skew_ms, drift_ppm }`, `NetFaults { drop_pct, dup_pct, max_delay_ms, reorder }`, scheduler `Weights { write, gossip, deliver, tick, crash, restart }`. `step()` picks a random write, a gossip (an oracle standing in for reconciliation), a due delivery, a tick, a crash (now or at a durable write) or a restart.
- Per-step invariants (`check`): every group of up nodes holding the same parts of the same applied commits reads the same values; own `ts` strictly increasing across restarts and within `MAX_DRIFT` of the wall clock; no remote commit applied more than `MAX_DRIFT` ahead; no counter range of one session overlapping another commit's on one aspect; at quiescence every node holds the same parts and nothing pends. Engine errors on honest input and panics are failures.
- Scenarios: `two_nodes`, `three_random`, `crash_restart`, `drift_parks` (a commit pends with `Drift` until the receiver's clock catches up), `revoke_while_writing`, `grant_to_group`.

## Reachability model (`reach.rs`)
One model for both sims, not a packet machine. Each node has LAN segments and an uplink (public address, a NAT, none); `route(from, to, url, blocked)` is the best item of a `peer://` URL: a LAN address on a shared segment, the target's public address, a punch (`osis_transport::nat::punch_opens`) or a relay both reach. A relayed link ends with its relay, a punched one does not. Partitions are the caller's (`blocked`). A host (`NetSim::add_host`, `World::add_host`, osis-node's `Net::add_host`) is a node that cannot read: node sync on a bare engine above its hub, admission open.

## API world (`world.rs`)
`World`: `osis::Osis` handles on `Runtime::Manual`, osis-host `Hub`s and peer links over in-memory queues under one `ManualClock` (`cfg_clocked`: a node on its own skewed or drifting clock); the osis crate's tests use it. `add_host`, `cfg`/`account`, `run`, `advance`, `until(future, step, n)` (panics if it does not resolve), `set_online` (offline nodes still tick), `place`, `lan_announce`, `set_peer_reachable`, `set_relay_up`, `restart`, `diagnostics`/`trace`, `traffic` (bytes per node), `start_tally`/`tally` (upstream frames by kind). A settle past `STORM` rounds panics naming what it carries.

## Phase B: sync engines and hosts (`NetSim`)
- `NetSim::new(name, seed, NetConfig)`; `add_peer` (an osis-host `Hub` over its own faulty store), `add_node(hosts, ClockSpec)` (`SyncEngine` over an `Engine`, its own skewed clock). Two hosts never connect: data crosses only through a reader connected to both. Actions are carried engine to engine (`Dial`, `Send`, `Close`, `Wake`) in the order made, as the node driver does: a call's `Hub` downs go to the node's hub after its other actions (`NetSim::actions`), else a nested call's newer `Wake` is overwritten by the outer call's older one and the node never ticks again (`net::a_restart_in_place_with_served_peers_keeps_the_latest_wake`); after every node call the sim fails unless the wake it holds is the one the node last asked (`after_node`, `SyncEngine::asked_wake`); `peer://` dials go through the reachability model.
- **Links** are ordered byte streams with `LinkFaults { cut_pct, dup_pct, max_delay_ms }`, blind to content: releases at keyed random moments, a cut loses what is on its way (both ends told), a release may arrive twice (the receiver must survive it). Compared runs (`with_arrivals`) deliver all that is due per deliver step, others one message a step.
- **Scheduler** (`NetWeights`): write, deliver, tick, node crash (now or at a durable write) and restart, host crash and restart, partition and heal of a (node, host) pair. A crash at a durable write is power loss: the crashed store takes the device down before any of the call's outputs go; every step and `quiet` fail on a device left up on a dead store (`no_dead_store_up`). A planned `Fault::Fail` is a one-off failed write: the device stays up and its next calls must work. Also `sever`, `wipe_host`, `lose_disk`, `reconnect_all`.
- **Setup** is calm (no faults): flows helpers `person`, `pair`, `introduce` (a contact card's parts), `direct` (everything a node holds, including another account's whole creation commit, which the state bound does not count; only pairing and `peer_group` use it), `group`, `grant`, `remove`, `item`, `carry`, `quiet(max)`. `run(n)` turns faults on; `run_until_quiescent(max)` heals, restarts everything, settles a resync interval at a time until idle and unchanged for two rounds, then checks. Idle (`NetSim::idle`): `SyncEngine::is_idle` (every session the node dialed started: one waiting for a Hello a host dropped is a pass not started) and no up host the node can reach waiting to be dialed again (`retrying`): else a node cut from a dishonest host by a stall syncs with it after the check and its late pass changes the honest host. A request a dishonest host never answers is no work (`is_idle_but_unanswered_at`): its own periodic requests move the stall clock (spec/sync.md §6 Stall: any link speed passes, so other bytes move it up to `MAX_AHEAD`), so the connection stays up with the request out for good (`evil_host_drops` seed 889902233282/889902233296: a dropped Pong while the host re-pulls every round).
- **Quiescent invariants** (`net/check.rs`): convergence by held deltas; nothing pends; no certificate copy still waits; holder liveness (every node of an account on an admin's roster the model keeps connected to the admin reads the group; one cut off for good counts in `Report::unjudged`, which fails the run unless the scenario lists it in `excused`) and agreement per connected part; per host and label, no live entry tombstoned or back after a tombstone, every must-hold body (`SyncEngine::verdicts`) in a live entry, nothing a node may delete as must-not-hold still live, deposits promoted; purged bodies at no host and no honest node; state size (spec/requirements.md Scale: a node's stored bytes ≤ 2 × must + 2 KiB × entries + 16 KiB × labels + 64 KiB, `net/check.rs` `STATE_*`; a hostless label counts every commit made under it); no ping-pong (three more resync rounds log nothing). A settle of more than 5000 deliveries is a message storm. `excused` nodes (removed, lost) are left out of liveness, agreement and purge checks.

## Shared setups
`NetSim::setup(name, params, Seeds { setup, seed }, cfg, build)`: a scenario's calm setup is built once per process per (scenario, setup seed, `params`, run mode), and every run is a copy of it (notes/test-harnesses.md, Copied worlds) that goes on from the run's seed: the scheduler's dice and every keyed roll are the seed's, and every seeded generator in the nodes and hosts draws a new stream (`copying_reseeded`).
- The setup seed is `sim-sweep --setup`, by default `--from`: one setup per scenario per sweep, a fresh one per gate and release check. Seeds of one sweep share the setup's keys, tids, label and blob IDs (and the tie-breaks they decide), clock skews and message order; across sweeps all of it varies.
- `build` takes no scheduler step (checked). It is the scenario's prefix before its first `run`, cut earlier where the seed chooses (`snapshot_rights`, `large_edits`, `concurrent_writers`, `deposit_flood`, `future_format`); a seed choice the setup depends on is a `params` key (`no_host`'s topology, the ephemeral host caps). Run modes (`with_full_passes`, `with_other_stream`, `with_arrivals`) key their own setups. Phase A scenarios build their few-commit setups per seed.
- Saves about a third of the sweep's CPU against a setup per seed, for about 50% more peak memory (1.5 GB at 15 seeds).

## Work sets against full passes
`core/test/sim/tests/it/work_sets.rs` (notes/node-sync-work-sets.md): `net::with_full_passes(f)` makes every node added in `f` judge everything at each pass; a scenario run both ways may differ in messages only, with no tolerance on fault and write counters, when each entry's bytes, deposit and registration first reached each host and when a delete took a host's last copy (`with_arrivals`: a missed trigger shows as a later arrival), and `Report::parts` (what each node and host ends up with). Blobs are named by commit and parts, never by ID (IDs, wraps and salts are the luck of the random stream: `compared_runs_ignore_the_random_stream`). It guards that work sets miss no trigger, not that the judging helpers are right (the sweep's invariants do that).
- Default test `work_sets_purge_on_replace`; by hand `work_sets_match_full_passes` (every scenario at `OSIS_SIM_SEEDS`, default 20, from `OSIS_SIM_FROM`; `OSIS_SIM_ONLY` narrows; about 18 min at 100 seeds on 16 cores) and `honest_flows_wait_for_no_resync` (no faults).

## Scenarios (`net/scenarios.rs`, `net/library.rs`, `net/ephemeral.rs`, `net/adversary.rs`, `net/skew.rs`)
Expected outcomes are in each scenario's doc comment.
- Basics: `two_nodes_host`, `three_accounts_two_hosts`, `removed_writer`, `reader_relays`, `stranded_reseal`, `host_loses_data`, `offline_rotation`, `compaction`, `grant_lost_on_crash`, `large_edits` (bytes sent per edit within 1.2x of the changed chunks plus the root node and 32 KiB), `no_host` (three holders with no host: LAN, public addresses, relayed or punched behind NATs, by seed), `no_host_chain`.
- Library (setup by flows, a faulty `run` around the story's moment, the story's outcome, then the quiescent invariants): `revocation_bob`, `revocation_carol`, `demotion_synced`/`demotion_unsynced`, `link_redeem`, `link_race`, `chat_join_leave`, `team_reads_member_thing`, `folders`, `bundles`, `disappearing`, `purge_on_replace`, `concurrent_writers` (`NetSim::count_placed`). Story marks go in `s:story.0` (`library::tags`), which random writes leave alone.
- Ephemeral (`ephemeral`, `ephemeral_capped`): random ephemeral and signal writes, slow hosts and per-host caps (0, below one snapshot, about the snapshots, twice them, plenty). `ephemeral::check` (first in `quiescent`): a host is "lossy" when it lacks an entry an up node holds and cannot fit it; holders connected through non-lossy hosts read durable items' ephemeral state alike; host charge within its cap; signals at most once per node; after quiescence `author_leaves` and `signal_reaches` (exactly once at every holder sharing a host with the sender). The durable checks skip `e:` aspects.
- Adversaries: hand-driven dialer sessions into a `Hub` (`NetSim::rogue`, `rogue_do`, `rogue_raw`, `rogue_close`), a hostile writer's entries put in a host's store by its rules (`NetSim::host_put`), a host's lies (`NetSim::host_says`). `evil_host` (`NetSim::dishonest` hosts are skipped by the label checks), `evil_host_drops`, `removed_replayer`, `malformed_blobs`, `equivocating_writer` (`NetSim::equivocation` exempts it from the honest-counter check), `tombstone_liar`. A stolen pairing offer is the osis crate's tests.
- Version skew: `future_format` (a commit at `FORMAT_VERSION + 1`: parked everywhere, `NetSim::parked_ok`, relayed, kept through an old writer's compaction), `newer_schema`.

## Sim tests
`core/test/sim/tests/it` holds only what the sweeps do not: a scenario's faults happening (`two_nodes_converge`, `three_nodes_random_delivery`, `drift_parks_until_clock_catches_up`, `two_nodes_host`, `ephemeral`; by hand `crash_and_restart`, `three_accounts_two_hosts`), replay exactness, the work-sets comparison, scale counts and hand-written examples. No test replays a scenario at a seed for its own sake.
