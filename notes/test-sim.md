# Simulator
> Summary: The deterministic simulator (core/test/sim, osis-sim): engine-to-engine runs, the invariants checked at every step and at quiescence, `sim-sweep`, and how to replay a failing seed. Networked scenarios are osis-sync's `sims::` (notes/test-properties.md).

## Running and replaying
- `cargo run --bin sim-sweep -- --seeds N [--from S] [--only a,b] [--blocked] [--budget-secs T] [--jobs J] [--out DIR] [--list]` (dev profile, about 1.3x the release time). Runs seed-major across scenarios on J threads until done or out of budget; prints failures per scenario with each seed's replay; `--out` writes `DIR/failing-seeds.txt`; exits 1 on any failure. Sizes: notes/testing.md, Sizes.
  - Its `N failing` summary leaves out KNOWN failures: a script judging a sweep greps `failing: osis_sim`, never ` 0 failing`.
  - A sweep cut by its budget says so only in its per-scenario seed counts.
  - A seed past `OSIS_SEED_TIMEOUT_SECS` fails as hung (notes/test-harnesses.md, Seed runners).
- **Replaying a seed**: a failure prints `osis_sim::replay("<scenario>", <seed>)` and the same run as `sim-sweep --seeds 1 --from <seed> --only <scenario>`. Call it from a test (`cargo test -p osis-sim --test it`), then write a minimal reproducer of the broken property; never pin the seed (notes/principles.md).
- A failure carries scenario, seed, step and the last 40 trace lines; a "read differently" failure ends with a divergence dump (per node, every commit naming the differing aspect, its part's status and the aspect's state: `Engine::aspect_dump`). `OSIS_SIM_TRACE=1` prints every trace line as it happens (on a one-seed replay), for a wait that began before the kept tail.
- In-test sweep: `OSIS_SIM_SEEDS=N [OSIS_SIM_FROM=S] [OSIS_SIM_ONLY=a,b] cargo test -p osis-sim --test it sweep -- --ignored` (an empty `OSIS_SIM_ONLY=` runs nothing).
- `osis_sim::SCENARIOS` lists every scenario; `osis_sim::BLOCKED` maps a scenario to the issue that breaks it (sweeps skip it; empty). Known-failing repros of open issues (any crate) are `#[ignore = "issues/<name>.md"] repro_*`; release commands skip them (`--skip repro_`) and the fix renames the test.
- The gate's sweep is CPU-bound and balanced: only less work per seed shortens it.

## Engines (`Sim`)
`Sim::new(name, seed, Config)` boots real engines, each over its own `MemoryBackend` + `MemoryRoot` sharing one `osis_store::Faults` plan, a `ManualClock` and a seeded rng; all randomness comes from one `Dice` seeded by the run seed. `Config`: per-node `ClockSpec { skew_ms, drift_ppm }`, `NetFaults { drop_pct, dup_pct, max_delay_ms, reorder }`, scheduler `Weights { write, gossip, deliver, tick, crash, restart }`. `step()` picks a random write, a gossip (an oracle standing in for reconciliation), a due delivery, a tick, a crash (now or at a durable write) or a restart.
- Setup as a real node does it: each node makes an account at its start (`local_peer::make_account`, its profile public; `Sim::account`); each account is every other's contact by its contact card, a locator of the profile (`Engine::locator`), which each other node follows (`follow_locator`, so the first sync brings the profile), redeems for its account (`redeem_locator`: the account's strong to the profile) and unfollows, so a granter holds the grantee's card and fires at its inbox; things are minted with the minting node's account as mint admin, `Sim::grant` grants the grantee's account by the flow (`Engine::grant`) and the grantee holds the thing from its node root, so each node writes only what it holds. A random write on a thing whose offer gave a role before its minting arrived is refused (`UnknownThing`), as the API refuses it. Fires go apart from commits, as sync's fire step carries them (`Sim::fires`, in `sync_all` and each gossip, lost at the drop rate).
- **Per step** (`check`): up nodes holding the same parts of the same applied commits read the same values; own `ts` strictly increasing across restarts and within `MAX_DRIFT` of the wall clock; no remote commit applied more than `MAX_DRIFT` ahead; no counter range of one session overlapping another commit's on one aspect; at quiescence (each full exchange ending every node's pass, `Engine::settle_needs`, so what a node was handed and needs nothing for goes, a stub's content among it) nothing pends and every node holds each part the sync IDs it syncs carry as another node sees them (`carried_under`; a stub-class sync ID its role-class parts alone; the certificates `sent_parts` hands every peer besides are not judged). Engine errors on honest input and panics are failures.
- **At quiescence, apart from any sender** (`Sim::check_history`, counted in `Report::history_checked`): the harness records what it played (`History`: things minted and with what mint admin, roles given and removed, content commits, sim-schema parts); each node must hold, unmissing, every recorded write on each thing it reads by that history, by a writer who may write there and was never removed there (a removed writer's writes turn on the removal's frontier, which the history lacks). Covered and dropped parts count as held (`commit_parts_missing` names only missing ones). This catches a sender that never carries some thing's bodies, which the sender-defined check passes (a planted `missing()` dropping one thing's parts fails `two_nodes` and `three_random` at seed 0).
- Scenarios: `two_nodes`, `three_random`, `crash_restart`, `drift_parks` (a commit pends with `Drift` until the receiver's clock catches up), `revoke_while_writing`.

## Sim tests
`core/test/sim/tests/it` holds only what the sweeps do not: a scenario's faults happening (`two_nodes_converge`, `three_nodes_random_delivery`, `drift_parks_until_clock_catches_up`; by hand `crash_and_restart`) and hand-written examples (`partial_relay_gets_its_rest_spec_commits_4`). No test replays a scenario at a seed for its own sake.
