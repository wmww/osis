# Rust API: implementation
> Summary: How the `osis` crate is built over the engine and sync engine: module map, the handle's lock and `after`, writes and sources, futures, sharing helpers, status, large values, text sessions, tests. The API's shape: notes/api.md.

Module map (`core/osis/src`): `handle` (`Osis`, `Config`, `Store`, `MemStore`, the lock and `after`, schema registration), `internals` (doc-hidden: the `Internals` trait on `Osis` with `engine`, `sync_engine`, `waiting`, `take_actions`, `feed`, plus `ManualNet` and the `node` re-export, for the CLI's `inspect`, the sim and tests), `net` (`Runtime`, `SyncOptions`, `Net`, the driver host, `Waiter`/`Pending`), `commit_id` (`CommitId`, `CommitPos`, `CommitFrom`, opaque over the engine's), `value_type` (`ValueType`), `account` (pairing), `share` (grants, demotions, links, cards, nodes, peers, group sync, status, bundles), `serving`, `clients`, `sources` (routes), `port` (the client port), `retention`, `keep`, `read`, `write`, `large` (`ValueStream`, `len`, `set_stream`), `text` (`TextSession`), `watch`, `commits` (`Commit`, listings, listeners, undo), `diagnostic`, `keys`, `error`.
- **Handle and sync**: one mutex over `Locked { sync: SyncEngine (owns the engine), events, seq, waiters, status, offers, links }`. Every call under it ends in `after`: engine events go to the dispatcher in commit order; if the call (not the driver) caused events, `SyncEngine::handle(Event::Local)` runs; then direct-link upkeep (rotate the dialable key when one ended), the status (a `Msg::Status` to watchers when it changed, a `Stranded` diagnostic on a new stranding) and the waiters. Network actions leave through `Net` under the lock (FIFO, so frames keep their order): `Off` drops them, `Manual(ManualNet)` queues them for a test harness (`Internals::take_actions`/`feed`), `Driver` sends `Control::Apply` to osis-node's `sync::driver::run_shared` running on the app's or osis's own tokio runtime with the handle as its `Shared` (a weak reference; the driver stops when the node closes). `close()` fails `Invalid` from a callback and `StillOpen` while other user handles exist (`Life` counts them; osis's own short-lived holders, the dispatcher running a callback, a driver engine call, timers, use uncounted handles: `Osis::internal`, `WeakOsis::hold`), else waits uncapped until the store is closed (each such holder ends on its own); dropping `Net` sends the driver `Shutdown`. Engine calls run in `block_in_place`, which a runtime shutdown does not wait for: the task polled on after one would hit a timer of the shut-down runtime and tokio panics. So the driver task holds a drop guard: osis's own runtime (`Runtime::Own`) is shut down by an `osis-sync-stop` thread once the guard dropped (at most 5 s, then `shutdown_timeout` 5 s; the drop itself may run inside that call, hence the thread; the store is already closed: `Inner` drops `eng` first), and `close` waits for that thread (so every task on it, the host's too, is gone and `host.redb` is free for a reopen); on the app's multi-thread runtime `close` waits (uncapped, in place when inside it; on a current-thread one not at all: no engine call runs in `block_in_place` there, and the host store may stay locked until the app drives that runtime again) for the guard (the driver awaits the host task's end on `Shutdown`), so the app may shut its runtime down next; and the driver polls no timer while a control message waits, so a `Shutdown` queued by a drop before the runtime's shutdown is seen first (an app dropping the runtime while the node is open can still hit the panic). Wake timers hold a weak sender and are armed only for a waiter that did not resolve at once. A driver task that panics (or that its runtime drops unfinished while the node is open) ends sync for the handle's life (`net::Watched` around the task, `driver_died`): under the lock it sets `Net::died` and fails every waiter with `Network("sync driver panicked: <msg>")` (else they hung: their wake timer sends to a closed channel); later waits fail the same way at once, `listen`/`client_listen` too; then a `SyncStopped` diagnostic (best effort: the engine may be what panicked); the panic goes on to the runtime. `osis serve` (and `diag --follow`) exit 6 on that diagnostic; the app shows it. A thin client's connection thread (`port::client::Io`) fails its calls and closes its subscriptions in `Drop`, so a panic there does not hang a `node_task` either.
- **Write and sources**: a `Write` records its API ops (`WriteOp`: create, group ops, path ops at a key-table index, expiry as wall time, retention, purge, delete) with each call's checks done as it is recorded, and builds the engine `Mutation` at `commit` under the lock (`delete` expands against the state held then; its expiry conflicts surface there); the op list is the request of a write at a node (notes/client-port.md). Every call addressed by a tid, group or scope starts with `self.source(..)`: `sources::Source::{Local, Node(connection)}`, a match at each site.
- **Futures**: no call takes a timeout (Tess): a future cancels on drop, a caller wraps it in its own runtime's timeout. `wait_until(late, check)` registers a check on the sync engine and status, run after every change (and on any call, so `late` passes offline too; a driver wake, `Net::timer`, looks at it); no public call passes a `late` now. A link naming no saved peer on a node that dials nobody directly (`Inner.dials_peers`) is `Network` at once. A waiter whose future was dropped is removed; held link keys go with a guard on every outcome; a waiter dropped unanswered answers `Closed`. A driver gone answers `Network` (`driver_died`), a node closing answers port rows `Closed` (`Job::Closing`). `Pending` resolves through a slot with the stored waker: runtime-agnostic (tests poll with a no-op waker or a park/unpark waker). Without a runtime they fail `Network` at once. **Connecting**: `async` too. A thin client (`connect`, `connect_socket`) needs its node for `me()` and all else, so it returns connected or fails with why its one attempt did not, leaving nothing; a node's `connect_node` keeps the connection and retries, `status` showing it, as the node can work without it. `CONNECTION_WAIT` bounds one attempt and a sync write across a drop, which has no future to drop.
- **Account**: `create` runs flows' `create_person` (the sync engine is built first so it sees every event), writes an empty `group.0` on the account (home = account), records `account` and `hosts` app records. `open` refuses an account without `keys.0` (`Invalid`). `create_person` mints a recovery key (an admin by a plain edge) and drops the card (recovery is out of the API, issues/recovery-redesign.md; the engine's `recover` serves node tests until issues/recovery-redesign.md). Pairing messages are CBOR `[1, ...]` in base64url with `osis://pair/`, `osis://pair-request/`, `osis://pair-reply/` prefixes; MACs are `kdf(purpose, secret, body)`; the request carries the new node's commits, the reply the grant id and the packages `take_direct_for(node)` returns (the grant or re-seal, the account's certificates and `label.0` commits: about 20 KB, whatever the account holds); offers live in memory (`OFFER_LIFETIME_MS`).
- **Sharing**: each call is a flow plus `carry_out`. `grant` maps a missing `keys.0` to `UnknownActor` and `Permission` to `needs: Admin`. A demotion syncs nothing first (addenda, notes/api.md Demotion and addenda). `sync(group)` gives the group secrets of its own and its sync ID in one commit (`Engine::give_own_secrets_on`): a label whose genesis is at its first admin's derived epochs cannot be verified by a holder reaching it through a link actor (issues/node-sync-gaps.md). Links: K → (L, target, single_use, direct, ended) in memory and the `links` app record; single use is the link's `flags` bit: the redeemer removes L in its redemption; finalization is node-sync's. A self-removal (`leave`) is sealed and uploaded before the leaver drops what it lost (`Done::drop_lost`). `contact_card` makes profile P (first admin: me, a group of itself, labeled), places the account's `created.0`/`keys.0` commits under P's label as certificates, makes a read link to P and keeps its text (`contact` record). `import_contact` holds L, follows K's label, waits for P's first admin's `keys.0`, drops L.
- **Ephemeral signals**: a fire of a `+~` aspect is an ephemeral write the engine signs at write time as a relay-only commit (notes/ephemeral.md Ephemeral signals); `on_fire` hears it once here, like a remote one.
- **Status**: from `SyncEngine::label_status` per label: no saved peers; stranded (a failed open); `Synced` when every connection holding it open finished a pass with nothing outstanding; `Syncing` when connected or open; else `Unreachable`. A group shows its worst label. `wait_synced` judges each label (`label_state`, the check `share::synced`), not the group's worst state; `Thing(t)` scopes the synced groups whose closure holds t. Deliveries: `SyncEngine::pending_about` lists what each pending one is about (an inbox delivery's `SentInbox::things`, a deposit's label group; the outbox is stored, so a restart sends it again, and a queued deposit's host is dialed until it takes it, `wanted_hosts`); `pending_uploads` of the shape is not built.
- **Diagnostics** added: `NotSynced` (after a commit adding a thing to groups none of which is synced), `Stranded`; `Engine::report` dedups them.
- **Large values**: `stream` walks the chunk tree one chunk per call (`Engine::next_chunk` under the lock); `len` reads the CBOR head of the first chunk; a seek fetches nothing, the next read fetches the root and the nodes on the path to the target chunk (`TreeReader::seek`, lengths in tree nodes). `set_stream` reads the value whole, then sets it (issues/api-deferred.md).
- **Text sessions**: buffer plus base; `commit` writes `Op::Edit { base, new }` on a `text` position (rebased by the crdt; a paged text resolves it on the pages around the change when the text there still matches `base`, notes/engine-paged.md Paged state) or `Set` on a string register. Two locks: `st` (base, buffer; taken briefly, by keystrokes too) and `save` (held across a save or a merge, never by a keystroke). A save snapshots `(base, buf)` under `st`, commits with `st` released, then sets `base` to the snapshot: typing meanwhile stays pending, and `save` keeps a second save from committing the same edit. The session subscribes to its aspect undeduplicated (a watch's last value is not the session's base: its own commit then a `remove` would read as no change) and on every call `merge` reads the field under `save`: equal to `base`, nothing; else save, read the merged text, and if no typing came in meanwhile set base and buffer to it and call `on_merge` with `osis_crdt::changes` (the gaps of the Myers LCS over chars) as splices, else go round again. The first edit after a commit arms a timer on the node's runtime (`Net::after`: a tokio sleep, then a blocking task) that commits once the session has been idle `idle_commit` (re-armed for the rest otherwise; it clears `last_edit` before saving so a keystroke during its save starts a new pause instead of saving inline); without a runtime the next edit after `idle_commit` commits inline; drop commits (a failure reported as `Uncommitted`); `known` (the thing read known at open or after a commit) makes the save's write check `has_content` under the commit's lock (`Write::alive`, so a delete ingested between the check and the write is seen): false fails `UnknownThing` and the buffer keeps the edits (a merge then leaves the buffer alone). A commit that fails otherwise (lost write access, storage) reports an `Uncommitted` diagnostic and keeps the edits for the next try; a merge after a failed commit drops them. `Knobs::text_save` runs between a save's snapshot and its commit (the keystroke-during-save test). `edit(base, new)` places the change in the buffer under `st` (one splice of `base -> new` carried through the changes `base -> buf`, read as one change where that is disjoint, else as the char diff, so typing between two merges stays there; an insert inside a merge's change goes to its end), so a merge landing between the UI's read and its keystroke cannot move it.
- **Writes, reads, watching, undo**: writes act as `me()` (`act_as`); `commit` returns `Option<Commit>`; reads materialize with a budget; the dispatcher coalesces per aspect; undo, redo and the query read `Engine::held_commits`; a register edited twice undoes twice (spec/crdt.md §4.6).
- **Sharing helpers**: `holders` is a breadth-first walk over rosters. `set_role` loops over its first way for the holder: a direct grant goes through `lower` (or `grant` for a raise), a path through a link actor of a seed thing held (`held_links`, ended ones included) through `remove_joiner` (the engine's `revoke_joiner`: one commit, so no half-removal), anything else is refused. `add_peer`/`remove_peer`: `follow_labels` (one commit of `label.0` host-list sets) before the list is saved, then `follow_inbox`.
- **Not built** (issues/api-deferred.md): queries and backlinks, `undelete` and cut/paste in text sessions, `set_sync_options` heartbeats, bearer `open_link`, streaming writes, `pending_uploads`, a direct-connection pairing convenience.
- **Standard data**: the scenario tests (core/osis/tests/it: notes, tags, contact, event) use this API end to end (notes/std.md).
- **Tests**: core/osis/tests: `api`, `watch`, `commits` (query, undo/redo/revert, exact undo, two nodes, another actor's revert), `sync` (tier 1: `World` in core/test/sim/src/world.rs drives `Runtime::Manual` nodes and osis-host `Hub`s under one `ManualClock`; futures polled with a no-op waker), `sharing` (more sharing and status through `World`), `runtime` (tokio driver over `InProcess` against the host driver: a link redemption; QUIC tier 2, ignored).
