# Rust API: implementation
> Summary: How the `osis` crate is built over the engine: module map, the handle's lock and `after`, writes, futures, sharing helpers, large values, text sessions, tests. Sync: the handle holds an `osis_sync::Node` under its lock and steps it (`net`, `syncing`, `port`). The API's shape: notes/api.md.

Module map (`core/osis/src`): `handle` (`Osis`, `Config`, `Store`, `MemStore`, the lock and `after`, schema registration), `internals` (doc-hidden: the `Internals` trait on `Osis` with `engine`, `watches`, `acting_as`, store measures and test knobs, for the CLI's `inspect` and tests), `net` (`Runtime`, `Lan`, `blocking`, `Net`, the driver task, `ManualNet`, `listen`, `rotate_peer_address`), `syncing` (`status`, `on_status_change`, `wait_synced`, the `Waiting` future), `port` (the client port, node side), `commit_id` (`CommitId`, `CommitPos`, `CommitFrom`, opaque over the engine's), `value_type` (`ValueType`), `account` (pairing), `share` (grants, demotions, links, cards, nodes, status), `disputes`, `clients`, `sources` (client and source calls), `retention`, `keep`, `read`, `write`, `large` (`ValueStream`, `len`, `set_stream`), `text` (`TextSession`), `watch`, `track` (tracked reads), `backlinks`, `commits` (`Commit`, listings, listeners, undo), `diagnostic`, `keys`, `error`, `testing` (doc-hidden test knobs).
- **Handle**: one mutex over `Locked { node, events, seq, offers, out, wake, secret, port }`; `node` is the `osis_sync::Node`, which owns the engine (`Locked::engine`). `locked` steps sync with `Input::Wrote` when the call committed (the engine's `store_writes().committed` moved) and it stepped nothing itself, carries what the steps gave (`Net::carry`), queues engine events for the dispatcher (and `Msg::Status` after a step while a status listener exists), then off the lock wakes the futures waiting on sync (`Inner::waiters`). Client port requests are served only by `ReadOnly::step` (the one loop feeding the node's inputs: the driver task or `ManualNet`), after its step and off the lock, as the main handle (`port::serve`): no API call runs a client's request, so a caller holding another lock (`undo`) never waits on one, and requests run one at a time. Timers (`Inner::after`) are threads that sleep, then run.
- **Sync outputs** (`Net`): `Off` (`Runtime::None`: a dial is answered `Down` under the same lock, the one wake runs at the next call due); `Driver` (the tokio task `drive` owning `TransportLinks<Multi>`: each input stepped under the lock in `blocking`, outputs come back over the control channel in step order and `apply` carries them; `Ctl::Listen` restarts every listener, the client socket included, under the node's secret); `Manual` (`internals::ManualNet`, a test fabric: nodes by key, `run` delivers until quiet, jumping one `ManualClock` to the next wake, `advance(ms)`, `set_online`, `ups(i)`). The node's dialable secret is the engine app record `sync/node-key`; `Config::dial` becomes `SyncConfig::dial`. The compaction trigger runs in each sync step (`Node::handle`).
- **Close**: `close()` fails `Invalid` from a callback and `StillOpen` while other user handles exist (`Life` counts them; osis's own short-lived holders, the dispatcher running a callback, an engine call, timers, use uncounted handles: `Osis::internal`, `WeakOsis::hold`), else waits uncapped until the store is closed. Engine calls on a multi-thread runtime run in `block_in_place` (`net::blocking`).
- **Writes**: a `Write` records its API ops (`WriteOp`: create, group ops, path ops at a key-table index, expiry as wall time, retention, purge, delete, release), each call's checks done as it is recorded, and builds the engine `Mutation` at `commit` under the lock (`delete` expands against the state held then, and its expiry conflicts surface there); the op list is what a write at a node is to carry (notes/client-port.md). Writes act as `me()` unless `act_as`.
- **Futures**: no call takes a timeout (Tess): a future cancels on drop, a caller wraps it in its own runtime's timeout. `Pending` resolves through a slot with the stored waker, runtime-agnostic (tests poll with a no-op or park/unpark waker).
- **Account**: `create` runs flows' `create_account` and writes an empty `group.0` on the home group. `open` reads the engine's account record (`Storage` without one).
- **Sharing**: each call is a flow. `grant` maps a missing `keys.0` to `UnknownActor` and `Permission` to `needs: Admin`. A demotion syncs nothing first (notes/api.md Demotion and addenda). A first grant gives the thing secrets of its own and its sync ID in one commit (`Engine::give_own_secrets`). Links: made by the engine flow `create_link`; single use is the link's `flags` bit (the redeemer removes L in its redemption; finalization is sync's).
- **Sharing helpers**: `holders` is a breadth-first walk over rosters. `set_role` loops over its first way for the holder: a direct grant goes through `lower` (or `grant` for a raise), a path through a link actor of a held seed thing (`held_links`, ended ones included) through `remove_joiner` (the engine's `revoke_joiner`: one commit, so no half-removal); anything else is refused.
- **Diagnostics** added here: `NotSynced` (after a commit adding a thing to groups none of which is synced; the engine's for things a subgroup cut, by any cause, leaves in no synced group), `Stranded`; `Engine::report` dedups them.
- **Commit listings** (`engine::listing`; the rule is `listing::listed_part`, which undo's `kept` uses too; undo, redo and listings read `Engine::held_commits`). A page is O(log n + places walked), and a filter matching few walks the whole address; `reverted_by` and `in_effect` scan the commits on a listed commit's value aspects stamped after it, so a page from `Oldest` of an aspect with n commits costs O(page × n), as does each listener event for an old commit (stated, not optimized). Listeners are off until an open's first one (`Engine::watch_commits`, sticky) and cost nothing on an aspect none is on. A join on a listened aspect costs the commits it superseded (`Killed` dots, `listing::note_killed`), each told when it reads no longer listed; only a rebuild (a validity flip, an un-merge, a drop, a paged reset, O(commits held) anyway) compares the whole listing before and after. A part leaving at its keep bound changes no state: its aspect's one timer tells it (notes/engine-retention-history.md Leaving history). Dispatch finds subscriptions by (tid, ak), thing, group and role slots, O(log S + matched); the dispatcher coalesces per aspect. Purge requests are stored per aspect only when they name more than one delta, by name under `pn/` + aspect + commit. A register edited twice undoes twice (spec/crdt.md §4.6).
- **Ephemeral signals**: a fire of a `+~` aspect is an ephemeral write the engine signs at write time as a relay-only commit (notes/ephemeral.md Ephemeral signals); `on_fire` hears it once here, like a remote one.
- **Large values**: reads materialize against a byte budget; `stream` walks the chunk tree one chunk per call (`Engine::next_chunk` under the lock); `len` reads the CBOR head of the first chunk; a seek fetches nothing, the next read fetches the root and the nodes on the path to the target chunk (`TreeReader::seek`, lengths in tree nodes). `set_stream` reads the value whole, then sets it (issues/api-deferred.md).
- **Text sessions**: buffer plus base; `commit` writes `Op::Edit { base, new }` on a `text` position (rebased by the crdt; a paged text resolves it on the pages around the change when the text there still matches `base`, notes/engine-paged.md Paged state) or `Set` on a string register.
  - Two locks: `st` (base, buffer; taken briefly, by keystrokes too) and `save` (held across a save or a merge, never by a keystroke). A save snapshots `(base, buf)` under `st`, commits with `st` released, then sets `base` to the snapshot: typing meanwhile stays pending, and `save` keeps a second save from committing the same edit.
  - The session subscribes to its aspect undeduplicated (notes/listener-design.md Text sessions) and on every call `merge` reads the field under `save`: equal to `base`, nothing; else save, read the merged text, and if no typing came in meanwhile set base and buffer to it and call `on_merge` with `osis_crdt::changes` (the gaps of the Myers LCS over chars) as splices, else go round again.
  - `edit(base, new)` places the change in the buffer under `st`: one splice of `base -> new` carried through the changes `base -> buf`, read as one change where that is disjoint, else as the char diff, so typing between two merges stays there; an insert inside a merge's change goes to its end. So a merge landing between the UI's read and its keystroke cannot move it.
  - The first edit after a commit arms a timer (`Inner::after`: a thread that sleeps, then commits) that commits once the session has been idle `idle_commit` (re-armed for the rest otherwise; it clears `last_edit` before saving, so a keystroke during its save starts a new pause instead of saving inline); without a runtime the next edit after `idle_commit` commits inline; drop commits (a failure reported as `Uncommitted`).
  - `known` (the thing read known at open or after a commit) makes the save's write check `has_content` under the commit's lock (`Write::alive`, so a delete ingested between check and write is seen): false fails `UnknownThing` and the buffer keeps the edits (a merge then leaves the buffer alone). A commit that fails otherwise (lost write access, storage) reports `Uncommitted` and keeps the edits for the next try; a merge after a failed commit drops them. `Knobs::text_save` runs between a save's snapshot and its commit (the keystroke-during-save test).
