# Engine store records and the persisted index
> Summary: What the engine keeps in its encrypted `Store`: local record prefixes, store kinds (aspect units and their three tables), the rebuildable `node/*` index tables, and how an open uses them (the rules tag, `node/perm`, headers decoded at open, the role walk rebuilt), with open costs. Not here: the store itself (units, key tree, shredding: notes/local-store.md), sync's `y/` records (notes/sync.md), paging layouts (notes/engine-paged.md). Module map: notes/engine.md.

## Principle
The commit records and local records are the truth; every `node/*` table is an index, a function of the held commits that a rebuild must give, so a store whose index fails to read is rebuilt, never repaired. A fast open derives from the index; the role walk is derived state rebuilt at each open.

## Local records
Layouts in `engine/records.rs` (and the module named); all are `*_local` store records.

| prefix | holds |
|---|---|
| `seed`, `hlc` | the node seed; the last `ts` issued or seen |
| `c/`+commit | applied commit records: a head (`index::record_head`, version 1: received, origin (a repair's own commit marked, with the blobs it encrypted afresh, `Meta::repair`), dropped parts with what each keeps (`Hold::Dropped`; one dropped as covered, whether its blobs drop it too: `Dropped::strips`), stripped parts and whether each leftover keeps own values (`Hold::Leftover`), the canonical bytes of the header's linked lists), then the current blob. A held header is whole in its record (its list blobs go at the commit's expiry, spec/wire.md §5), so no open reads them |
| `t/`+tid | creation records |
| `v/`+aspect | gone deltas (expired, purged): the join-time removal list |
| `w/`+aspect+commit+ai | leftovers (notes/engine-retention-purge.md) |
| `p/`+aspect, `pn/`+aspect+commit, `z/`+commit+tid | purge requests on a whole aspect or author; requests naming a commit; a request that dropped a permanent delta (`retention::lasting`) |
| `x/`+T+commit+ai | timers (expiry, keep bounds) |
| `s/`+tid | things this node was asked to sync |
| `o/`+commit | commits voided by overlapping session ranges |
| `g/`+tid+commit | `keys.0` parts whose held body wrote a keyset, any validity (`ix.keyset_parts`, kept while the commit is held); `independent` = things with such a part valid (`apply::keys::refresh_independent`, on noting, flips, load), so an uncover keeps it and an invalid rotation drops it |
| `k/`+actor | opened epochs of a thing (`established`, `claims`, `snapshot`; never re-inferred; written from the index's journal at each transaction's end, `index::write_secrets`, never by hand). | `b/`+commit+tid | pending boxes kept sealed by forgetting (`apply/keys.rs` `SEALED`; notes/engine-lost-access.md) |

Other store kinds (osis-store's catalog):
- **Aspect units**: the state (`state::Stored`); a unit exists exactly while its aspect has a state, so a key scan of a thing's units lists them (`Transaction::aspects_of`, `aspects.0`; `all_aspects` for an open and a rebuild): snapshot grammar with its pages inline; for a paged state `[1, skeleton, [[set ID, path, encoding]*]]` (paged collections reduced to their reset and `W`); or `[2, commit ID]`, the state as that commit's part in its record (notes/thing-cost.md, States stored as their body).
- **Aspect tables** (`engine/pages.rs`, notes/engine-paged.md): table 0 state pages (key = set ID ‖ order-preserving bytes of the page's first dot, the first page the set ID alone; value `[first dot, next page's first dot, page]`); table 1 paged maps by key and paged sets by value (set ID ‖ keyed BLAKE3 of the key or value, links by content hash (`pages::ident`, key `Core::key_salt` from the node seed) ‖ entry or element dot; a superset, rebuilt with the layout); table 2 a paged sequence's placement (layout: the comment above `Place` in `pages.rs`); table 3 an aspect's held writes (dated: from its first death; any: from its first expiring part) (`osis_crdt::Held`'s rows in pages, `P` + a page's first key cut to the key bound, `osis_crdt::PagedRows`; `retention::bounds::settle_index`): a function of its held valid bodies, built again from them when missing. Tables 1 and 2 are rebuildable: written with the layout, the unit tag naming their rules.
- Counters (memory overlay rows only, notes/engine-apply.md Counters), pending and parked commits, blob ciphertexts (pages, chunks, header-list trees).

## Index tables
Rebuildable `node/*` tables (`engine/index.rs`; Principle). The index check's rebuild must give every row: state a fast open needs is persisted in its own rows (the role walk excepted: The role walk, below).
- `node/metas`: per commit what this node judged of it, never what its header says: a byte per part (valid, the rotation role it needs, a grant's overreach, missing, whole, miskeyed) and, in a split commit, what is decided here of each thing's path (`View::paths`). Every input of a part's judgment that comes from its body is in the row, so a fast open judges a held part as the running node did; the rest of the `View` comes from the header (`View::of`), which an open decodes.
- `node/boxes to`, `node/epoch intro`, `node/keysets`, `node/delete hints`, `node/required`, `node/snapshots` (per aspect, with frontiers), `node/perm`, `node/refs to` and `node/refs from` (the reference index, notes/engine-refs.md).

## Open (`apply::load`)
- **Fast open** with an index of these rules (tag `i/v`: package version and the build script's hash of the engine's and its osis dependencies' sources, not sync's): reads the commit record heads and decodes each header (extent by `osis_base::item_prefix`, hash checked against the ID, `Header::decode_stored` skipping what was verified on arrival: delete-key point decompression, inline-list size re-encode; linked lists resolved from the record; no part decoded, nothing re-judged), the `node/metas` rows, the parts table and the derived index tables, perm's inputs from `node/perm` and the `account.0` states. `secrets.0` states are not read (epochs and own keys persist); `keys.0` states are read by neither open (observing one only ends delete hints, which a load reads from the index or not at all).
- **Rebuild** once, re-judging every delta and writing the index (`write_all`, index tables dropped shredded first), when the store is tagged with other rules, the index was invalidated (`index::invalidate`: tests' `rebuild_index`), or an index row fails to decode or is missing (`Engine::reload` retries as a rebuild). Damaged bytes never reach decoding: the store's AEAD makes them an open error (`Error::Store`). So a stored commit record decodes decode-only (`CommitBlob::decode_stored`: this node's canonical encoding, each part's delta kept as bytes), as stored states do; a parked row may hold a peer's bytes as received, so reexamining one uses `CommitBlob::decode` (`apply::read_pending`). It starts from the persisted `k/` epochs and reads every `secrets.0` state and pending commit's boxes again over them by the open's sweep (`flows::reopen_all`, the live node's own read path: notes/engine-roles.md Ingestion), only after the re-judge: a box gives a secret only where the node's roles do (`rotation::may_take_role`), and until the re-judge judges a removal's delete keys and re-derives its edge writes (`resolve_unresolved`) the removal removes nobody, so the node's own boxes on a thing it left would give back what it dropped.
- **`node/perm`**: per role commit (`Kind::is_role`), perm's reading of its held `roles.0` parts (`validity::PermParts`: each entry's dot, the holder its key names, the grant its value reads, as `edge_of` parses). A pure function of the commit record, written by `Tx::put_commit` whenever the record is written (first apply; late parts in `join_late`, passing `apply::PartsRead::perm` of what they applied: role-class parts join whole, so the record holds exactly those; `drop_part`; forget; same transaction and shred flag; `Tx::remove_commit` removes it shredded), all by `write_all`. Covered by the index's rules tag. The index check compares the rows with a rebuild's reading (`Core::rebuilt_perm`): one row per role commit, none other. Each row duplicates its commit's decoded `roles.0` values.
- Perm's held set (`engine/held.rs`) reads held commits only, the same reading as the row: `validity::add_role_commit` sets all it reads of a commit (edge writes, standing) from the parts held, replacing the earlier reading (late parts in any order, drops, destroys, a release's leftovers), and `apply::unindex` takes it all out with the record (`Held::remove`). A forgetting gives the timeline the change once after all its commits (`retention::forget`; `unindex_commit` per commit): each update replays the components touched, so once per commit would cost O(commits × component). Edge writes keep the depth filter where they are stored (`add_role_commit`): a record goes only with every part on its thing and once nothing minted below it is held (`retention::needed`), so that filter cannot go stale. The index check compares per thing its edge commits and record (`IndexDigest::held`).
- Perm's adaptation (`holder_keys`, unresolved removals) runs at every open over the rows, oldest first as a rebuild does. Role-class snapshots reach perm on a fast open as on apply. `Indexes::snapshots` keeps each aspect's held snapshot bodies in (`ts`, ID) order, so a fast open and a rebuild list them alike.
- **Headers**: `Meta::header` is the decoded header, kept in memory for the engine's life (readers outside a transaction have no store); `Meta::view` is what the per-commit indexes read of it with this node's decided paths. The view is the bulk of a header (its aspects), and every commit's view is needed at open, so a row holding it would be the header stored twice for no saving.
- **The role walk**: derived state, built at each open over a memory store (`MemStore`): an open touches every held commit, so the walk reads each one's reading (`validity::reading`) and its header (issues/perm-eval-cost.md).
- Test: the debug index check after sampled transactions (`Engine::check_index`, notes/test-harnesses.md Index check: an open and a rebuild equal the running node, each with the open's sweep `flows::reopen_all`, so a live index lacking what reading every `secrets.0` state and pending box whole gives fails there, not only after a restart); damage, crashes and restores in `caches::`.

## Open costs
An open restores the persisted index, re-judging nothing, but is O(commits): it reads every header and rebuilds the role walk from them (issues/perm-eval-cost.md, issues/long-aspect-cost.md).
