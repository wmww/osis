> Summary: Implement the local engine in `osis-node` without networking: node identity and local things, the HLC with corrected clock, turning local ops into signed commits (schema defaults, counters, dot form, paged deltas), receiving commits (signature, dedup, certificate chains via perm, pending reasons, parking, drift cap, atomic apply in one store transaction, membership before content, listeners after), per-delta validity and un-merge, retention bookkeeping (deaths, bounds, covered, keep-at-most drops), expiry, purge requests, compaction snapshots, undo, synthetic aspects, move/import, diagnostics, engine events. Defines the module layout the two other node plans fill.

## Deliverables
- Identity: node seed → key actor, node thing with `/created`, `/node`, `/keys`; creation of things (creation record, tid, owner); colliding record rule (keep held, diagnostic).
- Clock: HLC per spec/crdt.md §2.2 over `Clock` + offset from node-sync; `logical` is 16 bits, so a writer that exhausts it within one ms waits for the next; park commits more than `MAX_DRIFT` ahead and re-examine as time passes.
- Writing: a `Mutation` collects ops across things; resolve against local state (crdt ops, diff with the schema `View`), one delta per aspect, counters per (aspect, node) durable before signing, node or commit dot form, retention from schema defaults with overrides, expiry defaults, schema table, chunk list (plans/large-values.md plugs in), `CommitBuilder`; the acting actor's role on every touched thing checked via perm before signing (`Permission` error; `UnknownThing` when `/created` is not held), never emitted to be un-merged elsewhere; deltas page above `PAGE_TARGET` through the crdt `PageSink`; sign; apply locally (listeners fire for local writes too); hand to `labeling/` (a trait hook until node-sync lands).
- Receipt record: on every apply, record per (tid, ak, author node) the contiguous counter ranges received and the receipt time (plus commit-form IDs); snapshot frontiers add ranges (spec/crdt.md §8). It is a store unit with local granularity and horizon policy; demotions read it to build frontiers "as of T" (spec/permissions.md §5.1, plans/membership-flows.md). Pending and parked commits are not received.
- Receiving: `ingest(commit bytes, deltas...)`: signature, dedup by commit ID, prefix-vs-header check (when framed), delta hash check, range checks; pending reasons (chain certificates missing, `/created` unknown, parked part, drift, atomic apply waiting for deltas/pages); re-examination triggers (new certificates, start/stop syncing a thing, time); parked commits kept as bytes with header.
- Atomic apply: one `Store` transaction joining every readable delta of the commit, membership commits before content, engine events emitted after commit; per-delta validity from perm; invalid delta un-merged (re-join of held bodies via crdt, the current state counting as a held snapshot), later re-grant re-merges. Atomic apply waits only for deltas that belong under a label this node syncs (entitlement, spec/commits.md §4); a delta of an applied commit arriving later is joined on arrival.
- Retention: per body first/last death from the crdt change summary; keep-at-least/at-most bounds; `covered` by held snapshots (join-identity test on canonical bytes); keep-at-most drop in the killing transaction (at most 0) or at the bound; `nobody`/`admin`/`author`/`writer` rights via perm at request time; purge request application (value-less from then on, drop bodies incl. snapshots, re-snapshot trigger); expiry at T (value-less, drop body); snapshot production for an aspect (writer) with paging through store/large-values; delete-at-blind-node obligations recorded for node-sync (a queue of (label, blob, time) the sync layer executes).
- Undo: derived stack from the actor's own commits in scope; undo commits per crdt §4.6; undo buffer kept in the store unit; admin view of others' changes.
- Synthetic aspects `/tid`, `/aspects`, `/groups` (closure over `/group` writes, maintained incrementally), `/created` guaranteed.
- Move: import commit production (origins, re-sourcing through crdt), `/was` and `/moved` writes, the "do not import while holding a copy" guard; resolution view for reads (perm's rule) applied by the engine to values returned and to roster reads.
- Engine events channel (typed) and diagnostics (structured, deduped, rate-limited per peer); the `osis` API builds on these. Per applied commit: the `(tid, ak)` set whose read may have changed (from the crdt change summary), origin (local or remote), author actor and node, `ts`, receipt time, commit ID; plus roster changes, signals received, sync status changes (from node-sync) and diagnostics. Emitted after the store transaction is durable, outside engine locks.
- A `LocalPeer` test harness: two engines exchanging commit bytes directly (the simulator's seed; plans/sim.md grows it).
