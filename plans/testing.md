# Testing strategy
> Summary: How osis is tested from the start of the Rust implementation: models as oracles, conformance vectors, differential tests against the models, property tests and fuzzing per crate, a deterministic multi-node simulator with fault injection and adversaries, security and size regression tests, and a spec-to-test map. Starts as a plan; becomes notes/testing.md as the pieces land.
> Tags: tests

## Principles
- The spec is the oracle. Every MUST in spec/ has a test that would fail without it, and every test names the spec section it checks (in its name or a comment), so `grep` answers "what checks §X".
- Determinism everywhere: seeded randomness, simulated clocks, in-process transport. A failure is a seed, and a seed replays. No flaky tests; a flake is a bug.
- Untrusted input never panics: every decoder and message parser is fuzzed, and panics are failures (`panic = abort` in test profiles where practical).
- Models are independent re-derivations of the spec, kept small and slow; they are never the implementation and the implementation never depends on them.
- Code is cheap, attention is not: prefer many small automatic checks and seed replay over hand-written scenario suites that need reading.

## Layout
- `crates/`: the implementation (workspace). Unit and property tests inside each crate.
- `models/`: `crdt` (today `crdt-model/`), `membership` (today `tools/fixpoint/`), `tla/` (plans/tla-models.md). Moved, not rewritten.
- `vectors/`: language-neutral conformance vectors (CBOR or JSON files plus expected outputs) with a runner crate; shipped with the spec so other implementations can use them.
- `sim/`: the deterministic simulator crate and its scenario and invariant library.
- `fuzz/`: cargo-fuzz targets, with corpora committed.

## 1. Models (existing, refactored)
- **crdt model**: stays the reference for merge semantics. Add what notes/crdt.md lists as unmodeled where cheap (own-counter checks, strict rule 7 rejection) so differential tests cover them. Expose a library API (apply ops, join, read, encode) for the differential harness.
- **membership model**: refactor so the rule code mirrors spec/permissions.md section by section and can be audited against the prose; add counterexample traces with shrinking (minimal failing history printed as a scenario); add quiescence checks ("after all deliveries, every node agrees" as the standard property); expose the walk as a pure library function over a history for differential tests.
- **TLA+ / stateright**: plans/tla-models.md.
- Model findings flow to spec first, then to the implementation; a model is never patched to match the implementation.

## 2. Conformance vectors
From plans/protocol-spec.md: canonical CBOR of every value type, tid derivation, every key derivation (`kdf`, `derive_key`, `keyed_hash`, label keys, token secrets per level, commitments), sealed boxes and wraps (known-answer tests with fixed randomness), commit headers and signatures, blob prefixes and padding, chunking (gear table on fixed inputs), delta encodings per merge encoding (including every rule 7 rejection as a negative vector), snapshots with frontiers, inbox blobs, registration steps and claim sets, signals, bundles. Each vector: input, expected bytes, expected decode, or expected rejection with the rule. Generated by the implementation once reviewed against the model where one exists, then frozen; a change to a frozen vector is a format change.

## 3. Differential tests (implementation vs model)
- CRDT: random op sequences from the model's generator applied to both; equal reads, equal canonical bytes, equal results under random delivery orders, duplication, snapshots and expiry stripping. Run on every commit at modest size, nightly at large size.
- Membership: random histories from the membership model applied to the implementation's timeline; equal rosters, equal validity per write, equal effect of roster snapshots and projections.
- Decoders: model decoder and implementation decoder agree on accept/reject for random and mutated inputs.

## 4. Per-crate property tests and fuzzing
- proptest in every crate for its algebra: join laws, encode/decode round trips, canonical form, diff/read identities, HLC monotonicity under skew, retention arithmetic, paging (every page fits `PAGE_TARGET`, pages re-join to the state).
- cargo-fuzz targets for every parser of bytes that can arrive from a peer: CBOR, blob prefix, commit header, delta, snapshot page, sync messages, bundle, inbox blob, link and card formats. Corpora seeded from vectors. Runs nightly; crashes become regression tests.
- Crypto: known-answer tests from the primitive crates' vectors plus ours; test that each domain string is distinct and used once; a test that every signature verifies only under its own domain.

## 5. Deterministic simulation (the main tool once nodes exist)
A simulator runs real node code with: an in-process transport, a simulated clock per node with configurable skew and drift, a seeded scheduler choosing which node acts, and fault injection: partitions, drops, reorders, duplicates, delays, crash and restart mid-write (storage must recover), disk loss (reinstall from card), blind servers that go away or lose data. Blind servers are real server code. The harness is built before networking, as soon as two nodes can exchange commits in memory.
- **Invariants** checked after every step or at quiescence: all honest nodes with the same readable set read the same values; an un-authorized write is never read as valid on any node; a departed member holds no secret of a post-departure epoch and can decrypt no later body; label required sets hold at servers; purged bodies are absent from every reachable honest node and server once right holders synced; state size bounded per the tension-14 rules; no ping-pong (bounded uploads per quiescent period); every current member eventually reads (liveness by quiescence).
- **Scenario library**: the reference scenarios from notes (revocation scenario with Bob, Carol variant; stolen device backdating; demotion without syncing below with and without pre-sync; link redemption races; move with import; rotation during offline spans; re-seal of stranded member; chat pattern join/leave; folder patterns). Each scenario is also a seed family for randomized exploration around it.
- **Adversaries** as node implementations in the same harness: equivocating writer, backdating ex-member, flooding depositor, malformed-blob sender, replaying server, server that lies about tombstones, colluding ex-member plus dishonest server (checks tension 7's bound and nothing more leaks). Each has an expected outcome: fails, bounded, or accepted-by-tension.
- **Version skew**: old and new format versions and schema revisions mixed in one run (notes/versioning.md); the parking rule holds, an old writer never destroys what it cannot read.
- Nightly runs with many seeds; failing seeds are committed as regression tests with a one-line description.

## 6. Security tests beyond the simulator
- Negative tests per permission rule: every "MUST NOT be able to" in spec/permissions.md and spec/sync.md as a test where an actor tries it and fails.
- Metadata tests: blind-node view checks (a server sees only what spec/sync.md says it sees; blob sizes padded; no author linkage across labels without the read key).
- Dependency and unsafe policy: `cargo deny`, `unsafe` forbidden outside named crypto bindings, `cargo audit` in CI.
- A review pass per subsystem by a fresh agent with the attack list in notes as a checklist, before each milestone.

## 7. Size and performance regression
- Byte budgets as tests: commit for a small edit, removal from an N-member roster, roster snapshot of N, revoke frontier after a long tenure, text of M characters after K edits (crdt-model's `text_bench` becomes a tracked bench). Fail on regression beyond a margin.
- Benches with criterion for join, read, encode, page, sync reconciliation; tracked over time, not gated.

## 8. API and app level
- The Rust API tested through small example apps in the repo (notes, chat per notes/chat.md, folder): end-to-end tests in the simulator, driving two or more app instances.
- GUI apps, when they exist, via the gui-testing skill for smoke tests only; logic stays testable below the GUI.

## 9. Infrastructure
- CI on every commit: unit, property (small), differential (small), vectors, smallest TLA+ instances, clippy, deny. Nightly: large property runs, fuzzing, simulator seed sweeps, big model instances. Everything headless.
- A spec-to-test map in notes/testing.md generated by grep over section tags; gaps listed and treated like issues.
- Coverage measured but not gated; it finds untested branches of decoders.

## Order of work
Superseded by plans/mvp_meta.md §7; the infrastructure items are plans/test-infra.md and plans/sim.md, the per-crate items live in each crate's plan. Kept for reference:
1. Workspace layout; move the models; vectors runner with the first vectors (CBOR, tids, kdf).
2. CRDT crate with differential tests against the model from the first commit.
3. Simulator skeleton with in-process transport as soon as commits exist; invariants grow with features.
4. Fuzz target per parser as it lands.
5. Membership model refactor and differential tests when the timeline is implemented.
6. TLA+ models in parallel (plans/tla-models.md).
7. Adversaries and version skew once sync and rotation exist.

## Done when
Each layer above exists and runs in CI or nightly, and notes/testing.md describes what each covers, how to run it and what it does not cover. Then delete this plan.
