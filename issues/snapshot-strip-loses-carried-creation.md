# A snapshot's carried entry creation is lost when its copies are stripped
> Summary: Joining a snapshot strips its copies of held deltas' writes (`strip_held_copies`); when that leaves a map entry with only the creation stamp of a never-held writer, the entry is pruned and the creation never reaches the state, so the state's canonical form depends on arrival order (reads agree).
> Tags: node, crdt

Repro (same on main): `OSIS_ORDER_SEED=9129 cargo test --workspace --test it order::arrival_order_exhaustive_large -- --ignored`, shrunk: `vec![Edge { by: 0, t: 1, member: 2, role: None }, Write { by: 0, t: 0, op: 19, k: 0, v: 4 }, Write { by: 0, t: 0, op: 19, k: 0, v: 7 }, Write { by: 0, t: 1, op: 19, k: 1, v: 3 }, Edge { by: 0, t: 0, member: 2, role: Some(Write) }, Compact { by: 0, t: 0, op: 19 }]`, held set without W1 (the put creating `k0`). W2 writes `k0`'s value inside W1's entry; snapshot S carries the entry with W1's `created` and W2's value. W2 then S: S's copy of W2's value is stripped (W2 held), the entry is left with only `created`, and it goes (a creation stamp lives only with content, `prune_entry`): the state has no `created` for `k0`. S then W2: S joins whole, `created` stays. Same mechanism as issues/deaths-carried-creation.md case 1 (there in a recompute).

Also order alike seed 12209 (range 12000+300, `OSIS_ORDER_START=12000 OSIS_ORDER_SEEDS=300`, shrinks to about 30 steps): the as-made order holds the writer's later value write (W2) before the valid snapshot carrying the entries' creations, so the creations go; a shuffled order holds the snapshot first and keeps them. Fails `alike` on states (`created` only), reopen and rebuild alike.
