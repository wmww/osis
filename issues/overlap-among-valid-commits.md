# A holder of a signer's key can void that signer's honest writes
> Summary: spec/commits.md §4 voids both commits of one session whose counter ranges on an aspect overlap, counting every held commit, so a holder of a key with no standing (a removed or stolen key) voids that key's honest writes whose session it knows. Counting only otherwise valid commits was tried and fails (held-model `overlap`); the hole stays.
> Priority: low
> Tags: engine, perm

- **The rule**: judged from headers at apply (`apply/atomic.rs` `overlaps`), kept in `records::VOID`; a void commit's addenda vouch for nothing, its purge requests drop nothing. Role commits and snapshots are commit form, so never void. A stranger cannot do it (the session names the author and the signature binds it). notes/account-membership-design.md §2 step 7: a removed node's unlisted write on counters its pre-theft write used voids the listed write too.
- **Rejected: overlap among otherwise valid commits only** (core/test/held-model `overlap`, `tests/it/props_overlap.rs`). Validity then reads validity: a void commit's addenda, setting and purge requests are inputs of other rules, and held sets exist with no consistent verdict (`liar_setting`, `liar_addenda`); it is well-founded only as a last layer no rule reads (a carve-out) or with every rule input moved to commit form. And a shared dot has no owner: a valid and a junk write claiming one dot make un-merge attribute by the order of the ranges (`shared_dot_has_no_owner`).
- **A direction, not designed**: make reuse impossible rather than judged (a removal ends the removed signer's named sessions at their last counters, or session counters bound to a signed chain), so no dot is claimed twice by a commit any reader keeps.
