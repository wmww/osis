# An ended first admin's keep is decided per node
> Summary: `retention/end.rs` keeps an ended thing's record and edges only where a dependent is held at the ending; a node holding none drops its edges (and deletes them at hosts), so a dependent arriving there later is judged without them: rosters diverge, and a node joining later does not read the dependent at all. Repro: `ending::repro_ended_first_admin_edges_lost_where_no_dependent_was_held`.
> Priority: critical
> Tags: engine, node-sync, permissions

- Case: t (first admin g) expires; b is admin of x (first admin t) only by an edge on t, and grants on x. c held t but not x at the expiry: it keeps nothing of t, edges included. Once x reaches c (t's record comes raw from g's label), c's roster of x lacks b's grant that a and b show. The same held commits at a and b give another verdict than c's held set: c's no longer holds t's edge commit, and nothing fetches it again.
- A node granted g afterwards does not read x at all in the same case (it does when t has no edges: `ending::a_node_joining_after_a_first_admin_ended_reads_its_dependents_spec_commits_5`). Cause not split out: t's own secrets (no rotation boxes an ended thing's to a newcomer), or c's deletes at the host of t's edge commit.
- The rule "keep while a dependent is held" makes a node's held set depend on arrival order, and an ending's deletes at hosts are everyone's. Directions: keep an ended thing's record and `roles.0` whenever its record names a first admin and it may have dependents anywhere (every Thing record: the cost is one record and its edges per ended thing, growth row 5), dropping them only by a rule every node computes alike; or have the ending never delete `roles.0` bodies at hosts, fetching them again when a dependent arrives (an ended thing's `roles.0` parts are already taken while its record is held). Needs a decision before expiry-8 merges.
