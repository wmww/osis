# Deaths replays left O(aspect history)
> Summary: A late writer delta replays only the window it can change (`retention/deaths.rs` `window`), skipping snapshots that can date none of its writes, but validity flips, a snapshot or import arriving, or one judged or dying after the late `ts` still replay every held body and the whole state; the window spans every body from the first changed one to its latest death.
> Tags: node, retention, performance

Repro: `cargo test --release --workspace --test it scale::late_delta_deaths_cost -- --ignored --nocapture` (`OSIS_SCALE_N`), alone after `free -g`.

Measured (N = 10^4, release): keep-at-least, a late delta 380 -> 6 ms (load 30-50; 1.3 ms at load 9-22), 5 in a batch 380 -> 35 ms (6 ms at 9-22); compacted after the N commits, a late delta 170-240 ms (load 30-58) -> 6-8 ms (load 9-22), 5 in a batch 210-290 -> 12 ms; notes/node.md, Deaths.

Left:
- Whole replay (O(held bodies + residues + state)): any validity flip on a bounded aspect, a snapshot or import arriving, a snapshot or import among the judged bodies, or one at or after the window's start with a death after the first late `ts`.
- A window that must play a snapshot (it may carry a copy stamped at or after the window's start whose own commit is not held and has no residue, `playing_copies`) or an import reads and plays all its copies (O(compacted state)); one meeting a dropped body without a residue joins the whole state (O(state); common on keep-at-most aspects, cheap there). Deciding the skip scans the aspect's bodies from the window's start to the last snapshot in memory (a residue read per dropped one up to the first without one): O(bodies), about 3 ms per window at 10^4.
- The window spans from the first changed body to its latest death: a late delta superseding a write that lived long (a map key written once and overwritten much later) replays every body in between. Skipping the bodies between that touch no judged write's position is not possible exactly from what is held: a body supersedes a judged write only with a record at or above its position (a field, case, entry dot or element dot path), and neither the death records (first and last per body, no per-write death) nor any index says which positions a body holds records at, so each must be read to find out. Exact design: a rebuildable per-aspect index from position (step path) to the held bodies and residues holding a write there (O(writes) store, written at apply and drop); the window would collect the judged writes' positions and their ancestors and play, in `(ts, ID)` order, only the bodies the index lists at those positions (plus root resets), with snapshots restricted the same way. Not built.
