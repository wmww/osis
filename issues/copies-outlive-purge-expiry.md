# A body's copy of another write's value outlives that write's purge or expiry
> Summary: A delta body may carry a copy of another delta's value under the original's dot (an undelete's char; a map entry's key, repeated by every edit into the entry). When the original expires or is purged only its own body (and snapshots) are stripped, so the copy stays on disk and syncs to peers. Recommended: one invariant (no held body carries a value of a value-less write), checked in the one rebuild walk; a leftover strips every value it carries; a copy of an expiring value MUST expire no later. Seeds 9220029, 7520036, 9250009.
> Tags: security, engine, crdt, retention

## Study

### 1. Bodies carrying another write's value
Two classes.

**Under the original's dot** (attributed to the original's delta, spec/crdt.md §4.7):
- **Snapshot copies** (§8): handled (item 274, stripped/leftover snapshots).
- **An undelete's char** (`FlagW` string, §3.2, §5.7): from an undo of a text delete or a plain `undelete(dots)` (clipboard). Spec: "goes wherever that value goes".
- **A map entry's key, repeated by every edit into the entry** (§5.6: records are `(dot, key)`; a put or path op writes into the lowest live keyed record, `Eid { dot, key }` in `batch.rs`). Not named anywhere as a copy; same hazard: a reaction or edit into an expiring or purged entry keeps the key (app data) in its own body. §4.7 "Writes into an expiring element" only says the writer SHOULD expire it no later.
- `Derived` embedded chars (§7) belong to the register write's own delta: no foreign copy.

**Under the copier's own dots** (undo restores, §4.6): a previous register value, a set/bag/map re-add, a list re-insert, a re-inserted fragment. These are the undo's own writes. Expiry is covered (the undo expires at the earliest T it copies; its leftover strips its own values). Purge is covered only for an undo written after its node held the request; an undo concurrent with the purge keeps the value under its own dots, and the purge (one edit) never reaches it. Requirements-level: notes/questions-for-tess.md §4.

**Does a reader that lacks the original see the copy?** Yes, by design: §5.7 "so readers that lack it recover it"; a map record without its creation is not live, but its key is still in the body on disk. A node holding the original's header strips on arrival (§4.7 "strips the value from any copy that arrives later"; `drop_gone` only checks a part's own writes, so this is also an implementation gap). A node without the header (joined after T, when hosts dropped the original's blobs, or after `ROLE_KEEP` for a purge request) reads the undelete's char for good unless the copier's body itself expires.

**Spec today:** purge already says the right thing (spec/commits.md §5: "holds every body carrying their values, snapshots included, as its leftover"); the engine does it for snapshots only. Expiry does not: spec/commits.md §6 and crdt §4.7 make only the delta's own body a leftover, and a leftover is "the same delta with every value-carrying write value-less", read by the engine as its own writes only.

### 2. Candidates
- **(a) A copy inherits the original's lifetime.** Writer side: a delta carrying a copy of an expiring value (undelete char, repeated key) expires no later than it, in its own commit if needed (one expiry per commit; undo already does this). This is the only rule that protects a node without the original's header, and it makes held copies harmless for expiry: by the original's T the copier is a leftover, provided a leftover strips every value it carries (the seed's actual bug). Cannot help purge (the purge comes after). "A purge naming the original also names its copies" needs the copier set, which is (b) or (c).
- **(b) Index copied dot to copier bodies.** A persistent index kept in step with drops, leftovers, falls and re-arrivals. A cache with its own windows; rejected.
- **(c) Check held bodies at each value-less event.** Every expiry and purge already rebuilds the aspect from every held body (`rebuilt`, item 274's one path). The walk can report bodies carrying a value under a dot on the value-less list; those become leftovers stripped of it, then one more rebuild. Nearly free when none is found; purge's separate snapshot loop (`drop_carrying`, `drop_purged_snapshot`) folds into it. On arrival, `drop_gone` checks every carried dot, not just own writes. Falls: a stripped body (any kind) is asked for again, as snapshots are now.
- **(d) Forbid carried copies.** Undelete without a char breaks undoing an old text delete once compaction dropped the original: snapshots do not carry deleted elements' chars (§3.2 Content), so nobody has the char and the flag revives nothing. Undelete as a list-style re-insert with fresh dots changes text identity: marks, cursors and concurrent inserts anchored at the old dots no longer attach to the restored text, and it moves the case into the own-dot class (purge gap above). Keys cannot be dropped from entry edits without readdressing map records. Rejected.

### 3. Recommendation: (c) with (a)'s writer rule
One invariant for expiry, purge and snapshots alike: **no held body carries the value of a write the node holds value-less**; such a body is held as its leftover with that value stripped. Enforced at the two places it can break: when the value-less list grows (the rebuild walk) and when a body arrives (join). A delta's own leftover strips every value it carries, own or copied. Writer rule: a copy of an expiring value expires no later than the original (MUST), so nodes without the original's header are safe and hosts drop it at T.

Spec changes (no spec/requirements.md change):
- crdt §4.7: name copies under another dot (an undelete's char, a map key an entry's record repeats) as going with the value; a leftover is the body with every value it carries value-less; the expiry rule holds every held body carrying a copy of the delta's values as its leftover (as purge does); "Writes into an expiring element": a delta carrying a copy of its value MUST expire no later than T (the rest stays SHOULD).
- commits.md §5 Purge: "every body carrying their values" names deltas carrying copies too. permissions.md §7: "a held body stripped for carrying a purged value" (not only snapshots) is asked for again on a fall.
- The concurrent-undo-before-purge case (own-dot copies) is a requirements limit: notes/questions-for-tess.md §4.
