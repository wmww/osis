# Evaluating the role timeline: what is still not incremental
> Summary: Appending to a group's role history costs about a quarter of a millisecond at 10^4 role writes; a late write in the middle is placed without a re-walk unless something forces one (2-5 ms when nothing later reads it; 0.1-0.3 s when over a hundred later items must be re-judged, about what a re-walk costs); new holders and things named before their `created.0` join by going on from where the walk meets them. Still costly: the late writes that must re-walk, re-judging many dependents, and demotion frontiers that grow with the remover's chain.
> Priority: low
> Tags: permissions, node, performance

Repro: `cargo test --release -p osis-perm --test it -- --ignored --nocapture bench::` (`OSIS_BENCH_N=<n>` runs one size, for `valgrind --tool=callgrind`, not installed on every box; `perf` has no event access on the dev box; `bench_deltas`, `bench_late_write`, `bench_certificates` time one thing each); node: `cargo test --release -p osis-node --test it -- --ignored --nocapture scale::role_change_and_open_cost`. Run the bench alone: `bench_10k_edges` peaks at about 13 GB (each held set of the org at 10^4 is about 3 GB; parallel runs were OOM-killed silently).

Done: notes/permissions.md "Implementation" (`Timelines::append`, the found-order rule for D, placed late writes and joining nodes, shared kept states) and "Walk cost" (numbers).

Remaining, in order of expected payoff:
1. Late writes that still re-walk (`Walked::insert`, notes/permissions.md): one with a drop of D found at or after it (found by an earlier walk, whose state there is not kept); one a later item writes the same edge of (the later write's restore reads the new value; the difference runs along that edge's later writes, so exactness needs those re-judged with a changed edge record, untried); two ops on one edge; one whose own audit drops something new (D grows: unavoidable). A later item that does otherwise with it only moves the re-walk to that item. Re-judging costs about 0.5 ms per dependent item at 10^4 (they are the costly items to walk: mostly explicit writes on team edges whose audits read many nodes), so it pays only for few dependents; past an eighth of a long rest the write re-walks (`SHADOW_SHARE`). `bench_late_write` at 10^4 (release, shared box, load 7-32): a read grant nothing later reads 4.2-8.1 ms; a read grant by the key actor at the top (no earlier write of its own on the doc) 8.6-20 ms; a removal (an audit, 142 dependents), an admin grant (144) and a write grant on a team (472) 0.09-0.35 s (a re-walk: 0.14-0.65 s). In `bench_10k_edges` the late write in the middle (an admin's read grant on a doc it had not written yet) 0.05 s. Cheaper next: a narrower static dependence (most dependents are flagged because a node that may reach a holder of a team could be audited on what the new edge reaches; the dynamic reach check skips none of them in the bench), or re-judging only the audit pairs (x, n) the new edges touch. The plain placement is about 2.1 ms at 10^4 at low load: the later-item scan about 0.75 ms, the log splice about 0.55 ms (undo entries are 152 bytes; boxing the applied records would cut it a fifth), item and kept-state shifts about 0.35 ms.
2. A new node that is first admin of a thing walked before, or two components merging, still evaluate anew.
3. Walk residue from scratch: 1.39G instructions at 10^4 (callgrind, `--toggle-collect=osis_perm::walk::drive`) measured before the dense edge state (`graph::Dense`), which halved it at 3000 writes (178M); not profiled at 10^4 since. Certificates at 3000 writes 116M; admins' deltas at 10^4 3.5-6 ms (point overlays).
4. Demotion frontiers grow with the remover's chain (cost of carrying them: issues/frontier-certificate-cost.md) (spec/permissions.md §5.1): they list by commit ID (32 bytes each) every role commit among the remover's chain certificates, and, since role commits use commit form, every role commit of the demoted node it received on the things in scope; a long-serving admin's frontier can list thousands. Computing the list (`Timeline::certificates`) takes 7-12 ms at 10^4 (an evaluate 0.27 s). Role history is never compacted (spec/commits.md §5), so nothing bounds the list but the chain's history.
5. Compaction snapshots list every absorbed commit-form commit with its author (spec/crdt.md §8, 47 bytes each), so a `secrets.0` snapshot grows with the actor's rotation count.
