# Evaluating the membership timeline: what is still not incremental
> Summary: A from-scratch evaluation of a group's membership history now takes about half a second at 10^4 membership changes (was 4-7 s); a write after the others, a late write and a restart reuse the walk. Still costly: opening a node evaluates every group from scratch, a late write early in a long history re-walks most of it, a changed group's deltas are re-judged with nothing memoized, and point role queries copy the edge state.
> Tags: permissions, node, performance

Repro: `cargo test --release -p osis-perm --test bench -- --ignored --nocapture` (`OSIS_BENCH_N=<n>` runs one size, for `valgrind --tool=callgrind`; `perf` has no event access on the dev box).

Measured (org bench: 311 nodes, 221 things, 10^4 edge writes by 10 admins; 16-core box at load 10-25, so +-50%): from scratch 0.45-0.8 s (main: 4.5-5.1 s; this branch before the round 6.4-7.5 s), one more write 30 ms, a late write at the middle 0.36-0.6 s, a role query 0.3 ms, a role at a past point 0.25-0.45 ms, `delta_valid` cold 0.2-0.4 ms (1000 deltas cold 11 ms with the per-node end-role memo), owner chain depth 64 evaluate 1.3-2 ms. Done: notes/permissions.md "Walk cost".

Remaining, in order of expected payoff:
1. Open: `apply::load` evaluates every component from scratch (0.5 s per 10^4 edge writes in one component). Persist each component's walk (`Walked` with its undo log, D, epoch starts, `reach`) as a rebuildable store cache unit keyed by its exact inputs (notes/local-store.md), or accept the cost.
2. Late arrivals early in the history: `extend` re-walks everything after the earliest new commit, and falls back to from scratch when a non-final walk reached it (any earlier restart past that point, or epoch-start changes) or a new author/member appears (`nodes`). Exactness for the latter needs care (a new node changes `xs` in earlier audits).
3. Re-judging a changed component: the node re-judges every delta on its things with a fresh memo; `first_held` replays history with a forward search per change until the node holds the role (O(history x search) per (node, thing) cold), and a role at a past point clones a checkpoint edge state (O(edges)). Ideas: per-(node, thing) role step function computed by replaying only changes on paths into the thing; a `View` over a checkpoint plus a change overlay instead of a clone; carry memo answers over `extend` for deltas before the rollback point.
4. Walk residue (callgrind, 10^4): `View::standing` and `invite` in `audit_fall`'s full branch (X whose roles the restored edge raises: removing a team from a doc raises each team member), `reach_backward` per explicit write that restores, `Owners::chain` allocations.
5. Demotion frontiers grow with the remover's chain (spec/permissions.md §5.1): they list by commit ID (32 bytes each) every membership commit and roster snapshot among the remover's chain certificates, and, since membership commits use commit form, every membership commit of the demoted node it received on the things in scope; a long-serving admin's frontier can list thousands. Writing one runs `Timeline::certificates`: commits are now found through an index by (member, target) built once per timeline (was a scan of every held commit per chain point), and the closure takes points latest first, building the edge state when the point changes; what remains is that copy (O(edges)) per point change, which item 3's overlay view would remove (numbers: notes/permissions.md "Walk cost"). Idea for size: bound the listed chain by the newest roster snapshot (its ledger already vouches for what came before).
6. Compaction snapshots list every absorbed commit-form commit with its author (spec/crdt.md §8, 47 bytes each), so a `/secrets` snapshot grows with the actor's rotation count.
7. Chain certificates (`cert.rs`): adding the node's chain for the same thing at every later write that may demote it (§4; a static check, so dropped demotions count) made them about 4x slower: at 10^4, 0.56-0.59 s against 0.15 s before, 1.5-1.6x a from-scratch evaluate (0.37 s), same box at load 12. Computed once per demotion write the node places; the closure visits about 10x the states. Ideas: filter by reach at the demotion's point, or skip demotions the full timeline records as falls for the node.
