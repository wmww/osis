# A snapshot's last death may be dated early or missing
> Summary: Remaining ways a compaction snapshot's death can come out missing (so it is past a relative keep at least early): `Parts::carries` misses a kill whose superseder's body is dropped and that no held snapshot's frontier holds, and commit-form writes of imports this node does not hold are attributed to no snapshot.
> Tags: retention, crdt

Deaths are dated per node by joins (notes/node.md, Deaths dated per node). Fixed: a stripped entry's creation kept (`remove_writes`), commit-form and import writes attributed by `Absorbed` and to the import's own body, a superseder known through a held snapshot (`Parts::carries`). The dating oracle (retention.rs `deaths_never_early_random_*`) no longer accepts a snapshot death the recompute lacks (old case 3: it was a `Parts::carries` miss; 3000 seeds green).

1. `Parts::carries` with the superseder's own body not held and no held valid snapshot whose frontier holds it (the superseder dropped and every snapshot carrying it dropped, or it is commit-form: `seen` is node-form only) falls back to the state; when the superseder is itself dead there (a later write beat it), the state reports the write dead by the later one and the snapshot gets no death from it. Shape: S (bounded, `ts` above K's, frontier lacks K) carries W; K kills W; K2 beats K; K's body and every snapshot carrying K dropped. A fix needs the kill without the superseder's content: e.g. keep, per dropped body, the stamps it superseded (cost: an index per dropped body).
2. A `Commit(C)` write is attributed to a snapshot whose `Absorbed` lists C or a held import of C; an import listed there whose header this node does not hold cannot be mapped to its origin, so that snapshot gets no death from the write. Likewise `replay_all` removes a snapshot's copies only of writes whose dot maps to a held part (`commit_of`), which an import's never does (dot names the origin); the replay's dedup of dead stamps keeps the dates right in the tests so far.
