# Gone writes: what is left of the rewrite
> Summary: spec/crdt.md §4.7 (an expired or purged write has no effect on the read) is built in osis-crdt, crdt-model and the engine (engine green, expiry in place); left: listing a purged part (Tess deciding), osis-sync blob rewrite and the suspect fixture, register/case `Option` values, engine wording, Tess's call on a requirements line.
> Priority: normal
> Tags: crdt, engine

Built: a gone delta's writes are removed from each body before it joins (`Fragment::remove_gone`, crdt-model `Frag::remove_gone`); a gone delta left with no write is dropped (`DropFor::Other`), as is an expiring snapshot at its T, so no leftover row is kept for either; a purged whole replace is no own replace (what it covered is missing again); no wire form or state of osis-crdt or crdt-model holds a value-less `W`, list creation, register or case write (decoders reject them).

Left:
- **Listing a purged part** (osis `commits::purged_part_lists_until_its_expiry_spec_commits_7`, `edits::{a_listener_hears_an_edit_once_under_the_fire,a_purge_of_a_fire_takes_its_versions}_spec_commits_5`, `listing::{a_purge_lists_no_part_that_had_left_the_listing_spec_commits_7,purge_commit_is_delete_for_everyone_spec_commits_5,purge_takes_no_setting_expiry_spec_commits_5}`). Two causes:
  - A commit kept only for its purged parts is forgettable at once (`Engine::forgettable` via `kept_purged`), so its header goes before the listing rule is asked: the three FOREVER-history tests list nothing. Forgetting changes the commit listing, a read: it must wait until no part is listed (spec/commits.md §7 Listed parts), and sync must re-judge it when that window ends (no wake does today).
  - "Its writes, but for the purge, would be in the aspect's current state" (spec/commits.md §7) cannot be judged from what a node holds once the purged body is removed: the header gives the dots, not the positions, and a write after the purge may be what would have replaced it. Judging once at the purge depends on arrival order (a replacement before or after the purge). Options for Mizzen/Tess: (a) keep each purged part's write skeleton (positions by field and dot, stamps; no values or keys: `osis_crdt::Winners`) durably while it may be listed, judged against the held writes and the other skeletons (exact, a function of the held commits; set value removals' hiding needs a value-free form); (b) restate the listing rule to what headers decide (listed while a body replaced at its own `ts` would be in history), which drops the "live with no history" tombstone the API promises (notes/api.md Commits, delete for everyone).
- **osis-sync** `deletes::a_purge_of_one_part_rewrites_the_blob_everywhere_spec_sync_judgement_2`: after the purge of one part, no node (not even readers 0 and 2) logs any blob of the two-part commit: the rewrite without the purged part is never logged. The part now drops (`DropFor::Other`) where it was held as a leftover; both forms are `Meta::body_gone`, so the cause is elsewhere in sync's body judgement (`sync::bodies`), not found. Five `suspect::*_spec_sync_compaction_1`/`_spec_permissions_4`: their fixture (a paged whole replace with a page away, then its purge) no longer diverges (the purged writes have no effect at either node) and `strip_purged` raises no flag for it any more; they need a divergence a drop still leaves that a writer's snapshot repairs (node 1 lacking a value node 0's state holds, with no body left to fetch: e.g. a body node 1 dropped as covered by a snapshot that then turns invalid there while node 0 still holds it valid). Not built.
- **osis-crdt types**: `RegWrite::value` and `CaseWrite::case` are still `Option`, as are crdt-model's `Frag::Register`/`Enum` writes (only `None` from hand-built tests and `tests_join`); make them plain in both. Decide whether a keyless map record may carry a creation or a fragment (spec/crdt.md §3.2 `Entry` still allows the fragment); if not, reject on decode in both implementations.
- **Engine wording**: about a hundred comments still say "value-less" for what is now gone (removed) or a leftover's carried copies; `Hold::Leftover::valued` and `Meta::bare` name the old meaning.
- **Purge re-snapshot** (spec/commits.md §5 Purge, `purge::owe_resnapshot`): still needed. A node that dropped a body as covered under a snapshot carrying the purged write cannot bring back what the purged write replaced; a writer still holding the replaced body re-snapshots and so carries it to them. So the duty now serves "purging brings back what it replaced" at nodes that compacted.
- spec/requirements.md Decentralization's arrival-order limit for expiring edits no longer describes a divergence: Tess's call whether to drop it.
