# Gone writes: what is left of the rewrite
> Summary: spec/crdt.md §4.7 (an expired or purged write has no effect on the read) is built in osis-crdt, crdt-model, the engine and sync; left: listing a purged part (Tess deciding), whether suspect repair still has a purpose, keyless map records, snapshot `Carried` and held-model wording, Tess's call on a requirements line.
> Priority: normal
> Tags: crdt, engine

Built: a gone delta's writes are removed from each body before it joins (`Fragment::remove_gone`, crdt-model `Frag::remove_gone`); a gone delta left with no write is dropped (`DropFor::Other`), as is an expiring snapshot at its T, so no leftover row is kept for either; a purged whole replace is no own replace (what it covered is missing again); no wire form or state of osis-crdt or crdt-model holds a value-less `W`, list creation, register or case write (decoders reject them; register and case writes always hold their value). A body is purged for sync (must-not-hold) only when every part is; a purged part beside a live one strips and the rest is logged as the rewrite.

Left:
- **Listing a purged part** (osis `commits::purged_part_lists_until_its_expiry_spec_commits_7`, `edits::{a_listener_hears_an_edit_once_under_the_fire,a_purge_of_a_fire_takes_its_versions}_spec_commits_5`, `listing::{a_purge_lists_no_part_that_had_left_the_listing_spec_commits_7,purge_commit_is_delete_for_everyone_spec_commits_5,purge_takes_no_setting_expiry_spec_commits_5}`). Two causes:
  - A commit kept only for its purged parts is forgettable at once (`Engine::forgettable` via `kept_purged`), so its header goes before the listing rule is asked: the three FOREVER-history tests list nothing. Forgetting changes the commit listing, a read: it must wait until no part is listed (spec/commits.md §7 Listed parts), and sync must re-judge it when that window ends (no wake does today).
  - "Its writes, but for the purge, would be in the aspect's current state" (spec/commits.md §7) cannot be judged from what a node holds once the purged body is removed: the header gives the dots, not the positions, and a write after the purge may be what would have replaced it. Judging once at the purge depends on arrival order (a replacement before or after the purge). Options for Mizzen/Tess: (a) keep each purged part's write skeleton (positions by field and dot, stamps; no values or keys: `osis_crdt::Winners`) durably while it may be listed, judged against the held writes and the other skeletons (exact, a function of the held commits; set value removals' hiding needs a value-free form); (b) restate the listing rule to what headers decide (listed while a body replaced at its own `ts` would be in history), which drops the "live with no history" tombstone the API promises (notes/api.md Commits, delete for everyone).
- **Suspect repair has no case left**: under the gone-write rule no honest-use fixture leaves two co-readers apart for a writer's snapshot to mend (a dropped body is gone with no effect, carried by a held valid snapshot, or counts as never received and is fetched again; validity is a function of the held commits). osis-sync's suspect tests cover listing with flags raised by hand; the writer's repair (`Engine::repair_suspect`, spec/sync-compaction.md §1 Repair) has no end-to-end test. Mizzen/Tess: shrink flags, lists and repair to what still has a purpose (perhaps nothing: `Why::PendingExpiry` flags a part whose writes have no effect anywhere), or name the divergence they serve (fork sides were not examined).
- **Keyless map records**: decide whether a keyless map record may carry a creation or a fragment (spec/crdt.md §3.2 `Entry` still allows the fragment); if not, reject on decode in osis-crdt and crdt-model.
- **Wording left**: `retention::snapshot::Carried` (its `valued` spans, "value-less counters", `covered_join`) and the snapshot.rs comments around it still describe copies held without values; held-model (`model.rs` `valueless`, its leftover and snapshot rules) still models value-less writes. Both need their mechanism re-judged under §4.7, not a rename.
- **Purge re-snapshot** (spec/commits.md §5 Purge, `purge::owe_resnapshot`): still needed. A node that dropped a body as covered under a snapshot carrying the purged write cannot bring back what the purged write replaced; a writer still holding the replaced body re-snapshots and so carries it to them. So the duty now serves "purging brings back what it replaced" at nodes that compacted.
- spec/requirements.md Decentralization's arrival-order limit for expiring edits no longer describes a divergence: Tess's call whether to drop it.
