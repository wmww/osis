# Tier 1 is slow and partly opaque
> Summary: Tier-1 tests should be fast, readable and deterministic in what they check: cut the slow tail, replace pinned generator seeds with minimal hand-written reproducers (or delete them), and take the easy wins (shared setup, cheaper debug checks). Deleting and consolidating tests is in scope.
> Tags: tests

Goal: most tests in milliseconds, none over about a second, each one's scenario readable from its body. **Deleting tests that add little, are redundant with others, or test a seed rather than a rule is fully valid, as is merging near-duplicates.** A test earns its tier-1 cost by catching something no cheaper test catches (notes/testing.md "What finds bugs": tier 1 found about 2 of about 300 bugs).

## Measured (dev profile, every tier-1 binary run alone with `--report-time`, box load 20-40)
- CPU-s per binary at that load: osis-node `it` (`order::` included) about 1180, osis `it` about 710, osis-engine lib 220, osis-crdt lib 115, osis-sim `it` 110-130, osis-chat `it` 65-70, osis-perm `it` 50-57.
- Tests at 1 s or more, each alone (excluding `order::`, `deaths::`, `settled::`, retention, perm and first-admin tests): about 120, 390 CPU-s at load 17-25 (alone CPU-s run 1.5-2x a quiet box's). Slowest now (CPU-s alone at that load): osis `port_clients::client_session_differential_against_grants` 7, node `shred_sync::purged_synced_body_crash_safe_spec_commits_5` 7 (every crash point, a forensic attack each), node `wrap_poison::useless_entry_found_late_still_goes_spec_sync_7` 6.6 and `useless_mark_outlives_the_tombstone_lifetime_spec_sync_6` 5.4, sim `work_sets::work_sets_revocation_bob_seed_9461` 6.5 and `net::snapshot_rights` 6 (seven pinned seeds), proto `slow_link::bulk_over_slow_link_spec_sync_6` 5.6, chat `flows::new_node_of_a_participant_sees_history_spec_sync_6` 5, crdt proptests (`tests_seq::*_matches_model*`, `part_judges_as_whole_of_histories`) 4-5 each, node `encodings::big_list_insert_fits_blobs_spec_crdt_3_3` 4.9 (8 MiB of content), host `store::tests::ephemeral_churn_keeps_durable_cursors` 4.9, base `decode_peak_within_the_bound` 4.8 (a child process per shape), osis `write_ops::commit_equals_single_op_commits` 4.8, `tied::*` 3.5-4.5 each (about 20 of them), node `inbox_life::{pending,burst}_grants_*` 3.7-4.2 (past `INBOX_WAITING`, a format constant).
- Known costs inside: a body's must-hold is quadratic in its parts (issues/body-keep-quadratic.md); a paged text joins per element under the rebuild check (`validity::unmerge_paged_matches_fresh_spec_crdt_4_6`, tier 2).
- Whole-binary CPU of osis-node `it` (cpuprof, `order::` included, on a tree with the forensic attack at 17%): crypto 33% inclusive, `order::check_orders` 20%, `check_rebuilt` 13%, cbor 10%, allocation 20%. Toy crypto would gain at most about 1.5x: not the lever. A median test is a whole in-memory network: sync settling about 55-60%, group and peer setup 20-30%, apply about 20%.

## Work
1. **Slow tail.** For each tier-1 test over about 1 s (all crates; `RUSTC_BOOTSTRAP=1 <binary> -Z unstable-options --report-time`, notes/testing.md; judge by CPU-s alone): shrink it to its point, merge it into a sibling, move it to tier 2, or delete it. The list above is what is left; patterns that worked: fewer, larger elements where a size threshold is the point (`common::link_aspects`, 4-byte chars for text bytes), a config knob for a batch size (`SyncConfig::fill_batch`), one clock jump past a lifetime instead of a day at a time, a stride over exhaustive orders in tier 1 with the full set as a `#[ignore]` twin, cpuprof before guessing. Not touched: `order::`, retention, perm and first-admin tests (other work).
2. **Pinned generator seeds** (about 115 tier-1 tests run a random scenario generator at fixed seeds, e.g. `osis-engine` `rotation::tests::withheld_*`, 750 ms each). A seed's scenario drifts with every change to the generator or engine and nothing notices: `withheld_regrant_by_unaware_admin_spec_crypto_4` seed 9490147 no longer reaches the excused path its comment describes (282407 and 9490002 still do). Replace each with a minimal hand-written scenario of the bug it was pinned for (the steps in the test body, asserting the rule), or delete it where the rule is already covered. The generators stay as tier-2 explorers. The `withheld_departures` oracle's excuses (`invalid_raise`, `regranted`, `sharers`) each want a spec sentence or removal. Hand-made seed tests already exist in osis-node `pinned::`; issues/seed-pinned-bugs-without-test.md is one still missing.
3. **Easy wins.**
   - Shared fixtures: build the common starting network (group, peers, grants) once and clone it per test instead of every test signing and syncing it from scratch.
   - Test rules below the network: validity, retention and permission rules against the engine or perm layer directly; a full `Net` only where sync is the point.
   - `check_rebuilt` (13%): sample it more sparsely in tier 1, or keep it full only in tests of apply and validity, if that does not lose what it catches (it found bugs; measure before cutting).
   - The forensic attack (mostly trial decrypts): what is left per wrong candidate is a wrap's AEAD open per unopened section and blob; a test calling it per crash point (`purged_synced_body_crash_safe`) still costs seconds.
   - `order::` (20%): fewer random orders per held set where the exhaustive and fixed orders already cover it.
   - The debug re-decode on every `secrets_in` cache hit (22% of `osis` `it`, notes/testing.md): move it into `Engine::recheck`.
