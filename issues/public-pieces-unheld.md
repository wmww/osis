# Public pieces nobody reading T holds
> Summary: T's readers learn the public's grant on X (and its removal) only from the public pieces under T's sync ID, which only a node reading T that holds them logs. A node whose account reads X only by the public never receives the removal (it keeps reading X's last content forever), and an account holding X at sync only never learns X became public (it keeps X unread where the spec's unit reads it).
> Priority: normal
> Tags: sync, security

Repro: osis-sync `differential::repro_a_redeemer_learns_the_public_removed` (node 0 makes X public, node 1 of another account redeems a public link to it, node 0 removes the public and writes again; node 1 still reads the old value, roster showing the public at read, `Engine::public_reads` true).

Why: spec/sync-set.md §2 Public pieces has T's readers learn the removal from the public's edge piece on X carried under T's sync ID, "from what the logging node holds". T here is node 1's account A1: its only loggers are A1's nodes, which read X by the public alone. The removal itself is under X's sync ID, which node 1 synced by the public entry; the removal's step no longer lists the public entry, so no source opens X's sync ID toward node 1 any more (a public claim is shown only where the public reads S's thing, spec/sync-opens.md §4), and J judges node 1 unknown, not departed, so it is not moved past its keys either (§6). held-model `closure::public_epochs` passes because its logger of T holds everything (a writer of X among T's readers), which an account that only redeemed a public link never has.

What an ordinary removed holder gets instead: a removal from outside is delivered to H's inbox (spec/sync-inbox.md §5), and H's nodes are opened the target's sync ID no more (Departed). The public has no inbox. Candidate rule (one mechanism): the public's edge piece is delivered to whoever shows the public credential at S: a Hit on the public entry at a step past the head listing it is answered with the public's edge piece on S's thing (its removal, as certificate copies), as a sealed copy delivers an edge piece to a holder. Then the node holds the removal, the public's role on X ends there (spec/sync-set.md §2 Own things), and X leaves A1's unit as it does at X's writers. Model it first (`closure::public_epochs` with a T whose loggers read X only by the public).

**The grant, alike** (full-size differential, the largest class: "node N reads thing N unlike the reference", node value None, the reference's roster listing the public): account A1 holds X at sync (its nodes keep X unread) and strongs it; X's admin then grants the public read. By spec/sync-set.md §2 (T's keys open), X is in A1's unit, read. But a sync holder is sent X's role-class parts cut to its own pieces (sync copies), never the public's grant, and X's own entries are sealed under the read epoch it lacks: no node reading A1 holds X's public piece, none logs it, and A1's nodes never learn. held-model `closure::World::public` counts the public everywhere (the differential's model): to model the spec as written it needs carriers for public pieces, (t, x) logged only where a node reading t holds X's public piece otherwise (reads X, or redeemed it: the follow reads X's sync ID by the public entry), as `Net::logged` does for bridges and stubs. Either the model takes that (and the property is weaker than "a strong to a public thing brings it in"), or the public's edge piece also goes to X's sync holders (as a sync copy does), which the rule above for removals would share.

Seen on main in osis-sync `differential::histories_hold_their_closure_plain` (seed 65054997954: node 1 keeps thing 0 unread at sync, value none, where the reference's roster lists the public at read; tools/known_failures.txt).
