# Tests that pass or fail with the store's random draws
> Summary: Ten node and osis tests flip with how many random values the store draws per commit (the store shares its rng with record ids, nonces and the node log incarnation). On unchanged store code, 2 extra draws per store commit fail six of them, 7 fail a seventh; the store as built (a key tree as tall as its slots need draws fewer node keys) fails all ten. Each asserts an order, a pick or a count that random ids decide; one (the redeem) is a real flow failure.
> Priority: normal
> Tags: tests, sync, osis

Reproduce: add `for _ in 0..k { let _ = Secret32::random(rng); }` at the top of `Pager::commit_inner` and run them (k = 2 fails the first six).
- osis `disputes::disputes_listed_told_and_chosen_spec_permissions_5_1` (k=2): the told dispute is `(b, a, Author)`, not `(a, b, Holder)`; the setup orders b's removal first by going online first, but something orders by a random value.
- node `awaits::a_part_missing_again_is_fetched_under_every_label_spec_sync_6` (k=2): fresh blobs per label `[1, 1]`, not `[2, 2]`.
- node `ephemeral::restart_starts_a_new_session_spec_crdt_2_1` (k=2): sorts dots by session and expects the new session after the old one; sessions are random nonces.
- node `leaving::an_until_under_no_host_a_co_reader_past_its_own_until_refuses_nothing_spec_perm_2` (k=2).
- node `order::kill_and_purge_in_one_commit_keeps_leftover_spec_commits_5` (k=2): the leftover is dropped as covered.
- node `scale::validity_flip_is_linear_and_invalid_arrival_flat_spec_permissions_5_2` (k=2): 31 tags left, not 30.
- osis `sharing::redeem_after_a_joiner_left_spec_permissions_7` (k=7, and at the store's draws as built): a real flow failure, not an ordering assert. After two joiners left and K rotated twice, dave's redeem returns `Unsynced`: his node registers its path for g's label at the host, the host answers `NOT_HEAD` for every step (`open.rs`, Registering: "the peer holds it off the recorded path"), the label fails, every host has failed it, so it reads `stranded` and the redeem ends with `Unsynced`, which the API says means it can never finish. It does finish: a stranded report gets a re-seal, and the same redeem called again after the next resync returns g and reads the thing. Two faults: a fresh joiner's node holding a path the host does not (old open code, deleted in Phase 3), and `Stranded` set from one failed open that a resync retries. Phase 4 scenario (issues/sync-rewrite.md): a link redeemed after its key actor rotated twice (two joiners left) joins and reads on the first call, for every draw.
- node `unread::a_dialer_holding_only_the_public_sync_key_pulls_nothing_spec_sync_10` and `unread::a_node_holding_only_the_public_keys_finds_no_proof_in_a_readers_filter_spec_sync_10`: `dialing_node(false)` makes a second group that p reads, then `Net::label(a)` takes the first of a's labels by group tid, which may be that group's; the tests then check the wrong label.

- node property `validity::unmerge_paged_matches_fresh_large_spec_crdt_4_6` (deterministic, no seed; fails at the store's draws as built and at 1, 3, 5 extra draws, passes at 2 and 8): `rejudge: rebuild` counts 7, not one per flipped aspect (5). The re-judged set (`flipped`, core/engine/src/apply/validity.rs) holds two more aspects for some draws: an engine count, not old sync, so it outlives the rewrite; find which two aspects flip and whether that is right.

Each should pin what it means (the label of `g`, the session by identity, the removal by author) or the property should hold for every draw. All ten are listed in tools/known_failures.txt. All but the osis ones run on old node sync; check which shapes the rebuilt sync's tests keep before fixing here.
