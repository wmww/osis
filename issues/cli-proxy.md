# Client port: remote API over the sync connection (daemon, thin clients, per-group sources)
> Summary: Tracking issue for notes/client-port.md: the `osis` API usable from another process or device through new message kinds of the node-to-node protocol on the same connection as sync, served on node listeners only; three session tiers (Owner over the unix socket by peer uid, a scoped client actor signing its own commits, a scoped node-authored client); scope by kind with actors and secret-bearing things never in scope; per-group local/remote sources; the minimal query API; a no-store build profile; a client cache. Seven branches, each mergeable alone; (c2) and (f) carry owner decisions. Nothing built.
> Tags: api, cli, proto, node-sync, transport, security, design

Design: notes/client-port.md (decisions, wire, tiers, scope rules, stall and memory bounds, plan with files, tests, risks). Strike each branch when merged; move anything still useful into the note.

## Branches
- [ ] **(a) `handle-source`**: `Source::{Local}` behind every API method; `Write` records API ops, `Mutation` built at `commit`. Refactor, no behaviour change; property test op list -> same `Mutation`; measure the write path (`bench`, `scale::`).
- [ ] **(b) `client-port`**: proto kinds 24-29 (Auth, Call with `max_reply`, Reply with change seq, Sub/Unsub with reserved ids, Notify incl. `lapsed` and `changed_too_large`), `ServingOutput::Request`, `ServingInput::{Reply, Notify}`, client `Command::{Call, Sub, Unsub}`; node `Action::{Request, Room}`/`Event::{Reply, Notify}` (Notify batched per engine change), `Peer::{Key, Unix}` on connections, tier set at accept; `osis::port::{serve, client}` with the worker off the lock, dirty-flag subscriptions, `SIGNAL_BYTES`, `MAX_SUBS`; the Owner tier and its method rows; `unix://` transport (`SO_PEERCRED` both ways, socket under `$XDG_RUNTIME_DIR/osis/`, `<store>/sock` naming it); `serve` listens there; CLI falls back to it (locked and no live socket: exit 8); clients in their own `max_clients` pool, authenticated sessions count as opened. Spec: wire §11.1-§11.2, sync §10. Tests: proto round trips and id rules; osis tier 1 over `InProcess` (Owner through a fake `Peer::Unix`; a keyed peer never Owner; retry under a nonce applies once; no deadlock from `settle` in a remote callback; unauthenticated flood evicts no client); CLI tier 2 localhost. Measure: `get` round trip, watch latency, worst method row vs a Sync pass.
- [ ] **(c1) `client-cred`**: `clients.0^` on the node thing, `add_client`/`clients`/`remove_client` (node-authored first), Auth over canonical `[client_pk, challenge, static_key]` with a client session id, the `Scoped` view (inputs and outputs; out of scope reads `UnknownThing`; every method row declares its check), scope by kind (no `groups: all`, no home group, no actor or secret-bearing thing, Admin never on actor things), write scope (every named tid in scope, created things placed into scope in the batch) and undo scope (every `(tid, ak)` in scope), `WRITE_NONCES` per credential, `until` as an engine timer, re-check at execution, revocation closing sessions, `MAX_CONNS_PER_CLIENT`; CLI `clients`. Spec: data-model §9, crypto §2 domain. Tests: notes/client-port.md §3's list.
- [ ] **(c2) `client-actor`** (owner decision: whether a thin *device* mode is wanted besides): `author: own` as a key actor with edges on its scope groups; Sign `[id, call_id, header]`/Signed (proto requester and answering roles, `SMALL_REPLY`, `serve_open_ms` deadline), client checks every derivable header field and computes the commit ID, `MAX_PENDING_SIGN` 1, commit form now (session form after issues/session-sources.md step 2), thin `node()`, `remove_client` demoting. Tests: attribution and edge-bound validity at a third device; refused Signs (purge, extra aspect, other actor, no outstanding Call); bounded non-signer; demoted client's next Call fails.
- [ ] **(d) `group-sources`**: several attachments, `routes` (local wins; persisted app record, or `Config.remotes` without a store), `group_source(g, Local | Remote(node))` = sync/unsync plus the route, merged `status`, `Network` for a disconnected remote (no stale reads), the reconnect contract (Auth, schemas, Subs, Live again). CLI `group source`.
- [ ] **(e) `query-min`**: `query(in_group, with, order Time, page <= QUERY_PAGE) -> Live`, local scan over the group index, remote as a Sub (`MAX_QUERY_SUBS`); CLI `ls`. Measure N = 10^4 items against a Sync pass. (First item of issues/api-deferred.md; `backlinks` after.)
- [ ] **(f) `thin-profile`** (owner decision: a default `store` feature on `osis`, outside notes/architecture.md §4's networking-only rule): `--no-default-features` keeps base, crypto, crdt, schema, commit, proto, transport and `Remote`; `attach` without a database; a gate step `cargo check -p osis --no-default-features` when `osis` or its deps changed.
- [ ] **(g) `client-cache`**: cached values only for live-subscribed aspects, invalidated when the subscription lapses, never offline, no write-through; bounded by `materialize_limit`.
