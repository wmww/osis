# Client port: remote API over the sync connection (daemon, thin clients, per-group sources)
> Summary: Tracking issue for notes/client-port.md: the `osis` API usable from another process or device through new message kinds of the node-to-node protocol on the same connection as sync, served on node listeners only; three session tiers (Owner over the unix socket by peer uid, a scoped client actor signing its own commits, a scoped node-authored client); scope by kind with actors and secret-bearing things never in scope; per-group local/remote sources; the minimal query API; a no-store build profile; a client cache. Seven branches, each mergeable alone; (c2) and (f) carry owner decisions; review 2 (go for (b)) gates (c1)/(c2)/(e) and remote clients on items the note now settles. Nothing built.
> Tags: api, cli, proto, node-sync, transport, security, design

Design: notes/client-port.md (decisions, wire, tiers, scope rules, stall and memory bounds, plan with files, tests, risks). Strike each branch when merged; move anything still useful into the note.

Review gates (second review, items by its numbering; all settled in the note, the branch must build them): (b) settles N-S7 (nonces per (identity, session) under a node epoch), N-N2 (socket dir fallback, path sockets only) and the 0/∞ lines; (c1) and (c2) wait on N-B1a (the client signs its own creation + `keys.0` through Sign at first Auth), N-B1b/N-B2 (scope = owned by a scope group; key actors and the person excluded by record), N-B1c (`aspects` refused with `own`; Admin for a client actor stated), N-B1e (`pk` in node-authored records); (c2) also on N-S1 (`ts`, inline lists, delete keys as stated node trust) and N-S1b (no Sign deadline); (e) on N-B5 (dirty by group, incremental page); remote clients ship only with N-B4 (a client listener key that does not rotate with reach, in (d)).

- [ ] **(c1) `client-cred`** (after N-B1b/N-B1e/N-B2): `clients.0^` on the node thing with `pk`, `add_client`/`clients`/`remove_client` (node-authored first), Auth over canonical `[client_pk, challenge, static_key]` with a client session id, the `Scoped` view (inputs and outputs; out of scope reads `UnknownThing`; every method row declares its check), scope = owned by a scope group (no `groups: all`, no home group, key actors and the person excluded by record, Admin never on actor things), write scope (every named tid in scope, a created thing's owner in scope and never the client actor) and undo scope (every `(tid, ak)` in scope), `WRITE_NONCES` per credential, `until` as an engine timer, re-check at execution, revocation closing sessions, `MAX_CONNS_PER_CLIENT`; CLI `clients`.
