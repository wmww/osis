# Client port: remote API over the sync connection (daemon, thin clients, per-group sources)
> Summary: Tracking issue for notes/client-port.md: the `osis` API usable from another process or device through new message kinds of the node-to-node protocol on the same connection as sync; the daemon case (CLI through `<store>/sock` while `serve` runs, which ends "one process per store"); credentials issued by the node's owner; client-signed authorship; per-group local/remote sources; the minimal query API; a no-store build profile; a client cache. Seven branches, each mergeable alone; (c2) and (f) need owner decisions. Nothing built.
> Tags: api, cli, proto, node-sync, transport, security, design

Design: notes/client-port.md (decisions, wire, credentials, authorship, plan with files, tests, risks). This issue tracks the branches; strike each when merged and move anything still useful into the note.

## Branches
- [ ] **(a) `handle-source`**: `Source::{Local}` behind every API method; `Write` records API ops, `Mutation` built at `commit`. Refactor, no behaviour change; property test op list -> same `Mutation`; measure the write path (`bench`, `scale::`).
- [ ] **(b) `client-port`**: proto kinds 24-29 (Auth, Call, Reply, Sub, Unsub, Notify), `ServingOutput::Request`, `ServingInput::{Reply, Notify}`, client `Command::{Call, Sub, Unsub}`; node `Action::Request`/`Event::Reply`; `osis::port::{serve, client}` (requests run off the handle lock); `Remote` source for one attachment (scope all, author node); `unix://` transport with uid-derived peer keys; `serve` listens on `<store>/sock`; CLI falls back to the socket when the store is locked (locked and no live socket: still exit 8). Spec: wire §11.2. Tests: proto round trips; osis tier 1 over `InProcess` (two handles, one attached); CLI tier 2 localhost (`watch` running while `create`/`get` go through the socket; another uid refused).
- [ ] **(c1) `client-cred`**: `clients.0^` on the node thing, `add_client`/`clients`/`remove_client`, Auth signature over challenge and static key, scope `{groups, aspects, role}` enforced before every call and on every Notify, revocation closes sessions; CLI `clients`. Spec: data-model §9, sync §10. Tests: out-of-scope refused, narrowed scope drops subscriptions, expiry closes, the node thing never in scope.
- [ ] **(c2) `client-sign`** (owner decision: `add_client(.., author: own)` writes the device grant for a storeless client): Sign/Signed, `MAX_PENDING_SIGN`, client-signed commit-form headers (session form once issues/session-sources.md step 2 lands), thin `node()`. Tests: attribution at a third device; a non-signing client is bounded; a bad signature applies nothing.
- [ ] **(d) `group-sources`**: several attachments, `routes` (local wins; persisted app record, or `Config.remotes` without a store), `group_source(g, Local | Remote(node))` = sync/unsync plus the route, merged `status`, `Network` for a disconnected remote (no stale reads). CLI `group source`.
- [ ] **(e) `query-min`**: `query(in_group, with, order Time, page) -> Live`, local scan over the group index, remote as a Sub; CLI `ls`. Measure N = 10^4 items. (Closes the first item of issues/api-deferred.md; `backlinks` after.)
- [ ] **(f) `thin-profile`** (owner decision: a default `store` feature on `osis`, outside notes/architecture.md §4's networking-only rule): `--no-default-features` keeps base, crypto, schema, proto, transport and `Remote`; `attach` without a database; a gate step `cargo check -p osis --no-default-features` when `osis` or its deps changed.
- [ ] **(g) `client-cache`**: cached values only for live-subscribed aspects, invalidated when the subscription lapses, never offline, no write-through; bounded by `materialize_limit`.
