# Expired ephemeral writes leave anchors that fill a holder's cap
> Summary: An expired ephemeral list element or fresh map entry stays in the aspect's state as a value-less record (about 575 B decoded, charged about 1.15 KB at holders), never collected, so an ephemeral event list or per-message map hits the 16 MiB node cap after about 14,000 expired elements over its lifetime; the lattice needs the records, so an O(live) fix changes a convergence limit (Tess) and a smaller form keeps the growth.
> Priority: normal
> Tags: ephemeral, crdt, node, tess-call

Follows from the principle (notes/ephemeral.md: durable semantics held in memory): expiry keeps the writes value-less and a snapshot carries them (spec/crdt.md §4.7, §8). Durable state keeps the same records at 3-4 B each, run-compressed (notes/growth.md). In memory the state is held decoded (`Core::states`): a value-less list record is a whole `SeqElem` (inline sources, `pos` vector, content fragment), about 575 B by `Fragment::approx_bytes`, charged twice (`Engine::memory_charge`, `memory::eph_leftover_memory`). Per key, a value kept alive leaves one record per key ever used; per write, list elements and map entries at fresh keys leave one each. A restart frees nothing while another holder serves the snapshot back.

## What the value-less record is for
- **Placement.** Every append anchors at the element before it. Dropping an expired record puts the live elements anchored at it on `END`, ordered by the anchor's dot (source bytes), not by the tree: with two concurrent appenders an expiry reorders live elements (e ← b newer, e ← a, a ← c reads `e b a c`; once e and a expire, `b c` can read `c b`). So expiry dropping the creation outright (as for an embedded char) is out.
- **Late writes.** An insert anchored at it or a write into it (a reaction to an expired message: spec/requirements.md Data model, an expired write takes only its own content) may arrive any time later, and must place and show as at a node that kept the record.
- **No lattice rule collects it.** A rule over the state's shape ("all writes value-less, nothing anchors at it") does not commute with join: a late child in the other operand keeps the record in `collect(S1 ⊔ S2)` but not in `collect(S1) ⊔ S2`. Rules by time or by every holder having seen the expiry are rejected already (notes/crdt.md Rejected: staleness horizon, stability GC; spec/requirements.md Ephemeral data: nothing kept until everyone has seen it).
- spec/requirements.md Scale accepts the growth itself (state grows with the edits ever made, a few bytes each). The defect is the in-memory size.

## Options
- **A. A compact form** for value-less records (a stamp and an anchor each, sources interned, chains as runs), charged near its encoded size. Keeps every rule; still O(ever written), at a few bytes (about a million lifetime elements per label at 16 MiB). osis-crdt `Seq` storage and placement work.
- **B. Spent records leave snapshots** (O(live)). A record all of whose writes are value-less and at which no record anchors is spent in a node's state; a snapshot omits spent records, and a body counts as covered when joining it into the snapshot adds only records spent in the node's state (spec/commits.md §5 Covered), so holders drop the leftovers and rebuild without them. The crdt join is unchanged. Cost: a late child or nested write of a record already dropped reads differently there (child at its virtual anchor, nested write hidden) until a writer holding both writes a snapshot, which carries the record again (the writer of the late write holds it). That widens spec/requirements.md Convergence's limit from "a node that never held an expiring edit" to one that dropped it: Tess's call. Durable too, by the principle: the sweep then can no longer take "no creation held though its delta is reflected" as dead (it would reset a late reaction everywhere), so the sweep needs another test of a pruned creation.
- **C. A stated limit** in notes/ephemeral.md Bounds: lifetime elements per label about cap / 1.15 KB.

Question for Tess: accept B's wider limit (late writes into or after an expired, collected element read differently until a writer's snapshot), or keep exact convergence and build A?
