# A chat's add costs each node O(members + messages)
> Summary: After the per-pass fixes and role moves by subject, an add costs a node about 10-20 ms, flat in messages, but for one pass of what posts left waiting (7 us per message since the last add). Left: a joiner 16 ms per earlier member and 1.1 ms per message, an admin a pass per label it syncs, store 57 KB per member. Repro and numbers: `scale::chat_members`, notes/testing.md.
> Tags: engine, node-sync, performance

Gone: the per-pass secrets decode (`Core::secrets_read`, `held_for`, `head_keys`, `Work::beats_*`, `mark_dirty_of`); an add's full pass of the label and the engine's walk of the label's commits (roles move only upstream of the changed edge's holder: `work::RoleMoves`, `Core::stale_authors`, notes/sync.md Work sets, notes/node.md Validity); `secrets.0` decoded whole per add (`keys::secrets_patch`); the liveness cache walked per role write (`Core::forget_live`).

Left, largest first:

1. **A joiner: O(members + messages).** 16 ms per earlier member (16 KB down per member: its add commit and card), 1.1-1.8 ms per message. Per-commit work, no longer per-commit-pair (`apply/waits.rs`).
2. **An admin: O(labels it syncs) per role commit.** Every role commit marks every label dirty; an admin that met each member has a label per contact, a pass and a `departures` walk each: `share` 2.8 s at 500. Each now judges almost nothing, the passes remain. Also about 20 us per label on every step of the sync engine. Branch `labels-cost` works here.
3. **Work waiting at labels no post passes.** A changed commit goes to every label's work set (`spread_touches`) though a post passes only labels holding it (`mark_dirty_of`): the next wide mark judges them all, about 7 us per message since the last add per node, and the set holds 32 B per message per label till then (an admin's hundred labels, 10^6 messages: 3 GB). Keep from a label's set the commits on nothing it holds.
4. **An add at a node: 10-20 ms.** Over the target of a few: `apply: join` about 4 ms (the state's pages and encode of a `roles.0` under a page), certificates 1 ms, a `departures` walk 0.1 ms per pass and member. 35 ms at 500 members at load 15, so still some part per member: there `apply: observe` is 12 ms and 13 state pages load per add (`observe_state`).
5. **Store: 57 KB per member at every node**, 176 KB at the host. At 40 members, per member: rows 38 KB, 8.9 blobs 19 KB. In the rows: the member's own first commit (person: `created.0`, `keys.0`, `label.0`, `roles.0`, `secrets.0`) 7.1 KB, its add 4.3 KB, a `keys.0` commit 1.6 KB, node card 1.0 KB; `keys.0` states 7.6 KB (3.2 things, 2.4 KB each: post-quantum public keys), `secrets.0` state 3.6 KB (three boxes and a history box), other states 1.3 KB; the rest (11 KB) indexes and sync entries. The blobs are the same commits again, under the label's key. No small fix: a node needs only the first commit's `created.0` and `keys.0` of a member, and the record and the blob are one commit twice, but dropping either is new machinery. `Engine::held_report` prints this.

Not measured: kicks at these sizes (issues/long-aspect-cost.md has them by messages), 1000 members all online (M nodes in one process do M^2 work per add; see the table's note).
