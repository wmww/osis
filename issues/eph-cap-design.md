# Ephemeral data at a server cap: own covers
> Summary: Design analysis (no code yet). The capped-server bug family (items 32, 44, 50, two open issues) all come from covers that absorb other authors' commits, which concurrent holders make and a full server must choose between. Proposal: a node compacts only its own commits (the presence rule, generalized) on a doubling trigger that counts per-entry overhead and has no floor. A server's cap refusal triggers nothing beyond the periodic retry, and past the cap the outcome is defined and checkable. This deletes forced compaction, `forced`, `own_full`, `server_full`, the cover closure, the `/created` coverage rule, `COMPACT_FLOOR` and foreign-write carrying.
> Tags: node, server, ephemeral

## The family
Every rule added so far patches one feedback loop: a server refuses for its cap → holders compact → **several holders' covers, each carrying everyone's writes**, arrive concurrently → the server can fit one but not all, or holds a cover nobody's next cover absorbs → refusal again.
- Item 32: holders compacted each other's concurrent covers forever (`forced`); then a refused concurrent cover stayed out for good (`own_full`, the `frees` condition); then an entry refused for good was re-uploaded at every write (re-arm only by another's cover).
- Item 44: a refused entry was never re-sent (periodic retry); a cover counted `/created` parts of another thing as covered and got re-made at every refusal (record-chain rule).
- Item 50: a forced cover left a commit partly covered, so the cover held at the full server was never absorbed (closure over held commits).
- Open: issues/eph-cover-partial-absorb.md (cross-group commits, uncovered `/created`), issues/eph-capped-created-remnants.md (`/created`-only commits nobody may compact).
Each fix narrows when a cross-author cover is made or what it absorbs. The race itself (k holders, each able to cover everyone, deciding concurrently) stays. Presence never had these bugs: a presence cover absorbs only its author's commits (`may_absorb`), so covers form one chain per author and never race.

## Options
**(a) Server eviction at the cap** (rejected in item 32, notes/ephemeral.md Step 3, Final review fixes). It broke because a label whose state fits but whose held bodies do not, with the local trigger silent (cap below `COMPACT_FLOOR`, many small aspects), keeps only the newest entries. Connected holders never re-upload the rest, so a joiner misses them (`server_cap_compaction_frees_it_spec_sync_5`). Repairing that needs a cap-driven trigger again (eviction notices), with the same concurrent-cover races. This is still true. Worse, a blind server cannot evict fairly per author: it cannot tell authors apart without linkable member keys (notes/sync.md), and holders re-uploading what was evicted ping-pong with the eviction. What the user sees: shared ephemeral state silently missing for late joiners. Deletes nothing that matters. Not exactly checkable: what is missing depends on arrival order.

**(b) A full cap stops the label** (refuse all, report). This is a defined outcome, but on its own it deletes little: normal operation still needs compaction to stay under the cap, cross-author covers still race under the local trigger (k concurrent covers of size S exceed 2S), and it needs a resume rule. What the user sees: one heavy writer stops everyone's live sharing on that label at that server. Its useful part is the idea of a defined outcome past the cap. Adopted below in a narrower form: refuse what does not fit.

**(c) Caps per author.** A blind server cannot count per author (same reason as (a)). The useful part is structural: if each author's data is a separate unit that only its author compacts, it either fits or is refused as a whole. Adopted below, with the cap per label as now.

**(d) Finish the special cases.** At least two more rules for the open issues (judge pulled aspects outside the group scope; add a commit's `/created` things to the carried records; drop or delete `/created`-only remnants). The race family stays open-ended. The capped sims choose `CAP` "above a compacted state" by hand: no predicate says when convergence must hold under a cap, so `ephemeral_capped` cannot check it exactly.

**(e) Own covers (recommended).** One rule: **an ephemeral cover is made only by the author of everything it covers**. This is the presence rule, applied to plain ephemeral data.
- A node's cover for an actor is the join of its own non-expiring ephemeral writes (this session's and earlier sessions' commits it holds again, as presence already does). It covers every own aspect, across all labels, projected per label like any commit. It absorbs every own held non-expiring commit of that actor. It carries `/created` records of the ephemeral things its parts are on and those its own `/group` writes name, with their chains. These are the only writes not its own; they are self-certifying through the tid. Every commit carries exactly those records, so no record-only commits exist.
- Trigger: when its own held non-expiring bodies for the actor, each counted as blob plus a per-entry charge, exceed twice the cover. There is no floor, and no trigger from a server refusal. This is a performance switch between correct strategies. At a factor near 1 it compacts at every write (presence's behaviour). At infinity bodies pile up and the fit guarantee below is lost. The doubling rule makes rebuild cost O(1) per byte written, amortized. With overhead counted, a small register compacts every two or three writes. That is about what presence does already: one upload and one delete per round trip after coalescing.
- Server cap: unchanged (refuse with code 12). The refusing node reports `EphemeralRefused` and re-sends at the periodic pass (the existing `capped`/`eph_retry`: the ordinary retry after a resource refusal). It makes no forced compaction.
- Defined outcome (spec): a server carries a label's ephemeral entries up to its cap. An entry that does not fit does not reach holders through that server until room appears. Each author keeps its own entries within about twice its own state, so a cap of at least twice the sum of the authors' own states always fits. Past it, the authors whose entries were refused are not seen through that server and say so. This fits requirements.md as written ("bounded per group, with a defined outcome past the bound"), and passes the 0/infinity test: at 0 nothing syncs through the server, at infinity everything does.
- Why convergence holds by construction: covers form one chain per author (a node has one session at a time). A later cover is the join of everything it absorbs, so dropping what it absorbs never changes a holder's state, whatever the arrival order. No cover can be concurrent with another cover that absorbs the same commit. Holders exchange the ordinary must-hold set. What a full server lacks is exactly what it refused, so nothing depends on which holder's cover won.
- What the user sees: the same as today below the cap. Near the cap, the newest writes of whoever arrived when it was full stay out at that server (first come, first served, as with durable storage caps), with a diagnostic.
- What can still go wrong:
  - More server memory: k authors overwriting one value keep k values; an author's own state keeps text of its own that others deleted (join of own deltas, never shrunk by others' removals: projecting the current state onto own dots would shrink it, but would turn a revoked writer's removal into the author's own).
  - A departed author's data cannot be compacted by others. It stays at most about twice that author's state, since the rule ran at its last send.
  - A heavy writer can fill a label's cap. Any writer can already do that with junk (notes/sync.md).
  - Expiring writes stay uncompacted entries until they expire, as today.
- Verifiability: `ephemeral_capped` and `ephemeral` can check two exact invariants at quiescence. (1) Per label and server, either all holders sharing the server read alike, or an entry is refused there that genuinely does not fit (server charge plus its size over the cap, checked against the server's own accounting). (2) Each live author's own held non-expiring bodies are within twice its cover plus one in-flight commit. `CAP` stops being a hand-tuned value: any cap, including 0 and a cap below one cover, is a valid run.

## Recommendation: (e)
Delete (code):
- node `sync/ephemeral.rs`: `Lane::{server_full, forced, own_full}`, the forced-compaction block in `eph_step` (the `frees` closure, the "nothing could be compacted" report, the retry-after-compaction loop), `own_full` setting in `eph_status`, the re-arm in `eph_keep`, the `ephemeral_is_cover` uses for the cap.
- engine `ephemeral/remote.rs`: `compact_ephemeral_if`'s `scope`/`force`/`frees` parameters, the closure over held commits, the per-aspect `parts.len() < 2` skip, `compactable`'s scope check, the `record_chain`-based absorption judgement (a cover absorbs every own held commit it lists), `COMPACT_FLOOR`, foreign session writes in plain covers (`claim_of`, `claims`, the `Authors` naming of other nodes, "unattributable writes not carried"), the separate presence-only branch of `may_absorb` (it becomes "same author, same class"), record-only commits in `take_ephemeral_if`.
- Judging: a plain ephemeral part carries only its author's writes (plus records), so the rule "carried session writes are judged as their `Authors` node's" and the laundering fix it needed go. A part is judged as its author's delta.
- Tests that encode the old rules: the `own_full`/`forced` cases (`server_cap_stuck_entry_no_churn` stays as a no-churn check), `server_cap_compaction_frees_it` becomes "the author's own compaction keeps it under the cap" (it already writes from one author).
- Issues deleted once built: eph-cover-partial-absorb, eph-capped-created-remnants. issues/dropped-voucher-after-cover.md loses its ephemeral side.

Add:

- Spec: sync.md §9 Compaction rewritten as above (own writes only, the trigger, no refusal trigger). §9 Holding: drop the `Authors` carrying sentence. §5/§9 Caps: the defined outcome sentence. commits.md §2: an ephemeral commit carries only its author's writes and the `/created` records named above. permissions.md §5.2: a plain ephemeral part is judged as its author's delta.
