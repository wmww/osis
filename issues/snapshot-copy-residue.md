# Snapshot writes no held delta settles
> Summary: what a malicious *writer's* snapshot can still do (readers' snapshots give nothing since snapshot authority): forge a claimed author's write under a dot whose delta the receiver never held or dropped; copies of one dot that differ tie in the join (first held wins: order-dependent); an invalid snapshot's copies under dropped deltas' dots stay in the state; a mover imports what its state showed.
> Tags: security, node, crdt

Fixed so far: where the delta owning a dot is held, a snapshot's copies under its dots count for nothing in both arrival orders (issues/snapshot-forged-owned-dots.md; `strip_held_copies`, `refill`, `covered`, `moves::carriers`). Snapshot authority (owner decision, notes/mvp-progress.md round 13; spec/permissions.md §5.2): a carried write counts iff the snapshot's author could write the aspect at the snapshot (judged by commit ID, demotion frontiers included) and the write is valid as its claimed author's; an invalid snapshot joins nothing, covers nothing, replays nothing, adds no receipts, and gives none of its carried writes (a dot is un-merged only when no carrier gives it); a `Commit(C)` write is judged per the held claim, else its own snapshot's `Authors` entry. Readers' snapshots therefore change nothing (`snapshot_forging_unused_dot_changes_nothing`, `snapshot_forging_dropped_import_dot_changes_nothing`, `reader_snapshot_gives_nothing_either_order`, `reader_copy_voids_no_valid_carrier`, `reader_claim_judges_only_its_snapshot`). What remains, all needing a writer (accepted residual for forged authorship of writes whose originals a node lacks; the rest only buys determinism):
- **Unheld and dropped dots**: a writer's snapshot carrying another author's write under a dot whose delta the receiver never held is judged as that author's at the carried `ts`; under a dropped delta's dot it joins as is (one held set can give two states: the snapshot before the drop was stripped, after it was not). Fix sketch for the dropped case: keep, per dropped delta, a digest of its writes by dot (as `EdgeParts` keeps membership bodies) and compare copies against it as against a held delta.
- **Invalid after joining**: a snapshot valid when it joined and invalid later (its author demoted with a frontier not listing it) loses its carried writes, but its copies under dropped deltas' dots stay in the state (nothing tells them from the dropped delta's own); a later rebuild keeps them (it joins the state).
- **Ties**: copies of one dot from several snapshots (or a snapshot and the state) that differ tie in `join_write` (equal stamps), `join_entry` (keys) and seq `merge_elem` (creation, char): the first held stays. Deterministic options: a total order on same-stamp payloads in osis-crdt (range records included), or one designated carrier per dot (e.g. least snapshot ID) with `copies_outside` detecting the conflict and a rebuild resolving it. Either only buys determinism.
- **Keys under a held delta's entry**: a snapshot record keeps the entry's key while others' writes remain in it (every record repeats the key; stripping it lost those writes where the delta's own reset had pruned its creation: order seed 93004). A forged key there ties with the delta's (first seen); where the snapshot also copies the creation, `copies_outside` sees it and `refill` strips the key (`Fragment::strip_forged`), leaving the entry keyless if the delta's creation is pruned.
- **Moves**: a mover that lacked the forged write's own delta when it moved imports the forged copy (its state showed it); `walks::open_equals_rebuild_random_histories_forged` sees it on copies (seed 294), so it checks only the originals for forged values.
- `retention::deaths` plays snapshot copies with `held_part` (dropped parts only, unreceived parts count as held); left as is.
