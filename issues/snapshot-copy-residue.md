# Snapshot writes no held delta settles
> Summary: a snapshot's write under a dot whose own delta the receiver does not hold (never had it, dropped it, or no such delta exists) counts: a reader can forge a writer's write under an unused counter and every receiver shows it; a forged copy of a dropped delta's write shows where it arrives after the drop; differing copies of one dot tie in the join (first held wins: order-dependent); a mover imports what its state showed.
> Tags: security, node, crdt

What was fixed (issues/snapshot-forged-owned-dots.md, spec/permissions.md §5.2): where the delta owning a dot is held, a snapshot's copies under its dots count for nothing in both arrival orders (`strip_held_copies` on join and rebuild, `refill` when the delta comes after the snapshot), forged snapshots cover no body they disagree with (`covered`), and `moves::carriers` skips snapshots that disagree with held deltas. What remains:
- **Unheld dots** (the widest): a snapshot write under a dot no held delta owns is judged as its claimed author's at the `ts` it carries (vouch for nothing), so a reader's snapshot carrying the owner's register write at a counter the owner never used, stamped now, shows at every receiver (repro, ignored: `validity::snapshot_forging_unused_dot_shows`). Spec/requirements.md "malicious readers can only waste storage" holds only for dots of held deltas. Mitigation today: only writers stamp entries at servers (spec/sync.md §3), so a reader's snapshot spreads by direct links, bundles or a writer relaying it. Owner decision (notes/mvp-progress.md, round 13): a carried write is valid iff the snapshot's author could write the aspect at the snapshot and the claimed author's write is valid (compaction is a writer's job); the `osis` API reports a value known only from a snapshot as the snapshot's (author, `ts`). Not built yet; it bounds this to malicious writers.
- **Dropped delta**: once the owner's delta drops, a snapshot's copies under its dots count as its write (spec/permissions.md §5.2). A forged snapshot arriving after the drop joins as is: an extra element under a dropped import's `Commit(C)` shows (repro, ignored: `validity::snapshot_forging_dropped_import_dot_shows`), so one held set gives two states (the snapshot before the drop was stripped, after it was not). A forged snapshot held before the drop: a later rebuild re-joins its copies (same-position ties keep the state's, joined first; other positions and extra dots return), and an in-place un-merge then differs from the debug rebuild check (a debug assertion on hostile input). Fix sketch: keep, per dropped delta, a digest of its writes by dot (as `EdgeParts` keeps membership bodies) and compare copies against it as against a held delta.
- **Ties**: copies of one dot from several snapshots (or a snapshot and the state) that differ tie in `join_write` (equal stamps), `join_entry` (keys) and seq `merge_elem` (creation, char): the first held stays. Deterministic options: a total order on same-stamp payloads in osis-crdt (range records included), or one designated carrier per dot (e.g. least snapshot ID) with `copies_outside` detecting the conflict and a rebuild resolving it. Either only buys determinism.
- **Keys under a held delta's entry**: a snapshot record keeps the entry's key while others' writes remain in it (every record repeats the key; stripping it lost those writes where the delta's own reset had pruned its creation: order seed 93004). A forged key there ties with the delta's (first seen); where the snapshot also copies the creation, `copies_outside` sees it and `refill` strips the key (`Fragment::strip_forged`), leaving the entry keyless if the delta's creation is pruned.
- **Moves**: a mover that lacked the forged write's own delta when it moved imports the forged copy (its state showed it); `walks::open_equals_rebuild_random_histories_forged` sees it on copies (seed 294), so it checks only the originals for forged values.
- `retention::deaths` plays snapshot copies with `held_part` (dropped parts only, unreceived parts count as held); left as is.
