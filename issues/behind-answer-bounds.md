# Behind answers: what an old credential learns, and what one Offer costs
> Summary: a Behind item is answered with every step to the head, so any holder of an old sync secret (a removed reader, for ever) learns every later step and can watch L's rotations and test peers' filters for its head; one Offer of 1024 Behind items costs 1024 × steps crossed reads and an answer past `MAX_MESSAGE`.
> Priority: normal
> Tags: security, sync, tess-call

- **Exposure.** `unread_behind` (osis-node `sync/unread.rs`) answers a Behind item by a step's credential with the steps after it to the head. A sync key never expires as a credential (`step_with_sync` finds old steps for ever; only claim and static credentials end with the claim set, `ROLE_KEEP`), and a removed reader keeps its old sync secrets. So a removed reader can, at any time, learn the current head's public keys and every step between: how many rotations, when (by polling), and the head's sync key, whose beacon tells it which peers keep L. notes/label-access.md (Refused Register and Deposit learn the code alone) rejects exactly that: "anyone with a label ID (ex-holder, link holder) watch rotations ... forever". The Open it replaced answered one child per old key. The same holds for a used or revoked link key naming the older step that listed it.
- **Cost.** One item reads a step per step crossed; a holder of the genesis sync key names genesis on every item: 1024 × path length reads per Offer input (notes/flow-control.md Hub stall bounds asks for work comparable to honest work), and an answer of more than about 29 000 steps (323 B each) does not fit `MAX_MESSAGE`, so a reader that far behind can never be answered.
- **One rule that fixes both** (to weigh): answer through the first step whose sync key differs from the credential's step (one rotation per answer; a legit reader then asks on by its claim at that step, which lists it, or by the new epoch's sync key). Exposure goes back to one rotation past what the holder read; cost per item is the run of steps sharing one sync key. Cost: one Behind round trip per rotation crossed instead of one per catch-up (`scale::a_catch_up_takes_one_behind_item_spec_sync_5` would count rotations), and a reader not listed at an intermediate rotation (another admin's step made before it knew of the grant) waits at it for a re-seal, which the every-step answer avoided.
