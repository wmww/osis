# Hashed paths: what a commit acts on depends on the sections a node opened
> Summary: in the A1 Interim (notes/a1-spec/README.md step 1) a commit stating hashed paths acts on what its opened sections say, so a hostile signer makes honest readers of one thing disagree for good: paths acting on different things are bad input only where two sections open; a purge request whose sections a target's reader cannot open applies nowhere there.
> Priority: normal
> Tags: engine, commit, security

Only a hostile or future writer reaches it: the engine writes the hashed form only under the test hook `Core::hashed_through`. Both close with steps 3 and 4 only if their design covers them.

- **Acting apart.** `CommitBlob::check_paths` rejects opened `Salted`s acting on different things (Interim, one acting thing per commit). A signer writes A along `[1, X]` and B along `[1, Y]`, hashed: a node holding A's read secret alone opens A, acts on X and applies A's parts; a node holding both gets an error from `Envelope::open` and rejects the whole blob. Both read A, so they disagree on A's value for good, and a node given per-thing copies can end either way by arrival order. Checked with a forged envelope in osis-commit (two things, each its own secret: open with A's → acting X, with B's → Y, with both → `Err`). Step 3 judges each thing along its own path, so the one-acting rule goes; until then the honest fix is to judge each opened thing by its own path's last thing, or to refuse hashed forms acting apart for every reader (impossible: the hashes hide it).
- **Purge requests.** `retention::purge::acting` gives no acting thing to a request whose paths are hashed and none of whose sections opened, so it holds no right (`holds_right`, `could_stand`) at a node reading the target T but not the things the request writes; a node that opened one applies it. The two disagree on T's purged deltas for good. Today's header actor was public, so every reader judged alike. The A1 draft (notes/a1-spec/commits.md, Could hold the right; spec/permissions.md §6) reads "the path it states for the delta's thing", which a request writing nothing on T does not state at all: the draft must say which path a request is judged along for a thing it purges but does not write (e.g. a request states its path in the clear, or writes on every thing it purges).
