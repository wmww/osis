# An aspect whose snapshot root tables pass MAX_BLOB never compacts
> Summary: a snapshot's root tables (`Sources`, `Commits`, `Frontiers`, `Absorbed`, `Facts`) are inline in its root blob; past `MAX_BLOB` (8 MiB) the snapshot cannot be written, so that aspect never compacts on any node and every later overwrite of it is kept forever. Any writer reaches it with about 10^6 session-form or 78,000 commit-form commits whose writes survive; honest growth too. Paging them is a table redesign: three options below, costed; a design decision is owed before building.
> Priority: normal
> Tags: security, crdt, engine

- Sizes (issues/durable-decode-bound.md, Step 6): per surviving commit about 8 B in session form (a `Commits` entry), 107 B in commit form (`Sources` 33, `Absorbed` 54, `Commits` 6, `Facts` about 2).
- Effect: `Engine::compactions` reports it (`OwnWriteFailed`). A failed aspect is weighed again only once its estimate doubles (`Trigger::failed`), so the retry cost is bounded; the storage cost (every overwrite kept on every holder) stays until the tables page.

## What references what (spec/crdt.md §3.2, §3.3 rule 1, §8)
- Every element of every leaf page names table entries by index: a `Dot`'s `Src` (an index into `Sources`, in order of first appearance across the whole fragment, pages expanded in link order), a `Stamp`'s `Ci` (an index into `Commits` flattened, grouped by `Src` then ascending `ts`). No leaf page decodes without the entries its indices name.
- `Commits` entries are delta-coded within a source's group (`dwall` from the previous entry), so entry `i` needs every earlier entry of its group; one session's group is one array element, so a session of 10^6 commits is one 8 MB element.
- `Frontiers` has one entry per `Session` source, in `Sources` order; `Facts` one per `Commits` entry, in its order; `Absorbed` is sorted by commit ID, read by key (is commit C absorbed?).
- Readers: apply streams the whole part (`stream_snapshot`: tables first, then pages); `covered_body` reads a snapshot's part at a body's positions (`stream_checked_some`, `PageIndex`/`Wanted`: only the leaves holding them), and looks up the body's source's frontier and `Absorbed`. Local state reads never touch wire tables. So the one partial reader is covering, and today it holds the whole root (tables at most `MAX_BLOB`).

## Options
1. **Paged tables, stable indices, decoded whole first** (Step 6). Each table may be `[Link+]` paged like an element array (`Pager`, `codec::Levels`, `LinkTree`, the same canonical rule). `Commits` becomes one element per commit, `[Src, dwall, logical, base]` (dwall from the previous entry of the same source), so any session pages. The decoder reads the tables first, page by page, into compact tables (interned sources; per commit its source, ts and base: about 30-50 B), then the fragment's pages as now; the check re-encodes tables through `Replay`. Wire: about +2 B per commit (`Src` repeated, an array head), +25% on session-form tables. Memory: within the rule (a multiple of the table bytes delivered). Cost: a partial read (covering) holds the whole tables, as today, but no longer capped by a blob: a body judged covered against a snapshot of 10^6 commits loads about 50 MB of tables. About 400-600 lines (codec, stream, engine snapshot writer, model gen, vectors with tables over 3 levels, spec).
2. **Counted table pages**: table link pages carry each child's entry count (`[[Link, n]+]`), so index `i` is a path of `depth` table pages. Needs entries readable alone: absolute `wall_ms` per `Commits` entry (about +4-5 B per commit, +50-60% on session-form tables; restarting the delta coding per page is circular with content-defined cuts). A second link-page form breaks one mechanism unless every link page carries counts (+2-3 B a link; gives element arrays positional seek too). A partial read resolves each distinct index on its pages by a path (cached): `distinct indices × depth` table pages; a text page naming many commits approaches the whole table anyway. `Absorbed` by key needs a search over counted positions (`depth × log n` pages) or separator keys in its link pages (a third form).
3. **Per-page tables**: each leaf page carries its own `Sources`/`Commits` (indices page-local, first appearance within the page), with each entry's facts beside it (a session source's frontier counter, a commit-form commit's `Absorbed` tid, a commit's `Fact`); the root carries the skeleton's. Sources and commits that occur in no page (frontier-only sessions, absorbed commits whose writes are gone: the Absence rule needs them) go in one global list sorted by bytes, paged, read whole by covering. A page is then self-contained like a delta: a point read touches `depth` pages and no table, decode memory is one page, and the encoder needs no whole-fragment collecting pass for tables. Cost: a source or commit named on k pages is written k times (32-33 B IDs, 8 B commits): roughly +10-30% on text and list snapshots whose commits span many pages, nothing on small ones. The largest change: codec contexts per page, rule 1 per page, `stream.rs`, `PageIndex`, the engine snapshot writer, `covered_body`, model gen, vectors, spec §3.2-§3.3, §8.

## Recommendation
- Option 3 if covering at a point (and any future partial read of a snapshot) should cost its path, not the tables: it removes the global table as a structure, so no bound on tables is ever needed again. Option 1 if partial reads may keep costing the tables (as the root read does today, now past 8 MiB): smallest change that fixes the compaction failure. Option 2 costs more bytes than 1 and still degrades to whole tables for broad reads; not recommended.
- Either way the tables page by the same `Levels`/`LinkTree` rule, and the chunker vectors take a case whose tables span three levels.
