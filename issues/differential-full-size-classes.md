# Sync differential: failure classes beyond the gate's seeds
> Summary: the sync differential at full size (88 of 200 failing, most by two recorded design gaps: a removed node never told, public pieces nobody holds) and at small size beyond the gate's seeds: the classes by first panic, each to shrink into a hand test.
> Priority: normal
> Tags: sync, engine, tests

Seeds move whenever commit bytes change: work from scripts, and turn each class into a hand-written test (notes/principles.md, Never pin a seed). Replay: `OSIS_FULL=1 OSIS_SYNC_START=<n> OSIS_SYNC_SEEDS=1`; run the 200 seeds as four `tools/heavy` holds of 50.

- **The full-size run** (200 seeds; histories with public things, public-link redeems, cards and inbox moves, harnesses with public profiles and contact cards as public links): 88 of 200 fail, one hangs (150, past 600 CPU-s). Classes by first panic:
  - a node removed from its account reads a history thing (23: 10, 13, 19, 22, 27, 30, 34, 37, 39, 41, 63, 65, 79, 84, 88, 122, 130, 138, 142, 146, 151, 162, 166): issues/removed-node-never-told.md.
  - a node reads a thing unlike the reference, its value none where the reference's roster lists the public (20: 1, 3, 9, 15, 20, 21, 23, 52, 53, 74, 77, 83, 96, 97, 112, 124, 125, 128, 134, 139, 154, 159, 167, 183, 198 less the five below): an account holding the thing at sync never learns it became public, issues/public-pieces-unheld.md. The other five "unlike the reference" without the public in the roster, and "a node reads a thing the model does not" (6: 31, 86, 111, 131, 174, 184): the older reads class, unshrunk.
  - must-hold bodies with no entry at quiet (16: 16, 24, 40, 47, 64, 69, 76, 82, 104, 114, 116, 117, 148, 152, 178, 189): new with this run's histories (seed 16's: certificate copies, `on: Some(..)`, at a paired node whose S has no source); unshrunk.
  - must-hold bodies a caught-up reader lacks at quiet (7: 4, 7, 11, 102, 105, 120, 176); node-sync settle loop past its bound (6: 14, 18, 28, 70, 160, 163); a sync set holding a thing otherwise than the model (4: 26, 38, 78, 158); entries waiting for a read secret, not parked (182).
  Shrink each (`OSIS_SYNC_SHRINK=1`, under `tools/heavy`) into a hand test; replay first, seeds move with every byte change.
- **Small size, 60 seeds, with public things, redeems, cards and inbox moves** (seeds 0..60): 16 fail. Ten by issues/removed-node-never-told.md (a node removed from its account reads a history thing; every seed drawing `Unpair`). Others by first panic: a node's sync set holding a thing as None where the model keeps it unread (11); node 1 reading nothing of things 0 and 1 where the model reads both through a thing given write on 0 that is also public (28: `New(0), New(0), Give(0, 1, Node(1), Writes), Strong(2, Some(0), 1), Give(2, 0, Node(1), Syncs), Give(0, 0, Thing(1), Writes), Give(0, 1, Public, Reads), ..`); node-sync settle loop past its bound (24, 46, both after `Give(_, 0, Public, ..)`); must-hold bodies a caught-up reader lacks (51).
- **A debug check feeding its own settle** (latent hazard): `Engine::role_duty_due` checks itself against `rotated_already` in debug builds, a run rolled back; the rollback moves the stamps it undid, so the duty's key is due again at once, and the rolled-back writes (a grant fire owed) reach the fires feed. While a duty stays owed and its run fails (it failed with `NotHeld` on a holder actor the node held secrets of and not the thing, before the cascade skipped unheld actors), every round acts and the node never settles (seed 75's settle loop). A check run inside a frame should leave no stamp or feed moved.
- **S's required set hangs on what a node holds by other paths.** Script: `New(3), NewIn(3, 0), Give(3, 1, Holder::Node(1), Syncs), Strong(1, None, 1), Strong(1, None, 0), Give(3, 0, Holder::Node(1), Reads), Run, Unstrong(0, Some(0), 1)`: Alice makes T0 and T1 minted with admin T0, grants Bob sync on T1 and read on T0, Bob holds both from his root, Alice drops T0 -> T1. Bob logged T1's keying must-hold under T0's sync ID after Alice released T1, against spec/sync-set.md §2 ("T's sync ID carries exactly T's sync unit"). Replay first: copies per (commit, thing) may have changed it.
- **Stale status sources**: "sources status counts that are no member at quiet", unshrunk.
- **A revoked store never reopened** (latent, no reproducer on main): after a revocation nothing reopens S at a store whose credentials and `changed_at(S)` did not move, so it is never tested again (spec/sync-opens.md §5 Testing) and keeps S's entries.
