# Sync differential: failure classes beyond the gate's seeds
> Summary: the sync differential at full size (19 of 200 failing on 6dc89649f; the largest class's cause named in issues/chain-top-unseen-by-sync-holder.md, a design call; the public-pieces class built, its leftovers below) and at small size beyond the gate's seeds: the remaining classes by first panic, with shrunk scripts, each to turn into a hand test.
> Priority: normal
> Tags: sync, engine, tests

Seeds move whenever commit bytes change: work from scripts, and turn each class into a hand-written test (notes/principles.md, Never pin a seed). Replay: `OSIS_FULL=1 OSIS_SYNC_START=<n> OSIS_SYNC_SEEDS=1`; run the 200 seeds as four `tools/heavy` holds of 50. A script replays over many worlds in a scratch test (`differential::worlds("scratch", |_| vec![..])`); at small size most of the scripts below fail at seed 0 too (`holds_on(0, 2, 3, ..)`, full size `holds_on(0, 3, 4, ..)`).

- **The full-size run on 6dc89649f** (200 seeds, four holds of 50, 5,654 CPU-s): 19 of 200 fail, none hang, none storm. By first panic: reads unlike the reference 1, 3, 15, 23, 52, 53, 74, 102, 134 (9); sync set unlike the model 10, 38, 78, 151 (as None, the model Keys) and 149 (as None, the model Unread) (5); a node reads a thing the model does not 31, 162 (2); must-hold a caught-up reader lacks 12, 128 (2); must-hold with no entry 35 (1). Causes, by shrunk script (each fails at `holds_on(0, 3, 4, ..)`):
  - **Public pieces logged by timing** (31, 3; 1 by a related engine case): built as spec/sync-set.md §2 Following by the public entry (notes/public-and-cards-brief.md). On branch `spar-public-timing` seeds 1..31 at full size: 1 and 3 pass (seed 1's script is `differential::a_reader_lowered_before_it_ran_reads_a_public_thing_spec_sync_set_2`); 10, 12, 15 as below; 23 fails on main e1a312a2a alike (unshrunk); 19 is a new shape (31's, a departed public reader never told the public's removal, is `differential::a_departed_public_reader_holds_the_publics_removal_*`):
    - Seed 19's script is the hand test `differential::a_removed_sync_holder_follows_what_its_key_part_names_*` (the sync ID named by the sync copies in the account's key part).
  - **A chain's last grant hidden from a sync-alone holder** (10): issues/chain-top-unseen-by-sync-holder.md. 38, 78, 151 share its first panic, unshrunk.
  - **Lost role writes** (15): `New(1), Give(1, 0, Holder::Public, Syncs), Give(1, 0, Holder::Node(2), Reads), Unstrong(1, None, 0), Strong(2, None, 0)`. Node 1 releases thing 0 before any run, so its grant to the public goes with it (spec/sync-set.md §3 Nothing of R stays: no node holds that commit at the end). The grant to node 2's account reaches it as an offer. The reference, handed every commit, lists the public's grant among the roles. The oracle tracks lost value writes only (`lost_writes`). A lost role write changes the roster, so it needs the reference and the model built without it, but a lost commit can be the parent of one that survived as an offered piece. An oracle gap; the engine is right.
  - Unexamined: 52, 53, 74, 102 (reads), 149 (Unread), 12, 128, 35.
- **A removed writer kept unread by the public's sync alone** (seed 31 at full size, past its earlier read failure; fails on 9f1a9fe0b alike, masked there by that failure): `New(2), Give(2, 0, Holder::Node(0), Writes), Give(2, 0, Holder::Public, Syncs), Strong(3, None, 0), Revoke(2, 0, Holder::Node(0))` at `holds_on(0, 3, 4, ..)` (and `New(1), Give(1, 0, Holder::Node(0), Writes), Give(1, 0, Holder::Public, Syncs), Strong(0, None, 0), Revoke(1, 0, Holder::Node(0))` at `holds_on(0, 2, 3, ..)`): "node 0's sync set holds thing 0 as Some(Read), the model Some(Unread)". The public holds sync alone, so the model keeps the thing unread at every node a strong reaches; node 0, its account removed, holds no sync secret (no copy boxing one) and follows the thing by the public entry, which opens nothing while the public does not read. Open question: how a party with no role but the public's sync takes the public's sync box (the public pieces its account's unit carries, spec/sync-set.md §2, or the public entry listed at sync too).
- **Small size, gate seed 107609900815** (fails on main alike): "node 1's sync set holds thing 0 as None, the model Some(Keys)", the first panic of the chain-top class (issues/chain-top-unseen-by-sync-holder.md); unshrunk.
- **Small size, gate seed 277009481497** (fails on 458a5941e alike, listed in tools/known_failures.txt): "node 0's sync set holds thing 0 as None, the model Some(Read)"; unshrunk.
- **Older shrunk scripts still open** (each failed at `holds_on(0, 3, 4, ..)` on an earlier commit; replay first):
  - Sync set unlike the model (node 1 lacks thing 1, the model Keys): `New(0), New(2), New(2), New(1), Give(2, 1, Node(1), Reads), Strong(1, Some(3), 2), Give(2, 2, Thing(1), Reads)`. The class also fails with every sync-alone holder sent each step bearing its sync key (`flows::inbox::deliver_step`), so it has a cause besides the chain top.

- **A store on a step whose deposit seed was since replaced** takes what it lacks only once moved to a step of a seed held (no honest node keeps old seeds); every other store a step behind takes a role commit's entry stamped under the step parent it is pinned under, or as a deposit of itself (spec/sync-judgement.md §3 Giving a body).
- **Store entries under a sync ID not held** (default size, seed 802245521440 on 082419420; that seed passes with Following by the public entry and the public's sync alone modelled, so the class has no live reproducer): "node 0 keeps 14 store entries under thing 0's sync ID, which it does not hold" (node 0 holds thing 0 by sync alone, kept unread, roles covering every secret held), unshrunk.
- **Reads nothing, no secrets of it held** (default size, seed 527365123461, listed in tools/known_failures.txt, replays on f5bcabb26): "node 1 reads thing 0 unlike the reference": node 1 reads None with no roles where the reference reads `Str("v4")` with admin, sync and read roles; its role path's lost access says "not due: no secrets of it held", node closure `Unread`. Unshrunk.
- **Small size beyond the gate's seeds**: re-run seeds 0..60 with public things, redeems, cards and inbox moves.
- **A debug check feeding its own settle** (latent hazard): `Engine::role_duty_due` checks itself against `rotated_already` in debug builds, a run rolled back; the rollback moves the stamps it undid, so the duty's key is due again at once, and the rolled-back writes (a grant fire owed) reach the fires feed. While a duty stays owed and its run fails, every round acts and the node never settles. A check run inside a frame should leave no stamp or feed moved.
- **S's required set hangs on what a node holds by other paths.** Script: `New(3), NewIn(3, 0), Give(3, 1, Holder::Node(1), Syncs), Strong(1, None, 1), Strong(1, None, 0), Give(3, 0, Holder::Node(1), Reads), Run, Unstrong(0, Some(0), 1)`: Bob logged T1's keying must-hold under T0's sync ID after Alice released T1, against spec/sync-set.md §2 ("T's sync ID carries exactly T's sync unit"). Replay first.
- **Stale status sources**: "sources status counts that are no member at quiet", unshrunk.
- **A revoked store never reopened** (latent, no reproducer on main): after a revocation nothing reopens S at a store whose credentials and `changed_at(S)` did not move, so it is never tested again (spec/sync-opens.md §5 Testing) and keeps S's entries.
