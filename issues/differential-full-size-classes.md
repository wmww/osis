# Sync differential: failure classes beyond the gate's seeds
> Summary: the sync differential at full size (60 of 200 failing, most by must-hold bodies without an entry and public pieces nobody holds) and at small size beyond the gate's seeds: the classes by first panic, each to shrink into a hand test.
> Priority: normal
> Tags: sync, engine, tests

Seeds move whenever commit bytes change: work from scripts, and turn each class into a hand-written test (notes/principles.md, Never pin a seed). Replay: `OSIS_FULL=1 OSIS_SYNC_START=<n> OSIS_SYNC_SEEDS=1`; run the 200 seeds as four `tools/heavy` holds of 50.

- **The full-size run** (200 seeds; histories with public things, public-link redeems, cards and inbox moves, harnesses with public profiles and contact cards as public links), on dd5c0a3e4: 60 of 200 fail, none hang (about 4,900 CPU-s, four holds of 50). Classes by first panic:
  - must-hold bodies with no entry at quiet (18: 16, 24, 40, 47, 64, 69, 76, 82, 84, 95, 104, 114, 116, 148, 152, 169, 178, 189): seed 16's are certificate copies (`on: Some(..)`) at a paired node whose S has no source; unshrunk.
  - a node reads a thing unlike the reference, its value none where the reference's roster lists the public (17: 1, 9, 20, 21, 53, 77, 83, 96, 112, 128, 131, 134, 139, 154, 167, 183, 198): an account holding the thing at sync never learns it became public, issues/public-pieces-unheld.md.
  - must-hold bodies a caught-up reader lacks at quiet (6: 4, 7, 51, 102, 120, 176); node-sync settle loop past its bound (5: 14, 18, 28, 70, 160); "unlike the reference" without the public in the roster (5: 15, 23, 52, 97, 159) and "a node reads a thing the model does not" (4: 74, 86, 174, 184), the older reads class; a sync set holding a thing otherwise than the model (4: 26, 38, 78, 125); entries waiting for a read secret, not parked (182).
  Shrink each (`OSIS_SYNC_SHRINK=1`, under `tools/heavy`) into a hand test; replay first, seeds move with every byte change.
- **Small size, 60 seeds, with public things, redeems, cards and inbox moves** (seeds 0..60): 5 fail, by first panic: node 1 reading nothing of a thing the public reads, after `Unpair(0, 2)` (11; public pieces, issues/public-pieces-unheld.md, unshrunk); node 1 reading nothing of things 0 and 1 where the model reads both through a thing given write on 0 that is also public (28: `New(0), New(0), Give(0, 1, Node(1), Writes), Strong(2, Some(0), 1), Give(2, 0, Node(1), Syncs), Give(0, 0, Thing(1), Writes), Give(0, 1, Public, Reads), ..`); node-sync settle loop past its bound (24, 46, both after `Give(_, 0, Public, ..)`); must-hold bodies a caught-up reader lacks (51).
- **A debug check feeding its own settle** (latent hazard): `Engine::role_duty_due` checks itself against `rotated_already` in debug builds, a run rolled back; the rollback moves the stamps it undid, so the duty's key is due again at once, and the rolled-back writes (a grant fire owed) reach the fires feed. While a duty stays owed and its run fails (it failed with `NotHeld` on a holder actor the node held secrets of and not the thing, before the cascade skipped unheld actors), every round acts and the node never settles (seed 75's settle loop). A check run inside a frame should leave no stamp or feed moved.
- **S's required set hangs on what a node holds by other paths.** Script: `New(3), NewIn(3, 0), Give(3, 1, Holder::Node(1), Syncs), Strong(1, None, 1), Strong(1, None, 0), Give(3, 0, Holder::Node(1), Reads), Run, Unstrong(0, Some(0), 1)`: Alice makes T0 and T1 minted with admin T0, grants Bob sync on T1 and read on T0, Bob holds both from his root, Alice drops T0 -> T1. Bob logged T1's keying must-hold under T0's sync ID after Alice released T1, against spec/sync-set.md §2 ("T's sync ID carries exactly T's sync unit"). Replay first: copies per (commit, thing) may have changed it.
- **Stale status sources**: "sources status counts that are no member at quiet", unshrunk.
- **A revoked store never reopened** (latent, no reproducer on main): after a revocation nothing reopens S at a store whose credentials and `changed_at(S)` did not move, so it is never tested again (spec/sync-opens.md §5 Testing) and keeps S's entries.
