## S's required set hangs on what a node holds by other paths (189)
- Shrunk script (8 steps): `New(3), NewIn(3, 0), Give(3, 1, Holder::Node(1), Syncs), Strong(1, None, 1), Strong(1, None, 0), Give(3, 0, Holder::Node(1), Reads), Run, Unstrong(0, Some(0), 1)`; seed-0 form: Alice makes T0, and T1 minted with admin T0 (held from T0 alone), grants Bob sync on T1 and read on T0, Bob holds both from his root, Alice drops T0 -> T1. Fails on most worlds.
- Cause: a thing's `sync.0` and `created.0` are carried under its independent's sync ID (the nearest independent thing up its record chain) whatever that unit holds (spec/sync-ids.md §2; engine `sync_ids::published`). Bob, holding T1 by his root, logs T1's keying must-hold under T0's sync ID; Alice released T1 and forgot it. The engine is wrong by the principle (a body leaves a reader's store only for a reason every holder sees), and spec/sync-set.md §2 ("T's sync ID carries exactly T's sync unit") already says so.
- Built and parked (branch `keel-diff-rest6-withpub`, commit "A sync ID carries exactly its sync unit"): publishing removed whole, with a seed-0 holding test of the shape above. Every default test passes, but three full-size seeds start failing (61: sources status counts that are no member at quiet; 165: a paired node keeps a thing it was granted sync then read unread, shrunk `New(1), Give(1, 0, Holder::Node(0), Syncs), Run, Pair(0), Give(1, 0, Holder::Node(0), Reads), Run, Strong(3, None, 0)`; 181: entries waiting for a read secret, not parked).
