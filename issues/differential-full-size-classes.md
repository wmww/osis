# Full-size sync differential: classes to check once it runs again
> Summary: the sync differential (accounts as ordinary things) fails on some seeds: at small size a dependent its account's sync unit holds that no node of the account can fetch (2 of 36 seeds failed, one this class); at full size its removal seeds (issues/public-key-record-evidence.md, 3 of 8). The older classes (S's required set hanging on other paths, stale status sources) are unchecked: run the 200 full-size seeds once the removal class is fixed and turn each class into a hand test.
> Priority: normal
> Tags: sync, engine, tests

Seeds move whenever commit bytes change: work from scripts, and turn each class into a hand-written test (notes/principles.md, Never pin a seed). Replay: `OSIS_FULL=1 OSIS_SYNC_START=<n> OSIS_SYNC_SEEDS=1`; run the 200 seeds as four `tools/heavy` holds of 50.

- **A dependent in an account's sync unit that no node of the account can fetch** (small size, `OSIS_SYNC_START=23`, unshrunk; script in the run's output): Bob makes T0 and T1 minted with admin T0 (T0 holds T1); Alice's account gets write on T0 but holds no strong to it; Alice makes T2 (held from her account) and writes a strong T2 -> T1 before holding anything of T1. By spec/sync-set.md §2 the account's sync unit holds T1 (its keys open T1, through T2, which they open), and the model and the reference (Alice's twin, handed every commit) read it; Alice's nodes hold nothing of T1: only Bob's node holds it, it is no writer of Alice's account so logs nothing under its sync ID, and T0's sync ID, which carries T1, is synced by no node of Alice's (no strong to T0). Either the spec's sync unit (through every thing the keys open) needs a carrier rule for this, or a writer of the unit must fetch T1 from T0's sync ID: a design question, not probed in the engine.
- **S's required set hangs on what a node holds by other paths.** Script: `New(3), NewIn(3, 0), Give(3, 1, Holder::Node(1), Syncs), Strong(1, None, 1), Strong(1, None, 0), Give(3, 0, Holder::Node(1), Reads), Run, Unstrong(0, Some(0), 1)`: Alice makes T0 and T1 minted with admin T0, grants Bob sync on T1 and read on T0, Bob holds both from his root, Alice drops T0 -> T1. Bob logged T1's keying must-hold under T0's sync ID after Alice released T1, against spec/sync-set.md §2 ("T's sync ID carries exactly T's sync unit"). Replay first: copies per (commit, thing) may have changed it.
- **Stale status sources**: "sources status counts that are no member at quiet", unshrunk.
- **A revoked store never reopened** (latent, no reproducer on main): after a revocation nothing reopens S at a store whose credentials and `changed_at(S)` did not move, so it is never tested again (spec/sync-opens.md §5 Testing) and keeps S's entries.
