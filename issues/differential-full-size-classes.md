# Sync differential: failure classes beyond the gate's seeds
> Summary: the sync differential at full size (19 of 200 failing on spar-diff-4; the largest classes have causes named in issues/public-pieces-by-timing.md and issues/chain-top-unseen-by-sync-holder.md, both design calls) and at small size beyond the gate's seeds: the remaining classes by first panic, with shrunk scripts, each to turn into a hand test.
> Priority: normal
> Tags: sync, engine, tests

Seeds move whenever commit bytes change: work from scripts, and turn each class into a hand-written test (notes/principles.md, Never pin a seed). Replay: `OSIS_FULL=1 OSIS_SYNC_START=<n> OSIS_SYNC_SEEDS=1`; run the 200 seeds as four `tools/heavy` holds of 50. A script replays over many worlds in a scratch test (`differential::worlds("scratch", |_| vec![..])`); at small size most of the scripts below fail at seed 0 too (`holds_on(0, 2, 3, ..)`, full size `holds_on(0, 3, 4, ..)`).

- **The full-size run on spar-diff-4** (6dc89649f's tree with the storm cap counted per run; 200 seeds, four holds of 50, 5,654 CPU-s): 19 of 200 fail, none hang, none storm. By first panic: reads unlike the reference 1, 3, 15, 23, 52, 53, 74, 102, 134 (9); sync set unlike the model 10, 38, 78, 151 (as None, the model Keys) and 149 (as None, the model Unread) (5); a node reads a thing the model does not 31, 162 (2); must-hold a caught-up reader lacks 12, 128 (2); must-hold with no entry 35 (1).   - **Storm** (183 on 6dc89649f): no loop. A node powered off across about 40 runs is redialed every `REDIAL_MS` of each run's hour, which passed a cap counted over the world's life. The cap now counts one run (`World::run_from`; `world::the_storm_cap_counts_one_run`).
  - **Public pieces logged by timing** (31, 3; 1 by a related engine case): issues/public-pieces-by-timing.md. Seed 31's script (above) keeps reading; seed 3's `New(0), Give(0, 0, Holder::Node(1), Reads), Strong(1, None, 0), Give(0, 0, Holder::Public, Reads), PowerOff(1), Revoke(0, 0, Holder::Node(1))` never reads; seed 1's `New(2), Give(2, 0, Holder::Public, Reads), Give(2, 0, Holder::Node(1), Reads), Strong(1, None, 0), Lower(2, 0, Holder::Node(1), Syncs)` never holds the public's grant. Seed 23 shrinks (old binary, budget cut at 11 steps) to a public grant and its revoke beside an unstrong, probably the same class: `New(3), NewIn(3, 0), NewIn(3, 1), NewIn(3, 1), Run, Give(0, 3, Holder::Node(2), Reads), Strong(2, None, 3), Give(0, 1, Holder::Public, Reads), Give(0, 3, Holder::Node(1), Writes), Unstrong(0, Some(1), 3), Revoke(0, 1, Holder::Public)`. 162 and 134 unshrunk.
  - **A chain's last grant hidden from a sync-alone holder** (10): issues/chain-top-unseen-by-sync-holder.md. 38, 78, 151 share its first panic, unshrunk.
  - **Lost role writes** (15): `New(1), Give(1, 0, Holder::Public, Syncs), Give(1, 0, Holder::Node(2), Reads), Unstrong(1, None, 0), Strong(2, None, 0)`. Node 1 releases thing 0 before any run, so its grant to the public goes with it (spec/sync-set.md §3 Nothing of R stays: no node holds that commit at the end). The grant to node 2's account reaches it as an offer. The reference, handed every commit, lists the public's grant among the roles. The oracle tracks lost value writes only (`lost_writes`). A lost role write changes the roster, so it needs the reference and the model built without it, but a lost commit can be the parent of one that survived as an offered piece. An oracle gap; the engine is right.

- **A debug check feeding its own settle** (latent hazard): `Engine::role_duty_due` checks itself against `rotated_already` in debug builds, a run rolled back; the rollback moves the stamps it undid, so the duty's key is due again at once, and the rolled-back writes (a grant fire owed) reach the fires feed. While a duty stays owed and its run fails, every round acts and the node never settles. A check run inside a frame should leave no stamp or feed moved.
