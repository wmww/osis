# Sync differential: failure classes beyond the gate's seeds
> Summary: the sync differential at full size (36 of 200 failing, half the public-roster class, issues/public-pieces-unheld.md) and at small size beyond the gate's seeds: the remaining classes by first panic, with shrunk scripts, each to turn into a hand test.
> Priority: normal
> Tags: sync, engine, tests

Seeds move whenever commit bytes change: work from scripts, and turn each class into a hand-written test (notes/principles.md, Never pin a seed). Replay: `OSIS_FULL=1 OSIS_SYNC_START=<n> OSIS_SYNC_SEEDS=1`; run the 200 seeds as four `tools/heavy` holds of 50. A script replays over many worlds in a scratch test (`differential::worlds("scratch", |_| vec![..])`); at small size most of the scripts below fail at seed 0 too (`holds_on(0, 2, 3, ..)`, full size `holds_on(0, 3, 4, ..)`).

- **The full-size run** (200 seeds, four holds of 50, about 6,200 CPU-s): 36 of 200 fail, none hang, on 584c7396e with this job's fixes, before main's public-entry fix (dbf98d8f4), which passes much of the public class. By first panic:
  - a node reads a thing unlike the reference, its value none where the reference's roster lists the public (18: 1, 7, 9, 20, 21, 53, 64, 70, 83, 96, 112, 128, 131, 134, 139, 154, 167, 198): issues/public-pieces-unheld.md; rerun on main first.
  - **A sync set holding a thing otherwise than the model** (4: 10, 38, 78, 151; 80 and 99 at 0..100 before the last rebase). Full-size scripts, each failing at `holds_on(0, 3, 4, ..)`:
    - `New(2), Give(2, 0, Node(0), Syncs), Revoke(2, 0, Node(0)), Give(2, 0, Node(1), Syncs), Strong(1, None, 0)`: node 1 keeps nothing of thing 0, the model keeps it unread. Cause: the grant to node 1's account (sync alone) goes as sealed sync copies with the `sync.0` writes held then (`flows::inbox::deliver_copy`), but its box is at the sync epoch the revocation rotated to, whose step is issued only later; no later step reaches a holder of sync alone from outside, so it never has a step bearing its sync key (spec/permissions.md §4 Delivering an edge piece: "else not until one does", a stall). Likely fix: an admin issuing a step delivers it as a sealed sync copy to each holder of sync alone boxed at the epoch it registers that it may not write, as `flows::inbox::deliver_step` does for a removal (issues/sync-alone-removal-residuals.md, Blocked sync rotation: the same gap from the removal side); security-adjacent, review it.
    - `New(2), New(0), New(1), NewIn(1, 2), Give(1, 3, Node(2), Syncs), Strong(2, None, 3), Give(1, 2, Node(2), Reads)` (node 2 lacks thing 2, model Keys) and `New(0), New(2), New(2), New(1), Give(2, 1, Node(1), Reads), Strong(1, Some(3), 2), Give(2, 2, Thing(1), Reads)` (node 1 lacks thing 1, model Keys): unexamined.
    - Small size, the other way (node holds Keys, model none): `New(0), New(1), NewIn(1, 1), Give(1, 2, Node(0), Reads), Strong(0, None, 2), Strong(1, Some(2), 1), Give(1, 1, Public, Reads), Run, New(0), Strong(0, Some(0), 1), Revoke(1, 1, Public)` at seed 0 (node 0 holds thing 1 for keys after the public's removal); involves the public, check against issues/public-pieces-unheld.md first.
  - **The older reads class** (10): "unlike the reference" without the public in the roster (15, 23, 52, 102, 123) and "a node reads a thing the model does not" (74, 86, 174, 184): unshrunk.
  - **Entries waiting for a read secret, not parked** (26, node 0 after 951 deliveries): another cause than the part dropped after a blob's opening (fixed, `an_entry_waits_for_a_part_dropped_after_its_opening_*`); unshrunk.
  - **Must-hold bodies with no entry at quiet** (121): unshrunk.
  - **Must-hold bodies a caught-up reader lacks** (3: 11, 48, 84): seed 48 shrinks (unfinished, timed out) to `New(1), Give(1, 0, Node(0), Reads), Strong(0, None, 0), Unpair(0, 3), Pair(1), New(4), Run, Strong(0, None, 1), Give(4, 0, Node(0), Writes), Run, Write(0, 0), Give(1, 1, Thing(0), Reads), Run, Unstrong(0, None, 0), Strong(0, None, 0)`: a plain write on thing 0 three holders hold must, node 0 (which released and held thing 0 again) holds no entry and no tombstone of it. Likely spec/sync-judgement.md §3 Dropped bodies (fetched again once a strong reaches the thing again).
- **Default size**: seed 773223939837 (must-hold bodies a caught-up reader lacks), listed in tools/known_failures.txt (holder 1, reader 2), unshrunk; still fails with the certificate clause.
- **Store entries under a sync ID not held** (default size, seed 802245521440, listed in tools/known_failures.txt, replays on 082419420): "node 0 keeps 14 store entries under thing 0's sync ID, which it does not hold" (node 0 holds thing 0 by sync alone, kept unread, roles covering every secret held), unshrunk.
- **Small size beyond the gate's seeds**: re-run seeds 0..60 with public things, redeems, cards and inbox moves; the settle-loop seeds listed before passed once the step trigger for the public read what a step lists.
- **A debug check feeding its own settle** (latent hazard): `Engine::role_duty_due` checks itself against `rotated_already` in debug builds, a run rolled back; the rollback moves the stamps it undid, so the duty's key is due again at once, and the rolled-back writes (a grant fire owed) reach the fires feed. While a duty stays owed and its run fails, every round acts and the node never settles. A check run inside a frame should leave no stamp or feed moved.
- **S's required set hangs on what a node holds by other paths.** Script: `New(3), NewIn(3, 0), Give(3, 1, Holder::Node(1), Syncs), Strong(1, None, 1), Strong(1, None, 0), Give(3, 0, Holder::Node(1), Reads), Run, Unstrong(0, Some(0), 1)`: Bob logged T1's keying must-hold under T0's sync ID after Alice released T1, against spec/sync-set.md §2 ("T's sync ID carries exactly T's sync unit"). Replay first.
- **Stale status sources**: "sources status counts that are no member at quiet", unshrunk.
- **A revoked store never reopened** (latent, no reproducer on main): after a revocation nothing reopens S at a store whose credentials and `changed_at(S)` did not move, so it is never tested again (spec/sync-opens.md §5 Testing) and keeps S's entries.
