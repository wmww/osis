# Sync differential: failure classes beyond the gate's seeds
> Summary: the sync differential at full size (25 of 200 seeds failing on 339ddd951; 3 of them fixed since: an oracle gap, a KEM key due with no pass) by class with shrunk scripts and what is known of each cause, and the three small-size seeds tools/known_failures.txt lists: each class to turn into a hand-written test.
> Priority: normal
> Tags: sync, engine, tests

Seeds move whenever commit bytes change: work from scripts, and turn each class into a hand-written test (notes/principles.md, Never pin a seed). Replay a seed: `OSIS_FULL=1 OSIS_SYNC_START=<n> OSIS_SYNC_SEEDS=1 cargo test -p osis-sync --test it -- --ignored --exact differential::histories_hold_their_closure_plain`; run the 200 as four `tools/heavy` holds of 50 (about 1,450 CPU-s and 130-230 s wall each). A script replays in a scratch test in `differential.rs` (`holds_on(0, 3, 4, &script, String::new(), false)`, full size); `OSIS_SYNC_SHRINK=1` shrinks a seed.

## Full size, on 339ddd951
25 of 200 fail, none hang, none storm. Scripts replay at `holds(<seed>, ..)` under `OSIS_FULL=1` (their world seed) unless a `holds_on` is named. By first panic:

- **Reads unlike the reference** (15, 23, 52, 53, 102, 134).
  - 15: fixed (oracle: a release loses grants as it loses value writes; `a_grant_released_before_anyone_received_it_is_lost_spec_sync_set_3`).
  - 52, 134: fixed (engine: a KEM key due made an own write wanted no complete pass, so a lone node that moved its inbox never rotated and every grant fire to it waited; `a_lone_node_moving_its_inbox_takes_grants_from_outside_spec_crypto_3`).
  - 102, an oracle gap (the model's Dependent entry knows a dependent's mint admin without its record): `New(0), NewIn(0, 0), Give(0, 0, Holder::Node(1), Reads), New(1), NewIn(1, 2), Strong(1, Some(3), 1)`. Node 1's own thing strongs thing 1, a dependent of thing 0, which node 1 never held; its account reads thing 0 by the offer alone. held-model enters thing 0 at that strong (`Rule::dep_entry`, by `kinds[y]`); the engine needs thing 1's record to know whose dependent it is (`Core::secret_actor`), and nothing node 1 syncs carries it (spec/sync-set.md §2: "a strong to a thing whose record the node does not hold makes nothing held"). The fix is in held-model: Dependent entry only where the node holds D's record (a bridge logged it under T, a unit it reads carries it, a link it redeemed); held-model's `a_dependent_of_another_thing_is_carried_by_its_independent_or_a_bridge` asserts the entry with no bridge and needs the same look.
  - 53, undiagnosed (passes with the inbox move dropped; still fails with the moved inbox's KEM key rotated at once): `New(3), New(2), Give(2, 1, Holder::Node(1), Syncs), Give(2, 1, Holder::Public, Reads), Inbox(2, Some(1)), Revoke(2, 1, Holder::Public), Strong(1, None, 1), Run, Give(2, 1, Holder::Public, Reads)`: node 1 keeps thing 1 unread at sync where the public reads it again.
  - 23: the shrink was cut at 32 steps (its seed timeout); shrink on from its log's last script.
- **Sync set Read, the model Unread** (12, 19, 31, 68, 84, 85, 149). Seed 31's script, a removed writer kept unread by the public's sync alone: `New(2), Give(2, 0, Holder::Node(0), Writes), Give(2, 0, Holder::Public, Syncs), Strong(3, None, 0), Revoke(2, 0, Holder::Node(0))` (at `holds_on(0, 2, 3, ..)`: `New(1), Give(1, 0, Holder::Node(0), Writes), Give(1, 0, Holder::Public, Syncs), Strong(0, None, 0), Revoke(1, 0, Holder::Node(0))`). The public holds sync alone, so the model keeps the thing unread at every node a strong reaches; node 0, its account removed, holds no sync secret and follows the thing by the public entry, which opens nothing while the public does not read. Open question: how a party with no role but the public's sync takes the public's sync box (the public pieces its account's unit carries, spec/sync-set.md §2, or the public entry listed at sync too). The other seeds unshrunk.
- **Sync set Unread, the model Read** (43, 162, 167), the mirror of the class above: 162 `New(2), Give(2, 0, Holder::Node(0), Syncs), Strong(0, None, 0), Give(2, 0, Holder::Node(0), Reads), Revoke(2, 0, Holder::Node(0))`; 167 alike; 43 with a paired node holding it. The account is given sync, then read, and removed before any run: its nodes take the sync copies alone (a sync secret boxed before the removal), keep the thing unread, and stop at the step past their keys (path as deep as the readers', no entries: spec/sync-judgement.md §6 Stops). The model has them follow it by the public entry (their account's key part names its sync ID, `Made::named`), as spec/sync-set.md §2 (Following by the public entry) does for a node that "does not keep X unread"; the harness allows a stopped node only where the model holds nothing (`stopped`). The question: is a stopped node one that keeps X unread? If not, it should follow by the public entry (and see the public read X later). Decide with the class above, whose fix touches the same choice.
- **Sync set None, the model Keys** (10, 38, 78, 151): every one is issues/chain-top-unseen-by-sync-holder.md's question (a role through a holder the node knows only by an offer counts in held-model, not at the engine), a tess-call. 38: `New(0), New(2), New(2), New(1), Give(2, 1, Holder::Node(1), Reads), Strong(1, Some(3), 2), Give(2, 2, Holder::Thing(1), Reads)` (the account holds no role on thing 2 but through thing 1, and thing 1's grant on thing 2 is in thing 1's key part alone); 78: `New(1), Give(1, 0, Holder::Node(2), Syncs), New(1), New(1), Strong(2, None, 0), Give(1, 2, Holder::Node(2), Reads), Give(1, 0, Holder::Thing(2), Syncs)`; 151: `New(0), New(0), NewIn(0, 0), Give(0, 2, Holder::Public, Syncs), Give(0, 0, Holder::Node(2), Reads), Strong(2, None, 2)`.
