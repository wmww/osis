# Sync differential: failure classes beyond the gate's seeds
> Summary: the sync differential at full size (38 of 200 failing on b21ba1c7f; the largest class reads unlike the reference, much of it issues/public-pieces-unheld.md) and at small size beyond the gate's seeds: the remaining classes by first panic, with shrunk scripts, each to turn into a hand test.
> Priority: normal
> Tags: sync, engine, tests

Seeds move whenever commit bytes change: work from scripts, and turn each class into a hand-written test (notes/principles.md, Never pin a seed). Replay: `OSIS_FULL=1 OSIS_SYNC_START=<n> OSIS_SYNC_SEEDS=1`; run the 200 seeds as four `tools/heavy` holds of 50. A script replays over many worlds in a scratch test (`differential::worlds("scratch", |_| vec![..])`); at small size most of the scripts below fail at seed 0 too (`holds_on(0, 2, 3, ..)`, full size `holds_on(0, 3, 4, ..)`).

- **The full-size run** (200 seeds, four holds of 50, about 6,200 CPU-s): 38 of 200 fail, none hang, on b21ba1c7f (before ed7cdee1f, a public reader keeping a thing on taking its record). By first panic:
  - a node reads a thing unlike the reference (12: 9, 15, 23, 64, 70, 96, 102, 112, 123, 128, 131, 154): seed 15 shrinks to `New(1), Give(1, 0, Public, Reads), Strong(2, None, 0)`, the public in the reference's roster: issues/public-pieces-unheld.md. The rest unshrunk (the older reads class among them: 23, 102, 123 without the public in the roster before); rerun on main first.
  - **A node keeping a thing unread at a step behind its readers' head** (11: 25, 32, 50, 52, 80, 99, 101, 149, 171, 182, 190): unshrunk; compare issues/sim-lying-peer-unread-step-behind.md first.
  - **A sync set holding a thing otherwise than the model** (4 on b21ba1c7f: 10, 38, 78, 151). Full-size scripts, each failing at `holds_on(0, 3, 4, ..)`:
    - `New(2), Give(2, 0, Node(0), Syncs), Revoke(2, 0, Node(0)), Give(2, 0, Node(1), Syncs), Strong(1, None, 0)`: node 1 keeps nothing of thing 0, the model keeps it unread. Cause: the grant to node 1's account (sync alone) goes as sealed sync copies with the `sync.0` writes held then (`flows::inbox::deliver_copy`), but its box is at the sync epoch the revocation rotated to, whose step is issued only later; `flows::inbox::deliver_step` sends a holder of sync alone each step bearing its sync key (`tests_delivery::a_step_after_a_rotation_reaches_a_holder_of_sync_alone_*`); the script passes at `holds_on(0, 3, 4, ..)` with or without that, and seeds 10, 38, 78 and 151 still fail with it (a node holds a thing as None, the model Keys): the class has another cause.
    - `New(2), New(0), New(1), NewIn(1, 2), Give(1, 3, Node(2), Syncs), Strong(2, None, 3), Give(1, 2, Node(2), Reads)` (node 2 lacks thing 2, model Keys) and `New(0), New(2), New(2), New(1), Give(2, 1, Node(1), Reads), Strong(1, Some(3), 2), Give(2, 2, Thing(1), Reads)` (node 1 lacks thing 1, model Keys): unexamined.

- **Store entries under a sync ID not held** (default size, seed 802245521440, listed in tools/known_failures.txt, replays on 082419420): "node 0 keeps 14 store entries under thing 0's sync ID, which it does not hold" (node 0 holds thing 0 by sync alone, kept unread, roles covering every secret held), unshrunk.
- **Small size beyond the gate's seeds**: re-run seeds 0..60 with public things, redeems, cards and inbox moves; the settle-loop seeds listed before passed once the step trigger for the public read what a step lists.
- **A debug check feeding its own settle** (latent hazard): `Engine::role_duty_due` checks itself against `rotated_already` in debug builds, a run rolled back; the rollback moves the stamps it undid, so the duty's key is due again at once, and the rolled-back writes (a grant fire owed) reach the fires feed. While a duty stays owed and its run fails, every round acts and the node never settles. A check run inside a frame should leave no stamp or feed moved.
- **S's required set hangs on what a node holds by other paths.** Script: `New(3), NewIn(3, 0), Give(3, 1, Holder::Node(1), Syncs), Strong(1, None, 1), Strong(1, None, 0), Give(3, 0, Holder::Node(1), Reads), Run, Unstrong(0, Some(0), 1)`: Bob logged T1's keying must-hold under T0's sync ID after Alice released T1, against spec/sync-set.md §2 ("T's sync ID carries exactly T's sync unit"). Replay first.
- **Stale status sources**: "sources status counts that are no member at quiet", unshrunk.
- **A revoked store never reopened** (latent, no reproducer on main): after a revocation nothing reopens S at a store whose credentials and `changed_at(S)` did not move, so it is never tested again (spec/sync-opens.md §5 Testing) and keeps S's entries.
