# Suspect lists and repair are not built in the rebuilt sync
> Summary: No node sends Suspect lists (spec/permissions.md §4 Suspect list) and a received one is answered Ok and dropped, so the repair of spec/sync-compaction.md §1 never runs; the engine's flags (`Engine::suspects`, `state_digest`, `snapshot`) are built but not stamped. Plan: one engine change (stamped flags), then one osis-sync part with three pieces of state.
> Priority: normal
> Tags: sync

What it costs: an aspect a node computed from less than another holder (a body dropped as covered counting as never received, a part pending at its expiry) stays apart until the next write of that data (notes/engine-suspects.md, The limit it backstops). Reads diverge only in those rare shapes; no data a writer holds is lost.

Why it is not one contained part: the sending side needs an engine change first (Fathom's), and the receiving side needs streams' first-sync state and a reporter identity, each a reading to settle.

Plan:
- **Engine (first, Fathom's review)**: `suspect::store` only calls `tx.core.touch()`, a whole-engine generation, so an `Effects` key over `Engine::suspects` would rescan `q/` at every engine change. Stamp each `q/` write per (thing, aspect) and the list whole, so a reader follows the flags alone; dormancy (`receipt::settled`) moves with held snapshots, so the stamp must also move when a snapshot of a flagged aspect is applied or turns invalid. Add `suspects_of(s)`: the flagged, not dormant aspects of things in S's closure (the engine's `carrying(t)` inverted per flag), most recent first, each with `state_digest`; aspects with no known creation record left out.
- **Sending** (osis-sync, `inbox/suspect.rs` beside `stranded.rs`): one `Effects` key per read S over `suspects_of(s)`; per (connection, member S) the digest of the last list sent (memory only: a new connection is a new join, which sends again). On `Moved::Joined` and on a settle moving S's list, send it chunked to `MAX_MESSAGE` (an empty list sends nothing; a list going empty sends nothing either: the peer's repair is idempotent). Bound: one digest per (connection, S), dropped on `Moved::Left`.
- **Receiving**: for each entry, act only when this node may write the aspect (`Engine` role check on the thing), S's first sync here ended (spec/sync-streams.md §5; streams has no per-S "first sync done" value yet: add one, stamped), it holds state of the aspect, and its own digest differs. Then `Engine::snapshot` unless a row `(reporter, thing, ak, own digest)` says it already wrote one from this state for that reporter; the snapshot is an own commit, logged as any (read's own-commit path). Reporter: the peer's proven node, else its account (a peer proving neither is answered Ok and not acted on: no durable identity to bound by). Rows durable (old scenario suspect-repair-per-launch: once per launch is not enough), kept while the aspect's state is that digest; bound: one per (reporter, aspect) (a new state replaces it). Each judged entry a `DiagnosticKind::Repair`.
- **Tests**: fast, on a fake ground: a flag sent at join, again on change, not at an unchanged list; an entry repaired once per (state, reporter), not again after a restart, again after the state moves; not acted on before the first sync, without write, without state, or with an equal digest. One World test: a pending-expiry flag at a reader repaired by a writer.
