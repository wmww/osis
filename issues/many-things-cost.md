# What a node holding many things still pays per write
> Summary: Making one plain thing under the account root still grows with what is held (debug instructions, averaged over 100 makes: 39 M at 100 held, 48 M at 200, 55 M at 400): paged state decoded again per join and judgment, debug-only whole checks, and small remainders in read and drop settles. A 2000-thing commit costs about 17 M instructions per thing (debug).
> Priority: normal
> Tags: engine, sync, performance

Measured with `tools/icount` (per make: the run with 100 more makes less the run without, divided by 100; 20 makes swing with where compactions of `holds.0` fall) and `tools/cpuprof` on osis `it` (debug), profile shares scaled by the instruction count. What one thing stores, downloads and signs, and the changes left for it: notes/thing-cost.md.

- **Paged state decoded again.** The account root's `holds.0` gains a strong per make; it pages from about 75 strongs (notes/engine-paged.md), so a make writes one 3-6 KB page and store bytes per make are flat (`scale::a_set_grown_one_element_a_write_writes_what_it_gained`). Its CPU is about what the whole write cost (100-make averages: 35/45/58 M at 100/200/400 with the state written whole up to 64 KiB): each join loads the pages the delta's dots reach (`ensure_touch`, about 3 page loads per make) and evicts them after, and each piece read against the state (`Tx::state_at`) loads and evicts the pages it reaches, all of them for a snapshot of the whole set. Keeping a session's loaded pages across transactions (bounded) would make these one decode each.
- **Debug-only whole checks** grow with every held commit per transaction: `validity::misjudged` after each re-judge (about 4 M of the growth), `Timeline::check_first_held` (about 1.7 M). Release builds skip them; tests pay them, so a test's runtime grows with n squared.
- **Small remainders**, about 1 M each from 100 to 400, unexplained: sync `Read::settle` (`drop_body` via `retention::drop_part_for`), `Engine::follow`, `Status::held_elsewhere`.
- **Per thing of a big commit** (`commits::changes_on_as_many_things_spec_requirements_decentralization`, 38 G at 2000 things): `write::framing_for` and `follow_certificates` (a `Piece::Chain` per thing, each naming the account's commits). A commit's delete keys are found once per delete base (`secrets::KeyCache`, `published_keys`).
