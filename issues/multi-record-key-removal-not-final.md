# A key with several entries: a removed element shows again, and the sweep misjudges
> Summary: Under one map key with several live entries (concurrent puts), an element's creation, edits and removal can sit in different entries' records, and which records join the read changes as entries die. So a removed element reappears in an honest history (removal is not final), and the sweep, judging record by record, resets elements a node holding more still shows (`tests_life::sweep_laws_spec_sync_7`). Needs a design decision on multi-record keys.
> Priority: normal
> Tags: crdt, tess-call

Honest reproducer (osis-crdt ops, map of `list<int>`): x and y put `k` concurrently (`[1]` and `[2]`), so `k` reads `[2, 1]`. z deletes y's element: the reset goes into the lowest live entry, x's record (§5.6 path ops), and `k` reads `[1]`. w, who saw only x's put, removes `k`: x's entry is reset, y's survives as a concurrent add. `k` now reads `[2]`: the deleted element is back, because its removal lived in x's record. Violates "removal is final" (spec/requirements.md Data model, spec/crdt.md §1).

The same split breaks the sweep (spec/sync.md §7), whose premise is that removal is final. It judges each live record alone (with its key-erased record), so it resets an element that shows in the key's read when its creation sits in another record: another live entry of the key (seed 2990), or one not live yet because its entry's creation has not arrived (36965). Judging the join of the key's live records instead pulls in another record's list reset (fails at 35189) and still misses records not live yet. `sweep_laws` fails at most `OSIS_CRDT_SEED` values tried (5, 25, 2990, 36697, 36965, ...: the map-of-list types reach a key with two entries easily); reproduce with `OSIS_CRDT_SEED=5 cargo test -p osis-crdt --lib -- sweep_laws`. The gate rarely sees it because the committed seeds pass.

Direction to decide: a write into an element or entry goes into the record holding its creation (not the key's lowest live entry), so an element's removal lives and dies with its creation; or a key's records merge into one entry. Either way the sweep then judges per record, which is sound.
