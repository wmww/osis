# A part missing again turns invalid and stays missing, keeping its thing's record
> Summary: osis-engine `order::held_set_decides_plain` seed 915130969958 (length 60, settled): a node shows a released-elsewhere thing's roster (its mint admin's edge) where the keep-everything node shows none. Cause: a part dropped while invalid, valid again (missing, to fetch), then invalid again before it arrives stays `Missing`; a missing part makes its commit's other things needed (`retention::needed::needs`, `waiting`), so a record the node would drop stays.
> Priority: normal
> Tags: engine, tests

Replay: `OSIS_ORDER_SEED=915130969958 OSIS_ORDER_LEN=60 cargo test -p osis-engine --test it -- --ignored --exact order::held_set_decides_plain`; the shrunk history fails in a random order (order #4), not under `NAMED`.

What the shrink shows: commit C mints Y (its `created.0`) with the strong on G's `holds.0`. At the failing node C's part on G is dropped while invalid, valid again after a later removal arrives (`retention::valid_again`: missing, to fetch), then invalid again after another arrives: it stays `Hold::Missing`. `needs` counts a held commit's missing part on a thing in the node closure as a need of the commit's other things, so Y's record stays and its roster reads Y's mint admin. The keep-everything node, given the commits as made, holds C's part dropped while invalid: Y is released and its record goes (roster empty).

`retention::drops_invalid` says an invalid part is neither held nor missing, and `reopen_to_fetch` drops a reopened part judged invalid as invalid, but `drop_invalid` only drops held parts (`goes_invalid`), so a missing part turning invalid is never converted. Likely fix: a missing part judged invalid drops as invalid (no body), its commit put on `drop_due` (`Core::put_meta`, `index_validity` mark only held invalid parts today); check it against late parts of a first receipt (`ingests` with a split), which the same rule would turn dropped-while-invalid until valid.
