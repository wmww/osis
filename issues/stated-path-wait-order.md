# A part's path wait reads grants in any order, the spec writes ordered before
> Summary: spec/commits.md §4 Unjudgeable: an edge of a part's stated path has arrived when a held edge write on it, not itself unjudgeable, is ordered before the part (a removal counts). The engine (`validity::unreached`, `Held::granted_on`) and held-model (`model.rs` `unreached`, `granted`) read any held applied grant, whatever its order, and no removal. Recommendation: bring both to the spec.
> Priority: normal
> Tags: engine, permissions, tests

Why the spec's rule: a grant ordered after the part is no evidence the writer relied on. Read as arrival, it applies an honest part whose earlier grant has not come yet, judged invalid, and its body is dropped (spec/commits.md §4 Provisional: it comes back only from a node still holding it); waiting keeps it. Every write ordered before an honest part is one its writer's walk read, so the wait ends once that write arrives: no new stall. A removal ordered before the part is evidence like a grant (as for the key hop); it is judgeable only along a granted path, so only the thing's admins can set it, and a forgery along such an edge is judged invalid. Writes that are themselves unjudgeable never count: a forged write stated along an ungranted path must not make honest parts wait (the "latest such is itself unjudgeable" reading let one forged entry stall every later part on its edge while carried). Both rules are functions of the held set.

What changes: `Held::granted_on` keeps each edge's writes by order key (grants and removals, joined parts of applied commits), `unreached` takes the part's key; held-model's `granted` likewise; `paths::` and engine `evidence::` differentials after. Tests that state today's reading and flip: `receive::a_part_waits_for_the_edges_of_its_stated_path_spec_commits_4` (o's grant stamped after the write: the write keeps waiting), `receive::a_removal_leads_no_author_to_a_thing_spec_commits_4` (the removal ordered before the forgery: its part on t applies, invalid).
