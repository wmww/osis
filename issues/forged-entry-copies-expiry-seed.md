# Expiry does not commute with join: a Derived creation prunes a flag, then expires whole
> Summary: A forged `Derived` text creation above a flag write on its element prunes the flag (§4.2), and expiry then takes the creation entirely (§4.7 Embedded character), so stripping before the join keeps a flag-only record that stripping after drops. Two spec rules conflict; needs a design decision. Found by `tests_laws::entry_copies::forged_entry_copies_join_and_expire_alike_spec_5_6` at `OSIS_CRDT_SEED` 917311, 4402113, 77310519, 2854516606.
> Priority: normal
> Tags: crdt, tests

Minimal case (two text fragments, no map): `a` holds element `D = Derived(x:5):1` created at `(ts+4, D)` (a forged write of its own: later than the embedding's `ts`) with char `z`; `b` holds a delete of `D` at `(ts, y:17)`, below it. Strip everything: `strip(a ⊔ b)` is empty (the creation beat and dropped the flag, then went); `strip(a) ⊔ strip(b)` keeps the flag-only record. Reads agree (no creation, nothing shows), states and snapshot bytes do not.

Why: every other value-carrying write expires value-less and keeps beating what it beat (§4.7 Read). A `Derived` creation cannot (the value-less register's embedding has no chars, so strip takes it whole, `derived_anchor_outlives_its_register`), yet prune lets it destroy a flag below it (`seq::beaten_from`, crdt-model `prune` floor). Honest states never hit this: an honest embedded char sits at `(s.ts, Derived(s.dot), i)` beside the embedding's reset at `s`, which prunes every flag below it anyway. Only equivocated/forged `Derived` creations (other stamps of `s.dot`) do.

Options (none taken):
1. **No creation prunes a flag** (uniform): the char stays one register by stamp (read already compares, `SeqElem::char`), a beaten flag stays held like `prev`; "deleted" means the winning flag everywhere: wire `Content` (chars carried for elements whose winning flag is not a delete), presence, `drop_deleted_chars`/`drop_local_chars`, death/winners, remap, model wire and prune, held-model. Removes `beaten_from`/`drop_beaten_flag`. Keeps c9d7f8ca1's guarantee (a node drops a creation's char only under a winning flag, and a reset pruning that flag prunes the creation). Wide: §3.2 Content, §3.3 rule 5/7, §4.2, §5.7; seq wire code (touches seq files Halyard's paste work may be in).
2. **Only a `Derived` creation spares lower flags**: same consumers as 1, fewer states hit, plus a carve-out.
3. **A flag always beats an embedded creation**: small code, but brings back the forged-only limit c9d7f8ca1 removed (a reset between the flag and the creation shows the char only where the node kept it).
