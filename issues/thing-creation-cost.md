# Creating many things in a group costs O(k^2)
> Summary: One commit creating k things costs O(k^2) record hashes (`commit_in` scans the creation records per aspect; 10^4 things in one commit: 436 s, release), and every commit creating a thing under a group re-evaluates the group's whole membership component (O(things); 10^4 things 100 per commit: about 400 s at both nodes). Found by `scale::sync_aspect_pass_cost`, whose closure setup now creates 500 per commit.
> Tags: node, perm, performance

Repro: `OSIS_SCALE_N=1000 OSIS_SCALE_CLOSURE=10000 cargo test --release -p osis-node --test it -- --ignored --nocapture scale::sync_aspect_pass_cost` with the setup's batch size changed (it prints the closure setup time), plus `osis_node::costs::take()` around the setup for the spans below.

- Within a commit (core/engine): `engine/write.rs` `commit_in` (`created_here`: `plan.creates.iter().any(|r| r.tid() == tid)` per aspect), `check_authority`, `within_depth`, and `engine/secrets.rs` (two more `created.iter().find(..tid()..)`); `CreationRecord::tid` hashes the record on each call, so O(aspects x creates) hashes. At the receiver, `apply/atomic.rs` (each new thing's `/created`) iterates every held aspect (`tx.core.by_aspect.iter().filter(|((t, _), _)| *t == a.tid)`), O(creates x held aspects): 11 s for the 10^4-thing commit. Fix: tids computed once per commit (a map passed where the slice is now); `by_aspect` (a `JSetMap` keyed `(Tid, Ak)`) ranged by thing.
- Across commits (perm `incremental.rs`): `Timelines::append` declines when a touched thing's `/created` is new to its component (`inputs.2.contains(t) != held.created(t).is_some()`), so `update_touched` re-evaluates the whole region: at 5000 things, 100 per commit, the `timelines` span took 15.7 s over 50 commits at each node (about 0.13 ms per thing already in the group, per commit). A thing created under a group with no membership commits of its own changes no walk; `append` could join it as it joins a lone node.
