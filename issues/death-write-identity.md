# A death names a stamp, not a write
> Summary: `osis_crdt::Death` carries the dead write's stamp, not its position, and a stamp names many writes, so `replaced_at` judges a snapshot's writes by counting reports per stamp; `carried` dates a snapshot early when a later snapshot holds as many dead writes of a stamp, killed alike, but other ones (reproduced: history lost under keep-for-D).
> Priority: critical
> Tags: retention, crdt, engine

A snapshot's dating is per write (spec/commits.md §5: the latest death among the writes it carries that no later snapshot with at least its D carries). One write op stamps many writes (every value of a map set or struct replace shares the delta stamp), so `carried` counts reports per (stamp, killer) and `snapshot_deaths` per stamp as a stand-in for which writes died.

- `carried`, reproduced (osis-node `retention::repro_death_write_identity_carried_by_count_*`): P sets k1-k3 of a kept map (one value stamp). W beats k3, W2 beats W, X beats k2, each unseen by the others' writers; a reset R comes after all. Snapshot C (after W) holds P's k1, k2 and W; L, later (after X), P's k1, k3 and X. R kills three writes of P's stamp in each, so L counts as carrying them, and C dates at W's death (W2) instead of k2's (X). P itself dates at W's death, so from W2 + D to X + D nothing at a node holds k2's history once C is dropped as covered. A carried write of another stamp than the dead one is needed for it: the write that kept C from holding k3 must be dead too, at an earlier death than k2's.
- `snapshot_deaths`, not reproduced: one join reporting a write twice (a record pair's cross death, spec/crdt.md §5.6, beside a new record's `report_deleted`) could reach a stamp's count before all its writes are dead. Within one whole join each write seems to be reported once; not shown either way.

Direction: dead writes as a true set of positioned writes. Either each death carries its write's position (path and slot, per element in a range record), threaded through every crdt join and prune that reports one, or, likely simpler, the dead set is computed as a fragment: the part's writes absent from the part joined into the state (a side-by-side walk), `carried` asks whether a later snapshot holds each of them exactly (not dominates: `Fragment::contains` would count L's X as carrying P's k2), and a snapshot is dead by a body when none of them survive the join with the bodies so far. Then `counts` goes, and `deaths` can stream again (a set dedupes the creations a page piece repeats on its path). A study should first check that range records and records of one dot give the same position in every fragment.

Study findings (fragment direction):
- Range records agree: element k of a record is `seq_span::piece(.., k, 1)`, which gives the same writes as a record of that one dot (creation `(ts, nth(d, k))`, the shared flag write), provided a record's creation `pos` entry counts as its creation, as the crdt already treats it (`join_pos` and `prune_fields` skip `s.dot == d`).
- "Absent from the part joined into the state" is not §4.8 death: three of its cases leave the dead write in the fragment. A sequence position write beaten as `cur` stays as `prev` in the top-2 (`join_pos` reports it); a text creation dies at a delete but its record keeps it (`Changes::deleted`); a write in one record of a map dot beaten by one in another record of the dot stays in its own record (§5.6, `state::cross_deaths`). An absence-based dead set misses all three (a text delete would leave the inserting body never replaced).
- So the fragment direction needs a positioned "winning writes" of a fragment (held-model's state is exactly that set): positions by dot (a map entry by its dot alone, its records joined as one entry; `Slots` transparent; sequence elements per element), with those three cases restated beside the join, and a crdt law test that `winners(A) \ winners(A ⊔ B)` names exactly the stamps the join reports dead. The alternative is a position in each `Death`, threaded through every join and prune that reports one.
