# The writer's copy-expiry probe resolves a write against the whole state
> Summary: `write::copy_expiry` (spec/crdt.md §4.7 copy expiry) runs each of a write's ops a second time, alone, against the whole state (`tx.state`, every page loaded, cloned) whenever a held delta of the aspect has an expiry ahead. A chat with disappearing messages pays O(aspect) per write: about 4x a write's cost at 2000 messages.
> Tags: engine, performance

The probe also scans `ix.by_aspect` for an expiring header per write. Cheaper shapes: resolve once and re-split when a cap applies (the split runs before the resolve today, and form, counters and chunk framing depend on the group), or probe only the pages the ops touch (`load_for_ops`). Rough measurement (review of copies-gone, when the probe ran the ops together, test profile, one node, a map of n expiring messages, 50 more expiring puts): n=200 about 8 ms per write with or without the probe (noise); n=2000 about 85 ms with it, 20 ms without. `scale::` has no write-into-expiring-aspect case.

Beside it, pre-existing on main: each expiry rebuilds the aspect from every held body. Release, n=2000 expiring messages, one expiring per tick: about 120 ms per expiry on copies-gone, 450 ms on main (n=200: 6 ms and 23 ms); a disappearing chat pays O(messages) per message. The branch's always-full walk (no early stop while the value-less list changed) costs nothing measurable here.
