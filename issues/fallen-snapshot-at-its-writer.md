# A writer's own snapshot that falls and rises loses a copy it vouched for
> Summary: `order::arrival_order_settled_large` seed 73310002 (and its `_purges` twin): a writer holding no right in its own view drops its own snapshot under a relative keep at most (invalid, dated at its own `ts`); valid again it is missing, so its next snapshot lacks the invalid delta's write the first one vouched for. Every node reads less than the keep-everything oracle. Harmless shape, one seed in 200; the oracle needs a decision.
> Tags: engine, retention, tests

Replay: `OSIS_ORDER_START=73310002 OSIS_ORDER_SEEDS=1 OSIS_ORDER_SHRINK=0 cargo test -p osis-node --test it -- --ignored --exact order::arrival_order_settled_large_spec_commits_5`. Fails in `live_write_lost` ("given every body again": `t:map.0` reads `{}`, the oracle `{k0: whole}`). Main passes all 200 seeds from 73310000; the branch fails only this one.

The lost value is the write of a delta invalid everywhere (it breaks a required retention), read only through the valid snapshot's copy; real nodes all read alike, without it, once that snapshot's bound passes. Only the oracle keeps the snapshot for good. Exempting snapshots from `retention::falls` makes the seed pass, but then a forged snapshot parks its bytes at every reader. Options: leave the rule and excuse this shape in `live_write_lost`, or exempt only a node's own commits from a fall.
