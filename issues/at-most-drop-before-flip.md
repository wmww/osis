# Keep-at-most drops before a validity flip depend on order
> Summary: A body under keep at most dropped when its write was killed stays dropped if the killer (or the body's own write) later turns invalid, while a node that judged it invalid first never drops it: nodes holding the same commits then differ in what they hold (spec/requirements.md Decentralization).
> Tags: retention, node

Repro: the order harness with keep-at-most-0 writes by members (order.rs restricts ops 18-20 to the owner because of this); shrunk: `vec![Write { by: 2, t: 4, op: 18, k: 2, v: 4 }, Write { by: 1, t: 6, op: 18, k: 1, v: 4 }, Demote { by: 0, t: 4, member: 2, at: 3, to_read: false }]` (seed 1053), and seed 1024 `vec![Write { by: 0, t: 7, op: 18, k: 0, v: 9 }, Edge { by: 0, t: 0, member: 2, role: Some(Read) }, Write { by: 2, t: 4, op: 18, k: 2, v: 4 }]`.

The drop is irreversible (the bytes are erased); a revived write survives in the state only if it was live there. Directions: delay drops under keep at most while a killer's validity can still change (it always can, offline admins), or accept and state it in spec/commits.md §5 next to "bounds may differ between nodes until they hold the same commits".

Victim variant (the dropped body's own write turns invalid; its bound runs out first in one order, while a node judging it invalid first never dates its death, so never drops it): op 17 (keep at most 30 min) by a member, demoted with a backdated frontier, time past the bound; a wider tier-2 run (`OSIS_ORDER_SEEDS=300 OSIS_ORDER_LEN=30`, 23 ops) found seed 1085 `vec![Write { by: 2, t: 6, op: 17, k: 2, v: 7 }, Write { by: 0, t: 6, op: 17, k: 1, v: 4 }, Demote { by: 0, t: 0, member: 2, at: 0, to_read: false }, Advance { who: None, ms: 5203966 }]` and seed 1200 `vec![Demote { by: 0, t: 7, member: 1, at: 5, to_read: true }, Write { by: 1, t: 5, op: 17, k: 0, v: 1 }, Write { by: 0, t: 5, op: 17, k: 0, v: 5 }, Advance { who: None, ms: 5183786 }]` (order.rs does not restrict op 17).
