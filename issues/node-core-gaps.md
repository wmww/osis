# Node-core residue: membership-heavy changes
> Summary: Granting someone new to a large tree still re-judges every change in it (about 12 ms at 10^4 changes, linear); a change becoming valid again re-reads every held change of its aspect; opening still scans every commit record (no header decoded but linked ones), adapts every membership change from its view and `node/edges` row and restores the walk over its whole input (O(commits), no bodies decoded).
> Tags: node, permissions, performance

Repro: `cargo test --release --workspace --test it scale::membership_change_and_open_cost -- --ignored --nocapture`; flips: `scale::validity_flip_cost_spec_permissions_5_2`.

Done (notes/node.md: Validity, Snapshots vouch for nothing, Snapshots, Import, Open, Rollback): saved walks, the persisted index, journaled rollback, re-judging per changed timeline, the `node/edges` rows, the pass work sets of re-examination; validity that only falls un-merges in place (O(touched pages), no body read: a revoke flip 719 -> 28-40 ms, an invalid delta arriving 704 -> 4-6 ms at 10^4); the re-judge looks things up once per thing and asks perm once per (thing, author, role) (`Timeline::valid_from`): one grant at 10^4 26 -> 12 ms.

Remaining:
- A change that perm evaluates anew (a member new to the component joins it, an out-of-order or dropping write, an epoch start change) still visits every delta of the component: about 1 µs each, now mostly the walk over `by_thing` and the commit metas (memory-bound lookups) plus perm's query for deltas before their author's standing tenure. Skipping deltas whose answer cannot change needs perm to report, per evaluation, which (node, thing) answers moved (e.g. comparing each author's role history and demotions on the thing before and after): perm's timeline update, out of node's reach.
- Validity becoming valid again (a part or a carried write) rebuilds the aspect from every held body (O(aspect history)): re-merging needs them (a register's earlier value, another's write nested under a revalidated creation come back only from the bodies). So does a fallen write that superseded another in the state (a register, reset, flag or move of the invalid delta). A bounded re-merge would need an index of which bodies hold writes nested under or superseded by each delta.
- Open is still O(commits), not O(what changed). Split before lazy headers (release, load 25-100, 10^4 content + 10^4 edge writes, open 0.28-0.37 s): commit record scan about 45 ms, generic header decode 26, typed header 10, ID hash 6; metas 52 (per-aspect index derivation 20, parts rows 9); adaptation 64 (rows 18); walk restore 65. Done since (notes/node.md Open, Lazy headers): headers decoded on first use (`LazyHeader`), open indexing from each commit's persisted `View` (`node/metas`), adaptation from the view (frontier and chunk list now in it) and the `node/edges` rows, no header decoded at open but linked ones; `Core::by_chunk` and `by_thing` replaced the per-pass and per-write scans of every header. Now (release, load 6-12, least of three): 10^4 content commits open 59-67 ms; plus 10^4 edge writes 190-200 ms (headers 25, metas 42, adaptation 50 of which rows 15, walk restore 61-68). Each phase is still linear. Next steps toward O(changed):
  - Fetch a header from the store on first use instead of keeping its bytes (saves the open's record scan, the headers phase, and the bytes in memory). Not clean yet: store reads need `&mut Store` (a `Transaction`; the pager caches), while the readers are `&self` (`Engine::header`, the `Deref` of `LazyHeader`, sync's direct `core.commits` reads, about 180 sites) or run inside a transaction that already holds `&mut Store` (a second handle would alias). Shape: readers in a transaction go through `Tx::header(id)` (fetch via `tx.txn`, cache in the meta); `&self` readers get a read-only handle on the last committed root (`Store::reader(&self)`, pager behind a lock), or become `&mut self`; `LazyHeader` then keeps the view and an empty cell.
  - Load `by_aspect`, `ranges`, `invalid`, `by_chunk` per aspect on first touch from persisted rows (the metas phase).
  - A held set and perm timeline restorable per component without the whole input (walk restore: gathering the component's `Input` 15-27 ms, perm's partition and `Timeline::from_outcome` most of the rest; osis-perm).
  - Whole-map iterations over `Core::commits` left on rare paths decode every header (`held_commits` without a scope, forget's lost aspects, debug checks).
  Measured and set aside: a walk tag over a persisted hash of its inputs saves only the tag hash (5-8 ms); persisting perm's adapted records instead of the rows saves about the adaptation's own work (40-50 of 76) at the risk of runtime and open adaptation disagreeing.
