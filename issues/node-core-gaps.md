# Node-core residue: role-heavy commits
> Summary: Granting someone new to a large tree still re-judges every commit in it (about 12 ms at 10^4 commits, linear); a commit becoming valid again re-reads every held body of its aspect written in parts; opening still scans every commit record, adapts every role commit and restores the walk over its whole input (O(commits), no bodies decoded).
> Priority: low
> Tags: engine, permissions, performance

Counted: osis-engine `scale::grant_is_flat_in_content_commits` (open reads every header: O(commits)); `scale::validity_flip_is_linear_and_invalid_arrival_flat_spec_permissions_5_2` (a rebuild from every body). What is built: notes/engine-validity-rejudge.md, notes/engine-validity-rebuild.md, notes/engine-store.md Open.

- **Re-judging.** A commit perm evaluates anew (a holder new to the component joins it, an out-of-order or dropping write) visits every delta of the component: about 1 µs each, mostly the walk over `by_thing` and the commit metas plus perm's query for deltas before their author's standing. Skipping deltas whose answer cannot change needs perm to report, per evaluation, which (node, thing) answers moved: perm's timeline update, out of node's reach.
- **Valid again.** Rebuilding the aspect from held bodies stops at a whole-value write (`Fragment::settled_above`), but an aspect written in parts (a map's entries, a list's inserts) reads every body (O(aspect history), 60-170 µs per body), and so does a fallen write that superseded another in the state. A bounded re-merge needs an index of which bodies hold writes superseded by each delta.
- **Open is O(commits).** Release, 10^4 content commits: 59-67 ms; plus 10^4 edge writes: 190-200 ms (headers 25, metas 42, adaptation 50, walk restore 61-68). Each phase is linear. Steps toward O(changed):
  - Fetch a header from the store on first use instead of keeping its bytes (saves the record scan, the headers phase and the memory). Blocked on borrowing: store reads need `&mut Store` (a `Transaction`; the pager caches), while readers are `&self` (`Engine::header`, `LazyHeader`'s `Deref`, sync's direct `core.commits` reads, about 180 sites) or run inside a transaction already holding `&mut Store`. Shape: readers in a transaction go through `Tx::header(id)`; `&self` readers get a read-only handle on the last committed root (pager behind a lock) or become `&mut self`; `LazyHeader` keeps the view and an empty cell.
  - Load `by_aspect`, `ranges`, `invalid` per aspect on first touch from persisted rows (the metas phase).
  - Restore a held set and perm timeline per component without the whole input (walk restore: gathering the component's `Input` 15-27 ms, perm's partition and `Timeline::from_outcome` most of the rest; osis-perm).
  - Whole-map iterations over `Core::commits` on rare paths decode every header (`held_commits` without a scope, forget's lost aspects, debug checks).
  - Rejected: a walk tag over a persisted hash of its inputs (saves only the tag hash, 5-8 ms); persisting perm's adapted records instead of the rows (saves 40-50 of 76 ms at the risk of runtime and open adaptation disagreeing).
