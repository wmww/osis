# A join's placement prefetch: a move loads the whole placement, the round cap drops it
> Summary: the join's prefetch of a paged sequence's stored placement (`pages::prefetch`, `Fragment::dry_follow`) is wrong both ways. A move of 4 chars in an 80k-char text in a new session misses blocks until the budget runs out, loading every placement block (about 110; 1046 at 800k) where an insert or delete loads 3. And the cap of `PREFETCH` (8) dry runs gives up below the work budget, so a received concurrent move drops the stored placement (the next read by index rebuilds it).
> Priority: low
> Tags: engine, performance

- **Move cost**: O(text) in placement blocks, whether the target is 50 chars away or far; spec/requirements.md Scale wants O(change). Inserts, deletes, edits, undos and reads by index stay flat (`scale::text_edits_are_flat`, by hand). Repro: osis-engine `scale::repro_text_move_loads_placement`. Start from the `PlaceMisses` the move's `dry_follow` reports per round.
- **Round cap**: each dry run can reveal one more missing row, so a move into a region not loaded takes several rounds. `seq_cold_edits_keep_placement_spec_crdt_6_1` with its rngs at 0 meets a received move plus insert into a 4000-char text needing 12 rounds at 1270 work of a 4024 budget: the cap drops the placement and "placement kept" fails at step 27 (with the cap lifted it passes). The test keeps rng seeds 187, 189 until this is settled. Fix candidate: loop until no misses, the budget is spent, or a round loads nothing new; drop `PREFETCH` (notes/arbitrary-values-table.md, notes/engine-paged.md); set the test's rngs to 0.
