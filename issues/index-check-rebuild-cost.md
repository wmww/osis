# The end-of-history index check's rebuild cost
> Summary: The index check at each engine's drop (`Engine::check_index`) opens from the persisted index (with the open's secrets sweep) and rebuilds from the commit records: 15-20% of engine lib tests and over half of many engine `it` tests, the biggest debug-check cost; what is left is the rebuild's re-derivation and the sweep run twice. Checking only the rows each transaction wrote misses what the rebuild finds, so a cheaper check needs another design.
> Priority: low
> Tags: tests, engine

The check opens from the persisted index and rebuilds from the commit records (a second judging of the whole history, its records and parts not decoded again). What the rebuild catches that the open does not is a row the incremental code should have written and did not (planted: an edit's place left out of `originals`: 37 tests catch it, 16 without the rebuild). A per-transaction check of the rows a transaction wrote is blind to exactly that (17 of 37), so it is no replacement. A cheaper check keeping the property needs one of:
- a per-record derivation: for each record a transaction touched, every row it derives from that record alone, compared both ways (catches missing and stray rows of direct derivations; rows judged from other records, the arrival-order class, stay the rebuild's);
- the rebuild's own cost cut: it opens every live history entry again (`osis_keys` `open_histories` at every ingest) and decodes every state again (`observe_state`); cheaper loads are the product's open (issues/long-aspect-cost.md, Engine levers).

Where it goes (cpuprof, engine `it` `expiry_model::expiry_takes_its_commits_writes_spec_crdt_4_7`, 19.6 G): `checked_index` 65%, its `apply::load` 53%. The rebuild's placing of every recorded step (`Core::steps_recorded`, `sync_ids::steps::Recorded::of`: each step's signature verified, its four keys decompressed by `Step::parse`) 9%: the fast open takes the placed steps from `node/steps` and verifies none (notes/delete-keys.md, Placing), so what is left is the rebuild's, which must derive them; `Step::parse` decompressing the sync, write and deposit keys, which placing keeps only as bytes, is a third of it. The open's sweep (`flows::reopen_all`) 11%, run twice per check (after the fast open, and inside the rebuild's load): `secrets_decoded` (reading and decoding every `secrets.0` state, its pages) 61% of it, `ingest_secrets` 35%. In this test every sweep (232) is one round over 13 actors and learns nothing: at a fast open it rebuilds only `Waits::untaken` (memory) over epochs already persisted. Skipping it at a fast open needs `Waits::untaken` persisted, and the check then loses the open's half of its sweep oracle (a live index lacking what reading every state gives); not taken.

Rejected: reusing the live engine's decoded states (needs a bytes compare per state) or its opened boxes (memoized crypto: issues/test-time.md). Sampling the check is a Tess call (issues/test-time.md, Levers that need Tess).
