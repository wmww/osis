# Value-less writes living in the state alone
> Summary: Three ways a write ends up held only in an aspect's state, so an un-merge of a later write that superseded it there loses it and the result depends on arrival order: a late part of an expired or purged delta is skipped instead of joined value-less; a purged delta whose body was dropped as covered keeps no residue once the purge drops its coverer; a keep-at-most drop before a validity flip (spec/commits.md §5 "A drop is final", accepted by the spec but in conflict with spec/requirements.md Convergence).
> Tags: engine, retention, spec

Order seed 24111 fixed the main case: an expired or purged delta's body leaves a value-less residue (`w/`, `retention::make_valueless`), joined by `apply::atomic::rebuilt`. Left:

- **Late part after T or after the purge** (`order::repro_expired_late_part_skipped`). `on_apply` expires (or `purge_one` purges) a part still missing: no body, so no residue, and `drop_part` marks it dropped; `apply::late_parts` then skips the part when it arrives. spec/crdt.md §4.7 says a copy arriving after T is stripped of its values and joined ("another projection"). The whole commit hides an older value, the split commit shows it. Fix sketch: leave a missing part missing at expiry or purge (the value-less list already makes waits treat it as held), and have `join_late` expire or purge a late part on arrival (join it, store the residue, drop it). Only stale peers or relays deliver such a part (hosts drop expiring blobs at T). The order oracle misses it: its expiring writes (ops 27-29) are single-aspect commits, so split delivery never makes them late parts.
- **Purge of a covered delta** (`order::repro_purged_covered_write_lost_by_unmerge`). A body dropped as covered gives `make_valueless` no body, so no residue. The purge then drops the coverer snapshot, which leaves the delta's value-less write in the state alone. A later write that superseded it and turns invalid takes it along: the made order shows an older value, the demotion-first order shows nothing. The purger's re-snapshot (spec/commits.md §5) hides this when it reaches the node: it carries either the value-less write or the later write, which a valid snapshot vouches for. Without that re-snapshot (a purger that may not write the aspect, or before it arrives), the node diverges. Fix sketch: in `make_valueless`, when the body was dropped as covered, take the delta's writes from the held coverer bodies.
- **Keep-at-most drop before a flip** (`order::drop_before_flip_tolerated_spec_commits_5`, seed 1053). A body dropped under keep at most while its write was live, or once a later write killed it, leaves that write in the state alone or nowhere. If the killer later turns invalid, the write is gone at this node but present at a node that judged the killer invalid first. The divergence is permanent when nothing re-carries the write (at most 0: no carrier is written for a body with no live write). The spec accepts this ("A drop is final ... may differ"), and the order oracle tolerates it. A value-less residue cannot fix it: the other node holds the write with its value. This needs an owner decision. Either accept it in spec/requirements.md as an exception to Convergence, or date keep-at-most deaths only from killers whose validity cannot flip any more (there is no such notion today).
