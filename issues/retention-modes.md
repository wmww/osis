# Retention: three history modes
> Summary: Replace keep bounds with a per-write history mode (convenient | kept | none) beside purgeable-by and expiry (Tess). Every drop that is not expiry or purge is a right holder's covering compaction snapshot; a node without write drops nothing on its own but expired content. Death dating, carriers, carrier-only, keep bounds and their timers, keep-bound never-received, `Why::Flip`, dropped-snapshot liveness and crdt §4.6 "own state counts as a body" go. Decided (Tess): the history value is either `none` (gone once replaced) or keep-at-least-until T for T in [0, ∞]: 0 is convenient (no promise), ∞ kept forever, a finite T keeps and exposes the write's history until T (a duration is fixed into T at write time from the write's own `ts`). Expiry is the separate purge-at-T. Readers under none drop when a writer's covering snapshot arrives; none compacts at every replace; expiring deltas are kept to their T; `nobody` needs T = ∞; the purge floor stays.
> Priority: normal
> Tags: engine, spec, retention

## Model
- **convenient** (default): no promise, not in `history()`; a right holder compacts whenever it likes; its valid covering snapshot drops the body everywhere.
- **keep-at-least** (Tess, revised): until an absolute T and/or until D after replaced (T = ∞ forever). Enforced only as a limit on compaction and covered drops (every node alike, Readers below) and on what `history()` shows. "Replaced" is the earliest valid replacing write the node holds, by that write's signed `ts`; compactors may judge differently (each snapshot vouches); a replacing write that later turns invalid is the accepted compaction limit. `history()` shows an entry while the node holds no replacing write stamped more than D ago (and before T): a function of the held set, so nodes holding the same data show the same; nodes holding different replacements may differ, like any read. Earlier form, kept for reference: **keep until T** (T > now): must-hold and never compacted before T; leaves early only by purge or expiry; exposed by `history()` until T (H3, issues/history-verified-or-absent.md); after T it is convenient. T comes from the write (absolute, or `ts` + a duration fixed at write time), so every node judges it alike up to `MAX_DRIFT`; `history()` hides entries within `MAX_DRIFT` of T. T = ∞ is kept forever. `nobody` requires T = ∞.
- **none** (`writer` only): every writer holding the body that applies a write killing any write of it writes a covering compaction snapshot in that transaction; the body drops as covered everywhere.
- **Expiry** unchanged (content lifetime, unattended at every node). An expiring delta is never covered, so it is kept until T whatever its mode. **Purge** unchanged; the purge floor (ROLE_KEEP after the request) stays. ROLE_KEEP for keys/secrets/label becomes compactor policy.

## Uses
core.osis role aspects → convenient (+ROLE_KEEP policy); `created.0`, `required.0^` → kept (fixed); `purge.0` → convenient; notes `note:pinned.0` → none; chat messages → kept or expiry (chat `EditMode::Keep` needs kept); sim `s:latest.0` → none; absolute keep-at-most T (tests only) → goes; relative keep-at-least other than ROLE_KEEP: tests only.

## Survives of the R × D class
A cover that turns invalid (Uncovered repair, as today); a valid snapshot written after a kill that later turns invalid keeps the kill's copy (the stated Permissions limit, now at every none replace); expiry-pending and purge falls.

## Step 0 results (held-model, TLA sync; engine code untouched)
held-model models the modes (`Retention { by, history }` with `History::{None, Keep { until, after }}`, `Body::Dropped(cover)`, `Outcome::{replaced, replaced_at, history, owed, uncovered}`, `cover`, `snapshot_retention`; own state, carriers, death records and keep-at-most gone); seven random properties pass at 2400 seeds (AMBIGUITIES.md held-model-4 has the findings):
- state == join of held bodies: by construction in the model, and the TLA invariant `StateCarried` holds in every sync instance (no step leaves a live write in a node's state that no held body or snapshot carries), so crdt §4.6's own-state clause is not needed.
- nodes holding the same bodies read alike: the output is a function of the held set; a late commit, and the same commits arriving one at a time in any order with the node acting as they come, read alike once bodies whose cover or purge fell are fetched again.
- no right holder holds a replaced `none` body uncovered once it has acted (TLA: `NoneCovered`); a kept body leaves before its absolute T only by purge or expiry (TLA: `KeptUntil`, also for D after the kill as every node sees it); no node drops a D-bound body earlier than D after the earliest valid replacing write it holds (by signed `ts`; readers alike, the rule below) and `history()` (the replaced writes of kept bodies while their bound holds, a function of the held set) never shows a body the node may drop; demotions and re-grants are in the generator.
- Surviving shapes, exactly the expected three: a cover that turns invalid (the body is never received again and fetched; until then the node reads less); a valid cover written after a kill that later turns invalid keeps the kill's copy (nodes holding the cover read alike); expiry-pending (a part waiting past its expiry goes for good, so nodes differ by whether they applied it before T) and purge falls (fetched again).
- Two definitions the engine steps must follow. **Replaced** is "the body holds a write the canonical state does not hold" (write membership, what a snapshot from the state leaves out), not "has a dead write" (crdt §4.8): a root reset is dead once a later write implies one yet canonical form keeps it, so by deaths every cover of such an aspect is replaced for good and covers chase each other. **Covered-equal** snapshots at one `ts`: only the lower commit ID covers (sync §7), else two covers drop each other. A snapshot is `none` when it carries a `none` write live, else convenient. A local drop as covered needs no right of the dropping node (the snapshot's commit holds it); the spec's "the node itself holds it now" clause is for host deletion.
- No carve-out needed; the `none` fallback (writer purge per edit) was not modeled.

TLA sync (`SyncConvergence.tla`): timed deletes, keep-at-most, carriers-before-drop and `Serves` are gone; `NoneGone` (a covered `none` body is must-not-hold everywhere), `OwesCover` (a due snapshot), invariants `StateCarried`, `KeptUntil`, property `NoneCovered`. deposit, kept, none (228,943 states, 10 min), none_live and purge pass.

Today's engine against the model (`order::held_model_retention_modes_survey_*`, 36 histories, 33k aspects compared): the expected keep-bound failures and nothing else. Of 656 dropped bodies judged, 529 were keep-at-most-0 bodies the model keeps, every one at a node with no role on the thing (a non-member holder dropping at the bound with no cover: 216 replaced, 313 not even replaced, the engine's drop of an invalid body counted dead at its own `ts`), 81 keep-at-most-T drops; 102 covered `none` bodies still held (today's engine drops covered bodies only at compaction); 81 nodes whose state holds writes no held body does (carriers' own state), with 81 differing reads from the same drops. Writers' drops at the kill all had their carrier covering them. No validity, apply, purge, role or forbidden-value difference.

## Fallback for none (Tess)
If `none` as compaction-on-replace causes problems: `none` becomes `writer` purgeable plus the writer attaching a purge request for the replaced writes to each edit of such an aspect (generated automatically). Known costs from an earlier look (notes/engine-retention.md, writer-side purge): a purge cannot express a partial replacement of a body, a purge request is kept to its floor (ROLE_KEEP), and purged writes leave leftovers. Acceptable as a fallback ("a little more jank").

## Names (Tess)
"No history needed" is the default, never the delete-on-change option. The API and schema names carry this, not a doc line: the default is unnamed (no retention attribute: history not promised, not exposed, kept while convenient); keep-at-least is named for keeping (e.g. `keep_history: until T / for D after replaced / forever`); the delete-on-change mode is named for what it does, e.g. `purge_on_replace`, and documented as rarely the right choice because it costs more per change (public docs never mention compaction). `keep_history` until a past time or for 0 is the same as the default. Internal names (`none` above) follow the public ones when built.

## Readers under keep-for-D (decided, Tess)
One rule for every node: a body under keep-for-D is not dropped until D after the earliest valid replacing write the node holds (a function of the held set, not arrival order). Readers and writers holding the same data then show the same history.

## Small values (Tess)
Per-commit overhead matters less than extra mechanisms. Do: forget compacted headers when nothing needs them (growth row 1). Maybe: a whole replacement covering the old body directly, only if cheap. Don't: special commit forms for small durable writes.
