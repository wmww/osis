# A purge misses copies of a commit the node forgot
> Summary: A node strips a purged write's copies (snapshots carrying it) only while it holds the named commit's header. A node that forgot the header (own-cover forgetting, a purged leftover past its tombstone, or a new node) keeps those copies' values: the purger itself can read the value it purged, and its re-snapshot spreads it to every node.
> Priority: critical
> Tags: security, engine, retention

- Repro (main): the tombstone.rs `chat()` world, the register under no history (`net.keep(a, t, &[(GONE.ak(), History::PurgeOnReplace)])`). Writer b writes v1, then v2 (commit c2); admin a purges c2 by commit (`PurgeItem::Commit`). Before the purge a has already forgotten c2: b's compaction covered it, its author's cover (spec/commits.md §5 Forgetting). Then a reads v2 at once, `purged_on` is empty at a, and a node joining later reads v2. b, which still holds c2's header, reads None.
- Cause: a request names deltas by commit, and "a node judges a named delta once it holds the request and that commit's header" (spec/commits.md §5 Purge). With the header gone, nothing ties a snapshot's copies to the request. So a's own snapshot keeps v2 with its value. Its re-snapshot (`purge_resnapshots`) is written from that state and spreads v2.
- On branch eph-purge, a purged leftover is forgotten past its tombstone (`retention::kept_purged`). That node then behaves like a new node: in the repro, b too reads v2 after the window (from a's re-snapshot). The same happens without a's bug when an offline writer's old snapshot carrying the value arrives after the window.
- Direction to judge: let copies be judged without the named commit's header. For example, the request could carry the named writes' sources and ranges (sessions, as demotion frontiers do). Or a writer could refuse to purge by commit unless it holds the header, and purge by aspect or author instead. Keeping every purged header for good is another option, but it grows with purges, against notes/ephemeral.md and the forgetting rule.
