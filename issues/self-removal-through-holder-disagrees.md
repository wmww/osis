# Engine and perm judge disagree on a self-removal through a holder actor
> Summary: P1 holding admin on A only through group M removes M: the engine writes it as a self-removal (no frontier, no rotation) because `validity::self_removal` reads P1's role with M's edge left out, but the perm judge (`osis_perm::walk::judge`) counts edge-admin authority through M, so the write is no self-removal and no finalize and applies nothing. M stays a holder. Same for a node removing its own account's admin edge (a first admin's record edge included).
> Tags: perm, engine, keys, tests

Repro: `rotation::tests_departs::repro_own_group_removal_applies_nothing` (`#[ignore]`d). Spec (spec/permissions.md §2, Self-removal) says "through X included", matching the judge; then an honest removal would be an explicit demotion whose rotation P1 makes while leaving A, which leaks (issues/own-departure-named-by-own-entry.md). Reading it as the engine does (authority through X does not count) makes P1's write a self-removal: no rotation, the departure stays uncovered, and the leak's holder-actor shape goes. Pick one reading, change the spec and the other side to match.

Second shape (any build): account A (node n) holds an admin edge on T; n demotes A's edge on T (`Engine::demote`, holder A). The commit is written with no frontier and no rotation; `judged_valid` is false at n and A stays in T's roster everywhere. The same for a first admin's record edge removed by one of the first admin's nodes; the refused-case test `flows::last_admin_of_plain_thing_refused_spec_perm_1` uses a node as first admin (holder = author, a true self-removal) to avoid it.
