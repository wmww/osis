# What a node syncs follows group membership, not entitlement
> Summary: spec/commits.md §4 waits for deltas "under a label it syncs (entitlement, not group membership, decides)", but `Core::syncs` counts every thing a held `group.0` lists. A writer of a synced group can list another's private thing V: an honest commit across V and a thing the node holds then waits whole for V's part, which never comes, until the list changes. Same before `Core::syncs` (`sync_closure` was stickier). Not closed by reading `may_read`, as `commit_bodies_under` does: a private thing's record does not reach the node, so its reader actor is unknown there. Waiting when it is unknown keeps the hole; not waiting lets a host hiding a listed thing's record split every honest commit across it, and makes cross-thing commits show in part at every first sync while records are on their way (issues/sync-learned-after-apply.md's exception, for a common shape). Reading it only for a known record closes only the case nobody hits. Bounded meanwhile: a writer of the group can do this only while the listing stands, and an admin removes it. Needs a rule for who may list a thing, or the owner's call.
