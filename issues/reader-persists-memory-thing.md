# Any holder of a memory thing's record can make it durable
> Summary: a received memory commit carries its things' creation records, and a durable `created.0` part is always valid (spec/permissions.md, the record holds by its tid), so a reader can send a durable commit carrying only `created.0` of someone's draft and every node holding it persists the thing (`atomic::note_created`) for good. spec/data-model.md §1 has persistence come from a durable delta by a node that may write the thing.
> Tags: security, engine

Cost is small: the record (first admin, nonce) is kept forever at the thing's holders, the thing is never freed, its memory data stays memory. No content leaks and no right is gained; the reader needs a writer's promotion or a co-reader relay to reach hosts (spec/sync.md §3), and could spam durable commits of its own anyway. Breaks "a draft never given durable data is gone when no node holds it" for a non-writer. A fix would persist only on a commit that also validly writes a durable aspect of the thing (or one on its owned chain), which makes persisting depend on validity and so on arrival of grants; judge whether that is worth it before building.
