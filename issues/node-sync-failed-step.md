# Node sync relies on a restart after any failed engine transaction
> Summary: A node-sync step that meets a Local engine error (a one-off failed write: EIO, a full disk that frees up) stops there and leaves its in-memory state ahead of the store: a pushed entry taken but its commit's ingest failed is never opened again, and a failed `State::flush_storing` drops the blob bytes its kept writes need. The store and engine recover in place, so the node stays up and silently never gets that data until it restarts (`State::load`, `reconcile`, reopening entries).
> Priority: normal
> Tags: node, sync

- Reproducer: node `nodelog::a_failed_write_taking_bytes_needs_no_restart` (ignored on this issue): `Fault::Fail` at write 5 of node b taking a pushed event with its bytes (the engine's ingest commit in `open_entries`) leaves b reading "before" after five resync intervals.
- Mechanism: `ingest_failed` returns a Local error, the step ends ("a step that failed (a store gone) tries no more"), and what the step already took (stream position, entries recorded) stays in memory with nothing to open them again. `flush_storing` keeps `writes`, `log` and `paths` for the next flush on failure but not `blobs`; meanwhile the hub's store may hold the step's log rows from its own commit (committed before the engine's), while `Engine::settle_blobs` releases the failed transaction's holds.
- The store and engine side is settled (notes/local-store.md, Failed writes recover in place): a failed commit returns the store to its last durable state, the engine's rollback is exact and equals a fresh open (`check_index`).
- Direction: the same rule one level up: a node-sync step that fails on a Local error reloads node sync's state from the store as `SyncEngine::new` does (State::load with reconcile, entries reopened, connections closed and dialed again). Rare path, so brute force is fine. Patching each path (keeping the bytes, re-queueing the entry) is the per-path drift to avoid.
- The sims inject `Fault::Fail` (harness and net) but end in `run_until_quiescent`; check whether quiescence hides a stuck node (it restarts only nodes that are down).
