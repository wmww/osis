# A reader's static-entry Hit opens L for a dialer that cannot read it
> Summary: on a connection a peer dialed, a reader holding a key actor whose static entry L's head lists still Hits it where the dialer's filter shows it; a dialer keeping L's claim sets answers with the tag and the grant, proving nothing, and the reader then serves it L, against spec/sync.md §5 Opens (a dialer that cannot read L opens it only by proving the sync secret).
> Priority: normal
> Tags: security, node

- **Exposure**: `shared_test` tests a held key actor's static entry (`STATIC`, a Static item) on every connection, whatever actors the dialer proved. A dialer keeping L unread shows its head's claim-set entries in its filter, accepts the Static item (`static_signed`) and answers tag and grant from its own claim set (`unread_grant`); the reader's `granted` checks the path and box, which a node keeping L holds genuinely. So any node that keeps L's steps and claim sets (one `label.0` no longer lists, a stranger included) pulls L's ciphertext and its later events from a reader holding a key actor listed on L's head (a link redeemer) by dialing it.
- **Reflection**: the Static item's open signature is made by the listener over the dialer's Hello challenge, which the dialer picks. A dialer that copies the reader's challenge from another connection to it gets the key actor's signature over that connection's bytes, which the reader then accepts as a Static item from that dialer where it proved a known actor (unless two such connections cannot coexist). Same outcome as above; the fix must close both: no open signature from a listener, or a side byte in the open signature's digest (as the connection proof has).
- **Why not skipped at a listener today**: a redeemer that dialed nobody yet opens L by this Hit when a reader dials it before it holds the read secret, and `shared::{a_forged_grant_is_not_offered_again_spec_sync_10, a_forged_head_and_box_teach_nothing_spec_sync_10, a_substituted_box_teaches_nothing_spec_sync_2}` script exactly that (a hand dialer proving the sharer). Skipping static Hits on connections the peer dialed needs those tests moved to a hand listener, and a redeemer then opens only where it dials (the sharer, its link peers), which may be the intended rule.
- 6c's entitlement check decides it: a peer that cannot read L opens it only by proving an entitlement, and a reader proves nothing on a connection it did not dial.
