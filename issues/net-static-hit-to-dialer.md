# A reader's static-entry Hit opens L for a dialer that cannot read it
> Summary: on a connection a peer dialed, a reader holding a key actor whose static entry L's head lists still Hits it where the dialer's filter shows it; a dialer keeping L unread answers with the tag and the grant from the claim set it keeps, proving nothing, and the reader then serves it L. The sync-key case is closed (the dialer proves the sync secret, spec/sync.md §5 Opens).
> Priority: low
> Tags: security, node

- **Exposure**: `shared_test` tests a held key actor's static entry (`STATIC`, a Static item) on every connection. A dialer keeping L unread shows its head's claim-set entries in its filter, accepts the Static item (`static_signed`) and answers tag and grant from its own claim set (`unread_grant`); the reader's `granted` checks the path and box, which a node keeping L holds genuinely. So a node that keeps L's steps and claim sets (a node `label.0` no longer lists) and knows the reader holds that key actor (a link redeemer) pulls L from it by dialing it. Only readers holding a key actor listed on L's head are exposed.
- **Why not skipped at a listener**: a redeemer that dialed nobody yet opens L by this Hit when a reader dials it before it holds the read secret, and `shared::{a_forged_grant_is_not_offered_again_spec_sync_10, a_forged_head_and_box_teach_nothing_spec_sync_10, a_substituted_box_teaches_nothing_spec_sync_2}` script exactly that (a hand dialer proving the sharer). Skipping static Hits on connections the peer dialed needs those tests moved to a hand listener, and a redeemer then opens only where it dials (the sharer, its link peers), which may be the intended rule.
- 6c's entitlement check decides it: a peer that cannot read L opens it only by proving an entitlement, and a reader proves nothing on a connection it did not dial.
