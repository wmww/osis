# A node removed from a thing never redeems a public link to it
> Summary: A node whose account was granted a role on X and then removed redeems a public link to X and stays pending until its follow time: the source shows a departed peer no public entry, the tester skips a static or public grant when it judges the replier a holder, and its lost-access rule refuses (or drops) the entry box's secret once its removal is held. A rule for the third is a security call.
> Priority: normal
> Tags: sync, engine, security

Repro (ignored): osis-sync `public::a_removed_grantee_redeems_a_public_link_spec_sync_set_4` (two contacts; node 1 grants node 0's account write on X, never held there, makes X public and removes the grant; node 0 redeems a public link to X: pending, reads nothing, gives up at the follow time). A node that held X by a strong reads it already (the public's grant reaches it with its departure), so the redeem only matters where it did not.

Three blocks, in order (each confirmed by trace and by a probe undoing it):
1. **Source, spec/sync-opens.md §4 Departed**: the public entry is shown at no epoch (`opens/holds.rs` `node_creds`), so the Departed rule keeps it from a departed peer. The box it gives carries the head's current read epoch: showing it at the newest read epoch held (`rc.read_secrets`' max) lets the Hit open and the answer carry the open box once that epoch covers every departure.
2. **Tester, spec/sync-opens.md §5**: `Opens::replier_proved` returns at once where J judges the replier a reader or sync holder, before taking a static or public entry's grant; a removed node still holds X's roster naming the replier, so it opens with no secret. The grant should be taken (after `sig` verifies) whatever J says; J only decides whether the replier counts proved. Alone this changes nothing observable (block 3 refuses the secret).
3. **Tester, spec/permissions.md §3 Lost access**: `learn_secret_in` refuses the box's read secret (`rotation::may_learn` false: an ended edge of the node's on X is held, and no role covers X since the public's grant is not held yet: it would come with X's role entries, which need the secret). Were it taken, `loss_seen` would drop it the same way before the role entries arrive.

Proposal for 3 (security: needs review): an epoch covering every departure known here is no loss, the tester's side of the source's Departed rule (one rule): `may_learn` also takes a secret at an epoch that `rotation::uncovered` finds covering every departure of the thing known here, and `loss_seen`'s ended-edge clause counts only while a held secret of the thing is at an epoch not covering it (needs `departures`, a memo read through a `Tx`, in `loss_seen`). Check: `uncovered_by` answers covered for an epoch whose keyset is not held at all, so a removed node would also take an unknown epoch's secret from a verified head; argue that or tighten it. Rejected: counting a secret an open box gave as covered while the head lists the public (a provenance carve-out); taking the open's role entries before judging the loss (an ordering rule).

Also seen: node 0's record of X says its secrets derive from its mint admin (X's independence came with the offer, dropped with the removal); it learns X's own secrets only from the box, so check that the box makes X independent there once taken (`Core::own_record`).
