# Pending commits keep expired values
> Summary: A commit (or a late part) held pending past its delta's expiry keeps the delta's values on disk until it applies, maybe never (spec/commits.md §5 wants no copy past T); dropping the part at T instead loses its non-value writes and breaks arrival-order independence. Needs an owner call.
> Tags: security, engine, retention

Repro: `shred::repro_expired_while_pending_values_kept` (`#[ignore]`). Same for a late part that waits (`apply::late_parts` `Exam::Pending`) and for a pending commit a held purge request names (purge has the same shape until the commit applies).

Tried (branch pending-expiry, reverted): store pending/parked records without parts past T, an expiry timer per kept expiring part stripping it at T (shredded rewrite; an applied commit's late-part record left empty goes). It fixes the repro and a late-part variant, but fails `order::expired_residue_survives_unmerge_spec_crdt_4_6` and `order::valueless_list_order_independent_spec_crdt_4_7`: in the reversed order the commit arrives past T before its thing's `created.0`, so the dropped part's non-value writes and value-less stamps (spec/crdt.md §4.7: "its non-value writes stay"; the residue) never join, and an older value shows where the order as made reads absent.

Why it cannot be done locally: keeping the non-value writes needs the part's bytes checked against its delta hash before stripping (a stripped copy can never be checked later: the hash binds the full bytes), and that hash is keyed by the part's thing's record nonce. Review: only `UnknownCreated` of the part's own thing blocks that. A wait for the author's record (`MissingChain`) does not: the delta hash checks with the thing's record alone and the header stays whole, so the signature can be checked against it when the record comes (a residue whose signature never verifies goes, as a junk copy does). Elsewhere (delta, page, blob, drift waits) a checked value-less copy can be kept as a pending residue, joined at apply.

Options: (A) security first: a delta held pending at T (or arriving past T while it waits) counts as never received; its non-value writes come only from snapshots; the order oracles treat it so. (B) convergence first: spec §5/§6 except copies held pending until they apply (bounded by the pending caps). (C) A plus the checked-residue path wherever the thing's record is known (every wait but `UnknownCreated` of the part's thing), so only that wait diverges. (D) wire change keeping both: the delta hash commits to each value-carrying write's value through a hiding commitment (`H(salt_i, value)`, `salt_i` derived from a random per-delta salt carried in the delta and stripped with the values), so any node strips a part at T, keeps the commitments, and checks the stripped copy against the header whenever the records arrive. Costs: a salt per delta, a hash per value at write and check, a stripped encoding in the codec and the paged chunk tree (link hashes bind full pages too), spec/crypto.md §6 and spec/crdt.md §4.7 changes. Pending records encrypted under a key erased at T are not a fifth option: erasing the key is shredding, and the copy can no longer be checked, so it is A.

Review view: A's divergence is the one the system already has. Hosts delete the blob at T (spec/sync.md §5), so a node offline across T never gets the part and holds its non-value writes only through snapshots; a node that had the part pending at T is in the same place. C narrows A to the rare case of a part whose thing's `created.0` comes after T; D is complete but a wire and codec change for that case. Suggest C, or A if the pending-residue form costs more than it buys.

## Decision (round 13)
Owner: "if C is good go with C", balancing simplicity, deleting data when required and convergence; coordinator chose **C**: a part held pending at its expiry drops its values at T like any held body (requirement: no copy past T), and its non-value writes are kept as a checked residue wherever the thing's record is known, so convergence holds for every wait but a part waiting on its thing's creation record (`UnknownCreated`), the one accepted divergence (rare: the creation arrives after the content and after T). Simpler than D (no wire change), keeps deletion strict. Build it.

notes/convergence-study.md proposes revisiting: option A plus a self-reported "suspect aspect" flag in the heartbeat, repaired by a writer's ordinary compaction snapshot, instead of C's checked-residue path (owner call).

## Decision revised (round 13)
The convergence study (notes/convergence-study.md) recommends option A plus a self-reported `suspect` flag repaired by a writer's snapshot, instead of C; owner: "good". Build A + suspect with the R1/repair work, not C.
