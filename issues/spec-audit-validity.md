# Spec audit: commit and validity rules where code and spec part
> Summary: Code-side bugs and open decisions from the spec audit of commits, wire §3-§6 and permissions §5-§6 (spec-side wording was fixed on branch spec-audit): an over-invite edge judged three ways, `keys.0` role needs unstated, ephemeral-commit retention unchecked, zero-part blob prefixes unchecked, an unstated 8 MiB cap on linked header lists, unchunked large values accepted.
> Tags: spec, permissions, commit, engine

## Code disagrees with itself
- **Edge with `invite` above its role** (spec/permissions.md §2 says only "at most its role"). `engine/apply/validity.rs` `edge_of` reads it as no edge, so `edge_ops` turns a change into a removal (the reset still applies); `perm/src/walk.rs` `judge` (`well_formed`) treats the write as not applied; roster snapshot entries are dropped (`walk.rs` ~1945, `validity.rs` ~461). Pick one rule (suggest: such a value is bad input, judged from the delta), state it in §2, make all three paths follow it, add a vector.

## Missing from spec, needs a decision or code
- **Role a `keys.0` delta needs**: `validity.rs` `rotation_required`: write for keyset fields `read`/`write`, admin for the rest or a whole-value write/reset. spec/permissions.md §3 states this for `secrets.0` only. Coordinate with the keyset-names branch (spec/crypto.md §4) before writing it down.
- **Ephemeral commits' retention**: spec/commits.md §2 says a snapshot one's deltas are `writer` with no bounds; spec/wire.md §4 field 14 requires only `writer`; `Header::validate` checks neither bounds nor anything for session-form ones (which carry schema defaults, `author`). Either validate "writer, no bounds" for both shapes (simple) or drop the clause.
- **Zero-part commit blobs**: `labeling/blobs.rs` `open_commit` and the sync pass skip the prefix-vs-header check when a blob has no parts, so a header-only blob (spec/commits.md §5 purge) may carry any expiry and commitments. Decide what its prefix must be (none, or the commit's level-2 commitment like header-list chunks) and check it.
- **Linked header lists above 8 MiB**: `commit/src/lists.rs` `MAX_LIST_BYTES` (64 × `CHUNK_THRESHOLD`) is called a local policy, but `apply::examine` then fails the commit, so a spec-conforming commit with a huge aspect list never applies at osis nodes. Either make it a format constant writers respect (spec/wire.md §2, §4) or resolve lists streaming.
- **Unchunked atomic values above `CHUNK_THRESHOLD`**: spec/data-model.md §6 says they MUST be chunked; no reader rejects one inline (osis-crdt accepts it; only chunked-too-small is rejected, `label/src/chunks.rs`). Set/map equality differs between the two forms. State whether readers reject, and do it.
- **Promotion ends a tenure**: `perm/src/roster.rs` ends a write tenure at a promotion to admin; spec/permissions.md §6 Tenure ledger names only demotions. Changes snapshot bytes, not verdicts; write it into §6.
- roles-model `content.rs` says "Snapshots vouch for nothing" (it means delta validity); reword, and note no model checks vouching or misstatement (spec/permissions.md §5.2).
