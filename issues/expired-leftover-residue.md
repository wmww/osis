# Expired leftovers never reach a node that missed them
> Summary: `random_churn_converges_large` ends quiescent with holders reading differently when an expiring write expired before some holder got it (hosts delete it at T; its leftover lives only at the nodes that held it) and no writer compacts afterwards: the trigger leaves a small leftover residue uncovered for good. The spec states this as a limit (spec/crdt.md §4.7, "until a snapshot carries"), but nothing makes that snapshot come. Needs a rule for when a writer covers residual leftovers; each candidate has a cost.
> Priority: normal
> Tags: ephemeral, retention, sync, tests

## Failures on main
Replay: `OSIS_EPH_START=<seed> OSIS_EPH_SEEDS=1 cargo test -p osis-node --test it -- --ignored --exact ephemeral::random_churn_converges_large`. The failure dump shows each node's commits on the two aspects (`aspect_dump` in `lane_dump`).
- 807204138389: node 3 Puts `k2` (expiring 90 s, commit `aef8bcc1`); node 0 later `Set`s `k2 = v41` into that entry (lasting). The Put expires while nodes 1-3 hold it: they keep its leftover (the entry's key and creation, value-less) and read `k2: v41`. Node 0 restarts after T; hosts deleted the body at T, so it gets the Set without the entry it lives in and reads its own older `k2: v26`.
- 807204137228: node 0, cut off from both hosts, writes a reset and a Put that expire (90 s) before it reconnects. Its leftovers are never uploaded (a leftover uploads nowhere); node 0 reads the reset, the others do not.
- In both, a writer compacting the aspect after quiescence makes every holder read alike (checked by calling `compact_ephemeral_now` on each node before the reads).
- 807204137843 (the seed first listed) passes on main. On the build where it failed (48500eb98, before net step 3h2) node 1 held three own commits (a snapshot, a write and its undo) with no label entry at all, so a different cause in the pre-3h2 upload path; not traced further, since 3h2 replaced uploads with pull and the seed no longer fails.

## Why sync does not close the gap
Nobody offers the missing data, and nobody can: an expired body is deleted at hosts at T (spec/commits.md §6), and a leftover is a local body that is never uploaded (spec/crdt.md §4.7). The only carrier is a writer's compaction snapshot, which holds the leftover's writes value-less. The trigger (spec/sync.md §7, `retention/compact.rs`) counts leftovers but fires only when two or more droppable bodies cost more than `FACTOR` times the snapshot. One or two small leftovers stay below that until something else is written, and in a quiet aspect that may be never. The requirement (spec/requirements.md, Convergence limits) allows reading differently only "until a writer of that data next writes it or notices the difference". The build does neither: a writer's next delta write does not carry the leftover unless the trigger fires, and suspect lists come from the node that lacks data, which here cannot know.

Durable data has the same gap (notes/expiry-creation-design.md, Late nodes). The random churn run finds it through ephemeral data because restarts make late nodes common.

## Candidate rules (a decision is needed)
1. **Cover at T**: a writer holding an expired leftover that no held valid snapshot covers compacts at once (like a purge, spec/commits.md §5: "duplicates are harmless"). Simple, with no number. Cost: one whole-aspect snapshot per expiry per writer holding it. That is quadratic for a long-lived collection of expiring elements (an event list, a disappearing chat in one aspect) and breaks `scale::expiry_is_flat_spec_crdt_4_7`.
2. **Cover once quiet**: as 1, but only after the aspect has had no body arrive and no expiry for a time D. A stream is covered by the normal trigger, and the residue is covered once it stops. Cost: one snapshot per writer per quiet period. D is a new number: at 0 it becomes rule 1, at infinity it means never converging (notes/arbitrary-values.md). Reusing `MAX_DRIFT_MS` (1 h) would need no new constant but leaves an hour of divergence.
3. **Keep the limit**: accept the requirements' wording as it is and make the churn oracle excuse it. That excuse cannot be computed from the generated history alone, which makes it a carve-out (notes/coordination.md, Test what users can observe).

Rule 2 looks like the best trade. Build it in `Trigger` (a per-aspect quiet time next to `at`; a weighing with an uncovered leftover past T that has been quiet fires whatever the `FACTOR` test says), with spec/sync.md §7 Trigger and the spec/crdt.md §4.7 limit rewritten to say "until a writer holding it has been quiet for D". Add a default test: one leftover held at a writer, a node that restarts after T, and the reads equal once D passes.
