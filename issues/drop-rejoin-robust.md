# Dropped bodies coming back: make it simple and robust
> Summary: Tess's decision: keep the rule (a drop a later validity flip undoes counts as never received; the body rejoins from any copy; none left means gone alike) and build it better, spending download and CPU freely in this rare case. Seven changes: built 1 (one rebuild path), 2 (leftovers as ordinary bodies) and 5 (a debug rebuild check); left 3 (holders re-upload), 4 (brute-force refetch), 6 (a reference model), 7 (revoker snapshots for copy finding).
> Tags: engine, node-sync, tests

Why: most of the arrival-order bug stream (notes/testing.md What finds bugs, notes/convergence-study.md) is not the rule but its implementation: a dropped body leaves a stripped leftover (values gone, stamps and removal effects kept), and bringing the body back must leave every derived structure (map entries, text chars, snapshots carrying it, indexes, death dates) exactly as if never dropped; finding a copy is unreliable (keep at most 0 deletes at hosts in the same sync; the revoker may not hold it; a node without the revocation deletes a re-upload again); other drops stack (expiry, covers turning invalid); "nobody has it" looks like "not yet", so repair backstops can loop (seed 5288: a re-snapshot every 6 h).

Considered and rejected (Tess): making deletions final against later revocation (a removed or stolen device keeps delete power forever), keeping history so drops can roll back (no prompt permanent deletion), a writer's compaction vouching for a deletion (still diverges when every writer saw the revocation first).

Changes, each its own task, cost no object:
1. **One path.** Any validity flip, drop or re-arrival on an aspect marks it dirty; the aspect is rebuilt from held bodies. No incremental repair paths beside the rebuild (un-merge already rebuilds; remove the side state patched around it).
2. **Leftovers are bodies.** A purged or expired body is stored as the same delta with its values replaced by a marker, joined like any body; rejoin replaces it with the full body and rebuilds. No third "held value-less" state threaded through apply, indexes and sync.
3. **The holder uploads.** A node that receives a purge request (or a kill under keep at most 0) it judges invalid makes sure the targeted body is at the label's hosts: exactly the node that still has it.
4. **Brute-force refetch.** A body counting as never received is asked for by ID on every sync, from every host and peer, until it arrives (rate-limited, idempotent). No reliance on others' must-hold rules.
5. **Rebuild check.** In debug builds, after every transaction, compare the engine's derived state for touched aspects with a fresh rebuild from held bodies (like `Engine::recheck` for caches). Catches wrong derived state in tier 1 and the sim, on the first small test that hits it, with no second arrival order. **Built** (notes/testing.md, Rebuild check): states only; death dates differ by design (dated at the first superseder met). Gap: writes the state holds and no body gives pass, since `rebuilt` starts from the own state; a bodies-alone comparison where every part is held whole found a hidden key-erased record left by a forged snapshot (accepted, notes/core-triage.md D).
6. **Reference model** (notes/testing.md What finds bugs): from spec/ alone, what a node holding body set H reads; oracles compare each node with it after exchange.
7. **Revoker snapshot** (issues/session-sources.md step 3): the revoker compacts the aspects the demoted node wrote before stamping; its snapshot carries the content it never saw deleted, so a node that wrongly dropped it gets the copy with the revocation. Shrinks the frontier only for data whose history may be dropped.
Order left: 3, 4, 7; 6 alongside.

## Items 1 and 2 as built (one rebuild path, leftovers are bodies)
- **The leftover** of a part is its body with every value-carrying write of the expired or purged delta value-less (`Fragment::strip`: spec/crdt.md §4.7's own marker, a `[0, R, Stamp]` register, a value-less creation, a key-erased map record), one fragment per (commit, aspect) in row `w/` (`records::LEFTOVER`, `retention::leftover`: a kind byte, a snapshot's frontiers and `Absorbed`, the fragment in the state encoding). The commit's blob loses the slot; `Meta::stripped` names the part. Nothing of it reveals a value: the same bytes the old residue held (`osis_store::attack`, `shred::` tests).
- **It is a held body.** `Meta::holds` is true; `each_held_piece`, `held_parts_at` and `stores_part` hand it over like any part, so rebuilds, deaths, copy indexes, covering and the rebuild check read it with no second path. node-sync, the API's commit listings and history rows see no body (`Meta::body_gone`: dropped or stripped): must-not-hold, deleted at hosts, never uploaded, lasting as a purged part, `HistoryBody::Purged`.
- **Made** (`retention::make_leftover`) from the held body at expiry or purge, from what a waiting part was stripped to (the pending copy's slot `emptied`, the leftover row holding it), from a valid coverer's copies when the body was dropped as covered (held again from then on: order.rs `cover_leftover_outlives_its_cover`), or from a copy arriving for a delta held value-less (`drop_gone`). A snapshot carrying purged values is stripped the same way. A snapshot a request names itself has no values of its own: dropped (`DropFor::Other`) and refetched on a fall. A part missing when purged is dropped (a new node's tombstone), the list alone holding it value-less.
- **Replaced** only by a copy. On a purge's fall the part counts as never received (Tess's rule): its carrying commits leave the value-less list, a delta's leftover is set aside (the row stays, `Meta::stripped` no more, the part missing), the aspect is rebuilt without its writes and the node asks for the body (`Changed::undropped`); a copy joins whole and drops the stale row (`forget_joined_leftovers`); held value-less again before a copy comes (a rise, its expiry) it adopts the row, so a node that saw the fall and one that did not hold the same. An expired part's leftover is for good (a copy after T is the leftover). An applied commit's leftover row goes only with a whole copy joining, an `unstrip` for a copy, or a forget (`retention::stripped_part_fallen_then_expired_holds_its_leftover_*`); a row replaced is overwritten shredded (`shred::snapshot_leftover_stripped_again_unrecoverable_*`). A snapshot's leftover is not set aside at a fall but forgotten, shredded, and the snapshot unindexed: nothing but a copy makes it held again (no request names it, so no rise reaches it), and it keeps the values it copied of other deltas, which a later purge would not reach (`shred::fallen_snapshot_leftover_gone_for_a_later_purge_*`, `shred::fallen_snapshot_unindexed_seed_9230001`). A waiting part held value-less is told from a set-aside row by its emptied slot in the pending copy (`waiting_stripped`). Why not keep the leftover through a fall: a node that never received the body reads the older value while the stripped one reads the value-less winner, with no copy obliged to come, which is not "gone alike" (order seed 29617).
- **The value-less list (`v/`) stays** as the one join-time predicate (`apply::strip_valueless`, in `join_into_state` and at the end of `rebuilt`): exactly the carrying commits of stripped parts and of parts missing past their expiry or under a standing request. It cannot go: other bodies carry copies of value-less writes (an undelete's copy of an expired char, a snapshot's copy of a purged value) that must be stripped as they join, before any value reaches the state unit, and deriving the set per join would walk the aspect. It is a cache of headers and standing requests, not a third state. `check_rebuilt` asserts it against the parts: a stripped part's own writes all on it, a part held whole none.
- **One path (item 1).** `apply::rebuild(tx, tid, ak, gone, clear_undo)` is the only way an aspect changes other than by a valid join: validity flips (`validity::rejudge_once`), drops (`drop_part_for`), leftovers (`make_leftover`, `unstrip`), purge falls (`rejudge_purges`), memory vanishes, invalid deltas arriving (rebuilt once stored, `Joins::rebuild`, never joined-then-un-merged). `retention::never_received` stays (a part dropped at its expiry or purge while missing, no leftover set aside), which `copies::given_by` still needs so a turned-invalid snapshot's copies of such a part leave the state (order seeds 40093, 83009 in `arrival_order_found_histories`). The rebuild writes shredded and marks deaths due only where a body has a relative bound.
- **`check_rebuilt`** stays as is: for the aspects item 1 rebuilt it checks that a rebuild is a fixpoint (cheap, and it would catch a leftover not stored: `rebuilt` reads the bodies), and for the ordinary valid joins, which remain incremental, that the incremental state is the rebuild. Not removable: the joins are where derived-state bugs hide.
- **Invariant** (`retention::make_leftover` doc, test engine `retention::tests::leftover_is_a_held_body_spec_crdt_4_7` through `Engine::bodies_alone_state`): every write a node holds of a delta it holds value-less is in a held body, whole or leftover, never in the state alone; the state after an expiry or a purge equals the join of the held bodies alone. With the leftover not stored the bodies would lack the expired stamp and the join would show the older value.
- **Cost**: about +5 % tier-1 CPU over the incremental repair paths it replaced.
