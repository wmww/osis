# Fixes wanted upstream in `wt`
> Summary: Five fixes wanted in the `wt` script (reasonable-rust-builds plugin, wmww/agent-skills), for Tess to forward; osis's workarounds are in tools/claim and notes/build.md, Worktrees.
> Priority: low
> Tags: workflow, tess-call

- **Release: detach first, then prune.** `release` prunes the target (its marking build takes 1-4 min on a first release) while the branch is still checked out, and detaches HEAD only after. Meanwhile `wt claim <same branch>` in another worktree fails with git's "already used by worktree"; the coordinator hit it twice landing branches whose worker's backgrounded release was still pruning. Detaching first frees the branch at once, and the claim marker (removed last) still keeps the worktree from being handed out mid-prune. (tools/claim names the release still holding the branch.)
- **Claim of an existing local branch ignores the base silently.** `wt claim <branch> <base>` checks out the local `<branch>` when it exists and drops `<base>` without a word, so a reviewer got a stale local copy (an earlier pre-rebase state of the worker's work, not an ancestor of its push) twice. Wanted: when a base is given and the local branch is neither it nor contains it, print a warning naming both commits (or refuse unless `--existing`). (tools/claim resets such a branch to its pushed copy where one exists.)
- **Prune nightly cargo's build-dir layout.** Nightly cargo keeps each unit whole in `<profile>/build/<pkg>/<hash>/` (its `fingerprint/` inside, no `.fingerprint/` or `deps/`), so its pruning finds no profile and never prunes a nightly-built target (osis's `core/test/fuzz/target`). Wanted: treat `build/*/*/fingerprint` as units too. (tools/claim empties that target when its build key changes and drops its release profiles.)
- **Claim checks a branch out over a free tree that has a branch checked out.** `release` always detaches HEAD, so a free tree on a branch means someone works there without a claim; `claim` only checks `git status --porcelain` is clean, then checks its branch out over theirs. Seen twice: agents working unclaimed had HEAD switched by the next claim seconds after they started (the cause ours: agents trusting a harness-given cwd instead of claiming). Wanted: a tree whose `git branch --show-current` is non-empty is busy (skip it with a warning naming the branch).
- **Markers without a worktree are invisible and permanent.** A marker in `.git/wt-claims/` whose tree is gone: `list` iterates `.worktrees/` so never shows it, `trim` never clears it, and `claim` skips that number forever. Wanted: `list` prints markers with no tree, and `claim` or `trim` drops them.

Not a wt bug, so nobody chases it: "the claim marker vanished while an agent worked" was the agent never claiming. A spawned agent's environment names the parent's shell cwd as its working directory; when the coordinator's last command entered a tree it had just released, the next agent built there unclaimed.
