# A commit waiting for pages is examined again at every blob stored
> Summary: `reexamine` re-runs `examine` (signature check and a decode of each waiting part) for every durable commit parked under `Wake::Blobs` at each `put_blobs`, though its reach walk still lacks pages; a fill of P pages arriving in B batches costs about P·B page reads, so a server sending one page per message costs every requester P²/2, P unbounded per commit (a bulk replace of a large map is one commit). The walk already knows (`reach::lacks`); only memory commits consult it (`still_waits`).
> Priority: critical
> Tags: security, engine, sync

- Measured (engine `tests_paged::a_trickled_fill_reads_each_page_a_bounded_number_of_times_spec_commits_4`, ignored until fixed, small pages): 76 pages: 263 pages read given a round at a time, 3,666 one at a time; 288 pages: 1,013 and 47,542 (quadratic). At format pages a 1 GiB map (about 2^16 pages) trickled is about 2^31 page decodes at each requester. Who drives it: any node serving the commit's pages (it picks the batching), not only the writer.
- Each decode goes to the first missing page; a full check (`Dec::checking`) then goes on through the held pages of that position's tree for the tree rule (notes/decode-bounds.md, Link trees), so per examine about the held pages.
- Fix shape: skip a commit whose walk lacks a blob, as `still_waits` does for memory commits, but only for its parts waiting on blobs: a part awaiting a record must still apply when the record comes (each part judged alone, spec/commits.md §4), so the gate is per part, not per commit. Un-ignore the test above when fixed.
