# Texts and lists load whole in a session
> Summary: A received change, move, undo or `edit` of a large text or list loads all of it once per session (about 0.2 s for 10^5 characters), and writing a whole collection loads every page of a large state. Reads by index range and local inserts and deletes by index load only their pages; map keys, set values, struct fields and joins of received changes into maps and sets likewise.
> Tags: performance, node, storage, crdt

Repro: `cargo test --release --workspace --test it scale::text_ -- --ignored --nocapture` (`text_undo_and_first_access_cost`, `text_range_and_edit_cost`).

Done (notes/node.md, Paged state): collections paged at any depth below struct fields, enum payloads and map entries; lazy loading of the pages a read by key, a write to map keys, fields or set values (the value index), or a join touches; undo footprints by dot (text included); `/secrets` ingestion of the touched entries; body drops, expiry and purge rewrite the touched pages only.

Remaining:
- Sequences, writes and joins: a read by index range and a local insert or delete by index (one op, in a session that has not loaded the sequence whole) go through the stored placement order (notes/node.md Paged state: `pages::place_op`, kept per edit by `keep_placement`; spec/crdt.md §6.1). Measured (`text_range_and_edit_cost`, 10^5 chars, each in a new session): local insert 231-249 ms / 13 pages loaded → 2-61 ms (10 ms typical) / 1-2 pages, local delete of 5 chars 202-253 ms / 13 pages → 7-10 ms / 1 page; 1 state page and 3 placement rows written, store writes unchanged (insert 13-16 KB, delete 19-23 KB: the touched page, the unit with its undo buffer, which grows with the buffered footprints). Still loading the sequence whole and invalidating the placement (the next read by index pays a whole pass, 0.18-0.26 s at 10^5 chars, then later cold edits go through it again):
  - received joins (c): the join follows the in-memory `seq_lin::Lin`, which needs every record.
  - moves, pastes, `Op::Edit` (what `osis::text` writes: a diff against the whole read), undos (an undo needs no placement, §4.6, but its write still loads whole and would need the dot → block map to update the stored order), several ops on one aspect in a commit (the placement changes between them), an index segment in the path (`get_at` too: `Fragment::at` resolves it through the in-memory placement).
  - a session that loaded the sequence whole keeps the in-memory path (its first write invalidates the placement), so the next session's index edits load whole until a read by index lays it out again. Keeping the placement per edit there too needs no new structure (same `keep_placement`), at about 3 rows per edit.
  - a top marked `waits` (some anchor named no element at layout): every index edit loads whole until a relayout; exact handling needs the waiting dots stored.
  - What blocks the general case: ops resolve against `Seq::lin()` in `Batch` (`seq_ops`, `seq_diff`, `Layered`), and the join follows the in-memory `Lin`; both need every record. The follow reads: the anchor's row and the rows after it (`slot`: newer siblings with their subtrees), the siblings' records (`child_stamp`), the dot → block map (`DotMap`, O(n) in memory, not stored), `waiting` and `cyc` (not stored), the moved subtree's rows (`relocate`), and any fallback is a whole pass over every record. Shape of a fix: store the full rows (depth, parent, head, created; per block its least depth), `waiting`, `cyc` and the dot → block map (paged by dot like the state pages); let `Placement` blocks and `DotMap` chunks be unloaded stubs (count, least depth) and record lookups outside the loaded pages report a miss; the node runs the op or join on the partial state, and on a miss loads what was missed and retries (bounded by the page count; a fallback loads whole as now). Preloadable: the delta's dots and anchors and their rows.
  - Size: the top row holds one entry per group of up to 64 blocks of about 1 KB of runs, so it passes the 2 KB inline limit at about 150 groups (some 3·10^5 runs: a heavily edited text of millions of characters); a third level, or groups keyed by order, would keep it inline.
- Ops whose map keys or set values have struct or map parts load every page (the crdt matches them as the writer's type projects them, which the index cannot see).
- Collections inside list elements or at a `Slots` position (an `any` field written with several kinds) are not paged apart from what holds them: not a small extension (a list element's position needs the sequence's placement and its record's anchors, a `Slots` member the register embedding; osis-crdt work), best done with the sequences item.
- O(aspect state) by nature (notes/node.md, Whole rewrites): a reset of a paged collection or above it, a validity rebuild, a page or skeleton outgrowing `PAGE_TARGET` (once, re-laid out).
