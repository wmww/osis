# Texts and lists load whole in a session
> Summary: The first edit or received change of a large text or list in a session loads all of it (about 0.2 s for 10^5 characters; a read by index range loads only its pages, after one whole pass per session that edited), and writing a whole collection loads every page of a large state. Map keys, set values, struct fields and joins of received changes load only their pages.
> Tags: performance, node, storage, crdt

Repro: `cargo test --release --workspace --test it scale::text_ -- --ignored --nocapture` (`text_undo_and_first_access_cost`, `text_range_and_edit_cost`).

Done (notes/node.md, Paged state): collections paged at any depth below struct fields, enum payloads and map entries; lazy loading of the pages a read by key, a write to map keys, fields or set values (the value index), or a join touches; undo footprints by dot (text included); `/secrets` ingestion of the touched entries; body drops, expiry and purge rewrite the touched pages only.

Remaining:
- Sequences, writes and joins: a read by index range is done (`Engine::get_range` through the stored placement, notes/node.md Paged state; invalidated on write, rebuilt on read), but any write or join of a paged text or list still loads every page and builds the placement by a whole pass (first one per session about 0.17 s at 10^5 chars), and the next session's first read by index pays a whole pass again to lay the placement out.
  - Next step, local insert/delete by index (the typing hot path), exact with the stored visible-only placement: under spec/crdt.md §6.1 a new local insert carries the greatest stamp at its anchor, so it lands right after the anchor (the visible element at index - 1, or HEAD), with no sibling scan; a delete needs only the visible dots of its range (and a move or a range with hidden anchors inside still needs the full slice). Needs a crdt `Batch` entry point taking an anchor or dots instead of resolving through `Seq::lin()`, the join of the new records without the in-memory placement, the stored placement updated per edit (an incremental write path whose summary stays under the store's inline limit of 2 KB, so a two-level summary; the earlier per-edit rewrite cost 12 → 30 KB per edit: the 2.4 KB summary went to an overflow unit, each block write a put and a remove in two leaves), and a check of the undo footprint (`Fragment::footprint`) on a partly loaded sequence.
  - What blocks the general case (received joins, moves, ops resolving through the placement): ops resolve against `Seq::lin()` in `Batch` (`seq_ops`, `seq_diff`, `Layered`), and the join follows the in-memory `seq_lin::Lin`; both need every record. The follow reads: the anchor's row and the rows after it (`slot`: newer siblings with their subtrees), the siblings' records (`child_stamp`), the dot → block map (`DotMap`, O(n) in memory, not stored), `waiting` and `cyc` (not stored), the moved subtree's rows (`relocate`), and any fallback is a whole pass over every record.
  - Shape of a fix: store the full rows (depth, parent, head, created; per block its least depth), `waiting`, `cyc` and the dot → block map (paged by dot like the state pages); let `Placement` blocks and `DotMap` chunks be unloaded stubs (count, least depth) and record lookups outside the loaded pages report a miss; the node runs the op or join on the partial state, and on a miss loads what was missed and retries (bounded by the page count; a fallback loads whole as now). Preloadable: the delta's dots and anchors and their rows. The differential tests (`seq_placement_differential_{text,list}_spec_crdt_6`) check the stored placement against a whole pass after every write.
  - Measured (`text_range_and_edit_cost`, 10^5 chars, new sessions): read of 100 chars 163 ms / 13 pages → 4-6 ms / 1 page; local insert and received insert 166-225 ms / 13 pages either way; the first read by index after edits 0.39 s / 13 pages (lays the placement out), then 1-2 pages. Store writes per insert: first in a session 11.5 → 16.3 KB, later 15.2 KB.
  - `get_at` with an index segment into a paged list still loads the list whole (`Fragment::at` resolves the index through the in-memory placement).
- Ops whose map keys or set values have struct or map parts load every page (the crdt matches them as the writer's type projects them, which the index cannot see).
- Collections inside list elements or at a `Slots` position (an `any` field written with several kinds) are not paged apart from what holds them: not a small extension (a list element's position needs the sequence's placement and its record's anchors, a `Slots` member the register embedding; osis-crdt work), best done with the sequences item.
- O(aspect state) by nature (notes/node.md, Whole rewrites): a reset of a paged collection or above it, a validity rebuild, a page or skeleton outgrowing `PAGE_TARGET` (once, re-laid out).
