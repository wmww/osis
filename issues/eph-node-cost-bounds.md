# Node ephemeral caps count encoded bytes; some held-commit work is quadratic
> Summary: the per-label node cap counts blob bytes only. Decoded fragments, the engine's copies of waiting blobs (`Remote::pending`, `Remote::invalid`) and invalid held parts (removed members' commits, kept until restart) add memory the cap does not see, unpaged 8 MiB deltas included. `drop_absorbed` scans every held commit per arrival, so a writer sending many small commits costs holders quadratic CPU; `eph_containers` clones and joins a candidate cover part per replayed part. Low, and unmeasured.
> Tags: security, engine, node, ephemeral

- Memory: `Lane::bytes` (core/node/src/sync/ephemeral.rs:588, :920) counts the encoded blob. The engine also keeps each part's decoded `Fragment` (`HeldPart`), the joined state, and for parts waiting on a record a second copy of the whole blob (`Remote::pending`, core/engine/src/ephemeral/remote.rs:941). Since item 54 one delta can be 8 MiB encoded. The ratio of decoded to encoded size is not measured, and could be large for many small elements. Worth a bench like `cover_past_page_target_bounded` that measures RSS against the cap.
- Lingering: after a removal, the removed member's held commits turn invalid but stay held and counted until restart (`rejudge_ephemeral` keeps them). They are also listed as `gained` at every first Sync, so a server that lacks them asks for them, and their old stamps are refused with code 9 (diagnostics).
- CPU: `drop_absorbed` (remote.rs:1018) rebuilds the absorbed map from every held part and scans every held commit each time an arriving commit lists anything as absorbed. `eph_containers` clones each fitting cover part (same author, later or listing it) to test `contains`: a replayed tiny commit costs a copy of up to every held byte on its aspects, uncounted by any cap (Covered commits are neither held nor counted), and the same blob costs it again per source and per announcement. `drop_absorbed`'s vouch check clones each listing cover part once per arrival with absorbs. Up to the 16 MiB cap there can be about 10^5 small commits, so a writer sending commits that each list one absorbed ID costs about 10^10 map operations at every holder. `ephemeral_absorbers` (:480) is O(held) per dropped commit.

Fix direction: count decoded size, or a measured multiple of encoded size. Drop invalid held commits when a removal makes them invalid (they come back by reconcile if the member is re-added). Index absorbers, a map from absorbed ID to the covers listing it, so arrival and drop cost what the new commit lists. A non-mutating `Fragment` order test (`x <= c` without cloning `c`), or the lane remembering covered blob IDs per label like `RelaySeen`, would bound `eph_containers` by the replayed commit's size.
