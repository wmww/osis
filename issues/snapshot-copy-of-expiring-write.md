# A snapshot's copy of an expiring write does not stand in for its delta
> Summary: Order seeds 4136 and 4208 (shrunk, pinned as `order::repro_snapshot_*_seed_41{36,4208}`, ignored): a compaction snapshot stamped after a live expiring write and listing it (its frontier reaches the write's counter) does not give a node that never applied the write's delta the write's effect: a map entry's older content (4136) or a register's older value (4208) reads where a node that applied the delta before T reads none. Both pass on main only because main keeps a pending part past T and applies it later.
> Tags: engine, retention, crdt, tests

Surfaced by pending-past-expiry option A (a part pending at T counts as never received): in the failing order the expiring commit arrives before the base (or its thing's record), goes at T and is flagged suspect; the snapshot that lists it joins and clears the flag (`retention::suspect::settled_by`, `receipt::listed_by`), yet the state keeps the older content. Either the snapshot writer leaves a live expiring write out instead of carrying it value-less (spec/crdt.md §8), or the receiver strips the copy to nothing when the snapshot arrives after T (spec/crdt.md §4.7 says stripped and joined: the stamp should still supersede). A direct two-peer repro in the simple shape (an untyped `Set` at k0 by another writer, a typed field write, a first snapshot, the expiring typed `Set`, a `Set` at k1, a second snapshot) carries the expiring write value-less and a late peer reads alike, so the seeds' histories have an ingredient not yet isolated (`Demote`s and `Forged` copies in 4208; the `Nested` step's failing inner write and the Slots conflict in 4136).

Consequences: repair of hole 2 (notes/convergence-study.md) by a writer's snapshot relies on the copy standing in for the delta; `listed_by` as proof that a snapshot carried a delta's writes is only as good as that. On main the same shape needs a node that never receives the delta but receives the snapshot after T (a late joiner).
