# Public pieces are logged by timing
> Summary: whether an account reads a public thing its strong reaches, once its other path there goes, depends on whether one of its nodes happened to sync the thing (holding the public's grant) while that path stood; the model says it reads it either way. Proposed: a node follows such a thing's sync ID by the public entry, as a redeem does.
> Priority: normal
> Tags: sync, engine

T's keys open X by the public only through a public piece under T's sync ID (spec/sync-set.md §2 Public pieces). Only a node reading T that holds the public's grant on X logs one, which it does while it syncs X by a role of its own. A node holding no role on X never logs it. Logged pieces stay.

So T reads X after its own path to X goes exactly when some node of T synced X and took X's public grant before that: an accident of delivery, not of the history. In the model (spec/requirements.md: the public reads X; T holds a strong to it) T reads X either way. Scripts, each at `holds_on(0, 3, 4, ..)`:
- `New(2), Give(2, 0, Holder::Node(0), Syncs), Give(2, 0, Holder::Public, Reads), Strong(3, None, 0), Partition(3, 1), Run, Revoke(2, 0, Holder::Node(0))`: node 3 takes the grants in a partitioned run and logs the piece, so after the revoke node 0 reads thing 0. held-model logs pieces only at quiet runs and as the public is granted, so it says not read ("node 0 reads thing 0, the model does not").
- `New(0), Give(0, 0, Holder::Node(1), Reads), Strong(1, None, 0), Give(0, 0, Holder::Public, Reads), PowerOff(1), Revoke(0, 0, Holder::Node(1))`: node 1 is never on while it reads thing 0, logs nothing, and reads nothing at the end. held-model logs the piece at the public's grant, as if every node held everything, so it says read ("unlike the reference": the reference reads it).
- `New(2), Give(2, 0, Holder::Public, Reads), Give(2, 0, Holder::Node(1), Reads), Strong(1, None, 0), Lower(2, 0, Holder::Node(1), Syncs)`: node 1 is lowered to sync before it ever runs. It reads nothing of thing 0 and holds no public grant on it (roles: its own sync and the admin). The reference and held-model read it. Without the read and the lowering it does read: with `Give(1, 2, Holder::Public, Reads), Give(1, 2, Holder::Node(2), Syncs), Strong(2, None, 2)` (after `New(1)` three times) node 2 reads thing 2 by the public, whichever grant comes first. So a node syncing a thing sync-alone holds the public's grant, unless an edge write it holds once gave it read (a guess: `Core::sync_alone_on` is false once a held edge write gave read). This one looks like an engine bug, separate from the timing: unexamined.

Loss and partitions make the logging time unknowable from the history, so no logging point in the oracle can be exact. Fixing the oracle would only move the failures.

Proposed: a node of T whose unit has a strong to an independent X that T's keys do not open follows X's sync ID by the public entry, as a redeem does (spec/sync-set.md §4 Redeeming a public link; §1: the link's sync ID is in the redeemer's sync set while it redeems), and logs the piece once it holds the public's grant. Then a piece is logged wherever a strong of T reaches X and the public reads X, whoever synced X before, and held-model's rule loses its history (`Made::pieces` and the logging points go). Costs: one follow per such strong for as long as the public does not read X (peers serving X's sync ID refuse the public entry). This is the price of a dangling strong; it may need a bound, which would bring the timing back. Needs a coordinator's decision before it is built.
