# Build the account's sync record (holder trust)
> Summary: The spec's rule for a node keeping a thing unread (spec/sync.md §3 Sync record: sync IDs only from the account's accept or own reading, secrets only once a step of its own path bears them, kept in `kept^.0` on D) is specified and modeled (core/test/tla/net/NetTrust.tla) but not built: the code still takes boxes payloads by connected author, vouching stamps and accepted rows, keeps a node-local record, and sends the author's rotation line.
> Priority: normal
> Tags: security, sync, engine, label

What the code does that the spec no longer says (each a hole the design closes): a connected author attaches its own sync ID and dial hint to any thing the node syncs; a listing-only take gives secrets without sync ID (a closure thing granted by an unconnected author is stuck); forged secrets pile up in the node-local record; a boxes payload carries the author's rotation line (grows with account age, none sent past `MAX_ROTATIONS`); a later node of the account learns nothing of a sync-alone thing once the inbox blob expired.

## Plan
1. Schema and wire (osis-schema, osis-label): `kept^.0` on D (schema/core.osis); `BoxesPayload` per spec/wire.md §9 (no `commit_id`, `creation`, rotation line; `GrantSig` only on a grant); delete `BoxesPayload::verified`'s line walk, verify `GrantSig` against a key the caller passes; vectors and the inbox fuzz target follow.
2. Sender (core/engine/src/sync/deliveries.rs): `boxes_blob` signs only a grant's payload; delete `author_proof` and the `MAX_ROTATIONS` cliff.
3. Recipient (core/engine/src/sync/inbox.rs, records.rs): delete `take_boxes`' whole/listing split, `author_connected` for boxes, the `accepted` flag on waiting rows, `vouched` for boxes payloads, the `sy/` local record and `note_sync_secrets`. Replace with: the sync record read from `kept^.0` (a memo over D's state; `sync_record_now`/feed keep their shape, so osis-sync's callers barely move); held secrets = recorded ∪ boxes of held unexpired boxes payloads (a memo over `waiting_inbox`); `mark_acted` on an accept writes the offered sync IDs into `kept^.0` in its transaction (an invitation now includes a listed thing offered under a sync ID not kept); a lowering to sync writes the record from the node's own reading.
4. Confirmation (facade): osis-sync tells the engine when a kept unread S's path gains a step (Register taken) and the engine records each held secret whose sync key that step bears (one D write per newly confirmed secret). No new state in osis-sync: its path is already kept.
5. osis-sync: credentials of a kept-unread S from the facade's held secrets (unchanged call shape); dial hints of boxes payloads only while their sync IDs are kept; delete the stamp-vouch path for boxes payloads in `inbox/held.rs`.
6. Tests (one per rule, fast, facade-level): accept keeps the offered sync IDs and nothing else does (a forger's offer, a connected author's); a secret is recorded only once a step bears it (a forged box never); a sibling and a node paired after the blob expired keep S from `kept^.0`; rotation, removal, re-grant from strangers need no accept; a lowering writes the record; a closure-listed offer is an invitation. Rewrite facade.rs boxes tests (`a_forged_boxes_payload_is_refused`, `a_boxes_payload_for_a_listed_thing_is_taken`, `a_listed_thing_takes_only_its_own_boxes`, `a_forged_author_is_not_connected`, the two sync-record tests) and flows `a_sync_grant_accepted_on_one_node_is_taken_at_its_sibling`.

Cost: about 1,500-2,500 lines touched across osis-engine (most), osis-label, osis-schema, osis-sync and tests; engine-heavy, so Fathom reviews. Roughly half is deletion.

## Open
- A holder actor other than an account (a group G holding sync alone on T): each reading account accepts T for itself; an account reading G that arrives after `INBOX_LIFETIME` gets no box until T's next rotation or a re-seal. A record on G (`kept^.0` written by G's admins) would cover it; not specified until a use needs it.
