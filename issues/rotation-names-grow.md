# Every rotation re-writes every departure name the actor ever had
> Summary: A rotation's history boxes name every departure from the actor its rotator holds (spec/crypto.md §4), with no reset point, so each rotation and each grant's or re-seal's copy carries O(departures ever): about 76 B each, 76 KB per history box per role at 1000 departures, O(departures²) over a chat's life.
> Priority: low
> Tags: keys, performance

Nothing resets the list. The spec/requirements.md Scale exception covers keeping role history, not re-writing it per rotation. Measured at small size in notes/crypto.md (Costs: a 10-reader group's read history box grows by about 112 B per removal). Options: name only departures after the newest epoch the rotator's history box supersedes and whose names are met (a reset point from the epoch chain itself), or accept it as part of the role-history exception and state it.

**Proposal: a design step, not a slip.** Simplest bound consistent with depth 0: chain coverage through supersedes. A rotation to e names only the departures it knows that no epoch e supersedes (spec/crypto.md §4 Supersedes, read from e's rotation commit) already covers at the rotator; Covers becomes "e names it, or e supersedes an epoch established at the node that covers it" (recursive, memoized per epoch). Why it is sound: the rotator used each superseded epoch only once established, so it held every commit that epoch names (Met) and boxed no departed holder at e. Cost: Covers walks the supersedes chain (O(rotations) per actor once, cached), and a fork or a node missing an old rotation commit falls back to "not covered" (a re-rotation, as today for unmet names). "Name only the first target" does not bound anything (it trims the audit-drop bullet only). Needs spec/crypto.md §4 (Names, Covers, Attributes), osis-keys `covers`, engine `rotation/departures.rs::names`, and the TLA rotation model (`no departed holder reads`) re-run with forks and missing rotations before it is built.
