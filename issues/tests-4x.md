# Tests cost about a hundred times what they should
> Summary: The default tests take 2550 CPU-s (170 s wall on 24 cores) and the gate 8-10 min; a median node test runs 1.7 G instructions and a median osis test 2.4 G, where a test should cost milliseconds. Measured causes, as patterns: every test builds a multi-node world from nothing, debug oracles reload the whole store inside ordinary tests, byte-form keys are parsed again at every use, default tests enumerate orders, seeds and sizes at full width. Target (Tess): 4x faster without losing coverage that matters.
> Priority: normal
> Tags: tests, performance

## Measured (main 6a15e5b44, this box, 24 cores)
- Default tests: 2553 s summed test time; osis-node `it` 1299 s (1256 tests, median 0.37 s), osis `it` 705 s (511, median 0.58 s), osis-engine 221 s, osis-crdt 81 s, osis-sim 70 s, held-model 58 s, chat 39 s, perm 25 s. Wall is CPU over the cores per binary, the binaries one after another: only less CPU makes it faster.
- By length: the 100 slowest tests are 950 s (37%); tests of 1-5 s are 1009 s (486 tests); tests under 1 s are 600 s (2900 tests).
- The gate: build 40-60 s, default tests 170 s, selected properties 170-250 s, sim sweep 105-145 s.
- A median node test (`tombstone::a_lost_tombstone_is_uploaded_again`, 1.7 G instructions): `Engine::check_index` 26%, curve and KEM work about 30% (signature checks 11%, X25519 8%, `KemPublicKey::from_slice` 5%, `mul_base` 4%, `SigningSecret::from_seed` 3%), `create_account` 9%, value encode and decode about 15%, store commit 5%, `misjudged` 4%.
- A median osis test (`sync::grant_by_inbox`, 2.4 G): signature checks 16%, `check_index` 12%, `rejudge_all` 10% of which `misjudged` 9%, `body_keeps` 9%, `SigningSecret::from_seed` 6%, `World::account` 7%.
- All debug oracles off: node `it` 1260 to 797 CPU-s (37%), osis `it` 574 to 401 (30%). `check_index` (an open from the persisted index and a rebuild from the records, compared) is the largest; `check_rebuilt`, `misjudged`, the memo comparison and `Engine::recheck` share the rest.
- Raising `opt-level` to 2 for the workspace: 3-10% for a full rebuild. Not worth it.

## Patterns, by size
1. **Every test builds its world from nothing, and many build it once per case.** A world is accounts with real keys, groups with rotations, labels at hosts, and a settle. About 120 of the 260 slowest tests rebuild one setup per order, seed, case or crash point (about 700 s); the short tests are mostly setup (`tied::outsider()` builds 5 accounts in each of 9 tests, `sharing::alice_bob` 15 times, `Net::new` is called 489 times, `World::new` 160). The engine has `Peer::fork` and a few node tests copy a node (`copy_node`); nothing forks a `Net` or a sim `World`, and no setup is built once per binary. Fix: `Net::fork`, `World::fork`, `LocalPeer::fork` (copy the memory backends and roots, hub state and queues), setups built once per binary behind a `OnceLock` and forked per test, one world with a thing per case where cases differ only in data.
2. **Debug oracles run inside every ordinary test.** They are differential tests riding on all other tests, and each samples per engine (the first and sixteenth changing transaction, the fourth commit of an aspect), so in a suite of thousands of short-lived engines the sampling always fires. A third of all test CPU. Options, a Tess call since each trades oracle reach for time: (a) run them once per engine when it is dropped (a wrong state stays wrong, the argument the sampling already rests on) plus where a test asks; (b) sample by a hash of the transaction's commit so the rate does not restart with each engine; (c) keep them per transaction only in the property and sweep runs, whose random histories are what they are for.
3. **Keys kept as bytes are parsed at every use.** Verifying keys decompressed per check (`VerifyingKey::from_bytes` via `osis_label::cbor::get_key`, `DeleteKey::verifying_key`, `header::read_key`), KEM public keys parsed per seal and open, signing keys expanded from their seed per use (`SigningSecret::from_seed` in `label_role_key`, `KeyActorKeys::from_seed`, `host_key`). 10-15% of an ordinary test, and product cost too. Fix at the types: a parsed public key beside its bytes where it is decoded (public keys are not secret, so a parsed copy lives as long as the bytes do); derived signing keys kept with the epoch or identity they derive from.
4. **Default tests run at full width.** Order enumerations (11 node tests, 158 s: `order::held_set_decides` 44 s runs every subset and order for 16 seeds), seed loops with literal counts (about 45 tests, 250 s: held-model props 300 seeds each, roles-model 3000 worlds, crdt proptests looping every variant inside each of 32 cases), scale tests at 20/200 or 30/300 where 3/30 shows the same flatness against a counted bound (about 36 tests, 240 s), floods far past the bound they test, thousands of tiny entries standing in for "large" where a tenth as many larger ones fill the same pages (20 engine tests, 110 s), a 132k-character text to test streaming (`notes::large_body_streams`, 23 s). Fix by rule: a default test runs a covering set (named regressions, each item first and last, the smallest sizes where the counted quantity is not trivial, just past the threshold tested); the full width goes through `testenv::large_n` and the ignored `_large` twins the properties already have.
5. **Work done twice.** Near-duplicate tests on identical worlds (reconnect.rs:82 and :96, ending.rs:237 and :311, pass_sources.rs:109 and :120, write.rs:591 and :673, tied's copy-survives and group-admin pairs), a history replayed twice (`keep_for_d_named`, judgment's generate then replay, keep.rs:906), `advance(); run();` where `advance` already runs (33 times in tombstone alone), a must-fail `try_until` walked to its last step (sharing.rs:627 and :639: 200 steps each), a full compare or reopen after every step of a long script.
6. **Real time waited out** (osis real-runtime tests, about 10 s of wall): the node's 5 s redial after a heal (sources.rs:268), must-expire timeouts of 300 ms to 2 s (runtime.rs:409, port.rs:415-455), 200 ms sleeps (keep_clients.rs:218).
7. **Quadratic helpers**: `Net::item` rewrites the whole `group.0` per item, `apply::keys::tests::spread` sends every commit to every peer again, a receiver made as one of nine meshed peers.

Not a lever, measured: delivering only missing commits in `Net::pair` changed nothing.

## Order of work
1. Fork helpers and built-once setups (pattern 1), on the modules where setup is most of the time first (osis tied, sharing, sync; node ending, wrap_poison, pass_sources, listing, retention).
2. The oracle policy (pattern 2), once decided.
3. Parsed keys (pattern 3).
4. The width rule (pattern 4) and the duplicates (pattern 5), file by file.

## Method
Per-test times: run a test binary with `RUSTC_BOOTSTRAP=1 <bin> -Z unstable-options --report-time --format json` from its crate directory; sum `exec_time`. Instructions for one test: `tools/icount`. A profile: issues/derived-state-recomputed.md, Method.
