> Summary: Target (Tess): default tests 4x faster without losing coverage that matters; a test should cost milliseconds. Left, biggest first: osis-sync's differential worlds and per-delivery settles, a compaction snapshot re-judging every body it covers, `Effects::due`'s log scans.

## Left, by size
1. **A compaction snapshot re-judges every body it covers.** Each snapshot of an aspect (home's `group.0` every 3-5 new things) covers every earlier body: the previous snapshot is forgotten and hands its covered bodies down (`apply::unindex` `hand_down`: a `Meta` write per body), each body's carriers move, and each is joined against the new snapshot (`covered` per (snapshot, body), a new key per snapshot). osis `scale::a_new_thing_judges_the_bodies_it_changes` (a new thing writing no snapshot judges 2 bodies at n and 10n) leaves these out: about 6n judgements per snapshot. Levers: covers along the chain (a body covered by S and S covered by S' is covered by S' while both are valid: join-subsumption is transitive), so a new snapshot joins only what the last one did not cover; carriers named so a hand-down moves no body's facts.
2. **A body's facts are derived again per body whose reads moved.** The judgement moves only with its facts (`Engine::read_facts`, a row), but every write on an aspect re-derives the facts of each body on it: a part's date reads the aspect's state row (`deaths` at its positions), and own covers read the author's newest own replace (`part_covered` checks the newest two own replaces, a new `covered` key per body per write). Cheap per body (O(1) reads each since `held_writes_rows`), O(n) per write. Narrowing: dates stamped by the positions read (issues/derived-state-recomputed.md step 4); own covers checked against the first two covering own replaces after the body (spec/commits.md §5 Own replaces says any two), which is stable as writes land.

3. **osis-sync's differential and simulations** (3,000 G alone): a fresh world per seed (31% of a seed in one process), then per delivery a settle of every module. `may_log`'s `held_blobs` reads the sync store per judgement; `Effects::due`'s log reads 10%; `follow_certificates` at every follow.
4. **`order::held_set_decides`** (399 G alone, the costliest engine test): ingest about half, held-model compares a fifth, `check_index` a sixth; every order is ingested from the setup (Properties, below).
5. **`check_index` has no exact incremental form** (22% of osis-engine `it` inclusive): its halves are two loads from scratch; cheaper loads are the lever, and they are the product's open.
6. **The forensic attack's tries**: candidates (130-185K per attack) times each unopened section and blob; each candidate prepared again per attack.
7. `rotation_holds_spec_crypto_4` (46 G, 8 seeds; `tally` needs 8): ingest 50%, 95% of its ingests re-deliveries of known commits, each fully decoded before `late_parts` finds nothing new.
8. Engine lib, alone (G): `rotation_holds` 38, `seq_placement_differential_after_reset` 31 (its oracles `vis_whole` and `place_whole_pass` 40%), `arrival_order_holds_alike` 19, `seq_cold_edits_keep_placement` 19, `per_entry_secrets_ingestion_equals_whole_state` 14, `every_box_is_recorded_beside_it` 13. osis-perm `incremental::late_writes_across_kept_states` 37 G: 98% its oracle `check`, which asks every role, `roles_on` and three `delta_valid` before each of about 200 applied writes for six nodes of both timelines, ten times; each such past query is a checkpoint replay and a graph walk.
9. Allocation (glibc's allocator, the production one): `Value` trees for epochs, histories and schema reads; B-tree nodes of fragments; fragment clones where a join consumes its side; `kdf_key` formats `"osis v1 " + purpose` per call.

Rejected levers: `opt-level` 2 for the workspace (3-10% for a full rebuild). Fake crypto in tests: a debug-only switch (every forgery and wrong-key test must opt out), a verification memo in osis-crypto (debug and release differ), dependencies without debug assertions (loses their assertions), precomputed keys (keygen under 1%).

## Patterns, by size
1. **Derived values whose inputs move far more often than their answers.** A memo copies its inner reads into its readers (notes/engine.md, Derived values), so an `Effects` follower (each sync judgement) re-runs whenever anything a memo it asked read moved, though the answer did not. Where a value is read by many followers and its inputs are coarse (a component's whole timeline, an aspect's whole commit set), keep it as a `Cutoff` row (`wrap_blocked`, `held_writes_rows`, body facts and fates) or narrow its reads. The copy costs more than the rerun: n readers of an aggregate over n inputs record O(n²) reads per change. Next candidates by count: `life`'s lost-access and role-duty keys (moved by `timelines: whole`).
2. **Work done twice in one judgement**: the same facade value asked from several calls (`sync_body_now`, `sync_bodies`, `covered` are memos for it); `held_blobs` per judgement.
3. **Every test builds its world from nothing, and many build it once per case.** Exact in-memory copies exist for `LocalPeer`, the sim `World` and osis-sync's fixtures and differential worlds (notes/test-harnesses.md, notes/sync-test-harness.md). Left: tests that close and reopen a node from a store the setup kept, the order tree walk past the setup.
4. **Default tests at full width.** Rule: a covering set by default (named regressions, each item first and last, the smallest sizes where the counted quantity is not trivial, just past the threshold); the full width through `testenv::large_n` and `_large` twins. Left: `order::held_set_decides`' quick size, crdt variant loops other than `part_judges`, engine scale tests at 20/200 and 30/300, osis tests writing past `COMMIT_PAGE` (256) commits on one aspect.
5. **Real time waited out** (osis real-runtime tests): must-expire timeouts of 300 ms to 2 s (`runtime.rs`, `port.rs`).
6. **Quadratic helpers**: `apply::keys::tests::spread` sends every commit to every peer again.

## Properties and the sweep
- `order::held_set_decides` runs quick and quick-exhaustive in the default tests, plain and exhaustive as properties. Every order of a held set ingests the setup again in a fresh account; left, without losing an order: walk the permutation tree depth first, copying the node at each prefix past the setup (`Peer::copy`), so a prefix is ingested once.
- Fixed-seed properties run in every gate (forged_parts, tombstone, unmerge_paged, crdt stream and paging, base proptests): the same run each time; only worth it when the branch touches what they reach.
- Seed counts stay; the time is to come from the work each seed does.

## Order of work
1. osis-sync's per-delivery work and the snapshot re-judgement (Left 1, 3).
2. The facts' reads narrowed (Left 2).
3. The order tree walk (Properties).
4. The width rule (Pattern 4), file by file.

## Method
Per-test instructions: `tools/pertest.py` (every default test alone under `tools/icount`; `top`, `compare`). Whole binaries: `tools/icount <bin> -q` from its package dir, every binary through `tools/heavy`. Where a binary's time goes: `tools/cpuprof OUT <bin> -q`. Why a judgement re-ran: take `costs` in a test (`osis_base::costs::take()` before, again after) and read the `"<effects> <- <cause>"` counts (notes/engine.md, Why a key went due).
