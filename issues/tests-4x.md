# Tests cost about a hundred times what they should
> Summary: The default tests are about 6400 G instructions (each default binary under `tools/icount` at 16 threads: osis-node `it` 3490 G, osis `it` 1205 G) and 2900-3200 CPU-s, 250-370 s wall on ostrich at load 25-30 (the gate's share 1610 / 115); a median node test runs 1.0 G instructions and a median osis test 1.15 G, where a test should cost milliseconds. No single cause: every test builds a multi-node world from nothing; node-sync derives everything again on every pass (36% of default-test CPU); crypto is 19% (product paths, the forensic attack); every engine transaction, a read-only lookup included, pays the same epilogue (about 9%); the debug checks about 10%; default tests enumerate orders, seeds and sizes at full width; the gate runs the same properties at three sizes and each sweep scenario 15 times. A superlinear product path a test happens to reach shows as an outlier in the per-test counts (Whole default suite, below). Target (Tess): 4x faster without losing coverage that matters.
> Priority: normal
> Tags: tests, performance

## Profile (main f89ea208d and ffc5f52e4, ostrich, 16 threads)
Every default binary under `tools/icount` and `tools/cpuprof` in one run, and every default test alone under `tools/icount` (3931 tests, 7065 G: node `it` 3723, osis `it` 1413, engine lib 614, held-model 280, crdt lib 231, sim `it` 227, perm 155, chat 121, the rest 300).
- Shares of all samples (inclusive, overlapping): node-sync passes (`SyncEngine::handle`) 36% (40% of node `it`, 65% of osis `it`); crypto 19% (Curve25519 10% self; `VerifyingKey::verify` 3.5%, of it node-sync's stamp checks 1.8%; `aead::seal` 2.0%; the forensic attack's `Trial` 3%; `VerifyingKey::from_bytes` 2.0%, of it the host parsing a stored label `Step` at every read 0.7%; `SigningSecret::from_seed` 1.3%); ingest 13%; `crdt::stream::stream` 9.3% (a stored part read again decode-only at every join, `read_part` 4.8%); the work `Engine::run` does around its closure about 9% (store commit 3.7%, `index::write` 2.1%, `leave_if_removed` 1.5%, `commit_journal` 1.2%); `check_index` 6.5%, `misjudged` 2.0%, `check_rebuilt` 1.3%; states written whole (`write_full`) 2.4%; `create_account` 2.5%.
- By size: tests over 20 G are 21% of the instructions (43 tests), 10-20 G 20% (105), 5-10 G 17% (173), 2-5 G 20% (466), 1-2 G 12% (575), under 1 G 9% (2569). The 2-10 G middle is multi-node setup and sync passes.
- Setup alone: the commonest node setup (`Net::new`, a host, three nodes, one group with two holders, one item, `run`) is 968 M of a median node test's 1700 M; osis `sharing::alice_bob` is 2000 M of 2400 M. Account creation is not where setup goes, the whole scenario is: a setup has to be built once and copied whole, in memory (a copy by reopening restarts every node and pays its reconnect and first sync again).
- Crypto by primitive (% of all CPU, main 2426ee91e): Curve25519 9.7 (product 5.9, `misjudged` 3.1, `check_index` 0.7), XChaCha20-Poly1305 7.6 (product 2.1, forensic attack 5.5), BLAKE3 1.0, ML-KEM-768 0.6. Key generation in setup is under 1%.
- Per test (`tools/pertest.py`, 8 jobs): main 5e37f276b 3967 tests, 7077 G alone; with table pages encoded once per transaction (notes/local-store.md, Cost) 6943 G (node `it` and osis `it` -2.0%, store `it` -29%). By module (5e37f276b): node `ephemeral` 422, `order` 334, `scale` 332, `destruction` 190, `stream` 188, `shred_sync` 162. `awaits::a_part_missing_again_*`'s 30 G there was a deposit/delete storm, 1.5 G since. crdt `tests_stream::stream_check_matches_whole_spec_8` moves 18-24 G between identical runs.
- Whole binaries (`tools/icount BIN -q`, 5e37f276b): node `it` 3417 G, of it the index checks 359 G (10.5%; with `check_index` returning at once 3057 G); osis `it` 1134 G.
- Measured, not levers: duplicate index checks (41% of node `it`'s `check_index` calls ran on a store and clock already checked in the process, 25% by store bytes; a memo would save at most about 2.5% and put a cache in front of the oracle). Scale tests: the index checks are 43 G of the scale module's 328 G (in one process), so checking only at the small size of each n/10n pair would save about 1% of node `it`; "90% of the measured changes" in `scale::group_change_is_flat` is of the counted work, not of the test's cost. The forensic attack's section tries are a full AEAD open each (a section wrap's plaintext is a random key: no byte rules a candidate out early); about two thirds of `shred_sync::purge_leaves_reaction_*`.
- CPU seconds move 20-40% between identical runs (load, SMT): compare by `tools/icount`, find where time goes with `tools/cpuprof` over the whole binary.

## Left, by size
1. **Node-sync passes** (pattern 2): retention's replaced dates (`must_hold` -> `part_keeps` -> `judge_replaced_at`, 4.7% of osis `it`) are judged again whenever the aspect's state moves, so each write re-judges every held part of the aspect; an exact incremental form would date only the parts a write supersedes. Then `log_events_from` 17% and `certificates` 5.4% of osis `it`. `scale::role_entries_follow_role_churn` (47 G): `carry_out` 30%, `certificates` 21%.
2. **A read-only lookup is a whole transaction**: `has_blob` is 1.4% of default-test CPU, 0.15% of it the lookup; `get`, `covered` and node sync's other per-entry queries pay the same epilogue (addenda and `leave_if_removed`, the dues, `index::write`, the journal, the store commit). Skipping the epilogue when nothing changed is not exact (`leave_if_removed` reads current edges, which time ends without a write); a read path that cannot write would be.
3. **The forensic attack's tries**: candidates (130-185K per attack) × each unopened section and blob, the first attack on each thread in full; each candidate prepared again per attack (`Trial::new` 12% of `purged_synced_body_crash_safe`, dropping them 9%), the harvest of every window again per attack.
4. **`order::held_set_decides`** (282 G alone, the costliest test): ingest about half, held-model compares a fifth, `check_index` a sixth; `held::convert` converts every held body again after every ingest of a clocked order (O(n²) per order; a per-body cache would save at most 1.4% of node `it`).
5. **`check_index` has no exact incremental form**: its halves are two loads from scratch (persisted index; commit records with every validity judged anew), and everything it caught is incremental-vs-from-scratch on an unusual path. Checking only what a transaction wrote trusts the change tracking it tests. Cheaper loads are the lever, and they are the product's open. Inside a check: the rebuild about 60% (`secrets.0` states with every box opened again 14%, role bodies' parts decoded 11%, re-judging 7%, `note_required` 8%), the open from the index 17%, `misjudged` 7%, dropping the two cores 7%. Rejected schedules: once per engine at its drop (no gain; wrong for time-dependent state); one transaction in 8 (7.7% fewer instructions, but loses the check after an engine's first status change, where most of its finds are).
6. `write_full` re-encodes a whole state where `set_state_touched` cannot write the touched pages (2.4%; `ephemeral::grown_past_a_blob_compacts_spec_sync_9` 25%).
7. **A single-use link's redeem costs about ten reusable ones'**: 2.3-2.8 s of osis `sharing::link_spent` and chat `flows::link_joiners_are_participants`; the work is in the first `advance` after the join (node-sync passes, `rotate_below`, `reseal`, `part_keeps`).
8. `net_records::no_connection_resumes_*` (42.7 G, 12 seeds of 14 steps): node-sync passes 64%, the per-seed setup a quarter; a shared base per seed class or a covering seed set (9 of the 12) would save 20-25%.
9. `rotation_holds_spec_crypto_4` (54.9 G, 8 seeds; `tally` needs 8): ingest 50%, `check_index` 26%, `LocalPeer::packages` rebuilt whenever the sender moves 13%. 95% of its ingests are re-deliveries of known commits, each fully decoded before `late_parts` finds nothing new.
10. Allocation (glibc's allocator, the production one; no other wanted): still through a `Value` tree are epochs, histories and schema reads and a header's signatures and rotation keys; B-tree nodes of fragments and of `Winners`/`ByWrite`; fragment clones where a join consumes its side (`ops::joined`, `held_parts_at`'s owned copy, `amend_held_writes`); `kdf_key` formats `"osis v1 " + purpose` per call (3%).
11. The host parses a stored label `Step` (two point decompressions per key) at every `LabelStore::step` read (0.25%).

Rejected levers: `opt-level` 2 for the workspace (3-10% for a full rebuild). Fake crypto in tests (the ceiling is the 9.3% of product-path crypto): a debug-only runtime switch making crypto trivial (every forgery and wrong-key test must opt out, one that forgets is silently weaker), a verification memo in osis-crypto (debug and release differ, memory grows, about 1.6% gain), dependencies without debug assertions (about 1%, loses their assertions), precomputed keys (keygen under 1%).

## Patterns, by size
1. **Every test builds its world from nothing, and many build it once per case.** A world is accounts with real keys, groups with rotations, labels at hosts, and a settle. About 120 of the 260 slowest tests rebuild one setup per order, seed, case or crash point; the short tests are mostly setup. Exact in-memory world copies exist for `LocalPeer`, the node `Net` and the sim `World` with its `osis` handles (notes/test-harnesses.md, Copied worlds), and the common preludes are built once per process (osis `common::hosted_accounts`, node `hosted`, chat `flows`' `accounts` and `room` keyed by their `Options`). Open: setups used once or twice per key (osis `World::new` beyond `hosted_accounts`), tests that close and reopen a node from a `MemStore` the setup kept (not copyable), the order tree walk past the setup (Properties, below), `NetSim`.

2. **Node-sync derives everything again on every pass.** issues/derived-state-recomputed.md: about two thirds of osis `it` and nearly all of the sweep's heaviest scenario are inside `SyncEngine::handle`, of it `part_keeps` 17-23%, cover judging per pass (`drop_covered`), label judging. The memo work there is the lever for osis `it`, the sim tests and the sweep.
3. **Keys kept as bytes are parsed at every use** (main sites parsed once: notes/crypto.md, Parsed once). Left, each 0.3-1%: a role secret's derived keys (`DeleteSecret::derive` in `newest_delete_key`, `role_kem`, `possession_secret`, label keys tried per held secret in `registered_key`), which would need a role-secret type in `EpochInfo` holding them lazily in its own zeroizing container; `CreationRecord::KeyActor`'s key (osis-base, below osis-crypto) parsed per signature check (`apply::epoch_key`, `base_of`); an account's first-epoch KEM key read from `keys.0` per seal (`epoch_kem`); steps re-parsed when the `labels` memo recomputes.
4. **Default tests run at full width.** Rule: a default test runs a covering set (named regressions, each item first and last, the smallest sizes where the counted quantity is not trivial, just past the threshold tested); the full width goes through `testenv::large_n` and `_large` twins (a twin added where the width found bugs). Left: `order::held_set_decides`' quick size (one seed per emphasis, about 270 G: its cost is per order, pattern 1's tree walk), crdt variant loops other than `part_judges`, node scale tests at 20/200 and 30/300 and the net-built tests (`inbox_life`, `net_records`, `net_judgment`, `shared`, `stream`: the one-peer harness work is changing them), `notes::large_body_streams` (a 132k-char text is the smallest above `CHUNK_THRESHOLD`, which its Fetch-storm regression needs: a 69k unchunked body misses it; its cost is the text CRDT, 91% `crdt::stream::position`), `write::list_edits_match_whole` (larger items load 7 pages per edit against its bound of 6), `port_clients::client_session_differential_against_grants` (3 hand-picked walks, no twin).
5. **Work done twice**: near-duplicate tests on identical worlds (reconnect.rs:82 and :96, destruction.rs:237 and :311, pass_sources.rs:109 and :120, write.rs:591 and :673, tied's copy-survives and group-admin pairs), a history replayed twice (`keep_for_d_named`, keep.rs:906), `advance(); run();` where `advance` already runs (33 times in tombstone alone), a full compare or reopen after every step of a long script. Not a lever, measured: the must-fail `try_until` walks (sharing.rs, 200 steps): quiet steps are cheap (130 steps saved under 4%).
6. **Real time waited out** (osis real-runtime tests, about 10 s of wall): the node's 5 s redial after a heal (sources.rs:268), must-expire timeouts of 300 ms to 2 s (runtime.rs:409, port.rs:415-455), 200 ms sleeps (keep_clients.rs:218).
7. **Quadratic helpers**: `Net::item` rewrites the whole `group.0` per item, `apply::keys::tests::spread` sends every commit to every peer again, a receiver made as one of nine meshed peers.

Not a lever, measured: delivering only missing commits in `Net::pair` changed nothing.

## Properties and the sweep
Read, not measured per seed (35 property tests by `tools/test_select.py`'s rules: node 18, engine 2, perm 9, crdt 3, base 2, osis 1; 52 sweep scenarios at 15 seeds).
- **One property at three sizes in every gate**: `order::held_set_decides` runs quick (8 seeds) and quick-exhaustive (8 seeds, at most 4 commits) in the default tests (95-110 CPU-s, a fifth of osis-node `it`), plain (8 seeds of 60 steps, 85-220 CPU-s) and exhaustive (8 seeds, at most 6 commits, 530-790 CPU-s) as properties. Every order of every held set is a walk of one permutation tree from its root: each delivery makes a fresh account with real keys and ingests the whole setup again, and each order then reopens, re-judges and runs held-model twice; orders starting with the setup as made start from a copy of one node given it (`Played::setups`). Left, without losing an order: walk the tree depth first, copying the node at each prefix past the setup (`Peer::copy`), so a prefix is ingested once; skip a subtree whose prefix left the same store and index as one seen. The quick seeds gain little from it (the per-order checks and the clocked orders' held-model compare after every ingest dominate); the exhaustive property (every permutation of up to 6 commits) should gain more (not measured).
- **A sweep seed is mostly calm setup and quiescence.** `persons` and `shared_group` build accounts with real keys and call `quiet` per grant; `quiet` (sim `net/mod.rs`) needs at least three settles and two 61 s resync rounds even when nothing moves, the end adds three more for the ping-pong check, and `finish` formats and hashes every host log record into a digest the sweep drops. `member_churn` runs 13 quiets around about 120 random steps. A seed changes keys, clock skew and the faulty steps; the calm setup is the same story every time. Fix: a base world per scenario built once (two or three base seeds for key variety) and forked per seed; a setup quiet that stops at an empty queue with every node idle; the digest only where it is compared.
- **The same generator under several names**: the three eph window properties and churn (20 seeds each, 12 distinct setups), the reverts pair, the keep pair, eight sweep scenario pairs built by one function. One seed range per generator, the seed choosing the variant.
- **Checks after every step**: paged `stored_each`, held-model after every clocked ingest, resume's check, the engine-only sweep scenarios reading every aspect of every node each step.
- **Fixed-seed properties run in every gate** (forged_parts, tombstone, unmerge_paged, crdt stream and paging, base proptests): the same run each time; only worth it when the branch touches what they reach.
- **Wall, not CPU**: two single-threaded paged seeds hold the engine property step for 35-83 s with the other cores idle; tied's four seeds run one after another.
- Seed counts stay (15 per sweep scenario; the exhaustive order property 8, one per emphasis: its seed picks the emphasis, so fewer drops emphases). Fewer (5, 2) cut the gate from 480-625 s to 363 s, but the time is to come from the work each seed does, not from fewer seeds. Open: one shared seed range for same-generator properties; a failing gate seed rerun on main automatically, so a main failure becomes an issue and not a blocked branch.

## Order of work
1. The derived-state memos for node-sync's passes (pattern 2), as their blockers land.
2. Built-once setups (pattern 1): the order tree walk, `NetSim`.
3. Seed counts and same-generator merging in the gate, once decided; the setup `quiet`.
4. The width rule (pattern 4), the duplicates (pattern 5), tests that test nothing: file by file.
5. Read-only engine lookups without the transaction epilogue (Whole default suite, Left 1).

## Method
Per-test instructions: `tools/pertest.py` (every default test alone under `tools/icount`; `top`, `compare`). Per-test times: run a test binary with `RUSTC_BOOTSTRAP=1 <bin> -Z unstable-options --report-time --format json` from its crate directory; sum `exec_time` (rough: they move with load). To compare two builds: `tools/icount <bin> -q` over the whole binary. Where a binary's time goes: `tools/cpuprof OUT <bin> -q`. A profile: issues/derived-state-recomputed.md, Method.
