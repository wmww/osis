# A removed key's writes show where no node holding the removal syncs
> Summary: Removals travel lazily (notes/write-path-design.md §2, D1 to D3): a thing no remaining member writes, whose readers are served only by stores no node holding the removal syncs, shows the removed key's later writes as valid until such a node syncs it. Open bug (decided: not something to build around); held-model counts it as the gap.
> Priority: normal
> Tags: security, sync

**What happens.** X removes stolen key K from A. K wrote D through [A] before, and writes D again after. D's readers need the removal to drop the later write. It reaches D only where a node holding it holds D: as evidence of a write it judges there, logged by a node syncing both (D1); in D's keyset at D's next rotation by a writer holding it (D2); under the holder's sync ID and those whose keys open it (D3). Where no honest node syncs A (or another sync ID holding the removal) together with D, D's readers show K's later writes valid; the node holding everything drops them. spec/requirements.md as written allows it (a node missing data reads as if it never had it; a removal binds the nodes that receive it), but it is a hole a thief can use.

**The model.** held-model `evidence` judges each sync ID's reader against its reference (`World::reference`: everything but the removals no honest node syncing it holds) and counts where that differs from the node holding everything (`World::gap`). Hand worlds: `spec_evidence::gap_a_removal_no_node_holding_it_brings_leaves_the_write_showing` (findings 1, 3, 17, risk 3), `spec_reach::open14_*` (finding 18), `spec_gaps::gaps_a_removal_rides_a_write_through_a_read_hop_*` (finding 28). The properties print the count: `one_sync_id_reader_judges_as_everything_*`, `evidence_reach_and_generator_gaps_*` ("N worlds; M with the gap"). Counts: notes/evidence-model-findings.md 38 (and 41 with stamping: 105 of 1,848 `_plain` worlds, 360 of 6,544 `_large`).

**Candidates.** The reader's deposit on sight (write-path D4: a node holding the removal and a write it cuts that cannot stamp the unit deposits the removal's copy there) closes the part where some node reading the unit holds the removal; modelled as `Rule::deposit` (finding 41: 1,716 family and random worlds with the gap, 840 with D4; of the 876 it closes, 252 rest on a deposit no writer promotes). Nothing closes the rest without a node that holds both: an errand by the remover was modelled and dropped (Tess: no eager delivery).
