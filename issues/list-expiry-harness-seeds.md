# The expiring list oracle: one class fixed, one open (a value past T in an undo body)
> Summary: `order::arrival_order_list_expiry_large_spec_crdt_4_7` failures fall in two classes. (1) Fixed: a snapshot's hidden anchor vouched in the rebuild but not at join. (2) Open, security: an undelete's char copy of an expiring (or purged) char stays in the undo's body past the original's T: a leftover strips only the part's own writes. Seeds 9220029, 7520036, 9250009.
> Tags: security, engine, retention, tests

Repro: `OSIS_ORDER_SEED=<seed> cargo test -p osis-node --test it -- --ignored --exact order::arrival_order_list_expiry_large_spec_crdt_4_7`.

## Study (two classes)
1. **Vouch by a hidden anchor (fixed).** Seeds 9200001, 9200020, 9200037, 9220006, 9220011, 9220018, 9220021, 9220035, 9220036 and 7520035 (debug rebuild check on `t:listtext.0`, or a read of absent vs `[]`). A writer's expiring insert turns invalid. A valid snapshot taken after that holds the element as a hidden anchor with its creation's copy. The rebuild (`Unmerge::vouched`, from the copy index) counts that copy as vouching for the record, so the delta's chars stay in it as hidden anchors (spec/crdt.md §4.6 "Records a valid snapshot holds"). The join decided whether to rebuild with `holds_dots`, which ignores a content-less element, so it never rebuilt. Rule now: a snapshot piece triggers the rebuild exactly when the rebuild would read a vouched record from it (`copies::vouches_any`, shared with `vouched`). Not list-expiry specific: expiry only made the shape common. Pinned: `order::snapshot_anchor_vouches_invalid_insert_seed_9220021`, `order::snapshot_anchor_vouch_reads_alike_seed_9200020`.
2. **An undelete's copy outlives its value (open).** Seeds 9220029 (shrunk: `h = vec![Aim(Typed { by: 2, t: 0, op: 32, k: 0, v: 8 }), Aim(Typed { by: 2, t: 0, op: 33, k: 0, v: 9 }), Aim(Undo { by: 2, back: 2 })]` for `check(9220029, &h, Cfg { sync: true, ..LARGE })`), 7520036 and 9250009 (1 of 40 at offset 9250000 after the fix; 7 of 40 at 9260000, all insert, set text, undo of the set): `value_past_end`, "body X holds a value of Y, expired true". 2 inserts an expiring element and sets its text (deleting the chars). Its undo undeletes them, and its body carries the original chars (`undel: Some('8')`) under the creator's dots. The undo takes the earliest expiry among what it copies (`undo_expiring`), and at its own T it becomes a leftover. But `make_leftover` strips only the undo's own writes (`writes_of`), and §4.7 attributes the char copy to the creator ("goes wherever that value goes"). When the creator expires, `hold_valueless` strips only the creator's own body. No step strips copies of its values held in other deltas' bodies. Purge has the same gap (issues/copies-outlive-purge-expiry.md): `purge_one` strips held snapshots, never deltas.
   - The rule that is missing: when a write goes value-less here (by expiry or purge), every held body carrying a copy of its value (snapshots, and deltas through their undelete chars) is held as its leftover, stripped of it. A body arriving later is also stripped against the whole value-less list (`drop_gone` checks only the part's own writes).
   - What leaks: the state is stripped (`strip_valueless`), so reads and new snapshots here are clean. The body keeps the char on disk past T, and it is served to peers. A peer holding the creator's header strips it on join. One that never got that header was not checked.
   - Fix shape: finding the carriers needs either a per-aspect index of the bodies holding undelete chars (by copied dot) or a walk of the aspect's bodies on each expiry or purge, which costs O(bodies) per expiry. Not patched: this is a design choice, and the second seed-found fix in this area.

Also seen at the base, unrelated: sim `purge_falls` and `purge_falls_churn` seed 7410503, "the purge never reached the writer".
