# Vouch duty as a memo over its inputs
> Summary: `flows/vouches.rs` keeps "what a node owes for removal R" fresh by hand-kept triggers (notes/engine-roles.md, Vouches, Write: the inputs table); gaps were found one seed at a time. Make the decide an `osis_base::memo::Effects` value per removal so a changed input wakes it by construction; needs perm to stamp the decide's reads finely enough that the vouch cost tests still hold.
> Priority: normal
> Tags: engine, perm

**Why.** Each trigger of the vouch duty is code someone remembered to write (`note_changed`, `note_evaluated`, `wake`, `note_roles_moved`, `note_entered`, `note_due`). A missed one is an answer never written: an honest write the remover missed falls for good at every node. Meanwhile debug builds run `vouches::missed` after every durable transaction, so a miss in any history a test reaches fails at the transaction it happens; the triggers overlap (notes/engine-roles.md, the inputs table: `note_due` on late parts and `all_due` are backed by `note_changed`, `note_changed` by `wake`), and `note_evaluated` has no test failing without it.

**Design.** Split the judgement as today: the gathering (whether R applies, its candidates) and the decide (`owed`: this node's roles, its own counting answers, components, the node closure). Keep the decide's answer in an `Effects<CommitId, Owed>` (`osis_base::memo::Effects`: `settle(r, f)` records every stamped read, `due()` gives the removals whose reads moved, in proportion to the writes since). The due set becomes `Effects::due()` plus the gathering's own triggers. A read the debug `Checks` finds unstamped is a bug, found by construction rather than by a seed.

**What blocks it.** The decide reads the component's `Timeline` (`could_write`, `counted_by`, `component`, `trust`), and a timeline is one value per component: any role commit there (a removed party's junk included) would move every removal filed there, breaking `a_role_change_elsewhere_rescans_no_candidates`, `never_applying_removals_cost_an_honest_write_nothing` `a_removed_partys_junk_grant_and_forged_vouches_change_nothing` and `a_thing_entering_wakes_only_the_removals_filed_under_it`. Perm needs to offer stamped reads of: one party's roles on one thing at a point of the first walk (`could_write`, `role`), the counting entries per (voucher, removal) (`counted_by`), a thing's component, the trust set. With those, the decide's reads are as narrow as today's triggers, and the gathering (whose reads are the walk before R) can follow (issues/vouch-trigger-cost.md wants the same per-walk change report).
