# Edits of a signal's writes as an osis rule
> Summary: Proposal: osis checks "this write replaces my earlier one" for signals (same verified author, original held and valid, no edit of an edit) and folds versions in listings and watches, so chat's edit model (osis-chat `Timeline`, `find`, `edit_of`, the `prior` list, the second purge commit) becomes plain osis and every app with editable log entries gets honest edits. Not built; needs a design pass and Tess's go.
> Priority: low
> Tags: osis, crdt, chat, tess-call

- Today an edit is a chat message whose body claims to replace an earlier one; osis does not read the claim, so every reader must check it (same verified sender, original here and valid, no edit itself) or a forged edit replaces someone's message. osis-chat holds that fold so its Rust readers agree; another implementation must copy it from notes/chat.md. It is a protocol rule living in an app library.
- Proposal: a fire may name an earlier commit on the same signal aspect it replaces. osis honors it only when the named commit is held, valid, by the same verified actor, and replaces nothing itself; otherwise it is a write of its own. `fired` lists an original once, with its newest honored version (earlier versions on request); a watch hears a replacement as a change of the original. Newest by `(ts, ID)`.
- What it removes: the edit claim in chat's schema, the `prior` list kept to answer for tombstones, the second commit purging the old text (a purge request carries no expiry; "purge on replace" could become a signal retention option, today forbidden for signals, spec/commits.md §5 Signals), osis-chat's `Timeline`/`find`/`edit_of`. Fits "history is verified or absent" and "one mechanism" (a register already has replace).
- Questions: header field or checked body field (spec/wire.md, spec/commits.md §5); an index from original to versions (osis has no lookup by commit, issues/api-deferred.md); validity changes (an edit turned invalid shows the version before it; an original turned invalid takes its versions with it); expiry and keep bounds per version; "edits off" as a required rule refusing replacements; the listing's shape (one entry per original vs per commit with a checked `replaces`).
- Cost evidence (the app's typing freezes): a message's newest text is known only by walking from the newest message back to it (edits can come any time later, and nothing maps an original to its versions), so quoting a message costs the history since it. The app's chat page resolves its quotes in one walk (`osis_chat::find_all`), yet every re-render still pays the history back to the oldest message the page quotes: a reply to the first message of a long chat costs the whole chat per render. Folding in `fired` alone does not remove this; folding plus an index from original to newest honored version does (a quote becomes a read by place plus a lookup).
- Tess decided an edit is a new message (notes/chat.md Tess's decisions); this keeps that and moves only the check.
