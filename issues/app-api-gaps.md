# API gaps met by the first app
> Summary: What the kit/app prototype worked around in the `osis` API: callbacks only on the dispatcher thread (one marshaling hop per change), no per-app well-known root (devices racing at first start make duplicate app groups), and the item-versus-subgroup sync footgun of an app's internal group.
> Tags: core-ask, api, owner-call

Repro: app/ and kit/ (notes/app.md Prototype); no failing test.

- **Dispatcher on the UI thread**: callbacks run on osis's dispatcher thread, so every change crosses threads through kit's `marshal` mailbox and a winit user event before the UI can touch widgets. Ask (already in notes/app.md State in osis): a mode where the app pumps the dispatcher on its own thread (e.g. `Config.dispatch = Manual` plus `db.dispatch_pending()` and a wake callback). Not blocking.
- **Per-app root**: the app needs one internal group per person ("my notes"). It finds it by scanning home's subgroups for a marker aspect; two devices starting before their first sync each create one, and the app reads the union and writes to the smallest tid forever after. Ask, owner-call: a well-known thing per (person, app or schema), e.g. a tid derived from the person and a name, created idempotently, so concurrent creation converges to one thing. Alternatively bless the scan-and-union convention in notes/tags.md.
- **Item vs subgroup**: the obvious way to make an app group sync, `create(me, Place::In(home))` plus `make_group`, syncs the group's own aspects but not its items (a group's members are its items and its subgroups' members), so notes placed in it stay local; osis reports `NotSynced` per note, which an app that does not subscribe to diagnostics never sees. The app also calls `add_subgroup(home, g)`. Ask: either document this pattern next to `Place::In` (notes/api.md, notes/tags.md "Apps keep an internal synced group") or offer it as one call; consider failing `create(.., Place::In(g))` loudly (or a typed warning on `Committed`) when the placement reaches no synced group.
- Lists: no queries (issues/api-deferred.md): the app re-reads home, its groups and every note's name on each change and holds one `/name` watch per note.
