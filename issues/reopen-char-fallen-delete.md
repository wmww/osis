# A reopen's dropped char lost when the delete falls and the creation body is gone
> Summary: Suspected, untested: a node drops a deleted text char at reopen (spec/crdt.md §5.7); if the creation's body was dropped under keep-at-most and the delete (or delete and undo) later turns invalid, the un-merge rebuild has no body to give the char back, so this node reads a hidden anchor where a node that never reopened reads the char.
> Tags: engine, crdt, retention, tests

Shape: owner types a char (keep-at-most drops that body later, the char lives in the state); writer W deletes it; node A reopens (the char goes, `apply::atomic` `unmerged_as_rebuilt` comment: "its creation's body gives it back on a rebuild"); W is demoted below the delete. Node B, never reopened, reads the char; A reads nothing. With W's undo of the delete in between, A reads the undo's copy (`undel`) until the demotion takes the undo too (raised in the order-seeds-b work, seed 198). spec/crdt.md §4.6's keep-bounds limit covers what an un-merge leaves out of a dropped body, not a char the node dropped itself. Options: keep a deleted char whose creation body is not held, or state the limit in §4.6/§5.7. First write the order-harness case (keep bounds, reopen, demotion) to confirm.

Not reachable by the order harness yet (checked in the harness-clock work): no generated op writes a text under keep at most (the kept texts, ops 23-26, are keep-at-least), the arrival-order checks reopen only once everything is held, and `drops_alike` reopens after every ingest but gives every body back before comparing. The case needs a scripted test: a keep-at-most text (a new op or a `Step`), the drop, a reopen between the delete and the demotion.
