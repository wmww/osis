# Rules with two code homes in core, left unmerged
> Summary: Rules computed in two places in core that need a decision or a refactor larger than a merge: the writer's keys.0/secrets.0 role pre-check, duplicate-blob judgement, the drift bound's local exemption, hand-rolled record-chain walks, chain epoch folds, register planning.
> Priority: normal
> Tags: engine, sync

- **Writer role pre-check vs receivers** (`engine/write.rs` `ops_role` on the ops, `apply/validity.rs` `rotation_required`/`secrets_role` on the built delta). The writer lets through writes receivers judge as admin: a non-struct `keys.0` delta, a reset of field 8, a box record without its role's keyset; any `secrets.0` op passes as write (whole-value writes, key-erased records, keys that are no box key). The writer's own node applies `rotation_required` too, so nodes agree; the writer just accepts a write it then holds invalid. Fix: judge the built delta with `rotation_required` at the writer (and in `check_confined`), deleting `ops_role`. [Medium.]
- **Duplicate blobs of one commit** (spec/sync-compaction.md §1 Duplicates): `sync/read/judge.rs` `duplicates` groups by (parts, sealed) and keeps the lowest ID; `engine/sync/bodies.rs` `blob_loses` (`Loss::Spare`) also compares `ais` and applies `stands`; a sync-only shared blob beside a copy loses whatever its ID only in judge.rs. Decide against the spec which is right, then one rule. [Medium.]
- **Drift bound** (spec/crdt.md §2.2): `apply/mod.rs` exam holds a received commit more than `MAX_DRIFT` ahead, exempting local ones; `still_waits` has no exemption, so an own commit waiting for something else after the clock went back stays waiting until the wall catches up. [Small.]
- **Record-chain walks** (spec/permissions.md §1): `perm/timeline.rs`, `apply/validity.rs` `chains` walk `0..=MAX_CHAIN_DEPTH`; `engine/write.rs` (`clear_tells_nothing`, `held_path_secret`) and `apply/paths.rs` walk `0..=MAX_CHAIN_DEPTH + 1`, one thing past the deepest valid chain (unobservable: a thing that deep takes no valid write). Each walk does its own work per step; moving them onto `osis_base::record_chain` would give the bound one home. [Small.]
- **Chain epochs** (spec/crypto.md §3): `engine/secrets.rs` `chain_epochs` and `sync_ids/blobs.rs` `chain_epochs` fold `ActorEpochs::derived` over a reversed chain; inputs differ (nearest held actor vs every member). [Unsure whether one rule.]
- **Register fit** (spec/sync-ids.md §6 Register): the fork step's delete key is the head's, or the head's key endorses the last step: `sync/store/path.rs` `by_head` (receiver) and `sync/inbox/register.rs` (sender planning). [Low: a sender predicting its receiver.]
- **A body's certificate test**: `sync/bodies.rs` `bodies_for` says certificates are made of role-class parts, a card and a record; `retention::forget::certificate`, which it calls, has no card. [Unsure which is right.]
