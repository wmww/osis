# Ephemeral commits decoded later than their room check
> Summary: A memory commit is checked against the node cap's room only when it arrives (`ingest_memory`, `new_parts_bound`); one that waits (its pages not held yet, drift, epoch) is charged its bytes and applied later by `reexamine` with no bound check. Its pages are charged their bytes on arrival and counted in no bound, so a writer can make holders decode and hold about 200 times the cap per label (pages of tiny map entries, items per page unchecked for ephemeral). Breaks spec/sync.md §9 Caps ("decoded only as far as a bound ... fits the room left").
> Priority: normal
> Tags: security, ephemeral, engine, node

- Routes: (1) upload a paged commit's root before its pages: `pages_bound` counts only held pages, the commit goes pending (`WaitBlobs`), each page is charged its encoded size (`ingest_memory_blob`), and once the last page lands `reexamine` decodes all of them; (2) on main already: several commits with `ts` past `MAX_DRIFT`, each within the room at arrival but charged only its bytes while pending, so their bounds add up to about 100 times the cap. `recharge_applied` fixes the accounting afterwards, not the decode.
- The ephemeral page params skip `MAX_PAGE_ITEMS` (`PageParams::EPHEMERAL`, values inline), so nothing bounds one late page's decode but its blob (about 56 B per byte).
- A delta may link held pages outside its chunk list (nothing checks the converse of spec/wire.md §4 field 8); `pages_bound` follows only listed blobs, so such pages are decoded uncounted too.
- notes/ephemeral.md Bounds still names `PENDING_SHARE` and a pending charge by `memory_bound`; neither is in the code.
- Fix direction (one rule: nothing of a memory commit is decoded past the room): a memory commit is applied only within a room check made with all its bytes held. Either the engine keeps the room a pending memory commit was given and `reexamine` checks the full bound against it (`TooLarge` then, node-sync refusing the entry for room), or node-sync hands the engine a memory commit only once its listed pages are held. Plus: a delta linking a page its commit does not list is bad input (both classes), and a pending commit is charged its bound, not its bytes.
- Test: a paged commit whose root arrives before its pages, at a node whose cap holds the pages' bytes but not their decoded bound, is not applied there (`EphemeralRefused`); drift-pending commits likewise.
