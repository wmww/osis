# A writer's forged copy of another's write changes what it reads, unattributed and undetected
> Summary: a valid snapshot may carry another author's write under its stamp with another payload; copy order (spec/crdt.md §4.1) can pick the forged payload, so every reader shows the forger's value in place of the author's, with `changed` still naming the author's commit and no history entry for the change. A node holding both copies has proof (the author's signed delta, the forger's signed snapshot) but by spec never compares them. Should it?
> Priority: low
> Tags: security, crdt

**Decided (Tess):** an open issue, not built around. What a snapshot carries is its writer's word; to do: the API attributes a value to an author only where the author's own commit is held, else to nobody.

What a forger (any writer of the thing) can do, by spec (spec/permissions.md §5.2 Copies):
- Copy order decides each part by bytes (the greater value, a valued copy over a value-less one), so the forger picks a payload that wins: every node holding both copies reads it (osis-engine `retention::tests_forged`: all nodes alike, the forger's reference in place of admin 0's int).
- The author's write is not dead (copies are one write, spec/crdt.md §4.8), so its body is not replaced and stays (never covered by the forger's snapshot: spec/commits.md §5 Covered), and kept history shows no change. `Osis::changed` names the author's commit (snapshots are no change, notes/api.md Attribution); a watch hears the snapshot as `Origin` only where it arrives after the original.
- A snapshot's facts (spec/crdt.md §8) are its word too: one misnaming a carried write's purge author steers a purge by author at a node holding no honest snapshot of it; holding one, the two disagree and the purge takes nothing (osis-engine `retention::tests_carried::a_misnamed_purge_author_misleads_only_a_node_holding_no_honest_snapshot_*`).
- So a writer erases writes it has no right to purge, at some nodes: it names itself purge author of an admin's `author_or_admin` write in its snapshot and purges by author itself. A node holding that snapshot and the request, and neither the original nor an honest snapshot, reads the write gone; nodes holding the original are unaffected; a reader that later receives the original or an honest snapshot reads it again (the header decides; the lie never covers the original, so honest holders keep logging it). No accomplice is needed, and with one any writer can be the named author. Severity: a purge-right escalation (writer to admin's power) at snapshot-only nodes (a reader that never held the original; one that forgot it keeps its name and judges by that, spec/commits.md §5 A forgotten commit's name), lasting until an honest carrier reaches them; weaker than the forged value above, which every node holding both copies reads, for good (osis-engine `retention::tests_carried::a_writers_misnamed_fact_lets_it_erase_an_admins_write_at_a_snapshot_only_node_*`).
- Hiding is payload (spec/crdt.md §4.8: which elements a removal hides is read in the copies held as they join), so a forged copy of a value removal naming other parts, or of a set element's write holding another value, un-hides: a node holding it too dates the write's death later than one without it, or not at all (the element shows again), against spec/commits.md §5 "one holding more judges no later", which holds for honest copies only. Dates stay a function of the held set (osis-crdt `tests_winners::removal_copies_covering_the_dot_in_one_date_by_the_joined_copy_*`). A node that held only the honest copy may already have dropped the body from history: the forger's power is the one above (any writer may also just write a removal).
- An app pairing `changed` with the read ("edited by A") shows the forger's value under A's name. No API call attributes a value, so no API states it; but nothing shows the forger either.

Not wider than other snapshot powers: a writer's snapshot may carry a write no one made, under any stamp below its own (vouched, never judged as its claimed author's), with the same read and `changed`; that one at least kills the author's write, so history shows it replaced (by no attributable commit). Retention: a copy's superseding is dated at stamps no earlier than the victim's own, as a backdated replace is (issues/backdated-replace-cuts-history.md); same right (write).

The model question: a copy differing from a held original in a value (not by expiry, purge or key erasure) is a signed contradiction of a signed delta. Options: (1) as now, never compared; (2) a node holding both judges the snapshot invalid (it vouches for something its signer did not see), or flags its signer, the read keeping the original's payload; (3) copies differing in value never join (the original's payload wins wherever held). (2) and (3) make reads depend on whether the original is held, which (1) avoids for nodes holding the snapshot alone anyway; a fabricated write (no original anywhere) stays undetectable under any option.
