# A node that learns an ended actor raw reads it as a live thing
> Summary: A node granted after actor t ended learns t's record from a record blob and its frozen edges from copies, but never t's ending (no minting of t reaches it), so `Core::exists(t)` holds there: it knows t and reads t's roster, while every node that saw the ending reads t as absent (spec/commits.md §5). It also takes a copy of an edge write on t stamped after the ending, which nodes holding the ending drop (only a hostile holder places one), and a node that ended t keeping nothing, learning t's record again, judges and keeps a late copy of a content part on t.
> Priority: normal
> Tags: engine, node-sync, permissions

- Seen: in `ending::authority_through_an_ended_granted_admin_stands_spec_commits_5`, node d (granted g afterwards) has `knows(&t)` true and `roster(&t)` with t's two frozen admins; a, b, c have `knows(&t)` false and an empty roster. Writes are refused at d alike (`Core::writable` needs a held valid minting).
- Tried: reads asking for a held valid minting (a record alone makes a thing judgeable, not readable). It fixes d, but 15 node tests read things known by their record alone (inbox chains, invites before the creation arrives, `knows` of a record learned raw, `labels_of`'s debug recheck reading `label.0` through `get`), and held-model reads a raw-record thing as existing (`model.rs`, "a record is identity"). A semantics change for every raw record, model first.
- Directions: (a) the ending's evidence travels with the frozen history: a purge's request `purge.0` part as a certificate copy, an expiry's minting header as a header-only blob (its prefix without expiry), judged as an expired minting; (b) reads of a non-key thing need a held valid minting, content parts on a thing with none await one, and held-model follows.
