# Pairing as a rotation: a contact never reads a profile epoch its link was re-sealed at
> Summary: On the custody branches one osis-sync test fails, `siblings::a_sibling_paired_after_inbox_lifetime_keeps_an_accepted_grant_*`: a read-only rotation of an account's profile by a node not holding the card's link key's `keys.0` leaves the link out; the re-seal boxing it is wrapped under the new epoch the link lacks, and a read-only rotation issues no step, so the contact never reads the profile past it (nor the dial entries of nodes paired later).
> Priority: critical
> Tags: engine, sync, tests

- Fixture `stranger_siblings` plus a node 3 paired past INBOX_LIFETIME. Node 0 reads account 1's profile only through the card's link key L (static entry on the profile's sync ID). Node 3 writes its dial entry under the profile's derived epoch from its pairing epoch (plain at it then), so a read rotation merging that derived epoch is due (`rotation::merge`); the rotation (n3) is made where L's `keys.0` is not held: `members::sealing` gets no recipient for L, so L is left out. A later re-seal of L at n3 (spec/permissions.md §3 Re-seal) is wrapped under n3 (spec/crypto.md §5: only a rotation goes under the epoch it supersedes). L has no inbox (spec/sync-inbox.md §1) and a step is due only for a newer sync, write or admin epoch (spec/permissions.md §3), so no step's entry box carries n3 either. Node 0 never holds n3, never reads node 3's dial entry, dials only node 1, and node 3 (keeping the granted S unread) never gets a head of S.
- Two principled fixes, neither built: (a) a commit carrying boxes of read epoch e is wrapped under the epoch e supersedes whatever else it carries (drop "(a rotation)" from spec/crypto.md §5: a re-seal or grant is then read by every holder of the epoch before, and its role parts by floor holders through the roles secrets they hold); cost: a node lacking every superseded secret logs no grant or re-seal. (b) a step is due also for a newer read epoch than the head registers (every role alike), so a link's static entry box carries it; needs the head's read epoch at the issuer (only its entry boxes name it today).
- Seen with: `cargo test -p osis-sync --test it siblings::a_sibling_paired_after_inbox_lifetime`.
