# A held copy of a register write's embedding dies with no superseder
> Summary: `Fragment::winners` counts each embedded char's creation `(s.ts, Derived(s.dot), i)` as a write of its own, so a body holding text-slot copies of register write `s` that the join's winning copy does not embed (a forged text snapshot, or a `Slots` body whose register copy loses by copy order) has dead creations nothing supersedes: `Killed::note` returns `Corrupt` on an honest receiver's apply, and the node stops (issues/engine-invariant-wedges-sync.md).
> Priority: critical
> Tags: security, crdt, engine, retention

**Reach**: any writer. Register write `s` = "a" held; the writer signs a snapshot of the aspect carrying a plain text fragment with creations of `(Derived(s.dot), 1..=3)` at stamps `(s.ts, Derived(s.dot), i)`, chars "abc" (decodes: rule 7 rejects a `Derived` creation run only in a writer's delta). The join fits the text slot to the winning copy's embedding (`seq::fit_embedding`), the slot then adds nothing and goes, so creations 1..3 win in the snapshot and not in the join. A peer holding `s` fails receiving it ("receiving fails the node: engine invariant broken: a dead write nothing in its join supersedes"); the forger's own apply fails too when it holds `s`. Same with a `Slots` body holding register copy "ab" with its embedding beside a held "é" at `s` ("é" wins bytewise, crdt-level). Reproduced on main and on `forged-dead-write`.

**Rule**: spec/crdt.md §4.8 Which write already says a slot's embedding of the register is the register's writes, and copies of one write losing by copy order are no death; §7 calls every write at the embedding's stamps a copy of `s`. The dead side does not apply it: an embedded creation should be the register write `(Value, s)` at its position in `winners` (one write, whichever copy wins, dying when `s` dies), while as a superseder it still beats position and flag writes per char (`Payloads::embedding`, `held_writes`). Check `carried` and `held_writes` against the same rule, and the invariant comments on `ByWrite::first_superseding`, `judge_replaced_at` and `Killed::note`, which claim every dead write has a superseder. issues/embedding-copy-dates-early.md is the dating half of the same copies.

Test sketch (engine `tests_forged`): `reg` = `MFrag::Register` "a" at `mstamp(5, 3)`; `text` = `MFrag::Seq { text: true, .. }` with `MSeqElem::new((ts 5, Derived(mdot(3)), i), anchor i-1, Char)` for i in 1..=3; peer 1 forges `reg`, peer 0 forges `text`, peer 2 receives both: no local error, all read "a".
