# Range reconciliation leaves entries a host deleted
> Summary: A node whose cursor a host no longer serves (log trimmed, or a new log ID) falls back to range reconciliation, which only clears presence of the entries the host lacks; an entry whose bytes the node holds and has no delete key for stays in its sync state (and its co-reader feed) for good, where a log reader would have removed it on the deletion record. Blocks host log trim by age (notes/growth.md row 2).
> Tags: node-sync, host, growth

Repro (pre-existing with count-based trimming): a host with `log_keep: 16`; A (admin) and B (reader) on it; A writes `t:gone.0` (keep at most 1 h) v0, B reads it; B offline; A writes v1..v5 a minute apart; advance 2 h (the replaced bodies deleted at the host) and 1 min; B online, run, advance 2 h more. B reads v5, but `sync(b).entries(l)` still lists v0's body entry, which `host_ids` lacks. With B online throughout the sets are equal (the Deleted record went through `absent_at`).

Cause: `SyncEngine::reconciled` does `set_present(host, l, b, false)` for every id in `have`; `local_deletions` then removes an entry not present anywhere only when it can delete it (delete key) or no longer holds its bytes. A reader holding v0's ciphertext keeps the entry.

Why not just `absent_at` there: `CURSOR_INVALID` also answers a cursor under another log ID (a wiped or replaced host). Then `have` is everything the node knew present, and `absent_at` would tombstone each entry locally (peers' copies refused for `TOMBSTONE_LIFETIME`) and record it in `deleted` (re-upload judged as after a delete). The node cannot tell the two cases apart from the error alone. Options: the host says which (an error detail, or the reconcile reply carrying the log ID), or the node compares the fresh cursor's log ID before deciding.

Host log trim by age, ready once this is fixed (growth.md row 2): `HostStore::remove` puts a `Y` row for every durable removal (deletion with its tombstone, expiry without), its value the log position the entry went at (the Deleted record's sequence number, or `next_seq` at an expiry), due `tombstone_ms` later; the sweep drops each label's `G` rows up to the highest due position and raises its horizon there (each record once over the log's life). `MemoryLabelStore` mirrors it (a trim list per label, ephemeral removals excluded) so `agrees_with_reference_and_replays` still compares `log_after` (as an `Option`, at 0 and mid-log; the replay check skips a trimmed log). Spec: sync.md §4 log sentence. Test: overwrite churn plus an expiring entry, swept past the lifetime, leaves only the records after the last removal; the node-level repro above with the age trim in place of `log_keep`.
