# The public's listing counts only where no read secret is held
> Summary: `role_here` counts the public's sync from a head listing the public entry only while the node holds no read secret of the thing (Interim): the listing is noted at sync whatever role the box gives, and readers' listings never follow their head, so counting it everywhere breaks one test and a principled fix needs both.
> Priority: normal
> Tags: engine, sync

The rule wanted: a node's role on a thing is the max of what its grants give, the public's included, and the public's role its head lists (spec/sync.md §3 Holders by copies), whatever secrets it holds. `rotation::lost::role_here` counts the listing (`Core::public_listed`) only while the node holds no read secret; lost access's sync (`holds_sync`) counts it always.

Cause, found on `differential::a_node_lowered_with_the_public_reads_again_on_its_regrant_*` with the condition dropped: node 1 keeps the thing unread by its own sync grant, known by copies alone (the grant is under read epochs it lacks, so its role by grants is none). The public is granted read again, and the new step lists the public entry with a read box. Node 1 takes that box (`Engine::public_head`, `reads`) before the role commit regranting the public applies. `learn_grant` notes the listing at sync. With the listing counted, `role_here` is sync, so `loss_seen` sees "a role shows" and `judge` finds read secrets no role covers: it drops the read secrets the box just gave (`lost access ...: secrets dropped read[2,3]`), refuses the entries, and never reads again. Not counting the listing, `role_here` is none, so this is "secrets taken with no role yet", no loss, until the regrant applies.

What a fix needs, both together:
- The listing notes the role the box gives: read where the box carries read secrets and the head is current for reading (`unread::Public::Listed { reads }`, or an open by the public entry), sync otherwise. A head listing the public at read then gives read, and nothing is dropped.
- Readers' listings follow their own head. Only osis-sync's unread judgement clears a listing (`Engine::public_head`, at each head move of a sync ID kept unread); nothing clears one on a sync ID the node reads. A stale read listing counted would keep a reader reading after the public's removal. The reader's recorded head (the step its `sync.0` writes place) moving past the listed head should clear it as the unread path does.
