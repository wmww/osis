# API frictions the example apps hit
> Summary: Concrete usability gaps found writing examples/notes-app, chat and folder over the `osis` API: no expiry on placements, path ops into an absent map key fail, no clock for app timestamps, no owner accessor, no "how is X a member" answer (link joiners), signals listened to per thing only, no tid out of `write_with`, list reads without queries. Each has a workaround in the examples; none needs a wire change.
> Tags: api

Repro: the workarounds in examples/chat and examples/folder `src/lib.rs` (no failing test).

- **Expiring placement** (notes/chat.md disappearing messages: expiry on the message's deltas, placement included). `Write::create(owner, Place::In(g))` takes no expiry; the chat creates with `Place::Unsynced` and writes `w.at(g, core::GROUP).expires_in(d).path(p![FieldId(0)]).add(&m)` by hand, i.e. knows `/group`'s field ids. Proposal: `Place::In(g)` plus `Write::create_expiring(owner, place, at)`, or `place_expiring(t, g, d)`; a `core::group::ITEMS` field constant at least.
- **Path op into an absent map key**: `at(p, REACTIONS).path(p![msg]).add(&emoji)` on a `map<tid, set<string>>` without that key fails `Invalid("crdt: op does not fit: no live entry with that key")`. The app reads first and `put`s a one-element set when absent, a read-modify-write two devices can race (their two puts merge as the CRDT decides, invisibly to the app). Proposal: a path op into an absent map entry creates it with the type's empty value (spec/requirements.md: a write into a removed container brings it back; an absent one could behave alike).
- **No clock for the app**: the chat writes a `sent` timestamp; the database's clock (a `ManualClock` in tests, the HLC's wall in production) is not readable, so the scenario library takes `sent` as a parameter and the binary uses `SystemTime`. Proposal: `Osis::now() -> WallMs` (the corrected clock), or `Committed.ts` usable inside the batch (`Write::ts()`).
- **Owner of a thing**: no accessor; the chat reads `get(t, core::CREATED)` and matches `osis::schema::osis_core::CreationRecord::Thing { owner, .. }` (the type is not re-exported by `osis`). Proposal: `Osis::owner_of(t) -> Option<Tid>`; re-export `CreationRecord`.
- **Removing a link joiner**: `demote(chat, person, Remove)` fails `Invalid("no edge of that member was ever seen")`: a joiner is a member of the link actor K, not of the target. The app walks `links(chat)` and each K's `roster` to find the edge, demotes there and revokes a multi-use link (spec/permissions.md §9). Proposal: `Osis::member_path(target, actor) -> Vec<(Tid, Tid)>` (the edges through which `actor` reaches `target`), or `demote` accepting a member reached through a link actor it owns and doing this itself; a link joiner's removal is the common moderator action.
- **Signals per thing only**: typing signals live on each persona, so `on_typing(chat)` subscribes once per persona and misses personas that join later (the app must watch `/group` and re-subscribe). Proposal: `on_signal_in(group, kind, f)` for every thing in a group's closure.
- **`write_with` returns no value**: creating a thing and returning its tid needs the explicit `write()`/`commit()` form (`write_with_tid` exists but is `pub(crate)`). Proposal: make `write_with` generic over the closure's return value.
- **Lists**: notebooks, chat timelines, folder listings read `get(g, core::GROUP)` and then every item (issues/api-deferred.md, Queries): O(items) per refresh, and a timeline sorts by an app-written `sent` field because a hit's `ts`/`received` are not readable without `query` (or `history` per item).
- **`expires_in` takes a `Duration`**: an optional expiry needs a helper (`fn expiring(a, Option<Duration>)` in the chat). Minor: `expires(Option<Duration>)`.
