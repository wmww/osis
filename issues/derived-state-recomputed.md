# Derived state is recomputed on every change, by hand-wired caches
> Summary: Everything the engine and node-sync derive (epochs, labels, validity, blocked roles, body keeps) sits behind about thirty hand-keyed caches whose invalidation is all-or-nothing (`Core::generation`, `role_changed`), so any change rebuilds nearly all of it at the next pass. osis `sources::world_waiting` costs about 1.8 G instructions against a floor near 0.1 G. Plan, under way: one memo mechanism that records what it read (`engine/memo.rs`, notes/engine.md Derived values), replacing the caches one by one.
> Priority: normal
> Tags: engine, node, performance, tests

## What is wrong
The engine's facts are its held commits, the journaled indexes (`Core::ix`), the states, the seeds and the clock; everything else is a function of them. The code computes those functions when asked, and each one found slow got its own cache: a key picked by hand (`generation`, `role_generation`, change counts, `ViewKey`), invalidation calls at the write sites (`Core::wrote` matching aspect names, `role_changed` from about twenty sites, `touch`, the list in `rollback_to`), and a debug comparison with a fresh read because hand-wired invalidation cannot be trusted. Consequences:

1. **All-or-nothing invalidation.** `generation` moves on every changing transaction and `role_changed` on every held-set change, so the caches help only while nothing happens. After any change the next pass rebuilds: a label pass costs 20-30 M instructions whatever changed (36 label passes are half of the setup below), `Engine::ensure_rotated` reruns on 26 of 36 asks, `labels()` and head keys about once per pass. Every ingested commit touches the held set, so node-sync's role-keyed passes (`stamp_changes`, `prune_pass_sources`) run once per write step too.
2. **No cache where the inputs could not be named.** Commit validity: each part the five stale sets name (`stale_things`, `stale_authors`, `stale_under`, `stale_commits`, `stale_all`) is judged from scratch.
3. **Debug builds pay to police the caches**: about a third of the setup below (`apply::check_rebuilt` after every changing transaction 17%; `Engine::recheck` comparisons the rest).

Not redundant, by count: commit header signatures, stamps and serving proofs are checked once per receiver.

## Measured
osis `it` `sources::known_stays_here_and_unknown_goes_to_the_node` (almost all `world_waiting` setup: 3 nodes, one group, one client grant, 27 signed commits), debug profile: about 1.8 G instructions (thread timing moves the pass count by a few percent). The work the setup needs (27 commit signatures, the stamps, seals and key exchanges, each checked once per receiver) is 150-300 curve operations, 70-130 M instructions. Where the rest goes, inclusive: `SyncEngine::handle` about 70% (label passes: `body_sends` with `must_hold` and `body_keeps`, `usable_keys` with `ensure_rotated` and `blocked_roles_of`, `certificates`, `reseal`); inbound entries 15%; the test thread's own API calls about 25%.

Built so far, by `tools/icount` (debug profile, one sim seed): the held-writes and replaced-at memos took `world_waiting`'s test from 1.64-1.73 G to 1.55-1.60 G, `team_reads_member_thing` 22.6 G to 20.2-21.1 G, `member_churn` 68.1 G to 63.6-64.4 G. Then `body_keeps` as a memo (and `SyncEngine::keeps` gone): `world_waiting` 1.642 G to 1.570 G, `team_reads_member_thing` 21.66 to 21.19 G, `member_churn` 65.01 to 64.95 G. The rotations, departures and re-seal memos with the stamped clock: 1.614 G, 21.51 G, 64.78 G (no gain: in these workloads every role change moves them, and each memo's first-hit debug comparison is a run more than the caches' were).

Where the gate's time goes (its sweep's heaviest scenario, `sim-sweep --only member_churn`, one seed: 46 G instructions; nearly all in `SyncEngine::handle`): `retention::bounds::body_keeps` with `replaced_at` 23% (asked again for every body on every label pass: waits for history-3); signature checks 13%; `apply::held_parts_at` 12%; validity 10% (`Judge::valid_on`, almost all `Shown::verifies`) and its debug oracle `validity::misjudged` 9%, both mostly signature checks, which step 5 checks once; `check_rebuilt` 5%. The gate itself: default tests 170 s (194 s before the memos), selected properties 170-250 s and the sweep 105-145 s, both moving with the seeds and the box's load more than with anything built so far. On ostrich at the gate's 15 seeds `member_churn` is 982 of the sweep's 3414 CPU-s, one seed about 200 s (issues/gate-five-minutes.md).

## Design
One rule per kind of derived value (notes/coordination.md, Fast by construction):

- **A function of something immutable** is computed where the input enters and kept beside it for as long as the input lives; nothing invalidates it. Built: stored commit records and their parts (`engine/decoded.rs`), an account's role epochs (`AccountView::role_epochs`).
- **A function of mutable facts** is a memo that records what it read, the rule kit's graph follows (notes/fast-design.md §3: a value depends on exactly what it read and has no other way to read). Built (`engine/memo.rs`): the containers of facts stamp their changes and reads, per key for point reads and per container for walks; a memo asked again compares the stamps it saw. No hand-written key, no invalidation call, one debug comparison inside the memo type. Built on it: `Core::epochs`, the account signing chain, account epochs, head keys, holders named, key access, inbox actors, acting, labels, held links, published things, decoded `secrets.0` (patched in place, `Memo::amend`), an aspect's held writes, each part's replaced-at date and each commit's body bounds (`Engine::body_keeps`), departures and re-seal candidates per actor, node-sync's rotations.
- **A function of time** reads the time through `Core::time` (`memo::Clock`): whole (`get`, `labels()` where it judges a role) or until when its answer holds (`until`, `Core::horizon`: `SyncEngine::rotations`, `reseal_candidates`).

## Steps
1. Stamps where the facts are written. `Stamps` belongs below the store (osis-base), so the store stamps its own rows and blobs: `Core::states_read` and `records_read` are stamped by hand around the store today, a scan of a thing's aspect rows (`Engine::aspects`) and a blob's presence have no stamp, and a rollback moves every record. Then the plain `Core` fields a derivation reads (`left`, `groups`' public maps, `routed_away`).
2. The remaining engine caches: `live_trees` (reads the aspect rows and blobs: after 1); `bodies`, `live_bodies`, `copy_index`. `decoded::DecodedCommits` is bounded by bytes, which a memo is not: it stays, checked by `Engine::recheck` until the memo type can bound what it keeps.
3. Node-sync. Its caches and passes are keyed by `generation`, `role_generation` and `state.version` (`labels()`, `vet_inbox_hints`, `stamp_changes`, `send_suspects`, `drop_left`, hosting, peers, `prune_pass_sources`). Most are not values but effects to run when their inputs moved: split each into the value it derives (a memo over the engine's stamps and node-sync's own state, which needs stamps: `state.version` moves on every change of it) and the effect, run when the value differs from the one last acted on. `memo` goes public for it. Built: the labels synced (`SyncEngine::labels`: a memo's answer, with the one last asked for kept for reads between asks; the time is a stamped value read only where a role is judged). Also built: `Engine::body_keeps` (a memo of the bounds but for the clock), `SyncEngine::rotations` (a memo of `ensure_rotated`'s answer when it had nothing to do; its debug comparison runs `Engine::rotated_already`, whose transaction always rolls back). Measured (osis `sources::`, cpuprof, inclusive): the keyed triggers are small (`vet_inbox_hints` 1.6%, `stamp_changes` 0.8%); larger is `certificates` 7.6% (placing copies: blob puts and store commits). `unread_heads` (keyed by the hub store's `heads_generation`) stays: the hub store (osis-host) sits below osis-engine, where `Stamps` lives (step 1 moves it to osis-base), and its answer is every unread head, so a memo would move exactly when the generation does. Done when `role_changed`, `role_generation`, `generation`, the name matching in `Core::wrote`, the cache list in `rollback_to` and `Engine::recheck` are gone.
4. Finer stamps where a count shows the need. Known: states are stamped per aspect, so a changed join moves every part's replaced-at date on its aspect (member_churn: of 5500 `body_keeps` part judgments 2000 are stale, nearly all by a join of their aspect; a hit's first debug comparison costs one more run). Measured (member_churn, cpuprof, inclusive): `judge_replaced_at` 20% of the scenario; of that `held_writes` 57% (decoding every held body of the aspect again: `held_parts_at` 38%), and the debug comparisons nested in it about half (`held_writes`' 25%, the date's 18%, the body bounds' 15%). Two levers: `held_writes` amended by each join (`Memo::amend`, as `secrets_in`: a join adds its body's writes, a drop runs it again), so a write costs its body, not the aspect's; and a part's date stamped by the positions it read (`state_part_at` and its dead writes' entries in `HeldWrites`), so a write re-dates only the parts whose writes it can supersede. The second needs a stamp key per position (map key or sequence place) on the states and on `HeldWrites`. Also: the timelines are stamped per component, so a role commit moves every memo that read a timeline in its component (a grant on one group re-derives the epochs of its sibling groups). `osis_perm::Changed` names what moved (`edges`, `extended`, `evaluated`): stamp the things under those, and read roles through one call per (holder, target) instead of `timelines.get`. A range read (`keysets_of`, `acting_for`) reads its whole collection.
5. Validity as memos per part (`Judge::part`), so a part is judged again only when what it was judged on moved. Built: a possession signature is checked once per key while its part is held (`Showing::checked`); `member_churn` one seed: 18,520 signature checks (16,294 of them in `misjudged`) down to 533, about 10% of its CPU. Validity is then about 2% of its instructions (callgrind: `rejudge_all` 1.9% inclusive, `misjudged` 1.5% of that), so memos per part would gain at most that: their case is the hand-kept sets, not speed. Counted today (one seed of `member_churn`): 538 re-judge passes judge 3,390 parts, `misjudged` 54,178. Open, before the five stale sets can go:
   - Memos are pulled, validity flags pushed (a flip rebuilds its aspect), so the re-judge must list the parts whose reads moved without asking every held part (the rejected O(held) re-judge). `memo.rs` has no way to: it needs a change log per stamp table and an index from each read to the entries that made it.
   - Timelines are stamped per thing, coarser than the sets: `stale_under` with `stale_authors` re-judge only the authors whose role moved, so a grant judges 1 part at n and 10n (`scale::grant_is_flat_in_content_commits`); a part memo reading `timelines.get(t)` would re-judge every part on every thing of the continued component. Needs step 4's reads per (holder, target).
6. The debug checks: whether `check_rebuilt` still runs after every transaction; the memos' own comparison (a fresh run at each entry's hits 1, 4, 16, ...) is about 8-10% of a debug osis or sim test (`costs::paused` under `Memo::get_in`), most of it the first hit of entries that go stale soon after, so a memo with many short-lived entries pays about one run per answer twice.
7. Node-sync's pass reading what moved from the memos instead of its own triggers (notes/node-sync-work-sets.md; `stamp_changes` and `prune_pass_sources` run once per write step today); decide after step 3.
8. Test setup: a world built once and copied per test (as `local_peer::Peer::fork` does for engine tests).

Counted checks for each step (work, never time): a pass with nothing new derives no key, checks no signature, decodes no commit; this setup's counts of key derivations, validity judgments and label builds bounded by small multiples of its commits and nodes.

## Method
- Instructions: `tools/icount target/debug/deps/it-<hash> --exact <test>` (perf_event_open counting works; `perf record` sampling is refused on this box).
- Profile: `valgrind --tool=callgrind --callgrind-out-file=OUT <binary> -q --test-threads=1 --exact <test>` (about 20 s); `callgrind_annotate --inclusive=yes --threshold=100 OUT` by function, `--tree=caller` for callers with call counts, `--tree=calling` for what a function spends on. Inclusive cost of a recursive function (`Decoder::item'2`, `Walk::walk'2`) counts each level again: use the non-recursive entry or exclusive cost.
- Wall per step: `eprintln!` of `Instant` elapsed after each statement of `world_waiting`.
