# Derived state is recomputed on every change, by hand-wired caches
> Summary: Everything the engine and node-sync derive (epochs, labels, validity, blocked roles, body keeps) sits behind about thirty hand-keyed caches whose invalidation is all-or-nothing (`Core::generation`, `role_changed`), so any change rebuilds nearly all of it at the next pass. osis `sources::world_waiting` costs about 1.8 G instructions against a floor near 0.1 G. Plan: one memo mechanism that records what it read (`osis_base::memo`, notes/engine.md Derived values), replacing the caches one by one.
> Priority: normal
> Tags: engine, node, performance, tests

## What is wrong
The engine's facts are its held commits, the journaled indexes (`Core::ix`), the states, the seeds and the clock; everything else is a function of them. The code computes those functions when asked, and each one found slow got its own cache: a key picked by hand (`generation`, `role_generation`, change counts, `ViewKey`), invalidation calls at the write sites (`Core::wrote` matching aspect names, `role_changed` from about twenty sites, `touch`, the list in `rollback_to`), and a debug comparison with a fresh read because hand-wired invalidation cannot be trusted. Consequences:

1. **All-or-nothing invalidation.** `generation` moves on every changing transaction and `role_changed` on every held-set change, so the caches help only while nothing happens. After any change the next pass rebuilds: a label pass costs 20-30 M instructions whatever changed (36 label passes are half of the setup below), `Engine::ensure_rotated` reruns on 26 of 36 asks, `labels()` and head keys about once per pass. Every ingested commit touches the held set, so node-sync's role-keyed passes (`stamp_changes`, `prune_pass_sources`) run once per write step too.
2. **No cache where the inputs could not be named.** Commit validity: each part the five stale sets name (`stale_things`, `stale_authors`, `stale_under`, `stale_commits`, `stale_all`) is judged from scratch.
3. **Debug builds pay to police the caches**: about a third of the setup below (`apply::check_rebuilt` after every changing transaction 17%; `Engine::recheck` comparisons the rest).

Not redundant, by count: commit header signatures, stamps and serving proofs are checked once per receiver.

## Measured
osis `it` `sources::known_stays_here_and_unknown_goes_to_the_node` (almost all `world_waiting` setup: 3 nodes, one group, one client grant, 27 signed commits), debug profile: about 1.8 G instructions (thread timing moves the pass count by a few percent). The work the setup needs (27 commit signatures, the stamps, seals and key exchanges, each checked once per receiver) is 150-300 curve operations, 70-130 M instructions. Where the rest goes, inclusive: `SyncEngine::handle` about 70% (label passes: `body_sends` with `must_hold` and `part_keeps`, `usable_keys` with `ensure_rotated` and `blocked_roles_of`, `certificates`, `reseal`); inbound entries 15%; the test thread's own API calls about 25%.

The memos built, by `tools/icount` (debug, one sim seed): `member_churn` 68.1 G to 49.4 G, `team_reads_member_thing` 22.6 G to 17.9 G, `world_waiting` within noise; in these workloads every role change moves the rotations, departures and re-seal memos.

Where the gate's time goes (its sweep's heaviest scenario, `sim-sweep --only member_churn`, one seed: 46 G instructions; nearly all in `SyncEngine::handle`): `retention::bounds::part_keeps` with `replaced_at` 23% (asked again for every body on every label pass); signature checks 13%; `apply::held_parts_at` 12%; validity 10% (`Judge::valid_on`, almost all `Shown::verifies`) and its debug oracle `validity::misjudged` 9%, both mostly signature checks, which step 5 checks once; `check_rebuilt` 5%. The gate itself: default tests 170 s (194 s before the memos), selected properties 170-250 s and the sweep 105-145 s, both moving with the seeds and the box's load more than with anything built so far. On ostrich at the gate's 15 seeds `member_churn` is 982 of the sweep's 3414 CPU-s, one seed about 200 s (issues/gate-five-minutes.md).

## Design
One rule per kind of derived value (notes/coordination.md, Fast by construction):

- **A function of something immutable** is computed where the input enters and kept beside it for as long as the input lives; nothing invalidates it. Built: stored commit records and their parts (`engine/decoded.rs`), an account's role epochs (`AccountView::role_epochs`).
- **A function of mutable facts** is a memo that records what it read, the rule kit's graph follows (notes/fast-design.md §3: a value depends on exactly what it read and has no other way to read). Built (`osis_base::memo`): the containers of facts stamp their changes and reads where they are written, per key for point reads, per prefix for scans and per container for walks: the store its rows (`osis_store` `Stamping`), the engine's blob door its holds (`blobs::Cipher`), `Core` its indexes, held set, timelines (at the grain each read sees, step 4) and group index; a memo asked again compares the stamps it saw. No hand-written key, no invalidation call, one debug comparison inside the memo type. Built on it: `Core::epochs`, the account signing chain, account epochs, head keys, holders named, inbox actors, acting, labels, held links, published things, decoded `secrets.0` (patched in place, `Memo::amend`), an aspect's held writes (amended by each join, `Memo::get_amended_in`), each part's replaced-at date and each commit's body bounds (`Engine::part_keeps`), departures and re-seal candidates per actor, node-sync's rotations, each source's chunk trees (`Engine::tree_refs`, also `live_trees`), each commit's label body (`Core::bodies`), each delta's liveness (`Engine::delta_live`).
- **A function of time** reads the time through `Core::time` (`memo::Clock`): whole (`get`, `labels()` where it judges a role) or until when its answer holds (`until`, `Core::horizon`: `SyncEngine::rotations`, `reseal_candidates`).

## Steps
1. Done: stamps where the facts are written (notes/engine.md Derived values). Left: `Engine::tree_refs`' counted reaches (`tree_refs::Reach`) are incremental state, not a memo; each question still re-reads the node blobs a count lacked (`missing`, usually empty) and scans the thing's aspect rows (`sources`): both stamped now, so either could be a memo or be gated by the blob stamps' count if a count shows it. `Core::left` is read only where it is taken (`rotation::lost`): no derivation reads it.
2. Done: `bodies` and `live_bodies` are memos, `live_trees` answers from the counted reach of the live states. `decoded::DecodedCommits` is bounded by bytes (its values are whole bodies) and keeps each decode at its record row's stamp (`Transaction::local_stamp`): no drop by hand at a write or rollback. Debug builds check each hit by comparing the bytes it was decoded from with those read now, no decode.
   Measured (`tools/icount`, debug, before and after steps 1-2): osis `sources::known_stays_here_and_unknown_goes_to_the_node` 1.42-1.43 G both; sim `member_churn` one seed 45.95 G to 46.05 G. One stamp table for the whole store cost 1.2 G more there: a memo's debug comparison runs at hits after a container it read changed (step 6), and one table moves at every transaction, so the store stamps by family (catalog kind, a local record's first key byte).
3. Node-sync. Its caches and passes are keyed by `generation`, `role_generation` and `state.version` (`labels()`, `vet_inbox_hints`, `stamp_changes`, `send_suspects`, `drop_left`, hosting, peers, `prune_pass_sources`). Most are not values but effects to run when their inputs moved: split each into the value it derives (a memo over the engine's stamps and node-sync's own state, which needs stamps: `state.version` moves on every change of it) and the effect, run when the value differs from the one last acted on. `memo` goes public for it. Built: the labels synced (`SyncEngine::labels`: a memo's answer, with the one last asked for kept for reads between asks; the time is a stamped value read only where a role is judged). Also built: `Engine::part_keeps` (a memo of the bounds but for the clock), `SyncEngine::rotations` (a memo of `ensure_rotated`'s answer when it had nothing to do; its debug comparison runs `Engine::rotated_already`, whose transaction always rolls back). Measured (osis `sources::`, cpuprof, inclusive): the keyed triggers are small (`vet_inbox_hints` 1.6%, `stamp_changes` 0.8%); larger is `certificates` 7.6% (placing copies: blob puts and store commits). `unread_heads` (keyed by the hub store's `heads_generation`) stays: its answer is every unread head, so a memo would move exactly when the generation does. Done when `role_changed`, `role_generation`, `generation`, `memory_generation`, the cache list in `rollback_to` and `Engine::recheck` are gone. Their readers are all node-sync's (and `Engine::point`); the sync rewrite's Phase 3 deletes them with node-sync's triggers. In the engine itself: `Core::wrote` only records the states a transaction wrote (dropped on rollback: the working copy, not a cache); `Core::decoded` keeps its decodes at row stamps; the leaving check asks the replaced-at memo; what `rollback_to` still drops is `touches` (an index rebuilt on use) and the written states.
4. Finer stamps where a count shows the need. Counted with a throwaway counter in `memo::Memo::keep` (reruns of a kept key, of them equal to the answer replaced) and the read sites whose stamps had moved, debug, osis `it` `sources::` one thread and sim `member_churn` `--seeds 1 --from 1000`.
   - Built, the timelines read at the grain each read sees (notes/engine.md Derived values, `held::Read`): a thing's edges (`Timelines::on`: holders, roster, standings, applied writes; moved by `osis_perm::Changed::edges` into it and by its record), the writes held on it (`On::held`: any held input), a role (x, a) read backward from `a` (`roles_on`, `role`: the edges into each node reaching `a`), the set of things with a timeline (read too by a thing's read when it has none: a write naming it that sets nothing gives it one); `get` reads a component whole (`Core::horizon`, `may_rotate`, demotions in effect, an unapplied write's verdicts in `edge_logs`). The keyless actor grants are an index the timelines keep per component (`keyless`: a cycle lies in one component; moved only when the set changes), not a memo over every timeline that each consumer copied. `held_links` reads the link-seed things from `Indexes::aspect_things` (`by_aspect`'s keys, aspect first), not `by_aspect` whole. Reruns/equal, before to after: `sources::` epochs 3400/2643 to 1289/524, labels of 1555/1473 to 338/257, departures 1202/1199 to 208/205, head keys 1185/1095 to 198/104, held links 1117/1116 to 11/10, labels synced 1075/484 to 763/169, account view 1022/1022 to 458/458, published 690/376 to 459/146, account epochs 679/613 to 125/59, key access 609/609 to none; all memos 16080/13140 to 7413/4449. `member_churn` departures 328/286 to 112/70, epochs 303/217 to 168/81, held links 247/247 to 0, labels of 164/136 to 94/66, head keys 140/113 to 70/43, account view 110/110 to 39/39, account epochs 66/65 to 2/1, key access 84/84 to none; all 4180/3358 to 3133/2310. `tools/icount`, two runs each: `sources::` 119.2-119.8 G to 113.5 G, `member_churn` 28.54 G to 27.78 G. Counted: `engine::held::tests::timeline_reads_move_with_what_they_read` (each stamp write removed fails it) and `timeline_reads_match_a_fresh_read_through_random_writes` (random writes, records and undos; also the keyless grants against one evaluation of everything and perm's per-thing walk cache across an `until`); `aspect_things` with its insert removed fails 26 osis-engine lib tests, with its removal at a forget removed 3 (the index check).
   - Left, by count. `ensure rotated` 1081/1081 and `reseal: scan` 763/763 in `sources::` (191/190, 163/163 in `member_churn`), moved by `Core::horizon`'s whole read of the actor's component; its answer only bounds the clock (`time.until`), but reading it unrecorded altogether saves 0.6% of `sources::` and nothing of `member_churn` (icount): not built. `epochs` 1289/524, moved by `ix.secrets` (secrets learned). In `member_churn` the aspect state row is now most of what reruns: replaced at 1115/898 and part bounds 798/604 of 3133, moved by the state row (`Tx::load_lazy`) and `held_writes` (`retention::bounds`). States are stamped per aspect, so a changed join moves every part's replaced-at date on its aspect (of 5500 `part_keeps` part judgments 2000 are stale, nearly all by a join of their aspect; a hit's first debug comparison costs one more run). Built for it: `held_writes` amended by each join (`Memo::get_amended_in`: a join adds its body's writes while the aspect holds no invalid part; anything else reads it whole), so a write decodes its own body (`retention::tests::a_join_decodes_its_own_body_not_the_aspects`); `member_churn` 53.14 G to 49.38 G then. Measured after it (cpuprof, inclusive): `judge_replaced_at` 16% of the scenario; `held_writes` 24% of that, mostly its debug comparisons (a fresh read at each entry's hits and amends 1, 4, 16) and the aspects' first reads; the rest is the date memo's debug comparison (25%), `first_superseding` (13%), `deaths` (`state_part_at`, joins). The lever left there, a part's date stamped by the positions it read (`state_part_at` and its dead writes' entries in `HeldWrites`, a stamp key per position, map key or sequence place, on the states and on `HeldWrites`), so a write re-dates only the parts whose writes it can supersede, would save at most the stale re-judgments' share of that 16%, about half of which is debug comparison (step 6): not worth a per-position stamp until step 6 has cut the comparisons and a count still shows dating high. A range read (`keysets_of`, `acting_for`) reads its whole collection.
5. Validity per part on `memo::Effects` (`Judge::part`: `want` each held part, `due` gives the parts whose reads moved from the containers' write logs, `settle` judges one and reports a flip), so a part is judged again only when what it was judged on moved. Validity is then about 2% of its instructions (callgrind: `rejudge_all` 1.9% inclusive, `misjudged` 1.5% of that), so memos per part would gain at most that: their case is the hand-kept sets, not speed. Counted today (one seed of `member_churn`): 538 re-judge passes judge 3,390 parts, `misjudged` 54,178. Open, before the five stale sets can go:
   - A part's judgement reads its author's authority (`timelines.get`, the component whole): a part memo would re-judge every part on every thing of the continued component, where `stale_under` with `stale_authors` re-judge only the authors whose role moved (a grant judges 1 part at n and 10n, `scale::grant_is_flat_in_content_commits`). Step 4's reads (`roles_on`, `on`) are that grain; the judgement reads the timeline whole today.
6. The debug checks: whether `check_rebuilt` still runs after every transaction. The memos' own comparison (`memo::Checks`) runs at the 1st, 4th, 16th, ... hit of an entry at which a container it read has changed since its last such hit (an amend is one), and at its hits 16, 256, 4096, ... whatever changed (a missed read that changes alone); a comparison's own reads count for nothing (memo hits inside it neither count nor compare, `Engine::recheck` rechecks no cache there). `tools/icount`, debug, comparisons as total minus a run with them off, against hits 1, 4, 16 counted from the entry's first: `member_churn` one seed 6.2 G of 49.7 G to 2.9 G (no nesting alone 4.5 G, change-gated alone 3.5 G, both without hits 16, 256: 2.2 G); osis `it` (one thread) 119 G of 1255 G to 52 G (no nesting alone 88 G, change-gated alone 59 G, both 42 G). Plants (a stamp read removed), tests failing in osis-node `it`, all / by the comparison, old schedule to this one: the rotations memo's clock read 5/4 to 5/3 (without hits 16, 256: 3/1); `dated_replaced_at`'s `deaths` 133 to 96 (the loss is the inner hits no longer compared, 93 with only that change); worker counts, without hits 16, 256 (this schedule compares a superset): `held_writes`' accounted inputs (osis-engine lib) 8 to 10, `body_bounds`' settings read 7 to 7. Not tried: proving a memo stamped by construction (each memo's function takes the whole `Tx`, `Engine` or `Core`, so none qualifies without a narrower view type per function). The index check's schedule (notes/test-harnesses.md, Debug checks): only each count's first check would save 4.2% of node `it` but halves the tests a planted accumulating fault fails; it stays. Separate from the memos: `DecodedCommits` compares at every hit the bytes an entry was decoded from with those read now, no decode (`engine/decoded.rs`).
7. Node-sync's pass reading what moved from the memos instead of its own triggers (notes/node-sync-work-sets.md; `stamp_changes` and `prune_pass_sources` run once per write step today); decide after step 3.
8. Test setup: a world built once and copied per test (notes/test-harnesses.md, Copied worlds). The shared preludes cover the setups most tests share; what is left is small, measured (main 111aa21e5): of node and osis `it` modules, those whose one-process count is near the sum of their tests alone (no shared setup) are scenario tests whose prefixes differ past the first call (a scan of each test's first statements finds groups of 2-7 tests sharing 2-3 calls, 5-35 G a group, mostly setup already cached and a step or two after it), real-runtime worlds that cannot be copied (osis `sources::world`, over `osis_transport::Net`), scale tests that build each size once, and properties whose cost is per order or seed. Not a lever for a further share of the default tests.

Counted checks for each step (work, never time): a pass with nothing new derives no key, checks no signature, decodes no commit; this setup's counts of key derivations, validity judgments and label builds bounded by small multiples of its commits and nodes.

## Memo design review
Counted with a throwaway counter in `memo` (each run, rerun of a kept key, equal rerun, which reads had moved, and whether the outer's own reads all held while every inner memo it read gave the same value: what salsa-style early cutoff would skip), debug, sim `member_churn` one seed and osis `it` `sources::` one thread, after the held set was stamped per key:
- Reruns giving the value they replaced, of all reruns: `member_churn` held links 307/307, ensure rotated 248/252, reseal scan 231/231, account view 131/131, departures 317/360, epochs 227/372, part bounds 1451/1673, replaced at 1633/1859; `sources::` key access 653/653 (from the run before), account view 1037/1037, ensure rotated 1140/1140, departures 1266/1269, epochs 2634/3390, labels of 1454/1536, head keys 1155/1244.
- Of those, early cutoff would skip (own reads held, inners equal): `member_churn` part bounds 1315, epochs 128, labels of 82, head keys 78, account epochs 62; `sources::` epochs 2161, labels of 1259, head keys 1060, account epochs 548, labels synced 468. It saves the outer's own work only: an inner that moved is recomputed either way to learn it is equal. Part bounds' own work is a lookup per part (its cost is the replaced-at reruns, moved by their own reads: 39 of 1859 had theirs all hold). Not built: notes/engine.md Derived values says why.
- What moved the reruns, by the read whose stamp moved (top): `timelines.get` in `Core::edge_holders` (flows/mod.rs) for epochs 2259, labels of 1325, departures 1174, head keys 1136, account view 975 in `sources::`; `key_access`'s `timelines.things()` (whole) for departures 1232, ensure rotated 1109, reseal scan 814; `held_links`' whole `by_aspect` 1121 (every rerun); the aspect state row (`Tx::load_lazy`) for replaced at 1760 and part bounds 1508 in `member_churn`. Before the held set was stamped per key its `edge_commits` (one stamp for the whole held set) moved epochs 2468, labels 1397, departures 1250 and more; per key it moves none of the top: icount `member_churn` 47.35 G to 47.26 G, `sources::` 127.7-128.5 G both (its noise).
- Locks: 4.1 M taken in `member_churn` (47 G instructions), 19 M in `sources::` (128 G): under 1%.
- So the lever was the coarse stamps: built in step 4 (the timelines at their grains, key access an index kept per component, held links per aspect), which left the reruns step 4 lists.

## Not memos, by audit
Derivations recomputed per ask that read mutable state, outside node-sync (audited by reading, not profiled; node-sync's own triggers are the sync rewrite's):
- Per pass, clock-relative (a memo needs `Core::time.until(horizon)`, as `reseal_candidates` does): `rotation::blocked_roles_of` (node-sync's `placing`, twice per actor per label pass; its `deps` argument is caller-filtered), `Engine::reseal_due` (an effect: it writes the rotations and re-seals due, gated on node-sync's `complete_pass`, so it splits as step 3 says; its reads `pass_end_rotations`, `add_history`, `history_boxes` are 8% of `member_churn`, 5% of `sources::` by cpuprof), `rotation_due`, `own_secrets_candidates` (a scan of `holder_keys` per call), `Core::may_read` and the label pass's `actor_reads`/`readable_parts`, `finalizable`, `roster_of`, `links_due`. A memo of the quiet answer, as node-sync's `rotations` is, would rerun about as often as that one (94% of asks in `member_churn`) while it reads timelines whole (`may_rotate`, `horizon`).
- Per pass, not clock-relative: `labeling::certs::{latest_by, aspect_commits, destroyed_upstream, revoke_certificates, history_certificates}`, `label_bodies_meta`, `rotation_wrap_epoch` (decodes `keys.0` per placement), `part_body`/`header_body` (decode per copy), `Engine::inbox` and `deposit_seed` (`get_typed(KEYS)` per call), `keys_write_unapplied` (reads and decodes pending blobs), `Engine::epochs`' fallback (clones `ix.secrets[t]` when the memo gives none). Nothing blocks a memo on any of them; none shows in the profiles above 3%.
- Blocked by unstamped reads: `certificates`/`destroyed_needed` (read and edit `Core::destroyed_kept`, an `Option<BTreeSet>` filled once: kept-row state, not a derivation), `readable_by` (`sourced_elsewhere`), `next_timer`/`timers_due` (`compaction`, `timer_floor`), `freed_wants` (`freed_waits`). `lifetimes_due` (a flag and three store seeks) and `signing_due` (a flag) cost less than a memo hit.
- Hand-kept incremental state that stays, with its reason: `Core::states`/`pages` (the transaction's working copy, journaled by `written`), `undo::touch::Touches` (an index amended by `Meta` changes, byte-bounded, dropped on rollback), `tree_refs::Reach` (counted reaches), `epochs_judged_from` (the last value acted on: an effect trigger), perm's `Timeline::memo` (per timeline, replaced with it), perm's walk cache (`update_touched_cached`, keyed by its inputs and persisted), `Core::memory_waits` (pending commits known to be memory commits: a fact of the pending blob, which never changes, pruned to the pending set at each `reexamine`), `apply::reach::Walks` (walks of what waiting commits link, extended as blobs arrive, for node-sync's `blob_wants`).
- `Engine::point` (`ReadPoint`, the sim's convergence check caches each node's reads by it) and `Engine::recheck` read `generation` and `memory_generation`: they need a replacement when Phase 3 deletes them.

## Method
- Instructions: `tools/icount target/debug/deps/it-<hash> --exact <test>` (perf_event_open counting works; `perf record` sampling is refused on this box).
- Profile: `valgrind --tool=callgrind --callgrind-out-file=OUT <binary> -q --test-threads=1 --exact <test>` (about 20 s); `callgrind_annotate --inclusive=yes --threshold=100 OUT` by function, `--tree=caller` for callers with call counts, `--tree=calling` for what a function spends on. Inclusive cost of a recursive function (`Decoder::item'2`, `Walk::walk'2`) counts each level again: use the non-recursive entry or exclusive cost.
- Wall per step: `eprintln!` of `Instant` elapsed after each statement of `world_waiting`.
