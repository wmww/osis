# A cover turning invalid loses the commits it dropped, at some holders only
> Summary: validity is judged at the commit's stamp, so a writer revoked at T between an own commit X (valid) and its later cover C (invalid once T is known) splits holders: one holding C before learning of T dropped X (`drop_absorbed`, or `eph_containers` on a later arrival) and reads without it once C turns invalid; one that learned T first keeps X. Pre-existing for listed commits; `eph_containers` extends it to older unlisted commits C contains.
> Tags: engine, ephemeral, security

Order A: X, C (valid), revocation -> X dropped, C invalid: X's writes gone. Order B: revocation, X, C (invalid) -> C absorbs nothing, X held. Reads differ until restart. Also the writer's own deletes under C remove X from hosts, so X cannot come back by reconcile.

Fix direction (family of the durable rule, owner decision (a): a part a held snapshot of any validity lists counts as held, notes/node.md Snapshot authority): a dropped commit's writes stay through the cover only while the cover is valid, so either keep a dropped commit's parts (memory) until the cover's author can no longer be revoked before it (never ends), or count a part of an invalid cover that a valid earlier commit of its author would have carried (judge the cover's writes per original commit stamp, the `Authors` session stamps already in `HeldPart::authors`).

Precise trigger (devbox fable study, issues/eph-unify.md Order of the remaining steps): an admin's revoke cannot cause it: a demotion's frontier lists no ephemeral commit, so an explicit demotion invalidates all of W's ephemeral writes, X too, in both orders (spec/permissions.md §5.2 last bullet). X stays valid while C turns invalid only when W's role ends without an explicit demotion: an edge `until` (§5.2) or W's self-removal (§5.1 "audits nothing"); honest W stops covering and deleting once its wall clock passes `until`, so the realistic trigger is a leaving writer uploading C after its self-removal and deleting X before the rotation reaches the host. At stake: W's own earlier writes at holders that got C first, until a holder of X reconnects after the host's ephemeral tombstone (`MAX_DRIFT`) or all restart. `HeldPart::authors` above no longer exists (step 1 removed `Authors`); per-write judging of an invalid C would not close it (C holds only live writes). Decision: no local fix; the eph-unify swap deletes own covers and leaves durable's uncover transient (spec/permissions.md §5.2). A pinned repro (self-removal between X and C, two holders, both orders) is wanted as the swap's regression test.
