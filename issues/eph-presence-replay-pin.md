# Readers can pin an author's old presence entries
> Summary: presence entries leave no tombstone and a presence commit lists as absorbed only the previous one, so a reader can re-upload every presence entry an author made in the last 20 min. Each one is tied to the reader's connection, fills the server's presence cap (honest presence gets code 12) and is held by every holder, counting toward its per-label cap. Medium.
> Tags: security, server, engine, ephemeral

Scenario. Author A moves a cursor, which makes one presence commit per round trip (P1..Pn), each absorbing only the presence commits A still holds, in practice the previous one (`take_presence`, core/engine/src/ephemeral/remote.rs:409-415). The server removes each old entry when the next upload unties it, and leaves no tombstone (core/server/src/store.rs:720-723). A reader that kept P1..Pn-2 (valid stamps, prefix expiry `ts + MAX_LEASE`) uploads them on its own connection:
- server: each one is admitted as a new entry tied to the reader's connection and charged to `presence_bytes` (store.rs:793-805; accept at core/proto/src/server.rs:920-927). At about 1 KiB each with overhead, 4 MiB is reached after a few thousand entries, which is a few minutes of dragging. After that, every author's presence upload under the label is refused there.
- holders: `eph_covered` misses Pk for k < n-1, because the held Pn does not list it. So Pk is verified, held (the state is unchanged, since Pn's writes are newer) and counted in `Lane::bytes`. The node-cap effects of issues/eph-replay-absorbed.md follow. When A leaves, its stale values stay shown until each Pk's lease runs out. That part is the accepted lease residual.

Fix direction: a presence commit stands for its author's whole presence state for that actor. Holders can drop (and not hold) any presence commit of the same (author, actor) older than the newest held one, which is exact and needs no lists. At servers, give presence entries removed by a replacement or a delete a tombstone until their prefix expiry (at most 20 min, bounded by upload rate), so replays are refused. Entries removed only because their last tie closed can stay tombstone-free.
