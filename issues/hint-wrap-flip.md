# A host holding a hinted label under another thing can swap the real host's wraps
> Summary: before a label's `label.0` is held, a host that took a hinted open under thing X (a sender naming it, holding the real path) can announce the real host's blob IDs with wraps made under X's secret; `take_wrap` judged on its connection takes them (the old wrap does not open under X), so the real entries stop opening under the group until the real host announces them again. Traced, not run.
> Tags: node-sync, security

`group_of(l, conn)` judges per connection, and a label is held under the hint's thing X on the hostile host's connection and under its group G on the real host's until G's `label.0` is held (then `add_new_labels` moves every connection to G). Entries are one table per label, so in that window `take_wrap` on the hostile connection sees the real wrap as not opening (under X) and a crafted X wrap as opening, and replaces it while the blob's key is unknown; the real host is marked doubtful, and `doubts` is judged without a connection (an Open connection's group, maybe X). The real host's next announcement swaps it back; the hostile host can keep announcing after it. Needs a sender that holds X's read secret and colludes with a host it names.

Possible rules: a wrap that opens under any group the label is held under on some connection is never replaced; or one group per label across all connections at a time (the wanted one, Open connections included), which `add_new_labels` today keeps only once `label.0` is held (a label still opening keeps its thing until it fails, notes/sync.md Who owns a label on a connection).

Related, also traced: an admin of X can copy G's label (its steps) into X's own `label.0`. Then `labels()` lists the label under both, `add_new_labels` keeps either on a connection (any recording group counts, so it does not reopen at every call), and the window above never closes while X's `label.0` names a host the admin controls. Nothing checks that a label's genesis delete key derives from the recording thing's admin secret (readers cannot; admins could).
