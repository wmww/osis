# Resolved linked header lists stay in memory with no bound on how many
> Summary: A linked list of an applied commit stays resolved in `Meta` and is resolved again at open: up to about 320 MiB per list at `MAX_LIST_BYTES` (a frontier 292 MiB), per signed commit, with nothing limiting how many. Decoding one list is bounded now (read by shape, about 5 B per byte).
> Tags: security, commit, engine

Fixed: `Header::resolve` and tree nodes read by shape (`osis_base::Reader`), so a hostile list is refused at its first wrong item. The whole-value route is in issue value-decode-memory (closed).

- **Retained, measured at 64 MiB (dev profile, RSS growth).** Frontier 292 MiB, purge at 21 B per item 317 MiB, aspects at 70 B per item 250 MiB, chunks 100 MiB. Perm holds each frontier again as `Arc<Frontier>` (`BTreeSet<CommitId>`, about 100 MiB, not measured).
- **Who.** `Meta` keeps a linked header (`LazyHeader::ready`), `index::load` resolves all of them at open. Needs a signature and a valid header; list blobs can be shared, so each commit costs its author about 1 KB. One commit can link six lists.
- **Why not a small change.** Holding lists as bytes saves a factor of about 5 and leaves the count unbounded. Resolving on demand needs store access from `LazyHeader`'s `Deref`, which has none, and perm's input keeps every role commit's frontier in memory whatever the header does. Closing it means perm reads frontiers on demand too, or a limit on what one author's linked lists may hold.
- **Transient, for scale.** `examine` clones the resolved header, so a valid commit peaks at about twice the above (frontier 620 MiB measured with the list's bytes). `header_frontier` then builds a typed copy and a `Frontier`, so a frontier at the cap peaks near 1 GB (estimated). A commit that fails peaks at the same order, once per examination.
- **Signature before lists: only for a held author.** `examine` checks a held author's signature first. An author's record carried by the commit itself sits on a `created.0` part, and only the aspect list says which part that is, so an unknown author still resolves unsigned. Cost then: the memory above, plus decompressing up to 1.8 million delete keys if the keys list is linked (CPU, not measured; those checks could move after the signature).
- **Repeated chunk links.** Still legal at the tree level. A list made of them is refused at its first repeated item, so the 300 KB upload now buys a fetch of up to 64 MiB and a buffer of up to 96 MiB per examination, nothing retained. Not refused earlier: the rule costs a set of seen links for no further gain.
