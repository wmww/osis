# `--admit own` admits nothing from the CLI, and admitting by label ID stops links
> Summary: A dedicated host device run with `serve --admit own` refused even its own paired home label (the node reopened it three times, then "stranded: waiting for a re-seal"); `--admit own --label ID` syncs the group but `link make` times out because the link's inbox label is a label the host was never told to admit (deposit refused, code 13). Not-admitted is answered with the cap code 12, so a node never learns it is unwelcome. Found dogfooding (notes/dogfood.md); the host runs `--admit open` with caps meanwhile.
> Tags: cli, node-sync, host, security

Repro (binary at 4210a930, localhost, all through `osis`): `init` me; `pair join` a second store (the host device); `serve --listen quic://127.0.0.1:0 --admit own` once to learn the address; `hosts add ADDR` on both stores; `serve` again; `group sync G` on me: every label Unreachable; the host's own diagnostics say `label …: reopened 3 times, retrying later` for its own home label. In-process `hosting_own_then_open_spec_sync_5` passes, so the gap is in the CLI/runtime path. Suspects: the admission set (`SyncEngine::host_config`) is built from `labels()` at the host device, which only learns label records by syncing them, and it cannot sync them until admitted (for its home: the record it holds from pairing may list the host and still be refused: check `owns`, `set_person` timing against `host_step`, and that `hosts add` on the host device updates the record it holds).

- **Code 12 for "not admitted"**: `admit_label` answers `STORAGE_CAP`; during the first registration (`Phase::Opening`) the node reopens `MAX_REOPENS` times and waits, at `Phase::Open` it says "step refused for now" forever; `status` shows the group Stranded/Unreachable. A distinct refusal (or the node telling a permanent refusal from a full host) would let `init --host X` fail loudly when X will not take the home label.
- **Label-ID admission and links**: a link (and any deposit) uses an inbox label (`keys.0` inbox) that is not the group's label. `--label ID` for a group should cover the inbox labels of its sharing paths, or the CLI should take `--label GROUP` resolved to all of them (today `--label GROUP` needs the group synced at the host store, which a dedicated host device never is).
- **CLI host operations** (same root: one process per store, notes/cli.md Not built): the host address (`<url>#<key>`) is printed only by `serve`, so `hosts add` on the host store itself needs a serve-stop-add-serve dance; `hosting set` cannot run while `serve` holds the store, so admission cannot be tightened without a restart.
