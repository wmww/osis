# Finding the shared sync IDs
> Summary: Settled design, one mechanism with issues/net-reconnect.md. Rule: a node shares a sync ID with a connected peer exactly while, on what it holds now, the peer may hold it; everything remembered only says what need not be sent again. One filter of beacons per peer, each keyed by a credential's match value (a read secret, a key actor's static entry, a head's sync or deposit key); a Hit carries the credential's proof; role offers to judged holders; deposits are offers to proved holders of the inbox. Nothing keyed by node identity. A peer may recognise the same device reconnecting (Tess; spec/requirements.md). Model first. Part of issues/net-rework.md.
> Priority: normal
> Tags: sync, node, proto, crypto, spec, security

## The rule
**A node shares sync ID L with a connected peer exactly while, on what it holds now, the peer may hold L: an actor the peer proved on this connection is a current holder of L, or the peer showed an admissible credential of L (Words).** Every other state is a cache of that judgment or of what was already sent: losing it costs bytes, never a result (issues/net-reconnect.md).

Named exceptions, each following from a principle stated with it:
- **Unknown actors see nothing of what a node reads** (spec/requirements.md, Offline and network; Tess): the filter entries of a sync ID this node reads go only to a peer that proved a **known actor**. The entries of a sync ID it serves without reading name no actor of its own and go to every connection (Peers that cannot read).
- **The event that ends sharing is still sent** (Opens): a holder that missed a rotation can only prove the new epoch by receiving it, as spec/sync.md §5 sends a head's last event. Liveness of a current holder; a removed holder learns a rotation happened, which it could not read.
- A node that has not received a removal cannot tell: the rule's "on what it holds now", under any design.

## Words
- **Proven actors** of a connection: the actors the peer proved on it (issues/net-connect.md, Rules): its account, key actors it holds (a link key it redeems), its own node to nodes of its own account.
- **Known actor**: one whose proof this node can check: its own account, contacts, holders of anything it holds (through the rosters it holds) but their own account's private things (spec/sync.md §10), and a key actor listed by static entry on a roster or in a head claim set it holds (spec/sync.md §2: K's admin listed it there, so a node holding K may be shown it). A node holding only K's `label.0` (a peer that cannot read K) knows K's key actors this way and no account.
- **Credential** of L: a (match value, proof) pair. The match value keys the beacon; the proof is what a Hit on it must show. Four classes, one table:

  | class | match value | proof | in whose filter | the filter goes to |
  |---|---|---|---|---|
  | read secret of L at a current epoch (spec/crypto.md §4 Current) | the secret | the Hit's 32-byte beacon (only a holder computes it); the reply's tag | a reader of L | a peer that proved a known actor |
  | key actor A listed on L (a link key) | A's static entry on L (spec/wire.md §8) | this connection proved A | A's own node, for each L its link names; every node serving L: a reader for each key actor on L's roster it holds, a peer that cannot read for each static entry in L's head claim set | known actors (a reader); every connection (a peer that cannot read) |
  | sync key of L's head | `sync_pk` | an open signature by the sync key (spec/sync.md §5 Open) | a peer that cannot read L, per served head | every connection |
  | deposit key of L's head | `deposit_pk` | the deposit's signature (spec/sync.md §5 Deposit) | a peer that cannot read L, per served head | every connection |

  A match value that is public (a static entry, a role public key) is computable by anyone holding L's `label.0`, roster or `keys.0`; keyed under r it is testable only on this connection, and it opens nothing without its proof. A reader's filter holds no sync- or deposit-key entries: epochs apart between readers is ByRole's, and a deposit between readers is an offer (Deposits).
- **Judgment** J(L) of the connection, by the node's own view: holder if any proven actor is a current holder of L; else departed if any proven actor once held L and does not now; else unknown.
  - **Holder** is spec/crypto.md §4 "Holders for keys" on L's thing (the read role's holders, `until` disregarded), closed transitively through the rosters the node holds. An account on a roster holds through it; a key actor on a roster holds directly. A node's own account is a proven actor to its other nodes, its own node key only there.
  - **Departed**: every grant path the node has seen for the actor has ended by a removal or finalize it holds (Holders for keys: `until` disregarded). Keys read no clock (spec/crypto.md §4), so no clock enters J. A path the node cannot see (a roster it does not hold) is no path: departed means "known to have left by every path known here", not "left". Unknown is the answer for an actor reachable only through rosters this node lacks, and the only answer at a node holding no roster of L (a key actor's node before it has read K; a peer that cannot read).
- **Admissible** credential of L for a connection: a current credential of L, unless J(L) = departed, where only a current epoch **covering** every departure of the proven actors from L it holds counts (spec/crypto.md §4 Covers: a rotator knowing the departure sealed that epoch to the holders it judged current, so a credential at it shows a path this node cannot see; a static entry or role key never overrides departed). Unknown blocks nothing: a credential of L at a node that has never seen L's roster is admissible. Everything a node tests, sends or accepts for a peer is limited to admissible credentials; the admissible set is computed from what the node holds, per connection, after the proofs.
  - A node's credentials and J are functions of what it holds; nothing arrives by a peer's word.

## The pair key
Beacons are keyed over a pair key r, 32 random bytes shared by exactly the two nodes of a record (issues/net-reconnect.md): stable while the record lasts, so a peer can keep what it was sent; meaningless to anyone else; naming no node. A connection with no record derives r fresh from the connection's challenges (first contact; every connection of a peer that proved no known actor). r goes only over the connection, after both sides' proofs.

## Beacons
```
beacon(match, L, r) = BLAKE3(key = kdf("beacon", match, L), r)
```
- A node's filter for a connection holds one beacon per admissible credential of each L it holds, by the table (Words).
- A filter entry is the first `f` bits of a beacon. `f = ceil(log2(n)) + P` with n the entry count of the generation's whole filter (n = 0: `f = P`), fixed per generation; 256 caps it (P below).

## Account proofs across rotations
Rotations are self-verifying (each is signed at the epoch it rotates; `osis_perm::chain` counts them from held rotations and the side alone), so a peer hands them over with no trust and no sync connection, in the proof exchange of a connection, both ways:
- **Proof**: the prover names the epoch it signs at; the verifier says which rotations of that account it holds (its newest heads); the prover sends the signed rotations between. The verifier applies them by the chain rules, then checks the epoch. A verifier with no base for the account starts from the account's record (its root).
- **Refusal** carries the verifier's rotations the prover lacks (the same exchange the other way): an honest sibling that was offline catches up in that step and retries.
- **Removed against behind** needs no timestamp: an epoch is open only where it descends from every rotation held, so a removal closes a removed node's epoch, and once both sides hold the same rotations both answer alike.
- **Size** is the rotations since the verifier's head, not the history.
- A key actor proves its signing key over the connection's challenges; the verifier matches it to a static entry it holds (Words). Everything a connection proves comes over the connection, never from group data: a node's chain to its account is in this exchange, under step 6 of issues/account-signing.md the account's rotations alone.
Message bytes as built: spec/wire.md §11.2 Prove; the verifier's heads and the refusal's rotations are not built (this issue owns them; issues/account-signing.md points here).

## Messages
```
Beacons  [id, gen, Opt(base), f, lo, hi, gcs, more]               -> Status [id, [code]]
Offer    [id, [item*]]                                             -> Status [id, [[code, Opt(tag)]*]]
  item = [0, beacon, Opt(proof)] (Hit) | [1, sync_id, [beacon*]] (ByRole) | [2, sync_id, blob, wrap, sig] (Deposit)
Lost     [id, [[sync_id, cursor]*]]                                -> Status [id, [code]]
Digest   [d]                                                       (unanswered)
Members  [[sync_id*], more]                                        (unanswered, only on a digest difference)
```
`Digest` and `Members`: issues/net-reconnect.md, Agreement.
- **Beacons**: one `gen` of a side's filter, in pages over disjoint ascending ranges `[lo, hi)` of the `f`-bit space, each a Golomb-Rice coded multiset (gap Rice parameter P, duplicates gap 0), each within `MAX_MESSAGE`; `more` until the last. The receiver accepts additions only up to n entries past the whole filter's n; past that the sender must send whole (density ≤ 2^(1-P)). No `base`: the whole filter, replacing what the peer held. A `base`: **additions** to generation `base`; nothing is ever removed from a stored filter. A peer whose stored generation is not `base` answers code 13 (unknown) and gets a whole filter.
- **Staleness**: a removed credential leaves an entry the sender no longer honours; a tester that hits it sends a Hit and is refused. A sender sends a whole filter, new generation, when the entries it has added since the last whole one pass the entries in that one (twice the density at most): false positives stay within a factor 2, amortized cost one re-send per doubling.
- **Stored filter**: the peer's latest generation, durably with the record (issues/net-reconnect.md); nothing is stored for a connection without a record.
- **Testing**: a node holds a stored filter of the peer and its own **pending** set: its admissible beacons whose `changed_at` is past `acked_pos` (the peer has not acknowledged them, or an Offer from testing them is unanswered, issues/net-reconnect.md The record). Every completed filter arrival, whole or additions, every own change, and every re-marking below tests the pending set against the peer's latest stored filter; a whole first-contact filter tests every admissible beacon. The test merges sorted own values against the filter in one pass. A node tests with every credential it holds, of every class: a reader with its read secrets and its key actors' static entries, a depositor with the deposit keys of the inboxes it has deliveries for, a node opening a group at a peer that cannot read it with the group's sync key.
  - Why pending and not only the new: a pair (a at this node, b at the peer, a = b) is found if one side tests a after holding b. Each side keeps a pending until `acked_pos` passes it: the peer acknowledged a (its ack is sent after receiving a), this node tested a, and no Offer from that test is unanswered. If this side's test at b's arrival misses, a was acknowledged before b arrived; the peer's test of b at a's arrival then had b pending and found it. Two nodes gaining one credential at once cannot both miss.
  - A test runs at each filter arrival, before later messages of the connection; if an Offer is unanswered it runs when that Offer is answered, against the latest filter and pending set. So an `acked_pos` never passes a credential no finished test covered.
  - A dropped connection or lost reply leaves `acked_pos` where it was: the pending set is tested again on the next connection. `acked_pos` is durable; the connection's position of the peer's last ack and `tested_pos` start equal to it and last the connection. `acked_pos` rises only with no Offer unanswered, to `min(ack, tested_pos)`, and never falls except by the next rule.
  - **Re-marking a member pending** (per record, at every close: a `Lost` sent or received, a digest difference): `acked_pos` and `tested_pos` each become `min(self, changed_at(L) - 1)`, and a test of the pending set is due. The peer's ack stands: it still holds the beacon, so no beacon is re-sent for this. `changed_at` does not move, so no other peer's record or test is touched: a peer causing a close costs only its own record. Other sync IDs with `changed_at` above that position are tested again in the same pass (a merge, no bytes unless it hits); only a drop before the test re-sends them, once, as additions. An Offer unanswered when it happens finishes with a fresh test, as above.
- **Offer**, in hits-then-roles order: Hit items go first; ByRole only for L still not open once the Hits were answered; Deposit items at any time.
  - **Hit** `[beacon, Opt(proof)]`: the full 32-byte beacon of the tester's own credential whose `f` bits hit, with the credential's proof where its match value is public: an open signature for a sync key (as spec/sync.md §5 Open, over the connection's challenge); none for a static entry (the handshake proved the key actor) or a read secret (the beacon is the proof). It names no sync ID, so a false positive shows nothing. A deposit key is never Hit: a depositor that hits it sends the Deposit item.
  - **ByRole** `[sync_id, [beacon*]]`: only where J(L) = holder at the sender, for L not open and held; the beacons are the sender's at every epoch of L it holds. It shows L to the actor it judges a holder.
  - **Deposit** `[sync_id, blob, wrap, sig]`: an inbox blob for L, wrapped and signed as a Deposit (Deposits).
- **Receiving** an Offer: a Hit opens L when its beacon is one of the receiver's admissible beacons for this connection (exact match, on a table of this connection's beacons built when the first Hit arrives, then kept for the connection) and its class's proof holds: a static entry's key actor is a proven actor of this connection; a sync key's signature verifies under the head's `sync_pk` (or a superseded step's, answered as spec/sync.md §5). A ByRole opens L when the receiver holds L and J(L) = holder, or a listed beacon is its own at an admissible credential. A Deposit is taken under Deposits. Otherwise refused, one code (14), never a reason.
- **Reply** to an accepted Hit carries `tag = BLAKE3(key = kdf("beacon reply", match, L), beacon)`: the tester checks it, and that its beacon is still admissible for this connection, before it opens L on its side. An untagged 0 opens nothing for the tester. Without a tag a hostile peer answering 0 to a dense filter's every Hit would be served every sync ID. For a public match value the tag shows the replier holds L's `label.0` or roster (what serving L by that credential takes); a node that holds those and lies serves nothing it does not hold, and pulls only what the tester's own rule shares with it. A ByRole's reply carries none: its sender already judged the peer a holder.
- **Divergence** of the two sides' S (a restored store, a reply or `Lost` lost with its connection): compared once a connection by the digest of S; a member only one side holds is closed and re-marked pending on both sides (issues/net-reconnect.md, Agreement). A tester declining an accepted Hit (its beacon stopped being admissible and L is not open by another route) sends `Lost` at once.
- **Lost** `[sync_id, cursor]`: the sender no longer shares L. `cursor` is where L stopped for the receiver (issues/net-reconnect.md, Joining and rejoining). L was shared, so nothing is shown. Idempotent, and never resent: a `Lost` lost with its connection shows as a difference in the next digest. Every close of a member re-marks it pending at that side (Testing): a pair that closed with no credential change must still be able to reopen.

## Opens
- An open stands while the rule still holds at the serving node, re-judged on any change to L's credentials, roster or head.
- A node sets `L` open with the credential class and proof per side, in the record (issues/net-reconnect.md).
- **Ending**: at any change of L's credentials, roster or head the serving node re-judges. An open by holder judgment is untouched while J = holder. An open whose proof was a credential now not admissible, with J ≠ holder: L is served through that rotation event inclusively (the stream's `until`, issues/net-reconnect.md), then `Lost`, sent only once the requester's reported position has passed `until`. A current holder applies the rotation, has a new credential (an added beacon, a Hit), L opens again at no first-sync cost. A removal of the peer's actor: J = departed: `Lost` at once. An open by sync key ends when the head's sync key changes, through that head's event, as spec/sync.md §5.
- **Reopen by Offer**: the same rule; `L` rejoins (issues/net-reconnect.md).

## Peers that cannot read
A node serving L with no role in it holds no read secret and no roster: its credentials of L are the head's `sync_pk` and `deposit_pk` and the static entries of the head's claim set (Words), its J is unknown, and its filter for L goes to every connection, proofs or none (the entries name no actor of this node; what they show is Leaks). It tests nothing for L: a reader finds it by hitting its sync key with an open signature, a key actor by hitting its own static entry, a depositor by hitting the deposit key with a Deposit item. An open by sync key is spec/sync.md §5's, judged by the head, kept in the record where one exists (issues/net-reconnect.md). Two nodes that cannot read L hit each other's sync-key entries (both know `sync_pk`) and neither can sign: a match between them opens L only under issues/net-one-peer.md's consent rule (replication between own boxes). Readers dial such a node at an address they know (issues/net-connect.md: a LAN, a configured address, the serving-node listing a contact's profile carries), never from group data.

## Deposits
A deposit is a delivery of an inbox blob to the recipient's inbox sync ID (issues/net-role-sync.md: an actor's sync ID is its inbox; its `keys.0` names it with the deposit seed), and the depositor already knows the recipient (it holds its `keys.0`). So it needs no second mechanism: it is an Offer item to a node that may hold the inbox.
- **Between readers**: the depositor sends `Deposit [L, blob]` on a connection where J(L) = holder, L the inbox (the peer proved the recipient, or an actor holding the read role of the recipient's home: a team's member). The receiver takes it when the deposit signature verifies under its head's deposit key and it proved to this peer an actor holding L's read role; else 14. Both read the same proven actors, so neither learns anything by it: the depositor sends only where it already judged the peer a holder, and a receiver never confirms an inbox it did not prove an actor for. Refused for now (budget, rate, storage: spec/sync.md §5) is no answer, sent again by issues/net-reconnect.md's retry rule; taken, it leaves the depositor's pending set (issues/net-first-contact.md).
- **At a peer that cannot read**: the depositor hits the inbox head's deposit-key entry in that peer's filter and sends the Deposit item; the peer takes it as spec/sync.md §5. Anyone holding the recipient's `keys.0` can test this entry: such a node shows "I serve this inbox" to every holder of the recipient's card, as a host answering a Deposit does.
- **One-way knowledge** (the depositor holds the recipient's `keys.0`; the recipient's nodes do not know the depositor): the recipient's nodes prove nothing to it (identity only to known actors), so no connection judges them holders, and the delivery stays pending, shown, until a node that knows both is connected, or a peer that cannot read the inbox is. Whether the depositor may instead prove "I hold your `keys.0`" and have the recipient's node reveal itself is Tess's, asked once in issues/net-connect.md (Rules, one-way knowledge); a yes changes recognition there and nothing here.
- Rejected: **deposit beacons** (a per-connection list of `beacon(X25519(sk, R), L, r)` with a fresh scalar per connection, tested by holders of the recipient's read role by one X25519 per held inbox epoch, sent to every peer that proved any actor). Their one gain over this, a delivery to a recipient's node that does not know the depositor, is exactly the probe: a node proving any actor chooses a list over every `keys.0` it holds and learns which inboxes the peer serves, so which accounts it belongs to. Closing that (answering only known actors) leaves the same reach as offers at the cost of a second list, a scalar multiplication per inbox per connection (3 s at 10^5 inboxes) and a pending-delivery count shown to strangers.

## What each case gets
- Both current at a common epoch, whatever else: Hit.
- Epochs apart, one knows the other holds L: ByRole; the beacon list proves the epoch or J does (`Q ahead`).
- Concurrent rotations, each judges the other a holder: ByRole, J on both sides.
- A key actor's node (a link redeemer) against any node serving K (the sharer's, a joiner's, a peer that cannot read K): Hit on its static entry, either side testing; the sharer need not be online (issues/net-first-contact.md).
- A reader against a peer that cannot read L (issues/net-reconnect.md, Peers that cannot read): Hit on the sync key with an open signature; a depositor against it: a Deposit item after a deposit-key hit.
- A removed holder E with the current epoch (rotation is lazy, spec/crypto.md §4) meeting a node that has seen the removal: L is left out of E's filter and any Offer from E is refused (J = departed). Against a node that has not seen it: shared, no design can tell (above).
- Not matched: a holder no node it meets knows and whose epoch none shares current, stranded anyway; two branches of concurrent rotations where only one side knows the other, until either meets a node both can match. Both already accepted (Tess).

## Adversaries
- **Lying or flooding filter**: decoded gaps must stay within `[lo, hi)`, pages ordered, else Error 2 and close. The sender sends `f`; the receiver rejects a whole filter whose `f` is not `ceil(log2(n)) + P` for its decoded count n, an additions page whose `f` differs from its generation's, and additions past the whole filter's n (Messages): density stays at most `2^-P` whole, `2^(1-P)` after additions. A dense set hits every query only for values it could not choose without the credential; a hostile filter costs the tester a pass, and at most one 32-byte Hit each, per own credential: the peer gets PRF outputs it cannot use and no serving (no tag). At most one test pass in flight per peer; pages arriving wait.
- **Learning sync IDs beyond S**: a peer without a credential or J=holder gets the entry count and random bits. A false positive shows nothing (Hit names no L, and only a holder of the match value computes it). Beacons are PRF under a match value, scoped to r: different on every pair, unlinkable across peers. Only `ByRole`, `Lost` and `Deposit` carry a sync ID, each to a holder the sender judged.
- **Public match values**: a node holding L's `label.0` or roster computes L's static-entry and role-key beacons for any r it is given. It can hit a key actor's static entry only on a connection that proved that key actor (the receiver checks), sign for the sync key only with the key, and deposit only with a signature the head accepts. As a replier it can tag a Hit on a public value: the tester opens L toward a node that holds L's `label.0` (a peer of L, current or former), which then holds whatever the tester's own rule shares, ciphertext to a node that cannot read it.
- **Revoked node X of a known actor**: its removal rotates P in the same transaction, so X holds only the closed epoch's key: refused wherever that rotation is held, and no filter runs. Limit: a verifier not yet holding the rotation counts X's proof of P (issues/account-signing.md step (e)). X's node key counts only at P's nodes, and stops there with the removal (off D's roster). Fork window: as issues/account-signing.md (a removed node's fork counts until the owner's merge reaches the reader). X proving another actor it still holds (a link key whose seed it kept) and a still-current secret of L (rotation is lazy) matches and shares until L rotates: the verifier cannot tell X from a holder (the point of account signing), and X reads nothing new, as no writer encrypts under the old epoch after knowing the removal.
- **Restart, record loss, clock skew**: issues/net-reconnect.md. No clock anywhere above.
- **Departed actor keeps a stale copy of our filter**: stale entries hit, Hits are refused, one code: it learns only that L was once held (it was there).
- **Hostile Deposit items**: budgets and rates as spec/sync.md §5; a Deposit for an inbox the receiver proved no actor for is 14 whether or not it holds it.
  - Open: a depositor holding the inbox's `keys.0` (a team's card) but not its actor's roster learns from 0 against 14 whether an actor the receiver proved here holds the inbox's read role: a team's membership, which only its roster shows. An honest depositor sends only where its own J already said holder. Closing it means taking deposits only for an inbox whose actor the receiver proved itself (a team's members' nodes no longer take them), or accepting it (the prober is a peer the receiver proved to: a known actor or one it dialed).

## Leaks to accept
- A known-actor peer that shares nothing learns the node's count of current credentials, at first contact and as additions arrive (issues/net-reconnect.md). Padding counts shrinks the leak without closing it; the peer is a known actor.
- A node serving sync IDs it cannot read shows every connection, strangers included, the count of heads it serves (its filter's size), and shows "I serve L" to anyone who holds L's `label.0`, roster or `keys.0` and tests for it. A host answering Open and Deposit shows the same today; recorded in issues/privacy.md.
- A node that cannot read L and receives a Deposit learns a delivery to L exists; it holds it.

## Costs (N credentials at the node, N_p at the peer)
- **First contact**: filter N·(P+1 to P+2.5)/8 ≈ 1.2-1.3 B each at P = 8 (12-13 KB at 10^4, about 125 KB at 10^5), one BLAKE3 and one comparison per own credential, 32 B × N·2^-P ≈ 0.1 B per credential of false Hits, a few round trips. The side receiving Hits builds a table of its admissible beacons once per connection, O(N) (about 50 ms at 10^5). Role offers: only for L the filter did not open, 16 B + 32 B per epoch each. N counts a reader's read secrets per current epoch plus the key actors on its rosters; a peer that cannot read has three entries plus its claim-set static entries per head.
- **Deposits**: 32 B per inbox with a pending delivery per filter test; the blob once, to a judged holder.
- **Per peer, durably**: 1.2 B per peer credential plus S (issues/net-reconnect.md). At 10^5 credentials and 10^3 known peers each with that many: 120 MB, the record budget's largest stated case.
- **Reconnect**: additions only, O(changes), plus the O(N) Hit table if any Hit arrives.
- **Verdict on issues/net-role-sync.md Cost**: extra sync IDs (one per directly shared thing, per link) cost here about 1.2 B per peer and one hash at first contact, nothing on an idle reconnect, and no registration or inbox budget between readers (those exist only at peers that cannot read and for deposits actually sent). They do not bound the pairing or this design; the remaining per-sync-ID cost is the local tick (issues/idle-pass-per-label.md), about 35 ms per minute at 10^4 sync IDs, due-indexing before 10^6.

## Picked values
- **P = 8** (performance switch): 0 makes every own credential a refused Hit (correct, more bytes); infinity sends the 32-byte beacons. Class: performance, both correct.
- **Whole-filter re-send at doubling** (performance switch): 0 (re-send each change) and infinity (never: false positives only) are both correct; the receiver's limit on additions is this same value.

## Model
core/test/tla/net (issues/net-reconnect.md, Model) checks this design. It requires: a filter's arrival is tested with the pending set as of its arrival, before any later message of the connection; `acked_pos` moves only past what is acknowledged and tested with no Offer unanswered; the digest is first in each direction and no Offer precedes reading the peer's; a member lost with no credential change is re-marked pending on both sides, `tested_pos` with `acked_pos`.

## Replaces
`wanted_labels`' co-reader and link-route parts, `reach_nodes` as a serving check, claims between readers, the per-sync-ID Open at a peer that cannot read (the sync-key Hit is the open), the deposit loop over hosts (issues/net-sync-structure.md).

## Rejected
- Whole-list exchange, overlap from roles alone (misses both-stale holders); member beacons and pair hellos (need unproven actors or per-roster cost); removals from a stored filter (a collision removes another's entry, a false negative); the link seed as a beacon secret (only the seed's holders compute it: a redeemer and a joiner that is not the sharer never match; the static entry is what every node serving K holds); deposit beacons (Deposits); hash-only Offer bodies without a confirming tag (a dense filter would be served everything); DH private set intersection (32 B and a scalar multiplication per entry); Bloom filter (about 30% larger, no canonical encoding); past epochs in the filter (shows current holders to everyone who held an old epoch); Hits naming sync IDs (a false positive shows L); readers learning which nodes serve a group from group data (per-node data in groups, issues/account-signing.md; a co-holder outside the listing account's contacts could not read a profile listing either).

## Tests (default tests, over issues/net-tests.md)
Two nodes that never met, of accounts that know each other, find T; a node a rotation behind meets a holder granted after it; two concurrent branches heal through two old members; a removed holder matches no node that has seen the removal and learns nothing from offers; a peer answering 0 to a dense filter's Hits opens nothing; a known peer sharing nothing learns only counts; two nodes gaining one credential at once, connected, open it; a lost Hit reply or Lost is retried; a tester that saw a removal opens nothing for the removed node; a holder through a roster this node lacks, removed from a path it knows, matches at the removal's rotation epoch; a link redeemed through a joiner while the sharer is offline, and through a peer that cannot read K; a finalized link's static entry opens nothing at a node holding the finalize; a static-entry Hit on a connection that did not prove the key actor is refused; a reader opens a group at a peer that cannot read it by sync key, nothing else of that peer's filter opens; a grant between accounts that know each other arrives over a LAN with no third node, and the depositor learns nothing of inboxes it was not proved an actor for; a one-way grant stays pending, shown, and lands through a peer that cannot read the inbox; hostile filters (overlapping pages, oversized, adversarial density) close or cost linear work.

## Built
Per connection (`core/node/src/sync/shared.rs`, `core/proto/src/filter.rs`, kinds 36-40, spec/sync.md §10 Shared set): whole filter, additions, one generation in flight, pending (`acked_pos` and `tested` for this connection, `Testing`), Hits, tag, ByRole, Lost, re-judge at every change (`stamp_changes` sets `shared_dirty`). What a peer connection carries is S and its stream alone, both sides pulling (issues/net-reconnect.md Built); an accepted static-entry Hit's answer carries the head's entry box (`EntryGrant`); connection proofs name sources (`Proven::node`) and charges. A node's read credentials go only to a proved known actor, the head credentials of what it keeps unread to every connection: a dialer knowing no actor of the listener sends `NoRecord` and tests the listener's filter under the connection's pair key (a link's redeemer), and the listener runs the set for any dialer (a static entry absent from its filter is the redeemer's `static_entry_refused`).
Not covered: a known peer forces O(N) work per small message (each additions page re-sorts and tests; a Hit then `Lost` re-tests from `acked_pos`); no rate limit, within the stated linear cost per filter.
Across connections (step 7, issues/net-reconnect.md Built): S, `acked_pos`, both filters and their generations are the record's; the digest first each way, `Members` on a difference; `Lost` carries where the member stopped; a rotation ends an open by a stale credential at `until`, `Lost` once the requester reported past it. Not yet: a Hit's Departed rule at a covering epoch (Admissible; departed admits nothing); readers testing sync-key entries (step 9, 3h1).
Deposit items between readers (step 8, notes/inbox.md Deposit items): an inbox listing no host queues one deposit for its nodes (`Dest::Nodes`), offered one at a time per connection where J of the inbox actor is holder; the receiver checks its own proved actors and the head's deposit key, 14 otherwise; refused for now (5) backs off as at a host; taken leaves the pending set. A hint's thing's read secrets are credentials, so the granted group opens by the box's secret. Tests `deposits::`. Deposits at a peer that cannot read take the hub store's Deposit rules (3g); a depositor testing deposit-key entries is step 9's reader half (3h2). Two connections of a pair dialing each other both run a set until both sides pull on one connection (step 6's second part).

## Steps, in dependency order (with issues/net-reconnect.md)
1. **Model** (Model, issues/net-reconnect.md).
2. **Session proven actors** (built: `SyncEngine::proven(conn)`, `Prove`/`Proved`, spec/wire.md §11.2): the actors a connection proved, read only from the connection's own proof exchange, never from group data; key actors by signing key, the account by its epoch key, the node key between nodes of one account. One function; everything below reads only it.
3. **J and credentials** (built: `osis_engine::labeling::Judge`, `SyncEngine::judgments` and `credentials`, the listener's gate over rosters; a peer that cannot read gets `head_credentials` at step 9): J over rosters decides what a proven actor may reach, never "is an account"; holder/departed by actor over rosters; `credentials(L)` by class. A J that lets a node key alone (a chain to an account, without the account's epoch key) reach anything is a security bug: a node key holds roles only on its own account's D, private to that account.
4. **Records, r** (built: `core/store/src/record.rs`, `core/node/src/sync/records.rs`; issues/net-reconnect.md Built): a record found by r on the session's known key actors; `Resume`/`Resumed`; `changed_at` from step 3 (`SyncEngine::stamp_changes`). Filters, generations and what drives `acked_pos` and S come with step 5.
5. **Beacons, Offer, Lost, first contact** (built, a connection at a time; Built, below).
6. **The node log, Pull, Push** (issues/net-reconnect.md): built, both sides pulling, no uploads or Opens between readers, own writes placed in the node's store whatever hosts are connected, reports for status, one connection per pair with direct before relayed (issues/net-reconnect.md Built).
7. **Reconnect** (built): S restore, the digest, base generations, `Lost` cursors and lags, `until` and the reported position, read from the per-message reports (issues/net-reconnect.md Built).
8. **Deposit items** (built, with issues/net-first-contact.md).
9. **Peers that cannot read** through filters and records: sync-key, deposit-key and claim-set entries. Built inside issues/net-one-peer.md's build order: 3g (the serving side, over the hub's store: built, issues/net-one-peer.md 3g) and 3h1-3h2 (readers treating such a node as a peer, `known`).
10. **Account signing step 6** (built): an account proved at an epoch open here counts for J, credentials, the known gate and the records like any actor; the node key goes only to nodes of its own account (`provers(own)`: a dialer by the `reach.0` of the key it dials, a listener by the dialer's proofs; `Proven::node` only for such a node), so a node of another account is its account here; departure of a node is its removal plus P's rotation (one transaction), after which its proofs match no record and open nothing. What counts a peer without a node: `Proven::source` (budgets, suspect-repair dedupe, complete-pass waits and status sources: per account for other accounts' nodes). Tests: osis-node `net_accounts::`. Limit: a removed node keeps its epoch key until the removal's rotation reaches the verifier (issues/account-signing.md step (e)). Not built: carrying the rotations a verifier lacks and the refusal's (Account proofs across rotations): a verifier behind the signing epoch proves no account.
