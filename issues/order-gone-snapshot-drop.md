# Keep-at-most-0 snapshot dropped in one arrival order only
> Summary: order seed 2700027 (exhaustive), on main too: a snapshot whose carried write was killed by a superseder with a `ts` below the snapshot's never dies for it, so under keep at most 0 it keeps the dead value with no bound; in another order it drops.
> Tags: tests, retention, engine, security

Replay: `OSIS_ORDER_SEED=2700027 OSIS_ORDER_LEN=30 cargo test --workspace --test it order::arrival_order_exhaustive_large_spec_crdt_4_8 -- --include-ignored`. Shrunk: `vec![Write { by: 0, t: 1, op: 18, k: 1, v: 6 }, Send { from: 0, to: 1, back: 0 }, Undo { by: 0, back: 0 }, Compact { by: 1, t: 0, op: 18 }, Write { by: 0, t: 0, op: 18, k: 0, v: 5 }]`; the first differing index line is the snapshot's commit (dropped `{(0, 0)}` in order #1 only).

Shape: peer 1 snapshots a keep-at-most-0 register (the snapshot inherits at most 0 either way: the schema default before, the carried write's own delta now) holding a write that peer 0's undo already killed; peer 0 then writes again. In the as-made order the snapshot arrives with its write already dead and stays; in the reversed order the new write arrives first and the snapshot is dropped. Spec §5: under at most 0 a body with no live write goes; which of the two is wrong (a snapshot dead on arrival kept, or dropped too early) is to be found.

Diagnosis (snapshot-duty review): the snapshot S carries peer 0's first write w1, which the undo (`ts` below S's) killed before S was made, unseen by S's author. As made, the undo arrives first: S's copy of w1 is dead on arrival, and both `note_copies` (`d.at > ts`) and `carriers` (`*ts < at`, used by `note_deaths` and `replay_all`) date a carried write's death for a snapshot only after the snapshot's `ts`, so S gets no death, is never replaced, and under at most 0 holds w1's undone value with no bound (a keep-at-most leak, not just an order difference; any concurrent superseder with a lower `ts` than the snapshot does the same). Reversed, w2 (`ts` above S's) is the superseder S's join meets, so S dies and drops. Likely fix: a carried write already dead (or killed by a lower-`ts` superseder) dies for the snapshot at its `ts` (spec §5 "each dying for it at a date after the snapshot's ts" read as clamped, never earlier than the death), in `note_copies`, `note_deaths` and `replay_all` alike; `carriers` would need the snapshot's actual contents for snapshots taken after the death (the frontier alone over-counts a write the author already saw dead), e.g. through `Core::carried`. Deaths code, so not done in snapshot-duty.
