# One kind of peer
> Summary: A node has two kinds of peer (saved peer, the old host; direct peer, a co-reader) with two stores (the hub's and the engine's) behind the one hub session, local passes besides; one listening key (built, 3d). Make one: one key, one blind store and serving path (the hub, fed public data by node sync) that opens by key proof alone, peers that cannot read listed by the accounts they serve (issues/account-signing.md), consent by own nodes; then the API (`SyncId` out). The concept unification the rename waits for. Part of issues/net-rework.md.
> Priority: normal
> Tags: node, sync, host, proto, api, spec

| | Saved peer (old host) | Direct peer (co-reader) |
|---|---|---|
| Found by | fixed address in `label.0`, link and card text | `reach.0`, LAN, a link's sharer |
| Who can be one | a node with `host^.0` that admits the label | a node that reads the group |
| Serving code | `ServingSession` in the hub (`osis-host`, `HostStore`) | the same hub session, node sync above it serving the stream; local passes when no host is listed (notes/peers.md) |
| Store | `host.redb` (entries, blobs, durable log) | node sync's entries and the engine's blobs; the durable node log (notes/peers.md, The stream) |
| Key | the node's one key (the dialable key) | the same |
| Opens by | sync key, claim, static entry | those for a peer that cannot read; between readers nothing opens, the shared set's members are pulled (notes/peers.md, The stream) |
| Registration | first come, by parent's delete key | steps recorded in `label.0`, plus child steps peers register (memory only); new labels refused |

## Steps, in the order of what they unblock
1. **An address names a node** (built with 3d): a peer is dialed by key with hints (spec/sync.md §10, spec/wire.md §10): a `peer://` saved peer or label host is a host like any address (sim `no_server::a_peer_address_saved_peer_dialed_by_key_syncs_spec_sync_10`).
2. **One listening key per node** (built, 3d): the dialable key serves sync, data the node cannot read and the client port; dialers stay ephemeral; LAN listeners keep a fresh key per network join (issues/net-connect.md), served by the same path. A reader finds a sync ID by a peer's filter and opens it there, so the filter goes on the key that serves unread data. `Osis::listen` binds more addresses under the one key; a client is cut off by its own entry (issues/client-auth.md); key rotation is `rotate_peer_address`, by hand only, moving every listener. The client port keeps its own access rules: Auth before any request, client actors, the main-actor tier only from `Peer::Unix` (notes/client-port.md).
3. **One serving path**. Principle: one connection, one session, one store answering it; every secret above it, in node sync.
   - **Session owner**: the hub (`osis-host`), one `ServingSession` per connection, every listener and, from build 3i, every dial. The node's driver owns the transport secret and the listeners and drives the hub sans-I/O in node sync's own loop (as the simulator's `host_of` does), so node sync reads the hub's store directly (public data flows up) and the two exchange messages by function call, not by channel. Node sync is the session's upper layer on every connection, as it is for the client port.
   - **Routing** (kind: who answers):

     | kinds | answered by |
     |---|---|
     | Hello, Ping/Pong (2-3) | the session |
     | Register (7, with Step 6), Upload (10, Status 11), Delete (14) | the hub's store, for a sync ID node sync opened on this connection by sync key (below); Register of a genesis or a recorded path by admission alone |
     | Fetch (19-20) with a node-range id, any answer with a node-range id | node sync (it reads the bodies from the hub's store) |
     | Stranded, Suspect (30-31), Prove/Proved, Resume/Resumed (32-35), shared set (36-40, 45-46), stream (41-44) | node sync |
     | client port (24-29) | node sync, by the port's access rules |
     | Open/Opened (4-5), Deposit/Budget (12-13), Sync/Reconcile (15-18), Fetch without a node-range id, Subscribe/Unsubscribe/Push (21-23), Path (8-9) unless build 3h uses it | gone (build 3i): an open is a Hit, a deposit an Offer item, reading the stream |
   - **The hub calls up for nothing**: it judges no open and holds no secret, filter or record. Up: every message of the table's node sync rows, a connection's start with its binding (listener key, both challenges, transport peer, source), its end, and store changes (a head moved, entries logged). Down: messages to send (node sync's requests within the session's request window, answers at once), `open(conn, L)` and `close(conn, L)` (the session's gate for the store's kinds; a new head's sync key closes it there, as `still_open` does), public data for the store (below), and closing a connection.
   - **Flow control**: one request window per connection covers both layers: a request handed up counts against the peer's `MAX_UNANSWERED` until node sync answers it (as client-port requests do now), and node sync's stream pushes wait for the session's room (`WantRoom`/`Room`, as Notify does), not sent past it.
   - **Opens**: all node sync's, one S per connection (issues/net-shared-set.md). Between readers by read secret, ByRole or static entry; at a node that cannot read L, by a Hit on the head's sync key with an open signature (over the other end's challenge and transport key, whoever dialed), a key actor's static entry (answered with `EntryGrant` from the hub's claim sets) or a Deposit item after a deposit-key hit (put through the hub store's deposit rules, spec/sync.md §5). The filter's entries for a sync ID the node cannot read (sync key, deposit key, the head's claim-set static entries) come from the hub's store and go to every connection; `changed_at` moves when such a head moves. Upload, Register and Delete are taken only under a sync-key open: readers do not upload to readers.
   - **The store**: one (step 4), with one node-wide log the stream serves (issues/net-reconnect.md), per-label logs gone. Node sync writes its own and received entries there as a client; for a sync ID it reads it hands the hub the steps recorded in valid `label.0` (no first-come registration there; issues/net-role-sync.md, Replacement), and the hub takes Register only for sync IDs node sync does not read. Admission (`host^.0`: `open`, `labels`) decides which unread sync IDs the store keeps until step 6; `own` goes, since a node reading its own groups serves them as a reader to their holders.
   - **Readers treat a node that cannot read as a peer**: dial it by key (step 1; addresses as issues/net-connect.md, and `label.0` hosts until step 7), Hit, pull its stream, keep `known` (issues/net-reconnect.md, Peers that cannot read), and judge uploads, registration, promotions and deletes over `known`: one pass rule over `sources(L)`, a local pass being its empty case (issues/net-sync-structure.md (e)). The host client paths (Open, per-label Sync, Subscribe, fills, refusal back-offs) and replication between hubs go (replication is sync with a peer; between two nodes that cannot read, step 6).
   - Sync ID replacement (index > 0) goes last (build 3j; issues/net-role-sync.md).
4. **One store** (decided for 3f: the engine reaches the blobs in the hub's store; an engine transaction touching blob ciphertext opens one there, committed first, and the reconcile at open makes any crash point converge; app reads of large values read it directly; one set of store rules for every row, admission governing unread sync IDs only; replication to `replicate` peers only for unread sync IDs until step 6): ciphertext (entry rows with wrap and stamp, blobs, the node log, served steps and claim sets) in the hub's store, shredding on delete (notes/serving.md, Decisions); plaintext and secret-derived state (an entry's kind, certificates, `changed_at`, records, read secrets) in the engine's. `changed_at` takes its own sequence there (it fingerprints credentials, so it stays out of the hub; only `acked_pos` and `judged_pos` compare with it). A group a node reads and serves is held once. The hub's store is the truth for ciphertext and the engine's state a cache of it: an entry in the hub's store with no engine state is derived again, engine state with no ciphertext row is dropped, so a crash between the two commits converges. `host^.0` going drops the unread sync IDs (shredded), not the store. Node sync reaches it by direct calls in one loop (step 3), so no hop on hot paths; the cost to check is commits per inbound batch (two stores), counted at n and 10n. Built inside step 3's order (3e, 3f): the stream can serve unread members only from one log.

5. **Keep the boundary**: the code serving data a node cannot read cannot decrypt (`osis-host` has no engine or keys; tools/policy.py `host_blind`). With one path it serves readable data too, so the boundary is the crate: node sync stays the only reader, the hub keeps no secrets and the policy check carries over to the renamed crate.
6. **Consent**: who may store data a node cannot read on it: by default only the user's own nodes, which serve the user's groups with no setup; anyone else's is opt-in (decided), as `host^.0` admission written by them. Wider later.
7. **Peers that cannot read** are listed, with their addresses, by each account they serve, on its profile, not in group data (issues/account-signing.md). The listing is how the account's contacts and own nodes dial them off a LAN; which sync IDs a connected peer serves is found by the shared set (its filter of sync-key, deposit-key and claim-set entries, issues/net-shared-set.md Peers that cannot read), so a group's holder who is not the listing account's contact finds the peer wherever it can connect to it (a LAN, an address it knows) and never needs the listing. Adding one later works per account, also a box serving someone else's group by its consent (row 26). The listing account's own nodes keep it current when the box's key rotates. Two nodes serving L unread hit each other's sync-key entries and neither can sign: that match opens L only under step 6's consent (own boxes replicate; a stranger's box does not).
8. **API**: `peers(g)` one list; `sync(g, peers)` adds to it; `set_serving` only limits; `SyncId` and `sync_ids` leave the public API (decided). Admission (`admitted: set<SyncId>`, `caps` by `SyncId`) becomes internal: own nodes write the sync IDs of groups that list the peer into its `host^.0`.

## Build order for steps 2-4 (with issues/net-shared-set.md step 9)
Each step leaves main green, with default tests over the transport and sim of issues/net-tests.md.
- **3a Proofs as node kinds** (built): Prove and Resume join `Message::for_node`, Proved and Resumed by id (a dialing `ClientSession` takes the answers to its own until 3i); `LabelStore::prove` and `resume` gone; node sync checks at most once (`served_prove`, `served_resume`). Tests: `records::`, `net_accounts::` unchanged; `serving::tests::prove_and_resume_go_up`.
- **3b The hub in node sync's loop** (built): the node driver drives `Hub` sans-I/O; osis-host's tokio driver and `Control` go; the hub takes connections from the node driver's listeners. No behaviour change: `serving::` tests unchanged; `NODE_HOST` in tools/policy.py follows. The driver's `HubRun` (`sync/driver/hub.rs`) holds the hub, its listeners, replication dials and turns; osis-host's driver tests are osis-node `hub_loop::`.
- **3c Node sync above the hub** (built): the hub hands node sync each session's start with its binding, its node-kind messages, push room and end (`osis_host::Up`, `Event::Hub`) and takes node sync's messages, room requests and closes down (`Hub::down`, `Action::Hub`), the driver passing both in its loop (`hub_pump`); node sync keeps a hub connection as a served session the hub runs (`serve.rs` `Session::Hub`), so it proves to known dialers there and runs records, the shared set and the stream. A node request handed up counts against `MAX_UNANSWERED` until answered; the hub closes a session whose node request stalls; stream pushes on a hub session wait for `Room` (relay-only ones without room are dropped). Tests: `hub_loop::one_connection_serves_hosted_and_read_labels`, `hub_loop::a_stranger_gets_no_proof_spec_sync_10`; osis-host `hub::node_kinds_go_up_answers_come_down`, `hub::a_stalled_node_request_closes_spec_sync_6`; proto `serving::tests::node_requests_count_until_answered_spec_sync_6`.
- **3d One key** (step 2, built): every listener (dialable, `Osis::listen`'s, LAN, unix) feeds the hub, each session under its listener's key and serving the client port; node sync keeps each connection as a `Served` above it (`Up::Start` at Hello, `Up::Request`, `Up::Opened`; `Down::Reply`, `Down::Notify`, `Down::Keep`), its push room shared by the port and the stream one grant at a time; the hub's store is the host store while hosting, else an empty one admitting nothing. Session limits are one rule over every connection (notes/peers.md, Sessions), the transport slots following it (`Link::kept`). Tests: osis-node `port_tiers::a_client_acts_on_the_dialable_key_only_after_auth`, `peers_review::at_the_cap_a_stranger_goes_before_a_co_reader_spec_sync_5`, sim `no_server::a_peer_address_saved_peer_dialed_by_key_syncs_spec_sync_10`, osis `sources::a_flood_keeps_clients_in`.
- **3e The node-wide log in the hub's store** (built): osis-store's node log (`log_*`) on the hub's `Store` for every entry and head it holds, beside the per-label logs the host protocol reads until 3i (notes/serving.md, HostStore). The incarnation mark is the pager meta's (`log_drawn`), so the host store's suspended transactions append. Tests: osis-host `nodelog::a_listing_from_the_start_is_the_live_set_plus_retained_deletions`, `nodelog::an_entrys_earlier_events_compact_away` (n and 10n), `nodelog::a_restored_store_issues_no_cursor`; commits per batch unchanged (`file::host_batch_writes_do_not_grow_with_entries`).
- **3f One store** (step 4; built in part: `changed_at` is a sequence of its own, `core/store/src/changed.rs`; every node opens the hub's store beside the engine (`SyncEngine::hub_store`, an `Arc<Mutex<HostStore>>` the `Hub` locks per call), and `host^.0` going drops the labels kept for others (`Hub::stop_hosting`), not the store; the engine's blobs live in it (`osis_store::Ciphertext`, the engine's `Tx::blobs`, committed first; host `engine::`)): node sync's ciphertext and its node-log events move into the hub's store, the stream reads the hub's log, `changed_at` gets its own sequence; read sync IDs' paths come from `label.0`; `own` admission and the node's own address as a saved peer (`upkeep_serving_peer`) go. Tests: a group read and served is stored once (blobs counted); deleted wraps unrecoverable on the merged store (forensic); a crash between the two commits converges; commits per inbound batch counted at n and 10n.
- **3g The serving side for unread data** (shared-set step 9, its first half): the filter's sync-key, deposit-key and claim-set entries for unread heads, to every connection; the three Hits; `open(conn, L)` gating the store's kinds; a sync-key open ending through the new head's event (`until`); unread members in the stream, their ephemeral entries from the hub's memory part, relay-only entries through the hub's relay gate. Tests (hand dialer): a reader opens an unread L by sync key, pulls, uploads and deletes; nothing else in that filter opens; a stranger's filter holds only unread entries; a head change ends the open after its event; a deposit at an unread inbox is taken.
- **3h1 Readers read a node that cannot read as a peer**: Hit its sync-key entries, pull its stream, keep `known` (in the record, else for the connection). Open, per-label Sync, Subscribe, fills, `LConn` phases and the refusal back-offs (issues/net-sync-structure.md (d) 7-9) go from the reader. Tests: today's host-read tests over this path; a second reader gets everything through a box with the sharer offline.
- **3h2 Readers write to it**: uploads, registration (a path where the peer is listed and its filter shows no L, or the Hit is refused), promotions and deletes judged over `known`; deposits to an inbox it serves as Offer items; one pass over `sources(L)`, the local pass its empty case, presence keyed by host key (`host_holds`) gone. Tests: a box restored from a backup is uploaded to again from `known`; deletes reach it only from a delete-key holder; a deposit for an offline recipient lands at its box.
- **3i The host protocol goes**: kinds 4-5, 8-9 if unused, 12-13, 15-18, 21-23, Error 15, `osis_proto::rbsr`, per-label logs, replay and `log_keep`; `Replicator` and `replicate`; `ClientSession`, so a dialed connection is a hub session like an accepted one (issues/net-sync-structure.md (a)); spec/sync.md §5 Open, §6 First and Cursor sync, §8, spec/wire.md §11.3. Tests: a box that dialed a reader takes its uploads; remnant grep.
- **3j Replacement goes** (issues/net-role-sync.md, Replacement).

Interim states, each ended by the step named: stream pushes held for room only on served connections (to 3i); two logs in the hub's store (3e to 3i); `ClientSession` on dialed connections, so a node that cannot read and dialed a reader takes no uploads (to 3i); no replication between two nodes that cannot read (3i to step 6); a node hosting nothing serves an empty store, so a saved peer or label host naming a reader that does not host refuses its Open, Upload and Register (the label is not hostless there, so its readers sync with that peer only by the shared set, if they share it; to 3g).

Also: `osis-proto`'s `ClientSession` (the dialing side, not an API client) gets a name that says so (issues/net-rename.md).

## Unsure
- (design, 3f, open before the entry move) Node sync's entry rows do not all fit the hub's `E` rows (refcounted bytes, counted against caps and totals, served): node sync keeps rows without bytes (announced and not fetched, unvouched entries keeping no bytes, dropped chunks keeping only their salt) and tombstones of its own. Either a byteless entry kind in the hub's store that it never serves, or only rows with bytes move (a row then changes store when its bytes arrive, which the reconcile must cover).
- (design, 3f) With `own` and the self saved peer gone, entries a reader uploads to a read L at this node's hub land in the hub's store with no engine state, and the hub's sweep (expiry) and deletes remove rows node sync relies on, at run time, not only at open: node sync then needs the reconcile as a running source (reading the hub's log past a position it keeps, after every hub batch), not only at open. Or the hub refuses host-protocol writes to read labels until 3h.
- (design) A box you run to store your data without reading it (Tess, direction only, easy to change): it has no keys to your data. It is its own node, with an account of its own or none, set to sync your sync IDs encrypted; your account may hold admin over its actor without sharing your data with it. No special kind of node: its admission names the sync IDs or accounts it serves. A box with an actor its owner's account knows (the owner's nodes hold it through the admin relation, and the box knows the owner's account from the admin on its own actor or from its admission) proves a known actor both ways, so the two keep a record and reconnect at what changed. A box with no actor keeps none and pays a first contact per connection (issues/net-reconnect.md, Peers that cannot read, Limit). Settle the details when this job starts.
- (design) Rotating the one key: clients and listings in group data name it. Listings are rewritten by own reader nodes (step 7); clients reconnect by issues/client-auth.md's credentials, not the key.
- (design) Replacement of a sync ID: issues/net-role-sync.md.
