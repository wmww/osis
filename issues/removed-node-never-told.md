# A node removed from its account learns its removal only by chance
> Summary: A node removed from its account (spec/permissions.md §8 Removing) is told by no rule: its account's sync ID closes toward it at once (J departed at a reader source), and nothing is delivered to its node thing. It learned only where its account held a role on another thing whose sync ID carries the account's `keys.0` (a contact's profile granted by a read link). With contacts as public links that route is gone: the removed node keeps reading and holding everything.
> Priority: normal
> Tags: sync, security

Repro: osis-sync `differential::repro_a_removed_node_learns_its_removal` (`New(0), Run, Unpair(0, 2), Run` on the differential's world: node 2, removed from account 0, still reads thing 0, its role on the account Admin by the grant the removal took). The small differential fails on every seed drawing `Unpair` (half the seeds) the same way: tools/known_failures.txt.

Why: at the removal, node 0 judges node 2 departed at A's sync ID and closes it at once (spec/sync-opens.md §5, "J departed at a reader source closes at once"); offline at the removal, it never opens S again (§3 Departed). The removal is "from outside" node 2's node thing N, so it would be delivered to N's inbox (spec/sync-inbox.md §5, spec/permissions.md §4 Delivering an edge piece), but N takes no `grant@~0`, so nothing is fired. Before contacts were public links, the importer's account held read on each contact's profile; A's `keys.0` (the removal's rotation) went as certificate copies under that profile's sync ID (spec/sync-inbox.md §1 Public key record), which node 2 still opened by A's path and was served up to the rotation as an ended member (spec/sync-opens.md §5): it learned its removal there. A public profile gives the account no role, so no such sync ID is left. A one-account node never had one.

Candidates (one mechanism each):
- A node thing takes `grant@~0` from its making (as an account's inbox does), so a removal from its account reaches it as any removal from outside does: a sealed copy under N's sync ID, which only N's node reads.
- A departed reader at a reader source is ended, not closed (served up to the rotation covering its departure, as a store source's departed member is), within the stated bound "a removed reader learns at most one rotation past what it read" (spec/sync-hostile.md). Covers only a node connected at the removal.
