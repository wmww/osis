# Deprecated terms and concepts
> Summary: The one registry of old words and concepts still in the repo (Tess: each is gone or listed here, marked deprecated with what removing it takes). Per row: the term, where it remains, why, what removing takes. Words are fixed by spec/requirements.md Terms and notes/api.md Rules; a row goes when its last use does.
> Priority: low
> Tags: naming

Everything below is **deprecated**: never build on it, never add a use. Where a row points to another issue, that issue owns the work; this one only keeps the list whole. Not counted: `docs/` (refreshed on request), history logs (notes/complaints/), and words with another, current sense (below the table).

| Term or concept | Where it remains | Why | Removing takes |
|---|---|---|---|
| **host** (a keyless always-on node serving labels), **hosts** | engine comments (`retention/`, `engine/mod.rs`, `engine/large.rs`, `labeling/mod.rs`, `apply/keys.rs`, `ephemeral/signal.rs`, `local_peer.rs`); osis-label `ShareLink.hosts` (a link field spec/wire.md §10 does not have: issues/sync-unbuilt.md, Wire) and `host_prefix`; about 35 notes (notes/permissions.md, notes/growth.md, notes/ephemeral.md, notes/crypto.md, notes/engine-*.md most) | sync, spec and the sync notes are done ("a node keeping S unread", "source", `caps^.0`); the rest is words | a per-phrase sweep of engine comments and notes; `ShareLink.hosts` renamed with its vectors |
| **box**, **boxes**, **serving node** in the node sense, and any word naming a kind of node by what it can read ("blind node", "storage node", "keeper" for a node) | none left in code, spec or notes (the Serving API's own name stays until issues/sync-rewrite.md 6b replaces admission) | Tess: "box" is the old host renamed; whether a node can read data is a property of the pair (node, sync ID), never of the node, and every node serves. Say "a node (peer) that cannot read L", "the node keeping L unread for account A" | keep out |
| **admission** of what a node keeps unread: `host^.0` `admit`, keep lists | engine comments (`flows/mod.rs` `standing_chain`, `flows/edges.rs`); the running dogfood node, started at an older pin (`--admit open`) | code, spec and notes are done: a node keeps exactly the sync IDs of its synced group's closure | the comments; the dogfood node at its next pin (notes/dogfood.md) |

| Engine names under the API's: `Written`, `Mutation::expires` per aspect, `CommitKind` beneath the API's, `Time` as `WallMs` | engine | the API has one word; the engine's is older | issues/sync-rewrite.md |

Not old terms (other senses, kept): **placement** of sequence elements (osis-crdt, the paged store: positions in a list or text); **device** as storage or the machine an attacker holds (store `Device`, "an attacker holding the device"); the app's **Person** kind, an address-book contact; `on_change`/`Change<T>` (a value changing, notes/api.md); **server** for a chat community (notes/realms.md) and in third-party names; **blind** as the header's 16 random bytes (spec/crypto.md §7). **box** in the encryption sense (a sealed or symmetric box, "boxed to" an actor: spec/crypto.md, spec/wire.md §7) and for a machine ("this box", notes/build.md), and outpost's **box** (notes/outpost.md). **ended**, **ending** for what has a span: a grant's or edge's `until`, a link, a stream, a pass, a connection, a subscription, a shared-set member (a thing is never ended but **destroyed**; `tools/policy.py` `ended_names` keeps the old sense out of code).
