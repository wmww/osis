# Deprecated terms and concepts
> Summary: The one registry of old words and concepts still in the repo (Tess: each is gone or listed here, marked deprecated with what removing it takes). Per row: the term, where it remains, why, what removing takes. Words are fixed by spec/requirements.md Concepts and notes/api.md Rules; a row goes when its last use does.
> Priority: low
> Tags: naming

Everything below is **deprecated**: never build on it, never add a use. Where a row points to another issue, that issue owns the work; this one only keeps the list whole. Not counted: `docs/` (refreshed on request), history logs (notes/complaints/), and words with another, current sense (below the table).

## The code pass
Done but for the row above's leftovers. Words of concepts under redesign wait (issues/actors-one-mechanism.md): `actor` in identifiers and fields, key actor, holder actor, client actor, `mint_actor`, the account root, device for a node (the existing row).

## Writing rules for any later pass (Tess)
- Not word replacement: read each use and rewrite what carries the wrong implication or is plain confusing, e.g. wherever "actor or not" is treated as a property a thing has outside any commit, a mint admin as special to an app, or a team as a kind of thing.
- **Never call an old concept by a new name.** Where the built thing is still the old concept (the account root, key actors, the signing chain, chain certificates), keep its word and make only the edits that are right looking forward. A section may be marked for deletion or rewriting once a named change lands; that is allowed, not required.

Not old terms (other senses, kept): **placement** of sequence elements (osis-crdt, the paged store: positions in a list or text); **device** as storage or the machine an attacker holds (store `Device`, "an attacker holding the device"); the app's **Person** kind, an address-book contact; `on_change`/`Change<T>` (a value changing, notes/api.md); **server** for a chat community (notes/realms.md) and in third-party names; **blind** as the header's 16 random bytes (spec/crypto.md §7). **open** for opening a sync ID, a blob, an epoch's boxes or a sealed fire (`open_fire`); the `@` signals are **external**. **box** in the encryption sense (a sealed or symmetric box, "boxed to" an actor: spec/crypto.md, spec/wire.md §7) and for a machine ("this box", notes/build.md), and outpost's **box** (notes/outpost.md). **label** for a UI text label (kit, app, Masonry) and a run's or job's name in test tooling (`testenv`, `costs`, the roles-model's checks). **batch** for a group of store writes, records or events (osis-store, a pull reply). **ended**, **ending** for what has a span: a grant's or edge's `until`, a link, a stream, a pass, a connection, a subscription, a shared-set member (a thing is never ended but **destroyed**; `tools/policy.py` `ended_names` keeps the old sense out of code).
