# Deprecated terms and concepts
> Summary: The one registry of old words and concepts still in the repo (Tess: each is gone or listed here, marked deprecated with what removing it takes). Per row: the term, where it remains, why, what removing takes. Words are fixed by spec/requirements.md Terms and notes/api.md Rules; a row goes when its last use does.
> Priority: low
> Tags: naming

Everything below is **deprecated**: never build on it, never add a use. Where a row points to another issue, that issue owns the work; this one only keeps the list whole. Not counted: `docs/` (refreshed on request), history logs (notes/complaints/), and words with another, current sense (below the table).

| Term or concept | Where it remains | Why | Removing takes |
|---|---|---|---|
| **host** (a keyless always-on node serving labels), **hosts** | spec rule text throughout; engine, node-sync, proto, `osis-host` identifiers (`HostPolicy`, `HostKey`, `host^.0`, `host.redb`, `sync/host.rs`, `Hub`); `osis_label::ShareLink.hosts`, `RecoveryCard.hosts`, `Opening.hosts`, `hosts` in test helpers; `internals::host_limit`, `host_limits_unshown` | the peer unification is undecided: three serving paths, two stores, three keys (a concept, not a word) | issues/net-one-peer.md, then issues/net-rename.md |
| **label**, `LabelId`, `label.0` | spec rule text; engine, node, keys, label crates; `internals::LabelId`; `SyncId` is a label ID under the API's word | "sync ID" replaces it everywhere at once, with host | issues/net-rename.md |
| **placed** in the sync sense (a commit held under a label at a peer; "placed under", `Placed`, `placed`, `place`, `placed_with`, `untie_unplaced`, `unplaced_memory_commits`; spec/sync.md §5 **Placed**; test names such as `removal_placed_first_under_every_label_spec_perm_3`) | spec/sync.md, spec/permissions.md, spec/crypto.md; node-sync (`sync/deliver.rs`, `pass/`, `memory.rs`); node tests | every use reads "placed under a label", so the word goes with label; one word for it: **held at a peer** ("held at" a peer under a sync ID), "uploaded" where only the upload is meant | rename with label, spec definition first |
| **person**, `Person`, `create_person`, `set_person`, `.person`, `RecoveryCard.person`, person helpers in tests (`person`, `persons`, sim `NetSim::person`, keys `person`) | engine `flows/person.rs`, node-sync, label, sim, node and keys tests | the engine still calls the account actor so; waits for the recovery redesign (issues/recovery-redesign.md: `RecoveryCard.person` stays until then) | issues/account-rename.md |
| **`World::add_host`, `NetHost`, `hosts` in the sim and node test nets** (sim peers are always-on keyless hubs) | core/test/sim, core/node tests (`net.add_host()`), osis tests | a concept: the harness builds the one kind of peer the code still separates | issues/net-tests.md; renamed with issues/net-rename.md |
| **device** in the node sense | the TLA rotation models (`Depth0.tla`, `Depth0MC.tla`, `D0_fork_rm.cfg`, READMEs, `sides/`) | a TLA model rename means rerunning TLC | the models in one pass with a TLC rerun (app UI text may say device: Tess's Terms) |
| Spec rule words where a role is meant: **edge**, **rights**, **demotion**, **revocation**; one of **part** / **delta** | spec throughout; engine `Edge`, perm | concept changes listed with the peer work | issues/net-rename.md |
| **batch** or **change** for one write: "batch" in engine comments, osis-crdt `batch.rs` (one commit's ops on one aspect); notes/api.md "available changes" | engine, osis-crdt, osis | an API write is one wire commit, named by its `CommitId` | "batch"/"change" out of the comments; crdt `batch.rs` becomes `delta.rs` or `net.rs` |
| Engine names under the API's: `Written`, `Mutation::expires` per aspect, `CommitKind` beneath the API's, `Time` as `WallMs` | engine, node | the API has one word; the engine's is older | issues/net-rename.md |
| **ended**, **ending**, **end** for a thing that is gone (`w.end`, spec/commits.md §5 **Ending**, "ended thing/actor", `ended_certificate`, `ending_evidence`) | spec/commits.md, spec/permissions.md, spec/crypto.md; engine and node-sync identifiers; notes; issues/thing-lifetimes.md | Tess: a thing is released (storage reclaim, may come back), purged or expired (erasure); "ended" names no one of these | say which of released, purged or expired is meant; the umbrella for "gone, whichever way" is to be chosen with the rename |
| Links to deleted issues in the app | libs/kit/src/store.rs, libs/kit/src/render/mod.rs, app/tests/it/share.rs | the workarounds they cite are unchecked | issues/app-workarounds.md |

Not old terms (other senses, kept): **placement** of sequence elements (osis-crdt, the paged store: positions in a list or text); **device** as storage or the machine an attacker holds (store `Device`, "an attacker holding the device"); the app's **Person** kind, an address-book contact; `on_change`/`Change<T>` (a value changing, notes/api.md); `EphemeralId` (an own write's local number, until `BatchId` folds, above); **server** for a chat community (notes/realms.md) and in third-party names; **blind** as the header's 16 random bytes (spec/crypto.md §7).
