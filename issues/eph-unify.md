# Ephemeral as a storage property only
> Summary: Design (Tess's direction: "ephemeral should be same as durable in almost every way") to make ephemeral data ordinary data whose commits, bodies and index rows live in memory: own covers, the separate held-commit records, the node-sync lane and the ephemeral undo log go; ephemeral aspects take ordinary compaction snapshots and every retention option. Kept: memory storage itself, presence (author tie), signals (relay-only), the restart reconcile, a memory cap. Problems listed with their simplest answers; none blocks. Seven-step plan, roughly 3500 lines removed and 2000 added; steps 1-2 built, local memory commits moved into step 3; step 3's session form, memory-class routing, records beside the deltas, records in Core and freeing built; memory commits refuse durable-class aspects and receivers judge class by the AK's marker, received ones go through `ingest_memory` (3cd, no production caller); step A (Core prerequisites on the hidden path: expiry vanish, superseded expiring writes, node cap and decode bound, header forgetting) built; step B split: B1 (memory snapshots and covered drops in Core) and B2 (the swap: local writes as memory commits, received blobs through `ingest_memory`, own covers and the lane's own machinery deleted) built; left C (lane onto the durable sync path), D (undo over held bodies), E (durable automatic compaction).
> Tags: ephemeral, design

## Model
Lifetimes stay (ephemeral `~`, signal `*`, now the AK's marker, no schema flag; presence became renewed expiring writes, notes/ephemeral.md Values that live while their author is there). `ephemeral` means only: the commits, bodies, headers and every index or sync row derived from them live in memory, and are lost once no node holds them. Everything else is durable's: commits, dot form, validity (spec/permissions.md §5.2), atomic apply, pending, retention and purge, compaction snapshots, must-hold, deletes at hosts, undo. Expiry differs: an expired ephemeral delta vanishes whole, never value-less (spec/crdt.md §4.7 Ephemeral data; mvp-progress item 175; in Core since step A).

- **Session source.** Ephemeral writes need counters that need not survive a restart. Replace the `Commit(session)` hack and `Authors` with a source `Session(node tid, 16-byte nonce)`: counters per (aspect, source), contiguous. Frontiers then cover session sources, so snapshots need no `Absorbed` list for them, and attribution is in the dot (no session can be misattributed to another node). Demotion frontiers still list no session source: a demoted writer's ephemeral writes all go (today's rule).
- **Storage.** The store gets a memory overlay: each row is durable or memory by the class of the commit (or ephemeral thing) it derives from; reads merge both; open starts with an empty overlay. Invariant (already the "durable set closed under owner" rule, generalized): no durable row refers to a memory row. node-sync's per-entry sync records route the same way, so "a lane status leaked into the durable sync records" (a past restart bug) cannot happen by construction.
- **One storage class per aspect.** Built in step 2: `group.0`'s ephemeral side, joined at read, became a core ephemeral aspect `placed.0~` (type of `group.0`) read together with `group.0` by the group index; conversion at persistence stays. The engine's general durable+ephemeral join of one aspect goes.
- **Commits.** A memory commit holds only memory deltas; a mixed `Write` stays two commits at one `ts` (one change for undo, a local pairing). Persistence of ephemeral things (`created.0` chain in the first durable commit) is unchanged.
- **Retention.** Every option applies, default from the schema like durable. Ephemeral bodies are compacted by ordinary snapshots by any writer, under keep bounds. Expiry vanishes whole (Model). Durable never compacts an aspect whose snapshot would keep at least and at most (carrier only, spec/commits.md §5): unified, such ephemeral aspects get no coalescing either and grow until their own keep-at-most bounds or expiry drop bodies, against the node and host ephemeral caps; refuse that retention on ephemeral aspects, or accept it.
- **Signals** stay relay-only commits (no storage at all).

## Answers to Tess's questions
1. Own covers -> ordinary snapshots: yes. Removes `compact_own_ephemeral`, `coverable`, `caught_up`, `cover_est`/`COVER_FACTOR` (becomes the general compaction trigger), `only_of`, `eph_containers`, `drop_absorbed`, `absorbers`, `cover_part_bad`, `Remote::full` and split covers (memory deltas may page like durable ones), waiting deletes/orphans (durable delete-after-carrier and Replace). Adds: automatic compaction policy (durable needs it anyway: only explicit `compact` is built), frontier coverage of session sources, header forgetting (below).
2. Same retention options: yes, allowed, not mandated. Keep at least on ephemeral = kept in memory while anyone holds it; it is also how undo depth is set (the ephemeral undo log and `ephemeral_history` go). Mandating it would fill caps: a cursor at 30 writes/s keeps about 100k bodies an hour. Under caps a kept-history aspect behaves like durable under a host budget: past the cap uploads are refused (defined outcome, `EphemeralRefused`); a schema author chooses it knowingly.
3. Collapses: the engine's `Remote` (held records, judge, rebuild, pending/waiting apart, record freeing) into Core over the overlay; node-sync's lane into the durable sync path (must-hold, uploads, restamp/re-sign on code 9, deletes after carrier, work sets); the joined read; the undo log; `Authors`. Wire: the ephemeral header marker and prefix class stay (hosts must know what to keep in memory), the ephemeral commit kind's special rules go (the snapshot `Authors` array went in step 1). Coalescing becomes compaction before upload: while an upload is in flight own new commits accumulate; when answered, two or more of an aspect's unsent own bodies are snapshotted and only the snapshot goes up (covered bodies are may-hold, never uploaded).

## Serious problems and simplest answers
- **Forged snapshots.** Durable decided (notes/permissions.md Snapshots and history): a valid snapshot's copy governs a held original, so holders converge. With unification ephemeral data inherits it, applied once. Not blocking.
- **A cover turning invalid (issues/eph-cover-invalidated-loses-absorbed.md).** Same family as durable's answer (a body counting as never received again is fetched again where present; a part a held snapshot of any validity lists counts as held, Tess's decision (a)); with unification the ephemeral issue goes with it. Not blocking.
- **Host deletes.** Durable deletes a covered body at a label only while a snapshot under that label carries it, after keep-at-least (none by default: at once). That is today's "delete after the cover is there", per label by rule, which also closes the partial-label loss without `caught_up`. Not blocking.
- **Restart (issues/eph-caught-up-stall.md).** Gone: a snapshot covers only what the node's state holds (join-redundancy), and deletes are per label by carrier, so an earlier session's bodies need no catching up before compaction; any writer compacts them. The restart reconcile (cursor passed memory entries) stays.
- **Caps and others' data.** Node cap stays per label over every memory body not of own unsent writes, own snapshots included (they hold others' writes); a snapshot replaces what it covers, so compaction never grows the charge. Host cap per label: one snapshot per aspect replaces per-author covers (k authors overwriting one value now keep one value, not k). Risk: concurrent compactors at a full host, the loop own covers were made to stop. Answer: compactor = writer of the aspect's latest write after a randomized delay (notes/sync.md policy), upload names covered bodies as replaced (Replace), covered-equal drops duplicates, refusals retried at the periodic pass. Check with the capped `random_window` and sim `ephemeral_capped` oracles. Fallback, protocol unchanged: honest nodes snapshot only their own writes (a local policy).
- **Header memory.** Durable keeps every applied header forever; in memory that grows with write rate (about 15 MB an hour per author at presence rates). Answer: a memory commit's header is forgotten once its body is dropped and a held valid snapshot's frontier reaches its counters; a replay is recognized by the frontier. Spec commits.md §5 gets this exception for memory class.
- **Local write cost (requirement).** Tess accepted "no disk I/O, well under a millisecond, no signing or encryption until upload if needed". Measured in step 2 (below): an ordinary commit through Core with every row in memory is about 1.7M instructions, 0.15-0.18 ms on a quiet box (0.6 ms at load 67), 77x today's local ephemeral write and 0.46x a durable one; signing and verifying are about a quarter of it. Within the bound; the fallback (sign and encrypt only at upload) is not needed.
- **Memory deltas paging.** Pages become memory blobs with their own entries; the durable fetch-before-apply path handles them. The node cap's pre-decode bound merges with issues/durable-decode-bound.md.

Nothing found is truly blocking. Tess should confirm the local-write cost relaxation.

### Step 1 as built
- `SourceKind::Session(Session { node, nonce })` (osis-crdt `stamp.rs`, crdt-model `Source::Session`): wire `bytes(31)`, order `Session` < `Commit`; `Frontiers` per session; the snapshot `Authors` array, `Remote::mine` and `authors_of` gone; receivers keep a part's writes under the author's sessions only (`only_of`, `own_session`). `EphemeralId.session` is the nonce.
- Counters per (thing, aspect) per session (`Eph::next`), taken when a batch applies (`apply_ephemeral`), so the old reset-on-failure is gone.
- Counters of a freed thing are kept for the session (review: dropping them reused counter 1 when the thing came back from a holder, `freed_thing_received_again_keeps_counters_spec_crdt_2_1`). That test also shows a divergence not checked on main: the author gets the thing back without its own earlier writes (a reads `{k2}`, b `{k1, k2}`); step 3 (held bodies through Core) should remove it, check there.
- Not yet: no commit's own writes are a session's (ephemeral commits stay commit-form snapshots carrying session stamps, frontiers empty); receipt and validity read no session frontier entry; durable code treats a session dot as owned by no commit. Step 2/3 needs a header dot form whose own source is a session, and receipt/`ranges` per session source.
- Found: the own-cover trigger counted delta bytes plus `ENTRY_CHARGE` per commit, while a holder's node cap charges `PART_OVERHEAD` (2 KiB) per part; with `Authors` gone deltas shrank, covers came later, and a holder of several 1000-part small commits filled its default 16 MiB cap before the cover came, refused it and stayed diverged (`own_cover_split_by_aspect`, `cover_past_page_target_bounded`). Fixed: the trigger weighs each part, held or in the cover, as its bytes plus `PART_OVERHEAD` (`part_weight`, shared with the node cap's `part_charge`); both tests pass at default caps again. Step 5's compaction trigger must keep this: weigh per part what holders are charged.

- **Found** (why local memory commits wait for step 3; each is needed by received memory commits too, and doing local first would rewire `Remote`'s own state, covers and rebuilds only for step 3 to delete them):
  - Dot form keyed by session (a header field with the nonce; own source `Session(author, nonce)`): every form-dependent site (about 30: `Owned`, validity, receipts, retention by frontier, moves, undo, the index's `View` encoding) generalizes from the author node to a source, and `ix.ranges` must be keyed by source (two sessions of one node would overlap).
  - Ephemeral things' records in Core: the perm held set has no record removal (freeing), adds a timeline update per record, and `Core::created` has about 57 users that mean "durable"; persisting moves the `t/` row from memory to durable explicitly (row routing keeps a memory row in memory).

  - Freeing an ephemeral thing must drop its memory commits from Core's indexes cheaply (not `retention::forget`, which invalidates the persisted index and reloads).
  - Rows a durable-mode transaction creates for memory things (retention timers, value-less records, receipts, `DEATHS_DUE`, `index::write_all`) need routing by class; aspect-keyed catalog rows already route by the aspect's mark, opaque local keys do not.
  - Node-sync and the API must not see memory commits as durable: `take_changed`, labeling bodies, `commit_ids`, commit events (`Event::Ephemeral` instead), receipts (no demotion frontier may list a memory commit).
