# Ephemeral as a storage property only
> Summary: Design (owner direction: "ephemeral should be same as durable in almost every way") to make ephemeral data ordinary data whose commits, bodies and index rows live in memory: own covers, the separate held-commit records, the node-sync lane and the ephemeral undo log go; ephemeral aspects take ordinary compaction snapshots and every retention option. Kept: memory storage itself, presence (author tie), signals (relay-only), the restart reconcile, a memory cap. Problems listed with their simplest answers; none blocks. Seven-step plan, roughly 3500 lines removed and 2000 added.
> Tags: ephemeral, design

## Model
Lifetime flags stay (`ephemeral`, `presence`, `signal`). `ephemeral` means only: the commits, bodies, headers and every index or sync row derived from them live in memory, and are lost once no node holds them. Everything else is durable's: commits, dot form, validity (spec/permissions.md §5.2), atomic apply, pending, retention and purge, expiry, compaction snapshots, must-hold, deletes at blind nodes, undo.

- **Session source.** Ephemeral writes need counters that need not survive a restart. Replace the `Commit(session)` hack and `Authors` with a node-form source `Session(node tid, 16-byte nonce)`: counters per (aspect, source), contiguous, as `Node`. Frontiers then cover session sources, so snapshots need no `Absorbed` list for them, and attribution is in the dot as for `Node` (no session can be misattributed to another node). Demotion frontiers still list no session source: a demoted writer's ephemeral writes all go (today's rule).
- **Storage.** The store gets a memory overlay: each row is durable or memory by the class of the commit (or ephemeral thing) it derives from; reads merge both; open starts with an empty overlay. Invariant (already the "durable set closed under owner" rule, generalized): no durable row refers to a memory row. node-sync's per-entry sync records route the same way, so "a lane status leaked into the durable sync records" (a past restart bug) cannot happen by construction.
- **One storage class per aspect.** Today `/group` has a durable and an ephemeral side joined at read. Replace that side with a core ephemeral aspect `/placed` (type of `/group`) read together with `/group` by the group index; conversion at persistence stays. The engine's general durable+ephemeral join of one aspect goes.
- **Commits.** A memory commit holds only memory deltas; a mixed `Write` stays two commits at one `ts` (one change for undo, a local pairing). Persistence of ephemeral things (`/created` chain in the first durable commit) is unchanged.
- **Retention.** Every option applies, default from the schema like durable. Ephemeral bodies are compacted by ordinary snapshots by any writer, under keep bounds. Expiry is durable's. Durable never compacts an aspect whose snapshot would keep at least and at most (carrier only, spec/commits.md §5): unified, such ephemeral aspects get no coalescing either and grow until their own keep-at-most bounds or expiry drop bodies, against the node and server ephemeral caps; refuse that retention on ephemeral aspects, or accept it.
- **Presence** = ephemeral + implied keep at most 0 after replaced + the existing author tie (server deletes an entry when its uploading connection closes; nobody relays; a holder drops a body no source holds; lease `MAX_LEASE`). Presence aspects are never snapshotted (a non-author snapshot would outlive the author's connection); at-most-0 drops each superseded body at the kill, so a cursor keeps one body per author. Keep-alive rewrites the live values (a new commit superseding the old) instead of a presence cover. Presence covers, `may_absorb` and "a presence commit is the whole own state" go.
- **Signals** stay relay-only commits (no storage at all).

## Answers to the owner's questions
1. Own covers -> ordinary snapshots: yes. Removes `compact_own_ephemeral`, `coverable`, `caught_up`, `cover_est`/`COVER_FACTOR` (becomes the general compaction trigger), `only_of`, `eph_containers`, `drop_absorbed`, `absorbers`, `cover_part_bad`, `Remote::full` and split covers (memory deltas may page like durable ones), waiting deletes/orphans (durable delete-after-carrier and Replace). Adds: automatic compaction policy (durable needs it anyway: only explicit `compact` is built), frontier coverage of session sources, header forgetting (below).
2. Same retention options: yes, allowed, not mandated. Keep at least on ephemeral = kept in memory while anyone holds it; it is also how undo depth is set (the ephemeral undo log and `ephemeral_history` go). Mandating it would fill caps: a cursor at 30 writes/s keeps about 100k bodies an hour. Under caps a kept-history aspect behaves like durable under a server budget: past the cap uploads are refused (defined outcome, `EphemeralRefused`); a schema author chooses it knowingly.
3. Collapses: the engine's `Remote` (held records, judge, rebuild, pending/waiting apart, record freeing) into Core over the overlay; node-sync's lane into the durable sync path (must-hold, uploads, restamp/re-sign on code 9, deletes after carrier, work sets); the joined read; the undo log; `Authors`. Wire: the ephemeral header marker and prefix class stay (servers must know what to keep in memory), the snapshot `Authors` array and the ephemeral commit kind's special rules go. Coalescing becomes compaction before upload: while an upload is in flight own new commits accumulate; when answered, two or more of an aspect's unsent own bodies are snapshotted and only the snapshot goes up (covered bodies are may-hold, never uploaded).

## Serious problems and simplest answers
- **Forged snapshots.** Durable decided (notes/permissions.md Snapshots and history): a valid snapshot's copy governs a held original, so holders converge. With unification ephemeral data inherits it, applied once. Not blocking.
- **A cover turning invalid (issues/eph-cover-invalidated-loses-absorbed.md).** Same family as durable's answer (a body counting as never received again is fetched again where present; a part a held snapshot of any validity lists counts as held, owner decision (a)); with unification the ephemeral issue goes with it. Not blocking.
- **Server deletes.** Durable deletes a covered body at a label only while a snapshot under that label carries it, after keep-at-least (none by default: at once). That is today's "delete after the cover is there", per label by rule, which also closes the partial-label loss without `caught_up`. Not blocking.
- **Restart (issues/eph-caught-up-stall.md).** Gone: a snapshot covers only what the node's state holds (join-redundancy), and deletes are per label by carrier, so an earlier session's bodies need no catching up before compaction; any writer compacts them. The restart reconcile (cursor passed memory entries) stays.
- **Caps and others' data.** Node cap stays per label over every memory body not of own unsent writes, own snapshots included (they hold others' writes); a snapshot replaces what it covers, so compaction never grows the charge. Server cap per label: one snapshot per aspect replaces per-author covers (k authors overwriting one value now keep one value, not k). Risk: concurrent compactors at a full server, the loop own covers were made to stop. Answer: compactor = writer of the aspect's latest write after a randomized delay (notes/sync.md policy), upload names covered bodies as replaced (Replace), covered-equal drops duplicates, refusals retried at the periodic pass. Check with the capped `random_window` and sim `ephemeral_capped` oracles. Fallback, protocol unchanged: honest nodes snapshot only their own writes (a local policy).
- **Header memory.** Durable keeps every applied header forever; in memory that grows with write rate (about 15 MB an hour per author at presence rates). Answer: a memory commit's header is forgotten once its body is dropped and a held valid snapshot's frontier reaches its counters; a replay is recognized by the frontier. Spec commits.md §5 gets this exception for memory class.
- **Local write cost (requirement).** Today a local ephemeral set is about 20k instructions (50x a map insert); an ordinary commit applied into memory tables (header, hash, signature, deaths, indexes) will be several times more. Simplicity rule: relax "about an in-memory structure" to "no disk I/O, well under a millisecond", measured in step 2 (`ephemeral::bench_*`). If missed, sign and encrypt only at upload (a thing in no labeled closure never needs either), before any separate fast path. This is the one requirement change; not blocking unless the owner wants the old bound.
- **Memory deltas paging.** Pages become memory blobs with their own entries; the durable fetch-before-apply path handles them. The node cap's pre-decode bound merges with issues/durable-decode-bound.md.

Nothing found is truly blocking. The owner should confirm the local-write cost relaxation.

## Plan
Each step merges alone and passes the gate. Line counts are rough (now: engine `ephemeral/` 3442, node `sync/ephemeral.rs` 1807, tier-1 ephemeral tests about 4900).
1. Session source as node form (`Session(node, nonce)`, per-aspect counters, frontiers; `Authors` gone). crdt §2.1, §8. Built (step 1 as built below).
2. Store memory overlay and routing by class; `/placed` replaces the ephemeral side of `/group`; local ephemeral writes become ordinary commits applied in memory; measure write cost (decision point above). About +800/-500 (`mod.rs`, `place.rs`, joined reads).
3. Received memory commits through Core: durable verify, pending, validity, un-merge, atomic apply; `Remote` held/judge/rebuild/waiting go; header forgetting. About +400/-1500.
4. Sync: memory bodies through the durable must-hold/upload/delete path; the lane keeps presence sources and ties, relay-only, restart reconcile, node cap. Coalescing as compaction before upload. About +400/-1200.
5. Automatic compaction policy for both classes (trigger, randomized delay, Replace at cap); own covers deleted; presence as at-most-0 with rewrite keep-alive. About +300/-600.
6. Undo over held bodies for memory commits; undo log and `ephemeral_history` go; mixed batch pairing. About +100/-350.
7. Spec (commits §1-2, §5; sync §6, §9; crdt §2.1, §8; data-model §2, §8; permissions §5.2) and notes rewrite.

### Step 1 as built
- `SourceKind::Session(Session { node, nonce })` (osis-crdt `stamp.rs`, crdt-model `Source::Session`): wire `bytes(31)`, order `Node` < `Session` < `Commit`; `Frontiers { nodes, sessions }`; the snapshot `Authors` array, `Remote::mine` and `authors_of` gone; receivers keep a part's writes under the author's sessions only (`only_of`, `own_session`). `EphemeralId.session` is the nonce.
- Counters per (thing, aspect) per session (`Eph::next`), taken when a batch applies (`apply_ephemeral`), so the old reset-on-failure is gone.
- Not yet: no commit's own writes are a session's (ephemeral commits stay commit-form snapshots carrying session stamps, frontiers empty); receipt and validity read `Node` frontier entries only; durable code treats a session dot as owned by no commit. Step 2/3 needs a header dot form whose own source is a session (or node form keyed by session), and receipt/`ranges` per session source.
- Found: the own-cover trigger counts delta bytes plus `ENTRY_CHARGE` per commit, while a holder's node cap charges `PART_OVERHEAD` (2 KiB) per part; with `Authors` gone deltas shrank, covers came later, and a holder of several 1000-part small commits filled its 16 MiB cap before the cover came, refusing it (`own_cover_split_by_aspect`; `cover_past_page_target_bounded` similarly by a cover's decode bound). Both tests now give the holder a 64 MiB cap. Step 5's trigger must weigh what holders are charged, per part.

Tests: behavioural ephemeral and presence tests (convergence, restart, caps, presence leave, signals) carry over; cover-specific ones go. The randomized `random_window_*` and sim `ephemeral*` scenarios are the acceptance oracles for steps 3-5. Steps 3-5 are intricate changes in one area: one at a time.
