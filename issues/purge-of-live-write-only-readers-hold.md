# A purged live write whose body only readers hold leaves writers reading the older value for good
> Summary: a request naming a live write without resetting it: nodes that held the write's body hold its leftover and read nothing; nodes that never held it read what it replaced until a writer that held the body re-snapshots. With no such writer left (author gone, only readers held the body), an admin and a reader that sync read differently for good, against the wording of spec/requirements.md Convergence. Arrival order is not the cause.
> Priority: normal
> Tags: engine, tess-call

## What is true
- Reading is a function of the held set, not arrival order: a body arriving after the request naming it runs `purge_arrived` → `purge_one` → `hold_valueless`, the request's own path (`apply_request` → `purge_one`), and reads as in order (engine `resnapshot::purged_secret_reads_nothing_whatever_reaches_first_spec_commits_5`, `Secret::LateBody`).
- A node given only the header (the sender purged the body) never holds the body: the part is missing when judged, so it is dropped (`make_leftover`, `DropFor::Other`) and the list alone holds it value-less. Its write is in no held body, so the value it superseded wins there (spec/crdt.md §4.7: a value-less write takes part in "later wins" only where held). A writer's re-snapshot from a node holding the leftover carries the write value-less and repairs it (spec/commits.md §5 Purge, the re-snapshot sentence); `Secret::LateHeader` converges once 0's re-snapshot reaches 1.
- A leftover is local (spec/commits.md §5: "never logged"): only a writer's snapshot carries it to others. A reader's leftover cannot be relayed: it does not hash to the header entry, and a reader is trusted for availability only.

## The gap (reproduced, seed 0, 3 nodes)
Admin 0 writes "old"; writer 1 writes "SECRET" and gives it to reader 2 only, then is gone; 0 purges by author 1 on the aspect without resetting it. 2 holds the leftover and reads `None`; 0 gets SECRET's header from 2, never its body, reads `"old"` and its own re-snapshot carries `"old"`. Any number of exchanges: 0 `Some("old")`, 2 `None`. With a reset of the aspect in the request's commit both read `None` (the reset is relayable). The same holds for an expired write (spec/crdt.md §4.7 states it there: "until a writer holding the leftover ... snapshot carries the leftover's writes") and is the purge-side twin of issues/drop-rejoin-robust.md item 3.

## The question for Tess
spec/requirements.md Convergence: "at the latest once a writer of that data has synced with them". 0 is a writer of the aspect and synced with 2. Either:
1. **Accept and say so**: "a writer of that data" means a writer holding it; requirements (or spec/commits.md §5 Purge) state that a purge of a live write no syncing writer held leaves non-holders reading what it replaced, and requests SHOULD reset live content (spec/commits.md §5 already says so; the `osis` API's `Purge::Commit`/`Purge::Author` do not reset, `Purge::All` does). Cost: a user-visible divergence in a narrow case (live write, author gone, no reset).
2. **Close it: leftovers checkable by anyone.** The delta hash commits to each value by its hash (values as leaves), so a value-less body with value hashes in place of values verifies against the header; any holder logs its leftover, and a node lacking the body takes it as a body. Also closes §4.7's expiry limit and item 3's purge-fall gap for leftovers. Cost: a wire change (free) and a hash per value-carrying write in each leftover; checking cost per value.
3. Rejected unless Tess wants it: a purged write leaving "later wins" (every node reads "old"): resurrects a superseded value the user saw replaced, and breaks the expiry semantics it shares (a disappearing message would show its predecessor).
