# A link naming no blob fails its whole aspect's read
> Summary: A link where the type takes one (blob, string, `any`, or a non-small set element or map key, spec/data-model.md §6) that names no blob, or one under another thing's dedup secret, fails the whole read of its aspect: `Reader::get`/`get_path` above that position and every watch and `on_change` (they read untyped through `Reader::value`) get `blob missing` / `verification failed`, not one absent element. Thin clients cannot write links; a hostile writer node can, in any aspect it may write (core aspects included: a `string` field of `name.0` or `label.0`). A fix could read such a link as a per-position failure (absent element plus diagnostic) when materializing, as `misplaced_link` does for links where the type takes none.
