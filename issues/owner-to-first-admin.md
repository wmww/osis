# Owner becomes first admin: build plan
> Summary: Staged plan for notes/owner-removal-plan.md step 2: A ownerless things derive secrets (nothing but the record at creation), B one record form and one authority class (Class::Chain, owner links and their rules gone; person, links, ephemeral, inbox), C the remaining words in spec and code (derivation chain, `MAX_CHAIN_DEPTH`), D the public API, CLI and apps (conflicts with the API work). Inventory, exact spec text, tests per stage, risks to model or measure first, one question for Tess.
> Tags: permissions, keys, perm, engine, spec, api

## What owners do now and what replaces each
| Owner role today | After step 2 |
|---|---|
| Fixes the tid (record commits to the owner) | Record `{admin, nonce}` or `{key, nonce}`: the tid commits to the first admin, as ownerless records do now. History only: it gives no power once the edge goes. |
| Inheritance: a role on an actor reaches what it owns | Path rule only: the record edge is an admin edge from before every write, stored nowhere, removable. A role on F reaches T through F's record edge on T while it stands. |
| Plain things derive secrets from the owner | Derive from the first admin's, by the record chain (static). Any edge write on a plain thing gives it secrets of its own first (today only grants do), so derivation never outlives the edge except in the refused case below. |
| Top authority (`Class::Chain`, irremovable, outranks edge admin, "an edge cannot name the owner") | Gone. Classes: edge admin, invite. Fights between admins: step 3. Until then every thing has the hole of issues/ownerless-first-admin-backdate.md. |
| Roster snapshots | Gone (step 1). |
| Person: a recovery key owns the account | A device is first admin; a recovery card is a key actor with a plain admin edge, granted in the account's creation commit (so the account has secrets of its own from creation). A thief can remove it (accepted). |
| Link K "owned by the sharer" | K's first admin is the sharer's actor. |
| Move "never" | Grant then remove; no tid change (notes/moves.md). |

**The refused case**: a node MUST NOT remove or lower the last admin edge of a plain thing (refused locally, `Invalid`). Signed anyway it applies; the thing stays plain, its content stays readable through derivation by the first admin's holders, and nobody writes it. A stated limit, no machinery (only the remover's own data).

**Naming a first admin** needs write on it (today's owned rule, a client check: the record itself needs no authority once it carries nothing else). The creator then holds write on T through F, and F's admins hold admin. Tess asked for this to be settled (issues/api-after-owners.md): question below.

## Risks; model or measure first
1. **Key access after a grant is removed** (not modelled: keys-requirements-study §4, "grant removal"). The common case is now the record edge: F first admin of T, T granted on F (keyless); F removed from T makes T-on-F keyed and needs a re-seal. Add a Depth0 instance (earlier grant removed in a 2-cycle: no lockout, no leak) before B.
2. **Walk cost of a record edge per thing.** `Items::initial` and `Ever` hold every ownerless edge today and `Items` clones; B makes that every thing. Keep record edges virtual (read from the records; a written edge overrides) and measure perm `bench`, node `scale::`, sim scale before and after B. Audits by edge reach need a first-admin reverse index (today's ownership tree has the same size).
3. **Interim hole**: from B until step 3 a removed admin can backdate and take back any thing, accounts included (recovery no longer settles it). Pre-release; build step 3 next.
4. **Derivation after the edge goes**: covered by "any edge write gives secrets of its own first" plus the refused case; a forced removal on a plain thing is tested in A.
5. **Record-chain reads that outlive removal**: `admit own` (hosting only, ciphertext: kept static), inbox and `label.0` cross-publish (rules above so nothing goes to a removed first admin).
6. **Depth**: ownerless tops no longer reset the cap; chats add two links. Check app trees stay far under 64.
