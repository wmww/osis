# Re-snapshot neutrality fails when a drop removes its own cause
> Summary: `joint_resnapshot_neutral_large` fails on `OSIS_PERM_SEED` 6 (sample 3815) and 8 (sample 18665), predating the certificate fix: the full walk keeps a drop whose dropped write was what made the demotion a fall; the re-snapshot's roster (computed with that write dropped) replays the demotion as no fall, so the drop disappears.
> Tags: permissions, tests

Both samples have the same shape: X lowers or removes one of its own paths P1 to N (write W, unseen by R's author); a later explicit demotion R removes X's other path P2. In the first round R is a fall (P1 gone), so it drops W and the walk restarts; in the restarted walk P1 is back, R is no fall, but D only grows (§5.1 step 4), so W stays dropped. A re-snapshot of N carries the roster with P1 (W dropped) and R as a ledger end; replayed, R is no fall and W stands.

- Seed 6 sample 3815: nodes n0, n1; A0 owned by n1, A1 by n0, A2 by A0. Genesis: A1 admin on A0, A2 write on A1. n0 at t1 makes A2 admin on A0, at t2 removes it (W, n1 never receives it); n0 at t5 gives n1 write on A2 (also dropped); n0 at t6 makes A1 admin on A2; n1 at t8 lowers A1 to write on A0 (R). P1 = A1 -> A2 -> A0, P2 = A1's admin edge on A0.
- Seed 8 sample 18665: n0..n3; A0 owned by n3, A1 by A0, A2 by n0. Genesis: A1 and A2 admin on A0, n1 admin on A1 and A2. n1 at t1 removes A1 from A0 (W, unseen by n3); n1 at t3 makes n0 admin on A1 (owner-chain class, also dropped); n3 at t7 removes A2 from A0 (R). P1 = n1 -> A1 -> A0, P2 = n1 -> A2 -> A0.

Like sticky residue (`common::sticky_residue`, models/tla/membership M2: the first adding write in walk order wins), but R itself is not dropped, so the test does not skip it. Recommended detector (replacing `sticky_residue` in the neutrality, differential and projection tests): a drop is leftover residue when its cause R is not applied in the settled walk, or R is not a fall for the dropped write's author there; a snapshot may then only undo such drops. Alternative: change the walk so a restart re-judges earlier drops (a spec change to §5.1 step 4).
