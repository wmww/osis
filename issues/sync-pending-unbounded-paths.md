# What pends from a writer or a reader stays, and reexamine walks every pending commit
> Summary: unjudgeable commits pend (spec/commits.md §4); a writer's stamped entries carrying never-judgeable commits pend forever, uncharged and never judged by read; record blobs teach records for good from any reader; `reexamine` iterates every pending commit per call; sync's reopen of a named commit's carriers has no end-to-end test.
> Priority: normal
> Tags: sync, engine, security, tests

- **Stamped pending junk**: a writer of S can stamp entries of commits whose author's record never comes. Pending storage charges only unstamped entries, so nothing bounds them but the writer's own writes, and read never judges a commit not held, so no delete-key holder removes them, even after the writer's removal (requirements: authenticated malicious writers are bounded). Needs a rule: e.g. a stamped entry pending past a pass whose writer is no writer now counts as unstamped.
- **Records from record blobs** (`take_record_blob`): any holder of S's read secret can frame a record blob of arbitrary records (each proves only itself, `a_forged_record_in_a_record_blob_names_no_other_thing_spec_wire_3`), learned for good, unbounded (requirements: malicious readers only waste storage; peer input never causes unbounded storage). The inbox path's `learn_records` has the same shape. Learning only records something held or pending names needs the record blob entry kept and reopened when a record becomes wanted.
- **`reexamine` cost**: each call collects every pending key and skips those awaiting an unknown record: O(pending) per arrival, now that unjudgeable commits pend (a first sync with records late is O(commits × pending) cheap steps). `waits::on_record` already names who awaits each record.
- **Redelivery untested in sync**: `store::follow` opens every entry naming a blob of a commit `take_redeliver` names (`receive::junk_first_while_a_record_is_away_goes_once_it_comes_spec_commits_4` tests the engine side); the harness has no lie that sends a junk copy.
- `rewrap` refusing a per-sync-ID copy as a certificate of the same parts elsewhere has no test case that reaches it (no fixture found where both bodies hold the same parts).
