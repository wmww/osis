# One aspect with very many kept writes: what is left
> Summary: On one long kept aspect (a chat, 10^6 messages) a write and its arrival are flat, but a removal over about 1.9*10^6 commits cannot be sent (its list passes `MAX_LIST_BYTES`), every validity flip walks the thing's commits, open is O(commits), an aspect written in parts reads every body on a rise, a purge by author is one unbounded transaction, and store writes per message grow with the aspect.
> Priority: low
> Tags: engine, perm, performance

Counted in default tests: osis-engine `scale::long_aspect_writes_are_flat`, `scale::purge_rejudge_is_linear_in_requests_spec_permissions_6`, `scale::grant_is_flat_in_content_commits`, `scale::validity_flip_is_linear_and_invalid_arrival_flat_spec_permissions_5_2`. Release figures by hand, at 10^6.

In order of damage:
1. **A removal over about 1.9*10^6 commits cannot be sent**: its list passes `MAX_LIST_BYTES` and the member stays. Tess chose IDs only (spec/requirements.md Cost); ID batches are the fallback (notes/revocation.md, Frontier encoding).
2. **Purge by author is one store transaction under the engine lock**: about 1.4 ms and 35-66 KB of memory per delta dropped, so 10^5 deltas take minutes on every node and the hostile flood of notes/chat.md does not fit in memory. Chunking needs a persistent cursor per request run from the tick, resuming after a restart and after every later delta, reads and the watch seeing it part done, and `lasting` and re-snapshots at its end. A request by any writer also walks the aspect before any right is judged (2-3 µs per delta of the named author): judge `holds_right` once per (purge-by, actor) per walk.
3. **Every flip walks the thing's commits** under the engine lock (`validity::rejudge_all` over `by_thing`): 0.6 s at 10^6 for one flipped write; the first after an open also decodes every header (+2 GB resident). Skipping deltas whose answer cannot change needs perm to report which (node, thing) answers moved per evaluation.
4. **An aspect written in parts reads every body on a rise or a fallen winner** (a map's entries, a list's inserts; a whole-value write stops it at `Fragment::settled_above`): needs an index of which bodies hold writes superseded by each delta.
5. **Open is O(commits)** (5 s, 2.6 GB at 10^6): it scans every commit record, adapts every role commit and restores the walk over its whole input. Steps toward O(changed): fetch a header and its view from the store on first use (an open decodes every header today; blocked on borrowing: store reads need `&mut Store`, while about 180 readers are `&self`, e.g. `Engine::header`; shape: `Tx::header(id)` in a transaction, a read-only handle on the last committed root otherwise); load `by_aspect`, `ranges`, `invalid` per aspect on first touch; restore a held set and perm timeline per component. Rejected: a walk tag over a persisted hash of its inputs (saves little); persisting perm's adapted records (risks runtime and open adaptation disagreeing).
6. **A hostile admin's flips**: each role change making R named purge requests rise costs every peer about 0.36 ms per part in one transaction; bounded per role commit but repeatable. No narrower scope helps.
7. **Store writes per message grow** with the aspect (70 / 115 / 170 KB per batch at 10^4 / 10^5 / 10^6: key-tree nodes rewritten), though store size per message stays flat: disk wear.
8. **Ingest CPU per message grows during a fill** (0.75 ms at 10^5, 5.4 at 10^6) while a write after reopening stays 1.3-4 ms. Unexplained.
