# Call role grants "grants", not "edges"; let a node act as several things
> Summary: Engine and perm types and some defined spec terms still say "edge" for a role grant (`Edge`, `EdgeWrite`, "edge write", "edge admin", "record edge"); Tess dislikes "edge" for a permission: rename to "grant". Second: the `osis` API acts as one thing per node (`me()`); expose `Osis::act_as(actor)` so a caller can act as any thing the node holds roles on, `me()` the default.
> Priority: low
> Tags: api, perm, naming

- **Rename.** The `osis` API, CLI and notes already say grant. Left: engine and perm names, the defined spec terms and spec lines about mint admins. The perm walk's graph language (edges in the graph sense) stays. No wire change. issues/deprecated-terms.md lists the same rename among its rows.
- **Acting as several.** `Osis::act_as` exists crate-internal for the client port (notes/client-port.md §3). To make it public, every call must honour it: the sharing, sync and process-wide calls (the engine's grant and demote flows act with the node's authority and take no thing to act as); a text session (`edit_text`), whose idle-commit timer holds a `WeakOsis` that keeps no acting actor, so its merge reads and commits as the node; and `on_dispute`, which filters removals by the actor's role while `disputes` lists by the node's. Pairing a second account into a node is then a flow over it (notes/accounts-switch-brief.md piece 6).
