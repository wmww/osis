# A lasting snapshot under an expiring write owes covers for ever
> Summary: under purge on replace, a write a durable body holds that only an expiring write supersedes is dead (spec/crdt.md §4.8), so every snapshot of the aspect (which carries no expiring write, §8) is replaced the moment it is written and its writer owes another: held-model's `settle` never settles (seed 610247967463), and the spec's duty to cover has no fixpoint. Design question: which rule ends the chain.
> Priority: normal
> Tags: tests, held-model, engine

- The world: thing 13's register, setting purge on replace. A lasting body holds "bbc"; a valid delta with an expiry writes 1 over it at a greater stamp. The state holds 1; "bbc" is dead in it (beaten as a register winner). Snapshot 30202 carries the lasting state ("bbc", no expiring write) and is replaced (spec/commits.md §5 Bodies and deaths: it holds a write dead in the state, joining it changes nothing), under purge on replace, covered by no right holder's later snapshot: the right holder owes one (§5 Purge on replace). The cover it writes carries "bbc" again, so is replaced and owed in turn: one new cover per round, every round (`settle` gives up after 16).
- The model follows the spec here (`model.rs` Replaced bodies judges a lasting body against the whole state; only an expiring delta is judged against the state without its own writes). The engine's `retention::replace::replaced` judges alike, so it likely writes a fresh cover each transaction that marks the aspect due (unchecked).
- Options:
  1. A body without an expiry is judged against the lasting state (the state without the writes of deltas with an expiry, what a snapshot carries, spec/crdt.md §8): a write only expiring writes supersede is not dead to it, it comes back at their end. Generalised: a write is dead only once a write ending no earlier supersedes it (spec/crdt.md §4.8 When). Touches death and history dating, the model and the engine. Recommended: it is the rule that says what "replaced" is for (data never read again).
  2. A snapshot is never replaced by writes it could not carry: narrower, but a durable delta and the snapshot carrying its write would then be judged differently.
- Resolution needs spec/crdt.md §4.8 and spec/commits.md §5 Bodies and deaths changed, then held-model and the engine, with a held-model test of this shape (an expiring write over a lasting one under purge on replace) settling, and its control (the current rule) not.
