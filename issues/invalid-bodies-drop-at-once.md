# Dropping invalid bodies at once
> Summary: Tess's leaning (with addenda): a body judged invalid drops at the end of the transaction that judged it; one turning valid again (re-grant, a late addendum) is fetched from a holder or host, lost when none has it, nodes agreeing either way. Built on the `addenda` branch and taken out again: it changes what about fifty tests assume and exposes one engine asymmetry. What it needs is below.
> Priority: normal
> Tags: engine, retention, permissions, tess-call

## What was built (and removed)
`Core::drop_due` filled by `rejudge_once`, `apply_verified` and `join_late` with every part judged invalid and still held; `retention::drop_invalid_due` at the end of `Engine::run` (after `answer_removals`, so a witness lists what it still held), skipping role commits' parts, `addenda.0`, memory parts and, after chat broke, this node's own commits (its rejected posts are shown marked and sent again from the body: `Osis` history rows, chat `find`/`resend`). Bodies dropped so came back through `valid_again` (missing, `Changed::undropped`), and LocalPeer tests needed a second sync to fetch them.

## What it breaks
- **An engine asymmetry**: an aspect whose only delta arrived invalid and was dropped reads `None`; the same held set reached by the delta arriving valid and turning invalid reads `Some(List([]))` (the un-merge leaves the empty container, the drop rebuilds nothing). Pinned order seeds: `order::snapshot_anchor_vouch_reads_alike_seed_9200020`, `snapshot_anchor_vouches_invalid_insert_seed_9220021`, `snapshot_carries_write_nested_in_vouched_entry_seed_4136`, `snapshot_copy_of_deleted_text_creation_dies_seed_7731022`, `records_of_a_dropped_body_after_a_flip_seed_733028`, `dropped_live_write_given_again_after_flip_seed_733028`, `expired_record_keeps_keyed_valid_writes_seed_7340007`, `regrant_gives_purge_right_back_seed_3001`, `creation_lost_by_drop_then_flip_given_again`, `arrival_order_found_histories`, `arrival_order_required`. Fix: `drop_part_for(DropFor::Invalid)` must leave the aspect as a rebuild from the held bodies would.
- **Tests assuming invalid bodies are held** (spec/permissions.md §6, "nothing goes without a right"): retention `invalid_write_with_no_bound_keeps_its_body`, `invalid_write_drops_as_invalid`, `write_an_unmerge_took_drops_its_body`, `regrant_after_a_drop_healed_by_repair`, `demotion_lists_the_message_omits_the_delete`, `fall_of_a_fall_keeps_a_write_dead`, `fall_of_many_one_pass`, `register_rebuild_*`, `second_request_keeps_covered_leftover`, `purge_rights_both_arrival_orders`; required `broken_bodies_drop_without_right`, `broken_delta_falls_alone`, `setting_below_a_body_erases_nothing_held`, `writers_setting_goes_without_*`, `demoted_admins_change_falls_unmerge`, `setting_falls_through_acting`, `a_broken_permanent_delta_is_no_tombstone`, `delete_falls_after_reopen_reads_text`, `reopen_char_after_drop_healed_by_repair`; validity `unmerge_restores_register`, `cover_drop_coverer_flips_back_alike`, `coverer_demoted_after_cover_drop_alike`, `missing_snapshot_not_covered_by_older`, `inflated_snapshot_claims_count_nothing`; deletion `stale_drop_reads_alike`; history `invalid_body_reads_marked`, `events_per_commit_exact`; sim `coverer_revoked`. Each needs the spec rule restated (what a drop without a right means for required retention, purge leftovers, repairs and suspect flags) and the test rewritten to what a user observes after a fetch.
- **Re-grant restores less**: without a host, a re-grant restores only what a node that never applied the removal (or the author's own) still holds (LocalPeer tests sync again from such a node). With hosts, the blobs stay there (no right deletes them), so the fetch succeeds.

## Open for Tess
Whether to pursue it: the gain is storage at nodes holding others' invalid bodies (hosts keep them anyway); the cost is the fixes above and the loss when no holder is reachable. The addenda rules and the model hold either way (the model: only keeping invalid bodies loses nothing).
