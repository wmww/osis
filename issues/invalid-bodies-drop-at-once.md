# Drop invalid bodies at once
> Summary: Plan (Tess: dropping and refetching is fine): a body judged invalid drops at the end of the transaction that judged it, except the node's own commits (their author shows and resends rejected writes); one turning valid again (re-grant, late addendum) is refetched from any holder, lost when none has it, nodes agreeing. An invalid write contributes nothing to the state, so this fits the retention principle. Tried once on the addenda branch; what it needs is below. Today invalid bodies stay held (spec/permissions.md §6).
> Priority: normal
> Tags: engine, retention, permissions

0. **CRDT first (decided, Tess)**: a list's or text's order is computed from valid writes only. An invalid write's elements do not exist for ordering, even at a node holding them, so an ex-writer never influences the output. A valid element whose anchor is not a valid element goes to a fixed fallback place (e.g. the end, ordered by ID; the build picks the simplest deterministic rule); imperfect placement in this rare case (a writer removed while others edit around it) is accepted. spec/crdt.md §4.6's un-merge keeping an invalid delta's element records goes. Then an invalid body leaves nothing anything needs: it drops outright, is refetched if it turns valid, and needs no leftover. Without this, dropping junk hid valid elements anchored on its records (order seed 675857810820).
1. **Fix first, on its own**: dropping must equal rebuilding. Today an aspect whose only delta arrived invalid and was dropped reads `None`, while the same held set reached by the delta arriving valid then turning invalid reads `Some(List([]))` (the un-merge leaves the empty container). Pinned seeds that showed it: `order::snapshot_anchor_vouch_reads_alike_seed_9200020`, `snapshot_anchor_vouches_invalid_insert_seed_9220021`, `snapshot_carries_write_nested_in_vouched_entry_seed_4136`, `snapshot_copy_of_deleted_text_creation_dies_seed_7731022`, `records_of_a_dropped_body_after_a_flip_seed_733028`, `dropped_live_write_given_again_after_flip_seed_733028`, `expired_record_keeps_keyed_valid_writes_seed_7340007`, `regrant_gives_purge_right_back_seed_3001`, `creation_lost_by_drop_then_flip_given_again`, `arrival_order_found_histories`, `arrival_order_required`.
2. **Drop**: `drop_due` filled where a part is judged invalid; dropped at the end of `Engine::run` after `answer_removals` (a witness lists what it held); skip role commits' parts, `addenda.0`, memory parts and own commits; a flip back makes the part missing and fetched (`valid_again`).
3. **Tests**: about 30 assume invalid bodies are held (list in git history of this issue); rewrite each to what a user observes after a fetch; restate spec/permissions.md §6 ("nothing goes without a right") as the dropped-invalid rule.
